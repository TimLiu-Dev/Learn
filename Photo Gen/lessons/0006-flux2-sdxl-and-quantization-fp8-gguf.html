FLUX.2, SDXL, Split Loaders & Quantization (BF16 vs. FP8 vs. GGUF)

How Black Forest Labs' FLUX.2 family works, how split ComfyUI loaders replace single SDXL checkpoints, why BlockSwap destroys speed on UMA, and which weights are commercially licensed.

1. The Open-Weight Image Lineup & Licensing (Late 2026)

Model Scale & Capabilities License & Where It Shines
FLUX.2 [dev] 32B DiT + Mistral-3 24B VLM encoder; native up to 10 reference images, exact hex colors, 4MP coherence. Non-commercial open-weights (commercial API/license via BFL). Best for studio LinkedIn & Tinder photorealism.
FLUX.2 [klein] (4B / 9B) Compact rectified-flow family (distilled sub-second inference + undistilled base variants for LoRA training). 4B: Apache 2.0 (commercial-friendly!). Rapid seed exploration on M5 Max & Z13 before final 32B passes.
SDXL (and Pony / Illustrious) ~2.6B UNet + dual CLIP encoders; 4-channel latent. Open RAIL++. Ultra-fast generation, mature ControlNets, and unrestricted community fine-tunes.
Qwen-Image (2.1 / 3.0 / Layered) Multimodal LLM-paired backbone with native RGBA layer decomposition. Graphic design pipelines, complex text layout, and editable layer exports.

2. Split Loaders in ComfyUI (Why Load Checkpoint Fails on FLUX.2)

Classic SDXL bundles UNet + CLIP + VAE inside one 6.5GB file (CheckpointLoaderSimple). Modern 14B–32B models split those three pieces into separate files inside ComfyUI/models/ so you can quantize the heavy DiT independently of the text encoder and VAE:

ComfyUI Node Chain · FLUX.2 Quantized Split Loader
# M5 Max (GGUF path via ComfyUI-GGUF):
[UnetLoaderGGUF: flux2-dev-Q5_K_M.gguf] ──MODEL──▶ [FluxGuidance] ──▶ [KSampler]
[CLIPLoader: mistral_3_small_flux2_fp8 / gguf] ──CLIP──▶ [CLIPTextEncode] ──▶ [KSampler]
[VAELoader: flux2-vae.safetensors] ──VAE──▶ [VAEDecode]

# ROG Flow Z13 (ROCm FP8 path):
# Replace UnetLoaderGGUF with native [Load Diffusion Model] (flux2_dev_fp8mixed.safetensors)

3. Precision Math: BF16 vs. FP8 vs. GGUF

Rule of Thumb: Memory required ≈ params × bytes_per_weight + text encoder + activations. A 32B model in BF16 (2 bytes) needs ~64GB just for weights! On Unified Memory (M5 Max & Strix Halo), memory bandwidth—not capacity—controls seconds-per-step. Smaller quantized weights move fewer bytes per step across the memory bus:

Format Bits / Param M5 Max (MPS) ROG Z13 (ROCm) & Cloud NVIDIA
BF16 / FP16 16-bit (2 B) Clean & accurate; slower on 32B weights Native fast baseline on H100/L40S
FP8 (E4M3) 8-bit (1 B) Avoid (CPU fallback / poor MPS support) Recommended on Strix Halo & RTX 40/50/L40S (2× smaller & faster)
GGUF (Q4_K_M / Q5_K_M / Q8_0) 4–8 bit Best on M5 Max! Huge speedup, crisp quality at Q5_K_M/Q8_0 Great fallback when fitting huge 32B/14B models comfortably

4. Never Use BlockSwap on Unified Memory!

ComfyUI · Hardware-Specific Memory Strategy
# 16GB Discrete NVIDIA GPU (PC): RAM != VRAM -> BlockSwap offloads layers to system RAM
# 128GB M5 Max / Strix Halo:     RAM == VRAM -> BlockSwap copies from RAM to RAM (pure wasted overhead!)

# M5 Max optimal choices:
# - Load FLUX.2 / Wan 2.2 via GGUF Q5_K_M or Q8_0
# - Disable BlockSwap / CPU offload nodes
