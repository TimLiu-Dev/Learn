ComfyUI Setup on M5 Max & Strix Halo, Custom Nodes & Node DAGs

Turning your two 128GB unified-memory machines into private local AI studios, installing essential node packs via ComfyUI-Manager, organizing models/ cleanly, and reading typed DAG JSON.

Your Hardware Advantage
Most practitioners hit OOM crashes at 12GB–24GB VRAM. Both your MacBook Pro M5 Max (128GB) and ROG Flow Z13 Ryzen AI Max+ 395 (128GB) share 128GB Unified Memory—meaning 32B FLUX.2 and 14B Wan 2.2 fit locally once configured properly.

1. Configuring ComfyUI on Your Two 128GB Machines

A. MacBook Pro M5 Max (128GB Unified Memory · macOS MPS)

Precision Nuance: Older M1–M3 Macs used --force-fp16 because they lacked hardware BF16. Your M5 Max supports native BF16—avoid forcing global FP16 on FLUX/Wan to prevent black NaN overflow! Always launch ComfyUI with the MPS high-watermark limit disabled, enable PyTorch optimized attention, and prefer GGUF or native BF16 (avoid FP8 on MPS):

zsh · M5 Max 128GB Launch Script
git clone https://github.com/Comfy-Org/ComfyUI.git
cd ComfyUI
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# Install ComfyUI-Manager so custom node packs install cleanly from UI/CLI
git clone https://github.com/ltdrdata/ComfyUI-Manager.git custom_nodes/ComfyUI-Manager

# Critical: unlock full 128GB unified memory pool for PyTorch MPS
export PYTORCH_MPS_HIGH_WATERMARK_RATIO=0.0
python main.py --use-pytorch-cross-attention

B. ASUS ROG Flow Z13 (Ryzen AI Max+ 395 / Strix Halo · Radeon 8060S gfx1151)

  • BIOS / AMD Adrenalin VRAM Carve-Out: Set Dedicated/UMA Graphics Memory to 96GB–112GB (leaving 16GB–32GB for Windows/Linux OS) so PyTorch sees a massive single GPU pool.
  • ROCm 7.x Stack: Standard PyTorch wheels target discrete RDNA3 (gfx1100). Install ROCm 7.x / Strix Halo ComfyUI builds supporting gfx1151 so HIP detects the Radeon 8060S cleanly (supports both FP8 and GGUF).

3. ComfyUI Workflows Are Typed DAGs (Not Magic Boxes)

Remember the 4-stage pipeline from Lesson 01? ComfyUI exposes each tensor handoff as a typed wire between nodes: 

[Load Checkpoint] ──MODEL──▶ [KSampler] ◀──LATENT── [Empty Latent Image (1024x1024)]
        │                        ▲
      CLIP                       │ CONDITIONING (+ / -)
        ▼                        │
[CLIP Text Encode] ──────────────┘
                                 │ LATENT (denoised z_0)
                                 ▼
[Load Checkpoint].VAE ────▶ [VAE Decode] ────▶ [Save Image]

Wire types are strictly checked: MODEL, CLIP, CONDITIONING, LATENT, VAE, MASK, and IMAGE. You cannot wire a LATENT directly into Save Image without a VAE Decode node—and you cannot wire IMAGE into KSampler without VAE Encode first!

JSON · How ComfyUI Stores Node #3 (KSampler) Under the Hood
"3": {
  "class_type": "KSampler",
  "inputs": {
    "seed": 2027,
    "steps": 24,
    "cfg": 6.5,
    "sampler_name": "dpmpp_2m",
    "scheduler": "karras",
    "denoise": 1.0,
    "model": ["4", 0],          // output slot 0 of node "4" (MODEL)
    "positive": ["6", 0],       // output slot 0 of node "6" (CONDITIONING)
    "negative": ["7", 0],       // output slot 0 of node "7" (CONDITIONING)
    "latent_image": ["5", 0]    // output slot 0 of node "5" (LATENT)
  }
}
