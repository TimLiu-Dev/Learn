1. Android Developer → Linux Mental Bridge

Transferring Prior Knowledge

On Android you deal with Bootloader → boot.img (kernel + ramdisk) → init. Standard Linux follows the exact same architecture: UEFI → GRUB2 → Linux Kernel + initramfs → systemd (PID 1).

2. UEFI → GRUB2 → Kernel → initramfs → PID 1

Boot Architecture

1. UEFI/BIOS loads the EFI binary from /boot/efi.
2. GRUB2 reads /boot/grub/grub.cfg (generated from /etc/default/grub via update-grub) and loads the compressed kernel (vmlinuz) + initramfs into RAM.
3. Kernel decompresses, initializes hardware, and unpacks initramfs.
4. initramfs loads storage/LVM/LUKS drivers, unlocks and mounts the real root filesystem /.
5. Kernel switches root (switch_root) and executes /sbin/init (systemd, PID 1).

example-01: Inspecting /boot Artifacts & GRUB Config 
ls -la /boot              # vmlinuz kernel + initrd.img ramdisk
cat /boot/grub/grub.cfg   # Generated bootloader menu (never edit directly!)

3. Recovering Unbootable Systems with update-initramfs & chroot

Rescue Operations

When a server fails to boot because /etc/fstab, initramfs, or sshd_config broke: boot a rescue ISO, mount the root partition to /mnt, bind virtual filesystems (/dev, /proc, /sys), and run chroot /mnt /bin/bash so commands act directly inside the broken OS!

example-02: Regenerating GRUB & Initramfs After Kernel/Driver Edits 
sudo update-initramfs -u   # Rebuild initramfs for current kernel
sudo update-grub           # Regenerate /boot/grub/grub.cfg from /etc/default/grub

Automated patching failed silently across 40 VMs because a separate 512 MB /boot partition accumulated 9 old initrd.img files. Running apt autoremove --purge freed 350 MB per host and unblocked critical CVE kernel patches.

Interview Q1

Walk through what happens on Linux between pressing power and seeing a login prompt.

Model Answer: UEFI/BIOS initializes hardware → loads GRUB2 from EFI partition → GRUB2 loads vmlinuz + initramfs → kernel initializes devices and runs initramfs to load storage/LVM/LUKS drivers and mount real / → switch_root starts /sbin/init (systemd PID 1) → systemd launches multi-user targets and getty/sshd.

Interview Q2

How do you recover a server if someone forgot the root password and broke sudoers?

Model Answer: From console/GRUB, edit the boot entry to append init=/bin/bash (or boot rescue ISO + chroot), remount root read-write (mount -o remount,rw /), fix visudo/passwd, and reboot.
