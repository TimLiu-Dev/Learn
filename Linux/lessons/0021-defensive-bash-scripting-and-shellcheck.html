2. Bash Strict Mode & Defensive Variable Expansion

Fail-Fast Scripting

By default Bash ignores errors mid-script and expands missing variables to empty! Start production scripts with #!/usr/bin/env bash and set -euo pipefail: -e exits on non-zero command, -u fails on unset variables, and -o pipefail catches failures inside pipes (otherwise failing_cmd | cat exits 0!). Always wrap variables in double quotes: "$var".

example-01: Linting a Dangerous Script with shellcheck & Running Strict Script 
shellcheck ~/bad_deploy.sh   # Catches missing strict mode & unquoted rm -rf!
bash ~/health.sh
cat ~/script_kernel.txt

3. Cleanup with trap & Safe Re-Run Idempotency

Operational Reliability

Use trap 'rm -rf "$TMPDIR"' EXIT so temporary directories always clean up regardless of exit path. Make automation idempotent—safe to run twice in a row (e.g., mkdir -p, ln -sfn atomic symlink swap) without corrupting state.

Real Outage Pattern: Silent Backup Success While pg_dump Failed Inside Pipe

A database backup script lacked set -o pipefail and ran pg_dump prod | gzip > backup.sql.gz. When pg_dump failed authentication, gzip compressed 0 bytes cleanly and exited 0—so monitoring reported green backups for 3 weeks with empty 20-byte files!

Interview Q1

What does `set -euo pipefail` enable, and what is one caveat of `-e`?

Model Answer: -e exits on non-zero command, -u errors on unset variables, -o pipefail catches mid-pipe failures. Caveat: commands returning non-zero normally (like grep with 0 matches, or ((count++)) when count=0) abort unless guarded in an if or || true.

Interview Q2

Why use `#!/usr/bin/env bash` instead of `#!/bin/bash`?

Model Answer: It finds bash via $PATH across distros/macOS/Nix where Bash may live in /usr/local/bin or /opt (though on strict systemd/cron units, #!/bin/bash is often explicit).
