1. Android Developer → Linux Mental Bridge

Transferring Prior Knowledge

Your Android Emulator on Linux runs on KVM (Kernel-based Virtual Machine)! On AWS, GCP, and private clouds, the exact same KVM + QEMU + virtio paravirtual drivers power Linux guest VMs—bootstrapped automatically at boot via cloud-init.

2. KVM Hypervisor Stack & First-Boot cloud-init

Cloud Infrastructure

KVM exposes hardware virtualization (/dev/kvm) to QEMU, while virtio provides high-speed paravirtual NIC/disk drivers (vda, eth0) instead of slow emulated IDE hardware. At first boot, cloud-init fetches instance metadata (like 169.254.169.254) and runs once. In 2027, fleets increasingly bake Packer/bootc immutable images instead of mutating live pets!

example-01: Listing KVM VMs & Checking cloud-init Status 
virsh list          # Inspect running KVM/libvirt virtual machines
cloud-init status   # Confirm first-boot provisioning completed cleanly

Real Outage Pattern: Forgot cloud-init clean Before Baking a Golden AMI/Image

An engineer configured a VM manually, snapshotted it as a golden template, and spun up 20 clones. Every clone skipped cloud-init user-data because instance-ID state remained cached in /var/lib/cloud/! Running sudo cloud-init clean --logs (or building cleanly via Packer) before snapshotting solves this.

Interview Q1

Compare a KVM virtual machine vs a Linux container in terms of isolation and overhead.

Model Answer: A KVM VM runs its own isolated guest kernel and virtual hardware (stronger hypervisor boundary, higher boot/RAM overhead). A container shares the host kernel via namespaces/cgroups (sub-second startup, minimal overhead, narrower isolation boundary).

Interview Q2

What is `cloud-init` and when does it run?

Model Answer: It is the industry-standard multi-distro initialization tool that reads instance metadata and YAML user-data during first boot to configure SSH keys, users, disks, and packages.
