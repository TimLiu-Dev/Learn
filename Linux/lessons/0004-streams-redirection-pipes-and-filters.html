2. Streams 0/1/2 & Why > file 2>&1 Order Matters

FD Plumbing

Every Linux process opens three standard file descriptors: 0 (stdin), 1 (stdout), and 2 (stderr). Redirections are evaluated left-to-right: cmd > out.log 2>&1 points FD 1 to out.log, then copies FD 1's destination into FD 2—so both go to the file. Reversing them (2>&1 > out.log) leaves stderr pointing at the terminal!

example-01: Separating stdout and stderr vs Merging Both 
ls /etc/hostname /nonexistent_file > ~/ok.txt 2> ~/err.txt
cat ~/ok.txt
cat ~/err.txt

3. Composing cut, sort, uniq -c, tr & tee

Unix Filter Pipeline

Important rule: uniq only collapses adjacent duplicate lines, so you almost always run sort immediately before uniq -c. Follow with sort -nr to rank top offenders highest-first.

example-02: Ranking Top IP Addresses in a Log 
cut -d ' ' -f 1 /var/log/auth_ips.log | sort | uniq -c | sort -nr
Remember sort | uniq -c
Running uniq -c without sorting first misses non-adjacent duplicates—one of the most frequent CLI mistakes in interviews.

Real Outage Pattern: Silent Cron Errors Due to Reversed 2>&1

A nightly backup job used /usr/local/bin/backup.sh 2>&1 > /var/log/backup.log. Because 2>&1 came first, stderr never entered the log file—so disk-full errors vanished while engineers checked an empty backup.log assuming backups succeeded.

Interview Q1

Explain the difference between `cmd > file 2>&1` and `cmd 2>&1 > file`.

Model Answer: Redirections evaluate left to right. > file 2>&1 sends both FD 1 and FD 2 to file. 2>&1 > file sends FD 2 to the original stdout (terminal) and only FD 1 to file.

Interview Q2

How do you count the top 5 most frequent HTTP status codes in an access log using only coreutils?

Model Answer: Extract the status column with cut (or awk), then pipe into sort | uniq -c | sort -nr | head -n 5.
