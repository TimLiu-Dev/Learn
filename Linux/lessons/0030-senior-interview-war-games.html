2. Isolating Cascading Outages Without Panic

Incident Command

When paged at 2 AM, run a disciplined top-to-bottom check before restarting anything blindly (restarting destroys forensic evidence!):

  1. System & Kernel: uptime, dmesg -T (OOMs, disk errors?), free -h, vmstat.
  2. Storage: df -h, df -i, lsof +L1.
  3. Services & Logs: systemctl --failed, journalctl -p err.
  4. Network & Firewall: ss -tulnp, ip route, nft list ruleset, tcpdump -nn.
  5. Process/Security: strace, ausearch -m avc.
example-01: Rapid Multi-Layer Triage Sweep 
dmesg -T          # Kernel OOMs / I/O resets
df -h             # Disk fullness
lsof +L1          # Deleted-but-open disk leaks
ss -tulnp         # Bound ports & local addresses
journalctl -p err # Service & TLS errors

Real Outage Pattern: Three Simultaneous Failures During a Routine Traffic Spike

During a mobile app launch, an API stalled. Logs were silent because disk filled from an unrotated deleted file (lsof +L1), an auto-scaled node lacked net.core.somaxconn sysctl tuning, and an intermediate TLS cert expired. Systematic layer-by-layer isolation resolved all three in 18 minutes.

Interview Q1

Describe your mental checklist when someone says 'the server is slow'.

Model Answer: Apply the USE Method: uptime → dmesg -T (OOM/disk resets?) → vmstat / free -h (CPU runqueue, swap thrashing?) → iostat -xz (disk await?) → ss -s / sar -n DEV (network drops?) → perf/bpftrace for process-level hotspots.

Interview Q2

What makes a Linux portfolio project stand out to Senior hiring managers?

Model Answer: Reproducible automation (Ansible/cloud-init), real security hardening (nftables, SSH bastion, non-root systemd sandboxing, MAC), tested failure recovery (LVM backups, chaos drills), and clear documented postmortems/runbooks—exactly what you build in the AegisOps Capstone!
