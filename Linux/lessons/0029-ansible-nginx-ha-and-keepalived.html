1. Android Developer → Linux Mental Bridge

Transferring Prior Knowledge

Manually SSHing into 10 servers to edit nginx.conf guarantees configuration drift. Ansible automates whole fleets agentlessly over SSH, while Nginx + keepalived (VRRP) deliver zero-downtime TLS termination and failover.

2. Validating Nginx (nginx -t) & Fleet Playbooks

Fleet Operations

Before reloading Nginx, ALWAYS run sudo nginx -t so a syntax error never kills active TLS termination; then run systemctl reload nginx (graceful worker handoff, zero dropped requests) instead of restart. In Ansible, test dry-runs with --check --diff before rolling changes across production.

example-01: Catching Nginx Config Errors & Dry-Running Ansible 
cat /etc/nginx/conf.d/aegis.conf   # Inspect broken upstream rule
sudo nginx -t                      # Syntax check fails BEFORE broken reload!
ansible-playbook ~/site.yml --check

3. Eliminating Single Points of Failure with keepalived VRRP

High Availability

One Nginx reverse proxy is a single point of failure. Pair two proxy nodes with Keepalived running VRRP: a vrrp_script probes Nginx every 2 seconds, moving the shared floating Virtual IP (10.20.0.100/24) cleanly to the standby BACKUP node if the primary loses health.

example-02: Checking Live TLS Listener & Backend Socket Binding 
ss -tulnp                           # Verify 443 proxy + 127.0.0.1:8443 backend
curl -I http://127.0.0.1:8443/healthz

Real Outage Pattern: Non-Idempotent `shell: echo >> /etc/hosts` Broke After 50 Ansible Runs

An engineer used Ansible's shell: echo '10.0.0.5 db' >> /etc/hosts instead of ansible.builtin.lineinfile. Every nightly playbook run appended a duplicate line until DNS/hosts parsing choked on thousands of entries. Always use idempotent modules!

Interview Q1

Why does Ansible scale easily across fleets without installing daemon agents on target servers?

Model Answer: Ansible operates agentlessly over standard OpenSSH (using Python on the target) and achieves repeatability via idempotent modules and Jinja2 templates.

Interview Q2

What kernel `sysctl` limits commonly need tuning for a high-concurrency Nginx proxy?

Model Answer: net.core.somaxconn (listen backlog), file descriptor limits (LimitNOFILE / fs.file-max), and net.ipv4.ip_local_port_range.
