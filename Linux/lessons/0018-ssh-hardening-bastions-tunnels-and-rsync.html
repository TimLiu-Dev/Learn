2. Hardening SSH Keys & /etc/ssh/sshd_config

Zero-Password Access

Use Ed25519 keys (ssh-keygen -t ed25519)—faster and stronger than legacy RSA-2048. On every server, enforce PermitRootLogin no and PasswordAuthentication no in /etc/ssh/sshd_config, and ALWAYS test syntax with sshd -t while keeping an existing root/sudo SSH session open before reloading!

example-01: Generating Ed25519 Keys & Inspecting sshd_config 
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519 -N ""
ls -la ~/.ssh
cat /etc/ssh/sshd_config

3. Clean Bastion Hopping (ProxyJump), Port Forwarding & rsync

Secure Remote Ops

Never copy your private key onto a bastion host (and prefer ProxyJump over agent forwarding -A on untrusted bastions). Configure aliases in ~/.ssh/config so ssh prod-app hops cleanly through bastion, and use rsync -avz for fast resumable delta syncs.

example-02: Viewing Bastion Config Pattern & Running rsync 
# ~/.ssh/config pattern:
# Host prod-app
#   HostName 10.20.1.50
#   ProxyJump bastion
rsync -avz ~/projects/ android-dev@10.20.0.10:/srv/backups/

Real Outage Pattern: Restarted sshd After Bad Config Without a Second Session

An engineer disabled PubkeyAuthentication by typo while already disabling passwords, restarted sshd, and closed their terminal. With zero active sessions left and password auth off, nobody could log back in until cloud support mounted the root volume for repair.

Interview Q1

What is the difference between `ssh -L` and `ssh -R`?

Model Answer: -L forwards a local port on your client machine to a remote destination (e.g. reaching a remote DB); -R exposes a port on the remote server back to a service on your local machine.

Interview Q2

Why should `ssh-keygen` prefer Ed25519 over RSA?

Model Answer: Ed25519 provides high cryptographic strength with tiny 256-bit keys, faster signing/verification, and avoids legacy weak-key pitfalls.
