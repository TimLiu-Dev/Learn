1. Android Developer → Linux Mental Bridge

Transferring Prior Knowledge

Since Android 5.0, Android enforces SELinux in Enforcing mode—meaning even a root-owned process can be blocked by an SELinux policy! Senior Linux engineers apply that exact same Mandatory Access Control (SELinux on RHEL/Fedora, AppArmor on Ubuntu/Debian) plus Linux Capabilities on servers.

2. Debugging MAC Denials Without Disabling Security

Mandatory Access Control

DAC (chmod/chown) asks 'does the file owner allow this?'. MAC (SELinux labels or AppArmor path profiles) asks 'does system policy allow process context X to touch resource Y?'. When a service gets Permission denied despite 0644 permissions, check ausearch -m avc (SELinux) or aa-status / dmesg (AppArmor).

example-01: Auditing SELinux, AppArmor & AVC Denials 
getenforce           # Enforcing | Permissive | Disabled
aa-status            # Ubuntu AppArmor loaded & enforced profiles
sudo ausearch -m avc # Inspect blocked syscall/file denials

3. Splitting Root's Power with Linux Capabilities

Least Privilege Kernel

Traditional Unix gave UID 0 all-or-nothing god mode. Linux splits root privileges into ~40 discrete Capabilities (cap_net_bind_service to bind ports <1024, cap_net_raw for ping/tcpdump, cap_sys_admin). Grant only the exact capability needed via AmbientCapabilities=CAP_NET_BIND_SERVICE in systemd or setcap.

example-02: Inspecting Process Capabilities 
capsh --print   # View current & bounding capability sets

Real Outage Pattern: A setenforce 0 'Quick Fix' Left Production Unprotected for 14 Months

After moving Nginx's docroot to /data/web, an engineer hit permission errors and disabled SELinux instead of running semanage fcontext + restorecon -Rv /data/web. Learning to fix labels rather than turning off security is what separates Senior Engineers.

Interview Q1

What is the difference between DAC and MAC in Linux?

Model Answer: DAC (Discretionary Access Control: chmod/chown) lets file owners grant access arbitrarily and gives root full bypass. MAC (SELinux/AppArmor) enforces kernel-wide security policies over both processes and files—even restricting UID 0 processes.

Interview Q2

Why should you NEVER apply `chmod u+s` (setuid) to an interpreted script or Python binary?

Model Answer: The kernel ignores setuid on `#!` scripts for security, and making an interpreter like `python3` setuid root grants every local user instant root shell access.
