2. Bash vs Python Decision Rule & Safe subprocess.run

Engineering Judgment

Rule of thumb: under ~50 lines gluing simple CLI tools → Bash. Parsing JSON/YAML, HTTP APIs, complex math, retries, or >80 lines → Python 3. Always pass argument lists to subprocess.run([...], check=True) with shell=False (the default) instead of string interpolation with shell=True.

example-01: Safe Python CLI Snippet & Direct /proc Inspection 
python3 -c "import pathlib; print(pathlib.Path('/proc/uptime').read_text())"
cat /proc/uptime

3. Writing Operator-Ready Python CLIs (argparse, Structured JSON & Exit Codes)

Production Tooling

Production automation scripts executed by systemd timers or cron must distinguish data (stdout, e.g., JSON metrics) from diagnostics (stderr via Python logging) and return explicit exit codes (sys.exit(0) healthy, sys.exit(2) threshold breached) so callers alert cleanly.

example-02: Parsing /proc/meminfo Safely via Inline Python 
cat /proc/meminfo
python3 -c "import json, pathlib; print(json.dumps({'status':'ok'}))"

Real Outage Pattern: Shell Injection via os.system() on User-Supplied Filename

An internal build cleanup daemon used Python os.system(f'rm -rf /builds/{job_name}'). Someone passed a branch name containing a semicolon ;, turning the cleanup job into arbitrary code execution. Switching to shutil.rmtree and subprocess.run([...], shell=False) eliminated the whole class of bugs.

Interview Q1

How do you safely execute external Linux tools from Python without command injection?

Model Answer: Use subprocess.run([cmd, arg1, arg2], check=True) with shell=False (default), never string-interpolated os.system() or shell=True.

Interview Q2

Why shouldn't monitoring agents parse `top` or `ls -l` output in Python when `/proc` or `os.stat` exists?

Model Answer: Human-formatted CLI output changes across tool versions and locales; kernel files in /proc and os.statvfs()/os.stat() syscalls give stable machine interfaces.
