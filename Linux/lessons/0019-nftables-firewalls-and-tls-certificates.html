1. Android Developer → Linux Mental Bridge

Transferring Prior Knowledge

On Android you configure network_security_config.xml for TLS pinning and CAs. On Linux servers, you enforce L3/L4 host firewalling with Netfilter (nftables) and manage X.509 certificates + system CA trust under /etc/ssl.

2. Modern Host Firewalling with nftables & ufw

Packet Filtering

nftables replaced legacy iptables (ufw on Ubuntu is a friendly frontend over nftables/iptables). Every default-drop input chain needs three essentials: 1) accept loopback (iif "lo" accept), 2) accept return traffic (ct state established,related accept), and 3) explicitly allow SSH (tcp dport 22 accept) BEFORE setting policy drop so you don't lock yourself out!

example-01: Inspecting nftables Ruleset & ufw Status 
sudo nft list ruleset   # Canonical Netfilter kernel rules
sudo ufw status         # Simplified Ubuntu frontend view

3. Inspecting Certificates with openssl & Trusting Private CAs

TLS & PKI

Most Linux TLS outages fall into three buckets: expired cert, missing intermediate chain, or untrusted private CA. Check certificate metadata with openssl x509, never bypass errors with curl -k in production scripts, and install internal root CAs into /usr/local/share/ca-certificates/*.crt followed by update-ca-certificates.

example-02: Inspecting Certificate Dates & Subject 
openssl x509 -in /etc/ssl/certs/aegis.crt -noout -dates -subject

Real Outage Pattern: Forgot Loopback Accept Rule in nftables

A newly tightened firewall dropped local traffic on lo. Externally SSH worked fine, while Nginx → local backend 127.0.0.1:8443 hung for 60 seconds and returned 502 Bad Gateway! Always verify iif "lo" accept is rule #1.

Interview Q1

Why does `nftables` replace `iptables`, and how do you still recognize legacy rules?

Model Answer: nftables unifies IPv4/IPv6/ARP into one kernel VM with atomic table swaps and inline sets; legacy iptables had separate IPv4/IPv6 binaries (iptables/ip6tables) and non-atomic rule reloads.

Interview Q2

How do you inspect a remote server's live TLS certificate chain from CLI?

Model Answer: openssl s_client -connect host:443 -servername host </dev/null.

Local macOS Real-Kernel VM Companion

Run this in a real Linux VM

Inspect live Netfilter tables and live remote TLS X.509 certificate chains.

sudo nft list ruleset
openssl s_client -connect example.com:443 -servername example.com </dev/null 2>/dev/null | openssl x509 -noout -dates -ext subjectAltName
