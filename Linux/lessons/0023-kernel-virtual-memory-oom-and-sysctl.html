1. Android Developer → Linux Mental Bridge

Transferring Prior Knowledge

On Android, you know LMKD (Low Memory Killer Daemon) kills background apps by oom_score_adj before foreground apps die. Server Linux uses the exact same kernel OOM mechanism—plus aggressive RAM disk caching (Page Cache) that confuses beginners reading free.

Android LMKD & oom_score_adjKernel OOM Killer & /proc/<pid>/oom_score_adjSet OOMScoreAdjust=-900 in sshd.service/DB units so critical daemons survive!

2. Why 'Low Free RAM' Is Usually Healthy Linux Page Cache

Virtual Memory

Unused RAM is wasted RAM: Linux caches recent disk reads inside Page Cache (buff/cache). Always read the available column in free -h, NOT free. Watch si/so (swap in/out) in vmstat: non-zero swap allocation sitting idle is fine, while active continuous si/so thrashing destroys latency.

example-01: Inspecting Memory, Page Cache & sysctl Tunables 
free -h    # Look at 'available', not 'free'!
vmstat     # Check si/so (swap thrashing) and wa (I/O wait)
sysctl -a  # Inspect live kernel parameters in /proc/sys

3. Tuning sysctl & Protecting Services from OOM

Kernel Tuning

When physical RAM + swap runs dry, the kernel OOM Killer scores processes (/proc/<pid>/oom_score) and sends SIGKILL to the worst offender. Persist kernel parameters cleanly inside /etc/sysctl.d/99-custom.conf (e.g., vm.swappiness=10, net.core.somaxconn=8192) and apply via sysctl -w or sysctl --system.

example-02: Tuning Swappiness & Socket Backlog via sysctl 
sysctl vm.swappiness
sudo sysctl -w vm.swappiness=10
sudo sysctl -w net.core.somaxconn=8192

Real Outage Pattern: OOM Killer Killed `sshd` First Because App Workers Used cgroups Shielding

A runaway JVM container lacked a cgroup memory cap and pushed the host into OOM. Because sshd wasn't protected and the JVM had spawned dozens of smaller helpers, the kernel killed sshd—leaving the host alive as a black box nobody could SSH into to recover!

Interview Q1

Explain why Linux shows very little 'free' memory even when an application only uses 2 GB of a 32 GB server.

Model Answer: Linux borrows unused RAM for disk Page Cache (buff/cache) to speed up file I/O and frees it instantly on allocation. The true free headroom metric is MemAvailable.

Interview Q2

What is the difference between `VSZ` and `RSS`?

Model Answer: VSZ is total virtual memory mapped/reserved (including untouched pages and shared libs); RSS is the physical RAM frames actually resident for that process.
