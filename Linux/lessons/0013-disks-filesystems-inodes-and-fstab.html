1. Android Developer → Linux Mental Bridge

Transferring Prior Knowledge

On Android devices, partitions like /system, /vendor, and /data (ext4 or F2FS) are flashed via fastboot and mounted by init. On Linux servers, you partition NVMe/virtio disks, format them, and persist mounts in /etc/fstab.

2. Inspecting Block Devices (lsblk), Blocks (df -h) & Inodes (df -i)

Storage Inventory

lsblk shows physical disks, partitions, and LVM layers in one tree. Remember the critical split: df -h measures filesystem block space, df -i measures inode table exhaustion, and du -sh * sums directory trees on disk.

example-01: Checking Block Layout, Space & Inodes 
lsblk     # Physical disks -> partitions -> LVM -> mountpoints
df -h     # Human-readable block usage
df -i     # Inode usage (100% IUse% = ENOSPC even with free GB!)
free -h   # RAM + Swap usage

3. Crash-Safe /etc/fstab Using UUID & nofail

Persistent Mounts

Never write raw /dev/sdb1 in /etc/fstab—adding another disk can shift sdb to sdc and brick boot! Always use UUID= (from blkid or lsblk -f), add nofail for non-root data disks, and ALWAYS run sudo mount -a before rebooting to validate syntax.

example-02: Inspecting /etc/fstab & Active Mounts 
cat /etc/fstab
mount
Golden Rule Before Any Reboot
After editing /etc/fstab, always run sudo mount -a. A single typo in /etc/fstab drops the server into emergency single-user rescue mode on next boot!

Real Outage Pattern: Typo in /etc/fstab Bricked a Cloud VM on Reboot

An engineer edited /etc/fstab manually to mount a new NVMe volume, misspelled defaults as defualts, and didn't test with sudo mount -a. Two months later a kernel patch reboot dropped the VM into emergency shell—taking production offline until a console serial session fixed the typo.

Interview Q1

If `df -h` shows 100% used on `/`, how do you quickly locate which directory is consuming the space?

Model Answer: Run du -xhd 1 / (or du -sh /* 2>/dev/null | sort -h) using -x so you stay on the root filesystem without crossing into /proc, /sys, or separate mounts.

Interview Q2

What are the 6 columns of an `/etc/fstab` line?

Model Answer: Device/UUID, Mount point, Filesystem type, Mount options, Dump flag (0), and fsck pass order (1 for root, 2 for others, 0 to skip).
