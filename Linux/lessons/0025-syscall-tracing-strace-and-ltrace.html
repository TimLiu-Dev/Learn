1. Android Developer → Linux Mental Bridge

Transferring Prior Knowledge

On Android you have full Logcat stack traces and Android Studio's debugger. On Linux servers, third-party vendor binaries often crash printing nothing useful—strace is your X-ray vision showing the exact file path or socket call that failed inside the kernel!

2. Pinpointing ENOENT & EACCES with strace

Syscall X-Ray

Raw strace ./bin prints thousands of startup loader lines. Filter with -e trace=file (or -e trace=network), follow forked workers with -f, attach to live PIDs with -p <pid>, and add timestamps/durations with -tt -T. Note: strace uses ptrace and adds significant overhead—never leave it attached continuously on high-QPS production traffic (use eBPF in Lesson 0026 for zero-overhead live tracing!).

example-01: Catching Missing Config Path via strace & Env Check via ltrace 
strace -f -e trace=file /usr/local/bin/aegis-api
ltrace /usr/local/bin/aegis-api

Recommended Primary Source

Real Outage Pattern: Closed-Source Agent Ignored `HTTP_PROXY` Because of Hardcoded DNS

A proprietary monitoring agent failed silently on an air-gapped node. Running strace -f -e trace=network ./agent showed it trying direct connect() to an external IP instead of reading proxy env vars—solved in 30 seconds without source code.

Interview Q1

Why does `strace` add heavy overhead, and what modern Linux technology replaces it in high-throughput production?

Model Answer: strace uses ptrace, context-switching twice per syscall. Modern Linux uses in-kernel eBPF (bpftrace/bcc) to aggregate syscall latencies inside the kernel with near-zero overhead.

Interview Q2

How do you identify which syscall a seemingly frozen process is stuck on?

Model Answer: Run strace -p <pid> (or read /proc/<pid>/syscall and /proc/<pid>/stack without attaching ptrace!).
