1. Master Legend: How Every Lesson Works

Standard Benchmark Format

Difficulty & Capability Tiers

Each lesson card carries a tier badge showing what level of engineering autonomy it builds:

  • Tier 1: Foundations — Core CLI fluency, shell mental models, Vim/tmux, navigation, streams, and regex/awk forensics.
  • Tier 2: Systems Core — Users/PAM, permissions/ACLs, processes, `systemd`, timers/`chrony`, packages, disks, hardware/modules, and boot rescue.
  • Tier 3: Production Ops — `iproute2`/DNS, SSH bastions, `nftables`, TLS/PKI, `tcpdump`/WireGuard, strict Bash, and Python `/proc` tooling.
  • Tier 4: Senior Mastery — Kernel VM/OOM, SELinux/Auditd, `strace`, `perf`/eBPF, containers from scratch, KVM/`cloud-init`, Ansible HA, and war games.
  • Tier 5: Capstone — Full-stack multi-node production platform built, automated, monitored, chaos-tested, and ready for your resume.

Anatomy of Every Benchmark Lesson

Every lesson HTML file follows the pedagogical standard in Lesson 0001:

  1. Tightly Scoped Win: 1–2 concrete skills per lesson (~20–35 min) with spaced retrieval warmups from earlier lessons.
  2. Android → Linux Bridge: Maps `adb shell`, Zygote, Binder, SELinux, and `LMKD` directly to GNU/Linux servers.
  3. Runnable Examples & Sandbox: Every command block runs inline or inside the live browser shell.
  4. Isolated Practice Labs: Automated assertions (Check Solution), progressive Hints, and Show/Run Final Answer.
  5. Balanced Diagnostic Quizzes: Equal-length choices explaining why the right option works AND why each wrong option fails.
  6. Primary Sources & Reference Cards: Links to official docs (`man7.org`, `FHS 3.0`, `systemd.io`, `docs.kernel.org`) and printable cheat sheets in `./reference/`.
Workspace State Files (Teaching System)
Your learning state lives cleanly alongside the lessons: MISSION.md (your 2027 career target), RESOURCES.md (verified docs & communities like r/linuxadmin and unix.stackexchange.com), NOTES.md (preferences), learning-records/ (what you have mastered), and reference/glossary.html + reference/0001-navigation-fhs-cheatsheet.html.

Resume & Job-Ready Proof

Project Brief: Production Self-Healing Linux Application & Observability Platform

Your final project builds a reproducible, zero-trust, self-healing 3-node Linux infrastructure (Bastion Host + App Server + Observability/Backup Node) running an Android crash-telemetry ingestion API — bridging your mobile past directly into backend Linux systems engineering.

Technical Components You Will Engineer

  • Immutable Provisioning: Ansible playbooks + `cloud-init` bootstrapping hardened Ubuntu/RHEL KVM VMs with zero manual setup.
  • Defense-in-Depth Security: SSH Ed25519 + `ProxyJump` bastion, `nftables` stateful firewall, Fail2Ban, PAM limits, TLS/PKI automation, and enforcing SELinux/AppArmor profiles.
  • Storage & Disaster Recovery: LVM thin-provisioned `/var/lib/aegis` volume with automated `systemd` timer snapshots, encrypted off-node backups, and tested restore drills.
  • Service Isolation: Custom `systemd` unit with `cgroups v2` quotas (`MemoryMax`, `CPUQuota`, `ProtectSystem=strict`), watchdog restart, and Nginx TLS reverse proxy.
  • Observability & Chaos Verification: `journald` logs, Prometheus Node Exporter, `bpftrace`/eBPF latency probes, and fault-injection chaos drills (disk/inode fill, port conflict, OOM stress, dropped packets) with SRE postmortems.

Resume Bullets This Capstone Earns You

  • “Architected and automated a 3-node hardened Linux platform (Ansible, systemd, nftables, SELinux/AppArmor, TLS) with zero-trust SSH bastion access and automated CIS compliance checks.”
  • “Engineered LVM thin-snapshot backup/restore pipelines and cgroups v2 isolation, reducing simulated OOM and disk-exhaustion MTTR to under 90 seconds.”
  • “Diagnosed kernel, TCP/IP, and syscall bottlenecks using eBPF/bpftrace, perf, strace, ss, lsof, and tcpdump under simulated production chaos drills.”
End-to-End Verification Gate
To graduate the Capstone, a fresh VM must pass an automated bats / pytest verification suite checking open ports, firewall drops, SELinux/AppArmor mode, TLS chain validity, backup restore integrity, and auto-recovery after `kill -9`.
