Part 2 Capstone (1/3): IaC VPC, PrivateLink, KMS, Cognito & Edge Security

Before launching a single ECS Fargate container or Aurora database in Lesson 0049, a senior cloud engineer hardens the perimeter in zero-ClickOps Infrastructure as Code: Route 53, CloudFront + WAFv2, Cognito OIDC + PKCE, a 3-tier Multi-AZ VPC, PrivateLink endpoints, and customer-managed KMS keys.

Your Android Bridge

In Android, your client security story starts with AppAuth / Credential Manager running an OIDC Authorization Code + PKCE sign-in, an OkHttpClient talking TLS 1.3 to https://api.saas-app.com, and direct pre-signed uploads to https://cdn.saas-app.com. On AWS, everything on the server side of that TLS socket—edge DDoS/WAF filtering, origin lock-down, private network isolation, envelope encryption, and JWT key verification—must be wired cleanly in CDK or Terraform before any application code runs.

1. Mobile Edge Perimeter: Route 53, CloudFront, WAFv2 & Origin Lock-Down

Every mobile API and media request enters through Amazon Route 53 Alias records (A and AAAA) pointing to an Amazon CloudFront distribution. Terminating TLS 1.3 at one of CloudFront's 400+ global edge PoPs drops handshake latency dramatically on high-RTT cellular networks (often saving 60–150 ms per cold connection compared to terminating TLS directly in us-east-1).

Three production rules prevent the classic edge misconfigurations that break deployments or leave origins exposed:

  1. The us-east-1 Control-Plane Rule: CloudFront is a global service whose ACM TLS certificates and CLOUDFRONT-scoped AWS WAFv2 web ACLs must be provisioned in us-east-1, even if your VPC, ALB, and ECS tasks run in us-west-2 or eu-central-1. Your origin ALB still needs its own regional ACM certificate in the VPC's region for end-to-end TLS encryption between CloudFront and the ALB.
  2. Preventing Direct-to-ALB WAF Bypass: If your ALB sits in public subnets with a public DNS name (*.elb.amazonaws.com), attackers can bypass CloudFront and WAFv2 by connecting directly to the ALB. Lock down the ALB Security Group inbound rules to the AWS-managed prefix list com.amazonaws.global.cloudfront.origin-facing and configure CloudFront to inject a rotated secret custom header (e.g., X-Origin-Verify) validated by an ALB listener rule (returning fixed HTTP 403 if missing or mismatched).
  3. S3 Origin Access Control (OAC) + SSE-KMS: Never make an S3 media bucket public or rely on legacy Origin Access Identity (OAI). Use CloudFront OAC, which signs origin requests with SigV4 and supports SSE-KMS encrypted buckets—provided your KMS key policy also authorizes CloudFront (Section 3).

2. Multi-AZ VPC Topology, NAT Blast Radius & PrivateLink Economics

Inside our regional VPC (10.20.0.0/16, 65,536 IPv4 addresses across 3 Availability Zones), subnet sizing and routing enforce strict blast-radius isolation:

  • Public Subnets (/24 × 3, 251 usable AWS IPs each): Route 0.0.0.0/0 → igw. Host only the internet-facing ALB and one NAT Gateway per AZ. Never share a single NAT Gateway across 3 AZs in production: if that AZ experiences an impairment, tasks in the other two healthy AZs lose internet egress simultaneously, and cross-AZ NAT traffic pays an extra $0.01/GB in each direction.
  • Private App Subnets (/22 × 3, 1,019 usable IPs each): Route 0.0.0.0/0 → local-AZ NAT Gateway. Generous /22 blocks prevent IP exhaustion when ECS Fargate tasks or Lambda ENIs scale rapidly during traffic spikes or blue/green deployments.
  • Isolated Data Subnets (/24 × 3): Route table contains only the local VPC CIDR (10.20.0.0/16 → local) plus Gateway Endpoints if needed—zero route to any IGW or NAT Gateway. Even a compromised database process cannot exfiltrate data to an arbitrary internet host.

3. KMS Customer-Managed Keys, OAC Policies & Cognito OIDC PKCE

Encrypting S3 buckets, Secrets Manager secrets, CloudWatch log groups, and future Aurora/DynamoDB tables with an AWS KMS Customer-Managed Key (CMK) gives you centralized revocation, CloudTrail auditability, and automatic 365-day backing key rotation (enableKeyRotation: true). Old key material stays retained inside KMS automatically so older ciphertexts remain decryptable without re-encrypting petabytes of historical data.

The CloudFront OAC + SSE-KMS 403 Trap

Adding an S3 bucket policy for CloudFront OAC is not enough when the bucket uses SSE-KMS. CloudFront fetches the encrypted object on the user's behalf, so the KMS Key Policy must explicitly grant cloudfront.amazonaws.com actions kms:Decrypt, kms:Encrypt, and kms:GenerateDataKey* conditioned on AWS:SourceArn matching your exact distribution ARN—otherwise CloudFront fails with 403 AccessDenied.

For high-throughput services, always rely on envelope encryption (KMS generates a 256-bit AES Data Encryption Key, returning both plaintext and encrypted DEK; the service encrypts payloads locally and caches/stores the wrapped DEK). Calling KMS directly per payload hits regional API quotas and costs $0.03 per 10,000 requests.

Mobile Auth: Amazon Cognito OIDC + PKCE Rules

Your Android app authenticates users via Chrome Custom Tabs (AppAuth) against a Cognito User Pool using Authorization Code Flow with PKCE (S256):

  • No Client Secret in APKs: Configure the mobile app client as a public OAuth client (generateSecret: false). Any secret compiled into an APK or Gradle config can be extracted in seconds via jadx.
  • Short-Lived Access Tokens: Issue 15–60 minute access tokens and revocable refresh tokens (e.g., 30 days). Keep user attributes lean so JWTs stay well under header limits.
  • Strict Server/Edge JWT Verification: Validate RS256 signatures against the User Pool's /.well-known/jwks.json, verify iss matches https://cognito-idp.<region>.amazonaws.com/<poolId>, check client_id / aud and token_use, and explicitly reject alg: "none" or symmetric HS256 algorithm-confusion attacks.

4. Production IaC Blueprint (AWS CDK TypeScript)

Below is the core CDK stack establishing the zero-ClickOps foundation: 3-tier Multi-AZ VPC, Gateway & Interface endpoints, KMS CMK with OAC policy, CloudFront + WAFv2 + Origin Verify lock-down, and Cognito public mobile OIDC client. 

// infra/lib/capstone-foundation-stack.ts (AWS CDK TypeScript — zero ClickOps)
const vpc = new ec2.Vpc(this, "SaasVpc", {
  ipAddresses: ec2.IpAddresses.cidr("10.20.0.0/16"),
  maxAzs: 3,
  natGateways: 3, // 1 NAT per AZ for AZ independence (no cross-AZ NAT surcharge)
  subnetConfiguration: [
    { name: "Public",       subnetType: ec2.SubnetType.PUBLIC,             cidrMask: 24 },
    { name: "PrivateApp",   subnetType: ec2.SubnetType.PRIVATE_WITH_EGRESS, cidrMask: 22 },
    { name: "IsolatedData", subnetType: ec2.SubnetType.PRIVATE_ISOLATED,    cidrMask: 24 },
  ],
});

// Free Gateway Endpoints for S3 (also required by ECR layers) and DynamoDB
vpc.addGatewayEndpoint("S3Gateway",       { service: ec2.GatewayVpcEndpointAwsService.S3 });
vpc.addGatewayEndpoint("DynamoGateway",   { service: ec2.GatewayVpcEndpointAwsService.DYNAMODB });

// PrivateLink Interface Endpoints with Private DNS enabled
for (const svc of [
  ec2.InterfaceVpcEndpointAwsService.KMS,
  ec2.InterfaceVpcEndpointAwsService.SECRETS_MANAGER,
  ec2.InterfaceVpcEndpointAwsService.ECR,
  ec2.InterfaceVpcEndpointAwsService.ECR_DOCKER,
  ec2.InterfaceVpcEndpointAwsService.CLOUDWATCH_LOGS,
]) {
  vpc.addInterfaceEndpoint(`Vpce-${svc.shortName}`, { service: svc, privateDnsEnabled: true });
}

// Customer-Managed KMS Key with annual rotation + scoped CloudFront OAC permission
const dataKey = new kms.Key(this, "PlatformCmk", {
  enableKeyRotation: true, // 365-day automatic rotation
  removalPolicy: RemovalPolicy.RETAIN,
});

dataKey.addToResourcePolicy(new iam.PolicyStatement({
  principals: [new iam.ServicePrincipal("cloudfront.amazonaws.com")],
  actions: ["kms:Decrypt", "kms:Encrypt", "kms:GenerateDataKey*"],
  resources: ["*"],
  conditions: { StringEquals: { "AWS:SourceArn": distributionArn } },
}));

// Cognito User Pool Public Mobile Client (PKCE S256, NO client secret in APK)
const mobileClient = userPool.addClient("AndroidMobileClient", {
  generateSecret: false,
  accessTokenValidity: Duration.minutes(30),
  enableTokenRevocation: true,
  oAuth: {
    flows: { authorizationCodeGrant: true }, // Enforces PKCE for public clients
    scopes: [cognito.OAuthScope.OPENID, cognito.OAuthScope.EMAIL],
  },
});
