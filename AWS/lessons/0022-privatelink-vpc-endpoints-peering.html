PrivateLink, Gateway vs. Interface VPC Endpoints & VPC Peering

Putting compute inside a private subnet does not automatically make its traffic to AWS services private or cheap. Without VPC Endpoints, every S3 upload and SQS poll detours through your NAT Gateway at $0.045/GB—a silent cloud tax you can cut by 78% to 100% once you know how Gateway Endpoints, AWS PrivateLink, and non-transitive VPC Peering actually route packets.

Your Android Bridge

Think about how an enterprise Android app or internal QA build reaches a staging backend. On the public internet, packets traverse carrier NATs and public IPs—exposing endpoints to the open web and metering mobile data. With a private corporate VPN (WireGuard or IPsec), traffic stays inside private RFC 1918 tunnels (10.x.x.x) and never touches public routing tables. In AWS, private subnets without endpoints behave like an app accidentally routing internal calls over public 5G instead of the VPN: traffic hits the NAT Gateway and pays $0.045/GB to reach public AWS endpoints like s3.us-east-1.amazonaws.com. Gateway Endpoints, Interface Endpoints (PrivateLink), and VPC Peering keep your packets on private AWS paths.

1. The Hidden NAT Gateway Tax on Private Subnets

Suppose your ECS Fargate tasks sit in private subnets across 2 Availability Zones (10.0.10.0/24 and 10.0.11.0/24). Their route table sends 10.0.0.0/16 → local and 0.0.0.0/0 → nat-0abc... (your NAT Gateway).

When a container calls the AWS SDK to read 50 TB/month from Amazon S3 or query DynamoDB, what happens on the wire?

  1. DNS resolves s3.us-east-1.amazonaws.com to a public AWS IP (e.g., 52.216.x.x).
  2. Because 52.216.x.x is outside 10.0.0.0/16, the subnet route table matches 0.0.0.0/0 and forwards every packet through your NAT Gateway.
  3. Even though AWS keeps the physical bytes on its internal backbone between your VPC and S3, the Amazon VPC NAT Gateway meter still charges $0.045/GB in data processing plus $0.045/hour per AZ (~$32.85/month per 730-hour AZ).

For 50 TB/month (50,000 GB), that single missing route table entry costs 50,000 × $0.045 = $2,250/month in pure NAT Gateway processing fees—before you even pay for S3 requests or storage.

2. Gateway Endpoints vs. Interface Endpoints (AWS PrivateLink)

AWS provides two fundamentally different mechanisms under the "VPC Endpoint" umbrella. Mixing them up causes either unexpected monthly bills or broken cross-network architecture.

Dimension Gateway VPC Endpoint Interface VPC Endpoint (PrivateLink)
Supported Services Amazon S3 and DynamoDB only. 100+ AWS services (SQS, KMS, Secrets Manager, ECR, STS, S3 too) + custom NLB services + SaaS partners.
Network Mechanism Injects a managed prefix list (pl-xxxxxxx → vpce-xxx) into selected VPC route tables. Provisions an Elastic Network Interface (ENI) with a private 10.x.x.x IP inside your subnet(s).
DNS Resolution Service still resolves to its public IP; the route table intercepts that prefix before the NAT Gateway. With Private DNS enabled, sqs.us-east-1.amazonaws.com resolves directly to your ENI's private IP.
Cost (us-east-1) $0.00/hour and $0.00/GB (completely free). $0.01/AZ/hour ($7.30/mo per 730h AZ) + $0.01/GB processed (first 1 PB/mo).
Security Control Route table association + VPC Endpoint IAM Policy (no Security Groups). ENI Security Group (must allow inbound TCP 443) + VPC Endpoint IAM Policy.
On-Prem / Peered Reachability No. Route-table scoped to the local VPC only. Yes. Reachable over Direct Connect, Site-to-Site VPN, VPC Peering, or Transit Gateway via private IP.
Figure 1: Gateway Endpoints rewrite VPC routing for S3 and DynamoDB at $0. Interface Endpoints drop private ENIs into your subnets for 100+ AWS services and custom PrivateLink providers.
Four Production Traps with VPC Endpoints
  • The aws:SourceIp S3 Bucket Policy Trap: If an S3 bucket policy restricts access to your NAT Gateway's public Elastic IP via aws:SourceIp, attaching an S3 Gateway Endpoint immediately breaks your app with 403 AccessDenied! Gateway Endpoint traffic bypasses NAT and does not carry your NAT EIP—you must switch the bucket policy condition to aws:SourceVpce or aws:SourceVpc.
  • Low-Volume Interface Endpoint Overspend: Across 2 AZs, one Interface Endpoint costs 2 × 730 × $0.01 = $14.60/month fixed before sending a single byte. Break-even vs. an already-running NAT Gateway ($0.045/GB vs. $0.01/GB) is $14.60 / $0.035 ≈ 417 GB/month. Below 417 GB/mo, Interface Endpoints cost more than NAT unless compliance mandates zero public-endpoint routing.
  • Missing VPC DNS Settings: Interface Endpoint Private DNS requires both enableDnsSupport = true and enableDnsHostnames = true on the VPC. If either is disabled, AWS rejects Private DNS creation or workloads still resolve public IPs.
  • S3 Interface vs. Gateway Coexistence: S3 also offers an Interface Endpoint ($0.01/AZ/hr + $0.01/GB) specifically so on-premises hosts over Direct Connect/VPN can hit S3 via private IP. Never route in-VPC EC2/ECS S3 traffic to an S3 Interface Endpoint when a free S3 Gateway Endpoint works!

3. VPC Peering & The Non-Transitivity Rule

When your own microservices live across separate VPCs (e.g., VPC-App and VPC-Data), VPC Peering creates a direct 1:1 Layer-3 route (pcx-xxxxxxx) with no single point of failure and no bandwidth bottleneck. Same-AZ peered traffic is $0.00/GB; cross-AZ traffic (same or different VPC) is $0.01/GB each direction.

However, VPC Peering has three strict architectural rules that catch senior engineers migrating from traditional corporate networks:

  1. No Overlapping CIDRs: You cannot peer 10.0.0.0/16 with 10.0.0.0/16 or any overlapping sub-range. Plan non-overlapping IP blocks early.
  2. Strictly Non-Transitive Routing: If VPC-A peers with VPC-B, and VPC-B peers with VPC-C, VPC-A cannot route to VPC-C through VPC-B. Connecting N VPCs requires N(N - 1)/2 peering links (10 VPCs = 45 peering connections!).
  3. No Edge-to-Edge Routing: VPC-A cannot borrow VPC-B's Internet Gateway, NAT Gateway, Direct Connect, Site-to-Site VPN, or S3/DynamoDB Gateway Endpoint.
Figure 2: VPC Peering permits direct A↔B and B↔C traffic, but forbids A→C transit and forbids edge-to-edge reuse of VPC-B's Direct Connect or Gateway Endpoints.

When does PrivateLink beat VPC Peering? Suppose you expose an internal payment API or multi-tenant SaaS service to 20 consumer VPCs—some of which share the exact same 10.0.0.0/16 CIDR! VPC Peering fails immediately on CIDR overlap and exposes entire subnets at Layer 3. With an AWS PrivateLink Endpoint Service, you front your service with a Network Load Balancer (NLB); each consumer creates an Interface Endpoint ENI in their own VPC's CIDR, giving one-way client-initiated TCP access with zero CIDR conflict.

4. Production Code Example: Terraform Endpoints & S3 aws:SourceVpce Policy

Below is a production Terraform pattern pairing a free S3 Gateway Endpoint, an SQS Interface Endpoint with Private DNS, and an S3 Bucket Policy that enforces private VPC-only access using aws:SourceVpce instead of fragile public IPs: 

# 1. Free S3 Gateway Endpoint ($0/hr, $0/GB) — attaches to private route tables
resource "aws_vpc_endpoint" "s3_gateway" {
  vpc_id            = aws_vpc.main.id
  service_name      = "com.amazonaws.us-east-1.s3"
  vpc_endpoint_type = "Gateway"
  route_table_ids   = aws_route_table.private[*].id
}

# 2. SQS Interface Endpoint (PrivateLink: $0.01/AZ/hr + $0.01/GB)
resource "aws_vpc_endpoint" "sqs_interface" {
  vpc_id              = aws_vpc.main.id
  service_name        = "com.amazonaws.us-east-1.sqs"
  vpc_endpoint_type   = "Interface"
  subnet_ids          = aws_subnet.private[*].id   # Match workload AZs to avoid cross-AZ fees
  security_group_ids  = [aws_security_group.vpce_https.id] # Allows TCP 443 from app SG
  private_dns_enabled = true                       # Requires enableDnsSupport & enableDnsHostnames
}

# 3. Lock S3 bucket strictly to our Gateway Endpoint (NEVER use aws:SourceIp with Gateway EPs)
data "aws_iam_policy_document" "s3_vpce_only" {
  statement {
    sid       = "DenyAccessOutsideApprovedVpce"
    effect    = "Deny"
    principals { type = "*", identifiers = ["*"] }
    actions   = ["s3:*"]
    resources = [aws_s3_bucket.data.arn, "${aws_s3_bucket.data.arn}/*"]
    condition {
      test     = "StringNotEquals"
      variable = "aws:SourceVpce"
      values   = [aws_vpc_endpoint.s3_gateway.id]
    }
  }
}
