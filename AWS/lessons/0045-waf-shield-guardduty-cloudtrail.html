Edge & Account Defense: AWS WAF, Shield, GuardDuty, CloudTrail & Security Hub

Client attestation tells you an app binary is genuine; it does not stop attackers from hitting your public endpoints directly, overwhelming your origin with floods, or abusing leaked IAM credentials inside your AWS account. Learn how AWS splits defense across the Edge Plane (Shield + WAF) and the Control & Audit Plane (CloudTrail + GuardDuty + Security Hub).

Your Android Bridge

On Android, you integrate the Play Integrity API (replacing deprecated SafetyNet Attestation) so Google Play signs a verdict confirming your APK is untampered and running on a genuine device (MEETS_DEVICE_INTEGRITY). Yet attackers still bypass the app entirely—replaying captured tokens with curl, hammering unauthenticated /login endpoints from botnets, or probing leaked IAM keys directly against AWS APIs. On AWS, AWS Shield and AWS WAF guard your HTTP edge against volumetric and Layer-7 abuse, while CloudTrail, Amazon GuardDuty, and AWS Security Hub form the immutable account flight recorder and continuous threat engine behind it.

1. Edge Defense: AWS Shield (L3/L4) & AWS WAF (L7)

Edge defense separates volumetric network floods from malicious HTTP payloads before traffic reaches your ECS tasks, Lambda functions, or RDS databases.

  • AWS Shield Standard (Automatic, $0): Always enabled on CloudFront, Route 53, and ALBs at no extra cost. It mitigates common Layer 3/4 attacks—SYN floods, UDP reflection, and DNS amplification—inline at AWS edge POPs.
  • AWS Shield Advanced ($3,000/month, 1-year commit): Adds 24/7 access to the AWS Shield Response Team (SRT), automatic Layer-7 health-based WAF rate mitigation, and DDoS cost protection (service credits if an attack spikes your CloudFront, ALB, or WAF bills). Most startups rely on Shield Standard + CloudFront + WAF until compliance or sustained extortion threats justify Advanced.
  • AWS WAF (Layer 7 Inspection): Attaches to CloudFront (global scope, managed in us-east-1) or regional resources (ALB, API Gateway, AppSync, Cognito User Pools, Verified Access).

Every AWS WAF Web ACL evaluates rules strictly in ascending numeric Priority order (lowest integer runs first). Understanding rule actions and capacity limits prevents self-inflicted outages:

  1. Terminating vs. Non-Terminating Actions: Allow, Block, and unsolved CAPTCHA/Challenge actions terminate evaluation immediately—later rules never run. Count is non-terminating: it increments CloudWatch metrics, attaches metadata labels, and lets evaluation continue to the next rule.
  2. Web ACL Capacity Units (WCUs): Each Web ACL gets 1,500 WCUs by default (increasable up to 5,000 WCUs with additional cost above 1,500). Managed rule groups consume fixed budgets—for example, AWSManagedRulesCommonRuleSet consumes 700 WCUs and AWSManagedRulesSQLiRuleSet consumes 200 WCUs.
  3. Rate-Based Rules & CGNAT Trap: Rate-based rules count matching requests over a sliding 5-minute default window (configurable across 1, 2, 5, or 10 minutes), with a minimum threshold of 10 requests. Aggregating purely by source IP blocks thousands of legitimate Android users sharing one mobile carrier CGNAT gateway. Scope out /health and static paths at higher priority (lower number), or aggregate on a custom key (such as an authenticated user/device header combined with IP).
  4. Body Inspection Limit (16 KB Default): On CloudFront and ALB, WAF inspects only the first 16 KB of an HTTP request body by default (configurable up to 64 KB for an extra fee). If you leave OversizeHandling set to CONTINUE, an attacker can pad a JSON body with 17 KB of whitespace before injecting a SQLi payload—bypassing inspection unless you enforce OversizeHandling: MATCH or reject oversized payloads at the edge.
Production Rule: Always Bake New WAF Rules in Count Mode First

Managed SQLi and XSS rules routinely flag legitimate rich-text comments, GraphQL queries, or JSON payloads containing words like SELECT ... FROM or --. Deploy every new managed rule group with an override to Count for 24–72 hours, inspect sampled WAF logs in CloudWatch/S3, add scoped exclusions for false positives, and only then flip to Block.

2. Account Flight Recorder: CloudTrail, S3 Immutability & CloudTrail Lake

WAF only sees HTTP traffic hitting your edge endpoints. If an attacker steals an EC2 IAM role via SSRF or compromises a developer's access key, they call sts.amazonaws.com, iam.amazonaws.com, and s3.amazonaws.com directly—never touching your ALB or WAF.

AWS CloudTrail records every AWS control-plane API call (Management Events like CreateAccessKey, PutUserPolicy, RunInstances) and optionally data-plane operations (Data Events like s3:GetObject, dynamodb:PutItem, lambda:InvokeFunction). While the built-in 90-day Event History is free for single-region management events, production security requires three hardening layers:

  • Multi-Region Organization Trail into a Central Log Archive Account: Workload accounts must never own or be able to modify the trail. An Organization trail managed from the security/management account ensures member-account admins cannot run cloudtrail:StopLogging or cloudtrail:DeleteTrail.
  • Log File Integrity Validation: Enabling CloudTrail log file integrity validation emits hourly digest files signed with RSA-2048 containing SHA-256 hashes of every delivered log file. Any post-delivery edit breaks verification immediately.
  • S3 Object Lock (WORM) in Compliance Mode + KMS CMK: Even if an attacker obtains full AdministratorAccess—or even the root user—in the Log Archive account, S3 Object Lock Compliance Mode enforces Write-Once-Read-Many retention so logs cannot be deleted or overwritten before the retention date expires.

CloudTrail Lake vs. S3 + Athena: Instead of managing Glue crawlers and Athena date partitions over raw gzipped JSON files during an active breach, CloudTrail Lake stores events in an immutable, managed event data store (retained up to 7 years by default, or 10 years maximum) that you query directly with standard SQL.

3. Continuous Threat Detection & Triage: GuardDuty & Security Hub

Raw CloudTrail logs tell you what happened; Amazon GuardDuty tells you what looks malicious right now. GuardDuty operates agentlessly out of band, consuming three foundational AWS telemetry streams directly from AWS infrastructure without adding to your own VPC Flow Log or CloudTrail S3 storage bills:

  1. CloudTrail Management & S3 Data Events (catches unusual IAM reconnaissance, StopLogging attempts, or public bucket exposure).
  2. VPC Flow Logs (catches port scans, SSH brute force, and traffic to known command-and-control IPs).
  3. Route 53 DNS Query Logs (catches DNS tunneling data exfiltration and lookups to cryptocurrency mining pools like CryptoCurrency:EC2/BitcoinTool.B!DNS).

GuardDuty assigns every finding a normalized severity score: Low (0.1–3.9), Medium (4.0–6.9), High (7.0–8.9), and Critical (9.0–10.0). One of the highest-signal findings in modern cloud backends is UnauthorizedAccess:IAMUser/InstanceCredentialExfiltration.OutsideAWS—triggered the moment temporary STS credentials issued to an EC2 or ECS task role (:assumed-role/...) are used from an external IP address outside AWS.

AWS Security Hub sits above GuardDuty, Inspector, Macie, IAM Access Analyzer, and AWS Config. It normalizes findings into the standardized AWS Security Finding Format (ASFF), scores posture against benchmarks (AWS Foundational Security Best Practices, CIS), and emits events to Amazon EventBridge so you can page on-call engineers or trigger automated containment (e.g., attaching a deny-all quarantine policy) on High/Critical alerts.

4. Production Code: Terraform WAFv2 + CloudTrail Lake Hunt Query

Below is a realistic Terraform snippet declaring a priority-ordered WAFv2 Web ACL (with /health exempted before rate limiting, a 5-minute CGNAT-safe rate rule, and a count-mode SQLi bake-in) alongside a CloudTrail Lake SQL hunt query for privilege escalation and audit tampering: 

# 1. Terraform: Priority-Ordered AWS WAFv2 Web ACL (Regional ALB)
resource "aws_wafv2_web_acl" "api_edge" {
  name  = "prod-api-edge-acl"
  scope = "REGIONAL"

  default_action { allow {} }

  # Priority 10: Allow health probes BEFORE rate limiting (terminates on match)
  rule {
    name     = "allow-health-checks"
    priority = 10
    action { allow {} }
    statement {
      byte_match_statement {
        positional_constraint = "STARTS_WITH"
        search_string         = "/api/v1/health"
        field_to_match { uri_path {} }
        text_transformation { priority = 0, type = "NONE" }
      }
    }
    visibility_config { cloudwatch_metrics_enabled = true, metric_name = "AllowHealth", sampled_requests_enabled = true }
  }

  # Priority 20: Rate limit per X-Device-Id header + IP to avoid blocking mobile CGNAT
  rule {
    name     = "rate-limit-login"
    priority = 20
    action { block {} }
    statement {
      rate_based_statement {
        limit              = 100
        evaluation_window_sec = 300 # 5-minute sliding window
        aggregate_key_type = "CUSTOM_KEYS"
        custom_key { header { name = "x-device-id", text_transformation { priority = 0, type = "LOWERCASE" } } }
        custom_key { forwarded_ip {} }
      }
    }
    visibility_config { cloudwatch_metrics_enabled = true, metric_name = "RateLimitLogin", sampled_requests_enabled = true }
  }

  # Priority 30: Bake AWSManagedRulesSQLiRuleSet in COUNT mode before flipping to NONE (Block)
  rule {
    name     = "aws-managed-sqli"
    priority = 30
    override_action { count {} }
    statement {
      managed_rule_group_statement {
        vendor_name = "AWS"
        name        = "AWSManagedRulesSQLiRuleSet"
      }
    }
    visibility_config { cloudwatch_metrics_enabled = true, metric_name = "ManagedSQLi", sampled_requests_enabled = true }
  }

  visibility_config { cloudwatch_metrics_enabled = true, metric_name = "ApiEdgeAcl", sampled_requests_enabled = true }
}

-- 2. CloudTrail Lake SQL: Hunt Audit Tampering & Un-MFA'd IAM Escalation
SELECT eventTime, eventName, userIdentity.arn, sourceIPAddress, errorCode
FROM   <event-data-store-id>
WHERE  eventTime >= '2026-11-01 00:00:00'
  AND (
    eventName IN ('StopLogging', 'DeleteTrail', 'UpdateTrail')
    OR (
      errorCode IS NULL
      AND eventName IN ('PutUserPolicy', 'AttachUserPolicy', 'CreateAccessKey', 'UpdateAssumeRolePolicy')
      AND userIdentity.sessionContext.attributes.mfaAuthenticated = 'false'
    )
  )
ORDER BY eventTime DESC;
