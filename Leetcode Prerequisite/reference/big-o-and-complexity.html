Big O Complexity & Asymptotic Bounds Quick Reference

Essential cheat sheet for operational time complexity, the 107 CPU operations ceiling, built-in library traps, and auxiliary space accounting.

1. Asymptotic Hierarchy (Fastest to Slowest)

O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)
Big O Name Operations for n = 105 Common Exemplar
O(1) Constant 1 Array index lookup (arr[i]), hash map insert/lookup
O(log n) Logarithmic ~17 Binary search on sorted array, balanced BST search
O(n) Linear 100,000 Single pass loop, finding min/max, linear scan
O(n log n) Linearithmic ~1,700,000 Merge sort, TimSort (standard library .sort()), Heap sort
O(n²) Quadratic 10,000,000,000 (1010) → TLE! Brute force nested loops, bubble sort, pairwise comparisons
O(2ⁿ) Exponential Unfathomable (> 1030,000) Generating all subsets, brute-force recursion
O(n!) Factorial Instant freeze Generating all permutations, Travelling Salesperson brute force

2. Constraint Math: The 10⁷ Rule

Modern judge CPUs execute roughly 107 to 108 operations per second. If an algorithm requires > 107 operations for the max constraint n, it triggers Time Limit Exceeded (TLE).

LeetCode Constraint (n) Maximum Permissible Big O Target Algorithmic Strategy
n ≤ 10 – 12 O(n!) or O(n² · 2ⁿ) Permutations, TSP, Bitmask DP
n ≤ 20 – 25 O(2ⁿ) Backtracking, Subsets, Exhaustive Search
n ≤ 100 – 500 O(n³) Floyd-Warshall, 3D Dynamic Programming, Matrix Mult
n ≤ 1,000 – 2,000 O(n²) Nested loops, 2D Dynamic Programming, All-pairs scan
n ≤ 100,000 (10⁵) O(n log n) or O(n) Sorting, Heap, Two Pointers, Sliding Window, Hash Table
n ≤ 1,000,000 (10⁶) O(n) or O(n log n) with small constant Prefix sums, Monotonic Stack, Single-pass scans
n ≥ 10⁹ (or 2³¹ - 1) O(log n) or O(1) Binary search, Bit manipulation, Closed-form math

3. Multi-Variable Big O & Amortized Loop Rules

Multi-Variable Input Bounds

When inputs have independent lengths (e.g., arrays A of length n and B of length m, or a 2D grid of R rows and C columns):

  • Two Separate Scans: for (x in A) ... for (y in B) ... is O(n + m), NOT O(n) or O(2n).
  • Nested Cartesians: for (x in A) { for (y in B) { ... } } is O(n · m).
  • 2D Matrix Traversal: Visiting each cell of an R × C matrix is O(R · C).

Amortized Two-Pointer / Sliding Window

Do NOT count nested loops mechanically as O(n²) without analyzing pointer movement:

  • If the outer loop advances right from 0 to n-1 (moves at most n times), and an inner while loop advances left forward only:
  • left starts at 0 and can move forward at most n times across the entire execution of the program.
  • Total pointer steps = at most 2n → Amortized O(n) Time.

4. The "Hidden Big O" in Built-in Standard Methods

Language Method Call Actual Complexity Underlying Hardware Operation
Kotlin / Java list.contains(target) O(n) Linear scan through elements from index 0.
Kotlin / Java list.removeAt(0) O(n) Shifts all remaining n - 1 memory slots left by 1.
Kotlin / Java map.containsKey(key) O(1) avg Hashes key to directly compute bucket index.
Kotlin / Java string += char (in loop) O(n²) total Strings are immutable; copies full string each iteration. Use StringBuilder.
Python target in my_list O(n) Linear scan through list elements.
Python my_list.pop(0) O(n) Shifts all pointers down in the dynamic array. Use collections.deque for O(1).
Python target in my_dict / set O(1) avg Hash table probe.

5. Space Complexity Accounting

  • Total Space: Memory used by input arguments + output result + internal scratchpad.
  • Auxiliary Space: Memory used strictly by temporary allocations created by the algorithm (scratch arrays, hash maps, recursion stack frames). In interviews, "Space Complexity" almost always means Auxiliary Space.
  • Call Stack Space: Every recursive call pushes an active stack frame of size O(1). If recursion reaches depth d, auxiliary stack space is O(d).
  • Return Output Rule: If an interview question asks you to return an array of size n, the returned array is generally not counted against auxiliary space unless specified.
