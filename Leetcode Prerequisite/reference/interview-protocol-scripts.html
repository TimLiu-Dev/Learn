The 45-Minute Interview Protocol & Senior Scripts

Exact choreography, word-for-word verbal scripts, consensus checks, and verification procedures for Tier-1 Big Tech technical interviews.

1. The 45-Minute Choreography & Word-for-Word Scripts

Stage 1: Clarify & Validate Constraints (Minutes 00:00 – 05:00)

Do NOT Code Yet

Restate the problem in your own words. Confirm edge constraints, data types, and primary optimization targets.

“Just to ensure we are aligned, the objective is to return the 0-indexed positions of the two distinct elements that sum to target. A few quick clarifications: Can we assume the array always contains at least one valid solution, or should we handle the no-solution case? Can inputs include negative numbers or duplicates? And are we optimizing primarily for execution time or auxiliary memory?”

Stage 2: Verbalize Brute-Force Baseline (Minutes 05:00 – 06:00)

30-Second Drill

State the naive baseline concisely to establish a baseline and pinpoint the algorithmic bottleneck. Never code this unless asked.

“The baseline brute-force approach is an exhaustive pairwise comparison: loop over each element with pointer i, and check every subsequent element with pointer j. That runs in O(n²) time and O(1) auxiliary space.”

Stage 3: Isolate Bottleneck & Propose Optimal (Minutes 06:00 – 09:00)

The Tradeoff

Explain why the brute force is slow and propose the exact data structure or algorithmic technique that eliminates the bottleneck.

“The bottleneck is repeatedly scanning the remaining array in O(n) to find the complement (target - nums[i]). We can eliminate that search by trading O(n) auxiliary memory in a hash map: as we iterate through nums, we map each value to its index. That gives us O(1) average complement lookups, reducing total runtime to O(n).”

Stage 4: Secure Explicit Consensus (Minutes 09:00 – 10:00)

The Handshake

Never write code without the interviewer confirming agreement.

“Does this O(n) time, O(n) auxiliary space strategy make sense to you, or would you like me to begin implementing this solution?”

Stage 5: Implement Optimal Code (Minutes 10:00 – 30:00)

Talk While Coding

Narrate your intent out loud as you type. Use meaningful variable names (`seen`, `complement`, `target`).

“I'll declare a hash map called 'seen' mapping numbers to indices. Then I'll iterate through nums with index i. First, I compute complement = target - nums[i]. If seen contains complement, we return an array with seen[complement] and i. Otherwise, we record seen[nums[i]] = i...”

Stage 6: Trace & Run Edge-Case Gauntlet (Minutes 30:00 – 45:00)

Zero IDE Verification

Walk line-by-line through a sample input with a trace table before claiming you are finished.

“Before declaring this complete, let me walk through a concrete test case line-by-line: nums = [2, 7, 11, 15] with target = 9. At i = 0, complement is 7. Map is empty, so we store 2 -> 0. At i = 1, complement is 2. 2 exists at index 0, so we return [0, 1]. Now let's check edge cases...”

2. Universal 6-Point Edge-Case Gauntlet

# Edge Case Category Sample Input Failure Mode to Guard Against
1 Empty / Minimum Size [] or [1] IndexOutOfBoundsException, null pointer dereference
2 All Duplicate Values nums = [3, 3], target = 6 Hash map key collision overwriting original index
3 Negative Numbers nums = [-3, 4, 3, 90], target = 0 Flawed comparison logic assuming monotonic positive sums
4 Boundary Target at Ends Target formed by first and last items Off-by-one loop bounds terminating early (< vs ≤)
5 Integer Overflow Limits a + b > 2³¹ - 1 Silent arithmetic roll-over in 32-bit signed integers
6 No Solution Exists No two numbers sum to target Falling off function body without returning or throwing

3. Error Recovery Scripts (When Things Go Wrong)

  • When you get stuck:
    “I'm currently thinking through how to handle duplicate keys without losing prior indices. Let me step back and examine the state of our data structure at step i...” (Shows composure and transparency).
  • When you spot a bug during dry-running:
    “Tracing this reveals a bug: if we insert the current item before checking for complement, a number can erroneously pair with itself if 2 * num == target. To fix this, we simply check for complement first, and insert second.” (Turns a mistake into positive evidence of testing rigor).
  • When the interviewer gives a hint:
    “That makes sense. If we use a hash map instead of re-scanning, we eliminate the inner loop. Let me adapt the plan accordingly.” (Accepts hints gracefully without becoming defensive).
