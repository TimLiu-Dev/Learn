1. The Physics of the 107 – 108 Operations Rule

Beginners treat LeetCode's Constraints block at the bottom of the prompt as fine print. Experienced engineers read it before designing an algorithm because it reveals which Big O classes can physically pass within the 1–2 second online judge timeout:

  • A modern 3 GHz server core runs 3 × 109 raw clock cycles per second.
  • Factoring in loop branches, JVM/Python overhead, and RAM cache misses, a high-level loop safely executes roughly:
107 (conservative safe target) to 108 (hard ceiling) operations / second
🧸 ELI5: Airline Carry-On Sizer & Kitchen Rush Timer

Checking constraints first is checking the airline carry-on sizer before packing. If the problem says n ≤ 105, plugging n into O(n²) gives (105)2 = 1010 steps—100× over the 108 ceiling! You know immediately not to waste 20 minutes coding an O(n²) approach.

3. 32-Bit Integer Overflow & Why LeetCode Uses 109 + 7

32-Bit Signed Int vs. 64-Bit Signed Long
  • Int (32-bit): 1 sign bit + 31 value bits ⇒ -2,147,483,648 to +2,147,483,647 (≈ ±2.14 × 109).
  • Long (64-bit): 1 sign bit + 63 value bits ⇒ up to +9,223,372,036,854,775,807 (≈ ±9.22 × 1018).

The Subtle Kotlin / Java Multiplication Trap!

Look closely at this deadly one-line bug when a = 100_000 and b = 100_000: 

val wrongProduct: Long = a * b           // BUG! a * b multiplies as 32-bit Int FIRST -> overflows to 1410065408L!
val safeProduct: Long  = a.toLong() * b  // SAFE! Promotes left operand to 64-bit Long BEFORE multiplying -> 10_000_000_000L

Why Do Counting Problems Say "Return Answer Modulo 109 + 7"?

In combinatorics and Dynamic Programming, answers can exceed even 64-bit Long. LeetCode asks for ans % 1_000_000_007 because M = 1,000,000,007 is a prime number where:

  • M + M ≈ 2.0 × 109 fits inside a 32-bit signed Int without overflowing!
  • M × M ≈ 1018 fits inside a 64-bit signed Long without overflowing!
🧸 ELI5: The 6-Digit Vintage Car Odometer

Driving 1 mile past 999,999 on a mechanical odometer silently rolls the wheels to 000,000—no warning light flashes! On the JVM, exceeding +2,147,483,647 rolls into the negative sign bit without throwing an exception. Whenever constraint values say nums[i] ≤ 109 and you add or multiply them, switch your accumulator to Long!

4. Polyglot Code Study: Overflow-Proof Midpoint, Sums & Modulo

class SafeMath {
    private val MOD = 1_000_000_007L

    // 1. OVERFLOW-SAFE BINARY SEARCH MIDPOINT
    fun safeMidpoint(left: Int, right: Int): Int = left + (right - left) / 2

    // 2. SAFE ARRAY SUM WHEN nums[i] CAN REACH 10^9 (nums.sum() overflows Int!)
    fun safeArraySum(nums: IntArray): Long = nums.sumOf { it.toLong() }

    // 3. MODULAR MULTIPLICATION WITHOUT 64-BIT OVERFLOW
    fun modMul(a: Int, b: Int): Int = ((a.toLong() * b) % MOD).toInt()
}
class SafeMath:
    MOD = 1_000_000_007

    def safe_midpoint(self, left: int, right: int) -> int:
        return left + (right - left) // 2

    # Python ints have arbitrary precision automatically,
    # though taking % MOD at each step keeps bit-length small and O(1)!
    def mod_mul(self, a: int, b: int) -> int:
        return (a * b) % self.MOD
public class SafeMath {
    private static final long MOD = 1_000_000_007L;

    public int safeMidpoint(int left, int right) {
        return left + (right - left) / 2;
    }

    public long safeArraySum(int[] nums) {
        long total = 0L;
        for (int x : nums) total += x; // Promotes x to long on addition
        return total;
    }

    public int modMul(int a, int b) {
        return (int) (((long) a * b) % MOD);
    }
}
