How Computers Actually Run Code & Counting Elementary Steps

Before learning Big O or memory hardware, we must answer the most fundamental question: What is an algorithm, what does a computer do when executing code line-by-line, and how do we count the work it performs?

1. What Exactly is an Algorithm? (Code vs. Algorithm)

In everyday software engineering, we often say "I wrote some code to fix that bug." But in Computer Science, Code and an Algorithm are not the same thing:

  • An Algorithm is an abstract, step-by-step mathematical recipe that solves a problem for any valid input. It exists independently of Kotlin, Python, Java, or computers.
  • Code is the concrete syntax we type to translate that recipe into instructions a specific compiler or interpreter can execute.
🧸 ELI5: The Cookie Recipe vs. The Language It's Written In

Imagine a recipe for baking chocolate chip cookies:
"1. Mix 2 cups flour and 1 cup sugar. 2. Add 2 eggs. 3. Stir in chocolate chips. 4. Bake at 350°F for 12 minutes."

You can write this recipe in English, Spanish, or Japanese. You can print it on paper or read it on a phone. The language and paper are just the syntax (the code).

The sequence of steps that transforms raw ingredients into cookies is the algorithm. If the recipe says "stir each chocolate chip individually for 10 minutes," it will be horribly slow no matter which language you translate it into.

Deep CS Insight: The 4 Laws of Every Valid Algorithm
In computer science (Donald Knuth, The Art of Computer Programming), a procedure is only an algorithm if it satisfies four strict properties:
  1. Finiteness: It must terminate after a finite number of steps (never an accidental infinite loop).
  2. Definiteness: Every step must be unambiguous and deterministically specified.
  3. Input & Output: It accepts zero or more well-defined inputs and produces one or more verifiable outputs.
  4. Effectiveness: Every operation must be basic enough to perform mechanically in finite time with paper and pencil.

2. What is an "Elementary Step"? (How to Count Work)

When we judge whether an algorithm is "fast" or "slow", we never use a physical stopwatch. Running the exact same code on a 2014 laptop might take 3 seconds, while an M4 workstation finishes in 0.04 seconds. A stopwatch measures the hardware, not the algorithm.

Instead, computer scientists count Elementary Operations—actions so primitive that the CPU executes each one in a fixed, constant number of clock cycles:

Type of Action Example in Kotlin / Python Cost (Elementary Steps)
Variable Assignment val count = 0 / x = 10 1 step
Basic Arithmetic val sum = a + b / x * 2 1 step
Comparison if (a > b) / if x == target 1 step
Array Index Lookup val item = nums[0] 1 step (Instant!)
Function Return return total 1 step
🧸 ELI5: Counting Lego Bricks

Imagine snapping together a small Lego model. Clicking 1 brick into place is 1 elementary step.

Adding two numbers (2 + 3) clicks 1 brick. Checking x > 5 clicks 1 brick. Instead of timing your hands with a stopwatch, we count how many total Lego bricks the instructions require you to snap together.

3. Demystifying n: The Dial of Problem Size

Throughout LeetCode and computer science, you will see the italicized variable n everywhere.

What is n?
n is simply the size of the input—the number of elements your function receives:

  • Pass an array of 5 integers to a function → n = 5.
  • Pass a string of 10,000 characters → n = 10,000.
  • Pass two separate arrays of lengths n and m → we track both variables (n and m) rather than assuming they are equal!

Think of n as a volume knob. A strong algorithm stays responsive even when LeetCode cranks n from 10 up to 100,000.

4. How Loops Multiply Work: Sequential vs. Nested vs. Halving

Straight-line code without loops or function calls executes a fixed number of steps—Constant Work, written O(1). Once loops appear, step counts scale with n according to four core patterns:

Pattern A: Single Loop — n Steps (Linear)

fun sumAll(nums: IntArray): Int {
    var total = 0
    for (x in nums) {     // Repeats n times
        total += x        // 1 addition per element
    }
    return total
}

If nums.size is 1,000, the loop body runs 1,000 times. Work grows 1-for-1 with n.

Pattern B: Two Separate Sequential Loops — n + n = 2n Steps

fun minPlusMax(nums: IntArray): Int {
    var minVal = Int.MAX_VALUE
    for (x in nums) if (x < minVal) minVal = x  // Finishes n steps FIRST

    var maxVal = Int.MIN_VALUE
    for (y in nums) if (y > maxVal) maxVal = y  // Then runs another n steps
    return minVal + maxVal
}

Because the first loop finishes completely before the second loop starts, their work adds: n + n = 2n steps.

Pattern C: Nested Loops — n × n = n2 Steps (Quadratic)

fun countAllPairs(nums: IntArray): Int {
    var pairs = 0
    for (i in nums.indices) {         // Outer loop: runs n times
        for (j in nums.indices) {     // Inner loop: runs n times FOR EACH outer i!
            pairs++                   // Total executions: n * n = n²
        }
    }
    return pairs
}

Because the inner loop restarts from 0 on every single tick of the outer loop, the step counts multiply!

Pattern D: Multiplicative / Halving Loop — log2 n Steps

fun countHalvings(n: Int): Int {
    var curr = n
    var steps = 0
    while (curr > 1) {
        curr /= 2    // Cuts problem in half each step!
        steps++
    }
    return steps
}

Instead of subtracting 1 each time, curr /= 2 slashes the remaining work in half every iteration. Even for n = 1,000,000, this loop runs only 20 times!

🧸 ELI5: The High School Handshake Party

Imagine 10 students walk into a classroom (n = 10).

Single Loop: The teacher calls each student's name once for attendance. That takes 10 calls. If 1,000 students attend an assembly, attendance takes 1,000 calls.

Nested Loop: The teacher announces: "Every student must shake hands with every student!"
10 students × 10 handshakes = 100 actions. In the 1,000-student auditorium, 1,000 × 1,000 = 1,000,000 handshakes! Nested loops explode rapidly as n grows.

5. Polyglot Code Study: Sequential vs. Nested vs. Triangle Loops

class StepCountingDemo {
    // 1. SEQUENTIAL LOOPS: n + n = 2n steps -> Linear O(n)
    fun countSequential(nums: IntArray): Int {
        var steps = 0
        for (i in nums.indices) steps++
        for (j in nums.indices) steps++
        return steps
    }

    // 2. FULL NESTED GRID: n * n = n² steps -> Quadratic O(n²)
    fun countFullNested(nums: IntArray): Int {
        var steps = 0
        for (i in nums.indices) {
            for (j in nums.indices) {
                steps++
            }
        }
        return steps
    }

    // 3. UNIQUE PAIRS TRIANGLE: n * (n - 1) / 2 steps -> Still Quadratic O(n²)!
    fun countUniquePairs(nums: IntArray): Int {
        var steps = 0
        for (i in 0 until nums.size) {
            for (j in i + 1 until nums.size) {
                steps++
            }
        }
        return steps
    }
}

        return steps
