1. Fixed Primitive Arrays vs. Dynamic Arrays & Amortized O(1)

In Kotlin and Java, there are two fundamentally different array worlds in physical RAM:

  • Unboxed Primitive Arrays (IntArray, CharArray, BooleanArray): Raw contiguous bytes in RAM (4 bytes per Int), fixed length on creation, zero object wrapper overhead.
  • Resizable Dynamic Arrays (ArrayList<T> / mutableListOf<T>()): Wraps an internal array with spare capacity so you can call .add(x) dynamically (note: generic List<Int> boxes each Int into a heap Integer object referenced by a pointer).

How Can Resizing an Array Still Be "O(1) Amortized"?

When an ArrayList fills all 4 of its slots and you append a 5th item, it allocates a 2× larger array (capacity 8), copies the 4 old items over, and writes the 5th. Why isn't appending n items O(n²) like string concatenation?

Total Copies Across n Appends = 1 + 2 + 4 + 8 + … + n2 < 2n ⇒ 2n + n workn appends = 3 ops / append = O(1) Amortized!

Because we double capacity geometrically instead of adding +1 slot each time, expensive O(n) copies happen exponentially more rarely!

🧸 ELI5: Moving Apartments Only When Your Family Doubles

Moving houses takes all Saturday. If you moved every single time you bought 1 new book (str += ch), you'd spend your whole life packing trucks (O(n²)). Buying a bookshelf twice as big whenever the current one fills means 99% of books slide onto an open shelf in 1 second—spreading the rare moving day to ~2 seconds per book on average (Amortized O(1))!

In Kotlin and Java, calling seen.add(x) on a HashSet does both jobs in a single bucket lookup: it returns true if x was newly added, or false if x was already in the set! Writing if (!seen.add(x)) return true detects a duplicate in one clean hash probe.

3. Stacks (LIFO) & Queues (FIFO): Why ArrayDeque Rules Both

Two linear access disciplines appear in almost every Graph, Tree, and Parsing interview:

  • Stack (Last-In, First-Out — LIFO): Push and pop from the same end (matching parentheses, undo history, iterative DFS).
  • Queue (First-In, First-Out — FIFO): Enqueue at the back, dequeue from the front (level-by-level Breadth-First Search).

Why does ArrayList.removeAt(0) take O(n) while ArrayDeque.removeFirst() takes O(1)? Because ArrayDeque is a Circular Ring Buffer: instead of shifting 99,999 elements left in RAM, it simply increments a head index with modulo wrap-around (head = (head + 1).mod(cap))!

🧸 ELI5: Stack of Pancakes (LIFO) vs. Coffee Shop Line (FIFO)

Stack (LIFO): You eat the top pancake that came off the griddle last (addLast / removeLast). Queue (FIFO): The first customer in line gets served first (addLast / removeFirst). In Kotlin, ArrayDeque<T>() gives O(1) amortized speed for both!

4. Heap Reference Pointers: Decoding LeetCode's ListNode? & TreeNode?

When you open your first Linked List or Binary Tree problem on LeetCode in Kotlin, you will see this comment block above class Solution: 

/**
 * Definition for singly-linked list (provided by LeetCode — do NOT redeclare it!):
 * class ListNode(var `val`: Int) {
 *     var next: ListNode? = null
 * }
 */
  • Why the backticks around `` `val` ``? In Java/Python the field is named val. Because val is a reserved keyword in Kotlin, Kotlin escapes Java identifiers with backticks: read/write a node's number via curr.`val`!
  • Moving a Variable vs. Rewiring the Heap (Crucial Distinction!):
STACK FRAME HEAP MEMORY (Scattered Nodes) ┌──────────────┐ ┌───────────┐ ┌───────────┐ │ head ────────┼─────────────────►│ `val`: 10 │───►│ `val`: 20 │───► null │ curr ────────┼──┐ └───────────┘ └───────────┘ └──────────────┘ └────────────────────────────────▲ • curr = curr?.next → Moves YOUR local 'curr' finger on the Stack (list unchanged!) • curr?.next = null → Severs the arrow ON THE HEAP (mutates the actual list!)
🧸 ELI5: Scavenger Hunt Clue Envelopes

An array is a row of townhouses touching wall-to-wall. A ListNode chain is a city-wide scavenger hunt: Envelope A sits in a park bench and holds a slip of paper saying "Next envelope is behind the bakery" (next pointer). Walking yourself to the bakery (curr = curr.next) doesn't alter Envelope A; erasing the slip inside Envelope A (curr.next = otherNode) rewires the hunt for everyone!

    fun demoDeque() {
        val stack = ArrayDeque<Char>()
        stack.addLast('(')                 // push O(1)
        val top = stack.removeLast()       // pop  O(1)

        val queue = ArrayDeque<Int>()
        queue.addLast(10)                  // enqueue O(1)
        val front = queue.removeFirst()    // dequeue O(1) — NEVER ArrayList.removeAt(0)!
    }

    // 2. LINKED LIST TRAVERSAL: O(n) Time | O(1) Auxiliary Space
    fun sumLinkedList(head: ListNode?): Int {
        var total = 0
        var curr = head                    // Local pointer starts at head
        while (curr != null) {
            total += curr.`val`            // Backticks access 'val' property in Kotlin!
            curr = curr.next               // Advance pointer to next heap node
        }
        return total
    }
}
