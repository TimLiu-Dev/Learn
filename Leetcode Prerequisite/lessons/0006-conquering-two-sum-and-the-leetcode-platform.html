1. Demystifying the LeetCode Platform (Where is main()?)

Opening LeetCode for the first time surprises many self-taught engineers: there is no fun main(), no readln(), and no println() needed. Instead, you fill in one method inside class Solution: 

class Solution {
    fun twoSum(nums: IntArray, target: Int): IntArray {
        // Your implementation returns the answer directly

}
🧸 ELI5: The Restaurant Kitchen Ticket Window

You are the chef at the pass—you don't park cars or seat diners. LeetCode's Online Judge is the waiter: it hands your twoSum() method 60+ test plates (nums, target), inspects the IntArray plate you return, and checks both correctness and total runtime!

How the Judge Harness Executes Your Class (And the Stateful Field Trap!)
Behind the scenes, LeetCode imports standard packages (java.util.*, kotlin.math.*) automatically and runs a loop over hidden test inputs: 
val solver = Solution()
for (tc in hiddenTestSuite) {
    val actual = solver.twoSum(tc.nums, tc.target)
    check(actual.contentEquals(tc.expected))
}
Golden Rule: Keep mutable state (maps, counters, result lists) local inside the function (or explicitly .clear() them at the start of the method)—never leave leftover data in a class property or companion object across test cases!

2. Decoding All 6 LeetCode Verdicts When Debugging

Verdict What Happened First Thing to Check
Accepted (AC) Passed every visible & hidden test within time/memory limits. Verify you can state exact Time & Auxiliary Space Big O out loud!
Wrong Answer (WA) Returned an incorrect output on a specific test case. Copy the failing input into a trace table! Check edge cases (negatives, duplicates, returning values vs. indices, stale class fields, 32-bit Int overflow).
Time Limit Exceeded (TLE) Exceeded ~1–2s CPU budget (> 108 ops). Either your Big O is too slow for max n (e.g. O(n²) at n = 105) OR a while loop forgot to update its pointer (infinite loop!).
Memory Limit Exceeded (MLE) Allocated too much heap/stack RAM. Unbounded recursion, giant 2D array Array(100_000) { IntArray(100_000) }, or BFS pushing duplicates without marking visited before enqueuing.
Runtime Error (RE) Threw an unhandled exception mid-run. Read the stack trace: ArrayIndexOutOfBoundsException, NullPointerException (unsafe !!), StackOverflowError, or / 0.
Compile Error (CE) Code failed to compile before running any test. Check return type mismatch (e.g. returning List<Int> when signature says IntArray—use intArrayOf(...) or .toIntArray()!).

3. Deconstructing LeetCode #1 Two Sum

Problem Specification & Constraints
Given an integer array nums (2 ≤ nums.size ≤ 104, -109 ≤ nums[i], target ≤ 109), return indices of the two numbers such that they add up to target. Exactly one valid answer exists, and you may not use the same element twice.
  • Indices vs. Values: For nums = [2, 7, 11, 15], target = 9, return positions [0, 1]—not values [2, 7]!
  • No Self-Pairing: For nums = [3, 2, 4], target = 6, index 0 (value 3) cannot pair with itself to return [0, 0]; the valid answer is [1, 2].

4. From O(n²) Brute Force to O(n) One-Pass HashMap

Applying our Lesson 01–04 protocol:

1Brute-Force Baseline: Loop i from 0 until n and j from i + 1 until n. Time: O(n²), Auxiliary Space: O(1).
2Complement Rewrite: At index i, we need complement = target - nums[i]. Instead of scanning forward with j, store previously visited numbers in seen: HashMap<Int, Int> (mapping value → index).
3Order of Operations Invariant: Always check seen for complement BEFORE inserting seen[nums[i]] = i! That guarantees nums[i] never matches itself, AND handles valid duplicates like nums = [3, 3], target = 6 cleanly (when i = 1 checks the map, 3 → 0 is already waiting!).
class Solution {
    // Time: O(n) average | Auxiliary Space: O(n)
    fun twoSum(nums: IntArray, target: Int): IntArray {
        val seen = HashMap<Int, Int>() // value -> index

        for (i in nums.indices) {
            val complement = target - nums[i]
            val prevIdx = seen[complement]
            // 1. Check BEFORE inserting so nums[i] never pairs with itself
            if (prevIdx != null) {
                return intArrayOf(prevIdx, i)
            }
            // 2. Record current number -> index for future elements
            seen[nums[i]] = i
        }
        return intArrayOf()
    }
}
class Solution:
    # Time: O(n) average | Auxiliary Space: O(n)
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        seen: dict[int, int] = {}
        for i, num in enumerate(nums):
            complement = target - num
            if complement in seen:
                return [seen[complement], i]
            seen[num] = i
        return []
import java.util.HashMap;
import java.util.Map;

class Solution {
    // Time: O(n) average | Auxiliary Space: O(n)
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            Integer prevIdx = seen.get(target - nums[i]);
            if (prevIdx != null) {
                return new int[] { prevIdx, i };
            }
            seen.put(nums[i], i);
        }
        return new int[0];
    }
}

        for (i in 0 until nums.size) {
            for (j in i + 1 until nums.size) {
                if (nums[i] + nums[j] == target) {
                    return intArrayOf(i, j)
                }
            }
        }
        return intArrayOf()
    }
