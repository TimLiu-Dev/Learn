High-Throughput In-Memory Rate Limiting & Token Buckets

Designing sub-millisecond rate limiters capable of handling 500,000+ requests per second without thread lock contention, timer thread explosion, or memory bloat.

1. The 2027 Big-Tech Reality: The Timer Thread Trap

When asked to design a Token Bucket rate limiter, junior candidates almost always say: "I will create a background thread or `setInterval` that adds 1 token to the bucket every 100 milliseconds."

The 1,000,000 Timer Thread Explosion

If your API serves 1,000,000 active users, running 1,000,000 background timers will instantly crash the OS kernel due to context-switching overhead and CPU starvation.

2. The Senior Solution: Lazy On-Demand Refill

A Senior Engineer uses lazy mathematical refill. You never run a background timer. Instead, when a request arrives, you compute how many tokens should have accumulated since the last request using simple timestamp math:

LazyRefillMath.ts
// Zero background threads! Pure timestamp delta math:
function refillTokens(now: number) {
  const elapsedMs = now - this.lastRefillTimestamp;
  const tokensToAdd = elapsedMs * this.refillRatePerMs;
  
  this.currentTokens = Math.min(this.maxCapacity, this.currentTokens + tokensToAdd);
  this.lastRefillTimestamp = now;
}

3. Comparison of Core Algorithms

Algorithm Space Complexity Burst Handling Trade-off
Token Bucket $O(1)$ per user Allows controlled bursts up to bucket capacity Gold standard in modern API gateways (Stripe, AWS, Cloudflare).
Leaky Bucket $O(1)$ or $O(QueueSize)$ Smooths bursts to a constant output rate Queues or drops requests if ingress rate spikes.
Sliding Window Log $O(N)$ where $N$ = request count Extremely precise window boundary High memory overhead; unsuitable for high-frequency traffic.

Senior Phrasing to Use

"To support millions of tenant buckets without CPU thread explosion, I am rejecting background timers in favor of lazy mathematical refills on ingress. Token accumulation is calculated on-the-fly using the millisecond delta between requests."

Instant Disqualification Trap

Proposing to store an array of timestamps for every single API request in a sliding window log, which consumes gigabytes of memory under high-throughput DDoS attacks.
