Mid-Tech Case Studies: Smart Parking Garage & Dispatch Systems

Tackling the most asked mid-tech interview questions at a Senior level: dynamic spot allocation, vehicle size constraints, sensor state synchronizations, and ticket billing engines.

1. The 2027 Senior Reality: Why Toy Parking Lots Fail

Everyone knows the Parking Lot question. Junior candidates pass around Car objects, make a 2D array of booleans, and count occupied spots with a nested for-loop.

In a 2027 Senior Interview, the interviewer evaluates:

  • Polymorphic Vehicle Fitting Rules: Decoupled from hardcoded comparisons (e.g. Motorcycles fit anywhere, Compact cars fit in Compact/Large, Trucks require Large).
  • Sub-Millisecond Spot Lookup: Indexing available spots per floor and type (e.g. Map<SpotType, Set<ParkingSpot>>) instead of $O(N)$ linear scans.
  • Ticket Billing Strategy: Calculating fees via clean Strategy classes (hourly, flat-rate, peak surcharge) rather than hardcoded math.
  • Thread-Safe Concurrency: Preventing two gates from issuing the last available parking spot to two drivers simultaneously.

class ParkingSpot {
  private occupiedVehicle: Vehicle | null = null;
  
  canFit(vehicle: Vehicle): boolean { ... }
  assign(vehicle: Vehicle): void { ... }
  vacate(): Vehicle | null { ... }
}

// 3. Ticket Aggregate: Tracks entry, exit, spot, and calculated fee
class ParkingTicket {
  readonly ticketId: string;
  readonly issuedAt: Date;
  paidAt: Date | null = null;
  feeInCents: number = 0;
}

Senior Phrasing to Use

"Before assigning spots, I am defining a best-fit allocation strategy so smaller vehicles do not greedily consume large spots needed by trucks. We'll track available spots in a indexed map by spot type to achieve O(1) spot acquisition."

Instant Disqualification Trap

Iterating over an unindexed 2D array of 5,000 spots whenever a vehicle enters the gate, and ignoring ticket lifecycle or fee calculation completely.
