The Senior OOD 2027 Ultimate Interview Cheat Sheet

High-density mental models, 45-minute whiteboard pacing, pattern selection decision trees, concurrency checklists, and distributed-aware aggregate rules for Mid-Tech and Big-Tech interviews.

⏱️ The 45-Minute Interview Whiteboard Blueprint

00 – 07 min: Clarify & Scope

Clarify functional use cases, scale/throughput, invariants, and out-of-scope edges. Never write classes first!

07 – 18 min: Domain Contracts

Define Entities, Value Objects, Strategy interfaces, and State transitions. Zero primitive obsession.

18 – 32 min: Core Business Logic

Code the primary business method (e.g., reserveSpot, executeStep, refillBucket). Enforce fail-fast guards.

32 – 40 min: Concurrency & Races

Address check-then-act race conditions. Introduce RWLocks, atomic CAS, or lock ordering hierarchies.

40 – 45 min: Distributed Evolution

Discuss scaling out: Aggregate boundaries, Transactional Outbox, Idempotency keys, and Saga rollbacks.

🎯 Design Pattern Selection Matrix

  • Strategy: Multiple interchangeable algorithms for the same task (e.g. Dynamic Pricing, Sorting, Payment Providers). Avoid switch statements!
  • State: Object behavior alters dramatically based on internal state with strict transitions (e.g. Order Lifecycle, TCP Connection).
  • Observer / Pub-Sub: One-to-many event notification decoupling producers from consumers (e.g. Audit Logs, Notification Dispatch).
  • Chain of Responsibility / Pipeline: Sequential processing filters, interceptors, rate-limit middleware, or circuit breakers.
  • Composite: Tree structures where individual items and groups share identical interfaces (e.g. File Systems, Org Charts).
  • Command: Encapsulating requests as objects to support undo, queuing, or replay logging.

⚡ Concurrency & Thread-Safety Checklist

  • Check-Then-Act: Never check a condition outside a synchronized block/lock and act on it later. Must be atomic!
  • Lock Ordering: When locking multiple resources (e.g. Account A & B), always sort by ID (idA < idB) before acquiring locks to prevent deadlocks.
  • ReadWriteLock: Use when read operations vastly outnumber write mutations (e.g. 99% reads, 1% writes).
  • Atomic CAS: Use for high-frequency numeric counters and rate limiter timestamps with zero thread blocking.
  • Defensive Copying: Never return internal mutable collections directly. Wrap in read-only view or return clone.

🌐 DDD & Distributed Aggregate Boundaries

  • Value Object vs Entity: Value Object = defined by value, immutable, no ID. Entity = defined by unique ID, mutable lifecycle.
  • Aggregate Root: Only the Root is accessible from outside. Internal child entities can only be manipulated via Root methods.
  • Transactional Outbox: Write state mutation and outgoing event record in the same local atomic transaction. Eliminates dual-write bugs.
  • Idempotency: Every mutating request must accept a client-provided UUID. Check cache -> return existing result if already processed.
  • Saga Compensations: In multi-step distributed workflows, execute compensating steps in exact reverse topological order.

🏆 Top 5 Must-Know Interview Archetypes

  • 1. Smart Parking Garage: Vehicle sizing, spot allocation strategy (compact/motorcycle/large), hourly billing math.
  • 2. In-Memory LRU Cache: HashMap + Doubly-Linked List + RWLock. O(1) get/put, eviction when at max capacity.
  • 3. Elevator Dispatcher: SCAN/LOOK disk-scheduling algorithm, elevator bank status, direction prioritization.
  • 4. High-Throughput Rate Limiter: Token Bucket with lazy on-demand mathematical refill, burst capacity handling.
  • 5. Ride Matcher (Uber): Geospatial geohashing/bucketing, driver availability state, trip lifecycle FSM.

🧱 In-Memory LRU Cache Blueprint: O(1) Invariant Mechanics

The quintessential Big-Tech LLD question (Google, Meta, Amazon). Combines a Doubly-Linked List for O(1) node repositioning with a Hash Map for O(1) key lookups. 

class LRUCache<K, V> {
  // 1. Sentinel dummy head and tail eliminate null-pointer edge cases
  private head = new Node(null, null);
  private tail = new Node(null, null);
  private map = new Map<K, Node<K, V>>();

  constructor(private capacity: number) {
    this.head.next = this.tail;
    this.tail.prev = this.head;
  }

  get(key: K): V | null {
    if (!this.map.has(key)) return null;
    const node = this.map.get(key)!;
    this.moveToHead(node); // O(1) mark as most recently used
    return node.value;
  }

  put(key: K, value: V): void {
    if (this.map.has(key)) {
      const node = this.map.get(key)!;
      node.value = value;
      this.moveToHead(node);
      return;
    }
    if (this.map.size >= this.capacity) {
      const lru = this.tail.prev!;
      this.removeNode(lru);       // O(1) unlink
      this.map.delete(lru.key!);  // O(1) remove from map
    }
    const newNode = new Node(key, value);
    this.addToHead(newNode);
    this.map.set(key, newNode);
  }
}
