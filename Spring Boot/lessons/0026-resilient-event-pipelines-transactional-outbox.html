Resilient Event Pipelines: Retries, DLQs & The Transactional Outbox

Target: Master the signature distributed systems pattern expected of Senior Backend Engineers. Permanently solve the dual-write problem with the Transactional Outbox Pattern and non-blocking retry pipelines.

📖 Primary Source Recommendation

Study the official authority: Chris Richardson: Microservices Pattern - Transactional Outbox. Ground your learning in primary architecture rather than secondary summaries.

1. The Dual-Write Trap: Why Direct Sending Fails

⚠️ The Junior Dual-Write Trap

Junior engineers write: orderRepo.save(order); kafkaTemplate.send("orders", event);. If the Kafka broker has a network blip, the DB committed but the event is permanently lost! If the server crashes after sending to Kafka but before the DB commits, a ghost event is published! You cannot execute an atomic transaction across a database and a message broker without two-phase commit overhead.

2. The Transactional Outbox Architecture

Instead of publishing directly to Kafka during the HTTP request, write the event into an outbox table in the same PostgreSQL transaction:

@Transactional public void createOrder(Order order) { 1. orderRepository.save(order); 2. outboxRepository.save(new OutboxEvent("orders.v1", order.getId(), jsonPayload)); } // ACID COMMIT: BOTH succeed, or BOTH rollback. Data loss is impossible!

A background worker (or Debezium CDC) polls unexported records, publishes them to Kafka, and marks them sent.

3. Non-Blocking Retries & Dead Letter Queue (DLQ)

Spring Kafka 3.0+ introduces @RetryableTopic. If a consumer fails, messages are sent to non-blocking retry topics (e.g. orders.v1-retry-1000, orders.v1-retry-2000). After max attempts, it routes to a Dead Letter Queue (orders.v1-dlt), preventing pipeline stalls!

Outbox Atomic Write & Non-Blocking Retry 
package com.example.ecommerce.order;

import org.springframework.kafka.annotation.*;
import org.springframework.retry.annotation.Backoff;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class OrderEventService {

    private final OrderRepository orderRepo;
    private final OutboxRepository outboxRepo;

    public OrderEventService(OrderRepository orderRepo, OutboxRepository outboxRepo) {
        this.orderRepo = orderRepo;
        this.outboxRepo = outboxRepo;
    }

    // 1. Transactional Outbox atomic write:
    @Transactional
    public void placeOrder(OrderEntity order, String eventJson) {
        orderRepo.save(order);
        outboxRepo.save(new OutboxEntity("orders.v1", order.getId(), eventJson));
    }

    // 2. Non-blocking consumer with automated exponential backoff and DLQ:
    @RetryableTopic(
        attempts = "3",
        backoff = @Backoff(delay = 1000, multiplier = 2.0)
    )
    @KafkaListener(topics = "orders.v1", groupId = "fulfillment-service")
    public void handleOrderEvent(String orderJson) {
        System.out.println("Processing fulfillment: " + orderJson);
    }

    @DltHandler
    public void handlePoisonPill(String orderJson) {
        System.err.println("ALERT: Poison message routed to DLQ! " + orderJson);
    }
}
package com.example.ecommerce.order

import org.springframework.kafka.annotation.*
import org.springframework.retry.annotation.Backoff
import org.springframework.stereotype.Service
import org.springframework.transaction.annotation.Transactional

@Service
class OrderEventService(
    private val orderRepo: OrderRepository,
    private val outboxRepo: OutboxRepository
) {
    @Transactional
    fun placeOrder(order: OrderEntity, eventJson: String) {
        orderRepo.save(order)
        outboxRepo.save(OutboxEntity("orders.v1", order.id!!, eventJson))
    }

    @RetryableTopic(
        attempts = "3",
        backoff = Backoff(delay = 1000.0, multiplier = 2.0)
    )
    @KafkaListener(topics = ["orders.v1"], groupId = "fulfillment-service")
    fun handleOrderEvent(orderJson: String) {
        println("Processing fulfillment: $orderJson")
    }

    @DltHandler
    fun handlePoisonPill(orderJson: String) {
        System.err.println("ALERT: Poison message routed to DLQ! $orderJson")
    }
}

Architectural Breakdown:

Committing both the domain entity and the outbox event in the same ACID transaction eliminates distributed data loss permanently.
