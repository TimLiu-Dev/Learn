API Contracts, Backward Compatibility & OpenAPI 3.1

Target: Protect mobile apps from breaking changes. Master backward-compatible API evolution, URI vs Header versioning, and auto-generating living OpenAPI 3.1 contracts with springdoc-openapi.

📖 Primary Source Recommendation

Study the official authority: springdoc-openapi: Modern OpenAPI 3 with Spring Boot 3. Ground your learning in primary architecture rather than secondary summaries.

1. The Mobile Reality: Old APKs Never Die

When you deploy a web app, users get new JavaScript on refresh. In mobile development, 20% of your users remain on app version 1.2 for six months!

If you rename a field from userId to customerUuid in a REST response, millions of installed Android apps immediately crash with JSON deserialization errors!

2. The Two Laws of Backward-Compatible API Evolution

  • Additive Changes Are Safe: Adding a new optional field is safe (Moshi/Jackson ignore unknown properties by default).
  • Destructive Changes Require Versioning: Renaming fields, removing fields, or changing data types (e.g. int to string) requires a new API version!

3. Generating Living Contracts with `springdoc-openapi`

Add to build.gradle.kts:

implementation("org.springdoc:springdoc-openapi-starter-webmvc-ui:2.5.0")

Your API documentation and interactive Swagger UI automatically generate at /swagger-ui.html directly from your code annotations:

Documented & Versioned Controller 
package com.example.ecommerce.order;

import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.responses.*;
import io.swagger.v3.oas.annotations.tags.Tag;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

@Tag(name = "Orders V1", description = "Order processing APIs for Mobile App v1.x")
@RestController
@RequestMapping("/api/v1/orders")
public class OrderV1Controller {

    @Operation(summary = "Fetch Order by ID", description = "Returns full order representation including items and tracking status.")
    @ApiResponse(responseCode = "200", description = "Order found successfully")
    @ApiResponse(responseCode = "404", description = "Order does not exist")
    @GetMapping("/{id}")
    public ResponseEntity<OrderV1Response> getOrder(@PathVariable String id) {
        return ResponseEntity.ok(new OrderV1Response(id, "CONFIRMED"));
    }
}

💡 Complete Production Reference Solution
Java 21 Implementation:
package com.example.health;

import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.responses.ApiResponse;
import org.springframework.web.bind.annotation.*;

@RestController
public class HealthController {

    @Operation(summary = "System Health Check")
    @ApiResponse(responseCode = "200", description = "Service is healthy")
    @GetMapping("/health")
    public String getHealth() {
        return "UP";
    }
}
Kotlin 2.x Implementation:
package com.example.health
