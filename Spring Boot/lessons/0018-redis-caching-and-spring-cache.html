What is Redis? In-Memory Caching & Spring Cache

Target: Demystify in-memory data storage. Learn why RAM is 100,000x faster than disk, master Spring's @Cacheable abstraction, configure Time-To-Live (TTL), and prevent cache stampedes.

📖 Primary Source Recommendation

Study the official authority: Redis Documentation: Redis as an In-Memory Data Store. Ground your learning in primary architecture rather than secondary summaries.

1. What Actually Is Redis? (RAM vs Disk)

PostgreSQL writes to hard disk or SSDs (flash memory). Reading from SSD takes ~100 microseconds. Redis stores all data directly in RAM (Random Access Memory). Reading from RAM takes ~100 nanoseconds (1,000x faster!).

Redis operates as a shared key-value dictionary across all your cloud backend instances, making it the industry standard for caching, session stores, and rate limiting.

2. Spring Cache Abstraction Annotations

  • @Cacheable(value = "products", key = "#id"): Checks Redis first. If found (Cache Hit), returns immediately without touching PostgreSQL! If not found (Cache Miss), runs the method and caches the result.
  • @CacheEvict(value = "products", key = "#id"): Invalidates/deletes the cached entry when the product is updated.
  • @CachePut(value = "products", key = "#product.id"): Always executes the method and updates the cache.

3. Production Dual Redis Cache Implementation

Cached Product Service 
package com.example.ecommerce.product;

import org.springframework.cache.annotation.*;
import org.springframework.stereotype.Service;

@Service
public class ProductCacheService {

    private final ProductRepository productRepo;

    public ProductCacheService(ProductRepository productRepo) {
        this.productRepo = productRepo;
    }

    // Cache lookup: hits Redis before touching PostgreSQL!
    @Cacheable(value = "products", key = "#id", unless = "#result == null")
    public ProductDto getProductById(Long id) {
        return productRepo.findById(id)
            .map(p -> new ProductDto(p.getId(), p.getName(), p.getPrice()))
            .orElse(null);
    }

    // Cache eviction: deletes cached entry when updated!
    @CacheEvict(value = "products", key = "#id")
    public void updateProduct(Long id, ProductUpdateRequest request) {
        ProductEntity entity = productRepo.findById(id).orElseThrow();
        entity.updateDetails(request.name(), request.price());
        productRepo.save(entity);
    }
}
package com.example.ecommerce.product

import org.springframework.cache.annotation.*
import org.springframework.stereotype.Service

@Service
class ProductCacheService(
    private val productRepo: ProductRepository
) {
    @Cacheable(value = ["products"], key = "#id", unless = "#result == null")
    fun getProductById(id: Long): ProductDto? =
        productRepo.findById(id).map { ProductDto(it.id!!, it.name, it.price) }.orElse(null)

    @CacheEvict(value = ["products"], key = "#id")
    fun updateProduct(id: Long, request: ProductUpdateRequest) {
        val entity = productRepo.findById(id).orElseThrow()
        entity.name = request.name
        entity.price = request.price
        productRepo.save(entity)
    }
}

@Service
class ItemService {

    @Cacheable(value = ["items"], key = "#id")
    fun findItem(id: Long): ItemDto = ItemDto(id, "Item-$id")

        // Deletion logic...
    }
}
Architectural Breakdown:

@Cacheable bypasses database queries on subsequent calls, while @CacheEvict guarantees that deleted items do not linger as ghost entries in Redis.
