Spring Data Repositories & Constructor Record Projections

Target: Stop loading 40-column managed entities for read-only APIs. Master derived queries, Spring Data projections, and high-performance Java 21 Record constructor projections.

📖 Primary Source Recommendation

Study the official authority: Spring Data JPA Reference: Projections. Ground your learning in primary architecture rather than secondary summaries.

1. The Problem with Returning Full Entities

If your products table has 40 columns (descriptions, audit timestamps, images, specs) and your mobile app screen only needs id, name, and price:

  • Loading full entities loads megabytes of useless text data into the JVM Hibernate persistence context.
  • Hibernate must track dirty-checking states for all 40 fields on every entity, causing GC pressure.

2. The Solution: Constructor Record Projections

In Spring Data JPA, you can project directly into a Java 21 Record or Kotlin Data Class in the JPQL SELECT clause:

@Query(""" SELECT new com.example.ecommerce.product.ProductSummary(p.id, p.name, p.price) FROM ProductEntity p WHERE p.active = true """) List<ProductSummary> findActiveSummaries();

PostgreSQL only queries the 3 requested columns (SELECT id, name, price FROM products) and Jackson serializes the unmanaged records directly with zero Hibernate overhead!

3. Dual Java & Kotlin Repository Projections

Constructor Record Projection Pattern 
package com.example.ecommerce.product;

import org.springframework.data.jpa.repository.*;
import java.math.BigDecimal;
import java.util.List;

public record ProductSummary(Long id, String name, BigDecimal price) {}

public interface ProductRepository extends JpaRepository<ProductEntity, Long> {

    @Query("""
        SELECT new com.example.ecommerce.product.ProductSummary(p.id, p.name, p.price)
        FROM ProductEntity p
        WHERE p.category = :category
    """)
    List<ProductSummary> findSummariesByCategory(String category);
}
package com.example.ecommerce.product

import org.springframework.data.jpa.repository.JpaRepository
import org.springframework.data.jpa.repository.Query
import java.math.BigDecimal

data class ProductSummary(val id: Long, val name: String, val price: BigDecimal)

interface ProductRepository : JpaRepository<ProductEntity, Long> {

    @Query("""
        SELECT new com.example.ecommerce.product.ProductSummary(p.id, p.name, p.price)
        FROM ProductEntity p
        WHERE p.category = :category
    """)
    fun findSummariesByCategory(category: String): List<ProductSummary>
}

💡 Complete Production Reference Solution
Java 21 Implementation:
package com.example.order;

import org.springframework.data.jpa.repository.*;
import java.util.List;

public record OrderSummary(Long id, String orderNumber) {}

public interface OrderSummaryRepository extends JpaRepository<OrderEntity, Long> {
    @Query("SELECT new com.example.order.OrderSummary(o.id, o.orderNumber) FROM OrderEntity o")
    List<OrderSummary> findAllSummaries();
}
Kotlin 2.x Implementation:
package com.example.order

import org.springframework.data.jpa.repository.*

data class OrderSummary(val id: Long, val orderNumber: String)

interface OrderSummaryRepository : JpaRepository<OrderEntity, Long> {
    @Query("SELECT new com.example.order.OrderSummary(o.id, o.orderNumber) FROM OrderEntity o")
    fun findAllSummaries(): List<OrderSummary>
}
Architectural Breakdown:

Using constructor record projections pulls only the two required columns from PostgreSQL, executing fast and bypassing Hibernate entity lifecycle management.
