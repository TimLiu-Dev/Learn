OAuth2 Resource Server, Mobile PKCE, Passkeys (WebAuthn) & mTLS

Target: Move from DIY token signing to 2027 enterprise identity standards with Spring Security 7: asymmetric JWKS OAuth2 Resource Server verification, how Android/iOS mobile apps authenticate safely via Authorization Code + PKCE, phishing-resistant Passkeys (http.webAuthn(...)), and service-to-service Mutual TLS (mTLS).

📖 Primary Source Recommendation

Study the official authorities: Spring Security 7 Reference: OAuth2 Resource Server and Spring Security 7: Native WebAuthn / Passkeys.

1. Asymmetric JWKS Verification (Why Shared HMAC Secrets Fail at Scale)

Signing JWTs with a symmetric string secret (HMAC-SHA256) means every microservice that verifies tokens must hold the exact same secret capable of forging tokens! Enterprise backends use asymmetric keys (RS256 / ES256):

  • Identity Provider (Keycloak / Auth0 / Cognito / Spring Authorization Server): Signs tokens using a private key locked inside KMS/HSM.
  • Spring Boot Resource Servers: Configure spring.security.oauth2.resourceserver.jwt.issuer-uri to auto-discover public keys from /.well-known/jwks.json and rotate seamlessly via the JWT kid header.

2. Mobile OAuth2 PKCE & Spring Security 7 Passkeys (WebAuthn)

📱 Android Mental Model: Credential Manager Passkeys & PKCE

• Why Mobile Apps Use PKCE (RFC 7636): An Android APK is a public binary—anyone can decompile a hardcoded client_secret! Instead, your Android app generates a random code_verifier per login, sends code_challenge = SHA256(code_verifier) to the OAuth2 server, and proves possession of code_verifier when exchanging the authorization code—defeating malicious redirect-URI interception.
• Native Passkeys in Spring Security 7: Android's CredentialManager creates hardware-backed FIDO2/WebAuthn passkeys. Spring Security 7 supports Relying Party passkey verification natively via http.webAuthn(rp -> rp.rpId("nexuscommerce.com")...)!

3. Zero-Trust Internal Mesh: Mutual TLS (mTLS)

Standard HTTPS only proves the server's X.509 identity to the client. Under Mutual TLS (mTLS) (configured cleanly via Spring Boot SSL Bundles or Istio/Linkerd), both client and server present short-lived X.509 certificates during the TLS handshake—blocking lateral movement if an attacker breaches a perimeter pod.

4. Production Dual OAuth2 Resource Server + Role Mapping (Spring Security 7)

OAuth2 Resource Server + Custom JwtAuthenticationConverter 
package com.example.ecommerce.security;

import org.springframework.context.annotation.*;
import org.springframework.security.config.Customizer;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.oauth2.server.resource.authentication.*;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class OAuth2ResourceServerConfig {

    @Bean
    public SecurityFilterChain resourceServerSecurity(HttpSecurity http) throws Exception {
        return http
            .csrf(csrf -> csrf.disable())
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/v1/public/**", "/actuator/health/**").permitAll()
                .anyRequest().authenticated()
            )
            // Verifies asymmetric RS256/ES256 JWTs against IdP JWKS public keys!
            .oauth2ResourceServer(oauth2 -> oauth2.jwt(Customizer.withDefaults()))
            .build();
    }

    @Bean
    JwtAuthenticationConverter jwtAuthenticationConverter() {
        var rolesConverter = new JwtGrantedAuthoritiesConverter();
        rolesConverter.setAuthoritiesClaimName("roles");
        rolesConverter.setAuthorityPrefix("ROLE_");
        var converter = new JwtAuthenticationConverter();
        converter.setJwtGrantedAuthoritiesConverter(rolesConverter);
        return converter;
    }
}
package com.example.ecommerce.security

import org.springframework.context.annotation.*
import org.springframework.security.config.Customizer
import org.springframework.security.config.annotation.web.builders.HttpSecurity
import org.springframework.security.config.http.SessionCreationPolicy
import org.springframework.security.oauth2.server.resource.authentication.*
import org.springframework.security.web.SecurityFilterChain

@Configuration
class OAuth2ResourceServerConfig {

    @Bean
    fun resourceServerSecurity(http: HttpSecurity): SecurityFilterChain =
        http
            .csrf { it.disable() }
            .sessionManagement { it.sessionCreationPolicy(SessionCreationPolicy.STATELESS) }
            .authorizeHttpRequests { auth ->
                auth
                    .requestMatchers("/api/v1/public/**", "/actuator/health/**").permitAll()
                    .anyRequest().authenticated()
            }
            .oauth2ResourceServer { oauth2 ->
                oauth2.jwt(Customizer.withDefaults())
            }
            .build()

    @Bean
    fun jwtAuthenticationConverter(): JwtAuthenticationConverter {
        val rolesConverter = JwtGrantedAuthoritiesConverter().apply {
            setAuthoritiesClaimName("roles")
            setAuthorityPrefix("ROLE_")
        }
        return JwtAuthenticationConverter().apply {
            setJwtGrantedAuthoritiesConverter(rolesConverter)
        }
    }
}
