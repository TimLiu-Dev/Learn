Lesson 0055 • Part 2 Phase 17

Helm / Kustomize & Software Supply-Chain Security (SBOM + Cosign)

Target: Copy-pasting raw Kubernetes YAML files across dev, staging, and prod guarantees configuration drift and accidental outages. Meanwhile, modern enterprise security requires proving what is inside every deployed Spring Boot container (CycloneDX SBOM) and guaranteeing the image was built by your trusted CI pipeline (Cosign cryptographic signatures + immutable SHA256 digests). In this lesson, we structure environment overlays with Kustomize/Helm and harden the Spring Boot delivery pipeline.

📖 Primary Source Recommendation

Study the official authorities: Kubernetes Kustomize Reference and Spring Boot Reference: CycloneDX SBOM Support.

💡 Why This Matters in Production

When the next Log4Shell-scale zero-day hits, security teams ask one urgent question: "Which running pods contain vulnerable transitive dependency X?" With Spring Boot's built-in CycloneDX SBOM support and Paketo/Trivy/Cosign verification, you know the answer in seconds and block unsigned or vulnerable images before they ever reach EKS.

Key Architectural Takeaways

  • Kustomize vs. Helm: Kustomize layers clean, template-free YAML patches (base/ + overlays/prod/) natively inside kubectl; Helm packages parameterized charts for reusable multi-service distribution.
  • Pin Immutable Image Digests: Never deploy mutable tags like :latest in production—always deploy immutable digests (@sha256:...) verified by admission controllers.
  • Built-In Spring Boot SBOMs (Boot 3.3+ / 4.0): Add the CycloneDX Maven/Gradle plugin so Spring Boot embeds META-INF/sbom/application.cdx.json and optionally exposes /actuator/sbom (internally secured!).
  • Keyless Cosign Signing & Trivy Gates: Sign every built container digest in GitHub Actions via OIDC keyless Cosign so Kubernetes admission policies (Kyverno/OPA) reject tampered images.

Production Implementation (Kustomize Overlay & GitHub Actions Supply-Chain Gate)

Kustomize Prod Overlay & CycloneDX + Cosign Pipeline 
# overlays/prod/kustomization.yaml — DRY environment patching without copy-paste
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
namespace: nexus-prod
resources:
  - ../../base
images:
  - name: ghcr.io/nexus/order-service
    digest: sha256:9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08
patches:
  - path: replica-and-hpa-patch.yaml

---
<!-- pom.xml — Embedded CycloneDX SBOM inside Spring Boot JAR/OCI image -->
<plugin>
  <groupId>org.cyclonedx</groupId>
  <artifactId>cyclonedx-maven-plugin</artifactId>
  <executions>
    <execution>
      <phase>package</phase>
      <goals><goal>makeAggregateBom</goal></goals>
    </execution>
  </executions>
</plugin>

---
# GitHub Actions: Trivy CVE Gate + Cosign Keyless Signature
- name: Scan Image & Sign Digest
  run: |
    trivy image --exit-code 1 --severity CRITICAL ghcr.io/nexus/order-service@${IMAGE_DIGEST}
    cosign sign --yes ghcr.io/nexus/order-service@${IMAGE_DIGEST}
# overlays/prod/kustomization.yaml — Identical K8s overlay works for Kotlin services

---
// build.gradle.kts — CycloneDX SBOM plugin wired into bootJar / bootBuildImage
plugins {
    id("org.cyclonedx.bom") version "1.10.0"
}
