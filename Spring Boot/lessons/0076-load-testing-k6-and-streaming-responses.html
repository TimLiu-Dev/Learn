Load Testing with k6 & Memory-Safe Streaming (StreamingResponseBody)

Target: A junior engineer assumes a Spring Boot endpoint is fast because it returned HTTP 200 in 8ms in Postman. A senior engineer proves it holds P99 < 250ms under 500 virtual users before shipping—and ensures heavy report exports never crash the JVM with OutOfMemoryError by streaming rows straight to the HTTP socket via StreamingResponseBody.

📖 Primary Source Recommendation

Study the official authorities: Grafana k6 Official Docs: Thresholds & Load Scenarios and Spring Framework Javadoc: StreamingResponseBody.

💡 Android Mental Model Bridge

Just as Android's Macrobenchmark + Perfetto measures P95/P99 frame jank instead of trusting one tap in an emulator, Grafana k6 drives realistic concurrent HTTP load against your Dockerized Spring Boot service and fails CI automatically if P99 latency or error rate crosses your threshold.

1. Why Averages Lie & How k6 Catches Pool Starvation Early

Running a single `curl` request tells you nothing about HikariCP pool exhaustion, lock contention, or GC pauses. With a 25-line JavaScript `k6` script (`k6 run load-test.js`), you ramp up concurrent Virtual Users (`vus`), define automated pass/fail SLO gates (`http_req_duration: ['p(99)<250']`, `http_req_failed: ['rate<0.01']`), and watch HikariCP / Actuator metrics in real time.

2. Stopping OOM Crashes on Exports: StreamingResponseBody + JDBC Streaming

Never load 200,000 database rows into a List<OrderDto> or ByteArrayOutputStream in heap memory before returning a CSV/JSON export! Instead:

  • Return ResponseEntity<StreamingResponseBody> so Spring writes chunks incrementally to the HTTP output stream with $O(1)$ constant heap usage (~8KB buffer).
  • Detach JPA entities (or use JdbcTemplate.queryForStream(...) / keyset pagination) and flush periodically while respecting client disconnects.

@RestController
public class OrderExportController {

    @GetMapping(value = "/api/v1/orders/export", produces = "text/csv")
    public ResponseEntity<StreamingResponseBody> exportCsv(OrderExportService exportService) {
        StreamingResponseBody body = outputStream -> {
            try (var writer = new BufferedWriter(new OutputStreamWriter(outputStream, StandardCharsets.UTF_8))) {
                writer.write("id,status,total_cents\n");
                exportService.streamRows(row -> {
                    writer.write(row.id() + "," + row.status() + "," + row.totalCents() + "\n");
                });
                writer.flush();
            }
        };
        return ResponseEntity.ok()
            .header(HttpHeaders.CONTENT_DISPOSITION, "attachment; filename=\"orders.csv\"")
            .body(body);
    }
}
@RestController
class OrderExportController(private val exportService: OrderExportService) {

    @GetMapping("/api/v1/orders/export", produces = ["text/csv"])
    fun exportCsv(): ResponseEntity<StreamingResponseBody> {
        val body = StreamingResponseBody { outputStream ->
            outputStream.bufferedWriter(Charsets.UTF_8).use { writer ->
                writer.write("id,status,total_cents\n")
                exportService.streamRows { row ->
                    writer.write("${row.id},${row.status},${row.totalCents}\n")
                }
                writer.flush()
            }
        }
        return ResponseEntity.ok()
            .header(HttpHeaders.CONTENT_DISPOSITION, "attachment; filename=\"orders.csv\"")
            .body(body)
    }
}

Lab 0076 O(1)-Memory StreamingResponseBody Lab
To Do

Construct a StreamingResponseBody lambda that wraps outputStream in a writer, iterates rows writing each line, calls writer.flush(), and returns ResponseEntity.ok().body(body).

Hint 1: Define StreamingResponseBody
Use StreamingResponseBody body = outputStream -> { ... }; (or StreamingResponseBody { outputStream -> ... } in Kotlin).
Hint 2: Stream & Flush Rows
Wrap outputStream in a BufferedWriter, iterate rows.forEach(...), and call writer.flush().
Hint 3: Return ResponseEntity
Return ResponseEntity.ok().body(body).
💡 Complete Production Reference Solution
Java 21/25 Implementation:
package com.nexus.export;

import org.springframework.http.ResponseEntity;
import org.springframework.web.servlet.mvc.method.annotation.StreamingResponseBody;
import java.io.BufferedWriter;
import java.io.OutputStreamWriter;
import java.nio.charset.StandardCharsets;
import java.util.stream.Stream;

public class ExportEndpoint {
    public static ResponseEntity<StreamingResponseBody> streamCsv(Stream<String> rows) {
        StreamingResponseBody body = outputStream -> {
            try (var writer = new BufferedWriter(new OutputStreamWriter(outputStream, StandardCharsets.UTF_8))) {
                rows.forEach(line -> {
                    try { writer.write(line + "\n"); } catch (Exception e) { throw new RuntimeException(e); }
                });
                writer.flush();
            }
        };
        return ResponseEntity.ok().body(body);
    }
}
Kotlin 2.x Implementation:
package com.nexus.export

import org.springframework.http.ResponseEntity
import org.springframework.web.servlet.mvc.method.annotation.StreamingResponseBody
import java.util.stream.Stream

object ExportEndpoint {
    fun streamCsv(rows: Stream<String>): ResponseEntity<StreamingResponseBody> {
        val body = StreamingResponseBody { outputStream ->
            outputStream.bufferedWriter(Charsets.UTF_8).use { writer ->
                rows.forEach { line -> writer.write("$line\n") }
                writer.flush()
            }
        }
        return ResponseEntity.ok().body(body)
    }
}
Architectural Breakdown:

Pairing a database cursor/stream with StreamingResponseBody keeps heap allocation flat regardless of export size, while k6 thresholds prevent P99 regressions from slipping past CI.
