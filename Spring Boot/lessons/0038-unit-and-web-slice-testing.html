Unit & Web Slice Testing (JUnit 5, Mockito, MockMvc)

Target: A senior engineer never writes a test suite that takes 15 minutes to run and boots the full Spring ApplicationContext for every minor test. Booting full Spring contexts with '@SpringBootTest' for thousands of unit tests creates slow, brittle test suites that developers skip or ignore. Modern Spring testing follows the Test Pyramid: fast pure-unit tests for business domain logic (0ms startup), focused Sliced Tests ('@WebMvcTest', '@JsonTest', '@DataJpaTest') that boot only the isolated layer under test in 200ms, and integration tests with Testcontainers. In this lesson, we master MockMvc fluent assertions, Mockito verification, and slice testing fundamentals.

📖 Primary Source Recommendation

Study the official authority: Spring Boot Testing Reference Documentation: Test Slices & JUnit 5 Official User Guide.. Ground your learning in primary architecture rather than secondary summaries.

💡 Why This Matters in Production

When a regression breaks your API response schema or HTTP status code, waiting 15 minutes for a full integration test run kills velocity. WebMvc slice testing provides millisecond-level verification of HTTP routing, Jackson serialization, input validation (@Valid), and security filter rules without touching databases or external services.

Key Architectural Takeaways

  • Use '@WebMvcTest(TargetController.class)' to test the web layer in isolation without booting database, cache, or external client beans.
  • Mock dependencies using Spring Boot 3.4+ '@MockitoBean' (replacing deprecated '@MockBean') to mock collaborators cleanly.
  • Test both happy paths and boundary conditions: verify validation constraint violations trigger RFC 7807 ProblemDetails with HTTP 400.
  • MockMvc fluent assertions: verify JSON structure with JsonPath expressions (e.g. 'jsonPath("$.title").value("...")').
  • Keep unit tests pure: services with pure domain logic should be tested with vanilla JUnit 5 and standard MockitoExtension, without any Spring annotations.
  • Use '@AutoConfigureMockMvc(addFilters = false)' only if you explicitly intend to bypass Spring Security filters during controller slice testing.

1. The Spring Boot Test Slice Matrix

Annotation Components Loaded Excluded Components Primary Target
@WebMvcTest @Controller, @ControllerAdvice, WebMvcConfigurer, Jackson @Service, @Repository, @Component HTTP status, URL routing, JSON serialization, validation.
@DataJpaTest @Repository, Entities, EntityManager, TestDataSource @Controller, @Service, Web filters Custom SQL queries, JPA mappings, Flyway migrations.
@JsonTest Jackson ObjectMapper, Serializers, Deserializers Web layer, Database Custom DTO serialization, date formatting, null handling.

2. Replacing @MockBean with @MockitoBean

Starting in Spring Boot 3.4, the legacy @MockBean and @SpyBean annotations in org.springframework.boot.test.mock.mockito were deprecated in favor of first-class Spring Framework annotations: 

// Modern Spring Boot 3.4+:
import org.springframework.test.context.bean.override.mockito.MockitoBean;

@WebMvcTest(OrderController.class)
class OrderControllerTest {
    @MockitoBean
    private OrderService orderService;
}

This unified bean overriding model provides cleaner cache keys for Spring's test context caching mechanism.

Unit & Web Slice Testing (JUnit 5, Mockito, MockMvc) 
package com.example.testing;

import com.fasterxml.jackson.databind.ObjectMapper;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.WebMvcTest;
import org.springframework.http.MediaType;
import org.springframework.test.context.bean.override.mockito.MockitoBean;
import org.springframework.test.web.servlet.MockMvc;

import java.util.UUID;

import static org.mockito.ArgumentMatchers.any;
import static org.mockito.Mockito.verify;
import static org.mockito.Mockito.when;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.post;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.*;

@WebMvcTest(OrderController.class)
class OrderControllerWebMvcTest {

    @Autowired
    private MockMvc mockMvc;

    @Autowired
    private ObjectMapper objectMapper;

    @MockitoBean
    private OrderService orderService;

    @Test
    @DisplayName("POST /api/orders with valid request returns 201 Created and OrderResponse")
    void createOrder_validInput_returnsCreated() throws Exception {
        UUID orderId = UUID.randomUUID();
        CreateOrderRequest request = new CreateOrderRequest("SKU-12345", 2);
        OrderResponse response = new OrderResponse(orderId, "SKU-12345", 2, "CONFIRMED");

        when(orderService.placeOrder(any(CreateOrderRequest.class))).thenReturn(response);

        mockMvc.perform(post("/api/orders")
                .contentType(MediaType.APPLICATION_JSON)
                .content(objectMapper.writeValueAsString(request)))
            .andExpect(status().isCreated())
            .andExpect(header().exists("Location"))
            .andExpect(jsonPath("$.id").value(orderId.toString()))
            .andExpect(jsonPath("$.sku").value("SKU-12345"))
            .andExpect(jsonPath("$.status").value("CONFIRMED"));

        verify(orderService).placeOrder(any(CreateOrderRequest.class));
    }

    @Test
    @DisplayName("POST /api/orders with negative quantity returns 400 Bad Request ProblemDetails")
    void createOrder_negativeQuantity_returnsProblemDetails() throws Exception {
        CreateOrderRequest invalidRequest = new CreateOrderRequest("SKU-12345", -5);

        mockMvc.perform(post("/api/orders")
                .contentType(MediaType.APPLICATION_JSON)
                .content(objectMapper.writeValueAsString(invalidRequest)))
            .andExpect(status().isBadRequest())
            .andExpect(jsonPath("$.type").value("https://api.example.com/errors/validation-error"))
            .andExpect(jsonPath("$.title").value("Invalid Request Content"));
    }
}

Java 21 Implementation:
package com.example.testing;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.WebMvcTest;
import org.springframework.test.context.bean.override.mockito.MockitoBean;
import org.springframework.test.web.servlet.MockMvc;

import static org.mockito.Mockito.when;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.*;

@WebMvcTest(UserController.class)
public class UserControllerTest {

    @Autowired
    private MockMvc mockMvc;

    @MockitoBean
    private UserService userService;

    @Test
    public void getUserById_returnsOkAndJson() throws Exception {
        when(userService.findById("u-101")).thenReturn(new UserDto("u-101", "alice"));

        mockMvc.perform(get("/api/users/u-101"))
            .andExpect(status().isOk())
            .andExpect(jsonPath("$.id").value("u-101"))
            .andExpect(jsonPath("$.username").value("alice"));
    }
}
