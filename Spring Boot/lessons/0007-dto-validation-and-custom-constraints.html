Fail-Fast DTO Validation & Custom Constraints

Target: 'Never trust the client'. Enforce strict input validation using Jakarta Validation, nested DTO validation, and fail-fast constraints before hitting database transactions.

📖 Primary Source Recommendation

Study the official authority: Jakarta Bean Validation Specification. Ground your learning in primary architecture rather than secondary summaries.

1. Never Trust the Client

Mobile clients may have UI validation, but attackers can easily bypass Android APKs with curl or Postman. Validation on the server is a critical security perimeter.

2. Essential Jakarta Validation Annotations

  • @NotBlank: For Strings. Rejects null, "", and whitespace-only strings " ".
  • @NotNull: For Objects, Enums, UUIDs, and Numbers.
  • @Positive / @PositiveOrZero: For monetary amounts and counts.
  • @Size(min = 1, max = 50): For collections or string lengths.
  • @Valid: Crucial for nested objects! Without @Valid on child objects/lists, nested validation annotations are ignored!

3. Production Pattern: Validated DTO Record vs Kotlin Data Class

Validated CreateOrderRequest DTO 
package com.example.ecommerce.order;

import jakarta.validation.Valid;
import jakarta.validation.constraints.*;
import java.math.BigDecimal;
import java.util.List;

public record CreateOrderRequest(
    @NotBlank(message = "customerId is required")
    String customerId,

    @NotEmpty(message = "Order must contain at least one item")
    @Valid // Validates each item in the list!
    List<OrderItemDto> items
) {}

public record OrderItemDto(
    @NotBlank String sku,
    @Positive(message = "Quantity must be > 0") int quantity,
    @Positive(message = "Price must be > 0") BigDecimal price
) {}
package com.example.ecommerce.order

import jakarta.validation.Valid
import jakarta.validation.constraints.*
import java.math.BigDecimal

data class CreateOrderRequest(
    @field:NotBlank(message = "customerId is required")
    val customerId: String,

    @field:NotEmpty(message = "Order must contain at least one item")
    @field:Valid // Validates each item in the list!
    val items: List<OrderItemDto>
)

data class OrderItemDto(
    @field:NotBlank val sku: String,
    @field:Positive(message = "Quantity must be > 0") val quantity: Int,
    @field:Positive(message = "Price must be > 0") val price: BigDecimal
)

💡 Complete Production Reference Solution
Java 21 Implementation:
package com.example.dto;

import jakarta.validation.constraints.*;
import java.math.BigDecimal;

public record OrderRequest(
    @NotBlank @Email String email,
    @Min(1) int quantity,
    @Positive BigDecimal price
) {}
Kotlin 2.x Implementation:
package com.example.dto

import jakarta.validation.constraints.*
import java.math.BigDecimal

data class OrderRequest(
    @field:NotBlank @field:Email val email: String,
    @field:Min(1) val quantity: Int,
    @field:Positive val price: BigDecimal
)
Architectural Breakdown:

Combining @NotBlank and @Email ensures empty strings are rejected. @Min(1) and @Positive protect your business domain from negative quantity or pricing fraud.
