Kubernetes Probes, Graceful Shutdown & Secrets Injection

Target: Even with rolling updates configured, organizations frequently suffer bursts of HTTP 502/504 Bad Gateway errors every time a new version deploys. Why does this happen? When Kubernetes terminates an old pod, it sends a SIGTERM signal to the container and simultaneously updates the endpoint network routing tables (iptables/ipvs) on every worker node. Updating distributed network rules takes 2–5 seconds. If Spring Boot shuts down immediately upon receiving SIGTERM, in-flight HTTP requests are severed and new requests routed to the shutting-down pod fail with connection refused. In this lesson, we eliminate deployment downtime using 'server.shutdown=graceful', container 'preStop' hooks, and external secrets injection.

Study the official authority: Spring Boot Reference: Graceful Shutdown & Kubernetes Documentation: Container Lifecycle Hooks.. Ground your learning in primary architecture rather than secondary summaries.

💡 Why This Matters in Production

A zero-downtime deployment claim is an illusion if every deployment causes 15 seconds of customer checkout failures. Configuring Spring Boot's graceful shutdown lifecycle alongside a Kubernetes 'preStop' sleep hook guarantees in-flight transactions complete and eliminates 502 Bad Gateway errors during continuous deployment cycles.

Key Architectural Takeaways

  • The Race Condition: Kubernetes sends SIGTERM to the container at the EXACT same time it instructs kube-proxy to remove the pod from endpoint routing tables.
  • Because kube-proxy takes several seconds to update iptables across all worker nodes, new traffic continues arriving at the pod for 2–5 seconds after SIGTERM.
  • The Solution: Add a 'preStop' lifecycle hook with 'sleep 10' or 'sleep 15'. This forces the container to wait while kube-proxy removes it from load balancing BEFORE Spring receives SIGTERM.
  • Configure 'server.shutdown=graceful' and 'spring.lifecycle.timeout-per-shutdown-phase=30s' so Tomcat stops accepting new connections and waits for active requests to finish.
  • Secrets Security: Never store production credentials in plain Kubernetes ConfigMaps or standard base64 Secret YAMLs in Git repos. Use External Secrets Operator (ESO) to sync secrets from AWS Secrets Manager or Vault.

1. The Zero-Downtime Termination Lifecycle

Kubernetes triggers pod termination
  │
  ├──► [ Step 1: Endpoint Controller removes Pod from Service Endpoints ]
  │       └── Kube-proxy propagates iptables changes across cluster (~3-5s)
  │
  └──► [ Step 2: Kubelet executes container preStop hook ]
          └── Exec: /bin/sleep 15
                 │
                 ▼  (15 seconds elapse: Pod receives NO more incoming traffic)
       [ Step 3: Kubelet sends SIGTERM to Spring Boot process ]
                 │
                 ▼
       [ Step 4: Spring Boot enters Graceful Shutdown phase ]
                 │  - Pauses Tomcat accept queue
                 │  - Waits up to 30s for in-flight requests to complete
                 │  - Closes HikariCP connection pool cleanly
                 ▼
       [ Step 5: Container exits cleanly (Exit Code 0) ]

2. Spring Boot Graceful Shutdown Properties

server.shutdown=graceful
spring.lifecycle.timeout-per-shutdown-phase=30s

With graceful shutdown enabled, embedded Tomcat rejects new connections with HTTP 503, but allows existing in-flight HTTP requests up to 30 seconds to finish execution and commit their database transactions.

Production Implementation (Java 21 vs Kotlin 2.x)

Kubernetes Probes, Graceful Shutdown & Secrets Injection 
# application.yml
server:
  port: 8080
  shutdown: graceful # Enables Tomcat graceful connection draining

spring:
  lifecycle:
    timeout-per-shutdown-phase: 30s # Wait up to 30s for active requests to finish

management:
  endpoints:
    web:
      exposure:
        include: "health,info,prometheus"
  endpoint:
    health:
      probes:
        enabled: true # Exposes /actuator/health/liveness and /readiness
      show-details: when_authorized

---
# Kubernetes Pod Spec with Probes & preStop Hook
apiVersion: apps/v1
kind: Deployment
metadata:
  name: payment-service
spec:
  replicas: 3
  template:
    spec:
      containers:
        - name: payment-service
          image: ghcr.io/myorg/payment-service:2.0.1
          ports:
            - containerPort: 8080
          lifecycle:
            preStop:
              exec:
                # Essential: Delay shutdown to give kube-proxy time to update iptables!
                command: ["/bin/sh", "-c", "sleep 15"]
          livenessProbe:
            httpGet:
              path: /actuator/health/liveness
              port: 8080
            initialDelaySeconds: 20
            periodSeconds: 10
            failureThreshold: 3
            timeoutSeconds: 3
          readinessProbe:
            httpGet:
              path: /actuator/health/readiness
              port: 8080
            initialDelaySeconds: 15
            periodSeconds: 5
            failureThreshold: 2
            timeoutSeconds: 3
# ExternalSecrets Operator (ESO) Definition
# Syncs credentials directly from AWS Secrets Manager into Kubernetes Secrets
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: payment-service-db-secrets
spec:
  refreshInterval: "1h"
  secretStoreRef:
    name: aws-secrets-manager
    kind: ClusterSecretStore
  target:
    name: payment-service-k8s-secret # The generated K8s Secret name
    creationPolicy: Owner
  data:
    - secretKey: DB_PASSWORD
      remoteRef:
        key: production/payment-service/database
        property: password
