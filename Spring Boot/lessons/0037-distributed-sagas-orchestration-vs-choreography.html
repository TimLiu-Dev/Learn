Distributed Sagas: Orchestration vs Choreography & Compensating Transactions

Target: In distributed microservice architectures, maintaining ACID consistency across multiple databases is impossible without distributed locks or Two-Phase Commit (2PC). However, 2PC is a toxic anti-pattern in high-throughput cloud environments: it blocks database connections across network hops, drastically elevates P99 latency, and suffers catastrophic cascading outages if the coordinator fails. The Saga Pattern is the distributed systems solution: an eventual-consistency workflow modeled as a sequence of local transactions, where each step updates a local database and emits a message. If a intermediate step fails, the system executes explicit 'Compensating Transactions' in reverse order to semantically roll back previous state changes.

📖 Primary Source Recommendation

Study the official authority: Sagas (1987) by Hector Garcia-Molina & Kenneth Salem (Princeton University) & Chris Richardson: Microservices Patterns (Saga Pattern).. Ground your learning in primary architecture rather than secondary summaries.

💡 Why This Matters in Production

Distributed failures are inevitable in real-world distributed architectures: credit card payments decline after inventory was reserved, flight bookings fail after hotels were booked, or network timeouts partition services. Without robust Sagas and compensating actions, distributed databases desynchronize into invalid business states requiring painful manual database patching.

Key Architectural Takeaways

  • Two-Phase Commit (2PC / XA transactions) does not scale in microservices due to distributed lock holding and coordinator single-points-of-failure.
  • A Saga is a sequence of local transactions: T1, T2, ..., Tn. If transaction Ti fails, compensating transactions C(i-1), ..., C1 are executed to undo earlier actions.
  • Compensating transactions are NOT physical rollbacks: they are semantic forward actions that reconcile state (e.g., if T1 was 'deduct $50', C1 is 'refund $50 credit').
  • Choreography-based Saga: Services react to domain events published to brokers (e.g. Kafka). High decoupling, but workflow logic is decentralized and difficult to visualize or trace.
  • Orchestration-based Saga: A centralized Saga Orchestrator (state machine) directs participants by sending command messages and waiting for reply events. Easier to monitor, debug, and timeout.
  • Idempotency is mandatory for all Saga participants and compensating endpoints: network retries will deliver duplicate messages.

1. Choreography vs Orchestration Tradeoffs

Dimension Choreography (Event-Driven) Orchestration (Coordinator)
Coupling Loose: Services only know about domain events. Tighter: Orchestrator knows all participant commands.
Complexity High cognitive load: cyclic dependencies and hard to debug. Centralized workflow definition (state machine).
Monitoring Requires distributed tracing (Jaeger/Tempo) to trace flow. Orchestrator tracks current state of every saga instance.
Best Fit Simple 2-3 step workflows. Complex enterprise workflows (e.g. Order -> Payment -> Inventory -> Shipping).

2. The Anatomy of a Compensating Transaction

Consider an order fulfillment saga:

  1. T1 (Order Service): Create Order in PENDING state.
  2. T2 (Inventory Service): Reserve 2 items in stock.
  3. T3 (Payment Service): Charge credit card. FAIL: Insufficient Funds!

Because T3 failed, the Saga triggers compensations in reverse:

  • C2 (Inventory Service): Release reserved items back to stock.
  • C1 (Order Service): Mark Order status as REJECTED_PAYMENT_FAILED.

3. The Pivot Transaction Concept

In every Saga, there is a Pivot Transaction. Once the pivot transaction commits, the Saga is guaranteed to proceed to completion (no compensation is possible). In the flow above, T3 (Payment) is the pivot transaction: once money is charged, subsequent failures (e.g. email receipt notification) cannot cancel the order; they must retry until successful.

package com.example.saga;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Component;
import org.springframework.stereotype.Service;

import java.util.UUID;

// 1. Saga State Definition
enum OrderSagaState {
    STARTED, INVENTORY_RESERVED, PAYMENT_PROCESSED, COMPLETED,
    INVENTORY_COMPENSATED, FAILED
}

record CreateOrderSagaContext(
    UUID sagaId,
    UUID orderId,
    String sku,
    int quantity,
    long amountCents,
    OrderSagaState state
) {}

// 2. Participant Contracts
interface InventoryClient {
    boolean reserveStock(UUID sagaId, String sku, int quantity);
    void releaseStockCompensation(UUID sagaId, String sku, int quantity);
}

interface PaymentClient {
    boolean processPayment(UUID sagaId, long amountCents);
    void refundPaymentCompensation(UUID sagaId, long amountCents);
}

// 3. Central Saga Orchestrator
@Service
class OrderSagaOrchestrator {
    private static final Logger log = LoggerFactory.getLogger(OrderSagaOrchestrator.class);
    private final InventoryClient inventoryClient;
    private final PaymentClient paymentClient;

    public OrderSagaOrchestrator(InventoryClient inventoryClient, PaymentClient paymentClient) {
        this.inventoryClient = inventoryClient;
        this.paymentClient = paymentClient;
    }

    public boolean executeOrderSaga(UUID orderId, String sku, int quantity, long amountCents) {
        UUID sagaId = UUID.randomUUID();
        log.info("Starting Order Saga [{}] for Order [{}]", sagaId, orderId);

        // Step 1: Execute T1 (Inventory Reservation)
        boolean inventoryReserved = inventoryClient.reserveStock(sagaId, sku, quantity);
        if (!inventoryReserved) {
            log.error("Saga [{}] Step 1 Failed: Out of stock. Aborting saga.", sagaId);
            return false;
        }
        log.info("Saga [{}] Step 1 Succeeded: Inventory reserved.", sagaId);

        // Step 2: Execute T2 (Payment Processing - The Pivot Step)
        boolean paymentSuccess = paymentClient.processPayment(sagaId, amountCents);
        if (!paymentSuccess) {
            log.warn("Saga [{}] Step 2 Failed: Payment declined! Initiating compensation...", sagaId);
            // Execute Compensating Action C1 in reverse order:
            inventoryClient.releaseStockCompensation(sagaId, sku, quantity);
            log.info("Saga [{}] Compensating Action C1 Completed: Inventory released.", sagaId);
            return false;
        }

        log.info("Saga [{}] Step 2 Succeeded: Payment captured. Saga COMPLETED successfully.", sagaId);
        return true;
    }
}
package com.example.saga

import org.slf4j.LoggerFactory
import org.springframework.stereotype.Service
import java.util.UUID

enum class OrderSagaState {
    STARTED, INVENTORY_RESERVED, PAYMENT_PROCESSED, COMPLETED, INVENTORY_COMPENSATED, FAILED
}

interface InventoryClient {
    fun reserveStock(sagaId: UUID, sku: String, quantity: Int): Boolean
    fun releaseStockCompensation(sagaId: UUID, sku: String, quantity: Int)
}

interface PaymentClient {
    fun processPayment(sagaId: UUID, amountCents: Long): Boolean
    fun refundPaymentCompensation(sagaId: UUID, amountCents: Long)
}

@Service
class OrderSagaOrchestrator(
    private val inventoryClient: InventoryClient,
    private val paymentClient: PaymentClient
) {
    private val log = LoggerFactory.getLogger(OrderSagaOrchestrator::class.java)

    fun executeOrderSaga(orderId: UUID, sku: String, quantity: Int, amountCents: Long): Boolean {
        val sagaId = UUID.randomUUID()
        log.info("Starting Order Saga [$sagaId] for Order [$orderId]")

        // Step 1: Inventory Reservation (T1)
        if (!inventoryClient.reserveStock(sagaId, sku, quantity)) {
            log.error("Saga [$sagaId] Step 1 Failed: Out of stock.")
            return false
        }

        // Step 2: Payment Processing (T2 - Pivot)
        if (!paymentClient.processPayment(sagaId, amountCents)) {
            log.warn("Saga [$sagaId] Step 2 Failed: Payment declined! Compensating...")
            // Compensate C1
            inventoryClient.releaseStockCompensation(sagaId, sku, quantity)
            return false
        }

        log.info("Saga [$sagaId] Completed successfully.")
        return true
    }
}

package com.example.saga;

import java.util.UUID;

interface TravelBookingClient {
    boolean bookFlight(UUID sagaId);
    void cancelFlightCompensation(UUID sagaId);
    boolean bookHotel(UUID sagaId);
}

public class TravelSagaOrchestrator {
    private final TravelBookingClient client;

    public TravelSagaOrchestrator(TravelBookingClient client) {
        this.client = client;
    }

    public boolean bookVacation(UUID sagaId) {
        boolean flightOk = client.bookFlight(sagaId);
        if (!flightOk) return false;

        boolean hotelOk = client.bookHotel(sagaId);
        if (!hotelOk) {
            client.cancelFlightCompensation(sagaId);
            return false;
        }

        return true;
    }
}

package com.example.saga

import java.util.UUID

interface TravelBookingClient {
    fun bookFlight(sagaId: UUID): Boolean
    fun cancelFlightCompensation(sagaId: UUID)
    fun bookHotel(sagaId: UUID): Boolean
}

class TravelSagaOrchestrator(private val client: TravelBookingClient) {

    fun bookVacation(sagaId: UUID): Boolean {
        if (!client.bookFlight(sagaId)) return false

        if (!client.bookHotel(sagaId)) {
            client.cancelFlightCompensation(sagaId)
            return false
        }

        return true
    }
}
