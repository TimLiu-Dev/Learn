Kafka Schema Registry & Exactly-Once Semantics (EOS)

Target: Prevent distributed contract breaks and duplicate transactions. Master Schema Registry governance (Avro/Protobuf), backward/forward compatibility rules, and Kafka Exactly-Once Semantics (EOS).

📖 Primary Source Recommendation

Study the official authority: Confluent: Schema Registry and Exactly-Once Semantics. Ground your learning in primary architecture rather than secondary summaries.

1. Why Plain JSON in Kafka Causes Production Outages

When you send arbitrary JSON strings over Kafka, there is no schema enforcement. If Team A renames field user_id to userId, all downstream consumer microservices crash with deserialization errors!

Schema Registry (Confluent / Apicurio): Acts as a central contract governor. Producers and consumers compile binary schemas (Apache Avro or Protobuf). If a producer tries to publish an event that violates the schema compatibility rules (e.g. removing a mandatory field), Schema Registry rejects the message at the producer gate!

2. Exactly-Once Semantics (EOS): How It Works

By default, Kafka provides At-Least-Once delivery (if network drops during ack, message is redelivered). To achieve true Exactly-Once Processing (EOS):

1. Idempotent Producer: `enable.idempotence=true` (Producer attaches sequence number + PID; broker discards duplicates!) 2. Transactional Messaging: `transactional.id=tx-order-` Allows writing to Kafka and committing consumer offsets atomically: `read -> process -> write to Kafka & commit offset` in ONE transaction!

3. Production Dual Java & Kotlin Exactly-Once Config

Kafka Exactly-Once Producer Configuration 
package com.example.ecommerce.kafka;

import org.apache.kafka.clients.producer.ProducerConfig;
import org.springframework.context.annotation.*;
import org.springframework.kafka.core.*;
import java.util.*;

@Configuration
public class KafkaEosConfig {

    @Bean
    public ProducerFactory<String, String> producerFactory() {
        Map<String, Object> props = new HashMap<>();
        props.put(ProducerConfig.BOOTSTRAP_SERVERS_CONFIG, "localhost:9092");
        
        // 1. Enable Idempotence:
        props.put(ProducerConfig.ENABLE_IDEMPOTENCE_CONFIG, true);
        props.put(ProducerConfig.ACKS_CONFIG, "all");
        props.put(ProducerConfig.RETRIES_CONFIG, Integer.MAX_VALUE);
        
        // 2. Transactional ID Prefix:
        DefaultKafkaProducerFactory<String, String> factory = new DefaultKafkaProducerFactory<>(props);
        factory.setTransactionIdPrefix("tx-order-");
        return factory;
    }
}
package com.example.ecommerce.kafka

import org.apache.kafka.clients.producer.ProducerConfig
import org.springframework.context.annotation.*
import org.springframework.kafka.core.*

@Configuration
class KafkaEosConfig {

    @Bean
    fun producerFactory(): ProducerFactory<String, String> {
        val props = mutableMapOf<String, Any>(
            ProducerConfig.BOOTSTRAP_SERVERS_CONFIG to "localhost:9092",
            ProducerConfig.ENABLE_IDEMPOTENCE_CONFIG to true,
            ProducerConfig.ACKS_CONFIG to "all",
            ProducerConfig.RETRIES_CONFIG to Int.MAX_VALUE
        )
        return DefaultKafkaProducerFactory<String, String>(props).apply {
            setTransactionIdPrefix("tx-order-")
        }
    }
}

💡 Complete Production Reference Solution
Java 21 Implementation:
package com.example.kafka;

import org.apache.kafka.clients.producer.ProducerConfig;
import java.util.Map;

public class KafkaConfigHelper {
    public static void configureIdempotence(Map<String, Object> props) {
        props.put(ProducerConfig.ENABLE_IDEMPOTENCE_CONFIG, true);
        props.put(ProducerConfig.ACKS_CONFIG, "all");
    }
}
Kotlin 2.x Implementation:
package com.example.kafka

import org.apache.kafka.clients.producer.ProducerConfig

object KafkaConfigHelper {
    fun configureIdempotence(props: MutableMap<String, Any>) {
        props[ProducerConfig.ENABLE_IDEMPOTENCE_CONFIG] = true
        props[ProducerConfig.ACKS_CONFIG] = "all"
    }
}
Architectural Breakdown:

Enabling idempotence with acks=all guarantees that retried network writes do not duplicate records on Kafka brokers.
