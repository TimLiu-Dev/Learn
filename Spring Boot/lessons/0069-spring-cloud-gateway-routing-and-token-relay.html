Spring Cloud Gateway: Edge Routing, Rate Limiting & OAuth2 TokenRelay

Target: When you run 10 internal microservices behind one public hostname (api.nexuscommerce.com), exposing every pod directly creates duplicated CORS, auth, rate limiting, and TLS headaches. Spring Cloud Gateway (available in both classic Server WebFlux and modern Virtual-Thread-friendly Server WebMvc!) serves as a programmable Java/Kotlin API Gateway—centralizing path routing, Redis Token Bucket rate limiting, Circuit Breakers, and the BFF TokenRelay pattern.

📖 Primary Source Recommendation

Study the official authority: Spring Cloud Gateway Reference (Server WebMvc & Filters).

💡 Why This Matters in Production

Think of the TokenRelay / BFF (Backend for Frontend) pattern as zero-token-exposure security for web & mobile clients: the Gateway completes OAuth2 login, keeps refresh tokens safely in server-side Redis sessions, and forwards short-lived JWT access tokens downstream via TokenRelay—so malicious browser XSS scripts can never steal refresh tokens!

Key Architectural Takeaways

  • Gateway Responsibilities (Cross-Cutting Edge): Path-based routing (/api/orders/** → http://order-service:8080), Redis-backed per-user/IP rate limiting, header sanitization (stripping spoofed internal headers from external clients!), and Resilience4j circuit breaker fallbacks.
  • Spring Cloud Gateway Server WebMvc (Spring Boot 3.2+ / 4.0): Runs on Spring MVC + Java 21/25 Virtual Threads instead of forcing reactive Netty/WebFlux mental overhead.
  • TokenRelay Filter: Automatically forwards the authenticated OAuth2 access token from the edge gateway down to internal Resource Server microservices.
  • When NOT to Overbuild a Gateway: Never put heavy domain business logic or cross-service DB joins inside your API Gateway—keep the gateway thin and stateless.

Production Implementation (Spring Cloud Gateway WebMvc Routes & Filters)

Declarative Gateway YAML + Java/Kotlin Functional Route 
# application.yml — Spring Cloud Gateway Server WebMvc
spring:
  cloud:
    gateway:
      mvc:
        routes:
          - id: order-service-route
            uri: http://order-service:8080
            predicates:
              - Path=/api/v1/orders/**
            filters:
              - RemoveRequestHeader=X-Internal-Admin
              - TokenRelay=
              - CircuitBreaker=orderServiceCB,forward:/fallback/orders

---
// Programmatic Java DSL Route (Spring Cloud Gateway Server WebMvc)
@Bean
public RouterFunction<ServerResponse> orderGatewayRoute() {
    return GatewayRouterFunctions.route("order-service-route")
        .route(RequestPredicates.path("/api/v1/orders/**"), HandlerFunctions.http("http://order-service:8080"))
        .before(BeforeFilterFunctions.removeRequestHeader("X-Internal-Admin"))
        .filter(FilterFunctions.circuitBreaker("orderServiceCB", URI.create("forward:/fallback/orders")))
        .build();
}
