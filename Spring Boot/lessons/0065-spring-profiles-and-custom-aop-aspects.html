Spring Profiles & Custom AOP Aspects (@Aspect / @Around)

Target: Two everyday Spring Boot primitives show up in nearly every codebase and technical screen: Spring Profiles (activating environment-specific beans and layering application-prod.yml over application.yml) and custom AOP Aspects (building reusable cross-cutting interceptors such as audit logging, tenant validation, or execution timing without duplicating boilerplate across 40 services). In this lesson, we prevent dangerous dev-bean leaks in production with @Profile("!prod") and write a safe custom @Around aspect ordered cleanly relative to @Transactional.

📖 Primary Source Recommendation

Study the official authorities: Spring Boot Reference: Profiles and Spring Framework Core: Aspect-Oriented Programming (AOP).

💡 Android Mental Model Bridge

Think of Spring Profiles like Android Gradle buildTypes / productFlavors—except resolved at container startup via SPRING_PROFILES_ACTIVE=prod so one single immutable Docker image runs identically across dev, staging, and production. Think of AOP @Around as an OkHttp Interceptor wrapped around Spring bean method invocations!

Key Architectural Takeaways

  • Profile Property Layering: Always put shared defaults in application.yml and environment overrides in application-prod.yml. Activate via environment variable SPRING_PROFILES_ACTIVE=prod—never compile different JARs per environment!
  • Negated Profile Guards (@Profile("!prod")): Protect dangerous development helpers (data seeders, mock payment gateways, relaxed CORS) with @Profile("!prod") or @Profile("local | dev") so they never register in production beans.
  • Custom AOP (@Aspect + @Around): Match methods cleanly using a custom marker annotation (@annotation(AuditAction)) rather than brittle wildcard package strings; always return joinPoint.proceed()!
  • Proxy & Ordering Rules: Custom aspects share Spring's proxy mechanism—meaning internal this.method() calls bypass aspects just like @Transactional, and @Order controls whether your aspect wraps outside or inside database transactions.

Production Implementation (Java 21/25 vs Kotlin 2.x)

@Profile Guarded Bean + Custom @Around Audit Aspect 
@Component
@Profile("!prod") // Never loads in production!
public class DevSeedRunner implements CommandLineRunner {
    @Override
    public void run(String... args) { /* seed test products locally */ }
}

---
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface AuditAction {
    String value();
}

@Aspect
@Component
@Order(1) // Runs BEFORE @Transactional (Ordered.LOWEST_PRECEDENCE)
public class AuditAspect {
    private static final Logger log = LoggerFactory.getLogger(AuditAspect.class);

    @Around("@annotation(auditAction)")
    public Object auditExecution(ProceedingJoinPoint pjp, AuditAction auditAction) throws Throwable {
        long start = System.nanoTime();
        try {
            return pjp.proceed();
        } finally {
            long ms = (System.nanoTime() - start) / 1_000_000;
            log.info("action={} method={} durationMs={}", auditAction.value(), pjp.getSignature().getName(), ms);
        }
    }
}
@Component
@Profile("!prod")
class DevSeedRunner : CommandLineRunner {
    override fun run(vararg args: String) { /* seed test products locally */ }
}

@Target(AnnotationTarget.FUNCTION)
@Retention(AnnotationRetention.RUNTIME)
annotation class AuditAction(val value: String)

@Aspect
@Component
@Order(1)
class AuditAspect {
    private val log = LoggerFactory.getLogger(AuditAspect::class.java)

    @Around("@annotation(auditAction)")
    fun auditExecution(pjp: ProceedingJoinPoint, auditAction: AuditAction): Any? {
        val start = System.nanoTime()
        return try {
            pjp.proceed()
        } finally {
            val ms = (System.nanoTime() - start) / 1_000_000
            log.info("action={} method={} durationMs={}", auditAction.value, pjp.signature.name, ms)
        }
    }
}

public class DevDataLoader { }

@Aspect
@Component
@Order(1)
public class TimingAspect {
    @Around("@annotation(auditAction)")
    public Object measure(ProceedingJoinPoint pjp, AuditAction auditAction) throws Throwable {
        return pjp.proceed();
    }
}
