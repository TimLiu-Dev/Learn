Spring for Apache Kafka: Producers, Consumer Groups & Partitions

Target: Master Spring Kafka in production. Understand partition key hashing, ordering guarantees, consumer group scaling, and authoring robust @KafkaListener components.

📖 Primary Source Recommendation

Study the official authority: Spring for Apache Kafka Reference Documentation. Ground your learning in primary architecture rather than secondary summaries.

1. The Sacred Rule of Kafka Ordering

⚠️ The Universal Law of Kafka Ordering

Kafka ONLY guarantees message ordering within a single PARTITION! There is NO global ordering across a topic. If you publish Order #100 events (Created, Paid, Shipped) without a partition key, they scatter randomly across partitions, and "Shipped" may be processed before "Created"! The Solution: Always pass the entity ID as the partition key! Kafka hashes the key (murmur2(orderId) % partitionCount), guaranteeing that all events for Order #100 land in the exact same partition in strict chronological order.

2. Consumer Groups & Horizontal Scaling

If a topic has 4 partitions and your consumer group has:

  • 2 Pods: Each pod reads from 2 partitions.
  • 4 Pods: Perfect 1:1 mapping (each pod processes 1 partition).
  • 5 Pods: The 5th pod sits completely idle! A partition can only be consumed by one consumer in a group at any given time.

3. Production Dual Kafka Producer & Consumer

Kafka Producer & Listener 
package com.example.ecommerce.kafka;

import org.springframework.kafka.annotation.KafkaListener;
import org.springframework.kafka.core.KafkaTemplate;
import org.springframework.kafka.support.KafkaHeaders;
import org.springframework.messaging.handler.annotation.Header;
import org.springframework.stereotype.Service;

@Service
public class OrderKafkaService {

    private final KafkaTemplate<String, String> kafkaTemplate;

    public OrderKafkaService(KafkaTemplate<String, String> kafkaTemplate) {
        this.kafkaTemplate = kafkaTemplate;
    }

    public void sendOrderEvent(String orderId, String jsonPayload) {
        // orderId is the message KEY for partition ordering!
        kafkaTemplate.send("orders.v1", orderId, jsonPayload);
    }

    @KafkaListener(topics = "orders.v1", groupId = "inventory-service")
    public void handleOrder(String payload, 
                            @Header(KafkaHeaders.RECEIVED_KEY) String orderId,
                            @Header(KafkaHeaders.RECEIVED_PARTITION) int partition) {
        System.out.println("Processing order " + orderId + " from partition " + partition);
    }
}

package com.example.kafka;

import org.springframework.kafka.annotation.KafkaListener;
import org.springframework.stereotype.Service;

@Service
public class OrderListener {

Architectural Breakdown:

@KafkaListener instructs Spring to spin up a background poll loop on the designated topic and partition, deserializing records and passing them to your method.
