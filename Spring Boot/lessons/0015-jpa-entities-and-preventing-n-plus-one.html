JPA Entities, Lazy Loading & Preventing N+1 Queries

Target: Master Hibernate internals. Learn why lazy loading causes the catastrophic N+1 query problem, solve it permanently with JOIN FETCH, and understand why data class is banned on JPA entities.

📖 Primary Source Recommendation

Study the official authority: High-Performance Java Persistence: The N+1 Query Problem (Vlad Mihalcea). Ground your learning in primary architecture rather than secondary summaries.

1. What Is the N+1 Query Problem?

Imagine you have 100 Order rows, each with multiple OrderItem rows. You query: List<Order> orders = orderRepo.findAll();.

  • Query 1 runs to fetch 100 orders: SELECT * FROM orders; (1 query).
  • As you loop through each order to get its items, Hibernate transparently fires an individual query for each order: SELECT * FROM order_items WHERE order_id = ?; (100 additional queries!).

Instead of 1 fast query, you just executed 101 database queries over the network! In production, this causes massive database latency and connection pool exhaustion.

2. The Senior Solution: `JOIN FETCH`

Do NOT set fetch = EAGER (which causes unexpected joins across your entire database). Keep fetch = LAZY on entity relationships, and use JOIN FETCH explicitly when you need the children: 

@Query("SELECT o FROM OrderEntity o JOIN FETCH o.items WHERE o.status = :status")
List<OrderEntity> findOrdersWithItems(@Param("status") String status);

Hibernate executes exactly 1 SQL query using an inner/left join, fetching parents and children together in one network roundtrip!

3. Why `data class` Is Banned on JPA Entities

⚠️ Kotlin Trap: Never Use `data class` for Entities!

A Kotlin data class automatically generates equals(), hashCode(), and toString() based on every property. If Order references OrderItem and OrderItem references Order, calling equals() triggers infinite mutual recursion leading to a StackOverflowError, or forces Hibernate to prematurely initialize all lazy collections! Always use standard class and base equals() strictly on the entity ID.

4. Production Dual Entity Implementation

Production JPA Entities (Java 21 vs Kotlin) 
package com.example.ecommerce.order;

import jakarta.persistence.*;
import java.util.*;

@Entity
@Table(name = "orders")
public class OrderEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String status;

    // Always FetchType.LAZY!
    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL, fetch = FetchType.LAZY)
    private List<OrderItemEntity> items = new ArrayList<>();

    // Correct equals & hashCode based on ID!
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof OrderEntity that)) return false;
        return id != null && id.equals(that.id);
    }

    @Override
    public int hashCode() {
        return getClass().hashCode();
    }
}
package com.example.ecommerce.order

import jakarta.persistence.*

// Standard class, NOT data class!
@Entity
@Table(name = "orders")
class OrderEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    var id: Long? = null

    var status: String = "PENDING"

    @OneToMany(mappedBy = "order", cascade = [CascadeType.ALL], fetch = FetchType.LAZY)
    var items: MutableList<OrderItemEntity> = mutableListOf()

    override fun equals(other: Any?): Boolean {
        if (this === other) return true
        if (other !is OrderEntity) return false
        return id != null && id == other.id
    }

    override fun hashCode(): Int = javaClass.hashCode()
}

💡 Complete Production Reference Solution
Java 21 Implementation:
package com.example.repository;

import org.springframework.data.jpa.repository.*;
import org.springframework.data.repository.query.Param;
import java.util.List;

public interface OrderRepository extends JpaRepository<OrderEntity, Long> {
    @Query("SELECT o FROM OrderEntity o JOIN FETCH o.items WHERE o.status = :status")
    List<OrderEntity> findAllWithItemsByStatus(@Param("status") String status);
}
Kotlin 2.x Implementation:
package com.example.repository

import org.springframework.data.jpa.repository.*
import org.springframework.data.repository.query.Param

interface OrderRepository : JpaRepository<OrderEntity, Long> {
    @Query("SELECT o FROM OrderEntity o JOIN FETCH o.items WHERE o.status = :status")
    fun findAllWithItemsByStatus(@Param("status") status: String): List<OrderEntity>
}
Architectural Breakdown:

By using JOIN FETCH, Hibernate loads orders and their line items in a single SQL query, reducing network roundtrips from 101 queries down to 1.
