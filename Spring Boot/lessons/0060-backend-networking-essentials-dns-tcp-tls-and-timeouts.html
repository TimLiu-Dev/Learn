Lesson 0060 • Stage 3 • Phase 14

Backend Networking Essentials: DNS, TCP Keep-Alive Pools, Timeouts, TLS SSL Bundles & L4 vs. L7 Load Balancers

Target: You do not need to memorize BGP routing tables to be a Senior Spring Boot Engineer, but you must understand the network hop between your Spring Boot pod and downstream databases or APIs. When production slows down at 2 AM, 80% of network incidents boil down to five things: missing connectTimeout / readTimeout, TCP ephemeral port exhaustion (no Keep-Alive connection pool), stale JVM DNS caching, TLS certificate failures (fixed cleanly with Spring Boot SSL Bundles), and L4 vs. L7 load-balancing mismatches.

📖 Primary Source Recommendation

Study the official authorities: Spring Boot Reference: SSL Bundles and Spring Boot Reference: HTTP Client Configuration & Timeouts.

💡 Android Mental Model Bridge

On Android, OkHttpClient gives you a shared TCP/TLS connection pool, sane 10-second timeouts, and system CA certificates out of the box. On a Spring Boot server, creating a fresh HttpClient per request or leaving timeouts unbounded will exhaust Linux ephemeral ports (TIME_WAIT) and hang every Virtual Thread or Tomcat worker until the pod locks up!

1. The 5 Networking Rules Every Senior Spring Boot Engineer Knows

  • Always Set Explicit connectTimeout and readTimeout: connectTimeout (e.g., 2s) bounds the TCP 3-way handshake; readTimeout (e.g., 5s) bounds how long your thread waits between response packets. Never leave either infinite.
  • Reuse Connections via HTTP Keep-Alive Pools: Each brand-new HTTPS socket pays a TCP handshake + TLS 1.3 handshake (~30–100ms) and occupies an ephemeral port in TIME_WAIT for 60s after closing. Use a single singleton RestClient backed by a pooled HttpClient (Apache HttpComponents 5 or Jetty) so Keep-Alive sockets are reused.
  • Spring Boot SSL Bundles (spring.ssl.bundle.*): When calling internal HTTPS services signed by a private enterprise CA (avoiding the dreaded PKIX path building failed error), never disable certificate verification! Configure a PEM/JKS truststore declaratively via spring.ssl.bundle.pem.* and wire it into RestClientSsl.
  • JVM DNS Caching (networkaddress.cache.ttl): Cloud load balancers (AWS ALB, RDS) rotate IPs frequently. Ensure your JVM does not cache DNS records forever (set -Dsun.net.inetaddr.ttl=30 or configure java.security DNS TTL to 30s).
  • L4 (TCP) vs. L7 (HTTP) Load Balancers + CLI Triage: An L4 NLB balances raw TCP connections (breaks HTTP/2 multiplexing across pods—one persistent gRPC connection sticks to a single pod!). An L7 ALB / Nginx terminates TLS and balances individual HTTP requests. Keep three CLI tools in your muscle memory: curl -v https://... (TLS + headers), dig +short api.internal (DNS), and nc -zv db-host 5432 (raw TCP reachability).

1. Anatomy of an Outbound HTTPS Request & Where Timeouts Apply

[ RestClient ] ──► 1. DNS Lookup (JVM TTL=30s) ──► 2. TCP SYN/ACK + TLS 1.3 (connectTimeout = 2s) │ [ Reuse Keep-Alive Socket Pool ] ◄────────────────────────┴──► 3. Wait for Response Bytes (readTimeout = 5s)

2. Network Timeout & Pooling Checklist Across Stack Layers

Layer Critical Setting Failure If Left at Default
Outbound RestClient connectTimeout=2s, readTimeout=5s Infinite socket read blocks Virtual Threads & upstream callers
Connection Pool Idle TTL Keep-Alive idle < Cloud NAT / ALB idle timeout (e.g., 45s < 60s) Intermittent Connection reset by peer on half-closed sockets!
JVM DNS Cache networkaddress.cache.ttl=30 Pods keep calling stale RDS/ALB IP after Multi-AZ failover

Always ensure your client HTTP pool's idle eviction timeout (e.g., 45 seconds) is shorter than the upstream load balancer's idle timeout (typically 60 seconds on AWS ALB), eliminating sporadic SocketException: Connection reset errors when reusing stale idle connections.

2. Production Implementation (Java 25 vs Kotlin 2.2+)

Pooled, Timeout-Bounded RestClient with Spring Boot SSL Bundle 
# application.yml — Spring Boot 3.1+/4.0 Declarative SSL Bundle
# spring:
#   ssl:
#     bundle:
#       pem:
#         internal-ca:
#           truststore:
#             certificate: "classpath:certs/internal-ca.pem"

package com.nexus.networking;

import org.springframework.boot.autoconfigure.ssl.SslBundles;
import org.springframework.boot.http.client.ClientHttpRequestFactoryBuilder;
import org.springframework.boot.http.client.ClientHttpRequestFactorySettings;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.client.RestClient;

import java.time.Duration;

@Configuration
public class NetworkClientConfig {

    @Bean
    RestClient ledgerRestClient(RestClient.Builder builder, SslBundles sslBundles) {
        var settings = ClientHttpRequestFactorySettings.defaults()
            .withConnectTimeout(Duration.ofSeconds(2))
            .withReadTimeout(Duration.ofSeconds(5))
            .withSslBundle(sslBundles.getBundle("internal-ca"));

        var requestFactory = ClientHttpRequestFactoryBuilder.detect().build(settings);

        return builder
            .baseUrl("https://ledger.internal:8443")
            .requestFactory(requestFactory)
            .build();
    }
}

Java 25 Implementation:
package com.nexus.networking;

import org.springframework.boot.autoconfigure.ssl.SslBundles;
import org.springframework.boot.http.client.ClientHttpRequestFactoryBuilder;
import org.springframework.boot.http.client.ClientHttpRequestFactorySettings;
import org.springframework.web.client.RestClient;
import java.time.Duration;

public class SecureClientFactory {
    public static RestClient create(RestClient.Builder builder, SslBundles sslBundles) {
        var settings = ClientHttpRequestFactorySettings.defaults()
            .withConnectTimeout(Duration.ofSeconds(2))
            .withReadTimeout(Duration.ofSeconds(5))
            .withSslBundle(sslBundles.getBundle("internal-ca"));
        var requestFactory = ClientHttpRequestFactoryBuilder.detect().build(settings);
        return builder
            .baseUrl("https://ledger.internal")
            .requestFactory(requestFactory)
            .build();
    }
}
Kotlin 2.x Implementation:
package com.nexus.networking

import org.springframework.boot.autoconfigure.ssl.SslBundles
import org.springframework.boot.http.client.ClientHttpRequestFactoryBuilder
import org.springframework.boot.http.client.ClientHttpRequestFactorySettings
import org.springframework.web.client.RestClient
import java.time.Duration

object SecureClientFactory {
    fun create(builder: RestClient.Builder, sslBundles: SslBundles): RestClient {
        val settings = ClientHttpRequestFactorySettings.defaults()
            .withConnectTimeout(Duration.ofSeconds(2))
            .withReadTimeout(Duration.ofSeconds(5))
            .withSslBundle(sslBundles.getBundle("internal-ca"))
        val requestFactory = ClientHttpRequestFactoryBuilder.detect().build(settings)
        return builder
            .baseUrl("https://ledger.internal")
            .requestFactory(requestFactory)
            .build()
    }
}
Architectural Breakdown:

Binding a singleton RestClient with bounded connect/read timeouts and a declarative Spring Boot SSL Bundle gives you Keep-Alive connection reuse, fast failure on network blackholes, and zero-hack private CA trust.
