Spring @Async, Bounded ThreadPoolTaskExecutor & TaskDecorator Context Propagation

Target: Putting @Async on a Spring service method without configuring a custom executor triggers two silent production disasters: Spring's default SimpleAsyncTaskExecutor either creates unbounded threads or ignores your bounded pool limits, and ThreadLocal context (SLF4J MDC trace IDs and Spring Security SecurityContext) vanishes on the worker thread! Master bounded ThreadPoolTaskExecutor sizing, CallerRunsPolicy backpressure, and TaskDecorator context propagation.

📖 Primary Source Recommendation

Study the official authorities: Spring Framework Reference: Task Execution & Scheduling and Spring Javadoc: TaskDecorator.

💡 Android Mental Model Bridge

Just as Android's CoroutineContext carries job cancellation and dispatchers down to child tasks, Spring's TaskDecorator intercepts a Runnable right before leaving the HTTP request thread, snapshots the caller's MDC map (traceId) and SecurityContext, restores them inside the worker thread's try block, and clears them in finally so pooled threads never leak user context!

1. Three Silent @Async Traps in Production Spring Boot

  • Trap 1 — Unbounded Queue OOMs (queueCapacity = Integer.MAX_VALUE): Never leave queueCapacity unbounded! If an email or webhook provider stalls, millions of queued lambdas eat container RAM until OOMKilled (137). Set explicit bounds (e.g. core=8, max=16, queue=200) and RejectedExecutionHandler (CallerRunsPolicy for natural backpressure, or throw + alert).
  • Trap 2 — Lost traceId & SecurityContext: Because SLF4J MDC and SecurityContextHolder store state in ThreadLocal, background @Async logs print empty traceId="" unless you wire a TaskDecorator (or Micrometer's ContextPropagatingTaskDecorator).
  • Trap 3 — Self-Invocation & Swallowed void Exceptions: Like @Transactional, @Async runs through a Spring AOP proxy—calling this.sendAsync() runs synchronously! Also, uncaught exceptions in @Async void methods never reach callers unless you register an AsyncUncaughtExceptionHandler.

2. Production Implementation (Java 21/25 vs Kotlin 2.x)

Bounded @Async Executor with MDC TaskDecorator & Graceful Shutdown 
package com.nexus.async;

import org.slf4j.MDC;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.task.TaskDecorator;
import org.springframework.scheduling.annotation.EnableAsync;
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor;
import java.util.Map;
import java.util.concurrent.Executor;
import java.util.concurrent.ThreadPoolExecutor;

@Configuration
@EnableAsync
public class AsyncExecutorConfig {

    @Bean(name = "notificationExecutor")
    public Executor notificationExecutor() {
        var executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(8);
        executor.setMaxPoolSize(16);
        executor.setQueueCapacity(200);
        executor.setThreadNamePrefix("notify-");
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
        executor.setWaitForTasksToCompleteOnShutdown(true);
        executor.setAwaitTerminationSeconds(20);
        executor.setTaskDecorator(mdcTaskDecorator());
        executor.initialize();
        return executor;
    }

    private TaskDecorator mdcTaskDecorator() {
        return runnable -> {
            Map<String, String> contextMap = MDC.getCopyOfContextMap();
            return () -> {
                try {
                    if (contextMap != null) MDC.setContextMap(contextMap);
                    runnable.run();
                } finally {
                    MDC.clear(); // Prevent ThreadLocal leak across pooled threads!
                }
            };
        };
    }
}

import org.slf4j.MDC;

package com.nexus.async

import org.slf4j.MDC
import org.springframework.core.task.TaskDecorator
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor
import java.util.concurrent.ThreadPoolExecutor

object SafeExecutorFactory {
    fun buildExecutor(): ThreadPoolTaskExecutor =
        ThreadPoolTaskExecutor().apply {
            corePoolSize = 8
            maxPoolSize = 16
            queueCapacity = 200
            setRejectedExecutionHandler(ThreadPoolExecutor.CallerRunsPolicy())

            setTaskDecorator(TaskDecorator { runnable ->
                val map = MDC.getCopyOfContextMap()

                    try {
                        if (map != null) MDC.setContextMap(map)

                        MDC.clear()

            initialize()
        }
}
Architectural Breakdown:

Bounded queues prevent OOM crashes during downstream outages, setWaitForTasksToCompleteOnShutdown protects in-flight work on SIGTERM, and TaskDecorator keeps distributed trace IDs intact without ThreadLocal leaks.
