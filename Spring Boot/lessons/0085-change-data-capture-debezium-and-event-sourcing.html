Change Data Capture (Debezium + PostgreSQL WAL) & Event Sourcing

Target: In Lesson 0040 you learned the Transactional Outbox pattern. Polling the outbox_events table every 500ms works at small scale, but hits PostgreSQL with constant SELECT churn at 20,000 events/sec. Enterprise teams replace polling with Change Data Capture (CDC) via Debezium + Kafka Connect reading PostgreSQL's Write-Ahead Log (WAL) directly—and know when true Event Sourcing (append-only immutable ledger + Snapshots) makes sense vs. standard CRUD + Outbox.

📖 Primary Source Recommendation

Study the official authorities: Debezium Documentation: Outbox Event Router and Microservices.io: Event Sourcing & Snapshots.

💡 Android Mental Model Bridge

Think of PostgreSQL's Write-Ahead Log (WAL) like a sequential Git commit log of every row change. Debezium attaches to PostgreSQL as a logical replication consumer (pgoutput), reads committed outbox inserts straight from disk in milliseconds with zero SELECT load on your application queries, and routes them via the EventRouter SMT straight into clean domain Kafka topics!

1. Polling Relay vs. Debezium Log-Based CDC & Event Sourcing

  • Why Debezium CDC Beats Polling: Polling hammers the database even when idle and struggles with strict ordering across multiple poller threads. Debezium reads PostgreSQL's sequential WAL replication slot (wal_level = logical), preserving commit order with sub-50ms latency and zero table-scan load.
  • Debezium Outbox Event Router SMT: Never expose internal DB schema columns (before/after Debezium envelopes) to downstream teams! Use Debezium's io.debezium.transforms.outbox.EventRouter Single Message Transform to unwrap payload, set the Kafka topic from aggregatetype, and route by aggregateid key.
  • Event Sourcing vs. Outbox: In Outbox, your source of truth is still current-state tables (orders + outbox_events). In Event Sourcing, you store only immutable domain events (OrderCreated, ItemAdded, OrderPaid) and rebuild state by replaying them (accelerating long streams with periodic Snapshots). Use Event Sourcing strictly for financial ledgers or strict audit domains—never for simple CRUD!

1. Polling Outbox Relay vs. Debezium Logical WAL Streaming

POLLING RELAY (@Scheduled): Every 500ms runs SELECT ... FOR UPDATE SKIP LOCKED (Simple setup, adds idle DB load) DEBEZIUM WAL CDC (pgoutput): [ Postgres WAL Commit ] ══(Streaming Replication Slot)══► [ Debezium EventRouter ] ──► [ Kafka ] (Sub-20ms latency, strict commit order, ZERO extra SELECT queries! Monitor replication slot lag so WAL disk never fills!)

2. Architectural Decision Matrix: Outbox + CDC vs. Event Sourcing

Pattern Primary Source of Truth Operational Complexity & Sweet Spot
State Tables + Transactional Outbox Mutable current-state SQL rows + append-only outbox Low/Medium — Best default for 95% of microservices
Full Event Sourcing + Snapshots Immutable append-only event log (state derived via fold) High (schema upcasting, CQRS views) — Accounting ledgers & regulatory audit

Critical operational guardrail for Debezium on PostgreSQL: always alert on pg_replication_slots active status and retained WAL bytes! If a Debezium Kafka Connect worker dies for days, PostgreSQL retains unread WAL segments on disk until the primary volume hits 100% full unless bounded via max_slot_wal_keep_size.

package com.nexus.eventsourcing;

import java.util.List;

public class WalletAggregate {
    public sealed interface WalletEvent permits Credited, Debited {}
    public record Credited(long cents) implements WalletEvent {}
    public record Debited(long cents) implements WalletEvent {}

    // Pure functional replay from snapshot + subsequent immutable events
    public static long replayBalance(long snapshotBalance, List<WalletEvent> events) {
        long balance = snapshotBalance;
        for (WalletEvent e : events) {
            balance = switch (e) {
                case Credited(var c) -> balance + c;
                case Debited(var d)  -> balance - d;
            };
        }
        return balance;
    }
}
package com.nexus.eventsourcing

sealed interface WalletEvent {
    data class Credited(val cents: Long) : WalletEvent
    data class Debited(val cents: Long) : WalletEvent
}

object WalletAggregate {
    fun replayBalance(snapshotBalance: Long, events: List<WalletEvent>): Long =
        events.fold(snapshotBalance) { bal, event ->
            when (event) {
                is WalletEvent.Credited -> bal + event.cents
                is WalletEvent.Debited  -> bal - event.cents
            }
        }
}

package com.nexus.eventsourcing;

import java.util.List;

public class LedgerReplay {
    public sealed interface Event permits Credited, Debited {}
    public record Credited(long cents) implements Event {}
    public record Debited(long cents) implements Event {}

    public static long applyEvents(long snapshotCents, List<Event> events) {
        long balance = snapshotCents;
        for (Event e : events) {
            balance = switch (e) {
                case Credited(var c) -> balance + c;
                case Debited(var d)  -> balance - d;
            };
        }
        return balance;
    }
}
