Lesson 0073 • Stage 1 • Phase 4

Dynamic Filtering with JPA Specification<T>, Auditing (@CreatedDate) & Soft Deletes

Target: In Lesson 0016 you learned derived queries like findByStatusAndMerchantId(...). What happens when a mobile search screen has 6 optional filter chips (status, minimum total, maximum total, merchant, date range, currency)? Writing $2^6 = 64$ repository methods—or concatenating raw SQL strings (a fatal SQL injection vulnerability)—is a junior anti-pattern. Senior Spring Boot engineers compose type-safe criteria predicates with JpaSpecificationExecutor (Specification<T>), automate lifecycle timestamps via Spring Data JPA Auditing, and enforce non-destructive deletion with Hibernate 6.4+ @SoftDelete.

📖 Primary Source Recommendation

Study the official authorities: Spring Data JPA Reference: Specifications and Spring Data JPA Reference: Auditing.

💡 Android Mental Model Bridge

On Android Room, dynamic filter queries force you into messy @RawQuery with manual SimpleSQLiteQuery string building. In Spring Data JPA, Specification<T> is a functional lambda (root, query, cb) -> Predicate that composes cleanly like Kotlin collection predicates (Spec.where(hasStatus(s)).and(minAmount(min))) while binding every parameter safely as a prepared JDBC variable!

1. Composable Dynamic Queries with JpaSpecificationExecutor<T>

By extending both JpaRepository<Order, UUID> and JpaSpecificationExecutor<Order>, your repository gains findAll(Specification<Order> spec, Pageable pageable). Each filter helper returns a Specification<Order> lambda; when a query parameter is null, the helper returns cb.conjunction() (or null, which Specification.allOf(...) ignores cleanly).

2. Automated Entity Auditing (@EnableJpaAuditing)

Manually setting order.setCreatedAt(Instant.now()) inside every service method is error-prone. Annotating a configuration class with @EnableJpaAuditing and adding @EntityListeners(AuditingEntityListener.class) to a base @MappedSuperclass automatically populates:

  • @CreatedDate & @LastModifiedDate: UTC Instant timestamps populated on insert and update.
  • @CreatedBy & @LastModifiedBy: Populated via an AuditorAware<String> bean that reads the current principal from SecurityContextHolder.

3. Declarative Soft Deletes in Hibernate 6.4+ (@SoftDelete)

Financial and e-commerce backends rarely execute physical DELETE FROM orders statements because regulatory audits and foreign-key history require preserving ledger records. Hibernate 6.4+ (Spring Boot 3.2+) provides native @SoftDelete(columnName = "deleted"): calling repository.delete(entity) issues an UPDATE ... SET deleted = true, and every SELECT query or join automatically appends WHERE deleted = false.

Composable JPA Specifications, Auditing & Soft Delete Entity 
package com.nexus.orders;

import jakarta.persistence.*;
import org.hibernate.annotations.SoftDelete;
import org.springframework.data.annotation.CreatedDate;
import org.springframework.data.annotation.LastModifiedDate;
import org.springframework.data.jpa.domain.Specification;
import org.springframework.data.jpa.domain.support.AuditingEntityListener;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.JpaSpecificationExecutor;

import java.math.BigDecimal;
import java.time.Instant;
import java.util.UUID;

@Entity
@Table(name = "orders")
@SoftDelete(columnName = "deleted")
@EntityListeners(AuditingEntityListener.class)
public class OrderEntity {
    @Id @GeneratedValue(strategy = GenerationType.UUID)
    private UUID id;
    private String status;
    private BigDecimal totalAmount;

    @CreatedDate @Column(nullable = false, updatable = false)
    private Instant createdAt;

    @LastModifiedDate @Column(nullable = false)
    private Instant updatedAt;
}

public interface OrderRepository extends JpaRepository<OrderEntity, UUID>, JpaSpecificationExecutor<OrderEntity> {}

public final class OrderSpecifications {
    public static Specification<OrderEntity> hasStatus(String status) {
        return (root, query, cb) ->
            (status == null || status.isBlank()) ? cb.conjunction() : cb.equal(root.get("status"), status);
    }

    public static Specification<OrderEntity> minTotal(BigDecimal min) {
        return (root, query, cb) ->
            (min == null) ? cb.conjunction() : cb.greaterThanOrEqualTo(root.get("totalAmount"), min);
    }
}
package com.nexus.orders

import jakarta.persistence.*
import org.hibernate.annotations.SoftDelete
import org.springframework.data.annotation.CreatedDate
import org.springframework.data.annotation.LastModifiedDate
import org.springframework.data.jpa.domain.Specification
import org.springframework.data.jpa.domain.support.AuditingEntityListener
import org.springframework.data.jpa.repository.JpaRepository
import org.springframework.data.jpa.repository.JpaSpecificationExecutor
import java.math.BigDecimal
import java.time.Instant
import java.util.UUID

@Entity
@Table(name = "orders")
@SoftDelete(columnName = "deleted")
@EntityListeners(AuditingEntityListener::class)
class OrderEntity(
    @Id @GeneratedValue(strategy = GenerationType.UUID)
    val id: UUID? = null,
    var status: String = "PENDING",
    var totalAmount: BigDecimal = BigDecimal.ZERO
) {
    @CreatedDate @Column(nullable = false, updatable = false)
    lateinit var createdAt: Instant

    @LastModifiedDate @Column(nullable = false)
    lateinit var updatedAt: Instant
}

interface OrderRepository : JpaRepository<OrderEntity, UUID>, JpaSpecificationExecutor<OrderEntity>

object OrderSpecifications {
    fun hasStatus(status: String?): Specification<OrderEntity> =
        Specification { root, _, cb ->
            if (status.isNullOrBlank()) cb.conjunction()
            else cb.equal(root.get<String>("status"), status)
        }

    fun minTotal(min: BigDecimal?): Specification<OrderEntity> =
        Specification { root, _, cb ->
            if (min == null) cb.conjunction()
            else cb.greaterThanOrEqualTo(root.get("totalAmount"), min)
        }
}

Kotlin 2.x Implementation:
package com.nexus.orders

import org.springframework.data.jpa.domain.Specification
import org.springframework.data.jpa.repository.JpaRepository
import org.springframework.data.jpa.repository.JpaSpecificationExecutor
import java.math.BigDecimal
import java.util.UUID

interface OrderRepository : JpaRepository<OrderEntity, UUID>, JpaSpecificationExecutor<OrderEntity>

object OrderSpecs {
    fun hasStatus(status: String?): Specification<OrderEntity> =
        Specification { root, _, cb ->
            if (status == null) cb.conjunction() else cb.equal(root.get<String>("status"), status)
        }

    fun minAmount(min: BigDecimal?): Specification<OrderEntity> =
        Specification { root, _, cb ->
            if (min == null) cb.conjunction() else cb.greaterThanOrEqualTo(root.get("totalAmount"), min)
        }
}
Architectural Breakdown:

Returning cb.conjunction() for omitted query parameters lets controllers chain Specification.allOf(...) unconditionally without branching logic or SQL injection risk.
