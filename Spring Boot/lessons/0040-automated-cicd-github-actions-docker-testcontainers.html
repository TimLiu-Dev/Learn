Automated CI/CD with GitHub Actions & Dockerized Testcontainers

Target: A robust test suite is only as effective as the continuous integration pipeline that enforces it. If tests only run on individual developer laptops ('it worked on my machine!'), broken dependencies, failing migrations, and subtle concurrency regressions will inevitably slip into main branches. In this lesson, we build an enterprise-grade GitHub Actions CI/CD workflow for Spring Boot: configuring dependency caching (Maven/Gradle), running Testcontainers inside Linux runners, collecting automated test reports, generating container images, and running security vulnerability scans with Trivy.

📖 Primary Source Recommendation

Study the official authority: GitHub Actions Documentation: Building and testing Java with Maven & Testcontainers Cloud / CI Documentation.. Ground your learning in primary architecture rather than secondary summaries.

💡 Why This Matters in Production

Running Testcontainers in cloud CI runners requires proper Docker daemon accessibility and aggressive dependency caching. Without cache optimization, builds spend 8 minutes downloading dependencies on every commit. With proper setup, builds execute in under 90 seconds, providing immediate feedback on pull requests.

Key Architectural Takeaways

  • GitHub Actions hosted runners (ubuntu-latest) have the Docker daemon pre-installed and running out-of-the-box, allowing Testcontainers to start without extra setup.
  • Always enable build dependency caching with 'actions/setup-java' (using 'cache: maven' or 'cache: gradle') to save gigabytes of redundant network downloads.
  • Fail fast on checkstyle and formatting errors before executing long-running integration tests.
  • Publish JUnit test reports to GitHub PR summaries using 'dorny/test-reporter' or 'action-junit-report'.
  • Incorporate container vulnerability scanning (Trivy or Snyk) directly into the pull request gate to prevent shipping CVEs into production.
  • Use GitHub Secrets for production credentials; never hardcode registry passwords in YAML workflows.

1. Anatomy of a Production-Grade CI Pipeline

  1. Lint & Format Check: Spotless or Checkstyle (10s).
  2. Compile & Unit Tests: Fast parallel JUnit 5 execution (30s).
  3. Integration Tests: Testcontainers spins up real PostgreSQL & Redis (60s).
  4. Artifact Packaging & Container Build: Spring Boot Cloud-Native Buildpack or Multi-stage Docker build.
  5. Vulnerability Scan: Trivy scans Docker image for high/critical CVEs.
  6. Publish: Push tagged image to GitHub Container Registry (GHCR) or AWS ECR.

2. Testcontainers in GitHub Actions: Docker Socket

Because standard GitHub Actions ubuntu-latest virtual machines run as bare VMs with root Docker access, Testcontainers connects directly to /var/run/docker.sock without requiring Docker-in-Docker (DinD). However, if your enterprise uses custom self-hosted Kubernetes runners, you must mount the host Docker socket into the runner pod.

Automated CI/CD with GitHub Actions & Dockerized Testcontainers 
# .github/workflows/ci-pipeline.yml
name: Backend CI/CD Pipeline

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  build-and-test:
    runs-on: ubuntu-latest
    timeout-minutes: 15

    steps:
      - name: Checkout Codebase
        uses: actions/checkout@v4

      - name: Set up JDK 21
        uses: actions/setup-java@v4
        with:
          java-version: '21'
          distribution: 'temurin'
          cache: 'maven' # Automatically caches ~/.m2 repository!

      - name: Compile and Run Unit & Slice Tests
        run: ./mvnw test -Dtest="*UnitTest,*WebMvcTest"

      - name: Run Testcontainers Integration Tests
        run: ./mvnw verify -Dtest="*IntegrationTest"
        env:
          TESTCONTAINERS_RYUK_DISABLED: "false"

      - name: Publish Test Results
        uses: dorny/test-reporter@v1
        if: always()
        with:
          name: JUnit Test Results
          path: '**/target/surefire-reports/*.xml'
          reporter: java-junit

      - name: Build Container Image with Spring Boot Buildpacks
        run: ./mvnw spring-boot:build-image -Dspring-boot.build-image.imageName=ghcr.io/${{ github.repository }}:${{ github.sha }}

      - name: Security Scan Container Image with Trivy
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: 'ghcr.io/${{ github.repository }}:${{ github.sha }}'
          format: 'table'
          exit-code: '1' # Fails the pipeline if CRITICAL vulnerabilities exist!
          severity: 'CRITICAL,HIGH'
# .github/workflows/gradle-ci.yml
name: Gradle Backend CI

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  verify:
    runs-on: ubuntu-latest
    timeout-minutes: 15

    steps:
      - uses: actions/checkout@v4

      - name: Set up JDK 21
        uses: actions/setup-java@v4
        with:
          java-version: '21'
          distribution: 'temurin'
          cache: 'gradle' # Automatically caches Gradle wrapper and dependencies!

      - name: Grant Execute Permission to Gradlew
        run: chmod +x gradlew

      - name: Run Full Test Suite with Testcontainers
        run: ./gradlew check --no-daemon

      - name: Scan Vulnerabilities with Trivy
        uses: aquasecurity/trivy-action@master
        with:
          scan-type: 'fs'
          severity: 'CRITICAL,HIGH'
          exit-code: '1'
