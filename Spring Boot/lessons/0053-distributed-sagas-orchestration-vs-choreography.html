Lesson 0053 • Stage 2 • Phase 12

Distributed Sagas: Orchestration vs. Choreography & Compensating Transactions

Target: Across separate microservice databases, Two-Phase Commit (2PC/XA) holds network locks that destroy P99 latency and availability. Master the Saga Pattern: sequences of local ACID transactions coordinated via Choreography or a state-machine Orchestrator, semantic Compensating Transactions executed in reverse order on failure, and Pivot Transactions.

📖 Primary Source Recommendation

Study the official authorities: Chris Richardson: Microservices Saga Pattern and Garcia-Molina & Salem (1987), Sagas.

1. Choreography vs. Orchestration Tradeoffs

Dimension Choreography (Event-Driven) Orchestration (State Machine Coordinator)
Coupling Loose: services only subscribe to domain events. Explicit: orchestrator invokes participant commands.
Visibility & Debugging Harder on 4+ steps; requires distributed tracing to reconstruct state. High: orchestrator persists exact SagaStatus row in PostgreSQL.
Best Fit 2–3 simple decoupled side effects (e.g., send welcome email). Multi-step financial/fulfillment flows (Reserve Stock → Charge Card → Ship).

2. Compensating Transactions & The Pivot Step

Because Step 1 (reserveStock) has already committed its local PostgreSQL transaction before Step 2 (chargeCard) runs, you cannot run SQL ROLLBACK across services. Instead, if Step 2 declines, the orchestrator executes an idempotent Compensating Transaction in reverse order (releaseStockCompensation) and records terminal status COMPENSATED.

Once the Pivot Transaction (e.g., capturing non-refundable payment) commits, the saga passes the point of no return: subsequent steps (like generating an invoice PDF) must retry forward until completion rather than compensating backward.

3. Production Implementation (Java 25 vs. Kotlin 2.2+)

Stateful Order Saga Orchestrator with Reverse Compensation 
package com.example.saga;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Service;
import java.util.UUID;

enum SagaStatus { COMPLETED, COMPENSATED, FAILED }

interface InventoryClient {
    boolean reserveStock(UUID sagaId, String sku, int quantity);
    void releaseStockCompensation(UUID sagaId, String sku, int quantity);
}

interface PaymentClient {
    boolean processPayment(UUID sagaId, long amountCents);
}

@Service
public class OrderSagaOrchestrator {
    private static final Logger log = LoggerFactory.getLogger(OrderSagaOrchestrator.class);
    private final InventoryClient inventoryClient;
    private final PaymentClient paymentClient;

    public OrderSagaOrchestrator(InventoryClient inventoryClient, PaymentClient paymentClient) {
        this.inventoryClient = inventoryClient;
        this.paymentClient = paymentClient;
    }

    public SagaStatus executeOrderSaga(UUID orderId, String sku, int quantity, long amountCents) {
        UUID sagaId = UUID.randomUUID();

        // Step 1 (Compensatable): Reserve Inventory
        if (!inventoryClient.reserveStock(sagaId, sku, quantity)) {
            log.warn("Saga {} aborted at Step 1: out of stock", sagaId);
            return SagaStatus.FAILED;
        }

        // Step 2 (Pivot): Capture Payment
        if (!paymentClient.processPayment(sagaId, amountCents)) {
            log.warn("Saga {} failed at Step 2: compensating inventory", sagaId);
            inventoryClient.releaseStockCompensation(sagaId, sku, quantity);
            return SagaStatus.COMPENSATED;
        }

        return SagaStatus.COMPLETED;
    }
}

Java 25 Implementation:
package com.example.saga;

import java.util.UUID;

enum SagaStatus { COMPLETED, COMPENSATED, FAILED }

interface TravelBookingClient {
    boolean bookFlight(UUID sagaId);
    void cancelFlightCompensation(UUID sagaId);
    boolean bookHotel(UUID sagaId);
}

public class TravelSagaOrchestrator {
    private final TravelBookingClient client;

    public TravelSagaOrchestrator(TravelBookingClient client) {
        this.client = client;
    }

    public SagaStatus bookVacation(UUID sagaId) {
        if (!client.bookFlight(sagaId)) {
            return SagaStatus.FAILED;
        }
        if (!client.bookHotel(sagaId)) {
            client.cancelFlightCompensation(sagaId);
            return SagaStatus.COMPENSATED;
        }
        return SagaStatus.COMPLETED;
    }
}
Kotlin 2.2+ Implementation:
package com.example.saga

import java.util.UUID

enum class SagaStatus { COMPLETED, COMPENSATED, FAILED }

interface TravelBookingClient {
    fun bookFlight(sagaId: UUID): Boolean
    fun cancelFlightCompensation(sagaId: UUID)
    fun bookHotel(sagaId: UUID): Boolean
}

class TravelSagaOrchestrator(private val client: TravelBookingClient) {

    fun bookVacation(sagaId: UUID): SagaStatus {
        if (!client.bookFlight(sagaId)) {
            return SagaStatus.FAILED
        }
        if (!client.bookHotel(sagaId)) {
            client.cancelFlightCompensation(sagaId)
            return SagaStatus.COMPENSATED
        }
        return SagaStatus.COMPLETED
    }
}
Architectural Breakdown:

Notice why passing sagaId to every participant and compensation call is critical: if a network timeout triggers a retry, the participant deduplicates on sagaId so a flight is never refunded twice!
