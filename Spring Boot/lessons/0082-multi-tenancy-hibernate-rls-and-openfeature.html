Multi-Tenancy (Hibernate @TenantId & PostgreSQL RLS) & Feature Flags (OpenFeature)

Target: B2B SaaS backends in Spring Boot must guarantee that Tenant A can never read or mutate Tenant B's rows—even if an engineer forgets a WHERE tenant_id = ? clause! Master Hibernate 6's native @TenantId discriminator filter, defense-in-depth PostgreSQL Row-Level Security (RLS), and vendor-neutral runtime Feature Flags via OpenFeature.

📖 Primary Source Recommendation

Study the official authorities: Hibernate ORM 6 User Guide: Multi-Tenancy & @TenantId and OpenFeature Official Java SDK Documentation.

💡 Android Mental Model Bridge

Think of Multi-Tenancy like scoped local storage per signed-in workspace, except on a shared database serving 5,000 companies simultaneously. Think of OpenFeature like Firebase Remote Config on Android—decoupling code deployment from feature rollout so you can enable a feature for 5% of tenants or kill-switch a broken flow in 1 second!

1. Multi-Tenancy Models & Defense in Depth

  • Shared Table + Discriminator (@TenantId): Highest density and easiest migrations (`tenant_id` column on shared tables). Hibernate 6's @TenantId + CurrentTenantIdentifierResolver automatically appends WHERE tenant_id = ? to every JPQL/Criteria query and populates tenant_id on persist.
  • PostgreSQL Row-Level Security (RLS): Because native SQL or JdbcClient bypasses Hibernate filters, enterprise teams add PostgreSQL RLS (ALTER TABLE invoices ENABLE ROW LEVEL SECURITY; CREATE POLICY ... USING (tenant_id = current_setting('app.tenant_id')::uuid))—enforcing isolation inside the database engine itself!
  • OpenFeature (Vendor-Neutral Feature Flags): Never hardcode if (env.equals("prod")); evaluate flags dynamically via OpenFeature's Client.getBooleanValue("new-checkout-flow", false, evaluationContext) backed by flagd, LaunchDarkly, or Unleash.

Hibernate 6 @TenantId + CurrentTenantIdentifierResolver & OpenFeature Check 
package com.nexus.multitenant;

import jakarta.persistence.*;
import org.hibernate.annotations.TenantId;
import org.hibernate.context.spi.CurrentTenantIdentifierResolver;
import org.springframework.stereotype.Component;
import java.util.UUID;

@Entity
@Table(name = "invoices")
public class InvoiceEntity {
    @Id @GeneratedValue(strategy = GenerationType.UUID)
    private UUID id;

    @TenantId
    @Column(name = "tenant_id", nullable = false, updatable = false)
    private String tenantId;

    private long amountCents;
}

@Component
public class TenantResolver implements CurrentTenantIdentifierResolver<String> {
    private static final ThreadLocal<String> CURRENT = new ThreadLocal<>();
    public static void set(String tenantId) { CURRENT.set(tenantId); }
    public static void clear() { CURRENT.remove(); }

    @Override
    public String resolveCurrentTenantIdentifier() {
        String id = CURRENT.get();
        return id != null ? id : "anonymous";
    }

    @Override
    public boolean validateExistingCurrentSessions() { return true; }
}
package com.nexus.multitenant

import jakarta.persistence.*
import org.hibernate.annotations.TenantId
import org.hibernate.context.spi.CurrentTenantIdentifierResolver
import org.springframework.stereotype.Component
import java.util.UUID

@Entity
@Table(name = "invoices")
class InvoiceEntity(
    @Id @GeneratedValue(strategy = GenerationType.UUID)
    val id: UUID? = null,

    @TenantId
    @Column(name = "tenant_id", nullable = false, updatable = false)
    var tenantId: String? = null,

    var amountCents: Long = 0
)

@Component
class TenantResolver : CurrentTenantIdentifierResolver<String> {
    companion object {
        private val current = ThreadLocal<String>()
        fun set(tenantId: String) = current.set(tenantId)
        fun clear() = current.remove()
    }

    override fun resolveCurrentTenantIdentifier(): String = current.get() ?: "anonymous"
    override fun validateExistingCurrentSessions(): Boolean = true
}

💡 Complete Production Reference Solution
Java 21/25 Implementation:
package com.nexus.multitenant;

import jakarta.persistence.*;
import org.hibernate.annotations.TenantId;
import java.util.UUID;

@Entity
public class OrderRecord {
    @Id private UUID id;
    @TenantId
    private String tenantId;
}

public class TenantFilterRunner {
    public static void runWithTenant(String tenantId, Runnable task) {
        TenantResolver.set(tenantId);
        try {
            task.run();
        } finally {
            TenantResolver.clear();
        }
    }
}
Kotlin 2.x Implementation:
package com.nexus.multitenant

import jakarta.persistence.*
import org.hibernate.annotations.TenantId
import java.util.UUID

@Entity
class OrderRecord(
    @Id val id: UUID? = null,
    @TenantId var tenantId: String? = null
)

object TenantFilterRunner {
    fun runWithTenant(tenantId: String, task: Runnable) {
        TenantResolver.set(tenantId)
        try {
            task.run()
        } finally {
            TenantResolver.clear()
        }
    }
}
Architectural Breakdown:

Combining Hibernate @TenantId with strict try/finally context cleanup (and PostgreSQL RLS for raw SQL) eliminates cross-tenant data leaks in pooled web servers.
