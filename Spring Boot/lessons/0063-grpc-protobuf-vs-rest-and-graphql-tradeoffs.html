API Architecture Tradeoffs: gRPC (Protobuf) vs. REST & GraphQL

Target: REST + JSON is the default for public mobile/web APIs. Inside large distributed backends, however, teams frequently choose gRPC (HTTP/2 + Protocol Buffers) for low-latency, strongly typed internal microservice-to-microservice calls—or GraphQL for BFF (Backend-for-Frontend) aggregation across heterogeneous mobile/web screens. In this lesson, we master when to use REST vs. gRPC vs. GraphQL, avoid GraphQL's infamous N+1 DataLoader trap, and define a Protobuf contract with Spring gRPC.

📖 Primary Source Recommendation

Study the official authorities: Spring gRPC Reference Documentation and Spring for GraphQL Reference.

💡 Android Mental Model Bridge

If you've used Protobuf DataStore on Android, you already know why gRPC loves .proto files: numbered binary fields (string order_id = 1;) serialize 5–10× smaller and faster than text JSON, compile into strict Java/Kotlin stubs, and enforce backward compatibility via field numbers (never reuse a deleted field number!).

Key Architectural Takeaways

  • REST / JSON: Best default for public external APIs, browser clients, and HTTP caching (ETag/CDN).
  • gRPC / Protobuf (HTTP/2): Best for high-throughput internal service-to-service RPC, polyglot backends (Java talking to Go/Python/Rust), and bidirectional streaming. Requires HTTP/2-aware L7 load balancers (Envoy/ALB gRPC) because HTTP/2 multiplexes many RPCs over one long-lived TCP connection!
  • GraphQL + DataLoader: Great for BFF aggregation where iOS/Android/Web want different field subsets in one round trip—but @BatchMapping / DataLoader is mandatory so nested resolvers don't trigger N+1 SQL storms.

Production Implementation (Protobuf Contract + Spring gRPC Service vs GraphQL @BatchMapping)

Protobuf Service Contract & Spring gRPC Server (Java 21/25 vs Kotlin 2.x) 
// inventory.proto — Strict binary contract; NEVER reuse deleted field numbers!
syntax = "proto3";
package nexus.inventory.v1;

service InventoryService {
  rpc ReserveStock (ReserveRequest) returns (ReserveResponse);
}

message ReserveRequest {
  string order_id = 1;
  string sku = 2;
  int32 quantity = 3;
}

message ReserveResponse {
  bool reserved = 1;
}

---
// InventoryGrpcService.java
@Service
public class InventoryGrpcService extends InventoryServiceGrpc.InventoryServiceImplBase {
    @Override
    public void reserveStock(ReserveRequest req, StreamObserver<ReserveResponse> observer) {
        boolean ok = inventoryEngine.tryReserve(req.getOrderId(), req.getSku(), req.getQuantity());
        observer.onNext(ReserveResponse.newBuilder().setReserved(ok).build());
        observer.onCompleted();
    }
}
// Kotlin gRPC coroutine stub (grpc-kotlin) OR Spring for GraphQL @BatchMapping
@Service
class InventoryGrpcService : InventoryServiceGrpcKt.InventoryServiceCoroutineImplBase() {
    override suspend fun reserveStock(request: ReserveRequest): ReserveResponse {
        val ok = inventoryEngine.tryReserve(request.orderId, request.sku, request.quantity)
        return reserveResponse { reserved = ok }
    }
}

---
// GraphQL N+1 Defense: @BatchMapping collects all Orders and queries Customer rows in 1 SQL IN(...)
@Controller
class OrderGraphQlController(private val customerRepo: CustomerRepository) {
    @BatchMapping
    fun customer(orders: List<OrderDto>): Map<OrderDto, CustomerDto> {
        val ids = orders.map { it.customerId }.distinct()
        val byId = customerRepo.findAllById(ids).associateBy { it.id }
        return orders.associateWith { byId.getValue(it.customerId) }
    }
}

💡 Complete Production Reference Solution
Java 21/25 Implementation:
// message OrderItem { reserved 2; string order_id = 1; int32 quantity = 3; }
@Controller
public class OrderBatchController {
    @BatchMapping
    public Map<OrderDto, CustomerDto> customer(List<OrderDto> orders) {
        List<UUID> ids = orders.stream().map(OrderDto::customerId).distinct().toList();
        Map<UUID, CustomerDto> byId = customerRepo.findAllById(ids).stream()
            .collect(Collectors.toMap(CustomerDto::id, Function.identity()));
        return orders.stream().collect(Collectors.toMap(o -> o, o -> byId.get(o.customerId())));
    }
}
Kotlin 2.x Implementation:

Architectural Breakdown:

Reserving deleted Protobuf field numbers keeps binary wire evolution safe, while @BatchMapping collapses GraphQL N+1 queries into one SQL IN (...) lookup.
