Real-Time Backends: SSE vs. WebSockets & Redis Multi-Pod Fan-Out

Target: Standard HTTP request-response breaks down for live order-status feeds, real-time notifications, collaborative whiteboards, and streaming AI/LLM responses. Choosing between Long Polling, Server-Sent Events (SSE), and WebSockets—and scaling persistent connections horizontally across multiple stateless Kubernetes pods via Redis Pub/Sub fan-out—is a core Senior System Design skill.

📖 Primary Source Recommendation

Study the official authorities: Spring MVC Async: HTTP Streaming & SseEmitter and Spring WebSocket Reference.

💡 Why This Matters in Production

On a single laptop, storing an in-memory Map<UserId, SseEmitter> works fine. Behind a Kubernetes Load Balancer with 5 pods, User A connects to Pod 1 while the Kafka/Order update arrives on Pod 4! Without a shared Redis Pub/Sub backplane (or external message broker), Pod 4 drops the live update silently.

Key Architectural Takeaways

  • SSE (Server-Sent Events) vs. WebSockets: Use SSE (text/event-stream, built-in browser auto-reconnect + Last-Event-ID, works cleanly over standard HTTP/2 & proxies) for 1-way server→client streams (notifications, stock tickers, LLM token streaming). Use WebSockets only when you need low-latency bidirectional frames (chat, multiplayer games).
  • Virtual Threads Make SSE Cheap: With Java 21/25 Virtual Threads, holding tens of thousands of idle open SSE streams no longer exhausts Tomcat's OS thread pool—just always register onCompletion / onTimeout / onError callbacks to clean up maps and prevent memory leaks!
  • Multi-Pod Fan-Out via Redis Pub/Sub: Every pod subscribes to a Redis channel (or user-scoped channel); when any pod publishes an event, the pod holding that user's local SseEmitter pushes it down the wire.

Production Implementation (Java 21/25 vs Kotlin 2.x — SseEmitter + Leak-Free Cleanup)

Leak-Safe SSE Stream + Multi-Pod Redis Pub/Sub Fan-Out 
@RestController
@RequestMapping("/api/v1/orders")
public class OrderStreamController {
    private final Map<String, SseEmitter> localEmitters = new ConcurrentHashMap<>();
    private final StringRedisTemplate redisTemplate;

    public OrderStreamController(StringRedisTemplate redisTemplate) {
        this.redisTemplate = redisTemplate;
    }

    @GetMapping(path = "/{orderId}/events", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public SseEmitter streamOrder(@PathVariable String orderId) {
        SseEmitter emitter = new SseEmitter(180_000L); // 3-min timeout
        localEmitters.put(orderId, emitter);

        // Mandatory cleanup callbacks to avoid memory leaks on client disconnect
        emitter.onCompletion(() -> localEmitters.remove(orderId, emitter));
        emitter.onTimeout(() -> localEmitters.remove(orderId, emitter));
        emitter.onError(ex -> localEmitters.remove(orderId, emitter));
        return emitter;
    }

    // Invoked by ANY pod when order state changes: broadcasts to all pods via Redis Pub/Sub
    public void publishOrderUpdate(String orderId, String status) {
        redisTemplate.convertAndSend("order-updates", orderId + ":" + status);
    }

    // Invoked by Redis MessageListener on every pod; only the pod holding emitter delivers
    public void onRedisBroadcast(String orderId, String status) {
        SseEmitter emitter = localEmitters.get(orderId);
        if (emitter != null) {
            try {
                emitter.send(SseEmitter.event().name("order-status").data(status));
            } catch (IOException ex) {
                localEmitters.remove(orderId, emitter);
                emitter.completeWithError(ex);
            }
        }
    }
}
@RestController
@RequestMapping("/api/v1/orders")
class OrderStreamController(private val redisTemplate: StringRedisTemplate) {
    private val localEmitters = ConcurrentHashMap<String, SseEmitter>()

    @GetMapping("/{orderId}/events", produces = [MediaType.TEXT_EVENT_STREAM_VALUE])
    fun streamOrder(@PathVariable orderId: String): SseEmitter {
        val emitter = SseEmitter(180_000L)
        localEmitters[orderId] = emitter

        emitter.onCompletion { localEmitters.remove(orderId, emitter) }
        emitter.onTimeout { localEmitters.remove(orderId, emitter) }
        emitter.onError { localEmitters.remove(orderId, emitter) }
        return emitter
    }

    fun publishOrderUpdate(orderId: String, status: String) {
        redisTemplate.convertAndSend("order-updates", "$orderId:$status")
    }

    fun onRedisBroadcast(orderId: String, status: String) {
        val emitter = localEmitters[orderId] ?: return
        try {
            emitter.send(SseEmitter.event().name("order-status").data(status))
        } catch (ex: IOException) {
            localEmitters.remove(orderId, emitter)
            emitter.completeWithError(ex)
        }
    }
}

Java 21/25 Implementation:
public SseEmitter subscribe(String orderId) {
    SseEmitter emitter = new SseEmitter(120_000L);
    emitters.put(orderId, emitter);
    emitter.onCompletion(() -> emitters.remove(orderId, emitter));
    emitter.onTimeout(() -> emitters.remove(orderId, emitter));
    emitter.onError(ex -> emitters.remove(orderId, emitter));
    return emitter;
}

public void broadcast(String orderId, String status) {
    redisTemplate.convertAndSend("order-updates", orderId + ":" + status);
}

Architectural Breakdown:

Using the two-argument remove(orderId, emitter) prevents a dying old tab from accidentally deleting a reconnected client's brand-new emitter.
