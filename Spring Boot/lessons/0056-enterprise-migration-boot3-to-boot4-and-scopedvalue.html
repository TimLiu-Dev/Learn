Enterprise Migration Playbook: Upgrading Spring Boot 3.x → 4.2 & Java 21 → 25 (ScopedValue & JSpecify)

Target: In 2027, senior engineers lead migrations of mission-critical Spring Boot 3.x / Java 21 LTS production repositories onto Spring Boot 4.2 (Spring Framework 7.1, Spring Security 7, Hibernate ORM 7, Jackson 3) & Java 25 LTS. Master the concrete enterprise upgrade checklist, compile-time null safety with JSpecify (@NullMarked / @Nullable), and replacing leaky ThreadLocal context holders with Java 25's ScopedValue (JEP 506).

📖 Primary Source Recommendation

Study the official authorities: Official Spring Boot 4.0+ Migration Guide, JSpecify Null-Safety User Guide, and OpenJDK JEP 506: Scoped Values (Final in Java 25).

1. The 5-Step Spring Boot 3.x → 4.2 Upgrade Playbook

Never jump straight from Boot 3.1 to Boot 4.2 in one giant PR! Senior teams execute a deterministic, OpenRewrite-assisted sequence:

  1. Step 1 — Upgrade to Spring Boot 3.5 Latest First: Resolve all Boot 3.x deprecations cleanly (replace removed @MockBean / @SpyBean with @MockitoBean / @MockitoSpyBean; enable spring.mvc.problemdetails.enabled=true).
  2. Step 2 — Modularized Starters & Test Slices: Spring Boot 4 split the monolithic spring-boot-autoconfigure JAR into focused modules. Update web starters to spring-boot-starter-webmvc + spring-boot-starter-webmvc-test, observability to spring-boot-starter-opentelemetry, and replace deprecated TestRestTemplate with fluent RestTestClient.
  3. Step 3 — Jackson 2 → Jackson 3 (tools.jackson): Update custom serializer/mapper imports from com.fasterxml.jackson.databind.ObjectMapper to immutable tools.jackson.databind.json.JsonMapper (annotations like @JsonProperty stay in com.fasterxml.jackson.annotation!). Verify API contract snapshots because Jackson 3 defaults to ISO-8601 date strings instead of numeric epoch timestamps.
  4. Step 4 — Hibernate ORM 7 & Jakarta EE 11 (Servlet 6.1): Run your full Testcontainers PostgreSQL 17 suite to catch stricter JPQL type checking and Jakarta Persistence 3.2 behaviors.
  5. Step 5 — Adopt JSpecify Nullness & Java 25 Runtime: Add @NullMarked on package-info.java so Kotlin callers and NullAway get compiler-verified null contracts across Java packages, and switch container images to JDK 25 with -XX:+UseZGC (Generational ZGC default).

2. Replacing Leaky ThreadLocal with Java 25 ScopedValue (JEP 506)

Legacy backends stuffed tenant IDs, correlation metadata, or locale context into mutable ThreadLocal<T> variables. That creates three production hazards: 1) forgetting threadLocal.remove() in a servlet filter leaks data onto the next customer's request, 2) any downstream helper can overwrite the value silently, and 3) copying mutable maps across millions of Virtual Threads wastes RAM.

Java 25 ScopedValue<T> solves all three: bindings are strictly immutable, automatically cleared the instant ScopedValue.where(KEY, val).call(...) exits, and inherited at near-zero cost by child virtual threads inside StructuredTaskScope!

3. Production Implementation (Java 25 JSpecify + ScopedValue vs. Kotlin 2.2 Interop)

JSpecify @NullMarked + Java 25 ScopedValue Request Filter & Native Boot 4 Features 
package com.nexus.boot4;

import org.jspecify.annotations.NullMarked;
import org.jspecify.annotations.Nullable;
import org.springframework.context.annotation.Configuration;
import org.springframework.resilience.annotation.ConcurrencyLimit;
import org.springframework.resilience.annotation.EnableResilientMethods;
import org.springframework.web.bind.annotation.*;
import org.springframework.web.service.registry.ImportHttpServices;

@NullMarked // Every parameter & return type is non-null unless marked @Nullable!
@Configuration
@EnableResilientMethods
@ImportHttpServices(types = { LedgerHttpClient.class })
public class Boot4MigrationConfig {}

@NullMarked
@RestController
@RequestMapping("/api/orders")
public class VersionedOrderController {

    public static final ScopedValue<String> TENANT_ID = ScopedValue.newInstance();

    @GetMapping(path = "/{id}", version = "2.0+")
    @ConcurrencyLimit(25)
    public String fetchOrder(
            @PathVariable String id,
            @RequestHeader(name = "X-Tenant-Id", required = false) @Nullable String tenantHeader) throws Exception {
        String resolvedTenant = (tenantHeader != null) ? tenantHeader : "default-tenant";
        // Automatically unbound as soon as call(...) finishes — zero ThreadLocal leak risk!
        return ScopedValue.where(TENANT_ID, resolvedTenant)
            .call(() -> "v2:" + TENANT_ID.get() + ":" + id);
    }
}
