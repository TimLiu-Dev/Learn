Advanced Dependency Injection: @Qualifier, Strategy Maps, ObjectProvider, Bean Scopes & BeanPostProcessor

Target: In Lesson 0003 you learned why constructor injection beats field injection. In real enterprise codebases and senior interviews, you quickly hit five deeper DI scenarios: multiple implementations of the same interface (NoUniqueBeanDefinitionException), dynamic Strategy Map<String, T> injection, optional/lazy lookup via ObjectProvider<T>, the Singleton-injecting-Request/Prototype scope trap, and how BeanPostProcessor wraps beans in AOP proxies.

📖 Primary Source Recommendation

Study the official authorities: Spring Framework Reference: Fine-tuning Annotation-based Autowiring & Scopes and Spring Framework Reference: BeanPostProcessor & Container Extensions.

💡 Android Mental Model Bridge

In Android Hilt/Dagger, you use @Named or @IntoMap multibindings when multiple implementations exist, and Provider<T> for lazy/scoped resolution. In Spring Boot, the exact counterparts are @Qualifier / @Primary, injecting Map<String, PaymentGateway> or List<DiscountRule> directly into constructors, and ObjectProvider<T>!

1. Resolving Multiple Beans, Strategy Maps & ObjectProvider<T>

  • @Primary vs. @Qualifier: If both StripeGateway and AdyenGateway implement PaymentGateway, Spring throws NoUniqueBeanDefinitionException. Mark the default fallback bean @Primary, or pick a specific one with @Qualifier("adyen").
  • Strategy Pattern via Collection/Map Injection: Instead of writing a giant switch or if/else chain, inject Map<String, PaymentGateway> (keys = bean names) or List<ValidationRule> (ordered via @Order) straight into your service constructor—adding a new gateway requires zero edits to the orchestrator!
  • ObjectProvider<T>: Safer than @Autowired(required = false) or @Lazy. Lets you call provider.getIfAvailable() for optional beans or provider.getObject() to obtain a fresh @Prototype instance inside a singleton.

2. Bean Scopes, Circular Dependencies & BeanPostProcessor

  • The Scope Mismatch Trap: A Spring bean is a singleton by default. Injecting a @RequestScope or @Scope("prototype") bean directly into a singleton freezes the very first instance forever—unless you use ObjectProvider<T> or @RequestScope(proxyMode = ScopedProxyMode.TARGET_CLASS).
  • Circular Dependencies (BeanCurrentlyInCreationException): Spring Boot 2.6+ disables circular references by default. Never hide a cycle behind @Lazy; extract the shared logic into a third service or publish a Spring ApplicationEvent.
  • BeanFactoryPostProcessor vs. BeanPostProcessor: BeanFactoryPostProcessor modifies bean metadata/properties *before* objects are instantiated (e.g. resolving placeholders). BeanPostProcessor intercepts beans *after* instantiation (postProcessAfterInitialization) to wrap them in CGLIB/JDK dynamic proxies for @Transactional, @Async, and @Cacheable.

3. Production Implementation (Java 21/25 vs Kotlin 2.x)

Strategy Map Injection, @Qualifier & ObjectProvider 
package com.nexus.di;

import org.springframework.beans.factory.ObjectProvider;
import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.stereotype.Service;
import java.util.Map;

public interface PaymentProcessor { String charge(long cents); }

@Service("stripe")
public class StripeProcessor implements PaymentProcessor {
    @Override public String charge(long cents) { return "stripe:" + cents; }
}

@Service("adyen")
public class AdyenProcessor implements PaymentProcessor {
    @Override public String charge(long cents) { return "adyen:" + cents; }
}

@Service
public class PaymentRouter {
    private final Map<String, PaymentProcessor> processors;
    private final PaymentProcessor defaultProcessor;
    private final ObjectProvider<AuditHook> optionalAudit;

    public PaymentRouter(
        Map<String, PaymentProcessor> processors,
        @Qualifier("stripe") PaymentProcessor defaultProcessor,
        ObjectProvider<AuditHook> optionalAudit
    ) {
        this.processors = processors;
        this.defaultProcessor = defaultProcessor;
        this.optionalAudit = optionalAudit;
    }

    public String route(String providerKey, long cents) {
        optionalAudit.ifAvailable(AuditHook::mark);
        return processors.getOrDefault(providerKey, defaultProcessor).charge(cents);
    }
}
package com.nexus.di

import org.springframework.beans.factory.ObjectProvider
import org.springframework.beans.factory.annotation.Qualifier
import org.springframework.stereotype.Service

interface PaymentProcessor { fun charge(cents: Long): String }

@Service("stripe")
class StripeProcessor : PaymentProcessor {
    override fun charge(cents: Long) = "stripe:$cents"
}

@Service("adyen")
class AdyenProcessor : PaymentProcessor {
    override fun charge(cents: Long) = "adyen:$cents"
}

@Service
class PaymentRouter(
    private val processors: Map<String, PaymentProcessor>,
    @Qualifier("stripe") private val defaultProcessor: PaymentProcessor,
    private val optionalAudit: ObjectProvider<AuditHook>
) {
    fun route(providerKey: String, cents: Long): String {
        optionalAudit.ifAvailable { it.mark() }
        return (processors[providerKey] ?: defaultProcessor).charge(cents)
    }
}

💡 Complete Production Reference Solution
Java 21/25 Implementation:
package com.nexus.di;

import org.springframework.beans.factory.ObjectProvider;
import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.stereotype.Service;
import java.util.Map;

@Service
public class GatewayRouter {
    private final Map<String, PaymentGateway> gateways;
    private final PaymentGateway defaultGateway;
    private final ObjectProvider<FraudCheck> fraudCheckProvider;

    public GatewayRouter(
        Map<String, PaymentGateway> gateways,
        @Qualifier("stripe") PaymentGateway defaultGateway,
        ObjectProvider<FraudCheck> fraudCheckProvider
    ) {
        this.gateways = gateways;
        this.defaultGateway = defaultGateway;
        this.fraudCheckProvider = fraudCheckProvider;
    }

    public String route(String key, long cents) {
        fraudCheckProvider.ifAvailable(FraudCheck::verify);
        return gateways.getOrDefault(key, defaultGateway).pay(cents);
    }
}
Kotlin 2.x Implementation:
package com.nexus.di

import org.springframework.beans.factory.ObjectProvider
import org.springframework.beans.factory.annotation.Qualifier
import org.springframework.stereotype.Service

@Service
class GatewayRouter(
    private val gateways: Map<String, PaymentGateway>,
    @Qualifier("stripe") private val defaultGateway: PaymentGateway,
    private val fraudCheckProvider: ObjectProvider<FraudCheck>
) {
    fun route(key: String, cents: Long): String {
        fraudCheckProvider.ifAvailable { it.verify() }
        return (gateways[key] ?: defaultGateway).pay(cents)
    }
}
Architectural Breakdown:

Strategy Map injection makes services open for extension and closed for modification, while @Qualifier and ObjectProvider eliminate ambiguity and brittle optional dependencies cleanly.
