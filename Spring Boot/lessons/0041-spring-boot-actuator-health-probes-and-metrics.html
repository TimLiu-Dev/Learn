Spring Boot Actuator: Custom Health Indicators & Metrics

Target: When your service is deployed across hundreds of pods in production, you cannot SSH into machines or read raw logs to determine if the application is healthy. Spring Boot Actuator is the production operational backbone of the Spring framework. It exposes production-ready endpoints for health checks, application info, environment variables, thread dumps, and Prometheus metrics. In this lesson, we configure Kubernetes Liveness and Readiness probes, implement custom HealthIndicators to detect downstream dependency outages, and expose custom Micrometer business metrics to Prometheus.

📖 Primary Source Recommendation

Study the official authority: Spring Boot Actuator Reference Documentation & Micrometer Instrumentation Guide.. Ground your learning in primary architecture rather than secondary summaries.

💡 Why This Matters in Production

If your Kubernetes readiness probe checks the database on every HTTP ping, a brief database network blip causes Kubernetes to kill all pods simultaneously, escalating a minor latency spike into a total catastrophic outage. Senior engineers understand the distinct roles of liveness versus readiness, and how to protect health probes from cascading failures.

Key Architectural Takeaways

  • Spring Boot Actuator separates health into two distinct Kubernetes probe groups: '/actuator/health/liveness' (is the process deadlocked/broken?) and '/actuator/health/readiness' (can it receive traffic right now?).
  • Never perform heavy database queries or network calls inside a Liveness probe! If downstream times out, Kubernetes will violently terminate your container in a crash loop.
  • Readiness probes inspect internal dependencies (database connectivity, cache reachability, Kafka consumer assignment) before accepting customer traffic.
  • Implement custom 'HealthIndicator' beans to publish service-specific health states with diagnostic details.
  • Micrometer is the vendor-neutral metrics facade for Spring: publish business KPIs (e.g. 'orders.created', 'payment.latency') using Counters, Gauges, and Timers.
  • Expose Prometheus metrics on '/actuator/prometheus' for scraping by Prometheus or Datadog agents.

1. The Difference Between Liveness and Readiness

Probe Endpoint Purpose Action on Failure
Liveness /actuator/health/liveness Checks if the JVM is alive and responsive (not stuck in an infinite loop or deadlock). Kubernetes restarts (kills) the Pod.
Readiness /actuator/health/readiness Checks if the service is ready to accept incoming user requests (DB connected, cache warm). Kubernetes removes Pod from Service load balancer. Pod is NOT restarted.

2. The Cascading Failure Trap

If you configure a Liveness probe to check PostgreSQL connectivity:

  1. PostgreSQL experiences a 10-second CPU spike.
  2. Liveness checks on all 20 Spring Boot pods time out.
  3. Kubernetes assumes all 20 pods are broken and kills them simultaneously!
  4. All 20 pods reboot at the exact same moment, hammering PostgreSQL with hundreds of startup connection handshakes, guaranteeing PostgreSQL crashes completely!

Rule: Liveness probes should ONLY verify internal JVM health (e.g. memory/deadlocks). Only Readiness probes should check external dependencies.

package com.example.actuator;

import io.micrometer.core.instrument.Counter;
import io.micrometer.core.instrument.MeterRegistry;
import io.micrometer.core.instrument.Timer;
import org.springframework.boot.actuate.health.Health;
import org.springframework.boot.actuate.health.HealthIndicator;
import org.springframework.stereotype.Component;

import java.time.Duration;

// 1. Custom Health Indicator for Downstream Payment Gateway
@Component
class PaymentGatewayHealthIndicator implements HealthIndicator {
    private final PaymentClient paymentClient;

    public PaymentGatewayHealthIndicator(PaymentClient paymentClient) {
        this.paymentClient = paymentClient;
    }

    @Override
    public Health health() {
        try {
            boolean available = paymentClient.pingGateway();
            if (available) {
                return Health.up()
                    .withDetail("gateway", "Stripe API")
                    .withDetail("responseTimeMs", 42)
                    .build();
            } else {
                return Health.down()
                    .withDetail("gateway", "Stripe API")
                    .withDetail("reason", "Gateway returned 503 Service Unavailable")
                    .build();
            }
        } catch (Exception ex) {
            return Health.down(ex)
                .withDetail("gateway", "Stripe API")
                .build();
        }
    }
}

// 2. Custom Business Metrics with Micrometer
@Component
class OrderMetricsService {
    private final Counter orderSuccessCounter;
    private final Counter orderFailureCounter;
    private final Timer orderProcessingTimer;

    public OrderMetricsService(MeterRegistry registry) {
        this.orderSuccessCounter = Counter.builder("orders.placed.total")
            .description("Total number of successfully placed orders")
            .tag("status", "success")
            .register(registry);

        this.orderFailureCounter = Counter.builder("orders.placed.total")
            .description("Total number of failed orders")
            .tag("status", "failure")
            .register(registry);

        this.orderProcessingTimer = Timer.builder("orders.processing.duration")
            .description("Time taken to process and fulfill an order")
            .publishPercentileHistogram()
            .register(registry);
    }

    public void recordSuccess() {
        orderSuccessCounter.increment();
    }

    public void recordFailure() {
        orderFailureCounter.increment();
    }

    public void recordDuration(Duration duration) {
        orderProcessingTimer.record(duration);
    }
}

interface PaymentClient {
    boolean pingGateway();
}
package com.example.actuator

import io.micrometer.core.instrument.Counter
import io.micrometer.core.instrument.MeterRegistry
import io.micrometer.core.instrument.Timer
import org.springframework.boot.actuate.health.Health
import org.springframework.boot.actuate.health.HealthIndicator
import org.springframework.stereotype.Component
import java.time.Duration

@Component
class PaymentGatewayHealthIndicator(private val paymentClient: PaymentClient) : HealthIndicator {

    override fun health(): Health {
        return try {
            if (paymentClient.pingGateway()) {
                Health.up()
                    .withDetail("gateway", "Stripe API")
                    .withDetail("responseTimeMs", 42)
                    .build()
            } else {
                Health.down()
                    .withDetail("gateway", "Stripe API")
                    .withDetail("reason", "503 Service Unavailable")
                    .build()
            }
        } catch (e: Exception) {
            Health.down(e).withDetail("gateway", "Stripe API").build()
        }
    }
}

@Component
class OrderMetricsService(registry: MeterRegistry) {
    private val successCounter: Counter = Counter.builder("orders.placed.total")
        .tag("status", "success")
        .register(registry)

    private val failureCounter: Counter = Counter.builder("orders.placed.total")
        .tag("status", "failure")
        .register(registry)

    private val timer: Timer = Timer.builder("orders.processing.duration")
        .publishPercentileHistogram()
        .register(registry)

    fun recordSuccess() = successCounter.increment()
    fun recordFailure() = failureCounter.increment()
    fun recordDuration(duration: Duration) = timer.record(duration)
}

interface PaymentClient {
    fun pingGateway(): Boolean
}

💡 Complete Production Reference Solution
Java 21 Implementation:
package com.example.actuator;

import org.springframework.boot.actuate.health.Health;
import org.springframework.boot.actuate.health.HealthIndicator;
import org.springframework.stereotype.Component;

interface ExternalCheckService {
    boolean isReachable();
}

@Component
public class ExternalServiceHealthIndicator implements HealthIndicator {
    private final ExternalCheckService checkService;

    public ExternalServiceHealthIndicator(ExternalCheckService checkService) {
        this.checkService = checkService;
    }

    @Override
    public Health health() {
        if (checkService.isReachable()) {
            return Health.up().build();
        } else {
            return Health.down().withDetail("error", "ThirdParty down").build();
        }
    }
}
Kotlin 2.x Implementation:
package com.example.actuator

import org.springframework.boot.actuate.health.Health
import org.springframework.boot.actuate.health.HealthIndicator
import org.springframework.stereotype.Component

interface ExternalCheckService {
    fun isReachable(): Boolean
}

@Component
class ExternalServiceHealthIndicator(private val checkService: ExternalCheckService) : HealthIndicator {

    override fun health(): Health {
        return if (checkService.isReachable()) {
            Health.up().build()
        } else {
            Health.down().withDetail("error", "ThirdParty down").build()
        }
    }
}
