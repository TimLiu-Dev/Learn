Database Migrations with Flyway in CI/CD

Target: Eliminate database drift. Master versioned SQL migrations with Flyway, immutable checksums, repeatable scripts, and zero-downtime schema evolution.

📖 Primary Source Recommendation

Study the official authority: Flyway Documentation: Core Concepts & Principles. Ground your learning in primary architecture rather than secondary summaries.

1. Why `ddl-auto = update` Is Banned in Production

Hibernate's spring.jpa.hibernate.ddl-auto=update allows rapid prototyping, but is strictly prohibited in senior enterprise environments:

  • It never deletes obsolete columns or tables (leading to schema rot).
  • It cannot create performance indexes, partial indexes, or custom check constraints.
  • When multiple server pods start simultaneously, they run concurrent alter-table statements, deadlocking the database!

2. How Flyway Works

Flyway executes SQL scripts from src/main/resources/db/migration in alphabetical/numerical order and records their SHA-256 checksums in a metadata table: flyway_schema_history.

Naming Convention: V1__create_users_table.sql # Versioned migration (runs once, immutable) V2__add_email_index.sql # Versioned migration (runs once, immutable) R__create_order_summary_view.sql # Repeatable migration (runs whenever file changes)

3. Dual Java & Kotlin Flyway Migration Callbacks

Flyway Java Migration Callback 
package com.example.ecommerce.database;

import org.flywaydb.core.api.callback.*;
import org.springframework.stereotype.Component;

@Component
public class FlywayAuditCallback implements Callback {

    @Override
    public boolean supports(Event event, Context context) {
        return event == Event.AFTER_MIGRATE;
    }

    @Override
    public boolean canHandleInTransaction(Event event, Context context) {
        return true;
    }

    @Override
    public void handle(Event event, Context context) {
        System.out.println("Flyway migration completed successfully! Verifying schema integrity.");
    }

    @Override
    public String getCallbackName() {
        return "FlywayAuditCallback";
    }
}

    sku VARCHAR(50) NOT NULL UNIQUE,

);
Kotlin 2.x Implementation:
CREATE TABLE products (
    id BIGSERIAL PRIMARY KEY,
    sku VARCHAR(50) NOT NULL UNIQUE,
    price NUMERIC(10, 2) NOT NULL
);
Architectural Breakdown:

Using BIGSERIAL ensures 64-bit ID safety. NUMERIC(10,2) avoids floating-point rounding errors on currency. NOT NULL UNIQUE ensures data integrity at the database boundary.
