Consumer-Driven Contract Testing (Spring Cloud Contract) & Repo-Wide ArchUnit Guardrails

Target: As backend teams scale from 1 service to 15 microservices, two silent failures appear: (1) Service A renames a JSON field in a PR, passing all its own unit tests while breaking Service B in staging, and (2) junior PRs bypass service boundaries or sneak in @Autowired field injection. Automate both defenses in CI using Spring Cloud Contract (Consumer-Driven Contracts + WireMock Stubs) and standalone ArchUnit architecture tests.

📖 Primary Source Recommendation

Study the official authorities: Spring Cloud Contract Reference Documentation and ArchUnit Official User Guide.

💡 Android Mental Model Bridge

Remember how you hated discovering in production that the backend team renamed priceCents to amountCents? Consumer-Driven Contract Testing turns the API contract into an automated JUnit test on the provider build AND publishes a verified WireMock stub JAR so consumers test against verified truth instead of hand-typed mocks!

1. Spring Cloud Contract vs. Hand-Written WireMock Mocks

  • The Hand-Written Mock Drift Problem: Hand-written WireMock JSON stubs in Service B stay green forever even after Service A removes a field.
  • The Spring Cloud Contract Loop: Define a YAML/Groovy contract (request + response). During Service A's build, Spring Cloud Contract auto-generates a JUnit MockMvc test verifying Service A fulfills the contract AND publishes a -stubs.jar artifact. Service B loads that exact stub via @AutoConfigureStubRunner.
  • Repo-Wide ArchUnit Tests: Beyond Spring Modulith, standalone ArchUnit JUnit tests enforce universal code standards automatically in CI: banning @Autowired field injection, ensuring @RestController classes never inject JpaRepository directly, and enforcing layered/hexagonal package dependencies.

1. The Consumer-Driven Contract Feedback Loop

1. Contract YAML (orders_v1.yml) lives in Provider repo (Order Service) 2. Order Service CI build: Spring Cloud Contract generates MockMvc test ==> Verifies real Controller + publishes orders-stubs.jar! 3. Consumer CI build (Shipping Service): @AutoConfigureStubRunner boots WireMock from orders-stubs.jar (Zero unverified mocks!)

2. High-Leverage ArchUnit Guardrails for Every Spring Boot Codebase

Code review comments ("please don't use field injection", "don't return @Entity from controllers") inevitably slip through on Friday afternoons. Encoding those exact invariants in a 30-line JUnit ArchitectureGuardTest inspects compiled JVM bytecode in < 500ms with zero Spring context startup cost—guaranteeing that controller-to-repository shortcuts, cyclic package imports, and unannotated @Transactional boundary leaks fail CI deterministically forever.

2. Production Implementation (Java 25 vs Kotlin 2.2+)

Standalone ArchUnit Guardrails (No Field Injection + Layer Boundaries) 
package com.nexus.arch;

import com.tngtech.archunit.junit.AnalyzeClasses;
import com.tngtech.archunit.junit.ArchTest;
import com.tngtech.archunit.lang.ArchRule;
import com.tngtech.archunit.library.GeneralCodingRules;
import org.springframework.web.bind.annotation.RestController;

import static com.tngtech.archunit.lang.syntax.ArchRuleDefinition.noClasses;
import static com.tngtech.archunit.library.Architectures.layeredArchitecture;

@AnalyzeClasses(packages = "com.nexus")
public class ArchitectureGuardTest {

    @ArchTest
    static final ArchRule no_field_injection =
        GeneralCodingRules.NO_CLASSES_SHOULD_USE_FIELD_INJECTION;

    @ArchTest
    static final ArchRule controllers_never_access_repositories_directly =
        noClasses().that().areAnnotatedWith(RestController.class)
            .should().dependOnClassesThat().haveSimpleNameEndingWith("Repository");

    @ArchTest
    static final ArchRule enforce_clean_layers = layeredArchitecture()
        .consideringAllDependencies()
        .layer("Web").definedBy("..web..")
        .layer("Service").definedBy("..service..")
        .layer("Persistence").definedBy("..repository..")
        .whereLayer("Web").mayNotBeAccessedByAnyLayer()
        .whereLayer("Service").mayOnlyBeAccessedByLayers("Web");
}
package com.nexus.arch

import com.tngtech.archunit.junit.AnalyzeClasses
import com.tngtech.archunit.junit.ArchTest
import com.tngtech.archunit.lang.ArchRule
import com.tngtech.archunit.lang.syntax.ArchRuleDefinition.noClasses
import com.tngtech.archunit.library.GeneralCodingRules
import org.springframework.web.bind.annotation.RestController

@AnalyzeClasses(packages = ["com.nexus"])
class ArchitectureGuardTest {

    @ArchTest
    val noFieldInjection: ArchRule =
        GeneralCodingRules.NO_CLASSES_SHOULD_USE_FIELD_INJECTION

    @ArchTest
    val controllersNeverAccessRepositories: ArchRule =
        noClasses().that().areAnnotatedWith(RestController::class.java)
            .should().dependOnClassesThat().haveSimpleNameEndingWith("Repository")
}
