Structured JSON Logging & High-Cardinality Metric Traps

Target: In Part 1, you enabled Actuator metrics and OpenTelemetry trace IDs. At production scale across 50 microservices, two silent failures break observability: unparseable plain-text multi-line stack traces that shatter log aggregation, and high-cardinality metric tags (like putting userId or orderId on a Micrometer Counter) that explode Prometheus memory and crash your monitoring stack. In this lesson, we configure Spring Boot 3.4+/4.0 native Structured JSON Logging, bind high-cardinality IDs safely into logs and trace spans instead of metrics, and configure Micrometer tag guards.

📖 Primary Source Recommendation

Study the official authority: Spring Boot Reference: Structured Logging (ECS & Logstash) and Micrometer Naming & Cardinality Best Practices.

💡 Why This Matters in Production

Think of metrics vs. logs like Android Analytics vs. Crashlytics breadcrumbs: aggregate counters track bounded categories (country, payment_method), while unbounded IDs (userId, orderId) belong in structured logs and trace attributes. One careless .tag("orderId", id) creates millions of unique Prometheus time series and triggers OOM kills on your observability cluster.

Key Architectural Takeaways

  • Zero-XML Structured Logging (Boot 3.4+ / 4.0): Enable logging.structured.format.console=ecs (Elastic Common Schema) or logstash to emit single-line JSON records with nested exception stack traces and automatic traceId/spanId fields.
  • The Cardinality Rule: Every unique combination of metric tag values creates a brand-new time series in Prometheus/Mimir. Never use unbounded values (userId, requestId, email, raw URL paths with IDs) as Micrometer tags.
  • Defense via MeterFilter.maximumAllowableTags: Guard shared metric prefixes in code so a runaway tag bug caps series growth instead of taking down Prometheus.
  • Put High-Cardinality Context in Logs & Spans: Use Slf4j MDC (or Logback structured key-value API) and OpenTelemetry span tags for per-order debugging; keep metric tags strictly low-cardinality (status, tier, region).
  • Prometheus Exemplars: Link a high-latency metric bucket directly to one real traceId without polluting metric cardinality.

// MetricsGuardConfig.java — Cap runaway tag cardinality + log unbounded IDs safely
package com.nexus.observability;

import io.micrometer.core.instrument.Counter;
import io.micrometer.core.instrument.MeterRegistry;
import io.micrometer.core.instrument.config.MeterFilter;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.boot.actuate.autoconfigure.metrics.MeterRegistryCustomizer;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class MetricsGuardConfig {
    private static final Logger log = LoggerFactory.getLogger(MetricsGuardConfig.class);

    @Bean
    MeterRegistryCustomizer<MeterRegistry> cardinalityGuard() {
        return registry -> registry.config().meterFilter(
            MeterFilter.maximumAllowableTags("nexus.orders", "tenant_tier", 50, MeterFilter.deny())
        );
    }

    public void recordOrderPlaced(MeterRegistry registry, String orderId, String tenantTier) {
        // SAFE: Bounded tag ('FREE', 'PRO', 'ENTERPRISE') in metric
        Counter.builder("nexus.orders.placed")
               .tag("tenant_tier", tenantTier)
               .register(registry)
               .increment();

        // SAFE: Unbounded 'orderId' goes into structured JSON log, NOT metric tags
        log.atInfo()
           .addKeyValue("order_id", orderId)
           .addKeyValue("tenant_tier", tenantTier)
           .log("Order persisted and queued");
    }
}

// MetricsGuardConfig.kt — Cap runaway tag cardinality + structured logging
package com.nexus.observability

import io.micrometer.core.instrument.Counter
import io.micrometer.core.instrument.MeterRegistry
import io.micrometer.core.instrument.config.MeterFilter
import org.slf4j.LoggerFactory
import org.springframework.boot.actuate.autoconfigure.metrics.MeterRegistryCustomizer
import org.springframework.context.annotation.Bean
import org.springframework.context.annotation.Configuration

@Configuration
class MetricsGuardConfig {
    private val log = LoggerFactory.getLogger(MetricsGuardConfig::class.java)

    @Bean
    fun cardinalityGuard(): MeterRegistryCustomizer<MeterRegistry> =
        MeterRegistryCustomizer { registry ->
            registry.config().meterFilter(
                MeterFilter.maximumAllowableTags("nexus.orders", "tenant_tier", 50, MeterFilter.deny())
            )
        }

    fun recordOrderPlaced(registry: MeterRegistry, orderId: String, tenantTier: String) {
        Counter.builder("nexus.orders.placed")
            .tag("tenant_tier", tenantTier)
            .register(registry)
            .increment()

        log.atInfo()
            .addKeyValue("order_id", orderId)
            .addKeyValue("tenant_tier", tenantTier)
            .log("Order persisted and queued")
    }
}
