Role-Based Access Control (RBAC) & Method Security

Target: Protect internal business logic. Enable @EnableMethodSecurity, configure @PreAuthorize, and prevent Insecure Direct Object Reference (IDOR) vulnerabilities with Spring Expression Language (SpEL).

📖 Primary Source Recommendation

Study the official authority: Spring Security Reference: Method Security. Ground your learning in primary architecture rather than secondary summaries.

1. Why Endpoint URL Security Is Not Enough

Configuring security only in SecurityFilterChain (e.g. .requestMatchers("/admin/**")) leaves internal service beans unprotected if called from background workers, scheduled cron jobs, or Kafka listeners.

Method Security: Places security guards directly on service interfaces and methods using @PreAuthorize.

2. Preventing IDOR with SpEL (Spring Expression Language)

⚠️ The OWASP #1 IDOR Vulnerability

A user logs in as User #5. They call GET /api/v1/orders/8921. If the server only checks isAuthenticated() without checking whether Order #8921 belongs to User #5, User #5 can view all orders across the entire company!

Using SpEL expressions in @PreAuthorize, you can enforce domain object ownership directly:

@PreAuthorize("hasRole('ADMIN') or #customerId == authentication.principal.id") public CustomerProfile getProfile(String customerId) { ... }

3. Production Dual Method Security Service

Method Security Service 
package com.example.ecommerce.user;

import org.springframework.security.access.prepost.PreAuthorize;
import org.springframework.security.config.annotation.method.configuration.EnableMethodSecurity;
import org.springframework.stereotype.Service;

@Service
@EnableMethodSecurity // Activates @PreAuthorize across Spring beans!
public class UserManagementService {

    @PreAuthorize("hasRole('ADMIN')")
    public void deleteUser(String userId) {
        System.out.println("User " + userId + " deleted by administrator.");
    }

    @PreAuthorize("hasRole('ADMIN') or #userId == authentication.name")
    public UserProfile updateProfile(String userId, UserProfile update) {
        System.out.println("Updating profile for user: " + userId);
        return update;
    }
}
package com.example.ecommerce.user

import org.springframework.security.access.prepost.PreAuthorize
import org.springframework.security.config.annotation.method.configuration.EnableMethodSecurity
import org.springframework.stereotype.Service

@Service
@EnableMethodSecurity
class UserManagementService {

    @PreAuthorize("hasRole('ADMIN')")
    fun deleteUser(userId: String) {
        println("User $userId deleted by administrator.")
    }

    @PreAuthorize("hasRole('ADMIN') or #userId == authentication.name")
    fun updateProfile(userId: String, update: UserProfile): UserProfile {
        println("Updating profile for user: $userId")
        return update
    }
}

Architectural Breakdown:

@PreAuthorize evaluates Spring Security's GrantedAuthority collection before method entry, throwing an AccessDeniedException (HTTP 403) if the caller lacks ROLE_ADMIN.
