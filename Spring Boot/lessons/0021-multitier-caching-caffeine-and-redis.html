Multi-Tier Caching: L1 Caffeine + L2 Redis & Stampede Defense

Target: Architect enterprise multi-tier caching. Combine sub-microsecond in-process Caffeine cache (L1) with distributed Redis cache (L2), synchronize invalidation via Redis Pub/Sub, and eliminate cache stampedes.

📖 Primary Source Recommendation

Study the official authority: Caffeine High-Performance In-Memory Cache Documentation. Ground your learning in primary architecture rather than secondary summaries.

1. Why Redis Network Roundtrips Slow Down High-Frequency Reads

Redis is fast (~1 millisecond over TCP), but for ultra-hot data queried 100,000 times per second (e.g. system configurations, tenant metadata, hot catalog items), network roundtrip latency and serialization become bottlenecks.

Multi-Tier Caching Architecture:

  • L1 In-Memory Cache (Caffeine): Lives directly inside JVM heap RAM. Access time: sub-microsecond (< 100ns) with zero serialization!
  • L2 Distributed Cache (Redis): Shared across all container pods. Access time: ~1ms.
  • L3 Relational Database (PostgreSQL): Disk/SSD access.

2. Invalidation Synchronization via Redis Pub/Sub

The classic problem with L1 in-process caching is cache inconsistency: If Pod A updates a product, how do Pod B and Pod C know to invalidate their local Caffeine caches?

1. Pod A updates product #42 in PostgreSQL & L2 Redis. 2. Pod A publishes an invalidation event to Redis topic: "cache:evict:products" -> "42" 3. Pod B and Pod C receive the message via Redis Pub/Sub listener! 4. Pod B & C immediately evict key "42" from their local Caffeine L1 caches!

3. Production Dual Multi-Tier Cache Manager

Multi-Tier Caching Service 
package com.example.ecommerce.cache;

import com.github.benmanes.caffeine.cache.Cache;
import com.github.benmanes.caffeine.cache.Caffeine;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Service;
import java.time.Duration;

@Service
public class MultiTierCacheService {

    // L1: In-process Caffeine Cache
    private final Cache<String, String> l1Cache = Caffeine.newBuilder()
        .maximumSize(10_000)
        .expireAfterWrite(Duration.ofMinutes(5))
        .build();

    private final StringRedisTemplate redis;

    public MultiTierCacheService(StringRedisTemplate redis) {
        this.redis = redis;
    }

    public String get(String key) {
        // 1. Check L1 Caffeine (sub-microsecond)
        String value = l1Cache.getIfPresent(key);
        if (value != null) return value;

        // 2. Check L2 Redis (~1ms)
        value = redis.opsForValue().get(key);
        if (value != null) {
            l1Cache.put(key, value); // Populate L1
            return value;
        }

        return null; // L3 DB miss handled by caller
    }

    public void evict(String key) {
        l1Cache.invalidate(key);
        redis.delete(key);
        redis.convertAndSend("cache:evict", key); // Notify peer pods!
    }
}
package com.example.ecommerce.cache

import com.github.benmanes.caffeine.cache.Cache
import com.github.benmanes.caffeine.cache.Caffeine
import org.springframework.data.redis.core.StringRedisTemplate
import org.springframework.stereotype.Service
import java.time.Duration

@Service
class MultiTierCacheService(
    private val redis: StringRedisTemplate
) {
    // L1: In-process Caffeine Cache
    private final val l1Cache: Cache<String, String> = Caffeine.newBuilder()
        .maximumSize(10_000)
        .expireAfterWrite(Duration.ofMinutes(5))
        .build()

    fun get(key: String): String? {
        // 1. Check L1 Caffeine
        l1Cache.getIfPresent(key)?.let { return it }

        // 2. Check L2 Redis
        val redisVal = redis.opsForValue().get(key)
        if (redisVal != null) {
            l1Cache.put(key, redisVal)
            return redisVal
        }

        return null
    }

    fun evict(key: String) {
        l1Cache.invalidate(key)
        redis.delete(key)
        redis.convertAndSend("cache:evict", key)
    }
}

Java 21 Implementation:
package com.example.cache;

import com.github.benmanes.caffeine.cache.Cache;
import org.springframework.data.redis.core.StringRedisTemplate;

public class MultiTierReader {
    public static String getWithFallback(Cache<String, String> l1, StringRedisTemplate redis, String key) {
        String val = l1.getIfPresent(key);
        if (val != null) return val;

        val = redis.opsForValue().get(key);
        if (val != null) {
            l1.put(key, val);
            return val;
        }
        return null;
    }
}

Architectural Breakdown:

L1 Caffeine avoids network hops for hot keys, while L2 Redis acts as the shared cluster source of truth before hitting PostgreSQL.
