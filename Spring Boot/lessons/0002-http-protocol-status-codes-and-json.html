The HTTP Protocol, Status Codes & Jackson 3 JSON Serialization

Target: Master the universal web contract. Understand HTTP methods, status code families (2xx, 4xx, 5xx), why security checks must run in strict evaluation order, and how Spring Boot 4's Jackson 3 JsonMapper converts JSON bytes into immutable Java Records and Kotlin data classes with exact BigDecimal money and UTC Instant timestamps.

📖 Primary Source Recommendation

Study the official authorities: RFC 9110: HTTP Semantics Specification and Spring Boot Reference: Jackson JSON Serialization.

1. What Does an HTTP Request Actually Look Like?

When your Android Retrofit code executes @GET("/api/v1/orders/8921"), OkHttp transmits structured HTTP frames over a TLS/TCP socket:

GET /api/v1/orders/8921 HTTP/1.1 Host: api.nexuscommerce.com Authorization: Bearer eyJhbGciOi... Accept: application/json

2. HTTP Status Codes: The Universal Contract

  • 2xx Success: 200 OK (success with body), 201 Created (resource created with Location header), 204 No Content (success without body, e.g., DELETE).
  • 4xx Client Errors: 400 Bad Request (malformed JSON / validation failure), 401 Unauthorized (missing or invalid credentials—unauthenticated), 403 Forbidden (authenticated identity, insufficient permission), 404 Not Found, 409 Conflict (optimistic lock or duplicate constraint), 429 Too Many Requests.
  • 5xx Server Errors: 500 Internal Server Error (unhandled server bug), 502 Bad Gateway (upstream crash), 503 Service Unavailable.

3. How JSON Becomes Code: Jackson 3 JsonMapper (Spring Boot 4.2)

Spring Boot 4 upgrades to Jackson 3 (tools.jackson.databind.json.JsonMapper): immutable thread-safe builders by default, unchecked JacksonException (no noisy checked JsonProcessingException!), and built-in ISO-8601 support for java.time.Instant without extra modules. Notice too that we use BigDecimal for money (never binary floating-point double, where 0.1 + 0.2 == 0.30000000000000004!).

🔄 In Existing Spring Boot 3.x / Java 25 Codebases

Spring Boot 3.x uses Jackson 2 (com.fasterxml.jackson.databind.ObjectMapper). Note that even in Jackson 3 / Spring Boot 4, Jackson annotations like @JsonProperty and @JsonIgnore intentionally keep the com.fasterxml.jackson.annotation.* package so shared DTO libraries stay binary-compatible!

Jackson 3 JsonMapper Serialization & Deserialization (Exact Money + UTC Instant) 
import tools.jackson.databind.json.JsonMapper;
import java.math.BigDecimal;
import java.time.Instant;

// Immutable Java 25 Record with exact BigDecimal money & UTC Instant
public record OrderDto(String orderId, BigDecimal total, Instant createdAt) {}

public class Jackson3Example {
    public static void main(String[] args) {
        // Jackson 3 JsonMapper is immutable & supports java.time.Instant out of the box!
        JsonMapper mapper = JsonMapper.builder().build();

        // 1. JSON String -> Java Record (Deserialization)
        String json = """
            {"orderId":"ORD-101","total":99.50,"createdAt":"2027-01-15T10:30:00Z"}
            """;
        OrderDto order = mapper.readValue(json, OrderDto.class);

        // 2. Java Record -> JSON String (Serialization)
        String output = mapper.writeValueAsString(order);
        System.out.println(output);
    }
}
import tools.jackson.module.kotlin.jacksonMapperBuilder
import tools.jackson.module.kotlin.readValue
import java.math.BigDecimal
import java.time.Instant

data class OrderDto(
    val orderId: String,
    val total: BigDecimal,
    val createdAt: Instant
)

fun main() {
    val mapper = jacksonMapperBuilder().build()

    // 1. JSON String -> Kotlin Data Class (Deserialization via reified readValue)
    val json = """{"orderId":"ORD-101","total":99.50,"createdAt":"2027-01-15T10:30:00Z"}"""
    val order: OrderDto = mapper.readValue(json)

    // 2. Kotlin Data Class -> JSON String (Serialization)
    val output = mapper.writeValueAsString(order)
    println(output)
}

Lab 0002 Status Code Security Decision Router
To Do

Goal: Implement resolveStatus(boolean authenticated, boolean authorized, boolean exists) in strict security order:

  • If not authenticated → return 401
  • Else if not authorized → return 403
  • Else if resource does not exists → return 404
  • Otherwise → return 200
Hint 1: Architectural Nudge
Evaluate conditions in strict security gate order: Authentication (!authenticated) first, Authorization (!authorized) second, Existence (!exists) third.
Hint 2: Syntax Signature
Use guard clauses (if (!authenticated) return 401;) in Java or a when expression in Kotlin.
Hint 3: Concrete Snippet
if (!authenticated) return 401; if (!authorized) return 403; if (!exists) return 404; return 200;
💡 Complete Production Reference Solution
Java 25 Implementation:
package com.example.foundation;

public class HttpStatusRouter {
    public static int resolveStatus(boolean authenticated, boolean authorized, boolean exists) {
        if (!authenticated) return 401;
        if (!authorized) return 403;
        if (!exists) return 404;
        return 200;
    }
}
Kotlin 2.2+ Implementation:
package com.example.foundation

object HttpStatusRouter {
    fun resolveStatus(authenticated: Boolean, authorized: Boolean, exists: Boolean): Int {
        return when {
            !authenticated -> 401
            !authorized -> 403
            !exists -> 404
            else -> 200
        }
    }
}
Architectural Breakdown:

Security evaluation order is non-negotiable: never reveal resource existence (404) to an unauthenticated caller (401), and never check domain permissions before verifying identity.
