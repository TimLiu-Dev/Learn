The HTTP Protocol, Status Codes & JSON Serialization

Target: Master the universal web contract. Understand HTTP methods, status code families (2xx, 4xx, 5xx), and how Jackson ObjectMapper converts JSON bytes into Java/Kotlin objects.

📖 Primary Source Recommendation

Study the official authority: RFC 9110: HTTP Semantics Specification. Ground your learning in primary architecture rather than secondary summaries.

1. What Does an HTTP Request Actually Look Like?

When your Android Retrofit code executes @GET("/users/123"), OkHttp transmits raw ASCII text over a TCP socket:

GET /api/v1/orders/8921 HTTP/1.1 Host: api.nexuscommerce.com Authorization: Bearer eyJhbGciOi... Accept: application/json

2. HTTP Status Codes: The Universal Contract

  • 2xx Success: 200 OK (success with body), 201 Created (resource created with Location header), 204 No Content (success without body).
  • 4xx Client Errors: 400 Bad Request (malformed JSON), 401 Unauthorized (missing/invalid token), 403 Forbidden (valid token, insufficient role), 404 Not Found, 409 Conflict (unique constraint violated).
  • 5xx Server Errors: 500 Internal Server Error (unhandled exception), 502 Bad Gateway (upstream service down), 503 Service Unavailable.

3. How JSON Becomes Code: Jackson ObjectMapper

Jackson Serialization & Deserialization 
import com.fasterxml.jackson.databind.ObjectMapper;

public record OrderDto(String orderId, double amount) {}

public class JacksonExample {
    public static void main(String[] args) throws Exception {
        ObjectMapper mapper = new ObjectMapper();
        
        // 1. JSON String to Java Record (Deserialization)
        String json = "{\"orderId\":\"ORD-101\",\"amount\":99.50}";
        OrderDto order = mapper.readValue(json, OrderDto.class);
        
        // 2. Java Record to JSON String (Serialization)
        String output = mapper.writeValueAsString(order);
        System.out.println(output);
    }
}
import com.fasterxml.jackson.module.kotlin.jacksonObjectMapper
import com.fasterxml.jackson.module.kotlin.readValue

data class OrderDto(val orderId: String, val amount: Double)

fun main() {
    val mapper = jacksonObjectMapper()
    
    // 1. JSON String to Kotlin Data Class (Deserialization)
    val json = """{"orderId":"ORD-101","amount":99.50}"""
    val order: OrderDto = mapper.readValue(json)
    
    // 2. Kotlin Data Class to JSON String (Serialization)
    val output = mapper.writeValueAsString(order)
    println(output)
}

Lab 0002 Status Code Decision Router
To Do

Goal: Implement resolveStatus(boolean authenticated, boolean authorized, boolean exists).

  • If not authenticated ➔ return 401
  • Else if not authorized ➔ return 403
  • Else if resource does not exist ➔ return 404
  • Otherwise ➔ return 200
Hint 1: Architectural Nudge
Evaluate conditions in security order: Authentication first, then Authorization, then Existence.
Hint 2: Syntax Signature
Use if/else if branches or Kotlin when expression.
Hint 3: Concrete Snippet
if (!authenticated) return 401; if (!authorized) return 403; if (!exists) return 404; return 200;
💡 Complete Production Reference Solution
Java 21 Implementation:
package com.example.foundation;

public class HttpStatusRouter {
    public static int resolveStatus(boolean authenticated, boolean authorized, boolean exists) {
        if (!authenticated) return 401;
        if (!authorized) return 403;
        if (!exists) return 404;
        return 200;
    }
}
Kotlin 2.x Implementation:
package com.example.foundation

object HttpStatusRouter {
    fun resolveStatus(authenticated: Boolean, authorized: Boolean, exists: Boolean): Int {
        return when {
            !authenticated -> 401
            !authorized -> 403
            !exists -> 404
            else -> 200
        }
    }
}
Architectural Breakdown:

Security evaluation order is non-negotiable: never reveal resource existence (404) to an unauthenticated caller (401), and never allow an unauthenticated actor to bypass authorization (403).
