Distributed Rate Limiting: Token Bucket with Redis & Bucket4j

Target: Protect your APIs from abuse, scraping, and mobile retry loops. Implement the Token Bucket algorithm using Redis and Bucket4j, emit HTTP 429 Too Many Requests, and configure Retry-After headers.

📖 Primary Source Recommendation

Study the official authority: Bucket4j: Java Rate Limiting Library based on Token-Bucket Algorithm. Ground your learning in primary architecture rather than secondary summaries.

1. Why Rate Limiting Is Essential for Mobile Backends

A buggy mobile client with an infinite retry loop or a malicious bot script can fire 50,000 requests per minute at your login or checkout endpoints.

Without distributed rate limiting, your database connection pool starves, causing outages for all legitimate users.

2. The Token Bucket Algorithm

Bucket Concept: - Capacity: 100 tokens max - Refill Rate: 10 tokens added every second - Rule: Each incoming HTTP request consumes 1 token. - If tokens > 0: Request allowed! - If tokens == 0: Request REJECTED! -> HTTP 429 Too Many Requests (Retry-After: 3)

3. Production Dual Rate Limiter with Bucket4j & Redis

Distributed Rate Limiter Service 
package com.example.ecommerce.ratelimit;

import io.github.bucket4j.*;
import org.springframework.stereotype.Service;
import java.time.Duration;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

@Service
public class RateLimiterService {

    private final Map<String, Bucket> buckets = new ConcurrentHashMap<>();

    public boolean tryConsume(String apiKey) {
        Bucket bucket = buckets.computeIfAbsent(apiKey, this::createNewBucket);
        return bucket.tryConsume(1);
    }

    private Bucket createNewBucket(String key) {
        // 50 requests per minute with burst up to 50
        Bandwidth limit = Bandwidth.builder()
            .capacity(50)
            .refillGreedy(50, Duration.ofMinutes(1))
            .build();

        return Bucket.builder()
            .addLimit(limit)
            .build();
    }
}

        return Bucket.builder()

            .build()
    }

package com.example.ratelimit;

public class RateLimitGate {
    public static boolean evaluateRateLimit(int currentTokens, int cost) {
        return currentTokens >= cost;
    }
}
Kotlin 2.x Implementation:
package com.example.ratelimit

object RateLimitGate {
    fun evaluateRateLimit(currentTokens: Int, cost: Int): Boolean =
        currentTokens >= cost
}
Architectural Breakdown:

This decision gate is the fundamental atomic check inside token bucket algorithms: allow if tokens exist, reject with HTTP 429 if depleted.
