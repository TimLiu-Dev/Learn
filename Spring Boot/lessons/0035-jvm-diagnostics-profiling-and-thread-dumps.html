JVM Diagnostics, Profiling & Thread Dumps in Production

Target: When a production service suddenly spikes to 100% CPU, grinds to a 30-second P99 latency halt, or crashes with 'java.lang.OutOfMemoryError: Java heap space', amateur engineers restart the container and pray it doesn't happen again. Senior staff engineers extract diagnostic forensics before restarting: JDK Flight Recorder (JFR) event recordings, thread dumps via 'jcmd', and live memory histograms. In the modern era of Java 21, diagnosing pinned virtual threads, lock contention, and off-heap memory leaks requires mastery of non-invasive JVM observability tools built directly into OpenJDK.

📖 Primary Source Recommendation

Study the official authority: OpenJDK Documentation: Java Flight Recorder and JDK Mission Control Guide & Java 21 jcmd Tool Reference.. Ground your learning in primary architecture rather than secondary summaries.

💡 Why This Matters in Production

In cloud environments running on Kubernetes, restarting a deadlocked pod destroys ephemeral diagnostic evidence. Knowing how to capture on-demand thread dumps, inspect pinned carrier threads via '-Djdk.tracePinnedThreads=full', and run low-overhead JFR continuous recordings gives you the capability to identify root causes within minutes rather than guessing blindly.

Key Architectural Takeaways

  • JDK Flight Recorder (JFR) has less than 1% runtime CPU overhead and captures thread allocations, GC pauses, lock contention, and I/O latency in production.
  • Use 'jcmd Thread.dump_to_file -format=json /tmp/threads.json' in Java 21 to capture both platform and virtual threads in structured JSON format.
  • Detect virtual thread carrier pinning in production logs by starting the JVM with '-Djdk.tracePinnedThreads=full' (or '=short').
  • Diagnose memory leaks using 'jcmd GC.heap_dump /tmp/dump.hprof' and analyze the dominator tree with Eclipse Memory Analyzer Tool (MAT).
  • High CPU with low throughput usually indicates excessive Garbage Collection thrashing (check GC pause times and allocation rates) or spinning lock loops.
  • Spring Boot Actuator '/actuator/threaddump' provides instantaneous thread status over HTTP without needing SSH access to the container.

1. The JFR Continuous Production Recording

Never run external profilers that use bytecode instrumentation in production; they induce stop-the-world pauses and skew timing measurements. Instead, enable continuous JFR: 

java -XX:+FlightRecorder \
     -XX:StartFlightRecording=disk=true,dumponexit=true,filename=/var/log/app.jfr,maxsize=200m,maxage=12h \
     -jar app.jar

This keeps a rolling 12-hour circular buffer of CPU execution samples, memory allocations, and socket latencies. If an outage occurs, dump the recording on demand: 

jcmd 1 JFR.dump filename=/var/log/incident.jfr

Open incident.jfr in JDK Mission Control (JMC) to see flame graphs of method CPU time and allocation hotspots.

2. Diagnosing Virtual Thread Pinning

If your application enables spring.threads.virtual.enabled=true but throughput unexpectedly drops, threads may be pinned inside legacy synchronized libraries. Enable pinning trace logging: 

-Djdk.tracePinnedThreads=full

When a virtual thread attempts a blocking operation while holding a monitor lock, the JVM logs a complete stack trace: 

Thread[#45,ForkJoinPool-1-worker-3,5,CarrierThreads]
    java.base/java.lang.VirtualThread$VThreadContinuation.onPinned(VirtualThread.java:183)
    com.example.LegacyClient.fetch(LegacyClient.java:42) <== PINNED HERE: synchronized(lock)

3. On-Demand JSON Thread Dumps in Java 21

Traditional kill -3 <pid> or jstack outputs thousands of lines of unstructured text that omit virtual threads. Java 21 introduced structured JSON dumps: 

jcmd 1 Thread.dump_to_file -format=json /tmp/threaddump.json

This outputs all thread groupings, virtual thread states, carrier thread pairings, and lock holder object IDs in parseable JSON.

JVM Diagnostics, Profiling & Thread Dumps in Production 
package com.example.diagnostics;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.boot.actuate.endpoint.annotation.Endpoint;
import org.springframework.boot.actuate.endpoint.annotation.ReadOperation;
import org.springframework.stereotype.Component;

import java.lang.management.ManagementFactory;
import java.lang.management.MemoryMXBean;
import java.lang.management.ThreadInfo;
import java.lang.management.ThreadMXBean;
import java.util.Arrays;
import java.util.HashMap;
import java.util.Map;

@Component
@Endpoint(id = "jvmhealth")
class JvmHealthCustomEndpoint {
    private static final Logger log = LoggerFactory.getLogger(JvmHealthCustomEndpoint.class);
    private final ThreadMXBean threadBean = ManagementFactory.getThreadMXBean();
    private final MemoryMXBean memoryBean = ManagementFactory.getMemoryMXBean();

    @ReadOperation
    public Map<String, Object> captureDiagnosticSnapshot() {
        Map<String, Object> snapshot = new HashMap<>();

        // 1. Thread Metrics
        int threadCount = threadBean.getThreadCount();
        int peakThreadCount = threadBean.getPeakThreadCount();
        long[] deadlockedThreads = threadBean.findDeadlockedThreads();

        snapshot.put("liveThreadCount", threadCount);
        snapshot.put("peakThreadCount", peakThreadCount);
        snapshot.put("hasDeadlocks", deadlockedThreads != null && deadlockedThreads.length > 0);
        if (deadlockedThreads != null) {
            snapshot.put("deadlockedThreadIds", deadlockedThreads);
            ThreadInfo[] deadlockedInfo = threadBean.getThreadInfo(deadlockedThreads, 15);
            snapshot.put("deadlockDetails", Arrays.stream(deadlockedInfo).map(ThreadInfo::toString).toList());
        }

        // 2. Heap and Non-Heap Memory Utilization
        var heapMemory = memoryBean.getHeapMemoryUsage();
        var nonHeapMemory = memoryBean.getNonHeapMemoryUsage();

        Map<String, Object> memDetails = new HashMap<>();
        memDetails.put("heapUsedMB", heapMemory.getUsed() / (1024 * 1024));
        memDetails.put("heapMaxMB", heapMemory.getMax() / (1024 * 1024));
        memDetails.put("heapUtilizationPercent", (double) heapMemory.getUsed() / heapMemory.getMax() * 100);
        memDetails.put("nonHeapUsedMB", nonHeapMemory.getUsed() / (1024 * 1024));

        snapshot.put("memory", memDetails);
        return snapshot;
    }
}
package com.example.diagnostics

import org.slf4j.LoggerFactory
import org.springframework.boot.actuate.endpoint.annotation.Endpoint
import org.springframework.boot.actuate.endpoint.annotation.ReadOperation
import org.springframework.stereotype.Component
import java.lang.management.ManagementFactory

@Component
@Endpoint(id = "jvmhealth")
class JvmHealthCustomEndpoint {
    private val log = LoggerFactory.getLogger(JvmHealthCustomEndpoint::class.java)
    private val threadBean = ManagementFactory.getThreadMXBean()
    private val memoryBean = ManagementFactory.getMemoryMXBean()

    @ReadOperation
    fun captureDiagnosticSnapshot(): Map<String, Any> {
        val deadlocked = threadBean.findDeadlockedThreads()
        val heap = memoryBean.heapMemoryUsage
        val nonHeap = memoryBean.nonHeapMemoryUsage

        return mapOf(
            "liveThreadCount" to threadBean.threadCount,
            "peakThreadCount" to threadBean.peakThreadCount,
            "hasDeadlocks" to (deadlocked != null && deadlocked.isNotEmpty()),
            "deadlockedThreadIds" to (deadlocked?.toList() ?: emptyList<Long>()),
            "memory" to mapOf(
                "heapUsedMB" to heap.used / (1024 * 1024),
                "heapMaxMB" to heap.max / (1024 * 1024),
                "heapUtilizationPercent" to (heap.used.toDouble() / heap.max * 100),
                "nonHeapUsedMB" to nonHeap.used / (1024 * 1024)
            )
        )
    }
}

💡 Complete Production Reference Solution
Java 21 Implementation:
package com.example.diagnostics;

import java.lang.management.ManagementFactory;
import java.lang.management.ThreadMXBean;

public class DeadlockDetector {
    private final ThreadMXBean threadMXBean = ManagementFactory.getThreadMXBean();

    public int getDeadlockedThreadCount() {
        long[] ids = threadMXBean.findDeadlockedThreads();
        return ids == null ? 0 : ids.length;
    }
}
Kotlin 2.x Implementation:
package com.example.diagnostics

import java.lang.management.ManagementFactory

class DeadlockDetector {
    private val threadMXBean = ManagementFactory.getThreadMXBean()

    fun getDeadlockedThreadCount(): Int {
        val ids = threadMXBean.findDeadlockedThreads()
        return ids?.size ?: 0
    }
}
