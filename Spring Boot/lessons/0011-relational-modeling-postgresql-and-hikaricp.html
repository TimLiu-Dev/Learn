PostgreSQL Architecture & HikariCP Connection Pool Sizing

Target: Move from Android SQLite/Room to networked PostgreSQL. Understand why connections are expensive, master the HikariCP pool sizing formula, and prevent pool starvation under load.

📖 Primary Source Recommendation

Study the official authority: HikariCP: About Pool Sizing (Brett Wooldridge). Ground your learning in primary architecture rather than secondary summaries.

1. SQLite on Android vs. Networked PostgreSQL

On Android, Room opens a local SQLite file directly on the phone's flash storage. In cloud backends, PostgreSQL is a separate networked server running on Linux. Every connection requires a full TCP handshake, TLS negotiation, authentication, and spawns a dedicated Linux backend process consuming 10–20MB of server RAM!

2. What Is HikariCP and the Pool Sizing Formula?

Junior developers assume that more connections equal more speed: "Let's set maximum-pool-size to 100!". This degrades performance dramatically! When 100 connections fight for 8 CPU cores, the OS spends all its time context-switching between processes instead of executing queries.

Pool Sizing Formula: connections = ((core_count * 2) + effective_spindle_count) For an 8-core server with SSD: (8 * 2) + 1 = 17 connections!

3. Dual Java & Kotlin HikariCP Configuration

Programmatic HikariCP DataSource Configuration 
package com.example.ecommerce.database;

import com.zaxxer.hikari.HikariConfig;
import com.zaxxer.hikari.HikariDataSource;
import org.springframework.context.annotation.*;
import javax.sql.DataSource;
import java.time.Duration;

@Configuration
public class DataSourceConfig {

    @Bean
    public DataSource dataSource() {
        HikariConfig config = new HikariConfig();
        config.setJdbcUrl("jdbc:postgresql://localhost:5432/nexus_db");
        config.setUsername("postgres");
        config.setPassword("secret");
        
        // Senior pool tuning:
        config.setMaximumPoolSize(16);
        config.setMinimumIdle(4);
        config.setConnectionTimeout(Duration.ofSeconds(10).toMillis());
        config.setIdleTimeout(Duration.ofMinutes(10).toMillis());
        config.setMaxLifetime(Duration.ofMinutes(30).toMillis());
        config.setPoolName("NexusHikariPool");

        return new HikariDataSource(config);
    }
}

Lab 0011 Calculate HikariCP Optimal Pool Size
To Do

Goal: Implement calculatePoolSize(int cpuCores, int diskSpindles):

Use Brett Wooldridge's formula: poolSize = (cpuCores * 2) + diskSpindles.

If cpuCores <= 0 or diskSpindles < 0, throw an IllegalArgumentException.

Hint 1: Architectural Nudge
Check if cpuCores <= 0 or diskSpindles < 0 and throw new IllegalArgumentException().
Hint 2: Syntax Signature
Return (cpuCores * 2) + diskSpindles.
Hint 3: Concrete Snippet
if (cpuCores <= 0 || diskSpindles < 0) throw new IllegalArgumentException(); return (cpuCores * 2) + diskSpindles;
💡 Complete Production Reference Solution
Java 21 Implementation:
package com.example.database;

public class HikariSizer {
    public static int calculatePoolSize(int cpuCores, int diskSpindles) {
        if (cpuCores <= 0 || diskSpindles < 0) {
            throw new IllegalArgumentException("Invalid hardware parameters");
        }
        return (cpuCores * 2) + diskSpindles;
    }
}
Kotlin 2.x Implementation:
package com.example.database

object HikariSizer {
    fun calculatePoolSize(cpuCores: Int, diskSpindles: Int): Int {
        require(cpuCores > 0 && diskSpindles >= 0) { "Invalid hardware parameters" }
        return (cpuCores * 2) + diskSpindles
    }
}
Architectural Breakdown:

Understanding this formula prevents connection pool starvation and CPU thrashing under high concurrency, separating senior backend engineers from junior developers who guess pool sizes.
