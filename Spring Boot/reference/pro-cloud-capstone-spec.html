NexusCommerce Production Platform: AWS, Kubernetes & LGTM Observability

In Part 1's Capstone, you built the NexusCommerce core application. In this Part 2 Capstone, you prove Staff/Platform-grade operational autonomy by taking NexusCommerce to production: provisioning AWS infrastructure declaratively with Terraform, operating zero-downtime Kubernetes workloads, and enforcing SLOs with full OpenTelemetry & Grafana LGTM observability.

1. Production Platform Architecture

2. Required Production Deliverables

✓
1. Declarative AWS Infrastructure (Terraform / OpenTofu): Provision a Multi-AZ VPC (private subnets for RDS and EKS nodes), RDS PostgreSQL with RDS Proxy, S3 bucket with CORS/SSE, SQS queue + DLQ, and least-privilege IAM roles via EKS Pod Identity / IRSA—zero AWS Console ClickOps.
✓
2. Hardened Kubernetes Manifests (Kustomize / Helm): Configure non-root Distroless/Buildpack images, JVM container memory flags (-XX:MaxRAMPercentage=75.0), CPU requests without latency-inducing tight limits.cpu throttling, HorizontalPodAutoscaler, PodDisruptionBudget, preStop sleep + graceful shutdown, and External Secrets Operator sync.
✓
3. Zero-Downtime Release & Expand-and-Contract Drill: Ship a backward-compatible schema migration (e.g., renaming or splitting an order column) across two rolling/canary releases without dropping a single checkout request.
✓
4. Full LGTM Observability & SLO Burn-Rate Alerting: Run structured ECS JSON logs with traceId/spanId, OpenTelemetry OTLP export, and Prometheus histograms (serviceLevelObjectives) free of high-cardinality tags (userId banned from metric labels). Define an error budget and multi-window burn-rate alert for POST /orders P99 < 250ms.
✓
5. Incident Simulation & Production Readiness Runbook: Trigger a simulated downstream slowdown or pod termination during load testing (k6), verify 0% HTTP 502s, trace the bottleneck from Prometheus Exemplar → Tempo span → Loki logs, and document the recovery steps in a RUNBOOK.md.

3. Ready-to-Use Senior / Platform Resume Bullets

NexusCommerce Production Platform — AWS, Kubernetes, Terraform & OpenTelemetry LGTM
  • Provisioned multi-AZ AWS infrastructure (VPC, private-subnet RDS PostgreSQL with RDS Proxy, S3, SQS, and EKS Pod Identity IAM) via modular Terraform configurations in GitOps PR workflows.
  • Eliminated deployment 502s and JVM CFS CPU throttling spikes by tuning Kubernetes HPA, PodDisruptionBudgets, graceful shutdown with preStop hooks, and Expand-and-Contract Flyway migrations.
  • Built end-to-end Grafana LGTM observability (Loki structured JSON logs, Tempo OTLP traces, Prometheus/Mimir histograms with trace exemplars) and SLO burn-rate alerts protecting P99 checkout latency.
  • Hardened the CI/CD software supply chain in GitHub Actions with non-root Distroless containers, CycloneDX SBOM generation, Trivy vulnerability gates, and Cosign artifact signing.
