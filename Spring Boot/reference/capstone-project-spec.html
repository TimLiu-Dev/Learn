Project 2: NexusCommerce — Distributed Event-Driven Order & Ledger Engine

To land senior backend roles in 2027 and overcome the "zero prior backend experience" stigma, you need an end-to-end distributed system built strictly with the skills mastered in Stages 1 & 2 (Lessons 0001–0057): high concurrency, race-condition defense, distributed caching & rate limiting, zero-trust security, Kafka Transactional Outbox messaging, and real Testcontainers verification. (Container hardening, OpenTelemetry/Grafana SLOs, CI/CD, and AWS follow next in Milestone 3!)

1. Stage 2 Distributed System Architecture

[ Android / iOS / Web Clients ] │ (HTTPS / REST + ETag + SSE Live Order Stream) ▼ [ Spring Boot 4.2 Core Order & Ledger Engine (Java 25 LTS) ] ├─ Virtual Threads (JEP 491) + ScopedValue Request Context ├─ Spring Security 7 (Stateless JWT RTR, Passkeys/PKCE, @PreAuthorize RBAC, Argon2id) ├─ Spring Modulith 2 Boundaries + Resilience4j CircuitBreaker + HMAC-SHA256 Webhooks │ ├──► [ PostgreSQL 17 Primary + Read Replica ] │ ├─ AbstractRoutingDataSource (@Transactional(readOnly = true) ──► REPLICA) │ ├─ Optimistic Locking (@Version) & Pessimistic Ledger Locking (FOR UPDATE) │ └─ ShedLock Distributed Cron Jobs + Range-Partitioned Audit Log │ ├──► [ Redis 7 ] (Multi-Tier Cache, Locks & Traffic Control) │ ├─ L1 Caffeine + L2 Redis JSON Cache (@Cacheable + Pub/Sub invalidation) │ └─ X-Idempotency-Key Deduplication + Bucket4j Token-Bucket Rate Limiting │ └──► [ Apache Kafka ] (Event-Driven Commit Log) ├─ Transactional Outbox Pattern publishing to orders.placed ├─ CooperativeStickyAssignor + AckMode.MANUAL_IMMEDIATE + Retry/DLQ │ └──► [ Fulfillment & Notification Service (Kotlin 2.2+ Coroutines) ] └─ Idiomatic Kotlin Spring Boot 4.2 worker (suspend fun, MockK tests) driving Saga compensation & Redis Pub/Sub SSE status updates!

✓

FOR UPDATE, and Redis X-Idempotency-Key envelopes.
✓
Polyglot Java 25 LTS + Kotlin 2.2+ Showcase (Lessons 0003, 0056–0057): The core order & ledger Modulith is written in modern Java 25 (Records, Sealed Switches, Virtual Threads, ScopedValue, JSpecify @NullMarked), while the downstream event worker uses idiomatic Kotlin 2.2+ Coroutines and MockK.
✓
Zero Dual-Write Event Reliability (Lessons 0038–0042, 0052–0054): Eliminates lost Kafka events via the Transactional Outbox pattern, enforces ArchUnit module boundaries with Spring Modulith 2, coordinates Saga compensations on payment failure, and verifies external Stripe/Adyen webhooks with constant-time HMAC-SHA256 + WireMock tests.
✓
Zero-Trust Spring Security 7 Hardening (Lessons 0043–0047): Implements stateless JWT access tokens with Redis-backed Refresh Token Rotation (reuse detection), OAuth2 PKCE / WebAuthn Passkey readiness, method-level @PreAuthorize BOLA ownership checks, and outbound SSRF guards.
✓
100% Real Infrastructure Testing via Testcontainers (Lessons 0026–0027, 0054): Every repository, Redis Lua/rate-limit rule, Kafka Outbox relay, and outbound HTTP client is verified against real containerized PostgreSQL 17, Redis 7, Kafka, and WireMock.

3. Ready-to-Use Resume Bullet Points

NexusCommerce — Distributed Order & Ledger Engine (Java 25, Kotlin 2.2, Spring Boot 4.2, Kafka, PostgreSQL 17, Redis)
  • Architected a polyglot event-driven commerce backend on Spring Boot 4.2 and Java 25 Virtual Threads, enforcing modular domain boundaries via Spring Modulith 2 and ArchUnit.
  • Eliminated inventory overselling and duplicate mobile charges using JPA optimistic locking (@Version), Redis-backed X-Idempotency-Key locks, and Bucket4j token-bucket rate limiting.
  • Built a zero-dual-write event pipeline with Apache Kafka, the Transactional Outbox pattern, and a Kotlin 2.2 Coroutines consumer executing idempotent Saga compensations and live SSE fan-out via Redis Pub/Sub.
  • Hardened API security with Spring Security 7 (JWT Refresh Token Rotation, Argon2id, @PreAuthorize BOLA guards, and constant-time HMAC-SHA256 webhook verification tested with WireMock & Testcontainers).
