Part 01 · First Principles

The Junior → Senior Mental Shift

Most junior Android developers equate "concurrency" with "running on a background thread." Senior engineers separate program structure from hardware execution and scheduling rules (Kotlin Coroutines Guide).

Concurrency (Structure)

Managing multiple tasks whose lifetimes overlap in time.

Possible even on a 1-core CPU! The OS or coroutine dispatcher interleaves progress on Task A and Task B via time-slicing or suspending during I/O wait.

Android example: Downloading 5 thumbnails over HTTP while keeping Compose animations smooth at 120fps.

Parallelism (Hardware Execution)

Physically executing multiple computations at the exact same instant across multiple CPU cores.

Parallelism multiplies throughput for CPU-bound work (image filtering, JSON parsing), whereas concurrency hides latency for I/O-bound waiting.

Trap: Spawning 500 OS threads for CPU math on an 8-core phone slows it down via context-switch thrashing.

Part 03 · Production Kotlin & Android

Junior Traps vs. Senior Patterns in Kotlin

Apply Android Coroutines Best Practices and keep CPU vs. I/O dispatchers separated.

Pattern 1: Separating CPU-Bound vs. I/O-Bound Dispatchers

✗ JUNIOR TRAP: Blocking Dispatchers.Default
viewModelScope.launch(Dispatchers.Default) {
    repeat(16) {
        launch {
            val bytes = legacyHttpClient.executeBlocking()
            parseJson(bytes)
        }
    }
}
// All ~8 CPU cores block idle on sockets; Compose/CPU starves!
✓ SENIOR PATTERN: Match Dispatcher to Bottleneck
viewModelScope.launch {
    val rawBytes = withContext(Dispatchers.IO) {
        legacyHttpClient.executeBlocking()
    }
    val parsed = withContext(Dispatchers.Default) {
        parseJson(rawBytes)
    }
    _uiState.value = UiState.Ready(parsed)
}

Pattern 2: Fixing Read-Modify-Write Lost Updates

✗ JUNIOR TRAP: @Volatile var count = 0
@Volatile var count = 0 // Visibility ONLY, NOT atomicity!
suspend fun runBroken() = coroutineScope {
    repeat(100) {
        launch(Dispatchers.Default) {
            repeat(1000) { count++ } // Lost updates!
        }
    }
}
✓ SENIOR PATTERN: AtomicInteger / Mutex.withLock
val count = AtomicInteger(0) // Lock-free CAS
// OR for multi-step suspending critical sections:
val mutex = Mutex()
suspend fun safeDeposit(amount: Int) {
    mutex.withLock {
        val current = store.read("balance")
        store.write("balance", current + amount)
    }
}

Pattern 3: Cooperative Yielding in Tight CPU Loops

✗ JUNIOR TRAP: Tight Loop Ignores Cancellation
val job = scope.launch(Dispatchers.Default) {
    var i = 0L
    while (true) { i += computeHash(i) } // Ignores cancel()!
}
✓ SENIOR PATTERN: isActive / yield()
val job = scope.launch(Dispatchers.Default) {
    var i = 0L
    while (isActive) {
        i += computeHash(i)
        if (i % 1000L == 0L) yield()
    }
}
