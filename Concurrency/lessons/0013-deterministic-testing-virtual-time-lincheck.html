Part 01 · First Principles

Replacing Wall-Clock Luck with Deterministic Verification

Flaky concurrency tests happen when correctness depends on OS thread preemptive scheduling jitter or arbitrary wall-clock waits. Senior engineers decouple tests from hardware clocks using TestCoroutineScheduler (Android Developers: Testing Kotlin Coroutines), assert exact stream contracts with CashApp Turbine, and explore adversarial schedules with JetBrains Lincheck.

StandardTestDispatcher (Queued)

Every new coroutine is enqueued on TestCoroutineScheduler instead of running immediately.

Nothing executes until you call runCurrent(), advanceTimeBy(ms), or advanceUntilIdle(). This gives you frame-by-frame control to assert transient states like UiState.Loading before delay() completes into UiState.Loaded.

UnconfinedTestDispatcher (Eager)

Executes newly launched coroutines eagerly on the current thread up to their first suspension point.

Convenient for simple event-collection tests where intermediate states don't matter, but dangerous when testing StateFlow conflation: an eager producer can jump past Loading into Loaded before your assertion or collector observes the transition.

How Lincheck Finds Races Deterministically

Running two threads 10,000 times in a loop often executes one thread completely before the other even boots—hiding a race condition for months. Lincheck inserts switch points at shared memory accesses, explores distinct schedules systematically (or via guided stress runs), and verifies that every concurrent outcome matches at least one valid sequential execution (linearizability).

Reading a Thread Dump (jstack / SIGQUIT)

When a test or production service hangs, capture a thread dump. Look for: (1) BLOCKED (on object monitor) + waiting to lock <0x0a1> paired with another thread - locked <0x0a1> (classic deadlock cycle); (2) DefaultDispatcher-worker-* threads stuck in RUNNABLE inside socket I/O (pool starvation). 

"worker-1" #24 prio=5 tid=0x01 BLOCKED
   - waiting to lock <0x000000076b0> (held by "worker-2")
   - locked <0x000000076a0> (a java.lang.Object)
"worker-2" #25 prio=5 tid=0x02 BLOCKED
   - waiting to lock <0x000000076a0> (held by "worker-1")
Virtual Time Boundary Rule: runTest skips delay() only for coroutines running on dispatchers linked to its TestCoroutineScheduler (kotlinx-coroutines-test docs). Hardcoding Dispatchers.IO or Dispatchers.Default escapes the virtual clock onto real OS threads, reintroducing wall-clock delays and race flakiness.

Part 03 · Production Kotlin & Android

Junior Traps vs. Senior Patterns in Coroutine Tests

Follow Android Coroutines Best Practices and Android Coroutines Testing Guidance to eliminate flaky CI suites.

Pattern 1: Flaky Thread.sleep / Real delay(500) vs. runTest + advanceTimeBy

✗ JUNIOR TRAP: Wall-Clock Sleep in CI
@Test
fun retryBackoffFlaky() = runBlocking {
    val vm = SyncViewModel(realRepo)
    vm.syncWithRetry()
    Thread.sleep(600) // Slow + breaks when CI GC pauses!
    assertEquals(State.Retried, vm.state.value)
}
✓ SENIOR PATTERN: Deterministic Virtual Clock
@Test
fun retryBackoffDeterministic() = runTest {
    val vm = SyncViewModel(fakeRepo, StandardTestDispatcher(testScheduler))
    vm.syncWithRetry()
    advanceTimeBy(499); runCurrent()
    assertEquals(State.Waiting, vm.state.value)
    advanceTimeBy(1); runCurrent()
    assertEquals(State.Retried, vm.state.value)
}

Pattern 2: StandardTestDispatcher vs. UnconfinedTestDispatcher Subtle StateFlow Miss

✗ JUNIOR TRAP: Eager Execution Conflates Loading
@Test
fun missesLoadingOnCacheHit() = runTest(UnconfinedTestDispatcher()) {
    val vm = ProfileViewModel(instantFakeRepo) // no delay on hit!
    vm.loadProfile() // Runs Loading -> Loaded synchronously!
    val seen = mutableListOf<UiState>()
    backgroundScope.launch { vm.uiState.toList(seen) }
    // StateFlow conflated Loading; seen only gets [Loaded]!
    assertEquals(listOf(Loading, Loaded), seen) // FAILS!
}
✓ SENIOR PATTERN: Standard + Turbine Subscription First
@Test
fun capturesEveryStateTransition() = runTest {
    val vm = ProfileViewModel(instantFakeRepo, StandardTestDispatcher(testScheduler))
    vm.uiState.test {
        assertEquals(UiState.Idle, awaitItem())
        vm.loadProfile() // Queued, not run yet
        runCurrent()     // Runs transitions while Turbine collects
        assertEquals(UiState.Loading, awaitItem())
        assertEquals(UiState.Loaded, awaitItem())
    }
}

Pattern 3: Injecting DispatcherProvider + Turbine test {} + backgroundScope

✗ JUNIOR TRAP: Hardcoded IO & Hanging Collector
class FeedRepository {
    suspend fun refresh() = withContext(Dispatchers.IO) {
        delay(5_000) // Escapes testScheduler! Waits 5 real sec!
    }
}
// Also inside runTest:
launch { vm.uiState.collect { /* infinite */ } }
// runTest waits forever and times out after 60s!
✓ SENIOR PATTERN: Injected Provider & backgroundScope
interface DispatcherProvider { val io: CoroutineDispatcher; val main: CoroutineDispatcher }
class FeedRepository(private val dispatchers: DispatcherProvider) {
    suspend fun refresh() = withContext(dispatchers.io) { delay(5_000) }
}
// In test:
val testDisp = StandardTestDispatcher(testScheduler)
backgroundScope.launch(UnconfinedTestDispatcher(testScheduler)) {
    vm.uiState.collect {} // Auto-cancelled when test body exits!
}

LAB 13.1 · VIRTUAL TIME SCHEDULER

Implement VirtualTestScheduler (60s Backoff in 0ms)

Build a virtual clock scheduler with schedule(delayMs, fn), runCurrent(), advanceTimeBy(ms), and advanceUntilIdle().

Not Run
• schedule(delayMs, fn) queues fn for currentTime + delayMs (FIFO tie-breaking for equal timestamps).
• advanceTimeBy(ms) executes all tasks due at <= currentTime + ms in chronological order (including nested tasks scheduled during execution) and sets currentTime to the target.
• advanceUntilIdle() drains all queued tasks across virtual time and returns final currentTime.

Not Run
