Part 01 · First Principles

Why a Single-Node Mutex Cannot Span a Network

Inside one JVM process, mutual exclusion relies on shared memory and a reliable hardware/OS scheduler. Across a network, there is no shared memory, packets delay arbitrarily, and a client holding a lease can freeze mid-request during a JVM garbage-collection pause (Kleppmann: How to do distributed locking).

The Lease-Only Illusion (GC Pause Race)

1. Worker A acquires a 5s lease from a lock service.
2. Worker A freezes for 12s (stop-the-world GC or OS swap). Its lease expires.
3. Worker B legitimately acquires a new lease and writes v2.
4. Worker A wakes up, still believing it holds the lock, and overwrites storage with stale v1 — a distributed race condition!

The Storage-Verified Fix (Fencing Tokens)

Every granted lease carries a strictly increasing fencing token (1, 2, 3...).

The lock service does not enforce safety by itself — the storage layer tracks lastSeenToken and rejects any write with token <= lastSeenToken. When Worker A wakes up with Token #1, storage rejects it because Token #2 already committed.

Distributed Coordination & Conflict Resolution Primitives

Mechanism Core Guarantee Primary Failure Mode Avoided When to Choose
Lease + Fencing Token Storage rejects stale writes (token <= lastSeenToken) GC pauses & delayed network packets corrupting exclusive writes Leader election, singleton batch jobs, exclusive storage writes
Optimistic CAS (Version / ETag) Conditional write: UPDATE ... WHERE version = :v or HTTP If-Match Lost updates under concurrent edits without holding a distributed lock REST APIs, Room/backend row updates with low-to-moderate contention
Transactional Outbox Domain row + outbox event commit in one local ACID transaction Dual-write split-brain (DB commits, Kafka/FCM publish crashes) Reliable event publishing, offline sync queues in Room + WorkManager
Vector Clocks Partial causal order: BEFORE, AFTER, EQUAL, CONCURRENT NTP wall-clock skew causing Last-Write-Wins (LWW) to drop newer edits Multi-device offline sync needing explicit conflict detection
State-Based CRDTs (PN-Counter) Join-semilattice merge: commutative, associative, idempotent Out-of-order syncs, duplicate retries, and disconnected offline writes Distributed counters, likes, inventory deltas, collaborative state
Why Physical Clocks Fail LWW: Relying on System.currentTimeMillis() for Last-Write-Wins assumes synchronized clocks across nodes. NTP step-backs and mobile clock drift mean a later edit can carry an earlier timestamp and vanish silently. Use Vector Clocks to detect true concurrency, or CRDTs (Shapiro et al., 2011) when concurrent updates can merge mathematically without coordination.

Part 03 · Production Kotlin & Android

Junior Traps vs. Senior Patterns in Kotlin

Move mutual exclusion checks to the authoritative storage boundary, pair local Room writes with a Transactional Outbox, and merge offline-first counters cleanly with CRDTs.

Pattern 1: Distributed Lock Without Fencing vs. Monotonic Fencing Token at Storage

✗ JUNIOR TRAP: Client-Trusted Lock Only
suspend fun processBillingBatch(batchId: String) {
    if (!redisLock.tryAcquire("billing:$batchId", ttl = 5.seconds)) return
    // If JVM hits a 12s GC pause here, lease expires!
    // Another node acquires lock and commits v2.
    // This node wakes up and blindly overwrites v2 with stale v1:
    storageDao.overwriteBatchResult(batchId, computeResult())
}
✓ SENIOR PATTERN: Storage Enforces Monotonic Token
suspend fun processBillingBatch(batchId: String) {
    val lease = lockService.acquireWithToken("billing:$batchId", ttl = 5.seconds)
        ?: return
    val result = computeResult()
    // SQL: UPDATE batches SET payload = :p, last_token = :tok
    //      WHERE id = :id AND last_token < :tok
    val rowsUpdated = storageDao.writeIfNewerToken(
        id = batchId, payload = result, fencingToken = lease.token
    )
    if (rowsUpdated == 0) throw StaleFencingTokenException(lease.token)
}

Pattern 2: Optimistic Concurrency with Version / ETag 409 Conflict Retry

✗ JUNIOR TRAP: Blind PUT Overwrites Peer Edits
suspend fun renameNote(noteId: String, title: String) {
    val remote = api.getNote(noteId)
    // No If-Match ETag or version check:
    // Any edit made by another device in between is silently clobbered!
    api.putNote(noteId, remote.copy(title = title))
}
✓ SENIOR PATTERN: ETag CAS + Bounded Conflict Retry
suspend fun renameNote(noteId: String, title: String): NoteDto {
    repeat(3) { attempt ->
        val current = api.getNote(noteId) // carries version / ETag
        val res = api.putNoteIfMatch(
            id = noteId,
            ifMatch = current.etag,
            body = current.copy(title = title)
        )
        if (res.isSuccessful) return res.body()!!
        if (res.code() != 409) throw HttpException(res)
        delay((50L shl attempt)) // reload latest state and rebase edit
    }
    throw OptimisticLockConflictException(noteId)
}

Pattern 3: G-Counter / PN-Counter CRDT Merge for Offline Sync

✗ JUNIOR TRAP: LWW Scalar Overwrites Offline Increments
data class LikeState(val count: Int, val updatedAtMs: Long)

fun mergeLikes(local: LikeState, remote: LikeState): LikeState {
    // Device A added +3 offline, Device B added +2 offline.
    // LWW picks one timestamp and loses the other device's likes!
    return if (remote.updatedAtMs > local.updatedAtMs) remote else local
}
✓ SENIOR PATTERN: PN-Counter Element-Wise Max Merge
data class PnCounter(val p: Map<String, Long>, val n: Map<String, Long>) {
    fun value(): Long = p.values.sum() - n.values.sum()
    fun merge(other: PnCounter): PnCounter {
        val keysP = p.keys + other.p.keys
        val keysN = n.keys + other.n.keys
        return PnCounter(
            p = keysP.associateWith { maxOf(p[it] ?: 0L, other.p[it] ?: 0L) },
            n = keysN.associateWith { maxOf(n[it] ?: 0L, other.n[it] ?: 0L) }
        ) // Commutative, associative, and idempotent across retries!
    }
}
Transactional Outbox Pattern (Android Room + Backend): Never update SQLite/PostgreSQL in one call and publish to Kafka or enqueue a network request outside the transaction. Instead, write both the entity mutation and an OutboxEventEntity row inside one atomic @Transaction (Room) or SQL BEGIN...COMMIT; a background relay (WorkManager / Debezium) reads pending outbox rows and marks them dispatched idempotently.

LAB 18.1 · LEASE MANAGER & FENCED STORAGE

FencedStorageCoordinator: Monotonic Fencing Tokens

Prevent a GC-paused worker with an expired lease from corrupting storage after a newer worker commits.

Not Run
• acquireLease(workerId, ttlMs): Grants a lease only if no active lease exists or this.now >= this.activeLease.expiresAt. Issues strictly monotonic token (1, 2, 3...) and returns { granted: true, workerId, token, expiresAt }; otherwise returns { granted: false, holder, token: null }.
• advanceTime(ms): Advances simulated clock this.now += ms.
• write(token, value): Storage rejects stale or duplicate tokens where typeof token !== 'number' || token <= this.lastSeenToken, returning { ok: false, reason: 'STALE_TOKEN', lastSeenToken: this.lastSeenToken, value: this.value }. Otherwise updates lastSeenToken and value and returns { ok: true, token, value }.

LAB 18.2 · CAUSAL ORDERING

compareVectorClocks & mergeVectorClocks

Detect causal precedence vs. true concurrent conflicts across sparse node clocks, and merge clocks cleanly.

Not Run
• compareVectorClocks(vcA, vcB): Compare over the union of keys from both objects (missing keys default to 0). Return 'EQUAL', 'BEFORE' (A < B), 'AFTER' (A > B), or 'CONCURRENT'.
• mergeVectorClocks(vcA, vcB): Return a new object mapping each key in the union to Math.max(aVal, bVal) without mutating inputs. Keep compareVectorClocks.merge = mergeVectorClocks; at the bottom.

LAB 18.3 · CONVERGENT REPLICATED DATA TYPE

PNCounterCRDT: Commutative, Associative, Idempotent Merge

Build a distributed Positive-Negative Counter CRDT that converges identically under out-of-order and duplicate syncs.

Not Run

• increment(delta = 1) / decrement(delta = 1): Validate delta >= 0 and add to this.p[this.nodeId] or this.n[this.nodeId].
