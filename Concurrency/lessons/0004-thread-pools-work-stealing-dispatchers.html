Part 01 · First Principles

Why Thread Pools, Bounded Queues & Work-Stealing Exist

An OS Thread is expensive to allocate and schedule. High-throughput JVM and Android runtimes amortize thread creation in pools and schedule lightweight Coroutines on top (Kotlin Coroutine Context & Dispatchers).

1. OS Thread Cost & Pool Sizing

On a 64-bit JVM/ART process, every OS thread reserves roughly ~1 MB of native call stack (configurable via -Xss) plus kernel descriptors and page-table overhead. Creating 2,000 threads reserves ~2 GB of virtual/stack space before doing useful work and triggers OS Preemptive Scheduling thrashing.

Sizing rule of thumb:
• CPU-bound: N_threads = N_cores (or N_cores + 1) for maximum Parallelism without cache thrashing.
• Blocking I/O-bound: N_threads = N_cores * U_target * (1 + W / C), where W / C is wait-time to compute-time ratio.

2. Bounded vs. Unbounded Queue OOM Traps

Java's Executors factory helpers hide two classic production OOM traps:
• newFixedThreadPool(n) uses an unbounded LinkedBlockingQueue(Integer.MAX_VALUE). If producers outpace workers, queued tasks consume the entire JVM heap.
• newCachedThreadPool() uses a SynchronousQueue with maximumPoolSize = Integer.MAX_VALUE—a traffic spike spawns thousands of OS threads and exhausts stack/OS thread limits.

Senior fix: Use a bounded ArrayBlockingQueue plus an explicit RejectedExecutionHandler (AbortPolicy, DiscardOldestPolicy, or CallerRunsPolicy for backpressure).

3. ForkJoinPool Work-Stealing Deques

A single shared FIFO queue forces every worker thread to contend on the same head/tail lock or CAS pointer. ForkJoinPool (and Kotlin's CoroutineScheduler) gives each worker its own double-ended queue (deque):

• Owner pops LIFO from its own head: newest child subtasks stay hot in L1/L2 CPU cache with zero lock contention.
• Idle thief steals FIFO from a busy victim's tail: grabs older, coarser-grained work from the opposite end, minimizing CAS collisions with the owner.

4. Dispatchers.Default & IO Share One Pool

In kotlinx.coroutines, Dispatchers.Default (CPU cap = max(2, cores)) and Dispatchers.IO (elastic cap = max(64, cores)) share the same underlying CoroutineScheduler thread pool!

Switching via withContext(Dispatchers.IO) inside a Default coroutine often keeps executing on the exact same OS thread—reclassifying the thread's quota from CPU to blocking I/O without an OS context switch (Official Dispatchers Spec).

Part 03 · Production Kotlin & Android

Junior Traps vs. Senior Patterns in Production

Spot the hidden OOM hazards in java.util.concurrent.Executors and use Kotlin's shared scheduler dispatchers cleanly.

Pattern 1: Unbounded Queue / Thread Explosion vs. Bounded ThreadPoolExecutor + CallerRunsPolicy

✗ JUNIOR TRAP: Executors.newCachedThreadPool() / newFixedThreadPool()
// Trap A: Unbounded threads (~1 MB stack each -> OOM!)
val cached = Executors.newCachedThreadPool()

// Trap B: Unbounded LinkedBlockingQueue -> Heap OOM!
val fixed = Executors.newFixedThreadPool(4)

// Under burst traffic, either native stack or JVM heap exhausts.
✓ SENIOR PATTERN: Bounded Queue + CallerRunsPolicy
val boundedPool = ThreadPoolExecutor(
    4, 4,
    0L, TimeUnit.MILLISECONDS,
    ArrayBlockingQueue(64), // Explicit memory bound!
    ThreadPoolExecutor.CallerRunsPolicy() // Natural backpressure
)
// When all 4 workers + 64 slots are full, the producer runs the task
// itself, slowing submissions without OOM or silent drops.

Pattern 2: Dispatchers.Default vs. Dispatchers.IO Sharing Threads

✗ JUNIOR TRAP: Blocking I/O on Dispatchers.Default
suspend fun loadUserProfile(id: String): Profile =
    withContext(Dispatchers.Default) {
        // Blocks one of only ~8 CPU threads on socket/disk wait!
        val json = blockingHttpClient.get("/users/$id")
        parseProfile(json)
    }
✓ SENIOR PATTERN: Shared CoroutineScheduler Hop
suspend fun loadUserProfile(id: String): Profile {
    val json = withContext(Dispatchers.IO) {
        blockingHttpClient.get("/users/$id")
    }
    // Returns to Default on the shared CoroutineScheduler—often
    // staying on the exact same OS thread without a context switch!
    return withContext(Dispatchers.Default) { parseProfile(json) }
}

Pattern 3: Bounding Legacy Subsystems with limitedParallelism(n)

✗ JUNIOR TRAP: Allocating a Private Thread Pool
// Allocates 4 permanent ~1MB OS threads that never shrink
// and leak if close() is forgotten!
private val dbDispatcher =
    Executors.newFixedThreadPool(4).asCoroutineDispatcher()

suspend fun queryUser(id: Long) = withContext(dbDispatcher) {
    legacyJdbcDao.find(id)
}
✓ SENIOR PATTERN: Dispatchers.IO.limitedParallelism(4)
// Independent view over the shared IO pool:
// caps concurrent DB calls at 4, allocates 0 idle threads,
// and never starves Dispatchers.Default!
private val dbDispatcher = Dispatchers.IO.limitedParallelism(4)

suspend fun queryUser(id: Long) = withContext(dbDispatcher) {
    legacyJdbcDao.find(id)
}

LAB 4.2 · BACKPRESSURE & REJECTION POLICIES

Bounded Executor Queue with Rejection Policies

Fix BoundedExecutorQueue so fast producers cannot grow the queue past capacity.

Not Run
Methods on class BoundedExecutorQueue:
• constructor(capacity, policy = 'ABORT') ('ABORT' | 'DROP_OLDEST' | 'CALLER_RUNS')
• submit(task): when queue.length < capacity, enqueue and return { status: 'ENQUEUED', queueSize }. When full:
  - 'ABORT': increment rejected and throw Error('RejectedExecutionException: queue full').
  - 'DROP_OLDEST': evict oldest (`shift()`), enqueue `task`, increment `dropped`, return { status: 'DROPPED_OLDEST', dropped: evictedTask, queueSize }.
  - 'CALLER_RUNS': invoke task() immediately on the caller thread, increment callerRuns, return { status: 'CALLER_RUNS', result, queueSize }.
• take() pops oldest (`shift()`, or `null` if empty); size() returns current length; stats() returns { enqueued, rejected, dropped, callerRuns, queued }.

LAB 4.3 · FORKJOIN WORK-STEALING DEQUE

LIFO Local Pop vs. FIFO Victim Tail Steal

Implement workStealingStep(deques, workerId) for 2 worker deques.

Not Run
Each array in deques = [deque0, deque1] puts the tail at index 0 and the head at length - 1:
• If deques[workerId] is non-empty, owner pops LIFO from its head (pop()) and returns { workerId, action: 'LOCAL_LIFO', task, fromWorker: workerId }.
• Else if the peer deque (1 - workerId) is non-empty, idle thief steals FIFO from the victim's tail (shift()) and returns { workerId, action: 'STEAL_FIFO', task, fromWorker: victimId }.
• If both deques are empty, return { workerId, action: 'IDLE', task: null, fromWorker: null }.
