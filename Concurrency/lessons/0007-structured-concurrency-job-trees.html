Part 01 · First-Principles Mental Model

The Job Hierarchy Tree & Two-Way Signal Flow

Structured concurrency enforces a strict lifetime invariant: no child coroutine may outlive its parent scope (Kotlin Coroutines Guide; Exception Handling & Supervision). Every launch or async reads the parent's Job from CoroutineContext, registers a new child Job under it, and wires two propagation channels:

Downward Flow (Cancellation & Waiting)

1. Cancellation cascades down: Cancelling a parent Job immediately cancels every descendant Job in its subtree—even across SupervisorJob children.

2. Parent waits for completion: A parent Job stays in Completing state until all children finish executing (or finish cancelling and running finally cleanup).

Upward Flow (Uncaught Child Failure)

With regular Job(): An uncaught non-CancellationException failure propagates upward to the parent, which cancels all siblings and re-propagates upward to the root.

With SupervisorJob(): Failure stops at the direct SupervisorJob parent. Siblings keep running, and the failed child's uncaught exception goes to CoroutineExceptionHandler (if root) or the thread uncaught handler.

Tree Comparison: Why launch(SupervisorJob()) Silently Fails

1. Correct Supervisor Root:             2. Anti-Pattern: scope.launch(SupervisorJob()) { ... }
   RootScope (SupervisorJob)               RootScope (Job)   ✕  [Parent link SEVERED!]
    ├── Child A (Job)  [SURVIVES]                            │
    ├── Child B (Job)  [THROWS]            Orphaned SupervisorJob()
    └── Child C (Job)  [SURVIVES]           └── Launcher (Regular Job!)  ← Parent of A & B!
                                                 ├── Child A (Job)  [CANCELLED!]
                                                 └── Child B (Job)  [THROWS]
Two-fold launch(SupervisorJob()) bug: Passing SupervisorJob() into launch(...) overrides the parent Job in the coroutine context. First, the launched coroutine itself creates a regular Job whose parent is that unparented SupervisorJob()—so nested launch siblings still share a regular Job and cancel each other! Second, the link to RootScope is broken, so cancelling RootScope leaks the orphaned subtree (Android Coroutines Best Practices).

Part 03 · Production Kotlin & Android Patterns

Junior Traps vs. Senior Patterns in Production Kotlin

Apply Android Coroutines Best Practices and Kotlin Exception Handling rules to prevent leaked work, silent supervision bugs, and unhandled crashes.

Pattern 1: GlobalScope Memory/Work Leaks vs. Lifecycle-Bound CoroutineScope

✗ JUNIOR TRAP: Unbounded GlobalScope
class CheckoutRepository(private val api: Api) {
    fun submitOrder(order: Order) {
        // Detached from ViewModel/process lifecycle!
        // Holds implicit `this` + callbacks past screen exit.
        @OptIn(DelicateCoroutinesApi::class)
        GlobalScope.launch(Dispatchers.IO) {
            api.postOrder(order)
        }
    }
}
✓ SENIOR PATTERN: Injected Structured Scope
class CheckoutRepository(
    private val api: Api,
    private val appScope: CoroutineScope // SupervisorJob() + Default
) {
    suspend fun submitOrder(order: Order) = withContext(Dispatchers.IO) {
        api.postOrder(order) // Ties to caller's lifecycle!
    }
    fun syncAuditLog(event: Event) {
        appScope.launch { api.log(event) } // Explicit app lifetime
    }
}

Pattern 2: The launch(SupervisorJob()) Anti-Pattern

✗ JUNIOR TRAP: launch(SupervisorJob())
suspend fun loadHome() {
    viewModelScope.launch(SupervisorJob()) {
        // BUG 1: Severed from viewModelScope! Rotation/clear leaks this!
        // BUG 2: Parent of these two is the launch's regular Job!
        launch { fetchBanner() } // Cancelled when fetchRecommendations throws!
        launch { fetchRecommendations() }
    }
}
✓ SENIOR PATTERN: supervisorScope / Root SupervisorJob
suspend fun loadHome() = supervisorScope {
    // Direct children of supervisorScope are isolated AND linked!
    // Cancelling viewModelScope cancels both children cleanly.
    val banner = async { runCatchingNonCancellable { fetchBanner() } }
    val recs = async { runCatchingNonCancellable { fetchRecommendations() } }
    HomeUi(banner.await(), recs.await())
}

Pattern 3: coroutineScope vs. supervisorScope & CoroutineExceptionHandler Placement

✗ JUNIOR TRAP: CEH on a Child Coroutine (Ignored!)
val handler = CoroutineExceptionHandler { _, e -> logError(e) }

viewModelScope.launch {
    // IGNORED! Child delegates exception to viewModelScope's root Job,
    // crashing the app even though `handler` was passed here!
    launch(handler) {
        throw IllegalStateException("Server 500")
    }
}
✓ SENIOR PATTERN: CEH on Root (or Direct Supervisor Child)
val handler = CoroutineExceptionHandler { _, e -> logError(e) }

// Works: `viewModelScope` has a SupervisorJob root, so this
// direct `launch(handler)` is treated as a root coroutine for CEH.
viewModelScope.launch(handler) {
    coroutineScope { // Fail-fast sub-tree; throws up to root handler
        launch { syncProfile() }
        launch { throw IllegalStateException("Server 500") }
    }
}

LAB 7.1 · JOB TREE & SUPERVISION INVARIANTS

Implement StructuredScope Parent-Child Propagation

Implement class StructuredScope modeling downward cancellation and upward failure propagation vs. SupervisorJob isolation.

Not Run
Contract for StructuredScope:
• new StructuredScope({ supervised = false, parent = null, onError = null }) starts with isActive = true, isCancelled = false, isFailed = false, error = null, children = [].
• createChild(opts) creates and registers a child linked to this. If this is not active, the new child starts cancelled immediately.
• cancel(reason) marks this cancelled (if still active) and recursively cancels all children (even if supervised is true!).
• fail(err) marks this failed (isFailed = true, isCancelled = true, isActive = false, error = err) and cancels all its own children. Then, if this.parent exists: if this.parent.supervised is true, isolate the failure (invoke this.parent.onError?.(err, this) without cancelling parent or siblings); otherwise propagate upward via this.parent.fail(err).
• async launch(fn) creates a child via createChild(), awaits fn(child) if active, and calls child.fail(err) if fn throws.
