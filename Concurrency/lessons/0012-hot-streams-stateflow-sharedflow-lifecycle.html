Part 01 · First-Principles Mental Model

Cold Producers vs. Hot Shared Broadcasts

A cold Flow is a lazy blueprint: every collect call launches an independent upstream execution. A hot stream (SharedFlow or StateFlow) decouples the producer from collectors so multiple UI observers share one live emission timeline (Kotlin Asynchronous Flow, Android StateFlow & SharedFlow).

SharedFlow: Configurable Event Bus

Multicasts every emitted item to all active collectors without equality filtering.

Configured by replay (cached values sent to late subscribers), extraBufferCapacity (slack for slow collectors), and onBufferOverflow (SUSPEND, DROP_OLDEST, DROP_LATEST).

Trap: Default MutableSharedFlow() has replay = 0, extraBufferCapacity = 0, and SUSPEND—so tryEmit() returns false whenever any collector is active, and one slow collector stalls everyone!

StateFlow: Conflated State Holder

A specialized SharedFlow holding exactly one current value (replay = 1, DROP_OLDEST, always has an initialValue).

Performs equality conflation (Any.equals): assigning a structurally equal value skips notifying collectors. Slow collectors never block writers—they skip intermediate states and read only the latest.

Trap: Because it conflates and replays on rotation, StateFlow is wrong for one-shot events like navigation or toasts unless modeled explicitly in UiState.

Cold Flow vs. SharedFlow vs. StateFlow vs. Channel

Primitive Producer Sharing Replay / Initial Equality Conflation Slow Collector Impact Best Production Role
Cold Flow Unshared (1 producer per collect) None (starts fresh) No (unless conflate()) Suspends its own upstream Repository queries, one-off pipelines
SharedFlow Hot multicast (0..N collectors) replay ≥ 0, no initial No (emits duplicates) With SUSPEND, stalls emit() & peers once buffer fills Broadcast events, converted sensor/bus feeds
StateFlow Hot multicast (0..N collectors) replay = 1 + required initial Yes (equals() skips emit) Never blocks writer; slow collector drops intermediate values Screen UiState exposed from ViewModel
Channel Hot unicast (1-to-1 fan-out) Buffer only (no replay) No Suspends sender or drops per buffer policy Single-consumer work queues or one-shot events

How shareIn & stateIn Bridge Cold Upstreams to Hot UI

Android UI collectors using repeatOnLifecycle(STARTED) or collectAsStateWithLifecycle() unsubscribe when the Activity stops during a ~300ms configuration rotation and re-subscribe milliseconds later (Lifecycle-aware Coroutines).

SharingStarted Policy Starts Upstream When 300ms Screen Rotation App Backgrounded (> 5s)
SharingStarted.Eagerly Immediately at stateIn creation Survives (never stops) Stays active forever (wastes battery/sockets)
SharingStarted.Lazily First collector subscribes Survives (never stops) Stays active forever once started
SharingStarted.WhileSubscribed(0) Subscriber count 0 → 1 Tears down & cold-restarts upstream! Stops immediately
SharingStarted.WhileSubscribed(5000) Subscriber count 0 → 1 Survives cleanly (timer cancelled at ~300ms) Stops cleanly after 5s grace window
Why 5000ms? Configuration changes (rotation, dark-mode toggle, split-screen resize) destroy and recreate the Activity in ~100–500ms while the ViewModel survives in memory. WhileSubscribed(5_000) keeps the upstream Room/WebSocket/network flow alive across that brief 0-subscriber gap, canceling the stop timer when the recreated UI attaches—yet still frees upstream resources 5 seconds after the user genuinely leaves the screen.

Part 03 · Production Kotlin & Android

Junior Traps vs. Senior Patterns

Production bugs with hot streams rarely crash loudly—they silently drop events, stall collectors, or re-fetch data on every rotation.

Pattern 1: The Default MutableSharedFlow() Zero-Buffer Trap

✗ JUNIOR TRAP: replay=0, extraBufferCapacity=0
// Default: replay=0, extraBufferCapacity=0, onBufferOverflow=SUSPEND
private val _clicks = MutableSharedFlow<ClickEvent>()

fun onButtonTap(event: ClickEvent) {
    // ALWAYS returns false whenever >= 1 collector is active!
    // No buffer slot exists to hand off without suspending.
    val sent = _clicks.tryEmit(event) // Dropped silently!
}

suspend fun broadcast(event: ClickEvent) {
    // If 1 collector is slow (e.g. disk write), emit() SUSPENDS
    // and blocks the producer + all fast collectors!
    _clicks.emit(event)
}
✓ SENIOR PATTERN: Explicit Buffer & Overflow Policy
// Non-suspending fire-and-forget telemetry / UI triggers:
private val _clicks = MutableSharedFlow<ClickEvent>(
    replay = 0,
    extraBufferCapacity = 64,
    onBufferOverflow = BufferOverflow.DROP_OLDEST
)

fun onButtonTap(event: ClickEvent) {
    // Never suspends; returns true and evicts oldest on overflow
    _clicks.tryEmit(event)
}

// Or for strictly one-shot UI navigation, prefer Channel:
private val _nav = Channel<NavTarget>(Channel.BUFFERED)
val nav = _nav.receiveAsFlow()

Pattern 2: One-Shot Navigation Events in StateFlow vs. UiState / Channel

✗ JUNIOR TRAP: Events Stuffed Into StateFlow
// BUG 1: Rotation replays replay=1 -> navigates twice or re-shows Toast!
// BUG 2: Equality conflation drops second identical Error("Timeout")!
// BUG 3: Background emission overwrites event before UI collects!
private val _navEvent = MutableStateFlow<Route?>(null)
val navEvent: StateFlow<Route?> = _navEvent

fun onSaveSuccess() {
    _navEvent.value = Route.Receipt // Re-fires on rotation!
}
✓ SENIOR PATTERN: Consumed UiState or Buffered Channel
// Option A (Google recommended): Model event as state + ack!
data class CheckoutUiState(
    val isSaving: Boolean = false,
    val navigateToReceipt: Boolean = false,
    val userMessage: String? = null
)
fun onNavigationHandled() = _uiState.update { it.copy(navigateToReceipt = false) }

// Option B: Channel + Dispatchers.Main.immediate
private val _events = Channel<UiEvent>(Channel.BUFFERED)
val events = _events.receiveAsFlow()
// Collect in LaunchedEffect with withContext(Dispatchers.Main.immediate)

Pattern 3: stateIn(viewModelScope, WhileSubscribed(5_000), initial)

✗ JUNIOR TRAP: Eagerly / WhileSubscribed(0) / Getter stateIn
// TRAP A: Eagerly keeps Room/WebSocket alive when app is backgrounded
val feed = repo.observeFeed()
    .stateIn(viewModelScope, SharingStarted.Eagerly, UiState.Loading)

// TRAP B: WhileSubscribed(0) restarts network/DB on every 300ms rotation
val feed2 = repo.observeFeed()
    .stateIn(viewModelScope, SharingStarted.WhileSubscribed(), UiState.Loading)

// TRAP C: Calling stateIn inside a function creates a new Flow per call!
fun loadUser(id: String) = repo.user(id)
    .stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), null)
✓ SENIOR PATTERN: Property-Scoped WhileSubscribed(5_000)
class FeedViewModel(repo: FeedRepository) : ViewModel() {
    // Created ONCE as a ViewModel property; shares 1 upstream across
    // rotations, cancels 5s after app backgrounds.
    val uiState: StateFlow<FeedUiState> = repo.observeFeed()
        .map { items -> FeedUiState.Ready(items) as FeedUiState }
        .catch { err -> emit(FeedUiState.Error(err)) }
        .stateIn(
            scope = viewModelScope,
            started = SharingStarted.WhileSubscribed(5_000),
            initialValue = FeedUiState.Loading
        )
}

LAB 12.1 · CONFLATED STATE HOLDER

Implement MiniStateFlow(initial)

Build equality conflation (===), CAS .update(fn), and immediate current-value replay on subscribe.

Not Run
Required API on class MiniStateFlow:
• constructor(initial) — stores initial state.
• get value() / set value(next) — if next === this._value, skip notifying subscribers (equality conflation); otherwise update and notify active subscribers.
• compareAndSet(expect, update) — if this._value === expect, assign this.value = update and return true; else return false.
• update(fn) — CAS loop: read prev = this._value, compute next = fn(prev), retry until compareAndSet(prev, next) succeeds (handles re-entrant updates!).
• subscribe(collector) — immediately invokes collector(this._value), registers collector, and returns an unsubscribe() function.

LAB 12.2 · MULTICAST BUFFER & REPLAY

Implement MiniSharedFlow(replay, extraBufferCapacity, onOverflow)

Support replay cache for late subscribers, synchronous tryEmit, and async emit under 'SUSPEND' and 'DROP_OLDEST'.

Not Run
Required API on class MiniSharedFlow:
• constructor(replay = 0, extraBufferCapacity = 0, onOverflow = 'SUSPEND') — total buffer per subscriber is replay + extraBufferCapacity.
• subscribe(collector) — immediately replays cached items (oldest-to-newest, up to replay) to collector, then delivers future emissions in order (awaiting async collectors sequentially per subscriber). Returns unsubscribe().
• tryEmit(value) — if 0 subscribers, records in replay cache (if replay > 0) and returns true. With subscribers: if 'SUSPEND' and any subscriber's queued items ≥ capacity (including capacity 0), returns false; if 'DROP_OLDEST', drops the oldest queued item for any full subscriber, updates replay cache, and returns true.
• async emit(value) — under 'DROP_OLDEST' delegates to tryEmit; under 'SUSPEND' with capacity 0 awaits all active collectors to finish processing value; with capacity > 0 suspends until every full subscriber frees a buffer slot, then enqueues.

LAB 12.3 · LIFECYCLE SHARING MANAGER

Implement WhileSubscribedController(stopTimeoutMs, onStart, onStop, scheduler)

Manage upstream start/stop lifecycles and cancel the stop timer if a UI subscriber reconnects during rotation.

Not Run
Required API on class WhileSubscribedController:
• constructor(stopTimeoutMs = 5000, onStart = () => {}, onStop = () => {}, scheduler = { setTimeout, clearTimeout })
• subscribe() — increments subscriber count. If a pending stop timer exists, cancel it via scheduler.clearTimeout without restarting upstream! Otherwise if upstream is inactive, mark active and call onStart(). Returns an idempotent unsubscribe() function.
• When unsubscribe() drops subscriber count to 0: if stopTimeoutMs <= 0, stop immediately and call onStop(); else schedule onStop() after stopTimeoutMs (only stopping if subscriber count is still 0 when the timer fires).
• isUpstreamActive() and getSubscriberCount() return current state.
