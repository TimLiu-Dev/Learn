Part 01 · First Principles

Why Unbounded Queues Crash & How Coordination Primitives Cap Work

In production concurrency, producers and consumers almost never match speeds for long. Without an explicit capacity bound and backpressure policy, the queue silently absorbs the mismatch as unbounded heap growth until an OutOfMemoryError or GC pause brings down the process (Kotlin Coroutines Guide; Kotlin Asynchronous Flow).

Counting Semaphores (Permits, Not Ownership)

A Semaphore(permits) maintains a non-negative permit counter. Each acquire() consumes a permit (suspending FIFO or parking if zero remain), and each release() restores one.

Unlike a Mutex (which enforces Mutual Exclusion with single-holder ownership), a counting semaphore has no owner: one coroutine or OS thread can call acquire() while another calls release()—making it ideal for bounding in-flight requests or producer/consumer slots.

Fixed-Capacity Ring Buffers

A ring buffer pre-allocates a fixed array of size N with two wrap-around cursors: head (oldest item to read) and tail (next slot to write), advancing modulo N.

Because memory is allocated once at construction, steady-state throughput creates zero node allocation churn, preserves cache locality, and establishes a strict upper bound on RAM regardless of producer bursts.

Part 03 · Production Kotlin & Android

Junior Traps vs. Senior Patterns in Kotlin

Apply Kotlin Coroutines Channels & Sync Primitives and Android Coroutines Best Practices to prevent OOMs, permit leaks, and startup races.

Pattern 1: Unbounded Queue OOM vs. Bounded Semaphore / Channel

✗ JUNIOR TRAP: Channel.UNLIMITED Under Burst
val uploads = Channel<Bitmap>(Channel.UNLIMITED)
scope.launch(Dispatchers.Default) {
    cameraFrames.collect { frame ->
        uploads.send(frame) // Never suspends; queues MBs!
    }
}
// Slow network upload leaves 100s of Bitmaps on heap -> OOM!
✓ SENIOR PATTERN: Bounded Channel + Explicit Overflow
val uploads = Channel<Bitmap>(
    capacity = 4,
    onBufferOverflow = BufferOverflow.DROP_OLDEST
) { evicted -> evicted.recycle() }

scope.launch(Dispatchers.Default) {
    cameraFrames.collect { frame -> uploads.send(frame) }
}

Pattern 2: Semaphore Permit Leak vs. withPermit

✗ JUNIOR TRAP: Manual acquire() / release() Without finally
private val apiGate = Semaphore(permits = 3)

suspend fun fetchPage(id: Int): Page {
    apiGate.acquire()
    val res = api.getPage(id) // Throws IOException or cancels!
    apiGate.release()         // Skipped! Permit leaked forever!
    return res
}
✓ SENIOR PATTERN: semaphore.withPermit { ... }
private val apiGate = Semaphore(permits = 3)

suspend fun fetchPage(id: Int): Page =
    apiGate.withPermit {
        // Releases permit in finally even on throw or CancellationException
        api.getPage(id)
    }

Pattern 3: Coordinating Multi-Worker Startup Phases

✗ JUNIOR TRAP: Arbitrary delay() Guessing
scope.launch { warmCache() }
scope.launch { loadConfig() }
delay(500) // Fragile race: fails on slow devices, wastes 450ms on fast!
startServingRequests()
✓ SENIOR PATTERN: CompletableDeferred / CountDownLatch
val readyGate = CompletableDeferred<Unit>()
// Or wait for N parallel init tasks via coroutineScope + async:
suspend fun bootAndServe() = coroutineScope {
    val cacheJob = async { warmCache() }
    val cfgJob = async { loadConfig() }
    awaitAll(cacheJob, cfgJob) // Deterministic barrier before Phase 2
    readyGate.complete(Unit)
    startServingRequests()
}
