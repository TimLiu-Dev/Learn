Part 01 · First-Principles Mental Model

Fault Isolation, Clean Draining & Observability Across Thread Hops

High-concurrency Spring Boot systems fail in three predictable places: cascading retries into a dying dependency, killing active Virtual Threads during Kubernetes deploys, and losing MDC trace IDs across async hops. Follow Resilience4j Official Documentation, Spring Boot Graceful Shutdown, and Micrometer Context Propagation.

1. Semaphore vs. ThreadPool Bulkhead

SemaphoreBulkhead caps concurrent callers with a lock-free permit counter (Semaphore) on the caller's thread. With Java 21–25+ Virtual Threads, waiting or blocking inside the guarded I/O call unmounts cleanly with zero extra OS threads.

ThreadPoolBulkhead copies calls onto a separate bounded platform-thread pool + ArrayBlockingQueue—built for legacy non-virtual-thread isolation or isolating CPU/JNI work, and it drops ThreadLocals unless wrapped with a ContextPropagatingTaskDecorator.

2. Resilience4j Decorator Ordering

Resilience4j's default Spring Boot aspect order wraps your target method from inside out:
Retry(CircuitBreaker(RateLimiter(TimeLimiter(Bulkhead(fn))))).

Why order matters: Every Retry attempt passes through CircuitBreaker. Once failures trip the breaker OPEN, subsequent retries hit CallNotPermittedException immediately and fast-fail without burning Bulkhead permits or hammering a dead dependency.

Request Enters ──▶ [Retry (Outermost)] │ only retries transient errors; fast-fails on CallNotPermittedException ▼ [CircuitBreaker] ──(OPEN?)──▶ 503 / Fallback (never touches RateLimiter or Bulkhead!) │ (CLOSED / HALF_OPEN) ▼ [RateLimiter] ──(quota 0?)──▶ RequestNotPermitted │ ▼ [SemaphoreBulkhead] ──(permits 0?)──▶ BulkheadFullException │ (try { ... } finally { releasePermit(); }) ▼ [Downstream I/O on Virtual Thread]

Bulkheads, Shutdown Phases & Context Propagation Matrix

Mechanism Primary Role Virtual Threads Interaction Production Failure Mode if Misconfigured
SemaphoreBulkhead Bounds max concurrent in-flight calls per downstream client Ideal: virtual thread unmounts on I/O; zero extra thread pools Without finally release or outer CircuitBreaker, permits leak or queue behind dead hosts
ThreadPoolBulkhead Dedicated bounded queue + platform thread pool Defeats virtual thread scaling if used for routine HTTP calls Drops MDC / SecurityContext unless decorated; platform thread starvation
server.shutdown=graceful Refuses new traffic (503) while draining active work Waits up to timeout-per-shutdown-phase (default 30s) for Virtual Threads & Kafka Without Kubernetes preStop sleep, kube-proxy sends packets after SIGTERM

The Kubernetes SIGTERM / kube-proxy Race: Sending SIGTERM to a Pod and updating iptables/IPVS endpoints across cluster nodes happen asynchronously (Kubernetes Pod Termination). Without a preStop sleep (e.g., 5–10s), your Spring Boot app flips to REFUSING_TRAFFIC and rejects legitimate Service traffic with 503 before Ingress stops routing to it.

Part 03 · Production Java 21–25+ & Spring Boot

Junior Traps vs. Senior Patterns in Production

Wire Resilience4j aspect ordering, Spring Boot graceful shutdown, and Micrometer context propagation together so resilience and observability hold up under load.

Pattern 1: Resilience4j Aspect Ordering (Retry(CircuitBreaker(RateLimiter(Bulkhead(fn)))))

✗ JUNIOR TRAP: Retry Inside CircuitBreaker + ThreadPoolBulkhead
// application.yml — WRONG aspect order + wrong bulkhead for Virtual Threads!
resilience4j:
  circuitbreaker:
    circuitBreakerAspectOrder: 1   # Lower number = OUTERMOST!
  retry:
    retryAspectOrder: 2            # Retries 3x INSIDE the breaker!
    instances:
      ledgerClient:
        maxAttempts: 4             # Hammers dead host 4x before CB records 1 failure!
  thread-pool-bulkhead:            # Spawns fixed OS threads; defeats Virtual Threads!
    instances:
      ledgerClient:
        maxThreadPoolSize: 8
✓ SENIOR PATTERN: Retry Outside Breaker + SemaphoreBulkhead
// application.yml — Retry(CircuitBreaker(RateLimiter(Bulkhead(fn))))
resilience4j:
  retry:
    retryAspectOrder: 1            # Outermost: fast-fails if CB throws CallNotPermittedException
    instances:
      ledgerClient:
        maxAttempts: 3
        waitDuration: 100ms
        ignoreExceptions:
          - io.github.resilience4j.circuitbreaker.CallNotPermittedException
  circuitbreaker:
    circuitBreakerAspectOrder: 2
    instances:
      ledgerClient:
        slidingWindowSize: 20
        failureRateThreshold: 50
  ratelimiter:
    rateLimiterAspectOrder: 3
  bulkhead:                        # SemaphoreBulkhead (Virtual Thread friendly!)
    bulkheadAspectOrder: 4
    instances:
      ledgerClient:
        maxConcurrentCalls: 32
        maxWaitDuration: 10ms

Pattern 2: Graceful Shutdown (server.shutdown=graceful) + Kafka + K8s preStop

✗ JUNIOR TRAP: Immediate Shutdown + No K8s preStop
# application.yml
server:
  shutdown: immediate   # Kills active HTTP requests & JDBC calls on SIGTERM!
# Missing timeout-per-shutdown-phase and Kafka stop timeout

# deployment.yaml
lifecycle: {}           # SIGTERM arrives while kube-proxy still routes traffic!
terminationGracePeriodSeconds: 30
✓ SENIOR PATTERN: Coordinated Drain Window & preStop
# application.yml (Spring Boot 3.4+)
server:
  shutdown: graceful
spring:
  lifecycle:
    timeout-per-shutdown-phase: 30s  # Tomcat + Kafka SmartLifecycle drain budget
  kafka:
    listener:
      ack-mode: record
      shutdown-timeout: 25000        # Finish current poll batch before closing consumer
management:
  endpoint:
    health:
      probes:
        enabled: true                # Exposes /actuator/health/readiness

# deployment.yaml — let kube-proxy remove pod IP before SIGTERM hits JVM
lifecycle:
  preStop:
    exec:
      command: ["sh", "-c", "sleep 5"]
terminationGracePeriodSeconds: 45  # Must exceed preStop (5s) + shutdown-phase (30s)

Pattern 3: Micrometer Context Propagation (Hooks.enableAutomaticContextPropagation() & ContextSnapshot)

✗ JUNIOR TRAP: Raw MDC / ThreadLocal Across Async Hops
public CompletableFuture<Receipt> processOrder(Order order) {
    // Runs on ForkJoinPool.commonPool() — MDC.get("traceId") is NULL
    // or worse: leaks a previous request's tenantId on a reused thread!
    return CompletableFuture.supplyAsync(() -> {
        log.info("Processing trace={}", MDC.get("traceId"));
        return ledgerClient.charge(order);
    });
}
✓ SENIOR PATTERN: Micrometer ContextSnapshot + Reactor Hook
// 1. WebFlux / Reactor global hook (or spring.reactor.context-propagation=auto)
@PostConstruct
void enableContextPropagation() {
    ContextRegistry.getInstance().registerThreadLocalAccessor(new MdcAccessor("traceId", "tenantId"));
    Hooks.enableAutomaticContextPropagation();
}

// 2. Imperative / Virtual Thread Executor propagation via ContextSnapshotFactory
private final ContextSnapshotFactory snapshots = ContextSnapshotFactory.builder().build();

public CompletableFuture<Receipt> processOrder(Order order, ExecutorService vtExecutor) {
    ContextSnapshot snapshot = snapshots.captureAll();
    return CompletableFuture.supplyAsync(snapshot.wrap(() -> {
        log.info("Processing trace={} tenant={}", MDC.get("traceId"), MDC.get("tenantId"));
        return ledgerClient.charge(order);
    }), vtExecutor);
}

LAB 26.1 · RESILIENCE4J DECORATOR CHAIN

Implement ResilienceChain (Bulkhead → CircuitBreaker → Retry)

Wire Retry outside CircuitBreaker and CircuitBreaker outside SemaphoreBulkhead so retries fast-fail when OPEN and permits never leak.

Not Run
• constructor({ maxConcurrent, failureThreshold, maxAttempts }) initializes activeBulkhead = 0, circuitState = 'CLOSED', consecutiveFailures = 0, and metrics = { downstreamCalls: 0, fastFailedOpen: 0, bulkheadRejected: 0, maxConcurrentSeen: 0 }.
• async execute(fn) runs up to maxAttempts: check CircuitBreaker first (if 'OPEN', increment fastFailedOpen and immediately rethrow CallNotPermittedException without retrying).
• Next check SemaphoreBulkhead (if activeBulkhead >= maxConcurrent, increment bulkheadRejected and throw BulkheadFullException without tripping the breaker).
• Inside try { ... } finally { this.activeBulkhead--; }: increment downstreamCalls, run await fn(); reset consecutiveFailures = 0 on success, or increment and trip circuitState = 'OPEN' when consecutiveFailures >= failureThreshold.

LAB 26.2 · GRACEFUL SHUTDOWN COORDINATOR

Implement GracefulShutdownServer Drain & Deadline

Reject new arrivals with 503 upon beginShutdown(), drain active requests cleanly, or force cancellation at gracefulTimeoutMs.

Not Run
• handleRequest(taskFn): if !this.acceptingTraffic, increment this.rejected503 and return { status: 503, error: 'Service Unavailable' }. Otherwise track an active token = { cancelled: false } in this.inFlight, await taskFn(token), return { status: 504, error: 'Shutdown Timeout' } if token.cancelled else increment this.completed and return { status: 200, value }. Always delete token from inFlight in finally and notify drain waiters if inFlight.size === 0.
• beginShutdown(): flip acceptingTraffic = false and readinessState = 'REFUSING_TRAFFIC'. If inFlight.size === 0, return { outcome: 'DRAINED_CLEANLY', remaining: 0 }. Otherwise wait until drained OR gracefulTimeoutMs expires (marking remaining tokens cancelled = true, incrementing this.timedOut, clearing inFlight, and returning { outcome: 'TIMEOUT_FORCED', remaining }).

LAB 26.3 · MICROMETER CONTEXT PROPAGATION

Implement ContextSnapshotPropagator

Capture ThreadLocal / MDC keys (traceId, tenantId) and restore them cleanly across nested dirty-thread async hops.

Not Run
• set(key, val), get(key), clear(key) operate on this.threadLocal (a Map).
• captureAll() returns a plain-object shallow copy of current entries (isolated from later mutations).
• withSnapshot(snapshot, fn) saves previous threadLocal entries, clears threadLocal (preventing stale keys like a previous tenant from leaking), applies snapshot keys, executes fn(), and restores previous entries in finally.
• wrap(fn) captures const snap = this.captureAll() at wrap time and returns (...args) => this.withSnapshot(snap, () => fn(...args)).
