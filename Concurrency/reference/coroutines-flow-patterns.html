Kotlin Coroutines, Flow & Android Concurrency Patterns

Side-by-side cheat sheet for Dispatchers, Structured Concurrency, Cancellation, Flow operators, Lifecycle collection, and Room/WorkManager invariants.

Dispatchers & Context Rules

  • Dispatchers.Default: CPU-bound work (~core count threads). Never block with I/O!
  • Dispatchers.IO: Blocking I/O (up to 64+ threads, shares pool with Default).
  • Dispatchers.IO.limitedParallelism(n): Isolated bounded lane (does not shrink Default).
  • Dispatchers.Main.immediate: Runs immediately if already on Main thread, skipping extra frame post.
  • Inject dispatchers via constructor so tests swap in StandardTestDispatcher.

Structured Concurrency & Cancellation

  • Use coroutineScope {} for fail-fast parallel work; supervisorScope {} for independent children.
  • Never pass SupervisorJob() directly to launch(SupervisorJob())—it breaks sibling supervision.
  • Never swallow CancellationException in catch(e: Exception) or runCatching; always rethrow it!
  • Wrap suspending cleanup in finally { withContext(NonCancellable) { ... } }.

Flow, StateFlow & Android UI Collection

// ViewModel: Cold Flow -> Hot StateFlow surviving 5s rotation gap
val uiState: StateFlow<UiState> = repo.observeFeed()
    .flowOn(Dispatchers.IO) // Affects UPSTREAM only!
    .catch { err -> emit(UiState.Error(err)) }
    .stateIn(
        scope = viewModelScope,
        started = SharingStarted.WhileSubscribed(5_000),
        initialValue = UiState.Loading
    )

// Atomic MVI state update (prevents concurrent copy() field loss)
_uiState.update { current -> current.copy(isRefreshing = false) }

// Compose UI: Lifecycle-safe collection
val state by viewModel.uiState.collectAsStateWithLifecycle()
