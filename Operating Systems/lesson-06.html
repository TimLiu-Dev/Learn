01 // MENTAL MODEL & INTERACTIVE SIMULATOR

2-Copy Unix Sockets vs 1-Copy Binder mmap vs 0-Copy DMA-BUF

Why Traditional IPC Copies Twice

Pipes / Unix Domain Sockets: Process A writes into a socket FD via write()/sendmsg():

Copy 1 (EL0 → EL1): Kernel executes copy_from_user() into an internal kernel sk_buff or pipe page.

Copy 2 (EL1 → EL0): Process B calls read()/recvmsg(); kernel executes copy_to_user() from sk_buff into Process B's heap buffer.

Also: sockets require separate epoll wakeups, carry no native thread-pool management, and do not propagate caller UID/PID credentials or priority inheritance out of the box.

How Binder Cuts Copies in Half (1-Copy Kernel mmap)

At startup, each Binder server opens /dev/binder and calls mmap(1MB). The kernel allocates physical pages and maps them simultaneously into:

1. Kernel EL1 address space (Read-Write) and 2. Server EL0 address space (Read-Only).

When Client sends a Parcel via ioctl(BINDER_WRITE_READ), the kernel allocates a slice in the Server's pool and calls copy_from_user() once directly into the shared physical page. The Server immediately reads the payload via pointer offset—zero second copy!

Security Invariant: The Receiver's mmap mapping is PROT_READ (read-only) in EL0! Even a compromised Server process cannot corrupt kernel metadata or forge another caller's sender_euid/sender_pid, because the Binder driver stamps credentials in EL1 and wakes the Server with BC_FREE_BUFFER ownership later.
03 // ANDROID INTERNALS BRIDGE

TransactionTooLargeException, 15-Thread Pool Exhaustion & GraphicBuffer

Why TransactionTooLargeException Happens Below 1MB

Shared Pool Across All Active Calls: Every Android app gets roughly a 1 MB (1024*1024 - 8KB in AOSP ProcessState.cpp) Binder mmap buffer shared across every concurrent incoming transaction—not 1 MB per call!

The 50% Async Cap: oneway (asynchronous) calls are strictly limited to half (~512 KB) of the target's pool so a spammy async client cannot starve synchronous replies or system lifecycle callbacks (ActivityThread.scheduleLaunchActivity).

Fix: Never pass large bitmaps or JSON blobs via AIDL/Bundle; pass a ParcelFileDescriptor backed by SharedMemory / memfd.

Binder Thread Pool Exhaustion & SurfaceFlinger 0-Copy

15 Worker Threads + Main Binder Thread: By default ProcessState caps Binder worker threads at 15 (16 total). If 16 synchronous Binder threads in Process A call Process B, which calls back synchronously into Process A (recursive IPC), all threads block—freezing the app until ANR!

SurfaceFlinger & DMA-BUF: A single 1440p RGBA frame is ~14 MB (33 MB at 4K). Apps render into a GraphicBuffer backed by a kernel DMA-BUF FD, then pass only the tiny FD handle over Binder to SurfaceFlinger, which hands it straight to the GPU/Display Hardware with 0 CPU copies.

LAB 1 OF 3 // SINGLE-COPY MMAP ALLOCATOR

Implement Binder mmap Buffer Allocator (binderSend)

Enforce 1MB pool limits, 8-byte alignment, 50% async (oneway) reservation, and single-copy offsets.

Not Run
Specification: binderSend(driver, tx) where:
• driver: { poolSize = 1048576, usedBytes, asyncUsedBytes, nextOffset, transactions }.
• tx: { id: string, size: number, oneway: boolean }.
• Validate tx.size is a non-negative integer; if not, return { ok: false, errno: -22 } (-EINVAL).
• Align size up to 8 bytes: alignedSize = Math.ceil(tx.size / 8) * 8.
• If alignedSize > poolSize, return { ok: false, errno: -7 } (-E2BIG).
• If tx.oneway and driver.asyncUsedBytes + alignedSize > Math.floor(poolSize / 2), return { ok: false, errno: -28 } (-ENOSPC).
• If driver.usedBytes + alignedSize > poolSize, return { ok: false, errno: -28 } (-ENOSPC).
• Otherwise allocate at offset = driver.nextOffset, update usedBytes, asyncUsedBytes (if oneway), nextOffset += alignedSize, push record to driver.transactions, and return { ok: true, offset, alignedSize, copyCount: 1 }.
LAB 2 OF 3 // THREAD POOL & STARVATION GUARD

Implement Binder Thread Pool Dispatcher (dispatchBinderPool)

Prevent oneway floods from starving synchronous calls and detect recursive thread-pool deadlock.

Not Run
Specification: dispatchBinderPool(pool, queue) where:
• pool: { maxThreads, busyThreads, activeSync, activeAsync }.
• queue: array of { id, oneway, recursiveWait? }.
• Partition into synchronous (!tx.oneway) first, then oneway, preserving FIFO order within each group.
• For each sync transaction: if pool.busyThreads < pool.maxThreads, dispatch it (increment busyThreads and activeSync, push tx.id to dispatched). Otherwise, if tx.recursiveWait is true, immediately return { ok: false, error: "-EDEADLK", dispatched, deferred }; else push tx.id to deferred.
• For each oneway transaction: reserve 1 thread for future sync calls whenever pool.maxThreads > 1 (so asyncCap = pool.maxThreads > 1 ? pool.maxThreads - 1 : 1). If pool.busyThreads < asyncCap, dispatch it (increment busyThreads and activeAsync, push tx.id to dispatched); else push tx.id to deferred.
• Return { ok: true, error: null, dispatched, deferred }.
LAB 3 OF 3 // KERNEL FD TRANSLATION

Implement Binder FD Translator (translateBinderFds)

Remap memfd / DMA-BUF descriptors into the target process's FD table with atomic rollback on error.

Not Run
Specification: translateBinderFds(txOffsets, srcFds, dstFds):
• txOffsets: array of { type: string, fd?: number }.
• srcFds / dstFds: plain objects mapping integer FD keys (e.g. 0, 1, 2, 5) to descriptor objects { kind, backingId, flags }.
• Ignore entries where entry.type !== "BINDER_TYPE_FD".
• For each BINDER_TYPE_FD: look up srcFds[entry.fd]. If missing, roll back all FDs installed into dstFds so far during this call and return { ok: false, errno: -9, translated: [] } (-EBADF).
• Otherwise find the lowest unused non-negative integer FD in dstFds (0, 1, 2, ...), install { ...srcDesc, cloexec: true } into dstFds[newFd], and record { srcFd: entry.fd, dstFd: newFd, backingId: srcDesc.backingId }.
• On success return { ok: true, translated }.
