01 // MENTAL MODEL & INTERACTIVE SIMULATOR

Hardware DMA, blk-mq, Event Readiness & Shared I/O Rings

1. DMA + IOMMU & Linux blk-mq

PIO → DMA + Scatter-Gather: Instead of the CPU copying bytes from device registers (Programmed I/O), the OS hands the NVMe/UFS/NIC controller a scatter-gather descriptor ring of physical RAM pages; the DMA engine transfers megabytes directly to DRAM and fires one completion IRQ.

IOMMU: Translates Device Virtual Addresses (IOVA) to Physical Addresses so a buggy/malicious PCIe/USB device cannot DMA-overwrite kernel memory.

blk-mq: Replaces Linux's old single-spinlock block queue with per-CPU software staging queues (merging contiguous sectors) feeding hardware dispatch queues mapped directly to NVMe/UFS submission queues.

2. epoll (LT vs ET) & io_uring

Why epoll Beats select/poll: select/poll copy and scan all N file descriptors on every syscall (O(N)). epoll_ctl registers FDs once into a kernel red-black tree, and waitqueue callbacks append ready FDs to an O(1) ready list returned by epoll_wait().

Level-Triggered (LT) vs Edge-Triggered (EPOLLET): LT notifies as long as unread bytes remain in the socket buffer. EPOLLET notifies only on a not-ready → ready transition—so failing to drain until EAGAIN hangs the socket forever!

io_uring: Maps two lock-free ring buffers (Submission Queue SQ & Completion Queue CQ) between EL0 and EL1. With IORING_SETUP_SQPOLL, a kernel thread polls the SQ—zero syscalls per I/O!

02 // C & KERNEL REALITY

Correct EPOLLET Drain Loops & io_uring Memory Barriers

epoll_et_drain.c — Non-Blocking Edge-Triggered Read Loop 
// Socket MUST be O_NONBLOCK when registered with EPOLLET!
for (;;) {
  ssize_t n = read(fd, buf, sizeof(buf));
  if (n > 0) {
    process_bytes(buf, n);
    continue; // Keep draining! Returning early risks permanent hang!
  }
  if (n == 0) {
    close_peer(fd); // EOF
    break;
  }
  if (errno == EAGAIN || errno == EWOULDBLOCK) {
    break; // Kernel buffer is now empty; next arrival will trigger edge!
  }
  if (errno == EINTR) continue;
  handle_error(fd);
  break;
}
iouring_submit.c — Shared Ring Producer/Consumer Barriers 
// User space (EL0) submitting an SQE into mmap'd io_uring rings
uint32_t tail = *sq->ktail;
struct io_uring_sqe *sqe = &sq->sqes[tail & *sq->kring_mask];
sqe->opcode = IORING_OP_READ;
sqe->fd = target_fd;
sqe->addr = (uint64_t)buf;
sqe->len = 4096;
sqe->user_data = req_id;

// Release barrier ensures SQE fields are visible BEFORE tail increments!
__atomic_store_n(sq->ktail, tail + 1, __ATOMIC_RELEASE);

// If IORING_SETUP_SQPOLL is active & thread isn't sleeping, 0 syscalls!
// Otherwise batch-notify kernel once for N SQEs:
io_uring_enter(ring_fd, submitted, 0, 0, NULL);
Why Memory Ordering Matters in io_uring & blk-mq:
io_uring rings are lockless Single-Producer/Single-Consumer queues shared directly across the user/kernel boundary. Without __ATOMIC_RELEASE when writing sqTail (and __ATOMIC_ACQUIRE when reading cqTail), weak-ordered ARM64 CPUs could reorder the tail pointer store ahead of the SQE payload writes—causing the kernel to read stale/uninitialized SQEs!
03 // ANDROID INTERNALS BRIDGE

Android Looper + MessageQueue Uses epoll_wait() + eventfd

Inside nativePollOnce() on Every Android UI Thread

No Busy-Waiting: When your app's Main Thread has no pending Handler messages or Choreographer VSync frames, it calls MessageQueue.nativePollOnce(ptr, timeoutMillis), which invokes Looper::pollInner() in C++ (libutils).

epoll_wait() + eventfd: The native Looper sleeps in epoll_wait() watching: (1) mWakeEventFd (an eventfd written to via write(8 bytes) whenever another thread calls Handler.post()), and (2) InputDispatcher socket/pipe FDs for touch events.

ANR Root Cause: If your main thread blocks inside a synchronous disk read or Binder call instead of returning to epoll_wait() within 5s, InputDispatcher's pipe fills/times out → Android raises an ANR.

UFS Flash blk-mq Merging & io_uring on Android

UFS 4.0 & blk-mq: Android phones use UFS flash with deep hardware command queues (32+ tags). Merging adjacent 4KB SQLite/Dex reads in blk-mq reduces UFS command overhead and boosts sequential bandwidth while keeping latency low via I/O schedulers like mq-deadline or kyber.

io_uring & Seccomp: While io_uring gives massive throughput wins for database/media engines, untrusted Android app sandboxes historically restricted io_uring_setup in seccomp-bpf due to kernel attack-surface hardening, whereas privileged system daemons (like apexd / update_engine / native servers) can leverage async I/O rings safely.

LAB 1 OF 3 // EPOLL LEVEL vs EDGE TRIGGERED

Implement epollStep(fdStates, interested, mode)

Emit ready FDs under "LT" or "ET" (EPOLLET) edge-transition semantics.

Not Run
Specification:
• fdStates: map object { [fd]: { ready: boolean, prevReady: boolean } }.
• interested: array of FD keys registered in this epoll instance.
• mode: "LT" (Level-Triggered) or "ET" (Edge-Triggered).
• For each fd in interested: if !fdStates[fd], skip it. Otherwise:
  • In "LT" mode: emit fd if fdStates[fd].ready === true.
  • In "ET" mode: emit fd only if fdStates[fd].ready === true && fdStates[fd].prevReady === false (rising edge).
  • Always update fdStates[fd].prevReady = Boolean(fdStates[fd].ready) after checking.
• Return the array of emitted FDs in the order checked.
LAB 2 OF 3 // IO_URING RING CONSUMER & PRODUCER

Implement ioUringProcess(sqRing, cqRing, maxBatch, executeOp)

Consume SQEs across power-of-2 ring wraparound without clobbering unread CQEs.

Not Run
Specification:
• sqRing: { head, tail, mask, entries } (ring capacity = mask + 1).
• cqRing: { head, tail, mask, entries, overflow }.
• Loop while processed < maxBatch && sqRing.head !== sqRing.tail:
  1. Read sqe = sqRing.entries[sqRing.head & sqRing.mask] and increment sqRing.head++.
  2. Execute cqe = executeOp(sqe) and increment processed++.
  3. If CQ has space ((cqRing.tail - cqRing.head) < (cqRing.mask + 1)), write cqRing.entries[cqRing.tail & cqRing.mask] = cqe and increment cqRing.tail++.
  4. Else CQ is full: increment cqRing.overflow++ without overwriting unread CQEs.
• Return processed.
LAB 3 OF 3 // BLK-MQ SECTOR MERGING

Implement blkMqMergeAndDispatch(requests, maxMergeBytes)

Sort block requests by sector and coalesce contiguous same-direction I/O up to maxMergeBytes.

Not Run
Specification: Each request in requests is { id, op: "READ"|"WRITE", sector, bytes } (1 sector = 512 bytes, bytes is a positive multiple of 512).
1. Do not mutate input array or objects. Sort a copy by sector ascending (preserving original order on equal sector).
2. Coalesce adjacent sorted requests into batches { op, startSector, totalBytes, ids } whenever:
  • curr.op === prev.op
  • prev.startSector + (prev.totalBytes / 512) === curr.sector (strictly contiguous)
  • prev.totalBytes + curr.bytes <= maxMergeBytes
3. Return the array of merged dispatch descriptors.
