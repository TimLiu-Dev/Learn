Lesson 09: Page Cache, MGLRU, ZRAM, PSI & Android LMKD

In Linux and Android, "free RAM is wasted RAM"—the kernel aggressively fills spare physical frames with the Page Cache. When memory tightens, the OS must decide which pages to drop, write back, or compress into ZRAM using Multi-Gen LRU (MGLRU)—and when thrashing threatens UI frames, PSI (Pressure Stall Information) triggers Android's lmkd before the kernel OOM killer freezes the phone.

Page Cache, Multi-Gen LRU Aging & Pressure-Driven Reclaim

1. Page Cache: File-Backed vs Anonymous Pages

Clean File Pages: Read from APK/DEX/shared libraries or ext4/f2fs files via address_space. Since an exact copy already lives on flash, the kernel can drop a clean page instantaneously (zero I/O) on reclaim.

Dirty File Pages: Modified in RAM (e.g. SQLite write before fsync). Must be written back to storage by flusher threads before the frame can be reused.

Anonymous Pages: Heap/stack/Zygote CoW private pages have no backing file on disk. Reclaiming them requires either compressing them into ZRAM (in-RAM block device) or swapping to disk.

2. From Clock & Active/Inactive LRU to MGLRU

Clock (Second-Chance): Scans frames circularly; if the hardware Accessed/Reference bit is 1, clears it and grants a second chance; if 0, evicts.

Why Classic 2-List LRU Struggles: Linux's legacy Active/Inactive lists struggle on 16GB phones running background apps + large sequential media reads, causing working-set thrashing and high CPU lock contention.

MGLRU (Linux 6.1+): Groups folios into multiple generations numbered min_seq .. max_seq. Referenced pages promote to max_seq; reclaim scans min_seq (oldest) first and prefers clean pages over dirty pages.

PSI (Pressure Stall Information) & Cgroups v2:
/proc/pressure/memory exposes exact microsecond stall percentages: some (at least one task stalled waiting on reclaim/swap) and full (all non-idle tasks stalled simultaneously—UI is frozen!). Paired with cgroups v2 (memory.min hard floor, memory.low soft protection, memory.high throttle), PSI lets Android's lmkd measure real user pain rather than guessing from raw free-page counts.

MGLRU Generations, ZRAM Swap-Out & PSI poll() Triggers

mglru_reclaim.c — Linux mm/vmscan.c MGLRU Aging & Scan 
// Simplified Linux Multi-Gen LRU (mm/vmscan.c)
struct lru_gen_folio {
  unsigned long max_seq;          // Newest generation counter
  unsigned long min_seq[ANON_AND_FILE]; // Oldest unreclaimed generation
  struct list_head folios[MAX_NR_GENS][ANON_AND_FILE][MAX_NR_ZONES];
};

// Aging walks page table PTE Accessed bits (or folio_test_referenced)
// and advances max_seq, keeping hot working-set folios in recent gens.
static int isolate_folios(struct lruvec *lruvec, int swappiness, int *type) {
  int gen = lru_gen_from_seq(lruvec->lrugen.min_seq[*type]);
  // Scan oldest generation: if folio_referenced(), promote to max_seq!
  // Otherwise isolate clean file folios first; dirty folios wait for writeback
  // or ZRAM compression if anon swappiness permits.
  return scan_gen_list(lruvec, gen, *type);
}

int psi_fd = open("/proc/pressure/memory", O_RDWR | O_CLOEXEC);
// Trigger EPOLLPRI when "full" memory stall exceeds 100ms in a 1s window (10%)
const char trigger[] = "full 100000 1000000";
write(psi_fd, trigger, sizeof(trigger));

struct epoll_event ev = { .events = EPOLLPRI, .data.fd = psi_fd };
epoll_ctl(epfd, EPOLL_CTL_ADD, psi_fd, &ev);

// When epoll_wait wakes on psi_fd:
// 1. Walk /proc/<pid>/oom_score_adj and /proc/<pid>/statm (RSS)
// 2. Skip protected processes (oom_score_adj < 0)

Cgroups v2 Memory Controllers & Direct Reclaim Avoidance:
Modern Linux uses cgroups v2 unified hierarchy for per-app / per-slice protection: memory.min guarantees hard protection (never reclaimed unless global OOM), memory.low gives best-effort soft protection, and memory.high throttles allocating threads into reclaim without hard-killing them. Keeping a healthy pool of free pages via background kswapd + ZRAM avoids synchronous direct reclaim on the UI render thread.
03 // ANDROID INTERNALS BRIDGE

Why Android Uses ZRAM (Not Disk Swap) & How lmkd Prevents Kernel OOM

Why Android Has Zero Disk Swap & Relies on ZRAM

Flash Wear & Latency: Swapping dirty anonymous pages to UFS/eMMC NAND flash causes severe write amplification, wearing out soldered storage prematurely and causing 50–200ms random read stalls when switching back to an app.

ZRAM Compressed RAM Swap: Android creates /dev/block/zram0 in RAM using lz4 or zstd. Cold anonymous pages (e.g. background app heaps) are compressed ~2.5x–3x inside RAM in microseconds—giving an 8GB phone ~11GB of effective memory with zero flash wear!

Android lmkd vs Linux Kernel OOM Killer

Kernel OOM Killer Is Too Late: The Linux OOM killer only triggers when page allocation completely fails—after the device has already thrashed and frozen for seconds. Worse, its oom_badness() heuristic doesn't understand Android's foreground/cached activity lifecycle.

lmkd (Low Memory Killer Daemon): Runs in user space, receives real-time kernel PSI notifications via epoll_wait(), and kills processes ordered by ActivityManagerService's oom_score_adj (900..999 cached → 700 previous → 200 perceptible → 0 foreground; negative values like -900 for system_server are untouchable).

LAB 1 OF 3 // CLOCK (SECOND-CHANCE) REPLACEMENT

Implement clockReplace(capacity, refs)

Simulate the circular Clock algorithm with hardware reference-bit second chances.

Not Run
Specification: Given capacity (integer ≥ 1) and refs (array of page IDs):
• Maintain a ring of occupied frames (initially empty []) and clock hand = 0.
• For each pageId in refs:
  1. If pageId is already in frames: increment hits, set that frame's refBit = 1 (do not move hand).
  2. Else: increment misses. If frames.length < capacity, push { pageId, refBit: 1 }.
  3. Else (ring is full): advance in a loop—while frames[hand].refBit === 1, clear frames[hand].refBit = 0 and advance hand = (hand + 1) % capacity. Once a frame with refBit === 0 is found, replace it with { pageId, refBit: 1 }, increment evictions, and advance hand = (hand + 1) % capacity.
• Return { hits, misses, evictions, frames: frames.map(f => f.pageId) }.
LAB 2 OF 3 // MGLRU GENERATION AGING & EVICTION

Implement mglruReclaim(pages, maxGen, needed)

Promote referenced pages to the newest generation, then reclaim oldest clean pages before dirty pages.

Not Run
Specification: Given pages (array of { id, gen, referenced, dirty }), maxGen (integer ≥ 0), and needed (integer ≥ 0):
1. Clone every page object so the caller's array is not mutated.
2. Aging / Promotion pass: For each cloned page, if page.referenced === true, promote it to page.gen = maxGen and clear page.referenced = false.
3. Reclaim pass: Evict Math.min(needed, cloned.length) pages ordered by:
  • Lowest gen first (oldest generation 0 before 1, etc.)
  • Within the same gen, clean (dirty === false) before dirty (dirty === true)
  • Preserve original input order on ties.
4. Return { evictedIds, remaining } where evictedIds lists evicted page IDs in eviction order, and remaining lists surviving cloned pages (in original relative order).
LAB 3 OF 3 // PSI & ANDROID LMKD VICTIM SELECTOR

Implement selectLmkdVictim(procs, psiFullPct, thresholdPct)

Enforce Android's PSI pressure gate, protected system-process immunity, and oom_score_adj ranking.

Not Run
Specification: Given procs (array of { pid, name, oomScoreAdj, rssKb }), psiFullPct, and thresholdPct:
• If psiFullPct < thresholdPct, return { action: "NONE", victim: null }.
• Filter to killable processes with oomScoreAdj >= 0 (processes with oomScoreAdj < 0 are protected).
• If no killable processes exist, return { action: "NO_KILLABLE", victim: null }.
• Otherwise select the single process with the highest oomScoreAdj; break ties by largest rssKb, then smallest pid. Return { action: "KILL", victim }.
