1. How Every Lesson Works — The Curriculum Legend

Every lesson follows the exact structure benchmarked in Lesson 01. Decode the badges and modules below.

01 // MENTAL MODEL

First-Principles Architecture & Simulators

Visual hardware/OS state diagrams and interactive step-by-step simulators so you see registers, stacks, page tables, and queues mutate in real time.

02 // C & KERNEL REALITY

Production C, ARM64/x86-64 & Linux Source

Real, idiomatic C and assembly snippets mapped to Linux 6.x kernel subsystems (arch/arm64, kernel/sched, mm/, fs/), never toy pseudocode alone.

03 // ANDROID BRIDGE

Android Internals Connection

Translates every OS primitive to what you already recognize on Android: ART, Zygote, bionic, Binder, Looper/epoll, lmkd, 16KB pages, and Perfetto.

04 // RUNNABLE CODE LAB

Live Execution, Auto-Checks, Hints & Solution

Each lesson includes 3 hands-on coding labs that run directly in your browser against deterministic kernel/VM test suites, with 3 progressive hints and a full final answer.

05 // CODE QUIZ

Diagnostic MCQs (Why Right & Why Wrong)

Code-reading and systems-debugging questions. Selecting an answer reveals why the correct choice holds and why every wrong option fails in production.

06 // SENIOR BAR

Production Failure Modes & Resume Artifacts

Security CVEs, tail-latency traps, observability commands (perf, strace, bpftrace), and senior-level interview rubrics.

Why the Browser Code Labs run deterministic OS-VM JavaScript alongside real C examples: In a browser, compiling C to WebAssembly still cannot execute real OS ring transitions, page faults, or kernel boundary checks. Our in-browser labs give you a real programmable OS/Hardware VM (virtual CPU registers, privilege bits, byte-addressable RAM, MMU page tables, syscall dispatch tables) that actually executes your code against adversarial edge-case tests offline, paired side-by-side with exact Linux C kernel code you can also compile locally with clang/gcc.

Milestone 1 (After Phase 1)

Boot, UART, Traps & Preemptive Scheduler

Boot via QEMU, initialize exception vectors, handle timer interrupts, and context-switch between 2+ kernel/user tasks using EEVDF-style virtual deadlines.

Milestone 2 (After Phase 2)

Spinlocks, Futexes & Ring-Buffer IPC

Implement atomic ticket locks, wait-queue futex(WAIT/WAKE), and a Binder-inspired single-copy shared-memory IPC channel with bounded transaction queues.

Milestone 3 (After Phase 3)

4-Level Paging, CoW & Slab Allocator

Enable MMU with kernel/user address-space split, demand paging on page fault, Copy-on-Write fork(), and a Buddy + SLUB-style object allocator.

Milestone 4 (After Phase 4)

ELF Loader, VFS, VirtIO-Blk & Async Ring

Load real ELF64 binaries from disk, mount a minimal inode-based filesystem over VirtIO, and add an io_uring-style submission/completion I/O ring.

Milestone 5 (After Phase 5)

Capabilities, Benchmarks & Fault Tests

Add syscall allowlists (seccomp-style), measure p50/p99 IPC & context-switch latency in cycles, and write automated CI tests under QEMU.

How this looks on a 2027 Resume (Example Bullets you will genuinely be able to defend in interviews):
  • Built AegisOS-64, a 64-bit preemptive OS kernel in C/ARM64 assembly under QEMU featuring 4-level virtual memory, Copy-on-Write fork(), and a Buddy + Slab kernel allocator.
  • Engineered a Binder-inspired single-copy shared-memory IPC subsystem with futex synchronization and lock-free submission/completion rings, achieving sub-3μs p99 round-trip IPC latency under contention.
  • Implemented VFS + VirtIO block driver and seccomp-style per-process syscall filtering, validated with automated fault-injection and memory-boundary test suites.
