Multi-core synchronization starts in silicon, not in pthread_mutex_lock(). 01 // MENTAL MODEL & INTERACTIVE SIMULATOR

Store Buffers, MESI Cache Lines & The 3-State Futex

1. Cache Lines, MESI & Store Buffers

Cache Coherency (MESI): CPU cores do not read/write individual bytes to RAM—they move 64-byte cache lines in states Modified, Exclusive, Shared, or Invalid. Writing a byte invalidates every other core's copy of that 64-byte line (causing false sharing if unrelated hot variables sit in the same 64 bytes).

Store Buffers & Weak Ordering: Waiting for remote invalidations on every store would stall the core. So cores enqueue writes in a private Store Buffer and continue executing subsequent reads! On weakly ordered ARM64, another core can observe stores out of program order unless you emit a barrier (DMB ISH) or acquire/release instructions (LDAR / STLR).

2. Why futex Beats Pure Spinlocks & Pure Kernel Locks

Spinlocks: Great inside the kernel for nanosecond critical sections with preemption disabled, but disastrous in user space if the lock holder gets preempted—waiters burn 100% CPU spinning.

Linux futex(uaddr, op, val) (Fast User-Space Mutex): Keeps an atomic 32-bit integer in user memory with 3 states: 0 = unlocked, 1 = locked (uncontended), 2 = locked (contended / waiters sleeping). Uncontended 0 ↔ 1 uses a single atomic CAS in EL0 with zero syscalls; only state 2 traps into EL1 to sleep or wake via a kernel hash-bucket waitqueue.

Acquire / Release Contract: A memory_order_release store guarantees all prior writes by this thread become visible before the flag/lock is published. A memory_order_acquire load guarantees subsequent reads by the consumer occur after observing the flag—forming a cross-core happens-before edge without full seq_cst overhead.

02 // C11 ATOMICS, ARM64 LSE/LL-SC & FUTEX

Acquire/Release Publication, ARM64 CAS & 3-State Futex Mutex

C11 <stdatomic.h> — Lock-Free Producer/Consumer 
#include <stdatomic.h>

struct Packet { int payload; };
struct Packet data;
_Atomic int ready = 0;

void producer(int val) {
    data.payload = val; /* Non-atomic write */
    /* STLR on ARM64: all prior stores visible BEFORE ready=1 */
    atomic_store_explicit(&ready, 1, memory_order_release);
}

int consumer(int *out) {
    /* LDAR on ARM64: no later read can speculate BEFORE ready==1 */
    if (atomic_load_explicit(&ready, memory_order_acquire) == 1) {
        *out = data.payload; /* Guaranteed to see val! */
        return 1;
    }
    return 0;
}
ARM64 Assembly — LL/SC (LDXR/STXR) vs ARMv8.1 LSE (CASAL) 
/* Classic ARMv8.0 LL/SC loop: prone to livelock under high contention */
retry:
    ldaxr   w2, [x0]         // Load-Acquire Exclusive *uaddr
    cmp     w2, w1           // Compare with expected
    b.ne    fail
    stlxr   w3, w4, [x0]     // Store-Release Exclusive newval
    cbnz    w3, retry        // Retry if exclusive monitor cleared!

/* ARMv8.1 LSE (Large System Extensions) single-instruction atomic:
 * Scales dramatically better on 8+ core mobile & 64+ core servers */
    mov     w2, w1
    casal   w2, w4, [x0]     // Atomic CAS with Acquire-Release semantics
Linux User-Space C — 3-State Futex Mutex (Ulrich Drepper Pattern) 
#include <linux/futex.h>
#include <sys/syscall.h>
#include <stdatomic.h>
#include <unistd.h>

/* state: 0 = unlocked, 1 = locked (no waiters), 2 = locked (waiters exist) */
void futex_lock(_Atomic int *uaddr) {
    int expected = 0;
    if (atomic_compare_exchange_strong_explicit(
            uaddr, &expected, 1, memory_order_acquire, memory_order_relaxed)) {
        return; /* FAST PATH: 0 syscalls! */
    }
    do {
        /* If state==2 OR we successfully upgrade 1->2, sleep in kernel if still 2 */
        if (expected == 2 ||
            atomic_compare_exchange_strong_explicit(
                uaddr, &expected, 2, memory_order_relaxed, memory_order_relaxed)) {
            syscall(SYS_futex, uaddr, FUTEX_WAIT_PRIVATE, 2, NULL, NULL, 0);
        }
        expected = 0;
    } while (!atomic_compare_exchange_strong_explicit(
                 uaddr, &expected, 2, memory_order_acquire, memory_order_relaxed));
}

void futex_unlock(_Atomic int *uaddr) {
    /* Only wake kernel waiters if prior state was 2 (contended) */
    if (atomic_exchange_explicit(uaddr, 0, memory_order_release) == 2) {
        syscall(SYS_futex, uaddr, FUTEX_WAKE_PRIVATE, 1, NULL, NULL, 0);
    }
}
Senior Insight — Why FUTEX_WAIT Checks Expected Value Atomically in Kernel: Without passing val = 2 to futex(FUTEX_WAIT, 2), Thread B could observe the lock held, get preempted, Thread A could unlock and call FUTEX_WAKE (waking nobody!), and then Thread B would enter FUTEX_WAIT and sleep forever ("lost wakeup"). The kernel checks *uaddr == 2 under its bucket spinlock and immediately returns -EAGAIN if Thread A already unlocked!
03 // ANDROID INTERNALS BRIDGE

ART synchronized Thin-Locks, pthread_mutex & False Sharing

1. ART synchronized Thin-Lock → Monitor → futex

Every Kotlin/Java object in ART begins with a 32-bit LockWord inside its object header:

Thin-Lock (Fast Path): On uncontended synchronized(obj), ART uses an atomic CAS to write the current thread's thin-lock ID and recursion count directly into the LockWord—no heap allocation and no syscall.

Fat Monitor (Contended Path): If a second thread contends (or calls Object.wait()), ART inflates the LockWord into a Monitor structure backed by a Linux futex waitqueue. Similarly, Android bionic's pthread_mutex uses CAS + optional adaptive spinning before falling back to FUTEX_WAIT_PRIVATE.

2. False Sharing in Native C++ Audio & Render Threads

In real-time Android native pipelines (AAudio / Oboe audio callbacks on Core 6 Big, UI/RenderThread on Core 7 Big, or metrics counters on LITTLE cores), placing two per-thread std::atomic<uint64_t> counters adjacent in a struct puts them inside the same 64-byte cache line.

Even though the threads touch disjoint variables, every atomic increment steals exclusive ownership (M state) and invalidates the peer core's L1 cache (I state)—degrading throughput by 5–15x! Fix it with alignas(64) (or std::hardware_destructive_interference_size) between independently written hot fields.

LAB 1 OF 3 // FAIR SPINLOCK

Implement ticketSpinlockStep(lock, ops)

Build a strict FIFO ticket spinlock (nextTicket, nowServing) that prevents thread starvation.

Not Run
Specification: Given initial lock = { nextTicket: 0, nowServing: 0 } (do not mutate caller's input; clone it or track locally) and ops = [{ threadId, action: "tryAcquire" | "unlock" }]:
• Maintain owner = null, waiting = {} (map of threadId -> ticket), and acquiredOrder = [].
• On "tryAcquire": if owner === threadId, ignore. Otherwise, if waiting[threadId] === undefined, assign waiting[threadId] = nextTicket++. Next, if owner === null && waiting[threadId] === nowServing, grant lock: owner = threadId, delete waiting[threadId], push threadId to acquiredOrder.
• On "unlock": ONLY if owner === threadId, release owner = null and increment nowServing += 1.
• Return { nextTicket, nowServing, owner, acquiredOrder, waiting }.

Implement futexMutexSim(ops)

Simulate the 3-state futex mutex (0=unlocked, 1=locked, 2=contended) and count FUTEX_WAIT / FUTEX_WAKE traps.

Not Run
Specification: Given ops = [{ threadId, action: "lock" | "unlock" }]:
• Start with state = 0, owner = null, waitQueue = [], syscalls = { wait: 0, wake: 0 }, acquiredOrder = [].
• On "lock": if state === 0, fast-path CAS sets state = 1, owner = threadId, pushes threadId to acquiredOrder (0 syscalls!). Otherwise, set state = 2, increment syscalls.wait += 1, and push threadId to waitQueue.
• On "unlock" (only if owner === threadId): clear owner = null. If state === 1, set state = 0 (0 syscalls!). If state === 2, set state = 0, increment syscalls.wake += 1; if waitQueue.length > 0, shift the next waiter w, grant lock to w (owner = w, push w to acquiredOrder, and set state = waitQueue.length > 0 ? 2 : 1!).
• Return { state, owner, waitQueue, syscalls, acquiredOrder }.
LAB 3 OF 3 // CACHE LINE COHERENCE

Implement analyzeFalseSharing(fields, cacheLineSize)

Detect cross-core cache-line sharing in struct layouts and compute a padded layout eliminating false sharing.

Not Run
Specification: Given fields = [{ name, size, align?, writerCore }] and cacheLineSize = 64:
• Helper roundUp(n, a) = Math.ceil(n / a) * a. Default align = field.align ?? Math.min(field.size, 8) (min 1).
• Natural Layout: Place fields sequentially: offset = roundUp(cursor, align), startLine = Math.floor(offset / cacheLineSize), endLine = Math.floor((offset + size - 1) / cacheLineSize), cursor = offset + size. Any cache line touched by ≥ 2 distinct writerCores belongs in sorted sharedLines.
• Padded Layout: Place fields sequentially; before placing a field, check the cache line curLine = Math.floor(pCursor / cacheLineSize). If any already-placed field on curLine has a different writerCore, bump pCursor = (curLine + 1) * cacheLineSize first, then align to align and place.
• Return { naturalSize, layout, sharedLines, hasFalseSharing: sharedLines.length > 0, paddedLayout, paddedSize }.
