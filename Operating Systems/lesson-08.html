Lesson 08: Physical Allocators, SLUB, Scudo & ARMv9 Memory Tagging

01 // MENTAL MODEL & INTERACTIVE SIMULATOR

From Physical Page Frames to Hardened Object Heaps

1. The Binary Buddy Allocator (Page-Frame Granularity)

Problem: Physical RAM is managed in 4KB/16KB frames. DMA engines and hugepages need physically contiguous multi-page blocks, while naive free lists suffer severe external fragmentation.

Power-of-2 Splitting: Blocks are grouped by order k of size 2^k pages (e.g. Order 0 = 1 page, Order 3 = 8 pages). To satisfy Order k, if free[k] is empty, split a block from Order k+1 into two buddies.

O(1) XOR Coalescing: Every block at frame index addr of order k has a unique buddy at addr ^ (1 << k). When freed, if its buddy is also free at order k, they merge recursively up to MAX_ORDER.

2. SLUB (Kernel) & Scudo (Hardened User Heap)

Why Buddy Isn't Enough: Allocating a whole 4KB page for a 128-byte kernel object wastes 97% of RAM (internal fragmentation).

Linux SLUB: Requests multi-page slabs from the buddy allocator and slices each slab into identically sized slots for hot types (inode, dentry, kmalloc-128). Free slots form an O(1) per-CPU lockless freelist stored inside the unallocated slots themselves.

Android Scudo: Replaces jemalloc with security-first design: size-classed primary regions + mmap secondary with guard pages, checksummed chunk headers, quarantine queues, and hardware MTE hooks.

ARMv9 MTE (Lock-and-Key Hardware Memory Safety):
ARM64 enables Top-Byte Ignore (TBI) so bits [59:56] of a 64-bit virtual pointer store a 4-bit pointer tag (16 values) without altering address translation. Every 16-byte aligned physical memory granule stores a matching 4-bit allocation tag in hidden tag RAM. On allocation, IRG picks a random tag and STG paints the granules. On free(), granules are re-tagged. Every load/store checks ptrTag == granuleTag in silicon—catching Use-After-Free and buffer overflows on the spot!

Linux Buddy Orders, SLUB Freelists, Scudo Headers & ARMv9 MTE

buddy_slub.c — Kernel Buddy Coalesce & SLUB Fast Path 
// Linux mm/page_alloc.c concept: XOR buddy lookup
static inline unsigned long find_buddy_pfn(unsigned long pfn, unsigned int order) {
  return pfn ^ (1UL << order);
}

// mm/slub.c: O(1) per-CPU lockless allocation fast path
struct kmem_cache_cpu {
  void **freelist;       // Next free object in active CPU slab
  unsigned long tid;     // Lockless preemption/IRQ guard counter
  struct slab *slab;     // Current slab page backing this CPU
};

void *slab_alloc_fast(struct kmem_cache *s, struct kmem_cache_cpu *c) {
  void *obj = c->freelist;
  if (likely(obj)) {
    // Hardened SLUB obfuscates next pointer: ptr ^ s->random ^ swab(ptr_addr)
    c->freelist = get_freepointer_safe(s, obj);
    return obj;
  }
  return __slab_alloc_slowpath(s, c); // Refill from node partial list or buddy
}
scudo_mte.c — Scudo Checksum Header & ARMv9 MTE Tagging 
// Android Scudo: 64-bit atomic header immediately before user payload
struct scudo_chunk_header {
  uint64_t class_id : 8;
  uint64_t state    : 2;  // AVAILABLE, ALLOCATED, QUARANTINED
  uint64_t size_or_unused : 38;
  uint64_t checksum : 16; // CRC/BSD checksum(cookie ^ ptr ^ header_fields)
};

// ARMv9 MTE inline primitives (compiled with -march=armv8.5-a+memtag)
static inline void *mte_tag_alloc(void *ptr, size_t aligned_sz) {
  void *tagged;
  __asm__ volatile("irg %0, %1" : "=r"(tagged) : "r"(ptr)); // Random 4b tag
  for (size_t off = 0; off < aligned_sz; off += 16) {
    __asm__ volatile("stg %0, [%0, %1]" :: "r"(tagged), "r"(off) : "memory");
  }
  return tagged;
}
Why Hardened SLUB & Scudo Both Authenticate Metadata:
In classic slab/heap allocators, a single 8-byte buffer overflow or UAF write could overwrite the embedded freelist next pointer—tricking the next malloc() / kmalloc() into returning an arbitrary kernel/GOT address (a classic exploitation primitive). Linux CONFIG_SLAB_FREELIST_HARDENED XOR-encrypts the freelist pointer with a per-cache random secret and the slot's own address, while Scudo verifies a 16-bit secret-salted checksum on every free() / realloc() and aborts immediately on header tampering.
03 // ANDROID INTERNALS BRIDGE

Scudo, HWASan, MTE & heapprofd in Production Android

Scudo vs jemalloc & Media/Codec Hardening

Android 11+ Native Allocator Switch: AOSP replaced jemalloc with LLVM's Scudo for system services and apps. While jemalloc optimizes multi-core throughput via aggressive thread caches, Scudo prioritizes exploit mitigation against vulnerabilities in C++ parsers (libstagefright, libskia, Binder parcels).

Primary + Secondary Split: Small/medium allocations come from randomized Primary size-class regions with no in-band chunk headers adjacent to guard zones; large allocations (>=64KB) use Secondary mmap regions flanked by unmapped PROT_NONE guard pages.

Quarantine: Recently freed chunks sit in a ring quarantine before reuse, breaking deterministic Use-After-Free heap feng-shui.

MTE vs HWASan & Live Heap Profiling (heapprofd)

HWASan (Software, 8-bit TBI tags): Compiles instrumentation around every load/store in C/C++, giving a 256-tag space (1/256 collision) at ~1.3x CPU and ~15% RAM overhead—ideal for dogfooding/CI.

ARMv9 MTE (Hardware, 4-bit tags): Supported on Pixel 8+ / modern ARMv9 SoCs. Runs in Sync mode (exact SIGSEGV / SEGV_MTESERR fault PC for critical binaries like Bluetooth/Media) or Async mode (low-overhead flag checked on syscall/kernel exit) or Asymmetric (sync reads, async writes).

heapprofd: Hooks bionic's Scudo dispatch table out-of-process via shared memory + stack unwinding, capturing native leaks into Perfetto without recompiling the app.

LAB 1 OF 3 // BINARY BUDDY ALLOCATOR

Implement createBuddyAllocator(totalPages)

Split larger power-of-2 blocks on demand and coalesce freed buddies recursively using XOR.

Not Run
Specification: Assume totalPages is a power of 2 (≥ 1). Let maxOrder = Math.log2(totalPages). Initially, order maxOrder has one free block at address 0. Return an object with:
• alloc(order): If order is not an integer in [0, maxOrder], return -1. Find the smallest k >= order with a free block. If none exists, return -1. Pop the lowest-address free block from order k. While k > order, decrement k, split into left addr and right buddy addr + (1 << k), add the right buddy to free list k, and continue splitting the left half. Record (addr, order) as allocated and return addr.
• free(addr, order): Validate order is an integer in [0, maxOrder], addr is a valid allocated block of that exact order. If invalid or double-free, return false. Remove from allocated set, then loop while curOrder < maxOrder: compute buddy = curAddr ^ (1 << curOrder). If buddy is free at curOrder, remove buddy from free list curOrder, set curAddr = Math.min(curAddr, buddy), and curOrder++; else break. Add curAddr to free list curOrder and return true.
• freeLists(): Return an array of length maxOrder + 1 where index o is a sorted ascending array of free start addresses at order o.
LAB 2 OF 3 // SLUB OBJECT CACHE

Implement createSlabCache(objSize, objsPerSlab)

Carve fixed-size objects from multi-slab freelists with O(1) alloc/free and zero internal fragmentation.

Not Run
Specification: Given positive integers objSize and objsPerSlab, let slabBytes = objSize * objsPerSlab. Return an object with:
• alloc(): Find the lowest-index existing slab with a free slot in its freelist; if all slabs are full (or none exist), grow by creating a new slab (slabId = slabs.length) pre-populated with slots 0 .. objsPerSlab - 1. Pop a free slot index in O(1) (e.g. LIFO stack or pop) and return { slabId, offset, ptr } where offset = slot * objSize and ptr = slabId * slabBytes + offset.
• free(ptr): Validate ptr is an integer, maps to an existing slabId, is aligned (offset % objSize === 0), and that slot is currently allocated. If invalid or double-free, return false. Mark slot free, push slot back onto that slab's O(1) freelist, and return true.
• stats(): Return { totalSlabs, allocatedObjs, freeObjs, internalWasteBytes: 0 }.
LAB 3 OF 3 // ARMV9 MTE TAG VERIFIER

Implement mteAccessCheck(granules, taggedPtr, accessSize)

Enforce 4-bit pointer-to-granule tag matching across 16-byte granules to catch UAF and out-of-bounds bugs.

Not Run
Specification:
• granules: array of 4-bit integer tags (0..15), one per 16-byte granule.
• taggedPtr: { tag: number, addr: number }.
• accessSize: bytes accessed in [addr, addr + accessSize).
1. Validate Number.isInteger(accessSize) && accessSize > 0, Number.isInteger(taggedPtr.addr) && taggedPtr.addr >= 0, and Number.isInteger(taggedPtr.tag) && taggedPtr.tag >= 0 && taggedPtr.tag <= 15. Otherwise return { ok: false, fault: "INVALID_ACCESS", mismatchGranule: null }.
2. Compute startG = Math.floor(addr / 16) and endG = Math.floor((addr + accessSize - 1) / 16).
3. If endG >= granules.length, return { ok: false, fault: "OUT_OF_BOUNDS", mismatchGranule: granules.length }.
4. Loop g from startG to endG: if granules[g] !== taggedPtr.tag, immediately return { ok: false, fault: "TAG_MISMATCH", mismatchGranule: g, ptrTag: taggedPtr.tag, granuleTag: granules[g] }.
5. If all granules match, return { ok: true, fault: null, checkedGranules: endG - startG + 1 }.
