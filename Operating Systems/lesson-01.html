Lesson 01: Boot, CPU Privilege Rings, Traps & System Calls

Every time an Android app logs to disk, allocates memory from the OS, or sends a Binder message, the CPU crosses a hardware security wall from unprivileged User Mode (EL0 / Ring 3) into privileged Kernel Mode (EL1 / Ring 0). Mastering this boundary is the foundation of OS engineering.

01 // MENTAL MODEL & INTERACTIVE SIMULATOR

From Power-On to the User/Kernel Hardware Wall

1. The Boot Chain (Power-On → Your App)

Reset Vector → BootROM: On power-on, the CPU executes immutable silicon code in BootROM, verifies the next stage signature (Hardware Root of Trust / Verified Boot), and loads the Bootloader.

Bootloader (UEFI / U-Boot / Android ABL): Initializes DRAM, checks dm-verity / vbmeta signatures, loads the Linux kernel image + Device Tree (DTB) + initramfs into RAM, and jumps to the kernel entry point in privileged mode.

Kernel start_kernel() → PID 1: Sets up page tables, interrupt vectors, scheduler, and mounts rootfs. Then launches PID 1 (/init). On Android, init parses init.rc, starts servicemanager, lmkd, and zygote64, which forks your app into an unprivileged sandbox.

2. CPU Privilege Levels (ARM64 vs x86-64)

Hardware enforces isolation—not C compilers! Even if a malicious C pointer points to kernel memory, the CPU MMU + privilege level blocks it.

ARM64 (Android & Apple Silicon):
EL0: User applications (ART, bionic, your Kotlin/JNI code).
EL1: OS Kernel (Linux) — owns page tables, device drivers, scheduler.
EL2: Hypervisor (KVM / Android pKVM).
EL3: Secure Monitor (ARM TrustZone / Keystore TEE).

x86-64 (Servers & Laptops): Ring 3 (User) vs Ring 0 (Kernel), plus VMX root for hypervisors.

Interrupts vs Exceptions vs Traps (System Calls):
• Hardware Interrupt (Async): External event (timer tick, NVMe completion, touch digitizer IRQ). Interrupts whatever instruction was running.
• Exception / Fault (Sync): CPU hits an error executing an instruction (page fault, divide-by-zero, undefined opcode, unaligned access).
• Trap / Syscall (Intentional Sync): User space deliberately executes SVC #0 (ARM64) or SYSCALL (x86-64) to request a kernel service.

02 // C & KERNEL REALITY

Real Linux Syscall Mechanics, copy_from_user & vDSO

In C, functions like write() or getpid() are not magic—they are thin wrappers in libc (bionic on Android, glibc on Ubuntu) that load registers according to the kernel ABI and execute a trap instruction.

raw_syscall_arm64.c — Calling Linux without libc 
// Compile on ARM64 Linux: gcc -nostdlib -static raw_syscall_arm64.c
long sys_write(int fd, const void *buf, unsigned long count) {
  register long x0 __asm__("x0") = fd;
  register long x1 __asm__("x1") = (long)buf;
  register long x2 __asm__("x2") = count;
  register long x8 __asm__("x8") = 64; // __NR_write on ARM64
  __asm__ volatile(
    "svc #0\n"
    : "+r"(x0)
    : "r"(x1), "r"(x2), "r"(x8)
    : "memory"
  );
  return x0; // Negative values -1..-4095 encode -errno!
}
kernel_uaccess.c — Why the Kernel Never Dereferences User Pointers 
// Simplified Linux kernel syscall pattern (EL1)
long sys_write(unsigned int fd, const char __user *buf, size_t count) {
  char kbuf[256];
  if (count > sizeof(kbuf)) count = sizeof(kbuf);

  // NEVER do memcpy(kbuf, buf, count)!
  // 1) buf could point to kernel RAM (Arbitrary Kernel Read CVE!)
  // 2) buf could be unmapped (page fault inside EL1!)
  // 3) User addr + count could overflow 64-bit integer!
  if (copy_from_user(kbuf, buf, count) != 0) {
    return -EFAULT; // -14
  }
  return vfs_write_fd(fd, kbuf, count);
}
Why System.nanoTime() doesn't trap on every call — The vDSO Optimization:
A full EL0 → EL1 → EL0 trap costs ~100–300ns (and flushes/stresses branch predictors and Mitigations like Spectre/KPTI). High-frequency calls like clock_gettime() or getcpu() would crush database and UI-frame throughput if they trapped. So Linux maps a tiny read-only shared object called the vDSO (virtual Dynamic Shared Object) into every user process's address space, along with a kernel-updated data page (vvar) containing clock multipliers and the last tick. User code reads the hardware cycle counter directly in EL0 with a sequence lock (seqlock) check—zero syscalls!
03 // ANDROID INTERNALS BRIDGE

What Happens When Your Android App Calls FileOutputStream.write()

The Full Stack Crossing

1. Kotlin/Java (EL0): FileOutputStream.write(bytes) → calls ART JNI native method IoBridge.write().

2. Native bionic libc (EL0): Validates arguments, invokes write() wrapper, loads x8 = 64, executes SVC #0.

3. seccomp-bpf Filter (EL1): Before dispatching, Android's Zygote-inherited seccomp filter checks whether an untrusted app is even allowed to invoke syscall #64.

4. Kernel VFS → F2FS → UFS (EL1): Validates FD in task's files_struct, copies bytes via copy_from_user into kernel page cache, returns bytes written in x0.

Why a Senior Engineer Cares

1. 120Hz Frame Budget (8.33ms): Tight loops doing unbuffered 1-byte write() or stat() syscalls burn thousands of context/mode switches on the UI thread (StrictMode flags disk I/O for a reason!).

2. JNI & Syscall Batching: Crossing Java→JNI has overhead, and crossing EL0→EL1 has 10x more. Buffering (BufferedOutputStream, io_uring, Binder batching) amortizes traps.

3. Security & SELinux + Seccomp: Even if native C++ code in an NDK .so uses inline assembly SVC #0 to bypass bionic, the EL1 kernel still enforces seccomp-bpf and SELinux!

LAB 1 OF 3 // PRIVILEGE & DISPATCH

Implement the Kernel Syscall Trap Handler (handleSyscallTrap)

Simulate the CPU + Kernel entry/exit path when user space runs SVC #0.

Not Run
Specification: Given cpu ({ mode, pc, sp, user_sp, kernel_sp, elr, spsr, seccompMask }), regs ({ x0, x1, x2, x8 }), and syscallTable (array of functions (x0, x1, x2) => number):
1. Save cpu.elr = cpu.pc and cpu.spsr = cpu.mode.
2. Escalate to kernel mode: cpu.mode = "EL1" and switch stack cpu.sp = cpu.kernel_sp.
3. Check seccomp: if cpu.seccompMask is a Set and !cpu.seccompMask.has(regs.x8), set regs.x0 = -1 (-EPERM) and do not invoke the handler.
4. Else validate regs.x8 is an integer within [0, syscallTable.length - 1] with a function entry. If invalid, set regs.x0 = -38 (-ENOSYS).
5. Else call syscallTable[regs.x8](regs.x0, regs.x1, regs.x2) and store the result in regs.x0.
6. Perform ERET: restore cpu.mode = cpu.spsr, cpu.sp = cpu.user_sp, and advance cpu.pc = cpu.elr + 4. Return regs.x0.

Implement Overflow-Safe copyFromUser(mmu, userAddr, len)

Defend the kernel against arbitrary kernel reads, integer wraparound CVEs, and unmapped page faults.

Not Run
Specification: USER_SPACE_LIMIT = 0x8000 (user addresses are 0x0000..0x7FFF; kernel space starts at 0x8000).
mmu.readByte(addr) returns { ok: true, byte: number } or { ok: false }.
• Validate userAddr and len are non-negative safe integers. If not, return { ok: false, errno: -14 }.
• If len === 0 and userAddr < USER_SPACE_LIMIT, return { ok: true, data: [] }.
• Check bounds without integer overflow: if userAddr >= USER_SPACE_LIMIT or len > USER_SPACE_LIMIT - userAddr, return { ok: false, errno: -14 } (-EFAULT).

• Otherwise return { ok: true, data: bytes }.

Optimize Syscall Latency (executeWorkload)

Eliminate unnecessary EL0→EL1 traps using vDSO reads and bounded syscall batching while preserving exact ordering.

Not Run
Specification: Given ops (array of { type: "gettime" } or { type: "write", payload: string }), hw API, and batchLimit (integer ≥ 1):
• hw.vdsoReadTime(): Reads clock in EL0 (8 cycles, 0 traps). Returns timestamp.
• hw.rawSyscallWrite(payload): Single write trap (120 cycles, 1 trap).
• hw.batchSyscallWrite(payloadsArray): Batches up to batchLimit writes in 1 trap (120 + 15*k cycles, 1 trap).
