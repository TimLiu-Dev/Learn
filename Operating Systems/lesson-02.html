Lesson 02: Processes, Threads & Kernel Execution Contexts

Linux has no separate kernel object for a "thread"—both processes and threads are represented by struct task_struct created via clone(). Understanding what resources are shared versus copied, how Copy-on-Write (CoW) makes Android Zygote app launches instantaneous, and how cpu_switch_to swaps execution contexts on ARM64 is core OS engineering.

01 // MENTAL MODEL & INTERACTIVE SIMULATOR

One Kernel Abstraction (task_struct), Many Sharing Modes

1. Processes vs. Threads in Linux (PID vs. TGID)

What user space calls a "Process" is a Thread Group in the kernel: one or more task_structs that share the same tgid (Thread Group ID, returned by getpid()), the same virtual address space (mm_struct), and the same open file descriptor table (files_struct).

What user space calls a "Thread" is a task_struct created with CLONE_VM | CLONE_FILES | CLONE_THREAD | CLONE_SIGHAND. It receives a unique kernel pid (returned by gettid()), its own user stack, its own 8–16 KB kernel stack, and its own saved CPU register context, while inheriting its leader's tgid.

2. Context Switch Cost & ASID/TLB Behavior

Same-process thread switch: prev->mm == next->mm. The kernel saves/restores callee-saved registers and switches kernel stacks, but leaves TTBR0_EL1 (the user page-table root) untouched. Zero TLB invalidation!

Cross-process switch: prev->mm != next->mm. The kernel switches TTBR0_EL1 to the new process's page table. On ARM64, each mm_struct is tagged with a hardware ASID (Address Space ID, 8 or 16 bits), allowing old TLB entries to remain cached without flushing the entire TLB on every context switch.

Copy-on-Write (CoW) fork(): When a process calls fork(), the kernel does not duplicate megabytes of RAM. It copies only the page tables and marks writable private pages Read-Only + CoW in both parent and child, bumping each physical page's reference count. Only when either process actually writes to a shared page does the MMU raise a permission fault so the kernel allocates a private physical page copy.

02 // C, LINUX KERNEL & ARM64 ASSEMBLY

task_struct, clone() Flags, cpu_switch_to & Zombie Reaping

kernel/fork.c & include/linux/sched.h — Task Descriptors & clone() Flags 
struct task_struct {
    unsigned int            __state;       /* TASK_RUNNING, TASK_INTERRUPTIBLE, ... */
    void                    *stack;        /* 16KB per-task kernel stack (ARM64) */
    pid_t                   pid;           /* Thread ID (returned by gettid()) */
    pid_t                   tgid;          /* Thread Group ID (returned by getpid()) */
    struct mm_struct        *mm;           /* Virtual address space (NULL for kthreads) */
    struct files_struct     *files;        /* Open file descriptor table */
    struct signal_struct    *signal;       /* Shared signal handlers & limits */
    struct task_struct      *real_parent;  /* Parent for waitpid() & reparenting */
    int                     exit_state;    /* EXIT_ZOMBIE or EXIT_DEAD */
    int                     exit_code;     /* Preserved until parent calls waitpid() */
    struct thread_struct    thread;        /* Saved callee-saved CPU regs & FPU/NEON */
};

/* User-space fork() vs pthread_create() mapped to sys_clone() flags: */
// fork():           clone(SIGCHLD, 0)                      -> copies mm (CoW), files, new tgid
// pthread_create(): clone(CLONE_VM | CLONE_FS | CLONE_FILES
//                       | CLONE_SIGHAND | CLONE_THREAD
//                       | CLONE_SETTLS | CLONE_PARENT_SETTID, stack)
arch/arm64/kernel/entry.S — ARM64 Context Switch 
/* struct task_struct *cpu_switch_to(
 *     struct task_struct *prev,   // x0
 *     struct task_struct *next);  // x1
 * Caller-saved x0..x18 were already spilled by C ABI.
 * Only callee-saved x19..x29, LR(x30), SP are saved! */
SYM_FUNC_START(cpu_switch_to)
    mov     x10, #THREAD_CPU_CONTEXT
    add     x8, x0, x10          // x8 = &prev->thread.cpu_context
    mov     x9, sp
    stp     x19, x20, [x8], #16
    stp     x21, x22, [x8], #16
    stp     x23, x24, [x8], #16
    stp     x25, x26, [x8], #16
    stp     x27, x28, [x8], #16
    stp     x29, x9,  [x8], #16  // FP (x29) + prev kernel SP
    str     lr,  [x8]            // Return PC inside __switch_to()

    add     x8, x1, x10          // x8 = &next->thread.cpu_context
    ldp     x19, x20, [x8], #16
    ldp     x21, x22, [x8], #16
    ldp     x23, x24, [x8], #16
    ldp     x25, x26, [x8], #16
    ldp     x27, x28, [x8], #16
    ldp     x29, x9,  [x8], #16
    ldr     lr,  [x8]
    mov     sp, x9               // Switch to next kernel stack!
    msr     sp_el0, x1           // current = next (fast pointer)
    ret                          // Jumps to next's saved LR
SYM_FUNC_END(cpu_switch_to)
User-Space C — fork() + waitpid() Zombie Reaping 
#include <sys/wait.h>
#include <unistd.h>
#include <stdio.h>

int spawn_and_reap(void) {
    pid_t pid = fork();
    if (pid == 0) {
        /* Child runs in CoW copy of parent's mm_struct */
        _exit(42);
    }

    /* Between child _exit() and parent waitpid(), child is
     * EXIT_ZOMBIE: its mm & files are freed, but task_struct
     * stays in kernel RAM holding exit_code = 42! */
    int status = 0;
    pid_t reaped = waitpid(pid, &status, 0);
    if (reaped > 0 && WIFEXITED(status)) {
        printf("Reaped PID %d exit=%d\n", reaped, WEXITSTATUS(status));
    }
    return 0;
}
Senior Insight — Lazy FPU/NEON & Kernel Stack Size: Saving 32 128-bit NEON/SVE vector registers on every switch is expensive. Linux uses lazy/owner-tracked FPU state: if a task stays on the same CPU and hasn't used NEON since the kernel entered, reloading NEON registers is skipped until an actual NEON instruction traps. Also notice why kernel recursion is forbidden: each thread's kernel stack is fixed at 16 KB on ARM64 (THREAD_SIZE) with an unmapped guard page (VMAP_STACK) to catch overflows cleanly.
03 // ANDROID INTERNALS BRIDGE

Zygote CoW Forking, 1:1 ART Threads & lmkd Process Killing

1. Zygote Pre-warming & CoW fork()

At boot, zygote64 initializes the ART runtime, JIT/AOT caches, boot.art heap image, ICU tables, and ~10,000 core framework classes—then opens an abstract Unix socket.

When you tap an app icon, system_server sends a spawn request to Zygote. Zygote calls fork() (via Zygote.forkAndSpecialize()) without calling execve()! Every app process instantly inherits read-only shared physical pages of ART and framework bytecode via CoW, cutting cold-start memory by 30–50 MB per app and avoiding repeated class parsing.

Crucial rule: Zygote must remain single-threaded when it calls fork()! Forking a multi-threaded process leaves mutexes held by vanished threads in a permanently deadlocked state in the child.

2. ART Threads (1:1 Linux Tasks) & lmkd Signals

1:1 Threading: Every java.lang.Thread in ART calls bionic pthread_create(), which invokes clone(CLONE_VM | CLONE_THREAD | ...). Each Java thread consumes a real kernel task_struct (schedulable entity) plus ~1 MB of virtual address space for its user stack. That's why spawning 2,000 raw threads triggers OOM/pthread_create failures while Kotlin Coroutines multiplex thousands of lightweight continuations onto a small thread pool.

SIGTERM vs SIGKILL in lmkd: Android's Low Memory Killer Daemon (lmkd) monitors PSI (Pressure Stall Information). When RAM is critical, it uses pidfd_send_signal(pidfd, SIGKILL, ...)—never SIGTERM—because frozen/cached or buggy apps could catch, ignore, or stall inside SIGTERM handlers, whereas SIGKILL is uncatchable and lets the kernel tear down mm_struct immediately.

Implement cloneTask(parent, flags, nextPid)

Model Linux copy_process() flag semantics for fork() vs pthread_create().

Not Run
Specification: Flag bitmasks: CLONE_VM = 0x100, CLONE_FILES = 0x400, CLONE_THREAD = 0x10000.
• Validate parent exists and Number.isInteger(nextPid) && nextPid > 0.

Implement reapAndReparent(procs, exitingPid, waitTargetPid)

Handle EXIT_ZOMBIE transitions, orphan reparenting to PID 1, and waitpid() reaping.

Not Run
Specification: Given procs (array of { pid, ppid, state, exitCode }), exitingPid (number or null), and waitTargetPid (null = no wait, -1 = wait any zombie, or specific pid > 0):
• Do not mutate caller's input objects; clone each entry first.
• Step 1 (Exit & Reparent): if exitingPid != null and found (and exitingPid !== 1), set its state = "ZOMBIE" (default exitCode = 0 if unset). Any process with ppid === exitingPid (and pid !== exitingPid) is reparented to ppid = 1; record its pid in reparentedPids (sorted ascending).
• Step 2 (Reap): if waitTargetPid === -1, find the lowest-pid process with state === "ZOMBIE". If waitTargetPid > 0, find the process with pid === waitTargetPid and state === "ZOMBIE".
• If a zombie target is found, remove it from the list and set reapedPid = target.pid; otherwise reapedPid = null.
• Return { procs: updatedProcs, reapedPid, reparentedPids }.
LAB 3 OF 3 // CPU CONTEXT SWITCH

Implement contextSwitch(cpu, prevTask, nextTask)

Save/restore callee-saved registers, switch kernel stacks, and skip TLB/ASID flush on same-mm thread switches.

Not Run
Specification:
• If prevTask is non-null: save a copy of cpu.regs into prevTask.savedRegs and save cpu.spEl0 into prevTask.userSp.
• Load a copy of nextTask.savedRegs into cpu.regs, set cpu.spEl0 = nextTask.userSp, and set cpu.kernelSp = nextTask.kernelSp.
