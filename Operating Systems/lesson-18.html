Asynchronous Signal Trampolines & The execve() Memory Blueprint

1. How the Kernel Delivers a Signal on ARM64

Pending vs. Blocked Bitmasks: Every task tracks pending and blocked (sigprocmask) 64-bit masks. Before returning from EL1 → EL0, Linux checks pending & ~blocked. Note: SIGKILL (9) and SIGSTOP (19) can never be caught or blocked.

rt_sigframe & rt_sigreturn: To invoke a user handler, the kernel pushes the interrupted user registers (`pt_regs`) onto `SP_EL0` (or `sigaltstack` if `SA_ONSTACK` is set), sets `ELR_EL1 = handler_pc`, sets `x30` (LR) to the vDSO's `__kernel_rt_sigreturn` trampoline, and executes `ERET`. When the handler returns, `rt_sigreturn` traps back into EL1 to pop the original registers!

2. ELF64 execve(), ASLR, PLT/GOT & RELRO

Kernel Setup: execve() tears down the old mm_struct, maps the binary's PT_LOAD segments (and PT_INTERP, e.g. /system/bin/linker64) at randomized ASLR bases, maps [vvar]/[vdso], and pushes argc, argv, envp, and auxv (AT_PAGESZ, AT_RANDOM, AT_BASE, AT_SYSINFO_EHDR) onto the user stack.

PLT / GOT & RELRO: Position-Independent Executables (PIE) resolve external functions via the GOT (Global Offset Table) and PLT stubs. Under lazy binding, the GOT stays writable so attackers can overwrite function pointers; with BIND_NOW + Full RELRO (default on modern Android), the dynamic linker resolves all symbols at startup and marks the GOT read-only (mprotect PROT_READ) before main() runs.

Async-Signal Safety, pidfd & Inspecting ELF Dynamic Headers

Safe Signal Handler + PID-Reuse-Proof Killing (pidfd) 
static volatile sig_atomic_t g_stop = 0;

// ONLY async-signal-safe calls here (NEVER printf or malloc!)
static void on_sigterm(int sig) {
  (void)sig;
  g_stop = 1; // Or write(wake_pipe_fd, "x", 1) to wake epoll!
}

// Race-free process termination (used by Android lmkd)
int kill_safely(int pid) {
  int pfd = syscall(__NR_pidfd_open, pid, 0);
  if (pfd < 0) return -1;
  int rc = syscall(__NR_pidfd_send_signal, pfd, SIGKILL, NULL, 0);
  close(pfd);
  return rc;
}
Why Calling malloc() in a Signal Handler Deadlocks 
// Thread T1 is inside Scudo/glibc malloc():
malloc() {
  lock(&arena_mutex);       // <-- T1 holds arena_mutex
  // ... SIGSEGV / SIGUSR1 arrives RIGHT HERE!
  // Kernel hijacks T1's PC to run signal_handler()
  // If signal_handler() calls malloc() or printf():
  //   malloc() tries lock(&arena_mutex) -> SELF-DEADLOCK!
}
// Fix: Use sigaltstack() + write(2) / _exit() or self-pipe!

03 // ANDROID INTERNALS BRIDGE

Android debuggerd Tombstones & bionic Linker Namespaces

How Android Captures Native Tombstones (SIGSEGV / SIGABRT)

Every Android process installs a debuggerd signal handler on a dedicated sigaltstack (essential if the crash was a stack overflow—otherwise pushing rt_sigframe onto an exhausted stack triggers an instant double fault!). The handler avoids Scudo locks, talks to tombstoned over a socket to receive a crash dump FD, and freezes threads via ptrace/process_vm_readv.

bionic Linker Namespaces & 16KB ELF Alignment

When Android apps load native .so libraries via System.loadLibrary(), /system/bin/linker64 enforces linker namespaces so apps cannot `dlopen` private vendor/platform `.so`s. All `PT_LOAD` segments must also be 16KB-aligned (`0x4000`) with Full RELRO (`BIND_NOW`) so GOT entries become immutable before app code runs.
