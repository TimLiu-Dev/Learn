Lesson 13: Security, Capabilities, Namespaces, Seccomp & SELinux

Containers and Android app sandboxes are not magic VMs—they are compositions of Linux kernel primitives: Namespaces (what a process can see), cgroups v2 (what it can consume), Capabilities (fine-grained root splits), seccomp-bpf (syscall filtering), and SELinux MAC (mandatory access control) backed by dm-verity and fscrypt.

The 5-Layer Linux Defense-in-Depth Isolation Stack

1. Visibility, Resources & Privilege Splitting

Namespaces (unshare / setns): Virtualize global kernel resources per process group: pid (process becomes PID 1 inside its own tree), mnt (private filesystem mounts / pivot_root), net (own NIC/routing table), user (UID 0 inside container maps to unprivileged UID 100000 on host!), ipc, uts, cgroup.

cgroups v2 (Unified Hierarchy): Enforces hierarchical accounting for cpu.max, memory.max (hard OOM limit) / memory.high (throttling watermark), io.max, and pids.max. Every charge walks up the parent chain atomically.

Capabilities: Splits traditional all-powerful UID 0 into ~41 bits (e.g., CAP_NET_BIND_SERVICE, CAP_NET_ADMIN, CAP_SYS_ADMIN). Dropping unused capabilities ensures a compromised daemon can't load kernel modules or mount filesystems.

2. Syscall Filtering, MAC & Storage Cryptography

seccomp-bpf: Runs a classic BPF filter on struct seccomp_data { nr, arch, instruction_pointer, args[6] } at every syscall entry in EL1. Actions: SECCOMP_RET_ALLOW, SECCOMP_RET_ERRNO (clean error), or SECCOMP_RET_KILL_PROCESS.

SELinux Mandatory Access Control (MAC): Traditional UNIX DAC (chmod 0777) fails if an app makes a file world-readable or if a service is tricked. SELinux assigns every process a domain (e.g., untrusted_app) and every file/socket a type (e.g., app_data_file). Everything is denied by default unless explicitly allowed: allow domain type:class perm;, guarded by compile-time neverallow policy assertions!

dm-verity & fscrypt: dm-verity validates every 4KB block read from read-only partitions against a signed Merkle tree hash. fscrypt encrypts per-file data/filenames on /data with distinct hardware-backed keys.

Why Every Layer Matters Together (Defense in Depth):
If a malicious native library exploits a memory bug inside an Android app:
1. Namespaces + UID isolate its /proc, mounts, and files from other apps.
2. cgroups v2 stops fork/memory bombs (pids.max, memory.max).
3. Zero Capabilities prevents raw sockets, mounts, or ptrace.
4. seccomp-bpf shrinks the kernel syscall attack surface (blocking obscure CVEs in keyctl, userfaultfd, io_uring).
5. SELinux MAC blocks access even if a file was accidentally left chmod 0777!

02 // C & KERNEL REALITY

Namespaces, cgroups v2, seccomp-bpf & SELinux Type Enforcement

sandbox_ns_cgroup.c — unshare(), cgroups v2 & Cap Drop 
// Minimal container/sandbox setup in C (Linux)
// 1. Create isolated user, mount, and PID namespaces without root!
unshare(CLONE_NEWUSER | CLONE_NEWNS | CLONE_NEWPID);

// 2. Enforce cgroup v2 hard limit (128 MiB) & enroll current PID
//    Write "134217728" -> /sys/fs/cgroup/sandbox/memory.max
//    Write PID         -> /sys/fs/cgroup/sandbox/cgroup.procs

// 3. Prevent gaining privileges via setuid binaries before seccomp!
prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0);

// 4. Drop bounding capabilities (e.g., CAP_SYS_ADMIN, CAP_NET_ADMIN)
prctl(PR_CAPBSET_DROP, CAP_SYS_ADMIN, 0, 0, 0);
prctl(PR_CAPBSET_DROP, CAP_NET_ADMIN, 0, 0, 0);
seccomp_selinux.c — BPF Arch Check + SELinux .te Policy 
// seccomp-bpf filter: MUST validate seccomp_data.arch first!
struct sock_filter filter[] = {
  // Load arch (offsetof(struct seccomp_data, arch))
  BPF_STMT(BPF_LD | BPF_W | BPF_ABS, offsetof(struct seccomp_data, arch)),
  BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, AUDIT_ARCH_AARCH64, 1, 0),
  BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_KILL_PROCESS), // Kill wrong ABI!

  // Load syscall number (nr)
  BPF_STMT(BPF_LD | BPF_W | BPF_ABS, offsetof(struct seccomp_data, nr)),
  BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_ptrace, 0, 1),
  BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_ERRNO | (EPERM & 0x0000ffff)),
  BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_ALLOW),
};

// SELinux Type Enforcement (.te) rule + neverallow invariant:
// allow untrusted_app app_data_file:file { read write getattr };
// neverallow untrusted_app init_exec:file execute_no_trans;
Two Classic Kernel Security Pitfalls:
1. Missing AUDIT_ARCH Check in seccomp-bpf: On 64-bit ARM64 or x86-64 kernels supporting 32-bit compat syscalls, syscall numbers differ! Without checking seccomp_data.arch == AUDIT_ARCH_AARCH64 first, an attacker could switch to 32-bit compat mode where __NR_execve has a harmless 64-bit syscall number and bypass your filter.
2. Why PR_SET_NO_NEW_PRIVS is Mandatory: Unprivileged processes can install seccomp-bpf only after setting NO_NEW_PRIVS, otherwise they could block a syscall like setuid/close or trick a setuid-root child binary into misbehaving under a hostile filter!
03 // ANDROID INTERNALS BRIDGE

The Android App Sandbox, Verified Boot (dm-verity) & fscrypt

1. How Android Sandboxes Every App

Unique Linux UID per App: Unlike desktop Linux where all apps run under your user UID, Android assigns every installed app a distinct UID (e.g., u0_a142) so kernel DAC isolates app data directories immediately.

Zygote seccomp-bpf Inheritance: Every app forks from zygote64, which installs a strict seccomp-bpf allowlist blocking dangerous syscalls (ptrace, kexec_load, syslog, raw bpf, legacy socketcall) before app code ever runs.

SELinux Domains + Mount Namespaces: Apps run in untrusted_app (or isolated_app for WebView/Chrome renderers, which can't even open network sockets or files directly—only Binder/memfd!). Per-app mount namespaces give each app a private view of /storage/emulated/0.

2. dm-verity Verified Boot & fscrypt (DE vs CE)

dm-verity: Mounts /system and /vendor through a kernel device-mapper target that verifies every 4KB block on-read against a cryptographic Merkle tree whose root hash is signed in vbmeta (verified by the bootloader from hardware Root of Trust). Any tampered block returns -EIO.

fscrypt File-Based Encryption (FBE): Encrypts file contents and filenames in /data using inline AES-XTS crypto hardware, split into two key classes:
• Device Encrypted (DE): Unlocked at boot before PIN entry (needed for alarms, incoming calls, accessibility).
• Credential Encrypted (CE): Locked until the user enters PIN/biometric, derived inside TrustZone/TEE KeyMint!

LAB 1 OF 3 // SECCOMP-BPF ENGINE

Implement evalSeccompBpf(rules, ctx)

Evaluate ordered BPF syscall filter rules on { nr, arch, arg0 } with fail-closed default KILL.

Not Run
Specification: ctx is { nr: number, arch: string, arg0?: number }. rules is an ordered array of rule objects:
• Optional match fields on a rule (if present, ALL present fields must match ctx):
- rule.arch !== undefined → ctx.arch === rule.arch
- rule.nr !== undefined → ctx.nr === rule.nr
- rule.arg0 !== undefined → ctx.arg0 === rule.arg0
- rule.arg0Mask !== undefined → ((ctx.arg0 || 0) & rule.arg0Mask) === rule.arg0Value
• Return the FIRST matching rule's action:
- If rule.action === "ERRNO": return { action: "ERRNO", errno: rule.errno !== undefined ? rule.errno : 1 }.
- Else: return { action: rule.action } ("ALLOW"` or `"KILL"`).
• If no rule matches (fail-closed default): return { action: "KILL" }.
LAB 2 OF 3 // SELINUX TYPE ENFORCEMENT

Implement checkSelinuxPolicy(allowRules, neverallowRules, req)

Enforce default-deny SELinux MAC with explicit (srcType, dstType, objClass, perm) matching and neverallow precedence.

Not Run
Specification: req is { srcType, dstType, objClass, perm }. Each rule in allowRules and neverallowRules is { srcType, dstType, objClass, perms: string[] }.
• A rule matches req iff (r.srcType === "*" || r.srcType === req.srcType) AND (r.dstType === "*" || r.dstType === req.dstType) AND (r.objClass === "*" || r.objClass === req.objClass) AND (r.perms.includes("*") || r.perms.includes(req.perm)).
• Step 1: If ANY rule in neverallowRules matches req, return { allowed: false, reason: "NEVERALLOW_VIOLATION" } (even if an allow rule exists!).
• Step 2: Else if ANY rule in allowRules matches req, return { allowed: true, reason: "ALLOWED" }.
• Step 3: Default-deny! Return { allowed: false, reason: "AVC_DENIED" }.
LAB 3 OF 3 // CGROUPS V2 HIERARCHY

Implement cgroupChargeMemory(node, bytes)

Walk the cgroups v2 parent chain to charge memory atomically, rolling back partial charges if any ancestor exceeds memory.max.

Not Run
Specification: node is { name: string, current: number, max: number | null, parent: node | null } (max === null means unlimited).
• Validate Number.isInteger(bytes) && bytes >= 0 (else return { ok: false, failedAt: node.name, reason: "EINVAL" }).
• Walk from node upward through .parent until null.
• At each node cur: if cur.max !== null && cur.max !== undefined && cur.current + bytes > cur.max, roll back bytes on all previously charged descendant nodes so NO node's current changes, and return { ok: false, failedAt: cur.name }.
• Otherwise add bytes to cur.current and push cur.name to chargedChain.
• If the entire chain up to root succeeds, return { ok: true, chargedChain }.
