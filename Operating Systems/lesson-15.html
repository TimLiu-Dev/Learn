01 // MENTAL MODEL & INTERACTIVE SIMULATOR

Tracing Overhead, the eBPF Static Verifier & Flamegraph Folding

1. Tracing Spectrum: ptrace vs Tracepoints vs eBPF

strace (ptrace): Stops the target process on every syscall entry AND exit, waking the tracer process twice via signals/context switches. Adds ~10–50μs per syscall (10x–100x slowdown!).

ftrace / Static Tracepoints: Compiled NOP sites patched at runtime to jump to ring-buffer loggers (sched_switch, binder_transaction) with ~50–150ns overhead.

kprobes / uprobes: Breakpoint/fentry hooks on any kernel or userspace symbol without recompiling. Combined with eBPF, aggregation happens inside the kernel (maps/histograms) so zero per-event data crosses to userspace!

2. eBPF ISA, Register ABI & Static Verifier Proofs

The eBPF virtual machine has eleven 64-bit registers (R0–R10) and a bounded 512-byte stack:

Registers: R1 holds the context pointer on entry; R1–R5 pass arguments to kernel helpers (and are clobbered on return!); R0 holds helper/program return values; R6–R9 are callee-saved; R10 is the read-only stack frame pointer.

The Verifier: Before JIT compilation, the kernel runs abstract interpretation over the CFG DAG: proving (1) termination (no unbounded backward loops), (2) all read registers/stack slots are initialized, (3) pointers & NULL-nullable map lookups are bounds-checked, and (4) R0 is initialized at EXIT.

02 // C, LIBBPF CO-RE, PERF & FLAMEGRAPHS

Production Kernel Tracing with CO-RE eBPF & perf_event_open

sched_delay.bpf.c — libbpf CO-RE Runqueue Latency Probe 
#include "vmlinux.h"
#include <bpf/bpf_helpers.h>
#include <bpf/bpf_core_read.h>

struct {
  __uint(type, BPF_MAP_TYPE_HASH);
  __uint(max_entries, 16384);
  __type(key, u32);    // pid
  __type(value, u64);  // wakeup timestamp (ns)
} wakeup_ts SEC(".maps");

SEC("tp_btf/sched_wakeup")
int BPF_PROG(on_wakeup, struct task_struct *p) {
  u32 pid = BPF_CORE_READ(p, pid);
  u64 ts = bpf_ktime_get_ns();
  bpf_map_update_elem(&wakeup_ts, &pid, &ts, BPF_ANY);
  return 0;
}

SEC("tp_btf/sched_switch")
int BPF_PROG(on_switch, bool preempt, struct task_struct *prev,
             struct task_struct *next) {
  u32 pid = BPF_CORE_READ(next, pid);
  u64 *tsp = bpf_map_lookup_elem(&wakeup_ts, &pid);
  if (!tsp) return 0; // Mandatory NULL check required by eBPF verifier!

  u64 delay_ns = bpf_ktime_get_ns() - *tsp;
  bpf_map_delete_elem(&wakeup_ts, &pid);
  if (delay_ns > 5000000ULL) { // > 5ms scheduling delay -> emit ringbuf event
    bpf_printk("runqueue stall pid=%u delay_ns=%llu", pid, delay_ns);
  }
  return 0;
}
perf_sampling.c — perf_event_open() PMU Hardware Sampling 
// Userspace profiler opening hardware CPU cycle sampling on a PID
#include <linux/perf_event.h>
#include <sys/syscall.h>

int open_cpu_sampler(pid_t pid, int cpu, uint64_t sample_freq_hz) {
  struct perf_event_attr attr = {
    .type = PERF_TYPE_HARDWARE,
    .size = sizeof(attr),
    .config = PERF_COUNT_HW_CPU_CYCLES,
    .sample_freq = sample_freq_hz, // e.g., 99 Hz (avoids lockstep aliasing!)
    .freq = 1,
    .sample_type = PERF_SAMPLE_IP | PERF_SAMPLE_TID | PERF_SAMPLE_CALLCHAIN,
    .exclude_hv = 1,
  };
  // Kernel writes IP + stack unwind into an mmap'd ring buffer;
  // only ~99 interrupts/sec -> < 0.5% production CPU overhead!
  return syscall(__NR_perf_event_open, &attr, pid, cpu, -1, PERF_FLAG_FD_CLOEXEC);
}
CPU Flamegraphs vs Off-CPU Flamegraphs (Don't Miss Blocked Threads!):
A CPU flamegraph (perf / simpleperf sampling at 99 Hz) only samples threads currently running on a CPU core. If an Android UI thread freezes for 400ms waiting on a futex, Binder reply, or fsync(), it is sleeping off-CPU—so it completely disappears from a CPU flamegraph! To diagnose ANRs and tail stalls, trace sched_switch off-CPU time (or use Perfetto thread-state tracks) to build an Off-CPU flamegraph weighted by blocked nanoseconds.
03 // ANDROID INTERNALS BRIDGE

Android bpfloader, simpleperf & Perfetto System Tracing

Android bpfloader in Production

At Android boot, bpfloader verifies and loads precompiled eBPF ELF programs into /sys/fs/bpf with strict SELinux policies:

1. netd / TrafficStats eBPF: Hooks cgroup socket filters (sk_filter / cgroup_skb) to count per-UID/per-app foreground & background bytes with zero iptables traversal overhead.

2. time_in_state & Power HAL: Attaches to sched_switch and cpu_frequency tracepoints to attribute per-UID CPU energy across big.LITTLE clusters in real time.

3. GPU / DMA-BUF / LMKD Hooks: Tracks per-process GPU memory and PSI/reclaim triggers without polling /proc files every millisecond.

Perfetto: The Staff Android Engineer's Microscope

How Perfetto Works: Daemon traced collects protobuf trace streams from traced_probes (kernel ftrace ring buffer: sched_switch, sched_waking, binder_transaction, mm_vmscan) + user-space atrace/SDK slices (Choreographer#doFrame) + heapprofd (DWARF/frame-pointer native heap sampling).

Diagnosing Jank & ANRs: When a 120Hz frame misses its 8.33ms budget, Perfetto connects the UI thread's sleeping gap directly via sched_waking to the Binder server thread or lock holder that stalled it—proving root cause in seconds.

LAB 1 OF 3 // eBPF STATIC VERIFIER

Implement verifyEbpfProgram(insns)

Simulate DAG reachability, register initialization, helper clobbering, and EXIT safety proofs.

Not Run
Specification: Entry at pc = 0 starts with initialized registers Set(["R1", "R10"]).
• Empty program or falling past insns.length without EXIT → { ok: false, reason: "FALLTHROUGH_NO_EXIT", pc }.
• { op: "MOV", dst, src }: If dst === "R10" → "R10_READONLY". If src is a string (register) not in init → "UNINITIALIZED_REG". Marks dst initialized.
• { op: "ALU", dst, src }: If dst === "R10" → "R10_READONLY". Both dst and string src must be in init else "UNINITIALIZED_REG".
• { op: "CALL", argCount }: Registers R1..R<argCount> must be in init (else "UNINITIALIZED_REG"). Clobbers R1..R5 (removes them from init) and marks R0 initialized (preserving R6..R10).
• { op: "JMP", target }: Must be valid index < insns.length (else "OUT_OF_BOUNDS_JUMP") and strictly forward target > pc (else "BACKWARD_JUMP").
• { op: "JCOND", reg, target }: reg must be in init; validate target like JMP; explore both fallthrough (pc + 1) and branch (target)!
• { op: "EXIT" }: "R0" must be in init (else "R0_UNINITIALIZED").
• If all reachable paths exit cleanly, return { ok: true, checkedStates }.
LAB 2 OF 3 // FLAMEGRAPH STACK FOLDING

Implement foldFlamegraph(samples)

Aggregate raw call-stack samples into inclusive & self counts sorted by hottest execution paths.

Not Run
Specification: Given samples (array of { stack: string[], count: number }):
• Skip entries with empty stack or count <= 0.
• For each sample, walk prefixes i = 0 .. stack.length - 1 with key path = stack.slice(0, i + 1).join(";"):
  - Add sample.count to inclusive for every prefix.
  - Add sample.count to self only when i === stack.length - 1 (the leaf frame on CPU).
• Return an array of { path, name, depth, inclusive, self } (where name = stack[i], depth = i) sorted by: inclusive descending, then self descending, then path ascending (ASCII a.path < b.path ? -1 : a.path > b.path ? 1 : 0).
LAB 3 OF 3 // TAIL LATENCY PERCENTILES

Implement computeLatencyStats(latenciesUs)

Compute p50, p95, p99, max, and mean microseconds without mutating input arrays.

Not Run
Specification: Given latenciesUs (array of numbers in microseconds):
• If not an array or empty, return null.
• Sort a copy numerically ascending (do not mutate caller's array!).
• Use nearest-rank percentile: pct(p) = sorted[Math.ceil((p / 100) * n) - 1].
• Return { count: n, min: sorted[0], p50: pct(50), p95: pct(95), p99: pct(99), max: sorted[n - 1], mean } where mean is rounded to 2 decimal places (Math.round((sum / n) * 100) / 100).
