VFS Object Model, Crash Consistency & Flash-Aware Storage

1. The 4 VFS Objects & Hard Links vs Symlinks

Linux's Virtual File System (VFS) exposes one unified POSIX API (openat, read, statx) across Ext4, F2FS, procfs, and FUSE using four core kernel structures:

super_block: One per mounted filesystem instance (block size, mount flags, root dentry, dirty inode list).

inode: The true file identity (i_ino, permissions, size, extent/block pointers, and i_nlink). Filenames do not live inside the inode!

dentry: Maps a directory + filename string to an inode. Cached in the dcache hash table for fast lockless RCU path walks.

file (Open File Description): Per-open() kernel state holding current offset f_pos, access mode, and refcount f_count (shared by dup()/fork()).

Hard link vs Symlink: A hard link adds another dentry pointing to the same inode (incrementing i_nlink; data is freed only when i_nlink == 0 AND all open file descriptors close). A symlink is a separate inode containing a target path string, resolved recursively up to MAXSYMLINKS (40) to stop cycles (-ELOOP).

2. Crash Consistency: Ext4 JBD2 vs F2FS

Modifying a file updates multiple blocks: data blocks, inode size/timestamps, and allocation bitmaps. If power dies mid-update, metadata can point to uninitialized garbage blocks or leak space.

Ext4 Journaling (JBD2): Writes changes into a circular write-ahead journal before updating home locations. In default data=ordered mode, data blocks are flushed first, then metadata + commit record are written to the journal—preventing stale garbage inside extended files without double-writing all data.

Why Flash Hates Ext4 In-Place Updates: NAND flash cannot overwrite a 4KB page in place; the FTL must copy valid pages from a multi-MB erase block, erase the block, and rewrite—causing high Write Amplification (WAF).

F2FS (Flash-Friendly File System): Uses a Log-Structured design! Updates are appended sequentially into 2MB segments grouped into hot/warm/cold logs (mapped via the Node Address Table, NAT). Periodically, F2FS Garbage Collection (GC) migrates remaining live blocks from fragmented segments and reclaims empty segments.

Durability Contract — fsync() vs fdatasync() vs Write Barriers:
• write() only copies bytes into the kernel Page Cache in RAM.
• fdatasync(fd) flushes dirty data blocks + minimal metadata needed to retrieve them (e.g., file size), skipping mtime.
• fsync(fd) flushes all dirty data + inode metadata AND sends storage write barriers (REQ_PREFLUSH | REQ_FUA) so the UFS/NVMe controller drains its volatile DRAM cache to NAND.
• The Classic Bug: Calling fsync(fd) on a newly created file does not persist its directory entry! You must also call fsync(parent_dir_fd).

VFS Kernel Structures, Ext4 Extents & Crash-Safe Atomic Rename

vfs_inode_file.c — Why dup() shares f_pos but open() does not 
// Conceptual Linux kernel VFS relationship (fs/file_table.c, include/linux/fs.h)
struct inode {
  unsigned long       i_ino;      // Unique inode number within super_block
  umode_t             i_mode;     // File type (S_IFREG/S_IFDIR/S_IFLNK) + perms
  unsigned int        i_nlink;    // Hard-link reference count on disk
  loff_t              i_size;     // File size in bytes
  struct address_space *i_mapping;// Page cache radix/xarray of cached 4KB pages
};

struct dentry {
  struct qstr         d_name;     // Filename component ("notes.db")
  struct inode       *d_inode;    // NULL for negative dentry (cached -ENOENT!)
  struct dentry      *d_parent;   // Parent directory dentry
};

struct file {
  struct path         f_path;     // (mnt, dentry) pair
  struct inode       *f_inode;    // Cached pointer to underlying inode
  loff_t              f_pos;      // Current read/write byte offset!
  atomic_long_t       f_count;    // Refcount: dup()/fork() increment f_count,
};                                // whereas two open() calls allocate two struct files!
atomic_save_fsync.c — Crash-Safe File Replacement in POSIX C 
// The ONLY crash-safe way to overwrite a config/DB file on Linux/Android
int atomic_write_file(const char *dir_path, const char *tmp_name,
                      const char *final_name, const void *buf, size_t len) {
  int dir_fd = open(dir_path, O_RDONLY | O_DIRECTORY | O_CLOEXEC);
  if (dir_fd < 0) return -1;

  int tmp_fd = openat(dir_fd, tmp_name, O_WRONLY | O_CREAT | O_TRUNC | O_CLOEXEC, 0600);
  if (tmp_fd < 0) { close(dir_fd); return -1; }

  // 1. Write payload into page cache, then force data + inode to NAND (with FUA barrier)
  if (write(tmp_fd, buf, len) != (ssize_t)len || fsync(tmp_fd) < 0) {
    close(tmp_fd); close(dir_fd); return -1;
  }
  close(tmp_fd);

  // 2. Atomically swing directory entry from old inode -> new inode
  if (renameat(dir_fd, tmp_name, dir_fd, final_name) < 0) {
    close(dir_fd); return -1;
  }
  // 3. CRITICAL: Persist the directory metadata itself! Without this, power loss
  //    can lose BOTH the new entry and leave the old file missing!
  int rc = fsync(dir_fd);
  close(dir_fd);
  return rc;
}
Ext4 Extents vs F2FS Segments in Practice:
Instead of legacy Ext2/Ext3 indirect block trees (which needed thousands of pointer blocks for a 4GB video), Ext4 stores contiguous runs as compact 12-byte extents (struct ext4_extent { ee_block, ee_len, ee_start_hi/lo }), mapping up to 128MB per leaf entry. Meanwhile, F2FS divides storage into 2MB segments and maintains a Segment Info Table (SIT) tracking valid-block bitmaps per segment so its Garbage Collector can pick cold, mostly-invalidated segments using a cost-benefit heuristic.
03 // ANDROID INTERNALS BRIDGE

Why Android Adopted F2FS, SQLite WAL & Scoped Storage FUSE Overhead

1. Why Android Switched /data from Ext4 to F2FS

Flash-Friendly Append Writes: Mobile workloads (SQLite journals, ART .odex/.vdex profiles, SharedPreferences, app caches) emit lots of small random 4KB writes. On Ext4, JBD2 journaling + random in-place updates amplify writes inside the UFS controller's FTL, degrading random read latency and wearing out NAND.

F2FS Atomic Writes for SQLite: F2FS originally added F2FS_IOC_START_ATOMIC_WRITE / COMMIT_ATOMIC_WRITE so SQLite could buffer pages in-memory/append segments and commit atomically without a separate rollback journal—cutting flash writes nearly in half.

Multi-Head Logging: F2FS separates hot (directory/small sync), warm (normal data), and cold (media/immutable) segments so cold data isn't repeatedly copied during GC.

2. SQLite WAL on Room & FUSE Scoped Storage Overhead

SQLite WAL Mode (Default in Android Room): Instead of modifying the main .db file in place, writers append frames + a commit frame to db-wal. Readers see a consistent snapshot using the db-shm WAL index. With PRAGMA synchronous=NORMAL, Room skips fsync() on individual WAL commits (survives app crashes, risks losing last uncommitted checkpoint on sudden battery pull) and fsync()s only during WAL checkpoints.

FUSE Scoped Storage Tax: External storage (/sdcard) runs through MediaProvider's user-space FUSE daemon for per-app privacy filtering. Every uncached read()/write() bounces App (EL0) → Kernel VFS (EL1) → /dev/fuse → MediaProvider (EL0) → Lower FS (EL1)! Android 12+ mitigates this via FUSE passthrough (FUSE_PASSTHROUGH) backed by an opened lower-FS file descriptor.

LAB 1 OF 3 // VFS PATH RESOLUTION

Implement resolveVfsPath(fs, startInodeId, path, maxSymlinks)

Walk /-separated paths, expand relative/absolute symlinks, and enforce -ENOENT, -ENOTDIR, and -ELOOP.

Not Run
Specification: fs is { rootId, inodes: { [id]: { id, type: "dir"|"file"|"symlink", entries?: { [name]: id }, target?: string } } }.
• Error codes: ENOENT = -2, ENOTDIR = -20, ELOOP = -40.
• If !path or non-string, return { ok: false, errno: -2 }.
• Start at curId = path.startsWith("/") ? fs.rootId : startInodeId. Split path on "/" into a queue (skipping "" and ".").
• While queue is non-empty, pop seg: look up cur = fs.inodes[curId]. If !cur return -2; if cur.type !== "dir" return { ok: false, errno: -20 }.
• Look up nextId = cur.entries?.[seg]. If nextId === undefined return { ok: false, errno: -2 }. Look up next = fs.inodes[nextId].
• If next.type === "symlink": increment symlink counter; if > maxSymlinks return { ok: false, errno: -40 }. If next.target.startsWith("/"), set curId = fs.rootId (else keep curId as parent dir), and prepend next.target's non-empty/non-"." segments to the queue.
• Else set curId = nextId. When queue finishes, return { ok: true, inodeId: curId }.
LAB 2 OF 3 // CRASH CONSISTENCY

Implement recoverWal(journalEntries, diskBlocks)

Replay ONLY committed transactions in commit order while discarding uncommitted, aborted, and torn writes.

Not Run
Specification: journalEntries is an array of entries: { txId, type: "BEGIN" | "WRITE" | "COMMIT" | "ABORT" | "TORN", blockId?, data?, checksumOk? }. diskBlocks is { [blockId]: string }.
• Do not mutate diskBlocks in place; clone it into blocks.
• A transaction txId is valid & committed iff: it saw BEGIN, never saw ABORT, never had type === "TORN" or checksumOk === false on any of its entries, and saw a COMMIT entry.
• Replay all WRITE entries of committed transactions in their COMMIT order (and write order within each tx), updating blocks[entry.blockId] = entry.data.
• Return { blocks, replayedTxIds, discardedTxIds } where replayedTxIds are committed IDs in commit order and discardedTxIds are non-committed seen IDs in first-seen order (unique).
LAB 3 OF 3 // F2FS COST-BENEFIT GC

Implement f2fsSelectGcSegment(segments)

Choose the victim flash segment minimizing F2FS cost-benefit (validRatio / (1 - validRatio)) / age and return migrated live blocks + reclaimed space.

Not Run
Specification: segments is an array of { id, capacity, liveBlocks: string[], age: number, isFree?: boolean }.
• Skip already-free segments (seg.isFree === true) and 100%-live segments (seg.liveBlocks.length >= seg.capacity, which yield 0 reclaimed space).
• Compute validRatio = seg.liveBlocks.length / seg.capacity.
• Cost-benefit score to minimize: if seg.liveBlocks.length === 0, score = 0 (free reclaim!). Else if seg.age <= 0, score = Infinity; else score = (validRatio / (1 - validRatio)) / seg.age.
• Break ties by smallest liveBlocks.length, then smallest id. If no eligible victim exists, return null.
• Otherwise return { victimId: best.id, score: bestScore, migratedBlocks: [...best.liveBlocks], reclaimedBlocks: best.capacity - best.liveBlocks.length }.
