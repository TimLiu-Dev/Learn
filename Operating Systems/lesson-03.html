Lesson 03: CPU Scheduling: EEVDF & Android Energy-Aware Scheduling

Starting in Linux 6.6, Linux replaced CFS with EEVDF (Earliest Eligible Virtual Deadline First), eliminating heuristic latency hacks by giving latency-sensitive tasks shorter virtual slices. On mobile ARM SoCs, EEVDF pairs with EAS (Energy-Aware Scheduling) and uclamp to balance 120Hz frame deadlines against battery life.

01 // MENTAL MODEL & INTERACTIVE SIMULATOR

From CFS vruntime to EEVDF Eligibility & Deadlines + EAS

1. Why CFS Needed EEVDF (Fairness vs. Latency)

CFS (2007–2023): Always picked the runnable task with the smallest vruntime (virtual runtime scaled inversely by weight/nice). Fair for throughput, but a task requesting tiny 1ms bursts waited behind 20ms batch tasks unless patched with fragile heuristics like sched_wakeup_granularity.

EEVDF (Linux 6.6+): Tracks two invariants per task: Eligibility (lag ≥ 0, meaning vruntime ≤ avg_vruntime so the task hasn't already consumed more than its fair share) and Virtual Deadline (vdeadline = vruntime + slice × 1024 / weight). Among eligible tasks, EEVDF picks the smallest vdeadline!

2. Heterogeneous Cores (big.LITTLE) & uclamp

The Energy Curve: A Big/Prime Cortex-X core delivers ~3x peak capacity of a LITTLE Cortex-A5xx core, but burns far more milliwatts per unit of work at high OPP voltages.

EAS + schedutil: Instead of blindly spreading threads across all cores, EAS simulates placing a waking task on each cluster's Energy Model and picks the lowest-energy core that still meets the task's required capacity: clamp(util_avg, uclamp_min, uclamp_max).

Scheduling Classes Hierarchy (Strict Priority Order):
Stop-machine > SCHED_DEADLINE (EDF + CBS bandwidth reservation) > SCHED_FIFO / SCHED_RR (Real-Time 1–99) > SCHED_NORMAL / SCHED_BATCH (EEVDF, nice -20..+19) > SCHED_IDLE. EEVDF only runs when no RT/DL task is runnable on that CPU!

02 // C, LINUX 6.6+ EEVDF & EAS KERNEL CODE

sched_entity, pick_eevdf(), SCHED_DEADLINE & uclamp

kernel/sched/fair.c — Linux 6.6+ EEVDF Eligibility & Deadline Selection 
struct sched_entity {
    struct load_weight  load;        /* Nice-mapped weight (nice 0 = 1024) */
    struct rb_node      run_node;    /* Augmented RB-tree ordered by vruntime */
    u64                 vruntime;    /* Virtual execution time accumulated */
    u64                 deadline;    /* vruntime + calc_delta_fair(slice, se) */
    u64                 min_vruntime;/* Subtree minimum vruntime/deadline */
    u64                 slice;       /* Requested latency slice (default ~3ms) */
    s64                 vlag;        /* Fair share lag: V_avg - vruntime */
};

/* A task is eligible if it has NOT received more CPU than its fair share: */
static inline bool entity_eligible(struct cfs_rq *cfs_rq, struct sched_entity *se)
{
    return (s64)(cfs_rq->avg_vruntime - se->vruntime) >= 0;
}

/* EEVDF selects the eligible entity with the EARLIEST virtual deadline:
 * vdeadline = vruntime + (slice * NICE_0_LOAD) / weight */
static struct sched_entity *pick_eevdf(struct cfs_rq *cfs_rq)
{
    struct sched_entity *se = __pick_first_entity(cfs_rq);
    struct sched_entity *best = NULL;

    /* Augmented RB-tree walks subtrees guaranteed to contain eligible nodes
     * and returns the eligible node with minimum se->deadline in O(log N). */
    return best;
}
User-Space C — SCHED_DEADLINE (EDF + CBS) & uclamp 
#include <linux/sched/types.h>
#include <sys/syscall.h>
#include <unistd.h>

/* Configure a thread with uclamp_min=600/1024 (58.6% min capacity)
 * so EAS places it on Big cores & schedutil boosts OPP immediately */
void boost_ui_thread_uclamp(pid_t tid, __u32 min_cap) {
    struct sched_attr attr = {
        .size = sizeof(attr),
        .sched_policy = SCHED_NORMAL,
        .sched_flags = SCHED_FLAG_UTIL_CLAMP_MIN,
        .sched_util_min = min_cap,   /* 0..1024 */
    };
    syscall(SYS_sched_setattr, tid, &attr, 0);
}

/* Audio DSP real-time reservation: 2ms every 5ms period */
void set_audio_deadline(pid_t tid) {
    struct sched_attr attr = {
        .size = sizeof(attr),
        .sched_policy = SCHED_DEADLINE,
        .sched_runtime  = 2000000ULL, /* 2 ms */
        .sched_deadline = 5000000ULL, /* 5 ms */
        .sched_period   = 5000000ULL, /* 5 ms */
    };
    syscall(SYS_sched_setattr, tid, &attr, 0);
}
kernel/sched/fair.c — EAS + uclamp Effective Utilization 
/* Effective utilization after clamping PELT util_avg */
unsigned long effective_cpu_util(int cpu, unsigned long util)
{
    unsigned long min_u = uclamp_eff_value(cpu, UCLAMP_MIN);
    unsigned long max_u = uclamp_eff_value(cpu, UCLAMP_MAX);
    return clamp(util, min_u, max_u);
}

/* EAS find_energy_efficient_cpu() simplified logic:
 * 1. Compute task's clamped utilization demand.
 * 2. For each performance domain (LITTLE / Mid / Big):
 *    - Find idle CPU with spare capacity >= demand
 *    - Estimate delta_energy = compute_energy(pd, cpu)
 * 3. Pick CPU yielding lowest system energy without
 *    overutilizing any domain (triggers schedutil OPP). */
Senior Insight — Why Nice Levels Don't Solve Latency Alone: Under CFS, raising priority (nice -10) gave a task more CPU share, yet a newly woken task with a tiny 0.5ms job could still wait behind a long-running task's slice. In EEVDF, even at nice 0, requesting a smaller virtual slice gives an earlier vdeadline, decoupling latency (slice) from throughput share (weight).
03 // ANDROID INTERNALS BRIDGE

120Hz uclamp_min Boosting, Cgroups & Binder Priority Inversion

1. UI uclamp_min Boosting & Background Cgroups

The 120Hz Problem (8.33 ms frame budget): An app's UI thread and RenderThread sleep while waiting for VSync, causing their PELT EWMA utilization (util_avg) to decay toward ~100/1024. When the user touches the screen, EAS would place the waking UI thread on a slow LITTLE core until PELT ramps up—missing the 8.33 ms frame deadline!

The Fix (top-app + ADPF): Android puts the focused app in /dev/cpuctl/top-app with cpu.uclamp.min boosted (and uses PerformanceHintManager / ADPF). Conversely, background and restricted cgroups set cpu.uclamp.max low (e.g., 200–400/1024) and lower cpu.weight, pinning sync/telemetry jobs to LITTLE cores.

2. Priority Inversion on Binder & Locks

The Trap: Suppose a high-priority UI_Thread (SCHED_FIFO or boosted top-app) makes a synchronous Binder IPC call into system_server, or waits on a lock held by a low-priority background thread. If the background thread is preempted by a medium-priority thread, the UI thread stalls indefinitely—causing frame drops or an ANR (Application Not Responding).

Priority Inheritance (PI): Android's Binder driver propagates the caller's scheduling policy and priority (sched_policy / nice / rt_prio) to the target Binder worker thread for the duration of the transaction, and kernel rt_mutexes transiently boost lock owners to the highest waiter's priority.

LAB 1 OF 3 // LINUX 6.6+ EEVDF

Implement pickNextEevdf(tasks, avgVruntime)

Filter runnable tasks, evaluate EEVDF eligibility (vruntime ≤ avgVruntime), and select the earliest virtual deadline.

Not Run
Specification: Each task has { pid, vruntime, weight, slice, runnable }.
• Keep only tasks where task.runnable !== false. If none are runnable, return null.
• Compute vdeadline = task.vruntime + (task.slice * 1024) / task.weight.
• A task is eligible iff task.vruntime <= avgVruntime.
• Among eligible runnable tasks, pick the one with the smallest vdeadline (tie-break smallest vruntime, then smallest pid).
• Fallback: if NO runnable task has vruntime <= avgVruntime, pick the runnable task with the smallest vruntime (tie-break smallest pid).
• Return { pid: chosen.pid, vdeadline: chosen.vdeadline, eligible: chosen.eligible }.
LAB 2 OF 3 // BIG.LITTLE EAS + UCLAMP

Implement placeEasTask(task, clusters)

Choose the lowest-energy core cluster meeting task.uclampMin (or highest-capacity fallback).

Not Run
Specification: Given task = { pid, util, uclampMin, uclampMax } and clusters = [{ id, capacity, freeCores, staticPower, dynamicPowerPerUtil }]:
• Consider only clusters with freeCores > 0. If none have free cores, return null.
• Compute clamped demand: demand = Math.min(task.uclampMax ?? 1024, Math.max(task.util ?? 0, task.uclampMin ?? 0)).
• Energy on a cluster: energy = c.staticPower + demand * c.dynamicPowerPerUtil.
• If one or more available clusters have c.capacity >= demand, pick the one with minimum energy (tie-break smaller capacity). Return { clusterId, energy, metCapacity: true }.
• Otherwise (no available cluster meets demand), pick the available cluster with the highest capacity (tie-break lower energy). Return { clusterId, energy, metCapacity: false }.
LAB 3 OF 3 // PRIORITY INVERSION

Implement resolvePriorityInversion(threads, locks)

Propagate Priority Inheritance across multi-hop lock wait chains to compute each thread's effective priority.

Not Run
Specification: Given threads = [{ id, basePrio }] (higher number = higher priority) and locks = [{ lockId, ownerId, waiterIds }]:
• Initialize a map effective[t.id] = t.basePrio.
• Iteratively propagate priority: if any waiter in lock.waiterIds has effective[waiterId] > effective[lock.ownerId], raise effective[lock.ownerId] to that waiter's effective priority.
• Repeat until a full pass makes zero changes (handles arbitrary-depth chains like High → L1 → Med → L2 → Low and terminates safely even if a deadlock cycle exists).
• Return the effective map object ({ [threadId]: effectivePrio }).
