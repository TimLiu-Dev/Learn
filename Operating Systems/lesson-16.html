01 // MENTAL MODEL & INTERACTIVE SIMULATOR

First-Principles Incident Triage & Reading Linux Kernel Source

1. Production Triage: USE Method + PSI

When a service degrades, never guess—read hardware & kernel signals in 30 seconds:

Memory Thrashing (THRASHING_RECLAIM): High /proc/pressure/memory (psiFull ≥ 25%) + surging major page faults (majorFaultsPerSec ≥ 1000) means the working set exceeds RAM/ZRAM and tasks are stalled inside MGLRU/direct reclaim.

Lock Convoy / Binder Starvation (FUTEX_CONTENTION): CPU looks idle, yet futexWaitPct ≥ 50%—threads pile onto a hot userspace mutex or exhausted Binder thread pool.

Syscall Storm vs fsync Stall: syscallsPerSec ≥ 500k burns %sys CPU on EL0↔EL1 traps, whereas iowaitPct ≥ 35% indicates synchronous flash/journal flush queues (fsync() on UI/critical path).

2. Navigating Linux & Android Common Kernel Source

arch/arm64/: Exception vectors (entry.S), TTBR0/1 MMU setup (mm/), and pKVM EL2 hypervisor (kvm/hyp/nvhe/).

kernel/sched/ & kernel/futex/: EEVDF virtual deadlines (fair.c), Android EAS energy model, and futex hash buckets/PI wait queues.

mm/ & fs/: Buddy allocator (page_alloc.c), SLUB (slub.c), MGLRU reclaim (vmscan.c), VFS & F2FS (fs/f2fs/).

drivers/android/binder.c: Single-copy mmap transaction ring & per-process Binder thread pool dispatch.

4 Fatal Kernel Patch Bugs Staff Engineers Catch Immediately

review_traps_1.c — Sleep-in-Atomic & Lock Order Inversion 
// BUG 1: SLEEP_IN_ATOMIC (Triggers "BUG: scheduling while atomic"!)
spin_lock(&dev->lock);
buf = kmalloc(4096, GFP_KERNEL); // WRONG! GFP_KERNEL can sleep in reclaim!
// FIX: Allocate with GFP_KERNEL BEFORE spin_lock(), or use GFP_ATOMIC.

rcu_read_lock();
mutex_lock(&cfg_mutex);        // WRONG! mutex_lock() may sleep inside RCU!
rcu_read_unlock();

// BUG 2: LOCK_ORDER_INVERSION (AB-BA Deadlock caught by lockdep)
// Global hierarchy: lock_A -> lock_B
// Thread 1 (good): spin_lock(&lock_A); spin_lock(&lock_B);
// Thread 2 (BUG!): spin_lock(&lock_B); spin_lock(&lock_A); -> DEADLOCK!
review_traps_2.c — uaccess Overflow, Unchecked Copy & Barriers 
// BUG 3: UACCESS_OVERFLOW + UNCHECKED_COPY_FROM_USER
long bad_ioctl(unsigned long addr, size_t len) {
  if (addr + len > TASK_SIZE) return -EFAULT; // WRONG: 64-bit wraparound!
  copy_from_user(kbuf, (void __user *)addr, len); // WRONG: return ignored!
  return 0;
}

// SAFE KERNEL PATTERN:
long safe_ioctl(unsigned long addr, size_t len) {
  if (len > sizeof(kbuf)) return -EINVAL;
  if (!access_ok((void __user *)addr, len)) return -EFAULT; // overflow-safe
  if (copy_from_user(kbuf, (void __user *)addr, len) != 0)
    return -EFAULT; // Prevents leaking uninitialized kbuf bytes!
  return 0;
}

// BUG 4: Missing smp_store_release() / smp_load_acquire() on lock-free pub.
Why copy_from_user() Return Values Are Security-Critical:
copy_from_user() returns the number of bytes that failed to copy (not 0/-1). Ignoring its return value leaves uninitialized kernel stack/slab bytes inside kbuf—if later copied back to userspace or logged, it becomes a textbook kernel info-leak CVE (bypassing KASLR).
03 // ANDROID SYSTEMS DESIGN INTERVIEW BLUEPRINT

End-to-End Design: High-Throughput Camera / ML Telemetry Pipeline

Architecture Using Lesson 01–15 Primitives

1. Zero-Copy Frame Transport: Camera HAL writes 4K frames into a DMA-BUF heap buffer. Instead of passing 12MB pixel arrays over Binder (which fails with TransactionTooLargeException at the 1MB Binder mmap cap), pass only the 4-byte DMA-BUF FD over Binder!

2. Async Persistence via io_uring: Telemetry worker batches metadata records into page-aligned slab buffers and submits async NVMe/UFS writes over io_uring SQ/CQ rings—eliminating 1 syscall per frame and isolating fsync() stalls off the UI/camera threads.

Hardening, Sizing & Observability

3. Memory Safety & Isolation: Native C++ parser runs under Android's hardened Scudo allocator + ARMv9 MTE (catching UAF/overflows in hardware) and strict seccomp-bpf + SELinux domain (or pKVM Microdroid for sensitive ML weights).

4. Bounded Memory & Telemetry: Pre-size the ring pool against both RSS caps (avoiding lmkd kills) and p99 latency SLAs, and instrument stages with Perfetto atrace + eBPF tail-latency histograms.

LAB 2 OF 3 // CAPACITY & SLA SIZING

Implement planBufferPool(reqBytesPerSec, latencyBudgetUs, maxRssMb)

Size a 4-slot page-aligned ring buffer pool satisfying both p99 latency budget and RSS ceiling.

Not Run
Specification:
• Validate all 3 inputs are positive numbers (> 0). If not, return { feasible: false, reason: "INVALID_PARAMS" }.
• Compute maxRssBytes = maxRssMb * 1024 * 1024.
• Compute batchBytes = Math.ceil((reqBytesPerSec * latencyBudgetUs) / 1000000).
• Round up each slot to a 4KB page boundary (minimum 4096): slotBytes = Math.max(4096, Math.ceil(batchBytes / 4096) * 4096).
• Use numSlots = 4 (double-buffering + burst headroom), so totalPoolBytes = numSlots * slotBytes.
• If totalPoolBytes > maxRssBytes, return { feasible: false, reason: "EXCEEDS_RSS_BUDGET", requiredBytes: totalPoolBytes, maxRssBytes }.
• Otherwise return { feasible: true, slotBytes, numSlots, totalPoolBytes, flushIntervalUs: latencyBudgetUs }.
LAB 3 OF 3 // KERNEL PATCH AUDITOR

Implement auditKernelPatch(patch)

Flag dangerous Linux kernel bugs before they merge into Android Common Kernel.

Not Run
Specification: Inspect patch and return an array of triggered findings (sorted lexicographically, no duplicates):
• "SLEEP_IN_ATOMIC": if (patch.spinlockHeld || patch.rcuReadHeld) && patch.callsSleepingFn.
• "LOCK_ORDER_INVERSION": given patch.lockOrder (order acquired by this patch) and patch.globalLockHierarchy (canonical lock order), if any pair i < j in lockOrder has rank(lockOrder[i]) > rank(lockOrder[j]) in globalLockHierarchy (ignore locks not present in hierarchy).
• "UACCESS_OVERFLOW": if patch.copyUserChecks && !patch.copyUserChecks.checksOverflow.
• "UNCHECKED_COPY_FROM_USER": if patch.copyUserChecks && (!patch.copyUserChecks.hasAccessOk || !patch.copyUserChecks.checksReturn).
