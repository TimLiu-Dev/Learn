Problem #152: Maximum Product Subarray

View on NeetCode ↗

Official Problem Statement

Given an integer array nums, find a subarray that has the largest product, and return the product.

The test cases are generated so that the answer will fit in a 32-bit integer.

Example 1: nums = [2,3,-2,4] → Output: 6 (subarray [2,3])

Example 2: nums = [-2,0,-1] → Output: 0 (cannot be [-2,-1] because 0 separates them)

Example 3: nums = [-2,3,-4] → Output: 24 (product of entire array)

Plain-English Translation & Core Nuance

Like Maximum Subarray (#53), find the highest-product contiguous slice—but track BOTH the running max AND running min because two negatives multiply into a giant positive!

Official Constraints:
  • 1 <= nums.length <= 2 * 10^4
  • -10 <= nums[i] <= 10
  • The product of any subarray of nums is guaranteed to fit in a 32-bit integer.

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
nums = [-3] -> Single negative element; global max initialized to nums[0] returns -3.
Best-Case Early Exit
nums = [-2, 0, -1] -> Zero resets both curMax and curMin cleanly; answer is 0.
Worst-Case Full Scan
nums = [-2, 3, -4] -> curMin (-6) flips sign on -4 to become curMax = +24!

The Mental Model & "Explain Like I'm 12"

💡 The Jekyll-and-Hyde Sign-Flip Multiplier

In Maximum Sum (#53), a huge negative streak is garbage—you throw it away. In Maximum Product, a huge negative product like -100 is a sleeping superhero: the moment it hits another negative number like -2, (-100) * (-2) rockets to +200! So at every index, you carry two champions forward: the largest positive product (curMax) AND the most negative product (curMin).

The Mental "A-Ha!" Switch:

Track BOTH curMax and curMin ending at i! When nums[i] < 0, swap curMax and curMin (or take max/min across {n, n * prevMax, n * prevMin}), because negative times negative flips min into max!

Pattern Trigger:

Contiguous subarray product optimization with negative numbers and zeros.

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(N^2) Time, O(1) Space

Try all pairs (i, j) with nested loops accumulating running product.

Wasted Work: Recomputes overlapping subarray products across 2 * 10^4 elements -> 4 * 10^8 operations (TLE).
The Optimal Breakthrough O(N) Time, O(1) Space

Maintain curMax and curMin initialized to nums[0] (and ans = nums[0]). For each nums[i], save prevMax = curMax; curMax = max(n, n * prevMax, n * curMin); curMin = min(n, n * prevMax, n * curMin); ans = max(ans, curMax).

Core Invariant: At step i, curMax and curMin equal the exact maximum and minimum subarray products ending at index i.
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
Naive: All Subarray Pairs O(N^2) O(1) TLE at N = 20,000.
Trap: Single curMax Kadane's O(N) O(1) Fails on [-2, 3, -4] because it discards -6.
Optimal: Dual curMax/curMin DP O(N) O(1) ★ Handles negatives, zeros, and sign flips in O(1) space.

2. Core Traversal & Decision Rule

Maintain curMax and curMin initialized to nums[0] (and ans = nums[0]). For each nums[i], save prevMax = curMax; curMax = max(n, n * prevMax, n * curMin); curMin = min(n, n * prevMax, n * curMin); ans = max(ans, curMax). 3. Invariant Maintenance & State Transition

Initialize curMax = curMin = ans = nums[0]. For each i from 1 to n-1, snapshot prevMax = curMax, update curMax = max(n, n * prevMax, n * curMin) and curMin = min(n, n * prevMax, n * curMin), and update ans = max(ans, curMax). Throughout every transition, we preserve the core invariant: At step i, curMax and curMin equal the exact maximum and minimum subarray products ending at index i.

4. Termination & Output Guarantee

Check for early-exit conditions (nums = [-2, 0, -1] -> Zero resets both curMax and curMin cleanly; answer is 0.). Once traversal completes, return the accumulated result. Because we kept `curMin = -6` at index 1, multiplying by `-4` at index 2 unlocks `(-6) * (-4) = 24`!

Production Implementations

From Naive to Optimal & Runnable Practice Arena

Approach 1: Brute-Force All Subarrays

Evaluate every contiguous [i..j] product in nested loops.

Time: O(N^2) Space: O(1) 
class Solution {
    fun maxProduct(nums: IntArray): Int {
        var ans = nums[0]
        for (i in nums.indices) {
            var prod = 1
            for (j in i until nums.size) {
                prod *= nums[j]
                if (prod > ans) ans = prod
            }
        }
        return ans
    }
}
Kotlin Runtime & Memory Nuance:

Quadratic O(N^2) exceeds time limits when N approaches 20,000.

Pure interpreter nested loops time out quickly on N = 2 * 10^4.

class Solution {
    public int maxProduct(int[] nums) {

            int prod = 1;
            for (int j = i; j < nums.length; j++) {

            }
        }
        return ans;
    }
}

Approach 2: Dual Extremum Rolling DP

Maintain both curMax and curMin at each step so negative sign flips promote curMin to curMax.

Time: O(N) Space: O(1) 
class Solution {
    fun maxProduct(nums: IntArray): Int {
        var curMax = nums[0]
        var curMin = nums[0]
        var ans = nums[0]
        for (i in 1 until nums.size) {
            val n = nums[i]
            val prevMax = curMax
            curMax = maxOf(n, maxOf(n * prevMax, n * curMin))
            curMin = minOf(n, minOf(n * prevMax, n * curMin))
            if (curMax > ans) ans = curMax
        }
        return ans
    }
}
Kotlin Runtime & Memory Nuance:

Snapshots prevMax before overwriting curMax so curMin computes against the prior step's max.

class Solution:
    def maxProduct(self, nums: list[int]) -> int:
        cur_max = cur_min = ans = nums[0]
        for n in nums[1:]:
            prev_max = cur_max
            cur_max = max(n, n * prev_max, n * cur_min)
            cur_min = min(n, n * prev_max, n * cur_min)
            ans = max(ans, cur_max)
        return ans
Python Runtime & Memory Nuance:

Uses O(1) scalar variables; can also iterate by index range(1, len(nums)) to avoid slicing nums[1:].

class Solution {
    public int maxProduct(int[] nums) {
        int curMax = nums[0], curMin = nums[0], ans = nums[0];
        for (int i = 1; i < nums.length; i++) {
            int n = nums[i];
            int prevMax = curMax;
            curMax = Math.max(n, Math.max(n * prevMax, n * curMin));
            curMin = Math.min(n, Math.min(n * prevMax, n * curMin));
            if (curMax > ans) ans = curMax;
        }
        return ans;
    }
}
Java Runtime & Memory Nuance:

Zero heap allocations; handles zeros naturally because max(n, 0, 0) resets on the next non-zero.
