Problem #733: Flood Fill

External Judge ↗

Official Problem Statement

You are given an image represented by an m x n grid of integers image, where image[i][j] represents the pixel value of the image. You are also given three integers sr, sc, and color.

Perform a flood fill starting from pixel image[sr][sc]: recolor the starting pixel and all 4-directionally connected pixels sharing the same original color as image[sr][sc] to color, and return the modified image.

Example 1: image = [[1,1,1],[1,1,0],[1,0,1]], sr = 1, sc = 1, color = 2 → Output: [[2,2,2],[2,2,0],[2,0,1]]

Example 2: image = [[0,0,0],[0,0,0]], sr = 0, sc = 0, color = 0 → Output: [[0,0,0],[0,0,0]]

Plain-English Translation & Core Nuance

Like the paint-bucket tool in a drawing app: record origColor = image[sr][sc], guard origColor == color immediately (to prevent infinite ping-pong recursion!), and recolor every 4-directionally reachable origColor cell to color.

Official Constraints:
  • m == image.length, n == image[i].length
  • 1 <= m, n <= 50
  • 0 <= image[i][j], color < 2^16

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
1x1 grid [[3]], sr=0, sc=0, color=7 -> recolors single cell to [[7]].
Best-Case Early Exit
origColor == color (Example 2: 0 -> 0) -> returns immediately in O(1) without recursion or visited array!
Worst-Case Full Scan
50x50 uniform grid -> visits each of the 2,500 cells once in O(R * C) time.

Section 01 • Cognitive Anchor

The Mental Model & "Explain Like I'm 12"

💡 The Paint-Bucket Spill with Self-Sealing Paint

Pouring new blue paint onto connected white tiles spreads up, down, left, and right only onto white tiles. Because each painted tile immediately turns blue, the new color itself acts as your 'visited' marker—EXCEPT when the bucket already holds white paint (origColor == color)! Checking if (origColor == color) return image at the very top prevents infinite neighbor bouncing without needing an extra visited[][] matrix.

The Mental "A-Ha!" Switch:

Guard if (origColor == color) return image upfront; once origColor != color, mutating image[r][c] = color serves as an O(1)-overhead visited check!

Section 02 • Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap StackOverflowError if origColor == color

Run recursive DFS recoloring neighbors without checking origColor == color or allocating an explicit visited[R][C] matrix.

Wasted Work: Without the same-color guard, two adjacent 0-pixels infinitely recurse between each other until the call stack crashes.
The Optimal Breakthrough O(R · C) Time, O(R · C) Worst-Case Queue/Stack

Short-circuit when image[sr][sc] == color, then run iterative Queue BFS (or bounded DFS) painting cells on enqueue.

Core Invariant: Every enqueued cell had value origColor and is immediately overwritten to color != origColor before its neighbors are explored.
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
Trap: Unguarded In-Place DFS Infinite Loop StackOverflow Crashes immediately on Example 2 (orig == color).
Recursive DFS + Same-Color Guard O(R · C) O(R · C) call stack Concise for 50x50; risks stack overflow on 2000x2000 images.
Optimal: Iterative BFS + Same-Color Guard O(R · C) O(R · C) heap queue ★ Stack-safe in production even on multi-megapixel grids.

1. Boundary Guards & Container Setup

Check degenerate inputs upfront (1x1 grid [[3]], sr=0, sc=0, color=7 -> recolors single cell to [[7]].) and initialize only the auxiliary state needed to avoid Without the same-color guard, two adjacent 0-pixels infinitely recurse between each other until the call stack crashes..

2. Core Traversal & Decision Rule

Short-circuit when image[sr][sc] == color, then run iterative Queue BFS (or bounded DFS) painting cells on enqueue. Instead of re-scanning prior elements, each step makes a local O(1) or O(log N) transition.

3. Invariant Preservation Across Steps

Guard if (origColor == color) return image upfront; once origColor != color, mutating image[r][c] = color serves as an O(1)-overhead visited check! After every update, the core invariant holds: Every enqueued cell had value origColor and is immediately overwritten to color != origColor before its neighbors are explored.

4. Early Exit & Final Return

Short-circuit immediately when decisive conditions trigger (origColor == color (Example 2: 0 -> 0) -> returns immediately in O(1) without recursion or visited array!); otherwise complete traversal and return the final state. Pixel (2,2) stays 1 because flood fill is strictly 4-directional—diagonals do not connect!

Section 05 • Production Implementations

From Naive to Optimal & Runnable Practice Arena

Strict ordering: Kotlin (Default) → Python → Java across all approaches.

Recursive 4-Directional DFS

Guards orig == color, then recursively paints 4-directional matching neighbors.

Time: O(R · C) Space: O(R · C) stack 
class Solution {
    fun floodFill(image: Array<IntArray>, sr: Int, sc: Int, color: Int): Array<IntArray> {
        val orig = image[sr][sc]
        if (orig == color) return image
        fun dfs(r: Int, c: Int) {
            if (r < 0 || r >= image.size || c < 0 || c >= image[0].size || image[r][c] != orig) return
            image[r][c] = color
            dfs(r - 1, c)
            dfs(r + 1, c)
            dfs(r, c - 1)
            dfs(r, c + 1)
        }
        dfs(sr, sc)
        return image
    }
}

class Solution {
    public int[][] floodFill(int[][] image, int sr, int sc, int color) {
        int orig = image[sr][sc];
        if (orig == color) return image;
        dfs(image, sr, sc, orig, color);
        return image;
    }

    private void dfs(int[][] image, int r, int c, int orig, int color) {
        if (r < 0 || r >= image.length || c < 0 || c >= image[0].length || image[r][c] != orig) return;
        image[r][c] = color;
        dfs(image, r - 1, c, orig, color);
        dfs(image, r + 1, c, orig, color);
        dfs(image, r, c - 1, orig, color);
        dfs(image, r, c + 1, orig, color);
    }
}

Optimal: Iterative Queue BFS (Stack-Safe)

Paints cells on enqueue using an explicit ArrayDeque/deque so deep 2000x2000 grids never overflow the call stack.

Time: O(R · C) Space: O(R · C) 
import java.util.ArrayDeque

class Solution {
    fun floodFill(image: Array<IntArray>, sr: Int, sc: Int, color: Int): Array<IntArray> {
        val orig = image[sr][sc]
        if (orig == color) return image
        val rows = image.size
        val cols = image[0].size
        val q = ArrayDeque<IntArray>()
        image[sr][sc] = color
        q.addLast(intArrayOf(sr, sc))
        val dirs = arrayOf(intArrayOf(-1, 0), intArrayOf(1, 0), intArrayOf(0, -1), intArrayOf(0, 1))
        while (q.isNotEmpty()) {
            val curr = q.removeFirst()
            val r = curr[0]
            val c = curr[1]
            for (d in dirs) {
                val nr = r + d[0]
                val nc = c + d[1]
                if (nr in 0 until rows && nc in 0 until cols && image[nr][nc] == orig) {
                    image[nr][nc] = color
                    q.addLast(intArrayOf(nr, nc))
                }
            }
        }
        return image
    }
}
Kotlin Runtime & Memory Nuance:

In Optimal: Iterative Queue BFS (Stack-Safe), Kotlin uses unboxed JVM primitive arrays (IntArray / BooleanArray) to eliminate object header overhead; and uses circular-buffer ArrayDeque for O(1) head/tail operations without node allocations.

from collections import deque

class Solution:
    def floodFill(self, image: list[list[int]], sr: int, sc: int, color: int) -> list[list[int]]:
        orig = image[sr][sc]
        if orig == color:
            return image
        rows, cols = len(image), len(image[0])
        q = deque([[sr, sc]])
        image[sr][sc] = color
        dirs = [[-1, 0], [1, 0], [0, -1], [0, 1]]
        while q:
            curr = q.popleft()
            r, c = curr[0], curr[1]
            for d in dirs:
                nr, nc = r + d[0], c + d[1]
                if 0 <= nr < rows and 0 <= nc < cols and image[nr][nc] == orig:
                    image[nr][nc] = color
                    q.append([nr, nc])
        return image
Python Runtime & Memory Nuance:

In Optimal: Iterative Queue BFS (Stack-Safe), Python uses collections.deque for true O(1) popleft() instead of O(N) list.pop(0).

import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public int[][] floodFill(int[][] image, int sr, int sc, int color) {
        int orig = image[sr][sc];
        if (orig == color) return image;
        int rows = image.length, cols = image[0].length;
        Deque<int[]> q = new ArrayDeque<>();
        image[sr][sc] = color;
        q.addLast(new int[]{sr, sc});
        int[][] dirs = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};
        while (!q.isEmpty()) {
            int[] curr = q.removeFirst();
            for (int[] d : dirs) {
                int nr = curr[0] + d[0], nc = curr[1] + d[1];
                if (nr >= 0 && nr < rows && nc >= 0 && nc < cols && image[nr][nc] == orig) {
                    image[nr][nc] = color;
                    q.addLast(new int[]{nr, nc});
                }
            }
        }
        return image;
    }
}
Java Runtime & Memory Nuance:

In Optimal: Iterative Queue BFS (Stack-Safe), Java uses resizable ArrayDeque instead of pointer-heavy LinkedList; and operates on unboxed primitive Java arrays to avoid Integer autoboxing GC pressure.

          Phase 1: Clarifying Constraints
          
I'll confirm connectivity is 4-directional (not 8-directional) and check the key edge case: what if image[sr][sc] already equals color? In that case the image is unchanged and we must return immediately.

        

        

          Phase 2: Space-Time Trade-Off Pitch
          
Once orig != color is guarded, recoloring a pixel from orig to color automatically marks it visited in-place. While recursive DFS is short for 50x50, iterative Queue BFS avoids JVM/Python call-stack overflow on large production images.

        

        

          Phase 3: Clean Implementation Narration
          
I recolor (sr, sc) before enqueuing—and recolor every valid neighbor right when enqueuing rather than on dequeue—so no pixel is ever pushed into the queue twice.

        

        

          Phase 4: Boundary Dry-Run Verification
          
Testing Example 2 ([[0,0,0],[0,0,0]], color=0): orig == color triggers line 1 and returns in O(1). Testing Example 1: (2,2) is only diagonally adjacent to 1s, so it remains 1.
