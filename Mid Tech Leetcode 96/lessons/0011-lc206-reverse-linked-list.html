LeetCode 206: Reverse Linked List

Official LC #206

Official Problem Statement

Given the head of a singly linked list, reverse the list, and return the reversed list.

Example 1: Input: head = [1,2,3,4,5] → Output: [5,4,3,2,1]

Example 2: Input: head = [1,2] → Output: [2,1]

Example 3: Input: head = [] → Output: []

Plain-English Translation & Core Nuance

You have a chain of objects where each node only knows where the next node lives. Your mission is to make every arrow point backwards so that the original tail becomes the new head, and the original head points to null.

⚠️ Critical Danger: If you overwrite curr.next = prev before caching curr.next into a temporary pointer, you severed the link to the entire remainder of the list! The rest of the list is immediately garbage-collected and lost forever.
Input Constraints

Node count: [0, 5000]

Node values: -5000 ≤ val ≤ 5000

→ O(N) linear time is mandatory, O(1) space expected.

Empty & Single-Node List

head = [] → null

head = [1] → [1]

Algorithm must gracefully handle null and 1-element without null pointer exceptions.

Standard Chain

[1 → 2 → 3 → 4 → 5]

Output: [5 → 4 → 3 → 2 → 1]

All next references flipped in place; old head points to null.

Conceptual Architecture

Physical Mental Model: The Train Coupler Reversal

🚂

Decoupling and Recoupling Backwards

Imagine a line of train cars hitched together facing North. You are standing next to car curr:

  1. Look Ahead: Identify the next car north and remember its identifier (nextTemp = curr.next).
  2. Unhitch & Flip: Unhitch the hitch pointing North and hook it onto the car South of you (curr.next = prev).
  3. Step North: Step your feet forward: your previous location becomes curr, and your current car becomes nextTemp.
When curr steps past the last car into empty space (curr == null), prev is standing firmly on the brand new engine (the original caboose)!

Strategic Contrast

Naive Trap vs. Optimal Breakthrough

❌

The Naive Trap: Copy to Array / Stack & Rebuild

Beginners often traverse the list, push every node's value into an ArrayList or a Stack, then traverse backwards allocating brand new ListNode objects.

• Time Complexity: O(N) traversal + O(N) allocation

• Space Complexity: O(N) auxiliary heap allocation

• Senior Interview Penalty: Fails when interviewer specifies: "Must modify original nodes in-place with O(1) extra memory."

✅

The Breakthrough: Three-Pointer In-Place Flip

Use exactly 2 reference variables outside the list (prev = null, curr = head) and 1 loop-scoped temporary pointer (nextTemp). Reverse the link in one pass.

• Time Complexity: O(N) single linear pass

• Space Complexity: O(1) strict auxiliary memory

• Clean Exit: When curr == null, return prev directly as the new head.

Approach Time Space Mutates Input? Tradeoff Summary
1. Array / Stack Buffer O(N) O(N) Creates New Nodes Trivial to implement, but wastes heap space and memory bandwidth.
2. Recursive Reversal O(N) O(N) stack In-Place Elegant recurrence (head.next.next = head), but causes StackOverflowError for N > 10,000.
3. 3-Pointer Iterative (Optimal) O(N) O(1) In-Place Production gold standard. Zero allocations, immune to stack overflow.

Explore Brute Force, Recursive, and the Optimal In-Place 3-Pointer implementation.

Approach 1: Push All Nodes to Stack & Re-link

Traverse the original list and push each ListNode onto an explicit LIFO Stack. Pop each node sequentially and link them back up, capping the last popped node with null.

Time: O(N) Space: O(N) 
class Solution {
    fun reverseList(head: ListNode?): ListNode? {
        if (head?.next == null) return head
        
        val stack = java.util.ArrayDeque<ListNode>()
        var curr = head
        while (curr != null) {
            stack.push(curr)
            curr = curr.next
        }
        
        val newHead = stack.pop()
        var tail = newHead
        while (stack.isNotEmpty()) {
            tail.next = stack.pop()
            tail = tail.next!!
        }
        tail.next = null // Prevent cycle!
        return newHead
    }
}
class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        if not head or not head.next:
            return head
        
        stack = []
        curr = head
        while curr:
            stack.append(curr)
            curr = curr.next
            
        new_head = stack.pop()
        tail = new_head
        while stack:
            tail.next = stack.pop()
            tail = tail.next
        tail.next = None
        return new_head
class Solution {
    public ListNode reverseList(ListNode head) {
        if (head == null || head.next == null) return head;
        
        Deque<ListNode> stack = new ArrayDeque<>();
        ListNode curr = head;
        while (curr != null) {
            stack.push(curr);
            curr = curr.next;
        }
        
        ListNode newHead = stack.pop();
        ListNode tail = newHead;
        while (!stack.isEmpty()) {
            tail.next = stack.pop();
            tail = tail.next;
        }
        tail.next = null;
        return newHead;
    }
}

Approach 2: Recursive Post-Order Call Stack

Recurse down to the terminal tail node. As the call stack unwinds from right to left, execute head.next.next = head (redirecting child's arrow back to parent) and sever the parent's forward pointer with head.next = null.

Time: O(N) Space: O(N) Call Stack (StackOverflow risk on deep chains) 
class Solution {
    fun reverseList(head: ListNode?): ListNode? {
        // Base case: empty list or single node reached (new head)
        if (head?.next == null) return head
        
        val newHead = reverseList(head.next)
        
        // head.next is our child. Make child point back to us:
        head.next!!.next = head
        head.next = null // Sever forward pointer
        
        return newHead
    }
}
class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        if not head or not head.next:
            return head
            
        new_head = self.reverseList(head.next)
        head.next.next = head
        head.next = None
        return new_head
class Solution {
    public ListNode reverseList(ListNode head) {
        if (head == null || head.next == null) return head;
        
        ListNode newHead = reverseList(head.next);
        head.next.next = head;
        head.next = null;
        return newHead;
    }
}

Approach 3: Iterative 3-Pointer In-Place Reversal (Production Optimal)

INTERVIEW DEFAULT

Maintains prev and curr. Within the loop, captures val nextTemp = curr.next, reverses the pointer with curr.next = prev, and shifts both pointers forward. Total zero allocations, maximum CPU cache friendliness.

Time: O(N) (Single pass) Space: O(1) (Strict constant memory) 
/**
 * Example:
 * var li = ListNode(5)
 * var v = li.`val`
 * Definition for singly-linked list.
 * class ListNode(var `val`: Int) {
 *     var next: ListNode? = null
 * }
 */
class Solution {
    fun reverseList(head: ListNode?): ListNode? {
        var prev: ListNode? = null
        var curr: ListNode? = head
        
        while (curr != null) {
            val nextTemp = curr.next // 1. Cache future node to prevent link loss
            curr.next = prev        // 2. Flip link backwards
            prev = curr             // 3. Shift prev forward
            curr = nextTemp         // 4. Shift curr forward
        }
        
        return prev // When curr is null, prev points to the new head
    }
}
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next
class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        prev = None
        curr = head
        
        while curr:
            next_temp = curr.next  # 1. Cache future node
            curr.next = prev       # 2. Redirect pointer
            prev = curr            # 3. Advance prev
            curr = next_temp       # 4. Advance curr
            
        return prev
/**
 * Definition for singly-linked list.
 * public class ListNode {
 *     int val;
 *     ListNode next;
 *     ListNode() {}
 *     ListNode(int val) { this.val = val; }
 *     ListNode(int val, ListNode next) { this.val = val; this.next = next; }
 * }
 */
class Solution {
    public ListNode reverseList(ListNode head) {
        ListNode prev = null;
        ListNode curr = head;
        
        while (curr != null) {
            ListNode nextTemp = curr.next; // 1. Cache future node
            curr.next = prev;              // 2. Redirect pointer
            prev = curr;                   // 3. Advance prev
            curr = nextTemp;               // 4. Advance curr
        }
        
        return prev;
    }
}

          🚀
          Senior Scalability & System Follow-Ups
        

        

          

            1. Concurrent / Thread-Safe Linked Lists:
            

              In multi-threaded architectures (e.g. concurrent skip-lists or lock-free queues), pointer updates cannot be performed sequentially without locks. If another thread traverses during reversal, it encounters severed pointers. Solution: Read-Copy-Update (RCU) or hand-over-hand mutex locking.
            

          

          

            2. Massive Out-of-Core Linked Lists (Exceeding RAM):
            

              If the chain represents terabytes of sequential records stored on disk blocks or distributed storage (S3/GCS): nodes cannot be traversed via random in-memory pointer chases. Solution: Store records in chunked sequential block offsets, reverse chunk pointers, and batch-reverse internal block buffers.
