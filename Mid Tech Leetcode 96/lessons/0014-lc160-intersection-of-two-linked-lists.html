LeetCode 160: Intersection of Two Linked Lists

Official LC #160

Official Problem Statement

Given the heads of two singly linked-lists headA and headB, return the node at which the two lists intersect. If the two linked lists have no intersection at all, return null.

For example, the following two linked lists begin to intersect at node c1:

A: a1 → a2 \
           c1 → c2 → c3
B: b1 → b2 → b3 /

Note: Retain original list structure. You may assume there are no cycles in the entire linked structure.

Plain-English Translation & Core Nuance

Two paths may start at different locations, but eventually merge into a shared common tail. Find the exact memory reference of the first shared node (by reference equality pA === pB, NOT by value).

✨ Distance Equalization (A + B = B + A): If List A has length a + c and List B has length b + c, the difference in lengths is $|a - b|$. If pointer A traverses A then B, and pointer B traverses B then A, both travel exactly a + c + b steps! They arrive at the intersection node at the exact same step.
Input Constraints

Node count: [1, 30,000]

Values: 1 ≤ val ≤ 100,000

O(N + M) time and O(1) memory are strictly required.

No Intersection

A: [2,6,4], B: [1,5] → null

Neither shares nodes.

Both pointers traverse A+B and simultaneously reach null. Loop terminates cleanly!

Identical List / Immediate Merge

headA === headB → headA

Intersection occurs at root.

Loop detects equality on iteration 0 without head swap.

Physical Mental Model: Two Hikers on Merging Trails

🥾

Trail Swap Distance Equalization

Hiker A starts on Trail A (length a) and Hiker B starts on Trail B (length b). Both trails merge into a shared scenic ridge (length c).

  • If they hike at the exact same speed, Hiker A arrives at the scenic ridge after a miles, and Hiker B after b miles. Because a \neq b, they miss each other.
  • The Equalizer: When Hiker A reaches the end of the ridge, they immediately start Trail B. When Hiker B reaches the end, they start Trail A.
  • Now, both hikers walk exactly a + c + b = b + c + a miles. They step onto the start of the scenic ridge at the exact same second!

Strategic Contrast

Naive Trap vs. Optimal Breakthrough

❌

The Naive Trap: Nested Loops or HashSet

Approach A uses nested loops: for each node in A, iterate through all nodes in B to check pointer equality — O(N × M) time. Approach B stores visited nodes of A in a HashSet — O(N) auxiliary space.

• Nested Loops: 30,000 × 30,000 = 900,000,000 ops (Time Limit Exceeded)

• HashSet: 30,000 heap node allocations (Fails O(1) space constraint)

✅

The Breakthrough: Dual Head-Swap Pointers

Initialize pA = headA and pB = headB. When pA reaches null, switch to headB; when pB reaches null, switch to headA. In at most 2 passes, pA === pB.

• Time Complexity: O(N + M) strictly ≤ 2 × (N + M) steps

• Space Complexity: O(1) auxiliary space (2 local pointer variables)

• Clean null exit: If no intersection, both pointers reach null simultaneously!

Approach Time Space Passes Tradeoff Summary
1. Nested Loops O(N × M) O(1) N × M Times out on large inputs (30,000 nodes).
2. Length Difference Alignment O(N + M) O(1) 3 passes Valid O(1) space, but requires 3 passes (count lenA, count lenB, advance diff, walk).
3. Dual Pointer Head Swap (Optimal) O(N + M) O(1) ≤ 2 passes Production optimal. 5-line implementation, self-synchronizing distance.

Solution Evolution

From O(N*M) Naive to Elegant Dual Head Swap

Approach 1: Nested Pairwise Loops

For each node in list A, iterate through every node in list B and check if references match (nodeA === nodeB). Unusable on large lists due to quadratic runtime.

Time: O(N × M) Space: O(1) 
class Solution {
    fun getIntersectionNode(headA: ListNode?, headB: ListNode?): ListNode? {
        var pA = headA
        while (pA != null) {
            var pB = headB
            while (pB != null) {
                if (pA === pB) return pA
                pB = pB.next
            }
            pA = pA.next
        }
        return null
    }
}
class Solution:
    def getIntersectionNode(self, headA: ListNode, headB: ListNode) -> Optional[ListNode]:
        pA = headA
        while pA:
            pB = headB
            while pB:
                if pA is pB:
                    return pA
                pB = pB.next
            pA = pA.next
        return None
public class Solution {
    public ListNode getIntersectionNode(ListNode headA, ListNode headB) {
        for (ListNode pA = headA; pA != null; pA = pA.next) {
            for (ListNode pB = headB; pB != null; pB = pB.next) {
                if (pA == pB) return pA;
            }
        }
        return null;
    }
}

Approach 2: Length Difference Alignment (3 Passes)

Calculate lengths len(A) and len(B). Advance the pointer of the longer list by $|len(A) - len(B)|$ steps. Then advance both in lockstep until they collide or reach null.

Time: O(N + M) Space: O(1) Passes: 3 Passes 
class Solution {
    fun getIntersectionNode(headA: ListNode?, headB: ListNode?): ListNode? {
        var lenA = 0; var pA = headA
        while (pA != null) { lenA++; pA = pA.next }
        
        var lenB = 0; var pB = headB
        while (pB != null) { lenB++; pB = pB.next }
        
        pA = headA; pB = headB
        while (lenA > lenB) { pA = pA!!.next; lenA-- }
        while (lenB > lenA) { pB = pB!!.next; lenB-- }
        
        while (pA != null && pB != null) {
            if (pA === pB) return pA
            pA = pA.next
            pB = pB.next
        }
        return null
    }
}
class Solution:
    def getIntersectionNode(self, headA: ListNode, headB: ListNode) -> Optional[ListNode]:
        lenA, lenB = 0, 0
        pA, pB = headA, headB
        while pA: lenA += 1; pA = pA.next
        while pB: lenB += 1; pB = pB.next
        
        pA, pB = headA, headB
        while lenA > lenB: pA = pA.next; lenA -= 1
        while lenB > lenA: pB = pB.next; lenB -= 1
        
        while pA and pB:
            if pA is pB: return pA
            pA = pA.next
            pB = pB.next
        return None
public class Solution {
    public ListNode getIntersectionNode(ListNode headA, ListNode headB) {
        int lenA = 0, lenB = 0;
        for (ListNode p = headA; p != null; p = p.next) lenA++;
        for (ListNode p = headB; p != null; p = p.next) lenB++;
        
        ListNode pA = headA, pB = headB;
        while (lenA > lenB) { pA = pA.next; lenA--; }
        while (lenB > lenA) { pB = pB.next; lenB--; }
        
        while (pA != null && pB != null) {
            if (pA == pB) return pA;
            pA = pA.next;
            pB = pB.next;
        }
        return null;
    }
}

Approach 3: Dual Pointer Head Swap (Production Optimal)

INTERVIEW DEFAULT

Traverses both lists. When pA hits null, redirect to headB; when pB hits null, redirect to headA. Because a + c + b = b + c + a, both pointers align on the second pass and exit simultaneously.

Time: O(N + M) (At most 2 passes) Space: O(1) (Two pointers) 
class Solution {
    fun getIntersectionNode(headA: ListNode?, headB: ListNode?): ListNode? {
        if (headA == null || headB == null) return null
        
        var pA = headA
        var pB = headB
        
        while (pA !== pB) {
            // If at end of chain, switch to other head; else advance
            pA = if (pA == null) headB else pA.next
            pB = if (pB == null) headA else pB.next
        }
        
        return pA // Either the intersection node, or null if no overlap
    }
}
class Solution:
    def getIntersectionNode(self, headA: ListNode, headB: ListNode) -> Optional[ListNode]:
        if not headA or not headB:
            return None
            
        pA, pB = headA, headB
        while pA is not pB:
            pA = headB if pA is None else pA.next
            pB = headA if pB is None else pB.next
            
        return pA
public class Solution {
    public ListNode getIntersectionNode(ListNode headA, ListNode headB) {
        if (headA == null || headB == null) return null;
        
        ListNode pA = headA;
        ListNode pB = headB;
        
        while (pA != pB) {
            pA = (pA == null) ? headB : pA.next;
            pB = (pB == null) ? headA : pB.next;
        }
        
        return pA;
    }
}

          Phase 1: Clarify & Confirm Boundaries
          

            "Are we looking for value equality or reference equality? Reference equality: two nodes pointing to the exact same memory address. Should we mutate the lists? No, problem specifies lists must retain original structure. What if there is no intersection? Return null."
          

        


        

          Phase 2: Propose Strategy & Invariant
          

            "I'll use a dual-pointer head-swap technique. pA starts at headA, pB at headB. When pA reaches null, it redirects to headB. When pB reaches null, it redirects to headA. By the principle of commutativity, both travel exactly len(A) + len(B) steps, equalizing their offsets and meeting at the intersection node in at most two passes."
          

        


        

          Phase 3: Trace Edge Case Walkthrough
          

            "What if they don't intersect? After pA traverses A then B, and pB traverses B then A, both reach null at the exact same step! The condition pA == pB becomes null == null (true), the loop exits, and we return null. No infinite loop."
          

        


        

          Phase 4: Conclude & Space-Time Bounds
          

            "Time complexity is strictly O(N + M) because each pointer takes at most N + M steps. Space complexity is O(1) auxiliary memory since we only use two local pointer handles."

          Senior Scalability & System Follow-Ups
        

        

          

            1. What if Lists May Contain Cycles? (Senior System Design):
            

              If cycles are permitted, lists can intersect before the loop or inside the loop. Use Floyd's cycle detection on both lists:
              1) If neither has a cycle → standard LC 160 logic.
              2) If one has a cycle and the other doesn't → impossible to intersect.
              3) If both have cycles → check if loop entry nodes match or if one entry node can reach the other inside the loop.
            

          

          

            2. Distributed Commit DAGs (Git Merge Base):
            

              In Git repositories, commits form a directed acyclic graph (DAG). Finding the common ancestor of two divergent branches uses BFS/topological traversal to identify the lowest common ancestor commit where divergence began.
