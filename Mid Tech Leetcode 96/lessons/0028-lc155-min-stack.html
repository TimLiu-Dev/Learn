LeetCode #155: Min Stack

Official LC #155

Official Problem Statement

Design a stack that supports push, pop, top, and retrieving the minimum element in constant time.

Implement the MinStack class:

  • MinStack() initializes the stack object.
  • void push(int val) pushes the element val onto the stack.
  • void pop() removes the element on the top of the stack.
  • int top() gets the top element of the stack.
  • int getMin() retrieves the minimum element in the stack.

You must implement a solution with O(1) time complexity for each function.

Example 1: ["MinStack","push","push","push","getMin","pop","top","getMin"] [[],[-2],[0],[-3],[],[],[],[]] → Output: [null,null,null,null,-3,null,0,-2]

Plain-English Translation & Core Nuance

Build a stack where finding the minimum value takes O(1) time without looping. Each element records what the minimum was at the exact moment it was pushed. When an element is popped, the minimum naturally rolls back to what it was before.

Official Constraints:
  • -2^31 <= val <= 2^31 - 1
  • Methods pop, top and getMin operations will always be called on non-empty stacks.
  • At most 3 * 10^4 calls will be made to push, pop, top, and getMin.

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
Single element pushed → top() == getMin() == val.
Best-Case Early Exit
Strictly decreasing pushes [-1, -2, -3] → Each push becomes the new minimum.
Worst-Case Full Scan
Popping duplicate minimums → Correctly decrements tracking without losing minimum.

The Mental Model & "Explain Like I'm 12"

💡 The Stack of Labeled Plates

Imagine a cafeteria stack of plates. Each time you wash a plate, you write two numbers on its rim: the plate's own weight, and the minimum weight of any plate below it (including itself). To find the minimum plate in the stack, you simply glance at the rim of the top plate. Popping a plate automatically exposes the previous minimum beneath it.

The Mental "A-Ha!" Switch:

Stacks are LIFO. The minimum cannot change between pushes and pops. Storing `currentMin` alongside each node (or in a parallel min-stack) guarantees O(1) lookup.

Pattern Trigger:

Whenever asked for O(1) queries on dynamic stack state → Parallel Stack or (Value, State) Node Tuple.

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap push/pop/top: O(1), getMin: O(N)

Standard stack implementation; getMin iterates through the entire stack to find the minimum value. Fails constant time constraint.

Wasted Work: Re-scanning historical elements on every getMin call when LIFO guarantees historical minimums do not change.
The Optimal Breakthrough All operations O(1) Time, O(N) Space

Store (val, currentMin) pairs or maintain a synchronized `minStack` where top is always the running minimum.

Core Invariant: At any stack depth D, the min-tracker stores the minimum of elements from depth 0 to D.
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
1. Linear Scan getMin getMin: O(N) O(N) Scans stack on query; fails O(1) requirement.
2. Parallel Min Stack All O(1) O(2N) Dedicated secondary stack tracking min values.
★ 3. Value-Min Node Pair All O(1) O(N) Single stack of Pair(val, min). Cleanest OOP.

Production Implementations

From Naive to Optimal & Runnable Practice Arena

Strict ordering: Kotlin (Default) → Python → Java across all approaches.

Two Parallel Stacks

Use mainStack for values and minStack where minStack.top() is always the running min.

Time: All operations O(1) Space: O(2N) 
class MinStack() {
    private val stack = ArrayDeque<Int>()
    private val minStack = ArrayDeque<Int>()

    fun push(`val`: Int) {
        stack.addLast(`val`)
        val currentMin = if (minStack.isEmpty()) `val` else minOf(`val`, minStack.last())
        minStack.addLast(currentMin)
    }

    fun pop() {
        stack.removeLast()
        minStack.removeLast()
    }

    fun top(): Int = stack.last()

    fun getMin(): Int = minStack.last()
}
Kotlin Runtime & Memory Nuance:

`ArrayDeque` in Kotlin is high-performance, non-synchronized, and cache-friendly.

class MinStack:
    def __init__(self):
        self.stack = []
        self.min_stack = []

    def push(self, val: int) -> None:
        self.stack.append(val)
        current_min = val if not self.min_stack else min(val, self.min_stack[-1])
        self.min_stack.append(current_min)

    def pop(self) -> None:
        self.stack.pop()
        self.min_stack.pop()

    def top(self) -> int:
        return self.stack[-1]

    def getMin(self) -> int:
        return self.min_stack[-1]
Python Runtime & Memory Nuance:

Two parallel Python lists. Extremely simple and clean for a 5-minute phone screen solution.

import java.util.ArrayDeque;
import java.util.Deque;

class MinStack {
    private Deque<Integer> stack = new ArrayDeque<>();
    private Deque<Integer> minStack = new ArrayDeque<>();

    public MinStack() {}

    public void push(int val) {
        stack.push(val);
        int currentMin = minStack.isEmpty() ? val : Math.min(val, minStack.peek());
        minStack.push(currentMin);
    }

    public void pop() {
        stack.pop();
        minStack.pop();
    }

    public int top() {
        return stack.peek();
    }

    public int getMin() {
        return minStack.peek();
    }
}
Java Runtime & Memory Nuance:

Use `ArrayDeque` rather than `java.util.Stack`. Stack inherits from Vector and has synchronization overhead.

Single Stack with Pair Object

Store an internal Node/Pair holding (value, currentMin) at each level.

Time: All operations O(1) Space: O(N) 
class MinStack() {
    private data class Element(val value: Int, val min: Int)
    private val stack = ArrayDeque<Element>()

    fun push(`val`: Int) {
        val currentMin = if (stack.isEmpty()) `val` else minOf(`val`, stack.last().min)
        stack.addLast(Element(`val`, currentMin))
    }

    fun pop() {
        stack.removeLast()
    }

    fun top(): Int = stack.last().value

    fun getMin(): Int = stack.last().min
}
Kotlin Runtime & Memory Nuance:

Kotlin `data class` keeps value and min tightly coupled, eliminating synchronization bugs between two separate stacks.

Python Runtime & Memory Nuance:

Tuples `(val, current_min)` avoid creating a custom class in Python while maintaining 100% cohesion.

import java.util.ArrayDeque;
import java.util.Deque;

class MinStack {
    private static class Node {
        final int val;
        final int min;
        Node(int val, int min) {
            this.val = val;
            this.min = min;
        }
    }

    private Deque<Node> stack = new ArrayDeque<>();

    public void push(int val) {
        int currentMin = stack.isEmpty() ? val : Math.min(val, stack.peek().min);
        stack.push(new Node(val, currentMin));
    }

    public void pop() {
        stack.pop();
    }

    public int top() {
        return stack.peek().val;
    }

    public int getMin() {
        return stack.peek().min;
    }
}
Java Runtime & Memory Nuance:

Static nested Node class is the canonical enterprise Java pattern for encapsulated linked state.

Optimal: Singly-Linked Head Pointer (Zero Collection Overhead)

Custom singly linked list where head is the stack top and stores min.

Time: All operations O(1) Space: O(N) Minimum Memory Footprint 
class MinStack() {
    private class Node(val value: Int, val min: Int, val next: Node?)
    private var head: Node? = null

    fun push(`val`: Int) {
        val currentMin = if (head == null) `val` else minOf(`val`, head!!.min)
        head = Node(`val`, currentMin, head)
    }

    fun pop() {
        head = head?.next
    }

    fun top(): Int = head!!.value

    fun getMin(): Int = head!!.min
}
Kotlin Runtime & Memory Nuance:

Bypasses standard collection frameworks entirely. Allocating a single Node per push with pointer linking gives the fastest runtime.

class MinStack:
    class Node:
        def __init__(self, val: int, min_val: int, next_node=None):
            self.val = val
            self.min = min_val
            self.next = next_node

    def __init__(self):
        self.head = None

    def push(self, val: int) -> None:
        current_min = val if self.head is None else min(val, self.head.min)
        self.head = self.Node(val, current_min, self.head)

    def pop(self) -> None:
        self.head = self.head.next

    def top(self) -> int:
        return self.head.val

    def getMin(self) -> int:
        return self.head.min
Python Runtime & Memory Nuance:

Custom linked node implementation demonstrates deep data structure mastery without relying on built-in collections.

class MinStack {
    private static class Node {
        int val;
        int min;
        Node next;
        Node(int val, int min, Node next) {
            this.val = val;
            this.min = min;
            this.next = next;
        }
    }

    private Node head = null;

    public void push(int val) {
        int currentMin = (head == null) ? val : Math.min(val, head.min);
        head = new Node(val, currentMin, head);
    }

    public void pop() {
        head = head.next;
    }

    public int top() {
        return head.val;
    }

    public int getMin() {
        return head.min;
    }
}
Java Runtime & Memory Nuance:

The production gold standard for low-overhead stack implementations. Zero array resizing or queue wrappers.

          Phase 1: Clarifying Questions & Edge Cases
          
"I clarify: will pop, top, and getMin always be called on non-empty stacks? Yes, per constraints. What range of integers should we expect? Standard 32-bit signed integers. Must all operations strictly run in O(1) time? Yes, including getMin."

        

        

          Phase 2: Space-Time Strategy Pitch
          
"For space-time trade-off: a standard stack requires O(N) linear scan to find the minimum. To achieve O(1) time for getMin, we trade O(N) additional memory by maintaining a snapshot of the minimum element at each stack depth. We can do this with either a parallel minStack, a Node object containing (value, min), or a custom linked list."

        

        

          Phase 3: Live Coding Narrative
          
"I'll implement the custom Node approach. Each Node holds its value and the minimum at or below its position. For push(x), the new node's min is min(x, head.min). For pop(), we advance head to head.next. For top() and getMin(), we read head.value and head.min directly."

        

        

          Phase 4: Cold Edge-Case Verification
          
"Dry run edge cases: pushing duplicates of the minimum: if we push -2, then -2 again, both nodes correctly record -2 as the minimum; popping one still leaves -2 as the minimum. Everything runs in strict O(1) time with zero array reallocation."

        

      


      

        ⚡ Senior Architectural & Scalability Follow-Up:
        
Senior Scalability: What if memory is extremely constrained and we cannot afford the 2x space overhead? We can use mathematical difference encoding: store (val - currentMin) as a 64-bit long in a single stack, tracking currentMin in a single variable. When popping a negative value, currentMin can be reconstructed in O(1) time without extra memory.
