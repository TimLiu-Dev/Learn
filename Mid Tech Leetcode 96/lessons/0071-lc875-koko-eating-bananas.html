LeetCode #875: Koko Eating Bananas

Official LC #875

Official Problem Statement

Koko loves to eat bananas. There are n piles of bananas, the ith pile has piles[i] bananas. The guards have gone and will come back in h hours.

Koko can decide her bananas-per-hour eating speed of k. Each hour, she chooses some pile of bananas and eats k bananas from that pile. If the pile has less than k bananas, she eats all of them instead and will not eat any more bananas during this hour.

Koko likes to eat slowly but still wants to finish eating all the bananas before the guards return.

Return the minimum integer k such that she can eat all the bananas within h hours.

Example 1: piles = [3,6,7,11], h = 8 → Output: 4

Example 2: piles = [30,11,23,4,20], h = 5 → Output: 30

Example 3: piles = [30,11,23,4,20], h = 6 → Output: 23

Plain-English Translation & Core Nuance

We need to find the minimum eating speed k (bananas/hour). The possible speed k ranges from 1 to `max(piles)`. For any chosen speed k, the hours needed to eat pile p is `ceil(p / k) = (p + k - 1) / k`. If Koko can finish within h hours, this speed is feasible, so we try a slower speed (`high = mid`). If she cannot finish, k is too slow, so we must increase the speed (`low = mid + 1`). This is Binary Search on Answer running in O(N log(maxPile)).

Official Constraints:
  • 1 <= piles.length <= 10^4
  • piles.length <= h <= 10^9
  • 1 <= piles[i] <= 10^9

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
h == piles.length → Koko must eat at speed equal to max(piles) since she can only eat from 1 pile per hour.
Best-Case Early Exit
Huge h h >= sum(piles) → Returns minimum possible speed k = 1.
Worst-Case Full Scan
Large pile sizes up to 10^9 → 64-bit integer arithmetic prevents 32-bit overflow when summing total hours.

💡 The Treadmill Speed Dial

Imagine a treadmill dial with speeds from 1 km/h to 100 km/h. At speed 1, you will take too long and run out of time (guards return). At speed 100, you finish way ahead of schedule, but you are exhausted. You want the slowest possible dial setting that still finishes before the buzzer. You binary search the dial: test the middle speed; if you beat the buzzer, dial it down. If you fail, dial it up.

The Mental "A-Ha!" Switch:

The problem doesn't give us a sorted array, but the ANSWER space [1..maxPile] is strictly sorted! Furthermore, the feasibility function `canFinish(k)` is monotonic: if speed k works, every speed > k also works. This enables Binary Search on Answer.

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(maxPile * N) Time, O(1) Space

Linear search starting from k = 1, incrementing k by 1 until canFinish(k) returns true.

Wasted Work: Testing speeds 1, 2, 3... sequentially. When maxPile = 10^9, 10^13 operations causes severe TLE.
The Optimal Breakthrough O(N log(maxPile)) Time, O(1) Space

Binary Search over range [1..maxPile]. At most 30 feasibility checks, each taking O(N) time.

Core Invariant: The optimal minimum speed k* lies in `[low..high]`. If `hours(mid) <= h`, `high = mid`; else `low = mid + 1`.
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
1. Linear Search O(M * N) O(1) M = 10^9 → catastrophic timeout.
★ 2. Binary Search on Answer O(N log M) O(1) 30 iterations of N ops → under 20ms execution.

From Naive to Optimal & Runnable Practice Arena

★ Approach: Binary Search on Answer (Production Optimal)

Search the monotonic answer range [1..maxPile]. At each midpoint speed, calculate total hours using ceiling division `(p + mid - 1) / mid`. Adjust bounds accordingly.

Time: O(N log(maxPile)) Time Space: O(1) Space 
class Solution {
    fun minEatingSpeed(piles: IntArray, h: Int): Int {
        var low = 1
        var high = piles.maxOrNull() ?: 1

        while (low < high) {
            val mid = (low + high) ushr 1
            if (canFinish(piles, h, mid)) {
                high = mid // Feasible; try to find a smaller speed
            } else {
                low = mid + 1 // Too slow; must eat faster
            }
        }
        return low
    }

    private fun canFinish(piles: IntArray, h: Int, k: Int): Boolean {
        var hours = 0L
        for (p in piles) {
            hours += (p + k - 1L) / k // Ceiling division without float conversion
            if (hours > h) return false
        }
        return true
    }
}

class Solution:
    def minEatingSpeed(self, piles: list[int], h: int) -> int:
        low, high = 1, max(piles)

        while low < high:
            mid = (low + high) // 2
            # Sum hours needed for speed mid
            hours = sum((p + mid - 1) // mid for p in piles)
            if hours <= h:
                high = mid  # Can finish, try smaller speed
            else:
                low = mid + 1  # Cannot finish, must speed up

        return low

class Solution {
    public int minEatingSpeed(int[] piles, int h) {
        int low = 1;
        int high = 1;
        for (int p : piles) {
            if (p > high) high = p;
        }

        while (low < high) {
            int mid = (low + high) >>> 1;
            if (canFinish(piles, h, mid)) {
                high = mid;
            } else {
                low = mid + 1;
            }
        }
        return low;
    }

    private boolean canFinish(int[] piles, int h, int k) {
        long hours = 0;
        for (int p : piles) {
            hours += (p + k - 1L) / k; // Ceiling division
            if (hours > h) return false;
        }
        return true;
    }
}

""The key insight is that the search space is monotonic: if a speed k works, any speed greater than k also works. If speed k does not work, no speed less than k can work.
