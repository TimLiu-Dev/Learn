Problem #55: Jump Game

View on NeetCode ↗

Official Problem Statement

You are given an integer array nums. You are initially positioned at the array's first index, and each element in the array represents your maximum jump length at that position.

Return true if you can reach the last index, or false otherwise.

Example 1: nums = [2,3,1,1,4] → Output: true

Example 2: nums = [3,2,1,0,4] → Output: false

Plain-English Translation & Core Nuance

Starting at index 0, where nums[i] tells you the furthest number of steps you can jump forward from i, determine if it is possible to reach the final index n - 1 without getting trapped on a 0.

Official Constraints:
  • 1 <= nums.length <= 10^4
  • 0 <= nums[i] <= 10^5

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
nums = [0] -> Already at the last index (0 == n - 1), returns true immediately.
Best-Case Early Exit
nums = [10, 0, 0, 0] -> First jump reaches beyond n - 1 immediately.
Worst-Case Full Scan
nums = [3, 2, 1, 0, 4] -> All jumps funnel into index 3 (val 0), leaving index 4 unreachable.

The Mental Model & "Explain Like I'm 12"

💡 The Expanding Gas Tank Horizon

Instead of guessing which specific jump length to pick at each stone, imagine an expanding 'reachable horizon' (maxReach). As you walk index by index from left to right, first check: 'Is my current index i beyond maxReach?' If i > maxReach, you hit a chasm you could never cross! Otherwise, standing on stone i lets you push the horizon out to max(maxReach, i + nums[i]).

The Mental "A-Ha!" Switch:

Because jumping UP TO nums[i] steps means every intermediate index between i and i + nums[i] is reachable, the reachable set is always a single contiguous prefix [0 .. maxReach]!

Pattern Trigger:

Determining reachability across sequential steps where each position grants a maximum forward range.

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(2^N) Backtracking / O(N^2) DP Time, O(N) Space

Try every possible jump from 1..nums[i] recursively (or with a boolean dp[] table marking reachable indices).

Wasted Work: Repeatedly marks the same overlapping index ranges as reachable in O(N^2) nested loops.
The Optimal Breakthrough O(N) Time, O(1) Space

Track a single integer maxReach = 0. Iterate i from 0 to n - 1: if i > maxReach return false; update maxReach = maxOf(maxReach, i + nums[i]); if maxReach >= n - 1 return true.

Core Invariant: At step i, every index in [0 .. maxReach] is guaranteed reachable from index 0.
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
Naive: Recursive DFS Backtracking O(2^N) O(N) Exponential branching across jump choices; TLE immediately.
Better: 1D Dynamic Programming O(N^2) O(N) Marks dp[i + j] = true; still quadratic when jump lengths are large.
Optimal: Greedy Farthest Horizon (maxReach) O(N) O(1) ★ Single pass, 1 integer variable, early exit as soon as maxReach >= n - 1.

3. Invariant Maintenance & State Transition

I'll initialize maxReach = 0 and loop i from 0 to nums.lastIndex. First, if i > maxReach, index i is unreachable so we return false. Otherwise we update maxReach = maxOf(maxReach, i + nums[i]), and if maxReach >= nums.lastIndex we exit early with true. Throughout every transition, we preserve the core invariant: At step i, every index in [0 .. maxReach] is guaranteed reachable from index 0.

4. Termination & Output Guarantee

Check for early-exit conditions (nums = [10, 0, 0, 0] -> First jump reaches beyond n - 1 immediately.). Once traversal completes, return the accumulated result. No matter which path you take from 0, 1, or 2, the maximum reachable index never exceeds 3.

From Naive to Optimal & Runnable Practice Arena

Approach 1: Dynamic Programming (Bottom-Up Reachability)

Allocate a BooleanArray dp where dp[i] is true if index i can reach the end, checking all jump steps 1..nums[i].

Time: O(N^2) Space: O(N) 
class Solution {
    fun canJump(nums: IntArray): Boolean {
        val n = nums.size
        val dp = BooleanArray(n)
        dp[n - 1] = true

        for (i in n - 2 downTo 0) {
            val furthest = minOf(n - 1, i + nums[i])
            for (next in i + 1..furthest) {
                if (dp[next]) {
                    dp[i] = true
                    break
                }
            }
        }
        return dp[0]
    }
}
Kotlin Runtime & Memory Nuance:

Inner loop scans up to nums[i] steps even though we only care about the leftmost 'true' goal post.

class Solution:
    def canJump(self, nums: list[int]) -> bool:
        n = len(nums)
        dp = [False] * n
        dp[n - 1] = True
        for i in range(n - 2, -1, -1):
            furthest = min(n - 1, i + nums[i])
            for j in range(i + 1, furthest + 1):
                if dp[j]:
                    dp[i] = True
                    break
        return dp[0]
Python Runtime & Memory Nuance:

O(N^2) worst case when elements near the end cannot reach n - 1.

class Solution {
    public boolean canJump(int[] nums) {
        int n = nums.length;
        boolean[] dp = new boolean[n];
        dp[n - 1] = true;
        for (int i = n - 2; i >= 0; i--) {
            int furthest = Math.min(n - 1, i + nums[i]);
            for (int j = i + 1; j <= furthest; j++) {
                if (dp[j]) {
                    dp[i] = true;
                    break;
                }
            }
        }
        return dp[0];
    }
}
Java Runtime & Memory Nuance:

Allocates an unnecessary O(N) boolean array.

Approach 2: Greedy Farthest Reachable Horizon

Maintain maxReach in a single forward pass. If i > maxReach, return false; otherwise extend maxReach = max(maxReach, i + nums[i]).

Time: O(N) Space: O(1) 
class Solution {
    fun canJump(nums: IntArray): Boolean {
        var maxReach = 0
        for (i in nums.indices) {
            if (i > maxReach) return false
            maxReach = maxOf(maxReach, i + nums[i])
            if (maxReach >= nums.lastIndex) return true
        }
        return true
    }
}
Kotlin Runtime & Memory Nuance:

Early exit when maxReach >= nums.lastIndex skips scanning the remaining tail.

class Solution:
    def canJump(self, nums: list[int]) -> bool:
        max_reach = 0
        last_idx = len(nums) - 1
        for i, jump in enumerate(nums):
            if i > max_reach:
                return False
            if i + jump > max_reach:
                max_reach = i + jump
            if max_reach >= last_idx:
                return True
        return True
Python Runtime & Memory Nuance:

Using an explicit if (i + jump > max_reach) avoids function-call overhead of max() in tight Python loops.

class Solution {
    public boolean canJump(int[] nums) {
        int maxReach = 0;
        int lastIdx = nums.length - 1;
        for (int i = 0; i <= lastIdx; i++) {
            if (i > maxReach) return false;
            maxReach = Math.max(maxReach, i + nums[i]);
            if (maxReach >= lastIdx) return true;
        }
        return true;
    }
}
Java Runtime & Memory Nuance:

Zero heap allocations; strictly O(1) registers.
