LeetCode #19: Remove Nth Node From End of List

Official LC #19

Official Problem Statement

Given the head of a linked list, remove the nth node from the end of the list and return its head.

Example 1: head = [1,2,3,4,5], n = 2 → Output: [1,2,3,5] (node 4 removed)

Example 2: head = [1], n = 1 → Output: []

Example 3: head = [1,2], n = 1 → Output: [1]

Plain-English Translation & Core Nuance

Remove the nth node counting backward from the tail in a single pass. Use a dummy head node to handle deleting the first element. Advance a fast pointer n + 1 steps ahead of a slow pointer. When fast reaches null, slow is positioned exactly right before the node to be deleted.

Official Constraints:
  • The number of nodes in the list is sz.
  • 1 <= sz <= 30
  • 0 <= Node.val <= 100
  • 1 <= n <= sz

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
head = [1], n = 1 → Deleting the only node → returns null.
Best-Case Early Exit
Deleting the head node head = [1, 2], n = 2 → Dummy node sentinel handles smoothly.
Worst-Case Full Scan
Deleting the tail node n = 1 → Slow stops at second to last node, sets next = null.

The Mental Model & "Explain Like I'm 12"

💡 The Fixed-Length Spacing Tape

Imagine two runners connected by a rigid stick of length n + 1. The lead runner (fast) runs down a narrow corridor. The trailing runner (slow) follows behind at the exact same speed, held at fixed distance. When the lead runner hits the dead end (null), the trailing runner is guaranteed to be standing directly in front of the trapdoor (the node before target). The trailing runner reaches over and uncouples the target car.

The Mental "A-Ha!" Switch:

A dummy sentinel node (`dummy.next = head`) eliminates all edge cases for removing the head node. Spacing `fast` ahead of `slow` by `n + 1` steps guarantees that when `fast == null`, `slow.next` is the exact node to bypass.

Pattern Trigger:

Whenever finding or deleting the k-th element from the end of a singly linked list → Offset Two Pointers (Slow & Fast) + Dummy Node.

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(2N) Time (Two Passes), O(1) Space

First pass traverses the list to count total length L. Second pass traverses to index L - n and unlinks the node.

Wasted Work: Traversing the list twice when a single pass with offset pointers can solve it in one go.
The Optimal Breakthrough O(N) Time (Single Pass), O(1) Space

One-pass with fast pointer n + 1 steps ahead of slow. Constant memory, zero backtracking.

Core Invariant: Distance between fast and slow is invariant (n + 1 nodes) throughout the traversal.
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
1. Two-Pass Length Count O(2N) O(1) Scans entire list twice; redundant pass.
★ 2. One-Pass Offset Two Pointers O(N) O(1) Single pass with dummy sentinel node.

Two-Pass Length Counting

First loop counts total length L, second loop advances L - n steps to delete.

Time: O(2N) Space: O(1) 
class Solution {
    fun removeNthFromEnd(head: ListNode?, n: Int): ListNode? {
        val dummy = ListNode(0).apply { next = head }
        var length = 0
        var curr = head
        while (curr != null) {
            length++
            curr = curr.next
        }
        var prev: ListNode? = dummy
        for (i in 0 until length - n) {
            prev = prev?.next
        }
        prev?.next = prev?.next?.next
        return dummy.next
    }
}
Kotlin Runtime & Memory Nuance:

Straightforward two passes. Computes `length - n` explicitly before unlinking.

Optimal: One-Pass Offset Two Pointers (Standard)

Advance fast pointer n + 1 steps ahead of slow with dummy node sentinel.

Time: O(N) (Single Pass) Space: O(1) 
class Solution {
    /**
     * Optimal: One-Pass Offset Two Pointers with Sentinel Dummy Node
     * Time: O(N) - Fast pointer traverses the list exactly once
     * Space: O(1) - Constant auxiliary pointer memory
     */
    fun removeNthFromEnd(head: ListNode?, n: Int): ListNode? {
        val dummy = ListNode(0).apply { next = head }
        var fast: ListNode? = dummy
        var slow: ListNode? = dummy

        // Advance fast pointer n + 1 steps so gap is n + 1
        for (i in 0..n) {
            fast = fast?.next
        }

        // Move both pointers until fast reaches null
        while (fast != null) {
            fast = fast.next
            slow = slow?.next
        }

        // Unlink target node
        slow?.next = slow?.next?.next

        return dummy.next
    }
}
Kotlin Runtime & Memory Nuance:

The sentinel `dummy` node completely eliminates special-case checks for deleting the list head.

    # Optimal: One-Pass Offset Two Pointers

class Solution {
    /**
     * Optimal: One-Pass Offset Two Pointers
     * Time: O(N) - Single traversal
     * Space: O(1)
     */
    public ListNode removeNthFromEnd(ListNode head, int n) {
        ListNode dummy = new ListNode(0, head);
        ListNode fast = dummy;
        ListNode slow = dummy;

        // Gap of n + 1 steps
        for (int i = 0; i <= n; i++) {
            fast = fast.next;
        }

        while (fast != null) {
            fast = fast.next;
            slow = slow.next;
        }

        // Bypass target node
        slow.next = slow.next.next;

        return dummy.next;
    }
}

Recursive Backtracking with Call-Stack Return

Traverse recursively to the end, then count backward on return unwinding.

Time: O(N) Space: O(N) Call Stack 
class Solution {
    private var count = 0

    fun removeNthFromEnd(head: ListNode?, n: Int): ListNode? {
        val dummy = ListNode(0).apply { next = head }
        removeHelper(dummy, n)
        return dummy.next
    }

    private fun removeHelper(node: ListNode?, n: Int) {
        if (node == null) return
        removeHelper(node.next, n)
        count++
        if (count == n + 1) {
            node.next = node.next?.next
        }
    }
}
Kotlin Runtime & Memory Nuance:

Educational recursive solution. Shows how the recursion stack can replace a two-pointer gap.

class Solution:
    def removeNthFromEnd(self, head: Optional[ListNode], n: int) -> Optional[ListNode]:
        count = 0
        dummy = ListNode(0, head)
        
        def helper(node):
            nonlocal count
            if not node:
                return
            helper(node.next)
            count += 1
            if count == n + 1:
                node.next = node.next.next
                
        helper(dummy)
        return dummy.next
Python Runtime & Memory Nuance:

Uses `nonlocal count` to unwind and delete during stack retraction.

class Solution {
    private int count = 0;

    public ListNode removeNthFromEnd(ListNode head, int n) {
        ListNode dummy = new ListNode(0, head);
        helper(dummy, n);
        return dummy.next;
    }

    private void helper(ListNode node, int n) {
        if (node == null) return;
        helper(node.next, n);
        count++;
        if (count == n + 1) {
            node.next = node.next.next;
        }
    }
}
