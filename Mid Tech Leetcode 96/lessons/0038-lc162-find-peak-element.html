LeetCode #162: Find Peak Element

Official LC #162

Official Problem Statement

A peak element is an element that is strictly greater than its neighbors.

Given a 0-indexed integer array nums, find a peak element, and return its index. If the array contains multiple peaks, return the index to any of the peaks.

You may imagine that nums[-1] = nums[n] = -∞. In other words, an element is always considered to be strictly greater than a neighbor that is outside the array.

You must write an algorithm that runs in O(log n) time.

Example 1: nums = [1,2,3,1] → Output: 2 (3 is a peak element and your function should return index 2)

Example 2: nums = [1,2,1,3,5,6,4] → Output: 5 (or index 1, where value is 2)

Plain-English Translation & Core Nuance

Find the index of any local peak (where nums[i] > nums[i-1] and nums[i] > nums[i+1]). You don't need to find the global maximum, just any peak. If nums[mid] < nums[mid + 1], you are on an upward slope, so a peak is guaranteed to exist to the right. If nums[mid] > nums[mid + 1], you are on a downward slope (or at a peak), so a peak exists to the left or at mid.

Official Constraints:
  • 1 <= nums.length <= 1000
  • -2^31 <= nums[i] <= 2^31 - 1
  • nums[i] != nums[i + 1] for all valid i.

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
nums = [1] → Boundary walls are -∞ → index 0 is always a peak.
Best-Case Early Exit
Strictly increasing [1, 2, 3] → Last element is peak (3 > -∞).
Worst-Case Full Scan
Zigzag array [1, 3, 2, 4, 3] → Any of multiple valid peaks acceptable.

The Mental Model & "Explain Like I'm 12"

💡 The Foggy Mountain Climber

Imagine climbing in dense fog where you can only see one foot ahead. If the ground slopes UP to your right (`nums[mid] < nums[mid + 1]`), walking right is guaranteed to lead to a peak (even if the terrain keeps rising all the way to the boundary, the boundary drops off to -∞, creating a peak). If the ground slopes DOWN to your right, you either are at a peak or passed one, so walk left.

The Mental "A-Ha!" Switch:

You do not need a sorted array to use binary search! Because boundaries are -∞, following the rising slope is mathematically guaranteed to terminate at a peak.

Pattern Trigger:

Whenever asked to find a local extrema in O(log N) time on an unsorted array → Slope-Following Binary Search.

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(N) Time, O(1) Space

Linear scan checking where `nums[i] > nums[i+1]`. Fails the strict O(log N) requirement.

Wasted Work: Checking every step instead of skipping half the mountain range based on slope direction.
The Optimal Breakthrough O(log N) Time, O(1) Space

Binary search. If `nums[mid] < nums[mid+1]`, search right (`l = mid + 1`); else search left (`r = mid`).

Core Invariant: The current search interval `[left..right]` contains at least one local peak at all times.
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
1. Linear Scan O(N) O(1) Scans every element; fails logarithmic constraint.
★ 2. Slope Binary Search O(log N) O(1) Optimal. Follows upward slope to peak.

Linear Scan Baseline

First index where nums[i] > nums[i+1] is guaranteed to be a peak.

Time: O(N) Space: O(1) 
class Solution {
    fun findPeakElement(nums: IntArray): Int {
        for (i in 0 until nums.size - 1) {
            if (nums[i] > nums[i + 1]) return i
        }
        return nums.size - 1
    }
}

Optimal: Slope-Following Binary Search (Production Standard)

If nums[mid] < nums[mid+1], climb right; else climb left.

Time: O(log N) Space: O(1) 
class Solution {
    /**
     * Optimal: Slope-Climbing Binary Search
     * Time: O(log N) - Halves mountain search space on each step
     * Space: O(1) - Constant auxiliary memory
     */
    fun findPeakElement(nums: IntArray): Int {
        var left = 0
        var right = nums.size - 1

        while (left < right) {
            val mid = left + (right - left) / 2

            if (nums[mid] < nums[mid + 1]) {
                // Ascending slope: peak is guaranteed to the right
                left = mid + 1
            } else {
                // Descending slope: mid could be a peak, or peak is to the left
                right = mid
            }
        }

        return left
    }
}
Kotlin Runtime & Memory Nuance:

`while (left < right)` ensures `mid + 1` is always a valid array index, eliminating IndexOutOfBoundsException.

class Solution:
    # Optimal: Slope-Following Binary Search
    # Time: O(log N)
    # Space: O(1)
    def findPeakElement(self, nums: list[int]) -> int:
        left = 0
        right = len(nums) - 1
        
        while left < right:
            mid = (left + right) // 2
            
            if nums[mid] < nums[mid + 1]:
                left = mid + 1
            else:
                right = mid
                
        return left
Python Runtime & Memory Nuance:

The canonical Python solution. Converges when left == right.

     * Optimal: Slope-Following Binary Search
     * Time: O(log N)
     * Space: O(1)
     */
    public int findPeakElement(int[] nums) {
        int left = 0;
        int right = nums.length - 1;

            }

Recursive Divide and Conquer

Recursive formulation of slope climbing.

Time: O(log N) Space: O(log N) Call Stack 
class Solution {
    fun findPeakElement(nums: IntArray): Int {
        return search(nums, 0, nums.size - 1)
    }

    private fun search(nums: IntArray, l: Int, r: Int): Int {
        if (l == r) return l
        val mid = l + (r - l) / 2
        return if (nums[mid] < nums[mid + 1]) {
            search(nums, mid + 1, r)
        } else {
            search(nums, l, mid)
        }
    }
}
Kotlin Runtime & Memory Nuance:

Recursive divide and conquer. Elegant proof of convergence.

class Solution:
    def findPeakElement(self, nums: list[int]) -> int:
        def search(l, r):
            if l == r:
                return l
            mid = (l + r) // 2
            if nums[mid] < nums[mid + 1]:
                return search(mid + 1, r)
            return search(l, mid)
            
        return search(0, len(nums) - 1)

          Phase 1: Clarifying Questions & Edge Cases
          
"I clarify: can there be multiple peaks? Yes, returning ANY peak index is acceptable. Are adjacent elements guaranteed to be non-equal? Yes, nums[i] != nums[i + 1]. What are the boundary conditions? nums[-1] = nums[n] = -∞, which guarantees that every array has at least one peak."

        

        

          Phase 2: Space-Time Strategy Pitch
          
"For strategy: a linear scan takes O(N). Because adjacent elements are never equal and boundaries are -∞, if nums[mid] < nums[mid + 1], there is guaranteed to be a peak in the right half (even if the values keep rising all the way to the right boundary). Otherwise, a peak exists at mid or to the left. Thus, we can apply binary search to find a peak in O(log N) time and O(1) space."

        

        

          Phase 3: Live Coding Narrative
          
"I set left = 0, right = nums.length - 1. While left < right: compute mid = left + (right - left) / 2. If nums[mid] < nums[mid + 1], left = mid + 1. Else, right = mid. When left == right, we have converged on a peak, and I return left."

        

        

          Phase 4: Cold Edge-Case Verification
          
"Dry running edge cases: single element [1]: loop does not run, returns 0 (which is a peak since 1 > -∞ on both sides). Strictly ascending [1, 2, 3]: always climbs right, converges on index 2 (val 3). Time complexity is strictly O(log N)."

        

      


      

        ⚡ Senior Architectural & Scalability Follow-Up:
        
Senior Scalability: What if adjacent elements CAN be equal (nums[i] == nums[i+1])? Then slope direction becomes ambiguous on a plateau (e.g. [1, 2, 2, 2, 3] vs [1, 2, 2, 2, 1]); binary search can no longer guarantee O(log N) and degrades to O(N) linear search.
