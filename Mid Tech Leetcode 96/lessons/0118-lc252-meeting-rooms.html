Problem #252: Meeting Rooms

External Judge ↗

Official Problem Statement

Given an array of meeting time intervals where intervals[i] = [starti, endi], determine if a person could attend all meetings.

Note: Back-to-back meetings where end1 == start2 (such as [0, 8] and [8, 10]) do not conflict.

Example 1: intervals = [[0,30],[5,10],[15,20]] → Output: false

Example 2: intervals = [[7,10],[2,4]] → Output: true

Example 3: intervals = [[0,8],[8,10]] → Output: true

Plain-English Translation & Core Nuance

Sort all meetings chronologically by start time, then verify no meeting begins strictly before the previous meeting ends (currStart < prevEnd).

Official Constraints:
  • 0 <= intervals.length <= 10^4
  • intervals[i].length == 2
  • 0 <= start_i < end_i <= 10^6

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
intervals = [] or [[5, 10]] -> 0 or 1 meeting can never conflict -> returns true.
Best-Case Early Exit
After sorting, intervals[1].start < intervals[0].end -> returns false on index 1.
Worst-Case Full Scan
10^4 non-overlapping meetings -> O(N log N) sort + single O(N) adjacent check returns true.

Section 01 • Cognitive Anchor

The Mental Model & "Explain Like I'm 12"

💡 Single-Track Train Schedule

Imagine lining up all reservations on a single conference room calendar in order of start time. You never need to compare every meeting against every other meeting: once sorted by start time, if Meeting i doesn't overlap Meeting i-1 (start_i >= end_{i-1}), it cannot overlap any earlier meeting either because every earlier meeting ended <= end_{i-1}!

The Mental "A-Ha!" Switch:

Sorting by start time reduces N-choose-2 pairwise overlap checks to N - 1 adjacent comparisons: conflict iff intervals[i][0] < intervals[i - 1][1].

Section 02 • Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(N²) Time, O(1) Space

Check every pair (i, j) for overlap using max(start_i, start_j) < min(end_i, end_j).

Wasted Work: Comparing 10^4 intervals pairwise performs ~50 million checks on temporally distant meetings.
The Optimal Breakthrough O(N log N) Time, O(1)–O(N) Sort Space

Sort intervals by start ascending, then check adjacent pairs i = 1..N-1 for intervals[i][0] < intervals[i - 1][1].

Core Invariant: If intervals[0..i-1] are sorted by start and mutually disjoint, their maximum end time is strictly intervals[i - 1][1].
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
Naive: All-Pairs Overlap Check O(N²) O(1) Slow when N = 10^4.
Optimal: Sort by Start + Adjacent Scan O(N log N) O(log N)–O(N) ★ Canonical foundation for every interval problem.

Section 05 • Production Implementations

From Naive to Optimal & Runnable Practice Arena

Strict ordering: Kotlin (Default) → Python → Java across all approaches.

Brute Force: All-Pairs Overlap Check

Checks every pair (i, j) without sorting in O(N²) time.

Time: O(N²) Space: O(1) 
class Solution {
    fun canAttendMeetings(intervals: Array<IntArray>): Boolean {
        for (i in intervals.indices) {
            for (j in i + 1 until intervals.size) {
                if (maxOf(intervals[i][0], intervals[j][0]) < minOf(intervals[i][1], intervals[j][1])) {
                    return false
                }
            }
        }
        return true
    }
}
Kotlin Runtime & Memory Nuance:

In Brute Force: All-Pairs Overlap Check, Kotlin uses unboxed JVM primitive arrays (IntArray / BooleanArray) to eliminate object header overhead.

        return True

Optimal: Sort by Start + Adjacent Boundary Check

Clone/sort intervals by start ascending, then check currStart < prevEnd in one linear scan.

Time: O(N log N) Space: O(N) 
class Solution {
    fun canAttendMeetings(intervals: Array<IntArray>): Boolean {
        if (intervals.size <= 1) return true
        val sorted = intervals.sortedBy { it[0] }
        for (i in 1 until sorted.size) {
            if (sorted[i][0] < sorted[i - 1][1]) return false
        }
        return true
    }
}
Kotlin Runtime & Memory Nuance:

In Optimal: Sort by Start + Adjacent Boundary Check, Kotlin uses unboxed JVM primitive arrays (IntArray / BooleanArray) to eliminate object header overhead.

class Solution:
    def canAttendMeetings(self, intervals: list[list[int]]) -> bool:
        if len(intervals) <= 1:
            return True
        ordered = sorted(intervals, key=lambda iv: iv[0])
        for i in range(1, len(ordered)):
            if ordered[i][0] < ordered[i - 1][1]:
                return False
        return True
Python Runtime & Memory Nuance:

In Optimal: Sort by Start + Adjacent Boundary Check, Python uses clean tuple unpacking and in-place pointer transitions for Meeting Rooms.

import java.util.Arrays;

class Solution {
    public boolean canAttendMeetings(int[][] intervals) {
        if (intervals.length <= 1) return true;
        int[][] sorted = Arrays.copyOf(intervals, intervals.length);
        Arrays.sort(sorted, (a, b) -> Integer.compare(a[0], b[0]));
        for (int i = 1; i < sorted.length; i++) {
            if (sorted[i][0] < sorted[i - 1][1]) return false;
        }
        return true;
    }
}

Live Interview Spoken Script & Mid-Level (L4) Follow-Ups

        
4-phase spoken communication script for Karat, pair-programming screens, and onsite loops.

      


      

        

          Phase 1: Clarifying Constraints
          
First I clarify endpoint inclusivity: if one meeting ends at t=8 and the next starts at t=8, is that allowed? Yes, half-open intervals [start, end) do not conflict at 8 == 8, and empty/single-meeting schedules return true.

        

        

          Phase 2: Space-Time Trade-Off Pitch
          
All-pairs checking costs O(N²). Sorting by start time in O(N log N) means any non-overlapping prefix has its latest end strictly at intervals[i-1][1], so checking adjacent pairs suffices.

        

        

          Phase 3: Clean Implementation Narration
          
I'll ask whether mutating the caller's array is okay or sort a shallow copy with Integer.compare(a[0], b[0])—never a[0] - b[0]—then scan i = 1..n-1 returning false if sorted[i][0] < sorted[i-1][1].

        

        

          Phase 4: Boundary Dry-Run Verification
          
Dry-running [[0,8],[8,10]]: 8 < 8 is false, so it returns true. On [[0,30],[5,10]]: 5 < 30 is true, returning false on i=1.

        

      


      

        ⚡ Mid-Level (L4) Production & Requirement-Pivot Follow-Up:
        
If meetings arrive dynamically as an online booking calendar (LC #729 My Calendar I), sorting on every insert degrades to O(N) per call; instead store bookings in a TreeMap<Int, Int> (start -> end) and check floorEntry(start) and ceilingEntry(start) in O(log N) per booking.
