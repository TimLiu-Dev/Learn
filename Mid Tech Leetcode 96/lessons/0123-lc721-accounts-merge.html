Problem #721: Accounts Merge

External Judge ↗

Official Problem Statement

Given a list of accounts where accounts[i][0] is a person's name and the rest of the elements are emails of that account, merge accounts belonging to the same person.

Two accounts definitely belong to the same person if there is some common email to both accounts. Note that two people may share the same name! Return each merged account as [name, ...sortedUniqueEmails] in any account order.

Example 1: [["John","johnsmith@mail.com","john_newyork@mail.com"],["John","johnsmith@mail.com","john00@mail.com"],["Mary","mary@mail.com"],["John","johnnybravo@mail.com"]] → Output: [["John","john00@mail.com","john_newyork@mail.com","johnsmith@mail.com"],["Mary","mary@mail.com"],["John","johnnybravo@mail.com"]]

Plain-English Translation & Core Nuance

Names are NOT unique IDs—two different Johns can exist! Treat account indices 0..N-1 as Union-Find nodes: map each email -> firstOwnerAccountIdx, and whenever an email was already seen under prevIdx, union(i, prevIdx). Finally group all unique emails by find(ownerIdx), sort each group's emails, and prepend accounts[root][0].

Official Constraints:
  • 1 <= accounts.length <= 1000
  • 2 <= accounts[i].length <= 10
  • accounts[i][0] consists of English letters; emails are valid lowercase ASCII.

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
Single account [["Ada", "b@x.com", "a@x.com", "a@x.com"]] -> Deduplicates and sorts emails to [["Ada", "a@x.com", "b@x.com"]].
Best-Case Early Exit
Two accounts sharing the same name 'John' with ZERO shared emails -> Remain two separate 'John' records!
Worst-Case Full Scan
Transitive chain A-B, B-C, C-D -> Union-Find merges all into one root component in O(E α(N)) + O(E log E) sort.

Section 01 • Cognitive Anchor

The Mental Model & "Explain Like I'm 12"

💡 Customer Identity Resolution via Shared Email Bridges

In real Fintech/Retail identity systems, display names ('John') collide constantly, whereas a verified email is a unique bridge. Number the account rows 0..N-1. As you read every email in row i, look it up in emailToAcc: if nobody claimed it yet, record emailToAcc[email] = i; if row prev already claimed it, union(i, prev) fuses their entire identity clusters! Once all bridges are unioned, every email in emailToAcc jumps straight to its cluster root find(accIdx).

The Mental "A-Ha!" Switch:

Union-Find over account indices 0..N-1 (bridged via emailToFirstAccountIdx map) avoids string-parent maps AND preserves each cluster's display name at accounts[root][0]!

Section 02 • Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(N² · E) Repeated Pairwise Merging

Repeatedly scan all pairs of accounts for intersecting email sets and merge until no pair overlaps.

Wasted Work: A chain of accounts merging at the very last link forces multiple quadratic passes over all sets.
The Optimal Breakthrough O(E · log E) Time, O(E) Space (where E = total emails)

Union-Find over account indices 0..N-1 in O(E · α(N)) + group unique emails by find(idx) + sort each component's emails in O(E log E).

Core Invariant: Two emails e1, e2 belong to the same person iff find(emailToAcc[e1]) == find(emailToAcc[e2]).
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
Alt: Bipartite Email Graph + DFS O(E log E) O(E) Valid and clean; builds adjacency sets between emails.
Optimal: Account-Index Union-Find O(E log E) O(N + E) ★ Integer parent[N] array + single emailToAcc map; minimal memory.

Email Graph Adjacency + Connected-Component DFS

Builds star edges from each account's first email to its other emails, then runs DFS over unvisited emails.

Time: O(E log E) Space: O(E) 
import java.util.ArrayDeque

class Solution {
    fun accountsMerge(accounts: List<List<String>>): List<List<String>> {
        val adj = HashMap<String, MutableList<String>>()
        val emailToName = HashMap<String, String>()
        for (acc in accounts) {
            val name = acc[0]
            val first = acc[1]
            for (j in 1 until acc.size) {
                val em = acc[j]
                emailToName[em] = name
                adj.getOrPut(first) { mutableListOf() }.add(em)
                adj.getOrPut(em) { mutableListOf() }.add(first)
            }
        }
        val visited = HashSet<String>()
        val res = mutableListOf<List<String>>()
        for (em in emailToName.keys) {
            if (!visited.add(em)) continue
            val comp = mutableListOf<String>()
            val q = ArrayDeque<String>()
            q.addLast(em)
            while (q.isNotEmpty()) {
                val cur = q.removeFirst()
                comp.add(cur)
                for (nb in adj[cur] ?: emptyList()) {
                    if (visited.add(nb)) q.addLast(nb)
                }
            }
            comp.sort()
            val row = mutableListOf(emailToName[em]!!)
            row.addAll(comp)
            res.add(row)
        }
        return res
    }
}

In Email Graph Adjacency + Connected-Component DFS, Kotlin uses HashMap for amortized O(1) lookups via getOrPut / getOrDefault; and uses HashSet for O(1) membership checks.

from collections import defaultdict, deque

class Solution:
    def accountsMerge(self, accounts: list[list[str]]) -> list[list[str]]:
        adj = defaultdict(list)
        email_to_name = {}
        for acc in accounts:
            name = acc[0]
            first = acc[1]
            for em in acc[1:]:
                email_to_name[em] = name
                adj[first].append(em)
                adj[em].append(first)
        visited = set()
        res = []
        for em in email_to_name.keys():
            if em in visited:
                continue
            visited.add(em)
            comp = []
            q = deque([em])
            while q:
                cur = q.popleft()
                comp.append(cur)
                for nb in adj[cur]:
                    if nb not in visited:
                        visited.add(nb)
                        q.append(nb)
            comp.sort()
            row = [email_to_name[em]]
            row.extend(comp)
            res.append(row)
        return res

import java.util.*;

class Solution {
    public List<List<String>> accountsMerge(List<List<String>> accounts) {
        Map<String, List<String>> adj = new HashMap<>();
        Map<String, String> emailToName = new HashMap<>();
        for (List<String> acc : accounts) {
            String name = acc.get(0);
            String first = acc.get(1);
            for (int j = 1; j < acc.size(); j++) {
                String em = acc.get(j);
                emailToName.put(em, name);
                adj.computeIfAbsent(first, k -> new ArrayList<>()).add(em);
                adj.computeIfAbsent(em, k -> new ArrayList<>()).add(first);
            }
        }
        Set<String> visited = new HashSet<>();
        List<List<String>> res = new ArrayList<>();
        for (String em : emailToName.keySet()) {
            if (!visited.add(em)) continue;
            List<String> comp = new ArrayList<>();
            Deque<String> q = new ArrayDeque<>();
            q.addLast(em);
            while (!q.isEmpty()) {
                String cur = q.removeFirst();
                comp.add(cur);
                for (String nb : adj.getOrDefault(cur, Collections.emptyList())) {
                    if (visited.add(nb)) q.addLast(nb);
                }
            }
            Collections.sort(comp);
            List<String> row = new ArrayList<>();
            row.add(emailToName.get(em));
            row.addAll(comp);
            res.add(row);
        }
        return res;
    }
}

Optimal: Account-Index Union-Find (Path Compression + Rank)

Unions integer account indices 0..N-1 via emailToAcc, then groups & sorts unique emails per root.

Time: O(E log E) Space: O(N + E) 
class Solution {
    fun accountsMerge(accounts: List<List<String>>): List<List<String>> {
        val n = accounts.size
        val parent = IntArray(n) { it }
        val rank = IntArray(n)

        fun find(x: Int): Int {
            var cur = x
            while (parent[cur] != cur) {
                parent[cur] = parent[parent[cur]]
                cur = parent[cur]
            }
            return cur
        }

        fun union(a: Int, b: Int) {
            val ra = find(a)
            val rb = find(b)
            if (ra == rb) return
            if (rank[ra] < rank[rb]) {
                parent[ra] = rb
            } else if (rank[ra] > rank[rb]) {
                parent[rb] = ra
            } else {
                parent[rb] = ra
                rank[ra]++
            }
        }

        val emailToAcc = HashMap<String, Int>()
        for (i in 0 until n) {
            val acc = accounts[i]
            for (j in 1 until acc.size) {
                val em = acc[j]
                val prev = emailToAcc[em]
                if (prev == null) {
                    emailToAcc[em] = i
                } else {
                    union(i, prev)
                }
            }
        }

        val groups = HashMap<Int, MutableList<String>>()
        for (em in emailToAcc.keys) {
            val root = find(emailToAcc[em]!!)
            groups.getOrPut(root) { mutableListOf() }.add(em)
        }

        val res = mutableListOf<List<String>>()
        for (root in groups.keys) {
            val emails = groups[root]!!
            emails.sort()
            val merged = mutableListOf(accounts[root][0])
            merged.addAll(emails)
            res.add(merged)
        }
        return res
    }
}

In Optimal: Account-Index Union-Find (Path Compression + Rank), Kotlin uses unboxed JVM primitive arrays (IntArray / BooleanArray) to eliminate object header overhead; and uses HashMap for amortized O(1) lookups via getOrPut / getOrDefault.

from collections import defaultdict

class Solution:
    def accountsMerge(self, accounts: list[list[str]]) -> list[list[str]]:
        n = len(accounts)
        parent = list(range(n))
        rank = [0] * n

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def union(a: int, b: int) -> None:
            ra, rb = find(a), find(b)
            if ra == rb:
                return
            if rank[ra] < rank[rb]:
                parent[ra] = rb
            elif rank[ra] > rank[rb]:
                parent[rb] = ra
            else:
                parent[rb] = ra
                rank[ra] += 1

        email_to_acc = {}
        for i in range(n):
            for em in accounts[i][1:]:
                if em not in email_to_acc:
                    email_to_acc[em] = i
                else:
                    union(i, email_to_acc[em])

        groups = defaultdict(list)
        for em, idx in email_to_acc.items():
            groups[find(idx)].append(em)

        res = []
        for root, emails in groups.items():
            emails.sort()
            merged = [accounts[root][0]]
            merged.extend(emails)
            res.append(merged)
        return res

import java.util.*;

class Solution {
    public List<List<String>> accountsMerge(List<List<String>> accounts) {
        int n = accounts.size();
        int[] parent = new int[n];
        int[] rank = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;

        Map<String, Integer> emailToAcc = new HashMap<>();
        for (int i = 0; i < n; i++) {
            List<String> acc = accounts.get(i);
            for (int j = 1; j < acc.size(); j++) {
                String em = acc.get(j);
                Integer prev = emailToAcc.get(em);
                if (prev == null) {
                    emailToAcc.put(em, i);
                } else {
                    union(i, prev, parent, rank);
                }
            }
        }

        Map<Integer, List<String>> groups = new HashMap<>();
        for (Map.Entry<String, Integer> e : emailToAcc.entrySet()) {
            int root = find(e.getValue(), parent);
            groups.computeIfAbsent(root, k -> new ArrayList<>()).add(e.getKey());
        }

        List<List<String>> res = new ArrayList<>();
        for (Map.Entry<Integer, List<String>> g : groups.entrySet()) {
            List<String> emails = g.getValue();
            Collections.sort(emails);
            List<String> row = new ArrayList<>();
            row.add(accounts.get(g.getKey()).get(0));
            row.addAll(emails);
            res.add(row);
        }
        return res;
    }

    private int find(int x, int[] parent) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];
            x = parent[x];
        }
        return x;
    }

    private void union(int a, int b, int[] parent, int[] rank) {
        int ra = find(a, parent), rb = find(b, parent);
        if (ra == rb) return;
        if (rank[ra] < rank[rb]) parent[ra] = rb;
        else if (rank[ra] > rank[rb]) parent[rb] = ra;
        else { parent[rb] = ra; rank[ra]++; }
    }
}
