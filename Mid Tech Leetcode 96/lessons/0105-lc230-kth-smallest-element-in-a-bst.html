Problem #230: Kth Smallest Element in a BST

View on NeetCode ↗

Official Problem Statement

Given the root of a binary search tree, and an integer k, return the kth smallest value (1-indexed) of all the values of the nodes in the tree.

Example 1: root = [3,1,4,null,2], k = 1 → Output: 1

Example 2: root = [5,3,6,2,4,null,null,1], k = 3 → Output: 3

Plain-English Translation & Core Nuance

Find the k-th smallest number in a Binary Search Tree (where k=1 means the very smallest). Because a BST's In-Order traversal (Left -> Node -> Right) visits nodes in strictly sorted ascending order, we just need to stop on the k-th node visited.

Official Constraints:
  • The number of nodes in the tree is n.
  • 1 <= k <= n <= 10^4
  • 0 <= Node.val <= 10^4

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
n = 1, k = 1 -> Single root node returned immediately after 1 left check.
Best-Case Early Exit
k = 1 on balanced BST -> Dive straight down the leftmost spine in O(log N) steps and return.
Worst-Case Full Scan
Right-skewed tree with k = N -> Traverses all N nodes down the right spine.

The Mental Model & "Explain Like I'm 12"

💡 The Iterative Left-Spine Elevator

In a Binary Search Tree, smaller values always live to the left. Imagine taking an elevator all the way down the left wall of a building until you hit the basement (the 1st smallest value). From there, each time you pop a floor from your call stack, you count it as visited, and if that floor has a right hallway, you take the elevator all the way down the left wall of that right hallway. The moment your counter hits k, you step off and return that floor!

The Mental "A-Ha!" Switch:

An In-Order traversal of a BST yields values in sorted ascending order. Using an explicit Stack lets us pause and return immediately at the k-th popped node without visiting the rest of the tree!

Pattern Trigger:

Finding the k-th smallest/largest or sorted predecessor/successor in a BST.

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(N log N) or O(N) Time, O(N) Space

Traverse the entire tree to collect all N node values into an ArrayList, then return list[k - 1].

Wasted Work: Visits all N nodes and allocates an O(N) list even when k = 1 on a 10,000-node tree!
The Optimal Breakthrough O(H + k) Time, O(H) Space (where H = tree height)

Use an iterative stack for In-Order traversal: push all left children down to null, pop a node, decrement k, return node.val if k == 0, and move curr to node.right.

Core Invariant: The k-th node popped from the In-Order stack is guaranteed to be the k-th smallest element in the BST.
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
Naive: Full Tree DFS + Sort O(N log N) O(N) Ignores the BST ordering property completely.
Better: Full In-Order Array Capture O(N) O(N) Uses BST order, but still traverses the entire tree and allocates O(N) memory.
Optimal: Iterative Stack In-Order Early Exit O(H + k) O(H) ★ Halts immediately at the k-th element using only O(H) stack depth.

1. Guard Clauses & State Initialization

Before entering the main loop, verify base boundaries (n = 1, k = 1 -> Single root node returned immediately after 1 left check.) and allocate the primary state containers required for Kth Smallest Element in a BST so that subsequent lookups or pointer updates run in O(1) time.

2. Core Traversal & Decision Rule

Use an iterative stack for In-Order traversal: push all left children down to null, pop a node, decrement k, return node.val if k == 0, and move curr to node.right. At each step, instead of re-scanning elements we already visited, we use our maintained state to make an immediate local decision.

3. Invariant Maintenance & State Transition

I'll initialize an ArrayDeque stack and set curr = root. In our outer loop, an inner while loop pushes curr and advances curr = curr.left until null. Then we pop a node, decrement k, and if k == 0 we immediately return curr.val. Otherwise we advance curr = curr.right. Throughout every transition, we preserve the core invariant: The k-th node popped from the In-Order stack is guaranteed to be the k-th smallest element in the BST.

4. Termination & Output Guarantee

Check for early-exit conditions (k = 1 on balanced BST -> Dive straight down the leftmost spine in O(log N) steps and return.). Once traversal completes, return the accumulated result. Nodes 4, 5, and 6 were never even popped or explored because k reached 0 at Node 3!

Production Implementations

From Naive to Optimal & Runnable Practice Arena

Strict ordering: Kotlin (Default) → Python → Java across all approaches.

Approach 1: Full In-Order List Collection

Run recursive In-Order DFS across the entire tree into a list, then index at k - 1.

Time: O(N) Space: O(N) 
class Solution {
    fun kthSmallest(root: TreeNode?, k: Int): Int {
        val sorted = mutableListOf<Int>()
        fun inorder(node: TreeNode?) {
            if (node == null) return
            inorder(node.left)
            sorted.add(node.`val`)
            inorder(node.right)
        }
        inorder(root)
        return sorted[k - 1]
    }
}
Kotlin Runtime & Memory Nuance:

Simple to write, but wastes O(N) heap space and traverses the right subtree even when k = 1.

Python Runtime & Memory Nuance:

Allocates an O(N) Python list of boxed integers.

import java.util.*;

class Solution {
    public int kthSmallest(TreeNode root, int k) {
        List<Integer> vals = new ArrayList<>();
        inorder(root, vals);
        return vals.get(k - 1);
    }

    private void inorder(TreeNode node, List<Integer> vals) {
        if (node == null) return;
        inorder(node.left, vals);
        vals.add(node.val);
        inorder(node.right, vals);
    }
}
Java Runtime & Memory Nuance:

Boxes every int into java.lang.Integer inside the ArrayList.

Approach 2: Recursive In-Order with Early Pruning

Maintain a mutable counter and answer field during recursion, returning early once count == 0.

Time: O(H + k) Space: O(H) call stack 
class Solution {
    fun kthSmallest(root: TreeNode?, k: Int): Int {
        var remaining = k
        var answer = -1
        fun dfs(node: TreeNode?) {
            if (node == null || remaining == 0) return
            dfs(node.left)
            if (--remaining == 0) {
                answer = node.`val`
                return
            }
            dfs(node.right)
        }
        dfs(root)
        return answer
    }
}
Kotlin Runtime & Memory Nuance:

Local function captures 'remaining' and 'answer' in a Ref$IntRef closure.

class Solution:
    def kthSmallest(self, root: Optional[TreeNode], k: int) -> int:
        self.rem = k
        self.ans = -1
        def dfs(node):
            if not node or self.rem <= 0:
                return
            dfs(node.left)
            self.rem -= 1
            if self.rem == 0:
                self.ans = node.val
                return
            dfs(node.right)
        dfs(root)
        return self.ans
Python Runtime & Memory Nuance:

Uses instance attributes to avoid nonlocal binding boilerplate.

class Solution {
    private int remaining;
    private int answer;

    public int kthSmallest(TreeNode root, int k) {
        this.remaining = k;
        dfs(root);
        return this.answer;
    }

    private void dfs(TreeNode node) {
        if (node == null || remaining <= 0) return;
        dfs(node.left);
        if (--remaining == 0) {
            answer = node.val;
            return;
        }
        dfs(node.right);
    }
}
Java Runtime & Memory Nuance:

Clean recursion, though unwinding the call stack still touches parent frames on the way out.

Approach 3: Iterative Stack In-Order (Zero Unwinding)

Simulate the In-Order call stack explicitly with ArrayDeque and return immediately when --k == 0.

Time: O(H + k) Space: O(H) heap stack 
class Solution {
    fun kthSmallest(root: TreeNode?, k: Int): Int {
        val stack = ArrayDeque<TreeNode>()
        var curr = root
        var rem = k

        while (curr != null || stack.isNotEmpty()) {
            while (curr != null) {
                stack.addLast(curr)
                curr = curr.left
            }
            curr = stack.removeLast()
            if (--rem == 0) {
                return curr.`val`
            }
            curr = curr.right
        }
        return -1
    }
}
Kotlin Runtime & Memory Nuance:

ArrayDeque is faster than java.util.Stack (no synchronized lock overhead) and avoids recursion depth limits.

class Solution:
    def kthSmallest(self, root: Optional[TreeNode], k: int) -> int:
        stack = []
        curr = root
        while curr or stack:
            while curr:
                stack.append(curr)
                curr = curr.left
            curr = stack.pop()
            k -= 1
            if k == 0:
                return curr.val
            curr = curr.right
        return -1
Python Runtime & Memory Nuance:

Python list .append() and .pop() run in amortized O(1) time.

import java.util.*;

class Solution {
    public int kthSmallest(TreeNode root, int k) {
        Deque<TreeNode> stack = new ArrayDeque<>();
        TreeNode curr = root;

        while (curr != null || !stack.isEmpty()) {
            while (curr != null) {
                stack.push(curr);
                curr = curr.left;
            }
            curr = stack.pop();
            if (--k == 0) {
                return curr.val;
            }
            curr = curr.right;
        }
        return -1;
    }
}
Java Runtime & Memory Nuance:

Deque<TreeNode> via ArrayDeque is the standard JVM iterative tree traversal idiom.
