Merge Strings Alternately

View on LeetCode ↗

Problem Description

You are given two strings word1 and word2. Merge the strings by adding letters in alternating order, starting with word1. If a string is longer than the other, append the additional letters onto the end of the merged string.

Return the merged string.

🗣️
Plain-English Translation:

"Zipper two words together one letter at a time, taking from word1, then word2, then word1, and so on. If one word runs out before the other, just paste whatever remains from the longer word directly onto the end."

Official Examples

Example 1 (Equal Lengths):
Input: word1 = "abc", word2 = "pqr"
Output: "apbqcr"
a from word1, p from word2, b from word1, q from word2...
Example 2 (Word2 Longer):
Input: word1 = "ab", word2 = "pqrs"
Output: "apbqrs"
word2 is longer; leftover "rs" is appended onto the end.
Example 3 (Word1 Longer):
Input: word1 = "abcd", word2 = "pq"
Output: "apbqcd"
word1 is longer; leftover "cd" is appended onto the end.
Official Constraints:
  • 1 <= word1.length, word2.length <= 100 (Input is small in LC, but testing senior memory awareness in interviews)
  • word1 and word2 consist of lowercase English letters. (Pure ASCII 'a'-'z', no spaces or surrogate pairs)
The 3 Canonical Input Shapes (Mental Boundary Checks):
1. Symmetrical Balance
word1 = "ab", word2 = "cd"
Both words exhaust simultaneously after exactly 2 alternating pairs. No remainder slice.
2. Word 1 Dominated Tail
word1 = "abcdef", word2 = "z"
word2 exhausts on step 1. Remainder "bcdef" must be appended in a single block.
3. Word 2 Dominated Tail
word1 = "a", word2 = "zxywvu"
word1 exhausts on step 1. Remainder "xywvu" must be appended in a single block.

          🧥 The Real-World Analogy
        

        
The Winter Jacket Zipper Slider

        

          Picture zipping up a winter jacket. The zipper has two tracks of metal teeth: Track 1 (word1) on the left side, and Track 2 (word2) on the right side.
        

        

          As the mechanical slider pulls upward, it grabs one tooth from the left (word1[i]), then locks in one tooth from the right (word2[j]), alternating back and forth with rhythmic precision.
        

        

          What happens if the right side is longer than the left side? The slider finishes locking all the matching teeth from the left, runs out of Track 1 teeth, and then effortlessly slides all remaining teeth from Track 2 straight through to the top.
        

      


      
      

        
        

          

            💡 The "A-Ha!" Switch
          

          
One Condition While-Loop with In-Bounds Checks

          

            Beginners often write convoluted if-else blocks trying to find the shorter string, looping over its length, and then writing a second slice operation.
          

          

            The clean architectural breakthrough is a single loop: while (i < n || j < m). Inside, simply append word1[i++] if i < n, and append word2[j++] if j < m. Clean, branch-free, and handles all unequal lengths naturally!

        02
        

          Algorithmic Trade-offs
          
The Naive Trap (Red) vs. Optimal Breakthrough (Green)

        

      


      

        
        

          

            
              The Naive Trap (String Concatenation +=)
            
            O((N + M)²) Time
          


          
Repeated String Immutability Copies

          

            In Java, Kotlin, and Python, Strings are immutable. Writing result += c allocates a brand new string object in the heap on every single iteration, copying all previous characters over and over.
          


          

            Why this is an interview red flag:
            
    
              
  • Copies 1 + 2 + 3 + \dots + (N + M) = \frac{(N + M)^2}{2} characters in total.
    • 
              
  • Triggers massive Garbage Collection (GC) pauses as thousands of temporary orphan string objects are discarded.
    • 
              
  • Junior candidates often fail FAANG/Mid-Tech screens solely due to this string immutability trap.
    • 
            

          

        


        
        

          

            
              Optimal (StringBuilder / CharArray)
            
            O(N + M) Linear
          


          
Pre-Allocated Mutable Buffer

          

            Pre-size a mutable buffer with exact capacity word1.length + word2.length. Appending each character takes O(1) amortized time.
          


          

            The Engineering Breakthrough:
            
    
              
  • Time drops from O((N + M)²) to strictly O(N + M) linear.
    • 
              
  • Pre-sizing the capacity prevents internal buffer array doubling and reallocations.
    • 
              
  • Zero Garbage Collection pressure during character interleaving.
    •

          Solution Evolution & Production Code
          
From Brute Force to Optimal & Interactive Sandbox

        

      


      
      

        
        

          

            Approach:
            

              
              
              
            

          


          
          

            Time: O(N + M) | Space: O(N + M) • ★ Production Standard
          

        


        
        

          

            
            
            
          


          
        


        
        

          
          
          
          
          

            
class Solution {
    /**
     * Approach 1: Naive String Concatenation (+=)
     * 
     * Time Complexity:  O((N + M)^2) - Copies prior string on each append.
     * Space Complexity: O((N + M)^2) - Intermediate orphan strings in heap.
     * 
     * Anti-Pattern: Never use repeated immutable string concatenation in a loop!
     */
    fun mergeAlternately(word1: String, word2: String): String {
        var result = ""
        var i = 0
        var j = 0

        while (i < word1.length || j < word2.length) {
            if (i < word1.length) result += word1[i++]
            if (j < word2.length) result += word2[j++]
        }

        return result
    }
}

            

              Brute Force Trap Analysis:
              
    
                
  • String Immutability: In Kotlin/Java, result += char translates to creating a new StringBuilder, appending the old string, appending the char, and calling toString().
    • 
                
  • Memory Churn: Discards N + M temporary string objects, forcing frequent Garbage Collection stop-the-world pauses.
    • 
              

            

          


          
          

            
class Solution:
    """
    Approach 1: Naive String Concatenation (+=)
    
    Time Complexity:  O((N + M)^2) in general Python runtimes.
    Space Complexity: O((N + M)^2) intermediate allocations.
    """
    def mergeAlternately(self, word1: str, word2: str) -> str:
        result = ""
        i, j = 0, 0
        n, m = len(word1), len(word2)
        
        while i < n or j < m:
            if i < n:
                result += word1[i]
                i += 1
            if j < m:
                result += word2[j]
                j += 1
                
        return result

            

              Python String Concatenation Breakdown:
              
    
                
  • Although CPython has a small in-place string reallocation optimization when reference count is 1, it is non-standard and fails across PyPy and other implementations.
    • 
                
  • Idiomatic Python builds a list: [], calls .append(), and returns "".join(list).
    • 
              

            

          


          
          

            
class Solution {
    /**
     * Approach 1: Naive String Concatenation (+=)
     * 
     * Time Complexity:  O((N + M)^2)
     * Space Complexity: O((N + M)^2) intermediate heap churn.
     */
    public String mergeAlternately(String word1, String word2) {
        String result = "";
        int i = 0, j = 0;
        int n = word1.length(), m = word2.length();

        while (i < n || j < m) {
            if (i < n) result += word1.charAt(i++);
            if (j < m) result += word2.charAt(j++);
        }

        return result;
    }
}

            

              Java Immutability Warning:
              
    
                
  • Java compiler cannot optimize += inside a while loop with multiple branch conditions into a single StringBuilder.
    • 
              

            

          


          
          
          
          
          

            
class Solution {
    /**
     * Approach 2: Single Index Loop with Math.max
     * 
     * Time Complexity:  O(max(N, M)) = O(N + M)
     * Space Complexity: O(N + M)
     */
    fun mergeAlternately(word1: String, word2: String): String {
        val sb = StringBuilder(word1.length + word2.length)
        val maxLen = maxOf(word1.length, word2.length)

        for (k in 0 until maxLen) {
            if (k < word1.length) sb.append(word1[k])
            if (k < word2.length) sb.append(word2[k])
        }

        return sb.toString()
    }
}

            

              Single Index Tradeoff:
              
    
                
  • Uses a single index k from 0 to max(N, M) instead of tracking two separate pointers.
    • 
                
  • Very concise code, but does redundant index checks on the shorter word once it has already finished.
    • 
              

            

          


          
          

            
class Solution:
    """
    Approach 2: Single Index Loop with max length
    
    Time Complexity:  O(N + M)
    Space Complexity: O(N + M)
    """
    def mergeAlternately(self, word1: str, word2: str) -> str:
        res = []
        n, m = len(word1), len(word2)
        
        for k in range(max(n, m)):
            if k < n:
                res.append(word1[k])
            if k < m:
                res.append(word2[k])
                
        return "".join(res)

            

              Python List Append Breakdown:
              
    
                
  • "".join(res) pre-calculates the exact total character size in C before copying bytes, maximizing memory efficiency.
    • 
              

            

          


          
          

            
class Solution {
    /**
     * Approach 2: Single Index Loop with Math.max
     * 
     * Time Complexity:  O(max(N, M))
     * Space Complexity: O(N + M)
     */
    public String mergeAlternately(String word1, String word2) {
        int n = word1.length(), m = word2.length();
        int max = Math.max(n, m);
        StringBuilder sb = new StringBuilder(n + m);

        for (int k = 0; k < max; k++) {
            if (k < n) sb.append(word1.charAt(k));
            if (k < m) sb.append(word2.charAt(k));
        }

        return sb.toString();
    }
}

            

              Java Single Loop Breakdown:
              
    
                
  • Pre-sizing StringBuilder(n + m) avoids internal array doubling.
    • 
              

            

          


          
          
          
          
          

            
class Solution {
    /**
     * Approach 3: Optimal Two Pointers with Tail Append
     * 
     * Time Complexity:  O(N + M) - Exactly (N + M) character copies.
     * Space Complexity: O(N + M) - Exact-sized buffer with zero reallocation.
     */
    fun mergeAlternately(word1: String, word2: String): String {
        val n = word1.length
        val m = word2.length
        val sb = StringBuilder(n + m)
        var i = 0
        var j = 0

        // Phase 1: Alternate while both strings have characters remaining
        while (i < n && j < m) {
            sb.append(word1[i++])
            sb.append(word2[j++])
        }

        // Phase 2: Append remainder in a single block operation
        if (i < n) sb.append(word1.substring(i))
        if (j < m) sb.append(word2.substring(j))

        return sb.toString()
    }
}

            

              Kotlin Senior Engineering Breakdown:
              
    
                
  • StringBuilder(n + m): Guarantees the internal char[] buffer is allocated once with exact capacity, eliminating resizing.
    • 
                
  • Block Tail Append: When one string is much longer (e.g. word1 = "a", word2 = "bcdefghij"), the while loop breaks after 1 iteration, and the remaining 8 chars are copied via bulk memory operations (System.arraycopy under the hood) rather than per-character checks.
    • 
              

            

          


          
          

            
class Solution:
    """
    Approach 3: Optimal Two Pointers with Tail Slice
    
    Time Complexity:  O(N + M) - Bulk slice copies for tail.
    Space Complexity: O(N + M) - Clean list buffer.
    """
    def mergeAlternately(self, word1: str, word2: str) -> str:
        res = []
        i, j = 0, 0
        n, m = len(word1), len(word2)
        
        while i < n and j < m:
            res.append(word1[i])
            res.append(word2[j])
            i += 1
            j += 1
            
        # Bulk append remaining slice
        if i < n:
            res.append(word1[i:])
        if j < m:
            res.append(word2[j:])
            
        return "".join(res)

            

              Python Senior Engineering Breakdown:
              
    
                
  • Slicing word1[i:] delegates directly to C-level memcpy, executing orders of magnitude faster than iterating in Python.
    • 
                
  • "".join() allocates the final unicode string in a single memory layout.
    • 
              

            

          


          
          

            
class Solution {
    /**
     * Approach 3: Optimal Two Pointers with Tail Substring
     * 
     * Time Complexity:  O(N + M)
     * Space Complexity: O(N + M)
     */
    public String mergeAlternately(String word1, String word2) {
        int n = word1.length();
        int m = word2.length();
        StringBuilder sb = new StringBuilder(n + m);
        int i = 0, j = 0;

        while (i < n && j < m) {
            sb.append(word1.charAt(i++));
            sb.append(word2.charAt(j++));
        }

        if (i < n) sb.append(word1.substring(i));
        if (j < m) sb.append(word2.substring(j));

        return sb.toString();
    }
}

            

              Java Senior Engineering Breakdown:
              
    
                
  • StringBuilder.append(CharSequence, start, end) or bulk substring utilizes hardware vector instructions (AVX-512) for large string copies.
    • 
                
  • Zero heap reallocation occurs throughout execution.
    •

            Phase 1: Clarifying Constraints (Before Typing)
            Duration: ~45 seconds
          

          

            "Let's confirm the constraints: Are word1 and word2 guaranteed to be non-empty? (Yes, length >= 1). Are the characters standard ASCII lowercase? (Yes). Can the lengths be drastically different, like 1 character versus 100 characters? (Yes, and leftover characters must be appended onto the end). Finally, we start with word1's first character, correct? (Yes)."
          

        


        
        

          

            Phase 2: Proposing Approaches & Trading Off
            Duration: ~60 seconds
          

          

            "A naive implementation would use simple string concatenation `result += char`. However, because strings are immutable in Java, Kotlin, and Python, that creates a new string object on every iteration, leading to O((N + M)²) time and unnecessary GC pressure.


            Instead, I will use a mutable StringBuilder pre-sized to `word1.length + word2.length`. Using two pointers i and j, I'll alternate appending characters while both indices are within bounds. Once the shorter string finishes, I will append the entire remaining suffix of the longer string in a single bulk slice. This guarantees O(N + M) linear time and minimal allocations."
          

        


        
        

          

            Phase 3: Coding & Narration
            Duration: ~4 minutes
          

          

            "I'm initializing our StringBuilder with capacity `n + m`. In my loop, as long as `i < n && j < m`, I append `word1[i++]` followed by `word2[j++]`. After the loop terminates, at most one string has remaining characters. I append `word1.substring(i)` and `word2.substring(j)` and return `sb.toString()`."
          

        


        
        

          

            Phase 4: Verification & Edge Cases
            Duration: ~60 seconds
          

          

            "Let's trace two edge cases: First, equal lengths: word1 = 'ab', word2 = 'pq'. The loop runs twice, buffer becomes 'apbq', and both suffixes are empty, returning 'apbq'. Second, word1 is a single letter and word2 is long: word1 = 'a', word2 = 'bcde'. Loop runs once ('ab'), word1 is exhausted, and word2's remainder 'cde' is appended directly, yielding 'abcde'. The algorithm is complete and bug-free."
          

        

      


      
      

        

          🚀 Senior Scalability Follow-Up: "What if the words are 50 GB streaming text files?"
        

        

          If you are merging two massive files that cannot fit into memory:
        

        
    
          
  • Buffered Character Streams: Open two BufferedReader streams and a BufferedWriter. Read one character or 8KB buffer block from Stream 1, write it; read one from Stream 2, write it. This executes with O(1) memory consumption regardless of file size.
    • 
          
  • Channel Multiplexing (TCP / Sockets): In network protocols (e.g. HTTP/2 or multiplexed WebSockets), interleaving chunks from multiple streams uses this exact alternating pump model to prevent head-of-line blocking.
