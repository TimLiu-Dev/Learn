LeetCode #33: Search in Rotated Sorted Array

Official LC #33

Official Problem Statement

There is an integer array nums sorted in ascending order (with distinct values).

Prior to being passed to your function, nums is possibly rotated at an unknown pivot index k (1 <= k < nums.length) such that the resulting array is [nums[k], nums[k+1], ..., nums[n-1], nums[0], nums[1], ..., nums[k-1]] (0-indexed). For example, [0,1,2,4,5,6,7] might be rotated at pivot index 3 and become [4,5,6,7,0,1,2].

Given the array nums after the possible rotation and an integer target, return the index of target if it is in nums, or -1 if it is not in nums.

You must write an algorithm with O(log n) runtime complexity.

Example 1: nums = [4,5,6,7,0,1,2], target = 0 → Output: 4

Example 2: nums = [4,5,6,7,0,1,2], target = 3 → Output: -1

Example 3: nums = [1], target = 0 → Output: -1

Plain-English Translation & Core Nuance

In any rotated sorted array, splitting the array at midpoint `mid` guarantees that at least one of the two halves is strictly sorted! We check if the left half is sorted (`nums[low] <= nums[mid]`). If it is, and target lies within `[nums[low]..nums[mid]]`, we search left (`high = mid - 1`); otherwise we search right (`low = mid + 1`). If the left half is not sorted, the right half must be sorted, so we apply the symmetric logic. This maintains O(log N) halving on every step.

Official Constraints:
  • 1 <= nums.length <= 5000
  • -10^4 <= nums[i] <= 10^4
  • All values of nums are unique.
  • nums is an ascending array that is possibly rotated.
  • -10^4 <= target <= 10^4

The Mental Model & "Explain Like I'm 12"

💡 The Two Ramps with a Cliff

Imagine a ramp that was sliced and shifted: you have an ascending ramp on the left, a cliff drop in the middle, and another ascending ramp on the right. If you stand in the middle (`mid`), you look to your left: is the left side a smooth, unbroken ascending ramp (`nums[low] <= nums[mid]`)? If yes, and your target altitude is between `nums[low]` and `nums[mid]`, you stay on that smooth ramp. If not, your target must be on the other side of the cliff.

The Mental "A-Ha!" Switch:

No matter where the pivot split is, the midpoint divides the array such that ONE half is guaranteed to be completely sorted without a pivot. A sorted half is trivially bounded by its endpoints `[low..mid]` or `[mid..high]`, allowing an exact O(1) membership check.

Pattern Trigger:

Search for target in rotated sorted array in O(log N) time → Modified Binary Search checking which half is sorted first.

★ Approach: One-Pass Modified Binary Search (Production Optimal)

Halve the search space in each iteration by determining whether the left half or right half is sorted, then checking if the target lies within the boundaries of the sorted half.

Time: O(log N) Time Space: O(1) Space 
class Solution {
    fun search(nums: IntArray, target: Int): Int {
        var low = 0
        var high = nums.size - 1

        while (low <= high) {
            val mid = (low + high) ushr 1
            if (nums[mid] == target) return mid

            // Check if left half is normally sorted
            if (nums[low] <= nums[mid]) {
                if (target >= nums[low] && target < nums[mid]) {
                    high = mid - 1 // Target is in sorted left half
                } else {
                    low = mid + 1  // Target is in right half
                }
            } else {
                // Right half must be normally sorted
                if (target > nums[mid] && target <= nums[high]) {
                    low = mid + 1  // Target is in sorted right half
                } else {
                    high = mid - 1 // Target is in left half
                }
            }
        }
        return -1
    }
}

class Solution:
    def search(self, nums: list[int], target: int) -> int:
        low, high = 0, len(nums) - 1

        while low <= high:
            mid = (low + high) // 2
            if nums[mid] == target:
                return mid

            # Check if left half is normally sorted
            if nums[low] <= nums[mid]:
                if nums[low] <= target < nums[mid]:
                    high = mid - 1
                else:
                    low = mid + 1
            else:
                # Right half is normally sorted
                if nums[mid] < target <= nums[high]:
                    low = mid + 1
                else:
                    high = mid - 1

        return -1

class Solution {
    public int search(int[] nums, int target) {
        int low = 0;
        int high = nums.length - 1;

        while (low <= high) {
            int mid = (low + high) >>> 1;
            if (nums[mid] == target) return mid;

            // Check if left half is sorted
            if (nums[low] <= nums[mid]) {
                if (target >= nums[low] && target < nums[mid]) {
                    high = mid - 1;
                } else {
                    low = mid + 1;
                }
            } else {
                // Right half is sorted
                if (target > nums[mid] && target <= nums[high]) {
                    low = mid + 1;
                } else {
                    high = mid - 1;
                }
            }
        }
        return -1;
    }
}

""Normally, binary search requires the entire array to be sorted. We can test which half is sorted in O(1): if `nums[low] <= nums[mid]`, the left half is sorted. If target lies in `[nums[low]..nums[mid])`, we narrow search to the left by setting `high = mid - 1`; otherwise, target must be on the right, so `low = mid + 1`.
