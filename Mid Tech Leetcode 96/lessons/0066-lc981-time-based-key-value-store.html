LeetCode #981: Time Based Key-Value Store

Official LC #981

Official Problem Statement

Design a time-based key-value data structure that can store multiple values for the same key at different time stamps and retrieve the key's value at a certain timestamp.

Implement the TimeMap class:

  • TimeMap() Initializes the object of the data structure.
  • void set(String key, String value, int timestamp) Stores the key key with the value value at the given time timestamp.
  • String get(String key, int timestamp) Returns a value such that set was called previously, with timestamp_prev <= timestamp. If there are multiple such values, it returns the value associated with the largest timestamp_prev. If there are no values, it returns "".

Example 1: ["TimeMap", "set", "get", "get", "set", "get", "get"] [[], ["foo", "bar", 1], ["foo", 1], ["foo", 3], ["foo", "bar2", 4], ["foo", 4], ["foo", 5]] → Output: [null, null, "bar", "bar", null, "bar2", "bar2"] Explanation: TimeMap timeMap = new TimeMap(); timeMap.set("foo", "bar", 1); // store the key "foo" and value "bar" along with timestamp = 1. timeMap.get("foo", 1); // return "bar" timeMap.get("foo", 3); // return "bar", since there is no value corresponding to timestamp 3 and timestamp 2, then the only value is at timestamp 1 is "bar". timeMap.set("foo", "bar2", 4); // store the key "foo" and value "bar2" along with timestamp = 4. timeMap.get("foo", 4); // return "bar2" timeMap.get("foo", 5); // return "bar2"

Plain-English Translation & Core Nuance

Store each key's history in a HashMap mapping from key to a dynamic list of (timestamp, value) pairs. Because the problem guarantees timestamps arrive in strictly increasing order, appending to the list is O(1) and the list is always sorted by timestamp. When calling get(key, timestamp), run Binary Search on the list to find the largest timestamp <= query timestamp in O(log M) time.

Official Constraints:
  • 1 <= key.length, value.length <= 100
  • key and value consist of lowercase English letters and digits.
  • 1 <= timestamp <= 10^7
  • All the timestamps timestamp of set are strictly increasing.
  • At most 2 * 10^5 calls will be made to set and get.

💡 The Microfilm Archive with Timeline Index

Imagine a library where each drawer is labeled with a topic (the key). Inside each drawer is a chronological reel of microfilm clippings stamped with exact dates. When someone asks: 'What was the official policy on foo on March 3rd?', you pull drawer 'foo'. Since clippings are filed in chronological order, you don't read them one by one—you binary search to find the latest clipping dated on or before March 3rd.

The Mental "A-Ha!" Switch:

The problem guarantees `set` timestamps are strictly increasing! This means we never need an expensive sorted tree (TreeMap / balanced BST) to keep entries sorted. An ordinary `ArrayList` retains natural sorting at zero overhead, unlocking O(log M) binary search for `get` and O(1) amortized `set`.

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(1) Set, O(M) Get

Store entries in an ArrayList and do a linear scan from end to start looking for timestamp_prev <= timestamp.

Wasted Work: Scanning sequentially through thousands of entries when the list is already sorted (2 \times 10^5 operations).
The Optimal Breakthrough O(1) Set, O(log M) Get

HashMap>. Since set calls arrive chronologically, list is sorted. Binary search (upper bound - 1) in O(log M).

Core Invariant: For any key, `list[i].timestamp < list[i+1].timestamp`. Binary search finds the rightmost index where `list[mid].timestamp <= timestamp`.
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
1. Linear Scan History Set: O(1), Get: O(M) O(N) Times out when multiple gets query long historical chains.
2. TreeMap FloorEntry Set: O(log M), Get: O(log M) O(N) Tree node pointer overhead; set takes O(log M).
★ 3. ArrayList + Binary Search Set: O(1) Amortized, Get: O(log M) O(N) Optimal cache locality; fastest write throughput.

Approach 1: TreeMap FloorEntry (Java / Kotlin)

Use HashMap>. TreeMap's floorEntry(timestamp) retrieves the largest key <= timestamp in O(log M).

Time: Set: O(log M) Space: Get: O(log M) 
import java.util.TreeMap

class TimeMap {
    private val map = HashMap<String, TreeMap<Int, String>>()

    fun set(key: String, value: String, timestamp: Int) {
        map.computeIfAbsent(key) { TreeMap() }[timestamp] = value
    }

    fun get(key: String, timestamp: Int): String {
        val tree = map[key] ?: return ""
        val entry = tree.floorEntry(timestamp) ?: return ""
        return entry.value
    }
}

import java.util.HashMap;
import java.util.Map;
import java.util.TreeMap;

class TimeMap {
    private Map<String, TreeMap<Integer, String>> map;

    public TimeMap() {
        map = new HashMap<>();
    }

    public void set(String key, String value, int timestamp) {
        map.computeIfAbsent(key, k -> new TreeMap<>()).put(timestamp, value);
    }

    public String get(String key, int timestamp) {
        TreeMap<Integer, String> tree = map.get(key);
        if (tree == null) return "";
        Map.Entry<Integer, String> entry = tree.floorEntry(timestamp);
        return entry == null ? "" : entry.getValue();
    }
}

★ Approach 2: HashMap of ArrayList + Manual Binary Search (Production Optimal)

Take advantage of monotonic timestamp ordering in set! Store chronological lists. Appending is O(1). Use binary search to find floor timestamp.

Time: Set: O(1) Amortized Space: Get: O(log M) 
class TimeMap {
    private data class Entry(val timestamp: Int, val value: String)
    private val map = HashMap<String, ArrayList<Entry>>()

    fun set(key: String, value: String, timestamp: Int) {
        map.computeIfAbsent(key) { ArrayList() }.add(Entry(timestamp, value))
    }

    fun get(key: String, timestamp: Int): String {
        val list = map[key] ?: return ""
        var low = 0
        var high = list.size - 1
        var res = ""

        while (low <= high) {

                low = mid + 1

class TimeMap:

        self.store = {}

    def set(self, key: str, value: str, timestamp: int) -> None:
        if key not in self.store:
            self.store[key] = []
        self.store[key].append((timestamp, value))

    def get(self, key: str, timestamp: int) -> str:
        if key not in self.store:
            return ""
        arr = self.store[key]

Pythonic implementation using optimal data structures and built-ins.

import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

class TimeMap {
    private static class Entry {
        final int timestamp;
        final String value;
        Entry(int timestamp, String value) {
            this.timestamp = timestamp;
            this.value = value;
        }
    }

    private final Map<String, List<Entry>> map;

    public TimeMap() {
        map = new HashMap<>();
    }

    public void set(String key, String value, int timestamp) {
        map.computeIfAbsent(key, k -> new ArrayList<>()).add(new Entry(timestamp, value));
    }

    public String get(String key, int timestamp) {
        List<Entry> list = map.get(key);
        if (list == null) return "";

        int low = 0, high = list.size() - 1;
        String res = "";

        while (low <= high) {
            int mid = (low + high) >>> 1;
            if (list.get(mid).timestamp <= timestamp) {
                res = list.get(mid).value;
                low = mid + 1;
            } else {
                high = mid - 1;
            }
        }
        return res;
    }
}

          Phase 2: Space-Time Strategy Pitch
          
""Because timestamps for each key arrive strictly in increasing order, any list of entries we append to is automatically sorted by timestamp. This is a critical insight: we do not need a TreeMap or balanced tree, which would pay an O(log M) cost on every `set`! Instead, we can map each key to an `ArrayList` of (timestamp, value) pairs. `set` is O(1) amortized append. When `get(key, timestamp)` is called, we perform binary search over the array list in O(log M) time to find the largest timestamp <= query timestamp.""

""Tracing with `set("foo", "bar", 1)`. `get("foo", 1)` finds exact match `"bar"`. `get("foo", 3)` checks mid=0 (ts=1 <= 3), records `"bar"`, low becomes 1, loop ends, returns `"bar"`.
