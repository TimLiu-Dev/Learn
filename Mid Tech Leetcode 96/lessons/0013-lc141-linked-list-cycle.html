LeetCode 141: Linked List Cycle

Official LC #141

Official Problem Statement

Given head, the head of a linked list, determine if the linked list has a cycle in it.

There is a cycle in a linked list if there is some node in the list that can be reached again by continuously following the next pointer. Internally, pos is used to denote the index of the node that tail's next pointer is connected to (0-indexed). It is -1 if there is no cycle. Note that pos is not passed as a parameter.

Return true if there is a cycle in the linked list. Otherwise, return false.

Example 1: head = [3,2,0,-4], pos = 1 → Output: true

Example 2: head = [1,2], pos = 0 → Output: true

Example 3: head = [1], pos = -1 → Output: false

Plain-English Translation & Core Nuance

Determine if traversing this linked list will loop forever or eventually reach a dead end (null).

🏃 Relative Velocity Principle: If you place two runners on a circular track where Runner A moves at 1 m/s and Runner B moves at 2 m/s, Runner B's relative velocity is 1 m/s faster. In every time tick, the gap between them shrinks by exactly 1 meter. Therefore, Runner B is mathematically guaranteed to lap and collide with Runner A without skipping over them!
Input Constraints

Node count: [0, 10,000]

Values: -100,000 ≤ val ≤ 100,000

Interviewer expectation: Solve in O(1) extra space without mutating node values.

Null or Single Node

head = [] → false

head = [1] (no cycle) → false

Guard condition: if (head == null || head.next == null) return false;

Self-Loop or Multi-Node Cycle

[1] → [1] (pos = 0) → true

[3 → 2 → 0 → -4 → 2] → true

Fast and slow pointer meet exactly inside the cyclic component.

Tortoise (1x) vs. Hare (2x) Velocity Synchronization

Picture two runners on a track that begins with a straight entry path before merging onto a closed circular loop:

  • The Tortoise (slow): Advances 1 node per iteration (slow = slow.next).
  • The Hare (fast): Advances 2 nodes per iteration (fast = fast.next.next).
  • Open Track (No Cycle): The Hare hits null or fast.next == null in at most N/2 steps. Instant confirmation of false.
  • Closed Loop (Cycle): Once both enter the loop, the relative distance between Hare and Tortoise decreases by 1 node per step until they collide (slow === fast). Instant confirmation of true.

Strategic Contrast

Naive Trap vs. Optimal Breakthrough

❌

The Naive Trap: Visited HashSet or Sentinel Mutation

Approach A stores visited node addresses in a HashSet<ListNode>, consuming \mathcal{O}(N) memory. Approach B mutates node values (e.g. val = 1000001), which destroys production input data and breaks concurrency.

• Approach A Memory: O(N) heap allocations for 10,000 node pointers

• Approach B Penalty: Violates const correctness and causes race conditions

• Both rejected when interviewers specify: "O(1) auxiliary space, non-destructive."

✅

The Breakthrough: Floyd's 2-Pointer Tortoise and Hare

Initialize slow = head and fast = head. While fast != null && fast.next != null, advance slow by 1 step and fast by 2 steps. If slow === fast, return true. If loop exits, return false.

• Time Complexity: O(N) — Fast catches slow in ≤ Cycle Length iterations

• Space Complexity: O(1) strict auxiliary memory (2 reference pointers)

• Completely non-destructive: zero modifications to the input list.

Approach Time Space Mutates Data? Tradeoff Summary
1. Visited HashSet O(N) O(N) No Simple logic, but wastes substantial heap allocation storing pointer references.
2. Sentinel Value Flagging O(N) O(1) Yes (Destructive) Overwrites node values with sentinel (e.g. 1000001); banned in production systems.
3. Floyd's Tortoise & Hare (Optimal) O(N) O(1) No (Read-Only) Universal gold standard. O(N) runtime, zero allocations, leaves list untouched.

Solution Evolution

From HashSet Memory Overhead to In-Place Floyd's Algorithm

Approach 1: Track Visited Nodes in a HashSet

As you traverse, insert each ListNode reference into a HashSet. If a node is already present in the set, a cycle exists. If you reach null, there is no cycle.

Time: O(N) Space: O(N) (stores reference to every node) 
class Solution {
    fun hasCycle(head: ListNode?): Boolean {
        val visited = HashSet<ListNode>()
        var curr = head
        while (curr != null) {
            if (!visited.add(curr)) {
                return true // Already visited this node!
            }
            curr = curr.next
        }
        return false
    }
}
class Solution:
    def hasCycle(self, head: Optional[ListNode]) -> bool:
        visited = set()
        curr = head
        while curr:
            if curr in visited:
                return True
            visited.add(curr)
            curr = curr.next
        return False
public class Solution {
    public boolean hasCycle(ListNode head) {
        Set<ListNode> visited = new HashSet<>();
        ListNode curr = head;
        while (curr != null) {
            if (!visited.add(curr)) {
                return true;

        }
        return false;
    }
}

Approach 2: Destructive Sentinel Value Flagging

Mutates each visited node's value to a magic flag outside the constraint range (e.g. 1000001). If a node with this sentinel is reached again, a cycle is confirmed. Destroys original data and prohibited in concurrent production systems.

Time: O(N) Space: O(1) Danger: Mutates Input Data 
class Solution {
    fun hasCycle(head: ListNode?): Boolean {
        val sentinel = 1000001
        var curr = head
        while (curr != null) {
            if (curr.`val` == sentinel) return true
            curr.`val` = sentinel
            curr = curr.next
        }
        return false
    }
}

Approach 3: Floyd's Tortoise and Hare (Production Optimal)

INTERVIEW DEFAULT

Advances slow by 1 step and fast by 2 steps. If a cycle exists, relative velocity ensures they collide. Zero memory allocations, zero modifications to the list.

Time: O(N) Space: O(1) (Two pointers) Mutates Data: No (Read-Only) 
class Solution {
    fun hasCycle(head: ListNode?): Boolean {
        if (head?.next == null) return false
        
        var slow = head
        var fast = head
        
        while (fast != null && fast.next != null) {
            slow = slow!!.next       // 1 step
            fast = fast.next!!.next  // 2 steps
            
            if (slow === fast) {
                return true         // Hare collided with Tortoise!
            }
        }
        
        return false                 // Fast reached null (dead end)
    }
}
class Solution:
    def hasCycle(self, head: Optional[ListNode]) -> bool:
        if not head or not head.next:
            return False
            
        slow = head
        fast = head
        
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
            if slow == fast:
                return True
                
        return False
public class Solution {
    public boolean hasCycle(ListNode head) {
        if (head == null || head.next == null) return false;
        
        ListNode slow = head;
        ListNode fast = head;
        
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            
            if (slow == fast) {
                return true;
            }
        }
        
        return false;
    }
}

            1. Finding the Cycle Entry Node (LeetCode #142 Math):
            

              Let distance from head to cycle entrance be F, and entrance to collision be a, with cycle length C. Fast runs twice distance of slow: 2(F + a) = F + a + nC \implies F = nC - a. Therefore, if you reset `slow` to `head` and keep `fast` at the collision point, and advance both at 1x speed, they will meet exactly at the cycle entry node after F steps!
            

          

          

            2. Kernel Deadlock & Distributed Dependency Detection:
            

              In OS process schedulers (wait-for graphs) and database transactions (Postgres/MySQL lock managers), cyclic dependencies cause deadlocks. Fast-and-slow pointer techniques and Tarjan's Strongly Connected Components (SCC) detect cyclic transaction deadlocks for victim transaction rollback.
