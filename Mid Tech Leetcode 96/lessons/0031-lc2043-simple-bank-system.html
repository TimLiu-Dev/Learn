LeetCode #2043: Simple Bank System

Official LC #2043

Official Problem Statement

You have been tasked with writing a program for a popular bank that will automate all its operations. The bank has n accounts numbered from 1 to n. The initial balance of each account is stored in a 0-indexed integer array balance of size n, with the (i + 1)th account having an initial balance of balance[i].

Execute all the valid transactions. A transaction is valid if:

  • The given account number(s) are between 1 and n, and
  • The amount of money withdrawn or transferred is less than or equal to the balance of the account.

Implement the Bank class:

  • Bank(long[] balance) Initializes the object with the 0-indexed integer array balance.
  • boolean transfer(int account1, int account2, long money) Transfers money dollars from the account numbered account1 to account2. Return true if the transaction was successful, or false otherwise.
  • boolean deposit(int account, long money) Deposit money dollars into the account numbered account. Return true if the transaction was successful, or false otherwise.
  • boolean withdraw(int account, long money) Withdraw money dollars from the account numbered account. Return true if the transaction was successful, or false otherwise.

Example 1: ["Bank","withdraw","transfer","deposit","transfer","withdraw"] [[[10,100,20,50,30]],[3,10],[5,1,20],[5,20],[3,4,15],[10,50]] → Output: [null,true,true,true,false,false]

Plain-English Translation & Core Nuance

Design an OOP banking ledger class. Accounts are 1-indexed (account k maps to balance[k-1]). Validate account existence (1 <= account <= n) and balance sufficiency before updating. Return true on valid execution, false otherwise. Must handle 64-bit Long balances to avoid overflow.

Official Constraints:
  • n == balance.length
  • 1 <= n <= 10^5
  • 0 <= balance[i] <= 10^12
  • 1 <= account, account1, account2 <= n
  • 0 <= money <= 10^12
  • At most 10^4 calls will be made to each function transfer, deposit, withdraw.

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
Invalid account account > n → Immediately return false without mutating state.
Best-Case Early Exit
Valid transfer with exact balance balance[acc] == money → Account balance becomes 0, return true.
Worst-Case Full Scan
10^12 money transactions → Requires 64-bit integers (Long in Kotlin/Java) to prevent arithmetic overflow.

💡 The Bank Teller Gatekeeper

Think of a bank teller with a ledger binder. For every request, the teller executes three mandatory security checks before touching cash: 1) Does the account number exist in the ledger? 2) Does the destination account exist? 3) Does the sender have enough funds? If any check fails, the teller rejects the slip immediately (returns false) with zero state alteration.

The Mental "A-Ha!" Switch:

1-indexed accounts mapping to a 0-indexed LongArray. Encapsulating an `isValid(account)` helper method ensures clean code and eliminates off-by-one errors across deposit, withdraw, and transfer.

Pattern Trigger:

Whenever designing entity state management with transactional validations → Modular OOP with atomic validation guards.

Direct LongArray with Validation Guards

Store balance array directly and check 1-indexed bounds with helper method.

Time: All operations O(1) Space: O(N) Primitive Storage 
class Bank(private val balance: LongArray) {

    private fun isValid(account: Int): Boolean {
        return account in 1..balance.size
    }

    fun transfer(account1: Int, account2: Int, money: Long): Boolean {
        if (!isValid(account1) || !isValid(account2) || balance[account1 - 1] < money) {
            return false
        }
        balance[account1 - 1] -= money
        balance[account2 - 1] += money
        return true
    }

    fun deposit(account: Int, money: Long): Boolean {
        if (!isValid(account)) return false
        balance[account - 1] += money
        return true
    }

    fun withdraw(account: Int, money: Long): Boolean {
        if (!isValid(account) || balance[account - 1] < money) {
            return false
        }
        balance[account - 1] -= money
        return true
    }
}

Defensive Copying & Encapsulated Account Entities

Model individual Account domain objects with private locks for thread-safe balance mutations.

Time: All operations O(1) Space: O(N) 
class Bank(initialBalances: LongArray) {
    private class Account(val id: Int, var balance: Long)

    private val accounts = Array(initialBalances.size) { i ->
        Account(i + 1, initialBalances[i])
    }

    fun transfer(account1: Int, account2: Int, money: Long): Boolean {
        if (account1 !in 1..accounts.size || account2 !in 1..accounts.size) return false
        val acc1 = accounts[account1 - 1]
        val acc2 = accounts[account2 - 1]

        synchronized(acc1) {
            if (acc1.balance < money) return false
            synchronized(acc2) {
                acc1.balance -= money
                acc2.balance += money
                return true
            }
        }
    }

    fun deposit(account: Int, money: Long): Boolean {
        if (account !in 1..accounts.size) return false
        synchronized(accounts[account - 1]) {
            accounts[account - 1].balance += money
            return true
        }
    }

    fun withdraw(account: Int, money: Long): Boolean {
        if (account !in 1..accounts.size) return false
        val acc = accounts[account - 1]
        synchronized(acc) {
            if (acc.balance < money) return false
            acc.balance -= money
            return true
        }
    }
}

class Bank {
    private static class Account {
        long balance;
        Account(long balance) { this.balance = balance; }
    }

    private final Account[] accounts;

    public Bank(long[] balance) {
        this.accounts = new Account[balance.length];
        for (int i = 0; i < balance.length; i++) {
            accounts[i] = new Account(balance[i]);
        }
    }

    public synchronized boolean transfer(int account1, int account2, long money) {
        if (account1 < 1 || account1 > accounts.length || account2 < 1 || account2 > accounts.length) {
            return false;
        }
        Account a1 = accounts[account1 - 1];
        Account a2 = accounts[account2 - 1];
        if (a1.balance < money) return false;
        a1.balance -= money;
        a2.balance += money;
        return true;
    }

    public synchronized boolean deposit(int account, long money) {
        if (account < 1 || account > accounts.length) return false;
        accounts[account - 1].balance += money;
        return true;
    }

    public synchronized boolean withdraw(int account, long money) {
        if (account < 1 || account > accounts.length) return false;
        Account a = accounts[account - 1];
        if (a.balance < money) return false;
        a.balance -= money;
        return true;

}

Optimal: Zero-Allocation Guarded Array (Production Standard)

Maximum performance with strict guards and zero garbage collection overhead.

Time: All operations O(1) Space: O(1) Auxiliary Memory 
class Bank(private val balance: LongArray) {
    /**
     * Optimal: Zero-Allocation Guarded Primitive LongArray
     * Time: O(1) for all methods
     * Space: O(1) auxiliary memory (in-place)
     */
    private val accountCount = balance.size

    @Suppress("NOTHING_TO_INLINE")
    private inline fun isValid(account: Int): Boolean = account in 1..accountCount

    fun transfer(account1: Int, account2: Int, money: Long): Boolean {
        if (!isValid(account1) || !isValid(account2)) return false
        val idx1 = account1 - 1
        val idx2 = account2 - 1
        if (balance[idx1] < money) return false
        
        balance[idx1] -= money
        balance[idx2] += money
        return true
    }

    fun deposit(account: Int, money: Long): Boolean {
        if (!isValid(account)) return false
        balance[account - 1] += money
        return true
    }

    fun withdraw(account: Int, money: Long): Boolean {
        if (!isValid(account)) return false
        val idx = account - 1
        if (balance[idx] < money) return false
        balance[idx] -= money
        return true
    }
}

class Bank {
    /**
     * Optimal: Direct Primitive Array with Short-Circuit Guards
     * Time: O(1)
     * Space: O(1) auxiliary
     */
    private final long[] b;
    private final int n;

    public Bank(long[] balance) {
        this.b = balance;
        this.n = balance.length;
    }

    public boolean transfer(int account1, int account2, long money) {
        if (account1 < 1 || account1 > n || account2 < 1 || account2 > n) return false;
        int i1 = account1 - 1;
        int i2 = account2 - 1;
        if (b[i1] < money) return false;
        b[i1] -= money;
        b[i2] += money;
        return true;
    }

    public boolean deposit(int account, long money) {
        if (account < 1 || account > n) return false;
        b[account - 1] += money;
        return true;
    }

    public boolean withdraw(int account, long money) {
        if (account < 1 || account > n) return false;
        int i = account - 1;
        if (b[i] < money) return false;
        b[i] -= money;
        return true;
    }
}

        ⚡ Senior Architectural & Scalability Follow-Up:
        
Senior Scalability: In a multi-threaded banking environment, concurrent transfers between account A and B can cause deadlocks if two threads lock them in reverse order (A->B vs B->A). To prevent deadlocks, we must always acquire locks in global consistent order, e.g. `synchronized(min(acc1, acc2)) { synchronized(max(acc1, acc2)) { ... } }`.
