LeetCode #227: Basic Calculator II

Official LC #227

Official Problem Statement

Given a string s which represents an expression, evaluate this expression and return its value. 

The integer division should truncate toward zero.

You may assume that the given expression is always valid. All intermediate results will be in the range of [-2^31, 2^31 - 1].

Note: You are not allowed to use any built-in function which evaluates strings as mathematical expressions, such as eval().

Example 1: s = "3+2*2" → Output: 7

Example 2: s = " 3/2 " → Output: 1

Example 3: s = " 3+5 / 2 " → Output: 5

Plain-English Translation & Core Nuance

Process the string character by character. Maintain the previous operator (initialized to '+') and the current number being formed. When a new operator or the end of the string is reached, apply the PREVIOUS operator: for '+' push num; for '-' push -num; for '*' or '/' pop top of stack, multiply or divide by num, and push result back. Finally, sum all numbers on the stack.

Official Constraints:
  • 1 <= s.length <= 3 * 10^5
  • s consists of integers and operators ('+', '-', '*', '/') separated by some number of spaces.
  • s represents a valid expression.
  • All the integers in the expression are non-negative integers in the range [0, 2^31 - 1].

The Mental Model & "Explain Like I'm 12"

💡 The Immediate Multiplication Workbench

Imagine an accountant entering transactions. Addition and subtraction can wait—you just write them on an invoice with their positive or negative signs. But multiplication and division are urgent contracts: as soon as you see a '*' or '/', you take the last number you wrote down, multiply or divide it immediately, and replace it on the invoice. At the end of the day, you simply sum up the invoice.

The Mental "A-Ha!" Switch:

Operator precedence means '*' and '/' have higher priority than '+' and '-'. By deferring addition and subtraction onto a stack (or running sum) and resolving '*' and '/' immediately against the last operand, we avoid any complex parsing or recursion.

Pattern Trigger:

Arithmetic expression without parentheses, mixed operator precedence (+, -, *, /) → Stack or Two-Variable Deferred Sum.

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(N) Time, O(N) Space

Tokenize the expression into a list of numbers and operators, then make two passes: first pass evaluates * and /, second pass evaluates + and -.

Wasted Work: Allocating intermediate token lists and multiple array passes (2N string and token objects).
The Optimal Breakthrough O(N) Time, O(1) Auxiliary Space

Single pass keeping `lastNum` and `totalSum`. Evaluates high-precedence operators on-the-fly without an explicit stack.

Core Invariant: At each operator boundary, `lastNum` holds the value of the most recent additive term. When '*' or '/' arrives, `lastNum` is updated in-place; when '+' or '-' arrives, `lastNum` is finalized into `totalSum`.
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
1. Two-Pass Tokenizer O(N) O(N) Allocates tokens list and intermediate reduced lists.
2. Explicit Stack O(N) O(N) Pushes all additive terms to stack, then sums at end.
★ 3. O(1) Space Running Accumulator O(N) O(1) Tracks lastNumber and currentSum; zero extra heap allocations.

Approach 1: Explicit Stack (O(N) Time, O(N) Space)

Push numbers onto a stack with their signs. For * and /, pop the top element, perform arithmetic, and push back. Sum stack at the end.

Time: O(N) Time Space: O(N) Space 
import java.util.ArrayDeque

class Solution {
    fun calculate(s: String): Int {
        val stack = ArrayDeque<Int>()
        var curr = 0
        var op = '+'

        for (i in s.indices) {
            val ch = s[i]
            if (ch.isDigit()) {
                curr = curr * 10 + (ch - '0')
            }
            if ((!ch.isDigit() && ch != ' ') || i == s.lastIndex) {
                when (op) {
                    '+' -> stack.push(curr)
                    '-' -> stack.push(-curr)
                    '*' -> stack.push(stack.pop() * curr)
                    '/' -> stack.push(stack.pop() / curr)
                }
                op = ch
                curr = 0
            }
        }

        var res = 0
        while (stack.isNotEmpty()) {
            res += stack.pop()
        }
        return res
    }
}

import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public int calculate(String s) {
        Deque<Integer> stack = new ArrayDeque<>();
        int curr = 0;
        char op = '+';

        for (int i = 0; i < s.length(); i++) {
            char ch = s.charAt(i);
            if (Character.isDigit(ch)) {
                curr = curr * 10 + (ch - '0');
            }
            if ((!Character.isDigit(ch) && ch != ' ') || i == s.length() - 1) {
                if (op == '+') {
                    stack.push(curr);
                } else if (op == '-') {
                    stack.push(-curr);
                } else if (op == '*') {
                    stack.push(stack.pop() * curr);
                } else if (op == '/') {
                    stack.push(stack.pop() / curr);
                }
                op = ch;
                curr = 0;
            }
        }

        int sum = 0;
        while (!stack.isEmpty()) {
            sum += stack.pop();
        }
        return sum;
    }
}

★ Approach 2: O(1) Auxiliary Space Accumulator (Production Optimal)

Keep only `lastNum` and `totalSum`. When encountering '+' or '-', flush `lastNum` into `totalSum`. When encountering '*' or '/', update `lastNum` directly.

Time: O(N) Time Space: O(1) Auxiliary Space 
class Solution {
    fun calculate(s: String): Int {
        var totalSum = 0
        var lastNum = 0
        var curr = 0
        var op = '+'

        for (i in s.indices) {
            val ch = s[i]
            if (ch.isDigit()) {
                curr = curr * 10 + (ch - '0')

                when (op) {
                    '+' -> {
                        totalSum += lastNum
                        lastNum = curr
                    }
                    '-' -> {
                        totalSum += lastNum
                        lastNum = -curr
                    }
                    '*' -> lastNum *= curr
                    '/' -> lastNum /= curr
                }
                op = ch
                curr = 0
            }
        }
        return totalSum + lastNum
    }
}

          Phase 2: Space-Time Strategy Pitch
          
""Because multiplication and division take precedence over addition and subtraction, we must evaluate them immediately. A standard stack approach pushes numbers with their signs, and when '*' or '/' is encountered, pops the top of stack to compute the product or quotient immediately. However, we can optimize this to O(1) auxiliary space! Because there are no parentheses, we only ever need two running numbers: `totalSum` (the accumulated sum of all previous terms) and `lastNum` (the pending product/quotient term being multiplied or divided). When '+' or '-' arrives, we commit `lastNum` into `totalSum` and start a new term. When '*' or '/' arrives, we multiply or divide `lastNum` directly.""

        

        

          Phase 3: Live Coding Narrative
          
""Let me write the code. I initialize `totalSum = 0`, `lastNum = 0`, `curr = 0`, and `op = '+'`. In a loop over the string, if character is a digit, update `curr = curr * 10 + digit`. If character is an operator or we reached the end of string: check `op`. If '+', `totalSum += lastNum; lastNum = curr`. If '-', `totalSum += lastNum; lastNum = -curr`. If '*', `lastNum *= curr`. If '/', `lastNum /= curr`. Then set `op = ch` and `curr = 0`. At the end, return `totalSum + lastNum`.""
