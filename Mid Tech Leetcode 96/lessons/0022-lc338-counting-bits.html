LeetCode 338: Counting Bits

Official LC #338

Official Problem Statement

Given an integer n, return an array ans of length n + 1 such that for each i (0 <= i <= n), ans[i] is the number of 1's in the binary representation of i.

Example 1: n = 2 → Output: [0,1,1]

Example 2: n = 5 → Output: [0,1,1,2,1,2]

Constraints: 0 <= n <= 10^5

Follow-up: Can you do it in linear time O(n) in a single pass without using any built-in popcount functions?

Plain-English Translation & Core Nuance

Return an array containing the set bit count for every single number from 0 up to n.

Evaluating each number independently takes O(n log n) or O(32n). But notice the parent-child relationship in binary:

dp[i] = dp[i >> 1] + (i & 1)

Any number i is simply i >> 1 shifted left with i & 1 appended as its least significant bit. Because i >> 1 < i, the subproblem answer is already computed!

Binary Tree Hierarchy of Right-Shift Subproblems

Number (i)  Binary   i >> 1 (Parent)  LSB (i & 1)  DP Calculation        ans[i]
-------------------------------------------------------------------------------
   0         0000          0              0         dp[0]                 = 0
   1         0001          0              1         dp[0] + 1 = 0 + 1     = 1
   2         0010          1              0         dp[1] + 0 = 1 + 0     = 1
   3         0011          1              1         dp[1] + 1 = 1 + 1     = 2
   4         0100          2              0         dp[2] + 0 = 1 + 0     = 1
   5         0101          2              1         dp[2] + 1 = 1 + 1     = 2
   6         0110          3              0         dp[3] + 0 = 2 + 0     = 2
   7         0111          3              1         dp[3] + 1 = 2 + 1     = 3

Section 1

Mental Model & Pattern Recognition

The Physical Metaphor: Binary Odometer Inheritance

Every integer in binary is generated from a parent integer by appending a single digit at the right end.

Take the number 13 (binary 1101).

Shift right by 1 bit: 13 >> 1 = 6 (binary 110).

The rightmost bit that got dropped was 13 & 1 = 1.

Therefore, the number of 1-bits in 13 is strictly equal to the number of 1-bits in 6, plus 1! Because 6 < 13, its bit count was already computed and is sitting in memory ready for O(1) lookup.

1) Right-shift: dp[i] = dp[i >> 1] + (i & 1) • 2) Lowest bit clear: dp[i] = dp[i & (i - 1)] + 1.

Section 2

Naive Trap vs. Optimal Breakthrough

×

The Naive Trap: Independent Popcount per Number

Running a nested loop that calculates the set bits for each number 0..n independently incurs O(n log n) time.

For n = 10^5, an O(32n) loop executes over 3.2 million bitwise operations.

It throws away the overlapping subproblems already solved by smaller numbers!

✓

The Optimal Breakthrough: 1D Dynamic Programming

By recognizing that i >> 1 has already been computed, each cell requires only 1 addition and 1 bitwise AND:

dp[i] = dp[i >> 1] + (i & 1)

Single pass from 1 to n with strictly 1 operation per integer.

→ O(n) Time, O(1) Auxiliary Space. Cache-friendly sequential memory writes.

Approach Time Complexity Space Complexity Pros Cons
1. Brute Force Popcount O(n × 32) O(1) aux Trivial implementation Fails follow-up linear time requirement
2. DP via High-Order Bit Offset O(n) O(1) aux Linear time complexity Requires tracking power-of-two offset
★ 3. DP via Right-Shift & LSB (Optimal) O(n) O(1) aux Minimal operations, no branch conditions, max speed None — gold standard answer

Section 5

Solution Evolution: From Naive to Optimal

Approach 1: Count Bits Individually

Time: O(n × 32) • Space: O(1) auxiliary space

class Solution {
    fun countBits(n: Int): IntArray {
        val ans = IntArray(n + 1)
        for (i in 0..n) {
            var count = 0
            var temp = i
            while (temp != 0) {
                temp = temp and (temp - 1)
                count++
            }
            ans[i] = count
        }
        return ans
    }
}
class Solution:
    def countBits(self, n: int) -> List[int]:
        ans = [0] * (n + 1)
        for i in range(n + 1):
            count, temp = 0, i
            while temp != 0:
                temp &= (temp - 1)
                count += 1
            ans[i] = count
        return ans
class Solution {
    public int[] countBits(int n) {
        int[] ans = new int[n + 1];
        for (int i = 0; i <= n; i++) {
            int count = 0, temp = i;
            while (temp != 0) {
                temp &= (temp - 1);
                count++;
            }
            ans[i] = count;
        }
        return ans;
    }
}

Approach 2: DP via Most Significant Bit Offset

Time: O(n) • Space: O(1) auxiliary space

class Solution {
    fun countBits(n: Int): IntArray {
        val ans = IntArray(n + 1)
        var offset = 1
        for (i in 1..n) {
            if (offset * 2 == i) {
                offset = i
            }
            ans[i] = 1 + ans[i - offset]
        }
        return ans
    }
}

★ Approach 3: DP via Right-Shift & LSB (Optimal)

Time: O(n) • Space: O(1) auxiliary space

class Solution {
    fun countBits(n: Int): IntArray {
        val ans = IntArray(n + 1)
        // Base case: ans[0] is automatically 0
        for (i in 1..n) {
            // ans[i] inherits set bits from parent (i >> 1) + 1 if i is odd
            ans[i] = ans[i shr 1] + (i and 1)
        }
        return ans
    }
}

    public int[] countBits(int n) {
        int[] ans = new int[n + 1];
        for (int i = 1; i <= n; i++) {
            ans[i] = ans[i >> 1] + (i & 1);
        }
        return ans;
    }
}

Mock Interview Dialogue & Senior Follow-Ups

      


      

        

          
1. Clarification & Constraints:

          
Candidate: "What is the expected behavior for n = 0? And should the output array include n itself?"

          
Interviewer: "For n = 0, return [0]. The output array length is n + 1, covering indices 0 through n."

        


        

          
2. Deriving the DP Recurrence:

          
Candidate: "If we compute each number independently using bit operations, it takes O(n * 32) time. However, any integer i has the exact same bit pattern as (i >> 1), except for the least significant bit (i & 1). Because i >> 1 < i, the bit count for (i >> 1) has already been computed and stored in our DP array. Thus, `ans[i] = ans[i >> 1] + (i & 1)` solves each entry in O(1) time and O(n) overall."

        


        

          
3. Alternative Brian Kernighan Recurrence:

          
Candidate: "Another equally valid recurrence is `ans[i] = ans[i & (i - 1)] + 1`. Since `i & (i - 1)` clears the lowest set bit of i, it always evaluates to a strictly smaller integer whose bit count is already known."

        


        

          
4. Senior Staff Follow-Up: Cache Locality & SIMD Acceleration

          
Interviewer: "Why is the `i >> 1` approach preferred in practice over `i & (i - 1)`?"

          
Candidate: "Both are O(n), but `ans[i >> 1]` accesses index `i / 2`, which is very cache-friendly and predictable for hardware prefetchers. Furthermore, the loop has zero conditional branches: it's pure sequential ALU operations that can be vector-unrolled by LLVM/HotSpot compiler."
