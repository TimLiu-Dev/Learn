Problem #40: Combination Sum II

External Judge ↗

Official Problem Statement

Given a collection of candidate numbers (candidates) and a target number (target), find all unique combinations in candidates where the candidate numbers sum to target.

Each number in candidates may only be used once in the combination.
Note: The solution set must not contain duplicate combinations.

Example 1: candidates = [10,1,2,7,6,1,5], target = 8 → Output: [[1,1,6],[1,2,5],[1,7],[2,6]]

Example 2: candidates = [2,5,2,1,2], target = 5 → Output: [[1,2,2],[5]]

Plain-English Translation & Core Nuance

Unlike Combination Sum I (#39), candidates contains duplicate values AND each array slot can be used at most once. Sort first, advance recursion to i + 1, and skip equal values at the same decision depth (if (i > start && candidates[i] == candidates[i - 1]) continue).

Official Constraints:
  • 1 <= candidates.length <= 100
  • 1 <= candidates[i] <= 50
  • 1 <= target <= 30

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
candidates = [5], target = 5 -> Single exact hit returns [[5]].
Best-Case Early Exit
Sorted pruning: as soon as candidates[i] > rem, break (not just continue) because all later elements are >= candidates[i]!
Worst-Case Full Scan
All 1s [1,1,...,1] (30 copies), target = 15 -> Without sibling pruning, C(30,15) = 155,117,520 branches TLE; with sibling pruning, only 30 linear steps!

Section 01 • Cognitive Anchor

The Mental Model & "Explain Like I'm 12"

💡 Twin Siblings at the Same Fork vs. Parent-and-Child Steps

Sort [1a, 1b, 2, 5, 6, 7, 10]. At the root fork (start = 0), picking 1a explores EVERY combination that begins with a 1 (including [1a, 1b, 6], because at the child fork start = 1, i = 1 == start IS allowed!). When we backtrack to the root fork (start = 0) and reach i = 1 (1b), picking 1b as our first element would only re-generate subsets of combos already found under 1a! Skipping i > start && a[i] == a[i - 1] blocks twin siblings at the same depth while allowing twins down a chain.

The Mental "A-Ha!" Switch:

i > start && candidates[i] == candidates[i - 1] is the surgical invariant: i == start allows using a second copy as a child; i > start blocks re-picking the same value as a sibling!

Pattern Trigger:

Subsets II (#90), Combination Sum II (#40), and 3Sum (#15) — any unique-tuple search over inputs with duplicate numbers.

Section 02 • Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(2^N) Time (TLE on Repeated Values)

Explore all 2^N subsets without pruning duplicates, then deduplicate at the leaves with a HashSet<List<Int>>.

Wasted Work: On thirty 1s with target=15, generating 155 million identical [1,1,...,1] leaves before HashSet deduplication times out.
The Optimal Breakthrough O(2^N) Worst-Case, Exponentially Pruned in Practice

Sort candidates ascending; inside dfs(start, rem), break if candidates[i] > rem, continue if i > start && candidates[i] == candidates[i - 1], and recurse on i + 1.

Core Invariant: At recursion frame start, each distinct value v in candidates[start..N-1] is branched at most once (at its earliest index >= start).
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
Naive: Brute 2^N + HashSet Dedupe O(N · 2^N) O(2^N) TLE on [1,1,...,1] (100 ones) hidden LeetCode test!
Optimal: Sort + Sibling Skip + Early Break O(2^N) tight O(target) stack ★ Collapses [1]*100 from 2^100 down to O(target) calls.

2. Core Traversal & Decision Rule

Sort candidates ascending; inside dfs(start, rem), break if candidates[i] > rem, continue if i > start && candidates[i] == candidates[i - 1], and recurse on i + 1. Instead of re-scanning prior elements, each step makes a local O(1) or O(log N) transition.

3. Invariant Preservation Across Steps

After every update, the core invariant holds: At recursion frame start, each distinct value v in candidates[start..N-1] is branched at most once (at its earliest index >= start).

4. Early Exit & Final Return

Short-circuit immediately when decisive conditions trigger (Sorted pruning: as soon as candidates[i] > rem, break (not just continue) because all later elements are >= candidates[i]!); otherwise complete traversal and return the final state. Notice i=1 WAS explored inside dfs(1, 2) (i == start), and SKIPPED inside dfs(0, 3) (i > start).

Section 05 • Production Implementations

From Naive to Optimal & Runnable Practice Arena

Strict ordering: Kotlin (Default) → Python → Java across all approaches.

Frequency-Counter Group Backtracking

Groups identical numbers into (value, count) pairs and chooses how many copies 0..count to include.

Time: O(2^N) Space: O(N) 
class Solution {
    fun combinationSum2(candidates: IntArray, target: Int): List<List<Int>> {
        val freq = HashMap<Int, Int>()
        for (x in candidates) freq[x] = (freq[x] ?: 0) + 1
        val unique = freq.keys.toList().sorted()
        val res = mutableListOf<List<Int>>()
        val path = mutableListOf<Int>()

        fun dfs(idx: Int, rem: Int) {
            if (rem == 0) {
                res.add(path.toList())
                return
            }
            if (idx == unique.size || unique[idx] > rem) return
            val v = unique[idx]
            val maxCopies = minOf(freq[v] ?: 0, rem / v)
            for (cnt in 0..maxCopies) {
                for (k in 0 until cnt) path.add(v)
                dfs(idx + 1, rem - cnt * v)
                for (k in 0 until cnt) path.removeAt(path.size - 1)
            }
        }
        dfs(0, target)
        return res
    }
}
Kotlin Runtime & Memory Nuance:

In Frequency-Counter Group Backtracking, Kotlin uses unboxed JVM primitive arrays (IntArray / BooleanArray) to eliminate object header overhead; and uses HashMap for amortized O(1) lookups via getOrPut / getOrDefault.

from collections import Counter

class Solution:
    def combinationSum2(self, candidates: list[int], target: int) -> list[list[int]]:
        freq = Counter(candidates)
        unique = sorted(freq.keys())
        res = []
        path = []

        def dfs(idx: int, rem: int) -> None:
            if rem == 0:
                res.append(list(path))
                return
            if idx == len(unique) or unique[idx] > rem:
                return
            v = unique[idx]
            max_copies = min(freq[v], rem // v)
            for cnt in range(max_copies + 1):
                for _ in range(cnt):
                    path.append(v)
                dfs(idx + 1, rem - cnt * v)
                for _ in range(cnt):
                    path.pop()

        dfs(0, target)
        return res

In Frequency-Counter Group Backtracking, Python leverages Python's open-addressed dict hash table for amortized O(1) lookups.

import java.util.*;

class Solution {
    public List<List<Integer>> combinationSum2(int[] candidates, int target) {
        Map<Integer, Integer> freq = new HashMap<>();
        for (int x : candidates) freq.put(x, freq.getOrDefault(x, 0) + 1);
        List<Integer> unique = new ArrayList<>(freq.keySet());
        Collections.sort(unique);
        List<List<Integer>> res = new ArrayList<>();
        dfs(0, target, unique, freq, new ArrayList<>(), res);
        return res;
    }

    private void dfs(int idx, int rem, List<Integer> unique, Map<Integer, Integer> freq, List<Integer> path, List<List<Integer>> res) {
        if (rem == 0) { res.add(new ArrayList<>(path)); return; }
        if (idx == unique.size() || unique.get(idx) > rem) return;
        int v = unique.get(idx);
        int maxCopies = Math.min(freq.get(v), rem / v);
        for (int cnt = 0; cnt <= maxCopies; cnt++) {
            for (int k = 0; k < cnt; k++) path.add(v);
            dfs(idx + 1, rem - cnt * v, unique, freq, path, res);
            for (int k = 0; k < cnt; k++) path.remove(path.size() - 1);
        }
    }
}
Java Runtime & Memory Nuance:

In Frequency-Counter Group Backtracking, Java uses HashMap / HashSet with Java 8+ red-black tree collision fallback; and operates on unboxed primitive Java arrays to avoid Integer autoboxing GC pressure.

Optimal: Sort + Same-Depth Sibling Skip + Early Break

Sorts in-place, breaks when candidates[i] > rem, and skips i > start && candidates[i] == candidates[i - 1].

Time: O(2^N) Space: O(target) stack 
class Solution {
    fun combinationSum2(candidates: IntArray, target: Int): List<List<Int>> {
        candidates.sort()
        val res = mutableListOf<List<Int>>()
        val path = mutableListOf<Int>()

        fun dfs(start: Int, rem: Int) {
            if (rem == 0) {
                res.add(path.toList())
                return
            }
            for (i in start until candidates.size) {
                if (candidates[i] > rem) break
                if (i > start && candidates[i] == candidates[i - 1]) continue
                path.add(candidates[i])
                dfs(i + 1, rem - candidates[i])
                path.removeAt(path.size - 1)
            }
        }

        dfs(0, target)
        return res
    }
}

In Optimal: Sort + Same-Depth Sibling Skip + Early Break, Kotlin uses unboxed JVM primitive arrays (IntArray / BooleanArray) to eliminate object header overhead.

import java.util.*;

class Solution {
    public List<List<Integer>> combinationSum2(int[] candidates, int target) {
        Arrays.sort(candidates);
        List<List<Integer>> res = new ArrayList<>();
        dfs(0, target, candidates, new ArrayList<>(), res);
        return res;
    }

    private void dfs(int start, int rem, int[] candidates, List<Integer> path, List<List<Integer>> res) {
        if (rem == 0) {
            res.add(new ArrayList<>(path));
            return;
        }
        for (int i = start; i < candidates.length; i++) {
            if (candidates[i] > rem) break;
            if (i > start && candidates[i] == candidates[i - 1]) continue;
            path.add(candidates[i]);
            dfs(i + 1, rem - candidates[i], candidates, path, res);
            path.remove(path.size() - 1);
        }
    }
}

Live Interview Spoken Script & Mid-Level (L4) Follow-Ups

        
4-phase spoken communication script for Karat, pair-programming screens, and onsite loops.

      


      

        

          Phase 1: Clarifying Constraints
          
Two critical differences from Combination Sum I (#39): first, each array index can be picked at most once (dfs(i + 1, ...) instead of dfs(i, ...)), and second, candidates contains duplicate values while output combinations must be unique.

        

        

          Phase 2: Space-Time Trade-Off Pitch
          
Generating all 2^N subsets and deduplicating with a Set times out when candidates has dozens of repeated 1s. Sorting first unlocks two optimizations: early break when candidates[i] > rem, and sibling deduplication if (i > start && candidates[i] == candidates[i - 1]) continue.

        

        

          Phase 3: Clean Implementation Narration
          
Notice why i > start (not i > 0!) is the exact condition: when i == start, we are picking the first element at this new depth (allowing [1, 1, 6]), whereas when i > start, we just backtracked from an identical sibling at the exact same depth.

        

        

          Phase 4: Boundary Dry-Run Verification
          
Tracing [1, 1, 1, 1] with target = 2: i=0 picks 1, child i=1 == start picks 1 -> records [1, 1], sibling i=2 > 1 skips, root i=1,2,3 > 0 all skip!

        

      


      

        ⚡ Mid-Level (L4) Production & Requirement-Pivot Follow-Up:
        
If we only needed the *count* of valid combinations (or boolean feasibility) rather than enumerating every list, replace backtracking with 1D 0/1 Knapsack DP (#416) or grouped polynomial DP in O(N * target) time.
