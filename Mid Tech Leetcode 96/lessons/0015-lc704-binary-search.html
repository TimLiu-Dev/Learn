LeetCode 704: Binary Search

Official LC #704

Official Problem Statement

Given an array of integers nums which is sorted in ascending order, and an integer target, write a function to search target in nums. If target exists, then return its index. Otherwise, return -1.

You must write an algorithm with O(log n) runtime complexity.

Example 1: nums = [-1,0,3,5,9,12], target = 9 → Output: 4

Example 2: nums = [-1,0,3,5,9,12], target = 2 → Output: -1

Plain-English Translation & Core Nuance

Find an element in a sorted list by repeatedly checking the middle element. Since the list is sorted, one comparison tells you which entire half of the search space can be permanently eliminated.

⚠️ The Famous 30-Year Integer Overflow Bug: Writing mid = (left + right) / 2 overflows a 32-bit signed integer if left + right > 2,147,483,647. Always calculate midpoint as: mid = left + (right - left) / 2.
Input Constraints

1 ≤ nums.length ≤ 10,000

-10,000 < nums[i], target < 10,000

All integers are unique and sorted ascendingly.

Single Element Case

nums = [5], target = 5 → 0

nums = [5], target = -5 → -1

Must use while (left ≤ right) so that single-element search range [0, 0] is evaluated.

Boundaries (First / Last Index)

target == nums[0] or nums[n-1]

Output: 0 or n - 1

Check extreme boundaries without out-of-bounds indexing.

Strategic Contrast

Naive Trap vs. Optimal Breakthrough

❌

The Naive Trap: Linear Scan & Midpoint Overflow

Traversing for (i in nums.indices) takes O(N) time and fails the explicit problem constraint requiring O(log N). Furthermore, calculating (left + right) / 2 overflows into negative numbers on large arrays.

• Linear Scan: O(N) time — Rejected by problem specification

• Overflow Risk: (2,000,000,000 + 2,000,000,000) = -294,967,296 in 32-bit int

• Infinite Loop Trap: Using `while (left < right)` and `mid = (left + right) / 2` without careful boundary update causes infinite loops.

✅

The Breakthrough: Closed-Interval Binary Search

Define the search interval as [left, right] (inclusive). Loop condition: while (left ≤ right). Safe midpoint: mid = left + (right - left) / 2. If nums[mid] < target, then left = mid + 1. If nums[mid] > target, then right = mid - 1.

• Time Complexity: O(log N) guaranteed (halves search interval every step)

• Space Complexity: O(1) strict auxiliary space

• Invariant: Target must lie within [left, right] if it exists.

1. Linear Scan O(N) O(1) 10,000 Ignores sorted prerequisite; fails O(log N) requirement.

From Linear Search to Overflow-Safe Binary Search

Approach 1: Linear Scan O(N)

Traverses the array from index 0 to N-1. Ignores the prerequisite that nums is already sorted, failing the O(log N) interview requirement.

Time: O(N) Space: O(1) 
class Solution {
    fun search(nums: IntArray, target: Int): Int {
        for (i in nums.indices) {
            if (nums[i] == target) return i
        }
        return -1
    }
}
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        for i, num in enumerate(nums):
            if num == target:
                return i
        return -1
class Solution {
    public int search(int[] nums, int target) {
        for (int i = 0; i < nums.length; i++) {
            if (nums[i] == target) return i;
        }
        return -1;
    }
}

Approach 2: Recursive Binary Search

Calls a recursive helper function passing (left, right) boundaries. Logarithmic time, but costs O(log N) stack frames.

Time: O(log N) Space: O(log N) Call Stack 
class Solution {
    fun search(nums: IntArray, target: Int): Int {
        return binarySearch(nums, target, 0, nums.size - 1)
    }
    
    private fun binarySearch(nums: IntArray, target: Int, left: Int, right: Int): Int {
        if (left > right) return -1
        val mid = left + (right - left) / 2
        return when {
            nums[mid] == target -> mid
            nums[mid] < target -> binarySearch(nums, target, mid + 1, right)
            else -> binarySearch(nums, target, left, mid - 1)
        }
    }
}
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        def helper(left: int, right: int) -> int:
            if left > right:
                return -1
            mid = left + (right - left) // 2
            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                return helper(mid + 1, right)
            else:
                return helper(left, mid - 1)
        return helper(0, len(nums) - 1)
class Solution {
    public int search(int[] nums, int target) {
        return helper(nums, target, 0, nums.length - 1);
    }
    
    private int helper(int[] nums, int target, int left, int right) {
        if (left > right) return -1;
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) return mid;
        else if (nums[mid] < target) return helper(nums, target, mid + 1, right);
        else return helper(nums, target, left, mid - 1);
    }
}

Approach 3: Iterative Closed-Interval Binary Search (Production Optimal)

INTERVIEW DEFAULT

The canonical textbook binary search. Closed interval [left, right], condition while (left ≤ right), safe midpoint left + (right - left) / 2. Fast, overflow-safe, zero allocations.

Time: O(log N) Space: O(1) 
class Solution {
    fun search(nums: IntArray, target: Int): Int {
        var left = 0
        var right = nums.size - 1
        
        while (left <= right) {
            // Safe midpoint avoiding (left + right) integer overflow
            val mid = left + (right - left) / 2
            
            when {
                nums[mid] == target -> return mid
                nums[mid] < target -> left = mid + 1   // Discard left half
                else -> right = mid - 1                // Discard right half
            }
        }
        
        return -1 // Target not found
    }
}
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        left, right = 0, len(nums) - 1
        
        while left <= right:
            mid = left + (right - left) // 2
            
            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                left = mid + 1
            else:
                right = mid - 1
                
        return -1
class Solution {
    public int search(int[] nums, int target) {
        int left = 0;
        int right = nums.length - 1;
        
        while (left <= right) {
            int mid = left + (right - left) / 2;
            
            if (nums[mid] == target) {
                return mid;
            } else if (nums[mid] < target) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
        
        return -1;
    }
}

            "I will use an inclusive closed-interval binary search [left, right] with loop condition while (left ≤ right).           Phase 3: Trace Edge Case Walkthrough
          

            "Consider a single-element array nums = [5], target = 5. left = 0, right = 0. left ≤ right is true! mid = 0 + (0-0)/2 = 0. nums[0] == 5 matches target, returns 0 immediately. If target were 2, right becomes -1, loop terminates, returns -1. The inclusive interval handles size 1 naturally."
          

        


        

          Phase 4: Conclude & Space-Time Bounds
          

            "Time complexity is strictly O(log N) because the search space is divided by 2 on every iteration. For 10,000 elements, at most 14 comparisons are executed. Space complexity is O(1) auxiliary memory since only three scalar variables (left, right, mid) are retained."

          Senior Scalability & System Follow-Ups
        

        

          

            1. Database B+ Trees & SSTable Index Lookups:
            

              In LSM-tree storage engines (RocksDB, Cassandra, Bigtable), on-disk Sorted String Tables (SSTables) maintain an in-memory block index. Binary search finds the candidate 4KB disk block in \mathcal{O}(\log B) memory checks before executing a single disk I/O seek.
            

          

          

            2. Lower Bound vs. Upper Bound (Bisect Left vs. Right):
            

              When duplicates are introduced (LC 34), we search for the leftmost insertion index where `nums[mid] >= target` shrinks `right = mid - 1`. This lower-bound formulation forms the backbone of range queries and percentile histograms.
