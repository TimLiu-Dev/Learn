Problem Statement & Boundary Checks

LeetCode #125 ↗

Verbatim Problem Statement

A phrase is a palindrome if, after converting all uppercase letters into lowercase letters and removing all non-alphanumeric characters, it reads the same forward and backward. Alphanumeric characters include letters and numbers.

Given a string s, return true if it is a palindrome, or false otherwise.

Plain-English Translation

Strip away all spaces, punctuation, symbols, and casing differences. Now, check if the remaining letters and digits form a mirror reflection: the 1st character matches the last, the 2nd matches the 2nd-to-last, and so forth. If they match all the way to the center, return true; the moment any pair mismatches, return false.

Example 1 (Classic True)
Input: s = "A man, a plan, a canal: Panama"
Output: true

Explanation: After removing punctuation and converting to lowercase, it becomes "amanaplanacanalpanama", which is an exact palindrome.

Example 2 (Mismatch False)
Input: s = "race a car"
Output: false

Explanation: Strips down to "raceacar". At index 3 ('e') vs index 4 ('a'), characters mismatch.

Example 3 (Empty / Spaces True)
Input: s = " "
Output: true

Explanation: Strips down to the empty string "". An empty string reads identically forward and backward, so it is valid.

Constraints

  • 1 ≤ s.length ≤ 2 * 105 (200,000 characters)
  • s consists only of printable ASCII characters.

3 Canonical Boundary Check Shapes

1. Punctuation Only: ".,;: ??" → Pointers must safely cross without out-of-bounds error and return true.
2. Single Character: "a" or "Z" → Trivial single-element symmetry, returns true.
3. Immediate Pair Mismatch: "0P" → Lowercases to '0' vs 'p', fails on first iteration, returns false.

The Mental Model & "Explain Like I'm 12"

How to conceptualize inward converging pointers without allocating heap memory.

The Tape Ribbon Pinch Metaphor

Imagine holding a long paper tape printed with letters, spaces, commas, and dots. You place your left index finger at the very start (index 0) and your right index finger at the very end (index length - 1).

Whenever a finger lands on a space, comma, or punctuation mark, it simply glides forward (or backward) to the next alphanumeric character. Punctuation is pure "white noise" to be ignored.

Once both fingers rest on valid characters, you look at them: Are they identical letters or numbers (ignoring capitalization)?

  • Match: Both fingers step inward by 1 position (left++, right--) and repeat.
  • Mismatch: You immediately stop and crumple the ribbon. It cannot possibly be a palindrome! Return false.
  • Fingers Cross (left ≥ right): Every single pair passed inspection. Return true!

The "A-Ha!" Architectural Trigger

Whenever a problem asks for symmetry, palindrome validation, or reversal checks, avoid copying, filtering, or reversing strings. Since strings in memory are random-access indexed arrays, you can evaluate mirror properties in-place in O(1) space by converging two pointers inward.

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

Why string manipulation libraries fail senior-level scrutiny.

The Naive Trap: Regex Replace + Reverse O(N) Extra Memory

Junior engineers frequently write: 

val clean = s.replace(Regex("[^a-zA-Z0-9]"), "").lowercase()
return clean == clean.reversed()
  • Heap Churn: Creates 3 separate brand-new strings on the heap: the regex result, the lowercase copy, and the reversed copy.
  • Garbage Collector Pressure: For large strings (200,000 characters), this allocates over 1.2 megabytes of transient heap garbage.
  • Regex Overhead: Regex engines compile a deterministic finite automaton (DFA) which is significantly slower than simple character range checks.
Interview Verdict: Fails senior memory review
Optimal Breakthrough: In-Place Converging Pointers O(1) Auxiliary Space

Senior engineers inspect the original string in place: 

var left = 0; var right = s.length - 1
while (left < right) {
    while (left < right && !s[left].isLetterOrDigit()) left++
    while (left < right && !s[right].isLetterOrDigit()) right--
    if (s[left].lowercaseChar() != s[right].lowercaseChar()) return false
    left++; right--
}
return true
  • Zero Allocations: Does not allocate a single byte of heap memory. Operates with only 2 integer indices.
  • Single Pass: Each character is examined at most twice (once to skip, once to compare). Exactly O(N) operations.
  • Immediate Early Exit: Returns false on the very first character mismatch without checking the remainder.
Interview Verdict: Top-tier senior benchmark

From Brute Force to Optimal & Interactive Sandbox

Evolution from naive string duplication to in-place zero-allocation pointer convergence.

Approach 1: Regex Replacement & String Reversal

Filter out non-alphanumeric characters with a regular expression, convert to lowercase, and check if the string equals its reverse. While concise in code length, this creates multiple heap copies and incurs substantial garbage collection overhead. 

class Solution {
    fun isPalindrome(s: String): Boolean {
        // Regex strips everything except a-z, A-Z, 0-9
        val clean = s.replace(Regex("[^a-zA-Z0-9]"), "").lowercase()
        return clean == clean.reversed()
    }
}
import re

class Solution:
    def isPalindrome(self, s: str) -> bool:
        # Substitute non-alphanumeric characters, lowercase, and reverse slice
        clean = re.sub(r'[^a-zA-Z0-9]', '', s).lower()
        return clean == clean[::-1]
class Solution {
    public boolean isPalindrome(String s) {
        // Regex replace allocates new String, toLowerCase allocates another
        String clean = s.replaceAll("[^a-zA-Z0-9]", "").toLowerCase();
        String reversed = new StringBuilder(clean).reverse().toString();
        return clean.equals(reversed);
    }
}
Approach 2: Filter into Buffer / List + Two Pointers

Avoids the regex engine and string reversal by manually iterating through s and appending alphanumeric characters into a dynamic buffer (StringBuilder or list). Then, use two pointers inward. Still requires O(N) extra space. 

class Solution {
    fun isPalindrome(s: String): Boolean {
        val clean = StringBuilder()
        for (ch in s) {
            if (ch.isLetterOrDigit()) {
                clean.append(ch.lowercaseChar())
            }
        }
        
        var left = 0
        var right = clean.length - 1
        while (left < right) {
            if (clean[left] != clean[right]) {
                return false
            }
            left++
            right--
        }
        return true
    }
}
class Solution:
    def isPalindrome(self, s: str) -> bool:
        # Filter list comprehension
        clean = [ch.lower() for ch in s if ch.isalnum()]
        left, right = 0, len(clean) - 1
        while left < right:
            if clean[left] != clean[right]:
                return False
            left += 1
            right -= 1
        return True
class Solution {
    public boolean isPalindrome(String s) {
        StringBuilder clean = new StringBuilder();
        for (int i = 0; i < s.length(); i++) {
            char ch = s.charAt(i);
            if (Character.isLetterOrDigit(ch)) {
                clean.append(Character.toLowerCase(ch));
            }
        }
        
        int left = 0;
        int right = clean.length() - 1;
        while (left < right) {
            if (clean.charAt(left) != clean.charAt(right)) {
                return false;
            }
            left++;
            right--;
        }
        return true;
    }
}
Approach 3: In-Place Two Pointers (O(1) Auxiliary Space)

Pinch inward directly on the original string array. Inner while loops advance pointers over non-alphanumerics while safeguarding bounds with left < right. Zero allocations, instant early return. 

class Solution {
    fun isPalindrome(s: String): Boolean {
        var left = 0
        var right = s.length - 1

        while (left < right) {
            // 1. Advance left pointer past non-alphanumeric characters
            while (left < right && !s[left].isLetterOrDigit()) {
                left++
            }
            // 2. Retreat right pointer past non-alphanumeric characters
            while (left < right && !s[right].isLetterOrDigit()) {
                right--
            }

            // 3. Compare characters after normalizing to lowercase
            if (s[left].lowercaseChar() != s[right].lowercaseChar()) {
                return false
            }

            // 4. Advance both pointers inward
            left++
            right--
        }

        return true
    }
}
class Solution:
    def isPalindrome(self, s: str) -> bool:
        left, right = 0, len(s) - 1

        while left < right:
            # 1. Skip non-alphanumeric characters from left
            while left < right and not s[left].isalnum():
                left += 1
            # 2. Skip non-alphanumeric characters from right
            while left < right and not s[right].isalnum():
                right -= 1

            # 3. Case-insensitive comparison
            if s[left].lower() != s[right].lower():
                return False

            # 4. Step both pointers inward
            left += 1
            right -= 1

        return True
class Solution {
    public boolean isPalindrome(String s) {
        int left = 0;
        int right = s.length() - 1;

        while (left < right) {
            // 1. Skip non-alphanumeric characters from left
            while (left < right && !Character.isLetterOrDigit(s.charAt(left))) {
                left++;
            }
            // 2. Skip non-alphanumeric characters from right
            while (left < right && !Character.isLetterOrDigit(s.charAt(right))) {
                right--;
            }

            // 3. Case-insensitive comparison
            if (Character.toLowerCase(s.charAt(left)) != Character.toLowerCase(s.charAt(right))) {
                return false;
            }

            // 4. Step both pointers inward
            left++;
            right--;
        }

        return true;
    }
}
★ Senior Engineering Guardrails

1. Why the inner while loop must re-verify left < right: If the input string is composed entirely of whitespace and punctuation (e.g., " "), an unchecked while (!s[left].isLetterOrDigit()) left++ would increment past s.length - 1 and crash with an IndexOutOfBoundsException.

2. Character normalization without object allocation: In Kotlin, Char.lowercaseChar() returns a primitive Char. In Java, Character.toLowerCase(char) returns a primitive char. Neither triggers any heap allocation or auto-boxing!

Case is insensitive, meaning 'A' equals 'a'. If the string is empty or contains only punctuation, does it count as a palindrome?"

              Phase 2: Naive Critique
              Stating and Dismantling the Naive Approach
            

            

              
You: "The most direct way would be to run a regex replacement to filter out non-alphanumerics, lowercase the string, and compare it with its reverse. However, that allocates O(N) memory across multiple new string instances and compiles a regex DFA. If s is 200,000 characters or streamed over network, that generates unnecessary GC churn."

              
Interviewer: "Good observation. How would you do it without allocating extra memory?"

            

          


          
          

            

              Phase 3: Optimal Pitch
              In-Place Two-Pointer Architecture
            

            

              
You: "We can achieve strictly O(1) auxiliary space using two pointers: left starting at index 0 and right at s.length - 1. In each step, we advance left past any non-alphanumeric character, and decrement right past any non-alphanumeric character. Crucially, each inner skip loop checks left < right to avoid out-of-bounds. Once both land on valid characters, we compare their lowercase values. If they differ, we exit immediately with false. If they match, we step inward and continue until the pointers meet or cross."

              
Interviewer: "Looks solid. Let's write the code."

            

          


          
          

            

              Phase 4: Verification
              Dry Run & Corner Cases
            

            

              
You: "Let's dry run with corner cases: 1) Empty string or string with only spaces "   ": The inner loop increments left until left == right, loop terminates, returns true safely. 2) Single character "a": left == 0, right == 0, loop condition left < right is false, returns true. 3) Two differing characters "0P": compares '0' with 'p', returns false immediately. Time complexity is strictly O(N) with at most N total pointer moves; space complexity is strictly O(1)."

            

          

        


        
        

          

            Senior Scalability Follow-Up: Unicode & UTF-16 Surrogate Pairs
          

          

            In standard ASCII, 1 char equals 1 code point. But what if the interviewer asks: "What if the string contains multi-byte Unicode characters, accented letters (e.g. é vs e + ́), or emojis?"
          

          
    
            
  • Surrogate Pairs: In Java and Kotlin, characters outside the Basic Multilingual Plane (BMP) like emoji (e.g., 😀) occupy two 16-bit code units (char). Indexing by single char splits the surrogate pair. A production Unicode-safe solution uses codePointAt() and advances by Character.charCount(codePoint).
    • 
            
  • Unicode Normalization: Accented characters like é can be represented as a single precomposed character (NFC) or as e plus combining accent (NFD). Before comparing, canonical normalization via java.text.Normalizer.normalize(s, Normalizer.Form.NFC) ensures identical binary equivalence.
