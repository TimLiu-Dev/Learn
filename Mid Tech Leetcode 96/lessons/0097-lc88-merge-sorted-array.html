LeetCode #88: Merge Sorted Array

Official LC #88

Official Problem Statement

You are given two integer arrays nums1 and nums2, sorted in non-decreasing order, and two integers m and n, representing the number of elements in nums1 and nums2 respectively.

Merge nums1 and nums2 into a single array sorted in non-decreasing order.

The final sorted array should not be returned by the function, but instead be stored inside the array nums1. To accommodate this, nums1 has a length of m + n, where the first m elements denote the elements that should be merged, and the last n elements are set to 0 and should be ignored. nums2 has a length of n.

Example 1: nums1 = [1,2,3,0,0,0], m = 3, nums2 = [2,5,6], n = 3 → Output: [1,2,2,3,5,6]

Example 2: nums1 = [1], m = 1, nums2 = [], n = 0 → Output: [1]

Example 3: nums1 = [0], m = 0, nums2 = [1], n = 1 → Output: [1]

Plain-English Translation & Core Nuance

You need to combine two sorted lists into the first list in-place. The first list has buffer space at the end. If you merge from the front, you will overwrite elements in nums1 that you haven't processed yet. If you merge backwards from the tail, you always write into empty buffer space, avoiding any overwrites.

Official Constraints:
  • nums1.length == m + n
  • nums2.length == n
  • 0 <= m, n <= 200
  • 1 <= m + n <= 200
  • -10^9 <= nums1[i], nums2[j] <= 10^9

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
m = 0, n = 1: nums1 is pure buffer zeros; copy nums2 directly.
Best-Case Early Exit
n = 0: nums2 is empty; nums1 is already sorted, 0 operations required.
Worst-Case Full Scan
m = 100, n = 100: 200 elements merged step-by-step from tail.

The Mental Model & "Explain Like I'm 12"

💡 The Moving Van Loading from the Back

Imagine two lines of heavy furniture sorted by size. You must pack both lines into a single moving truck that already holds line 1 in the front and has empty space in the back. If you try to slide smaller items into the front, you crush the furniture already there. Instead, you pick the biggest items from both lines and load them directly into the back of the truck. No shifting, no crushing.

The Mental "A-Ha!" Switch:

Merge backwards! Three pointers: p1 at m-1, p2 at n-1, and write at m+n-1. The largest remaining element always claims the write position.

Pattern Trigger:

Merging two sorted sequences in-place with existing trailing buffer capacity.

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O((M + N) log(M + N)) Time, O(1) Space

Append nums2 directly into the buffer zeros of nums1, then invoke the language standard sorting routine (Timsort / Dual-Pivot Quicksort).

Wasted Work: Completely discards the pre-existing sorted invariant of both input arrays, incurring unnecessary comparison and branching overhead.
The Optimal Breakthrough O(M + N) Time, O(1) Space

Initialize three pointers: p1 at m-1, p2 at n-1, and write at m+n-1. While p2 >= 0, compare nums1[p1] and nums2[p2], place the larger at write, and decrement.

Core Invariant: write is always >= p1, mathematically guaranteeing that an unread element in nums1 is never overwritten.
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
Naive: Append & Sort O((M + N) log(M + N)) O(1) to O(M + N) Ignores sorted order; fails senior bar for efficiency.
Better: Auxiliary Copy Buffer O(M + N) O(M) Copies nums1 prefix; linear time but wastes O(M) auxiliary heap memory.
Optimal: Three Pointers from Tail O(M + N) O(1) ★ Production standard. Zero extra allocations, single pass.

From Naive to Optimal & Runnable Practice Arena

Approach 1: Append and Sort

Copy nums2 into trailing buffer and sort with standard language library.

Time: O((M+N) log(M+N)) Space: O(1) auxiliary 
class Solution {
    fun merge(nums1: IntArray, m: Int, nums2: IntArray, n: Int): Unit {
        for (i in 0 until n) {
            nums1[m + i] = nums2[i]
        }
        nums1.sort()
    }
}
Kotlin Runtime & Memory Nuance:

Standard TimSort requires (M+N) log(M+N) comparisons and ignores sorted input.

class Solution:
    def merge(self, nums1: list[int], m: int, nums2: list[int], n: int) -> None:
        nums1[m:] = nums2
        nums1.sort()
Python Runtime & Memory Nuance:

Slice assignment followed by Timsort.

import java.util.Arrays;

class Solution {
    public void merge(int[] nums1, int m, int[] nums2, int n) {
        System.arraycopy(nums2, 0, nums1, m, n);
        Arrays.sort(nums1);
    }
}
Java Runtime & Memory Nuance:

System.arraycopy is fast native memory move, but sorting dominates asymptotic runtime.

Approach 2: Auxiliary Array Copy

Copy first m elements into auxiliary buffer, merge forward into nums1.

Time: O(M + N) Space: O(M) memory 
class Solution {
    fun merge(nums1: IntArray, m: Int, nums2: IntArray, n: Int): Unit {
        val copy = nums1.copyOfRange(0, m)
        var p1 = 0
        var p2 = 0
        var write = 0
        while (p1 < m && p2 < n) {
            if (copy[p1] <= nums2[p2]) {
                nums1[write++] = copy[p1++]
            } else {
                nums1[write++] = nums2[p2++]
            }
        }
        while (p1 < m) nums1[write++] = copy[p1++]
        while (p2 < n) nums1[write++] = nums2[p2++]
    }
}
Kotlin Runtime & Memory Nuance:

Allocates a new IntArray of size M on the JVM heap.

class Solution:
    def merge(self, nums1: list[int], m: int, nums2: list[int], n: int) -> None:
        copy = nums1[:m]
        p1, p2, w = 0, 0, 0
        while p1 < m and p2 < n:
            if copy[p1] <= nums2[p2]:
                nums1[w] = copy[p1]; p1 += 1
            else:
                nums1[w] = nums2[p2]; p2 += 1
            w += 1
        while p1 < m:
            nums1[w] = copy[p1]; p1 += 1; w += 1
        while p2 < n:
            nums1[w] = nums2[p2]; p2 += 1; w += 1
Python Runtime & Memory Nuance:

Creates slice copy; linear memory.

class Solution {
    public void merge(int[] nums1, int m, int[] nums2, int n) {
        int[] copy = new int[m];
        System.arraycopy(nums1, 0, copy, 0, m);
        int p1 = 0, p2 = 0, w = 0;
        while (p1 < m && p2 < n) {
            nums1[w++] = (copy[p1] <= nums2[p2]) ? copy[p1++] : nums2[p2++];
        }
        while (p1 < m) nums1[w++] = copy[p1++];
        while (p2 < n) nums1[w++] = nums2[p2++];
    }
}
Java Runtime & Memory Nuance:

Requires extra array allocation.

Approach 3: In-Place Three Pointers from Tail

Fill nums1 from the back using two pointers and write head. Zero extra allocations.

Time: O(M + N) Space: O(1) memory 
class Solution {
    fun merge(nums1: IntArray, m: Int, nums2: IntArray, n: Int): Unit {
        var p1 = m - 1
        var p2 = n - 1
        var write = m + n - 1

        while (p2 >= 0) {
            if (p1 >= 0 && nums1[p1] > nums2[p2]) {
                nums1[write--] = nums1[p1--]
            } else {
                nums1[write--] = nums2[p2--]
            }
        }
    }
}
Kotlin Runtime & Memory Nuance:

Zero allocations. Single while (p2 >= 0) loop handles early termination cleanly.

class Solution:
    def merge(self, nums1: list[int], m: int, nums2: list[int], n: int) -> None:
        p1 = m - 1
        p2 = n - 1
        w = m + n - 1

        while p2 >= 0:
            if p1 >= 0 and nums1[p1] > nums2[p2]:
                nums1[w] = nums1[p1]
                p1 -= 1
            else:
                nums1[w] = nums2[p2]
                p2 -= 1
            w -= 1
Python Runtime & Memory Nuance:

Idiomatic while loop with pointer decrements.

class Solution {
    public void merge(int[] nums1, int m, int[] nums2, int n) {
        int p1 = m - 1;
        int p2 = n - 1;
        int write = m + n - 1;

        while (p2 >= 0) {
            if (p1 >= 0 && nums1[p1] > nums2[p2]) {
                nums1[write--] = nums1[p1--];
            } else {
                nums1[write--] = nums2[p2--];
            }
        }
    }
}
Java Runtime & Memory Nuance:

Cache-friendly contiguous memory writes.
