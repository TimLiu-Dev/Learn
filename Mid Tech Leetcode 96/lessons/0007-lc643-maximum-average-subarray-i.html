Problem Statement & Boundary Checks

LeetCode #643 ↗

Verbatim Problem Statement

You are given an integer array nums consisting of n elements, and an integer k.

Find a contiguous subarray whose length is equal to k that has the maximum average value and return this value. Any answer with a calculation error less than 10-5 will be accepted.

Plain-English Translation

Imagine placing a stencil window covering exactly k consecutive numbers over the array. As you slide this stencil from left to right, which window captures the highest sum? Maximize the total sum first, and then divide by k at the very end to avoid cumulative floating-point rounding errors.

Example 1 (Classic Mix)
Input: nums = [1, 12, -5, -6, 50, 3], k = 4
Output: 12.75000

Subarray [12, -5, -6, 50] has the largest sum 51. Average = $51 / 4 = 12.75$.

Example 2 (Single Element)
Input: nums = [5], k = 1
Output: 5.00000

With k = 1, the window is just the single element 5. Average = $5.0$.

Example 3 (Negative Range)
Input: nums = [-1], k = 1
Output: -1.00000

Average can be negative. Crucial reminder: do not initialize maxSum = 0!

Constraints

  • n == nums.length
  • 1 ≤ k ≤ n ≤ 105
  • -104 ≤ nums[i] ≤ 104

3 Canonical Boundary Check Shapes

1. k == n: The window covers the entire array. Loop never slides; simply return sum / k.
2. All Negative Numbers: [-4, -2, -9, -1], k = 2 → Initializing maxSum = 0 would cause a bug. You must initialize maxSum to the sum of the first window!
3. k == 1: Window size of 1 equivalent to finding the maximum element in the array.

The Mental Model & "Explain Like I'm 12"

Why a fixed-size window operates in O(1) time per step.

The Passenger Bus Window Metaphor

Imagine a bus with exactly k passenger seats driving down a one-way street. At every bus stop:

  • Exactly one passenger leaves from the back door (nums[i - k]).
  • Exactly one new passenger steps on through the front door (nums[i]).
  • All k - 2 passengers sitting in the middle don't move at all!

If you want to know the total weight of the passengers on the bus, do you re-weigh all k passengers at every stop? Of course not! You take the previous total weight, subtract the weight of the person who exited, and add the weight of the person who entered.

newSum = oldSum - nums[i - k] + nums[i]

This arithmetic takes exactly 2 operations regardless of whether k = 4 or $k = 1,000,000$. That is why sliding windows are O(1) per shift.

Whenever a problem specifies a contiguous subarray of FIXED size k, immediately recognize the Fixed Sliding Window template: compute the first window of size k, then loop from i = k to N - 1, updating with window += nums[i] - nums[i - k].

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

Why re-summing slices causes quadratic time failure.

The Naive Trap: Slicing and Re-Summing O(N × K) Time

Recomputing the sum of all k elements at every starting index i: 

var maxSum = Int.MIN_VALUE
for (i in 0..nums.size - k) {
    var currentSum = 0
    for (j in i until i + k) {
        currentSum += nums[j]
    }
    if (currentSum > maxSum) maxSum = currentSum
}
return maxSum.toDouble() / k
  • Redundant Work: Re-reads (k - 1) identical elements over and over. When $k = 50,000 and N = 100,000$, performs $2.5 imes 10^9$ additions.
  • Division in Inner Loop: Dividing by k inside the loop leads to precision loss and slow floating-point CPU cycles.
Interview Verdict: TLE on large k inputs
Optimal Breakthrough: Sliding Window Running Sum O(N) Time • O(1) Space

Compute the first window sum in k steps, then slide with 1 subtraction and 1 addition: 

var windowSum = 0
for (i in 0 until k) windowSum += nums[i]
var maxSum = windowSum

for (i in k until nums.size) {
    windowSum += nums[i] - nums[i - k]
    if (windowSum > maxSum) maxSum = windowSum
}
return maxSum.toDouble() / k
  • Single Pass: Total operations = k + (N - k) = N. Exactly 1 pass over the input array.
  • Single Floating Point Division: Integer sums are exact; divide by k once at the very end.
Interview Verdict: 100% optimal execution

From Brute Force to Optimal & Interactive Sandbox

Evolution from quadratic slice summation to fixed sliding window arithmetic.

Approach 1: Nested Loops Re-Summing Slices (O(N × K))

For every starting index i, iterate k steps forward and compute the window sum. Times out when N = 10^5 and $k = 50,000$. 

class Solution {
    fun findMaxAverage(nums: IntArray, k: Int): Double {
        var maxSum = Int.MIN_VALUE
        for (i in 0..nums.size - k) {
            var sum = 0
            for (j in i until i + k) {
                sum += nums[j]
            }
            if (sum > maxSum) maxSum = sum
        }
        return maxSum.toDouble() / k
    }
}
class Solution:
    def findMaxAverage(self, nums: list[int], k: int) -> float:
        max_sum = float('-inf')
        for i in range(len(nums) - k + 1):
            curr_sum = sum(nums[i:i + k])
            if curr_sum > max_sum:
                max_sum = curr_sum
        return max_sum / k
class Solution {
    public double findMaxAverage(int[] nums, int k) {
        int maxSum = Integer.MIN_VALUE;
        for (int i = 0; i <= nums.length - k; i++) {
            int sum = 0;
            for (int j = i; j < i + k; j++) {
                sum += nums[j];
            }
            if (sum > maxSum) maxSum = sum;
        }
        return (double) maxSum / k;
    }
}
Approach 2: Prefix Sums Array (O(N) Time, O(N) Space)

Precompute a cumulative prefix sum array prefix[i] = nums[0] + ... + nums[i-1]. Any k-length sum can be retrieved in O(1) via prefix[i + k] - prefix[i]. Solves in O(N) time, but consumes an unnecessary O(N) array buffer. 

class Solution {
    fun findMaxAverage(nums: IntArray, k: Int): Double {
        val prefix = IntArray(nums.size + 1)
        for (i in nums.indices) {
            prefix[i + 1] = prefix[i] + nums[i]
        }
        var maxSum = Int.MIN_VALUE
        for (i in k..nums.size) {
            val sum = prefix[i] - prefix[i - k]
            if (sum > maxSum) maxSum = sum
        }
        return maxSum.toDouble() / k
    }
}
class Solution:
    def findMaxAverage(self, nums: list[int], k: int) -> float:
        prefix = [0] * (len(nums) + 1)
        for i in range(len(nums)):
            prefix[i + 1] = prefix[i] + nums[i]

        for i in range(k, len(nums) + 1):
            curr_sum = prefix[i] - prefix[i - k]
            if curr_sum > max_sum:
                max_sum = curr_sum
        return max_sum / k
class Solution {
    public double findMaxAverage(int[] nums, int k) {
        int[] prefix = new int[nums.length + 1];
        for (int i = 0; i < nums.length; i++) {
            prefix[i + 1] = prefix[i] + nums[i];
        }
        int maxSum = Integer.MIN_VALUE;
        for (int i = k; i <= nums.length; i++) {
            int sum = prefix[i] - prefix[i - k];
            if (sum > maxSum) maxSum = sum;
        }
        return (double) maxSum / k;
    }
}
Approach 3: Fixed Sliding Window (O(N) Time, O(1) Auxiliary Space)

Prime the first window sum in k steps. Slide the window forward by subtracting the exiting element on the left (nums[i - k]) and adding the entering element on the right (nums[i]). Exactly 1 final division at return. 

class Solution {
    fun findMaxAverage(nums: IntArray, k: Int): Double {
        // 1. Compute the sum of the first window of size k
        var windowSum = 0
        for (i in 0 until k) {
            windowSum += nums[i]
        }

        var maxSum = windowSum

        // 2. Slide the window: subtract element leaving on left, add element entering on right
        for (i in k until nums.size) {
            windowSum += nums[i] - nums[i - k]
            if (windowSum > maxSum) {
                maxSum = windowSum
            }
        }

        // 3. Exactly one floating point division to maintain precision
        return maxSum.toDouble() / k
    }
}
class Solution:
    def findMaxAverage(self, nums: list[int], k: int) -> float:
        # 1. Sum first window
        window_sum = sum(nums[:k])
        max_sum = window_sum

        # 2. Slide window forward
        for i in range(k, len(nums)):
            window_sum += nums[i] - nums[i - k]
            if window_sum > max_sum:
                max_sum = window_sum

        # 3. Single float division
        return max_sum / k
class Solution {
    public double findMaxAverage(int[] nums, int k) {
        // 1. Compute sum of initial k elements
        int windowSum = 0;
        for (int i = 0; i < k; i++) {
            windowSum += nums[i];
        }

        int maxSum = windowSum;

        // 2. Slide window across remainder of array
        for (int i = k; i < nums.length; i++) {
            windowSum += nums[i] - nums[i - k];
            if (windowSum > maxSum) {
                maxSum = windowSum;
            }
        }

        // 3. Cast to double and divide
        return (double) maxSum / k;
    }
}
★ Senior Engineering Guardrails

1. Never initialize maxSum = 0: If all numbers in nums are negative (e.g. [-5, -10, -2]), a 0 initialization will cause your function to incorrectly return 0.0 instead of the negative maximum average. Always initialize maxSum = windowSum!

2. Potential 32-bit Integer Overflow Check: The constraints state N ≤ 10^5 and $nums[i] ≤ 10^4$. The maximum possible window sum is 10^5 imes 10^4 = 10^9. Since $10^9 < 2^{31} - 1 pprox 2.14 imes 10^9$, standard 32-bit signed integers (Int / int) will not overflow. However, in production systems where values can reach 10^9, using a 64-bit integer (Long / long) is mandatory.

              Phase 1: Clarify
              Scoping & Window Fixed Size
            

            

              
You: "Let me clarify the requirements: We are given an array of integers nums and an integer k. We want to find the maximum average of a contiguous subarray of exactly length k. Can numbers be negative? Is k guaranteed to be $≤ nums.length$?"

              
Interviewer: "Yes, numbers can be negative (down to -10,000), and $1 ≤ k ≤ nums.length$ is guaranteed."

            

          


          
          

            

              Phase 2: Naive Critique
              Identifying Redundant Computations
            

            

              
You: "A naive approach would evaluate each slice from index i to i + k - 1 by recalculating the sum of all k elements. That would result in O(N \cdot k) time. In the worst case where $k = N / 2 = 50,000$, that takes $pprox 2.5 	imes 10^9$ operations, which exceeds time limits. We can do much better because adjacent windows share k - 1 common elements."

              
Interviewer: "How do you avoid re-summing those common elements?"

            

          


          
          

            

              Phase 3: Optimal Pitch
              Fixed Sliding Window Mechanics
            

            

              
You: "We can use a fixed-size sliding window: First, sum the initial k elements to initialize windowSum and maxSum. Then, as we iterate from index k to N - 1, we slide the window by 1: we subtract nums[i - k] which fell out of the left, and add nums[i] which entered on the right. At each step we update maxSum = max(maxSum, windowSum). Finally, we divide by k once at the end. This is strictly O(N) time and O(1) auxiliary space."

              
Interviewer: "Good. Why do you divide by k at the end instead of every step?"

              
You: "Floating-point division is computationally expensive and subject to IEEE 754 precision inaccuracies. Since k is constant and positive, maximizing the sum is mathematically equivalent to maximizing the average."

            

          


          
          

            

              Phase 4: Verification
              Corner Case Dry Run
            

            

              
You: "Let's check corner cases: 1) k == n: loop from k to N - 1 doesn't execute; returns initial sum divided by k. 2) All negative elements [-10, -5], k = 1: by initializing maxSum = windowSum (which is -10), the loop tests -5, updates to -5, and returns -5.0. 3) k = 1: acts as finding max single element in linear time. The solution is rock solid."
