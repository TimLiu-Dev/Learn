LeetCode #394: Decode String

Official LC #394

Official Problem Statement

Given an encoded string, return its decoded string.

The encoding rule is: k[encoded_string], where the encoded_string inside the square brackets is being repeated exactly k times. Note that k is guaranteed to be a positive integer.

You may assume that the input string is always valid; there are no extra white spaces, square brackets are well-formed, etc. Furthermore, you may assume that the original data does not contain any digits and that digits are only for those repeat numbers, k.

Example 1: s = "3[a]2[bc]" → Output: "aaabcbc"

Example 2: s = "3[a2[c]]" → Output: "accaccacc"

Example 3: s = "2[abc]3[cd]ef" → Output: "abcabccdcdcdef"

Plain-English Translation & Core Nuance

Maintain two stacks or recurse when opening bracket '[' is met: a count stack for repeat multipliers (k) and a string stack for parent string buffers. When encountering ']', pop the count and parent string, repeat current buffer k times, and append to the parent string. Digits accumulate into multi-digit numbers, and characters append to current buffer.

Official Constraints:
  • 1 <= s.length <= 30
  • s consists of lowercase English letters, digits, and square brackets '[]'.
  • s is guaranteed to be a valid input.
  • All the integers in s are in the range [1, 300].

💡 Russian Nesting Boxes with Stencils

Imagine building rubber stamp patterns. Whenever you see a number followed by '[', you pause your current canvas, write down the multiplier, and put your current canvas in a box on top of a stack. You take out a fresh canvas for what's inside the brackets. When you hit ']', you stamp your current canvas k times onto the old canvas you pop back out from the box.

The Mental "A-Ha!" Switch:

Nested brackets require LIFO evaluation (innermost must be resolved before outermost can be multiplied). Two parallel stacks (or a single call stack in recursion) store the snapshot of the outer world while the inner expression is assembled.

Pattern Trigger:

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(maxK^depth * N) Time, O(N) Space

Regex string replacement iteratively finding innermost bracket pattern `\d+\[[a-z]+\]` and replacing in-place.

Wasted Work: Repeatedly allocating new strings and re-parsing from start on every bracket reduction (O(N^2) string copies).
The Optimal Breakthrough O(Output Length) Time, O(Output Length) Space

Single pass with CountStack and StringStack. Each character pushed and popped once; output built directly with StringBuilder.

Core Invariant: At any point, `currentStr` holds the decoded content for the current nesting level, and `strStack.peek()` holds the accumulated prefix from the enclosing scope.
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
1. Iterative Regex Reduction O(D * N^2) O(N) High string allocation and regex matching overhead.
2. Recursive Descent Parser O(L) O(D) Elegant but uses call stack proportional to bracket depth.
★ 3. Two-Stack LIFO Parser O(L) O(L) Production standard; explicit memory bounds with StringBuilder.

Approach 1: Recursive Descent Parsing

Advance a global index pointer. Recurse whenever '[' is encountered, and return when ']' or end of string is reached.

Time: O(L) Time Space: O(D) Space 
class Solution {
    private var idx = 0

    fun decodeString(s: String): String {
        idx = 0
        return helper(s)
    }

    private fun helper(s: String): String {
        val sb = java.lang.StringBuilder()
        var k = 0

        while (idx < s.length) {
            val ch = s[idx++]
            when {
                ch.isDigit() -> k = k * 10 + (ch - '0')
                ch == '[' -> {
                    val inner = helper(s)
                    repeat(k) { sb.append(inner) }
                    k = 0
                }
                ch == ']' -> return sb.toString()
                else -> sb.append(ch)
            }
        }
        return sb.toString()
    }
}

class Solution {
    private int idx = 0;

    public String decodeString(String s) {
        idx = 0;
        return helper(s);
    }

    private String helper(String s) {
        StringBuilder sb = new StringBuilder();
        int k = 0;
        while (idx < s.length()) {
            char ch = s.charAt(idx++);
            if (Character.isDigit(ch)) {
                k = k * 10 + (ch - '0');
            } else if (ch == '[') {
                String inner = helper(s);
                while (k-- > 0) sb.append(inner);
                k = 0;
            } else if (ch == ']') {
                return sb.toString();
            } else {
                sb.append(ch);
            }
        }
        return sb.toString();
    }
}

★ Approach 2: Two-Stack Iterative Parser (Production Optimal)

Maintain countStack for repeat factors and stringStack for parent prefixes. Linear pass over characters, resolving brackets strictly LIFO.

Time: O(L) Time Space: O(L) Space 
import java.util.ArrayDeque

class Solution {
    fun decodeString(s: String): String {
        val countStack = ArrayDeque<Int>()
        val strStack = ArrayDeque<StringBuilder>()
        var currStr = StringBuilder()
        var k = 0

        for (ch in s) {
            when {
                ch.isDigit() -> k = k * 10 + (ch - '0')
                ch == '[' -> {
                    countStack.push(k)
                    strStack.push(currStr)
                    currStr = StringBuilder()
                    k = 0
                }
                ch == ']' -> {
                    val repeatCount = countStack.pop()
                    val parent = strStack.pop()
                    val decoded = currStr.toString()
                    repeat(repeatCount) { parent.append(decoded) }
                    currStr = parent
                }
                else -> currStr.append(ch)
            }
        }
        return currStr.toString()
    }
}

import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public String decodeString(String s) {
        Deque<Integer> countStack = new ArrayDeque<>();
        Deque<StringBuilder> strStack = new ArrayDeque<>();
        StringBuilder currStr = new StringBuilder();
        int k = 0;

        for (char ch : s.toCharArray()) {
            if (Character.isDigit(ch)) {
                k = k * 10 + (ch - '0');
            } else if (ch == '[') {
                countStack.push(k);
                strStack.push(currStr);
                currStr = new StringBuilder();
                k = 0;
            } else if (ch == ']') {
                int repeatCount = countStack.pop();
                StringBuilder parent = strStack.pop();
                String inner = currStr.toString();
                while (repeatCount-- > 0) {
                    parent.append(inner);
                }
                currStr = parent;
            } else {
                currStr.append(ch);
            }
        }
        return currStr.toString();
    }
}

          Phase 2: Space-Time Strategy Pitch
          
""Because brackets can be nested, we must evaluate inner brackets before outer multipliers can be applied. This is a classic Last-In, First-Out (LIFO) pattern. I will use two stacks: a countStack for integers and a strStack for parent string buffers. As I iterate: if I see a digit, I accumulate `k = k * 10 + digit`. If I see '[', I push k to countStack, push the current string buffer to strStack, and reset both. If I see a character, I append it. If I see ']', I pop the count and parent string, repeat the current buffer that many times, and prepend the parent string.""

          Phase 4: Cold Edge-Case Verification
          
""Tracing with `"3[a2[c]]"`. At 3: k=3. At '[': push 3, push "". At 'a': curr="a". At 2: k=2. At '[': push 2, push "a". At 'c': curr="c". At first ']': pop 2, pop "a" → "a" + "c"*2 = "acc".
