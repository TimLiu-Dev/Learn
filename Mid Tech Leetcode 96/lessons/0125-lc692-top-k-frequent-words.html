Problem #692: Top K Frequent Words

External Judge ↗

Official Problem Statement

Given an array of strings words and an integer k, return the k most frequent strings.

Return the answer sorted by the frequency from highest to lowest. Sort the words with the same frequency by their lexicographical order ("i" before "love").

Example 1: words = ["i","love","leetcode","i","love","coding"], k = 2 → Output: ["i","love"]

Example 2: words = ["the","day","is","sunny","the","the","the","sunny","is","is"], k = 4 → Output: ["the","is","sunny","day"]

Plain-English Translation & Core Nuance

Count word frequencies in a HashMap. To keep only the best k words inside a bounded Min-Heap (which evicts the *worst* survivor first!), define 'worse' as lower frequency OR same frequency and lexicographically LARGER (b.compareTo(a)), then pop and reverse!

Official Constraints:
  • 1 <= words.length <= 500
  • 1 <= words[i].length <= 10
  • k is in [1, number of unique words]

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
words = ["a"], k = 1 -> Returns ["a"].
Best-Case Early Exit
Tie-break test: ["love", "i", "love", "i"], k = 1 -> Both have freq 2; heap evicts "love" ("love" > "i") and returns ["i"]!
Worst-Case Full Scan
U unique words -> O(N) counting + O(U log k) bounded heap (or O(U + k log U) heapify).

Section 01 • Cognitive Anchor

The Mental Model & "Explain Like I'm 12"

💡 The Inverted Tie-Breaker Trap in Worst-First Eviction

In Top K Frequent Elements (#347), order didn't matter and ties didn't exist. Here, 'i' (freq 2) beats 'love' (freq 2) alphabetically! Inside a size-k Min-Heap, the root is the first candidate to get kicked out when size > k. Between 'i' and 'love' at freq 2, who should get kicked out? 'love'! Therefore 'love' must sit at the root BEFORE 'i'—meaning the Min-Heap comparator sorts frequency ascending (fa - fb) and word descending (b.compareTo(a)), then reverses at the end!

The Mental "A-Ha!" Switch:

In a size-K Min-Heap, root = WORST kept item: lower frequency (fa - fb) AND lexicographically LARGER word (b.compareTo(a)), followed by res.reverse()!

Section 02 • Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(U log U) Full Sort

Count frequencies in O(N), then sort all U unique words by (-freq, word) and slice the first k.

Wasted Work: When N = 10^6 search queries and k = 10 autocomplete suggestions, sorting all U unique queries wastes O(U log U) time and O(U) sort buffer.
The Optimal Breakthrough O(N + U log K) Time, O(U) Map + O(K) Heap Space

Count frequencies in O(N), push into a size-K Min-Heap with inverted comparator (fa != fb ? fa - fb : b.compareTo(a)), then poll K items and reverse.

Core Invariant: At every step, pq holds the best min(seen, k) words, with the single worst among them (lowest freq, or largest word on tie) at pq.peek().
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
Full Sort on (-freq, word) O(N + U log U) O(U) Great baseline; slower when K << U.
Max-Heap Heapify ((-freq, word)) O(N + U + K log U) O(U) Clean in Python (heapq.heapify in O(U) + K pops).
Optimal: Bounded Size-K Min-Heap O(N + U log K) O(U) map, O(K) heap ★ Best streaming/autocomplete scaling when K = 10.

2. Core Traversal & Decision Rule

Count frequencies in O(N), push into a size-K Min-Heap with inverted comparator (fa != fb ? fa - fb : b.compareTo(a)), then poll K items and reverse. Instead of re-scanning prior elements, each step makes a local O(1) or O(log N) transition.

3. Invariant Preservation Across Steps

In a size-K Min-Heap, root = WORST kept item: lower frequency (fa - fb) AND lexicographically LARGER word (b.compareTo(a)), followed by res.reverse()! After every update, the core invariant holds: At every step, pq holds the best min(seen, k) words, with the single worst among them (lowest freq, or largest word on tie) at pq.peek().

4. Early Exit & Final Return

Short-circuit immediately when decisive conditions trigger (Tie-break test: ["love", "i", "love", "i"], k = 1 -> Both have freq 2; heap evicts "love" ("love" > "i") and returns ["i"]!); otherwise complete traversal and return the final state. If you forgot b.compareTo(a) and wrote a.compareTo(b), 'i' would sit at the root and get evicted if a freq-3 word arrived!

Section 05 • Production Implementations

From Naive to Optimal & Runnable Practice Arena

Strict ordering: Kotlin (Default) → Python → Java across all approaches.

HashMap + Full Custom Sort

Counts frequencies and sorts all unique words by (-freq, word) in O(U log U) time.

Time: O(N + U log U) Space: O(U) 
class Solution {
    fun topKFrequent(words: Array<String>, k: Int): List<String> {
        val freq = HashMap<String, Int>()
        for (w in words) freq[w] = (freq[w] ?: 0) + 1
        val unique = freq.keys.toMutableList()
        unique.sortWith { a, b ->
            val fa = freq[a]!!
            val fb = freq[b]!!
            if (fa != fb) fb - fa else a.compareTo(b)
        }
        return unique.subList(0, k)
    }
}
Kotlin Runtime & Memory Nuance:

In HashMap + Full Custom Sort, Kotlin uses HashMap for amortized O(1) lookups via getOrPut / getOrDefault.

from collections import Counter

class Solution:
    def topKFrequent(self, words: list[str], k: int) -> list[str]:
        freq = Counter(words)
        ordered = sorted(freq.keys(), key=lambda w: [-freq[w], w])
        return ordered[:k]
Python Runtime & Memory Nuance:

In HashMap + Full Custom Sort, Python leverages Python's open-addressed dict hash table for amortized O(1) lookups.

import java.util.*;

class Solution {
    public List<String> topKFrequent(String[] words, int k) {
        Map<String, Integer> freq = new HashMap<>();
        for (String w : words) freq.put(w, freq.getOrDefault(w, 0) + 1);
        List<String> unique = new ArrayList<>(freq.keySet());
        Collections.sort(unique, (a, b) -> {
            int fa = freq.get(a), fb = freq.get(b);
            return fa != fb ? fb - fa : a.compareTo(b);
        });
        return unique.subList(0, k);
    }
}

In HashMap + Full Custom Sort, Java uses HashMap / HashSet with Java 8+ red-black tree collision fallback.

Optimal: PriorityQueue Heap (O(N + U log K) / O(N + K log U))

Uses a bounded size-K Min-Heap with inverted lexicographical tie-breaker in Kotlin/Java, and O(U) heapify + K pops in Python.

Time: O(N + U log K) Space: O(U) 
import java.util.PriorityQueue

class Solution {
    fun topKFrequent(words: Array<String>, k: Int): List<String> {
        val freq = HashMap<String, Int>()
        for (w in words) {
            freq[w] = (freq[w] ?: 0) + 1
        }
        val pq = PriorityQueue<String> { a, b ->
            val fa = freq[a]!!
            val fb = freq[b]!!
            if (fa != fb) fa - fb else b.compareTo(a)
        }
        for (w in freq.keys) {
            pq.offer(w)
            if (pq.size > k) pq.poll()
        }
        val res = mutableListOf<String>()
        while (pq.isNotEmpty()) {
            res.add(pq.poll())
        }
        res.reverse()
        return res
    }
}
Kotlin Runtime & Memory Nuance:

In Optimal: PriorityQueue Heap (O(N + U log K) / O(N + K log U)), Kotlin uses HashMap for amortized O(1) lookups via getOrPut / getOrDefault; and maintains heap ordering in O(log K) via PriorityQueue.

import heapq
from collections import Counter

class Solution:
    def topKFrequent(self, words: list[str], k: int) -> list[str]:
        freq = Counter(words)
        heap = [[-cnt, word] for word, cnt in freq.items()]
        heapq.heapify(heap)
        res = []
        for _ in range(k):
            res.append(heapq.heappop(heap)[1])
        return res
Python Runtime & Memory Nuance:

In Optimal: PriorityQueue Heap (O(N + U log K) / O(N + K log U)), Python uses C-backed heapq binary heap operations on flat lists; and leverages Python's open-addressed dict hash table for amortized O(1) lookups.

import java.util.*;

class Solution {
    public List<String> topKFrequent(String[] words, int k) {
        Map<String, Integer> freq = new HashMap<>();
        for (String w : words) {
            freq.put(w, freq.getOrDefault(w, 0) + 1);
        }
        PriorityQueue<String> pq = new PriorityQueue<>((a, b) -> {
            int fa = freq.get(a);
            int fb = freq.get(b);
            return fa != fb ? fa - fb : b.compareTo(a);
        });
        for (String w : freq.keySet()) {
            pq.offer(w);
            if (pq.size() > k) pq.poll();
        }
        List<String> res = new ArrayList<>();
        while (!pq.isEmpty()) {
            res.add(pq.poll());
        }
        Collections.reverse(res);
        return res;
    }
}
Java Runtime & Memory Nuance:

In Optimal: PriorityQueue Heap (O(N + U log K) / O(N + K log U)), Java uses binary-heap PriorityQueue with explicit comparator ordering; and uses HashMap / HashSet with Java 8+ red-black tree collision fallback.
