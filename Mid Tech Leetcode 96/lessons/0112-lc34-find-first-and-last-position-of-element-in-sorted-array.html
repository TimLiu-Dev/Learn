Problem #34: Find First and Last Position of Element in Sorted Array

View on NeetCode ↗

Official Problem Statement

Given an array of integers nums sorted in non-decreasing order, find the starting and ending position of a given target value.

If target is not found in the array, return [-1, -1].

You must write an algorithm with O(log n) runtime complexity.

Example 1: nums = [5,7,7,8,8,10], target = 8 → Output: [3,4]

Example 2: nums = [5,7,7,8,8,10], target = 6 → Output: [-1,-1]

Example 3: nums = [], target = 0 → Output: [-1,-1]

Plain-English Translation & Core Nuance

In a sorted array with duplicates, find both the leftmost and rightmost indices of target in strict O(log N) time—never scanning outward linearly from a hit.

Official Constraints:
  • 0 <= nums.length <= 10^5
  • -10^9 <= nums[i] <= 10^9
  • nums is a non-decreasing array.
  • -10^9 <= target <= 10^9

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
nums = [], target = 0 -> Empty array guard immediately returns [-1, -1].
Best-Case Early Exit
nums = [8,8,8,8], target = 8 -> All elements match; returns [0, 3] in O(log N) without linear scan.
Worst-Case Full Scan
nums = [5,7,7,8,8,10], target = 6 -> Target missing; first bound check returns -1 so second search can short-circuit.

The Mental Model & "Explain Like I'm 12"

💡 Two Bookmarks in a Multi-Copy Dictionary

Suppose a word appears on 500 consecutive pages of a dictionary. If you open to the middle and land on one copy, flipping page-by-page left and right takes O(N) time! Instead, do two binary searches: the first asks 'Is this copy still too far right?' (keep pushing right = mid - 1 after recording ans = mid to find the leftmost page). The second asks 'Is this copy still too far left?' (keep pushing left = mid + 1 after recording ans = mid to find the rightmost page).

The Mental "A-Ha!" Switch:

Never stop when nums[mid] == target! Record mid as a candidate bound and keep narrowing left (for first position) or right (for last position) in two clean O(log N) passes.

Pattern Trigger:

Finding exact range boundaries [first, last], frequency counts in sorted arrays, or lower/upper bounds.

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(N) Worst-Case Time, O(1) Space

Binary search to find one occurrence of target, then expand two while-loops outward (left--, right++) to find boundaries.

Wasted Work: When all 10^5 elements equal target (e.g. [8, 8, ..., 8]), expanding outward degrades straight to O(N) linear time, violating the O(log N) requirement.
The Optimal Breakthrough O(log N) Time, O(1) Space

Run one parameterized helper findBound(nums, target, isFirst): when nums[mid] == target, record ans = mid and continue halving left (right = mid - 1) if isFirst else right (left = mid + 1).

Core Invariant: ans always holds the best verified occurrence of target seen so far while the active [left..right] window probes strictly closer to the target edge.
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
Naive: Linear Scan O(N) O(1) Violates O(log N) prompt requirement.
Trap: Binary Search + Linear Expand O(N) worst O(1) Degrades to O(N) on arrays of identical elements.
Optimal: Dual Biased Binary Search O(log N) O(1) ★ Guaranteed O(log N) even when 100% of elements equal target.

2. Core Traversal & Decision Rule

Run one parameterized helper findBound(nums, target, isFirst): when nums[mid] == target, record ans = mid and continue halving left (right = mid - 1) if isFirst else right (left = mid + 1). At each step, instead of re-scanning elements we already visited, we use our maintained state to make an immediate local decision.

3. Invariant Maintenance & State Transition

I call first = findBound(nums, target, true). If first == -1, I return [-1, -1] immediately. Otherwise I call last = findBound(nums, target, false) and return [first, last]. Both run in O(log N) time and O(1) space. Throughout every transition, we preserve the core invariant: ans always holds the best verified occurrence of target seen so far while the active [left..right] window probes strictly closer to the target edge.

4. Termination & Output Guarantee

Check for early-exit conditions (nums = [8,8,8,8], target = 8 -> All elements match; returns [0, 3] in O(log N) without linear scan.). Once traversal completes, return the accumulated result. If the first pass returns -1, we can immediately return [-1, -1] without running the second search!

From Naive to Optimal & Runnable Practice Arena

Strict ordering: Kotlin (Default) → Python → Java across all approaches.

Approach 1: Binary Search + Linear Expansion

Locate any matching index with binary search, then walk left and right linearly. Degrades to O(N) on duplicates.

Time: O(N) worst Space: O(1) 
class Solution {
    fun searchRange(nums: IntArray, target: Int): IntArray {
        var left = 0
        var right = nums.size - 1
        var hit = -1
        while (left <= right) {
            val mid = left + (right - left) / 2
            if (nums[mid] == target) { hit = mid; break }
            else if (nums[mid] < target) left = mid + 1
            else right = mid - 1
        }
        if (hit == -1) return intArrayOf(-1, -1)
        var start = hit
        var end = hit
        while (start > 0 && nums[start - 1] == target) start--
        while (end < nums.size - 1 && nums[end + 1] == target) end++
        return intArrayOf(start, end)
    }
}
Kotlin Runtime & Memory Nuance:

Linear expansion fails the O(log N) interview requirement if all elements equal target.

class Solution {
    public int[] searchRange(int[] nums, int target) {
        int left = 0, right = nums.length - 1, hit = -1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) { hit = mid; break; }
            else if (nums[mid] < target) left = mid + 1;
            else right = mid - 1;
        }
        if (hit == -1) return new int[]{-1, -1};
        int start = hit, end = hit;
        while (start > 0 && nums[start - 1] == target) start--;
        while (end < nums.length - 1 && nums[end + 1] == target) end++;
        return new int[]{start, end};
    }
}

Hits O(N) worst case when target spans the majority of the sorted array.

Approach 2: Dual Biased Binary Search

Parameterized findBound(isFirst) helper guarantees strict O(log N) time even on uniform arrays.

Time: O(log N) Space: O(1) 
class Solution {
    fun searchRange(nums: IntArray, target: Int): IntArray {
        val first = findBound(nums, target, true)
        if (first == -1) return intArrayOf(-1, -1)
        val last = findBound(nums, target, false)
        return intArrayOf(first, last)
    }

    private fun findBound(nums: IntArray, target: Int, isFirst: Boolean): Int {
        var left = 0
        var right = nums.size - 1
        var ans = -1
        while (left <= right) {
            val mid = left + (right - left) / 2
            if (nums[mid] == target) {
                ans = mid
                if (isFirst) {
                    right = mid - 1
                } else {
                    left = mid + 1
                }
            } else if (nums[mid] < target) {
                left = mid + 1
            } else {
                right = mid - 1
            }
        }
        return ans
    }
}
Kotlin Runtime & Memory Nuance:

Early short-circuit when first == -1 saves the second binary search whenever target is absent.

class Solution:
    def searchRange(self, nums: list[int], target: int) -> list[int]:
        def find_bound(is_first: bool) -> int:
            left, right, ans = 0, len(nums) - 1, -1
            while left <= right:
                mid = left + (right - left) // 2
                if nums[mid] == target:
                    ans = mid
                    if is_first:
                        right = mid - 1
                    else:
                        left = mid + 1
                elif nums[mid] < target:
                    left = mid + 1
                else:
                    right = mid - 1
            return ans

        first = find_bound(True)
        if first == -1:
            return [-1, -1]
        return [first, find_bound(False)]
Python Runtime & Memory Nuance:

Shared find_bound closure eliminates duplicate binary-search logic cleanly without extra allocation.

class Solution {
    public int[] searchRange(int[] nums, int target) {
        int first = findBound(nums, target, true);
        if (first == -1) return new int[]{-1, -1};
        int last = findBound(nums, target, false);
        return new int[]{first, last};
    }

    private int findBound(int[] nums, int target, boolean isFirst) {
        int left = 0, right = nums.length - 1, ans = -1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) {
                ans = mid;
                if (isFirst) right = mid - 1;
                else left = mid + 1;
            } else if (nums[mid] < target) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
        return ans;
    }
}
Java Runtime & Memory Nuance:

Returns unboxed int[] in strict O(log N) worst-case time and O(1) space.
