LeetCode #362: Design Hit Counter

Official LC #362

Official Problem Statement

Design a hit counter which counts the number of hits received in the past 5 minutes (i.e., the past 300 seconds).

Your system should accept a timestamp parameter (in seconds granularity), and you may assume that calls are being made to the system in chronological order (i.e., timestamp is monotonically increasing). Several hits may arrive roughly at the same time.

Implement the HitCounter class:

  • HitCounter() Initializes the object of the hit counter system.
  • void hit(int timestamp) Records a hit that happened at timestamp (in seconds). Several hits may happen at the same timestamp.
  • int getHits(int timestamp) Returns the number of hits in the past 5 minutes from timestamp (i.e., the past 300 seconds, range [timestamp - 299, timestamp]).

Example 1: ["HitCounter","hit","hit","hit","getHits","hit","getHits","getHits"] [[],[1],[2],[3],[4],[300],[300],[301]] → Output: [null,null,null,null,3,null,4,3]

Plain-English Translation & Core Nuance

Track request rates over a sliding 300-second window. `hit(timestamp)` records an event; `getHits(timestamp)` returns the count of all hits that occurred in `(timestamp - 300, timestamp]`. Memory must not grow indefinitely with time.

Official Constraints:
  • 1 <= timestamp <= 2 * 10^9
  • All the calls are being made to the system in chronological order (i.e., timestamp is monotonically increasing).
  • At most 300 calls will be made to hit and getHits.

The Mental Model & "Explain Like I'm 12"

💡 The 300-Second Circular Conveyor Belt

Imagine a circular sushi carousel with exactly 300 plates numbered 0 to 299. Each second maps to plate `timestamp % 300`. If a plate's label matches the current timestamp, you add a hit token to it. If the plate holds an old timestamp from 5 minutes ago, you throw away the old tokens, update the plate's timestamp to now, and reset count to 1. To get the 5-minute hit count, you simply sum the tokens on all plates whose timestamp is >= timestamp - 300.

The Mental "A-Ha!" Switch:

A 300-element circular buffer `times[300]` and `hits[300]` provides strict O(1) memory! Memory never exceeds 300 integers, regardless of whether 1,000 or 1,000,000,000 hits occur.

Pattern Trigger:

Whenever designing rate limiters, hit counters, or sliding metrics over fixed time W → Circular Ring Buffer of size W.

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap Queue: O(N) space growth, linear scan getHits

Store every timestamp in a dynamic list. Memory grows without bound over days of operation.

Wasted Work: Storing individual timestamps instead of bucketing by second, and letting expired historical hits leak memory.
The Optimal Breakthrough hit: O(1), getHits: O(300) = O(1) Time, O(300) = O(1) Space

Fixed circular array of 300 buckets storing `(timestamp, hitCount)`. Strictly constant memory.

Core Invariant: Only events within `(timestamp - 300, timestamp]` contribute to the sum; circular indexing recycles expired buckets.
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
1. Unbounded List getHits: O(N) O(N) memory leak Memory exhausts over long runtimes.
2. Deque Eviction Amortized O(1) O(MaxHitsInWindow) Safe for single hits; balloons if bursty.
★ 3. Circular Array (Size 300) All O(1) O(300) = O(1) Production standard. Zero memory growth.

Queue Sliding Window Eviction

Use ArrayDeque to store hit timestamps and poll expired timestamps on each query.

Time: hit: O(1), getHits: O(Expired) amortized O(1) Space: O(MaxHitsInWindow) 
class HitCounter() {
    private val queue = ArrayDeque<Int>()

    fun hit(timestamp: Int) {
        queue.addLast(timestamp)
    }

    fun getHits(timestamp: Int): Int {
        while (queue.isNotEmpty() && timestamp - queue.first() >= 300) {
            queue.removeFirst()
        }
        return queue.size
    }
}
Kotlin Runtime & Memory Nuance:

Simple and concise. However, if 10 million hits arrive at the same second, queue size grows to 10 million.

class HitCounter:
    def __init__(self):
        from collections import deque
        self.queue = deque()

    def hit(self, timestamp: int) -> None:
        self.queue.append(timestamp)

    def getHits(self, timestamp: int) -> int:
        while self.queue and timestamp - self.queue[0] >= 300:
            self.queue.popleft()
        return len(self.queue)
Python Runtime & Memory Nuance:

Standard Python queue eviction. Amortized O(1) time per operation.

import java.util.ArrayDeque;
import java.util.Deque;

class HitCounter {
    private Deque<Integer> queue = new ArrayDeque<>();

    public HitCounter() {}

    public void hit(int timestamp) {
        queue.offer(timestamp);
    }

    public int getHits(int timestamp) {
        while (!queue.isEmpty() && timestamp - queue.peek() >= 300) {
            queue.poll();
        }
        return queue.size();
    }
}
Java Runtime & Memory Nuance:

Clean for low traffic. Under high concurrency, memory is not strictly bounded.

Optimal: Fixed 300-Second Circular Array (Production Standard)

Store hits in 300 circular buckets of (timestamp, hitCount). Guaranteed O(1) space.

Time: hit: O(1), getHits: O(300) = O(1) Space: O(300) = O(1) Absolute Memory Cap 
class HitCounter() {
    /**
     * Optimal: 300-Slot Circular Ring Buffer
     * Time: hit: O(1), getHits: O(300) = O(1)
     * Space: O(300) = O(1) Strict Constant Memory
     */
    private val times = IntArray(300)
    private val hits = IntArray(300)

    fun hit(timestamp: Int) {
        val idx = timestamp % 300
        if (times[idx] != timestamp) {
            times[idx] = timestamp
            hits[idx] = 1 // Reset slot for new timestamp cycle
        } else {
            hits[idx]++
        }
    }

    fun getHits(timestamp: Int): Int {
        var total = 0
        for (i in 0 until 300) {
            if (timestamp - times[i] < 300) {
                total += hits[i]
            }
        }
        return total
    }
}
Kotlin Runtime & Memory Nuance:

Staff-level design: handles unlimited hits per second without memory expansion. Memory is fixed at exactly 600 integers.

class HitCounter {
    /**
     * Optimal: 300-Bucket Circular Array
     * Time: O(1) hit, O(300) getHits
     * Space: O(1) (600 ints total)
     */
    private final int[] times = new int[300];
    private final int[] hits = new int[300];

    public HitCounter() {}

    public void hit(int timestamp) {
        int idx = timestamp % 300;
        if (times[idx] != timestamp) {
            times[idx] = timestamp;
            hits[idx] = 1;
        } else {
            hits[idx]++;
        }
    }

    public int getHits(int timestamp) {
        int total = 0;
        for (int i = 0; i < 300; i++) {
            if (timestamp - times[i] < 300) {
                total += hits[i];
            }
        }
        return total;
    }
}

Thread-Safe Concurrent Circular Buffer

Add lock-free AtomicInteger arrays or synchronized locks for concurrent multi-threaded hits.

Time: All O(1) Space: O(1) 
import java.util.concurrent.atomic.AtomicIntegerArray

class HitCounter() {
    private val times = AtomicIntegerArray(300)
    private val hits = AtomicIntegerArray(300)

    fun hit(timestamp: Int) {
        val idx = timestamp % 300
        synchronized(this) {
            if (times.get(idx) != timestamp) {
                times.set(idx, timestamp)
                hits.set(idx, 1)
            } else {
                hits.incrementAndGet(idx)
            }
        }
    }

    fun getHits(timestamp: Int): Int {
        var total = 0
        for (i in 0 until 300) {
            if (timestamp - times.get(i) < 300) {
                total += hits.get(i)
            }
        }
        return total
    }
}

class HitCounter {

    private final AtomicIntegerArray hits = new AtomicIntegerArray(300);

    public synchronized void hit(int timestamp) {
        int idx = timestamp % 300;
        if (times.get(idx) != timestamp) {
            times.set(idx, timestamp);
            hits.set(idx, 1);
        } else {
            hits.incrementAndGet(idx);
        }
    }

    public synchronized int getHits(int timestamp) {
        int total = 0;
        for (int i = 0; i < 300; i++) {
            if (timestamp - times.get(i) < 300) {
                total += hits.get(i);
            }
        }
        return total;
    }
}

          Phase 2: Space-Time Strategy Pitch
          
"For strategy: a Queue works by polling timestamps < t - 300, but memory scales with the number of hits. If millions of hits occur in a burst, memory balloons. A superior production approach is a fixed 300-element circular buffer: times[300] and hits[300]. Any timestamp maps to timestamp % 300. This caps memory strictly to 600 integers (O(1) space) and makes hit() O(1) and getHits() O(300) = O(1)."

        

        

          Phase 3: Live Coding Narrative
          
"I allocate int[] times = new int[300] and int[] hits = new int[300]. In hit(t), idx = t % 300. If times[idx] != t, it means this slot held a timestamp from >= 300 seconds ago; we overwrite times[idx] = t and reset hits[idx] = 1. Otherwise, we increment hits[idx]. In getHits(t), we loop through all 300 slots, summing hits[i] wherever t - times[i] < 300."

        

        

          Phase 4: Cold Edge-Case Verification
          
"Dry running edge cases: hit at t=1, query at t=301: 301 - 1 = 300, which is not < 300, so it is correctly excluded. Hit at t=300 and query at t=300: 300 - 300 = 0 < 300, included. Memory is strictly constant."
