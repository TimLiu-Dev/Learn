Problem #2: Add Two Numbers

View on NeetCode ↗

Official Problem Statement

You are given two non-empty linked lists representing two non-negative integers. The digits are stored in reverse order, and each of their nodes contains a single digit. Add the two numbers and return the sum as a linked list.

You may assume the two numbers do not contain any leading zero, except the number 0 itself.

Example 1: l1 = [2,4,3], l2 = [5,6,4] → Output: [7,0,8] (342 + 465 = 807)

Example 2: l1 = [0], l2 = [0] → Output: [0]

Example 3: l1 = [9,9,9,9,9,9,9], l2 = [9,9,9,9] → Output: [8,9,9,9,0,0,0,1]

Plain-English Translation & Core Nuance

Add two numbers whose digits are already reversed (ones place at the head), propagating carry forward node-by-node—including any trailing carry after both lists end.

Official Constraints:
  • The number of nodes in each linked list is in the range [1, 100].
  • 0 <= Node.val <= 9
  • It is guaranteed that the list represents a number that does not have leading zeros.

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
l1 = [0], l2 = [0] -> Single digit sum = 0, carry = 0, returns [0].
Best-Case Early Exit
l1 = [9,9], l2 = [1] -> Unequal lengths plus trailing carry; loop runs while (p != null || q != null || carry > 0) -> [0,0,1].
Worst-Case Full Scan
100-digit lists -> Converting to 64-bit Long overflows! Must add digit-by-digit.

The Mental Model & "Explain Like I'm 12"

💡 Elementary School Column Addition (Right-to-Left)

Because the linked lists store the ones digit at the head and tens/hundreds further down, they are ALREADY lined up in the exact order you add numbers by hand! You add digit1 + digit2 + carry, write down (sum % 10) on the result chain behind a dummy sentinel, and carry (sum / 10) to the next column. Even if both lists run out of digits, a leftover carry == 1 creates one final node.

The Mental "A-Ha!" Switch:

Use a dummy sentinel head and keep looping while (p != null || q != null || carry > 0)—eliminating separate cleanup loops for unequal list lengths and trailing carry!

Pattern Trigger:

Big-integer arithmetic, unequal-length linked list merging, or carry propagation.

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap Overflow / Invalid for > 19 Digits

Convert both linked lists into 64-bit integers (Long), add them, and convert the sum back into linked-list nodes.

Wasted Work: Constraints allow up to 100 digits! Even unsigned 64-bit integers overflow at 20 digits, failing immediately.
The Optimal Breakthrough O(max(M, N)) Time, O(max(M, N)) Output Space

Walk p and q simultaneously with a dummy head and integer carry. Treat null pointers as digit 0 and continue as long as p != null || q != null || carry > 0.

Core Invariant: At step k, carry holds the exact overflow from digit position k - 1, and curr points to the last finalized result node.
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
Trap: Convert Lists to 64-bit Long O(M + N) O(M + N) Overflows above 19 digits (constraints allow 100!).
Optimal: Dummy Head + Carry Loop O(max(M, N)) O(max(M, N)) ★ Handles arbitrary 100+ digit precision and trailing carry.

2. Core Traversal & Decision Rule

Walk p and q simultaneously with a dummy head and integer carry. Treat null pointers as digit 0 and continue as long as p != null || q != null || carry > 0. At each step, instead of re-scanning elements we already visited, we use our maintained state to make an immediate local decision.

3. Invariant Maintenance & State Transition

I initialize dummy = ListNode(0), curr = dummy, carry = 0, and loop while p != null || q != null || carry > 0. Each step sums carry + (p?.val ?: 0) + (q?.val ?: 0), writes ListNode(sum % 10) to curr.next, updates carry = sum / 10, and advances p, q, and curr. Throughout every transition, we preserve the core invariant: At step k, carry holds the exact overflow from digit position k - 1, and curr points to the last finalized result node.

4. Termination & Output Guarantee

Check for early-exit conditions (l1 = [9,9], l2 = [1] -> Unequal lengths plus trailing carry; loop runs while (p != null || q != null || carry > 0) -> [0,0,1].). Once traversal completes, return the accumulated result. Putting carry > 0 right inside the while condition handles [9,9] + [1] = [0,0,1] with zero extra post-loop if checks!

Approach 1: Two-Pass Separate Remainder Loops

Loop while both p and q are non-null, then handle remaining tail nodes and final carry in separate loops.

Time: O(max(M, N)) Space: O(max(M, N)) 
class Solution {
    fun addTwoNumbers(l1: ListNode?, l2: ListNode?): ListNode? {
        val dummy = ListNode(0)
        var curr = dummy
        var p = l1
        var q = l2
        var carry = 0
        while (p != null && q != null) {
            val sum = p.`val` + q.`val` + carry
            carry = sum / 10
            curr.next = ListNode(sum % 10)
            curr = curr.next!!
            p = p.next
            q = q.next
        }
        var rem = p ?: q
        while (rem != null) {
            val sum = rem.`val` + carry
            carry = sum / 10
            curr.next = ListNode(sum % 10)
            curr = curr.next!!
            rem = rem.next
        }
        if (carry > 0) curr.next = ListNode(carry)
        return dummy.next
    }
}
Kotlin Runtime & Memory Nuance:

Correct, but duplicates the carry-update and node-creation block unnecessarily.

class Solution:
    def addTwoNumbers(self, l1: ListNode | None, l2: ListNode | None) -> ListNode | None:
        dummy = ListNode(0)
        curr = dummy
        p, q, carry = l1, l2, 0
        while p and q:
            s = p.val + q.val + carry
            carry = s // 10
            curr.next = ListNode(s % 10)
            curr = curr.next
            p, q = p.next, q.next
        rem = p or q
        while rem:
            s = rem.val + carry
            carry = s // 10
            curr.next = ListNode(s % 10)
            curr = curr.next
            rem = rem.next
        if carry:
            curr.next = ListNode(carry)
        return dummy.next

Requires two separate while loops plus a trailing carry check.

class Solution {
    public ListNode addTwoNumbers(ListNode l1, ListNode l2) {
        ListNode dummy = new ListNode(0), curr = dummy;
        ListNode p = l1, q = l2;
        int carry = 0;
        while (p != null && q != null) {
            int sum = p.val + q.val + carry;
            carry = sum / 10;
            curr.next = new ListNode(sum % 10);
            curr = curr.next;
            p = p.next; q = q.next;
        }
        ListNode rem = (p != null) ? p : q;
        while (rem != null) {
            int sum = rem.val + carry;
            carry = sum / 10;
            curr.next = new ListNode(sum % 10);
            curr = curr.next;
            rem = rem.next;
        }
        if (carry > 0) curr.next = new ListNode(carry);
        return dummy.next;
    }
}
Java Runtime & Memory Nuance:

More verbose than unifying all three conditions into one single loop.

Approach 2: Unified Dummy-Head Carry Loop

Unify p, q, and trailing carry inside a single while (p != null || q != null || carry > 0) loop.

Time: O(max(M, N)) Space: O(max(M, N)) 
class Solution {
    fun addTwoNumbers(l1: ListNode?, l2: ListNode?): ListNode? {
        val dummy = ListNode(0)
        var curr = dummy
        var p = l1
        var q = l2
        var carry = 0
        while (p != null || q != null || carry > 0) {

            curr.next = ListNode(sum % 10)
            curr = curr.next!!
            p = p?.next
            q = q?.next
        }
        return dummy.next
    }
}

Kotlin null-safe ?. and Elvis ?: 0 operators handle unequal lengths and trailing carry in one clean loop.

Python Runtime & Memory Nuance:

Integer floor division // 10 and modulo % 10 preserve arbitrary 100+ digit precision cleanly.

class Solution {
    public ListNode addTwoNumbers(ListNode l1, ListNode l2) {
        ListNode dummy = new ListNode(0);
        ListNode curr = dummy;
        ListNode p = l1, q = l2;
        int carry = 0;
        while (p != null || q != null || carry > 0) {
            int x = (p != null) ? p.val : 0;
            int y = (q != null) ? q.val : 0;
            int sum = carry + x + y;
            carry = sum / 10;
            curr.next = new ListNode(sum % 10);
            curr = curr.next;
            if (p != null) p = p.next;
            if (q != null) q = q.next;
        }
        return dummy.next;
    }
}
Java Runtime & Memory Nuance:

Dummy sentinel eliminates head null checks and avoids mutating caller-owned input nodes.
