Problem #528: Random Pick with Weight

View on NeetCode ↗

Official Problem Statement

You are given a 0-indexed array of positive integers w where w[i] describes the weight of the ith index.

You need to implement the function pickIndex(), which randomly picks an index in the range [0, w.length - 1] (inclusive) and returns it. The probability of picking an index i is w[i] / sum(w).

For example, if w = [1, 3], the probability of picking index 0 is 1 / (1 + 3) = 0.25 (25%), and the probability of picking index 1 is 3 / (1 + 3) = 0.75 (75%).

Example 1: Solution([1]), pickIndex() → Output: 0 (100% probability)

Example 2: Solution([1, 3]), pickIndex() x4 → Output: [1, 1, 1, 0] (~75% 1s, ~25% 0s)

Example 3: Solution([1, 9]), pickIndex() x100 → Output: ~10% index 0, ~90% index 1

Plain-English Translation & Core Nuance

Given positive weights, build a weighted random sampler so each index is chosen proportionally to its share of the total weight—without duplicating elements in a giant array.

Official Constraints:
  • 1 <= w.length <= 10^4
  • 1 <= w[i] <= 10^5
  • pickIndex will be called at most 10^4 times.

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
w = [5] (Single element) -> Prefix sum is [5]; every random target in 1..5 maps to index 0.
Best-Case Early Exit
w = [1, 999] -> Target lands in [2..1000] 99.9% of the time; binary search resolves index 1 in O(log N).
Worst-Case Full Scan
w.length = 10^4, 10^4 calls -> Prefix build O(N) once; each pickIndex runs in O(log N) binary search.

The Mental Model & "Explain Like I'm 12"

💡 The Weighted Number-Line Dartboard

Imagine laying wooden planks end-to-end along a ruler, where plank i has length w[i]. For w = [1, 3, 2], plank 0 spans (0, 1], plank 1 spans (1, 4], and plank 2 spans (4, 6]. When you drop a dart at a random integer tick from 1 to 6, each plank captures an interval proportional to its weight. Because the plank endpoints [1, 4, 6] are strictly sorted, finding which plank caught your dart is a single binary search for the first endpoint >= dart!

The Mental "A-Ha!" Switch:

Convert weights into a monotonically increasing Prefix Sum array, pick a uniform random integer target in 1..totalSum, and binary search for the leftmost index where prefix[mid] >= target.

Pattern Trigger:

Weighted random sampling, load balancing by server weight, or probabilistic ad selection.

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(sum(w)) Space, O(1) Pick

Expand an explicit bucket array repeating index i exactly w[i] times, then pick a random slot.

Wasted Work: If w has 10^4 items of weight 10^5, the expanded array requires 10^9 integers (~4 GB RAM) and immediately hits Memory Limit Exceeded.
The Optimal Breakthrough O(N) Init, O(log N) Pick, O(N) Space

Precompute prefix[i] = prefix[i - 1] + w[i]. On pickIndex(), draw target in [1..total] and run lower-bound binary search (first prefix[mid] >= target).

Core Invariant: Because all w[i] >= 1, prefix[] is strictly increasing, making lower-bound binary search exact over [0..N-1].
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
Naive: Expanded Ticket Array O(W) init / O(1) pick O(sum(w)) OOM when weights reach 10^5.
Better: Prefix Sums + Linear Scan O(N) init / O(N) pick O(N) 10^4 x 10^4 = 10^8 operations -> slow.
Optimal: Prefix Sums + Lower-Bound Binary Search O(N) init / O(log N) pick O(N) ★ Production load-balancer standard.

1. Guard Clauses & State Initialization

Before entering the main loop, verify base boundaries (w = [5] (Single element) -> Prefix sum is [5]; every random target in 1..5 maps to index 0.) and allocate the primary state containers required for Random Pick with Weight so that subsequent lookups or pointer updates run in O(1) time.

2. Core Traversal & Decision Rule

Precompute prefix[i] = prefix[i - 1] + w[i]. On pickIndex(), draw target in [1..total] and run lower-bound binary search (first prefix[mid] >= target). At each step, instead of re-scanning elements we already visited, we use our maintained state to make an immediate local decision.

3. Invariant Maintenance & State Transition

In the constructor, I accumulate running total into prefix[i]. In pickIndex(), I pick target = Random.nextInt(total) + 1. Then standard lower-bound binary search with left = 0, right = prefix.size - 1: if prefix[mid] >= target, keep mid with right = mid; else advance left = mid + 1. Return left. Throughout every transition, we preserve the core invariant: Because all w[i] >= 1, prefix[] is strictly increasing, making lower-bound binary search exact over [0..N-1].

4. Termination & Output Guarantee

Check for early-exit conditions (w = [1, 999] -> Target lands in [2..1000] 99.9% of the time; binary search resolves index 1 in O(log N).). Once traversal completes, return the accumulated result. Target 1 maps to idx 0 (1/6); targets 2, 3, 4 map to idx 1 (3/6); targets 5, 6 map to idx 2 (2/6).

Production Implementations

From Naive to Optimal & Runnable Practice Arena

Strict ordering: Kotlin (Default) → Python → Java across all approaches.

Approach 1: Prefix Sum + Linear Scan

Build prefix sums in O(N), then scan linearly for the first bucket exceeding random target.

Time: O(N) pick Space: O(N) 
import kotlin.random.Random

class Solution(w: IntArray) {
    private val prefix = IntArray(w.size)
    private var total = 0

    init {
        for (i in w.indices) {
            total += w[i]
            prefix[i] = total
        }
    }

    fun pickIndex(): Int {
        val target = Random.nextInt(total) + 1
        for (i in prefix.indices) {
            if (prefix[i] >= target) return i
        }
        return prefix.size - 1
    }
}
Kotlin Runtime & Memory Nuance:

Linear scan takes O(N) per pickIndex() call, timing out when N=10^4 and pickIndex runs 10^4 times.

import random

class Solution:
    def __init__(self, w: list[int]):
        self.prefix = []
        total = 0
        for weight in w:
            total += weight
            self.prefix.append(total)
        self.total = total

    def pickIndex(self) -> int:
        target = random.randint(1, self.total)
        for i, val in enumerate(self.prefix):
            if val >= target:
                return i
        return len(self.prefix) - 1
Python Runtime & Memory Nuance:

Avoids memory explosion of naive bucket expansion, but O(N) scan per pick fails latency SLAs.

import java.util.Random;

class Solution {
    private final int[] prefix;
    private int total = 0;
    private final Random rand = new Random();

    public Solution(int[] w) {
        prefix = new int[w.length];
        for (int i = 0; i < w.length; i++) {
            total += w[i];
            prefix[i] = total;
        }
    }

    public int pickIndex() {
        int target = rand.nextInt(total) + 1;
        for (int i = 0; i < prefix.length; i++) {
            if (prefix[i] >= target) return i;
        }
        return prefix.length - 1;
    }
}
Java Runtime & Memory Nuance:

Precomputes primitive int[] prefix cleanly, though linear lookup wastes sorted monotonicity.

Approach 2: Prefix Sum + Lower-Bound Binary Search

Precompute prefix sums in O(N) and resolve random targets in O(log N) with lower-bound binary search.

Time: O(log N) pick Space: O(N) 
import kotlin.random.Random

class Solution(w: IntArray) {
    private val prefix = IntArray(w.size)
    private var total = 0

    init {
        for (i in w.indices) {
            total += w[i]
            prefix[i] = total
        }
    }

    fun pickIndex(): Int {
        val target = Random.nextInt(total) + 1
        var left = 0
        var right = prefix.size - 1
        while (left < right) {
            val mid = left + (right - left) / 2
            if (prefix[mid] >= target) {
                right = mid
            } else {
                left = mid + 1
            }
        }
        return left
    }
}
Kotlin Runtime & Memory Nuance:

Uses unboxed IntArray for prefix sums and Random.nextInt(total) + 1 to draw uniform integer ticks in [1..total].

import bisect
import random

class Solution:
    def __init__(self, w: list[int]):
        self.prefix = []
        total = 0
        for weight in w:
            total += weight
            self.prefix.append(total)
        self.total = total

    def pickIndex(self) -> int:
        target = random.randint(1, self.total)
        return bisect.bisect_left(self.prefix, target)
Python Runtime & Memory Nuance:

bisect.bisect_left runs in C and returns the exact leftmost index where prefix[i] >= target in O(log N).

import java.util.Random;

class Solution {
    private final int[] prefix;
    private int total = 0;
    private final Random rand = new Random();

    public Solution(int[] w) {
        prefix = new int[w.length];
        for (int i = 0; i < w.length; i++) {
            total += w[i];
            prefix[i] = total;
        }
    }

    public int pickIndex() {
        int target = rand.nextInt(total) + 1;
        int left = 0;
        int right = prefix.length - 1;
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (prefix[mid] >= target) {
                right = mid;
            } else {
                left = mid + 1;
            }
        }
        return left;
    }
}
Java Runtime & Memory Nuance:

Halves the search range with overflow-safe mid = left + (right - left) / 2 and zero per-query allocations.
