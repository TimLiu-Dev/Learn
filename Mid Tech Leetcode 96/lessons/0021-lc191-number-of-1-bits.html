LeetCode 191: Number of 1 Bits

Official LC #191

Official Problem Statement

Given a positive integer n, write a function that returns the number of set bits (1s) in its binary representation (also known as the Hamming weight).

Example 1: n = 11 → Output: 3 (11 in binary is 1011)

Example 2: n = 128 → Output: 1 (128 in binary is 10000000)

Example 3: n = 2147483645 → Output: 30

Constraints: 1 <= n <= 2^31 - 1

Plain-English Translation & Core Nuance

Count how many 1s appear when n is written in base 2. While checking all 32 bits takes constant time O(32), senior candidates know the optimal algorithm:

Brian Kernighan's Algorithm: In a binary integer, the expression n & (n - 1) flips the lowest set bit (rightmost 1) to 0 while leaving every other bit completely untouched.

By repeating n = n & (n - 1) until n == 0, the loop runs strictly K times, where K is the exact number of set bits!

Brian Kernighan's Bit-Clearing Mechanics

Trace for n = 11 (binary 1011):

Iteration 1:
      n     = 1011  (11)
    n - 1   = 1010  (10)
  n & (n-1) = 1010  (10)  --> Cleared rightmost bit at index 0. Count = 1

Iteration 2:
      n     = 1010  (10)
    n - 1   = 1001  (9)
  n & (n-1) = 1000  (8)   --> Cleared rightmost bit at index 1. Count = 2

Iteration 3:
      n     = 1000  (8)
    n - 1   = 0111  (7)
  n & (n-1) = 0000  (0)   --> Cleared rightmost bit at index 3. Count = 3

n is now 0. Loop terminates in exactly 3 iterations instead of 32!
Constraints
1 ≤ n ≤ 2^31 - 1
Positive 32-bit integer range. Zero can also be handled cleanly.
Optimal Complexity
Time: O(K) where K = set bits • Space: O(1)
K ≤ 32. For sparse bits (e.g. 1024), completes in 1 iteration!
Power of Two Property
n & (n - 1) == 0
If n has exactly one 1-bit, it becomes 0 after 1 step (LeetCode 231).

Section 1

Mental Model & Pattern Recognition

The Physical Metaphor: Knocking Down Standing Dominoes

Imagine a row of 32 domino pins. Most are already fallen (0s), with only a few standing tall (1s).

If you check every single domino from left to right, you must inspect all 32 positions every time.

Subtracting 1 from a binary number acts like a laser targeted precisely at the lowest standing pin: it knocks it down to 0 and flips trailing zeros to 1s.

Bitwise ANDing n & (n - 1) extinguishes that lowest standing pin while canceling the flipped trailing 1s. Each operation eliminates exactly one standing domino!

Section 2

Naive Trap vs. Optimal Breakthrough

×

The Naive Trap: String Conversion or Fixed 32 Loops

Converting Integer.toBinaryString(n) creates unnecessary heap allocations and garbage collection overhead.

A loop that shifts 32 times (n & 1; n >>>= 1) works in O(32), but always executes 32 full iterations even if n = 1.

Also: using signed shift (>>) instead of logical unsigned shift (>>>) causes infinite loops on negative numbers!

✓

The Optimal Breakthrough: Brian Kernighan's Algorithm

Instead of examining inactive 0-bits, jump directly from one set bit to the next:

while (n != 0) {

    n = n & (n - 1);

    count++;

}

→ Loops strictly K times (where K = number of 1-bits). O(K) Time, O(1) Space.

Approach Time Complexity Space Complexity Pros Cons
1. String Conversion O(32) O(32) One-liner in high-level languages Heap allocation, poor performance
2. 32-Bit Unsigned Shift O(32) constant O(1) No memory allocations Always runs 32 times even for n = 1
★ 3. Brian Kernighan (Optimal) O(K) O(1) Loops only over 1-bits; extremely fast Requires knowledge of bit trick

Solution Evolution: From Naive to Optimal

Approach 1: Convert to Binary String

Time: O(32) • Space: O(32) string memory overhead

class Solution {
    fun hammingWeight(n: Int): Int {
        // Form string representation and count characters
        return Integer.toBinaryString(n).count { it == '1' }
    }
}
class Solution:
    def hammingWeight(self, n: int) -> int:
        return bin(n).count('1')
class Solution {
    public int hammingWeight(int n) {
        String binary = Integer.toBinaryString(n);
        int count = 0;
        for (char c : binary.toCharArray()) {
            if (c == '1') count++;
        }
        return count;
    }
}

Approach 2: 32-Bit Logical Right Shift

Time: O(32) constant iterations • Space: O(1) auxiliary space

class Solution {
    fun hammingWeight(n: Int): Int {
        var count = 0
        var num = n
        for (i in 0 until 32) {
            count += (num and 1)
            num = num ushr 1 // Unsigned logical shift
        }
        return count
    }
}
class Solution:
    def hammingWeight(self, n: int) -> int:
        count = 0
        for _ in range(32):
            count += (n & 1)
            n >>= 1
        return count
class Solution {
    public int hammingWeight(int n) {
        int count = 0;
        for (int i = 0; i < 32; i++) {
            count += (n & 1);
            n >>>= 1; // Logical shift without sign extension
        }
        return count;
    }
}

★ Approach 3: Brian Kernighan's Algorithm (Optimal)

Time: O(K) where K = number of 1-bits • Space: O(1) auxiliary space

class Solution {
    fun hammingWeight(n: Int): Int {
        var count = 0
        var num = n
        while (num != 0) {
            // Clears the lowest set bit in a single operation
            num = num and (num - 1)
            count++
        }
        return count
    }
}

    def hammingWeight(self, n: int) -> int:
        count = 0
        while n != 0:
            n &= (n - 1)  # Strips lowest 1-bit
            count += 1
        return count

    public int hammingWeight(int n) {

            count++;
        }
        return count;
    }
}

Mock Interview Dialogue & Senior Follow-Ups

      


      

        

          
1. Clarification & Signedness:

          
Candidate: "How should negative numbers or signed integers be treated? In Java, ints are signed 32-bit values."

          
Interviewer: "Treat the 32-bit pattern as an unsigned bitfield. The prompt specifies positive integers, but your code should handle any 32-bit word cleanly."

          
Candidate: "Understood. That means if we used a shift loop, we must use the logical unsigned right shift `>>>` rather than the arithmetic shift `>>`."

        


        

          
2. Proposing Brian Kernighan's Algorithm:

          
Candidate: "Instead of running 32 iterations, we can use Brian Kernighan's bit manipulation trick: `n = n & (n - 1)`. In binary arithmetic, subtracting 1 flips the rightmost 1-bit and turns all trailing zeros to 1s. Performing a bitwise AND cancels out that lowest 1-bit and all trailing bits. Thus, each iteration clears exactly one set bit, running in O(K) time where K is the number of 1-bits."

        


        

          
3. Senior Staff Follow-Up: Hardware POPCNT & SWAR Parallel Counting

          
Interviewer: "If this function is called billions of times per second in a real-time network packet router, can we do even better than O(K) branches?"

          
Candidate: "Yes! Modern x86 and ARM CPUs offer dedicated single-cycle hardware instructions: `POPCNT` on x86 and `VCNT` on ARM, accessible via Java's `Integer.bitCount()` or C++ `__builtin_popcount()`. If restricted to pure ALU operations without popcount instructions, we can use SWAR (SIMD Within A Register) divide-and-conquer bit masks to count all 32 bits in just 12 parallel arithmetic operations without any loops or branches!"
