LeetCode #973: K Closest Points to Origin

Official LC #973

Official Problem Statement

Given an array of points where points[i] = [xi, yi] represents a point on the X-Y plane and an integer k, return the k closest points to the origin (0, 0).

The distance between two points on the X-Y plane is the Euclidean distance (i.e., √(x1 - x2)2 + (y1 - y2)2).

You may return the answer in any order. The answer is guaranteed to be unique (except for the order that it is in).

Example 1: points = [[1,3],[-2,2]], k = 1 → Output: [[-2,2]] Explanation: (1)^2 + (3)^2 = 10, (-2)^2 + (2)^2 = 8. Since 8 < 10, [-2,2] is closer.

Example 2: points = [[3,3],[5,-1],[-2,4]], k = 2 → Output: [[3,3],[-2,4]] (or in reverse order)

Plain-English Translation & Core Nuance

Compare points by their squared Euclidean distance `x^2 + y^2` (avoiding floating point square root calculations). Maintain a Max-Heap of size `k`. When size exceeds `k`, eject the point with the largest distance. At the end, the heap contains the `k` closest points.

Official Constraints:
  • 1 <= k <= points.length <= 10^4
  • -10^4 <= x_i, y_i <= 10^4

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
k == points.length → All points are requested; return the input array immediately.
Best-Case Early Exit
Point at origin [0, 0] → Distance is 0, guaranteed to enter and stay in the heap.
Worst-Case Full Scan
Ties in distance → Problem statement guarantees return order does not matter.

The Mental Model & "Explain Like I'm 12"

💡 The Perimeter Defense Dome (Max-Heap of Size K)

You have a defensive shield that can only shelter the k closest targets to the central fortress (0,0). To ensure only the closest k units stay inside, the perimeter scanner always tracks the MOST DISTANT unit currently inside the shelter (Max-Heap root). When a new unit approaches, if it is closer than the furthest sheltered unit, the outermost unit is kicked outside the dome, and the closer one takes its spot.

The Mental "A-Ha!" Switch:

We do NOT need `Math.sqrt()`! Because f(d) = \sqrt{d} is strictly monotonically increasing for d ≥ 0, comparing x^2 + y^2 preserves the exact same relative ordering while avoiding floating-point inaccuracies.

Pattern Trigger:

Find K smallest / closest items → Max-Heap of size K (eject largest when size > K).

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(N log N) Time, O(N) Space

Sort all points by x^2 + y^2 using full quicksort or mergesort, then slice the first k elements.

Wasted Work: Sorting all N elements when we only need the smallest k in arbitrary order.
The Optimal Breakthrough O(N log K) Time, O(K) Space

Max-Heap of size k keyed on squared distance x^2 + y^2. Memory is strictly bounded by K.

Core Invariant: The Max-Heap root holds the point with the greatest distance among the current k closest candidates.

Full Array Sort by Distance (Naive)

Sort all points by squared distance in ascending order, then return the first k elements.

Time: O(N log N) Space: O(N) 
class Solution {
    fun kClosest(points: Array<IntArray>, k: Int): Array<IntArray> {
        points.sortWith { a, b ->
            val distA = a[0] * a[0] + a[1] * a[1]
            val distB = b[0] * b[0] + b[1] * b[1]
            distA.compareTo(distB)
        }
        return points.copyOfRange(0, k)
    }
}

QuickSelect on Distance (In-Place Linear Average)

Partition points around a pivot distance until the k smallest are in indices 0 to k-1.

Time: O(N) Average, O(N^2) Worst Space: O(1) Auxiliary 
class Solution {
    fun kClosest(points: Array<IntArray>, k: Int): Array<IntArray> {
        var left = 0
        var right = points.size - 1

        while (left <= right) {
            val pivotIdx = partition(points, left, right)
            when {
                pivotIdx == k -> break
                pivotIdx < k -> left = pivotIdx + 1
                else -> right = pivotIdx - 1
            }
        }
        return points.copyOfRange(0, k)
    }

    private fun partition(points: Array<IntArray>, left: Int, right: Int): Int {
        val pivotDist = dist(points[right])
        var p = left
        for (i in left until right) {
            if (dist(points[i]) <= pivotDist) {
                val temp = points[p]
                points[p] = points[i]
                points[i] = temp
                p++
            }
        }
        val temp = points[p]
        points[p] = points[right]
        points[right] = temp
        return p
    }

    private fun dist(p: IntArray) = p[0] * p[0] + p[1] * p[1]
}
Kotlin Runtime & Memory Nuance:

In-place QuickSelect eliminates extra memory. Worst-case is O(N^2) on bad pivot choices.

Max-Heap of Size K (Optimal Primary)

Maintain a Max-Heap of capacity k. Eject the furthest point when size > k. Optimal for stream processing.

Time: O(N log K) Space: O(K) 
class Solution {
    /**
     * Optimal: Max-Heap of Size K
     * Time: O(N log K) - Each point insertion takes log K
     * Space: O(K) - Heap capacity strictly bounded by K
     */
    fun kClosest(points: Array<IntArray>, k: Int): Array<IntArray> {
        val maxHeap = java.util.PriorityQueue<IntArray> { a, b ->
            val distA = a[0] * a[0] + a[1] * a[1]
            val distB = b[0] * b[0] + b[1] * b[1]
            distB.compareTo(distA) // Furthest at top
        }

        for (pt in points) {
            maxHeap.offer(pt)
            if (maxHeap.size > k) {
                maxHeap.poll()
            }
        }

        val result = Array(k) { IntArray(2) }
        var i = 0
        while (maxHeap.isNotEmpty()) {
            result[i++] = maxHeap.poll()
        }
        return result
    }
}

Using squared distance eliminates `Math.sqrt()` float precision and CPU cycles.

class Solution {
    /**
     * Optimal: Max-Heap of Size K
     * Time: O(N log K) - Consistent heap maintenance
     * Space: O(K) - Heap bounded to K points
     */
    public int[][] kClosest(int[][] points, int k) {
        PriorityQueue<int[]> maxHeap = new PriorityQueue<>((a, b) -> {
            int distA = a[0] * a[0] + a[1] * a[1];
            int distB = b[0] * b[0] + b[1] * b[1];
            return Integer.compare(distB, distA);
        });

        for (int[] pt : points) {
            maxHeap.offer(pt);
            if (maxHeap.size() > k) {
                maxHeap.poll();
            }
        }

        int[][] result = new int[k][2];
        for (int i = 0; i < k; i++) {
            result[i] = maxHeap.poll();
        }
        return result;
    }
}
Java Runtime & Memory Nuance:

Use `Integer.compare` to prevent subtraction integer underflow/overflow bugs.
