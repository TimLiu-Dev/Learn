Problem #143: Reorder List

View on NeetCode ↗

Official Problem Statement

You are given the head of a singly linked-list. The list can be represented as:
L0 → L1 → ... → Ln - 1 → Ln
Reorder the list to be on the following form:
L0 → Ln → L1 → Ln - 1 → L2 → Ln - 2 → ...

You may not modify the values in the list's nodes. Only nodes themselves may be changed.

Example 1: head = [1,2,3,4] → Output: [1,4,2,3]

Example 2: head = [1,2,3,4,5] → Output: [1,5,2,4,3]

Example 3: head = [1] → Output: [1]

Plain-English Translation & Core Nuance

Fold a singly linked list in half from the outside in (1st -> last -> 2nd -> 2nd-to-last...) strictly in O(1) extra space by rewiring node pointers.

Official Constraints:
  • The number of nodes in the list is in the range [1, 5 * 10^4].
  • 1 <= Node.val <= 1000

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
head = [1] or [1, 2] -> Zero or one link; loop terminates immediately with zero cycles.
Best-Case Early Exit
head = [1, 2, 3, 4] (Even length) -> Split [1,2] and [4,3], zip into [1,4,2,3].
Worst-Case Full Scan
head = [1, 2, 3, 4, 5] (Odd length) -> Split [1,2,3] and [5,4]; MUST sever slow.next = null to prevent cycle!

The Mental Model & "Explain Like I'm 12"

💡 Cutting a Deck of Cards & Perfect Riffle Shuffle

You can't walk backwards in a singly linked list. So to pair the front card with the back card, cut the deck cleanly in half using slow/fast pointers, reverse the second half on the table so the bottom card is now on top, and zip the two halves together one card at a time!

The Mental "A-Ha!" Switch:

Reorder List is a 3-act synthesis of Pass 1 primitives: (1) Find Middle (Slow/Fast) + Cut (slow.next = null), (2) Reverse Second Half (#206), (3) Interleave Merge (#21-style).

Pattern Trigger:

Pairing front-and-back elements in a singly linked list in O(1) space.

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(N) Time, O(N) Space

Copy all ListNode references into an ArrayList, then rewire pointers using inward two pointers left++ and right--.

Wasted Work: Allocates an O(N) pointer array on the heap instead of doing pure O(1) in-place pointer rewiring.
The Optimal Breakthrough O(N) Time, O(1) Space

1) Find middle with slow/fast; 2) Split list via second = slow.next; slow.next = null; 3) Reverse second half; 4) Interleave first and second halves alternating next pointers.

Core Invariant: Cutting slow.next = null guarantees two strictly disjoint acyclic halves before interleaving.
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
Better: ArrayList + Two Pointers O(N) O(N) Valid warmup, but wastes O(N) heap array.
Optimal: Mid-Split + Reverse + Zip O(N) O(1) ★ Canonical O(1) pointer synthesis.

1. Guard Clauses & State Initialization

Before entering the main loop, verify base boundaries (head = [1] or [1, 2] -> Zero or one link; loop terminates immediately with zero cycles.) and allocate the primary state containers required for Reorder List so that subsequent lookups or pointer updates run in O(1) time.

2. Core Traversal & Decision Rule

1) Find middle with slow/fast; 2) Split list via second = slow.next; slow.next = null; 3) Reverse second half; 4) Interleave first and second halves alternating next pointers. At each step, instead of re-scanning elements we already visited, we use our maintained state to make an immediate local decision.

3. Invariant Maintenance & State Transition

First, advance slow by 1 and fast by 2 while fast.next != null && fast.next.next != null. Second, reverse slow.next and set slow.next = null to prevent a cycle. Third, zip first and second by saving tmp1 = first.next, tmp2 = second.next, linking first.next = second, second.next = tmp1, and advancing both. Throughout every transition, we preserve the core invariant: Cutting slow.next = null guarantees two strictly disjoint acyclic halves before interleaving.

4. Termination & Output Guarantee

Check for early-exit conditions (head = [1, 2, 3, 4] (Even length) -> Split [1,2] and [4,3], zip into [1,4,2,3].). Once traversal completes, return the accumulated result. Forgetting slow.next = null leaves node 3 pointing to 4, creating an infinite cycle when zipping!

From Naive to Optimal & Runnable Practice Arena

Approach 1: ArrayList Copy + Two Pointers

Store node pointers in a flat ArrayList and rewire using inward left/right indices.

Time: O(N) Space: O(N) 
class Solution {
    fun reorderList(head: ListNode?): Unit {
        if (head?.next == null) return
        val nodes = ArrayList<ListNode>()
        var curr = head
        while (curr != null) {
            nodes.add(curr)
            curr = curr.next
        }
        var l = 0
        var r = nodes.size - 1
        while (l < r) {
            nodes[l].next = nodes[r]
            l++
            if (l == r) break
            nodes[r].next = nodes[l]
            r--
        }
        nodes[l].next = null
    }
}
Kotlin Runtime & Memory Nuance:

Easy to reason about, but uses O(N) auxiliary list memory.

import java.util.*;

class Solution {
    public void reorderList(ListNode head) {
        if (head == null || head.next == null) return;
        List<ListNode> nodes = new ArrayList<>();
        ListNode curr = head;
        while (curr != null) {
            nodes.add(curr);
            curr = curr.next;
        }
        int l = 0, r = nodes.size() - 1;
        while (l < r) {
            nodes.get(l).next = nodes.get(r);
            l++;
            if (l == r) break;
            nodes.get(r).next = nodes.get(l);
            r--;
        }
        nodes.get(l).next = null;
    }
}
Java Runtime & Memory Nuance:

Must remember nodes.get(l).next = null at the end to terminate the reordered chain.

Approach 2: Mid-Split + Reverse + In-Place Zip

Find middle via slow/fast, sever & reverse second half, and interleave nodes in O(1) space.

Time: O(N) Space: O(1) 
class Solution {
    fun reorderList(head: ListNode?): Unit {
        if (head?.next == null) return
        var slow = head
        var fast = head
        while (fast?.next != null && fast.next?.next != null) {
            slow = slow?.next
            fast = fast.next?.next
        }
        var second = reverseList(slow?.next)
        slow?.next = null

        var first = head
        while (second != null) {
            val tmp1 = first?.next
            val tmp2 = second.next
            first?.next = second
            second.next = tmp1
            first = tmp1
            second = tmp2
        }
    }

    private fun reverseList(node: ListNode?): ListNode? {
        var prev: ListNode? = null
        var curr = node
        while (curr != null) {
            val nxt = curr.next
            curr.next = prev
            prev = curr
            curr = nxt
        }
        return prev
    }
}
Kotlin Runtime & Memory Nuance:

Strict O(1) space using only scalar node references across all 3 phases.

Saving tmp1, tmp2 before rewiring prevents losing tail references during interleaving.

class Solution {
    public void reorderList(ListNode head) {
        if (head == null || head.next == null) return;
        ListNode slow = head, fast = head;
        while (fast.next != null && fast.next.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }
        ListNode second = reverseList(slow.next);
        slow.next = null;

        ListNode first = head;
        while (second != null) {
            ListNode tmp1 = first.next;
            ListNode tmp2 = second.next;
            first.next = second;
            second.next = tmp1;
            first = tmp1;
            second = tmp2;
        }
    }

    private ListNode reverseList(ListNode node) {
        ListNode prev = null, curr = node;
        while (curr != null) {
            ListNode nxt = curr.next;
            curr.next = prev;
            prev = curr;
            curr = nxt;
        }
        return prev;
    }
}
Java Runtime & Memory Nuance:

Severing slow.next = null before merging guarantees zero linked-list cycles.
