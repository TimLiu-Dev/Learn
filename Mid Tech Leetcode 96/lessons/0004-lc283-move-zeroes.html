LeetCode #283 Easy Two Pointers

Move Zeroes

View on LeetCode ↗

Problem Description

Given an integer array nums, move all 0's to the end of it while maintaining the relative order of the non-zero elements.

Note: You must do this in-place without making a copy of the array.

🗣️
Plain-English Translation:

"Compact the list so all actual numbers pack together at the front in their original order, while all zeroes are flushed to the back. You cannot create a second array; you must rearrange the original numbers directly in-place."

Official Examples

Example 1:
Input: nums = [0,1,0,3,12]
Output: [1,3,12,0,0]
Relative order of 1, 3, 12 is preserved at front; two zeroes at end.
Example 2:
Input: nums = [0]
Output: [0]
Single element array with zero remains zero.
Official Constraints:
  • 1 <= nums.length <= 104 (N up to 10,000 → O(N²) quadratic shifts will TLE)
  • -231 <= nums[i] <= 231 - 1 (Elements span full 32-bit signed integers, can be negative)
  • Follow-up: Could you minimize the total number of operations done? (Solved by the Swap method)
The 3 Canonical Input Shapes (Mental Boundary Checks):
1. All Zeroes
nums = [0, 0, 0]
fast pointer never finds non-zero; slow stays at 0. Exactly 0 swaps performed.
2. No Zeroes (Already Compact)
nums = [1, 2, 3]
slow and fast move lockstep together. Redundant self-swaps should be guarded.
3. Heavy Leading Zeroes
nums = [0, 0, 0, 1]
fast travels to end before first non-zero is found; 1 is swapped into index 0.

          🚜 The Real-World Analogy
        

        
The Factory Conveyor Belt Sorter & Scout

        

          Imagine a factory conveyor belt carrying shipping boxes. Some boxes have valuable cargo (non-zero numbers), while others are empty placeholder air bubbles (0s).
        

        

          You need to compress all real cargo to the front of the conveyor without moving the belt backward.
        

        

          Two workers stand by the belt:
        

        
    
          
  • The Sorter (slow pointer): Stands at the current destination where the next real cargo box belongs.
    • 
          
  • The Scout (fast pointer): Walks ahead looking at incoming boxes. If the scout sees an empty bubble (0), they ignore it and keep walking. But the moment the scout finds real cargo (!= 0), they swap it with the empty slot at the Sorter (slow), and the Sorter steps forward one space!
    • 
        

        

          When the Scout reaches the end of the belt, every piece of real cargo is packed neatly in front, and all the empty bubbles have naturally accumulated at the rear!
        

      


      
      

        
        

          

            💡 The "A-Ha!" Switch
          

          
Flip the Problem: Move Non-Zeroes, Not Zeroes

          

            Beginners obsess over "how do I shift zeroes to the end?" Trying to bubble zeroes to the end takes O(N) operations for every zero found, exploding to an O(N^2) quadratic disaster.
          

          

            The breakthrough: Ignore the zeroes completely! Focus solely on discovering non-zeroes and placing them sequentially at index slow++. The zeroes will take care of themselves.
          

        


        
        

          

            🎯 Pattern Recognition Trigger

            Reach for Same-Direction Fast/Slow Two Pointers whenever:
          

          
    
            
  • You must filter, compact, or partition an array in-place (O(1) space)
    • 
            
  • You must preserve the relative order of remaining elements

        02
        

          Algorithmic Trade-offs
          
The Naive Trap (Red) vs. Optimal Breakthrough (Green)

        

      


      

        
        

          

            
              The Naive Trap (Shifting on Zero)
            
            O(N²) Time
          


          
Shifting Array Elements on Every Zero

          

            When a zero is found, shift all subsequent N - i elements one position to the left, and append zero to the end.
          


          

            Why this is an interview failure:
            
    
              
  • Takes O(N) operations for each zero. An array of zeroes with alternating numbers degrades to O(N^2) quadratic runtime.
    • 
              
  • Or, allocating an auxiliary array copies everything in O(N) space, directly violating the prompt's "in-place without making a copy" rule!
    • 
            

          

        


        
        

          

            
              Optimal (Two-Pointer In-Place Swap)
            
            O(N) Time • O(1) Space
          


          
Single Pass with Minimal Memory Writes

          

            Fast pointer scans every element exactly once. Whenever nums[fast] != 0, swap with nums[slow] and advance slow++.
          


          

            Why this answers the follow-up:
            
    
              
  • Time is strictly linear O(N) with zero extra heap allocations (O(1) space).
    • 
              
  • Only performs writes when a non-zero element is encountered, answering the interview follow-up: "Could you minimize the total number of operations done?"
    •

          Solution Evolution & Production Code
          
From Brute Force to Optimal & Interactive Sandbox

        

      


      
      

        
        

          

            Approach:
            

              
              
              
            

          


          
          

            Time: O(N) | Space: O(1) • ★ Minimal Operations
          

        


        
        

          

            
            
            
          


          
        


        
        

          
          
          
          
          

            
class Solution {
    /**
     * Approach 1: Auxiliary Array Copy
     * 
     * Time Complexity:  O(N)
     * Space Complexity: O(N) - Violates strict in-place problem constraint!
     */
    fun moveZeroes(nums: IntArray) {
        val nonZeroes = IntArray(nums.size)
        var writeIdx = 0

        for (num in nums) {
            if (num != 0) {
                nonZeroes[writeIdx++] = num
            }
        }

        // Copy back to original array
        for (i in nums.indices) {
            nums[i] = nonZeroes[i]
        }
    }
}

            

              Constraint Violation Warning:
              
    
                
  • Allocates a second array of size N, which directly breaks the requirement: "You must do this in-place without making a copy of the array."
    • 
              

            

          


          
          

            
class Solution:
    """
    Approach 1: Auxiliary Array Copy
    
    Time Complexity:  O(N)
    Space Complexity: O(N) auxiliary allocation.
    """
    def moveZeroes(self, nums: list[int]) -> None:
        temp = [x for x in nums if x != 0]
        zeros = len(nums) - len(temp)
        temp.extend([0] * zeros)
        nums[:] = temp  # Slice assignment mutates original list

            

              Python Memory Caveat:
              
    
                
  • List comprehension allocates O(N) extra memory. While slice assignment nums[:] = temp modifies in place, it fails memory constraints.
    • 
              

            

          


          
          

            
class Solution {
    /**
     * Approach 1: Auxiliary Array Copy
     * 
     * Time Complexity:  O(N)
     * Space Complexity: O(N) extra memory.
     */
    public void moveZeroes(int[] nums) {
        int[] temp = new int[nums.length];
        int idx = 0;
        for (int num : nums) {
            if (num != 0) temp[idx++] = num;
        }
        System.arraycopy(temp, 0, nums, 0, nums.length);
    }
}

            

              Java In-Place Violation:
              
    
                
  • Allocates new int[nums.length], failing the interview test.
    • 
              

            

          


          
          
          
          
          

            
class Solution {
    /**
     * Approach 2: Overwrite Non-Zeroes then Fill Trailing Zeroes
     * 
     * Time Complexity:  O(N) - Two passes over the array.
     * Space Complexity: O(1) - Pure in-place.
     */
    fun moveZeroes(nums: IntArray) {
        var slow = 0

        // Pass 1: Compact non-zeroes forward
        for (fast in nums.indices) {
            if (nums[fast] != 0) {
                nums[slow++] = nums[fast]
            }
        }

        // Pass 2: Fill remaining tail with zeroes
        while (slow < nums.size) {
            nums[slow++] = 0
        }
    }
}

            

              Tradeoff Analysis:
              
    
                
  • O(1) space and clean code. However, it always performs N write operations because it writes every non-zero, then writes zeroes across the entire rest of the array.
    • 
                
  • Can we avoid writing redundant zeroes if they are already in place? Yes, by swapping!
    • 
              

            

          


          
          

            
class Solution:
    """
    Approach 2: Overwrite Non-Zeroes then Fill Trailing Zeroes
    
    Time Complexity:  O(N)
    Space Complexity: O(1)
    """
    def moveZeroes(self, nums: list[int]) -> None:
        slow = 0
        
        for fast in range(len(nums)):
            if nums[fast] != 0:
                nums[slow] = nums[fast]
                slow += 1
                
        while slow < len(nums):
            nums[slow] = 0
            slow += 1

            

              Python Two-Pass Breakdown:
              
    
                
  • Satisfies the in-place constraint cleanly without additional lists.
    • 
              

            

          


          
          

            
class Solution {
    /**
     * Approach 2: Overwrite Non-Zeroes then Fill Trailing Zeroes
     * 
     * Time Complexity:  O(N)
     * Space Complexity: O(1)
     */
    public void moveZeroes(int[] nums) {
        int slow = 0;
        for (int fast = 0; fast < nums.length; fast++) {
            if (nums[fast] != 0) {
                nums[slow++] = nums[fast];
            }
        }
        while (slow < nums.length) {
            nums[slow++] = 0;
        }
    }
}

            

              Java Overwrite Breakdown:
              
    
                
  • Solid solution, but requires two sequential loops.
    • 
              

            

          


          
          
          
          
          

            
class Solution {
    /**
     * Approach 3: Optimal In-Place Two-Pointer Swap (Minimizing Operations)
     * 
     * Time Complexity:  O(N) - Single pass through the array.
     * Space Complexity: O(1) - Pure in-place modification.
     * 
     * Follow-Up Optimization: Minimizes total array writes! Only writes when
     * non-zeroes are encountered.
     */
    fun moveZeroes(nums: IntArray) {
        var slow = 0

        for (fast in nums.indices) {
            if (nums[fast] != 0) {
                // Swap only when slow and fast diverge to avoid redundant self-writes
                if (slow != fast) {
                    val temp = nums[slow]
                    nums[slow] = nums[fast]
                    nums[fast] = temp
                }
                slow++
            }
        }
    }
}

            

              Kotlin Senior Engineering Breakdown:
              
    
                
  • if (slow != fast): An essential senior optimization. In arrays like [1, 2, 3] with zero zeroes, slow == fast on every step. Guarding against self-swaps reduces array write operations from N to 0 writes!
    • 
                
  • Partition Invariant: At every step, all elements before slow are guaranteed non-zero; all elements between slow and fast are zeroes; all elements after fast are uninspected.
    • 
              

            

          


          
          

            
class Solution:
    """
    Approach 3: Optimal In-Place Two-Pointer Swap (Minimizing Operations)
    
    Time Complexity:  O(N) - Single linear pass.
    Space Complexity: O(1) - Constant auxiliary space.
    """
    def moveZeroes(self, nums: list[int]) -> None:
        slow = 0
        
        for fast in range(len(nums)):
            if nums[fast] != 0:
                if slow != fast:
                    nums[slow], nums[fast] = nums[fast], nums[slow]
                slow += 1

            

              Python Tuple Unpacking Swap:
              
    
                
  • nums[slow], nums[fast] = nums[fast], nums[slow] executes via bytecode ROT_TWO in CPython with zero temporary list overhead.
    • 
              

            

          


          
          

            
class Solution {
    /**
     * Approach 3: Optimal In-Place Two-Pointer Swap (Minimizing Operations)
     * 
     * Time Complexity:  O(N)
     * Space Complexity: O(1)
     */
    public void moveZeroes(int[] nums) {
        int slow = 0;

        for (int fast = 0; fast < nums.length; fast++) {
            if (nums[fast] != 0) {
                if (slow != fast) {
                    int temp = nums[slow];
                    nums[slow] = nums[fast];
                    nums[fast] = temp;
                }
                slow++;
            }
        }
    }
}

            

              Java Senior Engineering Breakdown:
              
    
                
  • Direct primitive int[] mutation with zero boxing.
    • 
                
  • Avoids memory bus saturation on massive arrays by eliminating redundant writes.
    •

            Phase 1: Clarifying Constraints (Before Typing)
            Duration: ~45 seconds
          

          

            "Before jumping in: The problem requires modifying the array in-place, meaning auxiliary memory should be O(1) with no new array allocated, right? (Yes). Second, the relative order of non-zero elements must remain strictly preserved? (Yes). Can the array have negative numbers? (Yes). Can all elements be zero, or no zeroes at all? (Yes, and the algorithm must handle both cleanly)."
          

        


        
        

          

            Phase 2: Proposing Approaches & Trading Off
            Duration: ~60 seconds
          

          

            "A naive approach of shifting subsequent elements left upon encountering a zero takes O(N²) time. Alternatively, using an extra array is O(N) space, which violates the in-place constraint.


            A common working approach is two-pass: copy non-zeroes forward, then write zeroes in the remaining slots. However, this always does N writes even if there are no zeroes.


            To optimize operations and solve the follow-up, I will use a single-pass Two-Pointer Swap technique. A slow pointer tracks where the next non-zero should land, while a fast pointer scouts ahead. When fast finds a non-zero, we swap `nums[slow]` with `nums[fast]` and advance slow. Furthermore, by checking `if (slow != fast)` before swapping, we avoid useless self-swaps, minimizing write operations."
          

        


        
        

          

            Phase 3: Coding & Narration
            Duration: ~4 minutes
          

          

            "I'm initializing `slow = 0`. I loop `fast` from 0 to `nums.length - 1`. If `nums[fast] != 0`, I check if `slow != fast`; if so, I perform an in-place swap using a temporary variable. Then I increment `slow++`. The loop terminates naturally, leaving all zeroes at the tail."
          

        


        
        

          

            Phase 4: Verification & Edge Cases
            Duration: ~60 seconds
          

          

            "Let's trace: [0, 1, 0, 3, 12]. At fast=0 (0), slow stays 0. At fast=1 (1), slow!=fast, so swap 0 and 1 -> [1, 0, 0, 3, 12], slow becomes 1. At fast=2 (0), skip. At fast=3 (3), swap 0 and 3 -> [1, 3, 0, 0, 12], slow becomes 2. At fast=4 (12), swap 0 and 12 -> [1, 3, 12, 0, 0], slow becomes 3. Result is [1, 3, 12, 0, 0]. What if nums = [1, 2, 3]? Slow equals fast on every step, so 0 swaps are executed, keeping writes to zero!"
          

        

      


      
      

        

          🚀 Senior Scalability Follow-Up: "Why does write minimization matter in real systems?"
        

        

          In SSDs, NVMe storage, and flash microcontrollers:
        

        
    
          
  • Flash Endurance & Write Amplification: Flash memory cells have finite Program/Erase (P/E) cycles (~1,000 to 10,000 writes per cell). Writing unnecessarily wears out the physical hardware. The Swap approach with slow != fast eliminates redundant writes for already-sorted segments.
    • 
          
  • CPU Cache Invalidation: Writing to an array dirties L1/L2 cache lines, forcing cache coherence protocols (MESI) to broadcast invalidation signals across CPU cores. Minimizing writes keeps cache lines clean and speeds up multi-threaded applications.
    •
