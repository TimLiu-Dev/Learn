Two Sum

View on LeetCode ↗

Problem Description

Given an array of integers nums and an integer target, return indices of the two numbers such that they add up to target.

You may assume that each input would have exactly one solution, and you may not use the same element twice. You can return the answer in any order.

🗣️
Plain-English Translation:

"Scan the numbers. Which two distinct positions add up to the goal? Return their index numbers (e.g. [0, 1]). There is always exactly one pair that works, and you cannot add an element to itself."

Official Examples

Example 1:
Input: nums = [2,7,11,15], target = 9
Output: [0, 1]
Because nums[0] + nums[1] == 9, we return [0, 1].
Example 2:
Input: nums = [3,2,4], target = 6
Output: [1, 2]
Because nums[1] + nums[2] == 6, we return [1, 2].
Example 3:
Input: nums = [3,3], target = 6
Output: [0, 1]
Two identical values at different indices sum to 6.
Official Constraints:
  • 2 <= nums.length <= 104 (N up to 10,000 → O(N²) takes ~5×10⁷ ops, dangerous in live systems)
  • -109 <= nums[i] <= 109 (Values can be negative, zero, or positive 32-bit ints)
  • -109 <= target <= 109 (Target can also be negative)
  • Only one valid answer exists. (Guaranteed solution; no need to handle "not found")
The 3 Canonical Input Shapes (Mental Boundary Checks):
1. Minimum Base Case
nums = [3, 3], target = 6
Length = 2. Exact match on duplicates at different indices [0, 1].
2. Early Front Match
nums = [2, 7, 11, 15], target = 9
Complement 7 found at step 2. Halts immediately without evaluating index 2 or 3.
3. Polar Match at Endpoints
nums = [1, 5, 8, 9], target = 10
1 at index 0 matches 9 at index N-1. Requires storing all elements up to the last.

          🧥 The Real-World Analogy
        

        
The Coat Check Missing Puzzle Piece

        

          Imagine you walk into a crowded party holding a puzzle piece with the number 7. The host tells everyone: "Find the person whose number adds up with yours to exactly 9!"
        

        

          The naive partygoer walks around tapping each person on the shoulder one by one: "Are you a 2? Are you a 2? Are you a 2?" In a ballroom with 10,000 guests, that requires up to 50,000,000 exhausting conversations.
        

        

          The master partygoer sets up a clipboard table (HashMap) at the coat check door:

    2. 
          
  2. Check the clipboard: "Has someone holding 2 already registered their coat check ticket?"
    3. 
          
  3. If YES: Boom! You look up their ticket number (map.get(2)), grab their hand, and collect the prize: return [theirIndex, myIndex].
    4. 
          
  4. If NO: Nobody with a 2 has arrived yet. So you write your own number and ticket number onto the clipboard (map.put(7, myIndex)) so that whoever has a 2 in the future can find you instantly!

            💡 The "A-Ha!" Switch
          

          
Turn Addition Into Subtraction

          

            Beginners view Two Sum as an addition challenge: A + B == target. This tricks the mind into scanning forward into the future array to test pairs.
          

          

            The breakthrough is rearranging the equation: B = target - A. The moment you see number A, its partner B is uniquely determined. You query a hash table in O(1) time to see if B was already seen.

          Algorithmic Trade-offs
          
The Naive Trap (Red) vs. Optimal Breakthrough (Green)

        

      


      

        
        

          

            
              The Naive Trap (Nested Loops)
            
            O(N²) Time
          


          
Scanning Every Pair of Combinations

          

            Write two nested loops: for each index i, scan every index j > i to check if nums[i] + nums[j] == target.
          


          

            Why this is an interview trap:
            
    
              
  • Computes \frac{N(N - 1)}{2} additions. For N = 10^4, this is $\approx 50,000,000$ operations.
    • 
              
  • Repeatedly recalculates pair sums that have no mathematical chance of equaling target.
    • 
              
  • Interviewers expect you to mention this verbally in 30 seconds, but never write it on the whiteboard.
    • 
            

          

        


        
        

          

            
              Optimal (One-Pass HashMap)
            
            O(N) Time
          


          
Trading O(N) Space for O(1) Lookups

          

            As you iterate once through the array, treat the HashMap as your memory of all previously seen numbers and their indices.
          


          

            The Space-Time Bargain:
            
    
              
  • Time drops from O(N²) down to O(N): a single linear scan!
    • 
              
  • Hash lookups take O(1) amortized time.
    • 
              
  • Space cost: O(N) extra memory to hold at most N entries in the hash table.
    •

          Solution Evolution & Production Code
          
From Brute Force to Optimal & Interactive Sandbox

        

      


      
      

        
        

          

            Approach:
            

              
              
              
            

          


          
          

            Time: O(N) | Space: O(N) • ★ Production Standard
          

        


        
        

          

            
            
            
          


          
        


        
        

          
          
          
          
          

            
class Solution {
    /**
     * Approach 1: Brute Force (Nested Loops)
     * 
     * Time Complexity:  O(N^2) - Tests every pair (i, j) with j > i.
     * Space Complexity: O(1)   - Zero extra allocations.
     * 
     * Interview Status: State this in your first 30 seconds to define baseline.
     */
    fun twoSum(nums: IntArray, target: Int): IntArray {
        for (i in 0 until nums.size) {
            for (j in i + 1 until nums.size) {
                if (nums[i] + nums[j] == target) {
                    return intArrayOf(i, j)
                }
            }
        }
        throw IllegalArgumentException("No two sum solution found")
    }
}

            

              Brute Force Tradeoff Analysis:
              
    
                
  • The Redundant Work: Scans N(N - 1) / 2 pairs. At N = 10^4, that requires 50 million iterations.
    • 
                
  • Self-Match Avoidance: Inner loop starts at i + 1 to guarantee we never add an element to itself.
    • 
                
  • Interview Transition: "This O(N^2) solution runs with O(1) memory, but CPU cycles are wasted repeatedly searching for complements that we could look up in O(1) time with a Hash Map."
    • 
              

            

          


          
          

            
class Solution:
    """
    Approach 1: Brute Force (Nested Loops)
    
    Time Complexity:  O(N^2) - Quadratic pair scanning.
    Space Complexity: O(1)   - Operates entirely on input indices.
    """
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        n = len(nums)
        for i in range(n):
            for j in range(i + 1, n):
                if nums[i] + nums[j] == target:
                    return [i, j]
        return []

            

              Python Brute Force Breakdown:
              
    
                
  • range(i + 1, n) avoids duplicating pair checks and prevents comparing an element to itself.
    • 
                
  • In Python, nested bytecode loops suffer severe interpretation overhead on large arrays (N ≥ 10^4).
    • 
              

            

          


          
          

            
class Solution {
    /**
     * Approach 1: Brute Force (Nested Loops)
     * 
     * Time Complexity:  O(N^2) - Iterates all pairs.
     * Space Complexity: O(1)   - Returns small fixed array.
     */
    public int[] twoSum(int[] nums, int target) {
        for (int i = 0; i < nums.length; i++) {
            for (int j = i + 1; j < nums.length; j++) {
                if (nums[i] + nums[j] == target) {
                    return new int[]{i, j};
                }
            }
        }
        throw new IllegalArgumentException("No two sum solution");
    }
}

            

              Java Brute Force Breakdown:
              
    
                
  • Direct primitive int[] indexing without boxing or collection overhead.
    • 
                
  • Throws IllegalArgumentException if no pair is found, following production Java conventions.
    • 
              

            

          


          
          
          
          
          

            
class Solution {
    /**
     * Approach 2: Two-Pass Hash Map
     * 
     * Time Complexity:  O(N) - Two sequential passes over the array.
     * Space Complexity: O(N) - Hash map storing all N elements.
     */
    fun twoSum(nums: IntArray, target: Int): IntArray {
        val map = HashMap<Int, Int>()

        // Pass 1: Register all elements (value -> index)
        for (i in nums.indices) {
            map[nums[i]] = i
        }

        // Pass 2: Look up complement, ensuring we don't match the same index
        for (i in nums.indices) {
            val complement = target - nums[i]
            val compIndex = map[complement]
            if (compIndex != null && compIndex != i) {
                return intArrayOf(i, compIndex)
            }
        }

        throw IllegalArgumentException("No solution found")
    }
}

            

              Two-Pass Tradeoff & Self-Match Gotcha:
              
    
                
  • The Self-Match Gotcha: If target = 6 and nums[0] = 3, searching for 6 - 3 = 3 will return index 0 if you forget the guard compIndex != i!
    • 
                
  • Duplicate Values Overwrite: In Pass 1, if nums = [3, 3], the second 3 overwrites the map entry to index 1. In Pass 2, when evaluating index 0, it finds index 1, correctly returning [0, 1].
    • 
                
  • Optimization Question: "Can we combine both passes into a single scan so we don't need the self-match check at all?" → Yes! That brings us to Approach 3.
    • 
              

            

          


          
          

            
class Solution:
    """
    Approach 2: Two-Pass Hash Map
    
    Time Complexity:  O(N) - 2N operations.
    Space Complexity: O(N) - Dictionary storing up to N entries.
    """
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        hash_map = {}
        for i, num in enumerate(nums):
            hash_map[num] = i
            
        for i, num in enumerate(nums):
            complement = target - num
            if complement in hash_map and hash_map[complement] != i:
                return [i, hash_map[complement]]
                
        return []

            

              Python Two-Pass Breakdown:
              
    
                
  • hash_map[complement] != i prevents an element from pairing with itself (e.g. target = 6 and current number is 3).
    • 
                
  • Requires 2 full passes over the list.
    • 
              

            

          


          
          

            
import java.util.HashMap;
import java.util.Map;

class Solution {
    /**
     * Approach 2: Two-Pass Hash Map
     * 
     * Time Complexity:  O(N) - Two sequential passes.
     * Space Complexity: O(N) - HashMap storing up to N entries.
     */
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> map = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            map.put(nums[i], i);
        }

        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];
            if (map.containsKey(complement) && map.get(complement) != i) {
                return new int[]{i, map.get(complement)};
            }
        }
        throw new IllegalArgumentException("No two sum solution");
    }
}

            

              Java Two-Pass Breakdown:
              
    
                
  • Two passes require twice as many JVM method dispatches and iterations.
    • 
                
  • Demonstrates clear evolution towards the single-pass solution.
    • 
              

            

          


          
          
          
          
          

            
class Solution {
    /**
     * Approach 3: Optimal (One-Pass Hash Map) - Production Gold Standard
     * 
     * Time Complexity:  O(N) - Single linear traversal with O(1) average lookup/insert.
     * Space Complexity: O(N) - Stores at most N distinct integers in the HashMap.
     */
    fun twoSum(nums: IntArray, target: Int): IntArray {
        // Map storing: value -> its original array index
        val seen = HashMap<Int, Int>()

        for (i in nums.indices) {
            val num = nums[i]
            val complement = target - num

            // Check if complement arrived earlier in the stream
            val compIndex = seen[complement]
            if (compIndex != null) {
                return intArrayOf(compIndex, i)
            }

            // Register current number for future candidates
            seen[num] = i
        }

        throw IllegalArgumentException("No two sum solution found")
    }
}

            

              Kotlin Senior Engineering Breakdown:
              
    
                
  • val compIndex = seen[complement]: In Kotlin, single map query via get() returns nullable index. Checking if (compIndex != null) avoids the double-lookup penalty of containsKey() followed by get().
    • 
                
  • Automatic Self-Match Elimination: Because we check for the complement before calling seen[num] = i, an element can never match itself! Even with target = 6 and num = 3, index 0 is not yet in the map.
    • 
                
  • Early Exit Advantage: For arrays where the winning pair is at the beginning (e.g. [2, 7, 11, 15]), the algorithm halts on step 2, processing in < 1\mu\text{s} and ignoring millions of remaining items.
    • 
                
  • intArrayOf(compIndex, i): Instantiates an unboxed primitive int[] without boxing overhead.
    • 
              

            

          


          
          

            
class Solution:
    """
    Approach 3: Optimal (One-Pass Hash Map) - Production Gold Standard
    
    Time Complexity:  O(N) - Single linear pass with O(1) dictionary lookups.
    Space Complexity: O(N) - Stores at most N entries in the dictionary.
    """
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        seen = {}  # value -> index
        
        for i, num in enumerate(nums):
            complement = target - num
            if complement in seen:
                return [seen[complement], i]
            seen[num] = i
            
        return []

            

              Python Senior Engineering Breakdown:
              
    
                
  • enumerate(nums): Yields index and value pairs cleanly in C without manual index counter arithmetic.
    • 
                
  • if complement in seen:: Evaluated via Python's C-level hash table slot, executing in O(1) amortized time.
    • 
                
  • Memory footprint: Python 3.6+ dictionaries maintain insertion order via compact arrays with minimal hash collision perturbations.
    • 
              

            

          


          
          

            
import java.util.HashMap;
import java.util.Map;

class Solution {
    /**
     * Approach 3: Optimal (One-Pass Hash Map) - Production Gold Standard
     * 
     * Time Complexity:  O(N) - Single pass with O(1) average lookup/put.
     * Space Complexity: O(N) - Holds up to N mappings in the HashMap.
     */
    public int[] twoSum(int[] nums, int target) {
        // Pre-size map with capacity = (int)(nums.length / 0.75f) + 1 to prevent rehashing
        Map<Integer, Integer> seen = new HashMap<>();

        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];

            if (seen.containsKey(complement)) {
                return new int[]{seen.get(complement), i};
            }

            seen.put(nums[i], i);
        }

        throw new IllegalArgumentException("No two sum solution");
    }
}

            

              Java Senior Engineering Breakdown:
              
    
                
  • Map<Integer, Integer> seen = new HashMap<>(): Uses interface typing for testability and substitution.
    • 
                
  • Rehashing Optimization: In high-throughput systems, pre-sizing the HashMap capacity avoids the cost of resizing when the threshold ($0.75 \times \text{capacity}$) is crossed.
    • 
                
  • JVM Primitive Boxing Tradeoff: Each map entry boxes int into Integer (24 bytes per object on 64-bit JVM). In memory-critical systems, specialized libraries like FastUtil or Koloboke (Int2IntOpenHashMap) eliminate boxing entirely.
    • 
                
  • Treeification: When bucket collisions exceed 8, Java 8 converts the bucket list into a Red-Black Tree, bounding worst-case lookup to O(\log k).
    •

            Phase 1: Clarifying Constraints (Before Typing)
            Duration: ~45 seconds
          

          

            "Before jumping into code, I'd like to confirm a few assumptions: First, can the array contain negative numbers or zeros? (Yes, values span -10⁹ to +10⁹). Second, is it guaranteed that exactly one valid pair exists, or should I handle cases with no solution or multiple solutions? (Exactly one solution guaranteed). Third, we are returning indices, not values, correct? (Yes). Finally, can I use the same element twice? (No, each index may only be used once)."
          

        


        
        

          

            Phase 2: Proposing Approaches & Trading Off
            Duration: ~60 seconds
          

          

            "A brute-force approach would check every pair (i, j) with nested loops, giving O(N²) time and O(1) space. However, with N up to 10,000, that requires up to 50 million operations.


            Instead, we can optimize by trading space for time: we transform addition (A + B = target) into complement lookup (B = target - A). By keeping a HashMap of seen elements mapping value to index, we can check for the complement in O(1) time. Furthermore, if we check the map before inserting the current element in a single pass, we guarantee an element can never pair with itself. This drops our time complexity to O(N) linear time with O(N) space."
          

        


        
        

          

            Phase 3: Coding & Narration
            Duration: ~5 minutes
          

          

            "I'm initializing our HashMap. As I loop through indices, I calculate `complement = target - nums[i]`. If `seen.containsKey(complement)`, I immediately return the pair of indices `[seen.get(complement), i]`. Notice that by returning immediately on match, we get an early exit without scanning the rest of the array. Otherwise, I store `seen.put(nums[i], i)`. If we complete the loop without finding a pair, I throw an IllegalArgumentException."
          

        


        
        

          

            Phase 4: Verification & Edge Cases
            Duration: ~60 seconds
          

          

            "Let's trace two edge cases: First, duplicate numbers where target is twice that number, like nums = [3, 3] and target = 6. At i = 0, complement is 3; map is empty, so we insert 3 -> 0. At i = 1, complement is 3; map HAS 3 at index 0! It returns [0, 1] correctly. Second, negative numbers: nums = [-1, -3] and target = -4. At i = 1, complement is -4 - (-3) = -1, which is found at index 0. The math holds cleanly across the full 32-bit signed integer range."
          

        

      


      
      

        

          🚀 Senior Scalability Follow-Up: "What if the array cannot fit in RAM?"
        

        

          If you have 100 GB of numbers (billions of integers) on disk and only 4 GB of RAM:
        

        
    
          
  • Partition by Hash Buckets: Hash each number num % K into disk partitions. The complement (target - num) % K will map deterministically to a specific corresponding partition file. You only need to load paired partitions into RAM together.
    • 
          
  • External Merge Sort: Sort the array on disk in O(N \log N) using chunked disk sorts, then run the Two-Pointer inward sweep streaming values with two read pointers in O(1) RAM!
