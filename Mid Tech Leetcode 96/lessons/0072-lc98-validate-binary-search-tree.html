LeetCode #98: Validate Binary Search Tree

Official LC #98

Official Problem Statement

Given the root of a binary tree, determine if it is a valid binary search tree (BST).

A valid BST is defined as follows:

  • The left subtree of a node contains only nodes with keys less than the node's key.
  • The right subtree of a node contains only nodes with keys greater than the node's key.
  • Both the left and right subtrees must also be binary search trees.

Example 1: root = [2,1,3] → Output: true

Example 2: root = [5,1,4,null,null,3,6] → Output: false Explanation: The root node's value is 5 but its right child's value is 4.

Plain-English Translation & Core Nuance

A common trap is only checking if `left.val < node.val < right.val` for immediate children. A BST requires that ALL nodes in the left subtree are strictly less than the ancestor, and ALL nodes in the right subtree are strictly greater! We validate this using DFS by passing down valid range intervals `(low, high)`. For the left child, the range becomes `(low, node.val)`. For the right child, the range becomes `(node.val, high)`. If any node violates `low < node.val < high`, return false immediately.

Official Constraints:
  • The number of nodes in the tree is in the range [1, 10^4].
  • -2^31 <= Node.val <= 2^31 - 1

The Mental Model & "Explain Like I'm 12"

💡 The Restrictive Speed Limits Tunnel

Imagine driving down a branching highway tunnel system. At the start, the speed limit range is unbounded `(-infinity, +infinity)`. When you take a left exit at checkpoint 50, the maximum allowable speed drops to 50 for the entire rest of that network `(-infinity, 50)`. When you subsequently take a right exit at checkpoint 30, the minimum allowable speed becomes 30, narrowing the window to `(30, 50)`. Every checkpoint you pass tightens one of the two boundaries.

The Mental "A-Ha!" Switch:

Comparing a node only to its immediate parent is insufficient (e.g. `[5, 1, 6, null, null, 4, 7]` where 4 is less than 5 but in the right subtree). By propagating inherited `low` and `high` bounds down the recursion, every node validates against all its ancestors in O(1) time.

Pattern Trigger:

Validate BST property across entire subtrees → DFS with interval bounds `(low, high)` or In-Order traversal strictly increasing check.

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(N^2) Time, O(N) Space

For every node, traverse its entire left subtree to find maxVal, and right subtree to find minVal, then check maxVal < node.val < minVal.

Wasted Work: Re-traversing subtrees repeatedly from every ancestor node.
The Optimal Breakthrough O(N) Time, O(Height) Auxiliary Space

Single DFS pass passing down `(low, high)` bounds. Each node visited exactly once in O(1) time.

Core Invariant: At any node, `low < node.val < high`. For left child: `high' = node.val`; for right child: `low' = node.val`.
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
1. Subtree Min/Max Re-scan O(N^2) O(H) Scans descendants repeatedly from every level.
2. In-Order Traversal + Array Check O(N) O(N) Stores in-order list and checks if strictly sorted.
★ 3. DFS Bounded Interval Recursion O(N) O(H) Validates in-flight without array allocation; early exits on first violation.

Production Implementations

From Naive to Optimal & Runnable Practice Arena

Strict ordering: Kotlin (Default) → Python → Java across all approaches.

★ Approach: DFS Bounded Interval Recursion (Production Optimal)

Pass down strict low and high bounds (using Long to avoid integer overflow). Left child receives (low, node.val); right child receives (node.val, high).

Time: O(N) Time Space: O(Height) Space 
class TreeNode(var `val`: Int) {
    var left: TreeNode? = null
    var right: TreeNode? = null
}

class Solution {
    fun isValidBST(root: TreeNode?): Boolean {
        return validate(root, Long.MIN_VALUE, Long.MAX_VALUE)
    }

    private fun validate(node: TreeNode?, low: Long, high: Long): Boolean {
        if (node == null) return true
        val v = node.`val`.toLong()
        if (v <= low || v >= high) return false

        return validate(node.left, low, v) && validate(node.right, v, high)
    }
}
Kotlin Runtime & Memory Nuance:

Idiomatic Kotlin implementation optimizing collections and null-safety.

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

class Solution:
    def isValidBST(self, root: TreeNode | None) -> bool:
        def validate(node: TreeNode | None, low: float, high: float) -> bool:
            if not node:
                return True
            if not (low < node.val < high):
                return False
            return validate(node.left, low, node.val) and validate(node.right, node.val, high)

        return validate(root, float('-inf'), float('inf'))

}

""The optimal approach uses DFS to pass down an allowed interval `(low, high)` for each node.
