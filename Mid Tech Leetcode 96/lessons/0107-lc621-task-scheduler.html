Problem #621: Task Scheduler

View on NeetCode ↗

Official Problem Statement

You are given an array of CPU tasks, each represented by letters A to Z, and a cooling time, n. Each cycle or interval allows the completion of one task. Tasks can be completed in any order, but there's a constraint: identical tasks must be separated by at least n intervals due to cooling time.

Return the minimum number of intervals the CPU will take to complete all the given tasks.

Example 1: tasks = ["A","A","A","B","B","B"], n = 2 → Output: 8

Example 2: tasks = ["A","C","A","B","D","B"], n = 1 → Output: 6

Example 3: tasks = ["A","A","A", "B","B","B"], n = 3 → Output: 10

Plain-English Translation & Core Nuance

Schedule CPU tasks (like 'A', 'B') so that two identical tasks have at least n clock ticks between them. If no valid task is ready, the CPU sits idle. Find the minimum total clock ticks needed to finish everything.

Official Constraints:
  • 1 <= tasks.length <= 10^4
  • tasks[i] is an uppercase English letter.
  • 0 <= n <= 100

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
n = 0 -> Zero cooldown required; CPU never idles, answer is simply tasks.size.
Best-Case Early Exit
High task variety (e.g. 6 distinct tasks, n = 2) -> Zero idle slots needed, answer is tasks.size.
Worst-Case Full Scan
tasks = ['A','A','A','A'], n = 100 -> Bottlenecked by single frequent task: (4 - 1) * 101 + 1 = 304.

The Mental Model & "Explain Like I'm 12"

💡 The Bottleneck Frame & Cooldown Penalty Box

Always run the task with the highest remaining count first so it starts cooling down as early as possible! You can picture this two ways: (1) Simulation: a Max-Heap of ready task counts and a FIFO Cooldown Queue holding (remainingCount, readyAtTime) pairs; or (2) Geometry: the most frequent task (say 'A' appearing maxFreq times) creates (maxFreq - 1) frames of width (n + 1), plus a final tail holding all tasks tied for maxFreq!

The Mental "A-Ha!" Switch:

The minimum schedule length is max(tasks.size, (maxFreq - 1) * (n + 1) + countOfMaxFreqTasks)!

Pattern Trigger:

Scheduling items with cooldown/spacing constraints or rearranging characters so identical ones are k apart.

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(T * 26 log 26) Time, O(26) Space

Simulate every single CPU clock tick one by one using a Max-Heap of available counts and a Cooldown Queue of (remaining, unlockTime).

Wasted Work: When n = 100 and tasks = 10,000 'A's, tick-by-tick simulation steps through ~1,000,000 idle ticks unnecessarily.
The Optimal Breakthrough O(N) Time, O(1) Space (26-element array)

Count frequencies in IntArray(26), find maxFreq and how many tasks tie for maxFreq (maxCount), and return maxOf(tasks.size, (maxFreq - 1) * (n + 1) + maxCount).

Core Invariant: Idle slots only exist if (maxFreq - 1) * (n + 1) + maxCount exceeds tasks.size; otherwise all idle slots are filled and the CPU runs at 100% utilization (tasks.size).
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
Approach 1: Max-Heap + Cooldown Queue Simulation O(TotalTicks) O(1) (<= 26 items) Great for explaining actual schedule order in interviews.
Optimal: Greedy Frame Math Formula O(N) O(1) ★ Computes exact minimum intervals in a single pass over 26 frequencies.

Approach 1: Max-Heap + Cooldown Queue Simulation

Always execute the highest-frequency available task via a Max-Heap, placing remaining copies into a FIFO cooldown queue until time + n.

Time: O(TotalTicks) Space: O(1) (at most 26 tasks) 
import java.util.PriorityQueue

class Solution {
    fun leastInterval(tasks: CharArray, n: Int): Int {
        val freq = IntArray(26)
        for (t in tasks) freq[t - 'A']++

        val maxHeap = PriorityQueue<Int>(compareByDescending { it })
        for (f in freq) if (f > 0) maxHeap.offer(f)

        // Pair of (remainingCount, readyAtTime)
        val cooldown = ArrayDeque<IntArray>()
        var time = 0

        while (maxHeap.isNotEmpty() || cooldown.isNotEmpty()) {
            time++
            if (maxHeap.isNotEmpty()) {
                val rem = maxHeap.poll() - 1
                if (rem > 0) {
                    cooldown.addLast(intArrayOf(rem, time + n))
                }
            }
            if (cooldown.isNotEmpty() && cooldown.first()[1] == time) {
                maxHeap.offer(cooldown.removeFirst()[0])
            }
        }
        return time
    }
}
Kotlin Runtime & Memory Nuance:

Since at most 26 letters exist, PriorityQueue operations take O(log 26) = O(1) time per tick.

import heapq
from collections import Counter, deque

class Solution:
    def leastInterval(self, tasks: list[str], n: int) -> int:
        counts = Counter(tasks)
        max_heap = [-cnt for cnt in counts.values()]
        heapq.heapify(max_heap)

        time = 0
        q = deque()  # pairs of (-cnt, unlock_time)

        while max_heap or q:
            time += 1
            if max_heap:
                cnt = 1 + heapq.heappop(max_heap)
                if cnt != 0:
                    q.append((cnt, time + n))
            if q and q[0][1] == time:
                heapq.heappush(max_heap, q.popleft()[0])
        return time
Python Runtime & Memory Nuance:

Negating counts turns Python's min-heap (heapq) into a max-heap.

import java.util.*;

class Solution {
    public int leastInterval(char[] tasks, int n) {
        int[] freq = new int[26];
        for (char t : tasks) freq[t - 'A']++;

        PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
        for (int f : freq) if (f > 0) maxHeap.offer(f);

        Deque<int[]> cooldown = new ArrayDeque<>();
        int time = 0;

        while (!maxHeap.isEmpty() || !cooldown.isEmpty()) {
            time++;
            if (!maxHeap.isEmpty()) {
                int rem = maxHeap.poll() - 1;
                if (rem > 0) cooldown.offerLast(new int[]{rem, time + n});
            }
            if (!cooldown.isEmpty() && cooldown.peekFirst()[1] == time) {
                maxHeap.offer(cooldown.pollFirst()[0]);
            }
        }
        return time;
    }
}

Approach 2: Greedy Frame Math (O(N) Closed Form)

Calculate the frame size dictated by the highest-frequency task: maxOf(tasks.size, (maxFreq - 1) * (n + 1) + maxCount).

Time: O(N) Space: O(1) 
class Solution {
    fun leastInterval(tasks: CharArray, n: Int): Int {
        val freq = IntArray(26)
        var maxFreq = 0
        for (t in tasks) {
            val f = ++freq[t - 'A']
            if (f > maxFreq) maxFreq = f
        }

        var maxCount = 0
        for (f in freq) {
            if (f == maxFreq) maxCount++
        }

        val frameIntervals = (maxFreq - 1) * (n + 1) + maxCount
        return maxOf(tasks.size, frameIntervals)
    }
}
Kotlin Runtime & Memory Nuance:

Single 26-int primitive array on stack/heap; zero dynamic allocations.

class Solution:
    def leastInterval(self, tasks: list[str], n: int) -> int:
        freq = [0] * 26
        for t in tasks:
            freq[ord(t) - ord('A')] += 1

        max_freq = max(freq)
        max_count = freq.count(max_freq)

        frame_intervals = (max_freq - 1) * (n + 1) + max_count
        return max(len(tasks), frame_intervals)
Python Runtime & Memory Nuance:

O(N) frequency count + O(26) max and count scan.

class Solution {
    public int leastInterval(char[] tasks, int n) {
        int[] freq = new int[26];
        int maxFreq = 0;
        for (char t : tasks) {
            maxFreq = Math.max(maxFreq, ++freq[t - 'A']);
        }

        int maxCount = 0;
        for (int f : freq) {
            if (f == maxFreq) maxCount++;
        }

        int frameIntervals = (maxFreq - 1) * (n + 1) + maxCount;
        return Math.max(tasks.length, frameIntervals);
    }
}
