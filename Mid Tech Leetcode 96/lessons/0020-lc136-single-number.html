LeetCode 136: Single Number

Official LC #136

Official Problem Statement

Given a non-empty array of integers nums, every element appears twice except for one. Find that single one.

You must implement a solution with a linear runtime complexity and use only constant extra space.

Example 1: nums = [2,2,1] → Output: 1

Example 2: nums = [4,1,2,1,2] → Output: 4

Example 3: nums = [1] → Output: 1

Constraints: 1 <= nums.length <= 3 * 10^4, -3 * 10^4 <= nums[i] <= 3 * 10^4

Plain-English Translation & Core Nuance

Every number in the array comes with an exact twin brother, except for a lone survivor. The strict mandate is: O(n) time and O(1) auxiliary space.

Using a Hash Table solves it easily in linear time, but uses O(n) space, violating the constraint. Sorting takes O(n log n), violating the linear time constraint.

The key insight is the Bitwise XOR operator (^). Because x ^ x = 0 and x ^ 0 = x, chaining XOR across the entire array makes all twin pairs mutually annihilate to zero, leaving only the single number!

Bitwise Annihilation & Commutativity Model

Given nums = [4, 1, 2, 1, 2]

Bitwise XOR reduction:
  acc = 4 ^ 1 ^ 2 ^ 1 ^ 2

By Commutative & Associative Properties:
  acc = 4 ^ (1 ^ 1) ^ (2 ^ 2)
  acc = 4 ^ 0 ^ 0
  acc = 4  <-- Survives unharmed!

Bit-level view for 4 ^ 1 ^ 1:
    4:  0 1 0 0
  ^ 1:  0 0 0 1  -->  0 1 0 1 (5)
  ^ 1:  0 0 0 1  -->  0 1 0 0 (4) [Bit 0 flipped twice returns to 0]
Constraints
1 ≤ nums.length ≤ 3 × 10^4
Odd length guaranteed (2k + 1 elements). Can contain negative integers.
Optimal Complexity
Time: O(n) • Space: O(1)
Single pass over nums with a single integer accumulator.
Boundary Case
nums.length = 1
nums = [x] → loop runs once → returns x immediately.

Section 1

Mental Model & Pattern Recognition

The Physical Metaphor: Two-Way Toggle Switch

Imagine a row of 32 light switches, all initially OFF (state 0).

Every number in nums represents a set of switches to toggle.

When number X arrives, we flip its active switch bits.

When the twin duplicate of X arrives later, we flip those exact same switches again.

Flipping any toggle switch twice restores it to its initial state (OFF). Only the switches belonging to the unpaired single number are toggled once — remaining illuminated at the end!

Trigger Signals & Algebraic Laws of XOR

•
"Every element appears twice except one" + "O(1) space":

The signature LeetCode calling card for bitwise XOR annihilation.

•
Four Invariant Laws of XOR:

1) a ^ 0 = a • 2) a ^ a = 0 • 3) a ^ b = b ^ a • 4) (a ^ b) ^ c = a ^ (b ^ c).

Naive Trap vs. Optimal Breakthrough

×

The Naive Trap: HashSet Allocation or Sorting

Candidates often reach for a HashSet: add when seen, remove if already present. While simple, it requires O(n) auxiliary memory, explicitly violating the problem prompt.

Sorting in-place avoids extra memory, but incurs O(n log n) time, violating linear time requirements and modifying input data.

✓

The Optimal Breakthrough: Bitwise XOR Accumulator

By initializing var acc = 0 and folding over each integer acc ^= num, paired numbers cancel out regardless of their order in the array.

Runs in exactly 1 pass (O(n) Time).

Uses a single 32-bit CPU register (O(1) Space).

→ 100% optimal and impossible to improve upon.

Section 5

Solution Evolution: From Naive to Optimal

Approach 1: HashSet Insertion and Deletion

Time: O(n) • Space: O(n) auxiliary heap memory

class Solution {
    fun singleNumber(nums: IntArray): Int {
        val seen = HashSet<Int>()
        for (num in nums) {
            if (!seen.add(num)) {
                seen.remove(num)
            }
        }
        return seen.iterator().next()
    }
}
class Solution:
    def singleNumber(self, nums: List[int]) -> int:
        seen = set()
        for num in nums:
            if num in seen:
                seen.remove(num)
            else:
                seen.add(num)
        return seen.pop()
import java.util.HashSet;
import java.util.Set;

class Solution {
    public int singleNumber(int[] nums) {
        Set<Integer> seen = new HashSet<>();
        for (int num : nums) {
            if (!seen.add(num)) {
                seen.remove(num);
            }
        }
        return seen.iterator().next();
    }
}

Approach 2: In-Place Sort and Step-2 Scanning

Time: O(n log n) • Space: O(1) or O(n) depending on sort implementation

class Solution {
    fun singleNumber(nums: IntArray): Int {
        nums.sort()
        var i = 0
        while (i < nums.size - 1) {
            if (nums[i] != nums[i + 1]) {
                return nums[i]
            }
            i += 2
        }
        return nums[nums.size - 1]
    }
}
class Solution:
    def singleNumber(self, nums: List[int]) -> int:

import java.util.Arrays;

class Solution {
    public int singleNumber(int[] nums) {
        Arrays.sort(nums);
        for (int i = 0; i < nums.length - 1; i += 2) {
            if (nums[i] != nums[i + 1]) {
                return nums[i];
            }
        }
        return nums[nums.length - 1];
    }
}

★ Approach 3: Bitwise XOR Reduction (Optimal)

Time: O(n) • Space: O(1) auxiliary space

class Solution {
    fun singleNumber(nums: IntArray): Int {
        var result = 0
        for (num in nums) {
            result = result xor num
        }
        return result
    }
}

        Section 6
        
Mock Interview Dialogue & Senior Follow-Ups

      


      

        

          
1. Clarification & Constraints:

          
Candidate: "Can nums contain negative numbers, and is it guaranteed that exactly one element is unique while every other element appears exactly twice?"

          
Interviewer: "Yes, negatives are allowed, and every duplicate appears exactly twice, with exactly one unique element."

        


        

          
2. Technical Justification of XOR:

          
Candidate: "While a HashSet provides O(n) time, it violates the O(1) space constraint. Since XOR is commutative and associative, and x ^ x = 0 with x ^ 0 = x, folding all numbers with XOR reduces all twin pairs to 0 regardless of order. The final accumulated value will be the exact unique number."

        


        

          
3. Complexity & Architecture:

          
Candidate: "Time complexity is strictly O(n) across a single pass. Space complexity is O(1) using a single integer variable."

        


        

          
4. Senior Staff Follow-Up: Single Number II & III Variants

          
Interviewer: "What if every element appeared 3 times except for one single element?"

          
Candidate: "A simple XOR fails because x ^ x ^ x = x, so triplets do not cancel. Instead, we can sum each of the 32 bit positions across all numbers modulo 3. Any bit that is non-zero mod 3 belongs to the unique element. We can implement this in O(1) space using two bitmasks `ones` and `twos` to simulate a base-3 counter."

          
Interviewer: "And if TWO distinct elements appeared once, while all others appeared twice?"

          
Candidate: "XORing the whole array yields `diff = x ^ y`. Since x != y, `diff` has at least one set bit. We find the rightmost set bit via `diff & (-diff)` and partition the array into two subsets based on that bit. XORing each subset independently isolates x and y in O(n) time and O(1) space!"
