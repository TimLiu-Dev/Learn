Problem #295: Find Median from Data Stream

View on NeetCode ↗

Official Problem Statement

The median is the middle value in an ordered integer list. If the size of the list is even, there is no middle value, and the median is the mean of the two middle values.

  • For example, for arr = [2,3,4], the median is 3.
  • For example, for arr = [2,3], the median is (2 + 3) / 2 = 2.5.

Implement the MedianFinder class:

  • MedianFinder() initializes the MedianFinder object.
  • void addNum(int num) adds the integer num from the data stream to the data structure.
  • double findMedian() returns the median of all elements so far. Answers within 10-5 of the actual answer will be accepted.

Example 1: ["MedianFinder", "addNum", "addNum", "findMedian", "addNum", "findMedian"] [[], [1], [2], [], [3], []] → Output: [null, null, null, 1.5, null, 2.0] Explanation: MedianFinder medianFinder = new MedianFinder(); medianFinder.addNum(1); // arr = [1] medianFinder.addNum(2); // arr = [1, 2] medianFinder.findMedian(); // return 1.5 (i.e., (1 + 2) / 2) medianFinder.addNum(3); // arr[1, 2, 3] medianFinder.findMedian(); // return 2.0

Plain-English Translation & Core Nuance

The median divides numbers into two halves: a smaller half and a larger half. If we can instantaneously access the largest element of the small half and the smallest element of the large half, finding the median takes O(1) time! We maintain two heaps: (1) `maxHeap`: stores the smaller half of numbers (its root is the maximum of the small half). (2) `minHeap`: stores the larger half of numbers (its root is the minimum of the large half). Invariant: `maxHeap` is kept equal in size to `minHeap`, or exactly 1 element larger (`maxHeap.size == minHeap.size + 1`). When `addNum(x)` is called: we push `x` to `maxHeap`, then move `maxHeap.poll()` to `minHeap`. If `minHeap.size > maxHeap.size`, we move `minHeap.poll()` back to `maxHeap`. `findMedian()` takes O(1): if sizes are equal, average their roots; else return `maxHeap.peek()`.

Official Constraints:
  • -10^5 <= num <= 10^5
  • There will be at least one element in the data structure before calling findMedian.
  • At most 5 * 10^4 calls will be made to addNum and findMedian.

The Mental Model & "Explain Like I'm 12"

💡 The Two-Pan Balancing Scale

Imagine a classic two-pan balance scale. The left pan is a Max-Heap holding the lighter half of rocks; the top rock is the heaviest of the light ones. The right pan is a Min-Heap holding the heavier half of rocks; the top rock is the lightest of the heavy ones. Whenever a new rock arrives, we place it on the left pan, sift the heaviest rock over to the right pan, and re-level the scale so the left pan holds at most 1 more rock than the right. The median is always right at the fulcrum between the two pans!

The Mental "A-Ha!" Switch:

We don't need to keep the entire stream sorted! We only need the boundary between the lower 50% and upper 50%. Two balanced heaps achieve this in O(log N) insertion and O(1) median query.

Pattern Trigger:

Online streaming median / dynamic percentile queries → Balanced Dual Heaps (Max-Heap + Min-Heap).

Balanced Dual Heaps (Max-Heap + Min-Heap)

Two PriorityQueues: `maxHeap` stores smaller 50% of numbers, `minHeap` stores larger 50%. Balances sizes such that `maxHeap.size == minHeap.size` or `maxHeap.size == minHeap.size + 1`.

Time: O(log N) addNum Space: O(1) findMedian 
import java.util.PriorityQueue

class MedianFinder() {
    // Max-Heap stores lower half of numbers
    private val maxHeap = PriorityQueue<Int>(compareByDescending { it })
    // Min-Heap stores upper half of numbers
    private val minHeap = PriorityQueue<Int>()

    fun addNum(num: Int) {
        maxHeap.offer(num)
        minHeap.offer(maxHeap.poll())

        // Maintain balance: maxHeap must hold >= minHeap
        if (minHeap.size > maxHeap.size) {
            maxHeap.offer(minHeap.poll())
        }
    }

    fun findMedian(): Double {
        return if (maxHeap.size > minHeap.size) {
            maxHeap.peek().toDouble()
        } else {
            (maxHeap.peek().toDouble() + minHeap.peek().toDouble()) / 2.0
        }
    }
}

import heapq

class MedianFinder:
    def __init__(self):
        # Python heapq is min-heap; negate values for max-heap
        self.small = [] # max-heap (negated values)
        self.large = [] # min-heap

    def addNum(self, num: int) -> None:
        heapq.heappush(self.small, -num)
        heapq.heappush(self.large, -heapq.heappop(self.small))
        
        # Maintain balance invariant
        if len(self.large) > len(self.small):
            heapq.heappush(self.small, -heapq.heappop(self.large))

    def findMedian(self) -> float:
        if len(self.small) > len(self.large):
            return float(-self.small[0])
        return (-self.small[0] + self.large[0]) / 2.0

In Balanced Dual Heaps (Max-Heap + Min-Heap), Python uses C-backed heapq binary heap operations on flat lists for low-overhead O(log N) priority updates.

import java.util.Collections;
import java.util.PriorityQueue;

class MedianFinder {
    private final PriorityQueue<Integer> maxHeap;
    private final PriorityQueue<Integer> minHeap;

    public MedianFinder() {
        maxHeap = new PriorityQueue<>(Collections.reverseOrder());
        minHeap = new PriorityQueue<>();
    }

    public void addNum(int num) {
        maxHeap.offer(num);
        minHeap.offer(maxHeap.poll());

        if (minHeap.size() > maxHeap.size()) {
            maxHeap.offer(minHeap.poll());
        }
    }

    public double findMedian() {
        if (maxHeap.size() > minHeap.size()) {
            return maxHeap.peek();
        } else {
            return (maxHeap.peek() + minHeap.peek()) / 2.0;
        }
    }
}
