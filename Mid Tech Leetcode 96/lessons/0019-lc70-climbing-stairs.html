LeetCode 70: Climbing Stairs

Official LC #70

Official Problem Statement

You are climbing a staircase. It takes n steps to reach the top.

Each time you can either climb 1 or 2 steps. In how many distinct ways can you climb to the top?

Example 1: n = 2 → Output: 2 (Explanation: 1 step + 1 step, or 2 steps)

Example 2: n = 3 → Output: 3 (Explanation: 1+1+1, 1+2, or 2+1)

Constraints: 1 <= n <= 45

Plain-English Translation & Core Nuance

To reach step i, your very last move must have been either a 1-step stride from step i - 1 or a 2-step stride from step i - 2.

These two sets of paths are completely mutually exclusive (you can't simultaneously arrive via 1 step and 2 steps) and exhaustive (there are no 3-step strides). Therefore, by the sum rule of combinatorics:

ways(i) = ways(i - 1) + ways(i - 2)

This is identical to the classic Fibonacci sequence with base cases ways(1) = 1 and ways(2) = 2.

1 ≤ n ≤ 45

Time: O(n) • Space: O(1)

Critical Edge Cases
n = 1 (1 way), n = 2 (2 ways)

Section 1

Mental Model & Pattern Recognition

The Physical Metaphor: Two-Step Stride

Picture standing on the landing of a flight of stairs at step 10. How did you get your boots on step 10?

Possibility A: You were on step 9, and hopped 1 step up.

Possibility B: You were on step 8, and leaped 2 steps up.

There is no third option. Therefore, every single path that reaches step 10 either ended with a 1-step hop from 9, or a 2-step leap from 8. The total ways to reach step 10 is strictly the sum: ways(10) = ways(9) + ways(8).

Section 2

Naive Trap vs. Optimal Breakthrough

×

The Naive Trap: Pure Recursive Branching

Writing a direct recursive function climbStairs(n) = climbStairs(n-1) + climbStairs(n-2) without memoization causes redundant computation to explode exponentially at O(2^n).

For n = 45:

Number of recursive calls > 2^45 ≈ 3.5 × 10^13 operations.

→ Instant Time Limit Exceeded (TLE) in interview!

✓

The Optimal Breakthrough: Rolling Two Variables

To compute state i, we only ever read states i - 1 and i - 2. We do not need an array of size n.

Maintain two rolling integers: prev2 = 1, prev1 = 2.

Loop from 3 to n: curr = prev1 + prev2; prev2 = prev1; prev1 = curr.

→ O(n) Time, O(1) Auxiliary Space. Absolute perfection.

Approach Time Complexity Space Complexity Pros Cons
1. Naive Recursion O(2^n) O(n) stack Direct translation of recurrence Exponential explosion; TLE for n > 35
2. Memoization / DP Array O(n) O(n) Linear time, simple tabulation Allocates unnecessary array of size n
★ 3. Rolling DP (Optimal) O(n) O(1) Optimal runtime & zero heap memory None — standard production pattern

Section 5

Solution Evolution: From Naive to Optimal

Approach 1: Naive Recursive Branching

Time: O(2^n) • Space: O(n) recursion call stack

class Solution {
    fun climbStairs(n: Int): Int {
        if (n <= 2) return n
        // Exponential branching recalculates the same subproblems repeatedly
        return climbStairs(n - 1) + climbStairs(n - 2)
    }
}
class Solution:
    def climbStairs(self, n: int) -> int:
        if n <= 2:
            return n
        # O(2^n) time complexity - causes TLE for n >= 38
        return self.climbStairs(n - 1) + self.climbStairs(n - 2)

Approach 2: Tabulation DP Array / Memoization

Time: O(n) • Space: O(n) linear auxiliary space

class Solution {
    fun climbStairs(n: Int): Int {
        if (n <= 2) return n
        val dp = IntArray(n + 1)
        dp[1] = 1
        dp[2] = 2
        for (i in 3..n) {
            dp[i] = dp[i - 1] + dp[i - 2]
        }
        return dp[n]
    }
}
class Solution:
    def climbStairs(self, n: int) -> int:
        if n <= 2:
            return n
        dp = [0] * (n + 1)
        dp[1], dp[2] = 1, 2
        for i in range(3, n + 1):
            dp[i] = dp[i - 1] + dp[i - 2]
        return dp[n]
class Solution {
    public int climbStairs(int n) {
        if (n <= 2) return n;
        int[] dp = new int[n + 1];
        dp[1] = 1;
        dp[2] = 2;
        for (int i = 3; i <= n; i++) {
            dp[i] = dp[i - 1] + dp[i - 2];
        }
        return dp[n];
    }
}

★ Approach 3: Space-Optimized Rolling DP (Optimal)

Time: O(n) • Space: O(1) constant auxiliary space

class Solution {
    fun climbStairs(n: Int): Int {
        if (n <= 2) return n
        var prev2 = 1 // ways(1)
        var prev1 = 2 // ways(2)
        
        for (i in 3..n) {
            val curr = prev1 + prev2
            prev2 = prev1
            prev1 = curr
        }
        return prev1
    }
}
class Solution:
    def climbStairs(self, n: int) -> int:
        if n <= 2:
            return n
        prev2, prev1 = 1, 2
        for _ in range(3, n + 1):
            prev2, prev1 = prev1, prev2 + prev1
        return prev1
class Solution {
    public int climbStairs(int n) {
        if (n <= 2) return n;
        int prev2 = 1; // ways(1)
        int prev1 = 2; // ways(2)
        
        for (int i = 3; i <= n; i++) {
            int curr = prev1 + prev2;
            prev2 = prev1;
            prev1 = curr;
        }
        return prev1;
    }
}

Mock Interview Dialogue & Senior Follow-Ups

      


      

        

          
1. Clarification & Constraints:

          
Candidate: "Is n guaranteed to be a positive integer? And what is the maximum value of n?"

          
Interviewer: "Yes, 1 ≤ n ≤ 45."

          
Candidate: "Under n = 45, the 45th Fibonacci number is approximately 1.83 × 10^9, which safely fits inside a 32-bit signed integer. If n were larger, say n = 90, we would need 64-bit Long or BigInteger."

        


        

          
2. Mathematical Formulation & Proposing Recurrence:

          
Candidate: "To land on step i, we must come from either step i-1 with 1 step, or step i-2 with 2 steps. These two events are mutually exclusive and collectively exhaustive, giving ways(i) = ways(i-1) + ways(i-2). While a direct recursion would run in O(2^n) time due to repeated subproblems, we can compute it iteratively in O(n) time."

        


        

          
3. Space Optimization Breakthrough:

          
Candidate: "Instead of allocating an O(n) size DP array, notice that computing state i only reads the immediate two previous states i-1 and i-2. We can maintain just two rolling variables, reducing auxiliary space to strictly O(1)."

        


        

          
4. Senior Staff Follow-Up: Matrix Exponentiation for O(log n)

          
Interviewer: "What if n were 10^9? O(n) loop will timeout. Can you do faster than O(n) time?"

          
Candidate: "Yes! Since this is a linear recurrence relation, we can express it as a 2x2 matrix multiplication: [[F(n+1), F(n)], [F(n), F(n-1)]] = [[1, 1], [1, 0]]^n. Using binary matrix exponentiation, we can raise the transition matrix to the n-th power in O(log n) time!"
