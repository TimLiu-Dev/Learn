Problem Statement & Boundary Checks

LeetCode #121 ↗

Verbatim Problem Statement

You are given an array prices where prices[i] is the price of a given stock on the ith day.

You want to maximize your profit by choosing a single day to buy one stock and choosing a different day in the future to sell that stock.

Return the maximum profit you can achieve from this transaction. If you cannot achieve any profit, return 0.

Plain-English Translation

You can make at most one buy and one sell, strictly in chronological order (you must buy before you sell). Find the pair of days $(i, j) with i < j that maximizes prices[j] - prices[i]$. If prices only fall or stay flat, you make no trades and return 0.

Example 1 (Classic Peak)
Input: prices = [7, 1, 5, 3, 6, 4]
Output: 5

Buy on day 2 (price = 1) and sell on day 5 (price = 6), profit = 6 - 1 = 5. (Note: buying on day 2 and selling on day 1 is not allowed because you cannot travel back in time).

Example 2 (Strictly Decreasing)
Input: prices = [7, 6, 4, 3, 1]
Output: 0

In this case, no profitable transactions are possible since each day is cheaper than the last. Maximum profit = 0.

Example 3 (Late Valley Trap)
Input: prices = [2, 4, 1]
Output: 2

Buy at 2, sell at 4 gives profit 2. Even though day 3 has a lower price (1), there are no days left to sell after it.

Constraints

  • 1 ≤ prices.length ≤ 105 (100,000 days)
  • 0 ≤ prices[i] ≤ 104

3 Canonical Boundary Check Shapes

1. Single Element: [5] → Cannot buy and sell on distinct days; returns 0.
2. Monotonically Decreasing: [9, 7, 5, 3, 1] → Every future sale is a loss; returns 0.
3. Deep Valley on Last Day: [3, 8, 1] → Absolute minimum is 1 on day 2, but max profit was locked at 8 - 3 = 5 on day 1.

The Mental Model & "Explain Like I'm 12"

Why remembering the deepest past valley unlocks the optimal single transaction.

The Mountain Hiker's Lowest Valley Camera

Imagine you are hiking across a mountain range where each mountain's altitude represents the stock price on that day. You are carrying a camera that automatically keeps a picture of the lowest valley altitude you have ever touched so far (minPrice).

At every mountain peak you reach, you ask yourself one simple question:

"If I bought back at my lowest valley and sold right now at this altitude, how much money would I make?"

If that potential profit beats your all-time record (maxProfit), you update your record! If you happen to step into a new, even lower valley, you snap a new photo for minPrice so future peaks can measure against it.

Because you can only sell in the future, maintaining the running minimum from day 0 to the current day guarantees strict chronological validity.

The "A-Ha!" Architectural Trigger

When a problem asks for the maximum difference $arr[j] - arr[i] where i < j$, never use nested loops. Instead, iterate forward while carrying a single accumulator for the minimum element seen so far (minSoFar). This collapses an O(N^2) brute force into an optimal O(N) single pass.

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

Why nested pair checking times out on 10^5 inputs.

The Naive Trap: Nested Loop Pair Comparison O(N²) Time Limit Exceeded

Testing every possible buy day i against every future sell day j: 

var maxProfit = 0
for (i in prices.indices) {
    for (j in i + 1 until prices.size) {
        val profit = prices[j] - prices[i]
        if (profit > maxProfit) maxProfit = profit
    }
}
return maxProfit
  • Quadratic Explosiveness: For $N = 100,000$, total pair evaluations = $ rac{100,000 imes 99,999}{2} pprox 5 imes 10^9$ operations.
  • Guaranteed TLE: Exceeds the standard 1-second LeetCode execution budget (~10^8 ops) by 50x!
Interview Verdict: Instant rejection for lack of scalability
Optimal Breakthrough: Running Minimum Valley Tracking O(N) Time • O(1) Space

Carry the historical minimum price in a single scalar variable: 

var minPrice = Int.MAX_VALUE
var maxProfit = 0
for (price in prices) {
    if (price < minPrice) minPrice = price
    else if (price - minPrice > maxProfit) maxProfit = price - minPrice
}
return maxProfit
  • Strictly Linear: Visits each array element exactly once. Takes < 2 milliseconds for $100,000$ items.
  • Zero Extra Memory: Operates strictly on CPU registers with two primitive integer variables.
Interview Verdict: Gold standard senior implementation

From Brute Force to Optimal & Interactive Sandbox

Evolution from quadratic nested search to linear running valley tracking.

Approach 1: Nested Loops All-Pairs Search (O(N²))

Check every pair $(i, j) with j > i$ and track the maximum difference. Fails on LeetCode with Time Limit Exceeded when N ≥ 10^5. 

class Solution {
    fun maxProfit(prices: IntArray): Int {
        var maxProfit = 0
        for (i in prices.indices) {
            for (j in i + 1 until prices.size) {
                val profit = prices[j] - prices[i]
                if (profit > maxProfit) {
                    maxProfit = profit
                }
            }
        }
        return maxProfit
    }
}
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        max_profit = 0
        n = len(prices)
        for i in range(n):
            for j in range(i + 1, n):
                profit = prices[j] - prices[i]
                if profit > max_profit:
                    max_profit = profit
        return max_profit
class Solution {
    public int maxProfit(int[] prices) {
        int maxProfit = 0;
        for (int i = 0; i < prices.length; i++) {
            for (int j = i + 1; j < prices.length; j++) {
                int profit = prices[j] - prices[i];
                if (profit > maxProfit) {
                    maxProfit = profit;
                }
            }
        }
        return maxProfit;
    }
}
Approach 2: Prefix Minimum DP Array (O(N) Time, O(N) Space)

Precompute an array minPrices[i] storing the minimum price up to day i. Then do a second pass to find $\max(prices[i] - minPrices[i])$. Achieves O(N) time, but consumes unnecessary O(N) extra memory. 

class Solution {
    fun maxProfit(prices: IntArray): Int {
        if (prices.isEmpty()) return 0
        val minSoFar = IntArray(prices.size)
        minSoFar[0] = prices[0]
        for (i in 1 until prices.size) {
            minSoFar[i] = kotlin.math.min(minSoFar[i - 1], prices[i])
        }

        var maxProfit = 0
        for (i in prices.indices) {
            maxProfit = kotlin.math.max(maxProfit, prices[i] - minSoFar[i])
        }
        return maxProfit
    }
}
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        if not prices:
            return 0
        min_so_far = [0] * len(prices)
        min_so_far[0] = prices[0]
        for i in range(1, len(prices)):
            min_so_far[i] = min(min_so_far[i - 1], prices[i])

        max_profit = 0
        for i in range(len(prices)):
            max_profit = max(max_profit, prices[i] - min_so_far[i])
        return max_profit
class Solution {
    public int maxProfit(int[] prices) {
        if (prices.length == 0) return 0;
        int[] minSoFar = new int[prices.length];
        minSoFar[0] = prices[0];
        for (int i = 1; i < prices.length; i++) {
            minSoFar[i] = Math.min(minSoFar[i - 1], prices[i]);
        }

        int maxProfit = 0;
        for (int i = 0; i < prices.length; i++) {
            maxProfit = Math.max(maxProfit, prices[i] - minSoFar[i]);
        }
        return maxProfit;
    }
}
Approach 3: Running Valley Tracking (O(N) Time, O(1) Auxiliary Space)

Maintain a running minimum price and running maximum profit in two primitive scalar variables. In a single pass, evaluate every element as a potential valley or peak. 

class Solution {
    fun maxProfit(prices: IntArray): Int {
        var minPrice = Int.MAX_VALUE
        var maxProfit = 0

        for (price in prices) {
            if (price < minPrice) {
                // Found a cheaper buy day in history
                minPrice = price
            } else if (price - minPrice > maxProfit) {
                // Selling today yields a higher profit than any previous sale
                maxProfit = price - minPrice
            }
        }

        return maxProfit
    }
}
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        min_price = float('inf')
        max_profit = 0

        for price in prices:
            if price < min_price:
                min_price = price
            elif price - min_price > max_profit:
                max_profit = price - min_price

        return max_profit
class Solution {
    public int maxProfit(int[] prices) {
        int minPrice = Integer.MAX_VALUE;
        int maxProfit = 0;

        for (int price : prices) {
            if (price < minPrice) {
                minPrice = price;
            } else if (price - minPrice > maxProfit) {
                maxProfit = price - minPrice;
            }
        }

        return maxProfit;
    }
}
★ Senior Engineering Guardrails

1. Mutual Exclusivity (else if): If today's price is smaller than minPrice, then price - minPrice would be 0 or negative. Thus, you do not need to calculate profit on a day that establishes a new valley! Using else if saves an unnecessary subtraction on new minimum days.

2. Kadane's Algorithm Equivalence: Notice that if we define diff[i] = prices[i] - prices[i - 1], this problem is mathematically identical to finding the Maximum Subarray Sum on diff!
