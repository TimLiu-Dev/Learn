Problem #239: Sliding Window Maximum

View on NeetCode ↗

Official Problem Statement

You are given an array of integers nums, there is a sliding window of size k which is moving from the very left of the array to the very right. You can only see the k numbers in the window. Each time the sliding window moves right by one position.

Return the max sliding window.

Example 1: nums = [1,3,-1,-3,5,3,6,7], k = 3 → Output: [3,3,5,5,6,7] Explanation: Window position Max --------------- ----- [1 3 -1] -3 5 3 6 7 3 1 [3 -1 -3] 5 3 6 7 3 1 3 [-1 -3 5] 3 6 7 5 1 3 -1 [-3 5 3] 6 7 5 1 3 -1 -3 [5 3 6] 7 6 1 3 -1 -3 5 [3 6 7] 7

Example 2: nums = [1], k = 1 → Output: [1]

Plain-English Translation & Core Nuance

As a window of length `k` slides across `nums`, we must return the maximum element in each window. A naive scan takes O(N * k) time. A max-heap takes O(N log k). We can achieve optimal O(N) linear time using a Monotonic Decreasing Deque of *indices*. When element `nums[i]` arrives: (1) Any elements at the back of the deque smaller than `nums[i]` can NEVER be the window maximum again (since `nums[i]` is both larger and will survive longer in the window), so we pop them. (2) Pop the front if its index has slid outside the window (`deque.first <= i - k`). (3) Push index `i` to the back. Once `i >= k - 1`, the element at `nums[deque.first]` is the guaranteed window maximum.

Official Constraints:
  • 1 <= nums.length <= 10^5
  • -10^4 <= nums[i] <= 10^4
  • 1 <= k <= nums.length

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
Window size k = 1 nums = [1, -1], k = 1 → Returns exact original array [1, -1].
Best-Case Early Exit
Entire array is window k == nums.length → Returns single element [max(nums)].
Worst-Case Full Scan
Strictly increasing array [1, 2, 3, 4, 5], k = 3 → Deque keeps popping smaller back elements; front always holds latest.

💡 The Work Hierarchy Seniority Rule

Imagine a company hiring candidates over time. When a candidate arrives with skill level X: anyone already at the company who is LESS skilled than the new recruit and ALSO hired earlier will NEVER be the most valuable employee again—the new recruit outperforms them and will retire later! So all less skilled predecessors are removed from contention. The most valuable employee currently active is always the person standing at the very front of the line.

The Mental "A-Ha!" Switch:

Storing INDICES in the deque instead of values allows us to verify two things simultaneously: whether an element is smaller than the current value (`nums[deque.last] < nums[i]`), and whether it has expired past the window boundary (`deque.first <= i - k`).

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(N * K) Time, O(1) Space

Iterate through all N - K + 1 windows and take the maximum of each K elements.

Wasted Work: Re-scanning all K elements from scratch on every step when only 1 element enters and 1 element leaves.
The Optimal Breakthrough O(N) Time, O(K) Auxiliary Space

Monotonic Decreasing Deque of indices. Each index is pushed and popped at most once.

Core Invariant: The deque indices are strictly increasing, and their corresponding values `nums[idx]` are strictly monotonically decreasing from front to back.

3. Invariant Maintenance & State Transition

The key property is storing *indices* in the deque. When processing index `i`, we pop elements from the back of the deque that are smaller than `nums[i]`, because `nums[i]` is both greater and will remain in the window longer. Then we pop from the front if `deque.first <= i - k`. Throughout every transition, we preserve the core invariant: The deque indices are strictly increasing, and their corresponding values `nums[idx]` are strictly monotonically decreasing from front to back.

Monotonic Decreasing Deque of Indices

Double-ended queue (ArrayDeque) storing indices in decreasing order of their corresponding values. Prunes smaller back elements and slides out-of-bounds front elements in amortized O(1).

Time: O(N) Time Space: O(K) Space 
class Solution {
    fun maxSlidingWindow(nums: IntArray, k: Int): IntArray {
        if (nums.isEmpty() || k <= 0) return IntArray(0)

        val n = nums.size
        val res = IntArray(n - k + 1)
        val deque = ArrayDeque<Int>() // Stores indices

        for (i in 0 until n) {
            // Remove indices that are out of current window
            if (deque.isNotEmpty() && deque.first() <= i - k) {
                deque.removeFirst()
            }

            // Remove indices whose values are smaller than nums[i]
            while (deque.isNotEmpty() && nums[deque.last()] < nums[i]) {
                deque.removeLast()
            }

            deque.addLast(i)

            // Once window reaches size k, front is the window maximum
            if (i >= k - 1) {
                res[i - k + 1] = nums[deque.first()]
            }
        }

        return res
    }
}
Kotlin Runtime & Memory Nuance:

In Monotonic Decreasing Deque of Indices, Kotlin uses unboxed JVM primitive arrays (IntArray / BooleanArray) to eliminate object header overhead and keep traversal L1-cache friendly; and uses ArrayDeque as a zero-lock circular buffer for O(1) head/tail operations instead of synchronized java.util.Stack or pointer-heavy LinkedList.

from collections import deque

class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        if not nums or k <= 0:
            return []
            
        dq = deque() # Stores indices
        res = []
        
        for i, val in enumerate(nums):
            # Remove elements outside current window
            if dq and dq[0] <= i - k:
                dq.popleft()
                
            # Discard smaller elements from back
            while dq and nums[dq[-1]] < val:
                dq.pop()
                
            dq.append(i)
            
            # Record window maximum
            if i >= k - 1:
                res.append(nums[dq[0]])
                
        return res
Python Runtime & Memory Nuance:

In Monotonic Decreasing Deque of Indices, Python uses collections.deque for true O(1) popleft() / append(), avoiding the O(N) memory shift penalty of list.pop(0); and iterates with lazy C-iterators (range / enumerate) to avoid allocating intermediate index lists.

class Solution {
    public int[] maxSlidingWindow(int[] nums, int k) {
        if (nums == null || k <= 0) return new int[0];

        int n = nums.length;
        int[] res = new int[n - k + 1];
        Deque<Integer> deque = new ArrayDeque<>();

        for (int i = 0; i < n; i++) {
            // Evict elements outside the window
            if (!deque.isEmpty() && deque.peekFirst() <= i - k) {
                deque.pollFirst();
            }

            // Discard elements smaller than incoming nums[i]
            while (!deque.isEmpty() && nums[deque.peekLast()] < nums[i]) {
                deque.pollLast();
            }

            deque.offerLast(i);

            // Record maximum for complete windows
            if (i >= k - 1) {
                res[i - k + 1] = nums[deque.peekFirst()];
            }
        }

        return res;
    }
}
Java Runtime & Memory Nuance:

In Monotonic Decreasing Deque of Indices, Java uses resizable circular array ArrayDeque, which outperforms LinkedList by eliminating per-node 24-byte heap allocations; and operates directly on primitive Java arrays (int[] / char[]) to prevent autoboxing GC pressure.
