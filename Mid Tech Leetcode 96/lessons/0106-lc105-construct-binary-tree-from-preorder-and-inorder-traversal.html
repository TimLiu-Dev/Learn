Problem #105: Construct Binary Tree from Preorder and Inorder Traversal

View on NeetCode ↗

Official Problem Statement

Given two integer arrays preorder and inorder where preorder is the preorder traversal of a binary tree and inorder is the inorder traversal of the same tree, construct and return the binary tree.

Example 1: preorder = [3,9,20,15,7], inorder = [9,3,15,20,7] → Output: [3,9,20,null,null,15,7]

Example 2: preorder = [-1], inorder = [-1] → Output: [-1]

Plain-English Translation & Core Nuance

Rebuild the exact Binary Tree given two flat lists: Preorder (which always lists Root first, then Left subtree, then Right subtree) and Inorder (which lists Left subtree, then Root in the middle, then Right subtree).

Official Constraints:
  • 1 <= preorder.length <= 3000
  • inorder.length == preorder.length
  • -3000 <= preorder[i], inorder[i] <= 3000
  • preorder and inorder consist of unique values.

Canonical Input Shapes (Mental Boundary Checks)

Minimum Base Case
preorder = [-1], inorder = [-1] -> Single leaf node with left = null, right = null.
Best-Case Early Exit
Balanced 3-node tree [3, 9, 20] -> Root 3 splits inorder [9, 3, 20] cleanly at index 1.
Worst-Case Full Scan
Left-skewed tree of 3,000 nodes -> O(N^2) if linear indexOf is used; O(N) with HashMap lookup.

The Mental Model & "Explain Like I'm 12"

💡 The CEO Org-Chart Splitter

Preorder is a roll-call sheet where the boss always speaks first, followed by the entire West Coast division, then the East Coast division. Inorder is a seating chart where the West Coast sits on the left, the boss sits in the middle seat, and the East Coast sits on the right. You read the next boss from the Preorder roll-call, find their seat in the Inorder chart in O(1) using a directory map, and everything to their left becomes the left sub-tree while everything to their right becomes the right sub-tree!

The Mental "A-Ha!" Switch:

Preorder tells you WHO the current root is (via a monotonically advancing preIdx++); Inorder tells you HOW MANY nodes belong to the left vs. right subtree (via a precomputed HashMap<Value, Index>)!

Pattern Trigger:

Reconstructing a tree from two traversal arrays (Preorder + Inorder, or Postorder + Inorder).

Algorithmic Trade-off Analysis

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Naive Trap O(N^2) Time, O(N^2) Space

At every recursive step, linearly scan inorder[] to find the root's index and slice new preorder/inorder subarrays.

Wasted Work: On a skewed tree, linear scanning + array slicing does N + (N-1) + ... + 1 = O(N^2) work and allocates O(N^2) subarray copies.
The Optimal Breakthrough O(N) Time, O(N) Space

Precompute a HashMap mapping each value in inorder to its index in O(N). Maintain a single global preIdx pointer and pass (inLeft, inRight) index bounds into a recursive helper.

Core Invariant: Each call consumes preorder[preIdx++] as the root and recurses on [inLeft .. mid - 1] (left) then [mid + 1 .. inRight] (right).
Approach Time Complexity Space Complexity Practical Trade-off / Bottleneck
Naive: Array Slicing + Linear Scan O(N^2) O(N^2) Allocates new subarrays and scans for root on every node.
Better: Index Bounds + Linear Scan O(N^2) O(H) Eliminates array copies, but still takes O(N^2) time on skewed trees.
Optimal: HashMap Lookup + Index Bounds O(N) O(N) ★ O(1) root split lookup + zero array slicing. Visits each node once.

2. Core Traversal & Decision Rule

Precompute a HashMap mapping each value in inorder to its index in O(N). Maintain a single global preIdx pointer and pass (inLeft, inRight) index bounds into a recursive helper. At each step, instead of re-scanning elements we already visited, we use our maintained state to make an immediate local decision.

3. Invariant Maintenance & State Transition

I'll build inMap mapping inorder[i] -> i, and keep a pointer preIdx = 0. In helper(inLeft, inRight), if inLeft > inRight we return null. Otherwise we consume rootVal = preorder[preIdx++], look up mid = inMap[rootVal], build root.left on (inLeft, mid - 1), and root.right on (mid + 1, inRight). Throughout every transition, we preserve the core invariant: Each call consumes preorder[preIdx++] as the root and recurses on [inLeft .. mid - 1] (left) then [mid + 1 .. inRight] (right).

4. Termination & Output Guarantee

Check for early-exit conditions (Balanced 3-node tree [3, 9, 20] -> Root 3 splits inorder [9, 3, 20] cleanly at index 1.). Once traversal completes, return the accumulated result. Because Preorder visits Root -> Left -> Right, advancing preIdx++ naturally visits every left-subtree root before the first right-subtree root!

From Naive to Optimal & Runnable Practice Arena

Approach 1: Recursive Subarray Slicing

Find the root in inorder via indexOf and slice new subarrays for left and right recursive calls.

Time: O(N^2) Space: O(N^2) 
class Solution {
    fun buildTree(preorder: IntArray, inorder: IntArray): TreeNode? {
        if (preorder.isEmpty()) return null
        val rootVal = preorder[0]
        val mid = inorder.indexOf(rootVal)
        val root = TreeNode(rootVal)
        root.left = buildTree(
            preorder.sliceArray(1..mid),
            inorder.sliceArray(0 until mid)
        )
        root.right = buildTree(
            preorder.sliceArray((mid + 1) until preorder.size),
            inorder.sliceArray((mid + 1) until inorder.size)
        )
        return root
    }
}
Kotlin Runtime & Memory Nuance:

Easy to read, but sliceArray copies subarrays at every level and indexOf scans linearly.

Classic Python interview starter, but interviewers will immediately ask you to eliminate the O(N) list slices.

import java.util.*;

class Solution {
    public TreeNode buildTree(int[] preorder, int[] inorder) {
        if (preorder.length == 0) return null;
        int rootVal = preorder[0];
        int mid = 0;
        while (inorder[mid] != rootVal) mid++;

        TreeNode root = new TreeNode(rootVal);
        root.left = buildTree(
            Arrays.copyOfRange(preorder, 1, mid + 1),
            Arrays.copyOfRange(inorder, 0, mid)
        );
        root.right = buildTree(
            Arrays.copyOfRange(preorder, mid + 1, preorder.length),
            Arrays.copyOfRange(inorder, mid + 1, inorder.length)
        );
        return root;
    }
}
Java Runtime & Memory Nuance:

Arrays.copyOfRange allocates 4 new int[] arrays per tree node.

Approach 2: HashMap Index Lookup + Pointer Bounds

Precompute value -> inorder index in a HashMap and recurse using (inLeft, inRight) boundaries with a shared preIdx.

Time: O(N) Space: O(N) 
class Solution {
    fun buildTree(preorder: IntArray, inorder: IntArray): TreeNode? {
        val inMap = HashMap<Int, Int>(inorder.size * 2)
        for (i in inorder.indices) {
            inMap[inorder[i]] = i
        }
        var preIdx = 0

        fun helper(inLeft: Int, inRight: Int): TreeNode? {
            if (inLeft > inRight) return null
            val rootVal = preorder[preIdx++]
            val root = TreeNode(rootVal)
            val mid = inMap[rootVal]!!

            root.left = helper(inLeft, mid - 1)
            root.right = helper(mid + 1, inRight)
            return root
        }

        return helper(0, inorder.lastIndex)
    }
}
Kotlin Runtime & Memory Nuance:

Pre-sizing HashMap(inorder.size * 2) avoids internal rehashing while indexing all N elements.

class Solution:
    def buildTree(self, preorder: list[int], inorder: list[int]) -> Optional[TreeNode]:
        in_map = {val: idx for idx, val in enumerate(inorder)}
        self.pre_idx = 0

        def helper(in_left: int, in_right: int) -> Optional[TreeNode]:
            if in_left > in_right:
                return None
            root_val = preorder[self.pre_idx]
            self.pre_idx += 1
            root = TreeNode(root_val)
            mid = in_map[root_val]

            root.left = helper(in_left, mid - 1)
            root.right = helper(mid + 1, in_right)
            return root

        return helper(0, len(inorder) - 1)
Python Runtime & Memory Nuance:

Dictionary comprehension builds the lookup table in C-speed O(N); zero list slicing inside helper.

import java.util.*;

class Solution {
    private int preIdx = 0;
    private Map<Integer, Integer> inMap;

    public TreeNode buildTree(int[] preorder, int[] inorder) {
        inMap = new HashMap<>(inorder.length * 2);
        for (int i = 0; i < inorder.length; i++) {
            inMap.put(inorder[i], i);
        }
        preIdx = 0;
        return helper(preorder, 0, inorder.length - 1);
    }

    private TreeNode helper(int[] preorder, int inLeft, int inRight) {
        if (inLeft > inRight) return null;
        int rootVal = preorder[preIdx++];
        TreeNode root = new TreeNode(rootVal);
        int mid = inMap.get(rootVal);

        root.left = helper(preorder, inLeft, mid - 1);
        root.right = helper(preorder, mid + 1, inRight);
        return root;
    }
}
Java Runtime & Memory Nuance:

Each node is instantiated once with O(1) HashMap lookup; total time is strictly O(N).
