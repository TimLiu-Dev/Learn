LeetCode 21: Merge Two Sorted Lists

Official LC #21

Official Problem Statement

You are given the heads of two sorted linked lists list1 and list2.

Merge the two lists into one sorted list. The list should be made by splicing together the nodes of the first two lists.

Return the head of the merged linked list.

Example 1: Input: list1 = [1,2,4], list2 = [1,3,4] → Output: [1,1,2,3,4,4]

Example 2: Input: list1 = [], list2 = [] → Output: []

Example 3: Input: list1 = [], list2 = [0] → Output: [0]

Plain-English Translation & Core Nuance

You hold the keys to two already-sorted conveyor belts of numbers. Your job is to zip them together into a single sorted chain by simply redirecting the pointers between existing nodes—never allocating new nodes.

💡 The Dummy Head Trick: Starting without a dummy head forces messy if (head == null) branching on the first element. Creating a fake anchor node dummy = ListNode(0) allows uniform splicing: tail.next = nextSmallerNode, then returning dummy.next at the end.
Input Constraints

Nodes in each list: [0, 50]

Values: -100 ≤ val ≤ 100

Both lists are guaranteed sorted non-decreasingly.

One or Both Empty

list1 = [], list2 = [0] → [0]

list1 = [], list2 = [] → null

If either list is null, return the other list directly in O(1) time without looping.

Unequal Lengths

list1 = [5], list2 = [1,2,3,4,6]

Output: [1,2,3,4,5,6]

When one list exhausts, splice the remaining chain in a single O(1) step: tail.next = l1 ?: l2.

Strategic Contrast

Naive Trap vs. Optimal Breakthrough

❌

The Naive Trap: Copy to Array, Sort & Allocate New Nodes

Traversing both lists to copy numbers into an array, calling Collections.sort(), then iterating over the sorted array to create brand new ListNode objects.

• Time Complexity: O((N + M) log(N + M)) due to redundant sorting

• Space Complexity: O(N + M) heap allocation for array and new nodes

• Disregards the given prerequisite that both inputs are already sorted!

✅

The Breakthrough: Dummy Head Sentinel Pointer Splicing

Create a static sentinel dummy node. Maintain a moving tail pointer. Compare current values in O(1), append the smaller node to tail.next, advance tail. When one list is null, connect the other list in O(1).

• Time Complexity: O(N + M) single linear pass

• Space Complexity: O(1) auxiliary space (zero node allocations)

• Return: dummy.next cleanly bypasses sentinel without edge cases.

Approach Time Space Node Allocations Tradeoff Summary
1. Array Collect & Sort O((N+M) log(N+M)) O(N+M) N + M new nodes Ignores sorted invariant; severe memory and runtime penalty.
2. Recursive Splicing O(N+M) O(N+M) Stack 0 (In-place) Concise 5-line implementation, but risks stack overflow on long lists.
3. Iterative Sentinel (Optimal) O(N+M) O(1) 0 (Only 1 dummy reference) Standard production code. Fast, memory-free, immune to recursion depth limits.

Solution Evolution

From Sort Redundancy to In-Place Sentinel Splice

Approach 1: Collect Values into Array, Sort & Rebuild List

Traverses both lists, adds all values to an array, sorts the array, and instantiates brand new nodes. Incurs unnecessary heap allocations and \mathcal{O}((N+M)\log(N+M)) sorting overhead.

Time: O((N+M) log(N+M)) Space: O(N+M) 
class Solution {
    fun mergeTwoLists(list1: ListNode?, list2: ListNode?): ListNode? {
        val values = mutableListOf<Int>()
        var p1 = list1; var p2 = list2
        while (p1 != null) { values.add(p1.`val`); p1 = p1.next }
        while (p2 != null) { values.add(p2.`val`); p2 = p2.next }
        
        if (values.isEmpty()) return null
        values.sort()
        
        val dummy = ListNode(0)
        var curr = dummy
        for (v in values) {
            curr.next = ListNode(v)
            curr = curr.next!!
        }
        return dummy.next
    }
}
class Solution:
    def mergeTwoLists(self, list1: Optional[ListNode], list2: Optional[ListNode]) -> Optional[ListNode]:
        values = []
        p1, p2 = list1, list2
        while p1:
            values.append(p1.val)
            p1 = p1.next
        while p2:
            values.append(p2.val)
            p2 = p2.next
            
        if not values:
            return None
            
        values.sort()
        dummy = ListNode(0)
        curr = dummy
        for v in values:
            curr.next = ListNode(v)
            curr = curr.next
        return dummy.next
class Solution {
    public ListNode mergeTwoLists(ListNode list1, ListNode list2) {
        List<Integer> values = new ArrayList<>();
        for (ListNode p = list1; p != null; p = p.next) values.add(p.val);
        for (ListNode p = list2; p != null; p = p.next) values.add(p.val);
        
        if (values.isEmpty()) return null;
        Collections.sort(values);
        
        ListNode dummy = new ListNode(0);
        ListNode curr = dummy;
        for (int v : values) {
            curr.next = new ListNode(v);
            curr = curr.next;
        }
        return dummy.next;
    }
}

Approach 2: Recursive Subproblem Splicing

The smaller head becomes the root of the result. Its next is recursively set to the result of merging its own tail with the other list. Elegant and declarative.

Time: O(N + M) Space: O(N + M) Call Stack 
class Solution {
    fun mergeTwoLists(list1: ListNode?, list2: ListNode?): ListNode? {
        if (list1 == null) return list2
        if (list2 == null) return list1
        
        return if (list1.`val` <= list2.`val`) {
            list1.next = mergeTwoLists(list1.next, list2)
            list1
        } else {
            list2.next = mergeTwoLists(list1, list2.next)
            list2
        }
    }
}
class Solution:
    def mergeTwoLists(self, list1: Optional[ListNode], list2: Optional[ListNode]) -> Optional[ListNode]:
        if not list1:
            return list2
        if not list2:
            return list1
            
        if list1.val <= list2.val:
            list1.next = self.mergeTwoLists(list1.next, list2)
            return list1
        else:
            list2.next = self.mergeTwoLists(list1, list2.next)
            return list2
class Solution {
    public ListNode mergeTwoLists(ListNode list1, ListNode list2) {
        if (list1 == null) return list2;
        if (list2 == null) return list1;
        
        if (list1.val <= list2.val) {
            list1.next = mergeTwoLists(list1.next, list2);
            return list1;
        } else {
            list2.next = mergeTwoLists(list1, list2.next);
            return list2;
        }
    }
}

Approach 3: Dummy Head Sentinel Pointer Splicing (Production Optimal)

INTERVIEW DEFAULT

Eliminates all head-initialization special cases with a sentinel node. Directly splices existing node pointers in a single while loop. The leftover chain is attached in O(1) time.

Time: O(N + M) (Single pass) Space: O(1) (Zero node allocations) 
class Solution {
    fun mergeTwoLists(list1: ListNode?, list2: ListNode?): ListNode? {
        val dummy = ListNode(0) // Sentinel anchor
        var tail = dummy
        var p1 = list1
        var p2 = list2
        
        while (p1 != null && p2 != null) {
            if (p1.`val` <= p2.`val`) {
                tail.next = p1
                p1 = p1.next
            } else {
                tail.next = p2
                p2 = p2.next
            }
            tail = tail.next!!
        }
        
        // Attach remaining non-null sublist directly in O(1) time
        tail.next = p1 ?: p2
        
        return dummy.next
    }
}
class Solution:
    def mergeTwoLists(self, list1: Optional[ListNode], list2: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0)  # Sentinel anchor
        tail = dummy
        p1, p2 = list1, list2
        
        while p1 and p2:
            if p1.val <= p2.val:
                tail.next = p1
                p1 = p1.next
            else:
                tail.next = p2
                p2 = p2.next
            tail = tail.next
            
        # Splice whatever remains in O(1)
        tail.next = p1 if p1 else p2
        return dummy.next
class Solution {
    public ListNode mergeTwoLists(ListNode list1, ListNode list2) {
        ListNode dummy = new ListNode(0); // Sentinel anchor
        ListNode tail = dummy;
        ListNode p1 = list1;
        ListNode p2 = list2;
        
        while (p1 != null && p2 != null) {
            if (p1.val <= p2.val) {
                tail.next = p1;
                p1 = p1.next;
            } else {
                tail.next = p2;
                p2 = p2.next;
            }
            tail = tail.next;
        }
        
        // Directly wire remaining list
        tail.next = (p1 != null) ? p1 : p2;
        
        return dummy.next;
    }
}

          Phase 1: Clarify & Confirm Boundaries
          

            "Are the input lists guaranteed to be sorted? Yes. Should we reuse the existing nodes in-place rather than allocating new ones? Yes, splicing existing references is optimal. Can either list be null? If one is null, we immediately return the other in O(1)."
          

        


        

          Phase 2: Propose Strategy & Sentinel Invariant
          

            "I'll use a sentinel dummy node to anchor the merged list and avoid special-casing the first node. A tail pointer will advance as we attach the smaller of p1.val or p2.val. When the while loop finishes because one list exhausted, we attach the remainder in a single O(1) assignment: tail.next = p1 ?: p2."
          

        


        

          Phase 3: Trace Edge Case Walkthrough
          

            "Take list1 = [] and list2 = [0]. While loop terminates immediately because p1 is null. tail.next = p2 links to node 0. Return dummy.next returns node 0. No null pointer exceptions, perfectly handled in O(1)."
          

        


        

          Phase 4: Conclude & Space-Time Bounds
          

            "Time complexity is O(N + M) where N and M are the lengths of the two lists, as every node is visited at most once. Space complexity is O(1) auxiliary memory since we only allocate a single sentinel node and two pointer references."

            1. Scaling to K Sorted Streams (LeetCode #23):
            

              If merging K sorted streams with N total elements, sequential merging takes \mathcal{O}(K \cdot N). Instead, use a Min-Heap (PriorityQueue) of size K to extract the minimum in \mathcal{O}(\log K), giving \mathcal{O}(N \log K) overall runtime. Alternatively, use divide-and-conquer pairwise merging.
            

          

          

            2. Merge-Sort for Linked Lists (LeetCode #148):
            

              Arrays prefer QuickSort because of cache locality, but Linked Lists prefer MergeSort because this merge subroutine requires zero extra memory \mathcal{O}(1) space, compared to array merge sort which requires \mathcal{O}(N) scratch buffers.
