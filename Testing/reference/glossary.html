CANONICAL TERMINOLOGY

Master Testing Glossary (Adhered to Across All Lessons)

Consistent vocabulary prevents ambiguity in code reviews, test strategy RFCs, and Senior SDET interviews. All lessons in this workspace follow these exact definitions.

Term Precise Definition Android / SDET Context
ErrorA human mistake (misread requirement, wrong operator, typo) made during coding or design.Writing > instead of >= for a free-shipping threshold.
Fault (Defect / Bug)The static incorrect step or condition sitting inside source code or configuration.The wrong branch inside ShippingCalculator.kt prior to execution.
FailureObservable deviation from expected behavior when a fault is triggered at runtime.Customer charged \$7.99 shipping on an exact \$50.00 cart in production.
VerificationChecking whether we are building the product right against specs and contracts.JUnit 5 unit tests, static analysis, API schema checks.
ValidationChecking whether we built the right product for real user needs.E2E checkout journeys, accessibility audits, canary user metrics.
White-Box TestingStructural testing with full visibility into source code, branches, and paths.Covering every when branch in Kotlin; Kover coverage; Pitest mutation checks.
Black-Box TestingBehavioral testing strictly from external specs/UI/API without viewing internal code.Boundary Value Analysis, Appium/Maestro flows, Playwright E2E.
Gray-Box TestingDriving black-box external interfaces while controlling or inspecting internal state/plumbing.Compose UI test backed by OkHttp MockWebServer or seeded Room DB.
Test OracleThe independent source of truth determining whether a test's output is correct.Hardcoded expected value (2000) derived by hand from specs.
Tautological OracleAnti-pattern where the test copies production math/logic to compute its expected value.Both test and prod share the same bug and stay green together.
Mutant / Mutation TestingInjecting deliberate small faults (mutants) into production code to measure if tests actually fail.Changing >= to >; a strong test suite kills 100% of mutants.
Hermetic TestA self-contained test completely isolated from external networks, real clocks, and shared state.Injected Clock.fixed(), fake repositories, and local MockWebServer.
Flaky TestA test that passes and fails intermittently without any change to the code under test.Caused by race conditions, shared mutable singletons, real time, or Thread.sleep.
Shift-Left / Shift-RightMoving quality checks earlier (IDE/PR) vs monitoring real behavior in production (canaries/synthetics).PR JUnit + Compose checks (Left); Firebase Crashlytics + synthetic probes (Right).
Test DoubleUmbrella term for Dummy, Stub, Spy, Fake, and Mock substitutes used to isolate a System Under Test.In-memory FakeUserRepo vs MockK stubbing a network interface.
Contract TestingVerifying that a consumer (Android app) and provider (REST API) honor a shared payload schema.Consumer-Driven Contracts via Pact so backend changes don't silently break mobile.
ArchUnitJVM library enforcing package dependency and annotation rules as fast unit tests.Fails build if Spring controllers import repositories directly or domain classes import Spring.
Ephemeral EnvironmentShort-lived, isolated PR environment spun up from containers/IaC and torn down after merge.Prevents PR A's E2E seed data from colliding with PR B on a shared staging DB.
