Lesson 03: White-Box Testing, Coverage Myths & Mutation Testing

Why can a codebase with 95% line coverage still crash in production? Because coverage measures which lines executed, not whether your assertions actually verified anything. Enter Branch/Condition coverage and Mutation Testing.

01 Statement/Line vs Branch vs Condition / MC/DC Coverage

1. Line (Statement)

Weakest metric. An inline if (x > 0) a() counts as 100% line coverage even if the false branch never runs!

2. Branch (Decision)

Requires every if/else and when arm to evaluate both true and false at least once.

3. Condition / MC/DC

Inside if (A && B), each atomic boolean (A and B) independently flips the overall outcome.

02 Mutation Testing: Testing Your Tests

Tools like Pitest (JVM) mutate bytecode (flipping >= to >, changing return true to return false, deleting void calls). If your test suite stays green on a mutant, that mutant survived — proving you have a blind spot.

Why 100% Line Coverage Still Ships Bugs
Consider: fun eligible(age: Int) = age >= 18 && !isSuspended.
One test eligible(25, false) hits 100% line coverage, yet Pitest mutants changing >= 18 to > 18 or deleting !isSuspended both survive!
Equivalent Mutants & Cyclomatic Complexity
Equivalent Mutant: A syntax change that preserves identical behavior (e.g., i < 10 → i != 10 when i steps by +1 from 0).
Cyclomatic Complexity (V(G) = edges - nodes + 2): Counts independent paths; a function with score 12 needs ≥12 tests and should usually be split.

03 Kotlin Kover & Pitest in Gradle

kover {
  reports {
    verify {
      rule {
        minBound(85, coverageUnits = CoverageUnit.BRANCH)
      }
    }
  }
}
pitest {
  junit5PluginVersion.set("1.2.1")
  targetClasses.set(listOf("com.shoppulse.domain.*")) // Focus on high-value business logic
  excludedClasses.set(listOf("*Composable*", "*_Factory*")) // Skip Compose/Hilt generated glue
  mutators.set(listOf("STRONGER"))
  mutationThreshold.set(85)
  withHistory.set(true) // Incremental analysis keeps PR checks fast!
}
// MC/DC: N+1 tests (4 tests for 3 conditions) prove each clause independently flips the decision
@ParameterizedTest
@CsvSource(
  "true,  true,  false, true",  // Baseline: all true -> approved
  "false, true,  false, false", // Flip isVerified -> must fail
  "true,  false, false, false", // Flip hasBalance -> must fail
  "true,  true,  true,  false"  // Flip isBlocked -> must fail
)
fun `canAutoApprove satisfies MC_DC independence`(
  verified: Boolean, funded: Boolean, blocked: Boolean, expected: Boolean
) {
  assertThat(policy.canAutoApprove(verified, funded, blocked)).isEqualTo(expected)
}
