Lesson 23: Deflaking & Determinism at Scale

When CI fails 15% of the time for no reason, developers stop trusting tests and hit "Re-run" blindly — letting real bugs merge. As Google's Testing Blog documents, Senior SDETs systematically hunt the 7 root causes of flakiness and enforce a strict <1% Flake SLO.

00 Why Blanket Auto-Retries Hide Cancer

Setting retries: 3 in CI without tracking retry rates sweeps flakiness under the rug while tripling CI cost and hiding intermittent race conditions! Track flaky-pass rate (passed on retry) as an engineering metric and quarantine + fix repeat offenders within 48 hours.

01 The 7 Root Causes & Exact Fixes

Root CauseFix
1. Shared mutable state / test order couplingFresh Test Data Factories per test + Android Test Orchestrator (isolated process per test!).
2. Async race / Thread.sleep()StandardTestDispatcher, Compose waitUntil, Playwright web-first assertions.
3. Real system clock / midnight / timezoneInjected fixed Clock & explicit UTC timezone in tests.
4. Uncontrolled randomnessDeterministic PRNG seeds or explicit boundary fixtures.
5. Live external APIs / third-party widgetsMockWebServer, Pact stubs, or Playwright page.route().
6. OS animations & popupsDisable animator duration scales in Gradle + pre-grant permissions.
7. Resource leaks (unclosed DB/sockets)try/finally teardown + server.shutdown().

02 Android Test Orchestrator & Data Factory Pattern

android {
  testOptions {
    execution = "ANDROIDX_TEST_ORCHESTRATOR" // Clears shared prefs/DB & isolates crashes per test
    animationsDisabled = true
  }
}
object TestUserFactory {
  private val counter = AtomicInteger(0)
  fun create(email: String = "user_${counter.incrementAndGet()}@test.local") = User(id = "u-${counter.get()}", email = email)
}
Test Data Management: Seed via API/Builder & Scrub PII
Never click through 6 UI screens just to create a test user before testing Refund! Seed isolated fixtures directly via API/DB builders with unique run prefixes (test-worker-${runId}), and never copy unmasked production PII dumps into staging test DBs.
