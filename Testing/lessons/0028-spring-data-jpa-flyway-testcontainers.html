Module 1A.2: @DataJpaTest, Flyway & @ServiceConnection

By default, @DataJpaTest replaces your Postgres datasource with an embedded H2 database — masking broken Postgres SQL syntax, JSONB operators, FOR UPDATE SKIP LOCKED, and Flyway migration errors! Spring Boot's @ServiceConnection wires a real Docker PostgreSQL container in 3 lines.

00 Why H2 Creates False Confidence on Real Spring Backends

Always Set replace = AutoConfigureTestDatabase.Replace.NONE
When Hibernate auto-generates tables (ddl-auto: create-drop) inside H2, you never verify your real Flyway / Liquibase SQL migrations or Postgres-specific indexes! Use real Postgres via Testcontainers + @ServiceConnection with Flyway enabled.

01 @DataJpaTest + @ServiceConnection (Postgres & Redis, Java 21 & Kotlin)

Place @ServiceConnection on a static container (or a shared @TestConfiguration bean) so Spring Boot automatically wires JDBC URL, credentials, or Redis host/port without brittle @DynamicPropertySource boilerplate. 

@DataJpaTest
@Testcontainers
@AutoConfigureTestDatabase(replace = AutoConfigureTestDatabase.Replace.NONE)
class OrderRepositoryTest {
  @Container @ServiceConnection
  static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:16-alpine");

  @Autowired OrderRepository repo;
  @Autowired TestEntityManager em;

  @Test
  void findsPaidOrdersWithItemsInSingleJoinFetch() {
    var order = new OrderEntity("ord-1", Status.PAID, List.of(new OrderItem("SKU-1", 2)));
    em.persistAndFlush(order);
    em.clear(); // Crucial: clear L1 cache so Hibernate hits real PostgreSQL!

    var stats = em.getEntityManager().getEntityManagerFactory()
      .unwrap(SessionFactory.class).getStatistics();
    stats.setStatisticsEnabled(true);
    stats.clear();

    var found = repo.findAllPaidWithItems();
    assertThat(found).hasSize(1);
    assertThat(found.get(0).getItems()).hasSize(1);
    assertThat(stats.getPrepareStatementCount()).isEqualTo(1L); // Zero N+1 queries!
  }
}
@DataJpaTest
@Testcontainers
@AutoConfigureTestDatabase(replace = AutoConfigureTestDatabase.Replace.NONE)
class OrderRepositoryTest(
  @Autowired val repo: OrderRepository,
  @Autowired val em: TestEntityManager
) {
  companion object {
    @Container @ServiceConnection
    @JvmStatic val postgres = PostgreSQLContainer("postgres:16-alpine")
  }

  @Test
  fun `Flyway unique constraint rejects duplicate idempotency keys`() {
    repo.saveAndFlush(OrderEntity(id = "o-1", idempotencyKey = "idem-9"))
    assertThrows<DataIntegrityViolationException> {
      repo.saveAndFlush(OrderEntity(id = "o-2", idempotencyKey = "idem-9"))
    }
  }
}
@TestConfiguration(proxyBeanMethods = false)
public class ContainersConfig {
  @Bean @ServiceConnection
  PostgreSQLContainer<?> postgresContainer() { return new PostgreSQLContainer<>("postgres:16-alpine"); }

  @Bean @ServiceConnection(name = "redis")
  GenericContainer<?> redisContainer() { return new GenericContainer<>("redis:7-alpine").withExposedPorts(6379); }
}
// Import via @Import(ContainersConfig.class) across test classes to share warm containers!

02 Two Silent JPA Bugs Senior Backend Devs Catch in Tests

1. L1 Cache Illusion: Calling repo.save(entity) then repo.findById(...) in the same transaction reads Hibernate's in-memory 1st-level cache without running SELECT! Always call em.flush(); em.clear(); before querying.
2. N+1 Query Explosion: Loading 50 orders triggers 1 query + 50 lazy child queries in prod! Assert SQL statement counts via Hibernate Statistics or datasource-proxy.
