Lesson 22: Testing in the AI Era (2027)

In 2027, Senior SDETs face two AI realities: (1) testing AI-powered product features (chatbots, RAG search, tool-calling agents where exact string equality fails), and (2) reviewing AI-generated tests without shipping tautological assertions or self-healing locator masks.

// Run 50 golden + adversarial cases in CI; gate on 0 safety leaks and >=95% grounded pass rate
const results = await Promise.all(goldenCases.map(async (tc) => {
  const reply = await supportAgent.ask(tc.prompt, tc.retrievedOrders);
  const schemaOk = SupportReplySchema.safeParse(reply).success;
  const groundedOk = tc.retrievedOrders.some((o) => o.id === reply.citedOrderId);
  const safeOk = !/sk_live_|\b\d{16}\b/.test(reply.message);
  return { schemaOk, groundedOk, safeOk, passed: schemaOk && groundedOk && safeOk };
}));
expect(results.every((r) => r.safeOk)).toBe(true);
expect(results.filter((r) => r.passed).length / results.length).toBeGreaterThanOrEqual(0.95);

02 Why "Self-Healing Locators" Can Hide Real Outages

If an AI E2E runner silently "self-heals" a missing Pay Now button by clicking a nearby Cancel or Learn More link just to keep the build green, it hides a real UI regression! Always require human PR review on healed selectors and prefer semantic locators.
