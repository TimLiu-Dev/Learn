Module 1A.1: Spring Boot Test Architecture & @WebMvcTest Slices

Putting @SpringBootTest on every backend test boots the entire web server, JPA, security, and Hikari pool repeatedly — turning a 10-second build into 12 minutes. Senior Java & Kotlin Spring Boot engineers keep domain tests pure JVM and isolate HTTP boundaries with @WebMvcTest + @MockitoBean / @MockkBean.

01 @WebMvcTest in Java 21 (@MockitoBean / MockMvcTester) & Kotlin (@MockkBean)

Modern Spring Boot (Spring Boot Testing Docs) uses @MockitoBean (replacing deprecated @MockBean) in Java and SpringMockK @MockkBean in Kotlin. Spring Boot 3.4+ also introduced MockMvcTester so you get fluent AssertJ assertions on HTTP responses without checked throws Exception boilerplate. 

@WebMvcTest(OrderController.class)
class OrderControllerTest {
  @Autowired MockMvc mockMvc;
  @MockitoBean OrderService orderService; // Modern Spring Boot replacement for @MockBean

  @Test
  void createOrder_returns400_whenQuantityIsZero() throws Exception {
    mockMvc.perform(post("/api/orders")
        .contentType(MediaType.APPLICATION_JSON)
        .content("""{"sku":"SKU-1","quantity":0}"""))
      .andExpect(status().isBadRequest())
      .andExpect(jsonPath("$.errors[0].field").value("quantity"));

    verifyNoInteractions(orderService);
  }
}
@WebMvcTest(OrderController.class)
class OrderControllerFluentTest {
  @Autowired MockMvcTester mvc;
  @MockitoBean OrderService orderService;

  @Test
  void getOrder_returns404ProblemDetail_whenMissing() {
    when(orderService.findById("missing")).thenThrow(new OrderNotFoundException("missing"));

    assertThat(mvc.get().uri("/api/orders/missing"))
      .hasStatus(HttpStatus.NOT_FOUND)
      .bodyJson().extractingPath("$.title").isEqualTo("Order Not Found");
  }
}
@WebMvcTest(OrderController::class)
class OrderControllerTest(@Autowired val mockMvc: MockMvc) {
  @MockkBean lateinit var orderService: OrderService

  @Test
  fun `getOrder maps OrderNotFoundException via ControllerAdvice to 404`() {
    every { orderService.findById("missing") } throws OrderNotFoundException("missing")

    mockMvc.get("/api/orders/missing")
      .andExpect { status { isNotFound() } }
  }
}

02 Spring TestContext Caching & Why Dirtying Contexts Slows CI

Spring caches and reuses the ApplicationContext across tests that share identical configurations (context locations, active profiles, property sources, and @MockitoBean/@MockkBean sets). Adding @DirtiesContext or varying mocks across 20 test classes forces Spring to reboot 20 separate contexts!

Senior Fix: Shared Integration Base Class + @RestartScope
Define one abstract BaseIntegrationTest holding shared @ServiceConnection containers and common @MockitoBean stubs so 30 integration test classes share 1 cached ApplicationContext. Keep pure domain services completely Spring-free!
