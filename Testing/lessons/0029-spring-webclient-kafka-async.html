01 Spring Security JWT, RestClient / WireMock & Awaitility (Java & Kotlin)

Use @RestClientTest + MockRestServiceServer for synchronous Spring RestClient adapters, and WireMock (or WebTestClient + OkHttp MockWebServer) when testing reactive WebClient timeouts, retries, or full-stack @SpringBootTest HTTP stubs. 

@Test
void refundEndpoint_requiresAdminScope_returns403ForCustomerJwt() throws Exception {
  mockMvc.perform(post("/api/admin/orders/ord-1/refund")
      .with(jwt().authorities(new SimpleGrantedAuthority("ROLE_USER"))))
    .andExpect(status().isForbidden());

  verifyNoInteractions(orderService);
}

@Test // In @RestClientTest(PaymentClient.class):
void chargeCard_maps429RateLimit_toRetryableException() {
  server.expect(requestTo("https://pay.example/charge"))
    .andExpect(method(HttpMethod.POST))
    .andRespond(withTooManyRequests());

  assertThrows(RetryableGatewayException.class, () -> paymentClient.charge("ord-1", 2500));
}
// Full @SpringBootTest or WebClient test using WireMockServer:
wireMock.stubFor(post(urlEqualTo("/quote"))
  .willReturn(aResponse().withStatus(503).withFixedDelay(400)))

val client = WebClient.builder().baseUrl(wireMock.baseUrl()).build()
assertThrows<GatewayUnavailableException> { shippingAdapter.fetchQuote(client, "ord-9") }
@Test
fun `kafka consumer processes order event once and routes poison message to DLT`() {
  kafkaTemplate.send("orders.created", "evt-1", validPayload)
  kafkaTemplate.send("orders.created", "evt-bad", "{not-json")

  await.atMost(Duration.ofSeconds(5)).untilAsserted {
    assertThat(orderRepo.findByEventId("evt-1")).isNotNull()
    assertThat(dltListener.receivedKeys()).contains("evt-bad")
  }
}

02 Why Kafka Consumers Must Test Redelivery & Dead-Letter Topics

Kafka delivers at-least-once: duplicate events WILL arrive, and malformed "poison pill" JSON WILL crash an unprotected consumer in an infinite retry loop! Senior backend suites test both idempotent deduplication and DLT routing.
