Lesson 05: Modern JUnit 5 & Fluent Assertions

JUnit 5 (Jupiter) replaced JUnit 4's rigid @Rule system with composable Extensions, clean @Nested specification trees, and zero-boilerplate @ParameterizedTest suites (JUnit 5 User Guide). Pair it with Google Truth or Kotest assertions for crystal-clear CI failure logs.

01 @Nested, @ParameterizedTest, Extensions & Gradle Tags

By default JUnit 5 uses Lifecycle.PER_METHOD: each @Test gets a brand-new class instance so fields never leak between tests. Use @Nested inner class for Given-When-Then context grouping, @TempDir for ephemeral files, and @Tag("integration") to split fast PR checks from slower suites in Gradle. 

class CartPricingTest {
  @Nested
  inner class GivenValidPromo {
    @ParameterizedTest(name = "subtotal={0} -> total={1}")
    @CsvSource("1000, 800", "2500, 2000", "0, 0")
    fun `applies 20 percent discount`(subtotal: Int, expected: Int) {
      assertThat(pricing.apply("SAVE20", subtotal)).isEqualTo(expected)
    }
  }

  @Test
  fun `soft assertions report all field mismatches at once`() {
    val receipt = pricing.buildReceipt(1000)
    assertAll(
      { assertThat(receipt.currency).isEqualTo("USD") },
      { assertThat(receipt.taxCents).isEqualTo(80) },
      { assertThat(receipt.totalCents).isEqualTo(1080) }
    )
  }
}
class MainDispatcherExtension(
  private val dispatcher: TestDispatcher = StandardTestDispatcher()
) : BeforeEachCallback, AfterEachCallback {
  override fun beforeEach(context: ExtensionContext) = Dispatchers.setMain(dispatcher)
  override fun afterEach(context: ExtensionContext) = Dispatchers.resetMain()
}

// Usage: @ExtendWith(MainDispatcherExtension::class) on any ViewModel test class!
@Test
fun `writes receipt cache safely to isolated @TempDir`(@TempDir tempDir: Path) {
  val cache = ReceiptFileCache(tempDir)
  val saved = cache.write("ord-1", currency = "USD", totalCents = 1080)

  assertSoftly(saved) {
    currency shouldBe "USD"
    totalCents shouldBe 1080
    tempDir.resolve("ord-1.json").toFile().exists() shouldBe true
  }
}

02 Why Soft Assertions & Rich Matchers Matter

If a test checks 4 fields of a DTO sequentially and line 1 fails, standard assertions abort before showing you lines 2–4. JUnit 5's assertAll (or Kotest assertSoftly) collects all failures in one run so you debug in one CI cycle instead of four.

Matcher Rule: Assert Structure & Collections Expressively
Prefer assertThat(items).containsExactly("A", "B").inOrder() or shouldContainExactly(...) over assertTrue(items.size == 2 && items[0] == "A"). Fluent matchers automatically print the full expected vs. actual diff on failure.
