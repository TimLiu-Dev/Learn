Lesson 24: CI/CD Test Orchestration & Sharding

Great tests that take 50 minutes on CI get bypassed or disabled. Senior SDETs design 3-tier pipelines (<5m PR feedback, sharded merge/smoke gates, nightly deep matrices), shard tests smartly using Flank / Firebase Test Lab / Playwright shards, and publish rich Allure/HTML diagnostics.

01 GitHub Actions Sharded Pipeline & Ephemeral PR Environments

Avoid fighting over a single shared staging server! Spin up an ephemeral PR environment (Docker Compose / preview namespace seeded per PR) so parallel PRs never overwrite each other's test data, and always upload failure artifacts (Playwright trace.zip, Roborazzi diffs, Logcat). 

jobs:
  unit-and-snapshots:
    runs-on: ubuntu-latest
    steps:
      - run: ./gradlew testDebugUnitTest verifyRoborazziDebug
  playwright-e2e:
    strategy:
      fail-fast: false
      matrix: { shard: [1/4, 2/4, 3/4, 4/4] }
    steps:
      - run: npx playwright test --shard=${{ matrix.shard }} --reporter=blob
      - if: failure()
        uses: actions/upload-artifact@v4
        with: { name: "pw-trace-${{ strategy.job-index }}", path: "test-results/" }
flank:
  max-test-shards: 8
  shard-time: 120 # Balances slow vs fast Android tests by historical duration!
  num-flaky-test-attempts: 1
android.testOptions.managedDevices.localDevices {
  create("pixel6Api34") { device = "Pixel 6"; apiLevel = 34; systemImageSource = "aosp-atd" }
} // Runs headless Automated Test Device (ATD) images reliably in CI!

02 Why Duration-Based Sharding Beats Alphabetical Sharding

If Shard 1 gets 5 tiny 1-second tests and Shard 2 gets 5 heavy 40-second checkout tests, Shard 2 blocks the entire build for 200 seconds! Smart runners (like Flank) pack tests using historical execution times (LPT greedy bin-packing) so all shards finish together.
