Lesson 16: Espresso, UI Automator & Kaspresso

Real Android apps aren't pure Compose: they include legacy XML screens, OAuth WebViews, camera/notification OS permission dialogs, and deep links. Learn how Espresso, UI Automator, and Kaspresso tame hybrid Android UI flows cleanly.

00 Where Espresso Stops and UI Automator Takes Over

ToolScopeWhat It Can / Cannot Touch
EspressoIn-process Android XML Views + WebViewsFast main-thread sync inside your app; cannot tap OS permission dialogs or other apps!
UI AutomatorCross-app / System OS UI (UiDevice)Taps "Allow Camera", Settings toggles, Chrome tabs, notifications; slower without Espresso main-thread sync.
KaspressoUnified DSL over Espresso + UI Automator + ComposePage Objects (Kakao), automatic flaky-retry wrapper, rich Allure/Logcat step screenshots!

01 Page Object Pattern + IdlingResource Discipline

Never put raw onView(withId(R.id.btn_pay)).perform(click()) inside 30 test files. Wrap screen selectors in a Screen / Page Object so a layout ID change updates 1 file, not 30.

02 Kaspresso + UI Automator Permission Example

@Test
fun scanQr_grantsCameraPermissionAndNavigates() = run {
  step("Open scanner and accept OS camera dialog") {
    CartScreen { scanButton.click() }
    device.permissions.allowViaDialog()
  }
  step("Verify camera preview is active") {
    ScannerScreen { previewView.isVisible() }
  }
}
// Prefer GrantPermissionRule in androidTest when you aren't explicitly testing the prompt itself:
@get:Rule val permRule = GrantPermissionRule.grant(Manifest.permission.CAMERA)
