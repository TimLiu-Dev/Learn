Lesson 06: Test Doubles & MockK Deep Dive

Junior devs often mock every dependency with every { ... } and assert verify(exactly = 1) on internal implementation details. Senior engineers know all 5 test double types, prefer Fakes for stateful layers, and reserve MockK for clean boundary verification.

00 Over-Mocking vs Behavior Verification

Classic Refactoring Trap ("Testing the Mock")
If you mock a Repository AND assert verify { dao.getById("1") }, renaming getById to findUser breaks the test even when app behavior is 100% intact. Test observable state/outputs using a Fake whenever possible; verify calls only for true side effects (e.g., analytics events, payment charges).

01 The 5 Test Doubles (Meszaros / Google Testing Taxonomy)

DoubleDefinitionAndroid Example
DummyPassed to fill a parameter list; never actually called.DummyAnalytics() in a constructor unrelated to the test.
StubReturns canned answers to calls made during the test.coEvery { api.fetchUser() } returns User("Ada").
SpyRecords calls/arguments made to it (or wraps a real object).spyk(PriceCalculator()) or capturing analytics events.
FakeWorking lightweight implementation (not production-scale).FakeCartRepository backed by an in-memory MutableStateFlow.
MockPre-programmed with expectations; verifies exact interaction behavior.coVerify(exactly = 1) { gateway.charge(2500) }.

02 MockK Idiomatic Kotlin, In-Memory Fakes & Gradle testFixtures

Senior teams keep Fakes maintainable across multi-module Android/Kotlin repos using Gradle's java-test-fixtures plugin (so :feature-cart can import FakeAuthRepository from :core-auth's testFixtures without shipping test code in production APKs). Never mock third-party libraries directly ("Don't Mock What You Don't Own") — wrap them behind your own small adapter interface first. 

class FakeCartRepository : CartRepository {
  private val items = linkedMapOf<String, Int>()
  var shouldFailNetwork = false

  override suspend fun addItem(sku: String, qty: Int) {
    if (shouldFailNetwork) throw IOException("Simulated offline")
    items[sku] = (items[sku] ?: 0) + qty
  }
  override fun count(sku: String): Int = items[sku] ?: 0
}
@Test
fun `checkout charges payment gateway once with exact captured payload`() = runTest {
  val chargeSlot = slot<ChargeRequest>()
  val gateway = mockk<PaymentGateway> { coEvery { charge(capture(chargeSlot)) } returns Receipt("ok") }
  val analytics = mockk<Analytics>(relaxed = true) // Safe ONLY for fire-and-forget void telemetry
  val useCase = CheckoutUseCase(gateway, analytics)

  useCase.submit(totalCents = 2500, currency = "USD")

  coVerify(exactly = 1) { gateway.charge(any()) }
  assertThat(chargeSlot.captured.amountCents).isEqualTo(2500)
  verify { analytics.track("checkout_success") }
  confirmVerified(gateway) // Guarantees no unexpected duplicate charges!
}
// :core-data/build.gradle.kts
plugins { id("java-test-fixtures") }

// :feature-checkout/build.gradle.kts
dependencies {
  testImplementation(testFixtures(project(":core-data"))) // Reuse FakeCartRepository cleanly!
}
