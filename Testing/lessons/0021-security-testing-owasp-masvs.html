Lesson 21: Mobile & API Security Testing (OWASP MASVS)

Security defects are rarely caught by happy-path tests. Using OWASP MASVS as our standard, you will test Android deep-link / Intent injection, insecure token storage, and API Broken Object-Level Authorization (BOLA / IDOR).

01 Automated BOLA, Deep-Link & JWT / Network Security Checks

test("User A cannot read or cancel User B order (BOLA/IDOR guard)", async ({ request }) => {
  const res = await request.get("/api/orders/user-b-order-99", {
    headers: { Authorization: `Bearer ${userAToken}` }
  });
  expect([403, 404]).toContain(res.status());
});
@ParameterizedTest
@ValueSource(strings = ["https://evil.com/phish", "javascript:alert(1)", "shoppulse://checkout?redirect=http://evil.com"])
fun `deep link parser rejects untrusted external redirects`(rawUri: String) {
  assertThrows<SecurityException> { deepLinkRouter.parse(Uri.parse(rawUri)) }
}
// 1. Negative JWT tampering test: alg=none or altered role claim must return 401!
test("rejects unsigned alg=none or tampered JWT", async ({ request }) => {
  const res = await request.get("/api/admin/orders", {
    headers: { Authorization: `Bearer ${forgedAlgNoneToken}` }
  });
  expect(res.status()).toBe(401);
});

02 Why "AuthN" (401) Tests Are Not "AuthZ" (403) Tests

Testing that an unauthenticated user gets 401 proves Authentication works. It does not prove Authorization works! Every multi-tenant resource endpoint needs a cross-user test verifying User A's valid JWT cannot read or mutate User B's record.
