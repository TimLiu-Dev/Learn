1. End-to-End Platform Architecture Blueprint

Architecture Spec

This flagship system runs a multi-service Spring Boot backend (orders-api + payments-api + Multi-AZ PostgreSQL) across isolated staging and prod environments provisioned strictly through IaC and GitOps. 

[Developer Commit] --> [GitHub Actions (OIDC)] --> [GHCR Immutable @sha256]
                                                         |
[Terraform S3 State] --> [VPC + Private EKS + RDS Multi-AZ]
                                                         v
[GitOps Repo (Kustomize)] <-- [Argo CD ApplicationSet (staging -> prod)]
                                                         |
[Gateway API Traffic] --> [Argo Rollouts Canary (10% -> 50% -> 100%)]
                                 ^                       |
                                 | (Auto-Abort on 5xx)   v
[OpenTelemetry Collector] --> [Prometheus SLO Burn Alerts + Grafana + Tempo]
Platform Layer Tooling & Standard Multi-Env Design (Staging vs Prod)
Infrastructure (IaC) Terraform (VPC, EKS, IRSA, RDS) Encrypted S3 remote state + state locking; separate state prefixes per environment.
GitOps Delivery Argo CD ApplicationSet + Kustomize Auto-sync with prune: true and selfHeal: true; prod tracks pinned release overlays.
Progressive Delivery Argo Rollouts + Gateway API Canary shifts 10% → 50% → 100% gated by Prometheus HTTP 5xx & p95 latency AnalysisTemplate.
Observability & SRE OpenTelemetry + Prometheus + SRE SLOs 99.9% availability SLO with 14.4x (1h/5m) and 6x (6h/30m) multi-window burn-rate paging rules.

5. Failover Drill Checklist & 2027 Resume Bullet Templates

Portfolio & Career Proof

Production Failover & Chaos Drill Checklist

  1. Verify baseline SLO: Confirm orders-api and payments-api report 200 OK on /actuator/health and 0% error-budget burn across all AZs.
  2. Trigger bad canary release: Deploy an intentional 500-returning image at 10% canary weight; verify Argo Rollouts AnalysisRun auto-aborts within 2 minutes without hitting 100%.
  3. Drain a worker AZ node: Cordon and drain one Availability Zone node; verify PodDisruptionBudget (minAvailable: 2) keeps capacity online with zero 502s.
  4. Validate Multi-AZ RDS failover: Reboot primary DB with failover; measure client reconnect time and confirm RTO < 60 seconds.
  5. Publish Blameless Postmortem: Document timeline, PromQL alert trigger timestamp, MTTR, and 2 automated prevention items in Git.
