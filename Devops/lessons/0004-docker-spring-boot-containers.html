1. Mental Model Bridge: Gradle Builds to Multi-Stage Images

Start Here

Think of a Docker image like a signed, immutable APK/AAB artifact, and a container like a running process instance of that artifact. Just as you would never ship the entire Android SDK inside your Play Store APK, you should never ship Gradle, JDK compilers, or source code inside your production Spring Boot runtime image—multi-stage builds separate build tools from runtime cleanly.

Android / Spring Concept Docker Equivalent Production Payoff
Gradle compilation + R8 shrink → APK Multi-stage Dockerfile (AS build → JRE) Shrinks Spring Boot images from ~900 MB (full JDK + Gradle cache) to ~180 MB JRE runtime.
Gradle build cache across builds Ordered COPY layers (manifests before src/) Code edits reuse cached dependency layers instead of re-downloading Maven Central every build.
Android app sandbox UID per app Non-root USER appuser in runtime stage Limits blast radius if an HTTP framework vulnerability achieves remote code execution.
JVM heap tuning in gradle.properties -XX:MaxRAMPercentage=75.0 + exec-form ENTRYPOINT Respects container cgroup memory limits and receives SIGTERM directly as PID 1.
Always Pair Dockerfile with .dockerignore
Without .dockerignore, COPY . . sends .git/, build/, target/, and local .env secrets into the Docker build context—slowing builds and risking secret leaks.

Exec-Form vs Shell-Form ENTRYPOINT

Instruction PID 1 Process Receives SIGTERM?
ENTRYPOINT java -jar app.jar /bin/sh -c "java -jar app.jar" No. /bin/sh swallows SIGTERM; orchestrator waits 30s then sends SIGKILL.
ENTRYPOINT ["java","-jar","/app/app.jar"] java directly Yes. Spring Boot drains active HTTP traffic cleanly on stop.

5 Container Mistakes That Hurt Production Services

  1. Using :latest base tags: Silent upstream JDK or Alpine bumps break builds unexpectedly on Monday morning.
  2. Running as root: Every container without a non-root USER directive fails enterprise security admission policies.
  3. Copying . before dependency manifests: Every single Java/Kotlin edit invalidates the Gradle/Maven cache layer.
  4. Using shell-form ENTRYPOINT: Wrapping Java in /bin/sh -c blocks graceful shutdown signals during rolling deploys.
  5. Baking .env or keystores into COPY layers: Secrets stay inside immutable image history even if deleted in a later RUN step.

BuildKit, .dockerignore & Multi-Arch (arm64/amd64)
Always add a .dockerignore excluding .git, build/, and *.keystore so context uploads stay tiny. On Apple Silicon Macs deploying to Linux x86_64 servers, build with docker buildx build --platform linux/amd64,linux/arm64 and speed up Gradle builds with RUN --mount=type=cache,target=/root/.gradle.
