1. Mental Model Bridge: Spring Boot & Compose to Kubernetes

Start Here

Docker Compose manages containers on a single host; Kubernetes spreads Pods across a cluster of nodes using declarative reconciliation loops. Every control plane component has one clear responsibility, and your Spring Boot Actuator endpoints plug directly into Kubernetes probes.

Control Plane Reconciliation in One Sentence
Clients talk strictly to kube-apiserver, which persists desired state in etcd; kube-scheduler binds pending Pods to nodes based on requests, and kube-controller-manager continuously drives actual cluster state toward desired state.

Kubernetes QoS Classes & OOM Eviction Priority

QoS Class How It Is Assigned Eviction Priority Under Pressure
Guaranteed Every container sets CPU & memory requests == limits Last to be evicted; safest for stateful or critical Spring Boot APIs.
Burstable At least one container sets requests or limits (not equal) Evicted after BestEffort Pods if usage exceeds requests.
BestEffort Zero requests and zero limits set First to be killed when a node runs low on memory.

5 Mistakes That Break Production Kubernetes Workloads

  1. Sharing the same endpoint for liveness and readiness (or checking Postgres in liveness): A brief DB hiccup causes Kubernetes to restart every healthy Spring Boot Pod simultaneously!
  2. Omitting startupProbe on JVM services: A 35-second Spring Boot startup hits a 30-second liveness timeout and enters an infinite CrashLoopBackOff.
  3. Setting tight CPU limits unnecessarily: CFS CPU throttling spikes p99 latency even when node CPU is mostly idle; many teams set CPU requests without rigid CPU limits while keeping memory requests == limits.
  4. Skipping PodDisruptionBudget: Cluster autoscaler or EKS/GKE node upgrades can drain both replicas of a service at the same moment.
  5. Missing preStop sleep on graceful shutdown: SIGTERM reaches the container in parallel with Endpoint removal, causing in-flight 502 errors unless you pause ~5 seconds first.

DaemonSets, RBAC, kubectl debug & CPU Limits Tradeoff
Beyond Deployments: use DaemonSet for node-level log/OTel agents, CronJob for scheduled DB/DR checks, and least-privilege Role/RoleBinding for Pods querying the K8s API. Note the modern consensus: set memory requests == limits (Guaranteed QoS when paired with matching CPU), or omit rigid CPU limits on latency-sensitive JVM APIs if CFS cgroup throttling spikes p99 latency.
