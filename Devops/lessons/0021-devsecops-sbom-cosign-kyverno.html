1. Mental Model Bridge: APK Signing & Play Protect to Cloud Supply Chain

Start Here

On Android, Google Play refuses unsigned APKs, checks package signatures before updates, and flags vulnerable SDK dependencies. Kubernetes needs the exact same chain of custody: Sigstore Cosign signs immutable container digests using short-lived OIDC tokens, Syft records every JAR/OS package in an SBOM, Trivy blocks critical CVEs in CI, and Kyverno rejects unsigned or privileged pods at the cluster API door.

Android Security World Cloud Supply Chain Equivalent What It Prevents
build.gradle dependency lock / Play SDK checks SBOM (Syft) + Trivy CVE Gate Zero-day response blind spots (e.g., finding every image running a vulnerable Log4j/Spring JAR in seconds).
Play App Signing + upload keystore Cosign Keyless OIDC Signing + Rekor Transparency Log Tampered registry images pushed outside your trusted GitHub Actions repository.
Google Play installation verification Kyverno Admission ClusterPolicy (verifyImages) Attackers or misconfigured scripts deploying unsigned, :latest, or root-privileged pods into prod.
Android Keystore hardware-backed secrets External Secrets Operator + HashiCorp Vault / KMS Leaking database passwords or API keys inside Git repositories as plain base64 Kubernetes Secrets.
Always Sign & Verify by Immutable Digest (@sha256:...)
A tag like ghcr.io/acme/api:v1.4.0 is just a mutable pointer—someone with registry write access could overwrite it. Signing and deploying by cryptographic digest (@sha256:9f8a...) guarantees the exact bytes scanned by Trivy are the exact bytes Kyverno admits into production.

5 Mistakes That Undermine Supply Chain Security

  1. Signing mutable tags instead of digests: Signing :latest lets a tag-swap attack bypass verification logic if policy isn't pinned to @sha256:.
  2. Running Kyverno in Audit mode forever: Audit logs warn silently; critical guardrails must graduate to Enforce in production.
  3. Checking base64 K8s Secrets into Git: Base64 is encoding, not encryption; use External Secrets Operator + Vault or KMS-sealed secrets.
  4. Skipping ignore-unfixed triage strategy: Blocking builds on upstream OS CVEs with zero available patch stalls emergency security hotfixes; enforce strict gates on fixable CRITICAL,HIGH CVEs and base image rebuilds.
  5. Granting permissions: write-all in GitHub Actions: Violates least privilege; grant only id-token: write and packages: write on the specific build/sign job.
