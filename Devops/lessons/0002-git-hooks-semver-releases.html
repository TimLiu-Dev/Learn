1. Mental Model Bridge: Manual Releases to Git-Driven Automation

Start Here

When you build solo in Android Studio, you might manually increment versionCode in build.gradle.kts or commit messages like "fix". In team DevOps, CI reads structured commit history and Git tags directly via Conventional Commits and Semantic Versioning to decide whether a release is a patch, minor feature, or breaking major change.

Android / Spring Habit Production DevOps Equivalent Why It Matters in CI/CD
Long-lived develop / release branches (GitFlow) Trunk-based development + short-lived PR branches Avoids multi-week merge conflicts and keeps main continuously deployable behind feature flags.
Clicking "Merge" in IDE with noisy merge commits git rebase main on personal feature branches Produces clean linear history so git bisect and automated changelog generators work predictably.
Manually editing versionName / pom.xml Git tags (v1.4.2) + Conventional Commits One tag drives Spring Boot Docker image tags (api:1.4.2) and Android Play Store release notes.
Relying on PR reviewers to catch bad commits Git hooks (commit-msg, pre-commit) + CI lint Local hooks give instant feedback before push; CI checks enforce the rule for everyone.
Conventional Commits → SemVer Mapping
Format every commit as type(scope): summary. A fix: bumps PATCH (1.2.3 → 1.2.4), a feat: bumps MINOR (1.2.3 → 1.3.0), and adding ! (like feat(api)!:) or a BREAKING CHANGE: footer bumps MAJOR (1.2.3 → 2.0.0).

5. Primary Sources, Pitfalls & Next Steps

Knowledge & Retention
Recommended Primary Source to Read
Read the official Git Reference Documentation (git-rebase & githooks) alongside the Conventional Commits v1.0.0 Specification. Together they define the exact grammar and hook lifecycle that tools like semantic-release and Release Please rely on.

5 Git & Release Mistakes That Break Teams

  1. Rebasing shared branches: Rewriting commits on main or a shared PR forces teammates into destructive force-push conflicts.
  2. Trusting client-side hooks alone: Developers can bypass local hooks with git commit --no-verify; always re-validate in CI.
  3. Non-executable hook files: Copying a hook into .githooks/ without chmod 755 causes Git to silently skip it.
  4. Vague commit messages: Commits like "wip" or "fix bug" break automated changelogs and hide breaking API changes.
  5. Moving existing SemVer tags: Overwriting v1.2.0 after release breaks reproducible builds and caches—always ship v1.2.1 instead.

Senior Release Engineering Upgrades (2027)
Beyond hooks and SemVer, practice git bisect run ./gradlew test to pinpoint breaking commits automatically, use git worktree to inspect hotfixes without stashing, and enable SSH commit signing (git config gpg.format ssh) for verified release tags.
