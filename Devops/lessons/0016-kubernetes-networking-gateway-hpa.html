1. Mental Model Bridge: Compose Networking to Kubernetes Gateway & Storage

Start Here

In Docker Compose, containers resolve each other by service name, Caddy/Nginx terminates TLS, and named volumes persist Postgres data across restarts. Kubernetes scales those exact primitives across dozens of nodes with explicit role separation.

Compose / Single-Host World Kubernetes 2027 Standard Why It Matters in Production
Compose DNS service name (postgres:5432) ClusterIP Service + CoreDNS (svc.ns.svc.cluster.local) Gives ephemeral Pods a stable virtual IP and DNS name across rolling restarts.
Caddy/Nginx reverse proxy + Ingress annotations Gateway API (GatewayClass, Gateway, HTTPRoute) Separates platform-owned TLS listeners from app-team HTTP routing and weighted traffic splits without vendor annotation sprawl.
Docker Compose internal network isolation NetworkPolicy (default-deny + allow rules) Prevents a compromised frontend Pod from connecting directly to PostgreSQL on port 5432.
Compose named volume for Postgres StatefulSet + volumeClaimTemplates (PVC) Gives each database replica a sticky network identity (postgres-0) and its own persistent disk.
Manually bumping container replicas HorizontalPodAutoscaler / VPA / KEDA Automatically scales Spring Boot Pods on CPU/latency or scales queue workers from zero on Kafka/SQS backlog.
Ingress vs Gateway API in One Sentence
Legacy Ingress crammed TLS, timeouts, and traffic splitting into controller-specific annotations, whereas Gateway API splits cluster-wide listener infrastructure (Gateway owned by Platform) from typed route rules (HTTPRoute owned by App teams).

5 Networking, Storage & Autoscaling Pitfalls

  1. Assuming Kubernetes blocks Pod-to-Pod traffic by default: Without a CNI supporting NetworkPolicy and an explicit deny/allow policy, any compromised Pod can scan every internal service.
  2. Forgetting DNS egress in default-deny NetworkPolicy: Blocking all egress without allowing UDP/TCP port 53 to CoreDNS breaks every external API and service lookup.
  3. Running databases as Deployments with shared ReadWriteOnce PVCs: During a rolling update, the new Pod cannot mount a single-node EBS/PD volume still attached to the old Pod—causing a deadlock.
  4. Creating a LoadBalancer Service per microservice: Spawns expensive cloud load balancers for every API instead of routing all domains through one Gateway.
  5. Combining HPA and VPA on the same CPU metric: They fight each other in an oscillation loop unless VPA runs in Off/recommendation mode or targets memory only.

cert-manager & Event-Driven Scaling (KEDA)
Pair Gateway API listeners with cert-manager (ClusterIssuer) for automated ACME/internal TLS certificate renewal in Kubernetes. When CPU/memory lag behind queue backlogs (SQS/Kafka), adopt KEDA ScaledObject (practiced in Lesson 0028) for queue-depth and scale-to-zero autoscaling.
