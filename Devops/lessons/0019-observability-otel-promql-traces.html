1. Mental Model Bridge: Client Telemetry to OpenTelemetry & PromQL

Start Here

On Android, OkHttp interceptors inject a W3C traceparent header, Firebase Performance tracks network latency, and Logcat shows per-screen events. At platform scale, OpenTelemetry standardizes Metrics, Logs, and Traces across every Spring Boot Pod and funnels them through one Collector pipeline into Prometheus, Loki, and Tempo/Jaeger.

Android / Single-App World Scale Observability Equivalent Why It Matters in Production
Android OkHttp traceparent header Distributed Trace Context (Tempo / Jaeger spans) Links one mobile tap across API Gateway → Orders → Payments → Postgres using a single trace_id.
Logcat on one local emulator Structured JSON Logs + Loki + trace_id Indexes low-cardinality stream labels (namespace, app) while querying JSON fields by trace_id.
Firebase Performance p95 network duration PromQL histogram_quantile(0.95, ...) Averages hide tail latency spikes; p95/p99 histograms prove whether 1 in 20 checkouts takes 4 seconds.
App analytics batch uploader OTel Collector (receivers → processors → exporters) Decouples apps from storage backends, bounds memory via memory_limiter, and batches telemetry efficiently.
Tagging every metric with user_id High-Cardinality Label Explosion Pitfall Unbounded labels multiply Prometheus time series exponentially until TSDB OOM-crashes.
The Cardinality Rule in One Sentence
Put bounded dimensions (service, route, status_class) in Prometheus metric labels, and keep unbounded identifiers (user_id, order_id, trace_id) strictly inside structured logs and trace spans.

PromQL Core Functions Cheat Sheet

Expression Pattern What It Computes Critical Rule
rate(http_requests_total[5m]) Per-second rate of a monotonically increasing counter Always apply rate() to counters before summing across Pods.
histogram_quantile(0.95, sum by (le, service) (rate(..._bucket[5m]))) Cluster-wide p95 latency per service You MUST preserve le inside sum by (le, ...).
sum(rate(...{status=~"5.."}[5m])) / sum(rate(...[5m])) HTTP 5xx error ratio (0.0 to 1.0) Use matching window intervals on numerator and denominator.

5 Observability Mistakes That Crash Telemetry Stacks

  1. High-cardinality labels in Prometheus/Loki: Putting user_id, ip, or raw URL paths with IDs (/orders/98421) into labels blows up TSDB memory.
  2. Dropping le in histogram_quantile(): Writing sum(rate(..._bucket[5m])) without by (le) destroys histogram bucket boundaries and returns NaN.
  3. Running OTel Collector without memory_limiter: A sudden trace burst OOMKills the Collector and drops telemetry during an active incident.
  4. Evaluating avg() instead of p95/p99 latency: An average of 90ms looks healthy even while 5% of checkouts hang for 6 seconds.
  5. Missing trace_id in application logs: Without MDC/OTel log correlation, you cannot jump from a slow Tempo trace straight to the exact Spring Boot stack trace in Loki.

Prometheus Recording Rules & Tail-Based Sampling
Pre-compute expensive multi-window SLI ratios using PrometheusRule recording rules (e.g., slo:http_errors:ratio_rate5m) so dashboards and Lesson 0020 burn-rate alerts evaluate instantaneously. At high trace volume, configure OTel Collector tail_sampling to retain 100% of error/slow traces while sampling 5% of fast 200 OK traffic.
