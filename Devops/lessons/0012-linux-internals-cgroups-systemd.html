1. Mental Model Bridge: Android App Sandboxing to Linux Kernel Primitives

Start Here

Every Android app runs under a dedicated Linux UID with memory limits enforced by Android's lmkd (Low Memory Killer Daemon). Server containers and systemd services use the exact same Linux kernel machinery: namespaces isolate visibility, cgroups v2 cap resources, and systemd manages lifecycle supervision.

Android Concept Linux Kernel / systemd Equivalent Why Senior DevOps Engineers Care
App UID + isolated /data/data view Namespaces (pid, net, mnt, uts, user) Containers share the host kernel; namespaces make a Spring process think it has its own PID 1, IP, and rootfs.
Android lmkd killing heavy background apps cgroups v2 (memory.max, cpu.max) + OOM Killer If JVM heap + metaspace + native threads exceed memory.max, kernel sends SIGKILL → exit code 137 (128 + 9).
ForegroundService / WorkManager restart policy systemd Unit (Restart=on-failure, MemoryMax) Supervises host daemons (Caddy, Node Exporter, containerd, bare-metal JVMs) with structured journalctl logs.
StrictThread / JankStats frame drops /sys/fs/cgroup/.../cpu.stat (nr_throttled) Tight Kubernetes/cgroup CPU limits throttle JVM GC threads during bursts, spiking p99 HTTP latency.
Why Java Containers Hit Exit Code 137 Even With -Xmx
A 512Mi container limit includes JVM heap (-Xmx) plus Metaspace, thread stacks, code cache, and Netty/NIO direct buffers. Setting -XX:MaxRAMPercentage=75.0 leaves headroom for off-heap memory so the Linux OOM killer never sends SIGKILL (signal 9).

5 Kernel & systemd Mistakes That Cause Silent Production Outages

  1. Setting -Xmx equal to container memory.max: Off-heap Metaspace pushes total RSS past the limit and triggers exit 137.
  2. Running systemd services as root without NoNewPrivileges=yes: Expands the blast radius of any RCE vulnerability.
  3. Setting ultra-low CPU limits without watching cpu.stat: Multi-threaded JVM GC pauses suffer severe cgroup throttling.
  4. Using TimeoutStopSec=5s for heavy APIs: systemd escalates from SIGTERM to SIGKILL before in-flight checkouts drain.
  5. Ignoring journalctl and df -h during incidents: Full root/overlay disks silently stall container starts and database writes.

Extended Kernel Triage: strace, lsof & LimitNOFILE
Keep three more tools ready for deep incidents: lsof -p <pid> (inspect leaked sockets/files), iostat -xz 1 (disk I/O saturation), and strace -f -p <pid> (trace stuck syscalls). For high-concurrency Spring Boot services under systemd, raise file descriptor caps with LimitNOFILE=65536.
