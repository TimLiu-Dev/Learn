1. Mental Model Bridge: Running Builds on Clean Ephemeral VMs

Start Here

Unlike your laptop, a GitHub Actions runner starts fresh on every job and vanishes afterward. To stay fast and secure, workflows restore caches explicitly, pass outputs between jobs via artifacts, lock down GITHUB_TOKEN permissions, and authenticate to AWS/GCP via short-lived OpenID Connect (OIDC) tokens instead of long-lived static secrets.

Local Developer Action GitHub Actions Equivalent Why It Matters
Running ./gradlew test before committing on: [pull_request] + concurrency: cancel-in-progress Cancels stale PR runs on new pushes and keeps broken code out of main.
Warm ~/.gradle/caches on SSD gradle/actions/setup-gradle (pinned SHA) Cuts CI build times by 50–70% without polluting the runner across repos.
Storing AWS/GCP JSON keys in ~/.aws permissions: id-token: write + OIDC role trust Zero long-lived cloud keys to rotate or leak; tokens expire in minutes and scope to one repo/branch.
Confirming "yes, deploy to prod" in Slack environment: production with required reviewers Blocks production jobs until approved and restricts production secrets to protected branches.
Security Rule #1: Pin Actions to Full 40-Character Commit SHAs
Mutable tags like @v4 can be force-pushed if an upstream maintainer's account is compromised. Always pin third-party actions to an immutable 40-hex commit SHA (e.g., actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683 # v4.2.2).

5 GitHub Actions Mistakes That Leak Secrets or Waste Minutes

  1. Running untrusted PR code under pull_request_target: Checks out PR code with base-branch secret access—a classic RCE/secret-exfil vector.
  2. Interpolating ${{ github.event.pull_request.title }} directly in run:: Allows shell injection via crafted PR titles; pass via env: instead.
  3. Leaving default write-all token permissions: Always declare explicit top-level permissions: contents: read.
  4. Using static long-lived cloud keys: OIDC eliminates permanent AWS/GCP keys and binds roles strictly to branch/environment claims.
  5. Skipping concurrency groups on PRs: Pushing 5 quick fixes runs 5 overlapping Gradle builds, wasting runner minutes.
