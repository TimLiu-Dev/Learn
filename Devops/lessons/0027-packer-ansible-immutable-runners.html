1. Mental Model Bridge: Android Studio SDK Setup to Golden Images

Start Here

Installing JDK 21, Android SDK Build-Tools 35, NDK, and Docker manually over SSH creates fragile "snowflake" servers. Packer bakes those dependencies into an immutable Golden Image (just like a Dockerfile builds an immutable container image), while Ansible provides idempotent OS configuration and CIS hardening.

Android / Docker World VM & Runner Automation Production Guarantee
Dockerfile → immutable container image Packer HCL → Golden AMI / VM snapshot New CI runners boot in seconds with pre-warmed Gradle/SDK caches and zero runtime apt-get flakes.
Declarative Ansible / setup steps Ansible Playbooks (idempotent tasks) Re-running a playbook converges host state cleanly without breaking already-configured files.
Persistent build machine accumulating clutter Ephemeral Self-Hosted Runners Each CI job gets a fresh VM/Pod that destroys on exit—preventing cross-PR secret or cache poisoning.
Security Warning: Ephemeral Self-Hosted Runners Only
Never attach persistent self-hosted GitHub Actions runners to public repositories: a malicious fork PR can persist malware on the runner's disk and steal subsequent builds' secrets. Always use ephemeral single-use runners.

5 Runner & Configuration Management Mistakes

  1. Mutating live servers by hand: SSH hotfixes vanish when auto-scaling replaces an instance.
  2. Non-idempotent Ansible shell: tasks: Running raw bash without creates: or native modules breaks on second run.
  3. Reusing persistent CI runners across untrusted PRs: Leaves residual signing keys or poisoned Gradle caches on disk.
  4. Skipping --check --diff in CI: Applying Ansible directly without dry-run previews causes unexpected service restarts.
  5. Running Android emulators without KVM nested virtualization: Software-rendered ARM/x86 emulators time out CI jobs after 30+ minutes.
