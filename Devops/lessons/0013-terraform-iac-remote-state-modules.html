1. Mental Model Bridge: Gradle Build Graphs to Declarative IaC

Start Here

Terraform and OpenTofu work like a compiler for cloud infrastructure. You declare the desired end state in HCL; Terraform builds a dependency graph (DAG), compares your code against the recorded state file, and outputs an exact diff (plan) before changing any cloud resource.

Android / Gradle World Terraform / OpenTofu Equivalent Why It Matters at Senior Scale
build.gradle.kts declarative dependencies HCL resource & module blocks Resources resolve dependencies automatically (e.g., subnet waits for VPC ID without manual ordering).
gradle.lockfile checksum pinning .terraform.lock.hcl + required_providers Guarantees every CI runner downloads the exact verified provider binary SHA256 checksums.
:core:network shared Gradle module Versioned Terraform modules (dev / prod) Avoids copy-pasting 500 lines of VPC/EKS HCL across environments; changes roll out cleanly via inputs.
Encrypted Play signing state Remote backend (S3 encrypt = true + locking) Prevents two engineers from corrupting state simultaneously and keeps plaintext secrets out of Git.
PR lint + unit tests before merge plan on PR + OIDC apply after approval Reviewers inspect exact + add / ~ change / - destroy diffs before production is touched.

5 IaC Mistakes That Destroy Production Infrastructure

  1. Committing terraform.tfstate to Git: Leaks plaintext DB passwords/keys and causes teammates to overwrite each other's changes.
  2. Disabling state locking: Two simultaneous CI runs applying at once corrupt resource mappings.
  3. Running terraform apply -auto-approve on pull requests: Lets unreviewed forks or WIP commits mutate production.
  4. Ignoring - destroy lines in terraform plan: Renaming an RDS or subnet resource triggers destroy-and-recreate unless handled with moved {} blocks.
  5. ClickOps drift in the cloud console: Manual console edits silently diverge from Git until the next apply overwrites them.
