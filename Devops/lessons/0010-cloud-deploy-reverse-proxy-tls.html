1. Mental Model Bridge: Android Network Security to Edge Proxies

Start Here

In production, Spring Boot should bind to a private port (127.0.0.1:8080 or an internal Docker/VPC network) while an edge reverse proxy owns public ports 80 and 443, TLS certificates, HTTP/2, and upstream health checks.

Android / App World Cloud / Edge Infrastructure Why It Matters in Production
usesCleartextTraffic="false" Caddy automatic HTTPS (ACME / Let's Encrypt) Redirects HTTP → HTTPS automatically, rotates TLS 1.3 certificates before expiry, and shields Java from raw internet floods.
Retrofit base URL https://api.example.com dig +short DNS A/AAAA + openssl s_client Verifies DNS propagation and certificate SAN/expiry before pointing mobile clients at a new cloud host.

Don't Forget server.forward-headers-strategy=framework
Because Caddy/Nginx terminates TLS and speaks plain HTTP to Spring Boot locally, Spring needs server.forward-headers-strategy=framework (plus trusted X-Forwarded-Proto) so OAuth2 callbacks and pagination links emit https:// instead of http://.

5 Cloud Deployment Mistakes That Cause Outages

  1. Exposing Spring Boot port 8080 directly on 0.0.0.0: Bypasses your TLS proxy and rate limits.
  2. Opening PostgreSQL port 5432 to 0.0.0.0/0: Automated scanners probe public DB ports within minutes.
  3. Missing X-Forwarded-Proto handling: Causes infinite OAuth2 redirect loops between HTTPS client and HTTP backend.
  4. Cutting over traffic before /actuator/health/readiness passes: Sends live users to a JVM still running Flyway migrations.
  5. Skipping firewall rules (allowing only 80/443 + SSH/SSM): Leaves internal metrics or admin ports reachable externally.

Host SSH & Firewall Hardening on Cloud VMs
Before exposing a single cloud VM, disable SSH password logins (PasswordAuthentication no), restrict inbound ports strictly to 80/443 (allow SSH only via VPN/SSM/Tailscale), and manage the app/proxy lifecycle under systemd or Docker restart: unless-stopped.
