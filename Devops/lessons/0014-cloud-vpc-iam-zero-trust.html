1. Mental Model Bridge: App Security to Zero-Trust Cloud

Start Here

On Android and Spring Boot, you already practice isolation and scoped credentials: Android apps run in per-UID sandboxes with explicit runtime permissions, and Spring Security verifies short-lived JWTs rather than trusting any request inside the LAN. In cloud infrastructure, the same zero-trust rules govern VPCs, IAM roles, KMS keys, and CI/CD pipelines.

Android / Spring World Cloud Networking & IAM Equivalent Why It Matters in Production
Android network_security_config + TLS VPC public vs private subnets + Security Groups Only load balancers sit in public subnets; Spring Boot pods and RDS Postgres stay unreachable from the public internet.
Short-lived OAuth2 / Firebase Auth tokens GitHub Actions OIDC Federation + IAM Roles Eliminates static AWS_ACCESS_KEY_ID secrets; CI exchanges a signed OIDC JWT for 15-minute scoped credentials.
Android Keystore hardware-backed keys Cloud KMS Envelope Encryption (DEK + KEK) Data keys encrypt RDS disks and Secrets Manager values locally while the root key never leaves KMS hardware.
Android permission model (camera only, not contacts) Least-privilege IAM policy (Action + Resource + Condition) A compromised container or CI job can only push to one ECR repo or read one secret—never delete the whole account.
adb over authenticated USB/TLS vs open telnet Bastionless SSM Session Manager / GCP IAP Removes public port 22 SSH bastions entirely; every shell session is IAM-authenticated and audit-logged.
CIDR & Private Routing in One Sentence
A /16 VPC (e.g., 10.0.0.0/16 = 65,536 IPs) splits across Availability Zones into small /24 public subnets (ALB + NAT Gateway) and large private subnets (EKS nodes, Spring Boot, Postgres) whose outbound pulls route through NAT or VPC Endpoints without exposing inbound public IPs.

5. Primary Sources, Pitfalls & Next Steps

Knowledge & Retention
Recommended Primary Source to Read
Read GitHub Actions: Security Hardening Your Deployments (OIDC) together with HashiCorp Terraform Kubernetes & VPC Tutorials. The OIDC specification explains exact sub claim patterns so a feature branch PR can never assume your production deployment role.

5 Cloud Security & Networking Mistakes to Avoid

  1. Overlapping VPC CIDRs: Giving staging and prod both 10.0.0.0/16 breaks VPC peering and Transit Gateway routing later.
  2. Omitting OIDC sub conditions: Trusting token.actions.githubusercontent.com without scoping to your org, repo, and main branch lets any GitHub repo assume your role.
  3. Pulling ECR/S3 images over NAT Gateways: Without Gateway/Interface VPC Endpoints, container image pulls incur per-GB NAT data processing charges.
  4. Exposing port 22 SSH bastions to 0.0.0.0/0: Replace static SSH keys and public bastions with IAM-authenticated SSM Session Manager or GCP IAP.
  5. Allowing IMDSv1 on worker nodes: Require IMDSv2 session tokens (http_tokens = "required") so SSRF bugs cannot steal node IAM credentials.

EKS Pod Identity & KMS Key Policy Boundaries
For AWS EKS workloads in 2026–2027, evaluate AWS EKS Pod Identity alongside traditional IRSA—it eliminates per-cluster OIDC provider boilerplate across multi-cluster platforms. Always pair KMS CMKs with explicit key policies restricting kms:Decrypt to the specific workload role.
