If you have shipped Android apps with Gradle and Play Console, you already understand artifact immutability, build caching, and environment separation. Spring Boot DevOps applies the exact same discipline to server containers.

Testcontainers in GitHub Actions Without DinD Hacks

5 Mistakes That Break Real Spring Boot CI/CD Pipelines

  1. Testing against H2 in-memory mode: PostgreSQL JSONB, Flyway syntax, and locking bugs pass H2 and crash in production.
  2. Deploying :latest tags: Rolling back or auditing which commit is running becomes guesswork.
  3. Baking application-prod.yml secrets into the JAR: Anyone with registry pull access can extract database credentials.
  4. Omitting server.shutdown=graceful: Container replacements return HTTP 502 errors to mobile clients mid-request.
  5. Using static long-lived registry PATs instead of OIDC/GITHUB_TOKEN: Leaked tokens stay valid until manually rotated.

In self-hosted DinD/Kubernetes runners where /var/run/docker.sock isn't local, set TESTCONTAINERS_HOST_OVERRIDE or run rootless DinD sidecars. For faster Spring Boot image rebuilds and cold starts, leverage Spring Boot layered JARs (spring-boot-jarmode-tools) and AppCDS.
