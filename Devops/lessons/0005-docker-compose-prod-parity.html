1. Mental Model Bridge: "Works on My Laptop" to Production Parity

Start Here

Just as Android developers avoid testing Room migrations only on emulators with wiped state, Spring Boot engineers should avoid developing against H2 when production runs PostgreSQL. Docker Compose wires your API, database, cache, and reverse proxy together on private virtual DNS networks—using the exact same Postgres engine and Flyway SQL scripts you ship to production.

Local Dev Shortcut Docker Compose Production Parity Bug It Eliminates
Spring Boot H2 in-memory DB postgres:16.4-alpine + named volume pgdata PostgreSQL-specific SQL dialect, JSONB, and locking failures in prod.
localhost:5432 in application.yml Compose service DNS (jdbc:postgresql://db:5432/app) Connection refused because localhost inside a container points to itself.
Manual "start DB, wait 5s, start API" healthcheck + condition: service_healthy Crash-looping Spring Boot containers racing ahead of Postgres initialization.
Exposing DB ports to host 0.0.0.0 Private backend bridge network (no public DB ports:) Database exposure to untrusted LAN or internet scanners.
Service DNS Inside a Compose Network
Every service on the same Compose network is reachable by its service key name. If your database service is named db, Spring Boot connects via SPRING_DATASOURCE_URL=jdbc:postgresql://db:5432/orders—never localhost.

5. Primary Sources, Pitfalls & Next Steps

Knowledge & Retention
Recommended Primary Source to Read
Read the official Docker Compose Documentation and the Docker Build Guide. Pay special attention to Compose healthcheck, depends_on conditions, and named volume lifecycles.

5 Compose Mistakes That Break Local & Staging Stacks

  1. Using localhost in container DB URLs: Inside the api container, localhost is api itself, not db.
  2. Omitting named volumes on Postgres: Without a persistent volume, docker compose down wipes your entire database.
  3. Using plain depends_on: [db]: Waiting for container start instead of service_healthy triggers PSQLException race errors.
  4. Committing .env secrets to Git: Commit .env.example with placeholders and keep real .env files gitignored.
  5. Using tabs for YAML indentation: YAML strictly forbids tab characters and fails immediately with parse errors.

Docker Port Binding & Host Firewall Warning
Publishing ports: ["5432:5432"] binds 0.0.0.0:5432 and inserts Docker iptables rules that bypass ufw! On cloud VMs, always bind DBs to loopback (127.0.0.1:5432:5432) or omit ports: completely and rely on internal Compose networks.
