1. Mental Model Bridge: Android Studio to Production Linux

Start Here

As an Android developer, you already touch Linux every day: Android runs on a Linux kernel, adb shell opens a POSIX shell, and the Gradle daemon is a background JVM process holding locks and memory. In DevOps, the GUI disappears—you control builds and servers through text streams, POSIX file modes, exit codes, and signals.

Android / Gradle World Linux / DevOps Equivalent Why It Matters in Production
Clicking Build → Generate Signed AAB Non-interactive Bash with set -euo pipefail CI runners have no human watching; silent failures must abort immediately instead of shipping broken artifacts.
release.keystore stored locally chmod 600 + non-root service user World-readable keys (644/777) leak signing credentials; SSH and signing tools refuse loose keys.
Gradle daemon stuck → ./gradlew --stop ps aux / ss -tlnp + kill -15 (SIGTERM) Spring Boot graceful shutdown needs SIGTERM to drain active HTTP requests before exiting.
Android Studio Logcat filter bar grep, jq, sort | uniq -c Production APIs emit thousands of JSON lines per minute; shell pipelines isolate failing endpoints in seconds.
App crash / ANR Exit codes (0 = ok, 1–255 = fail) + stderr CI jobs and container orchestrators decide pass/fail strictly from process exit codes.
Streams & Exit Codes in One Sentence
Every Linux process reads from stdin (fd 0), writes normal output to stdout (fd 1), writes diagnostics to stderr (fd 2), and returns an integer exit code in $? (0 for success, non-zero for failure). See the GNU Bash Manual on Quoting & Pipelines.

Octal Permission Math (chmod(1))

Three octal digits represent Owner, Group, and Others. Each digit sums Read = 4, Write = 2, Execute = 1. Keep the Reference Cheat Sheet handy when hardening CI runners.

Octal Symbolic Typical DevOps Use Case
600 -rw------- Signing keystores (release.keystore), SSH private keys (id_ed25519), .env secrets
644 -rw-r--r-- Config files, JAR artifacts (app.jar), static web assets
755 -rwxr-xr-x Executable scripts (gradlew, deploy.sh) and directories
777 -rwxrwxrwx Never use in production. Lets any local user/process overwrite or execute your files.

5. Primary Sources, Pitfalls & Next Steps

Knowledge & Retention
Recommended Primary Source to Read
Read the GNU Bash Reference Manual — The Set Builtin & Quoting alongside signal(7) on man7.org. Primary manuals beat blog posts because they document edge cases (like grep returning exit code 1 when zero lines match under set -e).

5 Mistakes That Break Real Production & CI Systems

  1. Omitting set -euo pipefail: Step 2 fails, Bash keeps going, and CI reports a broken release as green.
  2. Unquoted variables ($DIR): Works locally until a directory or Git branch name contains spaces.
  3. Running chmod 777: Exposes secrets and causes OpenSSH / container security scanners to reject files.
  4. Defaulting to kill -9: Drops in-flight Spring Boot HTTP requests (502s) instead of draining cleanly via SIGTERM.
  5. Ignoring grep exit code 1: Finding zero matches exits 1, which aborts a set -e script unless handled (|| true).
