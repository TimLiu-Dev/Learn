AsyncStream & Bridging Legacy Asynchronous APIs

Bridging delegate callbacks, notification center observers, and WebSocket frames into AsyncSequence with backpressure policies.

← Master Curriculum & Systems Legend • 📖 Swift Concurrency Cheatsheet • 📚 Systems Glossary

🧠 The Senior Android Anchor: Systems Comparison

In Kotlin, bridging callback APIs into reactive streams uses callbackFlow { ... } with trySend() and awaitClose { ... }.

In Swift, the equivalent is AsyncStream (and AsyncThrowingStream). It adapts delegate protocols, NotificationCenter, and streaming data into modern AsyncSequence pipelines that support for await item in stream with explicit backpressure buffering.

⚡ Low-Level Core: How Swift Works Under the Hood

1. The AsyncStream Continuation Anatomy

func trackLocationUpdates() -> AsyncStream<CLLocation> {
    AsyncStream(bufferingPolicy: .bufferingNewest(10)) { continuation in
        let listener = LocationListener { location in
            continuation.yield(location) // Emit new item
        }
        continuation.onTermination = { @Sendable termination in
            listener.stopListening() // Cleanup on cancel or break
        }
        listener.startListening()
    }
}

2. Backpressure Buffering Strategies

  • .unbounded: Unbounded buffer. Memory risk if consumer is slow.
  • .bufferingNewest(limit): Drops oldest items when buffer is full. Ideal for real-time sensor and location streams.
  • .bufferingOldest(limit): Discards incoming items until buffer drains.
⚠️ Senior Failure Mode & Anti-Pattern:

Omitting continuation.onTermination: If the consumer breaks from a for await loop or the task cancels, failure to clean up resources in onTermination causes permanent delegate and memory leaks.

import Foundation

final class LegacySensorEmitter {
    private var callback: ((Int) -> Void)?
    private(set) var isRunning: Bool = false

    func start(onData: @escaping (Int) -> Void) {
        self.callback = onData
        self.isRunning = true
    }

    func emit(value: Int) {
        callback?(value)
    }

    func stop() {
        self.isRunning = false
        self.callback = nil
    }
}

func makeEventStream(emitter: LegacySensorEmitter) -> AsyncStream {
    AsyncStream(bufferingPolicy: .bufferingNewest(5)) { continuation in
        emitter.start { value in
            continuation.yield(value)
        }
        continuation.onTermination = { @Sendable _ in
            emitter.stop()
        }
    }
}

func runTests() async {
    print("🧪 Running Lesson 2.3 Verification Tests...")
    let emitter = LegacySensorEmitter()
    var collected: [Int] = []

    let task = Task {
        let stream = makeEventStream(emitter: emitter)
        for await val in stream {
            collected.append(val)
            if collected.count == 2 { break }
        }
    }

    try? await Task.sleep(nanoseconds: 5_000_000)
    emitter.emit(value: 101)
    emitter.emit(value: 102)

    _ = await task.value
    task.cancel()
    try? await Task.sleep(nanoseconds: 10_000_000)

    assert(collected == [101, 102])
    assert(emitter.isRunning == false)
    print("  ✅ All tests passed!")
}

await runTests()
Senior Engineering Walkthrough:

AsyncStream acts as an adapter between callback-driven APIs and modern async/await loops. Using continuation.yield emits data onto the consumer task, while onTermination ensures tear-down when the consuming loop breaks.
