XCFrameworks, Library Evolution & Mergeable Libraries

Static vs Dynamic vs Mergeable binaries, BUILD_LIBRARY_FOR_DISTRIBUTION (.swiftinterface), and xcodebuild -create-xcframework.

← Master Curriculum & Systems Legend • 📖 2027 Frontier Cheatsheet • 📚 Systems Glossary

🧠 The Senior Android Anchor: Systems Comparison

In Android, binary SDK distribution ships a single platform-neutral .aar bytecode archive via Maven.

In iOS, native Mach-O binaries are CPU-architecture and platform-slice specific (iOS arm64 device vs arm64/x86_64 simulator). Senior iOS engineers package closed-source or prebuilt modules as XCFramework bundles with Library Evolution enabled, and leverage Mergeable Libraries to get fast Debug incremental builds with zero Release dyld4 launch overhead.

⚡ Low-Level Core: How Swift Works Under the Hood

1. Building an ABI-Stable XCFramework

# 1. Archive with BUILD_LIBRARY_FOR_DISTRIBUTION=YES (generates .swiftinterface!)
xcodebuild archive -scheme PulseSDK -destination "generic/platform=iOS" \
  -archivePath build/ios.xcarchive SKIP_INSTALL=NO BUILD_LIBRARY_FOR_DISTRIBUTION=YES

xcodebuild archive -scheme PulseSDK -destination "generic/platform=iOS Simulator" \
  -archivePath build/sim.xcarchive SKIP_INSTALL=NO BUILD_LIBRARY_FOR_DISTRIBUTION=YES

# 2. Bundle into a single XCFramework
xcodebuild -create-xcframework \
  -framework build/ios.xcarchive/Products/Library/Frameworks/PulseSDK.framework \
  -framework build/sim.xcarchive/Products/Library/Frameworks/PulseSDK.framework \
  -output build/PulseSDK.xcframework

2. Mergeable Libraries (Xcode 15+ / 2027 Standard)

Setting MERGED_BINARY_TYPE = automatic links internal frameworks dynamically in Debug (instant incremental rebuilds) and merges them statically into the main app binary in Release (eliminating dyld4 rebase/bind launch cost).

⚠️ Senior Failure Mode & Anti-Pattern:

Shipping Binary Swift Frameworks Without BUILD_LIBRARY_FOR_DISTRIBUTION=YES: Without Library Evolution, Xcode emits opaque .swiftmodule files tied to the exact compiler version—meaning your SDK breaks the moment a client upgrades Xcode! Always enable Library Evolution and mark public enums @frozen only when binary layout stability is guaranteed.

import Foundation

struct XCFrameworkManifest {
    let slices: Set
    let hasSwiftInterface: Bool
    let sha256Checksum: String
}

enum BinaryPackageValidator {
    static func validate(_ manifest: XCFrameworkManifest, expectedChecksum: String) -> Bool {
        manifest.slices.contains("ios-arm64")
        && manifest.slices.contains("ios-arm64-simulator")
        && manifest.hasSwiftInterface
        && manifest.sha256Checksum == expectedChecksum
    }
}

func runTests() {
    print("🧪 Running Lesson 8.6 Verification Tests...")
    let valid = XCFrameworkManifest(slices: ["ios-arm64", "ios-arm64-simulator"], hasSwiftInterface: true, sha256Checksum: "abc123")
    let missingSim = XCFrameworkManifest(slices: ["ios-arm64"], hasSwiftInterface: true, sha256Checksum: "abc123")
    let noEvolution = XCFrameworkManifest(slices: ["ios-arm64", "ios-arm64-simulator"], hasSwiftInterface: false, sha256Checksum: "abc123")
    assert(BinaryPackageValidator.validate(valid, expectedChecksum: "abc123") == true)
    assert(BinaryPackageValidator.validate(missingSim, expectedChecksum: "abc123") == false)
    assert(BinaryPackageValidator.validate(noEvolution, expectedChecksum: "abc123") == false)
    assert(BinaryPackageValidator.validate(valid, expectedChecksum: "tampered") == false)
    print("  ✅ All tests passed!")
}
runTests()
