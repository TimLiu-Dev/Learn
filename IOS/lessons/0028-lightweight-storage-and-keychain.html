Lightweight Storage & Apple Keychain Services

UserDefaults (@AppStorage) for UI preferences vs Apple Keychain Services (SecItem) for biometric and hardware-encrypted tokens.

← Master Curriculum & Systems Legend • 📖 Persistence Cheatsheet • 📚 Systems Glossary

🧠 The Senior Android Anchor: Systems Comparison

In Android, simple preferences use SharedPreferences or Jetpack DataStore, while secure secrets rely on the Android Keystore system (EncryptedSharedPreferences).

In iOS, UserDefaults (and SwiftUI @AppStorage) stores unencrypted plist data—never store auth tokens or passwords in UserDefaults! Sensitive secrets must be stored in Apple Keychain Services (SecItemAdd, SecItemCopyMatching), which uses AES-256 hardware encryption managed by Darwin's securityd daemon.

⚡ Low-Level Core: How Swift Works Under the Hood

1. UserDefaults vs Keychain Boundaries

  • UserDefaults (@AppStorage): Unencrypted. Backed by a plist file in the sandbox. Survives app updates; deleted on app uninstall. Use only for UI state (e.g. hasSeenOnboarding, preferredTheme).
  • Keychain Services: Encrypted with hardware keys. Backed by SQLite database in securityd outside the app sandbox. Persists even after the app is uninstalled! Use for JWT bearer tokens, refresh tokens, and passwords.

2. Idiomatic Keychain CRUD Operations

import Security

func saveTokenToKeychain(account: String, tokenData: Data) -> OSStatus {
    let query: [String: Any] = [
        kSecClass as String: kSecClassGenericPassword,
        kSecAttrAccount as String: account,
        kSecValueData as String: tokenData,
        kSecAttrAccessible as String: kSecAttrAccessibleAfterFirstUnlock
    ]
    SecItemDelete(query as CFDictionary) // Clean old item
    return SecItemAdd(query as CFDictionary, nil)
}
⚠️ Senior Failure Mode & Anti-Pattern:

Storing Auth Tokens in UserDefaults: Plain-text plists inside UserDefaults are easily extracted from unencrypted device backups or jailbroken devices using basic file inspection tools. Always route sensitive credentials through Keychain Services.

import Foundation

final class MockKeychainVault {
    private var vault: [String: Data] = [:]

    func saveSecret(account: String, secret: String) -> Bool {
        guard let data = secret.data(using: .utf8) else { return false }
        vault[account] = data
        return true
    }

    func retrieveSecret(account: String) -> String? {
        guard let data = vault[account] else { return nil }
        return String(data: data, encoding: .utf8)
    }
}

func runTests() {
    print("🧪 Running Lesson 4.1 Verification Tests...")
    let keychain = MockKeychainVault()
    let saved = keychain.saveSecret(account: "auth_token", secret: "jwt_secret_xyz")
    assert(saved == true)

    let retrieved = keychain.retrieveSecret(account: "auth_token")
    assert(retrieved == "jwt_secret_xyz")

    let missing = keychain.retrieveSecret(account: "unknown")
    assert(missing == nil)
    print("  ✅ All tests passed!")
}
runTests()
Senior Engineering Walkthrough:

Keychain storage operates on raw Data buffers. Converting secrets to utf8 Data and scoping access to specific account identifier keys mirrors Apple's SecItemAdd and SecItemCopyMatching APIs.
