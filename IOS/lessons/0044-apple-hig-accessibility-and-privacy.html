Apple HIG, Accessibility & Privacy Manifests

Human Interface Guidelines compliance, Dynamic Type scaling, VoiceOver accessibility traits, and PrivacyInfo.xcprivacy required reason declarations.

← Master Curriculum & Systems Legend • 📖 Release & Ecosystem Cheatsheet • 📚 Systems Glossary

🧠 The Senior Android Anchor: Systems Comparison

In Android, accessibility relies on content descriptions (contentDescription) and font scaling with sp units, while permissions are declared in AndroidManifest.xml.

In iOS, Apple strictly rejects apps that do not support Dynamic Type font scaling or lack accessible VoiceOver traits. Furthermore, Apple mandates Privacy Manifests (PrivacyInfo.xcprivacy) for all apps and third-party SDK dependencies accessing Required Reason APIs (file timestamps, UserDefaults, system boot time).

2. Privacy Manifests (PrivacyInfo.xcprivacy)

A declarative plist in your app and SPM targets declaring:

  • NSPrivacyTracking: Boolean indicating whether the app tracks across third-party websites.
  • NSPrivacyCollectedDataTypes: Arrays specifying collected data (e.g. Email Address, Device ID) and purposes.
  • NSPrivacyAccessedAPITypes: Required reason API categories and explicit code rationale reasons (e.g. CA92.1 for UserDefaults).
⚠️ Senior Failure Mode & Anti-Pattern:

Missing PrivacyInfo in SPM Packages: If your local or remote SPM package accesses UserDefaults or file modification dates without declaring a signed Privacy Manifest, App Store Connect will reject the binary on upload. Always bundle PrivacyInfo.xcprivacy with required reason codes.

import Foundation

struct PrivacyManifestValidator {
    static func validate(category: String, reasonCode: String) -> Bool {
        if category == "NSPrivacyAccessedAPICategoryUserDefaults" {
            return reasonCode == "CA92.1" || reasonCode == "1C8F.1"
        }
        return false
    }
}

func runTests() {
    print("🧪 Running Lesson 7.1 Verification Tests...")
    let cat = "NSPrivacyAccessedAPICategoryUserDefaults"
    assert(PrivacyManifestValidator.validate(category: cat, reasonCode: "CA92.1") == true)
    assert(PrivacyManifestValidator.validate(category: cat, reasonCode: "1C8F.1") == true)
    assert(PrivacyManifestValidator.validate(category: cat, reasonCode: "INVALID_CODE") == false)
    assert(PrivacyManifestValidator.validate(category: "UnknownCategory", reasonCode: "CA92.1") == false)
    print("  ✅ All tests passed!")
}
runTests()

Privacy manifests require exact Apple-approved reason strings for sensitive system APIs. Validating reason codes against Apple's official privacy taxonomy prevents App Store Connect rejection.
