Test Doubles, Stubs & Async ViewModel Testing

Protocol mocks, in-memory repository fakes, testing async state transitions, and deterministic error paths.

← Master Curriculum & Systems Legend • 📖 Testing & Profiling Cheatsheet • 📚 Systems Glossary

🧠 The Senior Android Anchor: Systems Comparison

In Android, mocking uses Mockk or Mockito, and coroutine testing uses runTest with StandardTestDispatcher and Turbine for Flow assertions.

In iOS, Swift's strong type system and protocol orientation favor Hand-Crafted Protocol Fakes and Stubs over dynamic reflection mocking libraries. You inject a mock conforming to the service protocol, configure its stubbed return values, and assert asynchronous state transitions deterministically.

⚡ Low-Level Core: How Swift Works Under the Hood

1. The Types of Test Doubles

  • Dummy: Passed around but never actually used.
  • Stub: Provides pre-canned answers to calls made during the test.
  • Spy: Records the calls it receives (call count, passed arguments).
  • Mock: Pre-programmed with expectations that form a specification.
  • Fake: Working implementation with a shortcut (e.g. in-memory storage).

2. Testing Async State Transitions

final class MockNetworkService: NetworkServiceProtocol {
    var stubbedResult: Result<[Item], Error> = .success([])
    private(set) var fetchCallCount = 0

    func fetchItems() async throws -> [Item] {
        fetchCallCount += 1
        return try stubbedResult.get()
    }
}
⚠️ Senior Failure Mode & Anti-Pattern:

Testing Implementation Details Instead of Behavior: Asserting that private method X was called 3 times makes tests brittle to refactoring. Assert observable outputs and state transitions (e.g. viewModel.state == .success).

🔑 Reveal Final Reference Solution & Architecture Walkthrough 
import Foundation

enum ViewState: Equatable {
    case idle
    case loading
    case loaded(String)
    case failed
}

protocol NameService: Sendable {
    func fetchName() async throws -> String
}

final class MockNameService: NameService {
    var stubbedResult: Result = .success("TestUser")
    private(set) var callCount = 0

    func fetchName() async throws -> String {
        callCount += 1
        return try stubbedResult.get()
    }
}

final class UserViewModel {
    let service: any NameService
    var state: ViewState = .idle

    init(service: any NameService) {
        self.service = service
    }

    func loadData() async {
        state = .loading
        do {
            let name = try await service.fetchName()
            state = .loaded(name)
        } catch {
            state = .failed
        }
    }
}

func runTests() async {
    print("🧪 Running Lesson 6.2 Verification Tests...")
    let mock = MockNameService()
    let vm = UserViewModel(service: mock)

    await vm.loadData()
    assert(vm.state == .loaded("TestUser"))
    assert(mock.callCount == 1)

    mock.stubbedResult = .failure(NSError(domain: "test", code: -1))
    await vm.loadData()
    assert(vm.state == .failed)
    assert(mock.callCount == 2)
    print("  ✅ All tests passed!")
}

await runTests()
Senior Engineering Walkthrough:

Injecting MockNameService via protocol abstraction allows test code to simulate both success and failure paths deterministically in zero milliseconds without touching real networks.
