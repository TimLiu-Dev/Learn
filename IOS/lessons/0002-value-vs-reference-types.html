Value Types vs. Reference Types & Custom Copy-on-Write (CoW)

Deep dive into memory layouts (size, stride, alignment), stack vs heap allocation, and implementing production-grade Copy-on-Write using isKnownUniquelyReferenced.

← Master Curriculum & Systems Legend • 📖 Swift Syntax Cheatsheet • 📚 Systems Glossary

🧠 The Senior Android Anchor: Systems Comparison

In Android (Kotlin), every class and data class is a reference type allocated on the garbage-collected JVM heap. Passing an object passes a reference pointer; two variables pointing to the same instance share mutable state unless cloned via copy().

In Swift, struct and enum are value types. They are allocated inline on the stack or in CPU registers. When assigned or passed into functions, they have independent identity.

⚡ Low-Level Core: How Swift Works Under the Hood

1. MemoryLayout: Size, Stride & Alignment

Senior iOS engineers understand how the 64-bit compiler packs data into memory:

  • Size: Exact contiguous bytes of payload data.
  • Alignment: Address boundary multiple the type must align with (e.g. 8 bytes for Double/Int on 64-bit).
  • Stride: Distance in bytes between consecutive elements in an array (Size rounded up to Alignment multiple).
struct SensorPacket {
    var timestamp: Double // 8 bytes (align 8)
    var reading: Double   // 8 bytes (align 8)
    var flag: Bool        // 1 byte  (align 1)
}
MemoryLayout<SensorPacket>.size      // 17 bytes
MemoryLayout<SensorPacket>.alignment // 8 bytes
MemoryLayout<SensorPacket>.stride    // 24 bytes (17 rounded up to multiple of 8)

2. Implementing Custom Copy-on-Write (CoW)

Swift collections (Array, Dictionary) are value types backed by heap buffers. To avoid expensive copies on assignment, they share heap buffers until a mutation occurs. If the reference count is greater than 1, a deep copy is made just-in-time:

final class BackendBuffer<T> {
    var value: T
    init(value: T) { self.value = value }
}

struct CoWWrapper<T> {
    private var buffer: BackendBuffer<T>

    init(value: T) { self.buffer = BackendBuffer(value: value) }

    var value: T {
        get { buffer.value }
        set {
            if !isKnownUniquelyReferenced(&buffer) {
                buffer = BackendBuffer(value: newValue) // Diverge!
            } else {
                buffer.value = newValue
            }
        }
    }
}
⚠️ Senior Failure Mode & Anti-Pattern:

Over-allocating Structs (>3 words in Protocols): While structs are stack-allocated, boxing a large struct (>24 bytes) into an existential container (any Protocol) forces Swift to allocate heap memory behind the scenes. Keep structs lightweight or use generics (some Protocol).

import Foundation

final class Storage {
    var payload: T
    init(payload: T) { self.payload = payload }
}

struct CoWStore {
    private var storage: Storage

    init(payload: T) {
        self.storage = Storage(payload: payload)
    }

    var value: T {
        get { storage.payload }
        set {
            if !isKnownUniquelyReferenced(&storage) {
                storage = Storage(payload: newValue)
            } else {
                storage.payload = newValue
            }
        }
    }

    var pointerAddress: UnsafeMutableRawPointer {
        Unmanaged.passUnretained(storage).toOpaque()
    }
}

func runTests() {
    print("🧪 Running Lesson 1.2 Verification Tests...")
    let store1 = CoWStore(payload: "initial_data")
    var store2 = store1
    assert(store1.pointerAddress == store2.pointerAddress)
    store2.value = "modified_data"
    assert(store1.pointerAddress != store2.pointerAddress)
    assert(store1.value == "initial_data")
    assert(store2.value == "modified_data")
    print("  ✅ All tests passed!")
}
runTests()
Senior Engineering Walkthrough:

isKnownUniquelyReferenced checks the strong reference count of the object pointer in O(1) time without locking. When store2 mutates, the buffer was shared (count=2), so store2 cloned its own storage, isolating both structs with zero unwanted side-effects.
