Enums with Associated Values & Algebraic State Modeling

Sum types, recursive enums with indirect, pattern matching with switch and case let, and modeling bulletproof UI state machines.

← Master Curriculum & Systems Legend • 📖 Swift Syntax Cheatsheet • 📚 Systems Glossary

🧠 The Senior Android Anchor: Systems Comparison

In Kotlin, complex state hierarchies are modeled using sealed class or sealed interface with data subclasses (each subclass allocating an object on the JVM heap).

In Swift, enums are first-class algebraic sum types with associated values. They are value types stored inline without separate class allocations. Swift supports recursive enums via the indirect keyword.

⚡ Low-Level Core: How Swift Works Under the Hood

1. Exhaustive Algebraic State Modeling

Avoid boolean flag anti-patterns (isLoading, isError, data all optional). Model states mutually exclusively:

enum ViewState<T: Equatable>: Equatable {
    case idle
    case loading(message: String)
    case success(data: T)
    case failure(reason: String)
}

2. Recursive Enums with indirect

Enums need a fixed size at compile time. A recursive enum (like a binary tree or arithmetic expression) has infinite size unless boxed. The indirect modifier tells the compiler to insert a heap reference pointer (8 bytes) for recursive cases:

indirect enum BinaryTree<T> {
    case leaf(T)
    case node(left: BinaryTree<T>, right: BinaryTree<T>)
}
⚠️ Senior Failure Mode & Anti-Pattern:

Catch-All default: in Feature Switches: Adding default: to a switch statement on an internal enum disables compiler exhaustiveness checks. When a new enum case is added, the compiler will not warn you to handle it, leading to silent unhandled states.

import Foundation

enum AuthState: Equatable {
    case unauthenticated
    case authenticating
    case authenticated(token: String)
    case error(message: String)
}

enum AuthAction {
    case startLogin
    case loginSuccess(token: String)
    case loginFailure(error: String)
    case logout
}

func reduce(state: AuthState, action: AuthAction) -> AuthState {
    switch (state, action) {
    case (.unauthenticated, .startLogin):
        return .authenticating
    case (.authenticating, .loginSuccess(let token)):
        return .authenticated(token: token)
    case (.authenticating, .loginFailure(let err)):
        return .error(message: err)
    case (.authenticated, .logout):
        return .unauthenticated
    default:
        return state
    }
}

func runTests() {
    print("🧪 Running Lesson 1.4 Verification Tests...")
    let s1 = reduce(state: .unauthenticated, action: .startLogin)
    assert(s1 == .authenticating)
    let s2 = reduce(state: s1, action: .loginSuccess(token: "jwt_token_999"))
    assert(s2 == .authenticated(token: "jwt_token_999"))
    let s3 = reduce(state: s2, action: .logout)
    assert(s3 == .unauthenticated)
    print("  ✅ All tests passed!")
}
runTests()
Senior Engineering Walkthrough:

Tuple pattern matching switch (state, action) enables clean 2D state-machine transitions. Invalid actions return current state without side effects, eliminating impossible UI states.
