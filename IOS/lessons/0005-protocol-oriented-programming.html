Protocol-Oriented Programming (POP) & Method Dispatch

Witness Tables (PWT/VWT), Static vs Dynamic Dispatch, Protocol Extension Traps, and Opaque (some) vs Existential (any) Types.

← Master Curriculum & Systems Legend • 📖 Swift Syntax Cheatsheet • 📚 Systems Glossary

🧠 The Senior Android Anchor: Systems Comparison

In Java and Kotlin, polymorphism is class-centric: methods on classes use vtable dispatch (virtual method table), and interfaces require JVM interface table lookup (itable). All interface instances are heap-boxed objects.

Swift favors composition over inheritance. It uses Protocol Witness Tables (PWT) and Value Witness Tables (VWT) to resolve protocol requirements. Furthermore, Swift lets you choose compile-time static specialization (some) or runtime existential boxing (any).

⚡ Low-Level Core: How Swift Works Under the Hood

1. The Method Dispatch Spectrum

  • Static (Direct) Dispatch: The fastest dispatch mechanism. The compiler inlines instructions directly into the caller. Used on structs, enums, final classes, and methods defined only in protocol extensions.
  • Table Dispatch: Pointer lookup through a function table. Used for class inheritance (vtable) and protocol requirements (PWT).
  • Message Send: Dynamic runtime lookup via objc_msgSend. Used for Objective-C dynamic features.

2. The Protocol Extension Dispatch Trap (Senior Interview Classic)

protocol Worker {
    func execute() // Declared in protocol header -> PWT dispatch (Dynamic/Polymorphic)
}
extension Worker {
    func execute() { print("Default execute") }
    func inspect() { print("Default inspect") } // NOT in header -> Static dispatch!
}
struct LeadDeveloper: Worker {
    func execute() { print("Lead executing") }
    func inspect() { print("Lead inspecting") }
}

let w: Worker = LeadDeveloper()
w.execute() // Outputs: "Lead executing" (Resolved dynamically via PWT)
w.inspect() // Outputs: "Default inspect" (Bound statically to Worker extension!)

3. Opaque Types (some) vs Existential Containers (any)

some Shape: Monomorphic. The concrete type is fixed at compile time. Static dispatch, zero allocation overhead.

any Shape: Existential container. 5-word memory layout (3-word inline buffer + VWT + PWT). If payload > 24 bytes, Swift allocates heap memory.

⚠️ Senior Failure Mode & Anti-Pattern:

Defaulting to 'any' Protocol Everywhere: In Swift 5.7+, using any Service incurs existential container boxing overhead on every call. Prefer some Service or generic constraints <T: Service> for zero-overhead static specialization.

import Foundation

protocol PaymentProcessor {
    func process(amount: Double) -> String
    func refund(amount: Double) -> String
}

extension PaymentProcessor {
    func refund(amount: Double) -> String {
        return "Default refund of $\(amount)"
    }
}

struct StripeProcessor: PaymentProcessor {
    func process(amount: Double) -> String {
        return "Stripe charged $\(amount)"
    }

    func refund(amount: Double) -> String {
        return "Stripe refunded $\(amount)"
    }
}

func testDispatch(processor: any PaymentProcessor) -> String {
    return processor.refund(amount: 50.0)
}

func runTests() {
    print("🧪 Running Lesson 1.5 Verification Tests...")
    let stripe = StripeProcessor()
    let result = testDispatch(processor: stripe)
    assert(result == "Stripe refunded $50.0")
    print("  ✅ All tests passed!")
}
runTests()
Senior Engineering Walkthrough:

Declaring refund in the protocol contract allocates a slot in the Protocol Witness Table. When called via an existential (any PaymentProcessor), the runtime looks up StripeProcessor's custom implementation via PWT instead of defaulting to static extension dispatch.
