Multi-Package SPM Modularization Architecture

Decomposing monolithic Xcode projects into local Swift Package Manager modules: CoreNetwork, CoreDatabase, Features, and DesignSystem.

← Master Curriculum & Systems Legend • 📖 Architecture Cheatsheet • 📚 Systems Glossary

🧠 The Senior Android Anchor: Systems Comparison

In Android, multi-module architectures decompose apps into Gradle subprojects (:core:network, :feature:login) defined in settings.gradle.kts.

In iOS, modern enterprise apps use Swift Package Manager (SPM) to split code into decoupled local packages. SPM eliminates brittle Xcode project file conflicts (.pbxproj merge conflicts) and enables parallel incremental compilation.

⚡ Low-Level Core: How Swift Works Under the Hood

1. The Enterprise SPM Module Graph

App Target (Runner)
    ├── FeatureAuth ──> DesignSystem
    ├── FeatureDashboard ──> DesignSystem
    ├── CoreNetwork (URLSession, Interceptors)
    ├── CoreDatabase (SwiftData, SQLite)
    └── DomainModels (Pure Entities, Protocols)

2. Package.swift Manifest Architecture

// swift-tools-version: 6.0
import PackageDescription

let package = Package(
    name: "CoreModules",
    platforms: [.iOS(.v17)],
    products: [
        .library(name: "CoreNetwork", targets: ["CoreNetwork"]),
        .library(name: "DomainModels", targets: ["DomainModels"])
    ],
    targets: [
        .target(name: "DomainModels"),
        .target(name: "CoreNetwork", dependencies: ["DomainModels"]),
        .testTarget(name: "CoreNetworkTests", dependencies: ["CoreNetwork"])
    ]
)
⚠️ Senior Failure Mode & Anti-Pattern:

Circular Module Dependencies: If CoreNetwork imports DomainModels and DomainModels imports CoreNetwork, the build graph deadlocks and fails to compile. Strict dependency inversion (high-level modules depend on abstractions) prevents circularity.

import Foundation

final class DependencyGraph {
    private var adjList: [String: [String]] = [:]

    func addEdge(from: String, to: String) {
        adjList[from, default: []].append(to)
    }

    func hasCycle() -> Bool {
        var visited: Set = []
        var recStack: Set = []

        func dfs(_ node: String) -> Bool {
            visited.insert(node)
            recStack.insert(node)
            for neighbor in adjList[node, default: []] {
                if !visited.contains(neighbor) {
                    if dfs(neighbor) { return true }
                } else if recStack.contains(neighbor) {
                    return true
                }
            }
            recStack.remove(node)
            return false
        }

        for node in adjList.keys {
            if !visited.contains(node) {
                if dfs(node) { return true }
            }
        }
        return false
    }
}

func runTests() {
    print("🧪 Running Lesson 5.3 Verification Tests...")
    let acyclicGraph = DependencyGraph()
    acyclicGraph.addEdge(from: "App", to: "Features")
    acyclicGraph.addEdge(from: "Features", to: "CoreNetwork")
    acyclicGraph.addEdge(from: "CoreNetwork", to: "Domain")
    assert(acyclicGraph.hasCycle() == false)

    let cyclicGraph = DependencyGraph()
    cyclicGraph.addEdge(from: "ModuleA", to: "ModuleB")
    cyclicGraph.addEdge(from: "ModuleB", to: "ModuleA")
    assert(cyclicGraph.hasCycle() == true)
    print("  ✅ All tests passed!")
}

Senior Engineering Walkthrough:

SPM packages require a strict Directed Acyclic Graph (DAG). Modeling dependency validation with DFS cycle detection ensures modular architecture stays clean and buildable across large engineering teams.
