Swift 6.2/6.3 Approachable Concurrency & Mutex

SE-0461 nonisolated(nonsending), @concurrent opt-in, default @MainActor isolation, and Synchronization.Mutex for synchronous critical sections.

← Master Curriculum & Systems Legend • 📖 2027 Frontier Cheatsheet • 📚 Systems Glossary

🧠 The Senior Android Anchor: Systems Comparison

In Kotlin Coroutines, calling a suspend function stays on the caller's dispatcher until you explicitly call withContext(Dispatchers.IO). In Swift 6.0, calling a nonisolated async function unexpectedly hopped off @MainActor to the global cooperative pool, triggering confusing Sendable errors.

Swift 6.2/6.3 introduces Approachable Concurrency: under SE-0461, nonisolated(nonsending) keeps async helpers on the caller's executor by default, while @concurrent explicitly requests background execution. Meanwhile, Synchronization.Mutex replaces legacy GCD barrier queues and NSLock for fast synchronous locking.

⚡ Low-Level Core: How Swift Works Under the Hood

1. SE-0461: nonisolated(nonsending) vs. @concurrent

// Swift 6.2+ (NonisolatedNonsendingByDefault enabled):
// Runs on caller's actor (e.g., stays on MainActor if called from ViewModel!)
func formatUserSummary(_ user: User) async -> String { ... }

// Explicitly hops to the global concurrent executor for heavy CPU/IO work:
@concurrent
func parseLargeTelemetryBlob(_ data: Data) async -> [Metric] { ... }

2. Synchronization.Mutex vs. Actor

  • When to use actor: You need asynchronous coordination, suspension points (await), or task serialization.
  • When to use Mutex<State>: You need synchronous thread-safe access (e.g., an in-memory cache, OS callback, or metric counter) without await suspension overhead or actor reentrancy!
  • Compiler safety: Unlike NSLock, Mutex owns the protected value inside its closure (withLock { state in ... }) and enforces Sendable conformance automatically.
⚠️ Senior Failure Mode & Anti-Pattern:

Overusing Actors for Synchronous Hot-Path State: Wrapping a tiny counter or LRU cache in an actor forces every caller into an async context and introduces suspension points where actor reentrancy bugs can occur. Use Synchronization.Mutex for synchronous, sub-microsecond critical sections.

import Foundation
import Synchronization

final class ThreadSafeMetrics: Sendable {
    private let storage = Mutex<[String: Int]>([:])

    func recordHit(for endpoint: String) {
        storage.withLock { state in
            state[endpoint, default: 0] += 1
        }
    }

    func count(for endpoint: String) -> Int {
        storage.withLock { state in
            state[endpoint, default: 0]
        }
    }
}

func runTests() async {
    print("🧪 Running Lesson 8.2 Verification Tests...")
    let metrics = ThreadSafeMetrics()
    await withTaskGroup(of: Void.self) { group in
        for _ in 0..<200 {
            group.addTask {
                metrics.recordHit(for: "/v1/feed")
            }
        }
    }
    assert(metrics.count(for: "/v1/feed") == 200)
    assert(metrics.count(for: "/v1/missing") == 0)
    print("  ✅ All tests passed!")
}
await runTests()
Senior Engineering Walkthrough:

Synchronization.Mutex is itself ~Copyable and Sendable, allowing ThreadSafeMetrics to conform to Sendable cleanly while guaranteeing zero data races across 200 concurrent tasks without actor-hopping overhead.
