DocC Documentation, #Preview Workflows & SwiftUI Inspector

Authoring interactive DocC catalogs for SPM/XCFrameworks, fast mocked #Preview macros (@Previewable), and Instruments SwiftUI Inspector profiling.

← Master Curriculum & Systems Legend • 📖 SwiftUI Architecture Cheatsheet • 📚 Systems Glossary

🧠 The Senior Android Anchor: Systems Comparison

In Android, library docs use Dokka, fast UI iteration uses Compose @Preview, and recompositions are counted in Android Studio Layout Inspector.

In iOS, Apple's ecosystem mirrors and extends these with DocC (generating Apple-style docs, tutorials, and symbol graphs right inside Xcode and static websites via swift-docc-plugin), modern #Preview + @Previewable macros, and the SwiftUI Inspector / Instruments SwiftUI template for hunting frame drops and excess view updates.

⚡ Low-Level Core: How Swift Works Under the Hood

1. Interactive Previews Without Booting App Singletons

#Preview("Offline State", traits: .sizeThatFitsLayout) {
    @Previewable @State var filter = "All"
    DashboardView(
        store: .mock(items: [.sampleCritical]),
        filter: $filter
    )
}

Notice @Previewable (Xcode 16+): it lets you declare @State directly inside #Preview without wrapping everything in a disposable helper struct!

2. DocC Documentation Catalogs (.docc)

  • Symbol Links & Callouts: Use double-backticks ``PulseEngine/sync()``, - Parameters:, - Throws:, and > Note: inside /// doc comments.
  • Static Site Publishing: Run swift package generate-documentation --target PulseSDK --transform-for-static-hosting in CI to publish interactive docs for internal SPM modules and XCFrameworks.
  • SwiftUI Inspector & Instruments: Profile View Body counts, Core Animation Commits, and Cause & Effect Graphs in Instruments' SwiftUI track to verify zero redundant body evaluations.
⚠️ Senior Failure Mode & Anti-Pattern:

Letting #Preview Boot Real Network, Keychain, or SQLite Stacks: If your view's default initializer instantiates production URLSession or ModelContainer(for:) on disk, Xcode Previews become sluggish and crash randomly. Inject lightweight in-memory fakes/mocks via protocol or closure dependencies so previews render in <200ms.
