Generics, Associated Types & Type Erasure

Generic specialization, associatedtype, primary associated types, and building type-erasing AnyRepository wrappers.

← Master Curriculum & Systems Legend • 📖 Swift Syntax Cheatsheet • 📚 Systems Glossary

🧠 The Senior Android Anchor: Systems Comparison

In Kotlin/Java, generics suffer from type erasure: at runtime, all generic type parameters (like List<User>) are erased to List<Object>, requiring JVM boxing for primitives.

In Swift, generics are reified and specialized at compile time: when you write Array<Int>, the compiler monomorphizes and generates specialized machine code with direct scalar 64-bit storage and zero runtime boxing overhead!

⚡ Low-Level Core: How Swift Works Under the Hood

1. Protocols with Associated Types (PATs)

protocol Repository<Item> { // Primary associated type syntax (Swift 5.7+)
    associatedtype Item: Identifiable
    func fetch(id: String) -> Item?
    func save(item: Item)
}

2. Type Erasure: Why and How (Senior Interview Favorite)

Historically, protocols with associated types could not be used as standalone types (var repo: Repository threw 'can only be used as a generic constraint'). While Swift 5.7 introduced any Repository<User>, Senior engineers still use manual type erasers (like Combine's AnyPublisher or AnyRepository) to hide concrete implementation classes across SPM module boundaries:

final class AnyRepository<Item: Identifiable>: Repository {
    private let _fetch: (String) -> Item?
    private let _save: (Item) -> Void

    init<R: Repository>(_ repository: R) where R.Item == Item {
        self._fetch = repository.fetch
        self._save = repository.save
    }

    func fetch(id: String) -> Item? { _fetch(id) }
    func save(item: Item) { _save(item) }
}
⚠️ Senior Failure Mode & Anti-Pattern:

Code Bloat via Over-Specialization: Generic specialization generates new machine instructions for each concrete type combination. While blazingly fast, excessive indiscriminate generic specialization across 50+ types can increase application binary size. Balance with opaque types (some).

import Foundation

protocol DataStore {
    associatedtype T
    func retrieve() -> T
}

struct InMemoryDataStore: DataStore {
    let value: T
    func retrieve() -> T { value }
}

final class AnyDataStore: DataStore {
    private let _retrieve: () -> T

    init(_ store: D) where D.T == T {
        self._retrieve = store.retrieve
    }

    func retrieve() -> T {
        _retrieve()
    }
}

func runTests() {
    print("🧪 Running Lesson 1.7 Verification Tests...")
    let concreteStore = InMemoryDataStore(value: "Senior iOS Engineer")
    let erasedStore = AnyDataStore(concreteStore)
    assert(erasedStore.retrieve() == "Senior iOS Engineer")
    print("  ✅ All tests passed!")
}
runTests()
Senior Engineering Walkthrough:

Type erasure wraps the concrete store.retrieve method pointer into an internal closure _retrieve: () -> T. Callers interact exclusively with AnyDataStore, decoupling clients from specific storage implementations.
