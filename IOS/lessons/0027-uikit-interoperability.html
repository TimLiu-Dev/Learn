UIKit Interoperability: Representables & The Coordinator Pattern

UIViewRepresentable, UIViewControllerRepresentable, UIHostingController, and two-way delegate bridges via Coordinators.

← Master Curriculum & Systems Legend • 📖 SwiftUI Architecture Cheatsheet • 📚 Systems Glossary

🧠 The Senior Android Anchor: Systems Comparison

In Android, integrating legacy Android Views (like MapView or CameraX PreviewView) into Jetpack Compose uses AndroidView { context -> ... }.

In iOS, commercial enterprise apps contain millions of lines of UIKit. Senior engineers seamlessly bridge both frameworks using UIViewRepresentable and UIViewControllerRepresentable. The Coordinator pattern serves as the delegate bridge between UIKit target-actions and SwiftUI @Binding states.

⚡ Low-Level Core: How Swift Works Under the Hood

1. The UIViewRepresentable Lifecycle

struct SearchBarRepresentable: UIViewRepresentable {
    @Binding var text: String

    // 1. Create the UIKit instance:
    func makeUIView(context: Context) -> UISearchBar {
        let searchBar = UISearchBar()
        searchBar.delegate = context.coordinator
        return searchBar
    }

    // 2. Push SwiftUI state down to UIKit:
    func updateUIView(_ uiView: UISearchBar, context: Context) {
        uiView.text = text
    }

    // 3. Coordinator bridges UIKit delegate events back up to @Binding:
    func makeCoordinator() -> Coordinator {
        Coordinator(text: $text)
    }

    final class Coordinator: NSObject, UISearchBarDelegate {
        @Binding var text: String
        init(text: Binding<String>) { self._text = text }

        func searchBar(_ searchBar: UISearchBar, textDidChange searchText: String) {
            self.text = searchText // Mutates SwiftUI source of truth!
        }
    }
}

2. Hosting SwiftUI in UIKit (UIHostingController)

To embed SwiftUI into existing UIKit codebases, wrap views in UIHostingController(rootView: MySwiftUIView()).

⚠️ Senior Failure Mode & Anti-Pattern:

Triggering State Updates inside updateUIView(): Modifying SwiftUI @Binding or @State inside updateUIView creates an infinite render cycle (updateUIView -> state change -> view re-render -> updateUIView). State mutations must originate exclusively from user actions in the Coordinator delegate.

import Foundation

final class MockCoordinator {
    var textBinding: String

    init(initialText: String) {
        self.textBinding = initialText
    }

    func textDidChange(newText: String) {
        self.textBinding = newText
    }
}

func runTests() {
    print("🧪 Running Lesson 3.9 Verification Tests...")
    let coordinator = MockCoordinator(initialText: "initial")
    coordinator.textDidChange(newText: "searching swift 6")
    assert(coordinator.textBinding == "searching swift 6")
    print("  ✅ All tests passed!")
}

Senior Engineering Walkthrough:

The Coordinator pattern bridges object-oriented UIKit delegates to declarative SwiftUI state. When UIKit controls trigger delegate callbacks, the Coordinator mutates upstream bindings, keeping both runtimes synchronized.
