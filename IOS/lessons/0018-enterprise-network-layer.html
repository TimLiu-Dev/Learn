🧠 The Senior Android Anchor: Systems Comparison

In Android (OkHttp), request modification and authentication token refreshes are handled by chaining Interceptor classes (Authenticator).

In Swift, we build an Actor-Synchronized Token Engine. When multiple concurrent network requests receive an HTTP 401 Unauthorized, an actor serializes the refresh: exactly one refresh request is sent to the server, and all waiting concurrent requests receive the fresh token without triggering thundering-herd duplicate refresh storms!

⚡ Low-Level Core: How Swift Works Under the Hood

1. The Thundering Herd Problem (Senior System Design)

Imagine 5 concurrent requests hit the network when the access token expires. All 5 receive HTTP 401. If all 5 independently request a new token, the auth server invalidates refresh tokens or rate-limits the user. We must serialize token refreshes using an actor.

2. The Actor-Synchronized Token Refresh Pattern

actor TokenManager {
    private var token: String?
    private var refreshTask: Task<String, Error>?

    func validToken() async throws -> String {
        if let token { return token }

        // If refresh already in progress, await the SAME Task:
        if let refreshTask { return try await refreshTask.value }

        let task = Task { () -> String in
            defer { self.refreshTask = nil }
            let fresh = try await AuthAPI.refreshToken()
            self.token = fresh
            return fresh
        }
        self.refreshTask = task
        return try await task.value
    }
}
⚠️ Senior Failure Mode & Anti-Pattern:

Infinite 401 Retry Loops: If the refresh token itself is expired or revoked, retrying on 401 indefinitely hangs the app in an infinite network loop. Enforce maximum retry counts (e.g. maxRetries = 1) and post an authentication logout notification on failure.

import Foundation

actor AuthTokenActor {
    private var currentToken: String = "expired_token"
    private var activeRefreshTask: Task?
    var refreshExecutionCount = 0

    func fetchToken() async throws -> String {
        if let existing = activeRefreshTask {
            return try await existing.value
        }

        let task = Task {
            try await Task.sleep(nanoseconds: 10_000_000)
            refreshExecutionCount += 1
            return "fresh_token_123"
        }
        activeRefreshTask = task
        defer {
            activeRefreshTask = nil
        }

        let val = try await task.value
        currentToken = val
        return val
    }
}

func runTests() async {
    print("🧪 Running Lesson 2.10 Verification Tests...")
    let auth = AuthTokenActor()
    let tokens = await withTaskGroup(of: String?.self) { group in
        for _ in 0..<5 {
            group.addTask { try? await auth.fetchToken() }
        }
        var res: [String] = []
        for await t in group { if let t { res.append(t) } }
        return res
    }
    assert(tokens.count == 5)
    assert(tokens.allSatisfy { $0 == "fresh_token_123" })
    let count = await auth.refreshExecutionCount
    assert(count == 1)
    print("  ✅ All tests passed!")
}

await runTests()
Senior Engineering Walkthrough:

By holding the in-flight refresh Task in an actor variable before awaiting, all concurrent callers discover the running Task and await its single resolution. Exactly 1 network refresh runs, protecting the auth server from rate limits.
