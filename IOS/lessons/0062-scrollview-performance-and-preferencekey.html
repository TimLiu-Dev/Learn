High-Performance ScrollView, Lazy Containers & PreferenceKey

List vs LazyVStack memory trade-offs, scrollPosition/scrollTargetBehavior, .visualEffect, onScrollGeometryChange, and PreferenceKey upward flow.

🧠 The Senior Android Anchor: Systems Comparison

In Jetpack Compose, LazyColumn recycles/composes visible items and reports scroll position via LazyListState, while child-to-parent layout metadata flows via onGloballyPositioned.

In SwiftUI, Senior engineers know why LazyVStack inside a ScrollView never frees view state like List does, how modern .visualEffect and .onScrollGeometryChange replace expensive GeometryReader hacks for 120fps parallax/headers, and how PreferenceKey propagates child metrics upward safely.

⚡ Low-Level Core: How Swift Works Under the Hood

1. List vs. LazyVStack vs. VStack

  • VStack: Eagerly instantiates all child views at mount. Never use for unbounded feeds!
  • LazyVStack: Defers body evaluation until scrolled near the viewport, but keeps materialized child identities alive in memory as you scroll down.
  • List: Backed by platform cell recycling (UICollectionView); reclaims offscreen memory aggressively for 10,000+ row feeds.

2. Zero-Invalidation Geometry & PreferenceKey

// Modern 120fps scroll effects WITHOUT GeometryReader layout loops:
ScrollView {
    LazyVStack { ... }
}
.scrollPosition(id: $activeID)
.scrollTargetBehavior(.viewAligned)
.onScrollGeometryChange(for: CGFloat.self) { geo in
    geo.contentOffset.y
} action: { _, newOffset in
    headerOpacity = min(1, max(0, newOffset / 120))
}

When a child genuinely must report sizes or anchor frames upward (e.g., equal-width tab bars), implement a PreferenceKey with an associative reduce(value:nextValue:) combiner.

⚠️ Senior Failure Mode & Anti-Pattern:

Creating Infinite Layout Loops with GeometryReader + PreferenceKey: Measuring a child via GeometryReader, writing it into a PreferenceKey, and using that preference to resize the parent causes a feedback cycle if floating-point sizes oscillate by 0.001pt. Always quantize values or prefer .visualEffect and onGeometryChange (iOS 18+).

import Foundation

protocol SimplePreferenceKey {
    associatedtype Value
    static var defaultValue: Value { get }
    static func reduce(value: inout Value, nextValue: () -> Value)
}

enum MaxWidthPreferenceKey: SimplePreferenceKey {
    static let defaultValue: Double = 0.0

    static func reduce(value: inout Double, nextValue: () -> Double) {
        value = max(value, nextValue())
    }
}

enum VisibleWindowCalculator {
    static func visibleRange(totalCount: Int, offsetY: Double, rowHeight: Double, viewportHeight: Double) -> Range {
        guard totalCount > 0, rowHeight > 0, viewportHeight > 0 else { return 0..<0 }
        let clampedOffset = max(0.0, offsetY)
        let first = min(totalCount, Int(floor(clampedOffset / rowHeight)))
        let last = min(totalCount, Int(ceil((clampedOffset + viewportHeight) / rowHeight)))
        return first..
