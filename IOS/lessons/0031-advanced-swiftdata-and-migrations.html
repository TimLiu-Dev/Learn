Advanced SwiftData: VersionedSchema & ModelActor

Schema evolution with VersionedSchema, custom SchemaMigrationPlan stages, and thread-safe background ingestion with ModelActor.

← Master Curriculum & Systems Legend • 📖 Persistence Cheatsheet • 📚 Systems Glossary

🧠 The Senior Android Anchor: Systems Comparison

In Android (Room), database migrations require Migration(from, to) objects executing manual SQL ALTER TABLE statements, with fallback options like fallbackToDestructiveMigration().

In SwiftData, schema evolution is managed via VersionedSchema and SchemaMigrationPlan. You define explicit schema version enums (SchemaV1, SchemaV2) and declare lightweight or custom migration stages. Furthermore, background data ingestion without main-thread blocking uses the @ModelActor macro.

⚡ Low-Level Core: How Swift Works Under the Hood

1. The VersionedSchema Architecture

enum AppSchemaV1: VersionedSchema {
    static var versionIdentifier = Schema.Version(1, 0, 0)
    static var models: [any PersistentModel.Type] { [User.self] }

    @Model
    final class User {
        var id: String
        var fullName: String
    }
}

enum AppSchemaV2: VersionedSchema {
    static var versionIdentifier = Schema.Version(2, 0, 0)
    static var models: [any PersistentModel.Type] { [User.self] }

    @Model
    final class User {
        var id: String
        var firstName: String
        var lastName: String // Split name in V2
    }
}

2. Background Ingestion with @ModelActor

@ModelActor
actor DataIngestionService {
    func ingest(remoteRecords: [RecordDTO]) {
        for dto in remoteRecords {
            let item = Item(from: dto)
            modelContext.insert(item)
        }
        try? modelContext.save()
    }
}
⚠️ Senior Failure Mode & Anti-Pattern:

Destructive Schema Migrations in Production: Deploying an app update with a changed @Model schema without providing a VersionedSchema and migration plan will crash on launch or wipe the user's entire local database! Always version production schemas.

🔑 Reveal Final Reference Solution & Architecture Walkthrough 
import Foundation

struct SchemaVersion: Equatable, Comparable {
    let major: Int
    let minor: Int

    static func < (lhs: SchemaVersion, rhs: SchemaVersion) -> Bool {
        if lhs.major != rhs.major { return lhs.major < rhs.major }
        return lhs.minor < rhs.minor
    }
}

func resolveMigrationStage(current: SchemaVersion, target: SchemaVersion) -> String {
    if current == target { return "NO_OP" }
    if current == SchemaVersion(major: 1, minor: 0) && target == SchemaVersion(major: 2, minor: 0) {
        return "MIGRATE_V1_TO_V2"
    }
    return "UNKNOWN_STAGE"
}

func runTests() {
    print("🧪 Running Lesson 4.4 Verification Tests...")
    let v1 = SchemaVersion(major: 1, minor: 0)
    let v2 = SchemaVersion(major: 2, minor: 0)
    let stage = resolveMigrationStage(current: v1, target: v2)
    assert(stage == "MIGRATE_V1_TO_V2")
    let noop = resolveMigrationStage(current: v2, target: v2)
    assert(noop == "NO_OP")
    print("  ✅ All tests passed!")
}

Senior Engineering Walkthrough:

SchemaMigrationPlan defines a pipeline of MigrationStages (lightweight or custom) connecting VersionedSchema milestones. When opening a SQLite store, SwiftData evaluates the schema version and executes registered migration stages in order.
