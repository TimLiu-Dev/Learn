Enterprise Clean Architecture & Unidirectional Data Flow (UDF)

Separation of concerns: Views, ViewModels with @Observable, Use Cases/Interactors, and pure Reducer state machines.

← Master Curriculum & Systems Legend • 📖 Architecture Cheatsheet • 📚 Systems Glossary

🧠 The Senior Android Anchor: Systems Comparison

In Android, standard architecture follows Google's Recommended Architecture: UI Layer (Compose + ViewModel + StateFlow) -> Domain Layer (UseCases) -> Data Layer (Repositories + DataSources).

In iOS, Senior engineers build Clean Architecture with Unidirectional Data Flow (UDF). Views emit Actions -> Reducer/ViewModel computes pure next State -> View renders new State. Use Cases isolate domain business rules, keeping ViewModels free of raw networking or database calls.

⚡ Low-Level Core: How Swift Works Under the Hood

1. The Unidirectional Data Flow Cycle

State flows down; actions flow up. ViewModels cannot mutate state arbitrarily outside action handlers:

struct AppState: Equatable {
    var count: Int = 0
    var isLoading: Bool = false
}

enum AppAction {
    case increment
    case decrement
    case setLoading(Bool)
}

func appReducer(state: inout AppState, action: AppAction) {
    switch action {
    case .increment:
        state.count += 1
    case .decrement:
        state.count -= 1
    case .setLoading(let loading):
        state.isLoading = loading
    }
}

2. Use Cases / Interactors

A Use Case encapsulates a single business transaction (e.g. AuthenticateUserUseCase, FetchMetricsUseCase). ViewModels depend on Use Cases, never on raw database models or network endpoints.

⚠️ Senior Failure Mode & Anti-Pattern:

Massive View Controller / Massive ViewModel: Cramming network requests, Core Data contexts, notification observers, and formatting logic into a single ViewModel makes unit testing impossible. Decompose responsibilities into Domain Use Cases.

import Foundation

struct CartItem: Equatable {
    let id: String
    let price: Double
}

struct CartState: Equatable {
    var items: [CartItem] = []
    var totalPrice: Double {
        items.reduce(0) { $0 + $1.price }
    }
}

enum CartAction {
    case addItem(CartItem)
    case clearCart
}

func cartReducer(state: inout CartState, action: CartAction) {
    switch action {
    case .addItem(let item):
        state.items.append(item)
    case .clearCart:
        state.items.removeAll()
    }
}

func runTests() {
    print("🧪 Running Lesson 5.1 Verification Tests...")
    var state = CartState()
    cartReducer(state: &state, action: .addItem(CartItem(id: "c1", price: 25.0)))
    cartReducer(state: &state, action: .addItem(CartItem(id: "c2", price: 15.0)))
    assert(state.items.count == 2)
    assert(state.totalPrice == 40.0)

    cartReducer(state: &state, action: .clearCart)
    assert(state.items.isEmpty)
    assert(state.totalPrice == 0.0)
    print("  ✅ All tests passed!")
}
runTests()
Senior Engineering Walkthrough:

Pure reducers take inout state and an action, mutating state deterministically. Because reducers have no side-effects or asynchronous dependencies, they can be unit-tested instantaneously with 100% coverage.
