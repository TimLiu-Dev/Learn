The Composable Architecture (TCA) vs. @Observable UDF

Point-Free's @Reducer, @ObservableState, Effect cancellation, DependencyKey, TestStore exhaustive assertions, and senior architecture trade-offs.

← Master Curriculum & Systems Legend • 📖 2027 Frontier Cheatsheet • 📚 Systems Glossary

🧠 The Senior Android Anchor: Systems Comparison

In Android, teams debate Jetpack ViewModel + StateFlow (MVVM) vs. structured MVI frameworks (Orbit, Slack Circuit, Mavericks).

In iOS, Senior technical interviews almost always test the trade-off between lightweight @Observable MVVM/UDF and Point-Free's The Composable Architecture (TCA)—especially how TCA models side effects as values (Effect), tree-based navigation (@Presents), and exhaustive async testing (TestStore).

⚡ Low-Level Core: How Swift Works Under the Hood

1. Anatomy of a Modern TCA Feature

// Point-Free TCA (ComposableArchitecture)
@Reducer
struct FeedFeature {
    @ObservableState
    struct State: Equatable {
        var items: [String] = []
        var isLoading = false
    }
    enum Action { case refreshTapped, feedLoaded([String]) }
    @Dependency(\.feedClient) var feedClient

    var body: some ReducerOf<Self> {
        Reduce { state, action in
            switch action {
            case .refreshTapped:
                state.isLoading = true
                return .run { send in
                    let items = try await feedClient.fetch()
                    await send(.feedLoaded(items))
                }.cancellable(id: CancelID.refresh, cancelInFlight: true)
            case .feedLoaded(let items):
                state.isLoading = false
                state.items = items
                return .none
            }
        }
    }
}

2. Senior Trade-Off Matrix: @Observable MVVM vs. TCA

  • Choose @Observable UDF when: You want zero third-party macro coupling, fast Xcode compile times, and straightforward ViewModel unit tests.
  • Choose TCA when: You need deterministic parent-child composition, built-in effect cancellation, and TestStore guarantees that every emitted action and state mutation is explicitly asserted.
⚠️ Senior Failure Mode & Anti-Pattern:

Mutating State Inside Async Effects or Skipping Exhaustivity: In TCA, mutating state outside the synchronous Reduce closure causes race bugs—effects must send actions back to the reducer. Equally, adopting TCA without enforcing TestStore exhaustive assertions pays all the boilerplate cost with none of the correctness guarantees.

import Foundation

struct CounterState: Equatable {
    var count: Int = 0
    var isSyncing: Bool = false
}

enum CounterAction: Equatable {
    case increment
    case syncRequested
    case syncCompleted(Int)
}

enum MiniEffect {
    case none
    case emit(CounterAction)
}

func reduce(state: inout CounterState, action: CounterAction) -> MiniEffect {
    switch action {
    case .increment:
        state.count += 1
        return .none
    case .syncRequested:
        state.isSyncing = true
        return .emit(.syncCompleted(state.count))
    case .syncCompleted(let serverVal):
        state.isSyncing = false
        state.count = serverVal
        return .none
    }
}

final class MiniTestStore {
    private(set) var state: CounterState
    private var pendingActions: [CounterAction] = []

    init(initialState: CounterState) { self.state = initialState }

    func send(_ action: CounterAction, assertState: (inout CounterState) -> Void) {
        var expected = state
        assertState(&expected)
        let effect = reduce(state: &state, action: action)
        assert(state == expected, "State mismatch")
        if case .emit(let next) = effect {
            pendingActions.append(next)
        }
    }

    func receive(_ expectedAction: CounterAction, assertState: (inout CounterState) -> Void) {
        assert(!pendingActions.isEmpty, "No pending action to receive")
        let actual = pendingActions.removeFirst()
        assert(actual == expectedAction, "Action mismatch")
        var expected = state
        assertState(&expected)
        let effect = reduce(state: &state, action: actual)
        assert(state == expected, "State mismatch after receive")
        if case .emit(let next) = effect {
            pendingActions.append(next)
        }
    }

    func finish() {
        assert(pendingActions.isEmpty, "Exhaustivity failure")
    }
}

func runTests() {
    print("🧪 Running Lesson 8.4 Verification Tests...")
    let store = MiniTestStore(initialState: CounterState())
    store.send(.increment) { $0.count = 1 }
    store.send(.syncRequested) { $0.isSyncing = true }
    store.receive(.syncCompleted(1)) { $0.isSyncing = false; $0.count = 1 }
    store.finish()
    print("  ✅ All tests passed!")
}
runTests()
Senior Engineering Walkthrough:

This mirrors TCA's core invariant: state mutations happen exclusively in the pure reducer, side effects return as values, and MiniTestStore enforces exhaustive assertions on every state delta and emitted action.
