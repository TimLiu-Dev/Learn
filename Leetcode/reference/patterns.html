Arrays & Hashing High

Lesson: Session 1

Signals

  • Pair or complement lookup, duplicate detection
  • Counting, frequencies, anagrams
  • Grouping items by a shared key

Template

val indexOf = HashMap<Int, Int>()   // seen-before map
for ((i, x) in nums.withIndex()) {
    indexOf[target - x]?.let { j -> /* found pair (j, i) */ }
    indexOf[x] = i                     // record after checking
}
val freq = IntArray(26); for (c in s) freq[c - 'a']++                         // counts
val groups = HashMap<String, MutableList<String>>()
for (w in words) groups.getOrPut(keyOf(w)) { mutableListOf() }.add(w)      // grouping

Complexity

O(n) time, O(n) space. Trades memory for removing the inner loop.

Pitfalls

  • Insert after the lookup, or one element can pair with itself.
  • Use IntArray(26), not a map, when keys are a small fixed alphabet.
  • Use a List or String as a map key, never a raw IntArray: arrays compare by identity.

ProblemsTwo Sum · Valid Anagram · Group Anagrams · Top K Frequent Elements

Two Pointers High

Lesson: Session 2

Signals

  • Sorted array plus "find a pair / triple with sum X"
  • Palindromes, or comparing the two ends of a string
  • In-place rearranging with O(1) extra space

Template

var l = 0; var r = nums.size - 1          // opposite ends
while (l < r) {
    val sum = nums[l] + nums[r]
    when {
        sum == target -> { /* found */ l++; r-- }
        sum < target -> l++                // need bigger
        else -> r--                         // need smaller
    }
}
var write = 0                               // same direction: read / write
for (read in nums.indices) if (nums[read] != 0) nums[write++] = nums[read]

Complexity

O(n) time (plus O(n log n) if you sort first), O(1) extra space.

Pitfalls

  • Opposite-end pointers need sorted input. If it isn't sorted, sort it or use a hash map.
  • When the output can't repeat values, skip duplicates after a match (3Sum).
  • Loop while l < r, not l <= r, when an element can't pair with itself.

ProblemsValid Palindrome · Two Sum II · 3Sum · Container With Most Water

Sliding Window High

Lesson: Session 3

Signals

  • Longest / shortest / best contiguous subarray or substring
  • A window of fixed size k
  • A rule you can update in O(1) as elements enter and leave

Template

var left = 0; var windowSum = 0; var best = 0
for (right in nums.indices) {
    windowSum += nums[right]               // grow
    while (windowSum > target) {           // shrink while invalid
        windowSum -= nums[left]; left++
    }
    best = maxOf(best, right - left + 1)   // record the valid window
}
// fixed size k: add nums[right]; if (right >= k) remove nums[right - k]

Complexity

O(n) amortized time, because each index enters and leaves once. O(1) space, or O(alphabet) for character counts.

Pitfalls

  • Only works when shrinking always moves toward valid. With negative numbers and sum targets, use prefix sums instead.
  • Window length is right - left + 1.
  • Record the answer after shrinking, when the window is valid again.

ProblemsBest Time to Buy and Sell Stock · Longest Substring Without Repeating Characters · Longest Repeating Character Replacement · Permutation in String

Prefix Sums Medium

Lesson: Session 4

Signals

  • Many range-sum queries on an array that doesn't change
  • Count or find subarrays with sum k, or a multiple of k, when negative numbers are allowed
  • "Everything left of i combined with everything right of i"

Template

val prefix = IntArray(nums.size + 1)       // prefix[0] = 0
for (i in nums.indices) prefix[i + 1] = prefix[i] + nums[i]
fun rangeSum(l: Int, r: Int) = prefix[r + 1] - prefix[l]   // inclusive l..r
// subarray questions → pair-of-prefixes questions → hash map of earlier prefixes

Complexity

O(n) to build, O(1) per query, O(n) space.

Pitfalls

  • Off-by-one: the sum of l..r is prefix[r + 1] − prefix[l].
  • Seed the hash map with the empty prefix (sum 0) before counting.
  • Large sums can overflow an Int. Check the constraints and use LongArray if needed.

ProblemsRange Sum Query – Immutable · Product of Array Except Self · Subarray Sum Equals K · Continuous Subarray Sum

Stacks & Queues Medium

Lesson: Session 5

Signals

  • Matching or nested pairs: brackets, tags, calls
  • "Undo", "backspace", "cancel the previous one"
  • Expression evaluation; design problems with stack/queue rules

Template

val stack = ArrayDeque<Char>()          // stack: addLast / last() / removeLast()
for (c in s) {
    if (c == '(') stack.addLast(c)       // open: remember it
    else if (stack.isEmpty() || stack.removeLast() != '(') { /* invalid */ }
}
val ok = stack.isEmpty()                 // leftovers were never closed
val queue = ArrayDeque<Int>()           // queue: addLast / removeFirst()

Complexity

O(n) time, O(n) space. Each item is pushed and popped at most once.

Pitfalls

  • Check isEmpty() before last() or removeLast(). Both throw on an empty deque.
  • Check the stack is empty at the end. Unclosed openers mean invalid input.
  • With two operands, the first pop is the right operand (matters for - and /).
  • Queue from two stacks: pour "in" into "out" only when "out" is empty, for amortized O(1).

ProblemsValid Parentheses · Min Stack · Evaluate Reverse Polish Notation · Implement Queue using Stacks

Monotonic Stack Medium

Lesson: Session 6

Signals

  • "Next / previous greater or smaller element"
  • "How many days until a warmer (taller, cheaper) one"
  • How far each bar extends left and right: largest rectangle

Template

val nextGreater = IntArray(nums.size) { -1 }
val stack = ArrayDeque<Int>()                    // indices; values decrease bottom to top
for (i in nums.indices) {
    while (stack.isNotEmpty() && nums[stack.last()] < nums[i]) {
        nextGreater[stack.removeLast()] = nums[i]     // nums[i] answers the popped index
    }
    stack.addLast(i)
}
// next smaller: pop while nums[top] > nums[i] (stack increases bottom to top)

Complexity

O(n) time (amortized: each index pushed once, popped at most once), O(n) space.

Pitfalls

  • Store indices, not values. You often need a distance, and values can repeat.
  • Strict < vs <= decides how equal values are handled. Check against the problem's wording.
  • Indices left on the stack at the end have no answer. Make sure the default value is right.

ProblemsDaily Temperatures · Next Greater Element I · Car Fleet · Largest Rectangle in Histogram

Binary Search High

Lesson: Session 7

Signals

  • Sorted array, or a sorted array that was rotated
  • "Minimum or maximum value that still works"
  • The answer is a number in a big range, and you can check one guess quickly (binary search on the answer)

Template

var lo = 0
var hi = nums.size - 1                 // invariant: target, if present, is in nums[lo..hi]
while (lo <= hi) {                     // range not empty
    val mid = lo + (hi - lo) / 2       // no Int overflow
    when {
        nums[mid] == target -> { /* found at mid */ break }
        nums[mid] < target -> lo = mid + 1
        else -> hi = mid - 1
    }
}
// On the answer: smallest x with ok(x) true, where ok is false...false, true...true
// if (ok(mid)) { best = mid; hi = mid - 1 } else lo = mid + 1

Complexity

O(log n) time and O(1) space. Binary search on the answer costs O(log range × cost of one check).

Pitfalls

  • (lo + hi) / 2 can overflow. Use lo + (hi - lo) / 2.
  • Match the loop condition to the updates. Use lo <= hi with mid ± 1, or lo < hi with hi = mid when mid itself might be the answer.
  • When a check adds up large values (hours, sums), use a Long.

ProblemsBinary Search · Search a 2D Matrix · Koko Eating Bananas · Find Minimum in Rotated Sorted Array

Linked Lists Medium

Lesson: Session 8

Signals

  • Input is a ListNode? head
  • Reverse, merge, reorder, or remove nodes
  • Find the middle, a cycle, or the nth node from the end

Template

// Reverse in place
var prev: ListNode? = null
var curr = head
while (curr != null) { val next = curr.next; curr.next = prev; prev = curr; curr = next }

// Dummy head: the first node needs no special case; return dummy.next
val dummy = ListNode(0).apply { next = head }

// Fast and slow pointers: middle node, or cycle if they meet (compare with ===)
var slow = head; var fast = head
while (fast?.next != null) { slow = slow?.next; fast = fast.next?.next }

Complexity

O(n) time and O(1) space for pointer rewiring. Recursion adds O(n) stack space.

Pitfalls

  • Save curr.next before overwriting it, or you lose the rest of the list.
  • To delete a node you need the node before it, so start from a dummy head.
  • Compare nodes with === (identity), not by value.

ProblemsReverse Linked List · Merge Two Sorted Lists · Linked List Cycle · Remove Nth Node From End of List
