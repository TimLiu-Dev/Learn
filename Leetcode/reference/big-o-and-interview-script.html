Good clarifying questions

  • How large can n be? This tells you which complexity to aim for (see below).
  • Can the input be empty or null? Can values be negative or zero?
  • Are there duplicates? Is the input sorted?
  • Is there always a solution? If there are several, which one should I return?
  • May I modify the input in place?

Complexity rules

  • Drop constants and lower-order terms: 3n² + n → O(n²).
  • Nested loops over the input multiply. Loops one after another add, and the larger term wins.
  • Halving the problem each step gives O(log n). Sorting costs O(n log n).
  • Hash map and set operations are O(1) on average.
  • Space is the extra memory you allocate, including recursion depth. The output usually doesn't count, but say so if you're leaving it out.
