Gotchas

  • == compares contents (like equals) and === compares identity. Arrays are the exception: IntArray == IntArray compares identity. Use contentEquals, and never use a raw array as a HashMap key — use a data class, String, or List<Int> instead.
  • kotlin.collections.ArrayDeque vs java.util.ArrayDeque: Prefer Kotlin's built-in ArrayDeque<T>() (no import required; supports addFirst, addLast, removeFirst, removeLast, first, last, and O(1) indexed access dq[i]). Avoid import java.util.* wildcard imports when using Kotlin's ArrayDeque so the types don't collide.
  • binarySearch negative return trap: When x is missing, binarySearch(x) returns -(insertionPoint + 1), not -insertionPoint. Recover the lower-bound index with -(idx + 1) (or idx.inv()).
  • 0..n includes n, while 0 until n (or a.indices) stops before it. Off-by-one bugs often hide in the range.
  • Int overflows silently. Sums of many values, products, and comparator subtractions are the usual culprits — promote to Long (0L) and use compareBy instead of a - b.
  • listOf and mapOf are read-only interfaces. Use mutableListOf, HashMap(), or ArrayDeque() when mutating.
  • Avoid !! in production/interview code when a smart cast (if (cur != null)) or Elvis fallback (?: return) expresses the invariant cleanly.
