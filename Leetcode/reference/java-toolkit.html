Stacks & Queues (Avoid Legacy Stack!)

// NEVER use java.util.Stack (it extends Vector, synchronization overhead):
// ALWAYS use Deque<T> with ArrayDeque:
Deque<Integer> stack = new ArrayDeque<>();
stack.push(1);                        // same as addFirst()
int top = stack.peek();               // same as peekFirst()
int popped = stack.pop();             // same as removeFirst()

// Queue (FIFO):
Deque<Integer> queue = new ArrayDeque<>();
queue.offer(1);                       // add to tail
int head = queue.peek();              // inspect head
int polled = queue.poll();            // remove from head
boolean empty = queue.isEmpty();

Gotchas & 2027 Big Tech Nuances

  • Boxed Integer Equality Trap: Integer a = 200, b = 200; (a == b) evaluates to false! Integer cache only covers -128..127. Always use a.equals(b) or unbox before comparison.
  • Avoid (a, b) -> a - b comparator subtraction: If a = -2_000_000_000 and b = 2_000_000_000, a - b wraps around to a positive number, breaking sorting invariants. Use Integer.compare(a, b).
  • Array vs List memory overhead: An int[1_000_000] takes ~4 MB of RAM. An ArrayList<Integer> of 1,000,000 elements takes ~24 MB (object headers + references + boxed Integers), introducing substantial GC pressure.
  • Avoid java.util.Stack: It locks on every method call due to inheriting from Vector. Use ArrayDeque.
