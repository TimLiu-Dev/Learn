Reference · Core Nomenclature

Algorithmic & Interview Glossary

Exact terminology across complexity analysis, data structures, concurrency, and 2027 progressive rounds — use these terms out loud with interviewers to communicate invariants concisely.

1 · Complexity, Memory & Verbal Protocol

Loop / Data-Structure Invariant Session 0
A property guaranteed to hold before and after every iteration or operation (e.g., "every element inside window[l..r] is unique," or "every index on the monotonic stack has strictly decreasing heights"). Stating your invariant before coding catches off-by-one bugs early.
Amortized Time Complexity Session 5
The average cost per operation over a worst-case sequence of n operations, even if an occasional single step is expensive (e.g., dynamic array doubling, two-stack queue transfer, or sliding window l++ where each element enters and leaves at most once for O(1) amortized cost).
Best Theoretical Time Complexity (BTTC) Session 38
The information-theoretic lower bound required just to read the necessary input or emit the output (e.g., O(n) to inspect an unsorted array, O(log n) on sorted random-access data). Reaching BTTC with O(1) extra space signals you can stop optimizing.
Primitive vs. Boxed Layout Session 0
On the JVM, Kotlin IntArray (int[]) stores raw 4-byte integers contiguously in CPU cache, whereas Array<Int> / ArrayList<Integer> stores 8-byte references to 16-byte heap objects (~5–6× higher RAM and GC pressure, plus Java's Integer == cache trap outside -128..127).
Auxiliary Space vs. Output Space Session 0
Auxiliary space counts temporary working memory allocated by your algorithm (including call-stack recursion depth O(h)), excluding the space required to hold the returned answer itself. Always distinguish the two out loud in Step 6.
Monotonic Predicate Session 7
A boolean check feasible(x) over a range that transitions at most once from false → true (or true → false). Any monotonic answer space (eating speed, ship capacity, split sum) admits O(log(range)) binary search.

2 · Linear Structures, Trees & Graphs

Sentinel / Dummy Node Session 8
A permanent placeholder node placed before the head (and/or after the tail in an LRU doubly linked list) so insertions and deletions at list boundaries never require null head/tail special cases.
Monotonic Stack / Deque Session 6
A stack or deque that evicts elements violating sorted order upon push. Popping an index prev when element i arrives resolves prev's nearest greater/smaller neighbor in O(n) total pushes and pops.
Floyd's Tortoise & Hare Session 8
Advancing slow by 1 step and fast by 2 steps to find a linked-list midpoint, detect pointer cycles, or detect number-sequence loops (Happy Number, Duplicate Number) in strict O(1) memory.
Difference Array Session 4
Dual of prefix sums: recording diff[l] += val and diff[r + 1] -= val applies Q range additions in O(1) each, followed by one O(n) prefix-sum sweep at the end (Corporate Flight Bookings, Car Pooling).
0-1 BFS Session 17
Shortest-path search on graphs whose edge weights are exclusively 0 or 1: pushing 0-cost relaxations to the front of an ArrayDeque and 1-cost relaxations to the back maintains a sorted two-level frontier in O(V + E) without heap log V overhead.
Topological Ordering & Kahn's Algorithm Session 18
A linear ordering of vertices in a Directed Acyclic Graph (DAG) such that every directed edge u → v places u before v. Kahn's BFS repeatedly peels vertices with inDegree == 0; if fewer than V vertices are peeled, a directed cycle exists.
Path Compression & Union by Rank (DSU) Session 19
Two optimizations in Disjoint Set Union: rewiring visited nodes directly to the root during find(x) and attaching shorter trees under taller roots during union(x, y), yielding O(α(n)) ≈ O(1) amortized connectivity.
Edge Relaxation & Stale Heap Entries Session 20
Updating dist[v] = dist[u] + w whenever path through u improves the best known cost to v. Because Java/Kotlin/Python heaps lack O(log V) decrease-key, we push duplicate pairs and skip stale pops via if (d > dist[u]) continue.
Eulerian Path (Hierholzer's Algorithm) Session 34
A walk that traverses every edge in a graph exactly once. Hierholzer's algorithm consumes outgoing edges greedily and appends vertices in post-order (reversing at the end) so dead-end sinks never strand remaining cycles.

3 · Dynamic Programming, Greedy & Range Trees

Optimal Substructure & Overlapping Subproblems Session 22
The twin prerequisites for Dynamic Programming: an optimal global solution decomposes into optimal subproblem answers, and naive recursion recomputes the exact same state parameters exponentially many times.
Exchange Argument (Greedy Proof) Session 21
Justification that swapping any step in a hypothetical optimal schedule with your locally greedy choice (e.g., earliest-ending interval in Non-overlapping Intervals) never worsens the objective. Without a valid exchange/reachability invariant, use DP.
0/1 vs. Unbounded Knapsack Iteration Order Session 23
In space-optimized 1-D knapsack, iterating capacity downward (W downTo weight) reads the previous row so each item is used at most once (0/1), whereas iterating upward allows reusing the current item repeatedly (Unbounded).
State Compression / Rolling Array Session 24
Replacing an O(m × n) DP table with 1 or 2 rows of length min(m, n) whenever dp[r][c] depends only on row r and row r - 1.
Lowest Set Bit (i and -i) Session 26
Two's-complement bit identity isolating the rightmost 1-bit of i; powers Fenwick Tree (BIT) O(log n) prefix queries (i -= i and -i) and point updates (i += i and -i), while n and (n - 1) clears that lowest bit.
3-Way Dutch National Flag Partition Session 35
Partitioning an array into < pivot, == pivot, and > pivot zones in one O(n) pass; prevents Quickselect from degrading to O(n²) on inputs containing all-equal duplicates.

4 · System Design, Concurrency & 2027 Practical Rounds

Swap-with-Last Deletion Session 29
Achieving O(1) removal from a contiguous ArrayList (for uniform getRandom()) by overwriting the deleted index idx with list.last(), updating the moved element's index in a HashMap, and popping the tail.
Spurious Wakeup & Condition Loop Session 30
OS/JVM condition variables may wake a parked thread without a matching signal, or a competing thread may consume the resource before the awakened thread re-acquires the lock. Always guard condition.await() inside a while (!predicate) loop, never an if.
Lazy Expiration & Half-Open TTL Interval Session 37
Storing expiresAt = ts + ttl and treating an entry as live iff queryTs < expiresAt (half-open [ts, ts + ttl)) avoids background sweeper threads while keeping Stage 1/2 reads O(1).
Relative Remaining-TTL Snapshot Session 37
In multi-stage backup/restore specs, snapshots store remainingTtl = expiresAt - backupTs (copied by value, never by shared map reference) so restoring at a later restoreTs cleanly reconstructs restoreTs + remainingTtl.
