The idea

In a Binary Search Tree (BST), for every node: all values in the left subtree are strictly smaller, and all values in the right subtree are strictly larger. This gives average O(log n) search. An in-order traversal (Left → Node → Right) visits BST values in strictly ascending sorted order.

Reach for it when you see…

  • Validate whether a binary tree satisfies the BST invariant
  • Lowest Common Ancestor (LCA) in a BST
  • Kth smallest or kth largest element in a BST
  • Insert, delete, or search for a key in O(h) time

Pattern templates

// BST Search: prune half the tree at each step
fun searchBST(root: TreeNode?, target: Int): TreeNode? {
    var curr = root
    while (curr != null) {
        if (curr.`val` == target) return curr
        curr = if (target < curr.`val`) curr.left else curr.right
    }
    return null
}

Walkthrough: Lowest Common Ancestor of a BST

Given a BST and two nodes p and q, find their Lowest Common Ancestor (LCA).

1 · Clarify

Are all node values unique? Are p and q guaranteed to exist in the BST? Can a node be a descendant of itself? Yes: values are unique, p and q exist, and a node can be its own ancestor.

2 · Examples

Root = 6, p = 2, q = 8 → LCA is 6 (split point). p = 2, q = 4 → LCA is 2 (ancestor of 4).

3 · Approach

In an arbitrary binary tree, finding LCA requires post-order search. But in a BST, we can use the value ordering:

  • If both p and q are smaller than curr.val, the LCA must be in the left subtree.
  • If both are larger, the LCA must be in the right subtree.
  • If p and q split (one is smaller and one is larger, or one equals curr.val), curr is the LCA!
4 · Code 
class Solution {
    fun lowestCommonAncestor(root: TreeNode?, p: TreeNode?, q: TreeNode?): TreeNode? {
        var curr = root
        val pVal = p!!.`val`
        val qVal = q!!.`val`
        while (curr != null) {
            if (pVal < curr.`val` && qVal < curr.`val`) {
                curr = curr.left
            } else if (pVal > curr.`val` && qVal > curr.`val`) {
                curr = curr.right
            } else {
                return curr // Split point is the LCA
            }
        }
        return null
    }
}

6 · Complexity

Time O(h): visits at most one node per level. O(log n) for balanced BST, O(n) worst-case. Space O(1): iterative traversal uses no extra stack.

In-order traversal visits left subtree, current root node, then right subtree, matching the BST invariant.

When validating a BST with recursion, what must each recursive call verify for node value x?

  1. x is strictly greater than 0
  2. x has at least two children
  3. x equals its left child val
  4. x is between lower and upper

Checking only immediate children is insufficient; every node must fall strictly inside (low, high) bounds.

Validate Binary Search Tree Medium

  1. Checking node.left.val < node.val is not enough. Why? Consider a right child whose left grandchild is smaller than root.
  2. Pass valid bounds (low, high) down the recursive calls. Root starts with (-infinity, +infinity).
  3. When moving left, update the upper bound: (low, node.val). When moving right, update lower: (node.val, high). Use Long to avoid integer overflow.

Kth Smallest Element in a BST Medium

  1. An in-order traversal visits nodes in ascending order.
  2. Do an iterative in-order traversal with an explicit stack. Stop when you pop the kth element.
  3. Time is O(H + k), avoiding traversing the entire tree.

Insert into a Binary Search Tree Medium

  1. Search for the value as you would in standard BST lookup.
  2. When you hit a null pointer, that is the exact spot where the new TreeNode belongs.
  3. Return the original root, or return new TreeNode if root was null.
