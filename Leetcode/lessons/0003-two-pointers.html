Two Pointers

Two indices, one pass. Every step gets rid of a choice you no longer need.

Your winReplace a nested loop with two indices that walk toward each other, using O(1) extra space.

The idea

A nested loop checks every pair (i, j), which is O(n²). Often the input has some structure, like being sorted or symmetric. That structure lets you rule out a whole row of pairs with a single comparison. Two indices that only ever move forward (or inward) touch each element at most once, which is O(n).

Reach for it when you see…

  • a sorted array and "find a pair / triple with sum X"
  • palindromes, or anything that compares the two ends of a string
  • "in place" or "O(1) extra space" rearranging, like removing or compacting elements

Two shapes this pattern takes

// 1. Opposite ends: start at both edges and move inward
var l = 0
var r = nums.size - 1
while (l < r) {
    val sum = nums[l] + nums[r]
    when {
        sum == target -> { /* found a pair */ l++; r-- }
        sum < target -> l++     // too small: only a bigger left value can help
        else -> r--             // too big: only a smaller right value can help
    }
}

// 2. Same direction: read scans everything, write marks where the next kept value goes
var write = 0
for (read in nums.indices) {
    if (nums[read] != 0) nums[write++] = nums[read]
}

Walkthrough: Valid Palindrome

A string is a palindrome if it reads the same both ways after you lowercase it and drop everything that isn't a letter or digit. Return whether s is one.

1 · Clarify

"Do digits count? Is the comparison case-insensitive? What about an empty string, or one that is only punctuation?" Digits count. Case is ignored. A string with no letters or digits is a palindrome. The input is printable ASCII.

2 · Examples

"A man, a plan, a canal: Panama" → true. "race a car" → false. Edge case: " " → true, because nothing is left after cleaning.

3 · Approach

Brute force: build a cleaned, lowercased copy, then compare it with its reverse. That's O(n) time and O(n) extra space. It's correct and a fine first answer.

Better: skip the copy. Put l at the start and r at the end. Move each one past characters that don't count, compare the two characters, then step both inward. That's still O(n) time, but now O(1) space.

4 · Code 
class Solution {
    fun isPalindrome(s: String): Boolean {
        var l = 0
        var r = s.length - 1
        while (l < r) {
            if (!s[l].isLetterOrDigit()) { l++; continue }   // skip junk on the left
            if (!s[r].isLetterOrDigit()) { r--; continue }   // skip junk on the right
            if (s[l].lowercaseChar() != s[r].lowercaseChar()) return false
            l++
            r--
        }
        return true
    }
}

Say this as you code: "isLetterOrDigit also accepts non-English letters. That's fine here because the input is ASCII."

5 · Test

"race a car": r/r match, a/a match, c/c match, e/space (skip the space), then e/a: mismatch, so return false. ✓ " ": l = r = 0, so the loop never runs and we return true. ✓ "0P": '0' ≠ 'p', so return false. ✓ That last one catches anyone who only checks letters.

6 · Complexity

Time O(n): every step moves at least one pointer inward, and they meet once. Space O(1): two integers and no copy of the string.

Quick check

The array is sorted and nums[l] + nums[r] is smaller than the target. What do you do?

  1. Move r one step left
  2. Move both pointers in
  3. Move l one step right
  4. Restart from both ends

The sum is too small and r is already the largest value still available. Only a bigger left value can help, so move l right. This rules out every pair that uses the old nums[l].

Compared with building a cleaned, reversed copy, what does the two-pointer Valid Palindrome save?

  1. O(n) time overall
  2. O(n) extra space
  3. One sorting step
  4. A hash map lookup

Both versions take O(n) time. The two-pointer version skips the copy, so extra space drops from O(n) to O(1). Mention this out loud when you go from the first version to the second.

What usually has to be true for opposite-end pointers to find a pair sum?

  1. Values are unique
  2. Values are positive
  3. Length is even
  4. Array is sorted

Sorted order is what tells you which pointer to move. If the input isn't sorted, either sort it first in O(n log n) or use the hash map from Session 1.

Two Sum II – Input Array Is Sorted Medium

  1. Session 1's hash map would work. Why does the problem rule it out? Read the space requirement.
  2. Start one pointer at each end. When the sum is wrong, the sorted order tells you which pointer to move.
  3. Each move rules out every pair that uses the pointer you moved, so you never need to go back. Watch out: the answer is 1-indexed.

3Sum Medium

  1. Fix one number a. Now you need two other numbers that sum to −a. You just solved that problem.
  2. Sort first. For each index i, run the Two Sum II scan on the part of the array to its right.
  3. The output can't contain duplicate triples. Skip i when it has the same value as the previous i. After you find a match, move l past any repeated values.

Container With Most Water Medium

  1. Area = width × the shorter of the two lines. Start with the widest container: one pointer at each end.
  2. Every move makes the width smaller. Which of the two lines could possibly give a bigger area if you moved past it?
  3. Moving the taller line can never help, because the shorter line still limits the height. Always move the shorter one.
