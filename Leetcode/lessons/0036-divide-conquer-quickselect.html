The idea

Three classic linear/log-linear divide-and-conquer techniques round out Big Tech interview prep: (1) Quickselect (with randomized pivot & 3-way partition)—recurses into only ONE half after partitioning, yielding n + n/2 + n/4 + ... = 2n = O(n) average time and O(1) space; (2) Boyer-Moore Majority Vote—cancels pairs of distinct elements in O(n) time and O(1) space; and (3) Merge-Sort Divide & Conquer—sorts linked lists in O(n log n) / O(1) iterative or O(log n) stack space, and counts cross-half inversions (Reverse Pairs).

Reach for it when you see…

  • 'Kth largest / K closest in O(n) average time and O(1) space' (Quickselect)
  • 'Sort 3 distinct colors / keys in-place' (Dutch National Flag 3-way partition)
  • 'Element appearing more than n / 2 times in O(1) space' (Boyer-Moore Voting)
  • 'Sort a Linked List in O(n log n)' or 'count cross-half pairs i < j' (Merge Sort D&C)

        nums[mid] < pivot -> { val t = nums[low]; nums[low++] = nums[mid]; nums[mid++] = t }

    }
}

Walkthrough: Majority Element

Given an array nums of size n, return the majority element (the element that appears more than ⌊n / 2⌋ times) in O(n) time and O(1) space.

1 · Clarify

Is a majority element guaranteed to exist? Yes, problem guarantees an element appears strictly more than n / 2 times. If not guaranteed, a second O(n) verification pass checks whether candidate actually exceeds n / 2.

2 · Examples

[3, 2, 3] → 3. [2, 2, 1, 1, 1, 2, 2] → 2.

3 · Approach

Hash Map: O(n) time, O(n) space.

Boyer-Moore Voting: Think of every distinct pair of elements cancelling out in a battle. Because the true majority appears > n / 2 times, even if every non-majority element pairs off against a majority element, at least one majority instance survives! Maintain candidate and count: whenever count == 0, adopt the current element; increment if equal, decrement otherwise.

4 · Code 
class Solution {
    fun majorityElement(nums: IntArray): Int {
        var candidate = 0
        var count = 0
        for (x in nums) {
            if (count == 0) candidate = x
            count += if (x == candidate) 1 else -1
        }
        return candidate
    }
}

Quick check

In 3-way Dutch National Flag partitioning, why do we NOT increment mid after swapping with high?

  1. Because low holds unvisited elements
  2. Because high holds unvisited items
  3. Because mid must stay fixed
  4. Because twos break loop invariants

Everything in [0..low-1] is 0 and [low..mid-1] is 1, so swapping with low brings a known 1. Everything in [mid..high] is uninspected, so swapping with high brings an unknown element that must be checked.

Why does adding 3-way partitioning protect Quickselect from O(n²) worst-case behavior on duplicate-heavy arrays?

  1. Merges both halves linearly
  2. Picks median in O(1)
  3. Stores duplicates in HashMap
  4. Skips equal pivot bands

If all elements equal the pivot, 2-way Lomuto partition shrinks the array by just 1 element per step (O(n²)), whereas 3-way partition groups all equal pivots in one O(n) pass and returns immediately.

Why is Merge Sort preferred over Quicksort when sorting a Linked List in O(n log n)?

  1. Linked lists support random access
  2. Merge sort runs in O(n)
  3. No random indexing needed
  4. Avoids comparing node values

Quicksort relies heavily on cache-local random indexing, whereas Merge Sort on linked lists splits via fast/slow pointers and merges by rewiring .next pointers in-place.

Sort List Medium

  1. Use fast/slow pointers (starting fast = head.next) to split the list cleanly into two halves.
  2. Recursively sort left and right halves, then merge two sorted lists (like Session 8).
  3. Follow-up: bottom-up iterative merge sort with size = 1, 2, 4, ... achieves strict O(1) auxiliary space.

Reverse Pairs Hard

  1. You want pairs (i, j) with i < j and nums[i] > 2 * nums[j].
  2. Inside Merge Sort, before merging sorted halves [l..mid] and [mid+1..r], use two pointers: for each i in left, advance j in right while nums[i] > 2 * nums[j].
  3. Because both halves are sorted, j only moves forward across the entire left loop—O(n) count step per merge level!

Majority Element II Medium

  1. How many elements can appear strictly more than ⌊n / 3⌋ times? At most 2!
  2. Extend Boyer-Moore to track two candidates (cand1, count1 and cand2, count2), decrementing both only when a number matches neither.
  3. Unlike Majority Element I, existence isn't guaranteed—run a final verification pass counting both candidates.
