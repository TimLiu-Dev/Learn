The idea

Interval problems almost always become simple once sorted by start time. Two intervals [start1, end1] and [start2, end2] overlap if start2 <= end1. In sweep-line algorithms, decompose intervals into two discrete events: (start, +1) and (end, -1), then scan across time.

Walkthrough: Merge Intervals

Given an array of intervals where intervals[i] = [starti, endi], merge all overlapping intervals.

1 · Clarify

Can intervals be unsorted? Does [1, 4] and [4, 5] count as overlapping? Yes, intervals are unsorted. Touching boundaries count as overlapping.

2 · Examples

[[1,3],[2,6],[8,10],[15,18]] → [[1,6],[8,10],[15,18]]. [[1,4],[4,5]] → [[1,5]].

3 · Approach

1. Sort intervals by start time. Now any overlapping intervals must be adjacent.

2. Iterate through: if curr[0] <= prev[1], merge by setting prev[1] = max(prev[1], curr[1]). Otherwise, push prev to results and advance.

4 · Code 
class Solution {
    fun merge(intervals: Array<IntArray>): Array<IntArray> {
        intervals.sortBy { it[0] }
        val merged = mutableListOf<IntArray>()
        var current = intervals[0]

        for (i in 1 until intervals.size) {
            val next = intervals[i]
            if (next[0] <= current[1]) {
                current[1] = maxOf(current[1], next[1])
            } else {
                merged.add(current)
                current = next
            }
        }
        merged.add(current)
        return merged.toTypedArray()
    }
}

class Solution {
    public int[][] merge(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
        List<int[]> merged = new ArrayList<>();
        int[] current = intervals[0];

        for (int i = 1; i < intervals.length; i++) {
            if (intervals[i][0] <= current[1]) {
                current[1] = Math.max(current[1], intervals[i][1]);
            } else {
                merged.add(current);
                current = intervals[i];
            }
        }
        merged.add(current);
        return merged.toArray(new int[merged.size()][]);
    }
}

class Solution {
    fun merge(intervals: Array<IntArray>): Array<IntArray> {
        intervals.sortBy { it[0] }
        val merged = mutableListOf<IntArray>()
        for (cur in intervals) {
            if (merged.isEmpty() || cur[0] > merged.last()[1]) {
                merged.add(cur)
            } else {
                merged.last()[1] = maxOf(merged.last()[1], cur[1])
            }
        }
        return merged.toTypedArray()
    }
}

class Solution {
    public int[][] merge(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
        List<int[]> merged = new ArrayList<>();
        for (int[] cur : intervals) {
            if (merged.isEmpty() || cur[0] > merged.get(merged.size() - 1)[1]) {
                merged.add(cur);
            } else {
                merged.get(merged.size() - 1)[1] = Math.max(merged.get(merged.size() - 1)[1], cur[1]);
            }
        }
        return merged.toArray(new int[merged.size()][]);
    }
}

Quick check

If intervals are sorted by start time, when do intervals A and B (where A comes first) overlap?

  1. When B.start <= A.end
  2. When B.end <= A.start
  3. When B.start >= A.end
  4. When B.end >= A.start

Since B starts after or at A.start, they overlap if and only if B starts before or when A ends (B.start <= A.end).

In Java, what is dangerous about sorting intervals using (a, b) -> a[0] - b[0]?

  1. Breaks stable comparator logic
  2. Integer subtraction overflow
  3. Throws NullPointer on zeroes
  4. Array sorting becomes O(n²)

If a[0] is negative and b[0] is positive, subtraction can overflow Integer.MIN_VALUE, flipping comparison.

In the sweep-line meeting rooms problem, what delta values are assigned to start and end times?

  1. start: -1 and end: +1
  2. start: +2 and end: -1
  3. start: +1 and end: -1
  4. start: 0 and end: 100

A meeting start increases active room count by +1; a meeting end releases the room, subtracting -1.

Insert Interval Medium

  1. Add all intervals ending before newInterval starts.
  2. Merge all intervals overlapping with newInterval by updating start = min, end = max.
  3. Add remaining intervals that start after newInterval ends.

Non-overlapping Intervals Medium

  1. To remove the minimum number of intervals, keep intervals that finish earliest (greedy).
  2. Sort intervals by end time.
  3. Count how many intervals can fit without overlapping; answer is total - valid.

Meeting Rooms II Medium

  1. Use min-heap of end times or two sorted arrays for starts and ends.
  2. For each meeting start, check if the earliest meeting ended: if so, reuse room (pop).
  3. Max heap size equals minimum rooms required.
