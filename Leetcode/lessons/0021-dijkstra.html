Warm-up from memory

Close this page and recall: why does Dijkstra's algorithm fail on graphs with negative edge weights? Which algorithm handles negative weights?

The idea

Dijkstra's algorithm finds shortest paths from a single source in non-negative weighted graphs. It greedily pops the unvisited node with the smallest distance from a min-heap, relaxes its neighbors, and repeats. For graphs with negative weights or at most k stops constraints, Bellman-Ford / SPFA relaxes all edges repeatedly.

Reach for it when you see…

  • 'Network delay time', 'cheapest flight', 'minimum cost path'
  • Weighted directed/undirected graph with positive edge weights
  • Grid where moving between cells has variable costs

Walkthrough: Network Delay Time

You are given a network of n nodes labeled 1 to n. times[i] = (ui, vi, wi) represents the travel time from ui to vi. How long will it take for all nodes to receive a signal sent from node k? Return -1 if impossible.

1 · Clarify

Can there be disconnected nodes? Are times non-negative? Can weights be 0? Yes: disconnected nodes return -1. Times are non-negative integers (Dijkstra applies).

2 · Examples

times = [[2,1,1],[2,3,1],[3,4,1]], n = 4, k = 2 → 2 (node 4 reached at t=2).

3 · Approach

1. Build adjacency list: u → (v, w).

2. Run Dijkstra starting from k: maintain dist array initialized to ∞, dist[k] = 0.

3. Use min-heap (cost, node). When popped, if cost > dist[node], skip. Otherwise relax outgoing edges.

4. Max of dist[1..n] is the total time. If any node has ∞, return -1.

4 · Code 
class Solution {
    fun networkDelayTime(times: Array<IntArray>, n: Int, k: Int): Int {
        val graph = Array(n + 1) { mutableListOf<IntArray>() }
        for (t in times) graph[t[0]].add(intArrayOf(t[1], t[2]))

        val dist = IntArray(n + 1) { Int.MAX_VALUE }
        dist[k] = 0
        val pq = java.util.PriorityQueue<IntArray>(compareBy { it[1] })
        pq.offer(intArrayOf(k, 0))

        while (pq.isNotEmpty()) {
            val (u, d) = pq.poll()
            if (d > dist[u]) continue
            for (edge in graph[u]) {
                val v = edge[0]; val w = edge[1]
                if (d + w < dist[v]) {
                    dist[v] = d + w
                    pq.offer(intArrayOf(v, dist[v]))
                }
            }
        }

        var maxTime = 0
        for (i in 1..n) {
            if (dist[i] == Int.MAX_VALUE) return -1
            maxTime = maxOf(maxTime, dist[i])
        }
        return maxTime
    }
}

    def networkDelayTime(self, times: list[list[int]], n: int, k: int) -> int:

        for u, v, w in times:
            graph[u].append((v, w))

            d, u = heapq.heappop(pq)
            if d > dist[u]:
                continue
            for v, w in graph[u]:
                if d + w < dist[v]:
                    dist[v] = d + w
                    heapq.heappush(pq, (d + w, v))

        max_time = max(dist.values())
        return max_time if max_time < float('inf') else -1
class Solution {
    public int networkDelayTime(int[][] times, int n, int k) {
        List<List<int[]>> graph = new ArrayList<>();
        for (int i = 0; i <= n; i++) graph.add(new ArrayList<>());
        for (int[] t : times) graph.get(t[0]).add(new int[]{t[1], t[2]});

        int[] dist = new int[n + 1];
        Arrays.fill(dist, Integer.MAX_VALUE);
        dist[k] = 0;

        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[1], b[1]));
        pq.offer(new int[]{k, 0});

        while (!pq.isEmpty()) {
            int[] curr = pq.poll();
            int u = curr[0], d = curr[1];
            if (d > dist[u]) continue;
            for (int[] edge : graph.get(u)) {
                int v = edge[0], w = edge[1];
                if (d + w < dist[v]) {
                    dist[v] = d + w;
                    pq.offer(new int[]{v, dist[v]});
                }
            }
        }

        int maxTime = 0;
        for (int i = 1; i <= n; i++) {
            if (dist[i] == Integer.MAX_VALUE) return -1;
            maxTime = Math.max(maxTime, dist[i]);
        }
        return maxTime;
    }
}

class Solution {
    fun networkDelayTime(times: Array<IntArray>, n: Int, k: Int): Int {
        val adj = Array(n + 1) { mutableListOf<Pair<Int, Int>>() }
        for (t in times) adj[t[0]].add(t[1] to t[2])
        val pq = java.util.PriorityQueue<Pair<Int, Int>>(compareBy { it.second })
        pq.offer(k to 0)
        val dist = HashMap<Int, Int>()
        while (pq.isNotEmpty()) {
            val (u, d) = pq.poll()
            if (u in dist) continue
            dist[u] = d
            for ((v, w) in adj[u]) {
                if (v not in dist) pq.offer(v to d + w)
            }
        }
        return if (dist.size == n) dist.values.maxOrNull()!! else -1
    }
}

class Solution {
    public int networkDelayTime(int[][] times, int n, int k) {
        List<List<int[]>> adj = new ArrayList<>();
        for (int i = 0; i <= n; i++) adj.add(new ArrayList<>());
        for (int[] t : times) adj.get(t[0]).add(new int[]{t[1], t[2]});
        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
        pq.offer(new int[]{0, k});
        Map<Integer, Integer> dist = new HashMap<>();
        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            int d = cur[0], u = cur[1];
            if (dist.containsKey(u)) continue;
            dist.put(u, d);
            for (int[] edge : adj.get(u)) {
                int v = edge[0], w = edge[1];
                if (!dist.containsKey(v)) pq.offer(new int[]{d + w, v});
            }
        }
        if (dist.size() != n) return -1;
        int max = 0;
        for (int d : dist.values()) max = Math.max(max, d);
        return max;
    }
}

Quick check

In Dijkstra's algorithm, why do we include if (d > dist[u]) continue immediately after popping from heap?

  1. Prevents popping negative costs
  2. Discards outdated stale entries
  3. Breaks early when target found
  4. Sorts the adjacency edge lists

Standard priority queues cannot update keys in-place; they insert new (cost, node) tuples. Stale higher-cost tuples must be skipped.

Which algorithm is suitable for finding the shortest path when the graph contains negative edge weights?

  1. Standard Dijkstra priority heap
  2. Breadth-first search queueing
  3. Bellman-Ford algorithm checks
  4. Topological sort DAG search

Bellman-Ford relaxes all edges V-1 times, correctly handling negative weights and detecting negative cycles.

What is the primary constraint that allows Dijkstra's greedy choice to be provably optimal?

  1. Graph must be completely planar
  2. Graph cannot have directed loops
  3. Number of edges must exceed V
  4. Edge costs must be non-negative

Non-negative edge weights ensure that once a node is popped with the minimum distance, no future path can reach it with lower cost.

Cheapest Flights Within K Stops Medium

  1. Because of the k-stops constraint, Bellman-Ford running for k + 1 rounds is simpler than Dijkstra.
  2. Clone the dist array at each round so updates don't cascade across multiple edges in the same step.
  3. If dist[dst] == inf, return -1.

Path with Minimum Effort Medium

  1. Cost of path is max(abs(height1 - height2)) along the path.
  2. Run modified Dijkstra: relax neighbor with newEffort = max(effort, abs(diff)).
  3. Stop and return effort the moment target cell (m-1, n-1) is popped.

Swim in Rising Water Hard

  1. Minimum time to reach (n-1, n-1) where moving to cell costs max(time, grid[r][c]).
  2. Use min-heap: pop cell with lowest elevation.
  3. The first time (n-1, n-1) is reached gives the minimal maximum elevation.
