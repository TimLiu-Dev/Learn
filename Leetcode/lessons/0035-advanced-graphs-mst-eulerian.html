Warm-up from memory

Close this page and recall: how many edges does a Minimum Spanning Tree (MST) on V connected vertices always contain?

The idea

Three advanced graph patterns complete `roadmap.sh/leetcode`: (1) Minimum Spanning Tree (MST)—Prim's grows one tree from a root using a min-heap (or O(V²) array on dense graphs), while Kruskal's sorts edges and merges components with DSU in O(E log E); (2) Hierholzer's Algorithm (Eulerian Path)—consumes every edge exactly once via post-order DFS and reverses the resulting node list; and (3) Tarjan's Bridges—tracks discovery time disc[u] and lowest reachable ancestor low[u] to flag critical edges where low[v] > disc[u].

Reach for it when you see…

  • 'Minimum cost to connect all points / cities' (MST: Prim's or Kruskal's)
  • 'Use every flight ticket / edge exactly once' (Eulerian Path / Hierholzer's)
  • 'Critical connections / single-point-of-failure edges' (Tarjan's Bridges)

Walkthrough: Min Cost to Connect All Points

Given an array points of 2D coordinates [x_i, y_i], return the minimum total Manhattan distance |x_i - x_j| + |y_i - y_j| to make all points connected.

1 · Clarify

Are all points distinct? How many points? 1 <= points.length <= 1000, distinct integer coordinates. Since every pair of points can connect, this is a dense complete graph with ~N² / 2 edges.

2 · Examples

points = [[0,0],[2,2],[3,10],[5,2],[7,0]] → MST edges total 4 + 3 + 4 + 9 = 20.

3 · Approach

Kruskal's vs Prim's: Generating and sorting all O(N²) edges for Kruskal's uses O(N²) memory and O(N² log N) time. On dense complete graphs, Prim's O(N²) without a heap (or Prim's with min-heap) is optimal: maintain minDist[v] = cheapest edge from the visited MST component to unvisited vertex v. In each of N iterations, pick the unvisited vertex with minimum minDist, add it to MST, and relax distances to remaining unvisited points—O(N²) time and O(N) space!

class Solution {
    fun minCostConnectPoints(points: Array<IntArray>): Int {
        val n = points.size
        val minDist = IntArray(n) { Int.MAX_VALUE }
        val inMst = BooleanArray(n)
        minDist[0] = 0
        var total = 0

        for (step in 0 until n) {
            var u = -1
            for (i in 0 until n) {
                if (!inMst[i] && (u == -1 || minDist[i] < minDist[u])) u = i
            }
            inMst[u] = true
            total += minDist[u]
            for (v in 0 until n) {
                if (!inMst[v]) {
                    val d = kotlin.math.abs(points[u][0] - points[v][0]) +
                            kotlin.math.abs(points[u][1] - points[v][1])
                    if (d < minDist[v]) minDist[v] = d
                }
            }
        }
        return total
    }
}

Quick check

When is Kruskal's algorithm generally preferred over dense Prim's, and vice versa?

  1. Kruskal handles negative edges
  2. Prim uses Union-Find arrays
  3. Kruskal sparse, Prim dense
  4. Prim handles directed graphs

Kruskal's sorts an explicit edge list in O(E log E) (great when E ~ V), while dense Prim's avoids allocating O(V²) edges on complete graphs.

In Hierholzer's Algorithm (Reconstruct Itinerary), why do we append a node to the route in post-order?

  1. Dead ends belong at end
  2. Prevents revisiting any node
  3. Sorts airport codes fast
  4. Enforces DAG ordering rules

Greedy pre-order can walk into a dead-end node before exhausting a side loop; post-order naturally places the dead-end sink last once reversed.

In Tarjan's Bridge-Finding algorithm, when is tree edge (u, v) guaranteed to be a critical bridge?

  1. When low[v] equals disc[u]
  2. When degree[v] equals one
  3. When low[v] less than disc[u]
  4. When low[v] exceeds disc[u]

When `low[v] > disc[u]`, the subtree rooted at `v` has zero alternative back-edges back up to `u` or its ancestors—making `(u, v)` a bridge.

Reconstruct Itinerary Hard

  1. Sort each airport's destinations in reverse lexicographical order so pop() yields the smallest next airport in O(1) (or use a min-heap).
  2. Run Hierholzer's DFS starting from "JFK", consuming edges as you traverse.
  3. Append airport to route after its outgoing edges are exhausted, then return route[::-1].

Critical Connections in a Network Hard

  1. A critical connection is a bridge in an undirected graph—an edge not contained in any cycle.
  2. Track disc[u] (DFS discovery timestamp) and low[u] (earliest reachable ancestor via back-edges, ignoring immediate parent).
  3. If neighbor v gives low[v] > disc[u], record [u, v] as a bridge.

Path with Maximum Probability Medium

  1. Probabilities lie in [0, 1], so multiplying along a path can never increase probability—Dijkstra's greedy invariant holds!
  2. Use a max-heap storing (-prob, node) in Python (or negate/reverse comparator in Kotlin/Java) to expand highest-probability paths first.
