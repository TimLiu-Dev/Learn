The idea

A linked list is a chain of nodes. Each node holds a value and a next reference. You can't jump to index i the way you can in an array. Instead, you walk the chain and change where the next references point. Almost every list problem comes down to three tools.

Reach for it when you see…

  • the input is a ListNode? head
  • "reverse", "merge", "reorder", or "remove" nodes
  • "find the middle", "detect a cycle", or "the nth node from the end"

Three tools

  1. Reverse in place. Walk the list with prev and curr, and flip each next to point backward. The walkthrough below shows this.
  2. Dummy head. Create a fake node dummy whose next is the real list. The first real node then has a node before it like every other node, so you don't need a special case when the head changes. Return dummy.next.
  3. Fast and slow pointers. slow moves 1 step at a time and fast moves 2. When fast reaches the end, slow is at the middle. If the list has a cycle, fast laps slow and they meet. Starting the two pointers n nodes apart finds the nth node from the end.
// Dummy head: build a list without special-casing the first node
fun copyList(head: ListNode?): ListNode? {
    val dummy = ListNode(0)
    var tail = dummy
    var curr = head
    while (curr != null) {
        tail.next = ListNode(curr.`val`)
        tail = tail.next!!
        curr = curr.next
    }
    return dummy.next
}

// Fast and slow: slow ends on the middle node
fun middle(head: ListNode?): ListNode? {
    var slow = head
    var fast = head
    while (fast?.next != null) {
        slow = slow?.next
        fast = fast.next?.next
    }
    return slow
}

Walkthrough: Reverse Linked List

Given the head of a singly linked list, reverse it and return the new head.

1 · Clarify

"Can the list be empty? Should I reverse it in place, or may I build a new list? Do you want an iterative or recursive answer?" The list has 0 to 5000 nodes, so it can be empty. In place is expected, and both iterative and recursive answers are accepted.

2 · Examples

1 → 2 → 3 → 4 → 5 → 5 → 4 → 3 → 2 → 1. Edge cases: an empty list (null) returns null. A single node returns itself.

3 · Approach

Brute force: copy the values into a list, then build a new reversed list. That's O(n) time and O(n) extra space.

Better: walk the list once and turn each next arrow around. Flipping curr.next would lose the rest of the list, so save it in next first. Three references (prev, curr, next) are enough, which gives O(n) time and O(1) space.

4 · Code 
// LeetCode provides: class ListNode(var `val`: Int) { var next: ListNode? = null }
class Solution {
    fun reverseList(head: ListNode?): ListNode? {
        var prev: ListNode? = null
        var curr = head
        while (curr != null) {
            val next = curr.next    // save the rest of the list
            curr.next = prev        // flip one arrow
            prev = curr             // step forward
            curr = next
        }
        return prev                 // prev is the new head
    }
}
5 · Test

Empty list: curr starts as null, so the loop never runs and we return prev, which is null. ✓ Single node: one iteration sets 1.next = null, and we return node 1. ✓ For 1 → 2 → 3 → 4, follow the trace above.

6 · Complexity

Time O(n): each node is visited once. Space O(1): three references, no matter how long the list is. A recursive version is also O(n) time, but it uses O(n) stack space.

Quick check

In the reverse loop, why save curr.next before changing it?

  1. It makes the loop faster
  2. The flip loses the rest
  3. Kotlin requires a copy
  4. It frees the old node

After curr.next = prev, nothing points to the rest of the list anymore. Without the saved copy you can't continue.

Why start from a dummy head node?

  1. Traversal runs much faster
  2. It stores the list length
  3. It marks the list tail
  4. No special head case

With a node before the head, removing or replacing the first real node works the same as for any other node. Return dummy.next.

Slow moves 1 step and fast moves 2. If the list has a cycle, what happens?

  1. Fast eventually meets slow
  2. Fast reaches null first
  3. Slow overtakes fast first
  4. Both stop at the head

Inside the cycle, fast gains one node on slow every step, so it must land on slow eventually. Without a cycle, fast reaches null instead.

Merge Two Sorted Lists Easy

  1. Look at the front node of each list. Which one belongs next in the output?
  2. Start from a dummy node and keep a tail pointer. Attach the smaller front node, then advance that list and the tail.
  3. When one list runs out, the other is already sorted. Attach all of it with a single assignment.

Linked List Cycle Easy

  1. A HashSet of visited nodes works, but it uses O(n) space. Can you get O(1)?
  2. Picture two runners on a circular track, one twice as fast as the other.
  3. Loop while fast and fast.next are both non-null. Compare nodes by identity with ===, not by value. Two different nodes can hold the same number.

Remove Nth Node From End of List Medium

  1. Two passes works: count the length, then walk to the right spot. Can you do it in one pass?
  2. Put two pointers n nodes apart. When the front one reaches the end, where is the back one?
  3. To delete a node you need the node before it. Start both pointers at a dummy head so that removing the first node needs no special case.
