The idea

Linked lists represent linear sequences linked by explicit node references. Because indexing is O(n), solutions rely on pointer manipulation. Two essential techniques are: 1. Sentinel dummy nodes (eliminates special-case null checks for the head), and 2. Fast/slow pointers (detecting cycles and locating midpoints in O(n) time and O(1) space).

Reach for it when you see…

  • Reverse a linked list (or reverse subsegments k at a time)
  • Detect cycle or find cycle start node in O(1) memory
  • Find the middle node of a list in a single pass
  • Merge two or more sorted linked lists

Walkthrough: Reverse Linked List

Given the head of a singly linked list, reverse the list, and return the reversed list.

1 · Clarify

Can head be null? Can the list contain only one node? Yes, 0 <= nodes <= 5000. Reversal must be in-place with O(1) auxiliary space.

2 · Examples

head = [1,2,3,4,5] -> [5,4,3,2,1]. head = [1,2] -> [2,1]. head = [] -> [].

3 · Approach

Maintain three pointers: prev = null, curr = head, and nextTemp. At each node, save nextTemp = curr.next before severing the link. Reverse the pointer: curr.next = prev. Advance pointers: prev = curr, curr = nextTemp. When curr becomes null, prev points to the new head.

Quick check

What primary engineering problem do sentinel dummy nodes (dummy = ListNode(0)) solve?

  1. They allocate double memory to protect against JVM pointer corruption
  2. They eliminate special-case edge handling when modifying or deleting the head node
  3. They allow backward traversal in singly-linked lists like doubly-linked lists
  4. They automatically sort nodes in descending order

A dummy node ensures the new list always has a non-null predecessor, so inserting or deleting at head uses the identical logic as any middle node.

In Floyd's cycle-finding algorithm, fast moves 2 steps while slow moves 1 step. Why are they guaranteed to meet if a cycle exists?

  1. Fast wraps around and stops moving once inside the cycle
  2. Slow accelerates to 3 steps per tick inside the loop
  3. With each step, the distance between fast and slow decreases by exactly 1 modulo cycle length
  4. Because linked lists are bounded to a maximum of 1000 nodes

Relative speed = 2 - 1 = 1 node per iteration. Inside a cycle of length C, the gap shrinks by 1 each step, guaranteeing they meet in at most C steps without skipping over each other.

How do you find the middle of a linked list in a single pass using two pointers?

  1. Count all nodes with slow, then divide the integer counter by 2 with fast
  2. Reverse the first half of the list while simultaneously traversing the second half
  3. Hash each node reference into a set and return the median hash key
  4. Advance slow by 1 step and fast by 2 steps; when fast reaches the end, slow is at the middle

Since fast travels at twice the speed of slow, when fast reaches the tail (null or fast.next == null), slow has traveled exactly half the distance.

Merge Two Sorted Lists Easy

  1. Create a dummy head node and a tail pointer pointing to dummy.
  2. While both l1 and l2 exist, attach the smaller node: tail.next = l1; l1 = l1.next; tail = tail.next.
  3. Attach remaining non-null list: tail.next = l1 ?: l2. Return dummy.next.

Linked List Cycle Easy

  1. Use Floyd's tortoise and hare algorithm.
  2. slow = slow.next, fast = fast.next?.next.
  3. If slow == fast, a cycle exists. If fast or fast.next is null, no cycle exists.
