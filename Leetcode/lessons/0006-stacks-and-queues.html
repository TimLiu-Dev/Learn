The idea

A stack is last in, first out. You can only add to the top or remove from the top. Use it when the item you need next is the one you saw most recently, like the latest unclosed bracket or the last two numbers in an expression.

A queue is first in, first out. Items leave in the order they arrived. You'll use queues heavily for breadth-first search later. In Kotlin, one ArrayDeque does both jobs.

Reach for it when you see…

  • matching or nested pairs: brackets, tags, function calls
  • "undo," "backspace," or "cancel the previous one"
  • evaluating an expression, or a design problem with stack/queue rules

The operations you need

val stack = ArrayDeque<Int>()
stack.addLast(1)                 // push
val top = stack.last()           // peek (throws if empty)
val popped = stack.removeLast()  // pop  (throws if empty)
val empty = stack.isEmpty()      // check this before last() or removeLast()

val queue = ArrayDeque<Int>()
queue.addLast(1)                 // enqueue at the back
val front = queue.removeFirst()  // dequeue from the front

Walkthrough: Valid Parentheses

Given a string of the characters ()[]{}, decide whether every bracket is closed by the right type in the right order.

1 · Clarify

"Does the string contain only bracket characters? Can it be empty? How long can it be?" It contains only the six bracket characters. The length is between 1 and 10⁴.

2 · Examples

"([]{})" → true. "([)]" → false, because the ) arrives while [ is still open. Edge cases: "(" → false (never closed), ")" → false (nothing to close).

3 · Approach

Brute force: repeatedly delete adjacent pairs like "()" until nothing changes. Each pass is O(n), and there can be up to n/2 passes, so O(n²).

Key question: when I see a closer, which opener must it match? The most recent one that is still open. "Most recent" means a stack. Push openers. On a closer, pop and check the type. One pass is O(n) time and O(n) space.

4 · Code 
class Solution {
    fun isValid(s: String): Boolean {
        val openerFor = mapOf(')' to '(', ']' to '[', '}' to '{')
        val stack = ArrayDeque<Char>()               // openers still waiting for a closer
        for (c in s) {
            val opener = openerFor[c]
            if (opener == null) {
                stack.addLast(c)                        // c is an opener: remember it
            } else if (stack.isEmpty() || stack.removeLast() != opener) {
                return false                            // nothing to close, or wrong type
            }
        }
        return stack.isEmpty()                          // leftover openers were never closed
    }
}
5 · Test

Trace "([)]". Push (, push [. Then ) pops [, which isn't (, so return false. ✓

Edge cases: ")" hits a closer with an empty stack, so return false. "(" finishes the loop with ( left on the stack, so return false. ✓

6 · Complexity

Time O(n): each character is pushed or popped at most once. Space O(n): a string of all openers fills the stack.

Quick check

Which problem statement most strongly suggests a stack?

  1. Count how often each value appears
  2. Find two values summing to a target
  3. Match each closer to its latest opener
  4. Find the longest run without repeats

"Latest unmatched item" is the stack signal. The others point to hashing, hashing again, and a sliding window.

You push with addLast. How do you peek at the top of a Kotlin ArrayDeque stack?

  1. stack.last()
  2. stack.first()
  3. stack.peek()
  4. stack.top()

Pushes go on the end, so the top is last(). first() is the bottom. Kotlin's ArrayDeque has no peek() or top(). Those names belong to other languages and libraries.

In Valid Parentheses, the loop ends with ( still on the stack. What do you return?

  1. true: every closer matched
  2. true: no mismatch was seen
  3. false: the input had closers
  4. false: an opener stayed open

An opener left on the stack was never closed, so the string is invalid. That's why the function ends with return stack.isEmpty().

Min Stack Medium

  1. push, pop, and top are easy with one stack. The hard part is getMin in O(1) after some pops.
  2. When an element is pushed, the minimum of the stack at that moment is fixed. It stays the same until that element is popped.
  3. Store that "minimum so far" alongside each element, either in a second stack or as a pair. Then the top always knows the current minimum.

Evaluate Reverse Polish Notation Medium

  1. Evaluate ["2", "1", "+", "3", "*"] by hand. When you reach an operator, which numbers does it use?
  2. Numbers wait on a stack. An operator pops two numbers and pushes the result back.
  3. Order matters for - and /. The first value you pop is the right operand. Kotlin's Int division already truncates toward zero, as the problem requires.

Implement Queue using Stacks Easy

  1. What happens to the order of the items if you pop everything from one stack and push it onto another?
  2. Use two stacks: an "in" stack that takes every push, and an "out" stack that serves pops and peeks.
  3. Only pour "in" into "out" when "out" is empty. Then each element moves at most once. Be ready to explain the amortized complexity this gives.
