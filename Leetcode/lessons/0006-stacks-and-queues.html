The idea

Stacks (Last-In, First-Out) manage nested contexts: parentheses matching, expression evaluation, call stacks, and backtracking state. Queues (First-In, First-Out) preserve arrival order: scheduling, buffer pipelines, and tree/graph breadth-first search. In modern languages, ArrayDeque is the standard implementation for both.

Reach for it when you see…

  • Parentheses, brackets, XML tags, or syntax parsing
  • Reverse Polish Notation or arithmetic expression evaluation
  • Undo/redo history, browser back/forward buttons
  • Layer-by-layer exploration or arrival-order buffers

queue.offer(1);          // enqueue

Walkthrough: Valid Parentheses

Given a string s containing just the characters '(', ')', '{', '}', '[' and ']', determine if the input string is valid.

1 · Clarify

Can s be empty? What if closing brackets arrive before open brackets? Empty string is valid. Brackets must close in exact reverse order of opening.

2 · Examples

s = '()' -> True. s = '()[]{}' -> True. s = '(]' -> False. s = '([)]' -> False.

3 · Approach

When seeing an opening bracket, push its expected closing counterpart onto the stack. When seeing a closing bracket, pop from the stack: if the stack is empty or the popped character does not match, return false immediately. At the end, return true only if the stack is empty.

4 · Code 
class Solution {
    fun isValid(s: String): Boolean {
        val stack = ArrayDeque<Char>()
        for (c in s) {
            when (c) {
                '(' -> stack.addLast(')')
                '{' -> stack.addLast('}')
                '[' -> stack.addLast(']')
                else -> {
                    if (stack.isEmpty() || stack.removeLast() != c) return false
                }
            }
        }
        return stack.isEmpty()
    }
}
class Solution:
    def isValid(self, s: str) -> bool:
        stack = []
        mapping = {'(': ')', '{': '}', '[': ']'}
        for c in s:
            if c in mapping:
                stack.append(mapping[c])
            elif not stack or stack.pop() != c:
                return False
        return not stack
class Solution {
    public boolean isValid(String s) {
        Deque<Character> stack = new ArrayDeque<>();
        for (char c : s.toCharArray()) {
            if (c == '(') stack.push(')');
            else if (c == '{') stack.push('}');
            else if (c == '[') stack.push(']');
            else if (stack.isEmpty() || stack.pop() != c) return false;
        }
        return stack.isEmpty();
    }
}
5 · Test

Trace '([)]': c='(': push ')'. c='[': push ']'. c=')': pop ']' != ')'! Return False. ✓ Trace '()': c='(': push ')'. c=')': pop ')' == ')'. Stack empty at end -> True. ✓

6 · Complexity

Time O(n): each character is pushed and popped at most once. Space O(n): stack stores up to n closing tokens.

Quick check

Why should you use java.util.ArrayDeque rather than java.util.Stack in modern Java interviews?

  1. Stack extends legacy Vector and incurs synchronized method lock overhead
  2. Stack does not support push and pop operations in Java 17+
  3. ArrayDeque runs on the GPU whereas Stack runs on the CPU
  4. ArrayDeque sorts its elements automatically during push

java.util.Stack is a legacy class inheriting from Vector. Its methods are synchronized, incurring thread contention overhead. ArrayDeque is unsynchronized and cache-optimal.

When validating parentheses, what bug occurs if you return true at the end without checking stack.isEmpty()?

  1. Strings with extra closing brackets like ')))' would crash with stack overflow
  2. Strings with unclosed opening brackets like '(((' would be falsely declared valid
  3. Valid strings like '()' would be marked invalid
  4. Memory leak occurs because characters remain referenced on stack

If unclosed openers remain, no mismatch was triggered during iteration. Checking stack.isEmpty() ensures all opened scopes were properly closed.

How does MinStack achieve O(1) getMin() while supporting O(1) push and pop?

  1. Sorts the entire stack in O(1) whenever push is invoked
  2. Scans the entire stack from bottom to top upon each getMin() call
  3. Maintains an auxiliary stack tracking the minimum value at each stack depth
  4. Uses a binary search tree backed by a skip list

By pairing each element with the current minimum (or maintaining a parallel min_stack), the minimum for any stack prefix is accessible in O(1) time.

Min Stack Medium

  1. Store pairs (val, currentMin) on the stack, or maintain a parallel minStack.
  2. When pushing x, newMin = min(x, minStack.peek()).
  3. All operations (push, pop, top, getMin) run in O(1).

Evaluate Reverse Polish Notation Medium

  1. When seeing a number, push it onto the stack.
  2. When seeing an operator (+, -, *, /), pop two operands: b = pop(), a = pop().
  3. Evaluate (a op b) and push the result back onto the stack. Be careful with division truncation in Python vs Java.

Implement Queue using Stacks Easy

  1. Use two stacks: inStack for push operations, and outStack for pop/peek operations.
  2. When popping or peeking, if outStack is empty, transfer all elements from inStack to outStack to reverse their order.
  3. Amortized cost per operation is O(1) because each element moves between stacks at most once.
