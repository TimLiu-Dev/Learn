Prefix Sums

Pay O(n) once, then get the sum of any range with one subtraction.

Your winAnswer any range-sum query in O(1) after one O(n) pass that builds running totals.

The idea

Let prefix[i] be the sum of the first i elements, so prefix[0] = 0. The sum of nums[l..r] is then everything up to r minus everything before l:

sum(l..r) = prefix[r + 1] − prefix[l]

This identity also turns a question about a subarray into a question about a pair of prefixes. Questions about pairs are what the hash map from Session 1 is good at. You'll use that idea in two of the problems below.

Reach for it when you see…

  • many "sum of range [l, r]" queries on an array that doesn't change
  • "count / find subarrays whose sum is k" or "is a multiple of k", especially when values can be negative and a sliding window fails
  • "everything to my left combined with everything to my right", using prefix and suffix totals

The template

// prefix has n + 1 slots: prefix[i] = sum of nums[0 until i], prefix[0] = 0
val prefix = IntArray(nums.size + 1)
for (i in nums.indices) prefix[i + 1] = prefix[i] + nums[i]

// sum of nums[l..r], both ends inclusive, in O(1)
fun rangeSum(l: Int, r: Int) = prefix[r + 1] - prefix[l]

Walkthrough: Range Sum Query – Immutable

Design a class that takes nums once and then answers many sumRange(left, right) calls. Each call returns the sum from left to right, inclusive.

1 · Clarify

"Can the array change after construction? How many queries are there? Are the indices always valid, with left ≤ right? Can values be negative, and can the sum overflow an Int?" The array never changes. There are up to 10⁴ queries. Indices are valid. Values range from −10⁵ to 10⁵ with n ≤ 10⁴, so the largest possible total is 10⁹, which fits in an Int.

2 · Examples

nums = [-2, 0, 3, -5, 2, -1]: sumRange(0, 2) = 1, sumRange(2, 5) = −1, sumRange(0, 5) = −3. Edge case: left == right returns a single element.

3 · Approach

Brute force: loop from left to right on each call. That's O(n) per query, so O(n · q) in total, which is 10⁸ in the worst case.

Better: do the work once in the constructor by building prefix. Then each query is one subtraction. That's O(n) to build, O(1) per query, and O(n) space. Point out the tradeoff out loud: you pay up front so that every query is cheap.

4 · Code 
class NumArray(nums: IntArray) {
    private val prefix = IntArray(nums.size + 1)    // prefix[i] = sum of nums[0 until i]

    init {
        for (i in nums.indices) prefix[i + 1] = prefix[i] + nums[i]
    }

    fun sumRange(left: Int, right: Int): Int = prefix[right + 1] - prefix[left]
}
5 · Test

With [-2, 0, 3, -5, 2, -1], prefix is [0, -2, -2, 1, -4, -2, -3]. sumRange(0, 2) = prefix[3] − prefix[0] = 1 ✓. sumRange(2, 5) = −3 − (−2) = −1 ✓. sumRange(0, 5) = −3 − 0 = −3 ✓. Thanks to the leading 0, a range that starts at index 0 needs no special case.

6 · Complexity

Time: O(n) to build, then O(1) per query, so O(n + q) in total. Space O(n): the prefix array.

Quick check

With prefix[0] = 0, which expression gives the sum of nums[2..4], inclusive?

  1. prefix[4] − prefix[2]
  2. prefix[5] − prefix[2]
  3. prefix[5] − prefix[3]
  4. prefix[4] − prefix[1]

The formula is prefix[r + 1] − prefix[l] = prefix[5] − prefix[2]. Getting this off by one is the most common prefix-sum bug, so check it against a tiny example out loud.

You build the prefix array once and then answer q queries. What is the total time?

  1. O(n · q) in total
  2. O(q log n) in total
  3. O(n²) in total
  4. O(n + q) in total

Building is one O(n) pass and each query is O(1). Brute force would be O(n · q).

Why give prefix n + 1 slots with a leading 0?

  1. Ranges at 0 need no special case
  2. It prevents integer overflow
  3. It makes the build pass faster
  4. It lets you sort the array later

Without the leading 0, sumRange(0, r) would need prefix[-1]. The extra slot stands for "the sum of nothing", which removes that edge case.

Product of Array Except Self Medium

  1. Division isn't allowed. What two quantities multiply together to give answer[i]?
  2. The product of everything to the left of i, times the product of everything to the right of i. Those are prefix and suffix products.
  3. Compute the left products in one forward pass and the right products in one backward pass. Follow-up for O(1) extra space: store the left products in the output array, then sweep from the right with a single running variable.

Subarray Sum Equals K Medium

  1. Values can be negative, so a sliding window won't work (see Session 3's quiz). Start from the O(n²) brute force: fix a start index and extend it with a running sum.
  2. A subarray ending at index r sums to k exactly when some earlier prefix equals currentPrefix − k. Does that remind you of Two Sum?
  3. Keep a HashMap from prefix sum to how many times you've seen it. Seed it with the empty prefix: sum 0, seen once. For each element, count the matches first, then record the current prefix.

Continuous Subarray Sum Medium

  1. When is prefix[r + 1] − prefix[l] a multiple of k? Think about remainders.
  2. It's a multiple of k exactly when the two prefixes have the same remainder mod k. So you're looking for a repeated remainder.
  3. Map each remainder to the earliest index where it appeared, starting with remainder 0 at index −1 for the empty prefix. The subarray needs at least 2 elements, so only accept a match when the gap between indices is at least 2.
