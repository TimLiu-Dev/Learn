Monotonic Stack

Maintain monotonic ordering to find the next greater or smaller element in O(n).

The idea

Finding the 'next element greater than X' naively requires scanning rightwards in O(n) per element, taking O(n²) total. A monotonic stack enforces an invariant (e.g. elements are strictly decreasing). When a larger element arrives, it resolves and pops all smaller pending elements in O(1) amortized time.

Reach for it when you see…

  • Find next greater element or next smaller element
  • Previous greater element or span problems (Stock Spanner)
  • Largest rectangle in a histogram or trapping rain water
  • Removing digits to create smallest/largest number

// Monotonic decreasing stack (stores indices)
val stack = ArrayDeque<Int>()
val result = IntArray(nums.size)
for (i in nums.indices) {
    while (stack.isNotEmpty() && nums[i] > nums[stack.last()]) {
        val prevIdx = stack.removeLast()
        result[prevIdx] = i - prevIdx // resolved by index i!
    }
    stack.addLast(i)
}

stack = [] # stores indices
result = [0] * len(nums)

int[] result = new int[nums.length];
for (int i = 0; i < nums.length; i++) {
    while (!stack.isEmpty() && nums[i] > nums[stack.peek()]) {

        result[prevIdx] = i - prevIdx;

Walkthrough: Daily Temperatures

Given an array of integers temperatures, return an array answer such that answer[i] is the number of days you have to wait after the ith day to get a warmer temperature. If there is no future day for which this is possible, keep answer[i] == 0.

1 · Clarify

Can temperatures contain duplicates? What if no warmer day exists? Answer should be 0 if no warmer day exists. Array length up to 10^5.

2 · Examples

temperatures = [73, 74, 75, 71, 69, 72, 76, 73] -> [1, 1, 4, 2, 1, 1, 0, 0].

3 · Approach

Maintain a monotonic decreasing stack of indices. When inspecting index i with temperature T[i], if T[i] > T[stack.top()], day i is the warmer day for stack.top()! Pop prev = stack.pop() and record ans[prev] = i - prev. Repeat until stack is empty or T[i] <= T[stack.top()], then push i.

4 · Code 
class Solution {
    fun dailyTemperatures(temperatures: IntArray): IntArray {
        val n = temperatures.size
        val ans = IntArray(n)
        val stack = ArrayDeque<Int>() // stores indices
        for (i in 0 until n) {
            while (stack.isNotEmpty() && temperatures[i] > temperatures[stack.last()]) {
                val prev = stack.removeLast()
                ans[prev] = i - prev
            }
            stack.addLast(i)
        }
        return ans
    }
}

6 · Complexity

Time O(n): each index is pushed and popped at most once. Space O(n): stack holds at most n indices in worst case.

Quick check

Why is the monotonic stack approach O(n) time even though a while loop is nested inside the for loop?

  1. The stack capacity is hard-coded to a maximum of 32 items
  2. Popping from a stack takes O(1/n) time using vectorized memory
  3. The inner loop only runs on sorted ascending sequences
  4. Each index is pushed onto the stack exactly once and popped at most once

Every element enters the stack once (n pushes) and leaves at most once (<= n pops). The total number of while loop iterations across all n elements is bounded by n, giving O(n) amortized time.

Why do we push array indices onto the monotonic stack rather than the temperature values themselves?

  1. Indices let you calculate both day distance (i - prev) and retrieve values via nums[idx]
  2. Indices consume 1 byte of memory whereas values consume 8 bytes
  3. Stacks cannot compare duplicate values if elements are stored directly
  4. ArrayDeque in Kotlin only accepts index integers

Storing indices gives you full power: distance calculation (i - prev) and value lookup (nums[stack.top()]) simultaneously.

What invariant is maintained by the stack in Daily Temperatures?

  1. Indices on the stack are always consecutive consecutive integers
  2. Indices on the stack correspond to temperatures in strictly decreasing (or non-increasing) order
  3. The top of the stack is always the global maximum of the entire array
  4. The stack always contains an even number of elements

Any incoming element greater than the top pops the top, maintaining a strictly decreasing chain of unresolved elements.

  3. Push (price, span) and return span.
