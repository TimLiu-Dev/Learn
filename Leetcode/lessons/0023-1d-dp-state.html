The idea

Dynamic Programming applies when a problem exhibits Overlapping Subproblems and Optimal Substructure. The three steps to mastery: 1. State definition: what does dp[i] represent? 2. Recurrence relation: how does dp[i] relate to earlier states (e.g. dp[i-1], dp[i-2])? 3. Base cases & space optimization: if dp[i] only looks back 2 steps, replace the array with two rolling variables.

Reach for it when you see…

  • 'Count number of ways to reach step n'
  • 'Maximum profit without choosing adjacent elements' (House Robber)
  • 'Decode ways', 'Fibonacci numbers'

Pattern templates

// Rolling variables space optimization O(1)
var prev2 = 1 // dp[0]
var prev1 = 1 // dp[1]
for (i in 2..n) {
    val curr = prev1 + prev2
    prev2 = prev1
    prev1 = curr
}
# Rolling variables space optimization O(1)
prev2, prev1 = 1, 1
for i in range(2, n + 1):
    curr = prev1 + prev2
    prev2, prev1 = prev1, curr
// Rolling variables space optimization O(1)
int prev2 = 1, prev1 = 1;
for (int i = 2; i <= n; i++) {
    int curr = prev1 + prev2;
    prev2 = prev1;
    prev1 = curr;
}

Walkthrough: Climbing Stairs

You are climbing a staircase. It takes n steps to reach the top. Each time you can climb 1 or 2 steps. In how many distinct ways can you climb to the top?

1 · Clarify

Can n be 0 or negative? What is the upper bound on n? n is a positive integer up to 45 (fits in 32-bit integer).

2 · Examples

n = 2 → 2 ([1+1], [2]). n = 3 → 3 ([1+1+1], [1+2], [2+1]).

3 · Approach

1. State: dp[i] = number of distinct ways to reach step i.

2. Recurrence: To land on step i, you came from step i-1 (1 step) or step i-2 (2 steps). Therefore: dp[i] = dp[i-1] + dp[i-2].

3. Base cases: dp[1] = 1, dp[2] = 2.

4. Space optimization: Only the previous two values are needed, so use two variables for O(1) memory.

4 · Code 
class Solution {
    fun climbStairs(n: Int): Int {
        if (n <= 2) return n
        var prev2 = 1
        var prev1 = 2
        for (i in 3..n) {
            val curr = prev1 + prev2
            prev2 = prev1
            prev1 = curr
        }
        return prev1
    }
}

5 · Test

n = 1: returns 1 directly. n = 2: returns 2 directly. n = 3: loop runs once: curr = 2 + 1 = 3 → returns 3. n = 4: curr = 3 + 2 = 5 → returns 5. ✓

6 · Complexity

Time O(n): single linear loop from 3 to n. Space O(1): two integer variables.

Quick check

If a DP transition only depends on dp[i - 1] and dp[i - 2], what is the optimal space complexity?

  1. O(n) array table memory space
  2. O(log n) tree recursion stack
  3. O(n²) auxiliary lookup matrix
  4. O(1) space with two variables

We only need to retain the previous two computed states, so two scalar variables eliminate the array allocation.

In House Robber (cannot rob adjacent houses), what is the recurrence relation for dp[i]?

  1. max(dp[i-1], nums[i]+dp[i-2])
  2. dp[i-1] + dp[i-2] + nums[i]
  3. min(dp[i-1], nums[i]+dp[i-2])
  4. max(nums[i], dp[i-1]+dp[i-2])

Either you skip house i (taking dp[i-1]), or you rob house i (taking nums[i] + dp[i-2]).

What is the difference between Top-Down and Bottom-Up Dynamic Programming?

  1. Breadth-first search vs stacks
  2. Memoized recursion vs iteration
  3. Greedy heuristic vs tree search
  4. Unbounded knapsack vs 0/1 array

Top-down uses recursive calls with a memoization table; bottom-up iteratively fills the DP table from base cases up.

Min Cost Climbing Stairs Easy

  1. dp[i] is the minimum cost to reach step i.
  2. dp[i] = min(dp[i-1] + cost[i-1], dp[i-2] + cost[i-2]).
  3. Can be space-optimized to O(1) with two rolling variables.

House Robber Medium

  1. At house i, you either rob it (nums[i] + rob_prev2) or skip it (rob_prev1).
  2. new_rob = max(rob_prev1, nums[i] + rob_prev2).
  3. Update rolling variables in O(1) space.

Decode Ways Medium

  1. Single digit decode: valid if s[i-1] != '0'. Adds dp[i-1].
  2. Two digit decode: valid if '10' <= s[i-2..i-1] <= '26'. Adds dp[i-2].
  3. Base case: dp[0] = 1 (empty string has 1 decode way).
