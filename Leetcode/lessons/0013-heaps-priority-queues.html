The idea

A binary heap maintains the min or max element at the top in O(1) lookup. Adding and removing takes O(log n). For 'top k largest elements', keep a MIN-heap of size k: the smallest of the top k sits at the root, and smaller items get dropped in O(log k).

Reach for it when you see…

  • 'Top K frequent', 'kth smallest / largest element'
  • Continuous stream where you need median or running rankings
  • Merging k sorted lists or streams

Walkthrough: Kth Largest Element in a Stream

Design a class that accepts integers from a stream and maintains the kth largest element.

1 · Clarify

Does k change during execution? What if the stream has fewer than k elements initially? k is fixed at construction. Initial stream will have at least k - 1 elements.

2 · Examples

k = 3, nums = [4, 5, 8, 2]. Add 3 → [4, 5, 8] → 4. Add 5 → [5, 5, 8] → 5. Add 10 → [5, 8, 10] → 5.

3 · Approach

A min-heap of fixed capacity k holds the top k elements seen so far. The root is the kth largest.

When a new number arrives: push it. If heap size exceeds k, pop the minimum. The root peek() is always the kth largest in O(1) lookup and O(log k) add.

4 · Code 
class KthLargest(private val k: Int, nums: IntArray) {
    private val minHeap = java.util.PriorityQueue<Int>()

    init {
        for (x in nums) add(x)
    }

    fun add(`val`: Int): Int {
        minHeap.offer(`val`)
        if (minHeap.size > k) minHeap.poll()
        return minHeap.peek()
    }
}
import heapq

class KthLargest:
    def __init__(self, k: int, nums: list[int]):
        self.k = k
        self.heap = []
        for x in nums:
            self.add(x)

    def add(self, val: int) -> int:
        heapq.heappush(self.heap, val)
        if len(self.heap) > self.k:
            heapq.heappop(self.heap)
        return self.heap[0]
class KthLargest {
    private final int k;
    private final PriorityQueue<Integer> minHeap;

    public KthLargest(int k, int[] nums) {
        this.k = k;
        this.minHeap = new PriorityQueue<>();
        for (int x : nums) add(x);
    }

    public int add(int val) {
        minHeap.offer(val);
        if (minHeap.size() > k) minHeap.poll();
        return minHeap.peek();
    }
}

6 · Complexity

Time: O(n log k) to initialize, O(log k) per add call. Space O(k): the heap holds at most k elements.

Quick check

To maintain the K largest elements seen so far, which heap structure should you use?

  1. A max-heap of capacity k
  2. A min-heap of capacity k
  3. A binary search min-heap
  4. A linked priority queue

A min-heap keeps the smallest of the top k elements at the root, making eviction of non-top elements O(log k).

What is the time complexity of building a binary heap from an array of n numbers in-place?

  1. O(1) constant heapify
  2. O(log n) tree heapify
  3. O(n) linear heapify
  4. O(n log n) sorting pass

Bottom-up heap construction (heapify) takes O(n) linear time, whereas inserting n elements one-by-one is O(n log n).

In Python, what does calling heapq.heappop(heap) return from a standard populated heap?

  1. The maximum stored element
  2. The latest inserted item
  3. The median list element
  4. The minimum stored element

Python's heapq implements a min-heap by default; heappop removes and returns the smallest item.
