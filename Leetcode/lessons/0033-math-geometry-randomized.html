The idea

Walkthrough: Happy Number

A happy number is defined by repeatedly replacing the number with the sum of the squares of its digits until it reaches 1, or loops endlessly in a cycle that does not include 1. Return true if n is a happy number.

1 · Clarify

Can n be 1? Can digits exceed 32-bit integer bounds during squaring? Yes, n >= 1 (positive integer). For 32-bit ints (up to ~2*10^9, 10 digits), max sum of squares is 10 * 81 = 810, so values shrink immediately and either hit 1 or cycle within [1..810].

2 · Examples

n = 19 → 1² + 9² = 82 → 8² + 2² = 68 → 6² + 8² = 100 → 1 → true. n = 2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 (cycle) → false.

3 · Approach

Insight: This is an implicit linked list where next(x) = sumOfSquares(x). Instead of O(log n) / O(1) hash set storage, apply Floyd's Fast & Slow Pointers in strict O(1) space: advance slow by 1 step and fast by 2 steps until fast == 1 or slow == fast.

4 · Code 
class Solution {
    private fun nextNum(x: Int): Int {
        var n = x; var total = 0
        while (n > 0) {
            val d = n % 10
            total += d * d
            n /= 10
        }
        return total
    }

    fun isHappy(n: Int): Boolean {
        var slow = n
        var fast = nextNum(n)
        while (fast != 1 && slow != fast) {
            slow = nextNum(slow)
            fast = nextNum(nextNum(fast))
        }
        return fast == 1
    }
}

6 · Complexity

Quick check

In Detect Squares, how do you count axis-aligned squares for query point (qx, qy) in O(N) time?

  1. Check all point triples
  2. Sort points by distance
  3. Group points by line slope
  4. Match diagonal corner points

Given query (qx, qy) and one candidate diagonal corner (px, py) where |qx - px| == |qy - py| > 0, the other two corners (qx, py) and (px, qy) are uniquely fixed and looked up in a frequency map in O(1).

In Reservoir Sampling over a stream of unknown length, what probability selects the i-th item (0-indexed)?

  1. Probability one over i plus one
  2. Constant fifty percent odds
  3. Fixed one over total length
  4. Always replace with new item

At step i (0-indexed), keeping the new item with probability 1/(i+1) yields an exact uniform 1/N distribution after N items without knowing N beforehand.

In Random Pick with Weight, why do we build a prefix-sum array and run binary search?

  1. Keep weights sorted ascending
  2. Avoid all floating-point math
  3. Sample proportional intervals fast
  4. Guarantee strict O(1) lookup

Prefix sums partition [1..total] into segments proportional to each weight, so picking a random integer in [1..total] and binary searching takes O(log n) time and O(n) space.

Detect Squares Medium

  1. Store point frequencies in a map count[(x, y)] (plus a list of added points or x-bucket).
  2. On count(qx, qy), iterate over candidate diagonal corners (px, py).
  3. Skip if abs(qx - px) != abs(qy - py) or qx == px (zero area); add count[(qx, py)] * count[(px, qy)] (multiplied by count[(px, py)] if iterating unique keys).

Random Pick with Weight Medium Meta favorite

  1. Build prefix sums: prefix[i] = prefix[i-1] + w[i].
  2. Pick a uniform integer target in [1, prefix[-1]] (or float in [0, prefix[-1])).
  3. Binary search for the leftmost index where prefix[mid] >= target.

Multiply Strings Medium

  1. You cannot convert the whole strings to BigInteger / int directly.
  2. Product of num1[i] and num2[j] lands at positions i + j (carry) and i + j + 1 (digit) in an array of size m + n.
  3. Accumulate sums + carries from right to left, then strip leading zeros.
