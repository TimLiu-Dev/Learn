Sliding Window

Keep track of one contiguous stretch. Grow it on the right and shrink it on the left.

Your winFind the best contiguous subarray or substring in O(n) by growing and shrinking a window.

The idea

A sliding window is two pointers that both move the same way, left and right, marking the contiguous range [left, right]. The right pointer adds one element per step. The left pointer drops elements only when the window breaks the rule. Neither pointer ever moves backward, so each element enters once and leaves at most once. That's O(n) in total, even though there's a loop inside a loop.

Reach for it when you see…

  • "longest / shortest / maximum contiguous subarray or substring such that…"
  • a window of fixed size k, like "every block of k elements"
  • a rule you can update in O(1) as elements enter and leave, such as a sum or letter counts

Two shapes this pattern takes

// 1. Variable size: grow every step, shrink while invalid.
//    Example: longest subarray with sum <= target (non-negative values)
var left = 0
var windowSum = 0
var best = 0
for (right in nums.indices) {
    windowSum += nums[right]                // grow: add nums[right]
    while (windowSum > target) {            // shrink while the window breaks the rule
        windowSum -= nums[left]
        left++
    }
    best = maxOf(best, right - left + 1)    // [left, right] is valid: record it
}

// 2. Fixed size k: add the new element, drop the one that fell off
val k = 3
var sum = 0
for (right in nums.indices) {
    sum += nums[right]
    if (right >= k) sum -= nums[right - k]
    if (right >= k - 1) { /* window nums[right-k+1 .. right] is full */ }
}

Walkthrough: Best Time to Buy and Sell Stock

prices[i] is a stock's price on day i. Buy on one day and sell on a later day. Return the maximum profit, or 0 if no trade makes money.

1 · Clarify

"Exactly one buy and one sell? Must the sell come after the buy? What if prices only go down? Can there be just one day?" One transaction. The sell must come strictly after the buy. If no trade makes a profit, return 0. There's at least one day.

2 · Examples

[7, 1, 5, 3, 6, 4] → 5 (buy at 1, sell at 6). [7, 6, 4, 3, 1] → 0. Edge case: [5] → 0, because you can't sell on the same day you buy.

3 · Approach

Brute force: try every (buy, sell) pair with buy < sell. That's O(n²) time and O(1) space. With n up to 10⁵ it's too slow.

Window view: buy is the left edge and sell is the right edge. Slide sell forward one day at a time. If today's price is lower than the buy price, every later sale is better off buying today, so jump buy to sell. Otherwise, check the profit. One pass is O(n) time and O(1) space.

4 · Code 
class Solution {
    fun maxProfit(prices: IntArray): Int {
        var buy = 0                                   // left edge: cheapest day so far
        var best = 0
        for (sell in 1 until prices.size) {           // right edge moves every step
            if (prices[sell] < prices[buy]) buy = sell    // cheaper day: restart the window
            else best = maxOf(best, prices[sell] - prices[buy])
        }
        return best
    }
}
5 · Test

[7, 6, 4, 3, 1]: each day is cheaper than the last, so buy keeps moving and best stays 0. ✓ [5]: 1 until 1 is empty, so the loop doesn't run and we return 0. ✓ [2, 4, 1]: best becomes 2, and the later drop to 1 doesn't erase an earlier profit. ✓

6 · Complexity

Time O(n): sell visits each day once. Space O(1): two indices and one running best.

Quick check

In a variable-size window, when does left move?

  1. On every single step
  2. While the window is invalid
  3. While the window is valid
  4. Only once, at the very end

right grows the window every step. left shrinks it only until the window follows the rule again. Then you record the answer.

The template has a while loop inside a for loop. What is the total time?

  1. O(n²) due to nesting
  2. O(n log n) on average
  3. O(n) amortized in total
  4. O(k) for every window

left only moves forward and never passes n, so the inner loop runs at most n times in total. Add n steps of right and you get O(n). Say "amortized" in the interview.

"Count subarrays that sum to k" with negative numbers allowed. Why does a sliding window fail?

  1. Shrinking may not reduce the sum
  2. The window grows far too large
  3. Strings would need to be sorted
  4. The indices would go negative

The window works because shrinking always makes the sum smaller. With negative numbers, removing an element can make the sum go up, so you can't tell which way to move. Session 4, prefix sums, handles this case.

Longest Substring Without Repeating Characters Medium

  1. This uses the variable-size shape. What makes a window "invalid" here?
  2. A character appears twice inside it. Keep track of which characters are in the window, using a set or a count per character.
  3. When s[right] is already in the window, move left forward and remove characters until it isn't. Ask a clarifying question about the character set, because it decides between IntArray(128) and a map.

Longest Repeating Character Replacement Medium

  1. A window is valid if at most k changes turn it into a single repeated letter. How many changes does a given window need?
  2. It needs the window length minus the count of its most frequent letter.
  3. Keep letter counts in an IntArray(26), plus the highest count you've seen. Shrink from the left while length − maxCount > k.

Permutation in String Medium

  1. A permutation of s1 inside s2 is a substring of s2 with exactly the same letter counts as s1. That's the anagram idea from Session 1.
  2. Its length must be s1.length, so use the fixed-size shape.
  3. Keep two IntArray(26) counts and compare them at each step. Comparing 26 numbers is O(1). Once that works, can you track how many of the 26 letters match instead of comparing the whole array?
