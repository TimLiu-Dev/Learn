Arrays & Hashing

Spend memory to save time: remember what you've already seen.

Your winTurn an O(n²) "check every pair" solution into a single O(n) pass using a hash map.

Warm-up from memory

The idea

Many brute-force solutions rescan the array to answer "have I seen X?" or "how many Xs are there?". A HashSet or HashMap answers those questions in O(1) on average. Remember as you go, and a nested loop becomes a single loop.

Reach for it when you see…

  • "find a pair / complement" or "does a duplicate exist"
  • "count how many times", "most frequent", "anagram"
  • "group items that share some property"

Three shapes this pattern takes

// 1. Seen-before: a set or map of what you've already passed
val seen = HashSet<Int>()
for (x in nums) {
    if (x in seen) { /* found a repeat */ }
    seen.add(x)
}

// 2. Frequency count. For lowercase letters an IntArray(26) is faster than a map.
val freq = IntArray(26)
for (c in s) freq[c - 'a']++

// 3. Group by a key: items with the same key end up in the same list
val groups = HashMap<String, MutableList<String>>()
for (w in words) groups.getOrPut(keyOf(w)) { mutableListOf() }.add(w)

Walkthrough: Two Sum

Given nums and target, return the indices of the two numbers that add up to target.

1 · Clarify

"Is there exactly one answer? Can I use the same element twice? Can the numbers be negative? Does the order of the two indices matter?" The problem says there is exactly one answer, the same element can't be used twice, negatives are allowed, and any order is fine.

2 · Examples

[2, 7, 11, 15] with target 9 → [0, 1]. Edge case: [3, 3] with target 6 → [0, 1]. Duplicate values are allowed, but the two indices must be different.

3 · Approach

Brute force: try every pair. That's O(n²) time and O(1) space. With n up to 10⁴ it would pass, but the interviewer will ask whether you can do better.

Key question: when I'm standing on x, the only partner that works is target − x. So I'm really asking "have I already seen target − x, and at which index?" That's a hash map from value to index. One pass is O(n) time and O(n) space.

4 · Code 
class Solution {
    fun twoSum(nums: IntArray, target: Int): IntArray {
        val indexOf = HashMap<Int, Int>()        // value -> index where we saw it
        for ((i, x) in nums.withIndex()) {
            val j = indexOf[target - x]
            if (j != null) return intArrayOf(j, i)
            indexOf[x] = i                          // record AFTER checking
        }
        return intArrayOf()                         // unreachable: one answer is guaranteed
    }
}
5 · Test

Trace [3, 3] with target 6. At i=0 we need 3, and the map is empty, so we store 3→0. At i=1 we need 3, find it at index 0, and return [0, 1]. ✓

Why record after checking? Try [3, 2, 4] with target 6. If we stored 3→0 first, then at i=0 we'd find our own 3 and return [0, 0], using one element twice.

6 · Complexity

Time O(n): one pass, and each map operation is O(1) on average. Space O(n): in the worst case the map holds every element.

Quick check

In Two Sum, what does the hash map store?

  1. index → value seen so far
  2. value → index seen so far
  3. value → count seen so far
  4. pair → sum seen so far

We look up a value (the complement) and need its index back, so the key is the value.

A string contains only lowercase letters. What's the cleanest way to count its letters in Kotlin?

  1. HashMap<String, Int>
  2. MutableList<Char>
  3. Array<Int?>(26)
  4. IntArray(26)

There are only 26 possible keys, so index with c - 'a'. This uses fixed O(1) space and avoids boxing.

What does this pattern usually cost you in exchange for faster time?

  1. O(n) extra space
  2. O(n²) extra time
  3. A sorted input
  4. Changing the input

This is the classic time–space tradeoff. Mention it out loud in interviews: "this uses O(n) extra memory to get O(n) time."

Valid Anagram Easy

  1. If the lengths differ, can they be anagrams?
  2. Two strings are anagrams exactly when every letter appears the same number of times in both.
  3. One count array is enough: add 1 for each letter of s and subtract 1 for each letter of t. What must the array look like at the end?

Group Anagrams Medium

  1. This is shape 3, "group by key". What is identical about "eat", "tea", and "ate"?
  2. You need a key that every anagram maps to. One option is the word's letters sorted. Another is its 26 letter counts.
  3. Build a HashMap<String, MutableList<String>> with getOrPut. Then compare the cost of the two key choices for words of length k.

Top K Frequent Elements Medium

  1. Step one is shape 2: count frequencies.
  2. Sorting the distinct values by count works in O(n log n), which is a fine first answer. The follow-up asks for something better than O(n log n).
  3. A frequency can't be larger than n. What if you made an array of buckets indexed by frequency?
