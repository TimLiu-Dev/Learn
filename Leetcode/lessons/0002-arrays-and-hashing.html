The idea

Brute-force solutions rescan arrays to answer 'have I seen X?' or 'how many Xs exist?'. A hash set or map answers in average O(1). By recording items as you traverse, nested loops collapse into single-pass O(n) solutions.

Reach for it when you see…

  • Find a pair or complement: target - current
  • Detect duplicates or check if element occurred previously
  • Anagram detection or frequency distribution counting
  • Grouping elements sharing an invariant signature (e.g. sorted characters)

Walkthrough: Two Sum

Given an array of integers nums and an integer target, return indices of the two numbers such that they add up to target.

1 · Clarify

Can the same element be used twice? Is there always exactly one solution? Can numbers be negative? Problem constraints confirm exactly one solution, negatives allowed, same index cannot be used twice.

2 · Examples

nums = [2, 7, 11, 15], target = 9 -> [0, 1]. nums = [3, 2, 4], target = 6 -> [1, 2]. nums = [3, 3], target = 6 -> [0, 1].

3 · Approach

Brute force: Check all pairs (i, j) with i < j. Takes O(n²) time and O(1) space.

Hash map approach: As we iterate through index i with value nums[i], we require complement = target - nums[i]. We query the hash map for complement. If present, we return [seen[complement], i]. Otherwise, store seen[nums[i]] = i. One pass: O(n) time and O(n) space.

4 · Code 
class Solution {
    fun twoSum(nums: IntArray, target: Int): IntArray {
        val indexOf = HashMap<Int, Int>()
        for (i in nums.indices) {
            val complement = target - nums[i]
            indexOf[complement]?.let { return intArrayOf(it, i) }
            indexOf[nums[i]] = i
        }
        return intArrayOf()
    }
}

Quick check

In Two Sum, why must you check whether the complement exists BEFORE inserting the current number into the hash map?

  1. To avoid using the exact same element twice for target = 2 * num
  2. Because hash maps cannot overwrite existing identical keys
  3. To prevent integer overflow in the subtraction step
  4. Because dictionary lookup is O(n) after insertion

If you insert first, a test case like nums=[3,2,4], target=6 would see its own 3 at index 0 and incorrectly return [0, 0].

For counting lowercase English letter frequencies (a–z), why is IntArray(26) or int[26] superior to HashMap<Char, Int>?

  1. HashMap cannot store characters that repeat multiple times
  2. Array index arithmetic is O(1) worst-case with zero object boxing overhead
  3. Arrays automatically sort characters alphabetically on write
  4. HashMap requires O(n²) space for 26 unique alphabet keys

A 26-element primitive array eliminates object allocation, garbage collection, and hashing overhead, operating with strict cache locality.

What algorithmic tradeoff is being made when replacing an O(n²) double loop with an O(n) hash map pass?

  1. Sacrificing output correctness on unsorted integer arrays
  2. Increasing worst-case time to O(n³) while keeping space O(1)
  3. Trading O(n) memory to reduce time complexity from O(n²) to O(n)
  4. Requiring the array to be pre-sorted in ascending order

This is the canonical time-space tradeoff: allocating O(n) auxiliary space enables single-pass O(n) execution.

Group Anagrams Medium

  1. What signature is identical across 'eat', 'tea', and 'ate'?
  2. Either sort characters (O(k log k)) or create a count tuple (O(k)) as map key.
  3. Use HashMap> to collect matches.

Top K Frequent Elements Medium

  1. Count frequencies with hash map or Counter.
  2. Can you bucket by frequency from 0 to n to beat O(n log n)?
  3. Traverse bucket array backwards from n down to 1 to gather top k elements.
