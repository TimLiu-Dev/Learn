Binary Search

Halve the search space every step: O(log n) discovery on monotonic ranges.

The idea

When a search space is sorted or satisfies a monotonic boolean predicate (False, False, ..., True, True), checking the midpoint eliminates half of the remaining candidates. In O(log n) steps, a billion items are pruned down to 1 in about 30 comparisons. Always calculate mid as l + (r - l) / 2 to avoid integer overflow.

Reach for it when you see…

  • Sorted array or sorted matrix
  • Searching for minimum or maximum value satisfying a condition (search on answer)
  • Problem statement specifies O(log n) time requirement
  • Rotated sorted array or mountain array peak finding

Walkthrough: Binary Search

Given an array of integers nums which is sorted in ascending order, and an integer target, write a function to search target in nums. If target exists, then return its index. Otherwise, return -1.

1 · Clarify

Are elements unique? Is the array guaranteed to be sorted? What if nums is empty? Constraints guarantee sorted unique integers, length up to 10^4.

2 · Examples

nums = [-1,0,3,5,9,12], target = 9 -> 4. nums = [-1,0,3,5,9,12], target = 2 -> -1.

3 · Approach

Initialize boundaries l = 0 and r = len(nums) - 1. While l <= r, compute midpoint mid = l + (r - l) / 2. If nums[mid] == target, return mid. If nums[mid] < target, search right: l = mid + 1. If nums[mid] > target, search left: r = mid - 1. If loop exits, target is absent: return -1.

Quick check

Why is mid = l + (r - l) / 2 preferred over mid = (l + r) / 2 in Java and Kotlin?

  1. Because division by 2 is executed in hardware floating point without it
  2. Because (l + r) / 2 causes off-by-one errors on odd array lengths
  3. To prevent 32-bit signed integer overflow when l + r exceeds 2^31 - 1
  4. Compiler optimizations only recognize the subtraction formulation

In Java/Kotlin/C++, if l and r are large (e.g. 1.5 billion), l + r overflows to a negative integer, causing an ArrayIndexOutOfBoundsException.

What property must a search space satisfy for binary search to be applicable?

  1. Every element in the search space must be an even integer
  2. The array length must be an exact power of two (2, 4, 8, 16...)
  3. All elements must be stored in a linked list structure
  4. Monotonicity: elements or condition evaluations must change direction at most once

Binary search requires monotonicity: knowing whether condition(mid) is true or false must definitively rule out all elements either to the left or to the right.

In Search in Rotated Sorted Array (LeetCode 33), what crucial observation allows O(log n) search?

  1. At least one half (left or right) of the array is always strictly sorted
  2. The pivot element is always situated at index n/2
  3. Rotated arrays can always be un-rotated in O(1) time
  4. Binary search must be preceded by an O(n) linear scan

Splitting a rotated sorted array at mid always produces at least one cleanly sorted half. You check whether target lies within that sorted range to pick which side to keep.

Search in Rotated Sorted Array Medium

  1. Check which half is sorted: if nums[l] <= nums[mid], left half is sorted.
  2. If left half is sorted, check if target falls in nums[l]..nums[mid].
  3. Otherwise right half is sorted: check if target falls in nums[mid]..nums[r].

Find Minimum in Rotated Sorted Array Medium

  1. Compare nums[mid] with nums[r].
  2. If nums[mid] > nums[r], the minimum must lie in the right half: l = mid + 1.
  3. Else the minimum is at mid or left: r = mid.

Koko Eating Bananas Medium

  1. Search space is speed k from 1 to max(piles).
  2. Monotonic condition: if speed k finishes within h hours, any speed > k also finishes.
  3. Binary search on k using integer ceiling division: hours = sum((pile + k - 1) // k).
