The idea

If the data is sorted, one comparison with the middle element tells you which half can't contain the answer. Throw that half away and repeat. A million elements take about 20 steps, so the cost is O(log n).

Most binary search bugs are off-by-one errors. To avoid them, pick one invariant and keep it true on every step:

Invariant: if the target exists, it is inside nums[lo..hi]. The loop runs while (lo <= hi), which means "the range isn't empty". Each step either finds the target or moves lo to mid + 1 or hi to mid - 1. Once lo > hi, the range is empty and the target isn't there.

Compute the middle as lo + (hi - lo) / 2. The shorter (lo + hi) / 2 breaks when lo + hi is larger than Int.MAX_VALUE (about 2.1 × 10⁹): the sum overflows to a negative number. That can happen when you search over a range of answers up to 10⁹. hi - lo never overflows.

Reach for it when you see…

  • a sorted array, or a sorted array that was rotated
  • "find the minimum or maximum value that still works"
  • an answer that is a number in a big range, plus a fast way to check whether one guess works

Binary search on the answer

Sometimes there is no sorted array to search. Instead, the answer lies in a range such as 1 to 10⁹, and you can check a guess x. If the checks look like false, false, …, true, true as x grows, then binary search finds the first true. Koko Eating Bananas below works this way.

// 1. Classic: index of target in a sorted array, or -1
fun indexOf(nums: IntArray, target: Int): Int {
    var lo = 0
    var hi = nums.size - 1
    while (lo <= hi) {
        val mid = lo + (hi - lo) / 2
        when {
            nums[mid] == target -> return mid
            nums[mid] < target -> lo = mid + 1
            else -> hi = mid - 1
        }
    }
    return -1
}

// 2. On the answer: smallest x in [lo, hi] where ok(x) is true.
//    Assumes ok is false...false, true...true across the range.
fun firstTrue(lo0: Int, hi0: Int, ok: (Int) -> Boolean): Int {
    var lo = lo0
    var hi = hi0
    var best = hi0
    while (lo <= hi) {
        val mid = lo + (hi - lo) / 2
        if (ok(mid)) { best = mid; hi = mid - 1 }   // mid works; look for a smaller one
        else lo = mid + 1                           // mid fails; go bigger
    }
    return best
}

Walkthrough: Binary Search

Given a sorted array nums and a target, return the index of target, or -1 if it isn't there. The required time is O(log n).

1 · Clarify

"Sorted ascending? Can there be duplicates? What do I return if the target is missing?" The problem says it's sorted ascending, all values are unique, and a missing target returns -1. It also says n can be 1.

2 · Examples

[-1, 0, 3, 5, 9, 12] with target 9 → 4. Edge cases: target 2 is missing → -1. A single element [5] with target 5 → 0.

3 · Approach

Brute force: scan left to right. That's O(n) time, but the problem asks for O(log n).

Better: the array is sorted, so comparing the target with the middle element rules out half the range. Keep the invariant "if the target exists, it's in nums[lo..hi]". The range halves each step, so this is O(log n) time and O(1) space.

4 · Code 
class Solution {
    fun search(nums: IntArray, target: Int): Int {
        var lo = 0
        var hi = nums.size - 1                  // if target exists, it's in nums[lo..hi]
        while (lo <= hi) {                      // the range is not empty
            val mid = lo + (hi - lo) / 2        // can't overflow, unlike (lo + hi) / 2
            when {
                nums[mid] == target -> return mid
                nums[mid] < target -> lo = mid + 1   // target is right of mid
                else -> hi = mid - 1                  // target is left of mid
            }
        }
        return -1                               // range is empty: not found
    }
}
5 · Test

Trace [-1, 0, 3, 5, 9, 12] with target 9. lo=0, hi=5, mid=2 (3). 3 is smaller, so lo=3. Then mid=4 (9), which matches, so we return 4. ✓

Single element [5], target 5: lo=0, hi=0, mid=0, match, return 0. ✓ With while (lo < hi) instead, the loop would never run and we'd return -1 by mistake. That is why the invariant matters.

6 · Complexity

Time O(log n): the range halves on every step. Space O(1): only three integer variables.

Quick check

Why write mid = lo + (hi - lo) / 2 instead of (lo + hi) / 2?

  1. It rounds the midpoint up
  2. It is faster to compute
  3. lo + hi can overflow Int
  4. It handles negative values

The two are equal in math, but lo + hi can go past Int.MAX_VALUE and wrap to a negative number. hi - lo always fits.

With while (lo <= hi), when does the loop end without finding the target?

  1. When lo moves past hi
  2. When mid reaches index 0
  3. When lo becomes equal to hi
  4. After exactly log n steps

lo > hi means the range nums[lo..hi] is empty. When lo == hi there is still one element left to check.

In Koko Eating Bananas, speed k lets Koko finish in time. What else do you know?

  1. Every slower speed also fails
  2. Every speed is too slow
  3. Only speed k itself works
  4. Every faster speed also works

Eating faster never takes more hours. So the checks run false, …, false, true, …, true, which is the shape that binary search on the answer needs.

Find Minimum in Rotated Sorted Array Medium

  1. After a rotation, at least one half around mid is still sorted. Which single comparison tells you where the "drop" is?
  2. Compare nums[mid] with nums[hi]. If nums[mid] > nums[hi], which side must the minimum be on?
  3. Here mid itself might be the minimum, so don't skip past it. Use while (lo < hi) with hi = mid (not mid - 1). When the loop stops, lo == hi is the answer.
