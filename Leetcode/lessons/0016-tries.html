Warm-up from memory

Close this page and recall: what is the space complexity of inserting a word of length L into a Trie with alphabet size 26?

The idea

A Trie (prefix tree) is an n-ary tree where each edge represents a character (or bit). Nodes share common prefixes. Searching or inserting a word of length L takes O(L) time regardless of how many millions of words are stored. In 2027 Big Tech interviews, Bitwise Tries (branching on bits 0 and 1) are a Google/Meta favorite for Maximum XOR queries.

Reach for it when you see…

  • 'Autocomplete', 'prefix search', 'startsWith'
  • Word search on a grid with a dictionary of words (Word Search II)
  • 'Find two numbers with maximum XOR' (Bitwise Trie)

1 · Clarify

Are inputs only lowercase English letters? Can words be empty? Yes: lowercase 'a'-'z', word length >= 1.

2 · Examples

insert('apple'), search('apple') → true, search('app') → false, startsWith('app') → true, insert('app'), search('app') → true.

3 · Approach

A TrieNode contains an array of 26 child pointers and an isWord boolean.

  • insert(word): traverse down, creating missing nodes. Mark end node isWord = true.
  • search(word): traverse down. Return true if path exists AND curr.isWord == true.
  • startsWith(prefix): traverse down. Return true if path exists (regardless of isWord).

class Trie() {
    private class Node {
        val children = arrayOfNulls<Node>(26)
        var isWord = false
    }
    private val root = Node()

    fun insert(word: String) {
        var curr = root
        for (c in word) {
            val i = c - 'a'
            if (curr.children[i] == null) curr.children[i] = Node()
            curr = curr.children[i]!!
        }
        curr.isWord = true
    }

    fun search(word: String): Boolean {
        val node = findNode(word)
        return node != null && node.isWord
    }

    fun startsWith(prefix: String): Boolean = findNode(prefix) != null

    private fun findNode(str: String): Node? {
        var curr = root
        for (c in str) {
            curr = curr.children[c - 'a'] ?: return null
        }
        return curr
    }
}
class Trie:
    def __init__(self):
        self.root = {}

    def insert(self, word: str) -> None:
        curr = self.root
        for c in word:
            if c not in curr:
                curr[c] = {}
            curr = curr[c]
        curr['#'] = True  # word end sentinel

    def search(self, word: str) -> bool:
        curr = self.root
        for c in word:
            if c not in curr: return False
            curr = curr[c]
        return '#' in curr

    def startsWith(self, prefix: str) -> bool:
        curr = self.root
        for c in prefix:
            if c not in curr: return False
            curr = curr[c]
        return True
class Trie {
    private static class Node {
        Node[] children = new Node[26];
        boolean isWord;
    }
    private final Node root = new Node();

    public void insert(String word) {
        Node curr = root;
        for (char c : word.toCharArray()) {
            int i = c - 'a';
            if (curr.children[i] == null) curr.children[i] = new Node();
            curr = curr.children[i];
        }
        curr.isWord = true;
    }

    public boolean search(String word) {
        Node node = find(word);
        return node != null && node.isWord;
    }

    public boolean startsWith(String prefix) {
        return find(prefix) != null;
    }

    private Node find(String s) {
        Node curr = root;
        for (char c : s.toCharArray()) {
            curr = curr.children[c - 'a'];
            if (curr == null) return null;
        }
        return curr;
    }
}

insert('apple'): creates 'a'→'p'→'p'→'l'→'e'(isWord=true). search('app'): finds 'p' but isWord=false → returns false. startsWith('app'): path exists → returns true. ✓

6 · Complexity

Time: O(L) for insert, search, and startsWith where L is string length. Space O(N × L × 26): worst-case memory for storing distinct characters.

class Trie() {
    private val root = TrieNode()
    fun insert(word: String) {
        var curr = root
        for (c in word) {
            val idx = c - 'a'
            if (curr.children[idx] == null) curr.children[idx] = TrieNode()
            curr = curr.children[idx]!!
        }
        curr.isEnd = true
    }
    fun search(word: String): Boolean {
        var curr = root
        for (c in word) {
            val next = curr.children[c - 'a'] ?: return false
            curr = next
        }
        return curr.isEnd
    }
    fun startsWith(prefix: String): Boolean {
        var curr = root
        for (c in prefix) {
            val next = curr.children[c - 'a'] ?: return false
            curr = next
        }
        return true
    }
}

class Trie {
    private static class Node {
        Node[] children = new Node[26];
        boolean isEnd = false;
    }
    private final Node root = new Node();
    public void insert(String word) {
        Node curr = root;
        for (char c : word.toCharArray()) {
            int idx = c - 'a';
            if (curr.children[idx] == null) curr.children[idx] = new Node();
            curr = curr.children[idx];
        }
        curr.isEnd = true;
    }
    public boolean search(String word) {
        Node curr = root;
        for (char c : word.toCharArray()) {
            curr = curr.children[c - 'a'];
            if (curr == null) return false;
        }
        return curr.isEnd;
    }
    public boolean startsWith(String prefix) {
        Node curr = root;
        for (char c : prefix.toCharArray()) {
            curr = curr.children[c - 'a'];
            if (curr == null) return false;
        }
        return true;
    }
}

Quick check

What differentiates Trie startsWith(prefix) from search(word)?

  1. startsWith is an O(1) operation
  2. startsWith sorts the children
  3. startsWith does not check isWord
  4. startsWith reverses input chars

startsWith only requires that the path exists in the Trie, while search also checks that isWord is true.

For small lowercase alphabets, why is TrieNode[26] faster than a HashMap in Java?

  1. Reduces total heap allocation
  2. Allows dynamic binary search
  3. Auto-compacts deleted letters
  4. Avoids pointer hashing overhead

Direct array indexing c - 'a' has no hash collision, autoboxing, or entry node overhead.

How does a Bitwise Trie find the maximum XOR of a number x with stored numbers?

  1. Greedily branch to opposite bit
  2. Branch always to bit 1 first
  3. Branch always to bit 0 first
  4. Sort stored numbers in array

To maximize 1s in XOR, greedily traverse the opposite bit (1 ^ 0 = 1). If opposite bit exists, take it; else take same bit.

Design Add and Search Words Data Structure Medium

  1. A '.' character can match any of the 26 children.
  2. When '.' is encountered, branch into a recursive DFS across all 26 non-null children.
  3. Standard letters follow a single child pointer without recursion.

Word Search II Hard High frequency

  1. Doing grid DFS for each word individually causes TLE. Build a Trie of all dictionary words first.
  2. Traverse the grid with DFS while simultaneously walking down the Trie.
  3. Pruning: remove words from Trie once found, and prune dead-end leaf nodes.

Maximum XOR of Two Numbers in an Array Medium

  1. Represent each 32-bit integer as a 31-bit binary path in a 0/1 Bitwise Trie.
  2. For each number, query the Trie: at bit b, prefer moving to 1 - b to maximize XOR.
  3. Runs in O(31 * n) = O(n) time.
