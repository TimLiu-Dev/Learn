Warm-up from memory

Close this page and recall: what is the difference between Unbounded Knapsack (reuse items) and 0/1 Knapsack (each item at most once) in loop ordering?

The idea

In multi-choice DP, each state dp[i] considers a loop over all possible choices (e.g. all coin denominations or all earlier indices). In Knapsack problems: Unbounded Knapsack iterates capacity forward (1 to amount); 0/1 Knapsack iterates capacity backward (amount down to coin) to prevent reusing the same element.

Walkthrough: Coin Change

You are given an integer array coins and an integer amount. Return the fewest number of coins that you need to make up that amount, or -1 if impossible.

1 · Clarify

Can you use coins multiple times? What if amount is 0? Can coins contain 0 or negatives? Unlimited coins per denomination. If amount = 0, answer is 0. Coins are positive integers.

2 · Examples

coins = [1, 2, 5], amount = 11 → 3 (5 + 5 + 1). coins = [2], amount = 3 → -1.

3 · Approach

1. State: dp[i] = minimum coins to make amount i.

2. Recurrence: For each coin, if i - coin >= 0, then dp[i] = min(dp[i], dp[i - coin] + 1).

3. Base case: dp[0] = 0. Initialize all other entries to amount + 1 (represents ∞).

4. If dp[amount] > amount, return -1; else return dp[amount].

4 · Code

    fun coinChange(coins: IntArray, amount: Int): Int {
        val dp = IntArray(amount + 1) { amount + 1 }

                }
            }
        }
        return if (dp[amount] > amount) -1 else dp[amount]
    }
}

Quick check

In 0/1 Knapsack with a 1D DP table, why must the capacity loop run backwards from max_W down to w?

  1. Sorts items in ascending weights
  2. Avoids negative integer underflow
  3. Prevents using the same item twice
  4. Reduces time complexity to O(W)

Looping backwards ensures that dp[c - w] represents the state from the previous item, not the current one.

In Coin Change, why do we initialize the DP table with amount + 1 instead of Integer.MAX_VALUE?

  1. Saves half the allocated memory
  2. Allows faster dual-pivot sorting
  3. Matches maximum allowed recursion
  4. Prevents integer overflow in + 1

If dp[i - coin] is Integer.MAX_VALUE, adding + 1 overflows to Integer.MIN_VALUE, corrupting the minimum.

What is the optimal time complexity to find the Longest Increasing Subsequence (LIS)?

  1. O(n log n) using binary search
  2. O(n) linear single pass scan
  3. O(n²) standard double loop only
  4. O(2ⁿ) complete subset search

Patience sorting / tails array with binary search (bisect) finds LIS in O(n log n) time.

Word Break Medium

  1. dp[i] = true if s[0 until i] can be segmented into dictionary words.
  2. dp[i] = true if there exists some j < i where dp[j] == true and s[j until i] is in wordDict.
  3. Store wordDict in a HashSet for O(1) substring lookups.

Longest Increasing Subsequence Medium

  1. O(n²) approach: dp[i] = max(dp[j] + 1) for all j < i with nums[j] < nums[i].
  2. O(n log n) approach: maintain 'tails' array where tails[len] is smallest tail of all increasing subsequences of length len.
  3. Use binary search (bisect_left) on tails for each num.

Partition Equal Subset Sum Medium

  1. If sum(nums) is odd, partitioning is impossible → return false.
  2. Target is sum(nums) / 2. Problem reduces to 0/1 Knapsack: can any subset sum to target?
  3. Boolean dp[target + 1], loop target down to num: dp[t] = dp[t] || dp[t - num].
