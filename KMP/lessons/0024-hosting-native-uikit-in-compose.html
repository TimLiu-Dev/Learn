Hosting Native UIKit & SwiftUI Views inside Compose

Use UIKitView to embed native Apple Maps, camera previews, and Apple Pay buttons inside shared Compose screens.

1. The Why & Architectural Mental Model

While Compose Multiplatform renders almost everything with Skia, certain features require real platform-native views:

  • Apple Maps (MKMapView) for native 3D vector map rendering and Apple MapKit routing.
  • Camera Previews (AVCaptureVideoPreviewLayer).
  • Apple Pay Buttons (PKPaymentButton) mandated by App Store guidelines.

In iosMain, Compose provides UIKitView, which inserts a real native UIView into the Compose layout hierarchy, tracking position, clipping, and touch dispatching.

2. Production Code Examples

Embedding Apple MKMapView in iosMain

package com.pulsesync.ui.map

import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier
import androidx.compose.ui.interop.UIKitView
import platform.MapKit.MKMapView

@Composable
actual fun PlatformMapView(modifier: Modifier) {
    UIKitView(
        factory = {
            MKMapView().apply {
                showsUserLocation = true
            }
        },
        modifier = modifier,
        update = { mapView ->
            // Update map state on recomposition
        }
    )
}

3. Production Pitfalls & Anti-Patterns

Pitfall: Performance Cost of Excessive UIKitViews
Each UIKitView requires synchronizing the Skia Metal graphics pipeline with the UIKit CoreAnimation layer tree. Avoid scattering dozens of tiny UIKitViews inside a scrolling list. Use UIKitView only for complex hardware/system views like Maps or Camera.
