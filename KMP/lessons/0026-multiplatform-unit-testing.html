Multiplatform Unit Testing with kotlin.test

Write deterministic unit tests for ViewModels, Use Cases, and Repositories running across JVM and Kotlin/Native runners.

1. The Why & Architectural Mental Model

Testing in Kotlin Multiplatform is powered by kotlin.test, which unifies test assertions across backends:

  • On the JVM (Android), kotlin.test delegates to JUnit.
  • On Kotlin/Native (iOS), kotlin.test delegates to Apple's native test runner.

Tests are placed in commonTest. Running ./gradlew check or ./gradlew allTests executes your test suite across both the JVM and native iOS simulator targets.

2. Production Code Examples

Unit Testing a Use Case in commonTest

package com.pulsesync.domain

import kotlin.test.*
import kotlinx.coroutines.test.runTest

class GetIncidentsUseCaseTest {

    // Test Fake (Zero Mocking framework needed)
    private val fakeRepository = object : IncidentRepository {
        val testData = mutableListOf("Server Outage", "Database Latency")
        override suspend fun getActiveIncidents() = testData
    }

    private val useCase = GetIncidentsUseCase(fakeRepository)

    @Test
    fun shouldReturnActiveIncidentsFromRepository() = runTest {
        val result = useCase()
        assertEquals(2, result.size)
        assertEquals("Server Outage", result[0])
    }
}

3. Production Pitfalls & Anti-Patterns

Pitfall: Using Mockito or MockK in commonTest
Libraries like Mockito and MockK rely on dynamic JVM bytecode generation (cglib/bytebuddy). They cannot compile on Kotlin/Native (iOS). Instead, use Test Fakes (clean interface implementations) or multiplatform mocking libraries (Mockative).
