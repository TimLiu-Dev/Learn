The Multiplatform Architecture Mindset

Adopt Clean Architecture, define strict layer boundaries, and understand what to share vs. what to keep platform-native.

1. The Why & Architectural Mental Model

In high-performing KMP organizations, teams don't share code for the sake of sharing code. They follow the 80/20 Architectural Rule:

  • Share (80-90%): Domain Use Cases, Repositories, Database caching, HTTP networking, Serialization, Reactive State machines (ViewModels/MVI).
  • Specialize (10-20%): Platform hardware (Bluetooth, Camera, Biometrics), native push notification handlers, and system-level widgets.

Clean Architecture enforces dependency inversion: the Domain Layer (commonMain) has zero dependencies on Android SDK or Apple UIKit/Foundation.

2. Production Code Examples

Clean Architecture Domain Interface in commonMain

package com.pulsesync.domain.model

data class Incident(
    val id: String,
    val title: String,
    val severity: Severity,
    val timestamp: Long
)

enum class Severity { LOW, MEDIUM, HIGH, CRITICAL }

// Domain Repository Contract (Zero platform dependencies)
interface IncidentRepository {
    fun observeIncidents(): kotlinx.coroutines.flow.Flow>
    suspend fun resolveIncident(id: String): Result
}

3. Production Pitfalls & Anti-Patterns

Pitfall: Leaking Android Context into Domain Models
Never pass android.content.Context into domain use cases or shared repositories. If an operation requires a file path or system handle, wrap it behind a platform-agnostic interface injected via DI.
