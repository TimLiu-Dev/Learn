Ktor 3.x Client Architecture & Platform Engines

Build an enterprise HTTP client with Ktor 3.x, platform-specific engines (OkHttp & Darwin), and auto content negotiation.

1. The Why & Architectural Mental Model

In KMP, networking is unified using Ktor 3.x. Unlike Retrofit (which is JVM-only), Ktor provides a multiplatform HTTP client engine abstraction:

  • Android Target: Uses the OkHttp engine, benefiting from Android's connection pooling and HTTP/2 multiplexing.
  • iOS Target: Uses the Darwin engine, backed by Apple's native NSURLSession. This ensures the app respects iOS system proxy settings, VPN tunnels, and cellular low-data modes.

We declare an expect fun createHttpClient(): HttpClient or use dependency injection to supply the engine.

2. Production Code Examples

Factory Function with Platform Engine in commonMain

package com.pulsesync.network

import io.ktor.client.*
import io.ktor.client.engine.*
import io.ktor.client.plugins.contentnegotiation.*
import io.ktor.client.plugins.logging.*
import io.ktor.serialization.kotlinx.json.*
import kotlinx.serialization.json.Json

fun createKtorClient(engine: HttpClientEngine): HttpClient {
    return HttpClient(engine) {
        install(ContentNegotiation) {
            json(Json {
                ignoreUnknownKeys = true
                prettyPrint = false
                isLenient = true
            })
        }
        install(Logging) {
            level = LogLevel.INFO
            logger = Logger.DEFAULT
        }
    }
}

3. Production Pitfalls & Anti-Patterns

Pitfall: Using CIO Engine on iOS in Production
Ktor provides a pure-Kotlin engine called CIO (Coroutine I/O). While it works on iOS, it bypasses Apple's native NSURLSession, meaning system VPN configurations, custom corporate certificates, and cellular network constraints will not be respected. Always use Darwin on Apple targets!
