Design Systems, Theming & Platform Adaptivity

Construct responsive Material 3 design systems that adapt dynamically to dark mode and platform aesthetics.

1. The Why & Architectural Mental Model

A multiplatform design system must look natural on both Android and iOS. While Android users expect Material 3 ripples and bottom sheets, iOS users expect smooth spring physics, subtle blurs, and Cupertino-style dialogs.

Key design system pillars in Compose Multiplatform:

  • Material 3 Theme Tokenization: Centralize ColorScheme, Typography, and Shapes in commonMain.
  • Dark Mode Adaptivity: Automatically react to isSystemInDarkTheme() across Android and iOS.
  • Platform Adaptive Components: Create wrappers (e.g. AdaptiveAlertDialog, AdaptiveProgressIndicator) that render Material 3 on Android and Cupertino-inspired designs on iOS.

2. Production Code Examples

Theme Definition in commonMain

package com.pulsesync.ui.theme

import androidx.compose.foundation.isSystemInDarkTheme
import androidx.compose.material3.*
import androidx.compose.runtime.Composable
import androidx.compose.ui.graphics.Color

private val DarkColors = darkColorScheme(
    primary = Color(0xFF818CF8),
    background = Color(0xFF0F172A),
    surface = Color(0xFF1E293B)
)

private val LightColors = lightColorScheme(
    primary = Color(0xFF4F46E5),
    background = Color(0xFFF8FAFC),
    surface = Color(0xFFFFFFFF)
)

@Composable
fun PulseSyncTheme(
    darkTheme: Boolean = isSystemInDarkTheme(),
    content: @Composable () -> Unit
) {
    val colorScheme = if (darkTheme) DarkColors else LightColors
    MaterialTheme(
        colorScheme = colorScheme,
        typography = Typography(),
        content = content
    )
}

3. Production Pitfalls & Anti-Patterns

Pitfall: Hardcoding Hex Color Literals Inside Composables
Never write Modifier.background(Color(0xFF121212)) inside screen composables. Always reference semantic tokens like MaterialTheme.colorScheme.surface. Hardcoded colors break dark mode support and prevent unified branding updates.
