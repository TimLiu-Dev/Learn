Compose Multiplatform Core & Skia Rendering Pipeline

Understand how Compose Multiplatform renders declarative UI across Android and iOS via the Skia graphics engine.

1. The Why & Architectural Mental Model

Compose Multiplatform (CMP) allows sharing 100% of UI code between Android and iOS. However, their underlying rendering engines differ:

  • On Android: Compose renders directly via the Android platform Canvas and interacts with native Android View trees.
  • On iOS: JetBrains embeds Skia (Google's high-performance 2D graphics library, compiled to Metal on iOS). Compose renders pixels onto a Metal-accelerated CAMetalLayer inside a native UIViewController.

Because Skia renders identically on both platforms, UI components, custom Canvas drawings, and animations look and behave with pixel-perfect consistency.

2. Production Code Examples

Shared Composable Screen in commonMain

package com.pulsesync.ui

import androidx.compose.foundation.layout.*
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import androidx.compose.ui.unit.dp

@Composable
fun IncidentStatusBadge(severity: String, isResolved: Boolean) {
    Surface(
        color = if (isResolved) MaterialTheme.colorScheme.primaryContainer 
                else MaterialTheme.colorScheme.errorContainer,
        shape = MaterialTheme.shapes.small
    ) {
        Row(modifier = Modifier.padding(horizontal = 8.dp, vertical = 4.dp)) {
            Text(
                text = if (isResolved) "RESOLVED" else "CRITICAL: $severity",
                style = MaterialTheme.typography.labelSmall
            )
        }
    }
}

3. Production Pitfalls & Anti-Patterns

Pitfall: Hardcoding Android-Specific DP Assumptions
While Modifier.padding(16.dp) works across both platforms, remember that iOS devices have physical top safe areas (the Dynamic Island and notch) and bottom home indicator bars. Always use Modifier.windowInsetsPadding(WindowInsets.safeDrawing) to avoid clipping!
