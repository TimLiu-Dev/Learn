Key-Value Storage & Multiplatform Settings

Persist user preferences, feature flags, and UI configurations using Multiplatform Settings and DataStore.

1. The Why & Architectural Mental Model

Not all data belongs in a relational SQLite database. Simple user preferences (e.g. Dark Mode enabled, last sync timestamp, analytics opt-in) require lightweight key-value persistence.

In KMP, Multiplatform Settings (by Russell Wolf) is the industry standard:

  • On Android, it delegates to SharedPreferences.
  • On iOS, it delegates to NSUserDefaults.
  • It provides synchronous and observable (Flow-based) APIs through ObservableSettings.

2. Production Code Examples

Type-Safe Preference Repository

package com.pulsesync.data.settings

import com.russhwolf.settings.Settings
import com.russhwolf.settings.get
import com.russhwolf.settings.set

class AppPreferences(private val settings: Settings) {
    companion object {
        private const val KEY_DARK_MODE = "dark_mode_enabled"
        private const val KEY_LAST_SYNC = "last_sync_timestamp"
    }

    var isDarkModeEnabled: Boolean
        get() = settings[KEY_DARK_MODE, false]
        set(value) { settings[KEY_DARK_MODE] = value }

    var lastSyncTimestamp: Long
        get() = settings[KEY_LAST_SYNC, 0L]
        set(value) { settings[KEY_LAST_SYNC] = value }
}

3. Production Pitfalls & Anti-Patterns

Pitfall: Storing Cryptographic Passwords in NSUserDefaults / SharedPreferences
NSUserDefaults and standard SharedPreferences store data in unencrypted plaintext on the device filesystem. Never store user authentication tokens, private encryption keys, or passwords here. Use SecureStorage (Keychain/Keystore) as covered in Lesson 06!
