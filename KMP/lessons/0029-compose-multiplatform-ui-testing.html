Compose Multiplatform UI Testing

Author cross-platform UI tests using Compose UI test matchers, semantics assertions, and simulated user touch gestures.

1. The Why & Architectural Mental Model

In Compose, UI testing does not inspect raw pixels or platform View hierarchies. Instead, it inspects the Semantics Tree:

  • Every composable (Button, Text, TextField) publishes semantics (e.g. text content, click actions, test tags).
  • Compose UI Test runners find elements using matchers (hasText("Submit"), hasTestTag("login_button")).
  • Gestures (performClick(), performTextInput()) simulate real user behavior.
  • Assertions (assertIsDisplayed(), assertTextEquals("...")) verify visual and accessible state.

2. Production Code Examples

Cross-Platform Compose UI Test

package com.pulsesync.ui

import androidx.compose.ui.test.*
import kotlin.test.*

class IncidentItemUiTest {

    @OptIn(ExperimentalTestApi::class)
    @Test
    fun shouldDisplayIncidentTitleAndResolveOnTap() = runComposeUiTest {
        var isResolved = false

        setContent {
            IncidentRow(
                title = "Database Outage",
                isResolved = isResolved,
                onResolveClick = { isResolved = true }
            )
        }

        // 1. Verify text is visible
        onNodeWithText("Database Outage").assertIsDisplayed()

        // 2. Perform tap gesture
        onNodeWithText("RESOLVE").performClick()

        // 3. Verify state updated
        assertTrue(isResolved)
    }
}

3. Production Pitfalls & Anti-Patterns

Pitfall: Relying on Fragile Hardcoded Strings
If your UI is localized into multiple languages, tests matching hasText("Cancel") will break when running under a Spanish or German locale. Use Modifier.testTag("btn_cancel") and onNodeWithTag("btn_cancel") for locale-independent UI assertions!
