Navigation in Compose Multiplatform

Master type-safe navigation, backstack preservation, and deep linking with Jetpack Navigation Compose Multiplatform.

1. The Why & Architectural Mental Model

In modern Compose Multiplatform, Google's official Jetpack Navigation Compose has been ported to KMP. It provides:

  • Type-Safe Routes: In Kotlin 2.x, routes are defined using @Serializable objects/classes rather than raw URL strings.
  • Automatic Backstack Handling: Supports the Android system back button, predictive back gestures, and iOS edge-swipe back navigation.
  • ViewModel Scoping: Automatically scopes ViewModels to navigation graph backstack entries.

2. Production Code Examples

Type-Safe Navigation Graph in commonMain

package com.pulsesync.navigation

import androidx.compose.runtime.Composable
import androidx.navigation.compose.*
import kotlinx.serialization.Serializable

@Serializable
sealed interface Route {
    @Serializable data object IncidentList : Route
    @Serializable data class IncidentDetail(val incidentId: String) : Route
}

@Composable
fun AppNavHost() {
    val navController = rememberNavController()

    NavHost(navController = navController, startDestination = Route.IncidentList) {
        composable {
            IncidentListScreen(onIncidentClick = { id ->
                navController.navigate(Route.IncidentDetail(id))
            })
        }
        composable { backStackEntry ->
            val detail: Route.IncidentDetail = backStackEntry.toRoute()
            IncidentDetailScreen(incidentId = detail.incidentId, onBack = {
                navController.popBackStack()
            })
        }
    }
}

3. Production Pitfalls & Anti-Patterns

Pitfall: Passing Heavy Domain Models Through Routes
Do not pass large data classes as navigation arguments. Navigation arguments are serialized into route URLs. Pass only lightweight primitive IDs (e.g. incidentId: String) and have the destination ViewModel load the data from the local database.
