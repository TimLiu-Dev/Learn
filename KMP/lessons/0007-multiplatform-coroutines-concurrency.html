Multiplatform Coroutines & Concurrency

Master structured concurrency across JVM and Kotlin/Native, lifecycle cancellation, and multiplatform dispatchers.

1. The Why & Architectural Mental Model

In Kotlin Multiplatform, asynchronous code is powered by kotlinx.coroutines. Since Kotlin 1.9+, Kotlin/Native features the modern new memory model, meaning objects can be shared between threads without freezing or complex worker boundaries.

Key Coroutine rules in KMP:

  • Dispatchers.Main: Binds to Android Looper on Android and Apple Grand Central Dispatch (GCD) Main Queue on iOS.
  • Dispatchers.Default: CPU-bound background thread pool across all platforms.
  • Dispatchers.IO: Officially available across both JVM and Native (backed by background GCD queues on Apple targets).
  • Structured Concurrency: CoroutineScopes must be tied to lifecycles (e.g. ViewModel or lifecycle scope) to cancel background tasks when screens exit.

2. Production Code Examples

Structured Concurrency Worker in commonMain

package com.pulsesync.sync

import kotlinx.coroutines.*

class IncidentSyncWorker(
    private val scope: CoroutineScope = CoroutineScope(SupervisorJob() + Dispatchers.Default)
) {
    fun startSync(action: suspend () -> Unit): Job {
        return scope.launch {
            try {
                action()
            } catch (e: CancellationException) {
                // Cooperative cancellation: rethrow to allow scope shutdown
                throw e
            } catch (e: Exception) {
                println("Sync failed safely: ${e.message}")
            }
        }
    }

    fun cancel() {
        scope.cancel()
    }
}

3. Production Pitfalls & Anti-Patterns

Pitfall: Swallowing CancellationException
Never catch generic Throwable or Exception without rethrowing CancellationException. Swallowing cancellation breaks Kotlin Coroutines' cooperative cancellation model, causing memory leaks and zombie background workers.
