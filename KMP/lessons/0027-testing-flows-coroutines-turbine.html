Testing Flows & Coroutines with Turbine

Test reactive StateFlow emissions, debounce delays, and error states deterministically with Cash App's Turbine.

1. The Why & Architectural Mental Model

Testing asynchronous Flow streams by collecting into a list can lead to race conditions, hanging tests, or missing emissions. Turbine (by Cash App) solves this with a clean, sequential testing DSL:

flow.test {
    assertEquals(Item1, awaitItem())
    assertEquals(Item2, awaitItem())
    awaitComplete()
}

Turbine runs on both JVM and Native, making it the industry standard for testing KMP ViewModels and reactive repositories.

2. Production Code Examples

Testing ViewModel State Transitions with Turbine

package com.pulsesync.presentation

import app.cash.turbine.test
import kotlin.test.*
import kotlinx.coroutines.flow.flowOf
import kotlinx.coroutines.test.runTest

class IncidentViewModelTest {

    @Test
    fun shouldEmitLoadingThenContentState() = runTest {
        val flow = flowOf("Incident 1", "Incident 2")

        flow.test {
            assertEquals("Incident 1", awaitItem())
            assertEquals("Incident 2", awaitItem())
            awaitComplete()
        }
    }
}

3. Production Pitfalls & Anti-Patterns

Pitfall: Unconsumed Events in Turbine
Turbine enforces strict assertion completeness: if your flow emits an item that you do not assert via awaitItem() or cancelAndIgnoreRemainingEvents(), Turbine will intentionally fail your test to prevent silent unhandled emissions!
