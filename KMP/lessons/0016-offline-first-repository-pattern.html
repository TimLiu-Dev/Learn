The Offline-First Repository Pattern

Build a Single-Source-of-Truth synchronization engine that streams cache instantly and updates from network in background.

1. The Why & Architectural Mental Model

In high-grade mobile engineering, the app must never display an empty white screen or blocking spinner if data exists on the device. We achieve this with the Single Source of Truth (SSOT) pattern:

  1. The UI only observes the local database (Room / SQLDelight Flow).
  2. When a screen opens, cached data is rendered instantly (0ms latency).
  3. A background coroutine fetches fresh data from the network API (Ktor).
  4. Fresh data is written directly into the local database.
  5. The database automatically emits the updated list to the UI Flow.

2. Production Code Examples

Offline-First Repository Implementation

package com.pulsesync.data.repository

import com.pulsesync.data.local.IncidentDao
import com.pulsesync.data.remote.IncidentApiClient
import kotlinx.coroutines.flow.*

class OfflineFirstIncidentRepository(
    private val localDao: IncidentDao,
    private val remoteApi: IncidentApiClient
) {
    // 1. Single Source of Truth: UI observes local database
    fun streamIncidents(): Flow> {
        return localDao.observeAll().map { entities ->
            entities.map { it.toDomain() }
        }
    }

    // 2. Background Sync: Fetch from network and write to database
    suspend fun syncWithServer(): Result {
        return try {
            val remoteData = remoteApi.fetchIncidents()
            localDao.upsertAll(remoteData.map { it.toEntity() })
            Result.success(Unit)
        } catch (e: Exception) {
            Result.failure(e)
        }
    }
}

3. Production Pitfalls & Anti-Patterns

Pitfall: Clearing Cache on Network Failure
If a network request fails (e.g. offline mode, airplane mode, subway tunnel), do not clear or overwrite the local database cache! The app should silently retain cached data and expose a non-intrusive offline indicator to the user.
