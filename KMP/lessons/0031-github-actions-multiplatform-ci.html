GitHub Actions Multiplatform Matrix CI/CD

Automate dual-platform builds: cross-compiling Android AABs and iOS XCFrameworks using GitHub Actions matrix runners.

1. The Why & Architectural Mental Model

In modern engineering teams, pull requests cannot be merged without automated CI verification. In KMP, a production pipeline requires a matrix strategy:

  • Linux Runner (ubuntu-latest): Runs Android unit tests, Android lint, and compiles Android APKs/AABs (cost-effective, fast).
  • macOS Runner (macos-latest): Required for compiling Apple targets! Compiles Kotlin/Native iOS frameworks (SharedKit.xcframework), runs iOS simulator tests, and builds iOS IPAs.
  • Gradle Dependency Caching: Uses actions/setup-java and gradle/actions/setup-gradle to cache Gradle dependencies across CI runs.

2. Production Code Examples

Production .github/workflows/kmp-ci.yml

name: KMP CI Pipeline

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  check-and-test:
    name: Build & Test (${{ matrix.os }})
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        include:
          - os: ubuntu-latest
            task: check assembleDebug
          - os: macos-latest
            task: iosSimulatorArm64Test assembleSharedKitXCFramework

    steps:
      - uses: actions/checkout@v4

      - name: Set up JDK 17
        uses: actions/setup-java@v4
        with:
          distribution: 'temurin'
          java-version: '17'

      - name: Setup Gradle Cache
        uses: gradle/actions/setup-gradle@v3

      - name: Run Multiplatform Tasks
        run: ./gradlew ${{ matrix.task }} --scan

3. Production Pitfalls & Anti-Patterns

Pitfall: Running iOS Compilation on Linux Runners
Kotlin/Native Apple targets (iosArm64, iosSimulatorArm64) can only link into Apple frameworks on macOS runners because the link phase invokes the Xcode toolchain (Clang, ld64, codesign). Attempting to build iOS frameworks on Ubuntu will fail with an Xcode missing error.
