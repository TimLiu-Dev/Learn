Compile-Time DI with Kotlin-Inject

Explore the compile-time, zero-reflection alternative to Koin: Kotlin-Inject (Dagger for KMP).

1. The Why & Architectural Mental Model

While Koin is simple and popular, it resolves dependencies at runtime (service locator style). If a dependency is missing, Koin crashes at runtime when a screen is opened.

For teams seeking compile-time safety (similar to Dagger/Anvil on Android), kotlin-inject (by Eva Tatarka) is the multiplatform answer:

  • 100% compile-time verified via KSP.
  • Missing dependencies fail at build time, preventing runtime crashes in production.
  • Generates pure Kotlin dependency graphs with zero reflection overhead.

2. Production Code Examples

Kotlin-Inject Component Graph in commonMain

package com.pulsesync.di

import me.tatarka.inject.annotations.*

@Inject
class GetIncidentsUseCase(private val repository: IncidentRepository) {
    suspend operator fun invoke() = repository.getActiveIncidents()
}

@Component
abstract class ApplicationComponent {
    // Abstract property: kotlin-inject generates the implementation
    abstract val getIncidentsUseCase: GetIncidentsUseCase

    @Provides
    fun provideRepository(): IncidentRepository {
        return IncidentRepositoryImpl()
    }
}

3. Production Pitfalls & Anti-Patterns

Pitfall: Circular Dependencies in Compile-Time Graphs
Unlike Koin (which uses lazy lookup), compile-time DI graphs with circular dependencies (Class A requires Class B, Class B requires Class A) will cause KSP compilation to fail immediately. Structure your domain layers using strict unidirectional dependencies.
