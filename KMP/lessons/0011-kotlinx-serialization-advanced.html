Kotlinx.Serialization & Advanced Data Parsing

Master polymorphic JSON decoding, custom date/time serializers, and robust parsing of unknown or missing API fields.

1. The Why & Architectural Mental Model

In multiplatform development, we cannot use reflection-based parsers like Gson or Jackson because Kotlin/Native does not support full runtime Java reflection. Instead, we use kotlinx.serialization, which generates serialization logic at compile-time via a compiler plugin.

Key production techniques:

  • ignoreUnknownKeys = true: Prevents client crashes when backend APIs introduce new fields.
  • Custom Serializers: Used for parsing types without native support (such as ISO-8601 timestamps or UUIDs).
  • Polymorphic Deserialization: Handling heterogeneous event feeds using sealed classes tagged with a "type" discriminator.

2. Production Code Examples

Polymorphic Event Stream Parsing

package com.pulsesync.model

import kotlinx.serialization.*
import kotlinx.serialization.json.*

@Serializable
sealed interface ServerEvent {
    @Serializable
    @SerialName("incident_created")
    data class IncidentCreated(val id: String, val title: String) : ServerEvent

    @Serializable
    @SerialName("incident_resolved")
    data class IncidentResolved(val id: String, val resolvedAt: Long) : ServerEvent
}

val jsonConfig = Json {
    ignoreUnknownKeys = true
    classDiscriminator = "event_type" // Matches backend JSON discriminator
}

3. Production Pitfalls & Anti-Patterns

Pitfall: Omitting ignoreUnknownKeys
By default, Json { } has ignoreUnknownKeys = false. If your backend adds a single new field to an API response, your app will immediately crash with a SerializationException. Always configure ignoreUnknownKeys = true in production!
