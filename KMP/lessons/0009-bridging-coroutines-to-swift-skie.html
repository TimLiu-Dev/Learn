Bridging Kotlin Coroutines to Swift with SKIE

Eliminate unwieldy completion blocks in Swift and bridge Kotlin StateFlow to Swift AsyncSequence and @Observable.

1. The Why & Architectural Mental Model

By default, Kotlin/Native's Objective-C export converts suspending functions into legacy completion handlers:

// Default Kotlin/Native export in Swift:
viewModel.fetchData(completionHandler: { data, error in ... })

Moreover, Kotlin StateFlow and sealed interfaces lose their exhaustiveness and reactivity in Swift. SKIE (by Touchlab) is the industry-standard compiler plugin that fixes this:

  • Converts suspend fun directly into Swift async/await.
  • Converts StateFlow<T> into Swift AsyncSequence and integrates with SwiftUI's @Observable.
  • Translates Kotlin sealed interfaces into exhaustive native Swift enums.

2. Production Code Examples

1. Enable SKIE in gradle/libs.versions.toml and build.gradle.kts

// libs.versions.toml
[plugins]
skie = { id = "co.touchlab.skie", version = "0.9.3" }

// shared/build.gradle.kts
plugins {
    alias(libs.plugins.kotlin.multiplatform)
    alias(libs.plugins.skie) // Enables SKIE code generation
}

2. Consuming Kotlin StateFlow in SwiftUI

import SwiftUI
import SharedKit

struct IncidentListView: View {
    @StateObject var viewModel = ObservableIncidentViewModel()

    var body: some View {
        List(viewModel.state.incidents, id: \.id) { incident in
            Text(incident.title)
        }
        .task {
            // SKIE generates Swift async sequence observation:
            for await state in viewModel.uiState {
                viewModel.state = state
            }
        }
    }
}

3. Production Pitfalls & Anti-Patterns

Pitfall 1: Cancellation Across the Swift/Kotlin Boundary
When consuming a Kotlin coroutine via Swift's .task { } modifier, canceling the Swift Task must cooperatively cancel the underlying Kotlin coroutine. SKIE handles this automatically, but raw Objective-C completion handlers will leave background Kotlin jobs running forever!
Pitfall 2: ARC vs. GC Cross-Runtime Retain Cycles
Swift uses Automatic Reference Counting (ARC) while Kotlin/Native uses tracing Garbage Collection (GC). If a Swift class holds a strong reference to a Kotlin object and passes a closure (capturing self) into a Kotlin callback, a cross-runtime cycle is created that neither ARC nor GC can break. Always use [weak self] in Swift closures passed to Kotlin!
