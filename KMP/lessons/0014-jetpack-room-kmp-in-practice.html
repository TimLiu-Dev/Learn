Jetpack Room KMP in Practice

Construct entities, DAOs, reactive Flow queries, and multiplatform database builders with Room KMP.

1. The Why & Architectural Mental Model

Google's official port of Room to Kotlin Multiplatform brings the familiar Android Jetpack database experience to iOS. In KMP, the architecture consists of:

  1. @Entity data classes in commonMain defining database tables.
  2. @Dao interfaces in commonMain exposing suspending queries and reactive Flow<List<T>> observables.
  3. @Database class in commonMain inheriting from RoomDatabase.
  4. An expect fun getDatabaseBuilder(): RoomDatabase.Builder<AppDatabase> supplying the platform database file path and BundledSQLiteDriver.

2. Production Code Examples

Room Database in commonMain

package com.pulsesync.data.local

import androidx.room.*
import kotlinx.coroutines.flow.Flow

@Entity(tableName = "incidents")
data class IncidentEntity(
    @PrimaryKey val id: String,
    val title: String,
    val severity: String,
    val timestamp: Long
)

@Dao
interface IncidentDao {
    @Query("SELECT * FROM incidents ORDER BY timestamp DESC")
    fun observeAll(): Flow>

    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun upsert(incident: IncidentEntity)
}

@Database(entities = [IncidentEntity::class], version = 1)
abstract class AppDatabase : RoomDatabase() {
    abstract fun incidentDao(): IncidentDao
}

3. Production Pitfalls & Anti-Patterns

Pitfall: Schema Export Directory Not Set for KSP
Room KMP requires KSP to export schema JSON files for migration verification. In your build.gradle.kts, configure room { schemaDirectory("$projectDir/schemas") } to avoid compilation warnings and enable safe schema migrations.
