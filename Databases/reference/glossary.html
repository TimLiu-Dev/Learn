Canonical Database Glossary (2027 Senior Bar)

Compressed terminology adhered to across all 18 lessons and the PulseLedger Capstone. Designed for quick review and interview prep.

Core Terms A–Z

TermDefinition & Engineering SignificanceSeen In
3VL (Three-Valued Logic)SQL boolean logic with TRUE, FALSE, and UNKNOWN (caused by NULL). WHERE drops UNKNOWN rows.L01
ANN (Approximate Nearest Neighbor)Vector index search (e.g., HNSW, IVFFlat) trading tiny recall loss for sub-10ms latency at millions of embeddings.L17
B+TreeBalanced disk-paged search tree storing sorted keys in leaf pages; standard OLTP index for point & range scans.L05, L06
CDC (Change Data Capture)Streaming committed row mutations from the DB WAL (e.g., Debezium) or Transactional Outbox to Kafka/OLAP without dual-write races.L16
Covering IndexAn index containing all columns needed by a query (via keys or INCLUDE), enabling an Index-Only Scan without heap fetches.L06
Dead Tuple / BloatObsolete MVCC row versions left behind by UPDATE/DELETE until VACUUM marks their page space reusable.L08
Expand-and-ContractZero-downtime migration pattern: add new column/table (expand), dual-write & backfill, switch reads, then drop old structure (contract).L11
HOT (Heap-Only Tuple)PostgreSQL optimization where an UPDATE that modifies no indexed columns and fits on the same 8KB heap page skips updating all secondary indexes.L05, L08
HNSWHierarchical Navigable Small World graph index for high-recall, low-latency vector similarity search in pgvector.L17
Iceberg (Apache Iceberg)Open lakehouse table format over Parquet providing ACID snapshots, time travel, hidden partitioning, and safe schema evolution.L16
Idempotency KeyClient-supplied unique token stored with a UNIQUE constraint so retried network requests execute side effects at most once.L10, Capstone
InitPlan (RLS)Wrapping current_setting(...) in (SELECT ...) inside a PostgreSQL RLS policy so the planner evaluates the GUC once per statement instead of per row.L18, Capstone
Keyset PaginationCursor pagination using indexed bounds like WHERE (created_at, id) > (?, ?); O(log N) vs O(N) OFFSET.L07
LSM-TreeLog-Structured Merge-tree (append to memtable + immutable SSTables + background compaction); high write throughput, read/space amplification tradeoffs.L05
MVCCMulti-Version Concurrency Control: stores row tuple versions (xmin/xmax) so readers see consistent snapshots without blocking writers.L08, L09
OLTP vs OLAPOLTP = high-concurrency short transactions (row-store); OLAP = large analytical scans/aggregations (columnar store like DuckDB/ClickHouse).L16
PITRPoint-in-Time Recovery: restoring a physical base backup and replaying archived WAL segments to an exact second before an incident.L13
RLS (Row-Level Security)PostgreSQL policy layer enforcing tenant/user row filters inside the engine regardless of application WHERE clauses.L18
RPO / RTORPO = max acceptable data loss window; RTO = max acceptable downtime to recover service.L13
RRF (Reciprocal Rank Fusion)Score fusion formula Σ 1 / (k + rank_i) combining keyword BM25 and vector ANN ranks without fragile score normalization.L17
SARGableSearch ARGument-able: a predicate written so the planner can use an index range scan instead of wrapping the column in a function.L07
security_invokerPostgreSQL 15+ view option (WITH (security_invoker = true)) ensuring views evaluate permissions and RLS as the calling role rather than the view owner.L18
SKIP LOCKEDSELECT ... FOR UPDATE SKIP LOCKED lets concurrent workers claim disjoint queue jobs without waiting on locked rows.L10
STRICT (SQLite)SQLite 3.37+ table modifier forcing real type checking instead of loose dynamic type affinity.L01
WAL (Write-Ahead Log)Sequential append-only log written and fsync’d before data pages are modified, guaranteeing durability and crash recovery.L08
Write SkewConcurrency anomaly allowed under Snapshot Isolation (REPEATABLE READ) where two transactions read overlapping data and update disjoint rows, violating a cross-row invariant.L09
