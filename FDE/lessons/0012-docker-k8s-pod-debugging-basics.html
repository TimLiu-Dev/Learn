Track 1 · Phase 3 · Unit 0012 · Mid-Level FDE Container & Cluster Ops

Docker, Kubernetes Pod Debugging & CI/CD Basics

Getting your service running cleanly in customer clusters: slim multi-stage Docker images, diagnosing OOMKilled (Exit 137), probe kills, missing secrets, and automated CI test/build pipelines.

Estimated Time: 25 min Prerequisites: 0003, 0010 Tangible Win: Build a K8s Pod Triage Engine & Container Image/CI Readiness Gate

1. What Every Mid-Level FDE Debugs on Deployment Week

Unlike Android AAB uploads to Google Play, enterprise apps ship as Docker containers into customer Kubernetes namespaces (K8s Debug Guide). Master the 4 pod failure modes that account for ~90% of deployment stalls:

  1. OOMKilled (Exit 137): Loading PDF parsers or tokenizers blows past small default memory limits (e.g. 512Mi). Size resources.limits.memory realistically (1–2Gi+).
  2. Premature Liveness Probe Kill Loop: A 20-second model warmup gets killed at second 15 if livenessProbe starts immediately without a startupProbe.
  3. Missing Config / Secret Keys: Pod crashes instantly when required env vars aren't mounted from Kubernetes Secrets.
  4. Non-Root & Multi-Stage Dockerfiles: Customer security scanners block images running as root or bundling build compilers (gcc) in production.

2. Annotated Code: StartupProbe + Memory Limits

YAML / K8s Preventing Exit 137 OOMKills & Warmup CrashLoops 
containers:
  - name: aegis-rag-worker
    resources:
      requests: { memory: "1Gi", cpu: "500m" }
      limits:   { memory: "2Gi" }          # Prevents Exit 137 OOMKilled during tokenizer init
    startupProbe:
      httpGet: { path: /healthz, port: 8080 }
      failureThreshold: 30                 # Allows up to 30 * 5s = 150s warmup!
      periodSeconds: 5
