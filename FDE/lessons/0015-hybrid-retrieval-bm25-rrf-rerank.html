Hybrid Retrieval: BM25 + Vectors + RRF & Reranking

Why pure dense vector search silently whiffs on exact SKUs, error codes, and contract numbers—and how to combine lexical BM25 with semantic embeddings via Reciprocal Rank Fusion (RRF).

Estimated Time: 25 min Prerequisites: 0014 Tangible Win: Build a Cosine+Lexical Retriever & Reciprocal Rank Fusion Engine

1. Why Pure Vector Search Fails in Enterprise Deployments

Dense embeddings excel at semantic paraphrases ("how do employees request parental leave" matches "family care time-off policy"). But ask a pure vector index for error code ERR-4092-B, part SKU XG-9910, or clause Section 14.3(b), and it frequently ranks similar-looking codes (ERR-4091-A) above the exact match!

Production search pairs Lexical Search (BM25 / Postgres tsvector) with Dense Vector Search (pgvector), fused via Reciprocal Rank Fusion (RRF):

  1. Rank-Based Fusion (Not Raw Scores): BM25 outputs unbounded floats (e.g. 14.2) while cosine similarity outputs [0, 1]. Adding raw scores breaks whenever scales shift. RRF fuses pure rank positions cleanly: score(d) = sum(1 / (k + rank_i(d))) (typically k = 60).
  2. Two-Stage Retrieval → Rerank: Retrieve top-50 fast candidates with RRF, then pass top-50 to a cross-encoder reranker (or domain boost) to pick top-5 for the LLM prompt!
Why k = 60?
The constant 60 dampens extreme rank-1 dominance while ensuring documents appearing near the top of both lexical and semantic lists win decisively.

2. Annotated Code: Hybrid RRF Inside Single-Instance Postgres

SQL / pgvector Combining tsvector BM25 + Cosine Similarity with RRF in SQL 
WITH lexical AS (
  SELECT id, ROW_NUMBER() OVER (ORDER BY ts_rank_cd(tsv, plainto_tsquery($1)) DESC) AS r
  FROM chunks WHERE tenant_id = $2 AND tsv @@ plainto_tsquery($1) LIMIT 40
),
semantic AS (
  SELECT id, ROW_NUMBER() OVER (ORDER BY embedding <=> $3 ASC) AS r
  FROM chunks WHERE tenant_id = $2 LIMIT 40
)
SELECT COALESCE(l.id, s.id) AS chunk_id,
       COALESCE(1.0 / (60 + l.r), 0) + COALESCE(1.0 / (60 + s.r), 0) AS rrf_score
FROM lexical l FULL OUTER JOIN semantic s ON l.id = s.id
ORDER BY rrf_score DESC LIMIT 10;
