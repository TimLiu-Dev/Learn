Track 1 · Phase 4 · Unit 0017 · Latency, Cost & Streaming UI

Prompt Caching, Reasoning Budgets & SSE Streaming UX

Keeping prefix caches hot, bounding extended reasoning/thinking tokens for interactive SLAs, and parsing chunked Server-Sent Events (SSE) into crisp unidirectional React UI state.

Estimated Time: 25 min Prerequisites: 0016 Tangible Win: Build a Cache-Stable Prompt Assembler & Chunked SSE Parser

1. TTFT, Cache Prefixes & Android StateFlow → React SSE

Users forgive 6 seconds of total synthesis if tokens begin appearing in 500ms (TTFT — Time To First Token), but abandon apps that hang on a spinner for 8 seconds before dumping a wall of text. Three engineering levers control latency and spend:

  1. Prefix-Stable Prompt Ordering: Provider KV prompt caches match exact byte prefixes from index 0! Putting "Current time: 11:34:02" on line 1 busts the entire 8,000-token cache on every request. Put systemInstructions → toolSchemas → staticCorpus first, and dynamic timestamp / userQuery strictly at the tail!
  2. Test-Time Reasoning Budgets: Reasoning models spend thinking tokens before outputting answers. Cap thinkingBudgetTokens tightly for live chat while reserving deep thinking for async background workflows.
  3. SSE Framing Across Chunk Boundaries: Just like Android Flow reducers, your TypeScript UI reducer consumes streaming data: {...}\n\n frames—remembering that one TCP packet can split a JSON frame right down the middle!
Android Bridge:
Think of an SSE stream reducer exactly like Jetpack Compose StateFlow<ChatUiState> fed by partial WebSocket/Flow emissions—plus an explicit leftover line buffer!

2. Annotated Code: Prefix-Safe Prompt Layout vs. Cache Buster

TypeScript Static Prefix First Keeps 80–90% Prompt Cache Hits Intact 
// CACHE BUSTER: `const sys = "Time: " + Date.now() + "\n" + LONG_POLICY_MANUAL;` -> 0% cache hits!
// CACHE FRIENDLY:
const messages = [
  { role: "system", content: LONG_STATIC_SYSTEM_AND_ONTOLOGY_SPEC }, // Cached byte prefix!
  { role: "user", content: `Timestamp: ${nowIso}\nQuestion: ${userQuestion}` } // Dynamic tail
