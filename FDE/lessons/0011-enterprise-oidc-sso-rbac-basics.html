Enterprise Identity Basics: OIDC SSO & Tenant RBAC Guards

Bridging Android OAuth login tokens to enterprise Okta / Entra ID Single Sign-On: validating JWT issuer, audience, expiry, and tenant-scoped RBAC route policies cleanly.

Estimated Time: 25 min Prerequisites: 0003, 0010 Tangible Win: Build an OIDC Token Gate & Tenant-Scoped RBAC Middleware

1. Why Enterprise Customers Demand OIDC/SAML SSO on Day 1

Enterprise buyers reject email+password logins because IT teams need instant centralized control in Okta or Microsoft Entra ID (OIDC/SAML SSO; OpenID Connect Spec).

  1. Verify ALL 4 JWT Invariants: Signature (via JWKS public keys), iss (exact IdP issuer URL), aud (exact app client ID so tokens from low-privilege internal apps fail!), and exp > nowSec.
  2. Tenant + Role Binding: Never trust an unverified tenantId query parameter from the browser—derive tenantId and role strictly from verified server claims or directory records.
  3. Fail-Closed Default: Unknown roles or missing tenant bindings must return 403 Forbidden, never fall back to a default viewer role.

2. Annotated Code: FastAPI OIDC + Tenant RBAC Dependency

Python / FastAPI Fail-Closed Issuer, Audience, Expiry & Tenant Route Check 
def verify_oidc_claims(claims: dict, expected_iss: str, expected_aud: str, now_sec: int):
    if claims.get("iss") != expected_iss or claims.get("aud") != expected_aud:
        raise HTTPException(status_code=401, detail="Invalid OIDC issuer or audience")
    if int(claims.get("exp", 0)) <= now_sec:
        raise HTTPException(status_code=401, detail="Token expired")
    if not claims.get("tenant_id"):
        raise HTTPException(status_code=403, detail="Missing tenant binding")
    return claims
