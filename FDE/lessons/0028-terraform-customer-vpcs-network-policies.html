Terraform Customer VPC Modules & K8s NetworkPolicies

Replicating hardened cloud deployments across dozens of Fortune-500 VPCs without manual console click-ops: parameterized Terraform variables, customer-managed KMS keys, and zero-trust Kubernetes egress policies.

Estimated Time: 25 min Prerequisites: 0010, 0012 Tangible Win: Build a Terraform Customer VPC Auditor & NetworkPolicy Egress Validator

1. Scaling Customer VPCs Cleanly with Terraform & Zero-Trust Egress

Senior FDEs deploy into 10+ distinct customer cloud accounts without snowflake console edits (Terraform Docs; Terraform & K8s Ops):

  1. Parameterized Terraform Modules: Parameterize var.customer_slug, non-colliding var.vpc_cidr, private RDS (publicly_accessible = false), and customer-managed KMS encryption.
  2. Zero-Trust Kubernetes NetworkPolicy: Default-deny egress rules stop compromised pods from calling arbitrary internet servers—explicitly allowlist only DNS (UDP/53), internal Postgres (TCP/5432), and PrivateLink endpoints (TCP/443).

Inspect aegisops/infra/terraform/main.tf and aegisops/infra/k8s/deployment.yaml to see these exact controls in your capstone repo!

2. Annotated Code: Parameterized VPC + Default-Deny K8s Egress

HCL / Terraform Never Hardcode 10.0.0.0/16 or Expose RDS Publicly 
resource "aws_db_instance" "aegis_postgres" {
  identifier          = "aegisops-${var.customer_slug}-pg"
  storage_encrypted   = true
  kms_key_id          = aws_kms_key.tenant_data_key.arn
  publicly_accessible = false
  deletion_protection = true
}
