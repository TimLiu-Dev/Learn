Track 2 · Phase 9 · Unit 0034 · Measurement & Alignment

Retrieval Metrics (Recall@K / MRR) & Calibrated Judges

Separating retrieval failures from synthesis failures mathematically—and calibrating automated LLM-as-judge evaluators against human Subject Matter Experts (SMEs) with Cohen's kappa.

Estimated Time: 25 min Prerequisites: 0015, 0019 Tangible Win: Implement Recall@K + MRR Scorer & Cohen's Kappa Judge Calibrator

1. Always Measure Retrieval Before Blaming the LLM

When a RAG answer is wrong, 70% of the time the synthesis LLM wasn't broken—the retriever never fetched the right document into the top-K window! Measure retrieval independently:

  1. Recall@K: What fraction of expected gold documents appeared anywhere in the top K retrieved results? (e.g., if Recall@5 = 0.65, fix chunking/BM25/RRF before tweaking system prompts!).
  2. MRR (Mean Reciprocal Rank): Averages 1 / firstGoldRank across queries (1.0 if gold doc is #1, 0.5 if #2, 0 if absent in top-K)—measuring how high relevant evidence climbs.
  3. Calibrating LLM-as-Judge (Cohen's κ): Raw accuracy tricks you when 90% of answers pass (accuracy = 0.90 even for a broken rubber-stamp judge that always outputs PASS!). Compute Cohen's kappa (p_o - p_e) / (1 - p_e) against SME labels—require kappa >= 0.70 before trusting a judge in CI (Hamel Husain).
Why Kappa Catches Broken Judges:
If 90% of samples are pass, a dumb judge returning true blindly scores 90% accuracy—but Cohen's κ = 0.0!

2. Annotated Code: Cohen's Kappa Alignment Formula

Math / Python Evaluating LLM Judge Agreement Beyond Chance 
# p_o = observed agreement = (TP + TN) / N
# p_yes = ((TP + FN) / N) * ((TP + FP) / N)
# p_no  = ((FP + TN) / N) * ((FN + TN) / N)
# p_e = p_yes + p_no   (expected random agreement!)
# kappa = (p_o - p_e) / (1.0 - p_e)   # Target >= 0.70 against human SME split!
