Structured Outputs, Schema Repair & Grounded Abstention

Turning probabilistic prose into typed, citation-verified JSON contracts—with bounded self-repair loops and explicit abstention when retrieved evidence cannot support an answer.

Estimated Time: 25 min Prerequisites: 0015 Tangible Win: Build a Citation/Schema Validator & Bounded Repair Loop

1. Wrapping Probabilistic Models in Typed Contracts

On Android, Moshi or kotlinx.serialization expects clean JSON. With LLMs, even constrained JSON modes still fail on semantic contracts: citing fabricated chunk IDs ([doc_999] not present in context!), wrapping JSON in Markdown triple-backtick fencesjson fences on older/local vLLM endpoints, or guessing confidently when context lacks evidence (Anthropic Prompt Engineering).

Three guardrails make enterprise synthesis reliable:

  1. Deterministic Schema + Provenance Check: Validate types via Pydantic/Zod AND verify every cited chunkId actually exists in the retrieved context list.
  2. Bounded Repair Loop: On failure, feed the exact validation error back into the model (up to maxRepairs = 2), never infinitely!
  3. Explicit Grounded Abstention: If citations are missing on an "answered" claim or repair exhausts, refuse cleanly (status: "abstained") rather than hallucinating!
Enterprise Trust Rule:
One confident hallucinated SLA refund policy breaks executive trust far worse than saying "I don't have verified policy evidence for this."

2. Annotated Code: Pydantic Model + Validated Provenance Check

Python / Pydantic Rejecting Fabricated Citations at the Output Boundary 
class GroundedReply(BaseModel):
    status: Literal["answered", "abstained"]
    answer: str
    citations: list[str]

def verify_reply(raw_json: str, retrieved_ids: set[str]) -> GroundedReply:
    reply = GroundedReply.model_validate_json(strip_fences(raw_json))
    if reply.status == "answered":
        if not reply.citations or not set(reply.citations).issubset(retrieved_ids):
            raise ValueError("Missing or fabricated citation IDs")
    return reply
