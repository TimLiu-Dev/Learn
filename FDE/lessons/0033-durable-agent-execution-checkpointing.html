Track 2 · Phase 8 · Unit 0033 · Reliable Background Agents

Durable Agent Execution & Checkpointed Recovery

Keeping multi-minute workflows and multi-hour HITL pauses resilient across Kubernetes pod restarts—by checkpointing completed steps so recovery never replays external side effects.

Estimated Time: 25 min Prerequisites: 0007, 0031 Tangible Win: Build a Step-Checkpointing Workflow Runner & Stalled-Run Reconciler

1. Why Long-Running Agents Cannot Live Solely in HTTP Memory

On Android, WorkManager survives app kills by persisting work state to SQLite. On an FDE backend, a complex reconciliation or HITL-paused agent workflow might run for 4 minutes—or pause 6 hours waiting for a finance VP's approval click. During that window, Kubernetes might roll your deployment or evict a spot pod!

If workflow state lives only in Python/Node RAM, restarting from step 1 breaks production:

  1. Step-Level Checkpointing (Replay-Safe Memoization): Persist (run_id, step_id) → output in Postgres/Temporal after every completed step. On crash recovery, skip steps already present in the checkpoint store using their saved outputs!
  2. Clean HITL Suspension: When a step requires human approval, save status: "paused_hitl" to DB and free the worker thread immediately (never sleep-wait in RAM!).
  3. Heartbeat & Lease Reconciliation: Background sweepers detect runs stuck in running whose lease expired without heartbeats and enqueue safe checkpointed resumption (up to maxRecoveries).
Key Principle:
Each step function must still attach an idempotencyKey = runId + ":" + stepId on external API calls in case a crash happens right after the API call succeeded but before the DB checkpoint committed!

2. Annotated Code: Durable Checkpoint Wrapper (Python Concept)

Python Memoizing Completed Steps Across Pod Restarts 
async def run_step(run_id: str, step_id: str, fn):
    cached = await db.get_checkpoint(run_id, step_id)
    if cached is not None:
        return cached  # Already committed prior to crash — skip side effect!
    output = await fn(idempotency_key=f"{run_id}:{step_id}")
    await db.save_checkpoint(run_id, step_id, output)
    return output
