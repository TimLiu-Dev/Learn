Track 1 · Phase 1 · Unit 0002 · Discovery & Commercial Scoping

Stakeholder Decomposition, SOWs & Definition of Done

How Senior FDEs dismantle vague executive wishes into concrete stakeholder maps, security veto checks, and a bounded Week-1 thin slice before writing a line of integration code.

Estimated Time: 25 min Prerequisites: 0001 Tangible Win: Build a Discovery Readiness & SOW Thin-Slice Engine

1. Why Engineering Interviews Fail on "Decomp"

On Android teams, product managers absorb organizational ambiguity before handing you a Jira story and a Figma spec. In an FDE engagement—and in Palantir's famous Decomposition (Decomp) or Anthropic's customer simulation rounds—you are handed raw executive chaos: "Our logistics ops team wastes 30 hours a week on exception tickets. Build us an AI triage agent by Friday."

Junior engineers immediately start drawing vector databases and LLM prompts. Senior FDEs treat the enterprise as a socio-technical system first (Qureshi, Reflections on Palantir; roadmap.sh FDE). You must uncover four realities before quoting architecture or signing a Statement of Work (SOW):

  1. Buyer vs. Operator Gap: What the VP paying the invoice optimizes for ("cut headcount cost") often clashes with what the floor operator needs ("surface ERP reason codes faster without hallucinations").
  2. Data Ownership & Freshness: Who owns the underlying SAP/email tables, how stale are they, and can they grant read/write service credentials?
  3. Security & Compliance Veto: Does the CISO require VPC isolation, PII masking, or zero third-party LLM retention?
  4. Measurable Definition of Done (DoD): What quantitative Phase-1 Thin Slice proves value inside 5–10 days?
Interview Signal:
In a Decomp round, saying "Before picking a stack, I want to talk to one floor operator and their security owner" immediately separates you from 80% of coding-only candidates.
Ticket-Taker Reflex

Premature Stack Pitch

  • Hears "triage agent" → pitches multi-agent RAG + auto-reply bot on Day 1.
  • Never verifies if operators trust automated customer emails.
  • Signs an open-ended PoC promise with no measurable acceptance criteria.
Senior FDE Protocol

Discovery-First SOW

  • Probes data access, PII constraints, and operator pain points first.
  • Isolates a Draft-Only / Human-in-the-Loop Phase-1 thin slice.
  • Binds SOW exit criteria to concrete metrics (e.g., "Triage draft < 3s, 85% human acceptance").

2. Annotated Code: Modeling Discovery Gates as Executable Contracts

Good FDE teams codify discovery hygiene into deployment checklists so PoCs never start on missing foundations. Notice how structuring ambiguity into explicit domain types makes trade-offs unmistakable:

TypeScript Pattern Formalizing Discovery & Phase-1 SOW Constraints 
// Treat customer discovery like a strict pre-flight check before writing infra
const discoveryRecord = {
  buyerGoal: "Reduce ticket backlog 40%",
  operatorNeed: "Draft accurate carrier-delay replies with order history",
  cisoRules: { allowPublicLlm: false, requiresSso: true },
  dataAccess: { erpConnected: false, csvExportReady: true }
};

// A Senior FDE ships Week 1 on csvExportReady + draft-only HITL UI
// while scheduling ERP OAuth integration into Phase 2 instead of stalling!
