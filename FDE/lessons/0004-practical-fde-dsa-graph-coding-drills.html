1. Why FDE Coding Rounds Test Graphs, DAGs & Windows (Not Random Tricks)

Per roadmap.sh's FDE DSA branch, data structures and algorithms remain an interview gate. Unlike generic big-tech puzzles, FDE coding questions mirror field infrastructure:

  1. DAG Topological Sort (Kahn's Algorithm): Ordering dependent data transforms or Terraform/agent steps (A → B → C) AND detecting invalid dependency cycles cleanly (Practical DSA).
  2. Cycle-Safe BFS/DFS Graph Traversal: Expanding nested Okta/SCIM groups (user → eng → platform → all_staff) or entity-resolution merge graphs without infinite loops on mutual group cycles.
  3. Sliding Window & Interval Merging: Counting rate-limit hits over rolling 60s windows or merging overlapping SLA maintenance/late-arrival event intervals.
Interview Edge-Case Rule:
Always state and test 3 edge cases aloud before coding: empty graph, disconnected components, and cycles!
