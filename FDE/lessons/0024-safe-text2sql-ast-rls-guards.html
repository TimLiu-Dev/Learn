Safe Read-Only Text2SQL & AST/RLS Query Guards

Data-platform FDEs (Databricks, Snowflake, Palantir) routinely ship natural-language BI copilots. Never pass raw LLM SQL into db.execute()—enforce deterministic read-only guards, table allowlists, tenant predicates, and DB Row-Level Security.

Estimated Time: 25 min Prerequisites: 0008, 0023 Tangible Win: Build a Text2SQL Security Validator & Schema Context Grounder

1. Why Prompt-Only "Always Filter Tenant" Fails Enterprise Audits

Indirect prompt injection inside a customer ticket or an adversarial user prompt can override system rules and ask the LLM for SELECT * FROM users; DROP TABLE orders; (Safe Text2SQL; OWASP LLM Improper Output Handling). Senior FDEs enforce defense in depth:

  1. Deterministic SQL Validator: Reject semicolons (;), comments (--, /*), and non-SELECT DDL/DML keywords (INSERT, UPDATE, DELETE, DROP, GRANT, COPY).
  2. Table Allowlist + Tenant Isolation: Block unlisted tables (pg_catalog, users), verify/inject tenant_id = $1, and clamp LIMIT <= 100.
  3. Database-Level Isolation: Run queries on a Postgres read-only role with a 3-second statement_timeout and Row-Level Security (RLS).

2. Annotated Code: Postgres Row-Level Security + Read-Only Role

SQL / PostgreSQL Database Backstop Even If an App Parser Misses an Edge Case 
ALTER TABLE orders ENABLE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON orders
  USING (tenant_id = current_setting('app.current_tenant', true));

-- Executed inside read-only Text2SQL transaction:
SET LOCAL statement_timeout = '3000ms';
SET LOCAL app.current_tenant = 'acme_logistics';
