Track 2 · Phase 7 · Unit 0027 · Compliance & Sensitive Data

PII Redaction, Zero-Data-Retention & OWASP LLM Safety

Keeping regulated SSNs, emails, and leaked API secrets out of model prompts and observability logs—and enforcing Zero-Data-Retention (ZDR) egress policies before outbound LLM API calls leave your VPC.

Estimated Time: 25 min Prerequisites: 0005, 0025 Tangible Win: Build Reversible PII Tokenization & ZDR Egress Policy Gate

1. Sensitive Information Disclosure Is OWASP LLM02

According to the OWASP Top 10 for LLM Applications, sensitive data disclosure happens not just through prompt attacks, but through sloppy FDE plumbing: raw customer PII dumped into telemetry traces, unmasked SSNs sent to external LLM endpoints, or training-opt-in flags left enabled on trial keys.

Senior FDEs pair three concrete engineering controls:

  1. Deterministic Reversible Tokenization: Replace alice@acme.io with [EMAIL_1] consistently before an LLM analyzes a ticket—so the model still reasons about who emailed whom ([EMAIL_1] replied to [EMAIL_2]) without ever seeing real emails!
  2. Irreversible Secret Scrubbing: API keys (sk-..., Bearer ...) must NEVER be reversibly tokenized into prompts—strip them permanently as [SECRET_REDACTED].
  3. Out-Bound ZDR Policy Gate: Fail closed in code before making any external LLM HTTP request unless Zero-Data-Retention headers/contracts, approved VPC region endpoints, and audit logs are satisfied.
Important Distinction:
Scrubbing PII protects outbound prompts & logs, while Unit 0025/0026 ACLs protect who may read what. Both are mandatory together!

2. Annotated Code: Reversible vs. Irreversible Scrubbing

Python Pattern Consistent Placeholder Tokenization Preserves Reasoning Fidelity 
# Input ticket: "Alice (alice@acme.io) confirms alice@acme.io approved refund for SSN 123-45-6789."
# Sanitized:    "Alice ([EMAIL_1]) confirms [EMAIL_1] approved refund for SSN [SSN_1]."
# Notice: the model still knows both mentions refer to the SAME person [EMAIL_1]!
# Rehydration (after model responds, ONLY inside authorized user session):
#   token_map["[EMAIL_1]"] -> "alice@acme.io"
