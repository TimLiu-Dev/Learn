Track 2 · Phase 8 · Unit 0031 · Safe Agent Tool Execution

Tool Dispatchers, MicroVM Sandboxes & HITL Gates

Building typed tool-call dispatchers with step budgets and Human-in-the-Loop write approvals—and isolating dynamic agent code execution inside gVisor/MicroVM sandboxes instead of unsafe shared-kernel Docker.

Estimated Time: 25 min Prerequisites: 0006, 0018 Tangible Win: Build a HITL Tool Dispatcher & Agent Sandbox Security Gate

1. Preventing OWASP LLM06 (Excessive Agency) & Container Escapes

When an LLM invokes tools or writes code to analyze customer CSVs, two distinct security layers protect production:

  1. Application-Layer Tool Dispatcher: Never execute tools[name](args) blindly! Verify the tool is allowlisted for the user's tenant/role, validate arguments strictly, enforce a maxSteps loop breaker, and pause any mutating tool (risk: "write", e.g. issuing refunds or modifying ERP records) inside a Human-in-the-Loop (HITL) approval queue!
  2. Kernel-Level Agent Code Sandboxing: Standard Docker containers (runc) share the Linux host kernel. Treating untrusted, prompt-injected LLM-generated Python/shell scripts as benign apps inside shared-kernel runc invites container escapes! Production platforms isolate agent code execution inside gVisor user-space kernels or Firecracker/E2B MicroVMs with read-only root filesystems, zero host mounts, and locked egress.
Interview Signal (OpenAI / Anthropic):
Returning structured validation error messages back to the model when tool arguments fail lets the agent recover gracefully without crashing!
