Mobile Client → Multi-Tenant Backend Lifecycles

Rewiring single-device Kotlin/Retrofit instincts into server-side multi-tenant isolation, correlation tracing, and idempotent mutation endpoints.

Estimated Time: 25 min Prerequisites: 0001 Tangible Win: Implement Tenant Isolation Guard & Idempotency Middleware

1. Single-User Device vs. Shared Multi-Tenant Server

In an Android app, process memory belongs to one authenticated user at a time. When you store an object in a ViewModel or call Retrofit, there is zero chance User B's screen reads User A's in-memory state.

On an FDE backend (FastAPI in Python or Node/TypeScript), one server process serves dozens of enterprise tenants concurrently. Two lethal bugs ambush mobile developers switching to backend:

  1. Trusting Client-Supplied tenant_id: Never accept body.tenantId as authority—derive tenant scope strictly from the verified JWT/OIDC session or API key, and fail closed if headers disagree.
  2. Non-Idempotent Retries: Customer proxies and webhook senders retry timed-out POST requests automatically. Without Idempotency-Key enforcement scoped per tenant, a timeout double-charges or double-dispatches.
  3. Global Mutable State: Module-level variables shared across async awaits leak Tenant A's credentials or correlation IDs into Tenant B's response!
Android Bridge:
Think of a backend request context like a fresh scoped CoroutineContext per call—except shared global singletons must never hold per-request tenant state.

2. Annotated Code: Kotlin Retrofit vs. Python/TS Multi-Tenant Server

Python / FastAPI Fail-Closed Tenant Context + Scoped Idempotency 
@app.post("/v1/dispatches")
async def create_dispatch(
    req: DispatchBody,
    ctx: TenantContext = Depends(verify_jwt_tenant),   # Authority from verified token ONLY
    idempotency_key: str = Header(..., alias="Idempotency-Key"),
):
    if req.claimed_tenant_id and req.claimed_tenant_id != ctx.tenant_id:
        raise HTTPException(status_code=403, detail="Tenant claim mismatch")

    # Scope idempotency cache by (tenant_id, route, idempotency_key) — NEVER key alone!
    cache_key = f"{ctx.tenant_id}:POST:/v1/dispatches:{idempotency_key}"
    return await idempotent_execute(cache_key, req.model_dump(), lambda: run_dispatch(ctx, req))
