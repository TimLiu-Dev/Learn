Permission-Aware Retrieval: Pre-Filtering vs. Post-Filtering

Preventing cross-department executive leaks inside shared RAG indexes—and why filtering permissions after top-K vector search breaks both recall and security.

Estimated Time: 25 min Prerequisites: 0015, 0025 Tangible Win: Build a Pre-Filter ACL Retriever & Leakage Auditor

1. The #1 Enterprise AI Security Disaster: Shared Vector Leakage

Imagine indexing HR executive compensation, legal M&A memos, and public IT handbooks into one shared vector database. An intern asks: "What are typical VP bonus payouts?"

Two common shortcuts both fail catastrophically:

  1. No ACL Filtering (Instant Breach): Top-5 semantic matches pull confidential HR spreadsheets directly into the LLM prompt and summarize salaries to the intern!
  2. Post-Filtering Top-K (Starvation Failure): You fetch global LIMIT 5 first, then filter out chunks the intern can't read. All 5 chunks belonged to HR/Legal, so after filtering the intern receives 0 results—even though public handbook chunks ranked #6 and #7!

The Senior FDE rule: always enforce Pre-Filtered ACLs (tenant_id = $1 AND allowed_principals && $user_principals) before ranking and LIMIT top_k truncation!

ReBAC → Index Sync:
Materialize flattened allowed_principals[] (e.g. ["user:alice", "group:eng"]) on chunks and refresh on SCIM/ACL change events!

2. Annotated Code: Postgres Pre-Filtered Hybrid Retrieval

SQL / pgvector Pre-Filtering Tenant & SCIM Principals Before LIMIT Truncation 
-- Postgres GIN index on allowed_principals (TEXT[]) + HNSW index on embedding:
SELECT chunk_id, raw_text, 1 - (embedding <=> $query_vec) AS score
FROM chunks
WHERE tenant_id = $verified_tenant_id
  AND allowed_principals && $user_principals_array  -- Overlap check BEFORE LIMIT!
ORDER BY embedding <=> $query_vec ASC
LIMIT 5;
