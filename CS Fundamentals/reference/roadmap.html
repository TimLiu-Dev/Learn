The Roadmap

From typing your first hand-written line to a REST API you could build without Spring, where each phase stands on the one before it.

v4 · SESSION-SIZED LESSONS

12phases + capstone
47lessons
60–90 minper lesson
~7 moat 1–2 lessons/week

Every lesson shows the code in KOTLIN and JAVA side by side and points out what Kotlin does for you that Java makes you write yourself. You type every exercise by hand, with AI completion switched off. That's the whole point.

Anatomy of a lesson

One lesson fills one sitting. It's built from short, self-contained parts, so you can stop cleanly after any of them and pick up there next time.

Warm-up~10 minWrite code from memory using earlier lessons. After a week away, this is what stops the material fading.
Parts 1–3 (or 4)15–20 min eachOne concept per part: the explanation with citations, Kotlin and Java side by side, a hand-written exercise, then a quick check.
Final exercise~20 minA bigger program that combines the parts, with tests once phase 4 has taught you to write them.
Exit quiz~5 minShows what next lesson's warm-up should revisit.
Recall cardoptional, 10 minA short midweek retrieval drill between sessions.

Lesson numbers here match the file names in lessons/: L1 is 0001-…html. The builds on chips show which earlier phases each phase depends on.

Threads that run through every phase

  • Spaced recall. Every warm-up pulls from older lessons, not just the last one, and the midweek recall cards fill the gaps between sessions.
  • Git & the command line. Basics in L1, branches in L12, team workflow in L40, and used in every exercise.
  • Caching, at four levels. CPU caches (L22), HTTP caches (L31), database indexes (L35), and application caches (L41). It's the same idea every time: keep a copy closer to where it's needed.
  • Kotlin vs Java. Each lesson has a "what Kotlin does for you" box.
  • Glossary. Grows as you master terms, and every lesson uses its wording.
