One favourite per type

Favorites stores at most one value per type: a favourite String, a favourite Int, and so on. This is Bloch's "typesafe heterogeneous container" (Effective Java Item 33). Finish it:

  • put<T>(value) stores value in the slot for T, replacing any earlier one.
  • get<T>() returns the value in T's slot, or null. No unchecked casts.
  • The slot is chosen by the type argument: after put<CharSequence>("hi"), get<CharSequence>() is "hi", but get<String>() is null.
