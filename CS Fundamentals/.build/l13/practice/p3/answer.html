Why it works. Erasure removes T from the compiled function, but an inline function's body is pasted into each call site, where T is known. So T::class becomes String::class or Int::class there, and as? T becomes a real instanceof check. Java gets the same safety by asking the caller for a Class<T> token and using type.cast.

Common mistake. Keying the slot with value::class. That's the runtime class, so put<CharSequence>("hi") lands in the String slot, and get<CharSequence>() finds nothing. The caller's type argument is the key.
