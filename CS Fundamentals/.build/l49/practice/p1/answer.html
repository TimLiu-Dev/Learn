Why it works. Earliest finish is the rule the exchange argument proved: the first session to finish leaves the most room, so some best schedule starts with it. Sorting by end also means each new session only has to clear the last one taken, so the pass is O(n) and the sort's O(n log n) dominates. The result is already in time order.

Common mistake. Sorting by start. Everything else is the same and it looks equally sensible, but on trap1 it grabs long and returns one session instead of two. The random check catches it too.
