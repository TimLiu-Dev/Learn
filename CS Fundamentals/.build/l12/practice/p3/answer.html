Why it works. Branching writes one map entry, which is why real Git branches are instant: .git/refs/heads/fix is usually a tiny file holding one commit hash. A commit moves only branches[head], so main stays where it was. Switching changes which name head holds. History lives in the parent links, so log() on each branch shows its own line back to the shared commits.

Common mistake. Thinking of a branch as "the commits on it" and moving every branch that points at the old commit. Then committing on fix drags main along too, and the two lines can never diverge.
