Why it works. With total a Long, each Int year's seconds is added to a Long, and Long + Int gives a Long, so nothing wraps. Each single year, at most 31,622,400 seconds, still fits comfortably in an Int.

Common mistake. Converting at the end with total.toLong(). A conversion can't recover bits that were already lost: 2039 comes out as -2117514496. This is the real "year 2038 problem": 32-bit signed seconds since 1970 run out on 19 January 2038.
