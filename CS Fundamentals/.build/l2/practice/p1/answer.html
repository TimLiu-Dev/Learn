Why it works. The loop asks "is there another digit to the left?" (n / 10 != 0) instead of "is anything left?". So 0 counts as one digit, and negative numbers work because integer division moves them towards 0 too. Without abs(), there's nothing to overflow, so Int.MIN_VALUE just works.

Common mistake. Reusing digitSum's loop: abs() then while (n > 0). It passes the ordinary examples but returns 0 for 0 and for Int.MIN_VALUE, the two edge cases step 1 told you to write down.
