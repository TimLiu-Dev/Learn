Why it works. mod() follows the divisor's sign, so a negative offset still lands on a valid index. Converting a to Double first makes the addition Double + Int, which is done in Double arithmetic: there's no 32-bit limit to wrap round, and the division keeps the fraction. Comparing the difference with a tolerance absorbs the tiny binary rounding errors.

Common mistake. (a + b) / 2.0. It keeps the .5, but a + b is still Int + Int, which wraps before the division ever sees it: the average of two Int.MAX_VALUEs comes out as -1.0.
