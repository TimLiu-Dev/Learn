Recover what a crash left behind

This log is text: one record per line, "crc key=value\n", where crc is the CRC-32 of key=value's UTF-8 bytes as exactly 8 hex digits. A crash may have torn the last line, or left junk after it.

  • Write crcHex(payload) with java.util.zip.CRC32.
  • Write recover(log): replay records from the start (a later value wins) and stop at the first one that isn't whole and valid. Return the data and validLength, the number of characters of good records, so the caller can truncate there before appending.

A record counts only once its \n is there: that's what the writer writes last.
