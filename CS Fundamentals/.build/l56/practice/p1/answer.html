Why it works. Writes only append, and the index is the only thing that knows which record is current, exactly like Bitcask's keydir. The tombstone makes a delete part of the log, so replaying the log, which is all a restart can do, gives the same answer as the live store. Compaction copies one record per live key, and because every record moves, every offset in the index has to be rewritten.

Common mistake. A delete that only calls index.remove(key). It passes while the store stays open, then the reopen check finds emma back from the dead. The other one is a compact that rewrites the list but keeps the old offsets, so get reads the wrong record or runs off the end.
