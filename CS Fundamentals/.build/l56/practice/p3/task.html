Flush, look up, merge: an LSM tree in memory

MiniLsm is Part 3's design with the SSTables kept in memory: each run is a sorted map, and a null value is a tombstone. runs is ordered newest first. Write three pieces:

  • flush(): the memtable becomes the newest run, and a fresh memtable starts.
  • get(key): the memtable, then each run newest first. The first place that has the key decides, even if what it has is a tombstone.
  • mergeRuns(runs, dropTombstones): one sorted run with the newest version of every key. A full merge drops tombstones; a partial one must keep them.
