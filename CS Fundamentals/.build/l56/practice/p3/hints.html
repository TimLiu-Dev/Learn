flush: put the memtable at the front of runs (runs.add(0, mem)), then give mem a new TreeMap. Calling mem.clear() instead would empty the run you just stored, because it's the same map object: aliasing (L4).

---

get: a tombstone is stored as null, and map[key] also returns null for a missing key, so you can't tell them apart by the value. Ask key in run first. The first map that contains the key decides, whatever it holds. Avoid mem[key] ?: …: the elvis operator would step past a tombstone into older runs.

---

mergeRuns: the simplest correct merge visits the runs oldest first (runs.asReversed()) and putAlls each into one TreeMap, so newer versions overwrite older ones. Then, only if dropTombstones, merged.values.removeIf { it == null }. Java has runs.reversed() (JDK 21) and containsKey.
