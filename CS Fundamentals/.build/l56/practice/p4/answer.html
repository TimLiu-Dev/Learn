Why it works. json_each unpacks each book's authors array into rows, which stands in for the relational join, and CAST(… AS INTEGER) turns the one year that was stored as text into a number before comparing. The relational query needed no such care, because the table's column type decided what a year is once, at write time. In a document store, every query that reads year has to make that decision itself: schema-on-read.

Common mistake. WHERE d.doc ->> '$.year' < 1980 without the CAST. It runs, returns two plausible rows, and quietly counts Le Guin once instead of twice. Nothing warns you: the wrong answer looks just like a right one.
