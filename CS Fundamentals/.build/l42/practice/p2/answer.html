Why it works. A key's owner depends only on the nearest node position clockwise from it. Adding n5 inserts 50 new positions, and only the keys just before each of them change owner, all to n5: 2,110 of 10,000 here, against 7,954 for mod 4 → mod 5. Removing n3 hands each stretch of n3's to its clockwise neighbour, so only n3's keys move.

Common mistake. ring.ceilingEntry(h).value without the wrap. It works for almost every key, then throws NullPointerException for the keys that hash past the last position: 45 of 10,000 on the 50-vnode ring, few enough to slip through a quick test. Kotlin can't warn you, because ceilingEntry is a Java method with a platform type.
