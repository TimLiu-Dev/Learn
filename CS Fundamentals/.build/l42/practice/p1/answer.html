Why it works. Least-connections reads load from active, and active stays high on a slow backend because its requests take longer to finish. So the slow b2 gets 2 of 30 requests instead of its round-robin 10, and the last request finishes at tick 41 instead of 201: the same shape as the demo's 1.07 s against 4.2 s.

Common mistake. Choosing a backend but not doing active++. Least-connections then sees zero everywhere and sends every request to b1. The counter is the balancer's only view of load, so the pick must update it.
