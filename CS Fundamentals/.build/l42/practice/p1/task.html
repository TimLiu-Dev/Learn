Round-robin vs least-connections

Finish Balancer.pick(), the decision at the heart of Part 1's load balancer, without any networking:

  • Only healthy backends count. If none is healthy, return null.
  • ROUND_ROBIN takes the healthy backends in turn. LEAST_CONNECTIONS takes the one with the fewest requests in flight; ties go to the earlier backend in the list.
  • Count the request on the chosen backend: active and served both go up. finish is already written.

The last test replays the demo in miniature on a fake clock: b2 is ten times slower than the others.
