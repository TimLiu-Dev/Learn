Why it works. The worker records an id only after its email has gone out, so a failed attempt leaves no trace and the redelivery does the work. Any later delivery of the same id finds it in done and stops. At-least-once delivery plus this check gives an exactly-once effect, the bottom row of Part 3's table. One gap is left, as in the lesson: a crash between the send and done += m.id still sends twice. A database effect closes it by writing the effect and the id in one transaction.

Common mistake. if (!done.add(m.id)) return before sending. It reads neatly, but it records the job before doing it: when the send fails, the retry is skipped and the email is lost. That's at-most-once again. De-duplicating by body is the other trap: two customers' identical reminders would become one.
