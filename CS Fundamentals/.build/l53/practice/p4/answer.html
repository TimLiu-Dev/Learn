Why it works. Quotes decide whether a value goes through word splitting. "$f" and "$@" skip it, so each value stays exactly one argument, even an empty one. Unquoted $f, $* and $@ are split on whitespace, which is how rm $f ends up with two arguments. This model is simplified: real bash also splits on the characters in IFS and expands globs like * after splitting.

Common mistake. Removing the quotes first and then treating every token the same way. Quoting then changes nothing: cp "$f" behaves like the unquoted cp $f that made backup_broken.sh copy the wrong file.
