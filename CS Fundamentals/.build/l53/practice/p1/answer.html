Why it works. Each function is one stage, and topN is the pipeline: sorted() is sort, uniqC is uniq -c, sortedByDescending is sort -rn and take is head. Because sortedByDescending is stable (L18), paths with equal counts keep the alphabetical order the first sort gave them.

Common mistake. Leaving out the first sorted(). uniqC then counts runs, not paths, and every count can come out as 1, the same trap as uniq -c without sort.
