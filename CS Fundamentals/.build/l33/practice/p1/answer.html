Why it works. Only someone holding the key can compute the tag for a given message, so an edited message or a foreign key gives a tag that doesn't match. Recomputing from the message and comparing with MessageDigest.isEqual is the whole check, and every odd input falls through to null: the check fails closed.

Common mistake. Splitting at the first dot. Then v1.2.3.<tag> splits into v1 and 2.3.<tag>, and a genuine token is rejected. Split at the last dot, because that's the only one you know the tag doesn't contain.
