Why it works. Only someone holding the secret can produce the tag for a given timestamp and body, so an edited body, a different secret or a changed timestamp all fail the comparison. Signing the timestamp is what makes the age check meaningful. A captured delivery stays genuine forever, but once it's more than five minutes old it's refused, which is Stripe's default tolerance. MessageDigest.isEqual keeps the comparison constant-time, as Part 2 explains; GitHub's docs say "Never use a plain == operator". Dedupe by event id on top, as L32 showed, because the provider will legitimately deliver the same event more than once.

Common mistake. HMAC-ing the body alone and checking the timestamp separately. Every test about a fresh delivery passes, but an attacker who captured an old delivery just rewrites t= to the current time, and the tag still matches. If a value matters to a security decision, it has to be inside the signed text.
