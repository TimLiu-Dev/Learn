Why it works. A release contains all the changes since the last one, so the next version is decided by the biggest change: breaking beats feat, and feat beats fix. SemVer then says to reset everything to the right of the number you bump ("Patch and minor versions MUST be reset to 0 when major version is incremented"). The 0.x rule follows the Cargo convention described above: before 1.0.0, MINOR plays the role of MAJOR.

Common mistake. Forgetting the reset, so a feature on 1.4.2 gives 1.5.2. That version claims two bug-fix releases of 1.5 that never existed. A second classic is matching startsWith("feat:"), which misses scoped and breaking headers like feat(api)!:.
