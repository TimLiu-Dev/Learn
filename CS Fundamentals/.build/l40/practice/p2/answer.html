Why it works. Each picked commit owns a group, and a fixup or squash is appended to the end of its target's group, so it lands after the target and after any earlier fixups. Flattening the groups keeps the picks in their original order. This matches the real todo list above: Git also matches by the subject after the fixup! prefix, and only against commits earlier in the list.

Common mistake. Inserting each fixup at "target's index + 1". With one fixup that's right, but a second fixup for the same commit then lands in front of the first, and the fixes get applied in the wrong order.
