Why it works. Each filter holds the rest of the chain as next, so the first filter in the list is the outermost one. It runs first on the way in and last on the way out, which is why the trace reads A in, B in, handler, B out, A out. A filter that returns without calling next ends the chain, which is the JDK's "Terminate the chain of invocation". That's why the access log must sit outside the limiter to see the 429s. Every filter is a decorator of the same Handler interface (L39), and foldRight, L14's fold run from the end of the list, stacks them.

Common mistake. filters.fold(handler) { next, f -> … }. It compiles and passes the one-filter checks, but it wraps the list back to front, so the limiter ends up outermost and the access log never sees a 429.
