Check a security.txt before you rely on it

Before you report a bug, you look for /.well-known/security.txt (RFC 9116). Write problems(text, now), which returns what's wrong with one, in this order (an empty list means it's usable):

  • Skip blank lines and lines starting with #. A field is Name: value; names are case-insensitive, and unknown fields are ignored.
  • missing Contact if there's none. Each Contact must start with mailto:, tel: or https://, else Contact must use mailto:, tel: or https://: <value>.
  • missing Expires, or Expires must appear once, found 2; a parsable Expires before now gives expired on <instant>.
