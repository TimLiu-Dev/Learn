Why it works. Lookup order is precedence: the environment overrides the properties file, which overrides the default, as in Spring's externalized configuration. Collecting problems instead of throwing at the first one gives the operator the whole list in one go; Spring Boot's startup report for @Validated configuration properties likewise lists every field that failed validation.

Common mistake. Throwing at the first bad value. The message is right, but a file with two mistakes then takes two failed deploys to fix, and the test that sets both shelf.port and shelf.pool-size sees only one.
