A filter needs to know its next before it can run, so build the chain from the inside out. The last filter wraps the handler, the one before it wraps that, and so on. Each wrap is a new Handler { req -> f.filter(req, next) }.

---

"Start from the handler and walk the list backwards" is exactly foldRight: filters.foldRight(handler) { f, next -> Handler { … } }. RateLimit is an if: allowed means next.handle(req), and refused means you build the 429 Response yourself.

---

If the trace check prints B in before A in, you used fold, which wraps filters[0] first and leaves it innermost. In Java there's no foldRight: loop i from size - 1 down to 0, and copy the current handler into an effectively final local before the lambda captures it.
