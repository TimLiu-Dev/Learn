Why it works. A connection is always in exactly one place: free, or lent. Waiters are served in arrival order, so nobody starves, and the deadline check runs whenever a connection is about to change hands, so a borrower who has given up never receives one. In a real pool the waiting thread would wake up and get an exception; Hikari's message is "Connection is not available, request timed out after …ms". Here, the log line stands in for that exception.

Common mistake. Checking only the front of the line: while (waiters.first().deadline <= now) removeFirst(). It works while everyone uses the same timeout. A short timeout behind a long one is then never noticed, and that waiter is served after it has given up.
