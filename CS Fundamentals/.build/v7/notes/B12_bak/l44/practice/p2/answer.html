Why it works. GROUP BY turns six click rows into one count per code and day. The composite primary key makes (code, day) unique, so the upsert either inserts a new day's row or adds excluded.clicks to the count already there: 5 + 1 = 6 and 2 + 3 = 5. at_ms / 1000 turns milliseconds into the seconds 'unixepoch' expects. In the real flusher both statements run in one transaction (L36), so a crash can't count a click twice or lose it.

Common mistake. INSERT OR REPLACE. It runs without an error, but on a conflict it deletes the old row and inserts the new one, so yesterday's 5 clicks become this batch's 1. The check catches it: 4xdNF0v on the 13th shows 1, not 6.
