Why it works. An idempotent request has the same effect whether it arrives once or three times, so a client may retry it after a timeout (RFC 9110 §9.2.2). Everything else needs help from the server, and an Idempotency-Key is that help: the same key returns the first result instead of creating a second link. An allow-list of six methods treats anything unknown as unsafe, which is the right default for a reviewer.

Common mistake. Checking only for POST. PATCH isn't idempotent either (RFC 5789: "PATCH is neither safe nor idempotent"), because a patch such as "add 1 to clicks" applied twice adds 2. A deny-list also waves through methods it has never seen.
