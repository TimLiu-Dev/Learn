Split the job in two. First, scan every message and set three flags: breaking, feat, fix. Then a when picks the biggest bump, with breaking first, because a when takes the first branch that matches.

---

For the header line, a regex such as ^(\w+)(\([^)]*\))?(!)?: gives you the type (group 1) and the ! (group 3), and it copes with feat(api)!:, which startsWith("feat:") would miss. The footer is any line after the first that starts with BREAKING CHANGE:. Parse the version with require(Regex("""\d+\.\d+\.\d+""").matches(current)), then split(".").map { it.toInt() }.

---

The four results are "0.${minor + 1}.0" (breaking while major is 0), "${major + 1}.0.0", "$major.${minor + 1}.0" and "$major.$minor.${patch + 1}", else null. Compare numbers as Ints, never as strings. In Java, Pattern/Matcher and Integer.parseInt do the same job.
