Why it works. The zone's rules know exactly which offsets a local time can have: none in a gap, two in an overlap, one otherwise. ZonedDateTime.of quietly resolves the first two cases (shift forward, take the earlier offset), so you have to ask first if the user should hear about it. The ISO offset formatter always prints seconds, which RFC 3339 requires, and prints Z for a zero offset, which it allows.

Common mistake. Wrapping ZonedDateTime.of in try/catch and treating the exception as "doesn't exist". There is no exception: 02:30 silently becomes 03:30, and the booking is stored as Exact at a time the user never chose.
