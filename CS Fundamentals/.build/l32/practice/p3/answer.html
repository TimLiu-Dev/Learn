Why it works. 404 and 405 answer different questions. 404 says "nothing lives at this path", and 405 says "something lives here, but it doesn't do that". So the router asks about the path first, ignoring the method, and only then about the method. The Allow list comes from the same routes, which is how RFC 9110's "MUST generate an Allow header field" rule stays true as you add routes. Comparing whole segments also avoids the JDK server's prefix trap, where /booksXYZ reaches the /books context.

Common mistake. Skipping the size check and relying on zip: it stops at the shorter list, so /books/42/extra matches /books/{id}, and even /books/42 matches /books.
