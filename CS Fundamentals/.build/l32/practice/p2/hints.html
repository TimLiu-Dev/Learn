The server needs a memory that the plain POST doesn't have: a map from each key to what happened the first time. What must you store so you can both replay the answer and spot a different item?

---

Store key -> (item, response), for example mutableMapOf<String, Pair<String, Response>>(). At the top of post, if the key is known, compare items: the same item returns the stored response, and a different one returns Response(422, …). Either way, return before creating anything.

---

Only when the key is new (or null) do you create the order. Then save seen[key] = item to response, but only if key != null. Don't look for an existing order with the same item: two keys mean two orders the client really wants. In Java, a small record Seen(String item, Response response) holds the pair.
