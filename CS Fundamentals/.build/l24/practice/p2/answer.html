Why it works. A FIFO queue hands out objects in order of distance from the nearest root, so the first time an object is reached, it's by a shortest chain, and its parent never needs to change. Following parent back from the target replays that chain. This is how to read a leak: the chain ends at the object you expected to be gone, and the fix is to cut one link in it, here listeners → lambda#2, by unsubscribing.

Common mistake. Taking objects from the back of the deque (removeLast). That's DFS: it still finds a chain, but in the cache check it goes through sessions → table → node first and reports a chain of five objects instead of three.
