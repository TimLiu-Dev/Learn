Why it works. Primitives like Long in a local variable live in the stack frame (L4), not on the heap, so updating one creates no garbage. The loop now does arithmetic only, and the one object a caller needs is made at the end. For a 10,000-line basket that's 1 object instead of 20,001, and that much less work for the young collector.

Common mistake. Moving the sum into a Long but keeping (prices[i] * quantities[i]).cents. The answer is right, but times still makes a temporary Money per line: 10,001 allocations. In a real run, L23's escape analysis might remove some temporaries like these once C2 compiles the loop. Only an allocation profile tells you whether it did, which is why you measure.
