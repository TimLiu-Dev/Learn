A migration runner of your own

FakeDatabase stands in for SQLite: scripts are lines like create books, history plays the part of schema_version, and transaction { } undoes everything if its block throws. Write migrate:

  • Apply every migration whose version isn't in history yet, in version order, and return the versions applied.
  • Run each script and record its checksum in history inside one transaction, so a failure leaves no trace.
  • Before applying anything, refuse with an IllegalStateException naming the version (e.g. "V1 was edited") if an applied migration's checksum has changed.
