Why it works. floorMod maps every hash code, negative ones included, to a bucket from 0 to 99, so "bucket < percent" picks the same users every time and only ever adds users as the percent grows. The verdict refuses to judge on a handful of requests, then compares against the control group serving the same traffic at the same moment, not against last week.

Common mistake. Math.abs(h) % 100. It looks right and passes almost every user, but Math.abs(Integer.MIN_VALUE) is still negative (its docs say so), so one user in about four billion lands in bucket −48 and gets the canary even at 0%. Plain h % 100 is worse: it sends most negative hashes to the canary.
