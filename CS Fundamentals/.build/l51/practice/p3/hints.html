A deterministic machine's future depends only on its current configuration. So the first time you meet a configuration you've seen before, you know the rest: it will go round the same cycle forever.

---

Keep a HashMap from configuration to the step at which you first saw it (L19). Each step, before calling next, check the map: if the configuration is there at step e and you're now at step s, the answer is Loops(e, s - e). Otherwise record it, and call next; null means Halts(s).

---

val earlier = firstSeen.putIfAbsent(c, step) records and checks in one call: it returns the old step, or null if c is new. Then c = next(c) ?: return Verdict.Halts(step). Java has the same putIfAbsent, and the configurations need a proper equals and hashCode, which records give you.
