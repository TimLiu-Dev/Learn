Why it works. verify is linear in the certificate, so subset sum is in NP. search is "guess every certificate, then check it": 2n guesses, each checked quickly. That's the gap P vs NP asks about, and it's the same shape as Part 4's SAT brute force. Knapsack's DP would solve this too, in pseudo-polynomial time.

Common mistake. A verifier that only checks the sum. It accepts [0, 0] as a way to make 6 from a single 3. A sloppy verifier makes the whole definition of NP useless: a "proof" it accepts no longer proves anything.
