Why it works. The class never mentions remainders or bits: everything the machine "knows" is in the table, which is exactly what a DFA is (a finite table plus a current state). divisibleBy(5) is Erickson's δ(q, a) = (2q + a) mod 5, generated instead of written by hand, and the check against v % 5 on 1,024 numbers is the same cross-check Part 1 ran.

Common mistake. Starting with an empty list and adding a state per character. That loses the start state, so "110" gives 3 states instead of 4 and the empty input gives an empty trace. Reading n characters means being in n + 1 states, which is why runningFold returns one more element than its input.
