Run any DFA from its table

Part 1's DFAs had their moves written as code. Here the moves are data: table[q] maps a character to the next state, so one class can run any DFA.

  • trace returns every state the DFA is in, start state included. If a character has no entry in the table, the DFA rejects: return null.
  • accepts is true when the trace ends in an accepting state.
  • divisibleBy(m) builds the table for "binary numbers divisible by m": one state per remainder, and bit b takes remainder r to (2r + b) mod m (L48).
