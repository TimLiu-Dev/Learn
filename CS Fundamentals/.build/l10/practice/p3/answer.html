Why it works. Every outcome a caller should handle is now a value of the sealed AgeResult, and each one is detected on purpose. A missing field is checked, and a bad number comes from toIntOrNull. Nothing is caught broadly, so if the code had another bug, such as a wrong index, it would crash in testing instead of hiding as bad data.

Common mistake. Fixing the index but keeping catch (e: Exception). "Ada" then throws IndexOutOfBoundsException, the broad catch swallows it, and a missing field is reported as NotANumber("Ada").
