The starter's bug is check-then-act (L26): between "is it cached?" and "put it in the cache" every other thread can miss too. You need one atomic step that decides who loads. inFlight.putIfAbsent(key, future) returns null to exactly one caller.

---

On a miss, create val mine = CompletableFuture<V>() and try to register it. If putIfAbsent returns another future, join() it and return. Otherwise you're the loader: call loader(key), cache the value, mine.complete(value). Don't wrap the whole method in a lock: that makes key 2 wait for key 1.

---

Wrap the load in try/catch/finally: on an exception call mine.completeExceptionally(e) and rethrow, and in finally remove the key from inFlight, so a failure is shared once and then retried. Re-checking cache[key] after winning putIfAbsent closes the last small gap. Java's version is the same with Function<K, V> and loader.apply(key).
