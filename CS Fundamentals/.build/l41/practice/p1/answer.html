Why it works. Sorting puts the samples in rank order (L18), and nearest rank returns a value that a real request actually took, which is why p50 of [5, 5, 5, 5, 100] is 5 and p81 jumps straight to 100. With 1% slow calls, 10 calls give a 9.6% slow page and 100 calls give 63%: the tail at scale.

Common mistake. Using p / 100 × n as the index: p50 of ten values then returns the 6th smallest. Another is calling sort() on the caller's array: the answer is right, but you've silently reordered someone else's data (aliasing, L4).
