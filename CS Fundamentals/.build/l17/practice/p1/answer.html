Why it works. Without a loop, fast runs off the end and the method returns false. With a loop, both walkers end up circling it, and each round fast gains one node on slow, so the gap shrinks to zero and they meet within one lap. That's O(n) time and O(1) memory: Floyd's cycle-finding algorithm. A HashSet of visited nodes also works, at the price of O(n) memory.

Common mistake. Remembering the values you've seen. A list of four separate "x" nodes has no loop, but the second "x" looks like a revisit. A loop means the same node again, so compare nodes with ===, or keep a set of nodes.
