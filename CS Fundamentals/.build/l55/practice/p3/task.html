The token endpoint's checks

You're the authorization server. issue (given) stores a code after ana clicks Allow. Write the other end, where the app trades the code for tokens:

  • challengeOf(verifier): PKCE's S256, BASE64URL(SHA256(ASCII(verifier))) with no padding. The checks test it on RFC 7636's own example.
  • redeem(...) returns true only if the code exists, is at most 60 seconds old, was issued to this clientId and redirectUri, and the verifier's challenge matches. Any attempt, good or bad, uses the code up.
