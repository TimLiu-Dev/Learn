Why it works. Each check is one rule from the lesson. remove makes the code single use (RFC 6749 §4.1.2), and its 60-second life keeps a leaked code briefly useful at most (the RFC recommends 10 minutes at most). Matching the client and the exact redirect_uri is the token endpoint's duty in §4.1.3. The PKCE comparison means a code copied from a URL or a log is worthless without the verifier, which never left the app.

Common mistake. Looking the code up with grants[code] and never removing it. Every check still passes, so the code can be redeemed again and again: exactly what Part 3's check 1 rejects with "code already used".
