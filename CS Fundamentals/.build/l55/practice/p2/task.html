The checks around the signature

A strict verifier checks the header before the signature and the claims after it. Here both arrive already decoded, and the signature step in between is done for you. Write both checks: each returns null to accept, or the reason to reject.

  • headerProblem: alg must be exactly "HS256", else "alg must be HS256". Anything else, including "none" or a missing alg, is rejected.
  • claimsProblem, in this order: exp must be a number (a Long), else "no exp". If now >= exp + LEEWAY, it's "expired". Then aud must be the string "books-api", else "wrong audience".
