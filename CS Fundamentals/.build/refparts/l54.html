The language pipeline

Scanner (lexer)chars → tokens (type, text, line:col)
Maximal munchlongest token wins: letter is a name; Java reads a--b as a -- b ★
Lookahead/ vs //: peek one char
Tokens are regulareach kind is a regex; nesting is not (L51) ★
Parsertokens → syntax tree (sealed type)
Interpreterwalk the tree, post-order, with an environment (name → value)
Compilertree → bytecode, same post-order walk, emitting
Static checkresolve names before running, so errors come in one order
