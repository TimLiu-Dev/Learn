Why it works. Every inversion is either inside one half, which the recursion counts, or crosses the middle, which the merge counts. When right[j] goes first, the left.size - i items still waiting on the left are all bigger, so each makes one crossing inversion. Counting them in one addition, instead of one by one, keeps the whole thing O(n log n).

Common mistake. Taking from the right on a tie, right[j] <= left[i]. The array still ends up sorted, but every pair of equal values gets counted: [2, 2, 2] gives 3 instead of 0. It's the same < that makes merge sort stable.
