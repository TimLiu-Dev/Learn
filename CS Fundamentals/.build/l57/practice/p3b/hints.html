The store needs to remember two things per key: its value and the highest token it has accepted. Two maps keyed by the key will do.

---

Reject only when a token is smaller than the highest one seen. An equal token comes from the same lease, so it's the current holder writing again. A rejected write must not touch either map.

---

val seen = highest[key]; if (seen != null && token < seen) return false, then store both the token and the value and return true. In Java, highest.get(key) returns a Long that may be null; mark both methods synchronized so the check and the write happen as one step.
