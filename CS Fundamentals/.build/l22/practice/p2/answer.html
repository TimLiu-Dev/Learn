Why it works. Row-major reads 4 neighbours per line, so only the first read of each line misses: 64 / 4 = 16. Column-major cycles through 8 lines per column with room for only 4, so LRU always evicts exactly the line it will need next: 64 misses. Same accesses, same Big O, four times the misses. Give the cache 16 lines, enough for the whole grid, and column-major is fine again. That's why the real Grid was only slow once the grid outgrew the caches.

Common mistake. Evicting the oldest inserted line (first in, first out) instead of the least recently used. A plain LinkedHashSet, or a LinkedHashMap without accessOrder = true, does exactly that, and the "hit makes a line recently used" check counts 4 misses instead of 3.
