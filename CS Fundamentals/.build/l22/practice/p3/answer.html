Why it works. Each call to the source fetches up to a whole buffer, and the next 15 read()s are just array lookups, so 100 bytes cost 8 calls instead of 101. With an 8 KB buffer the ratio becomes about 1 call per 8,192 bytes, which is where Part 3's 60× came from. This is what BufferedInputStream does, plus thread safety and mark/reset.

Common mistake. Setting count = buf.size after a refill. With a source that returns only 5 bytes, the next 11 reads hand out stale bytes. It's the same bug as out.write(buffer) instead of write(buffer, 0, n) in the copy exercise: always trust the count read returns.
