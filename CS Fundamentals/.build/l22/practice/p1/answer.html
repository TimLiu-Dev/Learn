Why it works. Translation replaces only the page number. The offset passes through untouched, so neighbouring bytes stay neighbours inside a page. Because every process has its own page table, the same virtual address can land in different frames, which is how two JVMs both used 0x7c0000000. Real CPUs do this split in hardware on every access, with the TLB caching recent page → frame lookups.

Common mistake. Returning frame * PAGE_SIZE and forgetting the offset. Every byte of the page would then translate to the page's first byte. The "keeps the offset" check catches it.
