Why it works. Timestamp-then-node is a total order: any two different versions have a clear winner, and every replica computes the same one. That makes the merge commutative (order doesn't matter) and idempotent (a duplicate changes nothing), which is exactly what L42's at-least-once delivery needs. So the replicas always converge. They still converge by throwing one write away: the lamp is lost. Agreement isn't the same as keeping data, which is why the exercise keeps both versions instead.

Common mistake. Keeping the lesson's if (b.ts > a.ts) b else a. With one shared clock a tie never happened; with a counter per replica it does, and then each side keeps its own value forever: two "consistent-looking" replicas that silently disagree.
