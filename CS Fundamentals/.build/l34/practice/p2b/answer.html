Why it works. NOT EXISTS runs the subquery for each customer and asks only whether it found a row. A guest order's NULL customer_id never equals c.id, so it simply doesn't match, and Eli and Fay come back. Chen stays out: a cancelled order is still an order.

Common mistake. Trusting NOT IN because it worked in testing. It's correct only while the subquery has no NULLs, and here one guest checkout broke it. Adding WHERE customer_id IS NOT NULL inside the subquery also fixes it, but every future NOT IN needs the same care. NOT EXISTS is safe by design.
