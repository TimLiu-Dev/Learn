Why it works. Each rule lives on its column. NOT NULL makes book_id and stars required, the CHECKs limit their values, and ON DELETE CASCADE removes book 3's review along with the book. SQLite's docs say a CHECK that "evaluates to NULL … is not a constraint violation" (CREATE TABLE: CHECK constraints), so one CHECK on body both bans '' and keeps it optional. Part 2 explains why NULL makes a test unknown.

Common mistake. Copying the demo table exactly: stars INTEGER CHECK (stars BETWEEN 1 AND 5) without NOT NULL lets a review with no rating in. Leaving out ON DELETE CASCADE is the other one: then deleting book 3 fails with "FOREIGN KEY constraint failed".
