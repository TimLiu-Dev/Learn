Write range first and make lookup(key) simply range(key, key). Both are "find the start once, then walk right until a key is too big". All the cleverness is in lowerBound.

---

For lowerBound, keep lo = 0 and hi = size, with the answer always somewhere in lo..hi. Look at at(mid).key: if it's smaller than key, the answer is to the right (lo = mid + 1); otherwise mid itself might be the answer (hi = mid). Stop when lo == hi.

---

Don't return mid when the key is equal: with ten entries for member 42, you'd land on any one of them and miss those to its left. That's L18's binary search with one change. The walk is var i = lowerBound(lo); while (i < size) { val e = at(i++); if (e.key > hi) break; out += e.rowid }. Beware buildList { } here: inside it, size means the list being built (0), not the index. In Java, use (lo + hi) >>> 1 and an ArrayList.
