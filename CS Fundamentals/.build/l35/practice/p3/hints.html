Run the starter and read the plan: author_id alone gets you a SEARCH, but two problems remain. The rows still come out unsorted, and each one needs a trip to the table for year and title.

---

The sort disappears when the index already holds each author's books in year order: (author_id, year). Within one author, the entries are sorted by year, exactly like plan 5 in eqp.sql. Now ask: which column does the query still read from the table?

---

Add title after year: (author_id, year, title). Put it before year and the sort comes back, because within an author the entries would be in title order. Put year first and you're back to a SCAN: the leftmost prefix rule.
