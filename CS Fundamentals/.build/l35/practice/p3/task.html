One index, one line of plan

An author page runs SELECT year, title FROM books WHERE author_id = 2 ORDER BY year. With no index, its plan reads the whole table and then sorts; the starter's index on author_id alone fixes only half of that. Change the columns of that one CREATE INDEX (keep the name idx_books_author_year_title) so that the plan is a single line: a SEARCH using a COVERING INDEX, with no temp B-tree.

The check prints the plan after your statements; read its detail column. (Ignore id, parent and notused: they are SQLite's bookkeeping.)
