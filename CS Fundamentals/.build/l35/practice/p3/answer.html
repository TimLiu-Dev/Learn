Why it works. The column order follows the query: equality on author_id picks one contiguous slice of the index, year next means that slice is already in ORDER BY order, and title last means every column the query reads is in the index. So SQLite descends once, walks the slice, and never touches the table: SEARCH books USING COVERING INDEX idx_books_author_year_title (author_id=?).

Common mistake. (author_id, title, year). It has the same three columns and is still covering, but within one author the entries are sorted by title, so USE TEMP B-TREE FOR ORDER BY comes back. In a composite index, the order of the columns matters as much as which columns are in it.
