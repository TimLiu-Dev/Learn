Messages back out of a stream

Stream used readFully, which keeps reading until a message is complete. A server built on a Selector can't wait like that: each read hands it whatever bytes have arrived, which may be half a message, or two and a bit.

  • frame(message) encodes one message the way Stream did: a 4-byte big-endian length, then the UTF-8 bytes.
  • FrameDecoder.feed(chunk) is called with each read's bytes and returns every message that the chunk completes, in order. Bytes of an unfinished message wait for the next call.

The last check sends three frames over a real loopback socket and reads them 3 bytes at a time.
