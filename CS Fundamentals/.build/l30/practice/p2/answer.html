Why it works. Each entry remembers its deadline, so every lookup can say how long it has left. That's the countdown dig showed when the router answered from its cache. The fake clock is passed in as a function (L14), so a test can jump 300 seconds in a microsecond. The fixedTtl check is the Part 2 warning in code: a JVM can keep using 10.0.0.5 for 30 s even though DNS said 5.

Common mistake. Testing left < 0 instead of left <= 0. At the exact moment the TTL runs out, the cache still hands out an answer with 0 seconds left: one second longer than DNS allowed.
