This is L21's depth-first search, with one twist: add a task to the result after visiting all its dependencies (post-order). A recursive visit(name) inside executionOrder keeps it short.

---

You need two sets. done holds tasks already in the order, so a shared dependency like classes is skipped the second time. path holds the tasks on the current chain of calls. Meeting a task that is already on path means you went round a loop.

---

The cycle message is the part of path from the repeated task onwards, plus that task again: path.drop(path.indexOf(name)) + name, joined with " -> ". Check unknown names with tasks[name] ?: throw …. In Java, an ArrayDeque used with push keeps the newest task at the front, so reverse it before cutting out the cycle.
