Why it works. The service reports what happened as a sealed result, and only the handler knows HTTP, so the status codes live in one exhaustive when: a new result type won't compile until it's mapped. Validation runs first and collects every problem, so a client fixes its request in one round trip, and lend never sees an incomplete command.

Common mistake. Keeping the default Json. It writes "returned":null into the 201 and "errors":null into every 404 and 409. Valid JSON, but not the shape Shelf promises, and not what the Java server sends.
