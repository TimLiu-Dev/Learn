Start with the generator: val rnd = Random(seed), then inside repeat(runs) make List(rnd.nextInt(0, 31)) { rnd.nextInt(1000) } and rnd.nextInt(1, 11). Seeding is what makes a failure replayable.

---

For each case, loop: ask for the page at offset, stop on an empty page, append it to a list, and add limit to offset. Return a message as soon as a page is longer than limit, and compare the collected list with the original at the end. Bound the loop (say, offset <= items.size + limit), so a buggy pager can't keep you going forever.

---

Wrap the loop in try { … } catch (e: Exception) { return "threw $e …" }: one hidden pager throws past the end of the list, and that's a failure to report, not a crash. Put the inputs in every message, as in "pages gave $read: items=$items, limit=$limit". In Java, use new java.util.Random(seed), nextInt(0, 31) and addAll.
