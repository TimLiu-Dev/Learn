Both methods have the same shape: lock.withLock { … }; wait while you can't go on; change items; signal the other side. await() must be called while holding the lock, and it gives the lock up while it sleeps.

---

put: while (items.size == capacity) notFull.await(), then items.addLast(item) and notEmpty.signalAll(). take mirrors it with notEmpty, removeFirst() and notFull.signalAll(), and returns the item as the block's last expression.

---

It must be while, not if. signalAll() wakes every waiting taker, but only one gets the item; the others must check again and go back to sleep. Spurious wake-ups are allowed too. In Java, both methods declare throws InterruptedException and use lock.lock(); try { … } finally { lock.unlock(); }.
