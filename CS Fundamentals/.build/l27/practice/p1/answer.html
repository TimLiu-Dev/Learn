Why it works. The second check inside synchronized(lock) makes "check, then init" one atomic step, so a caller that lost the race finds the value already set and returns it. The first check skips the lock entirely once the value exists. It's safe only because value is volatile: the volatile write happens-before every later read, so a reader that sees the reference also sees everything init wrote. This is the shape of Kotlin's SynchronizedLazyImpl behind by lazy.

Common mistake. Dropping @Volatile. Every test you could run would still pass, which is exactly how broken double-checked locking spread; the modifier check is there because no timing test can catch it. The opposite mistake is locking the whole method: correct, but every call then queues for the lock.
