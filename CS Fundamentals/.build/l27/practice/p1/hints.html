Start with the slow path: wrap the "check, then run init" part in synchronized(lock) { … }, and check value again inside it. That alone fixes the race.

---

Now put the first check back in front of the lock: value?.let { return it }. Once the value exists, callers return without ever touching lock. That read happens with no lock, so which keyword from Part 1 does the field need?

---

@Volatile private var value: T? = null. Without it, the unlocked read has no happens-before edge to the write, so a reader could see the reference before the constructor's writes. In Java: private volatile T value;, and read it once into a local (T v = value;) on the fast path.
