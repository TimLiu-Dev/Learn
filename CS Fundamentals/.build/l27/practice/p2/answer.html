Why it works. With one global order, a thread waits only for a lock that's higher than every lock it holds, so the "waits for" arrows can never close into a cycle: circular wait is broken. The worst-interleaving check proves it. With the old order, both threads take their first lock, then each waits for the other's; with the fix, the second thread blocks on account 1 while holding nothing. audit is the same rule for n locks, and the recursion keeps every earlier lock held until the sum is done.

Common mistake. Locking the accounts one at a time in audit: sumOf { a -> a.locked { a.balance } }. It's in the right order and each read is safe, but a transfer can move money between two reads, so the total can be off by the amount in flight.
