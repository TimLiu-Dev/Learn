Why it works. Every question about time now goes to the injected Clock, so a test decides what "now" is, and can move it forward by exactly 3 days minus 1 ms. The ids come from newId, so they're predictable too. The class didn't get any less real: main passes Clock.systemUTC() and { UUID.randomUUID().toString() }.

Common mistake. Reading the clock once, into a field: private val now = clock.millis(). It compiles and the first check passes, but the shelf's "now" is frozen at construction, so no hold ever expires. The dependency is the clock, not one reading of it.
