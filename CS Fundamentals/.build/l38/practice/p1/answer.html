Why it works. Checkout depends only on the DiscountRule interface, so it's closed for modification and open for extension: FlatOff and the lambda arrive without a single edit. Because DiscountRule is a fun interface, a one-off promotion can even be a lambda (L14).

Common mistake. Moving the branches but keeping a when (rule) { MemberDiscount -> …; BulkDiscount -> …; else -> 0 } in Checkout. It passes the first three checks, then silently gives new rules a discount of 0. That's the chain of type checks from L8, back again.
