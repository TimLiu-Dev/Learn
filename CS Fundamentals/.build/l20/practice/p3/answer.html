Why it works. Leaves are already one-item heaps. Going backwards, each parent you reach sits on top of two heaps, and one sift-down merges them into a bigger heap. The same loop is in the JDK's PriorityQueue.heapify(), which is why the random test agrees with it exactly. Most nodes are near the bottom and sink only a level or two, so the total is O(n), not O(n log n). Note that [1, 2, 8, 3, 5, 9] differs from the [1, 2, 8, 5, 3, 9] that six adds gave: both are valid heaps.

Common mistake. Looping from the root down: for (i in 0 until n / 2). When you sift the root, its subtrees aren't heaps yet, so a small key deep down never gets up. Reverse-sorted input 9…1 ends as [7, 5, 3, 1, 8, 4, 9, 2, 6]: 7 at the root, with 1 two levels below it.
