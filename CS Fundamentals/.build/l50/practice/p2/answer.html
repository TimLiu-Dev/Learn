Why it works. It's choose, explore, un-choose, where each level picks the next number to the right of the last one. That's why each subset comes out ascending, and found once. The break is the pruning: on a sorted list, one number that overshoots means all later ones do, so the whole rest of the loop and every subtree below it is skipped. On 1 to 40 with target 3, the search makes a handful of calls instead of 240. This is Erickson's subset-sum problem from the same chapter.

Common mistake. Recursing with go(i, …) instead of go(i + 1, …). That allows reuse, so answers like [1, 1, 1, 1, 1] and [1, 2, 2] appear for target 5. That's LeetCode's Combination Sum, a different problem.
