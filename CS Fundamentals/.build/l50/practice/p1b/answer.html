Why it works. Each prefix sum is stored once, at the first index where it occurs. For a fixed end i, the longest run summing to k starts just after the earliest prefix equal to sum - k, and that's exactly what the map holds. One pass and O(1) map operations on average (L19) make it O(n). A sliding window can't do this: with negatives, growing the window can lower the sum.

Common mistake. Writing firstAt[sum] = i instead of putIfAbsent. The map then holds the latest index, so on [1, -1, 1, -1] with k = 0 the answer comes out as 2, not 4.
