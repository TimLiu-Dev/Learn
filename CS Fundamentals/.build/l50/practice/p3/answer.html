Why it works. Every prefix of query lies on one path from the root, so a single walk visits them all, shortest first. The last word end on that path is the longest match. The walk takes at most query.length steps, however many routes are stored. This is the routing example from the callout. Real routers match on the address's bits, not its characters, so 128.11 can't accidentally match 128.112… the way it would here.

Common mistake. Copying ?: return null from find. Falling off the trie then throws away the word end you already passed, so "shelf" gives null instead of "she".
