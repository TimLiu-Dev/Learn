Each bug is a different rule from the stream docs. squares and countLong write to shared state from inside the pipeline (side effects). balance breaks the rule that reduce's first argument must be an identity: accumulator(identity, t) == t. Every chunk starts from it.

---

Let the stream build the result instead of mutating something outside it. A collecting terminal operation (toList()) keeps encounter order; filter + count() replaces the counter; and reduce should start from 0L, with the opening amount added once, outside.

---

nums.parallelStream().map { it * it }.toList(), opening + deposits.parallelStream().reduce(0L) { a, b -> a + b }, and words.parallelStream().filter { it.length > 5 }.count().toInt(). In Java, the counter can't even be a plain local: lambdas may only capture effectively final variables, which is why AI-written Java reaches for int[] n = {0}. That compiles and races just the same.
