Why it works. bill only describes the work: each method returns a new stage at once, and the result completes when its inputs do. thenCompose expresses "orders need the user" without nesting futures, and thenCombine joins in the discount, which was started first so it overlaps the lookups. A failure skips every later stage until exceptionally turns it into a value.

Common mistake. Using e.message in exceptionally. A failure from an earlier stage arrives wrapped in CompletionException, whose message is the cause's toString(): java.lang.IllegalStateException: orders down. Unwrap cause first.
