Why it works. A parameter is a copy of the caller's arrow. That's exactly what makes swapCounts work: it changes the objects, which the caller shares. It's also why the old topThree broke the caller's list: sortDescending() sorted the one list both arrows point at. sortedDescending() sorts a new list instead. The tmp swap survives swapCounts(x, x), because it only ever writes values it saved first.

Common mistake. val sorted = scores, then sorting sorted. That copies the arrow, not the list, so the caller's list is reordered anyway. The arithmetic swap (a.count = a.count + b.count…) fails too: when a and b are the same object, it sets the count to 0.
