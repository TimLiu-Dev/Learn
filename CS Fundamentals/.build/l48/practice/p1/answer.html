Why it works. Two boolean inputs give exactly 2 × 2 = 4 rows (the product rule from Part 2), and equivalent visits every one of them. So when it returns true, it hasn't just gathered evidence, the way Claim B's 40 tests did: it has checked every case there is, and that's a proof. The converse fails on two rows, (true, false) and (false, true), which is why it isn't equivalent.

Common mistake. One loop instead of two: bools.all { b -> f(b, b) == g(b, b) }. It checks only the rows where p and q are equal, which are exactly the rows where an implication and its converse agree, so it "proves" the converse.
