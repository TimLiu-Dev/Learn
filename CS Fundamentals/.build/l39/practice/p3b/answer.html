Why it works. Switching on the state first makes each state's branch a list of the commands it accepts, so "what can happen to a published document?" has a one-line answer: nothing. The outer when has no else, so adding a fifth state stops the build until you decide what it accepts. The commands are plain objects, which is what lets replay rebuild a document's state from a stored list of them.

Common mistake. Switching on the command first, as in "Edit always gives a Draft". It reads well, and it quietly lets someone edit a document under review, or reopen a published one. The illegal-moves test catches it. An else branch on the outer when has the opposite problem: a new state is silently treated as "accepts nothing" instead of failing the build.
