Why it works. init runs on every path to a Booking: a direct call, copy, allDay and parse. So the cross-field rule start < end is checked once, in one place, and an invalid booking can't exist. The factories only translate their input into a constructor call. Java's version is the same idea: the record's compact constructor holds the rules, and the Builder is just a friendlier way to call it.

Common mistake. Bringing the Java habit across and validating in a factory such as Booking.of(…), the way a Builder validates in build(). The constructor stays public, and copy calls it directly, so b.copy(end = 9) quietly makes a booking that ends before it starts.
