Lists are eager: mapNotNull finishes the whole list before take starts. What one call turns the chain lazy, and what do you need at the end to get a List back?

---

ids.asSequence().mapNotNull(lookup).take(n).toList(). For collatz, use generateSequence(start) { n -> … }: return the next number, or null when n is 1. The seed and every non-null result are emitted, so 1 is still included.

---

Inside the lambda: when { n == 1 -> null; n % 2 == 0 -> n / 2; else -> 3 * n + 1 }. In Java, firstFound is ids.stream().map(lookup).filter(Objects::nonNull).limit(n).toList(). Stream.iterate(seed, hasNext, next) stops before emitting the element that fails hasNext, so you need a trick to keep the 1: for example, step from 1 to a sentinel 0 and use x -> x != 0.
