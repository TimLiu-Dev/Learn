Why it works. asSequence() makes each id travel through mapNotNull and take before the next id starts, so once take(n) has its names, nothing more is pulled and lookup isn't called again. generateSequence emits the seed, then keeps applying the function until it returns null.

Common mistake. Adding asSequence() after the eager step: ids.mapNotNull(lookup).asSequence().take(n). The answer is right, but by then the list's mapNotNull has already looked up every id. Laziness starts where asSequence() is.
