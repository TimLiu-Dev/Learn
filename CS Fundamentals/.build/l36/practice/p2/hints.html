Think about what the database does with WHERE … AND version = ?: if the row's version isn't the one you pass, the row doesn't match, nothing changes, and the update count is 0.

---

updateIfVersion: if version != expectedVersion, return 0. Otherwise set the balance, add 1 to the version, and return 1. writeIfUnchanged passes seenBalance + amount and seenVersion, and returns whether the count was 1.

---

In runSchedule: if (!ok) { retries++; queue.addLast("$name read"); queue.addLast("$name write") }. Forgetting the version++ is the subtle bug: every check then passes and the lost update is back. In Java, use step[0] + " read".
