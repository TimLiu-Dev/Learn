Why it works. After the checks, every character of the SQL text comes from your own code: fixed words, an allowlisted column name, and ?. User input exists only in params, where the driver sends it as data. That is OWASP's two rules in one function: bind values, and map identifiers to an allowlist.

Common mistake. Binding every value but gluing the keys in unchecked. The values are safe, yet a key like name = 'x', email still changes the statement, and a key like is_admin lets the client set a column you never meant to expose (mass assignment).
