Start from topoSort in Topo.kt: count what each task is waiting on, reverse the edges into unlocks, and keep a collection of ready tasks. Only that collection has to change.

---

"Repeatedly take the smallest" is a PriorityQueue (L20). Strings compare alphabetically, so PriorityQueue(readyKeys) needs no comparator. Use add to put a task in and poll to take the smallest out.

---

Sorting the ready tasks once at the start isn't enough: a task unlocked later must still compete with the ones already waiting, and the heap does that in O(log n) per task. The cycle check doesn't change: fewer tasks out than in means some never reached zero. Java's new PriorityQueue<>(collection) works the same way.
