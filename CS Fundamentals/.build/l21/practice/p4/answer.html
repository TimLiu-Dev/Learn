Why it works. Kahn's algorithm doesn't care which ready task you take, only that it's ready, so any choice gives a valid order. A PriorityQueue makes the choice "the smallest", at O(log n) per add and poll. The result is the alphabetically smallest valid order, and it no longer depends on the map's iteration order.

Common mistake. Sorting the initial ready tasks and keeping a FIFO ArrayDeque. The first test passes, but a task unlocked later joins the back of the queue, so a runs after z.
