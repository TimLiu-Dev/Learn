Why it works. Each call to memoize makes a new map, and the returned lambda captures it, so every memoized function has a private cache that outlives the call that created it. In multipliers, a for loop creates a new k per iteration, so each lambda captures a different variable.

Common mistake. Creating the map inside the returned lambda. It compiles and gives the right answers, but every call starts with an empty map, so nothing is ever cached. The check that counts calls to f catches it.
