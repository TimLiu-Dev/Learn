Why it works. Each status answers a different question. 404: there's nothing at this path. 405: there is, but not for this method, and Allow says what would work (RFC 9110 §15.5.6 requires it). 422: the request was well-formed, but the content makes no sense. 409: it clashes with what's already stored. 201: something new now exists, and Location says where.

Common mistake. Matching method and path together, as in method == "GET" && path == "/notes", with a 404 at the end. Every route works, but DELETE /notes says "not found" about a resource that plainly exists.
