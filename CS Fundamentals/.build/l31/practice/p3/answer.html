Why it works. A cache that holds several versions sends all their tags, and one that stored a weak tag sends it back with W/. If any of them is current, the client already has the bytes, so the origin answers 304 with only the headers a 200 would have sent for caching: ETag and Cache-Control (RFC 9110 §15.4.5). A 304 ends at the blank line: it "cannot contain content".

Common mistake. ifNoneMatch == etag, which is what this part's EtagServer does. It works for a client that sends back exactly one strong tag, but answers 200 for a list, a W/ tag or *, so those clients download bytes they already have.
