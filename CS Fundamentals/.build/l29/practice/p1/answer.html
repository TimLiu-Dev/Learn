Why it works. async starts each call and returns at once, so all three are running before the first await(). coroutineScope is the parent: when friendCount fails at 200 ms, it cancels posts (its delay throws CancellationException), waits for it to stop, then rethrows the IOException. supervisorScope doesn't cancel siblings, so page 13's failure waits in its Deferred until you await() it. Java has no scope to do this, so you cancel the other futures by hand, and the executor's close() waits for them.

Common mistake. Page(api.name(id), api.friendCount(id), api.posts(id)). It returns the right page, but the calls take 100 + 200 + 300 ms one after another. For id 13, posts never even starts, so there's nothing to cancel.
