Wrap the work in withContext(someDispatcher) { … }. The code after withContext is automatically back on the caller's dispatcher, so the "carries on on the UI thread" check needs nothing extra.

---

Inside the block, start one async { table to db.countRows(table) } per table, then awaitAll() and toMap(). If one count comes back as -1, that call waited for others that never started: they had no free thread.

---

Use Dispatchers.IO, not Default: these calls block, and Default has only as many threads as cores (L29's "Never block a Default thread"). In Java, call CompletableFuture.supplyAsync(() -> db.countRows(t), io) for each table, then join() them all.
