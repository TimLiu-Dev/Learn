Why it works. Each thread works on its own register, just as each real thread has its own registers and stack (L22). A write only puts back what that thread read earlier, so if the other thread wrote in between, its write is overwritten. Of the 20 possible orders, only the 2 that run one whole count++ after the other give 43. The other 18 lose an update.

Common mistake. Using one register for both threads. Then B's add works on A's value, and "ABAABB" gives 43. The simulation turns count++ back into one indivisible step, which is exactly the false belief that causes the race.
