Why it works. Every call to get holds the same lock from the check to the store. A second thread asking for any key waits (BLOCKED) until the first has stored its value, and then it finds the value cached. The same lock also makes loads++ safe and guards the reads of loads.

Common mistake. Locking the check and the store separately so that the slow loader runs outside the lock. Each step is safe, but the pair isn't: this is the JLS warning about "groups of operations" again. The price of the correct version is that a slow load holds up every key. L27's ConcurrentHashMap.computeIfAbsent locks per key instead.
