Why it works. All the threads start before any join, so they run at the same time and the three meeting tasks find each other. Each thread writes only its own array slot, so nothing is shared while they run. join then waits for every thread and makes their writes visible to the caller.

Common mistake. Joining each thread straight after starting it: thread { … }.join() inside the loop. It gives the right results, but the threads run one at a time, so you pay for the threads and get no concurrency. Calling run() instead of start() does the same, on the caller's thread.
