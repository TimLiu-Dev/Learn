Why it works. Each function now asks its own question. Arrays inherit identity equals, so contentEquals compares the elements. A change made through one reference shows through the other only when both point at one object, which is exactly what === checks. String overrides equals, so == finds a name typed at runtime, which === missed because it's a different object from the literal.

Common mistake. Deciding that Kotlin's == is always right and using it in isSameList too. A copy with equal contents is still a separate object: adding to it doesn't change the original.
