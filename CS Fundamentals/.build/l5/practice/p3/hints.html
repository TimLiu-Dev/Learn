There are two leaks: one on the way in (the constructor keeps the caller's list) and one on the way out (all returns the book's own list). Each needs a copy.

---

On the way in, the book still needs a list it can add to, so a plain toList() copy won't do. toMutableList() makes a mutable copy that only the book holds. Take the constructor parameter as a plain List<Int> while you're at it.

---

On the way out, get() = scores.toList() returns a fresh snapshot each time, so a list someone got earlier stays as it was, and a cast reaches only the copy. In Java: new ArrayList<>(scores) in the constructor, and List.copyOf(scores) in all().
