01 · Mental Model Bridge

Android Touch Dispatch, RecyclerView & Room DB → Browser Native APIs

If you have built Android UIs, you already understand tree-based event routing, viewport visibility callbacks, and structured local persistence. On the Web, these responsibilities live in standardized browser APIs rather than framework classes—and understanding their exact thread and lifecycle semantics prevents classic bugs.

First principles on the Web: A DOM event travels down from window to the clicked element (capturing), hits the element (target), and climbs back up (bubbling). Meanwhile, browser Observers batch geometry or DOM changes asynchronously off the hot scroll/resize path, localStorage blocks the main thread synchronously with strings only, IndexedDB runs asynchronously with indexed transactions, and structuredClone + Intl replace bulky utility packages natively.

Concept Domain Android / JVM Equivalent Web Browser Mechanism Key Web Pitfall
Event Propagation dispatchTouchEvent → onInterceptTouchEvent → onTouchEvent 3 DOM phases: Capture (top-down) → Target → Bubble (bottom-up) Confusing e.target (actual clicked node, e.g. an icon <span>) with e.currentTarget (listener owner).
List Item Clicks Single RecyclerView.Adapter click callback Event Delegation: one listener on parent + e.target.closest(selector) Attaching N listeners to N rows leaks memory and breaks when new rows are inserted dynamically.
Visibility & Size RecyclerView.OnScrollListener / View.onSizeChanged IntersectionObserver (visibility) & ResizeObserver (element box size) Polling getBoundingClientRect() inside scroll listeners triggers Layout Thrashing.
DOM Tree Watching ViewTreeObserver.OnGlobalLayoutListener MutationObserver (batches childList/attribute mutations as a microtask) Mutating the observed node inside its own callback without guarding causes infinite microtask loops.
Local Persistence SharedPreferences vs Room / SQLite localStorage / sessionStorage (sync ~5MB strings) vs IndexedDB (async DB) Storing JWTs in localStorage exposes them to XSS; large JSON freezes the main thread on parse.
Clone & Formatting Kotlin copy() & java.text.NumberFormat / DateTimeFormatter structuredClone() & Intl.NumberFormat / DateTimeFormat / RelativeTimeFormat JSON.parse(JSON.stringify(x)) silently drops Map/Set, turns Date into strings, and crashes on cycles.

06 · Real-World Verification & Next Steps

Chrome DevTools Verification Checklist + Teacher Follow-Up

  • Event Listeners & Delegation Audit: In DevTools → Elements → Event Listeners, verify lists attach a single delegated listener on the parent container rather than N duplicate listeners on every child row. Use monitorEvents(el, "click") in Console to trace live bubbling.
  • Observer & Layout Safety: In DevTools → Performance, scroll long feeds and resize panels. Confirm lazy images and infinite scroll use IntersectionObserver / ResizeObserver instead of synchronous scroll + getBoundingClientRect() reads.
  • Storage & Serialization Audit: In DevTools → Application → Storage, verify large structured offline datasets live in IndexedDB (never multi-megabyte JSON strings in localStorage) and sensitive session tokens are not stored in JS-readable Web Storage.
  • Bundle Hygiene Check: Audit package.json for heavy cloning or date/currency formatting utilities that native structuredClone() and Intl.* already handle with zero bundle bytes.
  • i18n & RTL Readiness: Test with pseudolocalization (~30% longer strings) and dir="rtl"; verify pluralized strings use ICU MessageFormat rules (never hardcoded count === 1 ? "" : "s") and locale bundles load lazily per active locale.
Primary Source Recommendation: Study MDN: Event Delegation & Bubbling and MDN: Intl, plus MDN references for IntersectionObserver, IndexedDB, and structuredClone().
