01 · Mental Model Transfer

JVM Stack/Heap, Lambdas & WeakReference → V8 Execution Context, Closures & WeakMap GC

Before diving into tricks, start with the fundamentals of how V8 executes JavaScript. Every time JS starts running a file or invokes a function, the engine creates an Execution Context and pushes it onto the single-threaded Call Stack. Each Execution Context has two phases: (1) the Creation Phase, which builds the Lexical Environment (allocating bindings for var initialized to undefined, function declarations, and uninitialized let/const in the Temporal Dead Zone) and resolves this; and (2) the Execution Phase, which assigns values and runs statements line by line. Because functions are first-class heap objects that retain a hidden link to the Lexical Environment where they were defined, a returned inner function keeps outer variables alive in the heap long after the outer stack frame pops—that is a closure.

06 · Real-World Verification & Next Steps

Chrome DevTools Memory Verification Checklist + Teacher Follow-Up

  • Detached DOM Audit: Open DevTools → Memory → take a Heap Snapshot after navigating away from a view or closing a modal, then type Detached in the class filter to spot uncollected DOM subtrees held by closures or event listeners.
  • Closure Retention Inspection: Click any leaked object in the Heap Snapshot and inspect the bottom Retainers pane. Look for context / Closure entries showing exactly which outer variable keeps the object reachable from a GC root.
  • Allocation Timeline Check: Record Allocation instrumentation on timeline while repeatedly opening and closing a component; blue bars that stay solid after GC runs indicate retained objects (e.g., an unbounded Map cache instead of a WeakMap).
  • Proxy & Error Diagnostics: In Console/Sources, expand err.cause chains and verify custom Proxy traps forward via Reflect so stack traces and getter receivers remain intact.
