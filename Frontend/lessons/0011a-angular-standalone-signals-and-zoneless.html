Angular Internals: Standalone Components, Signals & Zoneless Change Detection

Modern Angular looks almost nothing like legacy NgModule + Zone.js Angular. In this lesson, you will learn first-principles Angular reactivity from the ground up: why Standalone Components replaced NgModule, how signal(), computed(), effect(), and untracked() form a glitch-free reactive graph, how signal-based input()/model()/output() replace decorator boilerplate, and how OnPush + Zoneless change detection eliminate full-tree dirty checking.

01 · Mental Model Bridge (Android Bridge)

Compose State & Remember → Standalone, Signals & Zoneless

If you have built UIs in Jetpack Compose, Angular's modern reactivity model will feel remarkably familiar. In Compose, a @Composable function declares its own imports via Kotlin file scope, reads State<T> snapshots, derives memoized values with derivedStateOf, and triggers fine-grained recomposition only for the scopes that actually read the changed state. Modern Angular brings that exact same model to TypeScript templates—replacing legacy NgModule registries and global Zone.js monkey-patching.

Concept Jetpack Compose / Android Modern Angular (v17–v19+) First-Principles Web Nuance
Component Packaging @Composable function imports dependencies directly at top of file Standalone Component (standalone: true default in v19+; explicit imports: [...]) Eliminates legacy NgModule indirection so Angular's compiler + Vite/esbuild can tree-shake unused directives per component.
Mutable Local State remember { mutableStateOf(0) } count = signal(0) with .set() / .update() Reading count() inside a template or computed() automatically registers a dependency edge in Angular's reactive graph.
Derived State remember { derivedStateOf { ... } } total = computed(() => price() * qty()) Lazy & memoized: marked dirty on write, recomputed only when read, and guaranteed glitch-free across diamond graphs.
Side Effects LaunchedEffect(key) / snapshotFlow effect(() => { ... }) + untracked() + onCleanup() Runs asynchronously after change detection/render scheduling; use untracked() to read a signal without subscribing to it.
Component API Function parameters + callbacks (value, onValueChange) input(), input.required(), model(), output() Signal inputs are read-only reactive signals; model() creates a writable two-way signal pair ([(value)]).
Change Detection Snapshot system invalidates only reading RecomposeScopes OnPush + Zoneless (provideZonelessChangeDetection() / experimental in v18) Legacy Zone.js monkey-patched every browser async API and walked the entire component tree; Zoneless updates only dirty Signal views.
Why Legacy Angular Had NgModule & Zone.js: Before Signals, TypeScript classes used plain mutable fields (this.count = 1) with no runtime tracking. Angular couldn't know which component changed after a setTimeout or HTTP response, so Zone.js monkey-patched all browser async APIs (Promise, addEventListener, setTimeout, XHR) to ask Angular to dirty-check the whole tree from root to leaves. Signals give Angular explicit read/write tracking, making Zone.js unnecessary—just as Compose's Snapshot system avoids invalidating your whole Activity layout.

06 · Production Verification & Angular DevTools

Angular DevTools Profiler Checklist & Next Steps

  • Angular DevTools → Profiler: Record a user interaction and switch to the Flame Chart or Bar Chart view. In a healthy OnPush / Zoneless app, only the interacted subtree lights up—if the entire root-to-leaf tree flashes on a mousemove or timer tick, you have a Default CD component or un-throttled Zone.js event listener.
  • Signal Graph Inspection: In Angular DevTools (v18+/v19+), inspect a component's Signals panel to verify which signal(), computed(), and input() values are live and ensure no effect() is bouncing values back into writable signals.
  • Zoneless Readiness Audit: Remove zone.js from polyfills in angular.json, enable provideExperimentalZonelessChangeDetection() (v18) or provideZonelessChangeDetection() (v20+), and test async flows (setTimeout, WebSockets, third-party libs) to verify every view mutation goes through a Signal, async pipe, or ChangeDetectorRef.markForCheck().
  • Immutability Guardrail: Search for .push(, .splice(, or .sort( on component state arrays. Replace them with signal.update(arr => [...arr, item]) or arr.toSorted(...) so Object.is equality triggers change detection reliably.
