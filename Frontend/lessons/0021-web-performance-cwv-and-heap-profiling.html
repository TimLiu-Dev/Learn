01 · Mental Model Transfer & First Principles

From Android JankStats & LeakCanary to Core Web Vitals & Heap Snapshots

On Android, your APK bytecode ships ahead of time and Choreographer + JankStats track dropped frames, while LeakCanary watches destroyed Activity/Fragment instances for retained references. On the Web, users download HTML, CSS, JS, and fonts on the fly—and Google evaluates real-user experience at the 75th percentile (p75) across three Core Web Vitals: LCP (loading speed), INP (interactivity/responsiveness), and CLS (visual stability). Meanwhile, single-page apps (SPAs) stay alive in one tab for hours, so an uncleaned window listener or closure leaks entire detached DOM subtrees just like a static reference to a destroyed Activity.

06 · Chrome DevTools Playbook & Next Steps

Production Verification Checklist + Teacher Follow-Up

  • LCP Sub-Part Triage (Performance Panel): Record a cold load with 4x CPU + Slow 4G throttling. Expand the Timings track and click the LCP marker to split total time into TTFB, Resource Load Delay, Resource Load Duration, and Element Render Delay. Verify the hero <img> has fetchpriority="high" and zero loading="lazy".
  • INP & Long Tasks Audit: In DevTools Performance, interact with menus/filters and inspect Interactions + red-flagged Long Tasks (>50ms) and Long Animation Frames (LoAF). Break monolithic synchronous work with await scheduler.yield() or move heavy parsing/sorting to a Web Worker.
  • CLS & Font Stability Audit: Enable Rendering → Layout Shift Regions in DevTools to flash shifting elements in blue, and verify every media container sets explicit width/height or CSS aspect-ratio and webfonts use font-display: swap (with metric overrides) or optional.
  • Bundle & Route Splitting Check: Open DevTools Coverage (or Vite/Webpack bundle analyzer) after initial load; if >40% of downloaded JS bytes are unused on the landing route, split secondary routes and heavy modals behind dynamic import().
  • 3-Snapshot Heap Leak Hunting: Open DevTools → Memory → Heap snapshot. Take Snapshot 1 (baseline), perform an open/close or navigate-back-and-forth cycle 3× (and click the trash-can icon to force GC), then take Snapshot 2. Switch the dropdown to Objects allocated between Snapshot 1 and Snapshot 2 or filter by Detached, then inspect the bottom Retainers pane to find the exact Window listener, timer, or closure holding the node alive.
