01 · Mental Model Transfer & First Principles

From Kotlin Flow & StateFlow to RxJS Observables & Angular Signals

Before touching Angular APIs, lock down the three primitives from first principles: A Promise represents a single eager future value that cannot be cancelled once started. An RxJS Observable is a lazy push stream—just a function (observer) => teardown that emits 0..N values over time and returns a cleanup handle when you unsubscribe. An Angular Signal is a synchronous pull-based reactive cell that always holds a current value and tracks template/computed dependencies automatically without subscriptions.

Use RxJS for async events over time (debounce, cancellation, race control, retries, WebSockets) and Signals for synchronous component state. On Android, you already pair Kotlin Flow (stream operators) with StateFlow (UI state holder) via stateIn and collectAsStateWithLifecycle.

06 · Production Verification & Next Steps

Angular DevTools & Network Verification Checklist

  • Duplicate HTTP Request Audit: Open Chrome DevTools → Network (filter XHR/Fetch). Trigger a route navigation or view toggle. If identical GET calls fire simultaneously, check for multiple | async bindings on a cold Observable missing shareReplay({ bufferSize: 1, refCount: true }) or single toSignal() conversion.
  • Typeahead Cancellation Check: Throttle Network to Slow 3G and type "ang" → "angular" quickly. In the Network waterfall, the earlier ?q=ang request should show status (canceled)—confirming switchMap aborted the stale HttpClient XHR/fetch call.
  • Double-Submit Protection Check: On a slow throttled network, rapidly double-click any Save / Checkout button. Verify only 1 POST request leaves the browser because the click stream uses exhaustMap (and the UI button reflects status === 'submitting').
  • Subscription Leak & Error Survival Check: Navigate away from a component while an interval or WebSocket stream is active and confirm teardown runs (no console logs or network pings afterward). Also trigger a simulated 500 error in search, then type a valid query—confirm the stream stays alive because catchError sits inside switchMap.
