01 · Mental Model Bridge (Android Bridge)

From Dynamic Feature Modules & Firebase to Web System Design

Android Bridge: Dynamic Feature Modules & Firebase Remote Config/Crashlytics → RADIO System Design Framework, Micro-Frontend vs Monorepo Tradeoffs, RUM/OTel, Feature Flags & A/B Experiments.

In Android or Spring Boot systems, modular boundaries are enforced at compile time by Gradle modules and shipped as a single signed APK or container image. On the Web, every browser tab fetches live JavaScript over HTTP, multiple teams may deploy independently to the same URL origin, and a page tab can be backgrounded or killed instantly without running teardown callbacks. Below is how your existing intuition maps—and where the Web demands new primitives.

System Dimension Android / Spring Boot Equivalent Web Frontend Architecture First-Principles Trap to Avoid
Design Blueprint App Modularization + Clean Architecture RFC RADIO: Requirements, Architecture, Data Model, Interface, Optimizations Jumping straight into Redux vs Zustand before clarifying offline needs, SEO, or update frequency.
Team & Code Boundaries Gradle Multi-Module Repo vs Play Dynamic Feature Modules Monorepo (build-time splits) vs Micro-Frontends (Module Federation runtime splits) Using Micro-Frontends for 2–3 teams introduces version skew, duplicate React runtimes, and shared-state coupling.
Production Telemetry Firebase Crashlytics + Android Vitals (p90 cold start) RUM (p75 LCP/INP/CLS) flushed via sendBeacon on visibilitychange Tracking mean/average latency hides tail jank, and flushing on unload breaks bfcache and drops mobile beacons.
Distributed Tracing OkHttp Interceptor injecting W3C traceparent into Spring Boot OpenTelemetry Browser SDK propagating 00-<traceId>-<spanId>-01 on fetch() Forgetting CORS Access-Control-Allow-Headers: traceparent breaks cross-origin API requests in preflight.
Feature Flags & A/B UX Firebase Remote Config + A/B Testing + Crash-Free Users SLO Deterministic hash bucketing (userId:flagKey) + Guardrail Vitals + Error Budgets Using Math.random() flips variants on reload; shipping +3% conversion that regresses p75 INP burns user trust.
First-Principles Check: Why do frontend teams standardize on p75 (75th percentile) instead of averages for Core Web Vitals? A single 10-second outlier on a 2G train connection inflates an average, while medians (p50) hide slow tail devices. Measuring p75 guarantees at least 3 out of 4 real user page loads meet the UX threshold—matching Google's Core Web Vitals field evaluation standard.

06 · Production Verification Checklist & Sources

Shipping Safely: Telemetry, Flags & System Design Checklist

  • RADIO Check Before Coding: Write down functional vs non-functional requirements (SSR/SEO, offline, latency SLOs), sketch rendering + caching architecture, normalize client Data Model, define component/API Interfaces, and list targeted Optimizations.
  • Micro-Frontend Guardrail: In DevTools → Network (JS filter), verify shared frameworks (react, design system) are not downloaded twice across remotes and that shared state crosses cleanly via custom events or URL/cache contracts.
  • RUM & Beacon Audit: Switch tabs or minimize the browser window while watching DevTools → Network (Preserve log checked) to verify your telemetry payload flushes on visibilitychange (hidden) via sendBeacon without blocking navigation or breaking bfcache.
  • OTel Trace & CORS Check: Inspect outgoing API requests for the traceparent header (00-32hex-16hex-01) and confirm the backend responds with Access-Control-Allow-Headers: traceparent.
