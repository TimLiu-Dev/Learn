01 · Mental Model Transfer (First Principles + Android Bridge)

From Material 3 & Compose Modifiers to Web Design Systems

A Design System is the shared contract between Figma and React: it separates what a UI element means (semantic tokens and interactive states) from what pixels it paints. From first principles, every scalable web UI kit solves four orthogonal problems: (1) Tokens via CSS custom properties, (2) Styling & Variants via Tailwind + CVA, (3) Behavior & Accessibility via headless primitives, and (4) Visual Verification via state completeness and WCAG contrast math.

On Android, Material 3 bakes tokens into MaterialTheme.colorScheme and ships styled components (Button, ModalBottomSheet) out of the box. On the Web, CSS is global by default, every browser styles native controls differently, and overriding utility classes without a merge layer breaks silently. That is why modern React teams pair CSS Variables + Tailwind v4 + CVA + Radix / React Aria.

Design System Layer Android / Jetpack Compose Equivalent Web / React Mechanism Key Web Pitfall
Primitive vs Semantic Tokens Raw Color(0xFF2563EB) vs MaterialTheme.colorScheme.primary --palette-blue-600 mapped to --color-accent-primary in :root / [data-theme] Using raw palette tokens in components breaks dark mode and multi-brand theming.
Utility Styling & Overrides Chained Modifier.padding(...).background(...) Tailwind utilities + tailwind-merge (resolves conflicting utilities cleanly) Concatenating "px-4 " + "px-8" lets CSS stylesheet order win instead of the caller's override.
Component Variant Matrix Sealed enum parameters (ButtonDefaults, Size) CVA (variants, defaultVariants, compoundVariants) Ad-hoc boolean props (isPrimary, isDanger) create impossible states and class soup.
Headless Behavior & A11y Compose Foundation (clickable, FocusRequester, semantics) Radix UI / React Aria: ARIA roles, Escape/outside dismissal, focus traps Building modals or dropdowns with plain <div onClick> traps keyboard and screen reader users.
States & Contrast Audit InteractionSource states + Material contrast specs default, :hover, :focus-visible, disabled, aria-invalid + WCAG 2.2 luminance ratio Suppressing outline: none or using pale Figma grays (<4.5:1) fails accessibility audits.

06 · Real-World Verification & Next Steps

DevTools Design System Checklist + Teacher Follow-Up

  • CSS Variable Inheritance Audit: Open DevTools → Elements → Computed, filter by --color, and verify components read semantic tokens (e.g. --color-surface-card) rather than hardcoded hex or primitive palette tokens.
  • Keyboard & Focus-Visible Walkthrough: Unplug your mouse and press Tab / Shift+Tab through every interactive element. Confirm :focus-visible rings never get clipped by overflow: hidden, dialogs trap focus, and Escape restores focus to the trigger button.
  • WCAG 2.2 Contrast Inspection: Open the DevTools Color Picker on body text, muted helper text, placeholders, and error labels to verify ≥ 4.5:1 (normal text) and ≥ 3:1 (large text ≥ 18pt / 14pt bold, icons, and focus borders) across both Light and Dark themes.
  • Tailwind Override Verification: Inspect the resolved className on customized primitives in React DevTools; confirm caller overrides (px-8 over base px-4) pass through a merge helper rather than leaving duplicate conflicting utility classes.
Primary Source Recommendations: Study Adobe React Aria Documentation for headless accessibility state machines and WCAG 2.2 Understanding Contrast (Minimum) for exact luminance thresholds and exceptions.
