01 · Mental Model Bridge (Android Bridge)

Android contentDescription, TalkBack & Views → Semantic Landmarks, <dialog>, ARIA, <picture>/srcset & Keyboard A11y

In Android, View subclasses and Compose Modifier.semantics publish roles, labels, and actions directly to TalkBack's AccessibilityNodeInfo tree—and AlertDialog automatically runs in its own system window. On the Web, the browser builds an Accessibility Tree directly from your HTML DOM tags. Choosing a <div> instead of a <button>, <main>, or <dialog> silently strips role announcements, Enter/Space activation, focus management, and search-engine meaning.

Topic Area Android / Jetpack Compose Equivalent Web HTML5 & WCAG 2.2 Mechanism First Principles & Production Pitfall
Landmarks & Hierarchy TalkBack heading traversal (semantics { heading() }) & contentDescription <header>, <nav>, <main>, <article>, <aside>, <footer>, <h1>–<h6> Screen readers let users jump directly between landmarks and headings. Nested <div> soup flattens the page into tedious linear reading.
Modals & Popovers AlertDialog / ModalBottomSheet (isolated window + back-button dismiss) <dialog>.showModal() (Top Layer + ::backdrop) & popover="auto|manual" Custom <div class="modal"> overlays get clipped by parent overflow: hidden/z-index stacking contexts and fail to trap focus or restore it on close.
Data Tables Structured grid semantics with row/column index metadata <table>, <caption>, <thead>, <tbody>, <th scope="col|row"> Using CSS Grid/flexbox <div>s for tabular data prevents screen readers from announcing which column header applies to each data cell.
Forms & Validation TextInputLayout.error, hint, autofillHints <label for>, novalidate, Constraint Validation API, aria-invalid, aria-describedby Placeholders vanish as soon as typing begins and often fail 4.5:1 contrast. Unlinked error spans are invisible to screen readers when focus stays on the input.
Responsive Media & LCP res/drawable-xhdpi density buckets + Coil/Glide request priority <picture>, srcset, sizes, fetchpriority="high", explicit width/height Putting loading="lazy" on the above-the-fold hero image delays Largest Contentful Paint (LCP); omitting dimensions causes Cumulative Layout Shift (CLS).
Keyboard & WCAG 2.2 AA D-pad nextFocusRight, focusable(), 48dp minimum touch target Roving tabindex (0 / -1), :focus-visible, 4.5:1 contrast, 24×24px min target (WCAG 2.2) Using positive integers like tabindex="1" breaks natural DOM focus order; removing outline: none without :focus-visible strands keyboard users.

06 · DevTools / Production Checklist & Next Steps

Browser Accessibility & SEO Verification Checklist

  • Accessibility Tree Audit: In Chrome DevTools → Elements → Accessibility pane (or full-page Accessibility Tree toggle), verify every button/link/input has a Computed Role and non-empty Accessible Name, and that landmarks (banner, navigation, main, contentinfo) appear cleanly.
  • Keyboard-Only Tab Walkthrough: Put away your mouse and navigate your entire flow using Tab, Shift+Tab, Enter, Space, Escape, and Arrow keys. Confirm :focus-visible rings are clearly visible and never obscured by sticky headers (WCAG 2.2 Focus Not Obscured).
  • Contrast, Target Size & LCP Media Check: Use DevTools CSS Overview / Lighthouse to verify ≥ 4.5:1 normal text contrast (≥ 3:1 large text & UI borders), ≥ 24×24 CSS px interactive target sizes (WCAG 2.2), explicit width/height on images, and fetchpriority="high" (never loading="lazy") on the LCP hero image.
  • SEO & Social Graph Validation: Confirm a single descriptive <h1>, unique <title> + <meta name="description">, <link rel="canonical">, and complete og:title / og:description / og:image tags.
Primary Sources: Read MDN: Accessibility and the W3C ARIA Authoring Practices Guide (APG) for canonical keyboard interaction patterns across tabs, menus, comboboxes, and dialogs.
