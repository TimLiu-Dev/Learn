01 · Mental Model Transfer & First Principles

From JUnit + MockK + Compose UI Test to the Frontend Testing Trophy

Before writing a single assertion, establish the core law of modern frontend testing: a test only earns its maintenance cost if it fails when the user's experience breaks and passes when you refactor internals. Pure unit tests verify isolated functions (currency math, reducers, validators), while integration tests render real UI components together with state, routing, and a simulated HTTP boundary—running in milliseconds inside Node via jsdom or happy-dom without launching a full browser.

Coming from Android or Spring Boot, you already separate fast JVM tests (JUnit + MockK) from Compose/Espresso UI tests and OkHttp MockWebServer. Modern web testing shifts the center of gravity from heavy end-to-end tests and over-mocked unit tests into DOM-based integration tests powered by Vitest, Testing Library, and MSW.

Testing Dimension Android / Spring Boot Equivalent Modern Web Stack (Vitest + RTL + MSW) Core Principle & Key Difference
Test Strategy Shape Testing Pyramid (many JUnit ViewModel tests, fewer Espresso tests) Testing Trophy (Static Types → Unit → Integration → E2E) Integration tests give the highest confidence per dollar/second by testing component trees together.
Test Runner & Clocks JUnit 5 + runTest / StandardTestDispatcher Vitest + vi.useFakeTimers() / advanceTimersByTimeAsync() Vitest reuses Vite's native ESM transform graph; fake timers eliminate flaky sleep() waits.
UI Node Queries Compose onNodeWithRole / onNodeWithText / testTag getByRole > getByLabelText > getByText >> getByTestId Querying by ARIA role + accessible name proves both functionality and screen-reader accessibility.
User Interactions Compose performClick() / performTextInput() userEvent.setup() (user.click, user.type) userEvent dispatches the full browser event sequence (pointer, focus, keydown, input), unlike raw fireEvent.
Network Boundary Mock OkHttp MockWebServer / Retrofit fake MSW (http.get, setupServer, server.use) Intercepts real fetch/XHR calls at the network layer instead of mocking hooks or axios modules.
Over-Mocking Trap Mocking repository + mapper + useCase until test only tests MockK Mocking internal hooks, testing private state, or giant DOM snapshots If your test breaks when renaming an internal helper—or passes when fetch URLs break—the mock boundary is wrong.

06 · Real-World Verification & Next Steps

Vitest + Testing Library + MSW Production Checklist

  • Audit Your Query Calls: Search your test suite for getByTestId, container.querySelector, and fireEvent. Replace them with getByRole(..., { name }), getByLabelText, and userEvent.setup() wherever possible.
  • Check Your Network Boundary: Verify that API calls are intercepted via MSW (setupServer + onUnhandledRequest: "error") with afterEach(() => server.resetHandlers()) so tests never leak per-test error overrides or hit real endpoints.
  • Eliminate Flaky Async & Timers: Confirm tests use await findBy* for async DOM appearance, keep waitFor free of side effects, and pair vi.useFakeTimers() with vi.useRealTimers() in afterEach.
  • Ban Giant Component Snapshots: Replace multi-hundred-line toMatchSnapshot() assertions on JSX trees with targeted behavioral assertions on roles, text, and state transitions.
