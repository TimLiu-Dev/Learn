01 · Mental Model Transfer (Android Bridge + First Principles)

OkHttp WebSocket / gRPC → Web Protocols, Streams & Resilient Feeds

If you come from Android and Spring Boot, you already think in terms of Retrofit REST endpoints, OkHttp WebSocket listeners, Spring WebFlux Flux<ServerSentEvent>, and keyset pagination. On the Web, browsers expose lower-level primitives—fetch() with ReadableStream, EventSource, and WebSocket—where you own framing, cancellation (AbortController), reconnect jitter, and cache consistency.

Before jumping into streaming, lock down the three transport fundamentals from first principles: (1) Request/Response (REST & GraphQL) asks once and gets one complete payload; (2) Unidirectional Push (SSE) keeps a standard HTTP response open so the server pushes UTF-8 text events over time; and (3) Full-Duplex (WebSockets) upgrades HTTP to a persistent TCP frame pipe where client and server send messages independently at any instant.

Protocol / Pattern Android / Spring Boot Equivalent Web / Browser Mechanism First-Principles Tradeoff & Pitfall
REST & Cursor Pagination Retrofit + Spring Data keyset/seek pagination fetch() + opaque ?after=cur_9a&limit=20 Offset pagination (?page=2) drifts on live feeds—new inserts cause duplicate rows; deletes skip rows.
GraphQL & Caches Apollo Kotlin queries, fragments & normalized store Single /graphql POST + document cache (TanStack Query) vs normalized graph (Apollo/Relay) Document caches key by (query, vars); normalized caches update all views sharing __typename:id automatically.
SSE (EventSource) OkHttp EventSources + Spring SseEmitter new EventSource(url) over HTTP/1.1 or HTTP/2 (text/event-stream) Auto-reconnects with Last-Event-ID, but GET-only and cannot send custom Authorization headers or JSON bodies.
AI Token Streams (POST SSE) OkHttp streaming ResponseBody.source() / gRPC server-stream fetch(url, { method: "POST", signal }) + body.getReader() + TextDecoder TCP chunks split mid-line or mid-UTF-8 character; must buffer lines until \n\n and stop cleanly on [DONE] or abort.
WebSockets & Heartbeats OkHttp WebSocketListener + pingInterval / gRPC bidi new WebSocket("wss://...") (HTTP 101 upgrade) Zero built-in retry, no Last-Event-ID, and silent half-open drops behind NATs unless you send app-level ping/pong heartbeats.

06 · Real-World Verification & Next Steps

Production Debugging & Chrome DevTools Checklist

  • Inspect SSE & AI Streams: Open DevTools → Network, select the streaming request, and inspect the EventStream tab to verify id, event, and data frames. For fetch POST streams, check Content-Type: text/event-stream and verify chunks flush immediately (no proxy buffering).
  • Audit WebSocket Heartbeats: Filter by WS in DevTools → Network, open the Messages tab, and confirm periodic ping/pong frames fire on schedule and that disconnecting triggers jittered backoff instead of rapid 0ms loops.
  • Verify Cursor Consistency & Abort Safety: While scrolling an infinite feed, insert a new item on the server and fetch page 2—confirm zero duplicated or skipped IDs. On AI chat views, click "Stop" or navigate away and confirm the request shows (canceled) via AbortController.
  • End-to-End Contract & Generative UI Audit: Verify OpenAPI / Zod schemas match actual wire payloads (zero unvalidated as casts) and confirm streaming AI markdown/tool-call UIs sanitize links/HTML and handle partial incomplete JSON chunks without crashing.
