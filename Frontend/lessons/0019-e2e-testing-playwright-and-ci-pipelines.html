01 · Mental Model Transfer & First Principles

From Espresso / UIAutomator to Playwright Architecture

In Lesson 18, Vitest + React Testing Library ran inside a simulated DOM (jsdom) in the same Node process as your test code. Real End-to-End (E2E) testing launches an actual browser engine (Chromium, WebKit, or Firefox) and drives your live app over an out-of-process WebSocket/DevTools protocol—validating real layout geometry, pointer hit-testing, cookies, service workers, and cross-origin redirects.

If you come from Android instrumentation tests, you already know the pain of Thread.sleep(2000) flaking on slow CI emulators and why Espresso introduced IdlingResource. Playwright solves this problem at the protocol level: every locator action runs a built-in actionability state machine before dispatching synthetic input, and every web-first assertion automatically re-polls until timeout.

E2E Concern Android / Spring Boot Equivalent Playwright Mechanism First-Principles Why & Pitfall
Synchronization & Flakiness Espresso IdlingResource / Compose waitUntil (vs Thread.sleep) Actionability checks + web-first assertions (await expect(loc).toHaveText(...)) page.waitForTimeout(500) fails under CI CPU spikes and wastes time when fast. Auto-retry adapts dynamically.
Element Selection onView(withContentDescription(...)) / Semantics Tree User-facing locators: getByRole(), getByLabel(), getByTestId() Querying fragile CSS paths (div > ul > li:nth-child(2)) breaks on styling refactors; ARIA role locators test accessibility too.
Test State Isolation Android Test Orchestrator (clearing app data per test) BrowserContext per test + reusable storageState JSON Spinning up a fresh browser binary takes ~500ms; creating an isolated BrowserContext takes ~10ms with clean cookies/storage.
Network Determinism OkHttp MockWebServer / WireMock in Spring Boot page.route() interception + routeFromHAR() replay Third-party endpoints (Stripe, OAuth, analytics) cause flaky CI timeouts; intercept or abort non-owned origins cleanly.
Failure Forensics Emulator screen recording + Logcat + Espresso View Hierarchy dump Trace Viewer (trace: 'on-first-retry') + video: 'retain-on-failure' Screenshots only show the final broken frame; Traces record before/after DOM snapshots, network waterfall, and console logs per step.
CI Parallelism & Audits Firebase Test Lab sharding + Accessibility Scanner --shard=i/N + blob report merge + @axe-core/playwright + toHaveScreenshot() Running 300 serial E2E specs takes 40+ minutes; sharding + duration-balanced specs keep PR checks under 5 minutes.

06 · Production Verification & CI Checklist

Playwright CI Gate & Debugging Checklist

  • Zero Hard Sleeps: Search your test suite for waitForTimeout and replace every occurrence with web-first assertions (await expect(locator).toBeVisible()) or explicit API response waits (page.waitForResponse()).
  • Auth via Setup Project: Authenticate once in auth.setup.ts, persist playwright/.auth/user.json via storageState, and exclude auth credentials from git via .gitignore.
  • Trace-on-First-Retry: Configure retries: process.env.CI ? 2 : 0 and use: { trace: "on-first-retry", video: "retain-on-failure" } so passing runs stay fast while every flake captures a full Trace ZIP artifact.
  • Deterministic Visual & A11y Gates: In visual tests, pass animations: "disabled" and mask: [page.getByTestId("timestamp")] to toHaveScreenshot(), and run new AxeBuilder({ page }).analyze() on key routes to block critical WCAG regressions.
