01 · Mental Model Transfer (Android Bridge)

From AppAuth + EncryptedSharedPrefs to RHF, Zod, Actions & BFF Auth

On Android, an EditText owns its own text buffer natively, OS sandboxing protects EncryptedSharedPreferences, and OkHttp's Authenticator serializes 401 token refreshes on a background thread. On the Web, every keystroke in a controlled React input can re-render an entire form tree, and any XSS script shares the same JavaScript memory and localStorage. Let's build both systems from first principles.

Concern Android / Spring Boot Equivalent Web / React / Next.js Pattern Critical Pitfall
Form Input State EditText (uncontrolled native buffer) vs Compose TextField(value, onValueChange) React Hook Form (RHF) registers DOM refs (uncontrolled) instead of root useState on every keystroke Controlling 80+ inputs at the form root re-renders the whole tree on every character typed, spiking INP.
Validation & Contracts Kotlin kotlinx.serialization + Spring Boot @Valid / custom cross-field validators Zod schemas (z.object().superRefine(...)) shared between client zodResolver and server action/API Running Zod only on the client lets anyone curl your endpoint with malformed or forged payloads.
Submit Lifecycle & Actions ViewModel MutableStateFlow<SubmitState> + Retrofit suspend call React 19 useActionState: [state, formAction, isPending] wired to <form action={formAction}> Ignoring pending state causes double-submit race conditions; missing progressive enhancement breaks pre-hydration submits.
Multi-Step Wizards Navigation nested graph + shared SavedStateHandle / ViewModel + TalkBack focus Persistent FormProvider or step-merged state + aria-current="step", aria-invalid, focus on first error Unmounting Step 1 without preserving values wipes user data; failing to move focus strands keyboard & screen-reader users.
Token Storage EncryptedSharedPreferences backed by hardware Android Keystore (isolated app sandbox) BFF (Backend-for-Frontend) keeps tokens server-side or inside HttpOnly; Secure; SameSite=Lax cookies localStorage.getItem("jwt") is readable by any injected XSS script on your origin—stealing sessions silently.
OAuth2 Authorization AppAuth-Android + Chrome Custom Tabs using Authorization Code + PKCE (S256) Browser generates CSPRNG code_verifier & SHA-256 code_challenge; BFF exchanges code safely Using deprecated Implicit Flow exposes tokens in URL fragments (#access_token=) and browser history.
Silent Refresh Rotation OkHttp Authenticator with synchronized block so 1 refresh runs at a time Single-flight promise coalescing: 1 in-flight refresh Promise shared across all concurrent 401 waiters 5 parallel 401s firing 5 refreshes replay an already-rotated refresh token—triggering server-side family revocation!
First-Principles Rule of Thumb: Keep typing state close to the DOM (ref) until validation or submission needs React state; keep secrets out of JavaScript entirely (HttpOnly cookies via BFF) because browser JS runs in a shared-origin security boundary.

06 · Real-World Verification & Next Steps

DevTools Verification Checklist + Teacher Follow-Up

  • React DevTools Profiler (Typing INP): Record typing rapidly in your largest form. With RHF uncontrolled register(), sibling inputs should not flash green on every keystroke—only the active error message or subscribed field updates.
  • Accessibility & Keyboard Audit: Tab through every wizard step with the mouse unplugged. Verify failed submits set aria-invalid="true", bind aria-describedby to the rendered error element ID, and move focus to the first invalid control.
  • Application → Cookies & Storage Audit: Confirm zero access or refresh JWTs exist in localStorage or sessionStorage. Inspect your BFF session cookie in DevTools → Application → Cookies and verify HttpOnly, Secure, and SameSite=Lax (or Strict) are all checked.
  • Network Tab (PKCE + 401 Refresh Storm Test): Throttle network, trigger 5 parallel API calls after token expiry, and verify only one POST /auth/refresh request fires while all 5 callers replay cleanly with the rotated session.
