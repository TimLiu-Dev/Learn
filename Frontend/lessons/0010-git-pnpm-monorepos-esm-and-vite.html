01 · Mental Model Transfer & First Principles

Gradle Multi-Module, Version Catalogs & R8 → pnpm Workspaces, ESM & Vite

On Android and Spring Boot, Gradle coordinates module graphs, Version Catalogs pin library versions, and R8 compiles away dead classes before shipping an APK or JAR. On the Web, source code ships to browsers over HTTP and Node.js carries two incompatible module eras (CommonJS and ESM). Every layer of modern frontend tooling exists to solve dependency isolation, module resolution, instant local feedback, and minimal production bundle bytes.

First Principles Check — Git Workflows & Code Quality Gates:
1. Rebase vs. Merge: git merge preserves exact chronological branching with a two-parent merge commit; git rebase replays your branch commits onto a new base SHA, creating a clean linear history. Use rebase on private feature branches before opening a PR (or squash-merge PRs), and reserve merge for shared integration branches.
2. git bisect: Performs binary search across commit history (git bisect start, bad, good <sha>, or git bisect run pnpm test) to pinpoint a regression among 1,000 commits in ~10 steps (O(log N)). Linear history avoids broken intermediate commits.
3. Conventional Commits: Structured commit headers (feat(cart): ... → minor bump, fix(auth): ... → patch bump, feat!: ... or BREAKING CHANGE: → major bump) drive automated SemVer releases and changelogs via Changesets or semantic-release.
4. ESLint vs. Prettier: Prettier owns whitespace, quotes, semicolons, and line wrapping by reprinting the AST; ESLint owns logic bugs, hook dependencies, and import boundaries (with eslint-config-prettier disabling conflicting formatting rules).
