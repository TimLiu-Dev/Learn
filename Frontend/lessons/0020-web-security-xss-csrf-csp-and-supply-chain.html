01 · Mental Model Transfer

Android WebView/Intent Security → Browser Origin & Defense-in-Depth

In Android, the OS isolates each app by Linux UID and enforces explicit permissions on exported Activity, BroadcastReceiver, and WebView JavaScript bridges. On the Web, the browser's security boundary is the Origin (scheme + hostname + port)—known as the Same-Origin Policy (SOP). Two critical attack families emerge when that boundary is misunderstood: XSS executes attacker JavaScript inside your origin (complete compromise), while CSRF tricks a victim's browser into sending ambient cookies from a foreign origin to your server.

Security Boundary Android / Spring Boot Equivalent Web Browser Mechanism Critical Pitfall
Origin Isolation (SOP) Linux UID app sandbox + exported="false" Same-Origin Policy: scheme + host + port gates DOM & fetch() reads SOP blocks cross-origin reads, not cross-origin form/fetch writes (CSRF).
Code Injection (XSS) WebView.loadData() + @JavascriptInterface exposure innerHTML, dangerouslySetInnerHTML, javascript: hrefs HTML escaping text isn't enough for href URLs or JS contexts.
Ambient Auth (CSRF) Exported Intent without caller permission check; Spring CsrfFilter Cookies attach automatically to cross-site requests unless SameSite blocks them SameSite=Lax still sends cookies on top-level GET navigations.
Runtime Guardrails SELinux + Android App Signing / Network Security Config Nonce-based Strict CSP + Trusted Types DOM sink enforcement 'unsafe-inline' or domain allowlists on CDNs re-open XSS bypasses.

06 · Real-World Verification & Next Steps

Production Security Audit Checklist + Teacher Follow-Up

  • Response Headers Audit (Network Tab): Inspect the main document response in DevTools → Network and verify Content-Security-Policy uses a fresh per-request 'nonce-...' (never 'unsafe-inline'), plus object-src 'none' and frame-ancestors 'none'.
  • Cookie Flags Check (Application → Cookies): Confirm session cookies carry HttpOnly (blocks document.cookie theft via XSS), Secure (HTTPS-only), and SameSite=Lax or SameSite=Strict.
  • DOM Sink & SRI Inspection: Search your codebase for innerHTML, dangerouslySetInnerHTML, and window.addEventListener("message"); verify every third-party <script> carries an integrity="sha384-..." attribute and crossorigin="anonymous".
