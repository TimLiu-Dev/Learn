01 · Mental Model Bridge (Spring Boot Bridge)

From @RestController & Spring IoC to Node.js HTTP Engines

In Spring Boot, a single opinionated container wires together Tomcat/Netty, Jackson JSON serialization, Bean Validation (@Valid), @RestControllerAdvice, and Spring's IoC ApplicationContext. In Node.js, the standard library gives you low-level primitives (node:http), and you choose your abstraction tier: ultra-fast, plugin-encapsulated engines (Fastify, Hono) where you wire dependencies explicitly, or NestJS, which recreates Spring/Angular's decorator-driven Modules, DI container, Guards, Pipes, and Filters on top of Express or Fastify.

Backend Responsibility Spring Boot Equivalent Fastify / Hono (2027 TS Standard) NestJS Equivalent
Routing & Handlers @RestController + @GetMapping fastify.get('/orders/:id', handler) / app.get('/orders/:id', c => ...) @Controller('orders') + @Get(':id')
IoC & Dependency Injection ApplicationContext + @Service constructor injection Explicit Composition Root (makeService({ repo })) or lightweight TS container @Injectable() + @Module({ providers }) container
Validation & Serialization @Valid + Hibernate Validator + Jackson Fastify JSON Schema (Ajv + fast-json-stringify); Hono + Zod ValidationPipe (class-validator) + DTOs / Zod
Cross-Cutting Pipeline Filter → HandlerInterceptor → Controller Express flat (req, res, next); Fastify lifecycle hooks; Hono await next() Middleware → Guard → Interceptor → Pipe → Handler

REST Fundamentals from First Principles

REST (Representational State Transfer) treats your API as a graph of resources (nouns) manipulated via uniform HTTP verbs—never RPC verb URLs like POST /createOrder or GET /deleteUser?id=5. Every method carries strict guarantees about Safety (does not mutate server state) and Idempotency (calling it 1 time or 10 identical times leaves server state identical).

HTTP Method Resource Example Safe? Idempotent? Canonical Status Codes & Semantics
GET /v1/orders?status=paid&cursor=abc&limit=20 Yes Yes 200 OK (list/item), 404 Not Found, 304 Not Modified
POST /v1/orders (or /v1/orders/:id/cancel) No No (unless Idempotency-Key) 201 Created + Location header, 400, 409, 422
PUT /v1/users/:id/preferences No Yes (full replacement) 200 OK or 204 No Content (or 201 on upsert)
PATCH /v1/orders/:id No Not inherently (depends on patch) 200 OK (partial update), 409 Conflict (stale ETag/version), 422
DELETE /v1/sessions/:id No Yes (final state: absent) 204 No Content (empty body), or 404 Not Found
Status Code Precision (Interview Trap): 400 Bad Request = malformed syntax (broken JSON, wrong type); 401 Unauthorized = missing or invalid authentication credentials (unauthenticated); 403 Forbidden = authenticated identity lacks permission (unauthorized); 409 Conflict = state/uniqueness/optimistic-lock conflict (duplicate email, cannot ship cancelled order); 422 Unprocessable Content = valid JSON syntax, but domain/semantic validation failed (negative quantity); 429 Too Many Requests = rate limited (include Retry-After); 500 Internal Server Error = unhandled bug (never expose stack traces or SQL errors!).

06 · Real-World Verification & Next Steps

Production API & DI Verification Checklist

  • RFC 9457 Error Contract: Verify every 4xx/5xx error returns Content-Type: application/problem+json with type, title, status, detail, and instance—and verify 500 responses mask internal stack traces and DB details.
  • Idempotency & Retries: Require an Idempotency-Key header on non-idempotent money/order creation endpoints, fingerprint the payload to reject key reuse with mutated bodies (422), and avoid caching 5xx transient errors.
  • Cursor Pagination at Scale: Replace OFFSET pagination on growing feeds/tables with opaque keyset cursors (?cursor=...&limit=20) backed by a composite index to avoid duplicate rows and O(N) scans.
  • Zero-Socket Fast Tests: Use fastify.inject(), Hono's app.request(), or NestJS Test.createTestingModule() with constructor-injected fakes so unit/API suites run in milliseconds without opening TCP ports.
Primary Source Recommendation: Read the Fastify Docs (Encapsulation, Hooks, Validation & Serialization), NestJS Docs: Providers & DI, and RFC 9457: Problem Details for HTTP APIs.
