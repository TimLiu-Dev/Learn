01 · Mental Model Transfer & First Principles

From Kotlin Coroutines & Main Looper to the JS Event Loop

First Principles: A JavaScript engine (V8, JavaScriptCore, SpiderMonkey) owns a single Call Stack (LIFO execution frames) and a memory Heap. The engine itself does not have timers, sockets, or DOM painting—those live in the Host Environment (Web APIs in the browser, libuv in Node). When an async Web API completes (like fetch() or setTimeout()), it cannot interrupt running JS. Instead, it enqueues a callback into either the Microtask Queue (high-priority continuations drained completely after every JS turn) or a Task (Macrotask) Queue (processed one task per loop tick, with rendering/requestAnimationFrame interleaved on frame boundaries).

1 · Call Stack Synchronous JS runs to completion (run-to-completion). Nothing preempts an active frame.
2 · Microtask Checkpoint Drains all Promise.then, await resumes, and queueMicrotask—including newly queued ones!
3 · Frame & rAF Phase At vsync (~16.6ms @ 60Hz), runs requestAnimationFrame, Style, Layout, Paint, and GPU Composite.
4 · One Macrotask Pops one task from setTimeout, MessageChannel, or input queue—then repeats step 2.

06 · Real-World Verification & Next Steps

Chrome DevTools Async Audit Checklist + Teacher Follow-Up

  • Long Tasks & INP Audit: Open DevTools → Performance, record a slow interaction, and inspect red-flagged Long Tasks (>50ms). Break monolithic loops with scheduler.yield() / setTimeout(0) or move heavy CPU work to a Web Worker.
  • Microtask Checkpoint Inspection: Expand a Task in the Performance flame chart and look for Run Microtasks slices at the end of event handlers—unexpectedly wide bars indicate chained Promise storms delaying paint.
  • Async Stack Traces & Leaks: Keep Async stack traces enabled in Sources, listen for global unhandledrejection events in telemetry, and pass AbortController.signal into every fetch, timer, and for await...of stream.
