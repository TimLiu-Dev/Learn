01 · Mental Model Bridge (Android Bridge)

Jetpack Navigation + Deep Links → Angular Standalone Router, SSR & Event Replay

In Android, your APK already holds compiled bytecode for every screen on the user's phone—navigating from a list to a detail screen never waits on a JS bundle over cellular data. On the Web, a URL must solve three problems at once: (1) where the first HTML bytes are rendered (browser CSR vs per-request SSR vs build-time SSG), (2) which JS chunks are downloaded lazily via loadComponent/loadChildren, and (3) how the client attaches interactivity to server-painted DOM without flickering, dropping early taps, or duplicating API requests.

From first principles, think of SSR + Hydration as a two-act handoff. In Act 1 (Server), Angular executes your route tree on Node/Edge, awaits data fetches, serializes both the HTML markup and the fetched JSON responses (TransferState inside <script id="ng-state">), and streams ready-to-paint HTML to the browser. In Act 2 (Client), the browser paints immediately; a tiny inline script buffers user clicks via withEventReplay(); Angular boots and performs Non-Destructive Hydration (reusing the existing DOM nodes instead of wiping and recreating them); and @defer (hydrate on ...) blocks stay dormant until interacted with.

Standalone Router + Signal Input Binding

Configure lazy routes, functional guards using inject(), and automatic binding to Signal input().

// app.config.ts
provideRouter(routes, withComponentInputBinding())

// app.routes.ts
export const routes: Routes = [
  {
    path: 'orders/:orderId',
    canActivate: [authGuard],
    resolve: { order: orderResolver },
    loadComponent: () => import('./order-detail.component')
      .then(m => m.OrderDetailComponent)
  }
];

// order-detail.component.ts
orderId = input.required<string>(); // from :orderId
tab = input<string>();              // from ?tab=...
order = input.required<Order>();    // from resolve

Route-Level Rendering + Incremental Hydration

Pick CSR/SSG/SSR per route in app.routes.server.ts and enable replay + incremental hydration in app.config.ts.

// app.config.ts
provideClientHydration(
  withEventReplay(),
  withIncrementalHydration()
)

// app.routes.server.ts
export const serverRoutes: ServerRoute[] = [
  { path: '', renderMode: RenderMode.Prerender },
  { path: 'products/:id', renderMode: RenderMode.Server },
  { path: 'admin/**', renderMode: RenderMode.Client }
];

// template: keep heavy reviews dehydrated until clicked
@defer (hydrate on interaction) {
  <app-product-reviews [productId]="id()" />
}

06 · Real-World Verification & Next Steps

Angular & Chrome DevTools Verification Checklist + Teacher Follow-Up

  • View Source / Document Response: In Chrome DevTools → Network (filter by Doc), inspect the initial HTML response for SSR/Prerendered routes. Verify real component HTML is present (not an empty <app-root></app-root>) along with <script id="ng-state" type="application/json"> holding serialized TransferState.
  • Zero-Duplicate Fetch Audit: On initial load in the Network → Fetch/XHR tab, verify that GET endpoints executed on the server are not re-fetched by the browser during hydration.
  • Hydration Mismatch & Angular DevTools Check: Watch the Console for NG0500 hydration mismatch errors (commonly caused by direct DOM mutation or unguarded window/localStorage reads during SSR). Use the Angular DevTools extension to verify hydrated vs dehydrated @defer boundaries.
  • Lazy Chunk & Incremental Hydration Check: Clear the Network tab, then click an unhydrated @defer (hydrate on interaction) region or navigate to a loadComponent route—confirm the JS chunk downloads on demand rather than blocking initial boot.
