01 · Mental Model Transfer

What You Already Know from Android (and Where Web Differs)

On Android, your APK code is already compiled on the user's device; only data comes over OkHttp. On the Web, your entire application UI (HTML, CSS, JS, fonts) is downloaded over the network on first visit and parsed dynamically on a single main thread.

Pipeline Stage Android Equivalent Web Browser Mechanism Key Web Pitfall
Network & TLS OkHttp connection pool + TLS handshake DNS + TCP + TLS 1.3 + HTTP/2-3 + Cache-Control Unoptimized entry HTML or third-party origins add 300–600ms before rendering even starts.
Tree Construction XML inflation / Compose initial Composition Incremental HTML → DOM + CSS → CSSOM A plain <script> pauses HTML parsing; external CSS blocks painting until CSSOM completes.
Geometry & Pixels onMeasure() → onLayout() → onDraw() Render Tree → Layout (Reflow) → Paint → Composite Reading offsetWidth after changing styles triggers Forced Synchronous Layout.
Frame Budget Main Looper + Choreographer (16.6ms @ 60Hz) Event Loop + requestAnimationFrame (16.6ms; >50ms = Long Task) Animating top/left runs Layout on CPU every frame instead of GPU transform.

06 · Real-World Verification & Next Steps

Chrome DevTools Verification Checklist + Teacher Follow-Up

  • Network Waterfall: Open DevTools → Network, reload with Disable Cache checked, and verify your entry HTML is small, critical CSS loads early, and third-party origins use preconnect when needed.
  • Cache Headers Check: Inspect Response Headers on index.html (should be no-cache / short TTL) vs hashed JS/CSS bundles (should be max-age=31536000, immutable).
  • Layout Shift & Reflow Audit: Open DevTools → Performance, record a 3-second interaction, and look for purple Layout bars with red triangles ("Forced reflow is a likely bottleneck").
