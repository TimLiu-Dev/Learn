React State & 5-State UI: TanStack Query, Zustand, URL State & useOptimistic

Stop stuffing API responses, sidebar toggles, and filter parameters into one giant store. In this lesson, you will separate Server Cache (TanStack Query), Client UI Store (Zustand), URL Search Params, and React 19 useOptimistic—and ship all 5 UX states cleanly.

01 · Mental Model Transfer (Android Bridge)

From ViewModel + StateFlow to 4 Distinct State Owners

On Android, a ViewModel + StateFlow<UiState> often wraps a Repository (Room + Retrofit) and exposes a single screen state object. On the Web, mixing remote server data with local client state inside useState or a global Redux/Zustand store causes duplicate network calls, stale tabs, and forgotten error/loading flags.

First principle of modern React state: classify state by who owns the source of truth. Server data is a shared, asynchronous snapshot you do not own (cache it with TanStack Query). Browser-only preferences (drawer open, multi-select IDs, theme draft) belong in a Zustand client store. Shareable navigation state (filters, sort, page, tab) belongs in URL searchParams. Instant mutation feedback belongs in React 19 useOptimistic.

State Category Android Equivalent React / Web Mechanism Key Web Pitfall
Server Cache Repository + Room single-source-of-truth + Flow TanStack Query (queryKey, staleTime, gcTime, invalidation) Treating API JSON as useState or Zustand data—losing deduplication, background refresh, and cache expiry.
Client UI Store ViewModel local MutableStateFlow (modal, selection) Zustand (create() + fine-grained slice selectors) Subscribing to the whole store (useStore()) instead of a slice selector, causing unrelated component re-renders.
Shareable Navigation State SavedStateHandle + Navigation SafeArgs / Deep Links URL URLSearchParams (?status=open&page=2) Storing search/filter state only in React memory so refreshing the tab or sharing a link loses the user's view.
Optimistic Mutation Immediate UI update in Repository + rollback on Retrofit failure React 19 useOptimistic (or onMutate rollback) Mutating local state permanently without reverting when the server rejects (409/500), leaving ghost items on screen.
5-State UI Completeness Sealed UiState (Loading, Empty, Error, Content, Offline) Explicit 5-State Matrix (Skeleton, Empty, Inline Error, Optimistic/Undo, Offline) Showing a full-screen error spinner that wipes already-cached items when a background refetch fails or user goes offline.

06 · Real-World Verification & Next Steps

Production Verification Checklist + Teacher Follow-Up

  • TanStack Query DevTools Audit: Verify every query transitions through fresh → stale → inactive, confirm identical queryKeys never fire duplicate parallel requests, and check that staleTime matches how fast the resource actually changes.
  • Zustand Selector Render Check: Open React DevTools → Profiler ("Highlight updates when components render"), update an unrelated slice (like sidebar width), and confirm list rows do not flash because selectors use primitives or useShallow.
  • URL State & Reload Test: Apply filters, sort order, and page 3, copy the URL into a new tab, and press Browser Back—confirm the exact view restores without client-only memory loss.
  • 5-State Fault Injection: In Chrome DevTools → Network, test (1) Slow 3G (skeletons match final layout to prevent CLS), (2) Offline with cached data (stale data stays visible with offline banner), and (3) a forced 500 mutation (optimistic item rolls back with inline retry).
