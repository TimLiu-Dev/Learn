React Component & UX Architecture: Composition, Suspense, Boundaries & Motion

01 · Mental Model Transfer & First Principles

Compose Slot APIs & BackHandler → React Composition, Boundaries & UX

In Jetpack Compose, you instinctively pass content: @Composable () -> Unit slots instead of threading twenty configuration flags down five layers, use CompositionLocal sparingly for implicit tree-wide values, and hoist state out of stateless inputs. React shares that exact architecture—yet introduces Web-specific constraints around CSS stacking contexts, thrown-promise Suspense, Error Boundaries, and keyboard/motion accessibility.

From first principles: Composition keeps parent wrappers decoupled from child internals because children are already-created React elements owned by an ancestor. Compound Components pair composition with a scoped React Context so sub-parts (like Tabs.List, Tabs.Trigger, and Tabs.Panel) share state and ARIA wiring without prop drilling. Portals decouple DOM placement (escaping overflow: hidden or transform stacking traps) while preserving React Context and synthetic event bubbling. Finally, Hick's Law and prefers-reduced-motion keep rich interfaces fast for human brains as well as GPUs.

06 · Real-World Verification & Next Steps

Production & DevTools Verification Checklist

  • React DevTools Profiler ("Highlight updates"): Toggle a parent wrapper's state (like scroll or hover) and verify pre-composed children slots do not flash unnecessarily.
  • Stacking Context & Portal Audit: Inspect overlays in Elements → Computed / Layers; confirm dialogs/tooltips portal to a root container outside any transform, filter, or overflow: hidden card.
  • Keyboard & Reduced Motion Check: Navigate tabs and Cmd+K palettes with keyboard only (Arrow, Home, End, Enter, Escape), then toggle Emulate CSS media feature prefers-reduced-motion: reduce in DevTools Rendering panel.
  • Boundary Resilience Check: Verify every async Suspense subtree has an outer Error Boundary with a working resetKeys / retry path so a single failed widget never whites out the whole page.
