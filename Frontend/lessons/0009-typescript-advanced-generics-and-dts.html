01 · Mental Model Bridge & First Principles

From Kotlin Generics & Variance to TypeScript's Structural Type Algebra

In Kotlin/Java, generics live inside a nominal type system: two classes with identical properties are unrelated unless one inherits the other, and JVM generics undergo type erasure unless preserved with inline fun <reified T>. In TypeScript, every type exists strictly at compile time and describes sets of structural shapes. Think of TypeScript types as compile-time sets and functions over sets: a generic type like Pick<User, "id" | "name"> is literally a pure type-level function that transforms one object shape into another, and then vanishes completely when emitted to JavaScript.

Android Bridge: Kotlin Reified/Variance (in / out) → TypeScript Generics, keyof, Mapped/Conditional Types, infer, Awaited/NoInfer & .d.ts Module Augmentation. Notice the critical difference: because TypeScript erases 100% of types in production JS (no reified, no reflection like KClass<T>), compile-time type guarantees must be paired with runtime validation (such as schema checks or type predicates) at untrusted I/O boundaries.

Bounded Generics & Key Lookups <T : BaseModel>; Kotlin property refs User::email <T, K extends keyof T>(obj: T, key: K): T[K] and NoInfer<T> keyof T produces a union of literal keys; T[K] performs indexed lookup. NoInfer<T> stops a secondary argument from widening T.
Variance (out / in) Declaration-site out T (covariant producer) & in T (contravariant consumer) Structural variance: return positions are covariant; function parameter positions are contravariant under strictFunctionTypes Trap: Interface method syntax (onEvent(x: T): void) is bivariant for legacy reasons; arrow property syntax (onEvent: (x: T) => void) enforces sound contravariance.
Transforming Existing Shapes Manual DTO classes, Kotlin data class copies, or annotation processors (KSP/MapStruct) Built-in utilities (Partial, Pick, Omit, Record) powered by Mapped Types Mapped types iterate over union keys: { [K in keyof T]?: T[K] }. No codegen or duplicate DTOs needed—types derive directly from a single source of truth.
Type-Level Branching & Extraction No direct Kotlin compile-time equivalent (closest: when on runtime types or KSP) Conditional types T extends U ? X : Y + infer R + Awaited<T> Naked type parameter T distributes across unions automatically. Wrap in tuples [T] extends [U] to disable distribution.
String & Tree Type Modeling Regex / runtime string parsing; sealed recursive classes Template literal types (`on${Capitalize<E>}`) & recursive types (JsonValue, Paths<T>) TS enforces recursion depth limits (~50–1000 levels with tail-recursion). Guard infinite expansion on circular DOM/object graphs.
Extending Third-Party Types Kotlin extension functions (fun Window.foo()) Ambient .d.ts declarations (declare module, declare global) + interface merging In a file with top-level import/export, ambient globals require declare global { ... }. Plain .d.ts files without imports pollute global scope.

06 · Production Verification & Next Steps

TypeScript Compiler & .d.ts Production Checklist

  • Strict Variance & Function Safety: Confirm "strict": true (enabling strictFunctionTypes) in tsconfig.json, and declare callback properties on interfaces using arrow syntax (onSelect: (item: T) => void) rather than method syntax so contravariance is enforced.
  • No Silent Type Drift with NoInfer<T>: On generic helpers like createStore(initial, defaultKey) or selectOption(options, fallback), wrap secondary parameters in NoInfer<T> (TS 5.4+) so invalid fallback literals error instead of silently widening T.
  • Safe .d.ts Augmentation: Always include export {} (or an import) in module augmentation files, wrap Window/globalThis extensions in declare global { ... }, and use tsconfig.json "types" / "typeRoots" intentionally so test globals (e.g. Jest/Vitest) don't leak into browser bundles.
  • Boundary Validation Over Type Assertions: Never cast fetched JSON with as User; parse untrusted payloads with runtime validation (or type predicates) and derive static types from one source of truth.
Local Compiler Companion (tsc --noEmit): Pair these JS type-algebra labs with real compiler checks in a scratch .ts project (or TypeScript Playground): verify NoInfer<T> catches an invalid default key at compile time, test contravariant callback errors under strictFunctionTypes, and confirm an ambient global.d.ts file augments Window cleanly only when export {} is present.
