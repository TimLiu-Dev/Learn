Backend Testing, Observability & Docker: Supertest, Testcontainers, Pino & OTel

Shipping features that pass mocked unit tests only to fail on a Postgres constraint, leak Bearer tokens into log aggregators, or drop active HTTP requests on every Kubernetes deploy is not production engineering. In this lesson, you will test real HTTP and SQL behavior with Vitest, Supertest, and Testcontainers; emit redacted Pino JSON logs and W3C OpenTelemetry traces across Frontend→Node→Postgres; separate /healthz from /readyz; profile V8 heaps with node --inspect; and package non-root multi-stage Docker images that drain cleanly on SIGTERM.

01 · Mental Model Bridge (Spring Boot Bridge)

JUnit + MockMvc + Spring Actuator/SLF4J → Vitest, Supertest, Testcontainers, Pino, OTel & Docker

In Spring Boot, production readiness is built into the starter ecosystem: JUnit 5 + MockMvc exercises controllers, @Testcontainers boots ephemeral Postgres, SLF4J + MDC attaches correlation IDs, Micrometer Tracing propagates W3C trace headers, Spring Boot Actuator splits liveness from readiness, and server.shutdown=graceful drains in-flight threads on SIGTERM.

In Node.js, nothing is wired automatically by default—which means senior engineers assemble lightweight, composable primitives with zero magic. From first principles: real integration tests catch database constraint and serialization bugs mocks hide; structured redacted JSON logs + W3C trace context let you follow one browser click through Node into SQL; distroless/non-root multi-stage containers cut attack surface and image size by 80%; and explicit SIGTERM draining guarantees zero-downtime rolling deploys.

Operational Concern Spring Boot / JVM Equivalent Node.js Production Stack First-Principles Why & Key Pitfall
HTTP Route Testing MockMvc / WebTestClient Vitest + Supertest Drives your real Express/Fastify/Hono router, validation middleware, status codes, and JSON serialization in-process without binding a fixed TCP port.
Database Integration @Testcontainers + Flyway/Liquibase Testcontainers (Node) + real Postgres Mocking Prisma/Drizzle/pg skips UNIQUE constraints, ON CONFLICT, SQL syntax, and transactions. Real ephemeral containers verify actual queries.
Structured Logging SLF4J + Logback JSON + MDC Pino + redact + AsyncLocalStorage console.log emits unstructured text and blocks stdout under load. Pino writes fast newline-delimited JSON with automatic requestId and secret masking.
Distributed Tracing Micrometer Tracing / OTel Java Agent OpenTelemetry JS + W3C traceparent Propagates 00-<traceId>-<spanId>-<flags> from browser fetch through Node HTTP handlers into pg spans so latency bottlenecks show up in one waterfall.
Probes & Profiling Spring Actuator (/health/liveness, /readiness) + JFR /healthz vs /readyz + node --inspect Liveness checks if the event loop is alive; readiness checks Postgres/Redis + shutdown state. Putting DB checks inside /healthz causes cascading pod restarts.
Containers & Shutdown Layered JAR Dockerfile + server.shutdown=graceful Multi-stage Dockerfile (USER node) + SIGTERM drain Build deps stay out of runtime images, USER node blocks root breakout, and SIGTERM flips /readyz to 503, drains active sockets, closes pools, and enforces a deadline.

06 · Real-World Verification & Production Checklist

Release Verification Checklist + Teacher Follow-Up

  • Real-DB Integration Suite: Run vitest against Testcontainers Postgres with real migrations applied—verify 409 Conflict on unique-key violations, transaction rollbacks on partial failures, and Supertest schema/header assertions.
  • Log & Trace Audit: Trigger a sample authenticated request locally and inspect stdout: verify one JSON line per log via Pino, valid requestId + traceId + spanId fields, and "[Redacted]" on authorization, password, token, and cookie keys.
  • Probe & Shutdown Drill: Run docker build (confirm non-root whoami returns node, no TypeScript/devDependencies in final stage), start the container, hit /healthz and /readyz, send docker stop (SIGTERM), and verify active requests finish before the pool closes.
  • Memory Leak Triage: Start Node with node --inspect=127.0.0.1:9229 dist/server.js (never bind 0.0.0.0 in prod), open chrome://inspect, take two Heap Snapshots separated by load, and inspect Objects allocated between Snapshot 1 and Snapshot 2 to pinpoint retained closures or unbounded Maps.
Primary Source Recommendations: Bookmark Pino Logger Docs (redaction, child loggers, async transports), OpenTelemetry JS Docs (W3C Trace Context, auto-instrumentation), and Testcontainers for Node.js.
