04 · Architectural Decisions & Interview Defense

ADR Templates & Senior Interview Talking Points

Senior Interview Defense Prompts

Q1. Why keep filters and active drawer ID in the URL instead of Zustand or an Angular SignalStore? State Ownership

Defense: Filters, sort order, and the open issue ID (?status=triage&priority=p0&sort=updatedAt&issue=TRI-104) are shareable navigation state, not ephemeral UI state. Putting them in validated URL search params (TanStack Router validateSearch with Zod, or Angular Router queryParams + toSignal) guarantees deep-linking, browser Back/Forward history, and page-reload persistence with zero store synchronization bugs. Only non-shareable transient UI (e.g., whether Cmd+K is open or drag hover target) belongs in Zustand or local component Signals.

Q2. Two rapid optimistic transitions hit Issue TRI-104: move to "In Progress" then "Resolved". Call #1 fails with 500 while Call #2 succeeds. How do you prevent stale rollback corruption? Concurrency

Defense: Never blindly restore a single global snapshot on error when mutations overlap. Track per-entity in-flight mutation counts (or monotonic clientVersion / mutationId per issue), cancel or serialize per-issue transitions via an ordered queue or TanStack Query mutationKey: ['issue', id] + cancelQueries, and only roll back if the failing mutation is still the latest optimistic intent—otherwise invalidate from the authoritative server response in onSettled.

Q3. Why design all 5 UI states up front instead of adding skeletons and offline banners at the end? 5-State UX

Defense: Bolting on loading, empty, error, pending, and offline states late breaks layout stability (CLS) and leaves dead-end screens. By modeling a discriminated union (or Query status + isFetching + isPending + onlineStatus) at the design-system level, skeletons preserve exact column/card heights, empty states distinguish "no issues exist" from "filters matched zero issues" with a one-click reset CTA, and inline errors keep previously cached board rows readable instead of wiping the screen.

Q4. How do you guarantee your integration tests aren't coupled to TanStack Query or Signal internals? Testing & MSW

Defense: We mock at the network boundary using MSW (Mock Service Worker) rather than mocking hooks, services, or fetch spies. Tests render the real router, providers, and state stores, interact via userEvent, and assert exclusively via accessible ARIA roles (getByRole('button', { name: ... }), findByRole('status') for the undo toast, getByRole('dialog') for the drawer and Cmd+K palette). Injecting a simulated 500 via MSW server.use() verifies the full UI + cache rollback path end-to-end.

Q5. What makes your Cmd+K palette and slide-over drawer genuinely WCAG-compliant? Accessibility

Defense: The palette uses proper role="dialog" + role="combobox" / role="listbox" semantics with aria-activedescendant so screen readers announce highlighted options while typing continues uninterrupted. The slide-over drawer traps Tab/Shift+Tab inside focusable controls, closes on Escape, sets inert/aria-hidden on background content, returns focus to the exact issue card button that opened it, and wraps slide/scale animations in @media (prefers-reduced-motion: reduce).
