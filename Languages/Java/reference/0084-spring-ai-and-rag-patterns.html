Production AI Engineering in Java (Spring AI, RAG & @Tool)

Quick reference for structured record outputs, PgVectorStore RAG, and safe @Tool execution.

1. Core Spring AI Building Blocks

ComponentAPIProduction Purpose
Fluent PromptingchatClient.prompt().system(...).user(...)Separates trusted system instructions from parameterized user data.
Structured Output.call().entity(MyRecord.class)Maps LLM JSON output directly to an immutable Java 25 record.
RAG AdvisorQuestionAnswerAdvisor.builder(vectorStore)Injects top-K pgvector similarity matches with tenant metadata filtering.

Canonical Production Snippet: Structured Output + Tenant-Scoped RAG

public record FraudAssessment(String riskTier, List<String> reasons) {}

public FraudAssessment evaluate(String tenantId, String claimText) {
    return chatClient.prompt()
            .advisors(a -> a.param(QuestionAnswerAdvisor.FILTER_EXPRESSION, "tenantId == '" + tenantId + "'"))
            .user(u -> u.text("Evaluate claim:\n{claim}").param("claim", claimText))
            .tools(claimVerificationTools)
            .call()
            .entity(FraudAssessment.class);
}

Senior Production Pitfalls Checklist

  • Never Trust LLM Arguments for Authorization: Pass tenantId and userId from server-side security context (ToolContext / ScopedValue), never as an unverified @Tool parameter.
  • Always Enforce Tenant Metadata Filters in RAG: Unfiltered VectorStore.similaritySearch queries leak embeddings across tenants.
  • Keep DB Transactions Short Around LLM Calls: Never call chatClient.prompt().call() inside an open @Transactional database block—a 3-second LLM call will hold a HikariCP connection idle and exhaust the pool!
