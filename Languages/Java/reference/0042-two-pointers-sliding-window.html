Arrays, Two Pointers & Dynamic Sliding Window — Quick Reference

Two Pointers & Sliding Window Reference.

Two Pointers & Sliding Window Reference

Pattern Pointer Movement Prerequisites & Invariants
Inward Pointers left++ and right-- towards center Requires sorted order or convex metric (e.g. Container With Most Water).
Fast / Slow fast advances 2x or scans; slow marks partition In-place partitioning, cycle detection (Tortoise and Hare).
Dynamic Sliding Window right++ expands; left++ contracts on violation Monotonic window property: shrinking restores validity. Amortized O(N).
Fixed Sliding Window Advance both pointers together (right - left + 1 == k) Window of fixed width k; add incoming, subtract outgoing.

Canonical Production Snippet: Dynamic ASCII Sliding Window

public int lengthOfLongestSubstring(String s) {
    int[] lastSeen = new int[128];
    Arrays.fill(lastSeen, -1);
    int maxLen = 0, left = 0;

    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        if (lastSeen[c] >= left) {
            left = lastSeen[c] + 1; // Jump left pointer past previous occurrence
        }
        lastSeen[c] = right;
        maxLen = Math.max(maxLen, right - left + 1);
    }
    return maxLen;
}

Senior Production Pitfalls Checklist

  • Sorted Invariant Assumption: Never apply inward two-pointer sum search to an unsorted array without sorting first (or using a HashMap).
  • Off-by-One in Window Size: Window length between indices left and right (inclusive) is always right - left + 1.
  • Avoid Character Boxing: Use int[128] or int[256] instead of Map<Character, Integer> to eliminate boxing and hashing overhead.
