High-Contention Concurrency: ConcurrentHashMap, LongAdder, StampedLock & Semaphore — Quick Reference

LongAdder, StampedLock, and ConcurrentHashMap Mechanics.

Concurrent Collections & Locks Reference

Construct Contention Strategy Best Used When
LongAdder Striped cell array with cache-line padding High-frequency write metrics, counters, and telemetry.
StampedLock Optimistic validation stamp (zero memory writes) Predominantly read-heavy data where reads rarely conflict with writes.
ConcurrentHashMap Lock-free CAS for empty bins, synchronized per-bin node Concurrent key-value caching and thread-safe indexing.
ReentrantLock Exclusive re-entrant locking with Condition variables Complex critical sections requiring re-entrancy and timed acquisition.
Semaphore Permit counter based on AbstractQueuedSynchronizer (AQS) Rate-limiting external API calls and resource connection pools.

Canonical Production Snippet: StampedLock Optimistic Read Pattern

public class InventoryState {
    private int stock;
    private final StampedLock lock = new StampedLock();

    public int getStock() {
        long stamp = lock.tryOptimisticRead();
        int currentStock = stock;
        if (!lock.validate(stamp)) { // Interrupted by a write
            stamp = lock.readLock(); // Acquire pessimistic read lock
            try {
                currentStock = stock;
            } finally {
                lock.unlockRead(stamp);
            }
        }
        return currentStock;
    }
}

Senior Production Pitfalls Checklist

  • StampedLock Non-Reentrancy: StampedLock does not allow recursive locking. Re-acquiring a write lock from the same thread causes an immediate self-deadlock.
  • AtomicLong Under Contention: Replacing AtomicLong with LongAdder in hot counters can yield a 10x-50x throughput improvement on multi-core servers.
  • computeIfAbsent Re-entrancy: Never perform nested mutations or database queries inside a ConcurrentHashMap.computeIfAbsent() mapping function.
