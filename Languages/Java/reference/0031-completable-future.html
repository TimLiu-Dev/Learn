Asynchronous Composition, Timeouts & Custom Pools with CompletableFuture — Quick Reference

CompletableFuture Reference.

CompletableFuture Reference

Pipeline Method Functional Role Senior Production Usage Note
supplyAsync(task, pool) Initiates asynchronous task Always supply a dedicated I/O pool; avoid commonPool().
thenApply(fn) Synchronous transformation (map) Transforms T -> U; does not unwrap nested futures.
thenCompose(fn) Asynchronous chaining (flatMap) Unwraps T -> CompletableFuture<U> into CompletableFuture<U>.
completeOnTimeout(def, time, unit) Resilient fallback on delay Supplies default value if future does not complete in time.
orTimeout(time, unit) Hard SLA timeout Fails future with TimeoutException if time expires.

Canonical Production Snippet: Resilient Multi-Service Aggregation

public CompletableFuture<Dashboard> loadDashboard(String userId, Executor pool) {
    CompletableFuture<User> userFuture = CompletableFuture.supplyAsync(() -> userService.get(userId), pool)
        .orTimeout(2, TimeUnit.SECONDS);

    CompletableFuture<List<Order>> ordersFuture = CompletableFuture.supplyAsync(() -> orderService.get(userId), pool)
        .completeOnTimeout(List.of(), 1, TimeUnit.SECONDS);

    return userFuture.thenCombine(ordersFuture, Dashboard::new)
        .exceptionally(ex -> Dashboard.degraded(userId));
}

Senior Production Pitfalls Checklist

  • Never Block CommonPool: Never dispatch blocking I/O to supplyAsync(task) without specifying a dedicated custom thread pool.
  • Unhandled Exceptions: A failure inside an unhandled stage leaves the future completed exceptionally without logging; always attach exceptionally or whenComplete.
  • Use Java 9+ Timeouts: Never use blocking future.get(5, TimeUnit.SECONDS) when building reactive non-blocking web servers; use orTimeout() instead.
