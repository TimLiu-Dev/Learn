Spring Security 6 Filter Chains, OAuth2 Resource Server (JWT), @PreAuthorize & Layered Docker — Quick Reference

Spring Security 6 & Docker Reference.

Spring Security 6 & Docker Reference

Pattern / Component Implementation Senior Production Usage Note
SecurityFilterChain Bean Component-based DSL Replaces legacy WebSecurityConfigurerAdapter.
Stateless Resource Server oauth2ResourceServer.jwt() Validates signed JWTs; disables HTTP sessions and CSRF.
Layered Dockerfile layertools extract Maximizes Docker layer caching; runs as unprivileged appuser.

Canonical Production Snippet: Spring Security 6 Stateless Config

@Configuration
@EnableWebSecurity
@EnableMethodSecurity
public class SecurityConfig {
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        return http
            .csrf(csrf -> csrf.disable())
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/actuator/health", "/public/**").permitAll()
                .anyRequest().authenticated()
            )
            .oauth2ResourceServer(oauth -> oauth.jwt(Customizer.withDefaults()))
            .build();
    }
}

Senior Production Pitfalls Checklist

  • Non-Root Docker User: Never run Java containers as root; create a dedicated appuser in the Dockerfile.
  • Actuator Health Permit: Always permit /actuator/health unauthenticated so Kubernetes probes do not fail.
  • CORS Configuration: In single-page app (SPA) architectures, configure an explicit CorsConfigurationSource bean to handle preflight OPTIONS requests before security filters execute.
