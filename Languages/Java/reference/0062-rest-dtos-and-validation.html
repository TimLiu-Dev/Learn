REST APIs, DTOs & RFC 9457 Reference

Concept Standard / Mechanism Senior Production Usage Note
RFC 9457 ProblemDetail org.springframework.http.ProblemDetail Standardized error format (status, title, detail, type, instance).
Jakarta Validation @Valid @RequestBody Throws MethodArgumentNotValidException on rejected constraints.
DTO Records Java 16+ Records Never expose JPA Entities directly; use DTO records to decouple API schema.

Canonical Production Snippet: RFC 9457 Global Exception Handler

@RestControllerAdvice
public class GlobalExceptionHandler extends ResponseEntityExceptionHandler {
    @Override
    protected ResponseEntity<Object> handleMethodArgumentNotValid(
            MethodArgumentNotValidException ex, HttpHeaders headers, HttpStatusCode status, WebRequest req) {
        ProblemDetail problem = ProblemDetail.forStatusAndDetail(status, "Validation failed for request payload");
        problem.setTitle("Bad Request");
        List<String> errors = ex.getBindingResult().getFieldErrors().stream()
            .map(err -> err.getField() + ": " + err.getDefaultMessage())
            .toList();
        problem.setProperty("invalidFields", errors);
        return ResponseEntity.status(status).body(problem);
    }
}

Senior Production Pitfalls Checklist

  • Entity Exposure in APIs: Never return JPA @Entity objects directly in controllers; always map to DTO records.
  • Enable Standard Problem Details: Set spring.mvc.problemdetails.enabled=true in application.properties to enable RFC 9457 by default.
  • Sanitize Error Details: In production, never return raw SQL exception messages in the ProblemDetail detail field; log the stack trace and return a generic error message.
