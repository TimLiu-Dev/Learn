Garbage Collection Engineering: G1GC & Generational ZGC — Quick Reference

Modern Garbage Collection Reference.

Modern Garbage Collection Reference

Collector Target SLA / Pauses Recommended Production Use Case
G1 GC (Default) 100ms – 250ms target General purpose workloads with balanced throughput and latency.
Generational ZGC (Java 21+, default 24/25) < 1 millisecond Strict latency SLAs (trading, real-time gaming, high-throughput APIs).
Parallel GC Throughput-focused (seconds) Batch compute, offline analytics where pause times do not impact users.

Canonical Production Snippet: Generational ZGC Startup Flags (JDK 25 / JDK 21 note)

java -XX:+UseZGC \
     -Xms16g -Xmx16g \
     -XX:+DisableExplicitGC \
     -Xlog:gc*,gc+phases=debug:file=/var/log/jvm/gc.log:time,tags:filecount=5,filesize=100M \
     -jar payment-service.jar
# On JDK 21 only, add -XX:+ZGenerational (removed in JDK 24 JEP 490)

Senior Production Pitfalls Checklist

  • Disable Explicit GC: Always include -XX:+DisableExplicitGC to block rogue System.gc() calls from vendor dependencies.
  • Avoid Humongous Spikes: If G1 logs show humongous allocation, increase region size (-XX:G1HeapRegionSize=16m) or stream data instead of allocating massive arrays.
  • Log Rotation: Always configure unified GC logging with file count and file size limits to prevent filling root filesystem storage.
