JDK Dynamic Proxies vs CGLIB/ByteBuddy & The Self-Invocation Trap — Quick Reference

Dynamic Proxies & AOP Reference.

Dynamic Proxies & AOP Reference

Proxy Mechanism Underlying Technology Capabilities & Limitations
JDK Dynamic Proxy java.lang.reflect.Proxy Fast, built into JDK. Requires interfaces; cannot proxy concrete classes.
ByteBuddy / CGLIB Runtime subclass bytecode generation Proxies concrete classes. Fails on final classes and final methods.
Self-Invocation this.internalMethod() Critical Hazard: Bypasses proxy; annotations are silently ignored.

Canonical Production Snippet: Solving Self-Invocation via Collaborator

@Service
public class OrderService {
    private final PaymentProcessor paymentProcessor; // Injected proxy collaborator!

    public OrderService(PaymentProcessor paymentProcessor) {
        this.paymentProcessor = paymentProcessor;
    }

    public void processOrder(Order order) {
        // Calling collaborator goes through proxy wrapper -> @Transactional is enforced!
        paymentProcessor.charge(order.amount());
    }
}

Senior Production Pitfalls Checklist

  • Self-Invocation Bug: Never call an internal @Transactional or @Async method using this.method(). Extract the method to a collaborator bean.
  • Final Modifier Hazard: If using Spring Boot default CGLIB/ByteBuddy proxying, never mark proxyable service classes or methods as final.
  • Proxy Equality: Be careful with proxy.equals(target); proxies may not share identity with their underlying target objects.
