JVM Memory Layout & Compressed OOPs Reference.

JVM Memory Layout & Compressed OOPs Reference

Memory Segment Managed By Key Tuning Flags & Characteristics
Young Generation (Eden + S0/S1) Garbage Collector Holds short-lived allocations. Survived items age up to 15.
Tenured / Old Generation Garbage Collector Holds long-lived domain objects and caches.
Metaspace (Native OS) OS Native Allocator -XX:MaxMetaspaceSize=512m bounds class metadata memory.
Compressed OOPs HotSpot JVM Active below 32GB (-XX:+UseCompressedOops); disabled at >=32GB!

Canonical Production Snippet: Memory Sizing Inspection

// Recommended JVM flags for high-throughput container service
// -Xms31g -Xmx31g -XX:+UseCompressedOops -XX:MaxMetaspaceSize=512m

Senior Production Pitfalls Checklist

  • The 32GB Cliff: Never set -Xmx between 32GB and 40GB. 31GB yields more usable memory because 4-byte Compressed OOPs remain active.
  • Metaspace Leak in Containers: Dynamic class generators (CGLIB, reflection proxies) without classloader cleanup cause silent native memory growth and OS OOM killer kills.
  • Object Alignment Padding: All objects align to 8-byte boundaries. An empty object with 0 fields still consumes 16 bytes.
