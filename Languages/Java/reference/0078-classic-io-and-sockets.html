Classic java.io Decorators & Blocking Socket Rules

Quick checklist for choosing byte vs character streams, explicit UTF-8, flushing, and socket timeouts.

1. Classic java.io Decorator Reference

Decorator / APIStream TypeSenior Production Rule
InputStreamReader / OutputStreamWriterByte ↔ Char BridgeAlways pass StandardCharsets.UTF_8 explicitly.
BufferedReader / BufferedWriter8 KiB Char BufferAlways call writer.flush() before awaiting a peer reply on a socket.
Socket.setSoTimeout(ms)Read TimeoutMandatory before readLine() / read() so dead peers cannot hang threads forever.

Canonical Production Snippet: Virtual-Thread Blocking Socket Loop

// Safe Blocking Server Loop with Java 25 Virtual Threads
try (var server = new ServerSocket(9090)) {
    while (!Thread.currentThread().isInterrupted()) {
        Socket client = server.accept();
        Thread.ofVirtual().start(() -> handleClient(client));
    }
}

void handleClient(Socket socket) {
    try (socket;
         var in = new BufferedReader(new InputStreamReader(socket.getInputStream(), StandardCharsets.UTF_8));
         var out = new BufferedWriter(new OutputStreamWriter(socket.getOutputStream(), StandardCharsets.UTF_8))) {
        socket.setSoTimeout(3_000);
        String line = in.readLine();
        if (line != null && line.length() <= 4096) {
            out.write("ACK:" + line + "\n");
            out.flush();
        }
    } catch (IOException ignored) { /* log bounded warning */ }
}

Senior Production Pitfalls Checklist

  • Unflushed BufferedWriter Deadlocks: On interactive sockets, bytes sit in the 8 KiB JVM buffer until out.flush() is called.
  • Unbounded readLine() OOM: An attacker sending gigabytes without a newline character will exhaust heap memory on BufferedReader.readLine() unless stream length or frame size is bounded.
  • Infinite Socket Read Timeout: Default SO_TIMEOUT is 0 (forever); always set socket.setSoTimeout(millis).
