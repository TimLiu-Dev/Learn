Spring Data JPA: Projections, Keyset Pagination, OSIV Off & Read-Only Transactions — Quick Reference

Spring Data JPA Performance Reference.

Spring Data JPA Performance Reference

Pattern / Practice Mechanism Senior Production Usage Note
spring.jpa.open-in-view=false Closes DB session on tx end Prevents connection pool starvation; requires explicit fetch joins.
Keyset Pagination WHERE id > :lastId LIMIT :size Constant O(1) index seek vs degraded O(N) offset pagination.
@Transactional(readOnly = true) Disables dirty checking Saves CPU and memory; enables read-replica connection routing.
DTO Constructor Projections SELECT new Dto(...) Bypasses entity management in persistence context.

Canonical Production Snippet: Keyset Pagination with Projections

@Repository
public interface OrderRepository extends JpaRepository<Order, Long> {
    @Transactional(readOnly = true)
    @Query("SELECT new com.example.OrderSummary(o.id, o.orderNumber, o.amountCents) " +
           "FROM Order o WHERE o.id > :lastSeenId ORDER BY o.id ASC LIMIT :pageSize")
    List<OrderSummary> findNextPage(Long lastSeenId, int pageSize);
}

Senior Production Pitfalls Checklist

  • Always Disable OSIV: Add spring.jpa.open-in-view=false to your application.properties in every microservice.
  • Avoid Offset Pagination on Large Tables: Keyset pagination or cursor-based pagination is mandatory when tables exceed 100,000 rows.
  • LazyInitializationException with OSIV Off: With OSIV off, accessing uninitialized lazy relationships in controllers throws LazyInitializationException. Use JOIN FETCH or DTO projections in repository queries.
