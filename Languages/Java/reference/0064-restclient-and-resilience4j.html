Inter-Service HTTP: Spring RestClient, Resilience4j (Circuit Breakers, Retries) & Idempotency Keys — Quick Reference

Spring RestClient, Resilience4j & Idempotency Reference.

RestClient & Resilience4j Reference

Pattern Mechanism Failure Mitigation
RestClient Synchronous fluent client over Virtual Threads Explicit connect/read timeouts prevent socket exhaustion.
Circuit Breaker CLOSED → OPEN → HALF_OPEN state machine Fails fast when error rate exceeds threshold, preventing cascade failure.
Retry with Jitter Exponential backoff + randomized sleep Prevents synchronized thundering herd spikes against reviving hosts.
Idempotency Keys Atomic putIfAbsent / SET NX Guarantees exactly-once side effects on duplicate payment retries.

Canonical Production Snippet: RestClient with Resilience4j Decoration

CircuitBreaker breaker = CircuitBreaker.ofDefaults("externalApi");
Supplier<UserResponse> call = CircuitBreaker.decorateSupplier(breaker, () ->
    restClient.get()
        .uri("/users/{id}", userId)
        .retrieve()
        .body(UserResponse.class)
);
UserResponse response = Try.ofSupplier(call)
    .recover(CallNotPermittedException.class, ex -> UserResponse.fallback())
    .get();

Senior Production Pitfalls Checklist

  • Omitted Timeouts: Never initialize an HTTP client without setting explicit connect and read timeouts; defaulting to infinite causes dead thread starvation.
  • Atomic Idempotency Claims: Always use atomic insert operations (SET NX in Redis or putIfAbsent in memory) rather than checking existence before inserting.
  • Retry Only Transient Errors: Never retry client 4xx errors (like 400 Bad Request or 401 Unauthorized); retry only transient 503 Unavailable or network timeouts.
