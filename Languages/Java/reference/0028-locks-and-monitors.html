Synchronization & Locks Quick Reference.

Synchronization & Locks Quick Reference

Construct Key Capabilities Senior Recommendation
synchronized Block/method scoping, clean syntax, auto-unlock on exit Ideal for simple uncontended critical sections without timeouts.
ReentrantLock tryLock(timeout), fair mode, multiple conditions Mandatory when timeouts, interruptibility, or non-block scoping are needed.
Condition Separate wait-sets (notFull, notEmpty) Always await inside a while loop to survive spurious wakeups.
Lock Ordering Deterministic ordering across multiple locks Mathematically eliminates the Circular Wait condition for deadlocks.

Canonical Production Snippet: Timed Acquisition with tryLock

if (lock.tryLock(3, TimeUnit.SECONDS)) {
    try {
        processOrder();
    } finally {
        lock.unlock();
    }
} else {
    logger.warn("Could not acquire lock within 3s; shedding load");
    throw new ServiceUnavailableException("Server busy");
}

Senior Production Pitfalls Checklist

  • Spurious Wakeups: Never replace while (!ready) condition.await(); with an if block.
  • Unlock Outside Finally: Always place lock.unlock() inside a finally block immediately following lock acquisition.
  • Deadlock via Reverse Locking: If acquiring multiple locks (e.g., account transfers), always order locks by unique identifier before locking.
