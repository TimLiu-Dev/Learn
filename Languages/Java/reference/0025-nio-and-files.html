Java NIO.2, ByteBuffers, Channels & Atomic File Operations — Quick Reference

Java NIO.2 & File I/O Quick Reference.

Java NIO.2 & File I/O Quick Reference

API Method Resource Safety Production Usage Note
Files.readString(path) Auto-closed Best for small config files; reads entire file into heap string.
Files.lines(path) Requires try-with-resources Must be closed explicitly to prevent file descriptor leaks!
Files.newByteChannel(path) Requires try-with-resources Direct buffer streaming without buffering full payload in heap.
Files.move(..., ATOMIC_MOVE) Atomic OS Rename Guarantees crash safety; fails across cross-device mount boundaries.

Canonical Production Snippet: Crash-Resilient Atomic Write

public static void safeAtomicWrite(Path file, String content) throws IOException {
    Path parent = file.getParent() != null ? file.getParent() : Path.of(".");
    Path temp = Files.createTempFile(parent, "swap-", ".tmp");
    Files.writeString(temp, content, StandardCharsets.UTF_8);
    Files.move(temp, file, StandardCopyOption.ATOMIC_MOVE, StandardCopyOption.REPLACE_EXISTING);
}

Senior Production Pitfalls Checklist

  • Stream Descriptor Leak: Never chain Files.lines(p).count() without a try-with-resources wrapper.
  • Cross-Device Atomic Moves: ATOMIC_MOVE throws AtomicMoveNotSupportedException if the temp file and target file reside on different mount points. Always create temp files in the target file's parent directory.
  • ByteBuffer State: Always call buffer.flip() before writing channel data from a populated buffer, and buffer.compact() or buffer.clear() before refilling.
