Pass-by-Value Reference Semantics in Java — Quick Reference

Pass-by-Value & Stack Frame Semantics Reference.

Pass-by-Value Semantics Reference

Parameter Type What is Passed? Callee Capabilities & Limitations
Primitive (int, double) Raw bit value copy Cannot mutate caller's variable under any circumstances.
Reference (Object, int[]) Pointer address copy CAN mutate heap state (e.g. arr[0] = 5); CANNOT rebind caller pointer.

Canonical Mental Model: Reference Copy vs Heap Mutation

// 1. REASSIGNMENT: No effect on caller
void reassign(Box b) {
    b = new Box(99); // Modifies local stack slot only!
}

// 2. MUTATION: Mutates single shared heap object
void mutate(Box b) {
    b.setValue(99);  // Modifies object in heap; caller sees this!
}

Senior Production Pitfalls Checklist

  • The Fake Swap Method: In Java, a method cannot swap two caller references. Always return a tuple, record, or array.
  • Defensive Copying of Arguments: If a method accepts a mutable collection or array, clone it immediately if internal mutation must be isolated from the caller.
  • Immutable Types: Passing String, Integer, or records is inherently safe because their state cannot be mutated by callee methods.
