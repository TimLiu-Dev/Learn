HotSpot JIT (C1/C2, Escape Analysis) & Production Profiling (JFR, Async-Profiler, jcmd) — Quick Reference

HotSpot JIT, Escape Analysis & Production Diagnostics.

HotSpot JIT & Diagnostics Reference

Compilation Tier Compiler Optimization Goal
Tier 0 Interpreter Zero startup latency + runtime profiling collection.
Tiers 1–3 C1 (Client) Fast compilation, basic inlining, instrumented profiling.
Tier 4 C2 (Server) Global optimization: Escape Analysis, scalar replacement, loop unrolling, SIMD.

Essential Diagnostic CLI Commands

# 1. Start continuous 60s JFR recording in production container:
jcmd <pid> JFR.start name=prod_dump duration=60s filename=/tmp/prod.jfr

# 2. Dump thread stacks directly to a file:
jcmd <pid> Thread.dump_to_file /tmp/threads.tdump

# 3. Print VM flags and memory settings:
jcmd <pid> VM.flags -all

Senior Production Pitfalls Checklist

  • Escape Analysis Failure via Public Methods: Returning a temporary object or passing it to an un-inlined foreign method turns NoEscape into GlobalEscape or ArgEscape, forcing heap allocation.
  • Safepoint Bias: Sampling profilers that inspect threads only at JVM Safepoints yield distorted CPU profiles; use async-profiler for accurate flame graphs.
  • Avoid Microbenchmark Dead-Code Elimination: Always use JMH (Java Microbenchmark Harness) and consume computation results with Blackhole.consume().
