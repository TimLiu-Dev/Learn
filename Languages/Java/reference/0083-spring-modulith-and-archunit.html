Modular Monoliths (Spring Modulith), Hexagonal Ports & ArchUnit

Quick reference for enforcing clean module boundaries, hexagonal ports, and transactional module events.

Canonical Production Snippet: Spring Modulith + ArchUnit JUnit Gate

class ArchitectureGateTest {
    @Test
    void verifyModularStructure() {
        ApplicationModules.of(OrderPlatformApp.class).verify();
    }

    @Test
    void domainRemainsPureJava() {
        var imported = new ClassFileImporter().importPackages("com.acme");
        ArchRuleDefinition.noClasses()
                .that().resideInAPackage("..domain..")
                .should().dependOnClassesThat()
                .resideInAnyPackage("..web..", "..persistence..", "jakarta.persistence..")
                .check(imported);
    }
}

Senior Production Pitfalls Checklist

  • Cross-Module Table Joins: Never join or query another module's database tables directly; communicate via public module APIs or domain events.
  • Leaking JPA Entities Across Boundaries: Keep @Entity classes inside the persistence adapter or module `.internal` package; expose immutable Java `record` DTOs/events.
  • Unverified Architecture Rules: Any architectural boundary not checked by `ApplicationModules.verify()` or an `ArchUnit` test in CI will eventually be bypassed under deadline pressure.
