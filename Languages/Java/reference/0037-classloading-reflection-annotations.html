ClassLoaders, MethodHandles & Annotations Reference.

ClassLoaders, MethodHandles & Annotations Reference

Component Primary Responsibility Senior Performance & Safety Note
ClassLoader Hierarchy Bootstrap → Platform → Application Parent-first delegation prevents core JDK type hijacking.
MethodHandles.Lookup Direct method invocation C2 JIT inlines invokeExact calls; far faster than Method.invoke.
RetentionPolicy.RUNTIME Preserves metadata in memory Mandatory for annotations inspected at runtime by reflection or DI containers.
JPMS Strong Encapsulation Module boundaries (Java 17+) Illegal reflective access is blocked unless module opens packages.

Canonical Production Snippet: High-Performance MethodHandle Accessor

public class FastFieldAccessor {
    private static final MethodHandle GET_BALANCE;
    static {
        try {
            MethodHandles.Lookup lookup = MethodHandles.lookup();
            GET_BALANCE = lookup.findGetter(Account.class, "balance", long.class);
        } catch (ReflectiveOperationException e) {
            throw new ExceptionInInitializerError(e);
        }
    }

    public static long getBalance(Account acc) throws Throwable {
        return (long) GET_BALANCE.invokeExact(acc); // Direct JIT inlined native read
    }
}

Senior Production Pitfalls Checklist

  • Missing RUNTIME Retention: Forgetting @Retention(RetentionPolicy.RUNTIME) causes annotations to silently disappear when inspecting classes via reflection.
  • Static Final MethodHandles: Always store MethodHandle instances in static final fields so the JIT compiler can perform constant folding and call inlining.
  • ClassLoader Leaks: Storing classloader references in static caches or ThreadLocals prevents class metadata in Metaspace from ever being reclaimed.
