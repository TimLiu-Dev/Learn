Canonical Production Pattern: Sealed Hierarchy & Exhaustive Switch

public sealed interface DomainEvent permits UserCreated, UserSuspended, UserDeleted {}
public record UserCreated(UUID id, String email, Instant at) implements DomainEvent {}
public record UserSuspended(UUID id, String reason) implements DomainEvent {}
public record UserDeleted(UUID id) implements DomainEvent {}

public String processEvent(DomainEvent event) {
    return switch (event) {
        case UserCreated(var id, var email, _) -> "Notify " + email + " for user " + id;
        case UserSuspended(var id, var reason) -> "Halt access for " + id + ": " + reason;
        case UserDeleted(var id) -> "Purge records for user " + id;
    }; // Exhaustive! Adding a new permitted subtype will break compilation here.
}

Senior Production Pitfalls Checklist

  • Implicit NPE on Null: A switch without case null throws NullPointerException immediately on null selector input.
  • Order of Patterns Matters: Specific guarded patterns must precede broader unguarded patterns of the same type, or the compiler reports an "unreachable case label" error.
  • Default Masks Missing Subtypes: Avoid adding a default branch when switching over sealed hierarchies, as it silences compiler exhaustiveness warnings when new domain types are added.
