Canonical Production Snippet: Flyway & JPA Optimistic Lock

// 1. Database schema migration: V2__add_optimistic_version.sql
ALTER TABLE orders ADD COLUMN version BIGINT NOT NULL DEFAULT 0;

// 2. Entity definition in Spring Data JPA:
@Entity
@Table(name = "orders")
public class OrderEntity {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Version
    private Long version;
}

Senior Production Pitfalls Checklist

  • Never Modify Applied Migrations: Modifying a previously executed Flyway migration script breaks its cryptographic checksum, halting application startup.
  • Prevent Lock Inversion Deadlocks: Always acquire pessimistic locks in a consistent global order (e.g. sorted by entity ID).
  • Optimistic Retry Storms: When retrying on ObjectOptimisticLockingFailureException, apply exponential backoff with jitter to prevent cascading thread contention.
