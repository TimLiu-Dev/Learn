JDBC Batching & HikariCP Pool Sizing Cheat Sheet

Wire-level driver flags, HikariCP sizing math, timeout hierarchy, and atomic batch templates.

1. HikariCP & JDBC Timeout Hierarchy Matrix

Core sizing rule: connections = (core_count * 2) + effective_spindle_count (approx. 17–20 total active queries for an 8-vCPU SSD database, divided across application replicas).

Layer / Knob Property Name Recommended Range What It Bounds

2. Essential Driver Batching Flags

Database Driver JDBC URL Parameter Wire Effect
PostgreSQL (pgjdbc) reWriteBatchedInserts=true&prepareThreshold=5 Rewrites INSERT ... VALUES (?,?,?) batches into multi-row VALUES (...),(...) statements (10x–25x faster).
MySQL / MariaDB rewriteBatchedStatements=true&useServerPrepStmts=true Packs single-row inserts into multi-value packets up to max_allowed_packet.

3. Canonical Production JDBC Batch Template

public int batchInsert(DataSource ds, List<Row> rows) throws SQLException {
    final String sql = "INSERT INTO audit_log (id, actor, created_at) VALUES (?, ?, ?)";
    try (Connection conn = ds.getConnection()) {
        boolean priorAutoCommit = conn.getAutoCommit();
        conn.setAutoCommit(false);
        try (PreparedStatement ps = conn.prepareStatement(sql)) {
            int i = 0;
            for (Row r : rows) {
                ps.setObject(1, r.id());
                ps.setString(2, r.actor());
                ps.setObject(3, r.createdAt()); // Java 25 OffsetDateTime / Instant via JDBC 4.2
                ps.addBatch();
                if (++i % 500 == 0) {
                    ps.executeBatch();
                    ps.clearBatch();
                }
            }
            if (i % 500 != 0) {
                ps.executeBatch();
            }
            conn.commit();
            return i;
        } catch (Exception ex) {
            try { conn.rollback(); } catch (SQLException sup) { ex.addSuppressed(sup); }
            throw ex;
        } finally {
            conn.setAutoCommit(priorAutoCommit);
        }
    }
}

4. Senior Production Pitfalls Checklist

  • Never hold a DB connection across HTTP/RPC/Kafka I/O: Perform all external network calls before borrowing or after closing the JDBC connection.
  • Keep minimumIdle == maximumPoolSize: Dynamic pool shrinking/growing causes TLS handshake latency spikes right when traffic surges arrive.
  • Verify replicas * maximumPoolSize < max_connections: During rolling Kubernetes deploys (2x pod surge), oversized pools will trip PostgreSQL FATAL: sorry, too many clients already.
  • Chunk addBatch() at 500–1,000 rows: Unbounded addBatch() buffers millions of bind arrays in JVM heap before flushing to the socket.
  • Use ps.setObject(idx, OffsetDateTime/LocalDate): Prefer JDBC 4.2 java.time bindings over legacy java.sql.Timestamp to avoid JVM default-timezone shifts.
