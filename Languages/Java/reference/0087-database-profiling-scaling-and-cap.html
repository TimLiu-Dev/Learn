Canonical Production Snippet: Partial Covering Index + Lazy Replica Proxy

CREATE INDEX idx_orders_open_tenant
    ON orders (tenant_id, created_at DESC)
    INCLUDE (total_cents)
    WHERE status = 'OPEN';

@Bean
public DataSource dataSource(DataSource primary, DataSource replica) {
    var routing = new ReplicaRoutingDataSource();
    routing.setTargetDataSources(Map.of(Role.PRIMARY, primary, Role.REPLICA, replica));
    routing.setDefaultTargetDataSource(primary);
    routing.afterPropertiesSet();
    return new LazyConnectionDataSourceProxy(routing);
}

Senior Production Pitfalls Checklist

  • Non-Sargable Predicates: Wrapping columns in LOWER(col), DATE(created_at), or leading LIKE '%foo' bypasses standard B-Tree indexes.
  • Replication Lag Blind Spots: Redirecting straight to a replica read right after a POST write causes phantom 404s unless read-your-own-writes pinning is enforced.
  • Over-Indexing Write-Heavy Tables: Every extra index slows down INSERT/UPDATE/VACUUM and competes for PostgreSQL shared buffers; prefer narrow partial indexes.
