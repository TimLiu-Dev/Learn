JVM Execution & OpenJDK 25 Toolchain Reference

Quick-lookup guide for HotSpot compilation tiers, bytecode descriptors, diagnostic CLI flags, and warmup pitfalls.

1. HotSpot Tiered Compilation Matrix

Tier Execution Engine Profiling Overhead Key Optimizations & Role
Tier 0 Template Interpreter Full profiling Immediate startup execution; collects branch & type profiles; triggers OSR on hot loops.
Tier 1 C1 (Client JIT) None Compiles trivial getters/methods where further C2 optimization yields no gain.
Tier 2 C1 (Limited Profile) Light counters Used when C2 compiler queue is saturated; gathers invocation & back-edge counts.
Tier 3 C1 (Full Profile) MDO profiling Populates MethodDataOop (receiver types, null checks, branch frequencies) for C2.
Tier 4 C2 (Server JIT) None (peak speed) Deep inlining, Escape Analysis scalar replacement, loop unrolling, SIMD, speculative guards.

2. Essential OpenJDK 25 CLI & Diagnostic Commands

# Compile targeting strict JDK 25 APIs & classfile version 69.0 with all lint warnings
javac --release 25 -Xlint:all -d out src/com/acme/App.java

# Run with fixed heap (eliminates resize pauses), Generational ZGC, and compilation logging
# (Note: On JDK 21-22 pass -XX:+ZGenerational; on JDK 24/25+ -XX:+UseZGC is already generational-only)
java -Xms1g -Xmx1g -XX:+UseZGC -cp out com.acme.App

# Inspect bytecode instructions (-c), constant pool & StackMapTable (-v), including privates (-p)
javap -c -v -p out/com/acme/App.class

# Live production JVM diagnostics (zero-restart) via jcmd
jcmd <pid> VM.version
jcmd <pid> VM.flags
jcmd <pid> Compiler.queue
jcmd <pid> Thread.print -l

# Canonical production CLI entry-point skeleton
public final class BatchRunner {
    private BatchRunner() {}

    public static void main(String[] args) {
        if (args.length < 1) {
            System.err.println("Usage: BatchRunner <job-id>");
            System.exit(2);
        }
        System.out.printf("Running job=%s on JDK %d%n", args[0], Runtime.version().feature());
    }
}

4. Senior Production Pitfalls Checklist

  • Never pass .class to the java launcher: Run java com.acme.App (binary class name), not java com/acme/App.class.
  • Never trust raw System.nanoTime() loops for microbenchmarks: C2 Dead-Code Elimination, On-Stack Replacement quirks, and un-warmed Tier 0 interpretation invalidate manual loops—use JMH with Blackhole.
  • Mitigate cold-start tail latency on autoscaled pods: Warm critical code paths before joining load-balancer rotation, or enable AppCDS (-XX:ArchiveClassesAtExit / -XX:SharedArchiveFile) to cut classloading overhead.
  • Size ReservedCodeCacheSize on large monoliths: If the JIT CodeCache fills up, HotSpot stops compiling new methods and leaves hot paths trapped in the interpreter with sudden CPU regressions.
