Modern Unit Testing: JUnit 5, Parameterized Tests, AssertJ & Mockito — Quick Reference

Modern Unit Testing Reference.

Modern Unit Testing Reference

Library Core Capability Senior Best Practice
JUnit 5 @ParameterizedTest + @CsvSource Consolidates boundary condition matrix testing into clean data rows.
AssertJ Fluent assertions (assertThat) Use extracting() and containsExactly() for collections.
Mockito Mocking external I/O collaborators Never mock records/DTOs; mock only outbound side-effect boundaries.

Canonical Production Snippet: Parameterized Business Rule Test

@ParameterizedTest(name = "Tier {0} with volume {1} gives discount {2}")
@CsvSource({
    "BRONZE, 1000, 0",
    "SILVER, 5000, 250",
    "GOLD,   10000, 1000"
})
void testTierDiscounts(Tier tier, long volume, long expectedDiscount) {
    Order order = new Order(tier, volume); // Real record, not a mock!
    assertThat(FeeEngine.calculateDiscount(order)).isEqualTo(expectedDiscount);
}

Senior Production Pitfalls Checklist

  • Avoid Over-Mocking: Mocking value objects or internal business logic creates brittle tests that pass when software is broken.
  • AssertJ Descriptive Failures: Prefer assertThat(result).as("Order total must match tax rate").isEqualTo(expected) for debugging CI test failures.
  • Don't Test Frameworks: Test your business logic and domain rules, not whether Spring or Hibernate can execute standard getters.
