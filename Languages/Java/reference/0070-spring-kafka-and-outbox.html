Spring Kafka Async CompletableFuture Publishing, Retry/DLT, Transactional Outbox & Kafka Streams — Quick Reference

Spring Kafka & Outbox Reference.

Spring Kafka & Outbox Reference

Pattern / Mechanism Core Technology Senior Production Usage Note
Transactional Outbox Relational DB table + Debezium Solves Dual-Write problem; atomic business state + event persistence.
@RetryableTopic Spring Kafka Non-Blocking Retry Routes failed messages to progressive delay topics; unblocks main partition.
KafkaTemplate Async CompletableFuture<SendResult> Non-blocking offset logging and alerting via whenComplete.

Canonical Production Snippet: Non-Blocking Retry Listener

@RetryableTopic(
    attempts = "4",
    backoff = @Backoff(delay = 1000, multiplier = 2.0),
    dltStrategy = DltStrategy.FAIL_ON_ERROR
)
@KafkaListener(topics = "payments.processed", groupId = "analytics-group")
public void handlePayment(PaymentEvent event) {
    analyticsService.record(event);
}

@DltHandler
public void handleDlt(PaymentEvent event, @Header(KafkaHeaders.RECEIVED_TOPIC) String topic) {
    log.error("Payment {} routed to DLT after failed retries on {}", event.id(), topic);
}

Senior Production Pitfalls Checklist

  • Dual-Write Trap: Never publish directly to Kafka inside a @Transactional method without an Outbox; network failures create permanent state drift.
  • Blocking Retry Lag: Never call Thread.sleep() inside a @KafkaListener; use @RetryableTopic to keep partition consumption moving.
  • Poison Pill Records: Always configure a Dead Letter Topic (DLT) handler so deserialization errors or corrupted payloads do not loop indefinitely.
