Production Date/Time (java.time) & Financial Math (BigDecimal) — Quick Reference

Temporal Types (Instant, ZonedDateTime, Duration) and Financial BigDecimal Operations.

java.time & BigDecimal Reference

Class Semantic Meaning Primary Production Use Case
Instant UTC point on timeline (nanoseconds from Epoch) Audit logs, distributed tracing, database timestamps.
ZonedDateTime Timeline point with full geographic timezone & DST rules Scheduling meetings, calendar events, localized reports.
OffsetDateTime Timeline point with fixed UTC offset (no DST rules) REST APIs (ISO-8601 wire format) and SQL TIMESTAMP WITH TIME ZONE.
Duration Time-based amount (seconds, nanos) Thread timeouts, cache TTLs, latency metrics.
BigDecimal Arbitrary-precision signed decimal numbers Financial transactions, ledger balances, invoicing.

Canonical Production Snippet: Safe Financial Division & Scaling

import java.math.BigDecimal;
import java.math.RoundingMode;

public final class CurrencyOps {
    private static final int FINANCIAL_SCALE = 2;
    private static final RoundingMode ROUNDING = RoundingMode.HALF_EVEN;

    public static BigDecimal divideEqually(BigDecimal totalAmount, int parties) {
        return totalAmount.divide(BigDecimal.valueOf(parties), FINANCIAL_SCALE, ROUNDING);
    }
}

Senior Production Pitfalls Checklist

  • Never new BigDecimal(double): Always use new BigDecimal(String) or BigDecimal.valueOf(double) to avoid binary float precision corruption.
  • Avoid LocalDateTime for Global Events: LocalDateTime has no timezone information; storing it in distributed systems leads to timezone ambiguity.
  • Watch Out for Non-Terminating Division: Always supply a scale and RoundingMode when dividing BigDecimal values to avoid ArithmeticException.
