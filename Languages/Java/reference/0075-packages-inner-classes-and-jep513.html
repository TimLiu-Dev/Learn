Packages, Nested Classes & JEP 513 Flexible Constructors

Quick lookup for Java visibility scopes, initialization order, inner-class memory safety, and Java 25 constructor prologues.

1. Initialization Sequence & Visibility Rules

Construct / ModifierVisibility / Memory Scope2027 Senior Engineering Rule
public / protectedCross-package API / Subclasses + same packageKeep domain internals hidden; expose only narrow service ports or records as public.
package-private (default)Strictly current package (never subpackages)Default choice for internal repositories, mappers, and Spring Modulith module internals.
static vs. non-static inner classZero outer pointer vs. hidden synthetic this$0Always mark nested classes static unless they explicitly require an outer instance reference.
JEP 513 PrologueStatements before super(...) / this(...)Validate parameters and assign own fields before super(...); never read or invoke methods on this.
  1. Class load (once): Superclass static initializers → Subclass static initializers (in textual declaration order).
  2. Per instantiation: Superclass instance fields/blocks → Superclass constructor body.
  3. Java 25 Prologue (JEP 513): Parameter checks & own field writes before super(...); instance methods/reads of this only after super(...).

2. Production Snippets

import module java.base; // JEP 511: imports all packages exported by java.base

public class SecurePort extends BasePort {
    public SecurePort(int port) {
        if (port < 1024 || port > 65535) {
            throw new IllegalArgumentException("Bad port: " + port);
        }
        super(port); // JEP 513 prologue validation before super()
    }

    // Always prefer 'static' nested classes unless outer instance access is required
    public static final class ConfigSnapshot {
        private final int port;
        public ConfigSnapshot(int port) { this.port = port; }
    }
}

Senior Production Pitfalls Checklist

  • Non-Static Inner Class Leaks: Never omit static on nested helper/builder/task classes unless they intentionally need a strong this$0 reference to the enclosing object.
  • Package-Private Boundaries: Remember that com.acme.orders.web is a completely separate package from com.acme.orders; package-private members do not cross into subpackages.
  • JEP 513 Early-Construction Rule: Before super(...) completes, you may validate arguments and assign the subclass's own fields, but you must never read fields or invoke instance methods on this.
