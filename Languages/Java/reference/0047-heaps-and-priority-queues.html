Heaps, PriorityQueues & Two-Heap Quick Reference

Pattern selection matrix, complexity guarantees, copy-ready Java 25 templates, and production pitfalls.

1. Heap Pattern & Complexity Decision Matrix

Problem Archetype Heap Structure Time Extra Space Core Invariant
K-th Largest / Top-K Largest Min-Heap of size K O(N log K) O(K) if (pq.size() > k) pq.poll(); evicts smallest of top K; root is K-th largest.
K-th Smallest / Bottom-K Max-Heap of size K O(N log K) O(K) Comparator.reverseOrder(); root holds K-th smallest for instant eviction.
Merge K Sorted Lists/Streams Min-Heap of size K O(N log K) O(K) Push head of each non-empty stream; on poll(), push polled node's next.
Batch Static Heap Build new PriorityQueue<>(col) O(N) O(N) Bottom-up Floyd heapify() from index (N >>> 1) - 1 down to 0.
Streaming Exact Median Max-Heap (lo) + Min-Heap (hi) O(log N) add / O(1) median O(N) lo.peek() <= hi.peek() and 0 <= lo.size() - hi.size() <= 1.

2. Canonical Copy-Ready Java 25 Templates

Overflow-Safe Custom Comparators

// Min-Heap on record field
record Task(String id, int priority, long deadlineEpochMs) {}

PriorityQueue<Task> taskQueue = new PriorityQueue<>(
    Comparator.comparingInt(Task::priority)
              .thenComparingLong(Task::deadlineEpochMs)
);

// Max-Heap of primitives (boxed) - NEVER write (a, b) -> b - a
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Comparator.reverseOrder());

Two-Heap Streaming Median Template

public final class TwoHeapMedian {
    private final PriorityQueue<Integer> lo = new PriorityQueue<>(Comparator.reverseOrder());
    private final PriorityQueue<Integer> hi = new PriorityQueue<>();

    public void add(int val) {
        lo.offer(val);
        hi.offer(lo.poll());
        if (lo.size() < hi.size()) {
            lo.offer(hi.poll());
        }
    }

    public double median() {
        return lo.size() > hi.size()
            ? lo.peek()
            : ((double) lo.peek() + hi.peek()) / 2.0;
    }
}

3. Senior Production Pitfalls Checklist

  • Never subtract in comparators: Always use Integer.compare(a, b), Long.compare(a, b), or Comparator.comparingInt(...) to prevent two's-complement wrap-around.
  • Never trust PriorityQueue.iterator() order: Enhanced for loops and pq.stream() emit internal level-array order, not sorted priority order. Drain via while (!pq.isEmpty()) pq.poll().
  • Avoid pq.remove(obj) in hot paths: Removal by value scans Object[] linearly in O(N). Use lazy deletion (version stamps or visited arrays) or a TreeSet when arbitrary deletion is required.
  • Guard against NullPointerException: PriorityQueue unconditionally forbids null elements, and unboxing pq.peek() or pq.poll() on an empty queue throws NullPointerException.
  • Watch out for autoboxing GC churn: Under millions of primitive updates per second, consider specialized primitive arrays or Agrona/FastUtil primitive heaps if JFR profiles show heavy Integer.valueOf allocation outside [-128, 127].
