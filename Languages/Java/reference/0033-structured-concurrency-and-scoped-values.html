Structured Concurrency (StructuredTaskScope) & ScopedValue vs ThreadLocal — Quick Reference

StructuredTaskScope and ScopedValue Reference.

Structured Concurrency & Scoped Values Reference

Construct Cancellation / Lifecycle Semantics Primary Production Use Case
StructuredTaskScope.ShutdownOnFailure Cancels all siblings if ANY subtask fails Fan-out aggregations (e.g. User Profile + Orders + Payment).
StructuredTaskScope.ShutdownOnSuccess<T> Cancels all siblings when FIRST subtask succeeds Redundant quoting, querying replicated mirrors, fastest-wins searches.
ScopedValue<T> Immutable, lexically bounded to execution block Request trace IDs, tenant context, security credentials in Virtual Threads.
ThreadLocal<T> (Legacy) Mutable, unbounded lifetime, requires explicit remove() Legacy frameworks (avoid in modern millions-of-virtual-threads systems).

Canonical Production Snippet: Structured Task Aggregation

public InvoiceSummary buildInvoice(long orderId) throws Exception {
    try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
        Supplier<OrderDetails> orderSub = scope.fork(() -> orderService.get(orderId));
        Supplier<TaxDetails> taxSub = scope.fork(() -> taxService.calculate(orderId));

        scope.join();           // Wait for both or first failure
        scope.throwIfFailed();  // Propagate exception if any subtask failed

        return new InvoiceSummary(orderSub.get(), taxSub.get());
    }
}

Senior Production Pitfalls Checklist

  • Forgetting throwIfFailed(): Always invoke scope.throwIfFailed() after scope.join() before calling get() on subtask suppliers.
  • Unbounded ThreadLocal in Virtual Threads: ThreadLocal adds map overhead to every single virtual thread; use ScopedValue to avoid heap bloat.
  • Ensure Try-With-Resources: Always manage StructuredTaskScope inside try-with-resources to guarantee thread termination and socket cleanup on exit.
