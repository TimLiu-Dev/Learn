Fast Linked Lists & LRU Cache Reference.

Fast Linked Lists & LRU Cache Reference

Technique Time / Space Complexity Core Implementation Invariant
Floyd's Cycle Detection O(N) / O(1) space slow = slow.next; fast = fast.next.next; meet if cycle exists.
In-Place List Reversal O(N) / O(1) space Rewire curr.next = prev with forward tracking next pointer.
LRU Cache (HashMap + DLL) O(1) get / O(1) put Sentinel head and tail eliminate null edge-case branches.
LinkedHashMap LRU O(1) operations Constructor: accessOrder=true + override removeEldestEntry.

Canonical Production Snippet: LinkedHashMap LRU Cache

public class SimpleLruCache<K, V> extends LinkedHashMap<K, V> {
    private final int maxCapacity;

    public SimpleLruCache(int maxCapacity) {
        super(maxCapacity, 0.75f, true); // accessOrder = true enables LRU tracking
        this.maxCapacity = maxCapacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > maxCapacity; // Evicts oldest on overflow
    }
}

Senior Production Pitfalls Checklist

  • Null Pointer in Fast Pointer: Always guard while (fast != null && fast.next != null) before checking fast.next.next.
  • Sentinel Node Convenience: In custom Doubly Linked Lists, never allow real nodes to be head or tail; dummy sentinels make node splicing branchless.
  • Memory Leak in Eviction: When evicting an LRU node, remember to delete it from BOTH the doubly linked list AND the HashMap.
