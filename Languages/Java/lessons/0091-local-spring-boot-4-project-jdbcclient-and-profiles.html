Hands-On Local Spring Boot 4.0 Project: Gradle 9, Profiles, compose.yaml & JdbcClient

Bridge single-file browser drills into a real multi-file Gradle 9 + Java 25 + Spring Boot 4.0 backend service inside your workspace—mastering environment profiles, Docker Compose dev wiring, and SQL-first JdbcClient queries mapped directly to records.

1. Anatomy of a Production Spring Boot 4.0 + Gradle 9 Service

Browser drills build muscle memory on isolated classes, but senior backend engineers ship multi-file repositories. A complete runnable starter service lives right inside your workspace at projects/springboot4-order-service/. Open it in IntelliJ IDEA to see how the pieces fit together:

🔗 Android → Spring Boot 4 Bridge: BuildConfig Flavors vs. Spring Profiles & Env Vars
On Android, you compile separate APK variants (debug, staging, release) in app/build.gradle.kts with baked-in BuildConfig constants. Backend services follow the Twelve-Factor rule: Build Once, Deploy Everywhere. You build one immutable JAR and vary URLs, pool sizes, and secrets strictly at runtime via environment variables (${DB_PASSWORD} in application.yml) and SPRING_PROFILES_ACTIVE=local—plus developmentOnly("org.springframework.boot:spring-boot-docker-compose") automatically boots compose.yaml in local dev while stripping itself out of production JARs!

2. Externalized Profiles & Secret Hygiene in application.yml

Never commit real passwords or environment-specific hostnames without environment placeholders, and never activate permissive debug hooks in production without @Profile("local"): 

# ANTI-PATTERN: Hardcoded credentials & missing graceful shutdown
spring:
  datasource:
    url: jdbc:postgresql://prod-db.internal:5432/orders
    password: "SuperSecretProdPassword123!" # Leaked permanently in Git history!

# IDIOMATIC SPRING BOOT 4.0 (application.yml): Env placeholders + Virtual Threads + Graceful Shutdown
spring:
  threads:
    virtual:
      enabled: true
  mvc:
    problemdetails:
      enabled: true
  datasource:
    url: ${DB_URL:jdbc:postgresql://localhost:5432/orders_db}
    username: ${DB_USER:orders_user}
    password: ${DB_PASSWORD} # Mandatory in prod; fails fast at startup if unset!
server:
  shutdown: graceful

3. SQL-First Persistence with Spring Framework 7 JdbcClient

Not every microservice needs Hibernate's stateful EntityManager! When you want 100% transparent SQL, PostgreSQL RETURNING clauses, and zero N+1 or dirty-checking surprises, Spring's JdbcClient binds named parameters cleanly and maps rows directly into immutable Java 25 record constructors: 

// IDIOMATIC JAVA 25 + SPRING 7: Fluent JdbcClient mapped directly to a Java record
@Repository
public class OrderRepository {
    private final JdbcClient jdbcClient;

    public OrderRepository(JdbcClient jdbcClient) {
        this.jdbcClient = jdbcClient;
    }

    public record OrderRow(long id, String customerId, long amountCents, String currency) {}

    @Transactional
    public OrderRow insert(String customerId, long amountCents, String currency) {
        return jdbcClient.sql("""
                INSERT INTO orders (customer_id, amount_cents, currency)
                VALUES (:customerId, :amountCents, :currency)
                RETURNING id, customer_id, amount_cents, currency
                """)
                .param("customerId", customerId)
                .param("amountCents", amountCents)
                .param("currency", currency)
                .query(OrderRow.class) // Auto-maps snake_case columns to record components!
                .single();
    }

    @Transactional(readOnly = true)
    public Optional<OrderRow> findById(long id) {
        return jdbcClient.sql("SELECT id, customer_id, amount_cents, currency FROM orders WHERE id = :id")
                .param("id", id)
                .query(OrderRow.class)
                .optional();
    }
}
