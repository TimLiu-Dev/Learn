Java 25 Compact Sources (JEP 512), Module Imports (JEP 511) & Stream Gatherers (JEP 485)

Eliminate Java scripting boilerplate with JEP 512 instance main & java.lang.IO, bulk-import modules cleanly via JEP 511, and write custom stateful intermediate stream stages using JEP 485 Gatherers.

1. Paving the On-Ramp: JEP 512 Compact Sources & JEP 511 Module Imports

Previously, writing a 5-line utility or prototype in Java required wrapping everything in public class Foo { public static void main(String[] args) { System.out.println(...); } }. Java 25 finalizes JEP 512 (Compact Source Files & Instance Main Methods) alongside JEP 511 (Module Import Declarations):

  • Compact Source File: Omit the enclosing class declaration completely; top-level methods and fields live in an implicit final class launched via void main().
  • java.lang.IO: Automatically imported everywhere in Java 25 for concise console I/O: IO.println(...), IO.print(...), and IO.readln(...).
  • Automatic java.base Imports: Compact source files automatically import all exported packages of java.base (List, Map, Stream, Path, Gatherers). Explicit classes can obtain the exact same ergonomic import in one line with import module java.base;.
// script.java (run directly with: java script.java)
void main() {
    var batches = Stream.of(10, 20, 30, 40, 50)
            .gather(Gatherers.windowFixed(2))
            .toList();
    IO.println("Batches: " + batches); // Output: [[10, 20], [30, 40], [50]]
}

2. Production Trap: Custom Batching Outside Streams vs. JEP 485 Stream Gatherers

Before Java 24/25, Streams offered rich intermediate transforms (map, filter) and rich terminal accumulators (Collector), yet had no extensible intermediate stage. Teams hacked mutable AtomicInteger counters or Collectors.groupingBy(i -> idx.getAndIncrement() / batchSize)—breaking lazy short-circuiting! 

// ANTI-PATTERN: Stateful side-effect hack inside Stream.collect (eager & non-lazy!)
AtomicInteger idx = new AtomicInteger();
Collection<List<String>> chunks = records.stream()
        .collect(Collectors.groupingBy(r -> idx.getAndIncrement() / 500))
        .values(); // Forces full map materialization in memory!

JEP 485 Stream Gatherers (java.util.stream.Gatherer & java.util.stream.Gatherers) introduce composable, lazy intermediate operations directly into Stream.gather(...):

  • Gatherers.windowFixed(n): Emits non-overlapping List<T> batches of size n (with a trailing smaller batch if needed), lazily as downstream demands them.
  • Gatherers.windowSliding(n): Emits overlapping sliding windows of size n ([1,2,3], [2,3,4], ...).
  • Gatherers.scan(init, fn) & Gatherers.fold(init, fn): Lazy prefix-running accumulation and many-to-one state collapse mid-pipeline.
  • Gatherer.ofSequential(...): Build custom stateful intermediate operators (e.g., deduplicating consecutive duplicates cleanly in one pass).
// IDIOMATIC JAVA 25: Lazy batched processing + sliding window + custom Gatherer
import module java.base;

public final class GathererPipelines {
    public static void main(String[] args) {
        var sliding = Stream.of(10, 20, 30, 40)
                .gather(Gatherers.windowSliding(3))
                .toList(); // [[10, 20, 30], [20, 30, 40]]

        var runningTotals = Stream.of(5, 10, 15)
                .gather(Gatherers.scan(() -> 0, Integer::sum))
                .toList(); // [5, 15, 30]

        IO.println("sliding=" + sliding + " running=" + runningTotals);
    }
}
