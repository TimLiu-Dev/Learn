Production Observability: Micrometer, OpenTelemetry Tracing, MDC Logging & Graceful Shutdown

Master the Three Pillars of Observability: OpenTelemetry W3C distributed tracing, SLF4J MDC context propagation, and Kubernetes Actuator health probes.

1. The Three Pillars of Cloud-Native Observability

In microservices architectures running in Kubernetes, traditional unstructured console output (System.out.println) is an anti-pattern. Enterprise systems require three telemetry pillars:

  • Distributed Tracing (OpenTelemetry): Tracks a single user request end-to-end across service boundaries via W3C traceparent headers.
  • Structured Metrics (Micrometer / Prometheus): Low-overhead numerical gauges, counters, and timers measuring throughput, error rates, and JVM heap.
  • Contextual Logging (SLF4J MDC): Attaching dynamic contextual keys (traceId, userId, tenantId) to every log line in JSON format.
// ANTI-PATTERN: Unstructured logging without correlation trace IDs
logger.info("Order processed for user " + userId); // Impossible to correlate across microservices!

2. Under the Hood: W3C TraceContext & MDC Propagation

The W3C TraceContext standard defines the traceparent HTTP header format: 

# W3C traceparent header format:
# version-traceId-parentSpanId-traceFlags
traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01

When dispatching tasks to virtual threads or thread pools, standard SLF4J MDC (which is backed by ThreadLocal) does not propagate automatically: 

// IDIOMATIC JAVA 25: Decorating tasks with captured MDC context
public class MdcContextDecorator {
    public static Runnable wrapWithMdc(Runnable task) {
        Map<String, String> contextMap = MDC.getCopyOfContextMap();
        return () -> {
            Map<String, String> previous = MDC.getCopyOfContextMap();
            if (contextMap != null) {
                MDC.setContextMap(contextMap);
            } else {
                MDC.clear();
            }
            try {
                task.run();
            } finally {
                if (previous != null) {
                    MDC.setContextMap(previous);
                } else {
                    MDC.clear();
                }
            }
        };
    }
}
⚡ Spring Boot 4 OpenTelemetry & Health Package Split
In Spring Boot 4, modular observability arrives via spring-boot-starter-opentelemetry alongside micrometer-tracing-bridge-otel for automatic W3C traceparent propagation across RestClient and WebClient. Custom actuator probes also moved from org.springframework.boot.actuate.health to org.springframework.boot.health.contributor.{Health, HealthIndicator}.

3. Kubernetes Liveness vs Readiness Probes (Spring Boot Actuator)

Never use the same health check endpoint for both Kubernetes liveness and readiness: 

# Kubernetes pod health probe configuration:
# 1. /actuator/health/liveness: Checks if process is deadlocked or stuck (K8s will RESTART container)
# 2. /actuator/health/readiness: Checks if pod is ready to take traffic (DB connected, warm caches)
livenessProbe:
  httpGet:
    path: /actuator/health/liveness
    port: 8080
readinessProbe:
  httpGet:
    path: /actuator/health/readiness
    port: 8080
