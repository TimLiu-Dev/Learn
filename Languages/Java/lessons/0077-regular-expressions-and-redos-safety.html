Regular Expressions (Pattern/Matcher), Named Groups & ReDoS Defense

Avoid hot-loop regex recompilation via static final Pattern, understand matches() vs. find(), extract structured data with named groups, and neutralize catastrophic ReDoS backtracking.

1. Pattern vs. String.matches() & find() vs. matches()

Every call to input.matches(regex) or input.split(regex) compiles a brand-new finite automaton from scratch on every invocation—burning CPU and GC allocations under load. Worse, Java's Matcher.matches() implicitly anchors the entire input string (^...$), whereas Matcher.find() scans for any matching substring: 

// ANTI-PATTERN: Recompiles regex per request + ReDoS catastrophic backtracking hazard!
public boolean isValidTagBad(String raw) {
    // 1. String.matches compiles Pattern on every call!
    // 2. Nested quantifier (a+)+ triggers O(2^n) exponential backtracking on "aaaaaaaaaaaa!"
    return raw.matches("^(a+)+$");
}
⚠ Production Security Hazard: ReDoS (Regular Expression Denial of Service)
Java's java.util.regex engine uses a backtracking NFA. Nested ambiguous quantifiers such as ([a-z]+)+$ or overlapping alternations hang a server thread at 100% CPU on a single 35-character adversarial payload. Defend every untrusted regex with: (1) explicit input max-length bounds, (2) possessive quantifiers (a++) or atomic groups ((?>a+)), and (3) Pattern.compile constants.

2. Idiomatic Java: Named Capturing Groups & Matcher.results()

import java.util.List;
import java.util.regex.Matcher;
import java.util.regex.Pattern;

public final class LogParser {
    // Compiled ONCE at class load; immutable and thread-safe across all threads
    private static final Pattern EVENT_PATTERN = Pattern.compile(
        "level=(?<level>[A-Z]+)\\s+latencyMs=(?<latency>\\d++)"
    );

    public static List<String> extractHighLatency(String logs) {
        return EVENT_PATTERN.matcher(logs).results()
                .filter(mr -> Integer.parseInt(mr.group("latency")) >= 200)
                .map(mr -> mr.group("level") + ":" + mr.group("latency"))
                .toList();
    }
}

Notice three modern idioms: (1) Pattern instances are completely immutable and thread-safe, whereas Matcher instances hold mutable cursor state and must be created per match call; (2) (?<name>...) extracts readable named groups (mr.group("latency")); and (3) \\d++ uses a possessive quantifier so failed numeric scans never backtrack character by character.
