Inheritance, Polymorphism & Dynamic Dispatch

Master dynamic dispatch, vtable mechanics, monomorphic vs megamorphic call sites, and covariant return types.

1. The Fragile Base Class Problem & Dynamic Dispatch

Inheritance creates tight coupling between parents and children. When an internal implementation detail of a parent class changes (such as one method calling another internally), subclasses can break silently without compilation errors: 

// ANTI-PATTERN: The Fragile Base Class Trap (Effective Java Item 18)
public class InstrumentingHashSet<E> extends HashSet<E> {
    private int addCount = 0;

    @Override
    public boolean add(E e) {
        addCount++;
        return super.add(e);
    }

    @Override
    public boolean addAll(Collection<? extends E> c) {
        addCount += c.size();
        return super.addAll(c); // BUG: super.addAll() calls add() internally -> double counts!
    }
}

2. Under the Hood: Virtual Method Tables (vtables) & Inline Caching

In HotSpot, polymorphic method calls compile to the invokevirtual bytecode instruction. HotSpot resolves calls using an internal vtable (Virtual Method Table): 

// Dynamic dispatch mechanics:
// 1. Monomorphic Call Site: If 99% of calls target FastParser, C2 inlines it directly!
// 2. Bimorphic Call Site: If calls target two classes (A or B), C2 emits a bimorphic inline cache:
//    if (klass == TypeA) inlineMethodA(); else if (klass == TypeB) inlineMethodB();
// 3. Megamorphic Call Site: If 3+ implementations occur, C2 falls back to an indirect vtable lookup.
⚡ Why 'final' Matters for C2 Inlining
Marking classes or methods final guarantees to the JIT compiler that no subclasses exist or can be loaded later, enabling unconditional devirtualization and direct inlining without uncommon trap guards.

3. Method Overriding Invariants & Covariant Return Types

When overriding methods in Java:

  1. Visibility can be expanded (e.g. protected → public), but never reduced.
  2. Checked exceptions cannot be added; only subclass exceptions or fewer exceptions can be thrown.
  3. Covariant Returns: The overriding method can return a subtype of the superclass return type.
// IDIOMATIC JAVA 25: Covariant return types eliminating casts
public abstract class EntityBuilder {
    public abstract Entity build();
}

public class OrderBuilder extends EntityBuilder {
    @Override
    public Order build() { // Covariant return: returns Order directly, no casting needed!
        return new Order();
    }
}
