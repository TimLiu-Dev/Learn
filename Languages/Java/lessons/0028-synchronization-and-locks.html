Intrinsic Monitors, ReentrantLock, Conditions & Deadlock Prevention

Master intrinsic monitors, ReentrantLock, multiple Condition variables, spurious wakeups, and deadlock prevention.

1. Intrinsic Monitors vs ReentrantLock

Every Java object has an intrinsic monitor in its header Mark Word. The synchronized keyword provides structured monitor acquisition. However, modern high-concurrency systems frequently require java.util.concurrent.locks.ReentrantLock for non-blocking tryLock(), timed acquisition, and multiple condition variables: 

// ANTI-PATTERN: Indefinite thread blocking on synchronized without timeouts
synchronized (lock) {
    // If another thread hangs or deadlocks holding lock, this thread blocks FOREVER!
    doWork();
}

2. Under the Hood: Condition Variables and Spurious Wakeups

Thread coordination via Condition.await() or Object.wait() releases the lock and suspends the thread until signaled. Because operating system threads can wake up without any thread calling signal() (spurious wakeups), condition checks must always be inside a while loop: 

// PRODUCTION HAZARD: Checking conditions with 'if' instead of 'while'
if (queue.isEmpty()) {
    condition.await(); // BUG: Spurious wakeup leaves queue empty, causing crash below!
}
queue.remove();

// IDIOMATIC JAVA 25: Robust condition wait loop
while (queue.isEmpty()) {
    condition.await(); // Safe: re-evaluates condition upon any wakeup
}
queue.remove();

3. Deadlock Prevention: Consistent Lock Ordering Hierarchy

Deadlocks occur when threads acquire multiple locks in opposite order (Thread 1: A -> B; Thread 2: B -> A). Senior engineers prevent deadlocks by enforcing an immutable global lock order: 

// IDIOMATIC JAVA 25: Deadlock-free account transfer via deterministic lock ordering
public void transfer(Account from, Account to, long cents) {
    Account first = from.id().compareTo(to.id()) < 0 ? from : to;
    Account second = first == from ? to : from;

    first.lock().lock();
    try {
        second.lock().lock();
        try {
            from.debit(cents);
            to.credit(cents);
        } finally {
            second.lock().unlock();
        }
    } finally {
        first.lock().unlock();
    }
}
