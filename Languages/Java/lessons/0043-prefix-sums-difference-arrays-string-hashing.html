Prefix Sums + HashMap, Difference Arrays & String Rolling Hash / KMP

Master O(1) interval queries using Prefix Sums, O(1) batch range updates using Difference Arrays, and Polynomial Rolling Hash algorithms.

1. The Naive Range Scan vs Prefix Sums

In financial ledgers and analytical aggregations, querying the sum of values over arbitrary intervals [L, R] using naive iteration requires O(N) time per query. If Q queries arrive, overall complexity degrades to O(Q * N): 

// ANTI-PATTERN: Naive O(N) range queries causing latency timeouts
public long queryRangeSum(long[] array, int left, int right) {
    long sum = 0;
    for (int i = left; i <= right; i++) {
        sum += array[i]; // Degrades to O(N) for every single incoming query
    }
    return sum;
}

By precomputing a Prefix Sum Array in O(N), any range query is computed in strictly O(1) time using subtraction: 

// IDIOMATIC JAVA 25: O(1) Prefix Sum Array
public class PrefixSumCalculator {
    private final long[] prefix;

    public PrefixSumCalculator(long[] nums) {
        prefix = new long[nums.length + 1];
        for (int i = 0; i < nums.length; i++) {
            prefix[i + 1] = prefix[i] + nums[i];
        }
    }

    public long query(int left, int right) {
        return prefix[right + 1] - prefix[left]; // Exact O(1) query
    }
}

2. Difference Arrays for O(1) Range Updates

When multiple transactions apply batch increments across intervals [L, R], updating each index costs O(N). A Difference Array records deltas at boundaries in O(1) time, recovering final values via a single prefix sum sweep at the end: 

// IDIOMATIC JAVA 25: Difference Array for O(1) interval updates
public class RangeDeltaTracker {
    private final int[] diff;

    public RangeDeltaTracker(int n) {
        diff = new int[n + 1];
    }

    public void addRange(int left, int right, int delta) {
        diff[left] += delta;
        if (right + 1 < diff.length) {
            diff[right + 1] -= delta;
        }
    }

    public int[] buildResult(int n) {
        int[] res = new int[n];
        int current = 0;
        for (int i = 0; i < n; i++) {
            current += diff[i];
            res[i] = current;
        }
        return res;
    }
}

3. Under the Hood: Polynomial Rolling Hash (Rabin-Karp)

To compare substrings of length M in O(1) time without character-by-character scanning, we compute polynomial rolling hashes modulo a large prime (e.g., 109 + 7): 

// Rolling hash transition: O(1) sliding window hash update
// hash = ((hash - highChar * power) * base + newChar) % MOD
// Always add MOD before modulo in Java to avoid negative remainders!
long updatedHash = ((currentHash - (oldChar * power) % MOD + MOD) * BASE + newChar) % MOD;
⚠ The Java Modulo Operator Trap
In Java, the % operator computes remainder, NOT mathematical modulo! For negative numbers, -5 % 10 = -5. Always normalize negative intermediate values: (val % MOD + MOD) % MOD.
