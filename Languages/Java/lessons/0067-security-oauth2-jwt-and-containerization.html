Spring Security 7 Filter Chains, OAuth2 Resource Server (JWT), @PreAuthorize & Layered Docker

Master Spring Security 7 component filter chains, OAuth2 JWT stateless resource servers, and layered Dockerfiles.

1. Spring Security 7 Component-Based Configuration

Spring Security 7 (Spring Boot 4 / Servlet 6.1) preserves component-based filter configuration declared via SecurityFilterChain beans while removing deprecated Security 6 shims: 

// IDIOMATIC JAVA 25: Component-Based SecurityFilterChain
@Configuration
@EnableWebSecurity
@EnableMethodSecurity // Enables @PreAuthorize on methods!
public class SecurityConfig {
    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        return http
            .csrf(csrf -> csrf.disable()) // Stateless REST API: CSRF disabled!
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/actuator/health", "/public/**").permitAll()
                .anyRequest().authenticated()
            )
            .oauth2ResourceServer(oauth2 -> oauth2.jwt(Customizer.withDefaults()))
            .build();
    }
}

2. Method Security with @PreAuthorize

Fine-grained authorization should be enforced at the service or controller method boundary using @PreAuthorize expressions: 

// IDIOMATIC JAVA 25: Method-level RBAC authorization
@PreAuthorize("hasRole('ADMIN') or #userId == authentication.name")
@DeleteMapping("/users/{userId}")
public void deleteUser(@PathVariable String userId) {
    userService.delete(userId);
}

3. Production Multi-Stage Dockerfile with Layered Jars

Shipping a single fat JAR causes every minor code commit to invalidate Docker layer caches, re-uploading hundreds of megabytes of third-party dependencies. Spring Boot Layered Jars splits dependencies, Spring loader, and application classes into separate Docker layers: 

# IDIOMATIC JAVA 25: High-Performance Multi-Stage Dockerfile
FROM eclipse-temurin:25-jre-alpine as builder
WORKDIR /builder
COPY target/*.jar app.jar
RUN java -Djarmode=layertools -jar app.jar extract

FROM eclipse-temurin:25-jre-alpine
RUN addgroup -S appgroup && adduser -S appuser -G appgroup
USER appuser
WORKDIR /application
COPY --from=builder /builder/dependencies/ ./
COPY --from=builder /builder/spring-boot-loader/ ./
COPY --from=builder /builder/snapshot-dependencies/ ./
COPY --from=builder /builder/application/ ./
ENTRYPOINT ["java", "org.springframework.boot.loader.launch.JarLauncher"]
