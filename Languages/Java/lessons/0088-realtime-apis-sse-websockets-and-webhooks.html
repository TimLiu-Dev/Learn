Real-Time & Event-Driven HTTP APIs: SSE (SseEmitter), WebSockets/STOMP & Signed Webhooks

Replace wasteful client polling with Server-Sent Events (SSE) for LLM/live feeds, WebSockets/STOMP for bidirectional chat/collaboration, and HMAC-verified, replay-safe Webhooks for asynchronous partner integrations.

1. Choosing Polling vs. SSE vs. WebSockets vs. Webhooks

SOAP (XML/WSDL) is legacy-only in 2027 (encountered only when integrating older banking/ERP systems), and full HATEOAS (Richardson Level 3) is rarely needed outside specialized hypermedia APIs. 2. Production SseEmitter Streaming & Memory-Leak Prevention

With Java 25 Virtual Threads enabled, Spring MVC's SseEmitter scales to tens of thousands of open streams cleanly—for example, streaming Spring AI tokens or order-status events. The #1 bug is registering an SseEmitter in a collection without removing it on disconnect, timeout, or broken-pipe I/O errors: 

// IDIOMATIC SPRING BOOT 4: Lifecycle-Safe SseEmitter + Heartbeat Cleanup
@RestController
@RequestMapping("/api/events")
public class OrderStreamController {
    private final Map<String, Set<SseEmitter>> subscribers = new ConcurrentHashMap<>();

    @GetMapping(path = "/{tenantId}", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public SseEmitter subscribe(@PathVariable String tenantId) {
        SseEmitter emitter = new SseEmitter(Duration.ofMinutes(5).toMillis());
        Set<SseEmitter> set = subscribers.computeIfAbsent(tenantId, k -> ConcurrentHashMap.newKeySet());
        set.add(emitter);

        Runnable cleanup = () -> set.remove(emitter);
        emitter.onCompletion(cleanup);
        emitter.onTimeout(() -> { cleanup.run(); emitter.complete(); });
        emitter.onError(ex -> cleanup.run());
        return emitter;
    }
}

When full-duplex browser communication is required (such as collaborative editing or live chat), configure WebSockets with an external STOMP broker relay rather than an in-memory single-pod broker: 

// ANTI-PATTERN: config.enableSimpleBroker("/topic") -> drops messages across multiple pods!
// IDIOMATIC MULTI-POD WEBSOCKET/STOMP: External Broker Relay (RabbitMQ / ActiveMQ)
@Configuration
@EnableWebSocketMessageBroker
public class WebSocketRelayConfig implements WebSocketMessageBrokerConfigurer {
    @Override
    public void configureMessageBroker(MessageBrokerRegistry registry) {
        registry.setApplicationDestinationPrefixes("/app");
        registry.enableStompBrokerRelay("/topic", "/queue")
                .setRelayHost("stomp-broker.internal")
                .setRelayPort(61613);
    }
}

3. Inbound Webhook Security: Raw Body, HMAC-SHA256 & Anti-Replay

Never trust an unauthenticated webhook POST, and never verify HMAC signatures against a re-serialized Java DTO (whitespace or key-ordering differences break the MAC!). Always verify against the exact raw UTF-8 request bytes, check a strict timestamp window (e.g., ≤ 300 seconds), compare digests with constant-time MessageDigest.isEqual (Lesson 0079), and deduplicate by event ID: 

// ANTI-PATTERN: Re-serializing parsed DTO + Arrays.equals (whitespace mismatch + timing leak!)
// boolean ok = Arrays.equals(hmac(jsonMapper.writeValueAsBytes(dto)), headerSig);

// IDIOMATIC JAVA 25: Raw-Body HMAC-SHA256 + Anti-Replay Window + Constant-Time Check
public static boolean verifyWebhook(byte[] rawBody, long timestampSec, String signatureHex,
                                    String secret, long nowEpochSec) throws Exception {
    if (Math.abs(nowEpochSec - timestampSec) > 300) {
        return false; // Reject stale replay attacks!
    }
    String signedPayload = timestampSec + "." + new String(rawBody, StandardCharsets.UTF_8);
    Mac mac = Mac.getInstance("HmacSHA256");
    mac.init(new SecretKeySpec(secret.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
    byte[] expected = mac.doFinal(signedPayload.getBytes(StandardCharsets.UTF_8));
    byte[] provided = HexFormat.of().parseHex(signatureHex);
    return MessageDigest.isEqual(expected, provided); // Constant-time compare!
}
