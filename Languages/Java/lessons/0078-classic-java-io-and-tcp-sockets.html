Classic java.io Decorator Streams, UTF-8 Readers & Raw TCP Sockets

Understand Java's classic Decorator I/O hierarchy (bytes vs. characters), prevent corrupted encodings and socket hangs, and see why Virtual Threads revitalize simple blocking Socket code.

1. The java.io Decorator Matrix: Bytes vs. Characters

Before NIO.2 (Path, ByteBuffer), Java built I/O around composable Decorator streams separating raw binary byte streams from text character streams:

LayerRaw Binary (byte[])Text Characters (char[], UTF-8)
Source / SinkInputStream / OutputStream (FileInputStream, Socket.getInputStream())Reader / Writer (bridge via InputStreamReader / OutputStreamWriter)
Buffering DecoratorBufferedInputStream / BufferedOutputStreamBufferedReader (readLine()) / BufferedWriter
Structured FormattingDataInputStream / DataOutputStream (primitives)PrintWriter (always pass StandardCharsets.UTF_8!)

Notice why BufferedReader wraps an InputStreamReader wrapping a raw InputStream: without buffering, every single .read() invokes an OS read(2) syscall for 1 byte or 1 character; wrapping with BufferedReader reads an 8 KiB chunk once and decodes cleanly in memory.

2. Production Trap: Unbounded Socket.read() Hangs & Leaky Wrappers

Classic TCP ServerSocket and Socket calls block cleanly—and with Java 25 Virtual Threads (Thread.ofVirtual().start(...)), one-thread-per-connection blocking TCP code scales to tens of thousands of sockets effortlessly. Yet two classic bugs still bring down production socket servers: 

// ANTI-PATTERN: Missing read timeout, legacy charset default & unclosed socket on error
public void serveUnsafe(ServerSocket server) throws IOException {
    Socket client = server.accept(); // BUG 1: No try-with-resources! Leaks file descriptors!
    // BUG 2: No client.setSoTimeout(3000) -> slowloris client hangs connection forever!
    // BUG 3: Omitting charset on InputStreamReader risks encoding drift on older JDKs
    BufferedReader in = new BufferedReader(new InputStreamReader(client.getInputStream()));
    String line = in.readLine();
    System.out.println("Received: " + line);
}

Always bind try (server; client) with explicit socket.setSoTimeout(3_000), pass StandardCharsets.UTF_8 explicitly at every byte-to-character bridge (InputStreamReader, OutputStreamWriter, PrintWriter), and cap line/frame sizes on untrusted network sockets to prevent OutOfMemoryError on missing newlines. 

// IDIOMATIC JAVA 25: Try-with-resources + explicit UTF-8 + Virtual-Thread framing
import java.io.*;
import java.net.Socket;
import java.nio.charset.StandardCharsets;

public final class TcpLineProtocol {
    public static void handleClient(Socket socket) throws IOException {
        socket.setSoTimeout(3_000); // Fail fast on silent peers (SO_TIMEOUT)
        try (socket;
             var in = new BufferedReader(new InputStreamReader(socket.getInputStream(), StandardCharsets.UTF_8));
             var out = new BufferedWriter(new OutputStreamWriter(socket.getOutputStream(), StandardCharsets.UTF_8))) {
            String request = in.readLine();
            if (request == null || request.length() > 4096) return;
            out.write("ACK:" + request + "\n");
            out.flush(); // Critical: flush BufferedWriter before socket closes or awaits next line!
        }
    }
}
