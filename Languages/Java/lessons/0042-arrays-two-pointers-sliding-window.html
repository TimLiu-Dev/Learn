Arrays, Two Pointers & Dynamic Sliding Window

Master two pointers inward scans, fast/slow pointers, and dynamic sliding window amortized O(N) proofs.

1. The Two-Pointer Paradigm: Inward Scanning vs Fast/Slow

The Two-Pointer technique reduces brute-force O(N^2) search spaces into linear O(N) scans by leveraging problem invariants:

  • Inward Scanning (Left & Right): On sorted arrays, adjust pointers inward based on comparison (e.g., Two Sum II, Container With Most Water).
  • Fast and Slow Pointers: Detect cycles or partition arrays in-place (e.g., Remove Duplicates, Dutch National Flag).
// ANTI-PATTERN: Brute-force O(N^2) pair search on sorted array
for (int i = 0; i < nums.length; i++) {
    for (int j = i + 1; j < nums.length; j++) {
        if (nums[i] + nums[j] == target) return new int[]{i, j}; // O(N^2) CPU waste!
    }
}

2. Under the Hood: Dynamic Sliding Window Invariants

Sliding window algorithms maintain a window [left, right] representing an active valid state. As right expands the window, a while loop shrinks left whenever an invariant is violated: 

// UNDER THE HOOD: Dynamic window for Longest Substring Without Repeating Characters
int left = 0, maxLen = 0;
Set<Character> seen = new HashSet<>();
for (int right = 0; right < s.length(); right++) {
    while (seen.contains(s.charAt(right))) {
        seen.remove(s.charAt(left++)); // Shrink until valid
    }
    seen.add(s.charAt(right));
    maxLen = Math.max(maxLen, right - left + 1); // Maintain optimal metric
}

3. Amortized Analysis: Why Nested Loops Are O(N)

Although sliding window has a nested while loop inside a for loop, its time complexity is strictly O(N): 

// IDIOMATIC JAVA 21: O(N) Amortized Complexity Analysis
// Each index enters the window via right++ exactly once (N operations).
// Each index exits the window via left++ at most once (N operations).
// Total window pointer movements: 2N operations -> O(N) time complexity!
