ClassLoaders, MethodHandles, Reflection & Custom Runtime Annotations

Master classloader hierarchy, JPMS encapsulation, MethodHandles vs reflection, and custom runtime annotations.

1. The ClassLoader Delegation Model & JPMS Encapsulation

The JVM loads classes via a hierarchical delegation tree: Bootstrap ClassLoader (JDK runtime internals), Platform ClassLoader (Java SE platform modules), and Application / System ClassLoader (application classpath/modulepath). Under the standard parent-first delegation model, a classloader delegates loading to its parent before scanning its own repositories: 

// ANTI-PATTERN: Breaking encapsulation via reflective setAccessible in Java 17+
Field field = String.class.getDeclaredField("value");
field.setAccessible(true); // CRASH: InaccessibleObjectException under strong JPMS encapsulation!

2. Under the Hood: Reflection vs MethodHandles Performance

Standard java.lang.reflect.Method.invoke() performs dynamic permission and argument checks on every invocation, inhibiting JIT inlining. Java 7 introduced java.lang.invoke.MethodHandles, providing type-safe, direct method references. When stored in static final constants, MethodHandle.invokeExact() can be completely inlined into native CPU instructions by C2: 

// UNDER THE HOOD: High-performance invocation via MethodHandles
public class FastAccessor {
    private static final MethodHandle GET_NAME;
    static {
        try {
            MethodHandles.Lookup lookup = MethodHandles.lookup();
            GET_NAME = lookup.findVirtual(User.class, "name", MethodType.methodType(String.class));
        } catch (ReflectiveOperationException e) {
            throw new ExceptionInInitializerError(e);
        }
    }

    public static String readName(User u) throws Throwable {
        return (String) GET_NAME.invokeExact(u); // Inlines directly like direct code!
    }
}

3. Custom Runtime Annotations & Metadata Processing

Senior enterprise architectures (Spring, Quarkus, Jackson) drive behaviors via custom annotations. Annotations intended for runtime inspection require @Retention(RetentionPolicy.RUNTIME): 

// IDIOMATIC JAVA 21: Custom runtime rate-limiting annotation
@Retention(RetentionPolicy.RUNTIME)
@Target({ElementType.METHOD, ElementType.TYPE})
public @interface RateLimited {
    int maxRequests() default 100;
    int windowSeconds() default 60;
}
