Spring Boot 3 Auto-Configuration (@Conditional) & Record Properties

Master Spring Boot 3 auto-configuration, conditional bean registration, and record properties.

1. The Spring Boot 3 Auto-Configuration Engine

Spring Boot's opinionated defaults are driven by Auto-Configuration classes conditioned on the classpath and environment. In Spring Boot 3, auto-configuration classes are registered in META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports (replacing legacy spring.factories): 

// UNDER THE HOOD: Auto-configuration with conditional guards
@AutoConfiguration
@ConditionalOnClass(DataSource.class)
@ConditionalOnMissingBean(DataSource.class)
public class DataSourceAutoConfiguration {
    @Bean
    public DataSource dataSource(DataSourceProperties properties) {
        return properties.initializeDataSourceBuilder().build();
    }
}

2. Type-Safe Configuration Properties with Java Records

In modern Spring Boot 3, configuration properties should be declared as Java Records. Records provide immutable, thread-safe configuration with zero boilerplate getters/setters, combined with Jakarta Bean Validation: 

// IDIOMATIC JAVA 21: Validated record configuration properties
@Validated
@ConfigurationProperties(prefix = "app.payment")
public record PaymentProperties(
    @NotBlank String gatewayUrl,
    @Positive int connectTimeoutMs,
    @Min(1) @Max(5) int maxRetries
) {}

3. The ConditionalOnMissingBean Customization Guarantee

Auto-configuration beans must always be annotated with @ConditionalOnMissingBean. This allows application developers to define custom beans that gracefully override framework defaults without throwing BeanDefinitionOverrideException: 

// IDIOMATIC JAVA 21: Graceful user override pattern
@Bean
@ConditionalOnMissingBean
public TokenParser defaultTokenParser() {
    return new StandardTokenParser(); // Replaced automatically if user declares custom TokenParser!
}
