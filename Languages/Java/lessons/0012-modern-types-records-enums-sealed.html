Modern Algebraic Types: Records, Enums & Sealed Classes

Master Java records, state machine enums, and sealed classes with permits for exhaustive domain modeling.

1. The Modern Java Type Revolution

Modern Java eliminates verbose boilerplate (Lombok, manual getters/setters) and error-prone open class hierarchies with three modern constructs:

  • Records (Java 16+ JEP 395): Immutable transparent data carriers with auto-generated accessors, equals, hashCode, and toString.
  • Rich Enums: Type-safe singleton constants with instance fields, constructors, and constant-specific method behavior.
  • Sealed Types (Java 17+ JEP 409): Restricting inheritance to an explicitly permitted set of subtypes.
// ANTI-PATTERN: Mutable JavaBean with boilerplate
public class LegacyUser {
    private String id;
    private String email;
    // 50 lines of getters, setters, equals, hashCode, toString...
}

// IDIOMATIC JAVA 21: One-line transparent immutable data carrier
public record ModernUser(String id, String email) {}

2. Sealed Classes & Interfaces: Exhaustive Control

In traditional Java, an interface could be implemented by any arbitrary class anywhere in the world. sealed interfaces restrict implementation to a closed set using the permits clause: 

// IDIOMATIC JAVA 21: Sealed Algebraic Data Type
public sealed interface OrderCommand permits CreateOrder, CancelOrder, ShipOrder {}

public record CreateOrder(UUID id, BigDecimal amount) implements OrderCommand {}
public record CancelOrder(UUID id, String reason) implements OrderCommand {}
public record ShipOrder(UUID id, String trackingNumber) implements OrderCommand {}
⚡ Sealed Subtype Requirements
Every class permitted by a sealed type must reside in the same module (or same package if unnamed) and MUST explicitly declare one of three modifiers: final, sealed, or non-sealed.

3. Rich Enums as State Machines with Constant-Specific Behavior

Java enums can declare abstract methods that each constant implements individually, creating elegant, allocation-free state machines: 

// IDIOMATIC JAVA 21: Enum with constant-specific business logic
public enum OrderStatus {
    PENDING {
        @Override public OrderStatus next() { return PROCESSING; }
    },
    PROCESSING {
        @Override public OrderStatus next() { return COMPLETED; }
    },
    COMPLETED {
        @Override public OrderStatus next() { return COMPLETED; }
    };

    public abstract OrderStatus next();
}
