Servlet Containers, Filter Chains, DispatcherServlet & Tomcat Virtual Threads

Master Servlet 6.0 filter chains, DispatcherServlet architecture, and Spring Boot 3 Tomcat virtual threads.

1. The Jakarta Servlet 6.0 & DispatcherServlet Architecture

In Spring MVC, incoming HTTP requests pass through an ordered pipeline of Jakarta Servlet Filters before entering the central front-controller: DispatcherServlet. The DispatcherServlet consults HandlerMapping to identify target controller endpoints and delegates execution via HandlerAdapter: 

// UNDER THE HOOD: Servlet Filter Chain Execution
public class AuditLoggingFilter extends OncePerRequestFilter {
    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res, FilterChain chain)
            throws ServletException, IOException {
        long start = System.currentTimeMillis();
        try {
            chain.doFilter(req, res); // Passes request down the filter chain!
        } finally {
            long duration = System.currentTimeMillis() - start;
            res.setHeader("X-Response-Time-Millis", String.valueOf(duration));
        }
    }
}

2. Embedded Tomcat with Java 21 Virtual Threads

Historically, embedded Tomcat required a fixed thread pool (default 200 platform threads). In Spring Boot 3.2+ running on Java 21, enabling virtual threads dispatches one virtual thread per incoming HTTP request: 

// IDIOMATIC JAVA 21: application.properties
spring.threads.virtual.enabled=true
# Tomcat allocates a virtual thread for each request; 10,000 concurrent requests cost ~10MB RAM!

3. ThreadLocal Recycling Hazards in Virtual Thread Servlets

Platform thread pools recycle worker threads, making ThreadLocal.remove() mandatory to prevent data leaks between requests. With virtual threads, while threads terminate upon request completion, storing large payloads in ThreadLocal across millions of active requests can exhaust heap memory. Senior systems prefer ScopedValue: 

// ANTI-PATTERN: Heavy ThreadLocal allocations in high-volume virtual threads
public static final ThreadLocal<byte[]> BUFFER = new ThreadLocal<>(); // Memory bloat under 50k VTs!

// IDIOMATIC JAVA 21: Immutable ScopedValue context
public static final ScopedValue<SecurityContext> CTX = ScopedValue.newInstance();
