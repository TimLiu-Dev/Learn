Classes, Heap Allocation & Object Lifecycle

Master HotSpot object headers (Mark Word, Klass pointer), constructor initialization sequence, and Java record compact constructors.

1. The Object Header: Mark Word & Klass Pointer

Every object allocated on the Java heap carries an Object Header consisting of:

  • Mark Word (8 bytes): Identity hash code, GC age bits (4 bits = max age 15 before Tenuring), locking state (biased, thin, fat monitor), and GC flags.
  • Klass Word (4 bytes with CompressedClassPointers): Points to the class metadata in Metaspace.
  • Array Length (4 bytes): Present only on array instances.
// ANTI-PATTERN: Massive memory bloat from wrapper object overhead
// Integer object: 8 bytes (mark) + 4 bytes (klass) + 4 bytes (int) = 16 bytes!
// Primitive int: exactly 4 bytes. Storing 10M Integers consumes 160MB vs 40MB!

2. Constructor Chaining & Object Initialization Order

Object initialization executes in a strict deterministic sequence:

  1. Static initializers and static fields of parent, then child.
  2. Instance field initializers and instance blocks of parent.
  3. Parent class constructor body.
  4. Instance field initializers and instance blocks of child.
  5. Child class constructor body.
// PRODUCTION TRAP: Calling overridable method in constructor
public class SuperClass {
    public SuperClass() {
        init(); // DANGEROUS! Child fields not yet initialized!
    }
    public void init() {}
}

public class SubClass extends SuperClass {
    private String name = "Default";
    @Override
    public void init() {
        System.out.println(name.toUpperCase()); // CRASH! 'name' is still null here!
    }
}
⚠ Never Call Overridable Methods in Constructors
When a superclass constructor invokes an overridden method, the child's implementation executes before the child's instance field initializers have run, leading to subtle NullPointerException crashes.

3. Modern Java 21 Record Compact Constructors

Java records eliminate constructor boilerplate while providing compact constructors for domain validation without re-assigning fields: 

// IDIOMATIC JAVA 21: Record with compact constructor validation
public record OrderId(String value) {
    public OrderId {
        Objects.requireNonNull(value, "OrderId cannot be null");
        if (value.isBlank()) {
            throw new IllegalArgumentException("OrderId cannot be blank");
        }
        value = value.trim().toUpperCase(); // Modifies parameter before implicit field assignment!
    }
}
