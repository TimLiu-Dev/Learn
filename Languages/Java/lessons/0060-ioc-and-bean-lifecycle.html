Inversion of Control (IoC), Bean Scopes & BeanPostProcessor Internals

Master Spring IoC container architecture, BeanPostProcessor internals, and constructor injection.

1. The Spring IoC Container Lifecycle

The Spring ApplicationContext manages bean creation through a deterministic lifecycle:

  1. Bean Definition Loading: Scans component annotations and registers BeanDefinition metadata.
  2. BeanFactoryPostProcessor: Modifies bean definitions prior to instantiation (e.g. PropertySourcesPlaceholderConfigurer).
  3. Instantiation & Constructor Injection: Instantiates beans using constructors.
  4. BeanPostProcessor (Before): Inspects instances before initialization (e.g., @PostConstruct).
  5. Initialization: Calls InitializingBean.afterPropertiesSet() or custom init-methods.
  6. BeanPostProcessor (After): Wraps beans in AOP proxies (@Transactional, @Async).
// UNDER THE HOOD: BeanPostProcessor wrapping beans in proxies
public class TracingBPP implements BeanPostProcessor {
    @Override
    public Object postProcessAfterInitialization(Object bean, String beanName) {
        if (bean.getClass().isAnnotationPresent(Traced.class)) {
            return createProxy(bean); // Replaces raw bean with dynamic proxy!
        }
        return bean;
    }
}

2. Constructor Injection vs Field Injection Anti-Pattern

Annotating fields with @Autowired is an enterprise anti-pattern: it allows circular dependencies, permits uninitialized null fields, and prevents unit testing without reflection libraries: 

// ANTI-PATTERN: Field Injection
@Service
public class OrderService {
    @Autowired
    private PaymentClient paymentClient; // BRITTLE: Cannot be final, breaks new OrderService() in tests!
}

// IDIOMATIC JAVA 21: Constructor Injection with immutable final fields
@Service
public class OrderService {
    private final PaymentClient paymentClient; // Immutable, explicit, testable!

    public OrderService(PaymentClient paymentClient) {
        this.paymentClient = Objects.requireNonNull(paymentClient);
    }
}

3. The Prototype-in-Singleton Injection Trap

When a prototype bean (@Scope("prototype")) is injected into a singleton bean, Spring injects it only once at startup. The singleton retains that single instance forever, defeating the prototype scope: 

// IDIOMATIC JAVA 21: ObjectProvider for on-demand prototype retrieval
@Service
public class ReportGenerator {
    private final ObjectProvider<ReportTask> taskProvider;
    public ReportGenerator(ObjectProvider<ReportTask> provider) { this.taskProvider = provider; }

    public void generate() {
        ReportTask task = taskProvider.getObject(); // Instantiates fresh prototype instance!
        task.run();
    }
}
