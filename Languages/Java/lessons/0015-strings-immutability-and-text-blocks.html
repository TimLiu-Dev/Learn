Strings, Compact Strings, String Pool & Text Blocks

Master Compact Strings memory layout, Java 15+ Text Blocks, and modern StringConcatFactory concatenation.

1. The String Constant Pool & Compact Strings

In OpenJDK HotSpot, string literals are interned into the String Constant Pool (managed in native heap memory). Since Java 9, Compact Strings (JEP 254) encodes character arrays as byte[] instead of char[], using a 1-byte coder flag:

  • LATIN1 (0): 1 byte per character for ISO-8859-1 strings, halving memory consumption for ASCII strings!
  • UTF16 (1): 2 bytes per character for strings with multibyte characters (emojis, CJK).
// ANTI-PATTERN: Forced manual interning or redundant new String()
String bad = new String("literal"); // Allocates unnecessary heap wrapper!
String pooled = "literal";          // Reuses canonical String Constant Pool reference

2. Java 15+ Text Blocks (JEP 378)

Text Blocks (triple quotes """) eliminate tedious string concatenation and escape sequences for multi-line JSON, SQL, and HTML: 

// IDIOMATIC JAVA 25: Multi-line SQL with automatic indentation stripping
String query = """
    SELECT id, email, status
    FROM users
    WHERE status = 'ACTIVE'
    ORDER BY created_at DESC;
    """;
// Under the hood: compiler automatically strips common incidental leading whitespace!
⚡ Text Block Escape Sequences
Use \s to preserve trailing whitespace at the end of a line (which is normally stripped by default), and \ (trailing backslash) to suppress the newline character.

3. Under the Hood: StringConcatFactory & StringBuilder

In modern Java, string concatenation using the + operator does not allocate multiple intermediate StringBuilder objects. Since Java 9, javac emits an invokedynamic instruction to StringConcatFactory (JEP 280): 

// javac emits invokedynamic makeConcatWithConstants
String result = "User:" + id + ":" + role;
// Under the hood: single exact-size byte[] buffer allocation in one pass!
// In tight loops, however, manual StringBuilder sizing is still required:
StringBuilder sb = new StringBuilder(estimatedSize);
