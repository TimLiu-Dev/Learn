Threads, Happens-Before & The Java Memory Model (JMM)

Master the Java Memory Model, happens-before rules, volatile memory barriers, and atomic CAS operations.

1. The Java Memory Model & Hardware Reality

Modern multi-core processors have independent L1/L2 caches and write buffers. Without synchronization, CPU cores cache field values locally and reorder instructions. The Java Memory Model (JMM) defines formal semantics governing when a write by one thread becomes visible to a read by another thread. 

// ANTI-PATTERN: Loop flag without volatile or memory barrier
class Worker implements Runnable {
    private boolean stop = false; // BUG: Thread may cache 'stop' in L1/L2 cache forever!
    public void run() {
        while (!stop) { /* Busy loop never observes stop = true! */ }
    }
    public void stopRunning() { stop = true; }
}

2. Under the Hood: Happens-Before Relationships

A happens-before relationship guarantees that memory writes by action A are visible to action B. Core happens-before rules include:

  • Program Order Rule: Each action in a thread happens-before every subsequent action in that thread.
  • Volatile Variable Rule: A write to a volatile field happens-before every subsequent read of that field.
  • Monitor Lock Rule: An unlock on a monitor happens-before every subsequent lock on that same monitor.
  • Thread Start Rule: A call to Thread.start() happens-before any action in the started thread.
// UNDER THE HOOD: Volatile read and write memory barriers
volatile boolean flag = false;
int data = 0;

// Thread 1:
data = 42;         // Plain write
flag = true;       // StoreStore + StoreLoad barrier; data write is visible!

// Thread 2:
if (flag) {        // LoadLoad + LoadStore barrier
    assert data == 42; // Guaranteed true! Happens-before established.
}

3. Atomicity vs Visibility: The volatile Counter Trap

Marking a variable volatile guarantees visibility and prevents instruction reordering, but it does not guarantee atomicity for compound operations: 

// ANTI-PATTERN: volatile does NOT make compound operations atomic
volatile int counter = 0;
counter++; // EXPANDS TO: 1. read counter -> 2. add 1 -> 3. write counter (RACE CONDITION!)

// IDIOMATIC JAVA 21: Hardware atomic CAS operation
AtomicInteger counter = new AtomicInteger();
counter.incrementAndGet(); // Atomic compare-and-swap (CAS) via CPU LOCK instruction
