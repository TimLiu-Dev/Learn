Prefix Tries & Pruned Backtracking (Word Search II)

Master array-backed Prefix Tries, simultaneous Trie grid pruning, and in-place backtracking.

1. The Trie Architecture: Array vs HashMap Nodes

A Trie (Prefix Tree) organizes words by character transitions. In high-performance algorithmic searches over standard English lowercase alphabets, backing children with Node[26] arrays is 5-10x faster than Map<Character, Node> due to contiguous memory indexing and zero object boxing: 

// ANTI-PATTERN: HashMap-backed Trie nodes in tight loops
class SlowTrieNode {
    Map<Character, SlowTrieNode> children = new HashMap<>(); // Boxing + hashing overhead!
}

// IDIOMATIC JAVA 25: Primitive array offset indexing
class FastTrieNode {
    FastTrieNode[] children = new FastTrieNode[26]; // Direct memory offset c - 'a'
    boolean isWord = false;
}

2. Under the Hood: Pruned Backtracking (Word Search II)

Searching a 2D grid for a dictionary of words using naive DFS explores 4^L paths per word. By traversing the grid and the Prefix Trie simultaneously, search paths that do not form valid prefixes in the Trie can be pruned immediately, collapsing the exponential search space: 

// UNDER THE HOOD: Prefix pruning condition
int idx = board[r][c] - 'a';
if (node.children[idx] == null) {
    return; // PRUNED: No dictionary word starts with this prefix!
}

3. In-Place Board Visitation Masking

Allocating a boolean[rows][cols] matrix for visited state introduces GC allocation churn. Senior implementations mutate the board in-place using a sentinel mask (like '#') and restore the character during backtracking: 

// IDIOMATIC JAVA 25: In-place O(1) memory backtracking
char temp = board[r][c];
board[r][c] = '#'; // Mark visited in-place

dfs(board, r + 1, c, nextNode, res); // Explore neighbors

board[r][c] = temp; // Backtrack: restore character with zero allocation!
