Generics, Bridge Methods, Heap Pollution & Type Erasure

Master Java type erasure mechanics, synthetic bridge methods in bytecode, and @SafeVarargs heap pollution.

1. Compile-Time Invariance vs Runtime Type Erasure

Generics in Java were designed with one overriding constraint in 2004 (Java 5): binary backward compatibility with existing raw-type bytecode. Consequently, generic type parameters exist purely during compilation and are erased to their bounding types (or Object) in the resulting .class file: 

// ANTI-PATTERN: Believing generic type arguments exist at runtime
List<String> strings = new ArrayList<>();
List<Integer> integers = new ArrayList<>();

// At runtime: Both share the identical raw Class object!
boolean sameClass = (strings.getClass() == integers.getClass()); // TRUE! (both are ArrayList.class)
// if (strings instanceof List<String>) {} // DOES NOT COMPILE: Cannot verify generic type at runtime!

2. Under the Hood: Bridge Methods in Bytecode

When a class extends or implements a parameterized generic class or interface, type erasure would break dynamic polymorphic method dispatch (invokevirtual). To preserve polymorphism, the compiler automatically generates synthetic bridge methods: 

// Source code:
public class StringNode implements Comparable<StringNode> {
    @Override public int compareTo(StringNode other) { return 0; }
}

/* Javac generates TWO methods in bytecode:
  1. public int compareTo(StringNode other); // Your implementation
  2. public int compareTo(Object other) {     // SYNTHETIC BRIDGE METHOD!
         return compareTo((StringNode) other); // Performs cast and delegates
     }
*/
⚡ Inspecting Bridge Methods with Reflection
You can inspect synthetic compiler bridges programmatically: method.isBridge() returns true for the erased Object overload.

3. Heap Pollution & @SafeVarargs

Because generic arrays cannot be created (new T[] is illegal due to reification conflicts), mixing generic types with variable arguments (varargs) creates heap pollution: 

// IDIOMATIC JAVA 21: Safe generic varargs methods
@SafeVarargs // Asserts to compiler that method never pollutes the varargs array
public static <T> List<T> asImmutableList(T... elements) {
    return List.of(elements); // Only legal on final or static methods!
}
