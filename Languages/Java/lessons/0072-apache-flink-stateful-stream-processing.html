Apache Flink Stateful Streaming: Watermarks, KeyedProcessFunction, ValueState & RocksDB Checkpoints

Master Apache Flink event-time watermarks, KeyedProcessFunction managed state, and RocksDB checkpoints.

1. Flink Architecture: Event Time & Watermarks

In real-time stream processing, network latency and mobile disconnections cause events to arrive out-of-order. Event Time processes records based on the timestamp attached when the event actually occurred at the edge. Watermarks signal event-time completeness, asserting that no future events with timestamp <= watermark will arrive: 

// UNDER THE HOOD: Bounded-Out-Of-Orderness Watermark Strategy
WatermarkStrategy<PaymentEvent> strategy = WatermarkStrategy
    .<PaymentEvent>forBoundedOutOfOrderness(Duration.ofSeconds(5))
    .withTimestampAssigner((event, timestamp) -> event.timestampEpochMs());

2. Managed Keyed State with KeyedProcessFunction

Unlike stateless streaming engines, Flink maintains Managed Keyed State (e.g., ValueState<T>, ListState<T>) partitioned by stream key. Combined with the timer service, KeyedProcessFunction detects multi-event patterns across sliding time windows: 

// IDIOMATIC JAVA 25: KeyedProcessFunction State & Timer Pattern
public class VelocityFraudDetector extends KeyedProcessFunction<String, Transaction, Alert> {
    private transient ValueState<Long> lastTxAmountState;

    @Override
    public void open(Configuration parameters) {
        lastTxAmountState = getRuntimeContext().getState(new ValueStateDescriptor<>("lastTx", Long.class));
    }

    @Override
    public void processElement(Transaction tx, Context ctx, Collector<Alert> out) throws Exception {
        Long prevAmount = lastTxAmountState.value();
        if (prevAmount != null && prevAmount < 100L && tx.amountCents() > 1_000_000L) {
            out.collect(new Alert(tx.accountId(), "Suspected card-testing fraud pattern"));
        }
        lastTxAmountState.update(tx.amountCents());
    }
}

3. Fault Tolerance & Exactly-Once via Asynchronous Barriers

Flink achieves Exactly-Once state semantics using a variant of the Chandy-Lamport distributed algorithm. Stream sources inject Checkpoint Barriers into the data stream. When operators receive barriers, they snapshot their internal state (backed by RocksDB on local SSDs) asynchronously to remote durable storage (S3/HDFS) without halting stream processing: 

// IDIOMATIC JAVA 25: Flink Checkpoint Configuration
env.enableCheckpointing(10000, CheckpointingMode.EXACTLY_ONCE);
env.setStateBackend(new EmbeddedRocksDBStateBackend(true)); // Spills terabyte state to local NVMe!
