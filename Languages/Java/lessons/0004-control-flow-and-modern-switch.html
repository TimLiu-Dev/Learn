Control Flow & Modern Switch Expressions

Master Java 25 switch expressions, arrow syntax, yield blocks, and labeled loops for algorithmic traversal.

1. The Fall-Through Anti-Pattern vs Modern Arrow Switch

In legacy Java, switch statements inherited C's implicit fall-through semantics. Omitting an explicit break; statement caused code to execute adjacent branches silently: 

// ANTI-PATTERN: Silent fall-through bug in legacy switch
switch (userRole) {
    case "ADMIN":
        grantAdminRights();
        // BUG: Missing break causes ADMIN to fall through to USER!
    case "USER":
        grantUserRights();
        break;
}

Java 25 LTS Switch Expressions eliminate fall-through entirely with arrow syntax (->) and can return values directly: 

// IDIOMATIC JAVA 25: Exhaustive arrow switch expression
String roleDescription = switch (userRole) {
    case "ADMIN" -> "Full System Administrator";
    case "SUPPORT", "AUDITOR" -> "Read-Only Compliance User";
    case "USER" -> "Standard Authenticated Customer";
    default -> "Anonymous Guest";
};

2. Under the Hood: Labeled Loops for Algorithmic Traversal

In 2D grid matrix algorithms (e.g. searching a maze or LeetCode graph), breaking out of deeply nested loops typically requires awkward boolean flags. Java supports clean labeled control statements: 

// IDIOMATIC JAVA 25: Direct escape from nested iteration via labeled break
searchGrid:
for (int r = 0; r < matrix.length; r++) {
    for (int c = 0; c < matrix[r].length; c++) {
        if (matrix[r][c] == target) {
            foundRow = r;
            foundCol = c;
            break searchGrid; // Jumps directly past the outer loop!
        }
    }
}
⚡ The 'yield' Keyword in Multi-line Blocks
When a switch arrow arm requires multiple statements enclosed in curly braces { ... }, use the yield keyword to produce the returned expression value, rather than return (which would exit the surrounding method).

3. Bytecode Compilation: tableswitch vs lookupswitch

The HotSpot compiler translates switch statements into one of two bytecode instructions: 

// Continuous integers (e.g. 1, 2, 3) emit O(1) tableswitch:
// tableswitch { 1: L1, 2: L2, 3: L3, default: LDef } (Direct O(1) jump table)

// Sparse keys or String hash codes emit O(log N) lookupswitch:
// lookupswitch { 100: L1, 5000: L2, 999999: L3 } (Binary search on sorted key array)
