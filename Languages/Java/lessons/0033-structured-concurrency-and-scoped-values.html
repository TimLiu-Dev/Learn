Structured Concurrency (StructuredTaskScope) & ScopedValue vs ThreadLocal

Master Project Loom Structured Concurrency (JEP 453) to eliminate orphaned threads, and ScopedValue (JEP 446) for zero-leak context propagation.

1. The Unstructured Concurrency Crisis: Orphaned Threads & Leaks

In traditional Java concurrency with ExecutorService or CompletableFuture, task lifecycles are unstructured. If a request handler spawns sub-tasks and one sub-task fails, the remaining sub-tasks continue running in the background as orphaned threads, consuming CPU, database connections, and memory: 

// ANTI-PATTERN: Unstructured concurrency leaking orphaned threads
public UserProfile getUserProfile(String userId) throws Exception {
    CompletableFuture<User> userFuture = CompletableFuture.supplyAsync(() -> fetchUser(userId));
    CompletableFuture<Orders> ordersFuture = CompletableFuture.supplyAsync(() -> fetchOrders(userId));

    // If fetchUser fails, fetchOrders keeps running unnoticed in background!
    return new UserProfile(userFuture.get(), ordersFuture.get());
}

2. Under the Hood: StructuredTaskScope (JEP 453)

Modern Java 21 introduces Structured Concurrency via StructuredTaskScope. Subtasks are lexically bound to a syntactic block using try-with-resources. If one subtask fails in ShutdownOnFailure, the scope automatically cancels all sibling subtasks and cleans up: 

// IDIOMATIC JAVA 21: Structured Concurrency with automatic sibling cancellation
public UserProfile fetchUserProfile(String userId) throws Exception {
    try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
        Supplier<User> userSubtask = scope.fork(() -> fetchUser(userId));
        Supplier<Orders> ordersSubtask = scope.fork(() -> fetchOrders(userId));

        scope.join(); // Blocks until all subtasks finish or one fails
        scope.throwIfFailed(); // Propagates first failure if any subtask threw

        // Here, both subtasks are guaranteed completed successfully
        return new UserProfile(userSubtask.get(), ordersSubtask.get());
    } // Exiting block guarantees all spawned virtual threads have terminated!
}
⚡ ShutdownOnSuccess vs ShutdownOnFailure
Use StructuredTaskScope.ShutdownOnSuccess<T> for speculative fan-out (e.g. querying multiple replicas or redundant price quotes where the fastest result wins). The first subtask to succeed cancels all remaining siblings and returns immediately via scope.result()!

3. ScopedValue vs ThreadLocal (JEP 446)

When running millions of virtual threads, ThreadLocal causes severe overhead: every thread maintains its own mutable map, and failure to call remove() leaks memory. ScopedValue introduces immutable, bounded-lifetime context: 

// IDIOMATIC JAVA 21: ScopedValue for zero-overhead, immutable context propagation
public class SecurityContextHolder {
    public static final ScopedValue<UserCredentials> CURRENT_USER = ScopedValue.newInstance();

    public void handleRequest(UserCredentials creds) {
        // Bound ONLY for the lexical scope of the runnable
        ScopedValue.where(CURRENT_USER, creds).run(() -> {
            processPayment(); // Reads CURRENT_USER.get() without thread-local map overhead!
        });
        // Out here, CURRENT_USER is automatically unmapped! No memory leaks!
    }
}
