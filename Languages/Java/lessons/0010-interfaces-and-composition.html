Interfaces, Default Methods & Composition over Inheritance

Master modern interfaces (default, static, private methods), diamond conflict resolution, and composition over inheritance.

1. Modern Interfaces: Default, Static & Private Methods

Since Java 8 and 9, interfaces are no longer restricted to pure abstract method signatures. They provide rich API capabilities:

  • Default Methods (Java 8): Allow adding new methods to interfaces without breaking existing implementing classes.
  • Static Methods (Java 8): Factory and utility methods attached directly to the interface (e.g., Comparator.comparing(), List.of()).
  • Private Methods (Java 9): Helper methods encapsulated inside the interface to share logic between default methods.
// IDIOMATIC JAVA 25: Modern interface with static factories & default logic
public interface AuditLogger {
    void log(String message);

    default void logWithTimestamp(String message) {
        log(formatMessage(message)); // Shares encapsulated private helper
    }

    private String formatMessage(String message) {
        return Instant.now() + " | " + message;
    }

    static AuditLogger console() {
        return System.out::println; // Static factory method
    }
}

2. Under the Hood: The Diamond Problem & Conflict Resolution

When a class implements two interfaces that declare identical default method signatures, the compiler refuses to guess which implementation takes priority: 

// PRODUCTION TRAP: Diamond conflict compilation failure
interface Alpha { default String name() { return "Alpha"; } }
interface Beta  { default String name() { return "Beta"; } }

// COMPILATION ERROR: class Conflict inherits unrelated defaults for name() from types Alpha and Beta
class Conflict implements Alpha, Beta {
    @Override
    public String name() {
        return Alpha.super.name(); // Explicit resolution syntax required!
    }
}
⚠ The Class Wins Rule
If a superclass and an interface declare a method with identical signatures, the superclass method always wins. Default methods in interfaces never override concrete implementations inherited from a parent class.

3. Interface Segregation & Composition Over Inheritance

The Interface Segregation Principle (ISP) dictates that clients should not be forced to depend on methods they do not use. Prefer multiple small, focused interfaces (e.g., AutoCloseable, Comparable, Runnable) composed together: 

// IDIOMATIC JAVA 25: Composition of small, focused contracts
public class S3DataSink implements AutoCloseable, Flushable {
    private final Channel channel;

    public S3DataSink(Channel channel) {
        this.channel = channel;
    }

    @Override public void flush() { channel.flush(); }
    @Override public void close() { channel.close(); }
}
