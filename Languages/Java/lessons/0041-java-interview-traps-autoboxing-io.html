Java Interview Traps: Autoboxing Overhead, Sorting Adversaries & Fast I/O

Master Java interview traps: autoboxing GC churn, IntegerCache equality boundaries, and quicksort worst-case defense.

1. The Autoboxing Hidden Allocation Trap

Java transparently boxes primitive types (int to Integer, long to Long). In tight loops, autoboxing silently instantiates millions of temporary objects on the heap, triggering continuous GC pressure: 

// ANTI-PATTERN: Silent heap allocation in tight accumulator loop
Long sum = 0L; // Boxed Long object!
for (long i = 0; i < 10_000_000L; i++) {
    sum += i; // ALLOCATES 10,000,000 temporary Long objects on the Java heap!
}

// IDIOMATIC JAVA 25: Primitive register accumulation
long primitiveSum = 0L;
for (long i = 0; i < 10_000_000L; i++) {
    primitiveSum += i; // 0 allocations; runs in CPU hardware registers!
}

2. Under the Hood: The Integer Cache (-128 to 127) Trap

The JVM caches boxed Integer instances between -128 and 127 (JLS 5.1.7). Comparing boxed values with == appears to work in small tests but produces silent bugs in production when values exceed 127: 

// UNDER THE HOOD: Integer cache boundary behavior
Integer a = 100, b = 100;
assert a == b; // TRUE: References point to same cached instance in IntegerCache!

Integer x = 200, y = 200;
assert x == y; // FALSE: New distinct objects allocated on heap; == checks identity!
assert x.equals(y); // TRUE: Correct value comparison!

3. Dual-Pivot Quicksort Adversaries vs Timsort

Arrays.sort(int[]) uses Dual-Pivot Quicksort. Crafted adversarial inputs can degrade quicksort to O(N^2) time, causing Time Limit Exceeded (TLE) in competitive programming and interview benchmarks. In contrast, Arrays.sort(Object[]) uses Timsort, which guarantees O(N log N) worst-case time: 

// IDIOMATIC JAVA 25: Defending against quicksort worst-case degradation
// Option A: Shuffle primitive array before sorting to eliminate adversarial order
shuffle(primitiveArray);
Arrays.sort(primitiveArray); // Safe O(N log N) average case

// Option B: Box or use Timsort for guaranteed O(N log N) worst-case
Integer[] boxed = Arrays.stream(primitiveArray).boxed().toArray(Integer[]::new);
Arrays.sort(boxed); // Uses Timsort: strictly O(N log N) guaranteed!
