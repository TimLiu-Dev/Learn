Encapsulation, Immutability & Defensive Copying

Master encapsulation invariants, defensive copying on construction and access, and unmodifiable collections.

1. The Escaped Reference Security Hole

In enterprise security audits, returning direct references to mutable internal state (such as java.util.Date, primitive arrays, or mutable ArrayList) breaks encapsulation completely: 

// ANTI-PATTERN: Leaking internal mutable state through getters
public final class VulnerableSecurityToken {
    private final List<String> roles;

    public VulnerableSecurityToken(List<String> roles) {
        this.roles = roles; // DANGER: Caller retains reference to 'roles'!
    }

    public List<String> getRoles() {
        return this.roles; // DANGER: Caller can call getRoles().add("ADMIN")!
    }
}

An attacker who calls token.getRoles().clear() or .add("ADMIN") bypasses all role-based authorization checks because the internal collection pointer was leaked.

2. Defensive Copying vs Unmodifiable Collections

To guarantee true immutability, apply defensive copying on construction and defensive copying or unmodifiable views on access: 

// IDIOMATIC JAVA 21: Fully encapsulated immutable domain model
public final class SecureSecurityToken {
    private final List<String> roles;

    public SecureSecurityToken(List<String> roles) {
        // Defensive copy on ingestion + unmodifiable wrapper:
        this.roles = List.copyOf(roles); // Java 10+ List.copyOf produces truly immutable list!
    }

    public List<String> getRoles() {
        return this.roles; // Safe to return because List.copyOf is unmodifiable!
    }
}
⚡ Collections.unmodifiableList vs List.copyOf
Collections.unmodifiableList(list) creates an unmodifiable view. If the underlying original list is modified by another thread, the view reflects those changes! List.copyOf(list) creates an independent, deeply immutable snapshot.

3. Under the Hood: Primitive Arrays and clone()

Because arrays cannot be wrapped in unmodifiable views, primitive arrays must always be defensively copied in both constructors and accessors using clone() or Arrays.copyOf(): 

// IDIOMATIC JAVA 21: Defensive copying for byte buffers and arrays
public final class CryptoKey {
    private final byte[] secretKey;

    public CryptoKey(byte[] secretKey) {
        this.secretKey = secretKey.clone(); // Defend against caller mutation
    }

    public byte[] getSecretKey() {
        return this.secretKey.clone();     // Defend against callee mutation
    }
}
