Spring Data JPA: Projections, Keyset Pagination, OSIV Off & Read-Only Transactions

Master Spring Data JPA projections, keyset pagination, and disabling Open Session in View.

1. The Open Session in View (OSIV) Anti-Pattern

By default, Spring Boot historically set spring.jpa.open-in-view=true. OSIV keeps the Hibernate database session and connection open throughout the entire HTTP request lifecycle, including view rendering. In high-traffic microservices, this causes database connection pool exhaustion: 

// PRODUCTION HAZARD: OSIV holds database connection during slow network I/O
// Request enters -> Opens DB connection -> Controller finishes -> Serialization blocks on slow network -> DB connection held idle!
// REMEDY in application.properties:
spring.jpa.open-in-view=false # Closes DB connection immediately upon transaction completion!

2. Under the Hood: Keyset Pagination vs Offset Pagination

Offset pagination (OFFSET 1000000 LIMIT 20) forces the database engine to scan 1,000,020 index entries and discard the first million. Keyset Pagination (Seek Method) uses the primary key or indexed sorting column to resume navigation in O(1) time: 

// ANTI-PATTERN: Slow O(N) offset pagination
SELECT * FROM orders ORDER BY id ASC LIMIT 20 OFFSET 1000000; // Scans 1M rows!

// IDIOMATIC JAVA 25: High-performance O(1) keyset pagination
SELECT * FROM orders WHERE id > :lastSeenId ORDER BY id ASC LIMIT 20; // Instant index seek!

3. DTO Constructor Projections & Read-Only Transactions

Loading full JPA entities into the persistence context creates dirty-checking snapshots. For read-heavy operations, @Transactional(readOnly = true) combined with DTO constructor projections eliminates dirty checking overhead completely: 

// IDIOMATIC JAVA 25: Zero dirty checking with constructor projection
@Transactional(readOnly = true)
@Query("SELECT new com.example.AccountSummary(a.id, a.name, a.balance) FROM Account a WHERE a.active = true")
List<AccountSummary> findActiveSummaries();
