Project Loom Virtual Threads: Carrier Mounting, Continuations & Pinning

Master Java 21 Project Loom virtual threads, carrier mounting, continuation mechanics, and carrier pinning avoidance.

1. The Virtual Thread Revolution: Project Loom

Prior to Java 21, every Java Thread mapped 1-to-1 to an operating system kernel thread requiring ~1MB of reserved stack space. Virtual Threads (JEP 444) decouple Java threads from OS threads: millions of virtual threads run on a tiny pool of OS carrier threads (typically equal to CPU core count): 

// ANTI-PATTERN: Pooling virtual threads like expensive platform threads
ExecutorService pool = Executors.newFixedThreadPool(200); // PLATFORM THREAD POOL (Limited to ~200 threads)

// IDIOMATIC JAVA 21: Virtual thread per task without pooling
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    IntStream.range(0, 10_000).forEach(i -> executor.submit(() -> {
        Thread.sleep(Duration.ofMillis(100)); // Unmounts carrier thread; zero CPU wasted!
        return i;
    }));
} // Executor auto-closes and awaits all virtual tasks upon block exit!

2. Under the Hood: Continuations & Carrier Mounting

When a virtual thread executes a blocking operation (socket read, Thread.sleep, lock wait), the JVM yields the underlying Continuation. Its stack frame is copied to the heap, and the carrier thread is freed to run another virtual thread. When I/O completes (via OS epoll/kqueue), the virtual thread is rescheduled on any available carrier. 

// UNDER THE HOOD: Carrier thread unmounting
// Virtual Thread VT-1 mounts on Carrier Thread ForkJoinWorkerThread-1
// VT-1 blocks on socket read -> Continuation yields -> VT-1 stack copied to heap
// ForkJoinWorkerThread-1 immediately executes VT-2!
// Socket has data -> OS epoll signals JVM -> VT-1 re-mounts on Carrier Thread ForkJoinWorkerThread-3

3. The Carrier Pinning Hazard: synchronized vs ReentrantLock

A virtual thread is pinned to its carrier when it blocks inside a synchronized block or native JNI method. When pinned, the carrier thread cannot be released, defeating Loom scalability: 

// PRODUCTION HAZARD: synchronized block pins the carrier thread during I/O
public synchronized String fetchRemoteData() { // PINNED!
    return httpClient.send(req, BodyHandlers.ofString()).body(); // Carrier thread blocked!
}

// IDIOMATIC JAVA 21: ReentrantLock allows carrier unmounting
private final ReentrantLock lock = new ReentrantLock();
public String fetchRemoteDataSafe() throws Exception {
    lock.lock();
    try {
        return httpClient.send(req, BodyHandlers.ofString()).body(); // Unmounts safely!
    } finally {
        lock.unlock();
    }
}
