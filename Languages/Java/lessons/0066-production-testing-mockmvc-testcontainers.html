Production Testing Pyramid: @WebMvcTest, @DataJpaTest, WireMock & Testcontainers

Master the Spring testing pyramid, @WebMvcTest slice tests, Testcontainers, and WireMock.

1. The Production Spring Testing Pyramid

Running full @SpringBootTest for every test method boots the entire application context, resulting in 20-minute CI build pipelines. The senior testing pyramid uses fast, targeted slice tests:

  • Unit Tests: Pure Java POJOs/records; 0 milliseconds startup.
  • Slice Tests (@WebMvcTest): Boots only the MVC web layer via modular spring-boot-starter-webmvc-test; mocks collaborators via @MockitoBean (replacing removed @MockBean in Boot 4) and tests seamlessly with MockMvcTester / RestTestClient.
  • Repository Slices (@DataJpaTest): Boots only Hibernate 7, JPA repositories, and datasource.
  • Integration Tests: Full @SpringBootTest backed by real Docker containers via Testcontainers.
// UNDER THE HOOD: Fast Boot 4 Slice Test with @WebMvcTest & @MockitoBean
@WebMvcTest(AccountController.class)
class AccountControllerTest {
    @Autowired private MockMvc mockMvc;
    @MockitoBean private AccountService accountService; // Spring Framework 6.2+/Boot 4 core Bean Override

    @Test
    void shouldReturnAccount() throws Exception {
        when(accountService.findById("ACT-1")).thenReturn(new AccountDTO("ACT-1", "Alice"));
        mockMvc.perform(get("/api/accounts/ACT-1"))
            .andExpect(status().isOk())
            .andExpect(jsonPath("$.name").value("Alice"));
    }
}

2. Testcontainers vs Embedded In-Memory H2

Testing with in-memory H2 databases creates false confidence: H2 lacks PostgreSQL JSONB support, exhibits different locking semantics, and masks SQL dialect incompatibilities. Testcontainers spins up real Docker containers for PostgreSQL and Kafka: 

// IDIOMATIC JAVA 25: Real PostgreSQL with Testcontainers
@Testcontainers
@SpringBootTest
class OrderIntegrationTest {
    @Container
    static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:16-alpine");

    @DynamicPropertySource
    static void configureProperties(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", postgres::getJdbcUrl);
        registry.add("spring.datasource.username", postgres::getUsername);
        registry.add("spring.datasource.password", postgres::getPassword);
    }
}

3. WireMock for Resilient HTTP Dependency Simulation

Testing outbound REST clients (such as payment gateways) against third-party sandbox environments causes flaky CI builds. WireMock runs a local HTTP server that returns deterministic stubs and fault scenarios: 

// IDIOMATIC JAVA 25: Stubbing external HTTP service with WireMock
stubFor(get(urlEqualTo("/v1/rates/USD"))
    .willReturn(aResponse()
        .withStatus(200)
        .withHeader("Content-Type", "application/json")
        .withBody("{\"rate\": 1.25}")));
