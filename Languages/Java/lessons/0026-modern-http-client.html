Modern HTTP Client (java.net.http), HTTP/2 & Timeouts

Master java.net.http.HttpClient, connect vs request timeouts, HTTP/2 multiplexing, and async body handlers.

1. Architecture of java.net.http.HttpClient

Introduced in Java 11 and enhanced in LTS releases, java.net.http.HttpClient replaces the legacy HttpURLConnection and Apache HttpClient for modern web requests. It features native support for HTTP/2 multiplexing, non-blocking asynchronous requests via CompletableFuture, and reactive streams: 

// ANTI-PATTERN: Recreating HttpClient instances per HTTP request
for (String url : urls) {
    HttpClient client = HttpClient.newHttpClient(); // LEAK: Creates new thread pool & SSL context every loop!
    client.send(HttpRequest.newBuilder(URI.create(url)).build(), BodyHandlers.ofString());
}

2. Under the Hood: Connect Timeout vs Request Timeout

Production reliability demands distinguishing between the initial TCP/TLS handshake timeout and the total duration for server response delivery: 

// UNDER THE HOOD: Configuring dual timeouts
HttpClient client = HttpClient.newBuilder()
    .connectTimeout(Duration.ofSeconds(5)) // TCP SYN + TLS Handshake limit
    .version(HttpClient.Version.HTTP_2)
    .build();

HttpRequest request = HttpRequest.newBuilder(URI.create("https://api.example.com/data"))
    .timeout(Duration.ofSeconds(10)) // Response body delivery limit
    .GET()
    .build();

3. Asynchronous Non-Blocking Requests with CompletableFuture

Instead of blocking calling threads with client.send(), senior systems execute requests asynchronously via client.sendAsync(): 

// IDIOMATIC JAVA 25: Parallel async HTTP requests with CompletableFuture
List<CompletableFuture<String>> futures = urls.stream()
    .map(url -> client.sendAsync(
            HttpRequest.newBuilder(URI.create(url)).timeout(Duration.ofSeconds(3)).build(),
            HttpResponse.BodyHandlers.ofString()
        )
        .thenApply(HttpResponse::body))
    .toList();
