JDK Dynamic Proxies vs CGLIB/ByteBuddy & The Self-Invocation Trap

Master JDK Dynamic Proxies, CGLIB/ByteBuddy subclassing, and the notorious Self-Invocation Trap.

1. JDK Dynamic Proxies vs CGLIB / ByteBuddy

Aspect-Oriented Programming (AOP) in Spring, Micronaut, and Hibernate relies on runtime bytecode proxies:

  • JDK Dynamic Proxies (java.lang.reflect.Proxy): Built into the JDK. Generates classes at runtime implementing interfaces. Cannot proxy classes without interfaces.
  • CGLIB / ByteBuddy: Generates dynamic subclasses of target classes. Can proxy concrete classes, but fails if classes or methods are final.
// UNDER THE HOOD: Creating a JDK Dynamic Proxy
OrderService proxy = (OrderService) Proxy.newProxyInstance(
    OrderService.class.getClassLoader(),
    new Class<?>[]{ OrderService.class },
    (p, method, args) -> {
        System.out.println("Entering " + method.getName());
        return method.invoke(target, args);
    }
);

2. Under the Hood: The Self-Invocation Trap

The most notorious production bug in Spring/Java EE is the Self-Invocation Trap. When a method calls another method within the same class using this.method(), the call bypasses the proxy wrapper completely, silently ignoring @Transactional, @Async, and @Cacheable annotations: 

// PRODUCTION DISASTER: The Self-Invocation Trap
@Service
public class OrderService {
    public void createOrder() {
        this.chargeCard(); // CALLS RAW INSTANCE! Bypasses proxy! @Transactional is IGNORED!
    }

    @Transactional
    public void chargeCard() {
        // Runs WITHOUT transaction context because proxy was bypassed!
    }
}

3. Senior Solutions: Solving Self-Invocation

To ensure proxy interception, senior engineers apply one of three clean architectural patterns:

  • Separate Collaborator Service (Best Practice): Extract the transactional method into an independent injected service.
  • Self-Injection: Inject the bean into itself via @Lazy private OrderService self; and call self.chargeCard().
  • AopContext: Call ((OrderService) AopContext.currentProxy()).chargeCard(); (requires exposeProxy=true).
// IDIOMATIC JAVA 25: Extract collaborator to guarantee proxy boundary
@Service
public class OrderService {
    private final PaymentService paymentService; // Injected collaborator proxy!
    public OrderService(PaymentService p) { this.paymentService = p; }

    public void createOrder() {
        paymentService.chargeCard(); // Safely intercepted by transactional proxy!
    }
}
