Robust Exception Handling, Suppressed Exceptions & AutoCloseable

Master try-with-resources, suppressed exceptions, exception chaining, and unchecked domain exception architectures.

1. The Anti-Pattern: Swallowed Exceptions & Lost Root Causes

In enterprise services, few bugs are more difficult to triage than empty catch blocks or wrapping exceptions without preserving the underlying cause: 

// ANTI-PATTERN: Swallowing root cause and destroying stack trace
try {
    paymentGateway.charge(card);
} catch (SQLException e) {
    // BUG: Root cause 'e' is dropped! In production logs, the SQL error is lost forever!
    throw new PaymentFailedException("Payment processing failed");
}

Always chain the original exception as the cause so operators can inspect the complete causal chain via ex.getCause().

2. Try-With-Resources & Suppressed Exceptions

When closing multiple resources in legacy finally blocks, if both the try block and close() threw exceptions, the close exception masked the real business failure. Java 7+ try-with-resources preserves the primary exception and attaches close failures as suppressed exceptions: 

// IDIOMATIC JAVA 25: AutoCloseable try-with-resources with suppressed tracking
try (var in = Files.newInputStream(src);
     var out = Files.newOutputStream(dest)) {
    in.transferTo(out);
} catch (IOException e) {
    for (Throwable suppressed : e.getSuppressed()) {
        log.warn("Secondary failure while closing stream: ", suppressed);
    }
    throw new StorageException("File copy failed", e);
}
⚠ Never Catch Throwable or Error
Catching Throwable catches JVM fatal errors like OutOfMemoryError, StackOverflowError, and InternalError. The JVM may be in an inconsistent, non-recoverable state. Only catch Exception or specific domain exceptions.

3. Modern Error Architecture: Unchecked Domain Exceptions

Modern Java and Spring Boot architectures favor unchecked exceptions (subclasses of RuntimeException) decorated with domain error codes, mapped to RFC 7807 ProblemDetail responses: 

// IDIOMATIC JAVA 25: Clean unchecked domain hierarchy
public class OrderNotFoundException extends RuntimeException {
    private final String orderId;

    public OrderNotFoundException(String orderId) {
        super("Order not found: " + orderId);
        this.orderId = orderId;
    }

    public String getOrderId() { return orderId; }
}
🔗 Android / Kotlin Bridge: Checked vs Unchecked Exceptions
Kotlin eliminates checked exceptions completely (calling Java's Files.readString compiles with zero throws declaration). In Java, checked exceptions (IOException, SQLException) fail compilation unless caught or re-declared — and break standard Stream lambdas unless wrapped in UncheckedIOException (Lesson 0074).
