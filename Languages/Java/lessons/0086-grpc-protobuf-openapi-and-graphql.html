Beyond REST: gRPC (HTTP/2 & Protobuf), OpenAPI 3.1 Contracts & Spring for GraphQL (@BatchMapping)

Know when to choose REST + OpenAPI 3.1, binary gRPC/Protobuf for internal microservice RPC, or Spring for GraphQL for BFF aggregation—and how to eliminate the GraphQL N+1 DataLoader trap with @BatchMapping.

1. Choosing the Right Wire Protocol in 2027: REST vs. gRPC vs. GraphQL

Senior backend engineers do not treat REST/JSON as a hammer for every problem. Each protocol solves a specific communication boundary:

ProtocolWire Format & TransportBest Fit in ProductionKey Trade-Off
REST + OpenAPI 3.1UTF-8 JSON over HTTP/1.1, HTTP/2, or HTTP/3Public external APIs, partner webhooks, standard CRUDVerbose field-name repetition; over/under-fetching on complex UI screens.
gRPC (spring-grpc)Binary Protocol Buffers (Protobuf) over multiplexed HTTP/2High-throughput internal service-to-service RPC & bidirectional streamingRequires .proto schema compilation & Envoy/gRPC-Web proxy for browsers.
GraphQL (Spring for GraphQL)Typed Graph Query over HTTP POST / WebSocketBackend-for-Frontend (BFF) aggregating Orders + Users + Reviews for mobile/webSevere N+1 query multiplication unless resolved via @BatchMapping (DataLoader).

2. Production Trap: The GraphQL @SchemaMapping N+1 Explosion vs. @BatchMapping

When an Android or web client queries 50 orders along with each order's Customer in GraphQL, writing a naive @SchemaMapping resolver executes 50 separate customerClient.findById(id) calls! 

// ANTI-PATTERN: @SchemaMapping triggers 1 + N downstream queries for N orders!
@Controller
public class NaiveOrderGraphqlController {
    @QueryMapping
    public List<OrderDto> recentOrders() {
        return orderService.findRecent(50); // 1 query returning 50 orders
    }

    @SchemaMapping(typeName = "Order", field = "customer")
    public CustomerDto customer(OrderDto order) {
        // BUG: Invoked 50 separate times (once per OrderDto)!
        return customerService.findById(order.customerId());
    }
}

In Spring for GraphQL, replacing @SchemaMapping with @BatchMapping automatically registers a DataLoader that collects all 50 OrderDto instances from the current level of the GraphQL execution tree and dispatches one single batched Map<OrderDto, CustomerDto> lookup: 

// IDIOMATIC SPRING FOR GRAPHQL: @BatchMapping collapses N+1 into 1 bulk call!
@Controller
public class BatchedOrderGraphqlController {
    private final CustomerService customerService;

    public BatchedOrderGraphqlController(CustomerService customerService) {
        this.customerService = customerService;
    }

    @BatchMapping(typeName = "Order", field = "customer")
    public Map<OrderDto, CustomerDto> customer(List<OrderDto> orders) {
        Set<String> customerIds = orders.stream().map(OrderDto::customerId).collect(Collectors.toSet());
        Map<String, CustomerDto> byId = customerService.findAllByIds(customerIds); // 1 bulk WHERE id IN (...)!
        return orders.stream().collect(Collectors.toMap(o -> o, o -> byId.get(o.customerId())));
    }
}

3. Under the Hood: Protobuf Field Tags & Backward-Compatible Evolution

Unlike JSON (which transmits string keys like "customerAccountId": 42 on every message), Protocol Buffers (Protobuf) encodes fields using compact integer field numbers (1, 2, 3) plus a 3-bit wire type via base-128 varints. To keep rolling Kubernetes deployments backward- and forward-compatible, you must never reuse or change the field number of an existing field, and always reserved deleted tag numbers: 

// IDIOMATIC PROTOBUF v3 CONTRACT + SPRING gRPC SERVICE IMPLEMENTATION
/* syntax = "proto3";
   message RiskCheckRequest {
     reserved 2;           // Never reuse retired field tag #2!
     string order_id = 1;  // Tag 1 (wire key = (1 << 3) | 2)
     int64 amount_cents = 3;
   }
*/
@Service
public class RiskGrpcEndpoint extends RiskServiceGrpc.RiskServiceImplBase {
    @Override
    public void evaluateRisk(RiskCheckRequest req, StreamObserver<RiskCheckReply> responseObserver) {
        boolean approved = req.getAmountCents() <= 500_000L;
        RiskCheckReply reply = RiskCheckReply.newBuilder()
                .setApproved(approved)
                .build();
        responseObserver.onNext(reply);
        responseObserver.onCompleted(); // Mandatory to close the HTTP/2 gRPC stream!
    }
}
