Pass-by-Value Reference Semantics in Java

Master Java's strict pass-by-value semantics, stack-frame pointer copying, and heap object state mutation.

1. The Unbreakable Rule: Java is Strictly Pass-by-Value

One of the most persistent misconceptions in Java interviews is that objects are passed "by reference". Java is strictly pass-by-value, always, without exception.

  • For primitive types (int, double, boolean), the method receives a copy of the primitive bits.
  • For reference types (objects, arrays), the method receives a copy of the reference pointer (the 32-bit or 64-bit memory address).
// ANTI-PATTERN: Believing reassignment mutates caller reference
public static void reassign(Order order) {
    order = new Order("MODIFIED"); // Reassigns LOCAL pointer copy only!
}

Order original = new Order("INITIAL");
reassign(original);
// original STILL points to "INITIAL"! The caller pointer was never mutated!

2. Mutating Object State vs Reassigning the Pointer

Because the method receives a copy of the reference pointer, both the caller and callee reference the same underlying object on the heap: 

// IDIOMATIC JAVA 21: Distinguishing state mutation from reference swapping
public static void mutateState(List<String> list) {
    list.add("Item"); // MUTATES underlying heap object! Caller observes this.
}

public static void swapReferences(Order a, Order b) {
    Order temp = a;
    a = b;
    b = temp; // SWAPS LOCAL COPIES ONLY! Caller references are unchanged.
}
⚡ C++ Pointers vs Java References
In C++, you can pass a reference to a pointer (void swap(Order*& a, Order*& b)), which allows reassigning the caller's variable. Java does NOT have address-of operators (&) or pointer references. You cannot mutate the caller's reference variable from within a method.

3. Under the Hood: Stack Frames & Bytecode (iload vs aload)

When a method is invoked, HotSpot pushes a new stack frame containing the Local Variable Array (LVA): 

// Caller passes argument:
// 0: aload_1        // Push reference from slot 1 onto operand stack
// 1: invokestatic   // Passes reference copy to Callee Local Variable slot 0!

// Inside Callee:
// 0: astore_0       // Storing into slot 0 overwrites local frame copy only!
