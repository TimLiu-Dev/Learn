Section 8 · Delegation · Lesson 8.1

by lazy and lazy vs lateinit

Deferred property initialization: thread safety, mutability trade-offs, and memory safety.

Warm-up: Rapid Recall

  1. Can a Kotlin val be reassigned after its initial assignment?
    CheckNo. val is a read-only reference.
  2. What happens when you read an uninitialized lateinit var?
    CheckThrows UninitializedPropertyAccessException at runtime.
  3. Can primitive types like Int or Boolean be declared as lateinit?
    CheckNo. lateinit requires a non-primitive reference type because the JVM uses null sentinel values internally to check initialization.

The Concept: Deferred Initialization

1. by lazy: Thread-Safe, Immutable, Deferred

by lazy evaluates the initializing lambda on the first access and caches the result for all subsequent reads:

val database: DatabaseClient by lazy { println("Initializing database connection...") DatabaseClient.connect("jdbc:postgresql://localhost:5432/db") }

Thread-safety modes (via LazyThreadSafetyMode):

  • SYNCHRONIZED (Default): Thread-safe; uses lock so only one thread initializes the value.
  • PUBLICATION: Multiple threads can run the initializer concurrently, but only the first completed value is stored.
  • NONE: Zero synchronization overhead. Use on single-threaded environments (Android UI Main Thread).
val viewModel: MainViewModel by lazy(LazyThreadSafetyMode.NONE) { ViewModelProvider(this)[MainViewModel::class.java] }

2. lateinit var: Mutable, Framework Injection

Used primarily when a dependency injection framework (Dagger/Hilt, Spring) or lifecycle callback (Android onCreate, JUnit @BeforeEach) must assign a property after object construction:

class UserActivity : ComponentActivity() { @Inject lateinit var analytics: AnalyticsTracker override fun onCreate(savedInstanceState: Bundle?) { super.onCreate(savedInstanceState) // Check initialization state if necessary: if (::analytics.isInitialized) { analytics.track("screen_view") } } }

Quick Check

Why does lateinit var count: Int fail to compile in Kotlin?

On the JVM, primitive int cannot hold a null reference. Kotlin's compiler checks uninitialized state by testing whether the backing field is null, which is impossible for unboxed primitives.
