DSA strings, Char arithmetic & memoized DP

Zero-allocation character frequency arrays, linear-time string building with buildString, and top-down vs bottom-up Dynamic Programming in Kotlin.

Warm-up: Spaced Retrieval

  1. Why should you reach for ArrayDeque<T> instead of ArrayList.removeAt(0) when implementing a FIFO BFS queue?
    CheckArrayDeque uses a circular buffer with amortized O(1) addLast and removeFirst, whereas ArrayList.removeAt(0) shifts every remaining element in O(N) time (7.5).
  2. How do you allocate an R × C 2D matrix of unboxed 32-bit integers initialized to -1 in Kotlin?

The Concept: Interview String & DP Idioms Without AI

1. Char Arithmetic & IntArray(26) Frequency Tables

Never call deprecated ch.toInt() to parse a digit! '7'.code is ASCII 55, whereas '7'.digitToInt() returns 7.In Kotlin, Char is a distinct type—not a silent integer like in Java or C. Subtracting two characters yields their integer offset, which powers O(1)-space alphabet frequency arrays on LeetCode:

  • Alphabet index (0..25): val idx = ch - 'a' (returns Int).
  • Shift character forward: val nextChar = 'a' + offset (returns Char).
  • Parse numeric digit: ch.digitToInt() (throws on non-digit) or ch.digitToIntOrNull(), plus predicates ch.isLetterOrDigit() and ch.lowercaseChar().

2. Avoiding O(N²) String Concatenation: buildString & CharArray

Because JVM String is immutable, writing result += ch inside a loop copies the entire string on every iteration—turning an O(N) scan into an O(N²) Time Limit Exceeded (TLE) failure! Reach for two idiomatic tools instead:

  • buildString { append(...) }: Wraps a mutable StringBuilder inside a clean receiver lambda and returns the finished String in O(N) time.
  • s.toCharArray() → chars.concatToString(): Mutate or reverse characters in place with zero heap churn, then materialize once at the end.

3. Dynamic Programming: Bottom-Up IntArray vs Top-Down getOrPut

Every Dynamic Programming interview problem in Kotlin fits one of two clean shapes:

  • Bottom-up tabulation (best for dense 0..N states): Allocate an unboxed IntArray(n + 1) or LongArray(n + 1) and fill iteratively using minOf / maxOf.
  • Top-down memoization (best for sparse states or multi-key tuples): Cache recursive subproblems in one expression using memo.getOrPut(key) { ... } (or an IntArray(n) { -1 } sentinel array when keys are bounded indices).

Quick Check

1. Given val ch = '7', what is the difference between ch.digitToInt() and ch.code in Kotlin?

Use ch.digitToInt() (or ch - '0') for numeric value 0..9, and ch.code only when you intentionally want the Unicode code point.

2. Why does building a 50,000-character output with var out = ""; for (c in s) out += c fail with Time Limit Exceeded in interviews?

buildString { append(c) } appends into a resizable buffer in amortized O(1) per character, keeping total runtime strictly O(N).

3. When solving a DP problem whose state space is dense indices 0..N (with N = 10_000), why is IntArray(N + 1) { -1 } faster than HashMap<Int, Int>()?

Reach for HashMap.getOrPut when states are sparse or composite keys, and unboxed IntArray / LongArray when states are dense integer indices.
