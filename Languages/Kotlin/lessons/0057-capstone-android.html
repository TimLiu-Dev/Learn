Android feature capstone

Pillar 1: Production UDF architecture—atomic StateFlow.update, buffered one-off Channel effects, and lifecycle-safe Compose collection.

Warm-up: Rapid Recall

  1. Why is sealed interface UiState preferred over a single class with 4 nullable/boolean fields?
    CheckIt makes impossible combinations unrepresentable (such as isLoading = true while errorMessage != null) and gives compile-time exhaustive when checks.
  2. Why must Jetpack Compose screens collect ViewModel flows via collectAsStateWithLifecycle() instead of collectAsState()?
    CheckcollectAsState() keeps upstream producers active when the app is backgrounded, wasting CPU, network, and battery; collectAsStateWithLifecycle() cancels collection automatically when stopped.

The Concept: Senior Android UDF Blueprint

In production Jetpack Compose apps, screen state and transient one-off events have fundamentally different delivery semantics:

data class FeedUiState( val query: String = "", val articles: List<String> = emptyList(), val bookmarked: Set<String> = emptySet() ) { val filteredArticles: List<String> get() = if (query.isBlank()) articles else articles.filter { it.contains(query, ignoreCase = true) } } sealed interface FeedEffect { data class ShowSnackbar(val message: String) : FeedEffect } class FeedViewModel { private val _uiState = MutableStateFlow(FeedUiState()) val uiState: StateFlow<FeedUiState> = _uiState.asStateFlow() // Buffered Channel guarantees one-off events aren't dropped during rotation // AND aren't re-triggered when Compose recomposes! private val _effects = Channel<FeedEffect>(Channel.BUFFERED) val effects: Flow<FeedEffect> = _effects.receiveAsFlow() fun onQueryChanged(newQuery: String) { _uiState.update { it.copy(query = newQuery) } } }

Quick Check

1. Why is Channel<UiEffect>(Channel.BUFFERED).receiveAsFlow() preferred over MutableSharedFlow<UiEffect>(replay = 0) for single-observer navigation or snackbar triggers?

With SharedFlow(replay = 0), an event emitted while the Activity is momentarily detached during rotation has zero subscribers and is permanently dropped. A buffered Channel queues it until the collector reconnects, then delivers it once.

2. In Jetpack Compose, when should you wrap a calculation inside remember { derivedStateOf { ... } }?

derivedStateOf prevents redundant recompositions when high-frequency inputs (such as lazyListState.firstVisibleItemScrollOffset) change on every frame while the boolean result (offset > 0) rarely flips.

3. Why does passing a standard List<Article> parameter into a @Composable function sometimes prevent skipping in classic Compose without Strong Skipping?

List<T> is only a read-only view, not an immutable contract—the caller could still hold a MutableList reference and mutate it. Using ImmutableList<T> (from kotlinx.collections.immutable) or Kotlin 2.0+ Strong Skipping resolves this.
