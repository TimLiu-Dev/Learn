The Elvis operator ?:

Turn “maybe null” back into a real value: use a default, or leave the function early.

The problem: ?. keeps the null flowing

Safe calls stop the crash, but they leave you holding a nullable value. Sooner or later you need a real one: a name to show on screen, or a number to do maths with. Without a dedicated operator, you'd write this all the time:

val name = if (profile?.nickname != null) profile.nickname else "Athlete"

Docs: Null safety → Elvis operator.The Elvis operator says “this, or else that” in one symbol:

left ?: right means: if left isn't null, the result is left. Otherwise it's right. The right side is only evaluated when it's needed.

The important consequence is that if right isn't nullable, the result isn't nullable either. Elvis is where a nullable chain ends and normal, non-null code starts again.

Default values

class Profile(val nickname: String?, val email: String?) fun main() { //sampleStart val newUser = Profile(nickname = null, email = "kai@example.com") val name: String = newUser.nickname ?: "Athlete" // plain String now val minutes: Int = "45min".toIntOrNull() ?: 30 // parse, or fall back val label = newUser.nickname ?: newUser.email ?: "Anonymous" // first non-null wins println(name) println(minutes) println(label) //sampleEnd }

Elvis chains read left to right: “nickname, or else email, or else "Anonymous"”. The most common shape in real code is a safe-call chain ending in a default, a?.b?.c ?: fallback. That's the null-safety version of a whole if/else.

Watch the precedence

Spec: Elvis operator expressions. In the grammar, arithmetic binds tighter than ?:.?: binds more loosely than arithmetic, so a ?: 0 + base means a ?: (0 + base), not (a ?: 0) + base. Predict the output, then run it:

fun main() { //sampleStart val bonus: Int? = 5 val base = 100 println(bonus ?: 0 + base) // ? println((bonus ?: 0) + base) // ? //sampleEnd }

If an Elvis sits next to +, - or *, add parentheses.

Early exit: ?: return and ?: throw

Sometimes there's no sensible default. If the value is missing, the function should simply stop. Generated code often does this with nested ifs, which push the real work further and further right. Elvis lets you write guard clauses instead: deal with the missing case at the top, then carry on with non-null values.

class Coach(val name: String) class Workout(val title: String, val coach: Coach?) class Profile(val nickname: String?, val currentWorkout: Workout?) //sampleStart fun startMessage(profile: Profile?): String { val workout = profile?.currentWorkout ?: return "Nothing to start" val coach = workout.coach ?: throw IllegalStateException("${workout.title} has no coach") // From here on, workout and coach are non-null. No ?. needed. return "Starting ${workout.title} with ${coach.name}" } //sampleEnd fun main() { println(startMessage(null)) println(startMessage(Profile("Kai", Workout("Intervals", Coach("Maya"))))) println(startMessage(Profile("Kai", Workout("Tempo run", null)))) }

The third call crashes on purpose. A workout without a coach is a bug in our data, not a normal state, so we throw instead of returning. That's the rule of thumb: use ?: return when “missing” is normal, and ?: throw when “missing” means something has gone wrong.

Why can return appear in the middle of an expression?

Docs: Exceptions → The Nothing type: “a built-in type that is a subtype of all other types”.In Kotlin, return and throw are expressions, like if and try. Their type is Nothing, a special type meaning “this never produces a value, because control leaves here”. Nothing fits wherever any type is expected, so Workout? ?: Nothing comes out as plain Workout. That's why workout above is non-null with no extra checks. You don't need to write Nothing yourself yet. Just recognise why the pattern type-checks.

AI/Java-flavoured smells to spot
  • if (x != null) x else "default": that is exactly x ?: "default"
  • var result = "default", then if (x != null) result = x
  • Nested if (a != null) { if (b != null) { … } } where guard clauses (?: return) would keep the code flat
  • if (x == null) throw … followed by x!! later

Quick check

1. What is "45min".toIntOrNull() ?: 30?

"45min" isn't a valid number, so toIntOrNull() gives null and Elvis falls back to 30.

2. val bonus: Int? = 5 and val base = 100. What is bonus ?: 0 + base?

+ binds tighter, so it's bonus ?: (0 + base). bonus isn't null, so the result is 5. Parenthesise when you mix them.

3. Why is val w = profile?.currentWorkout ?: return allowed?

return and throw are expressions whose type is Nothing, which fits anywhere. So the Elvis type-checks, and the result is non-null.

4. After val workout = profile?.currentWorkout ?: return, what type is workout?

The only way past that line is with a non-null value, so workout is a plain Workout. That's the whole point of a guard clause.
