Enum classes: properties and entries

Stateful enumerations, the zero-allocation entries API, and exhaustive compiler checks.

Warm-up

    CheckIt is completely ignored by generated equals(), hashCode(), toString(), and copy().
  2. How do you create a modified copy of an immutable data class instance?
    CheckUsing the copy() function with named arguments: val updated = item.copy(price = 10.0).

Enums are full-featured classes in Kotlin

Docs: Enum classes. Each enum entry is an instance of the enum class.In Kotlin, enums are not just primitive integers; they can hold constructor properties, define functions, and implement interfaces:

enum class Difficulty(val multiplier: Double, val label: String) { EASY(1.0, "Beginner"), MEDIUM(1.5, "Intermediate"), HARD(2.0, "Advanced"); // semicolon required if defining member functions fun caloriesFor(base: Int): Int = (base * multiplier).toInt() }

The modern entries property (Kotlin 1.9+)

Previously in Java and older Kotlin, iterating over enums required calling Difficulty.values(). Every call to .values() allocated a brand new array on the heap, causing garbage collection pauses in performance-critical code (like Android rendering loops or high-frequency DSA algorithms).

Modern Kotlin introduces entries, which returns a pre-allocated, read-only list with zero heap allocations:

// Old / Java habit: allocates a new array every call for (d in Difficulty.values()) { ... } // Modern Idiomatic Kotlin: zero allocations! for (d in Difficulty.entries) { println("${d.name}: ${d.label}") }

Exhaustive when without else

When you evaluate an enum inside a when expression, the Kotlin compiler checks that every single enum case is handled. Do not add an else branch unless necessary:

fun targetHeartRate(d: Difficulty): Int = when (d) { Difficulty.EASY -> 120 Difficulty.MEDIUM -> 150 Difficulty.HARD -> 175 // NO else needed! If someone adds Difficulty.EXTREME later, // the compiler will immediately raise an error pointing here! }

Quick check

Why should you prefer MyEnum.entries over MyEnum.values() in modern Kotlin?

entries returns a pre-cached EnumEntries list, avoiding the heap array allocation overhead of values().

Heart Rate Zone Enum

Define an enum class CardioZone(val minBpm: Int, val maxBpm: Int) with entries:

  • REST(0, 99)
  • FAT_BURN(100, 139)
  • CARDIO(140, 169)
  • PEAK(170, 220)

Inside the enum, define a member function fun contains(bpm: Int): Boolean = bpm in minBpm..maxBpm.

In main, write a top-level function classify(bpm: Int): CardioZone that iterates over CardioZone.entries and returns the first matching zone (or REST if none match).

// 1. Define CardioZone enum // 2. Define classify function fun main() { println(classify(72)) println(classify(145)) println(classify(180)) }

Replace Java Integer Constants with an Enum

Refactor this legacy integer-constant system into a clean stateful WorkoutType enum with an exhaustive when expression.

// Refactor these raw constants into a WorkoutType enum: const val TYPE_RUN = 1 const val TYPE_CYCLE = 2 const val TYPE_SWIM = 3 fun getMultiplier(type: Int): Double { return when (type) { TYPE_RUN -> 1.0 TYPE_CYCLE -> 0.7 TYPE_SWIM -> 1.2 else -> throw IllegalArgumentException("Unknown type: $type") } } fun main() { val types = listOf(TYPE_RUN, TYPE_CYCLE, TYPE_SWIM) for (t in types) { println("Type $t multiplier: ${getMultiplier(t)}") } }
Hint 1: Enum class with propertyDefine enum class WorkoutType(val multiplier: Double) { RUN(1.0), CYCLE(0.7), SWIM(1.2) }.
Hint 2: Replace manual when mappingRemove the separate when block and implement fun getMultiplier(type: WorkoutType): Double = type.multiplier by reading the enum property directly.
