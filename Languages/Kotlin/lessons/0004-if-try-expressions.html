if and try as expressions

Why Kotlin has no ternary operator, and how to stop assigning variables in every branch.

Statements vs expressions

A statement does something. An expression produces a value. In many languages if is only a statement, so to choose between two values you need a separate operator, the ternary cond ? a : b.

Docs: Control flow → If expression: “The if expression serves the same purpose as the ternary operator … found in other languages.”In Kotlin, if is an expression, so a ternary would just be a second way to write the same thing. That's why Kotlin doesn't have one.

The pattern this replaces

In lesson 1.1 you wrote this to keep zone a val:

Before: assign in each branch

val zone: String if (heartRate > 160) { zone = "Peak" } else { zone = "Cardio" }

After: if produces the value

val zone = if (heartRate > 160) "Peak" else "Cardio"

One line, the type is inferred, and the name appears once. You can't accidentally forget to assign it in one branch.

Two rules

1. When if produces a value, else is required. Otherwise, what would the value be when the condition is false?

fun main() { //sampleStart val heartRate = 120 val zone = if (heartRate > 160) "Peak" // ❌ compile error: no else println(zone) //sampleEnd }

2. A branch can be a block, and its value is the last expression in it. Lines before that can do other work, like logging:

fun main() { //sampleStart val minutes = 45 val label = if (minutes > 30) { println("Long session logged") "Long" // ← this is the value } else { "Short" } println(label) //sampleEnd }

Return the expression, not from each branch

From Coding conventions → Conditional statements: “Prefer using the expression form of try, if, and when.”Because if produces a value, a function can return it directly:

Before

if (isPaused) return "Paused" else return "Running"

After

return if (isPaused) "Paused" else "Running"

With three or more branches, if … else if … else still works as an expression. But the conventions recommend when once there are three or more options, which is the next lesson (if versus when).

try is an expression too

Docs: Exceptions → try-catch. Also: “Kotlin treats all exceptions as unchecked”, so you're never forced to catch.The same idea applies to try. Its value is the last expression of the try block if nothing goes wrong, or of the catch block if an exception is caught. A finally block always runs, but it doesn't change the value.

fun main() { //sampleStart val input = "12a" // e.g. typed into a reps field val reps = try { input.toInt() } catch (e: NumberFormatException) { 0 } println(reps) // 0 //sampleEnd }

No var reps declared up front and patched in both blocks. It's one val with one source of truth. (For this exact case, input.toIntOrNull() is even better. It's a null-safety tool, coming in Section 2.)

throw is an expression too, of type Nothing (The Nothing type). So val bpm = if (ok) reading else throw IllegalStateException("No signal") compiles. You'll use this a lot with ?: in lesson 2.2.

AI/Java-flavoured smells to spot
  • A variable declared first, then assigned in every if/else or try/catch branch
  • if (c) return a else return b instead of return if (c) a else b
  • if (cond) true else false, which is just cond

Quick check

1. What happens with val zone = if (hr > 150) "High"?

When if is used for its value, every path must produce one, so else is required. Kotlin won't invent a default for you.

2. With minutes = 45, what is label?

val label = if (minutes > 30) { println("Long session logged") "Long" } else { "Short" }

A block's value is its last expression. The println runs, but it's not the value.

3. What is reps?

val reps = try { "12a".toInt() } catch (e: NumberFormatException) { 0 } finally { 99 }

"12a".toInt() throws, so the catch block's value 0 is used. finally always runs, but it never changes the result.

4. Which line is the idiomatic way to return one of two strings?

Kotlin has no ternary, so (b) doesn't compile. (c) works but repeats return. (d) works, but the conventions prefer if for two-way choices.
