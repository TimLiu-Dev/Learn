it-based scopes: let & also

Execute operations on non-null values and perform transparent side-effects without mutating the chain.

Warm-up: Rapid Recall

  1. What is the default parameter name for a single-argument lambda in Kotlin?
    Checkit. You can also give it an explicit name: { user -> ... }.
  2. Why does safe-call user?.name return String? instead of String?
    CheckBecause if the receiver (user) is null, the safe-call short-circuits and evaluates to null.
  3. What is the main difference between an expression and a statement?
    CheckAn expression evaluates to a value (which can be assigned or returned); a statement performs an action but returns no useful value.

The Concept: The it-Based Scope Functions

Kotlin provides five scope functions (let, also, apply, run, with). Their sole purpose is to execute a block of code within the context of an object. The difference lies in two questions:

  1. How is the context object referenced inside the lambda? (it vs this)
  2. What does the whole scope function return? (The lambda result vs the context object)

1. let: Transform Context & Execute on Non-Null

Inside let, the context object is passed as lambda argument it. let returns the result of the lambda:

val email: String? = getUserEmail() // Safe call + let: block only executes if email is NOT null val isCompanyDomain: Boolean = email?.let { // 'it' is guaranteed non-null String here (smart cast) it.endsWith("@company.com") } ?: false

Use let for:

  • Executing a code block only on non-null values: nullable?.let { nonNull -> ... }.
  • Introducing a localized variable scope to prevent polluting outer variables.
  • Mapping/transforming a value at the end of a chain.

2. also: Transparent Side-Effects

Inside also, the context object is also it. However, also returns the context object itself (ignoring whatever the lambda returns):

fun createTempFile(prefix: String): File { return File.createTempFile(prefix, ".tmp").also { file -> // Perform side-effect: logging, metrics, or validation println("Created temp file: ${file.absolutePath}") } // Returns the File instance! }

Think of also as: "And also do this side effect with the object, then return it". It is ideal for logging, telemetry, or assert checks in fluent builder chains.

Quick Check

Given: val x = "hello".also { it.length * 2 }. What is the value and type of x?

also always returns the context object itself ("hello"), regardless of what the lambda computes inside. If you wanted the computed 10, you would use let.

User Registration Audit Pipeline

Implement a function processUserRegistration(rawEmail: String?): String?:

  1. If rawEmail is null or blank, return null.
  2. Otherwise, trim the email and convert it to lowercase using let.
  3. Log the event by using also to print "Audit: Registering user <sanitized_email>".
  4. Return the sanitized email string.
fun processUserRegistration(rawEmail: String?): String? { // Write your implementation using .takeIf, .let, and .also return null } fun main() { val res1 = processUserRegistration(" Alice@Acme.COM ") val res2 = processUserRegistration(" ") val res3 = processUserRegistration(null) println("Result 1: $res1") println("Result 2: $res2") println("Result 3: $res3") }
Hint 1: Safe normalization pipelineChain rawEmail?.trim()?.takeIf { it.isNotBlank() }?.let { it.lowercase() } to sanitize the input.
Hint 2: Side-effect loggingAppend ?.also { sanitized -> println("Audit: Registering user $sanitized") } to log without altering the returned String?.
