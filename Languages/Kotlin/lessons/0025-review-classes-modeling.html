Warm-up: Rapid Recall

  1. When should you use data class vs a regular class?
    CheckUse data class for immutable data holders (DTOs, state models) where structural equality (==) and copying are required. Use a regular class when encapsulation, inheritance, or mutable identity matter.
  2. What is the difference between sealed interface and enum class?
    CheckAn enum has fixed singletons with identical structure. A sealed interface allows subtypes to hold different per-instance properties (e.g. Success(data) vs Error(msg)).
  3. What runtime memory overhead does a @JvmInline value class incur?
    CheckZero overhead; the compiler inlines the underlying primitive/reference directly on the JVM stack.

Quick check

Which of the following is considered an anti-pattern in modern Kotlin?

Writing manual getter/setter methods is redundant and non-idiomatic in Kotlin; properties with custom accessors or default getters should always be used.

Complete Feature Architecture

Model an athlete tracking feature using clean Kotlin constructs:

  1. A value class @JvmInline value class SessionId(val raw: String)
  2. An enum class ActivityType(val icon: String) with RUN("🏃") and CYCLE("🚴")
  3. A data class SessionRecord(val id: SessionId, val type: ActivityType, val distanceKm: Double)
  4. A sealed interface SyncState with:
    • data object Pending : SyncState
    • data class Completed(val record: SessionRecord) : SyncState
  5. A function describeSync(state: SyncState): String that returns "Syncing..." for Pending, and "${record.type.icon} ${record.id.raw}: ${record.distanceKm} km" for Completed

The Java Architecture Special

Refactor this legacy Java-style code into idiomatic Kotlin using primary constructors, data classes, and clean companion object factories.

class AthleteProfile { private var name: String private var maxHr: Int constructor(name: String, maxHr: Int) { this.name = name this.maxHr = maxHr } fun getName(): String = this.name fun getMaxHr(): Int = this.maxHr override fun toString(): String { return "AthleteProfile[name=" + name + ", maxHr=" + maxHr + "]" } override fun equals(other: Any?): Boolean { if (this === other) return true if (other !is AthleteProfile) return false return this.name == other.name && this.maxHr == other.maxHr } override fun hashCode(): Int { return 31 * name.hashCode() + maxHr } } fun main() { val p1 = AthleteProfile("Alex", 190) val p2 = AthleteProfile("Alex", 190) println("Equal: ${p1 == p2}") println(p1) }

Hint 2: Automatic compiler synthesisKotlin automatically generates equals, hashCode, toString, copy, and destructuring components for all primary constructor properties.
