What data class generates for free

Docs: Data classes. Primary constructor parameters must be val or var.In modern domain modeling, most classes are holders for immutable state (DTOs, UI states, database entities). By adding the data keyword, the compiler automatically generates:

  • equals() and hashCode(): structural value comparison (== works out of the box)
  • toString(): readable output like Workout(title=Tempo, km=10.0)
  • copy(): creates modified copies without mutating the original object
  • componentN(): enables destructuring declarations (val (title, km) = workout)
data class Workout(val title: String, val km: Double) val w1 = Workout("Tempo", 10.0) val w2 = Workout("Tempo", 10.0) println(w1 == w2) // true! (structural equality) // Non-destructive mutation using copy(): val w3 = w1.copy(km = 12.0) println(w3) // Workout(title=Tempo, km=12.0)

The #1 Data Class Trap: Body Properties

The compiler uses only properties declared in the primary constructor header for equals, hashCode, toString, and copy. Any property declared in the class body is completely ignored by generated methods:

data class Athlete(val name: String) { var score: Int = 0 // WARNING: Ignored in equals() and copy()! } val a1 = Athlete("Sam").apply { score = 100 } val a2 = Athlete("Sam").apply { score = 20 } println(a1 == a2) // prints TRUE! Even though score is totally different!
Spring & Android Rule

Never declare state properties in a data class body if they affect identity or equality. Keep all data properties in the primary constructor header.

Quick check

Which of the following is ILLEGAL for a data class in Kotlin?

Data classes cannot be open or abstract. Generated copy and equals cannot safely guarantee symmetry across inheritance hierarchies.

Fix the Identity Bug

This code has a major bug: user1 and user2 have different heart rate readings, but the system claims they are equal because heartRate was placed in the body! Fix the class so all properties participate in equality, copying, and string representations.

data class UserSession(val username: String) { var heartRate: Int = 0 var deviceTag: String = "Watch" } fun main() { val user1 = UserSession("Elena").apply { heartRate = 165 deviceTag = "ChestStrap" } val user2 = UserSession("Elena").apply { heartRate = 110 deviceTag = "WristWatch" } // BUG: prints true! Fix it so it prints false: println("Are equal: ${user1 == user2}") // Expected toString() should show all fields: println(user1) }
