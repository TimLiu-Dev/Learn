Grouping and aggregating

groupBy, single-pass partition, accumulator fold, and high-performance sumOf.

The Concept: Aggregating Collections

1. groupBy vs groupingBy

groupBy { keySelector } creates a Map<K, List<V>> immediately:

val words = listOf("apple", "banana", "apricot", "cherry", "blueberry") val byFirstLetter: Map<Char, List<String>> = words.groupBy { it.first() } // {'a': ["apple", "apricot"], 'b': ["banana", "blueberry"], 'c': ["cherry"]}

If you only need to count or sum each group, groupingBy { ... }.eachCount() does it without allocating intermediate lists!

2. partition: Single-Pass Split

Splits a collection into two lists in a single iteration based on a predicate, returning a Pair<List<T>, List<T>>:

val numbers = listOf(1, 2, 3, 4, 5, 6) val (evens, odds) = numbers.partition { it % 2 == 0 } // evens = [2, 4, 6], odds = [1, 3, 5]

3. fold vs reduce

  • fold(initial) { acc, elem -> ... }: takes an explicit initial accumulator value. Safe to call on empty collections (returns initial).
  • reduce { acc, elem -> ... }: uses the first element as the initial accumulator. Throws UnsupportedOperationException on an empty collection!
val prices = listOf(10, 25, 50) val totalWithShipping = prices.fold(initial = 5) { acc, price -> acc + price } // 90

4. Primitive-Friendly Reductions: sumOf

Instead of map { it.amount }.sum() which allocates an intermediate list of boxed numbers, use inline sumOf:

data class Transaction(val id: String, val amountCents: Long) // Zero intermediate list allocations: val totalVolume: Long = transactions.sumOf { it.amountCents }

Quick Check

What happens if you execute emptyList<Int>().reduce { acc, x -> acc + x }?

reduce has no initial value to return when the collection is empty. Prefer fold(0) { acc, x -> acc + x } or sumOf { it } to handle empty collections safely.
