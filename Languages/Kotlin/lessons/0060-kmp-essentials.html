Kotlin Multiplatform (KMP) essentials

Pillar 3: Source-set hierarchies, expect/actual vs common interfaces, and pure multiplatform domain design.

Warm-up: Rapid Recall

  1. What layers of an app are typically shared in commonMain across Android and iOS?
    CheckDomain models, business rules, networking (Ktor), serialization (kotlinx.serialization), persistence (SQLDelight / Room KMP), and state holders / ViewModels.
  2. How does KMP on iOS differ from JS-bridge frameworks?
    CheckKotlin/Native compiles shared Kotlin code directly into native ARM64 framework binaries (.xcframework) with direct Objective-C/Swift interop and zero JS bridge.

The Concept: expect/actual vs Common Interfaces

In KMP, commonMain cannot import java.* or android.* APIs. To bridge platform capabilities, you have two tools:

// 1. Low-level platform hook via expect / actual: // commonMain: expect fun currentPlatformName(): String // androidMain: actual fun currentPlatformName(): String = "Android ${android.os.Build.VERSION.SDK_INT}" // iosMain: actual fun currentPlatformName(): String = UIDevice.currentDevice.systemName()

Senior Architecture Rules in KMP

  1. Prefer Common Interfaces + Constructor Injection over expect class: Define interface ClockProvider or interface SecureStore in commonMain and inject platform implementations. Unlike expect class, regular interfaces can be swapped with lightweight fakes in commonTest!
  2. Use reflectionless libraries: Kotlin/Native on iOS does not have full JVM runtime reflection—use compiler-plugin-powered kotlinx.serialization (not Jackson/Gson), Ktor Client, and kotlinx-datetime.
  3. Use actual typealias when an existing platform class already matches the exact expect contract.

Quick Check

1. Why do senior KMP teams prefer defining a regular interface SecureStorage in commonMain over declaring expect class SecureStorage?

An expect class locks every test to the single actual class compiled for that target. A regular interface in commonMain lets unit tests pass a fast, deterministic FakeSecureStorage without touching Keychain or EncryptedSharedPreferences.

2. Why does commonMain use kotlinx.serialization instead of Jackson or Gson?

kotlinx.serialization uses a Kotlin compiler plugin to generate type-safe serializers at compile time, working identically across JVM, Android, iOS Native, JS, and Wasm.

3. Which import will immediately fail to compile inside src/commonMain/kotlin?

java.util.* belongs strictly to the JDK and does not exist on iOS/Native or Wasm targets. (Note: Kotlin 2.0+ introduced experimental multiplatform kotlin.uuid.Uuid in the standard library!)

Practice: Hands-On Exercises

Exercise 1 · Write from blank

Testable KMP Platform Abstraction & Fake

Design a KMP-ready token manager that works in commonMain and can be tested with an in-memory fake:

  1. interface KeyValueStore with fun put(key: String, value: String) and fun get(key: String): String?.
  2. class InMemoryKeyValueStore : KeyValueStore backed by a private mutableMapOf<String, String>().
  3. class SessionRepository(private val store: KeyValueStore) with fun saveToken(token: String) (requires token.isNotBlank(), stores under "auth_token") and val isLoggedIn: Boolean (true when stored token is non-null).
// 1. Declare common interface KeyValueStore // 2. Declare InMemoryKeyValueStore : KeyValueStore // 3. Declare SessionRepository(private val store: KeyValueStore) fun main() { val fakeStore = InMemoryKeyValueStore() val repo = SessionRepository(fakeStore) check(!repo.isLoggedIn) repo.saveToken("jwt_abc_123") check(repo.isLoggedIn) check(fakeStore.get("auth_token") == "jwt_abc_123") check(runCatching { repo.saveToken(" ") }.isFailure) println("All KMP abstraction & fake checks passed!") }
HintMake val isLoggedIn: Boolean get() = store.get("auth_token") != null a computed property with a custom getter so it always reflects the latest store state!
Exercise 2 · Refactor

Decouple JVM-Bound Domain Model for commonMain

LegacyDomainEvent cannot move into commonMain because it directly instantiates java.text.SimpleDateFormat and java.util.Date. Refactor it into an immutable pure-Kotlin data class DomainEvent(val id: String, val timestampMs: Long) plus an extension function fun DomainEvent.formatWith(formatter: (Long) -> String): String.

// REFACTOR THIS JVM-COUPLED CLASS INTO KMP-SAFE DomainEvent + formatWith EXTENSION: class LegacyDomainEvent(val id: String, val timestampMs: Long) { fun getFormattedDate(): String { val sdf = java.text.SimpleDateFormat("yyyy-MM-dd") return sdf.format(java.util.Date(timestampMs)) } } fun main() { // Update main() after refactoring to DomainEvent + formatWith: // val event = DomainEvent("evt_01", 1700000000000L) // val formatted = event.formatWith { ms -> "${event.id}@$ms" } // check(formatted == "evt_01@1700000000000") println("Refactor LegacyDomainEvent into pure KMP DomainEvent!") }
Hintfun DomainEvent.formatWith(formatter: (Long) -> String): String = formatter(timestampMs) keeps formatting rules injectable per platform while leaving DomainEvent 100% multiplatform.
