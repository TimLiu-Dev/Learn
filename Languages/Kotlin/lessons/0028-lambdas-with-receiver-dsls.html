Normal Lambda vs Lambda with Receiver

Docs: Function literals with receiver. Receiver type is specified before the dot: T.() -> R.In a normal lambda (StringBuilder) -> Unit, you must refer to the argument as it:

fun regularBuild(action: (StringBuilder) -> Unit): String { val sb = StringBuilder() action(sb) return sb.toString() } // Inside the lambda, you must type "it.append(...)": regularBuild { it.append("Hello"); it.append(" World") }

A lambda with receiver (StringBuilder.() -> Unit) changes the rules: the argument becomes this inside the lambda, allowing you to call its methods directly without any prefix:

fun idiomaticBuild(action: StringBuilder.() -> Unit): String { val sb = StringBuilder() sb.action() // calls action with 'sb' as receiver (this) return sb.toString() } // Inside the lambda, methods are called directly! idiomaticBuild { append("Hello") append(" World") }

The Standard Library Powerhouses

Kotlin's standard library uses lambdas with receiver everywhere:

  • buildString { append("Day "); append(1) }: Replaces manual StringBuilder creation.
  • buildList { add("Run"); add("Swim") }: Constructs immutable lists with builder syntax.
  • Scope function apply: val button = Button().apply { text = "Save"; isEnabled = true }.
Compose & Gradle Connection

In Jetpack Compose, Column { Text("Hello") } and in Gradle dependencies { implementation(...) } work precisely because they are lambdas with receiver on layout and configuration scopes!
