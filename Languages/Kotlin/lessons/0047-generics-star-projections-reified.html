Star projections & reified type parameters

Overcoming JVM type erasure: star projections (*) and runtime type inspection with reified.

Warm-up: Rapid Recall

  1. What happens to generic type arguments like <String> when compiled to JVM bytecode?
    CheckThey are erased (type erasure); List<String> and List<Int> both become raw List at runtime.
  2. Why does fun <T> checkType(obj: Any) = obj is T fail to compile?
    CheckBecause T is erased at runtime, so the JVM cannot perform instanceof T.

The Concept: Type Erasure & Kotlin's Solutions

1. Reified Type Parameters

Because Kotlin supports inline functions, the compiler can inline the actual bytecode at the call site. This allows Kotlin to preserve the concrete type using the reified keyword:

inline fun <reified T> isInstance(value: Any?): Boolean { return value is T // Legal! T is reified } inline fun <reified T> printTypeName() { println("Type is: ${T::class.simpleName}") // Direct reflection on T! }

Reified generics are heavily used in Android and Spring Boot:

// Android Intent navigation: inline fun <reified T : Activity> Context.startActivity() { startActivity(Intent(this, T::class.java)) } // JSON deserialization (Jackson / kotlinx.serialization): inline fun <reified T> parseJson(json: String): T = jsonMapper.decodeFromString(json)

2. Star Projections (*)

When you know nothing about the type argument, but still want type-safe operations, use star projection *:

  • List<*> means List<out Any?>: you can read elements as Any?, but cannot write.
  • MutableList<*>: you can read Any?, but writing is forbidden (compiler cannot know what type is accepted).
fun printListSize(list: List<*>) { println("Count: ${list.size}") for (item in list) { println(item) // item is typed as Any? } }

Quick Check

Can a regular non-inlined function have a reified type parameter?

reified works specifically because inlining copies the function body into the calling site where the type argument is known at compile time.

Type-Safe Service Locator with Reified Generics

Implement ServiceRegistry:

  1. An internal map val services = mutableMapOf<KClass<*>, Any>().
  2. inline fun <reified T : Any> register(instance: T) that stores instance keyed by T::class.
  3. inline fun <reified T : Any> resolve(): T that retrieves and casts the service, throwing IllegalStateException("Service not found") if missing.
import kotlin.reflect.KClass class ServiceRegistry { val services = mutableMapOf<KClass<*>, Any>() // 1. register // 2. resolve } class UserRepository class PaymentService fun main() { val registry = ServiceRegistry() registry.register(UserRepository()) registry.register(PaymentService()) val repo = registry.resolve<UserRepository>() println("Resolved service: ${repo::class.simpleName}") }
Hint 1: Reified type registrationDeclare inline fun <reified T : Any> ServiceRegistry.register(instance: T).
Hint 2: Class token lookupAccess the class token directly via T::class to key into an internal MutableMap<KClass<*>, Any>.
