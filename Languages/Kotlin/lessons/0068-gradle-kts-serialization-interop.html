Gradle Kotlin DSL, Serialization & JVM Interop

Reading and authoring build.gradle.kts + gradle/libs.versions.toml, schema-safe kotlinx.serialization rules, and @JvmOverloads / @JvmName / @JvmStatic / @Throws.

Warm-up: Rapid Recall

  1. Why do modern Android repositories store dependency coordinates in gradle/libs.versions.toml instead of repeating strings across module build.gradle.kts files?
    CheckVersion catalogs give every module type-safe autocomplete (libs.kotlinx.serialization.json), keep plugin/library versions synchronized in one place, and let Renovate/Dependabot update dependencies cleanly.
  2. Why is kotlinx.serialization preferred over reflection-based JSON mappers (such as Gson) in modern Kotlin?
    Checkkotlinx.serialization generates encoders/decoders at compile time: it respects Kotlin non-null types and default property values, avoids slow runtime reflection, and supports Kotlin Multiplatform.

The Concept: Tooling & Boundary Kotlin

1. Gradle Kotlin DSL (build.gradle.kts) & Version Catalogs (libs.versions.toml)

Hyphens (-) and underscores (_) in TOML alias keys automatically become dots (.) in Kotlin DSL: kotlinx-serialization-json becomes libs.kotlinx.serialization.json.Every real Android codebase mixes Gradle Kotlin DSL build scripts with a TOML Version Catalog. Even though Android Studio's autocomplete helps, you must be able to read and write these blocks without guessing:

// gradle/libs.versions.toml [versions] kotlin = "2.3.10" coroutines = "1.10.1" serializationJson = "1.8.0" [libraries] kotlinx-coroutines-android = { group = "org.jetbrains.kotlinx", name = "kotlinx-coroutines-android", version.ref = "coroutines" } kotlinx-serialization-json = { group = "org.jetbrains.kotlinx", name = "kotlinx-serialization-json", version.ref = "serializationJson" } [bundles] async = ["kotlinx-coroutines-android", "kotlinx-serialization-json"] [plugins] kotlin-serialization = { id = "org.jetbrains.kotlin.plugin.serialization", version.ref = "kotlin" } // app/build.gradle.kts (Kotlin DSL — uses plugins / dependencies blocks & Receiver Lambdas!) plugins { alias(libs.plugins.android.application) alias(libs.plugins.kotlin.serialization) } kotlin { jvmToolchain(17) // Aligns Kotlin + Java bytecode targets cleanly } dependencies { implementation(libs.bundles.async) ksp(libs.room.compiler) // Prefer KSP over legacy kapt for 2x+ faster codegen }

2. Evolution-Safe kotlinx.serialization Configuration

Mobile apps live on user devices long after backend APIs evolve. Never ship a bare Json decoder in production — configure it defensively so unknown backend fields or unexpected nulls degrade to Kotlin defaults instead of crashing active users:

import kotlinx.serialization.* import kotlinx.serialization.json.* @Serializable data class ApiProfile( val id: String, @SerialName("display_name") val displayName: String, val tier: String = "free" // Used automatically if field is omitted OR coerced from null! ) val networkJson = Json { ignoreUnknownKeys = true // Backend added "beta_flag"? Old app doesn't crash! coerceInputValues = true // Null for a non-null field with default ("tier": null) -> uses "free" explicitNulls = false // Skip emitting null fields on wire payloads }

3. JVM & Android Interop Annotations (Try Live!)

Android framework APIs (like custom View classes) and legacy Java callers do not understand Kotlin default arguments, top-level functions, or erased generic overloads. Four stdlib annotations bridge the gap cleanly:

  • @JvmOverloads: Generates separate Java/JVM overloaded methods or constructors for parameters with default values.
  • @JvmName("..."): Fixes JVM type erasure clashes when two Kotlin functions share a name and parameter raw type (like List<Int> vs List<String>), and renames ugly FileKt facade classes (@file:JvmName("NetUtils")).
  • @JvmStatic: Turns a companion object or object function into a true static JVM method (callable as Helper.build() without .Companion).
  • @Throws(ExceptionClass::class): Declares checked exceptions in bytecode so Java callers can catch them cleanly.
import java.io.IOException import java.lang.reflect.Modifier // Without @JvmName, JVM type erasure rejects having both List<Int> and List<String> overloads! @JvmName("sumScores") fun summarize(values: List<Int>): String = "scores=${values.sum()}" @JvmName("joinLabels") fun summarize(values: List<String>): String = "labels=${values.joinToString(",")}" class UrlBuilder { companion object { @JvmStatic @JvmOverloads fun buildPath(resource: String, version: Int = 2, includeTrailingSlash: Boolean = false): String { val tail = if (includeTrailingSlash) "/" else "" return "/v$version/$resource$tail" } @JvmStatic @Throws(IOException::class) fun validateHost(host: String): String { val trimmed = host.trim() if (" " in trimmed || trimmed.isBlank()) throw IOException("Invalid host: '$host'") return trimmed.lowercase() } } } fun main() { println(summarize(listOf(10, 20, 12))) println(summarize(listOf("auth", "feed"))) // Verify @JvmStatic + @JvmOverloads emitted the 1-arg static bridge method on UrlBuilder val singleArgMethod = UrlBuilder::class.java.getMethod("buildPath", String::class.java) check(Modifier.isStatic(singleArgMethod.modifiers)) println("Java 1-arg static call -> " + singleArgMethod.invoke(null, "users")) println("Checked host -> " + UrlBuilder.validateHost(" API.Example.COM ")) val rejected = runCatching { UrlBuilder.validateHost("bad host.com") }.exceptionOrNull() check(rejected is IOException) }

Quick Check

1. Why should an Android app configure Json { ignoreUnknownKeys = true; coerceInputValues = true } for backend API responses?

Defensive Json configuration lets backend teams add fields safely without breaking older mobile app versions already installed on devices.

2. Two top-level functions fun export(ids: List<Int>) and fun export(names: List<String>) fail to compile together on the JVM. Why, and what fixes it cleanly?

Adding @JvmName("exportIds") / @JvmName("exportNames") keeps clean overloaded Kotlin syntax at call sites while emitting distinct Java method names.

3. Which constructor pattern is idiomatic for a Kotlin custom Android View instantiated both from XML layout inflation and programmatically in Java/Kotlin?

Without @JvmOverloads, Android XML inflation crashes with NoSuchMethodException because the 2-argument Java constructor does not exist.

Practice: Hands-On Exercises

Exercise 1 · Write from blank

Version Catalog Resolver & JVM-Safe Bridge

Implement two pure-Kotlin utilities below main's header comments:

  1. fun resolveCatalogCoordinates(toml: String): Map<String, String> that reads a simplified TOML catalog containing [versions] and [libraries] sections (with key = "val" and alias = { group = "g", name = "n", version.ref = "verKey" }) and returns a map of normalized Gradle Kotlin DSL accessor keys (e.g., "libs.kotlinx.coroutines.core") to "g:n:version".
  2. object BuildConfigBridge with:
    • @JvmStatic @JvmOverloads fun formatEndpoint(baseUrl: String, version: Int = 2, strict: Boolean = true): String returning "$baseUrl/v$version?strict=$strict"
    • @JvmStatic @Throws(IllegalArgumentException::class) fun requireVersionTag(tag: String): String throwing IllegalArgumentException unless tag.startsWith("v") and length > 1, returning tag
  3. Two top-level overloaded functions disambiguated for JVM bytecode using @JvmName:
    • @JvmName("totalInts") fun total(items: List<Int>): Int returning the sum of ints
    • @JvmName("totalStrings") fun total(items: List<String>): Int returning the total character count across all strings
import java.lang.reflect.Modifier // Write resolveCatalogCoordinates, BuildConfigBridge, and both total(...) overloads here: fun main() { val sampleToml = """ [versions] coroutines = "1.10.1" serialization = "1.8.0" [libraries] kotlinx-coroutines-core = { group = "org.jetbrains.kotlinx", name = "kotlinx-coroutines-core", version.ref = "coroutines" } kotlinx-serialization-json = { group = "org.jetbrains.kotlinx", name = "kotlinx-serialization-json", version.ref = "serialization" } """.trimIndent() val coords = resolveCatalogCoordinates(sampleToml) check(coords["libs.kotlinx.coroutines.core"] == "org.jetbrains.kotlinx:kotlinx-coroutines-core:1.10.1") { "Got $coords" } check(coords["libs.kotlinx.serialization.json"] == "org.jetbrains.kotlinx:kotlinx-serialization-json:1.8.0") val bridgeMethod = BuildConfigBridge::class.java.getMethod("formatEndpoint", String::class.java) check(Modifier.isStatic(bridgeMethod.modifiers)) check(bridgeMethod.invoke(null, "https://api.example.com") == "https://api.example.com/v2?strict=true") check(BuildConfigBridge.requireVersionTag("v14") == "v14") check(runCatching { BuildConfigBridge.requireVersionTag("14") }.isFailure) check(total(listOf(4, 6, 10)) == 20) check(total(listOf("kt", "dsl")) == 5) println("Catalog resolver & JVM interop verified!") }
Hint 1: Simple TOML line parserTrack current section ("[versions]" vs "[libraries]"). For library lines, extract quoted values for group, name, and version.ref using Regex("""(\w+(?:\.\w+)?)\s*=\s*"([^"]+)""""), and map alias key with "libs." + alias.replace('-', '.').
Hint 2: JVM annotationsPut @JvmStatic @JvmOverloads directly on formatEndpoint(...) inside object BuildConfigBridge so reflection finds the 1-arg static method formatEndpoint(String).
Exercise 2 · Refactor

Harden Fragile Decoding & Collapse Redundant Overloads

Refactor this brittle Java-ported API decoder so it supports unknown backend keys and null/omitted defaulted fields safely (matching ignoreUnknownKeys + coerceInputValues semantics), collapses the three manual overloads using @JvmOverloads, and gives the erased JVM helper clean disambiguation.

import java.lang.reflect.Modifier data class UserDto(val id: String, val displayName: String, val role: String = "member") // REFACTOR: Collapse 3 manual overloads into ONE @JvmOverloads + @JvmStatic helper, // and make decoding tolerate unknown keys + null/missing "role" cleanly! class LegacyDecoder { companion object { fun decode(raw: Map<String, String?>): UserDto = decode(raw, false) fun decode(raw: Map<String, String?>, ignoreUnknown: Boolean): UserDto = decode(raw, ignoreUnknown, false) fun decode( raw: Map<String, String?>, ignoreUnknown: Boolean, coerceNullRole: Boolean ): UserDto { val allowed = setOf("id", "display_name", "role") if (!ignoreUnknown) { val unknown = raw.keys - allowed require(unknown.isEmpty()) { "Unknown keys: $unknown" } } val id = requireNotNull(raw["id"]) { "Missing id" } val name = requireNotNull(raw["display_name"]) { "Missing display_name" } val rawRole = raw["role"] val role = if (rawRole != null) rawRole else if (coerceNullRole) "member" else error("Role cannot be null!") return UserDto(id, name, role) } } } fun main() { val rollingApiPayload = mapOf( "id" to "u_42", "display_name" to "Ada", "role" to null, "new_backend_experiment" to "enabled" ) // After refactoring, default 1-arg static call ignores unknown keys & coerces null role -> "member"! val oneArg = LegacyDecoder::class.java.getMethod("decode", Map::class.java) check(Modifier.isStatic(oneArg.modifiers)) val user = oneArg.invoke(null, rollingApiPayload) as UserDto check(user == UserDto("u_42", "Ada", "member")) { "Got $user" } // Strict mode remains opt-in when caller disables ignoreUnknown check(runCatching { LegacyDecoder.decode(rollingApiPayload, ignoreUnknown = false) }.isFailure) println("Refactored tolerant decoder verified: $user") }
HintDelete the two delegating overloads, annotate the single fun decode(raw: Map<String, String?>, ignoreUnknown: Boolean = true, coerceNullRole: Boolean = true): UserDto with @JvmStatic @JvmOverloads, and use raw["role"] ?: if (coerceNullRole) "member" else error("Role cannot be null!").
