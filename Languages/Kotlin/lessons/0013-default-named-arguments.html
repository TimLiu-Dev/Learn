Section 3 · Functions · Lesson 3.1

Default and named arguments

Why Kotlin rarely needs constructor overloads, telescoping methods, or the Builder pattern.

Warm-up

  1. In val x = if (a > 0) a else 0, what is if acting as?
    CheckAn expression that produces a value, not a statement.
  2. How do you assign a fallback value to a nullable val name: String??
    CheckUsing the Elvis operator: val safe = name ?: "Athlete".

The problem default arguments solve

Docs: Functions → Default arguments.In Java and older languages, having optional parameters meant writing telescoping method overloads or creating a 50-line Builder class. In Kotlin, parameters can declare default values directly in the function signature:

fun logWorkout( title: String, durationMin: Int = 30, targetHeartRate: Int? = null, isIndoor: Boolean = false ) { println("$title: $durationMin min, target HR: $targetHeartRate, indoor: $isIndoor") }

You can now call logWorkout("Morning Run"), or pass only what you need. When calling functions with many flags, named arguments eliminate mystery boolean and integer literals:

// AI/Java habit: mystery booleans logWorkout("Intervals", 45, null, true) // Idiomatic Kotlin: clear intent logWorkout("Intervals", durationMin = 45, isIndoor = true)
Idiom Rule

Never write method overloads in Kotlin just to provide default parameter values. Use default arguments instead.

Quick check

Given fun notify(msg: String, sound: Boolean = true, priority: Int = 1), which call is invalid?

Positional arguments cannot follow named arguments unless they match the exact positional parameter order.

Exercise 2 · Refactor

Kill the Telescoping Overloads

This snippet uses Java-style method overloading. Refactor it into a single function with default arguments, and update main to use named arguments.

// Refactor these 3 overloads into ONE function: fun startRun(athlete: String): String { return startRun(athlete, 5.0) } fun startRun(athlete: String, distanceKm: Double): String { return startRun(athlete, distanceKm, false) } fun startRun(athlete: String, distanceKm: Double, isRace: Boolean): String { val raceTag = if (isRace) " (Race)" else "" return "Athlete $athlete: $distanceKm km$raceTag" } fun main() { println(startRun("Elena")) println(startRun("Marcus", 10.0)) println(startRun("Sarah", 21.1, true)) }
Hint 1: Unified signatureCollapse into fun startRun(athlete: String, distanceKm: Double = 5.0, isRace: Boolean = false): String.
Hint 2: Call site clarityCall startRun("Marcus", distanceKm = 10.0) and startRun("Sarah", distanceKm = 21.1, isRace = true) to make boolean literals explicit.
