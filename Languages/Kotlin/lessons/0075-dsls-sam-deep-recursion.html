The Concept: Safe DSLs & Overflow-Proof Recursion

1. @DslMarker: Sealing Nested Builder Scopes

When you nest lambdas with receivers—such as navGraph { screen("home") { screen("oops") {} } }—Kotlin normally keeps every outer this receiver in scope inside the inner block! Annotating your builder classes with a shared @DslMarker annotation instructs the compiler to forbid implicit calls to outer receivers, preventing accidental structural bugs in Compose, Gradle, Ktor, and custom team DSLs.

2. fun interface (Single Abstract Method Conversion)

Prefer fun interface AuthPolicy { fun canAccess(role: String): Boolean } over raw function type aliases (String) -> Boolean when a domain contract deserves a meaningful type name, documentation, or future default helper methods—while still letting callers pass a concise trailing lambda AuthPolicy { it == "admin" }!

3. tailrec vs DeepRecursiveFunction<T, R>

Standard JVM call stacks hold roughly 5,000–10,000 frames before crashing with StackOverflowError. Kotlin gives you two complementary tools to eliminate stack crashes:

  • tailrec (compile-time loop lowering): When the recursive call is the literal final operation in the function (tail position), tailrec compiles it into a zero-allocation while loop.
  • DeepRecursiveFunction<T, R> (heap-allocated continuations): When traversing deep trees, ASTs, JSON graphs, or linked structures where recursive calls are not in tail position (e.g., 1 + maxOf(callRecursive(left), callRecursive(right))), DeepRecursiveFunction suspends frames on the heap so 50,000-deep structures never overflow the JVM stack!

Quick Check

1. What specific bug does annotating DSL builder classes with a shared @DslMarker annotation prevent at compile time?

With @DslMarker, outer receivers are hidden inside nested lambdas unless explicitly qualified (this@RouterBuilder).

2. Which recursive function compiles cleanly into a zero-stack-allocation loop with the tailrec modifier?

For tailrec to eliminate stack frames, nothing—no pending arithmetic and no try/catch—may execute after the recursive call returns.

3. When should you reach for DeepRecursiveFunction<T, R> instead of tailrec?

tailrec compiles linear tail loops into fast bytecode jumps; DeepRecursiveFunction lifts branching or post-order recursion onto the heap.

Exercise 2 · Refactor

Eliminate Anonymous SAM Clutter & Fix a 25,000-Node Tree StackOverflowError

This AST analyzer has two problems: (1) NodeMatcher is a plain interface forcing verbose object : NodeMatcher ceremony at call sites; and (2) countMatchingDepth uses naive JVM stack recursion on a 25,000-deep skewed tree, risking StackOverflowError. Convert NodeMatcher to a fun interface (simplifying main) and rewrite treeDepth using DeepRecursiveFunction<AstNode?, Int>!

class AstNode(val tag: String, val left: AstNode? = null, val right: AstNode? = null) // REFACTOR 1: Make NodeMatcher a fun interface and simplify main() interface NodeMatcher { fun matches(tag: String): Boolean } // REFACTOR 2: Rewrite naive stack-recursive treeDepth using DeepRecursiveFunction<AstNode?, Int> fun treeDepth(root: AstNode?): Int { if (root == null) return 0 return 1 + maxOf(treeDepth(root.left), treeDepth(root.right)) } fun filterTags(tags: List<String>, matcher: NodeMatcher): List<String> = tags.filter { matcher.matches(it) } fun main() { // Build a 20,000-node deep skewed AST that overflows standard JVM recursion! var deepRoot: AstNode? = null repeat(20_000) { deepRoot = AstNode("div", left = deepRoot) } val matcher = object : NodeMatcher { override fun matches(tag: String): Boolean = tag.startsWith("h") } check(filterTags(listOf("div", "h1", "p", "h2"), matcher) == listOf("h1", "h2")) check(treeDepth(deepRoot) == 20_000) println("SAM matcher & 20,000-deep heap-safe treeDepth verified!") }
