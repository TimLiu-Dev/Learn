Secondary constructors and visibility

open vs final by default, delegating constructors, and modular internal encapsulation.

Secondary constructors: when and why

Docs: Secondary constructors. Must delegate to the primary constructor via this(...).In idiomatic Kotlin, default arguments in the primary constructor eliminate 95% of secondary constructors. However, secondary constructors are essential when initializing classes from multiple completely different representations (e.g. JSON strings vs parsed objects) or subclassing Android framework components:

class Athlete(val name: String, val birthYear: Int) { // Secondary constructor delegating to primary constructor constructor(name: String, currentAge: Int, currentYear: Int) : this(name, birthYear = currentYear - currentAge) }

final by default: Effective Java built into the language

In Java, classes and methods are open to inheritance unless explicitly marked final. This led to fragile base class bugs. Kotlin inverts this: all classes and member functions are final by default.

To allow a class to be inherited, you must explicitly mark it with open:

open class BaseService(val endpoint: String) { open fun execute() = println("Executing base call to $endpoint") } class AthleteService(endpoint: String) : BaseService(endpoint) { override fun execute() = println("Executing custom athlete call") }

Visibility modifiers: the power of internal

Docs: Visibility modifiers. Default is public.Kotlin has four visibility modifiers:

  • public (default): visible everywhere.
  • private: visible only inside the declaring file or class.
  • protected: visible only in subclasses.
  • internal: visible anywhere in the same compilation module (e.g. the same Gradle subproject or IntelliJ module).
Architecture Tip

In multi-module Android and Spring architectures, mark repository and service implementation classes as internal so other feature modules cannot bypass your public API interfaces.

Quick check

What happens if a class tries to extend another normal Kotlin class without the open keyword?

Kotlin classes are final by default; attempting to extend a class without open is a compile-time error.

Exercise 2 · Refactor

Eliminate Redundant Constructors

An AI produced this class with 4 telescoping secondary constructors. Refactor it to use one primary constructor with default arguments, while keeping the output of main identical.

class NetworkConfig { val timeoutMs: Int val retries: Int val baseUrl: String val debugMode: Boolean constructor(baseUrl: String) { this.baseUrl = baseUrl this.timeoutMs = 5000 this.retries = 3 this.debugMode = false } constructor(baseUrl: String, timeoutMs: Int) { this.baseUrl = baseUrl this.timeoutMs = timeoutMs this.retries = 3 this.debugMode = false } constructor(baseUrl: String, timeoutMs: Int, retries: Int, debugMode: Boolean) { this.baseUrl = baseUrl this.timeoutMs = timeoutMs this.retries = retries this.debugMode = debugMode } } fun main() { val c1 = NetworkConfig("https://api.run.com") println("${c1.baseUrl}: ${c1.timeoutMs}ms, retries: ${c1.retries}, debug: ${c1.debugMode}") val c2 = NetworkConfig("https://api.run.com", 10000) println("${c2.baseUrl}: ${c2.timeoutMs}ms, retries: ${c2.retries}, debug: ${c2.debugMode}") val c3 = NetworkConfig("https://api.run.com", 2000, 5, true) println("${c3.baseUrl}: ${c3.timeoutMs}ms, retries: ${c3.retries}, debug: ${c3.debugMode}") }
Hint 1: Default constructor parametersEliminate all secondary constructors. Define class NetworkConfig(val baseUrl: String, val timeoutMs: Int = 5000, val retries: Int = 3, val debugMode: Boolean = false) directly in the header.
Hint 2: Call sitesIn main, pass "https://api.run.com" with default arguments, or use named arguments such as timeoutMs = 10000 for selective overrides.
