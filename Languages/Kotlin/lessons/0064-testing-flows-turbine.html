Testing flows & Turbine

Why naive collect hangs tests, step-by-step stream assertions with Turbine, and backgroundScope for StateFlow.

Warm-up: Rapid Recall

  1. Why does calling stateFlow.toList() in a unit test hang indefinitely?
    CheckStateFlow is a hot, infinite stream that never completes on its own. toList() waits for completion before returning, causing the test to freeze.
  2. What is Turbine in the Kotlin testing ecosystem?
    CheckA small testing library by Cash App that lets you assert Flow emissions step-by-step: flow.test { assertEquals("A", awaitItem()) }.

The Concept: Testing Reactive Streams

1. The Problem with Testing Hot Flows

Cold flows complete when the builder finishes, but hot flows (like StateFlow and SharedFlow) stay open forever. In tests, collecting them directly hangs the test runner. Turbine solves this by attaching an observer to the flow and giving you an assertion block:

// Idiomatic Turbine assertion syntax: viewModel.uiState.test { assertEquals(ProfileUiState.Loading, awaitItem()) viewModel.loadUser() val success = awaitItem() as ProfileUiState.Success assertEquals("Alice", success.name) cancelAndIgnoreRemainingEvents() }

2. The Turbine Consumer Protocol Simulator

Under the hood, Turbine manages a queue of emissions and lets you await them one by one:

// Interactive Example: How Turbine verifies sequential flow items class FlowEventTestReceiver<T> { private val events = mutableListOf<T>() fun record(item: T) { events.add(item) } fun awaitItem(): T { check(events.isNotEmpty()) { "No item available to await!" } return events.removeAt(0) } fun expectNoEvents() { check(events.isEmpty()) { "Expected no events, but found: $events" } } } fun main() { val receiver = FlowEventTestReceiver<String>() // Simulate flow emitting states over time receiver.record("Loading") receiver.record("Loaded(Alice)") check(receiver.awaitItem() == "Loading") check(receiver.awaitItem() == "Loaded(Alice)") receiver.expectNoEvents() println("✅ All flow emissions verified in exact order!") }

3. backgroundScope in kotlinx-coroutines-test

When testing a class that collects a StateFlow, launch the collector inside backgroundScope. backgroundScope coroutines are automatically cancelled when the test body finishes, preventing the test from hanging on infinite streams.

Quick Check

1. Why does calling val items = mutableListOf<T>(); launch { stateFlow.toList(items) } often fail to capture state updates in a unit test?

Hot streams never complete. Testing hot flows requires either Turbine (which consumes items step-by-step and cancels on exit) or launching a collector inside backgroundScope.

2. What should you call at the end of a Turbine flow.test { ... } block if you only want to verify the first few emissions?

By default, Turbine fails the test if any unconsumed emissions remain when the block exits. Calling cancelAndIgnoreRemainingEvents() safely cleans up the subscription.
