The Concept: Structured Concurrency

Coroutines are not loose threads that can leak across your app. They must be launched inside a CoroutineScope, establishing a strict parent-child relationship:

  1. A parent coroutine does NOT complete until all its children complete.
  2. Cancelling a parent immediately cancels all its children.
  3. If a child throws an unhandled exception, it cancels the parent (and thus all siblings!), unless using a SupervisorJob or supervisorScope.

1. Cooperative Cancellation

Cancellation is cooperative. A coroutine does not abruptly stop at arbitrary bytecode instructions; it must check for cancellation:

suspend fun computePrimes() = withContext(Dispatchers.Default) { while (true) { ensureActive() // Throws CancellationException if cancelled! // or check: if (!isActive) break doHeavyComputationStep() } }

2. The Golden Rule of CancellationException

NEVER catch and swallow CancellationException without rethrowing it:

// BAD: Breaks coroutine cancellation! try { doWork() } catch (e: Exception) { // Swallows CancellationException! println("Ignored error") } // GOOD: try { doWork() } catch (e: CancellationException) { throw e // Always rethrow! } catch (e: Exception) { println("Handled normal business error: $e") }

3. supervisorScope: Failure Isolation

When you have multiple independent tasks and do NOT want one task's failure to cancel the others (e.g. downloading 5 independent images), use supervisorScope:

suspend fun downloadAll() = supervisorScope { launch { downloadFile1() } // If this fails... launch { downloadFile2() } // ...this continues running safely! }

Quick Check

What happens if a coroutine runs a CPU-bound while (true) loop without calling yield(), ensureActive(), or any suspending function, and its Job is cancelled?

Cancellation is cooperative. If a loop does not suspend or check isActive / ensureActive(), it cannot know it has been cancelled and will starve the thread.

Exercise 1 · Write from blank

Resilient Batch Worker with supervisorScope

Implement executeBatchTasks(taskIds: List<String>): List<String>:

  1. Use supervisorScope.
  2. For each ID, launch a deferred worker via async.
  3. If taskId == "fail", throw RuntimeException("Task failed").
  4. Catch exceptions on individual tasks using runCatching { deferred.await() } so failed tasks return "FAILED" while successful tasks return "SUCCESS-$id".
import kotlinx.coroutines.* suspend fun executeBatchTasks(taskIds: List<String>): List<String> = supervisorScope { // Implement resilient batch processing with async and runCatching emptyList() } fun main() = runBlocking { val results = executeBatchTasks(listOf("A", "fail", "B")) println(results) // Expected: ["SUCCESS-A", "FAILED", "SUCCESS-B"] }
Hint 1: Supervisor hierarchyWrap concurrent tasks in supervisorScope { ... } so one child failure does not cancel sibling jobs.
Hint 2: Graceful error handlingWrap individual child calls in runCatching { ... } or try/catch to log failures without throwing uncaught exceptions.
