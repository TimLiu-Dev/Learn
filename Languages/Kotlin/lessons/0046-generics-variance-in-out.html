Section 9 · Generics & Type System · Lesson 9.2

Variance: covariance (out) & contravariance (in)

The Liskov Substitution Principle, declaration-site variance, and solving Java's wildcard nightmare.

Warm-up: Rapid Recall

  1. In Java, is List<String> a subtype of List<Object>?
    CheckNo! In Java, generic types are invariant by default to prevent type safety corruption.
  2. Why CAN a Kotlin List<String> be passed where a List<Any> is expected?
    CheckBecause Kotlin's List<out E> is defined with declaration-site covariance (out) and is read-only.

The Concept: Declaration-Site Variance

Kotlin replaces Java's complex call-site wildcard gymnastics (? extends T and ? super T) with intuitive declaration-site keywords: out and in.

The Golden Rule: PECS (Producer Out, Consumer In)

1. Covariance: out T (Producer)

  • T only appears in out-positions (return types of functions).
  • Subtyping is preserved: If Dog is a subtype of Animal, then Producer<Dog> is a subtype of Producer<Animal>.
interface Source<out T> { fun produce(): T // OK: T is produced (in out-position) // fun consume(item: T) // COMPILATION ERROR! Cannot accept T as parameter } val dogSource: Source<Dog> = DogBreeder() val animalSource: Source<Animal> = dogSource // Perfectly valid!

2. Contravariance: in T (Consumer)

  • T only appears in in-positions (arguments to functions).
  • Subtyping is inverted: If Dog is a subtype of Animal, then Consumer<Animal> is a subtype of Consumer<Dog>!
interface Sink<in T> { fun consume(item: T) // OK: T is accepted (in in-position) // fun produce(): T // COMPILATION ERROR! Cannot return T } val animalSink: Sink<Animal> = AnimalShelter() val dogSink: Sink<Dog> = animalSink // Perfectly valid! Anything that can accept any animal can accept a Dog!

3. Invariance (No keyword)

If a class both produces AND consumes T (e.g. MutableList<T>), it must be invariant (no in or out).

Quick Check

Why cannot MutableList<T> be declared with out T?

Covariance (out) guarantees that the type is only produced. If MutableList<out Animal> allowed add(Cat()) into what was actually a MutableList<Dog>, runtime type safety would be violated.

Exercise 1 · Write from blank

Event Producer and Consumer Architecture

Implement the following generic interfaces and classes:

  1. Open class UIEvent(val timestamp: Long), subclass ClickEvent(timestamp: Long, val buttonId: String) : UIEvent(timestamp).
  2. Covariant interface EventSource<out T : UIEvent> with fun poll(): T?.
  3. Contravariant interface EventDispatcher<in T : UIEvent> with fun dispatch(event: T).
  4. Verify that an EventSource<ClickEvent> can be assigned to a variable of type EventSource<UIEvent>.
open class UIEvent(val timestamp: Long) class ClickEvent(timestamp: Long, val buttonId: String) : UIEvent(timestamp) // 1. Declare EventSource<out T : UIEvent> // 2. Declare EventDispatcher<in T : UIEvent> fun main() { val clickSource: EventSource<ClickEvent> = object : EventSource<ClickEvent> { override fun poll(): ClickEvent = ClickEvent(System.currentTimeMillis(), "btn_submit") } // Test covariance assignment: val uiSource: EventSource<UIEvent> = clickSource println("Polled event timestamp: ${uiSource.poll()?.timestamp}") }
Hint 1: Producer covarianceDeclare interface EventSource<out T : UIEvent> { fun poll(): T? } since it only produces values.
Hint 2: Consumer contravarianceDeclare interface EventDispatcher<in T : UIEvent> { fun dispatch(event: T) } since it only consumes values.
Exercise 2 · Refactor

Call-Site Variance Array Copy

Because Array<T> is invariant, copyArray(strings, objects) below fails to compile when both parameters are typed as Array<T>. Add Kotlin call-site variance projections (out / in) to the function signature so copying Array<String> into Array<Any?> compiles safely.

// REFACTOR SIGNATURE: Add call-site variance projections (out / in) fun <T> copyArray(from: Array<T>, to: Array<T>) { for (i in from.indices) { to[i] = from[i] } } fun main() { val strings: Array<String> = arrayOf("Kotlin", "Multiplatform", "Android") val objects: Array<Any?> = arrayOfNulls(3) copyArray(strings, objects) println(objects.joinToString()) check(objects.contentEquals(arrayOf<Any?>("Kotlin", "Multiplatform", "Android"))) }
Hint 1: Use-site variance (PECS)In fun <T> copyArray(from: Array<out T>, to: Array<in T>), mark the source with out and destination with in.
Hint 2: Type safetyfrom only produces items via from[i] (out), while to only consumes items via to[i] = ... (in).
