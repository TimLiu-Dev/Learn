Function types and trailing lambdas

Higher-order functions, implicit it, and the syntactic convention that powers Kotlin DSLs.

Function types: Functions as first-class citizens

Docs: Higher-order functions and lambdas. Function types use parentheses: (A, B) -> C.In Kotlin, functions can be assigned to variables, passed as arguments, and returned from other functions. The type of a function is expressed using arrow notation:

val isPaceFast: (Double) -> Boolean = { pace -> pace < 4.0 } val logMessage: () -> Unit = { println("Session started") }

The implicit it parameter

If a lambda has exactly one parameter, you can omit the parameter declaration entirely and refer to it as it:

// Explicit: val square: (Int) -> Int = { x -> x * x } // Idiomatic: val square: (Int) -> Int = { it * it }

The Trailing Lambda Convention

In Kotlin, if the last parameter of a function is a function type, the lambda can be placed outside the parentheses. If the lambda is the only argument, parentheses can be omitted entirely:

Awkward (Inside Parentheses)

runs.filter({ it.distance > 5.0 })

Idiomatic (Trailing Lambda)

runs.filter { it.distance > 5.0 }

This single syntactic rule is what makes Jetpack Compose, Gradle .kts build scripts, and standard library collection pipelines look like clean native language constructs rather than clumsy method calls.

Quick check

Given fun repeatAction(times: Int, action: (Int) -> Unit), what is the most idiomatic call?

When the last argument is a lambda, it moves outside the parentheses (repeatAction(3) { ... }).
