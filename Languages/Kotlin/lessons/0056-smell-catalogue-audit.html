Smell catalogue: 15 common anti-patterns

Spotting and eradicating AI hallucinations and legacy Java habits in real codebases.

Warm-up: Rapid Recall

  1. Why is calling list.stream().filter(...).collect(Collectors.toList()) a smell in Kotlin?
    CheckKotlin collections have direct inline extension functions (list.filter { ... }) that are faster, cleaner, and avoid Java 8 stream boxing.
  2. Why is using Optional<T> considered unidiomatic in Kotlin?
    CheckKotlin's type system has first-class nullable types (T?) and compiler-enforced null safety with zero object allocation overhead.

The Concept: The 15 Anti-Patterns Audit

  1. Unnecessary force-unwraps (!!): Replacing safe calls / Elvis with crash bombs.
  2. Java Streams in Kotlin: Using .stream() instead of stdlib extensions or asSequence().
  3. The Arrow of Scope: Nesting 4 layers of ?.let instead of safe-navigation.
  4. Optional<T> usage: Wrapping objects instead of using T?.
  5. Leaking mutable state: Exposing var or MutableList in public APIs.
  6. Legacy collections: Using java.util.Stack or Vector instead of ArrayDeque.
  7. Boilerplate getters/setters: Writing fun getTitle(): String = title.
  8. Primitive boxing in DSA: Using Array<Int> instead of IntArray.
  9. Manual Singletons: Writing Java double-checked locking instead of object or by lazy.
  10. Swallowing CancellationException: Breaking coroutine structured concurrency.
  11. Imperative if-else ladders: Avoiding exhaustive when expressions.
  12. Spawning raw threads: Calling Thread { ... } instead of coroutines.
  13. Eager allocations on large datasets: Chaining 5 operations without asSequence().
  14. Manual Builder pattern: Writing 100-line Builders instead of default arguments & apply.
  15. Class token passing: Passing Class<T> instead of inline fun <reified T>.

Exercise 2 · Refactor

The Ultimate Java-in-Kotlin Smell Refactor

Refactor this code which contains 4 distinct anti-patterns (Java stream, Optional, manual getter, and force-unwrap !!).

import java.util.Optional import java.util.stream.Collectors class Employee(private val name: String, private val salary: Double?) { fun getName(): String = name fun getSalary(): Optional<Double> = Optional.ofNullable(salary) } // REFACTOR THIS: fun findHighEarnersJavaStyle(employees: List<Employee>): List<String> { return employees.stream() .filter { it.getSalary().isPresent && it.getSalary().get() > 50000.0 } .map { it.getName().uppercase() } .collect(Collectors.toList()) } fun main() { val list = listOf(Employee("Alice", 75000.0), Employee("Bob", 40000.0), Employee("Carol", null)) println(findHighEarnersJavaStyle(list)) }
Hint 1: Idiomatic data classDeclare data class Employee(val name: String, val salary: Double?) without getters or Java Optional wrappers.
Hint 2: Kotlin collection pipelineFilter and map directly: employees.filter { (it.salary ?: 0.0) > 50000.0 }.map { it.name.uppercase() }.
