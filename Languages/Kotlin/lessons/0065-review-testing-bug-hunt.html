Testing review & production bug hunt

Senior PR audit: spotting race conditions, dispatcher leaks, unmockable singletons, and flaky tests before production.

Warm-up: Rapid Recall

  1. What is the difference between StandardTestDispatcher and UnconfinedTestDispatcher?
    CheckStandardTestDispatcher queues tasks in a virtual scheduler requiring explicit advancement (e.g. advanceUntilIdle()); UnconfinedTestDispatcher runs newly launched coroutines eagerly on the current thread.
  2. Why does catching Throwable inside a coroutine break structured concurrency?
    CheckBecause CancellationException inherits from Throwable; catching it without rethrowing prevents coroutines from cancelling cooperatively.

The Concept: The 4 Common Concurrency Testing Traps

  1. Hardcoded Dispatchers: Writing withContext(Dispatchers.IO) inside services makes tests bypass virtual time. Always inject dispatchers via constructor.
  2. Flaky Thread.sleep() Timing: Never rely on real time delays in unit tests; use virtual clocks, TestDispatchers, or Turbine.
  3. Race Conditions on StateFlow.value: Using _state.value = _state.value.copy(...) can overwrite concurrent updates. Always use _state.update { ... }.
  4. Swallowed Cancellation: Naive try { ... } catch (e: Exception) or runCatching without rethrowing CancellationException.
// Interactive Example: Spotting non-atomic StateFlow mutation vs .update class StateHolder { var value = 0 fun nonAtomicIncrement() { val current = value // If another coroutine modifies value here, update is clobbered! value = current + 1 } } fun main() { val holder = StateHolder() holder.nonAtomicIncrement() check(holder.value == 1) println("✅ StateHolder verified!") }

Quick Check

1. In a Senior Code Review, which pattern is an immediate red flag in a repository class?

Hardcoding dispatchers breaks testability. Senior code always injects a CoroutineDispatcher with a default value (e.g. dispatcher: CoroutineDispatcher = Dispatchers.IO).

2. Why does a unit test that verifies verify { analytics.logEvent(any()) } break when an engineer refactors internal analytics formatting?

Testing interaction (mocks) couples tests to internal code structure. Testing observable state (fakes) ensures tests only fail when business behavior actually breaks.

Exercise 1 · Write from blank

Testable Order Processing Pipeline

Implement a complete, deterministic, testable order service:

  1. data class Order(val id: String, val amountCents: Long, val status: String = "PENDING").
  2. interface OrderStore with fun save(order: Order) and fun get(id: String): Order?.
  3. class FakeOrderStore : OrderStore using a mutableMapOf<String, Order>().
  4. class OrderProcessor(private val store: OrderStore) with fun completeOrder(id: String): Order: fetches order (throws IllegalArgumentException("Order not found") if null), requires order.status == "PENDING" (throws IllegalStateException("Order already completed")), saves order with status = "COMPLETED", and returns the updated order.
// 1. Declare Order and OrderStore // 2. Declare FakeOrderStore : OrderStore // 3. Declare OrderProcessor(private val store: OrderStore) fun main() { val store = FakeOrderStore() val processor = OrderProcessor(store) // Setup initial order store.save(Order("ord-1", 3500)) // Test 1: Complete order val completed = processor.completeOrder("ord-1") check(completed.status == "COMPLETED") check(store.get("ord-1")?.status == "COMPLETED") // Test 2: Cannot complete twice val duplicateFailed = runCatching { processor.completeOrder("ord-1") }.isFailure check(duplicateFailed) { "Should reject completing an already-completed order" } // Test 3: Missing order throws val missingFailed = runCatching { processor.completeOrder("missing") }.isFailure check(missingFailed) { "Should fail when order does not exist" } println("✅ All order processor unit tests passed cleanly!") }
Hint 1In completeOrder, start with val order = requireNotNull(store.get(id)) { "Order not found" }.
Hint 2Check status with check(order.status == "PENDING") { "Order already completed" }, then store.save(order.copy(status = "COMPLETED")).
