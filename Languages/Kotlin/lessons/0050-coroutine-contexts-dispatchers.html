The Concept: Dispatchers and Context Switching

A coroutine always executes in a CoroutineContext, an indexed set of elements including a Job, a CoroutineDispatcher, and a CoroutineName.

1. Standard Dispatchers

DispatcherThread Pool ModelIntended Workload
Dispatchers.Main Single UI thread (Android / JavaFX) UI updates, user interactions, lightweight events
Dispatchers.IO Elastic thread pool (up to 64+ threads) Blocking I/O: HTTP requests, disk files, database queries
Dispatchers.Default Fixed pool (matches number of CPU cores) CPU-heavy math: JSON parsing, sorting 100k items, encryption
Dispatchers.Unconfined Runs in current caller thread until first suspension Advanced edge cases (rarely used in app code)

2. Switching Threads with withContext

To perform work on a background dispatcher and return the result cleanly to the caller without changing the outer scope, use withContext:

suspend fun loadAndParseData(url: String): ParsedData { // 1. Fetch raw data on IO thread pool: val jsonString = withContext(Dispatchers.IO) { downloadHttp(url) // Blocking or network call } // 2. Heavy CPU parsing on Default thread pool: return withContext(Dispatchers.Default) { parseComplexJson(jsonString) } }

Quick Check

You need to sort a list of 500,000 strings and compute their cryptographic SHA-256 hashes. Which dispatcher is most appropriate?

Sorting and cryptographic hashing are CPU-bound operations. Dispatchers.Default is backed by a thread pool sized to the machine's CPU cores, avoiding thread thrashing.
