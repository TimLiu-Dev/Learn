Section 4 · Classes & Modeling · Lesson 4.1

Primary constructors and properties

Declaring state in the class header, custom accessors, backing fields, and init blocks.

Warm-up

  1. In Kotlin, what does an extension function like fun String.wordCount(): Int compile to in JVM bytecode?
    CheckA static method with the receiver (String) as its first argument.
  2. Can an extension property have a backing field (field)?
    CheckNo. Extension properties cannot hold state; they can only define custom getters (and setters).

The problem primary constructors solve

Docs: Classes → Constructors.In Java, defining a simple class with three fields requires declaring private fields, writing a constructor that copies arguments to fields, and authoring boilerplate getters and setters. In Kotlin, the primary constructor is part of the class header:

// In Java: 25 lines of boilerplate. // In Kotlin: 1 line declares constructor, fields, and accessors! class Athlete(val name: String, var age: Int, val maxHeartRate: Int = 190)

Prefixing a constructor parameter with val or var automatically creates a property on the class. Omitting val/var makes it a plain constructor parameter accessible only in the init block or property initializers.

The init block: validation & setup

Because the primary constructor header has no body, initialization code goes inside init blocks:

class PaceCalculator(val minPerKm: Double) { init { require(minPerKm > 0.0) { "Pace must be positive, but was $minPerKm" } } }

Custom accessors & the backing field (field)

When reading or writing a property requires custom logic, define a custom get() or set(). Inside an accessor, use the special identifier field to access the underlying stored value without triggering infinite recursion:

class HeartRateZone(bpm: Int) { var bpm: Int = bpm set(value) { require(value > 30) { "Invalid heart rate: $value" } field = value // 'field' accesses the backing field } val isCardio: Boolean get() = bpm in 130..160 // computed property; no backing field needed }
Android & Spring Habit

Never write manual Java-style getter/setter methods like fun getAge(): Int or fun setAge(a: Int). Use Kotlin properties directly. Kotlin synthesizes Java-interop getAge() and setAge() automatically.

Quick check

In class User(name: String, val age: Int), what is name?

Without val or var, name is merely a constructor parameter available during initialization, not an accessible property on instances of User.

Exercise 1 · Write from blank

Workout Tracker Model

Define a class WorkoutSession with:

  • Primary constructor: title: String, distanceKm: Double, durationMinutes: Int (defaults to 30)
  • An init block validating that distanceKm > 0 and durationMinutes > 0 using require()
  • A computed read-only property paceMinPerKm: Double returning durationMinutes / distanceKm
  • A computed read-only property isLongRun: Boolean returning true if distance is ≥ 15.0 or duration ≥ 90
// Write WorkoutSession class here fun main() { val session1 = WorkoutSession("Morning 10k", 10.0, 50) println("${session1.title}: pace ${session1.paceMinPerKm} min/km, long run: ${session1.isLongRun}") val session2 = WorkoutSession("Half Marathon", 21.1, 105) println("${session2.title}: pace ${session2.paceMinPerKm} min/km, long run: ${session2.isLongRun}") }
Hint 1: Constructor and validationDeclare class WorkoutSession(val title: String, val distanceKm: Double, val durationMinutes: Int = 30) with an init block checking require(distanceKm > 0.0) and require(durationMinutes > 0).
Hint 2: Computed propertiesDefine computed properties inside the body: val paceMinPerKm: Double get() = durationMinutes / distanceKm and val isLongRun: Boolean get() = distanceKm >= 15.0 || durationMinutes >= 90.
Exercise 2 · Refactor

Kill the Java Getter/Setter Boilerplate

Refactor this Java-style class into idiomatic Kotlin. Output must remain identical.

class AthleteProfile { private var name: String = "" private var weeklyKm: Double = 0.0 constructor(name: String, weeklyKm: Double) { this.name = name this.weeklyKm = weeklyKm } fun getName(): String { return this.name } fun getWeeklyKm(): Double { return this.weeklyKm } fun setWeeklyKm(km: Double) { if (km < 0.0) throw IllegalArgumentException("Distance cannot be negative") this.weeklyKm = km } fun isHighVolume(): Boolean { return this.weeklyKm >= 50.0 } } fun main() { val athlete = AthleteProfile("Marcus", 42.0) println("${athlete.getName()}: ${athlete.getWeeklyKm()} km, high volume: ${athlete.isHighVolume()}") athlete.setWeeklyKm(55.0) println("${athlete.getName()}: ${athlete.getWeeklyKm()} km, high volume: ${athlete.isHighVolume()}") }
Hint 1: Primary constructor headerDeclare class AthleteProfile(val name: String, weeklyKm: Double) without manual getter methods.
Hint 2: Custom setter with backing fieldIn the class body, declare var weeklyKm: Double = weeklyKm with set(value) { require(value >= 0.0) { ... }; field = value } and val isHighVolume: Boolean get() = weeklyKm >= 50.0.
