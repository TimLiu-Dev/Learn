Delegated properties

How property delegation works under the hood, stdlib delegates, and Android/Compose state patterns.

The Concept: The Delegation Protocol

In Kotlin, val p: Type by Delegate() syntax delegates getter and setter calls to an object. Under the hood, the compiler transforms access into calls to operator functions:

operator fun getValue(thisRef: Any?, property: KProperty<*>): T operator fun setValue(thisRef: Any?, property: KProperty<*>, value: T) // for var

1. Standard Library Delegates

  • Delegates.observable(initialValue) { prop, old, new -> ... }: executes a callback on property mutation.
  • Delegates.vetoable(initialValue) { prop, old, new -> Boolean }: can intercept and reject property mutation.
  • Delegates.notNull<T>(): like lateinit, but works with primitives!
import kotlin.properties.Delegates class UserSession { var activeUsers: Int by Delegates.observable(0) { prop, old, new -> println("${prop.name} changed: $old -> $new") } var validPort: Int by Delegates.vetoable(8080) { _, _, new -> new in 1024..65535 // Veto invalid port updates } }

2. Android & Jetpack Compose Delegation

Modern Android architecture relies heavily on property delegation:

  • val viewModel: OrderViewModel by viewModels(): binds ViewModel lifecycle to the Activity/Fragment.
  • var text by remember { mutableStateOf("") }: in Compose, unboxes MutableState<T> so you can read and write text directly without writing text.value.

Quick Check

In Delegates.vetoable, what does returning false from the callback lambda do?

vetoable checks the predicate before updating. If the callback returns false, the assignment is rejected and the property retains its previous value.

Practice: Hands-On Exercises

Exercise 1 · Write from blank

Audited Configuration with Observable Delegate

Implement AppEnvironment:

  1. Property var activeProfile: String by Delegates.observable("development").
  2. Every time activeProfile changes, print "Profile update: switched from <old> to <new>".
  3. Property var maxConnections: Int by Delegates.vetoable(10) that only accepts updates where new in 1..100.
import kotlin.properties.Delegates class AppEnvironment { // 1. activeProfile observable // 2. maxConnections vetoable } fun main() { val env = AppEnvironment() env.activeProfile = "staging" env.activeProfile = "production" env.maxConnections = 50 println("Connections: ${env.maxConnections}") // 50 env.maxConnections = 500 // Vetoed! println("Connections: ${env.maxConnections}") // 50 }
Hint 1: Observable propertyDeclare var activeProfile: String by Delegates.observable("development") { _, old, new -> println("Profile update: switched from $old to $new") }.
Hint 2: Vetoable propertyDeclare var maxConnections: Int by Delegates.vetoable(10) { _, _, new -> new in 1..100 } to reject updates outside 1..100.
