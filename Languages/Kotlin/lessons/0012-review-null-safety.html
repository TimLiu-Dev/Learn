Null safety, mixed review

Nothing new today. Just retrieval, mixed up on purpose, with a few Section 1 ideas in the mix.

How to use this review

The questions jump between topics deliberately. Having to work out which tool a problem needs is the skill you'll use on real code, and mixing topics trains it. Getting some wrong is the point: each miss shows you which lesson to reopen. Don't look anything up until you've committed to an answer.

Warm-up

Say or write each answer before you check it.

  1. workout is a Workout? and title is a String. What type is workout?.title?
    CheckString?. A safe call always makes the result nullable (2.1).
  2. Why is val w = workout ?: return allowed, when return doesn't produce a value?
    Checkreturn and throw are expressions of type Nothing, which fits wherever any type is expected (2.2).
  3. Local val, local var, val property, var property. Which one is never smart-cast, and why?
    CheckThe var property. Other code could change it between the check and the use. Snapshot it into a local val (2.3).
  4. Name three ways to fail with a message instead of writing !!.
    CheckrequireNotNull(x) { … } for bad arguments, checkNotNull(x) { … } for bad state, and x ?: error("…") (2.4).
  5. Why is val zone = if (…) "Peak" else "Easy" better than var zone = "" plus an assignment in each branch?
    Checkif is an expression, so zone can be a val assigned exactly once, and the compiler forces every branch to produce a value (1.4, 1.1).

Mixed quiz

1. val name: String? = null. What is name?.length ?: 0?

name?.length is null, so Elvis uses the right-hand side. The result type is Int, not Int?.

2. In val zone = if (bpm > 160) "Peak" else "Easy", what is the if?

if is an expression in Kotlin, which is exactly why Kotlin doesn't need a ternary operator (1.4).

3. fun f(x: Any) { if (x is Int && x > 100) println(x) }. What happens?

The right side of && only runs if the left side was true, so x is smart-cast to Int there. A String just makes the condition false, with no crash.

4. Why doesn't lateinit var bpm: Int compile?

lateinit needs a non-null, non-primitive type on a var. For an Int that's set later, use Int? or a sensible starting value.

5. val p: String = System.getProperty("missing.key"). The key doesn't exist. What happens?

The return value is a platform type (String!), so either declared type compiles. Choosing String makes Kotlin insert a check at the assignment, and that check fails at runtime.

6. val raw: Any = 5. What is raw as? Double ?: 0.0?

5 is an Int, and an Int is not a Double. There are no implicit number conversions (1.1), and as? doesn't convert either. So the cast gives null, and Elvis gives 0.0.

7. user is null. What does println("Hi ${user?.name}") print?

A template turns null into the text "null". That's a common UI bug: add ?: "Guest" inside the braces (1.2).

8. fun label(x: Any) = when (x) { is Int -> "num"; is String -> "text" }. What happens?

A when used as an expression must be exhaustive, and Any has endless other types (1.5). Inside each branch, x is smart-cast.

Exercise 2 · Refactor

Untangle the profile summary

Classic AI/Java-flavoured null handling: nested ifs, a var result, casts after checks and !! everywhere. Refactor summary so the output is exactly the same. Don't change Profile, Repository or main.
