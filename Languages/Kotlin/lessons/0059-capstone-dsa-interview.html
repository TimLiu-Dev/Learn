  1. Why does IntArray beat Array<Int> in LeetCode memory and runtime?

  2. Which Kotlin stdlib class provides amortized O(1) operations at both ends for BFS queues and LIFO/monotonic stacks?

The Concept: Competitive & Interview Kotlin Rules

Write expressive Kotlin in technical interviews without falling into hidden JVM performance or overflow traps:

  • Primitive arrays: Use IntArray, LongArray, CharArray, BooleanArray, and Array(rows) { IntArray(cols) } for DP tables and visited grids.
  • Queues & Stacks: Use ArrayDeque (addLast / removeFirst for BFS queue; addLast / removeLast for stack). Never use synchronized legacy java.util.Stack.
  • Overflow-safe Heaps: Build max-heaps with PriorityQueue<Int>(compareByDescending { it })—never PriorityQueue { a, b -> b - a }, which silently overflows when comparing negative values near Int.MIN_VALUE!
  • Bitwise infix ops: Use shl, shr, ushr, and, or, xor, inv(), and countOneBits().
// Overflow-safe binary search midpoint + Max-Heap setup: val mid = (low + high) ushr 1 val maxHeap = java.util.PriorityQueue<Int>(compareByDescending { it })

Quick Check

1. Why does PriorityQueue<Int> { a, b -> b - a } fail on LeetCode edge-case inputs like intArrayOf(-2147483648, 5)?

Signed 32-bit subtraction wraps around on overflow, turning a positive difference negative and corrupting the heap invariant. Always use compareByDescending { it } or b.compareTo(a).

2. Which Kotlin expression computes a non-negative binary search midpoint safely even when low + high exceeds Int.MAX_VALUE?

Unsigned right shift (ushr 1, or equivalently low + (high - low) / 2) shifts a 0 into the sign bit, recovering the exact midpoint even if low + high overflowed into a negative Int.

3. How do you allocate an R x C 2D matrix of unboxed 32-bit integers initialized to -1 for memoization?

Array(R) { IntArray(C) { -1 } } creates R contiguous primitive int[] rows with zero Integer boxing.

Exercise 2 · Refactor

Sliding Window Maximum: O(N * K) to O(N) Monotonic Deque

Refactor the naive O(N * K) nested-loop sliding window below into an optimal O(N) algorithm using ArrayDeque<Int> storing window indices in decreasing order of their array values.

// REFACTOR THIS O(N * K) SOLUTION INTO O(N) USING ArrayDeque<Int>: fun maxSlidingWindow(nums: IntArray, k: Int): IntArray { if (nums.isEmpty()) return intArrayOf() val result = IntArray(nums.size - k + 1) for (i in 0..nums.size - k) { var m = nums[i] for (j in 1 until k) { if (nums[i + j] > m) m = nums[i + j] } result[i] = m } return result } fun main() { val arr = intArrayOf(1, 3, -1, -3, 5, 3, 6, 7) val maxArr = maxSlidingWindow(arr, 3) check(maxArr.contentEquals(intArrayOf(3, 3, 5, 5, 6, 7))) check(maxSlidingWindow(intArrayOf(9, 8, 7), 2).contentEquals(intArrayOf(9, 8))) println("Window Maxes: ${maxArr.joinToString()}") }
Hint 1For each index i: (1) pop from the front (removeFirst()) if deque.first() <= i - k (out of window); (2) pop from the back (removeLast()) while nums[deque.last()] <= nums[i].
Hint 2Push i with deque.addLast(i). Whenever i >= k - 1, the window's maximum value is sitting at nums[deque.first()].
