Warm-up: Spaced Retrieval

  1. Inside callbackFlow, why must listener callbacks call trySend(...) instead of emit(...), and what breaks if you omit awaitClose?
    Checkemit is suspending and cannot be called from ordinary callback threads; trySend sends without suspending. Omitting awaitClose closes the stream prematurely or throws IllegalStateException and leaks the registered listener.
  2. When using Kotlin 2.2+ when guard conditions (is Case if cond -> ...) on a sealed interface, what rule governs branch ordering?
    CheckPlace specific guarded branches before the unguarded fallback for the same subtype, otherwise the unguarded branch shadows the guarded one.
  3. Which two kotlinx.serialization.json.Json settings keep released Android apps from crashing when the backend adds fields or sends null for fields with defaults?
    CheckignoreUnknownKeys = true (ignores unrecognized backend fields) and coerceInputValues = true (falls back to Kotlin default values on unexpected null or unknown enums).

Quick Check

1. What architectural limitation of Kotlin extension functions do Kotlin Context Parameters (context(logger: Logger)) solve?

Before context parameters, an extension function fun Repo.save(...) already consumed your single extension receiver slot, making multi-capability helpers awkward.

2. A ViewModel exposes queries.flatMapLatest { search(it) }.stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), Idle). What happens when a user types "ko", then "kot" 20 ms later, and then rotates the phone?

flatMapLatest prevents out-of-order response bugs while WhileSubscribed(5_000) balances rotation continuity with battery savings when backgrounded.

3. Which pair of JVM interop annotations resolves colliding fun render(items: List<Int>) / fun render(items: List<String>) signatures AND supports Android XML View inflation?

Both annotations keep clean Kotlin APIs untouched while generating exact bytecode compatibility for JVM callers and Android XML layout inflation.

4. When should you reach for DeepRecursiveFunction instead of tailrec?

tailrec compiles linear loops into fast jumps; DeepRecursiveFunction lifts branching trees (like UI view hierarchies or JSON ASTs) onto the heap.

Offline-First Sync Engine: DSL + Guarded when + callbackFlow + Mutex

  1. @DslMarker annotation class SyncDsl and fun interface RetryPredicate { fun canRetry(attempt: Int, errorCode: Int): Boolean }.
  2. @SyncDsl class SyncPolicyBuilder with fun retryWhen(predicate: RetryPredicate) and top-level fun syncPolicy(block: SyncPolicyBuilder.() -> Unit): RetryPredicate returning the configured predicate (defaulting to returning false).
  3. sealed interface SyncOutcome with data object UpToDate : SyncOutcome, data class Synced(val count: Int) : SyncOutcome, and data class Failed(val code: Int, val attempt: Int) : SyncOutcome. Write fun classifyOutcome(outcome: SyncOutcome, retryRule: RetryPredicate): String using Kotlin 2.2+ guarded when:
    • SyncOutcome.UpToDate → "Idle"
    • is SyncOutcome.Synced if outcome.count == 0 → "No Updates"
    • is SyncOutcome.Synced → "Synced ${outcome.count}"
    • is SyncOutcome.Failed if retryRule.canRetry(outcome.attempt, outcome.code) → "Retry(${outcome.code})"
