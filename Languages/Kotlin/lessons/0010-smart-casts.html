Smart casts, is and as?

Check once, then use it. And why the compiler sometimes refuses to trust your check.

The problem smart casts solve

In many languages, checking a type and using it as that type are two separate steps. You check, and then you cast by hand. The cast repeats what you just proved, and if the check and the cast ever drift apart you get a crash.

Docs: Type checks and casts → Smart casts: “The compiler tracks the type checks and explicit casts for immutable values and inserts implicit (safe) casts automatically.”Kotlin merges the two steps. Once a check succeeds, the compiler remembers it and treats the value as the narrower type for as long as the check is guaranteed to hold. This is a smart cast. You've already been relying on it: it's what makes a String? usable as a String after a null check.

fun bpmLabel(bpm: Int?): String { if (bpm == null) return "No signal" // From here on, bpm is Int, not Int? return "${bpm + 10} bpm after warm-up" } fun main() { println(bpmLabel(null)) println(bpmLabel(132)) }

The same narrowing happens after ?: return, inside if (x != null) { … }, and on the right of && and ||:

if (title != null && title.length > 20) { … } // title is String after && if (title == null || title.isEmpty()) return // title is String after ||

is and !is: the same idea for types

Docs: Checks with is and !is.is checks a type at runtime, and !is is its negation. Values often arrive as Any: rows from a sync payload, or extras decoded from somewhere loosely typed. After an is check, the value is smart-cast:

fun describe(value: Any): String { if (value !is String) return "Not text" return "Text of length ${value.length}" // value is String here } fun main() { println(describe("Tempo run")) println(describe(42)) }

A when with is branches smart-casts inside each branch. You'll use this all the time with sealed classes in lesson 4.5:

fun render(entry: Any): String = when (entry) { is Int -> if (entry > 160) "Peak: $entry bpm" else "$entry bpm" // entry is Int is String -> "Note: ${entry.uppercase()}" // entry is String else -> "Unknown" } fun main() { println(render(148)) println(render("felt strong")) }

as vs as?: when you can't check first

Docs: Unsafe cast operator and Safe casts.Sometimes you just want to say “treat this as an Int”. There are two operators for that:

  • x as Int is the unsafe cast. If x isn't an Int, it throws ClassCastException.
  • x as? Int is the safe cast. If x isn't an Int, you get null, so the result type is Int?.

as? pairs naturally with the Elvis operator from last lesson: try the cast, and fall back to a default.

fun main() { //sampleStart val raw: Any = "45" // arrived as text, not a number val minutes = raw as? Int ?: 0 // cast fails → null → 0 println(minutes) // val boom = raw as Int // uncomment: ClassCastException //sampleEnd }

If you've just checked x is Int, you need neither. The smart cast already happened, so x as Int straight after is Int is pure noise.

When smart casts fail, and why

The compiler only smart-casts when it can prove that the value can't change between the check and the use. If something else could swap the value in that gap, trusting your check would be unsafe. So it refuses:

class Workout(val title: String) class WorkoutScreen { var current: Workout? = null fun headline(): String { if (current != null) { return current.title // ❌ smart cast impossible: current is a mutable property } return "No workout" } } fun main() { println(WorkoutScreen().headline()) }

The full rules: Smart cast prerequisites. For var properties the docs say “Never, because the variable can be modified at any time by other code.”current is a var property. Another function, another thread, or a callback could set it to null right after your check. The official rules boil down to this:

What you checkedSmart cast?
local valAlways
val propertyYes, if it's private/internal or in the same module, and it isn't open and has no custom getter
local varYes, if it isn't changed between the check and the use, and isn't captured by a lambda that changes it
var propertyNever

The fix is almost always to take a snapshot. Copy the property into a local val. A local val can't change, so the check holds:

val workout = current ?: return "No workout" return workout.title // workout is a local val, so this is safe

The other common fix is a safe call such as current?.title, or current?.let { … }, which you'll meet in lesson 6.1. What you should not reach for is current!!.title. It compiles, but it just moves the crash back to runtime. Lesson 2.4 covers !!.

Kotlin 2.0's compiler (K2) made smart casts smarter. For example, val isCat = animal is Cat; if (isCat) animal.purr() now works, and a is X || a is Y smart-casts to their common supertype. See What's new in Kotlin 2.0 → Smart cast improvements. Older answers online may say these don't work.

AI/Java-flavoured smells to spot
  • if (x is Int) { val n = x as Int … }: a manual cast after a check that already smart-cast
  • if (current != null) current!!.title: !! to silence a failed smart cast, instead of snapshotting into a val
  • raw as Int on data you don't control, where raw as? Int ?: default was meant

Quick check

1. fun f(x: Any) { if (x !is String) return; println(x.length) }. Does it compile?

The negative check returns early, so on the next line x can only be a String. That's a smart cast after an early exit.

2. In a class, var heartRate: Int? = null. Then if (heartRate != null) println(heartRate + 1) fails to compile. Why?

It's a var property, so other code could set it back to null after the check. The compiler never smart-casts var properties.

3. val raw: Any = "45". What is raw as? Int ?: 0?

"45" is a String, not an Int. as? doesn't parse anything: it returns null, and Elvis turns that into 0.

4. What's the idiomatic fix for the failed smart cast in question 2?

A local val snapshot can't change, so the check holds. !! and as just move the crash to runtime, and lateinit isn't even allowed on Int (lesson 2.4).
