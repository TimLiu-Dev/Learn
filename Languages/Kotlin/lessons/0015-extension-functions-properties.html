Extension functions and properties

Extending third-party types cleanly and retiring bloated Java utility classes.

Warm-up

  1. How do you convert fun add(a: Int, b: Int): Int { return a + b } to a single-expression function?
    Checkfun add(a: Int, b: Int): Int = a + b
  2. Why does fun check(x: Int) = { x > 0 } return a function rather than a boolean?
    CheckBecause curly braces on the right side of = define a lambda literal () -> Boolean.

The problem extensions solve

Docs: Extension functions. Under the hood, the compiler generates a static method with the receiver as the first parameter.In Java, if you wanted a helper method on a class you didn't own (like String, List, or Android's View), you had to create a static utility class:

// Java/AI habit: static utils classes StringUtils.capitalizeWords("morning run") ViewUtils.hide(myButton)

In Kotlin, extension functions let you call your helpers as if they were member functions of the class:

fun String.capitalizeWords(): String = split(" ").joinToString(" ") { it.replaceFirstChar(Char::uppercase) } // Idiomatic call site: println("morning run".capitalizeWords()) // prints "Morning Run"

Nullable receivers

An extension can be defined on a nullable type, handling nulls internally so callers don't need safe calls:

fun String?.orDefault(fallback: String): String = this ?: fallback val input: String? = null println(input.orDefault("None")) // perfectly safe, no ?. needed!

Extension properties

You can also extend classes with computed properties using custom getters (they cannot store backing fields):

val Int.minutesToSeconds: Int get() = this * 60
Design Rule

Never create classes named StringUtils, CollectionUtils, or DateUtils in Kotlin. Define top-level extension functions instead.

Quick check

Can an extension function access private members of the receiver class?

Extensions do not modify the original class; they are static helpers resolved at compile time, so they cannot bypass encapsulation.

Exercise 1 · Write from blank

Clean String & Number Extensions

Write two extensions from scratch:

  1. An extension property Double.asKm: String that formats the number with " km" (e.g. 5.2.asKm → "5.2 km")
  2. An extension function String?.blankToNull(): String? that returns null if the string is null, empty, or only whitespace, otherwise returns the string
// Write the 2 extensions here fun main() { println(42.195.asKm) val s1: String? = " " val s2: String? = "Intervals" val s3: String? = null println(s1.blankToNull()) println(s2.blankToNull()) println(s3.blankToNull()) }
Hint 1: Extension property syntaxExtension properties cannot have backing fields; declare an explicit getter: val Double.asKm: String get() = "$this km".
Hint 2: Nullable receiver extensionExtend the nullable type: fun String?.blankToNull(): String? = if (this.isNullOrBlank()) null else this.
Exercise 2 · Refactor

Retire the Java WorkoutUtils Class

Refactor this legacy utility class into idiomatic top-level extension functions.

class Workout(val title: String, val minutes: Int, val heartRate: Int?) // Retire this class into clean extensions: object WorkoutUtils { fun isIntense(workout: Workout): Boolean { return (workout.heartRate ?: 0) > 160 || workout.minutes > 60 } fun formattedSummary(workout: Workout): String { val hr = if (workout.heartRate != null) "${workout.heartRate} bpm" else "No HR" return "${workout.title}: ${workout.minutes} min ($hr)" } } fun main() { val w1 = Workout("Track Intervals", 45, 172) val w2 = Workout("Walk", 30, null) println(WorkoutUtils.formattedSummary(w1) + " - Intense: " + WorkoutUtils.isIntense(w1)) println(WorkoutUtils.formattedSummary(w2) + " - Intense: " + WorkoutUtils.isIntense(w2)) }
Hint 1: Convert methods to receiver callsDeclare fun Workout.isIntense(): Boolean = (heartRate ?: 0) > 160 || minutes > 60.
Hint 2: Access properties via thisInside fun Workout.formattedSummary(): String, access title, minutes, and heartRate directly as receiver properties.
