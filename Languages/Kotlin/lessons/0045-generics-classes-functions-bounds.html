Generics: classes, functions & bounds

Parameterizing types, enforcing compile-time safety, non-nullable bounds, and multi-constraint where.

Warm-up: Rapid Recall

  1. What is the default upper bound of a generic type parameter <T> in Kotlin?
    CheckAny? (meaning T is nullable by default!).
  2. How do you enforce that a generic type parameter T can NEVER be nullable?
    CheckSpecify <T : Any> as the upper bound.

The Concept: Kotlin Generics Foundations

1. Generic Classes and Functions

class ResultHolder<T>(val value: T) fun <T> singletonList(item: T): List<T> = listOf(item)

2. Upper Bounds

To call methods on generic instances, restrict the type parameter with an upper bound (syntax: T : SuperType):

// T must implement Comparable<T> fun <T : Comparable<T>> findMax(first: T, second: T): T { return if (first > second) first else second }

3. Multiple Constraints with where

When a type parameter must satisfy multiple interfaces or classes, place the constraints in a where clause at the end of the declaration:

fun <T> ensureValidAndAppend(target: T, value: CharSequence) where T : CharSequence, T : Appendable { if (target.isNotEmpty()) { target.append(" -> ") } target.append(value) }

Quick Check

In class Box<T>(val item: T), can Box hold a null value?

Unbounded <T> defaults to <T : Any?>. To forbid null, you must explicitly declare <T : Any>.

  2. If value > max, return max.
  3. Otherwise return value.
fun <T : Comparable<T>> clamp(value: T, min: T, max: T): T { // Implement generic clamp return value } fun main() { println(clamp(15, 0, 10)) // 10 println(clamp(-5, 0, 100)) // 0 println(clamp("kotlin", "a", "m")) // "kotlin" }
