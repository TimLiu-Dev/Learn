Say which values you mean, instead of managing a counter.

The problem ranges solve

Kotlin has no for (int i = 0; i < n; i++) loop. That's deliberate. That style of loop asks you to manage three things: where to start, when to stop, and how to step. Off-by-one bugs live in exactly those details: < or <=? n or n - 1?

Docs: Ranges and progressions.Kotlin asks a simpler question: which values do you want? You describe them as a range, which is an ordinary value you can loop over, test against, or store in a val.

Making ranges

fun main() { //sampleStart for (i in 1..5) print(i) // 12345 .. includes the end println() for (i in 0..<5) print(i) // 01234 ..< excludes the end println() for (i in 5 downTo 1) print(i) // 54321 counting down println() for (i in 0..30 step 10) print("$i ") // 0 10 20 30 println() for (c in 'a'..'e') print(c) // abcde Char works too //sampleEnd }

From Coding conventions → Loops on ranges: 0..n - 1 is marked “bad”, 0..<n “good”.You'll also see 0 until 5 in older code. It means exactly the same as 0..<5. The current conventions prefer ..<, and specifically flag 0..n - 1 as the thing to avoid.

Two surprises worth knowing:

  • 5..1 is empty, not reversed. .. only counts up. To count down, use downTo.
  • step can skip past the end. 1..9 step 3 gives 1, 4, 7. The last element is the last one that fits, not necessarily the end value (Progressions).

in and !in: checks that read like English

Ranges aren't only for loops. Any “is this value between A and B?” check becomes a range test:

Before

if (heartRate >= 114 && heartRate <= 133) { … } if (age < 18 || age > 100) { … }

After

if (heartRate in 114..133) { … } if (age !in 18..100) { … }

The range version names the zone once, can't get the boundaries the wrong way round, and can be stored: val fatBurnZone = 114..133. in checks also work for decimals, as in pace in 4.5..6.0. You can't loop over a Double range, though. What would the step be?

Looping over a list: you usually don't need the index

To visit each item in a list, loop over the list itself. If you really need the index, use indices, which is the range of valid indexes. That way you can't fall off the end:

fun main() { //sampleStart val zones = listOf("Warm-up", "Fat burn", "Cardio") for (zone in zones) println(zone) // most of the time for (i in zones.indices) println("$i: ${zones[i]}") // when you need i // for (i in 0..zones.size) … ❌ crashes: index 3 doesn't exist //sampleEnd }

Two helpers: repeat and coerceIn

To do something n times without caring about a counter, use repeat(3) { … }. (The { … } is a lambda; lesson 5.1 covers those. For now, read it as “a block to run”.)

API: coerceIn. It throws if min is greater than max.To clamp a value into limits, for example a treadmill speed the user typed in, use coerceIn instead of two ifs:

fun main() { //sampleStart repeat(3) { println("Rep done") } val requestedSpeed = 25.0 println(requestedSpeed.coerceIn(0.8, 20.0)) // 20.0 //sampleEnd }
AI/Java-flavoured smells to spot
  • for (i in 0..list.size - 1) or 0 until list.size when you only need the items
  • x >= a && x <= b instead of x in a..b
  • A while loop with a var counter that just counts up or down
  • Two ifs clamping a value, instead of coerceIn

Quick check

1. What does for (i in 1..9 step 3) print(i) print?

It starts at 1 and adds 3 each time, stopping at the last value that doesn't go past 9. 10 would, so the last value is 7.

2. Which expression is true exactly when hr is from 120 to 150, inclusive?

.. includes both ends. ..< and until both leave out 150, and !in is the opposite test.

3. Each loop body reads zones[i]. Which loop crashes at runtime?

0..zones.size includes zones.size itself, one past the last valid index. That's exactly the off-by-one that indices and ..< prevent.

4. What does for (i in 5..1) print(i) print?

.. only counts up, so 5..1 contains no values. It compiles fine and the loop runs zero times. Use 5 downTo 1.
