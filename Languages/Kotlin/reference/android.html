Android & Jetpack Compose Idioms

Unidirectional Data Flow (UDF), Compose state mechanics, lifecycle-aware flow collection, and one-off effect channels.

1. Unidirectional Data Flow & State Modeling

In modern Android architecture, state flows down and events flow up. Never expose mutable state to the UI layer:

// 1. Exhaustive UI State Hierarchy:
sealed interface ProfileUiState {
    data object Loading : ProfileUiState
    data class Success(val user: UserProfile, val isRefreshing: Boolean = false) : ProfileUiState
    data class Error(val message: String, val canRetry: Boolean = true) : ProfileUiState
}

// 2. Sealed One-Off Events (Navigation, Toasts, Snackbars):
sealed interface ProfileUiEffect {
    data class ShowToast(val text: String) : ProfileUiEffect
    data class NavigateToSettings(val userId: String) : ProfileUiEffect
}

// 3. ViewModel with Backing Property:
class ProfileViewModel(
    private val repository: UserRepository
) : ViewModel() {
    private val _uiState = MutableStateFlow<ProfileUiState>(ProfileUiState.Loading)
    val uiState: StateFlow<ProfileUiState> = _uiState.asStateFlow()

    // Channels ensure one-off events are consumed once without re-triggering on rotation:
    private val _effectChannel = Channel<ProfileUiEffect>(Channel.BUFFERED)
    val effects: Flow<ProfileUiEffect> = _effectChannel.receiveAsFlow()

    fun loadProfile() {
        viewModelScope.launch {
            _uiState.value = ProfileUiState.Loading
            repository.getUser()
                .onSuccess { user -> _uiState.value = ProfileUiState.Success(user) }
                .onFailure { err -> _uiState.value = ProfileUiState.Error(err.message ?: "Failed") }
        }
    }
}

2. StateFlow vs SharedFlow vs Channel

MechanismNatureReplayPrimary Android Use Case
StateFlow<T>Hot StateReplays last value (conflated)Screen UI State (always has current state, survives recomposition).
Channel<E>Hot Queue0 replay (bufferable)One-time events (Navigation, Snackbar, Dialog). Each event handled once.
SharedFlow<E>Hot BroadcastConfigurable replayBroadcast bus with 0 or multiple simultaneous observers.

3. Jetpack Compose State Mechanics

ConstructSyntaxWhy & When to use
Local State Delegationvar text by remember { mutableStateOf("") }Survives recomposition of this composable. Uses property delegation (getValue/setValue).
Survive Configuration Changesvar query by rememberSaveable { mutableStateOf("") }Survives screen rotations and Android activity recreation across process death.
Derived Calculationval showScrollTop by remember { derivedStateOf { listState.firstVisibleItemIndex > 0 } }Prevents recomposition on every pixel scroll; recomposes only when the boolean calculation changes.
Compose Stability@Immutable or @StableMarks classes as stable so the Compose compiler can skip recomposition when inputs don't change. (Kotlin 2.0 Strong Skipping mode automates this for most classes).

4. Safe Flow Collection: collectAsStateWithLifecycle

Never use plain collectAsState() on Android for UI state:

@Composable
fun ProfileScreen(viewModel: ProfileViewModel = viewModel()) {
    // IDIOMATIC: Automatically stops collecting when app enters background!
    val state by viewModel.uiState.collectAsStateWithLifecycle()

    when (val s = state) {
        is ProfileUiState.Loading -> LoadingIndicator()
        is ProfileUiState.Success -> ProfileContent(s.user)
        is ProfileUiState.Error   -> ErrorView(s.message)
    }
}

Why: collectAsState() keeps flow collection active even when the Activity is stopped in the background, consuming CPU, network, and battery. collectAsStateWithLifecycle() listens to the Android Lifecycle and cancels collection when in the background.
