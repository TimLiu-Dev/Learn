Kotlin Multiplatform (KMP) Architecture

Hierarchical source sets, expect/actual contracts vs interfaces, multiplatform ecosystem, and native concurrency.

1. Modern Source Set Hierarchy (Kotlin 2.0)

KMP organizes shared and platform-specific code into a directed acyclic graph of source sets managed by Gradle:

                     commonMain (100% pure Kotlin)
                     /        \
             jvmMain            nativeMain
            /       \          /          \
     androidMain  desktopMain appleMain    linuxMain
                              /       \
                          iosMain    macosMain
                         /       \
                  iosArm64Main  iosSimulatorArm64Main
Source SetCapabilitiesEcosystem Rules
commonMainShared domain logic, models, ViewModels, networking, repositories.Pure Kotlin only. No Java/Android/Apple SDK imports allowed.
iosMainCode shared across all iOS architectures (device & simulator).Direct access to Apple frameworks (UIKit, Foundation, CoreData).
androidMainAndroid-specific implementations.Direct access to Android SDK, Jetpack, Context, and JVM bytecode.

2. expect / actual vs Common Interfaces

Kotlin provides two mechanisms to bridge platform-specific code. Use each where it fits best:

MechanismWhen to useArchitecture Rule
Common Interface + DI
(Recommended for business logic)		 High-level domain dependencies (Key-Value storage, Location provider, Analytics, Audio player). Define interface KeyValueStorage in commonMain. Implement with AndroidSharedPrefsStorage in androidMain and IosUserDefaultStorage in iosMain. Inject via constructor or DI (e.g. Koin). Makes commonTest easy to mock without compiling native binaries.
expect / actual functions Low-level platform hooks, UUID generation, device platform names, and factory functions. Use when a standalone top-level function or factory method is needed. (Avoid expect class hierarchies as they add tight compiler coupling).
actual typealias Aliasing existing platform standard library types. E.g. actual typealias AtomicInt = java.util.concurrent.atomic.AtomicInteger.

3. The Essential KMP Multiplatform Library Stack

CapabilityKMP Standard LibraryIdiomatic Usage
JSON Serialization kotlinx.serialization Compiler plugin (no reflection). Annotate with @Serializable. Fast and safe across iOS and Android.
HTTP Networking Ktor Client Multiplatform HTTP engine. Configures OkHttp on Android, Darwin (NSURLSession) on iOS, CIO on server JVM.
Dates & Time kotlinx-datetime Cross-platform Instant, Clock.System.now(), and TimeZone without java.time.* dependencies.
Local Database SQLDelight or AndroidX Room KMP Generates type-safe Kotlin APIs from pure SQL queries with platform SQLite drivers (Android SQLite & iOS Native SQLite).
Concurrency kotlinx.coroutines Non-blocking asynchronous pipelines running natively on Android JVM threads and iOS Darwin run loops.

4. KMP Networking & Serialization Blueprint

// commonMain: Data transfer model with kotlinx.serialization
import kotlinx.serialization.Serializable
import io.ktor.client.*
import io.ktor.client.call.*
import io.ktor.client.request.*
import io.ktor.client.plugins.contentnegotiation.*
import io.ktor.serialization.kotlinx.json.*

@Serializable
data class ArticleDto(val id: String, val title: String, val views: Int)

// Multiplatform API Client in commonMain:
class NewsApiClient(private val httpClient: HttpClient) {
    suspend fun fetchTopArticles(): List<ArticleDto> =
        httpClient.get("https://api.example.com/articles").body()
}

// Factory in platform source sets or DI module:
fun createHttpClient(engine: io.ktor.client.engine.HttpClientEngine): HttpClient =
    HttpClient(engine) {
        install(ContentNegotiation) { json() }
    }
