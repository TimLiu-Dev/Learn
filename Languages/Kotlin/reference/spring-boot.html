1. The Mandatory Kotlin Compiler Plugins

Kotlin classes are final by default and do not generate no-arg constructors unless forced. Spring Boot projects must configure two compiler plugins in build.gradle.kts:

Compiler PluginWhat problem it solvesUnder the hood
kotlin-spring
(all-open)		 Spring requires classes and methods annotated with @Configuration, @Service, @Component, @Transactional, and @Async to be non-final for CGLIB runtime proxying. Automatically adds the open modifier to Spring-annotated classes and methods in generated bytecode without polluting your source code.
kotlin-jpa
(no-arg)		 JPA Hibernate instantiates entities via reflection and requires a zero-argument constructor (public Entity() {}). Synthesizes an invisible bytecode-only zero-argument constructor for classes annotated with @Entity, @Embeddable, and @MappedSuperclass.

2. Annotation Use-Site Targets: @field:, @get:, @param:

In Kotlin, a constructor property like val email: String compiles to three distinct bytecode elements: a private field, a getter method (getEmail()), and a constructor parameter. When annotating properties, you must tell the compiler where the annotation belongs:

PrefixTarget Bytecode ElementCritical Server-Side Use Case
@field:Underlying Java private fieldJakarta Bean Validation: @field:NotBlank, @field:Min(1), @field:Size(max = 100). (Ensures validation runs on field inspection).
@get:Generated getter methodJackson property overrides: @get:JsonProperty("user_id").
@param:Constructor parameterSpring Dependency Injection / Value binding: @param:Value("\${app.name}").
// IDIOMATIC SPRING DTO:
data class CreateUserRequest(
    @field:NotBlank(message = "Username is required")
    @field:Size(min = 3, max = 30)
    val username: String,

    @field:Email(message = "Invalid email format")
    val email: String,

    @field:Min(18)
    val age: Int = 18
)

3. Why NEVER Use data class on JPA Entities

Using data class on JPA Hibernate entities is one of the most destructive anti-patterns in backend Kotlin:

  1. Lazy Initialization Bomb: The auto-generated equals, hashCode, and toString access every property. If an entity has a lazy relation (e.g. @OneToMany), calling toString() or adding to a Set triggers full database table scans or throws LazyInitializationException.
  2. Circular Reference Crash: Bidirectional relations (Author <-> Book) cause generated toString() and hashCode() to enter infinite recursion, resulting in a fatal StackOverflowError.
  3. Mutable Primary Key Trap: In a data class, generated hashCode() uses all fields including id. When a new entity is saved, Hibernate assigns an ID (e.g. id = null -> id = 120). Its hash code mutates, corrupting any HashSet or HashMap containing it.

Idiomatic JPA Entity Pattern in Kotlin

import jakarta.persistence.*
import org.hibernate.proxy.HibernateProxy

@Entity
@Table(name = "customers")
class Customer(
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    var id: Long? = null,

    @Column(nullable = false)
    var name: String,

    @Column(nullable = false, unique = true)
    var email: String
) {
    // Only check ID and class identity for persistence equality:
    override fun equals(other: Any?): Boolean {
        if (this === other) return true
        if (other == null) return false
        val oEffectiveClass = if (other is HibernateProxy) other.hibernateLazyInitializer.persistentClass else other.javaClass
        val thisEffectiveClass = if (this is HibernateProxy) this.hibernateLazyInitializer.persistentClass else this.javaClass
        if (thisEffectiveClass != oEffectiveClass) return false
        other as Customer
        return id != null && id == other.id
    }

    override fun hashCode(): Int =
        if (this is HibernateProxy) this.hibernateLazyInitializer.persistentClass.hashCode() else javaClass.hashCode()

    override fun toString(): String =
        "${this::class.simpleName}(id=$id, email='$email')"
}

4. Jackson Kotlin Module (jackson-module-kotlin)

Jackson requires jackson-module-kotlin to deserialize JSON into Kotlin data classes without reflection boilerplate. It provides:

  • Instant instantiation using Kotlin primary constructors.
  • Strict null safety: Throws MissingKotlinParameterException if a non-nullable property is missing in JSON.
  • Automatic fallback to default argument values when JSON attributes are omitted.

5. Spring Data & Non-Blocking Coroutines WebFlux

// 1. Spring Data Extension Function:
val user = userRepository.findByIdOrNull(userId) ?: throw UserNotFoundException(userId)

// 2. Coroutine-Native Spring WebFlux Controller:
@RestController
@RequestMapping("/api/orders")
class OrderController(private val orderService: OrderService) {

    @GetMapping("/{id}")
    suspend fun getOrder(@PathVariable id: String): ResponseEntity<OrderResponse> {
        val order = orderService.fetchOrder(id) // non-blocking suspend call
        return ResponseEntity.ok(order)
    }

    @GetMapping("/stream", produces = [MediaType.TEXT_EVENT_STREAM_VALUE])
    fun streamEvents(): Flow<OrderEvent> {
        return orderService.eventStream() // reactive streaming via Flow
    }
}
