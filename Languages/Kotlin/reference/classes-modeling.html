Reference sheet · Section 4

Classes & Domain Modeling

Decision guide: primary constructors, data classes, sealed hierarchies, enums, and value types.

1. Choosing the Right Modeling Construct

ConstructBest Used ForKey Features
class Stateful domain entities with behavior and encapsulation. final by default; custom getters/setters with field.
data class Immutable value objects, DTOs, events. Auto-generates equals, hashCode, toString, copy, destructuring.
sealed interface Restricted state hierarchies (e.g. Loading / Success / Error). Exhaustive when checks; smart-casts per branch; multiple inheritance.
enum class Fixed singletons with identical structure (e.g. Days, HTTP methods). Zero-allocation entries list (Kotlin 1.9+); exhaustive when.
value class Type-safe IDs (e.g. UserId) and domain units (e.g. Km). Zero heap allocations; inlined at runtime to raw primitive.
object Thread-safe singletons and utility configurations. Lazy initialization; instantiated once across the app.

3. Data Class Rules & Pitfalls

RuleWhy
Parameters in primary constructor header only Only constructor properties participate in equals(), hashCode(), and copy(). Body properties are ignored!
Cannot be open or abstract Inheritance breaks symmetry in generated equals().
Arrays in data classes require manual equals Kotlin compares arrays by reference identity (===). Use List instead of Array.

4. Anti-Patterns & Smells

Java / AI HabitIdiomatic KotlinRationale
fun getName(): String / setName(...) Kotlin property access: user.name Properties synthesize accessors automatically.
Class with multiple nullable state flags sealed interface UiState Makes illegal states unrepresentable.
Double-checked locking singleton object MySingleton Language-level thread-safe singleton.
Passing raw strings for distinct IDs @JvmInline value class UserId(val id: String) Prevents swapped arguments with zero runtime cost.
