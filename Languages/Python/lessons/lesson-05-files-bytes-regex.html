1. pathlib.Path, Streaming I/O & JSON / CSV / tomllib

Leave legacy os.path.join(...) string juggling behind. Modern Python uses pathlib.Path, where the / operator joins paths cleanly across macOS, Linux, and Windows (Path("/tmp") / "logs" / "app.jsonl").

  • Always pass encoding="utf-8" when opening text files—otherwise Windows defaults to cp1252 and crashes on emojis or accents!
  • Stream huge files line by line (for line in f:) or with io.StringIO in memory/tests instead of calling f.read(), which loads multi-GB logs into RAM.
  • Structured formats in stdlib: json (UTF-8 APIs/JSONL), csv.DictReader (tabular exports), and tomllib (Python 3.11+ built-in TOML reader for pyproject.toml—requires binary mode "rb" with tomllib.load(f)!).

Write sum_passed_tokens(csv_text) that streams csv_text using io.StringIO and csv.DictReader (without loading split lines into big intermediate lists):

- Each row has columns "status" and "tokens".
- Ignore rows where row["status"].strip().lower() != "pass".
- Convert row["tokens"] to int and sum them up.

Hint 1: Inside the loop, write if row["status"].strip().lower() == "pass":.
Hint 2: When matched, do total += int(row["tokens"]).
Final Answer & Rationale: 
import csv
import io

def sum_passed_tokens(csv_text):
    total = 0
    reader = csv.DictReader(io.StringIO(csv_text))
    for row in reader:
        if row["status"].strip().lower() == "pass":
            total += int(row["tokens"])
    return total

csv.DictReader iterates lazily row by row over any file-like stream (open(...) or io.StringIO), keeping memory O(1) per row.

2. bytes, bytearray, memoryview & UTF-8 Encoding

Python 3 enforces a strict wall between text (str, abstract Unicode characters) and raw binary data (bytes, integers 0..255). Network sockets, files on disk, and LLM streaming SSE chunks transmit bytes; your business logic works on str.

  • str.encode("utf-8") → bytes · bytes.decode("utf-8") → str.
  • One character != one byte: len("🚀") is 1 character, while len("🚀".encode("utf-8")) is 4 bytes! Slicing raw UTF-8 bytes arbitrarily can slice a character in half and trigger UnicodeDecodeError.
  • bytearray is a mutable byte sequence (useful for building binary frames in place).
  • memoryview(buf) lets you slice large bytes/bytearray payloads with zero memory copying!

[PRACTICE 2] Safe UTF-8 Byte-Budget Truncator
Solved ✓

Many APIs (like Redis keys, HTTP headers, or database VARCHAR byte limits) enforce a maximum byte size, not character count. Implement truncate_utf8_bytes(text, max_bytes):

- If max_bytes < 0: raise ValueError("max_bytes must be non-negative").
- Encode raw = text.encode("utf-8").
- If len(raw) <= max_bytes: return text.
- Otherwise slice raw[:max_bytes] and decode safely using .decode("utf-8", errors="ignore") so an incomplete multi-byte emoji at the cut boundary is cleanly dropped rather than crashing with UnicodeDecodeError!

Hint 1: Encode with raw = text.encode("utf-8") and check if len(raw) <= max_bytes: return text.
Hint 2: Otherwise write return raw[:max_bytes].decode("utf-8", errors="ignore").
Final Answer & Rationale: 
def truncate_utf8_bytes(text, max_bytes):
    if max_bytes < 0:
        raise ValueError("max_bytes must be non-negative")
    raw = text.encode("utf-8")
    if len(raw) <= max_bytes:
        return text
    return raw[:max_bytes].decode("utf-8", errors="ignore")

Because UTF-8 is self-synchronizing, errors="ignore" discards any truncated trailing multi-byte prefix cleanly without corrupting valid earlier characters.

3. Custom Context Managers (__enter__/__exit__ & @contextmanager)

A with block guarantees setup before the body runs and cleanup after—even when an exception or early return happens inside. You can build your own in two ways:

  1. Class-based: Implement __enter__(self) (returns the resource bound by as x) and __exit__(self, exc_type, exc_val, exc_tb). Return False (or None) so exceptions propagate normally; returning True suppresses the exception!
  2. Generator-based (@contextlib.contextmanager): Write setup, yield value, and put cleanup inside try: ... finally: ...! Without try/finally, an exception in the caller's with block skips your cleanup lines!

[PRACTICE 3] Exception-Safe @contextmanager Config Override
Solved ✓

Implement @contextmanager def override_setting(config, key, temp_value): that temporarily sets config[key] = temp_value inside a with block and restores the original state afterward—even if an exception is raised inside the block:

- Save whether key originally existed (existed = key in config) and its old_value = config.get(key).
- Set config[key] = temp_value.
- Inside try: yield config.
- Inside finally: restore config[key] = old_value if existed was True, else remove key with config.pop(key, None).

Hint 1: Wrap yield config in try: followed by finally:.
Hint 2: In finally:, write if existed: config[key] = old_value and else: config.pop(key, None).
Final Answer & Rationale: 
from contextlib import contextmanager

@contextmanager
def override_setting(config, key, temp_value):
    existed = key in config
    old_value = config.get(key)
    config[key] = temp_value
    try:
        yield config
    finally:
        if existed:
            config[key] = old_value
        else:
            config.pop(key, None)

Without try/finally, any exception inside the with body would skip restoration and leave production config mutated!

4. Regular Expressions (re) & ReDoS Safety

  • Always use raw strings (r"...") so backslashes like \d or \s aren't eaten by Python string escapes.
  • Compile hot-path patterns once with re.compile(...) and use named capture groups (?P<name>...) so extracting fields stays readable.
  • re.match vs re.search vs re.fullmatch: match only checks the start; search scans anywhere; fullmatch enforces the entire string matches (best for input validation!).
[SECURITY] ReDoS (Regular Expression Denial of Service)

Python's re engine uses backtracking. Patterns with nested quantifiers like r"^(a+)+$" or overlapping alternations can take exponential 2n time on a crafted 30-character string—freezing your entire FastAPI server! Keep quantifiers non-overlapping (e.g. negated character classes [^/]+ instead of greedy .+) and bound lengths where possible.

[PRACTICE 4] Safe Named-Group API Log Parser (re)
Solved ✓

Compile a safe, non-backtracking regex LOG_RE and implement parse_access_log(line) to parse lines formatted exactly like "POST /v1/chat 200":

- Use named groups: method (uppercase letters [A-Z]+), path (starts with / followed by non-whitespace /\S*), and status (3 digits \d{3}).
- Match the whole stripped line using LOG_RE.fullmatch(line.strip()).
- If no match, return None.
- If matched, return {"method": ..., "path": ..., "status": int(...)} (note status must be an int!).

Hint 1: Pattern: r"(?P<method>[A-Z]+)\s+(?P<path>/\S*)\s+(?P<status>\d{3})".
Hint 2: Extract fields via return {"method": m.group("method"), "path": m.group("path"), "status": int(m.group("status"))}.
Final Answer & Rationale: 
import re

LOG_RE = re.compile(r"(?P[A-Z]+)\s+(?P/\S*)\s+(?P\d{3})")

def parse_access_log(line):
    m = LOG_RE.fullmatch(line.strip())
    if not m:
        return None
    return {
        "method": m.group("method"),
        "path": m.group("path"),
        "status": int(m.group("status")),
    }

Notice each token class ([A-Z]+, \s+, /\S*, \d{3}) is mutually disjoint—zero catastrophic backtracking risk!
