1. Dynamic Arrays, Tuples & Compact Hash Tables

Under the hood in CPython, a list is a dynamic array of object pointers (contiguous pointers in memory, over-allocated so .append() is amortized O(1)). A tuple is a fixed-size, immutable pointer array—slightly smaller in memory and hashable when all of its items are hashable.

By contrast, dict and set are compact hash tables (since Python 3.7, dict also preserves insertion order). Instead of scanning items one by one, Python computes hash(key) and jumps straight to the slot in O(1) average time.

Operation list (Dynamic Array) set / dict (Hash Table) Why It Matters in AI Backends
Index / Key Lookup items[i] → O(1) cache[key] → O(1) avg Both are fast when you already know the index or key.
Membership Test (x in c) O(n) linear scan O(1) avg hash lookup Checking 50k blocked IDs in a list stalls your API; use a set.
End Append vs. Front Insert append O(1) · insert(0, x) O(n) add / d[k]=v → O(1) avg list.pop(0) shifts every element; use collections.deque for queues.
Hashability Requirement Any object allowed Keys/elements must be hashable list and dict are mutable → unhashable; tuple of strs/ints is hashable.
[COMMON PITFALL] Unhashable Keys & KeyError

Trying to put a list or dict as a dict key or inside a set raises TypeError: unhashable type—because if a key mutated later, its hash slot would become unreachable. Convert fixed key sequences to a tuple first! And when reading optional keys, prefer d.get("model", "default") over d["model"].

Write filter_new_chunks(chunks, seen_ids) where each chunk is a tuple (doc_id, chunk_index, text) and seen_ids is a collection of already-indexed (doc_id, chunk_index) keys:

- Convert seen_ids into a set called known so lookups are O(1).

- For each doc_id, chunk_index, text in chunks, build key = (doc_id, chunk_index).
- If key not in known, add key to known and append (doc_id, chunk_index, text) to new_chunks (this also deduplicates duplicates inside chunks itself!).

Hint 1: Inside the loop, write key = (doc_id, chunk_index) and check if key not in known:.
Hint 2: When unseen, call known.add(key) and new_chunks.append((doc_id, chunk_index, text)) so later duplicates in the same batch are skipped too.
Final Answer & Rationale: 
def filter_new_chunks(chunks, seen_ids):
    known = set(seen_ids)
    new_chunks = []
    for doc_id, chunk_index, text in chunks:
        key = (doc_id, chunk_index)
        if key not in known:
            known.add(key)
            new_chunks.append((doc_id, chunk_index, text))
    return new_chunks

Copying seen_ids into a fresh set gives O(1) membership tests without mutating the caller's input, and composite tuple keys let us hash multi-part IDs cleanly.

2. Shallow vs. Deep Copy & collections Power Tools

Remember from Lesson 01: variables hold references, not boxes. Assignment (b = a) creates an alias to the exact same object. A shallow copy (a.copy(), a[:], or copy.copy(a)) builds a new outer container, but still shares references to any nested lists or dicts inside it! When cloning nested configs or tool payloads, use copy.deepcopy(a).

[COMMON PITFALL] The [[0] * 3] * 3 Trap

Writing grid = [[0] * 3] * 3 duplicates the reference to the same inner row list 3 times. Changing grid[0][0] = 9 mutates all three rows! Always build nested lists with a loop or list comprehension: [[0] * 3 for _ in range(3)].

For grouping and counting, skip manual if key not in d: d[key] = [] boilerplate and reach for Python's standard collections module:

  • collections.defaultdict(list): automatically creates an empty list when a new key is accessed.
  • collections.Counter(items): counts hashable items in O(n) and gives .most_common(k).

import copy

def clone_with_extra_tool(base_config, tool_name):
    cloned = copy.deepcopy(base_config)
    tools = cloned.setdefault("tools", [])
    if tool_name not in tools:
        tools.append(tool_name)
    return cloned

Because copy.deepcopy recursively clones nested lists and dicts, appending to cloned["tools"] leaves base_config["tools"] untouched.

from collections import Counter, defaultdict

def summarize_requests(logs):
    by_route = defaultdict(list)
    counts = Counter()
    for route, status in logs:
        by_route[route].append(status)
        counts[status] += 1
    return {
        "by_route": dict(by_route),
        "top_statuses": counts.most_common(2),
    }

Converting dict(by_route) at the boundary prevents callers from accidentally creating empty lists when probing missing routes.

3. UTC-First datetime & zoneinfo

Python has two kinds of datetime objects: naive (tzinfo is None, ambiguous!) and aware (attached to a real timezone). Comparing a naive and an aware datetime raises TypeError, and calling datetime.now() without a timezone silently uses whatever clock the container happens to run on.

[SENIOR MINDSET] The Golden Rule of Backend Time

1. Always generate UTC: Use datetime.now(timezone.utc) (note: datetime.utcnow() is deprecated in Python 3.12+ because it returns a naive object!).
2. Store & compare in UTC: Persist ISO-8601 strings with offset (e.g. 2027-03-14T15:30:00+00:00).
3. Convert to local timezone only at the edge: Use Python 3.9+ zoneinfo.ZoneInfo("America/New_York") when rendering for a human user. In minimal Docker/WASM containers that lack OS timezone files, install the official tzdata package.

Implement normalize_to_utc_iso(raw_iso, assume_utc_if_naive=False) for an ingestion pipeline:

- Parse dt = datetime.fromisoformat(raw_iso) (Python 3.11+ handles trailing "Z" natively!).

- Return dt.isoformat().

Hint 1: Inside if is_naive:, check if not assume_utc_if_naive: raise ValueError("Naive timestamp rejected"), then dt = dt.replace(tzinfo=timezone.utc).

Final Answer & Rationale: 
from datetime import datetime, timezone

def normalize_to_utc_iso(raw_iso, assume_utc_if_naive=False):
    dt = datetime.fromisoformat(raw_iso)
    is_naive = dt.tzinfo is None or dt.utcoffset() is None
    if is_naive:
        if not assume_utc_if_naive:
            raise ValueError("Naive timestamp rejected")
        dt = dt.replace(tzinfo=timezone.utc)
    return dt.astimezone(timezone.utc).isoformat()

Notice the distinction: .replace(tzinfo=...) stamps a timezone onto a naive clock without shifting the hour, while .astimezone(timezone.utc) shifts an aware instant into UTC!
