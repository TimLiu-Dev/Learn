1. Modules, __init__.py, src/ Layout & sys.path

A module is any .py file; a package is a directory containing an __init__.py file (which marks it as an explicit package and runs initialization/re-exports on import). When you run import rag_app.embedder, Python follows a strict 2-step lookup:

  1. Check sys.modules cache: If already imported in this process, Python returns the cached module object immediately (module top-level code runs only once!).
  2. Search sys.path in order: Current script directory (or CWD), PYTHONPATH, then your virtual environment's site-packages.
[SENIOR MINDSET] Why Production Repos Use the src/ Layout

Putting code in my_project/src/rag_app/ instead of my_project/rag_app/ stops Python from accidentally importing raw local folders from CWD during pytest—ensuring tests always verify the actually installed package (including entrypoints and metadata).

Write resolve_src_module(module_dotted, existing_files) to simulate classic package resolution under src/:

- Split module_dotted (e.g. "rag.core.embedder") into parts ["rag", "core", "embedder"].
- Every parent package prefix src/rag/__init__.py, src/rag/core/__init__.py MUST exist in existing_files.
- For the final target, check if f"src/{'/'.join(parts)}.py" exists (return it), else if f"src/{'/'.join(parts)}/__init__.py" exists (return it).
- If module_dotted is blank or any required file is missing, return None.

Hint 1: Loop for i in range(1, len(parts)):, build pkg_init = f"src/{'/'.join(parts[:i])}/__init__.py", and if pkg_init not in existing_files: return None.
Hint 2: Build base = f"src/{'/'.join(parts)}"; return f"{base}.py" if in existing_files, elif f"{base}/__init__.py" in existing_files, else None.
Final Answer & Rationale: 
def resolve_src_module(module_dotted, existing_files):
    if not module_dotted or not module_dotted.strip():
        return None
    parts = module_dotted.strip().split(".")
    for i in range(1, len(parts)):
        pkg_init = f"src/{'/'.join(parts[:i])}/__init__.py"
        if pkg_init not in existing_files:
            return None
    base = f"src/{'/'.join(parts)}"
    if f"{base}.py" in existing_files:
        return f"{base}.py"
    if f"{base}/__init__.py" in existing_files:
        return f"{base}/__init__.py"
    return None

Checking parent __init__.py files mirrors how Python's classic package hierarchy prevents random folders from shadowing real packages.

2. Circular Imports & Production Fixes

A circular import happens when routes.py imports services.py at module top level, and services.py imports routes.py at top level. While Python is halfway through executing routes.py, it tries to grab names from services.py before routes.py has finished defining them—raising ImportError: cannot import name '...' from partially initialized module.

  • Fix 1 (Best): Extract shared code into a third lower-level module (e.g. models.py or schemas.py) that both import.
  • Fix 2 (Type-only imports): Guard type annotations with from typing import TYPE_CHECKING and if TYPE_CHECKING: so they never execute at runtime.
  • Fix 3 (Local/lazy import): Move the import inside the specific function/method that needs it.
[PRACTICE 2] Import Cycle Detector (has_import_cycle)
Solved ✓

Write has_import_cycle(import_graph) where import_graph maps each module name to a list of modules it imports at top level (e.g. {"a": ["b"], "b": ["a"]}):

- Return True if any dependency cycle exists (including self-imports like "a": ["a"]), otherwise False.
- Use standard 3-state DFS (visiting set for current recursion stack, visited set for fully checked nodes).

Hint 1: Inside dfs(mod), loop for dep in import_graph.get(mod, []): and if dfs(dep): return True.
Hint 2: At the bottom, return any(dfs(mod) for mod in import_graph).
Final Answer & Rationale: 
def has_import_cycle(import_graph):
    visiting = set()
    visited = set()

    def dfs(mod):
        if mod in visiting:
            return True
        if mod in visited:
            return False
        visiting.add(mod)
        for dep in import_graph.get(mod, []):
            if dfs(dep):
                return True
        visiting.remove(mod)
        visited.add(mod)
        return False

    return any(dfs(mod) for mod in import_graph)

A clean module DAG (Directed Acyclic Graph) has layers pointing downward: routes → services → models, with zero back-edges.

3. Virtual Environments, PEP 621 pyproject.toml & uv Workspaces

Never install packages into your OS system Python. Always isolate dependencies inside a project virtual environment (.venv/). In 2027, uv (by Astral) unifies Python version installation (replacing pyenv), virtualenvs (venv), fast resolution (pip), and cross-platform lockfiles + monorepo workspaces:

Tool Role & Speed Lockfile & Python Versions Best Fit in 2027
uv All-in-one Rust package/project manager (10–100x faster than pip) uv.lock (cross-platform) + installs Python versions directly Default choice for new AI/backend services & monorepo workspaces
pip + venv Built-in baseline installer + venv module Manual requirements.txt; needs pyenv for Python versions Legacy repos or minimal Docker stages
Poetry Mature Python project manager poetry.lock; relies on external Python / pyenv Existing teams already standardized on Poetry

import tomllib

def parse_pyproject_summary(toml_text):
    data = tomllib.loads(toml_text)
    project = data.get("project")
    if not isinstance(project, dict) or not str(project.get("name", "")).strip():
        raise ValueError("Missing [project].name")
    return {
        "name": project["name"],
        "requires_python": project.get("requires-python", ""),
        "dependency_count": len(project.get("dependencies", [])),
        "scripts": sorted(project.get("scripts", {}).keys()),
    }

4. Building Shippable CLIs (argparse + Typer/Rich)

Every production AI service eventually needs an admin CLI (for running migrations, re-indexing vector embeddings, or running evals). You wire a function into [project.scripts] in pyproject.toml (ragctl = "rag_app.cli:main"), and uv installs it as a real terminal command!

  • argparse (Standard Library): Zero external dependencies, great for scripts and Pyodide. Use add_subparsers(dest="command", required=True) for git-style subcommands.
  • Typer + Rich (Production AI Stack): Uses Python type hints (top_k: int = 5) to generate CLIs, validation, and colorized tables/progress bars automatically.
Production Reference: Equivalent CLI in Typer + Rich
import typer
from rich.console import Console

app = typer.Typer(help="RAG operations CLI")
console = Console()

@app.command()
def ask(question: str, top_k: int = typer.Option(5, min=1, max=20)):
    console.print(f"[bold green]Querying top {top_k} chunks:[/] {question}")

if __name__ == "__main__":
    app()

Build run_rag_cli(argv) using argparse.ArgumentParser:

- Support two required subcommands:
  1) index with required --dir (str) and optional --batch (int, default 32).
  2) search with positional query (str) and optional --limit (int, default 5).
- Parse argv safely: if argparse.ArgumentError or SystemExit is raised, raise ValueError("Invalid CLI arguments").
- Also validate batch > 0 and limit > 0 (else raise ValueError), and return vars(args) as a dictionary.

Hint 1: Add idx_p.add_argument("--batch", type=int, default=32), srch_p.add_argument("query"), and srch_p.add_argument("--limit", type=int, default=5).
Hint 2: Check if result.get("batch", 1) <= 0 or result.get("limit", 1) <= 0: raise ValueError("Must be positive") before returning result.
Final Answer & Rationale: 
import argparse

def run_rag_cli(argv):
    parser = argparse.ArgumentParser(prog="ragctl", exit_on_error=False)
    subs = parser.add_subparsers(dest="command", required=True)

    idx_p = subs.add_parser("index", exit_on_error=False)
    idx_p.add_argument("--dir", required=True)
    idx_p.add_argument("--batch", type=int, default=32)

    srch_p = subs.add_parser("search", exit_on_error=False)
    srch_p.add_argument("query")
    srch_p.add_argument("--limit", type=int, default=5)

    try:
        ns = parser.parse_args(argv)
    except (argparse.ArgumentError, SystemExit) as exc:
        raise ValueError("Invalid CLI arguments") from exc

    result = vars(ns)
    if result.get("batch", 1) <= 0 or result.get("limit", 1) <= 0:
        raise ValueError("Numeric flags must be positive")
    return result

Accepting an explicit argv parameter (defaulting to None in production main(argv=None)) makes every CLI unit-testable without spawning subprocesses!
