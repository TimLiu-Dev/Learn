1. SQLAlchemy 2.0 Async, Connection Pools & Repository Pattern

Modern SQLAlchemy 2.0 pairs full Python type hints (Mapped[str], mapped_column) with non-blocking async drivers (asyncpg for PostgreSQL). A few core rules keep production databases healthy:

  • Create one AsyncEngine per process (holding the connection pool, e.g. pool_size=10, max_overflow=20, pool_pre_ping=True), and create one short-lived AsyncSession per HTTP request.
  • Repository + Unit of Work: Wrap raw SQL/ORM queries inside a Repository class (DocumentRepo) and commit once at the service/request boundary—never scatter session.commit() inside helper functions.
  • Never format values into SQL f-strings! Always use bound parameters (? in SQLite, :name / ORM expressions in SQLAlchemy) so SQL injection is impossible.
[PRODUCTION CODE — POSTGRES + SQLALCHEMY 2.0 ASYNC]
from sqlalchemy import ForeignKey, String, select
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column

engine = create_async_engine("postgresql+asyncpg://app:pw@db:5432/docupulse", pool_size=10, pool_pre_ping=True)
SessionLocal = async_sessionmaker(engine, expire_on_commit=False)

class Base(DeclarativeBase):
    pass

class Document(Base):
    __tablename__ = "documents"
    id: Mapped[str] = mapped_column(String(64), primary_key=True)
    tenant_id: Mapped[str] = mapped_column(String(64), index=True)
    title: Mapped[str] = mapped_column(String(255))

class DocumentRepository:
    def __init__(self, session: AsyncSession) -> None:
        self.session = session

    async def list_for_tenant(self, tenant_id: str) -> list[Document]:
        stmt = select(Document).where(Document.tenant_id == tenant_id).order_by(Document.id)
        return list((await self.session.scalars(stmt)).all())

import sqlite3

def init_schema(conn: sqlite3.Connection) -> None:
    conn.execute("""
        CREATE TABLE IF NOT EXISTS documents (
            id TEXT PRIMARY KEY,
            tenant_id TEXT NOT NULL,
            title TEXT NOT NULL
        )
    """)
    conn.commit()

def upsert_and_list(conn: sqlite3.Connection, tenant_id: str, docs: list[tuple[str, str]]) -> list[tuple[str, str]]:
    rows = [(doc_id, tenant_id, title) for doc_id, title in docs]
    conn.executemany(
        "INSERT OR REPLACE INTO documents (id, tenant_id, title) VALUES (?, ?, ?)",
        rows,
    )
    conn.commit()
    cur = conn.execute(
        "SELECT id, title FROM documents WHERE tenant_id = ? ORDER BY id ASC",
        (tenant_id,),
    )
    return cur.fetchall()

Notice two critical habits: parameterized ? bindings prevent SQL injection even on adversarial titles like "'; DROP TABLE documents;--", and every query enforces WHERE tenant_id = ?.

2. Eliminating N+1 Queries & Zero-Downtime Alembic Migrations

The N+1 query bug happens when you run 1 query to fetch 50 tenants, and then loop over them running 50 separate SQL queries to fetch each tenant's documents or counts. In SQLAlchemy Async, implicit lazy loading even crashes with MissingGreenlet! Fix it by eager loading (selectinload(Tenant.documents) or joinedload) or aggregating in one SQL JOIN.

[ALEMBIC MIGRATIONS] Expand-and-Contract for Zero Downtime

Never rename or drop a column in a single deploy while old app pods are still running! Instead: (1) Expand—add the new nullable column via alembic revision --autogenerate and backfill; (2) Deploy app code reading/writing the new column; (3) Contract—drop the old column in a later migration after old pods drain.

[PRACTICE 2] Eliminate N+1 Queries With a Single LEFT JOIN Aggregation
Solved ✓

Given tables tenants (id TEXT PRIMARY KEY, name TEXT) and chunks (id TEXT PRIMARY KEY, tenant_id TEXT), write count_chunks_per_tenant(conn) using one SQL query (no Python loops querying per tenant!) that returns a list of (tenant_id, name, chunk_count) tuples ordered by tenant_id ASC—including tenants that have 0 chunks!

Hint 1: Count COUNT(c.id), NOT COUNT(*)! With a LEFT JOIN, COUNT(*) would return 1 instead of 0 for tenants with no chunks.
Hint 2: Use LEFT JOIN chunks c ON c.tenant_id = t.id GROUP BY t.id, t.name ORDER BY t.id ASC.
Final Answer & Rationale: 
import sqlite3

def count_chunks_per_tenant(conn: sqlite3.Connection) -> list[tuple[str, str, int]]:
    query = """
        SELECT t.id, t.name, COUNT(c.id) AS chunk_count
        FROM tenants t
        LEFT JOIN chunks c ON c.tenant_id = t.id
        GROUP BY t.id, t.name
        ORDER BY t.id ASC
    """
    return conn.execute(query).fetchall()

COUNT(c.id) ignores NULL right-hand rows from LEFT JOIN, giving 0 for EmptyCo in a single database round trip.

3. Isolation Levels, Lost Updates & SELECT ... FOR UPDATE

Suppose a tenant has 10 LLM credits left and two concurrent API requests arrive at the exact same millisecond, each deducting 8 credits. If your code does read in Python → check → write back, both requests read 10 and both write 2—giving 16 credits for the price of 8!

Pattern PostgreSQL SQL When to Use
Conditional Atomic Update UPDATE quotas SET credits = credits - :amt WHERE id = :id AND credits >= :amt Fastest lock-free guard for counters, balances, and token quotas (check rowcount == 1).
Pessimistic Row Lock SELECT ... WHERE id = :id FOR UPDATE Complex multi-step read-modify-write inside a single transaction.
Non-Blocking Job Claim SELECT ... WHERE status = 'queued' FOR UPDATE SKIP LOCKED LIMIT 1 Multiple Postgres workers claiming background ingestion jobs without blocking each other.
[PRACTICE 3] Atomic Credit Reservation (Preventing Lost Updates)
Solved ✓

Given table quotas (tenant_id TEXT PRIMARY KEY, credits INTEGER NOT NULL), implement reserve_credits(conn, tenant_id, amount) -> bool:

- If amount <= 0, raise ValueError("amount must be positive").
- Inside a transaction (with conn:), execute a single conditional UPDATE that subtracts amount only when tenant_id = ? AND credits >= ?.
- Return True if cur.rowcount == 1 (reservation succeeded), else False (insufficient credits or unknown tenant).

Hint 1: Write with conn: and execute UPDATE quotas SET credits = credits - ? WHERE tenant_id = ? AND credits >= ? with (amount, tenant_id, amount).
Hint 2: Check return cur.rowcount == 1 directly!
Final Answer & Rationale: 
import sqlite3

def reserve_credits(conn: sqlite3.Connection, tenant_id: str, amount: int) -> bool:
    if amount <= 0:
        raise ValueError("amount must be positive")
    with conn:
        cur = conn.execute(
            "UPDATE quotas SET credits = credits - ? WHERE tenant_id = ? AND credits >= ?",
            (amount, tenant_id, amount),
        )
    return cur.rowcount == 1

Because the database executes the credits >= amount predicate and subtraction atomically under a row write lock, two concurrent requests can never overdraw the quota.

4. pgvector Cosine Similarity & Hybrid Search (RRF)

Why store embeddings in PostgreSQL via pgvector? You get transactional consistency with your tenant permissions and SQL filters in the same database—no syncing a separate vector SaaS!

  • Cosine Distance (<=>): Measures angle between vectors regardless of length. Similarity = 1.0 - (a <=> b).
  • HNSW Index: Faster recall/latency at query time than IVFFlat and works well even as rows grow dynamically (CREATE INDEX ON chunks USING hnsw (embedding vector_cosine_ops)).
  • Hybrid Search + Reciprocal Rank Fusion (RRF): Vector embeddings capture meaning ("automobile" ↔ "car"), while full-text keyword search (BM25 / Postgres tsvector) catches exact SKUs or error codes like ERR_4091. Fusing both ranked lists via score(doc) = sum(1 / (k + rank)) (typically k=60) gives the best of both worlds without brittle score normalization!

[PRACTICE 4] Cosine Similarity & Reciprocal Rank Fusion (RRF) Scorer
Solved ✓

Implement the core math behind hybrid RAG retrieval:

1. cosine_similarity(vec_a, vec_b) -> float: compute dot(a, b) / (norm(a) * norm(b)) using zip(..., strict=True). If either vector has zero norm (0.0), return 0.0 instead of crashing with ZeroDivisionError!
2. rrf_fuse(ranked_lists, k=60) -> list[str]: given a list of ranked doc-ID lists (e.g. [["d1", "d2"], ["d2", "d3"]]), accumulate scores[doc_id] += 1.0 / (k + rank) where rank is 1-based (enumerate(..., start=1)). Return doc IDs sorted by descending RRF score (tie-break by doc ID ascending).

Hint 1: In cosine_similarity, write if norm_a == 0.0 or norm_b == 0.0: return 0.0, then return dot_val / (norm_a * norm_b).
Hint 2: In rrf_fuse, do scores[doc_id] = scores.get(doc_id, 0.0) + 1.0 / (k + rank), then return sorted(scores.keys(), key=lambda d: (-scores[d], d)).
Final Answer & Rationale: 
import math

def cosine_similarity(vec_a: list[float], vec_b: list[float]) -> float:
    dot_val = sum(a * b for a, b in zip(vec_a, vec_b, strict=True))
    norm_a = math.sqrt(sum(a * a for a in vec_a))
    norm_b = math.sqrt(sum(b * b for b in vec_b))
    if norm_a == 0.0 or norm_b == 0.0:
        return 0.0
    return dot_val / (norm_a * norm_b)

def rrf_fuse(ranked_lists: list[list[str]], k: int = 60) -> list[str]:
    scores: dict[str, float] = {}
    for doc_list in ranked_lists:
        for rank, doc_id in enumerate(doc_list, start=1):
            scores[doc_id] = scores.get(doc_id, 0.0) + 1.0 / (k + rank)
    return sorted(scores.keys(), key=lambda d: (-scores[d], d))

Notice why RRF is beloved in production RAG: cosine scores live in [-1, 1] while BM25 scores are unbounded—RRF uses only ranks, so documents appearing near the top of both lists naturally rise to #1!
