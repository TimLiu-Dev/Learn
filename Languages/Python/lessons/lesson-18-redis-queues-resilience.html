1. Redis Caching, Distributed Locks & Idempotency Keys

  • Cache-Aside + TTL Jitter: Store expensive embedding lookups in Redis with a TTL (e.g., 3600 + random.randint(0, 300)) so thousands of keys don't expire at the exact same second (cache stampede).
  • Distributed Locks (SET key token NX PX 5000): Acquire with a unique random token and release via an atomic Lua script checking redis.call("get", KEYS[1]) == ARGV[1]—otherwise a slow worker whose lock expired could accidentally delete another worker's new lock!
  • Idempotency Keys on POST /ingest: Clients send Idempotency-Key: <uuid>. Store (payload_hash, response) in Redis/Postgres: if the same key returns with the same payload hash, replay the saved response; if the same key arrives with a different payload hash, reject with 409 Conflict!
[PRODUCTION CODE — REDIS ASYNCIO CACHE & LOCK]
import uuid
import redis.asyncio as redis

r = redis.from_url("redis://redis:6379/0", decode_responses=True)

async def acquire_lock(key: str, ttl_ms: int = 5000) -> str | None:
    token = str(uuid.uuid4())
    acquired = await r.set(key, token, nx=True, px=ttl_ms)
    return token if acquired else None

UNLOCK_LUA = """
if redis.call("get", KEYS[1]) == ARGV[1] then
    return redis.call("del", KEYS[1])
else
    return 0
end
"""
[PRACTICE 1] In-Memory TTL Cache & Idempotency Store
Solved ✓

Implement two core classes using an injectable clock now: float (which makes time-based tests deterministic!):

1. TTLCache: set(key, value, ttl_s, now) stores (value, now + ttl_s); get(key, now) returns value if now < expires_at, otherwise deletes the expired entry (if any) and returns None.
2. IdempotencyStore: execute(key, payload_hash, handler) checks internal dict self._records. If key was seen before: if stored payload_hash differs, raise ValueError("Idempotency key conflict"); else return the stored response without calling handler() again! Otherwise call res = handler(), save (payload_hash, res), and return res.

Hint 1: In TTLCache.get, do entry = self._data.get(key). If entry is None return None; unpack val, exp = entry; if now >= exp: del self._data[key]; return None; else return val.
Hint 2: In IdempotencyStore.execute, if key in self._records, unpack old_hash, old_res = self._records[key]; if old_hash != payload_hash raise ValueError("Idempotency key conflict"); else return old_res.
Final Answer & Rationale: 
class TTLCache:
    def __init__(self) -> None:
        self._data: dict[str, tuple[object, float]] = {}

    def set(self, key: str, value: object, ttl_s: float, now: float) -> None:
        self._data[key] = (value, now + ttl_s)

    def get(self, key: str, now: float) -> object | None:
        entry = self._data.get(key)
        if entry is None:
            return None
        val, exp = entry
        if now >= exp:
            del self._data[key]
            return None
        return val

class IdempotencyStore:
    def __init__(self) -> None:
        self._records: dict[str, tuple[str, object]] = {}

    def execute(self, key: str, payload_hash: str, handler):
        if key in self._records:
            old_hash, old_res = self._records[key]
            if old_hash != payload_hash:
                raise ValueError("Idempotency key conflict")
            return old_res
        res = handler()
        self._records[key] = (payload_hash, res)
        return res

Notice how injecting now: float lets unit tests fast-forward 10 seconds instantaneously without slow time.sleep()!

2. Background Worker Queues, DLQs & Token-Bucket Rate Limiting

Parsing a 50-page PDF and calling an embedding API takes seconds—never block an HTTP POST waiting on it. Instead, the API persists the job, pushes a job ID onto a Redis queue, and returns 202 Accepted. Background workers pop jobs, retry transient errors, and move permanently failing "poison pill" jobs into a Dead-Letter Queue (DLQ) after max_attempts so one bad PDF cannot stall the whole queue.

To protect your upstream OpenAI/Anthropic quota from one noisy tenant, enforce a Token Bucket rate limiter: each tenant's bucket holds up to capacity tokens (burst allowance) and refills steadily at refill_rate tokens per second.

[PRACTICE 2] Token-Bucket Rate Limiter (Burst + Steady Refill)
Solved ✓

Complete TokenBucket initialized with capacity: float, refill_rate: float (tokens/sec), and now: float = 0.0:

- Start with self.tokens = float(capacity) and self.last_refill = now.
- In allow(cost: float = 1.0, now: float = 0.0) -> bool:
1. Compute elapsed = max(0.0, now - self.last_refill).
2. Refill: self.tokens = min(self.capacity, self.tokens + elapsed * self.refill_rate) and update self.last_refill = now.
3. If self.tokens >= cost, subtract cost and return True; otherwise return False (without subtracting).

Hint 1: Compute elapsed = max(0.0, now - self.last_refill), then self.tokens = min(self.capacity, self.tokens + elapsed * self.refill_rate) and self.last_refill = now.
Hint 2: Check if self.tokens >= cost: self.tokens -= cost; return True, then return False.
Final Answer & Rationale: 
class TokenBucket:
    def __init__(self, capacity: float, refill_rate: float, now: float = 0.0) -> None:
        self.capacity = float(capacity)
        self.refill_rate = float(refill_rate)
        self.tokens = float(capacity)
        self.last_refill = float(now)

    def allow(self, cost: float = 1.0, now: float = 0.0) -> bool:
        elapsed = max(0.0, now - self.last_refill)
        self.tokens = min(self.capacity, self.tokens + elapsed * self.refill_rate)
        self.last_refill = now
        if self.tokens >= cost:
            self.tokens -= cost
            return True
        return False

Unlike fixed-window counters (which let 2x bursts sneak through right across a minute boundary), Token Bucket smoothly caps both sustained rate and burst size.

3. Resilient httpx Clients & Exponential Backoff + Full Jitter

Every external HTTP call (OpenAI, Anthropic, Cohere, internal webhooks) must obey three non-negotiable rules:

  • Explicit Timeouts: Configure httpx.Timeout(connect=3.0, read=25.0, write=5.0, pool=5.0) and reuse one shared httpx.AsyncClient via FastAPI lifespan (connection pooling!).
  • Retry ONLY Safe / Transient Errors: Retry network timeouts, 429, and 5xx—never retry 400 or 401!
  • Exponential Backoff + Full Jitter: Without randomness (jitter), 500 failed workers all retry at exact intervals (1s, 2s, 4s) and DDoS your own upstream server again (thundering herd). Full Jitter picks random.uniform(0, min(cap, base * (2 ** attempt))).
[PRACTICE 3] Full-Jitter Exponential Backoff & Retry Loop
Solved ✓

Implement two functions:

1. full_jitter_delay(attempt: int, base: float = 0.5, cap: float = 8.0, rand_fn=random.random) -> float: compute ceiling = min(cap, base * (2 ** attempt)) and return rand_fn() * ceiling.
2. call_with_retry(fn, max_attempts: int, retryable_exc=(TimeoutError,), sleep_fn=lambda d: None, rand_fn=random.random): try calling fn() up to max_attempts times. If it raises an exception in retryable_exc and attempts remain, compute delay = full_jitter_delay(attempt, rand_fn=rand_fn) (using 0-based attempt), call sleep_fn(delay), and retry; on the final failure, re-raise!

Hint 1: Inside except retryable_exc:, first check if attempt == max_attempts - 1: raise.
Hint 2: Otherwise call sleep_fn(full_jitter_delay(attempt, rand_fn=rand_fn)) so the loop continues to the next attempt.
Final Answer & Rationale: 
import random

def full_jitter_delay(attempt: int, base: float = 0.5, cap: float = 8.0, rand_fn=random.random) -> float:
    ceiling = min(cap, base * (2 ** attempt))
    return rand_fn() * ceiling

def call_with_retry(fn, max_attempts: int = 3, retryable_exc=(TimeoutError,), sleep_fn=lambda d: None, rand_fn=random.random):
    for attempt in range(max_attempts):
        try:
            return fn()
        except retryable_exc:
            if attempt == max_attempts - 1:
                raise
            sleep_fn(full_jitter_delay(attempt, rand_fn=rand_fn))

Dependency-injecting sleep_fn and rand_fn lets your test suite verify exact backoff bounds in milliseconds with zero real sleeping.

4. Circuit Breakers: Failing Fast When an Upstream Is Down

Retries help on brief blips, but if an LLM provider is completely down for 5 minutes, retrying every request piles up thousands of stuck coroutines! A Circuit Breaker stops the bleeding using 3 states:

  • CLOSED (normal): Requests pass through. Consecutive failures increment a counter; reaching failure_threshold trips the breaker to OPEN and records opened_at.
  • OPEN (fail-fast): Requests are rejected immediately without touching the network until now - opened_at >= recovery_timeout, when it transitions to HALF_OPEN.
  • HALF_OPEN (probe): Allows a trial request through: on success → resets to CLOSED; on failure → trips straight back to OPEN!
[PRACTICE 4] 3-State Circuit Breaker State Machine
Solved ✓

Implement CircuitBreaker(failure_threshold=3, recovery_timeout=10.0) with attributes state ("CLOSED", "OPEN", "HALF_OPEN"), failures (int), and opened_at (float | None):

- allow_request(now: float) -> bool: if "CLOSED" or "HALF_OPEN" return True. If "OPEN": if now - self.opened_at >= self.recovery_timeout, transition self.state = "HALF_OPEN" and return True; else return False.
- record_success() -> None: reset self.failures = 0, self.opened_at = None, self.state = "CLOSED".
- record_failure(now: float) -> None: increment self.failures += 1. If self.state == "HALF_OPEN" OR self.failures >= self.failure_threshold, set self.state = "OPEN" and self.opened_at = now.

Hint 1: In allow_request(now), if self.state == "OPEN" and self.opened_at is not None and (now - self.opened_at) >= self.recovery_timeout, set self.state = "HALF_OPEN" and return True; if still "OPEN" return False.
Hint 2: In record_failure(now), do self.failures += 1, then if self.state == "HALF_OPEN" or self.failures >= self.failure_threshold: self.state = "OPEN"; self.opened_at = now.
Final Answer & Rationale: 
class CircuitBreaker:
    def __init__(self, failure_threshold: int = 3, recovery_timeout: float = 10.0) -> None:
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.state = "CLOSED"
        self.failures = 0
        self.opened_at: float | None = None

    def allow_request(self, now: float) -> bool:
        if self.state == "OPEN":
            if self.opened_at is not None and (now - self.opened_at) >= self.recovery_timeout:
                self.state = "HALF_OPEN"
                return True
            return False
        return True

    def record_success(self) -> None:
        self.failures = 0
        self.opened_at = None
        self.state = "CLOSED"

    def record_failure(self, now: float) -> None:
        self.failures += 1
        if self.state == "HALF_OPEN" or self.failures >= self.failure_threshold:
            self.state = "OPEN"
            self.opened_at = now

Notice how cleanly a 20-line state machine protects your fast-failing FastAPI endpoints from cascading latency when an external provider goes down.
