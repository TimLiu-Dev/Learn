1. Function Decorators & @functools.wraps

In Python, functions are regular objects you can pass around and return. A decorator is simply a function that accepts another function and returns a replacement wrapper: 

@measure_time
def call_llm(prompt): ...

# Is exact syntax sugar for:
call_llm = measure_time(call_llm)
[WATCH OUT] Always Add @functools.wraps(func)!

Without @functools.wraps(func) on your inner wrapper function, the decorated function loses its original __name__, __doc__, and signature—breaking OpenAPI docs in FastAPI, debug tracebacks, and test discovery.

[PRACTICE 1] Scaffolded Lab: count_calls Decorator
Solved ✓

Write a decorator count_calls(func) that tracks how many times a function has been invoked:

- Decorate the inner wrapper(*args, **kwargs) with @functools.wraps(func).
- Initialize wrapper.call_count = 0 before returning wrapper.
- Each time wrapper runs, increment wrapper.call_count += 1 and return func(*args, **kwargs).

Hint 1: Place @functools.wraps(func) directly above def wrapper(*args, **kwargs):.
Hint 2: After defining wrapper, add wrapper.call_count = 0 and return wrapper.
Final Answer & Rationale: 
import functools

def count_calls(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        wrapper.call_count += 1
        return func(*args, **kwargs)
    wrapper.call_count = 0
    return wrapper

Functions in Python are objects, so attaching wrapper.call_count gives every decorated function its own isolated counter while @functools.wraps preserves __name__ and __doc__.

2. Parameterized Decorators & Class Decorators

How does @retry(max_attempts=3) take arguments? By adding one outer factory function! Python evaluates retry(max_attempts=3) first, which returns the actual decorator(func), which then returns wrapper(*args, **kwargs).

  • 3-layer mental model: factory(config) → decorator(func) → wrapper(*args, **kwargs).
  • Class decorators: @register_tool("search") receives a cls object instead of a function, letting you attach metadata or register classes into a central plugin dictionary without inheritance boilerplate.

Solved ✓

Implement retry_on_error(max_attempts=2, fallback=None) (3 nested functions):

- Preserve metadata with @functools.wraps(func).
- Try calling func(*args, **kwargs) up to max_attempts times (catching Exception).
- If all attempts fail: if fallback is not None, return fallback; otherwise re-raise the last exception (raise).

Hint 1: Loop with for attempt in range(1, max_attempts + 1): and wrap return func(*args, **kwargs) in try:.
Hint 2: In except Exception:, check if attempt == max_attempts: → if fallback is not None: return fallback, else raise.
Final Answer & Rationale: 
import functools

def retry_on_error(max_attempts=2, fallback=None):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, max_attempts + 1):
                try:
                    return func(*args, **kwargs)
                except Exception:
                    if attempt == max_attempts:
                        if fallback is not None:
                            return fallback
                        raise
        return wrapper
    return decorator

Notice the bare raise inside the final except block—it re-raises the exact original exception and traceback without wrapping it.

3. The Descriptor Protocol (__get__, __set__, __set_name__) & @property

Ever wondered how @property, SQLAlchemy columns, or regular methods work? They all implement Python's Descriptor Protocol—an object placed as a class attribute that intercepts dot-access (obj.attr / obj.attr = val):

  • __set_name__(self, owner, name): Called automatically when the class is created, telling the descriptor its attribute name (e.g. "temperature").
  • __get__(self, instance, owner): Called on read. Rule: when accessed on the class itself (Config.temperature), instance is None—return self!
  • __set__(self, instance, value): Called on assignment (makes it a data descriptor, which takes priority over instance.__dict__).
  • @property internals: Built-in property(fget, fset, fdel) is literally a C descriptor whose __get__ calls fget(instance) and whose __set__ calls fset(instance, value)!
[WATCH OUT] Never Store Per-Instance Values on self Inside a Descriptor!

A descriptor instance lives on the class, shared by every object of that class. Always store values in instance.__dict__[self.name] (never self.value = value), otherwise changing one instance overwrites all of them!

[PRACTICE 3] Reusable NonEmptyString Descriptor
Solved ✓

Implement a data descriptor NonEmptyString:

- __set_name__(self, owner, name): save self.name = name.
- __get__(self, instance, owner): if instance is None, return self; otherwise return instance.__dict__[self.name].
- __set__(self, instance, value): if not isinstance(value, str) or not value.strip(), raise ValueError; otherwise store value.strip() in instance.__dict__[self.name].

Hint 1: In __get__, return self when instance is None, otherwise return instance.__dict__[self.name].
Hint 2: In __set__, check if not isinstance(value, str) or not value.strip(): raise ValueError(f"{self.name} must be a non-empty string"), then assign instance.__dict__[self.name] = value.strip().
Final Answer & Rationale: 
class NonEmptyString:
    def __set_name__(self, owner, name):
        self.name = name

    def __get__(self, instance, owner):
        if instance is None:
            return self
        return instance.__dict__[self.name]

    def __set__(self, instance, value):
        if not isinstance(value, str) or not value.strip():
            raise ValueError(f"{self.name} must be a non-empty string")
        instance.__dict__[self.name] = value.strip()

Because NonEmptyString stores values inside instance.__dict__, two different AgentProfile objects stay completely independent while sharing one validation rule.

4. __init_subclass__ vs. Metaclasses

Sometimes you want validation or registration to run the moment a developer defines a subclass—before any object is ever instantiated:

Mechanism Complexity & Readability When to Choose
__init_subclass__ (PEP 487) Low — plain method on the base class 95% of cases: plugin auto-registration, enforcing required class attributes, class keyword args.
Metaclass (class Meta(type):) High — can cause metaclass layout conflicts when mixing bases (e.g. ABC, Enum) Framework internals needing to rewrite the class namespace before class creation (__prepare__ / __new__).
[SENIOR MINDSET] Tim Peters' Rule of Thumb

"Metaclasses are deeper magic than 99% of users should ever worry about." In modern Python 3.12, reach for class decorators or __init_subclass__ first; only write a custom metaclass when you genuinely need __prepare__ or cross-cutting type.__new__ interception.

Complete PluginBase.__init_subclass__(cls, *, plugin_id=None, **kwargs):

- Always call super().__init_subclass__(**kwargs).
- If not isinstance(plugin_id, str) or not plugin_id.strip(), raise TypeError("plugin_id is required").
- Normalize pid = plugin_id.strip(). If pid in PluginBase.registry, raise ValueError(f"Duplicate plugin_id: {pid}").
- Otherwise set cls.plugin_id = pid and store PluginBase.registry[pid] = cls.

Hint 1: Check if not isinstance(plugin_id, str) or not plugin_id.strip(): raise TypeError("plugin_id is required").
Hint 2: Normalize pid = plugin_id.strip(), check if pid in PluginBase.registry: raise ValueError(...), then set cls.plugin_id = pid and PluginBase.registry[pid] = cls.
Final Answer & Rationale: 
class PluginBase:
    registry = {}

    def __init_subclass__(cls, *, plugin_id=None, **kwargs):
        super().__init_subclass__(**kwargs)
        if not isinstance(plugin_id, str) or not plugin_id.strip():
            raise TypeError("plugin_id is required")
        pid = plugin_id.strip()
        if pid in PluginBase.registry:
            raise ValueError(f"Duplicate plugin_id: {pid}")
        cls.plugin_id = pid
        PluginBase.registry[pid] = cls

Bad or duplicate plugin definitions fail fast at import/class-definition time instead of silently overwriting each other in production!
