1. Python Data Model, @dataclass(frozen=True, slots=True) & StrEnum

Python classes customize built-in operators and functions through dunder ("double underscore") methods:

  • __repr__(self): unambiguous developer-facing representation (used in logs and tracebacks).
  • __eq__(self, other): value equality (a == b). Return NotImplemented if other is an incompatible type.
  • __hash__(self): makes instances usable as dict keys / set members. Rule: equal objects MUST produce identical hashes! If you define __eq__ manually, Python sets __hash__ = None until you also define __hash__.
  • __slots__ = ("x", "y"): stores attributes in a fixed C-level array instead of a per-instance __dict__—saving ~40–50% RAM on millions of objects and catching typo attributes!

Instead of writing boilerplate __init__, __repr__, and __eq__ by hand, use @dataclass(frozen=True, slots=True) (Python 3.10+): it generates all of them automatically, makes instances immutable and hashable, and enables __slots__! Use field(default_factory=list) for mutable defaults, and __post_init__ for validation. For fixed string constants (model tiers, job states), prefer Python 3.11+ enum.StrEnum so enum members compare equal to strings AND serialize cleanly to JSON.

Build a @dataclass(frozen=True, slots=True) class named CacheKey for an LLM response cache:

- Fields: model: str, prompt_hash: str, and max_tokens: int = 512.
- In __post_init__(self), validate that self.model.strip() is non-empty and self.max_tokens > 0; otherwise raise ValueError.
- Because it is frozen, instances must be hashable (usable as dict keys) and reject attribute mutation with FrozenInstanceError.

Hint 1: Put @dataclass(frozen=True, slots=True) right above class CacheKey:.
Hint 2: Inside __post_init__, check if not self.model.strip() or self.max_tokens <= 0: raise ValueError("Invalid CacheKey").
Final Answer & Rationale: 
from dataclasses import dataclass

@dataclass(frozen=True, slots=True)
class CacheKey:
    model: str
    prompt_hash: str
    max_tokens: int = 512

    def __post_init__(self):
        if not self.model.strip() or self.max_tokens <= 0:
            raise ValueError("Invalid CacheKey")

frozen=True auto-generates __hash__ alongside __eq__, and slots=True removes per-instance __dict__ memory overhead.

[PRACTICE 2] StrEnum + Custom Dunder Identity (__repr__, __eq__, __hash__)
Solved ✓

1. Define class JobStatus(StrEnum) with members PENDING = "pending", RUNNING = "running", and DONE = "done".
2. Complete class EvalJob (plain class with __slots__ = ("job_id", "status")) so that:

- __repr__ returns f"EvalJob(job_id={self.job_id!r}, status={self.status!r})".
- __eq__ returns NotImplemented if not isinstance(other, EvalJob), else compares self.job_id == other.job_id.
- __hash__ returns hash(self.job_id) (matching __eq__!).

Hint 1: Add RUNNING = "running" and DONE = "done" inside JobStatus.
Hint 2: In EvalJob.__eq__, check if not isinstance(other, EvalJob): return NotImplemented and return self.job_id == other.job_id; in __hash__, return hash(self.job_id).
Final Answer & Rationale: 
from enum import StrEnum

class JobStatus(StrEnum):
    PENDING = "pending"
    RUNNING = "running"
    DONE = "done"

class EvalJob:
    __slots__ = ("job_id", "status")

    def __init__(self, job_id: str, status: JobStatus = JobStatus.PENDING):
        self.job_id = job_id
        self.status = status

    def __repr__(self):
        return f"EvalJob(job_id={self.job_id!r}, status={self.status!r})"

    def __eq__(self, other):
        if not isinstance(other, EvalJob):
            return NotImplemented
        return self.job_id == other.job_id

    def __hash__(self):
        return hash(self.job_id)

Because equality depends solely on immutable job_id, hashing self.job_id preserves the Python invariant: a == b implies hash(a) == hash(b).

2. Inheritance, C3 MRO & Composition Over Inheritance

Python supports multiple inheritance, resolved by the C3 Linearization Method Resolution Order (MRO), viewable via cls.__mro__. Crucially, super() does not mean "my parent class"—it means "the next class in type(self).__mro__"! That lets cooperative mixins chain cleanly without calling a shared base twice in diamond hierarchies.

[SENIOR MINDSET] Prefer Composition Over Inheritance

Even though C3 MRO handles diamonds cleanly, deep inheritance makes AI services brittle. Instead of class OpenAIRAGBot(RetryMixin, CacheMixin, BaseBot), pass dependencies into __init__ (composition: has-a instead of is-a): RagPipeline(retriever=..., llm_client=...). Swapping mocks in pytest becomes trivial!

3. typing.Protocol vs. ABC & Container Decision Table

How do you define an interface (like an Embedder or VectorStore) in Python?

  • abc.ABC (Nominal subtyping): Subclasses must explicitly inherit from the ABC and implement every @abstractmethod, otherwise instantiation fails with TypeError.
  • typing.Protocol (Structural subtyping / static duck typing): Any class that happens to have the matching methods satisfies the protocol—no inheritance required! Ideal for decoupling third-party SDKs and test fakes. Add @runtime_checkable if you also want isinstance(obj, MyProtocol) checks at runtime.
Container Mutability Runtime Validation? Best 2027 Use Case
NamedTuple Immutable (tuple subclass) No (type hints only) Tiny fixed coordinate/row tuples needing unpacking & zero overhead.
@dataclass(slots=True) Mutable or frozen=True Manual (__post_init__) Internal domain models, configs, cache keys, fast in-memory state.
TypedDict Plain dict at runtime No (static checker only) Typing existing JSON/dict payloads without converting dicts to objects.
Pydantic BaseModel Configurable Yes (strict/coercing) Untrusted API boundaries, FastAPI requests, LLM structured outputs (Lesson 10).

    max_tokens: int = Field(default=512, ge=1, le=8192)

[PRACTICE 3] Composition + typing.Protocol RAG Pipeline
Solved ✓

Decouple a RAG service from any concrete database using structural subtyping and composition:

- Define @runtime_checkable class Retriever(Protocol): with method def search(self, query: str, k: int) -> list[str]: ....
- Implement class KeywordRetriever: (WITHOUT inheriting from Retriever!) taking docs: list[str] in __init__, where search(self, query, k) returns up to k docs containing query.lower() (case-insensitive).
- Implement class RagService: taking retriever: Retriever in __init__, with method answer(self, query: str, k: int = 2) -> dict returning {"query": query, "contexts": self.retriever.search(query, k)}.

Hint 1: In KeywordRetriever.search: q = query.lower(), then return [d for d in self.docs if q in d.lower()][:k].
Hint 2: In RagService.__init__: store self.retriever = retriever; in answer: return {"query": query, "contexts": self.retriever.search(query, k)}.
Final Answer & Rationale: 
from typing import Protocol, runtime_checkable

@runtime_checkable
class Retriever(Protocol):
    def search(self, query: str, k: int) -> list[str]: ...

class KeywordRetriever:
    def __init__(self, docs: list[str]):
        self.docs = list(docs)

    def search(self, query: str, k: int) -> list[str]:
        q = query.lower()
        return [d for d in self.docs if q in d.lower()][:k]

class RagService:
    def __init__(self, retriever: Retriever):
        self.retriever = retriever

    def answer(self, query: str, k: int = 2) -> dict:
        return {"query": query, "contexts": self.retriever.search(query, k)}

Because RagService composes any Retriever matching the structural protocol, you can swap in a fake or pgvector client without touching RagService.

[PRACTICE 4] Boundary Parsing: TypedDict to Immutable NamedTuple
Solved ✓

Convert raw JSON dicts typed with TypedDict into clean, unpackable NamedTuple records:

- Define class RawChunkPayload(TypedDict): with text: str and score: float.
- Define class ScoredChunk(NamedTuple): with text: str and score: float.
- Implement parse_chunk(raw: RawChunkPayload) -> ScoredChunk: strip raw["text"], raise ValueError if stripped text is empty or if not (0.0 <= raw["score"] <= 1.0), and return ScoredChunk(cleaned_text, float(raw["score"])).

Hint 1: Write text = raw["text"].strip() and if not text: raise ValueError("Empty text").
Hint 2: Write score = float(raw["score"]), check if not (0.0 <= score <= 1.0): raise ValueError("Score out of range"), and return ScoredChunk(text, score).
Final Answer & Rationale: 
from typing import NamedTuple, TypedDict

class RawChunkPayload(TypedDict):
    text: str
    score: float

class ScoredChunk(NamedTuple):
    text: str
    score: float

def parse_chunk(raw: RawChunkPayload) -> ScoredChunk:
    text = raw["text"].strip()
    if not text:
        raise ValueError("Empty text")
    score = float(raw["score"])
    if not (0.0 <= score <= 1.0):
        raise ValueError("Score out of range")
    return ScoredChunk(text, score)

TypedDict describes the raw dict shape for static type checkers, while NamedTuple gives an immutable, hashable, unpackable value object inside your core logic.
