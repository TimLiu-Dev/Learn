Asynchronous Python (asyncio) & Backpressure

AI applications spend 95% of their time waiting on LLM APIs, vector databases, and HTTP calls. Instead of spawning thousands of heavy OS threads, asyncio multiplexes thousands of concurrent I/O operations on a single event loop—provided you protect it from blocking calls and unbounded queues.

1. How the Event Loop & Coroutines Work

Calling an async def function does not run its body—it returns a coroutine object. Only when you await it (or schedule it as a Task) does the event loop drive it forward until it yields at the next await.

[BROWSER vs. TERMINAL] await at Top Level

In local .py scripts you start the loop with asyncio.run(main()). In this interactive Pyodide browser runtime (just like Jupyter notebooks), an event loop is already running—so call await main() directly at top level!

[PRACTICE 1] Concurrent Fan-Out with asyncio.TaskGroup
Solved ✓

Implement async def run_all_queries(prompts, fetch_fn) -> list[str]:

- Spawn one task per prompt inside async with asyncio.TaskGroup() as tg: calling fetch_fn(p).
- Preserve the input order of prompts when returning [t.result() for t in tasks]!

Hint 1: Create a list inside the async with block: tasks = [tg.create_task(fetch_fn(p)) for p in prompts].
Hint 2: After the async with block finishes, every task is guaranteed complete—return [t.result() for t in tasks].
Final Answer & Rationale: 
import asyncio

async def run_all_queries(prompts: list[str], fetch_fn) -> list[str]:
    async with asyncio.TaskGroup() as tg:
        tasks = [tg.create_task(fetch_fn(p)) for p in prompts]
    return [t.result() for t in tasks]

2. Bounded Concurrency with asyncio.Semaphore

If you have 5,000 document chunks to embed, firing 5,000 simultaneous requests via TaskGroup will immediately hit HTTP 429 Too Many Requests or exhaust sockets! Wrap each call in an asyncio.Semaphore(max_concurrent) so at most N coroutines talk to the upstream API at once.

[PRACTICE 2] Rate-Capped Fan-Out with asyncio.Semaphore
Solved ✓

Write async def map_bounded(items, worker_fn, max_concurrency: int) -> list:

- If max_concurrency <= 0, raise ValueError.
- Create sem = asyncio.Semaphore(max_concurrency).
- Run all items concurrently via TaskGroup where each task acquires async with sem: before awaiting worker_fn(item), returning results in original order.

Hint 1: Inside run_one: async with sem: return await worker_fn(item).
Hint 2: Then async with asyncio.TaskGroup() as tg: tasks = [tg.create_task(run_one(x)) for x in items] and return [t.result() for t in tasks].
Final Answer & Rationale: 
import asyncio

async def map_bounded(items: list, worker_fn, max_concurrency: int) -> list:
    if max_concurrency <= 0:
        raise ValueError("max_concurrency must be positive")
    sem = asyncio.Semaphore(max_concurrency)

    async def run_one(item):
        async with sem:
            return await worker_fn(item)

    async with asyncio.TaskGroup() as tg:
        tasks = [tg.create_task(run_one(x)) for x in items]
    return [t.result() for t in tasks]

3. Timeouts, Cancellation & Bounded asyncio.Queue Backpressure

Production HTTP clients like httpx.AsyncClient and aiohttp.ClientSession MUST always set explicit timeouts. Wrapping a coroutine in asyncio.wait_for(coro, timeout=...) (or Python 3.11+ async with asyncio.timeout(...):) cancels the task automatically if an upstream LLM hangs.

[PRACTICE 3] Timeout Wrapper with Safe Fallback (Never Swallow CancelledError!)
Solved ✓

Implement async def call_with_timeout(coro, timeout_s: float, fallback):

- Await asyncio.wait_for(coro, timeout=timeout_s).
- If TimeoutError (or asyncio.TimeoutError) occurs, return fallback.
- Note: wait_for raises TimeoutError on timeout, while outer task cancellation raises asyncio.CancelledError—do NOT catch CancelledError or BaseException!

Hint 1: Wrap return await asyncio.wait_for(coro, timeout=timeout_s) in try:.
Hint 2: Catch except TimeoutError: return fallback.
Final Answer & Rationale: 
import asyncio

async def call_with_timeout(coro, timeout_s: float, fallback):
    try:
        return await asyncio.wait_for(coro, timeout=timeout_s)
    except TimeoutError:
        return fallback
[PRACTICE 4] Bounded Producer-Consumer Pipeline with asyncio.Queue
Solved ✓

Implement async def process_pipeline(items: list[str], num_workers: int, queue_size: int) -> list[str]:

- Create queue: asyncio.Queue[str | None] = asyncio.Queue(maxsize=queue_size).
- Spawn num_workers consumer tasks that pull from queue.get() until receiving sentinel None, append item.upper() to results, and always call queue.task_done().
- Put every item in items onto the queue, then put one None sentinel per worker.
- Await queue.join() and all workers, then return results.

Hint 1: Create workers first: workers = [asyncio.create_task(worker()) for _ in range(num_workers)].
Hint 2: Enqueue items (`await queue.put(x)`), enqueue `num_workers` `None`s, then `await queue.join()` and `await asyncio.gather(*workers)` before returning `results`.
Final Answer & Rationale: 
import asyncio

async def process_pipeline(items: list[str], num_workers: int, queue_size: int) -> list[str]:
    queue: asyncio.Queue[str | None] = asyncio.Queue(maxsize=queue_size)
    results: list[str] = []

    async def worker():
        while True:
            item = await queue.get()
            try:
                if item is None:
                    return
                await asyncio.sleep(0.005)
                results.append(item.upper())
            finally:
                queue.task_done()

    workers = [asyncio.create_task(worker()) for _ in range(num_workers)]
    for item in items:
        await queue.put(item)
    for _ in range(num_workers):
        await queue.put(None)
    await queue.join()
    await asyncio.gather(*workers)
    return results
