1. CPython Memory Management & sys.getrefcount

Unlike Java or Android ART (which rely purely on background tracing garbage collectors), CPython's primary memory manager is immediate reference counting. Every heap object (PyObject) stores an integer counter ob_refcnt tracking how many variables, containers, or stack frames point to it.

  • Deterministic cleanup: As soon as ob_refcnt drops to 0, CPython immediately deallocates the object and runs any finalizer (__del__).
  • Why sys.getrefcount(x) looks 1 higher than expected: Calling sys.getrefcount(x) temporarily passes x as an argument into the function frame, adding +1 while the call runs!
  • Immortal Objects (Python 3.12+ / PEP 683): Singletons like None, True, False, and small integers have huge sentinel refcounts (e.g. > 1,000,000,000) and are never freed or refcount-mutated.

[PRACTICE 1] Measure Reference Count Deltas with sys.getrefcount
Solved ✓

Write measure_refcount_delta(n: int) -> tuple[int, int] to prove how container aliases increment and release ob_refcnt:

- Create a fresh list target = [10, 20, 30].
- Record base = sys.getrefcount(target).
- Create a list aliases = [target for _ in range(n)] holding n extra references.
- Record during = sys.getrefcount(target).
- Call aliases.clear() and record after = sys.getrefcount(target).
- Return (during - base, after - base).

Hint 1: Set aliases = [target for _ in range(n)], then during = sys.getrefcount(target).
Hint 2: Call aliases.clear(), set after = sys.getrefcount(target), and return (during - base, after - base).
Final Answer & Rationale: 
import sys

def measure_refcount_delta(n: int) -> tuple[int, int]:
    target = [10, 20, 30]
    base = sys.getrefcount(target)
    aliases = [target for _ in range(n)]
    during = sys.getrefcount(target)
    aliases.clear()
    after = sys.getrefcount(target)
    return (during - base, after - base)

Measuring deltas cancels out CPython's temporary call-frame +1 reference and proves aliases only add pointers—never deep copies.

2. Reference Cycles, Generational gc & weakref

Reference counting has one famous blind spot: reference cycles. If object A points to B and B points back to A, deleting all external variables leaves both objects with ob_refcnt == 1 forever!

  • Generational Cyclic GC (gc): CPython runs a backup cycle detector over container objects (lists, dicts, tuples, class instances) grouped into 3 generations (Gen 0 young → Gen 1 → Gen 2 long-lived). Surviving collections promote objects to older generations so short-lived objects are scanned often and long-lived ones rarely.
  • weakref (Zero-Overhead Cycle Breaker & Caches): A weak reference (weakref.ref(obj) or weakref.WeakValueDictionary) lets you point to an object without incrementing ob_refcnt. Calling a weakref returns the live object, or None once all strong references vanish!
  • Common Python Memory Leaks: Module-level caches/registries holding strong refs (like @lru_cache on methods!), unclosed cycles with legacy hooks, and global logger/handler lists that grow unboundedly.

[PRACTICE 2] Auto-Evicting Cache with weakref.WeakValueDictionary
Solved ✓

An AI chat server caches active Session objects by session_id so duplicate requests reuse them, without preventing disconnected sessions from being freed. Complete SessionCache using weakref.WeakValueDictionary:

- __init__(self): creates self._store = weakref.WeakValueDictionary().
- put(self, session_id: str, session: Session) -> None: stores session under session_id.
- get(self, session_id: str) -> Session | None: returns the live session or None.
- live_count(self) -> int: returns len(self._store).

Hint 1: Set self._store = weakref.WeakValueDictionary() in __init__.
Hint 2: Implement self._store[session_id] = session, return self._store.get(session_id), and return len(self._store).
Final Answer & Rationale: 
class SessionCache:
    def __init__(self):
        self._store = weakref.WeakValueDictionary()

    def put(self, session_id: str, session: Session) -> None:
        self._store[session_id] = session

    def get(self, session_id: str) -> Session | None:
        return self._store.get(session_id)

    def live_count(self) -> int:
        return len(self._store)

Because WeakValueDictionary holds weak references to values, entries automatically vanish as soon as callers drop their strong references.

[PRACTICE 3] Break a Parent-Child Cycle with weakref.ref
Solved ✓

In tree structures, a Parent holds strong references to children, while each Child wants a back-pointer child.parent. Storing a strong reference back to Parent creates a cycle! Fix Child using weakref.ref:

- In Child.__init__(self, name: str, parent: Parent), store self._parent_ref = weakref.ref(parent).
- Add a @property def parent(self) that returns self._parent_ref().
- Result: deleting Parent drops its refcount to 0 immediately—no gc.collect() required!

Hint 1: Inside Child.__init__, set self._parent_ref = weakref.ref(parent).
Hint 2: Inside @property def parent(self), return self._parent_ref() (calling the weakref object).
Final Answer & Rationale: 
class Child:
    def __init__(self, name: str, parent: Parent):
        self.name = name
        self._parent_ref = weakref.ref(parent)

    @property
    def parent(self):
        return self._parent_ref()

By keeping downward references strong and upward back-pointers weak, ownership forms a clean DAG and objects free immediately at zero refcount.

3. Why the GIL Exists & 2026–2027 Free-Threaded Python (PEP 703)

In classic CPython, updating ob_refcnt += 1 and mutating shared dictionaries are not atomic CPU operations. Without synchronization, two OS threads running Python bytecode simultaneously would corrupt reference counts and crash the interpreter. CPython's historical solution was the GIL (Global Interpreter Lock): a single mutex allowing only one thread to execute Python bytecode at a time per process.

Runtime Mode How It Works CPU-Bound Python Threads? Best Use Case (2027)
Standard CPython (GIL on) 1 mutex guards interpreter state; released during C I/O syscalls & NumPy/PyTorch C loops. Serialized (~1 core for pure Python) asyncio / I/O services + C-accelerated ML libs
Subinterpreters (PEP 684 / 3.14 concurrent.interpreters) Multiple isolated interpreters in 1 OS process, each with its own heap and private GIL. Parallel across cores (isolated memory) Sandboxed plugins, multi-tenant workers with fast IPC
Free-Threaded CPython (PEP 703: python3.13t / 3.14t) No GIL! Uses biased refcounting, immortal objects, mimalloc heaps, and fine-grained locks. True multi-core Python threads! CPU-bound Python parallel pipelines sharing memory
[SENIOR MINDSET] What PEP 703 Does NOT Fix Automatically

Running on python3.14t (free-threaded) keeps CPython's own objects from crashing, but your own shared lists/counters still need locks! A race condition like counter += 1 across two threads is still unsafe without threading.Lock. You will practice locks, deadlocks, and thread vs process tradeoffs in Lesson 14!
