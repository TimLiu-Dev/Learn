1. unittest, doctest & pytest (Fixtures + Parametrize)

Every solid test follows Arrange → Act → Assert: set up inputs, call one unit of code, and assert the expected output or exception. Python ships two testing tools in its standard library (unittest and doctest, both runnable right here in Pyodide), while production teams standardize on pytest for concise syntax.

Feature unittest (stdlib) pytest (2027 industry standard)
Test style Subclass unittest.TestCase, methods named test_* Plain functions def test_*(): (zero class boilerplate)
Assertions self.assertEqual(a, b), self.assertRaises(ValueError) Plain assert a == b (rewritten with rich diff!), with pytest.raises(ValueError):
Setup / Teardown setUp() / tearDown() methods Composable @pytest.fixture functions (yield for cleanup)
Data-driven cases with self.subTest(case=case): @pytest.mark.parametrize("inp,expected", [...])

import unittest

def split_chunks(text: str, size: int) -> list[str]:
    if size <= 0:
        raise ValueError("size must be positive")
    return [text[i : i + size] for i in range(0, len(text), size)]

class TestSplitChunks(unittest.TestCase):
    def test_splits_evenly_and_remainder(self):
        self.assertEqual(split_chunks("abcdef", 2), ["ab", "cd", "ef"])
        self.assertEqual(split_chunks("abcde", 2), ["ab", "cd", "e"])
        self.assertEqual(split_chunks("", 3), [])

    def test_invalid_size_raises(self):
        with self.assertRaises(ValueError):
            split_chunks("abc", 0)
        with self.assertRaises(ValueError):
            split_chunks("abc", -2)

Testing both happy-path boundaries (even split, remainder, empty string) and error contracts (size <= 0) prevents silent regressions.

2. Dependency Fakes vs unittest.mock & Property Testing

AI applications call external LLM APIs, vector databases, and object stores. Unit tests must be fast, offline, and deterministic—never burning real API tokens! You isolate I/O with two kinds of test doubles:

  • Dependency Fake (Preferred!): A simple in-memory class implementing the same interface (e.g., FakeLLMClient with a dict or list). Fakes test real behavior without tying tests to private implementation details.
  • unittest.mock (Mock / patch): Useful when you only need to verify a side-effect call happened (e.g., metrics.increment.assert_called_once_with("cache.hit")) or replace a module-level clock/UUID helper.
  • Property-Based Testing (hypothesis): Instead of writing 3 fixed inputs, you state an invariant (a rule that must ALWAYS be true—like len(chunk) <= size and "".join(chunks) == text) and let Hypothesis generate hundreds of tricky inputs (empty strings, Unicode emojis, huge sizes) and shrink failures to the minimal counterexample!
[WATCH OUT] The #1 unittest.mock.patch Bug: Patch Where It's Looked Up!

If service.py writes from time import monotonic, then @patch("time.monotonic") will NOT affect service.py because service already bound its own local name! You must patch "service.monotonic" (where the name is used, not where it was originally defined). Better yet: inject dependencies as function/constructor parameters so you can pass a clean Fake without patching globals at all.

from hypothesis import given, strategies as st

@given(text=st.text(), size=st.integers(min_value=1, max_value=50))
def test_split_chunks_roundtrip_property(text: str, size: int):
    chunks = split_chunks(text, size)
    assert "".join(chunks) == text
    assert all(1 <= len(c) <= size for c in chunks)
[PRACTICE 2] Build a FakeLLMClient to Test Retry Behavior Offline
Solved ✓

Complete FakeLLMClient so unit tests can test retry logic without hitting a real API:

- __init__(self, reply: str, fail_times: int = 0): stores self.reply, self.fail_times, and initializes self.calls: list[str] = [].
- complete(self, prompt: str) -> str: appends prompt to self.calls. If len(self.calls) <= self.fail_times, raises TimeoutError("Transient timeout"); otherwise returns self.reply.

Hint 1: In __init__, set self.reply = reply, self.fail_times = fail_times, and self.calls = [].
Hint 2: In complete, do self.calls.append(prompt) first, then if len(self.calls) <= self.fail_times: raise TimeoutError("Transient timeout"), then return self.reply.
Final Answer & Rationale: 
class FakeLLMClient:
    def __init__(self, reply: str, fail_times: int = 0):
        self.reply = reply
        self.fail_times = fail_times
        self.calls: list[str] = []

    def complete(self, prompt: str) -> str:
        self.calls.append(prompt)
        if len(self.calls) <= self.fail_times:
            raise TimeoutError("Transient timeout")
        return self.reply

A small Fake like this runs in microseconds, requires zero monkeypatching, and lets you inspect exact call history via fake.calls.

3. Coverage, ruff Lint+Format, tox & Sphinx/MkDocs Docs

Clean codebases automate style, lints, multi-version tests, and documentation in CI so reviewers focus on architecture—not trailing commas or stale docstrings.

  • Coverage (pytest --cov=src --cov-branch --cov-report=term-missing): Shows which lines and if/else branches never executed during tests. Remember: high coverage catches untested code, not weak assertions!
  • ruff (Lint + Format): Written in Rust, Ruff runs 10–100x faster than legacy Python tools and replaces flake8 + isort + pyupgrade + black in a single binary (ruff check --fix . and ruff format .).
  • tox: Automates running your test suite across a matrix of Python versions (e.g., py312, py313, py314) in isolated environments before releasing a library.
  • Sphinx & MkDocs (with Google-style docstrings): Tools like mkdocstrings (MkDocs) and sphinx.ext.autodoc parse structured docstrings (Args:, Returns:, Raises:) into searchable HTML docs—and doctest verifies the code examples inside them!

[tool.ruff.lint]

Final Answer & Rationale: 
def clamp_score(score: float, low: float = 0.0, high: float = 1.0) -> float:
    """Clamp a similarity score into the inclusive [low, high] range.

    Args:
        score: Raw score produced by a retriever.
        low: Minimum allowed score.
        high: Maximum allowed score.

    Returns:
        Clamped float score.

    Examples:
        >>> clamp_score(0.75)
        0.75
        >>> clamp_score(1.4)
        1.0
    """
    if low > high:
        raise ValueError("low must be <= high")
    return float(max(low, min(score, high)))

Running pytest --doctest-modules in CI executes every docstring example automatically so your MkDocs/Sphinx documentation stays truthful.
