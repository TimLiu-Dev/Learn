1. WSGI vs. ASGI Internals & Python Web Frameworks

Python web frameworks sit behind an application server (like Gunicorn or Uvicorn). The server translates raw TCP/HTTP bytes into a standard Python calling convention—either WSGI (2003, synchronous) or ASGI (Asynchronous Server Gateway Interface, modern async standard).

Dimension WSGI (Flask, Classic Django) ASGI (FastAPI, Starlette, Async Django)
Execution Model 1 request = 1 worker thread/process blocked until response finishes. Single-thread event loop runs thousands of suspended I/O coroutines concurrently.
Signature def app(environ, start_response) -> iterable[bytes] async def app(scope, receive, send) -> None
Streaming & SSE Pins a full OS thread open for the entire 30s LLM stream. Suspends cheaply between chunks; ideal for SSE, WebSockets, and LLM API calls.
Best Server gunicorn (sync/gthread workers) uvicorn (or gunicorn -k uvicorn.workers.UvicornWorker)

FastAPI vs. Django vs. Flask (2027 Decision Guide)

Framework Philosophy Choose When...
FastAPI ASGI-native, Pydantic v2 validation, automatic OpenAPI 3.1 docs, Depends() DI. Building AI APIs, microservices, SSE token streams, or high-concurrency I/O backends.
Django (+ DRF / Ninja) Batteries-included monolith (ORM, Admin UI, Auth, CSRF, Migrations). Building SaaS back-offices, content platforms, or CRUD apps needing built-in admin & auth fast.
Flask Minimal WSGI microframework; you assemble extensions yourself. Lightweight internal tools, legacy WSGI integrations, or small synchronous webhooks.
[COMMON PITFALL] Blocking the Event Loop Inside async def

In FastAPI, if you declare a route with async def and call a synchronous library like requests.get() or time.sleep(2), you freeze the entire Uvicorn event loop for every user! Rule of thumb: use async clients (httpx.AsyncClient) in async def routes, or declare plain def so FastAPI runs the route in a threadpool automatically.

def dispatch_asgi(scope: dict, routes: dict) -> tuple[int, dict]:
    if scope.get("type") != "http":
        return (400, {"detail": "Unsupported scope"})
    method = scope["method"].upper()
    path = scope["path"]
    if (method, path) in routes:
        return (200, routes[(method, path)](scope))
    if any(r_path == path for (_, r_path) in routes):
        return (405, {"detail": "Method Not Allowed"})
    return (404, {"detail": "Not Found"})

HTTP semantics matter: returning 405 instead of 404 when the path exists under another verb tells API callers immediately that the URL is right and only the HTTP method is wrong.

2. Production FastAPI: Routers, DI, OpenAPI & Cursor Pagination

A toy FastAPI tutorial puts every route in main.py. A production AI backend separates concerns cleanly:

  • APIRouter modules: Group routes by domain (/v1/documents, /v1/chat, /health).
  • Dependency Injection (Depends): Inject auth context, DB sessions, and rate limiters into endpoints so tests can swap them via app.dependency_overrides.
  • response_model contracts: Never return raw ORM/dict objects directly—use a Pydantic v2 response schema so internal fields (like hashed_api_key) are stripped automatically and OpenAPI docs stay accurate.
  • Cursor Pagination > Offset Pagination: OFFSET 10000 LIMIT 20 scans and discards 10,000 rows and drifts when new documents are inserted. Passing cursor=<last_seen_id> uses an index seek in O(log N) time!
[PRODUCTION CODE — RUN LOCALLY WITH FASTAPI]
from typing import Annotated
from fastapi import APIRouter, Depends, FastAPI, Header, HTTPException, Query
from pydantic import BaseModel

router = APIRouter(prefix="/v1/docs", tags=["documents"])

class DocumentOut(BaseModel):
    id: str
    title: str

class PageOut(BaseModel):
    items: list[DocumentOut]
    next_cursor: str | None

def require_tenant(x_tenant_id: Annotated[str | None, Header()] = None) -> str:
    if not x_tenant_id:
        raise HTTPException(status_code=401, detail="Missing X-Tenant-Id")
    return x_tenant_id

@router.get("", response_model=PageOut)
async def list_documents(
    tenant_id: Annotated[str, Depends(require_tenant)],
    cursor: str | None = None,
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
) -> PageOut:
    rows = await repo.list_after_cursor(tenant_id, cursor=cursor, limit=limit + 1)
    has_more = len(rows) > limit
    page = rows[:limit]
    return PageOut(items=page, next_cursor=page[-1].id if has_more else None)

def paginate_by_cursor(records: list[dict], cursor: str | None = None, limit: int = 2) -> dict:
    if limit < 1:
        raise ValueError("limit must be >= 1")
    filtered = records if cursor is None else [r for r in records if r["id"] > cursor]
    page = filtered[:limit]
    next_cursor = page[-1]["id"] if len(filtered) > limit else None
    return {"items": page, "next_cursor": next_cursor}

Fetching limit + 1 rows in SQL lets you know whether a next page exists without running a costly COUNT(*) query!

3. Server-Sent Events (SSE) for Real-Time LLM Token Streaming

Waiting 12 seconds for a full LLM answer makes users think your app froze. Because LLM generation is one-way (server → client per prompt), Server-Sent Events (SSE) over standard HTTP (Content-Type: text/event-stream) is simpler and more proxy-friendly than WebSockets.

  • Each SSE frame consists of newline-separated fields ending with a blank line (\n\n).
  • Standard fields: id: <seq>, event: <name>, data: <payload>.
  • Multi-line JSON or text inside a single event must never contain raw unescaped newlines—encode payloads as compact single-line JSON!
  • In FastAPI, return StreamingResponse(token_generator(), media_type="text/event-stream") with Cache-Control: no-cache and X-Accel-Buffering: no (so Nginx doesn't buffer chunks).

import json

def format_sse_event(event_type: str, payload: dict, event_id: int | None = None) -> str:
    data_json = json.dumps(payload, separators=(",", ":"))
    lines = []
    if event_id is not None:
        lines.append(f"id: {event_id}")
    lines.append(f"event: {event_type}")
    lines.append(f"data: {data_json}")
    return "\n".join(lines) + "\n\n"

def parse_sse_stream(raw_stream: str) -> list[tuple[str, dict]]:
    results = []
    for block in raw_stream.strip().split("\n\n"):
        if not block.strip():
            continue
        ev_type = "message"
        data_obj = {}
        for line in block.splitlines():
            if line.startswith("event:"):
                ev_type = line[len("event:"):].strip()
            elif line.startswith("data:"):
                data_obj = json.loads(line[len("data:"):].strip())
        results.append((ev_type, data_obj))
    return results

Notice how separators=(",", ":") keeps SSE wire payloads compact and guarantees single-line JSON so newlines inside string values are escaped as \n.

4. Structured LLM & Tool-Calling API Contracts

Production AI backends don't ask an LLM for "free-form text" when downstream code needs fields—they enforce Structured Outputs (JSON Schema generated directly from Pydantic v2 models) and validate every tool call against an explicit allowlist before executing anything.

[SECURITY & RELIABILITY RULE] Validate Tool Names & Arguments Explicitly

Treat every LLM tool-call payload as untrusted user input. Never pass raw model arguments into eval(), shell commands, or unvalidated SQL—route through an explicit allowlist of typed handlers and return structured RFC 9457 Problem Details ({"type", "title", "status", "detail"}) on invalid calls.

[PRACTICE 4] Allowlisted LLM Tool-Call Contract Router
Solved ✓

Implement execute_tool_call(call_payload, registry) safely:

- call_payload is expected to be a dict with "name" (str) and "arguments" (dict).
- If call_payload is not a dict or misses valid "name" (str) / "arguments" (dict), return {"ok": False, "status": 422, "error": "Invalid tool call schema"}.
- If name not in registry, return {"ok": False, "status": 403, "error": f"Tool not allowed: {name}"}.
- Otherwise call registry[name](**arguments) inside try/except (TypeError, ValueError) as exc: return {"ok": True, "status": 200, "result": output} on success, or {"ok": False, "status": 400, "error": str(exc)} on error.

Hint 1: Check if name not in registry: return {"ok": False, "status": 403, "error": f"Tool not allowed: {name}"}.
Hint 2: Wrap output = registry[name](**args) in try ... except (TypeError, ValueError) as exc: return {"ok": False, "status": 400, "error": str(exc)}.
Final Answer & Rationale: 
def execute_tool_call(call_payload: dict, registry: dict) -> dict:
    if not isinstance(call_payload, dict):
        return {"ok": False, "status": 422, "error": "Invalid tool call schema"}
    name = call_payload.get("name")
    args = call_payload.get("arguments")
    if not isinstance(name, str) or not isinstance(args, dict):
        return {"ok": False, "status": 422, "error": "Invalid tool call schema"}
    if name not in registry:
        return {"ok": False, "status": 403, "error": f"Tool not allowed: {name}"}
    try:
        output = registry[name](**args)
    except (TypeError, ValueError) as exc:
        return {"ok": False, "status": 400, "error": str(exc)}
    return {"ok": True, "status": 200, "result": output}

Returning structured error dictionaries (422/403/400) lets an AI agent self-correct on its next turn instead of crashing the worker!
