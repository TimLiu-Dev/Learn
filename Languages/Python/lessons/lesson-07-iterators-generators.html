1. The Iterator Protocol (__iter__, __next__, StopIteration)

Every for x in collection: loop in Python runs on just two dunder methods. Understanding the split between an Iterable and an Iterator eliminates one of Python's sneakiest bugs:

Concept Required Dunder Methods Analogy & Lifetime Examples
Iterable __iter__(self) → returns a fresh Iterator Like a music album: you can press Play from track 1 as many times as you want. list, tuple, dict, str, range
Iterator __iter__(self) → returns self
__next__(self) → returns next item or raises StopIteration		 Like the playhead cursor: single-pass. Once it reaches the end, every future next() raises StopIteration. Generators, iter(my_list), open file objects, zip, enumerate
[WATCH OUT] Iterators Exhaust After One Pass!

Because an iterator's __iter__() returns self (the same stateful cursor), looping over an iterator a second time produces zero items without raising an error! If a function needs to scan items twice, accept a sequence or iterate in a single pass.

LLM APIs rate-limit requests (HTTP 429). Implement an iterator class ExponentialBackoff(base_delay, factor, max_attempts):

- On attempt 0, 1, ..., max_attempts - 1, __next__ returns base_delay * (factor ** attempt).
- When attempt >= max_attempts, raise StopIteration.
- Implement __iter__(self) returning self.

Hint 1: Inside __iter__(self), write return self.
Hint 2: Inside __next__(self), check if self.attempt >= self.max_attempts: raise StopIteration, then calculate delay = self.base_delay * (self.factor ** self.attempt), add self.attempt += 1, and return delay.
Final Answer & Rationale: 
class ExponentialBackoff:
    def __init__(self, base_delay, factor, max_attempts):
        self.base_delay = base_delay
        self.factor = factor
        self.max_attempts = max_attempts
        self.attempt = 0

    def __iter__(self):
        return self

    def __next__(self):
        if self.attempt >= self.max_attempts:
            raise StopIteration
        delay = self.base_delay * (self.factor ** self.attempt)
        self.attempt += 1
        return delay

Notice how self.attempt acts as the saved cursor state between calls to next().

2. Generator Functions (yield) & yield from Delegation

Writing __iter__ and __next__ by hand gets tedious fast. Any function containing the keyword yield becomes a generator function: calling it does not run its body immediately; it returns a generator iterator whose execution pauses at each yield and resumes on the next next().

  • yield value: Emits value and freezes local variables and instruction pointer until the caller asks for the next item.
  • yield from sub_iterable (PEP 380): Delegates directly to another generator or iterable—cleaner and faster than writing for item in sub_iterable: yield item.
  • Memory win: A generator object takes ~200 bytes of RAM whether it streams 10 items or 100 million items!

Write two generator functions for a RAG document loader:

- clean_lines(text): iterate over text.splitlines(), strip each line, and yield it only if it is non-empty and does not start with "#".
- stream_all_docs(docs): iterate over docs and delegate each document to clean_lines(doc) using yield from.

Hint 1: In clean_lines, check if line and not line.startswith("#"): yield line.
Hint 2: In stream_all_docs(docs), write for doc in docs: yield from clean_lines(doc).
Final Answer & Rationale: 
def clean_lines(text):
    for raw in text.splitlines():
        line = raw.strip()
        if line and not line.startswith("#"):
            yield line

def stream_all_docs(docs):
    for doc in docs:
        yield from clean_lines(doc)

Both functions are true lazy generators: calling stream_all_docs(docs) does zero work until the caller pulls items with next() or for.

3. Comprehensions vs. Generator Expressions

Brackets decide whether Python allocates everything up front in RAM or computes values on demand:

Syntax Kind Evaluation Best Use Case
[x * 2 for x in xs] List comprehension Eager (allocates full list) You need indexing (res[0]), len(), or multiple passes
{x for x in xs} Set comprehension Eager (unique hashable items) Deduplicating IDs or tags in one readable line
{k: v for k, v in pairs} Dict comprehension Eager (key-value lookup map) Building fast O(1) ID → record lookup tables
(x * 2 for x in xs) Generator expression Lazy (one item at a time) Feeding sum(), any(), all(), next(), or huge streams
[SENIOR MINDSET] Drop the Square Brackets Inside Reductions

When calling sum([x for x in items]) or any([check(x) for x in items]), the inner brackets force Python to compute every item into a temporary list first. Writing any(check(x) for x in items) uses a generator expression and short-circuits immediately on the first True!

Write find_first_over_budget(requests, limit_tokens) using a generator expression inside next(..., None):

- Each item in requests is a dict like {"id": "req-2", "tokens": 1800}.
- Return the "id" of the first request whose "tokens" is strictly greater than limit_tokens.
- If no request exceeds limit_tokens, return None.
- Crucial: Because tests pass a lazy generator that raises if over-consumed, you must NOT convert requests to a list!

Hint 1: Write the generator expression (r["id"] for r in requests if r.get("tokens", 0) > limit_tokens).
Hint 2: Wrap it in return next((r["id"] for r in requests if r.get("tokens", 0) > limit_tokens), None) so exhausted streams return None instead of raising StopIteration.
Final Answer & Rationale: 
def find_first_over_budget(requests, limit_tokens):
    return next(
        (r["id"] for r in requests if r.get("tokens", 0) > limit_tokens),
        None,
    )

next(gen, default) pulls items one by one and halts immediately when the first match appears, leaving the rest of the stream untouched.

4. Memory-Constant Pipelines with itertools

Python's C-optimized itertools module gives you Lego blocks for composing lazy pipelines:

  • itertools.islice(iterable, stop) / islice(it, start, stop, step): Slices any iterator lazily—because gen[:5] raises TypeError!
  • itertools.chain.from_iterable(iterables): Lazily flattens an iterable of iterables into one continuous stream without copying.
  • itertools.batched(iterable, n) (Python 3.12+!): Groups a stream into fixed-size tuple chunks (last chunk may be shorter than n)—ideal for batching vector embeddings or SQL bulk inserts!
  • itertools.groupby(iterable, key=...): Groups consecutive items with the same key (remember: sort by the key first if identical keys aren't adjacent!).

Implement batch_rag_chunks(doc_streams, batch_size, max_batches) using itertools:

- Lazily flatten doc_streams with chain.from_iterable(doc_streams).
- Strip whitespace from each chunk and skip any chunk that becomes empty.
- Group cleaned chunks into batches of size batch_size with batched(..., batch_size).
- Take at most max_batches batches with islice(..., max_batches) and return them as a list of tuples.

Hint 1: Write clean = (s.strip() for s in flat if s.strip()) so cleaning happens lazily.
Hint 2: Chain batches = batched(clean, batch_size) and return list(islice(batches, max_batches)).
Final Answer & Rationale: 
from itertools import batched, chain, islice

def batch_rag_chunks(doc_streams, batch_size, max_batches):
    flat = chain.from_iterable(doc_streams)
    clean = (s.strip() for s in flat if s.strip())
    batches = batched(clean, batch_size)
    return list(islice(batches, max_batches))

Because every intermediate stage is lazy, even an infinite doc_streams source stops cleanly as soon as max_batches tuples are emitted.
