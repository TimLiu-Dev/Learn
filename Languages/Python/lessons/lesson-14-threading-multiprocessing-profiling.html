1. Threading, Race Conditions, Deadlocks & queue.Queue

Even with the GIL, race conditions still happen in Python! Why? Because an operation like balance += amount compiles to multiple bytecode steps (load → add → store), and the GIL can switch threads between any two bytecodes.

  • Protect shared state with threading.Lock(): Use with lock: so locks always release even on exceptions.
  • Avoid Deadlocks via Lock Ordering: If Thread A locks acct_1 then acct_2 while Thread B locks acct_2 then acct_1, both hang forever! Always acquire locks in sorted ID order!
  • Prefer queue.Queue: Thread-safe FIFO queues decouple producers and workers cleanly without manual locking.
[PRACTICE 1] Deadlock-Free Account Transfer (Consistent Lock Ordering)
Solved ✓

Write transfer(src, dst, amount) for two Account(id: str, balance: int, lock: threading.Lock) objects:

- If amount <= 0, raise ValueError("amount must be positive").
- If src is dst, return immediately (do not double-lock the same non-reentrant Lock!).
- Acquire both locks in deterministic ascending account.id order (e.g., first, second = (src, dst) if src.id < dst.id else (dst, src)) using nested with blocks.
- Inside the locks, if src.balance < amount raise ValueError("insufficient funds"); otherwise subtract from src and add to dst.

Hint 1: Order locks: first, second = (src, dst) if src.id < dst.id else (dst, src).
Hint 2: Nest with first.lock: and with second.lock:, then check if src.balance < amount: raise ValueError(...).
Final Answer & Rationale: 
import threading
from dataclasses import dataclass, field

@dataclass
class Account:
    id: str
    balance: int
    lock: threading.Lock = field(default_factory=threading.Lock)

def transfer(src: Account, dst: Account, amount: int) -> None:
    if amount <= 0:
        raise ValueError("amount must be positive")
    if src is dst:
        return
    first, second = (src, dst) if src.id < dst.id else (dst, src)
    with first.lock:
        with second.lock:
            if src.balance < amount:
                raise ValueError("insufficient funds")
            src.balance -= amount
            dst.balance += amount

2. Multiprocessing, concurrent.futures & Pickling Costs

To run pure-Python CPU work (like PDF parsing, chunk tokenization, or image hashing) across multiple CPU cores under the GIL, use concurrent.futures.ProcessPoolExecutor. Each worker is a separate Python OS process with its own memory space and GIL.

[LOCAL OS PATTERN] concurrent.futures Unified Pool API
from concurrent.futures import ProcessPoolExecutor, ThreadPoolExecutor

def heavy_cpu_hash(chunk: str) -> int:
    return sum(ord(c) * i for i, c in enumerate(chunk))

if __name__ == "__main__":  # REQUIRED on macOS/Windows ('spawn')!
    with ProcessPoolExecutor(max_workers=4) as pool:
        results = list(pool.map(heavy_cpu_hash, ["doc1", "doc2", "doc3"]))
[PRACTICE 2] Multiprocessing Picklability Filter (pickle.dumps)
Solved ✓

A common multiprocessing crash is submitting unpicklable objects (lambdas, closures, or open file handles) to a ProcessPoolExecutor. Write filter_picklable(items: dict[str, object]) -> tuple[list[str], list[str]]:

- Test each value with pickle.dumps(val).
- Return (picklable_keys, unpicklable_keys), both sorted alphabetically!

Hint 1: Loop over for key, val in items.items(): and try pickle.dumps(val).
Hint 2: Catch (pickle.PicklingError, TypeError, AttributeError) to put key in bad, then return (sorted(good), sorted(bad)).
Final Answer & Rationale: 
import pickle

def filter_picklable(items: dict[str, object]) -> tuple[list[str], list[str]]:
    good: list[str] = []
    bad: list[str] = []
    for key, val in items.items():
        try:
            pickle.dumps(val)
        except (pickle.PicklingError, TypeError, AttributeError):
            bad.append(key)
        else:
            good.append(key)
    return (sorted(good), sorted(bad))

3. CPU & Memory Profiling (timeit, cProfile, tracemalloc)

Senior engineers never optimize blindly. Python ships with three built-in measurement tools: timeit for micro-benchmarks, cProfile + pstats for CPU call hotspots, and tracemalloc for finding which line allocated the most RAM.

[EXAMPLE 1] Live cProfile & tracemalloc Inspection
[PRACTICE 3] Build a tracemalloc Peak-Memory Profiler Helper
Solved ✓

Implement measure_peak_bytes(fn, *args) -> tuple[object, int]:

- Start tracemalloc (remember to clear/stop cleanly in a finally: block!).
- Run result = fn(*args).
- Read _, peak = tracemalloc.get_traced_memory() and return (result, peak).

Hint 1: Inside try:, run result = fn(*args).
Hint 2: Then read _, peak = tracemalloc.get_traced_memory() and return (result, peak).
Final Answer & Rationale: 
import tracemalloc

def measure_peak_bytes(fn, *args) -> tuple[object, int]:
    tracemalloc.start()
    try:
        result = fn(*args)
        _, peak = tracemalloc.get_traced_memory()
        return (result, peak)
    finally:
        tracemalloc.stop()
