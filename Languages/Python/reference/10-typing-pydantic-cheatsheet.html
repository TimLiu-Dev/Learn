Static Typing, Generics & Pydantic v2 Cheat Sheet

Fast lookup for Python 3.12+ type syntax, static checker narrowing, and runtime validation at system boundaries.

1. Modern Type Syntax (Python 3.12+)

  • Unions: str | None (no need for Optional or Union).
  • Built-in generics: list[str], dict[str, int], tuple[int, ...].
  • PEP 695 generic functions: def first[T](items: list[T]) -> T | None:
  • PEP 695 type aliases: type JsonDict = dict[str, object]

2. Static vs Runtime Reality

  • CPython ignores type hints at runtime—mypy / pyright verify them statically before deploy.
  • Any turns off checking; object accepts anything safely until you narrow it.
  • TypeGuard[list[str]] tells type checkers a helper function narrowed a collection's item types.
  • typing.assert_never(val) catches unhandled Literal / Enum cases at type-check time.

3. Pydantic v2 at API & LLM Boundaries

  • Model.model_validate_json(raw) parses & validates JSON in Rust (pydantic-core).
  • Field(ge=0.0, le=1.0, min_length=1) declares constraints + OpenAPI metadata.
  • @field_validator("name") runs custom normalization/checks after type parsing.
  • model_config = ConfigDict(extra="forbid", strict=True) blocks unexpected fields and silent coercions.

4. AI Backend Boundary Rule

  • Never trust raw JSON from HTTP clients or LLM tool calls—validate once at the edge with Pydantic.
  • Pass validated, strongly typed models inward so core business logic stays simple and bug-free.
  • Use pydantic-settings (BaseSettings) to fail fast on missing env vars at startup.
