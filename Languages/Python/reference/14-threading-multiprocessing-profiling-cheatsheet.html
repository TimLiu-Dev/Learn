Threading, Multiprocessing & Profiling Cheat Sheet

Decision matrix for I/O-bound vs CPU-bound Python workloads, synchronization primitives, and CPU/memory profilers.

1. Choosing the Right Tool

  • Many network/DB calls: asyncio (Lesson 15) or ThreadPoolExecutor (sync libraries).
  • Heavy pure-Python CPU work: ProcessPoolExecutor (separate processes bypass GIL) or Free-Threaded 3.13t/3.14t.
  • Short micro-tasks: Avoid multiprocessing—pickling + IPC overhead often exceeds compute time!

2. Thread Safety & Deadlocks

  • += is NOT atomic! Always guard shared mutable state with with lock:.
  • Deadlock prevention: Always acquire multiple locks in a consistent global order (e.g., sorted account IDs).
  • Prefer queue.Queue message passing over shared-memory locking whenever possible.

3. Multiprocessing Guardrails

  • Always wrap entrypoints in if __name__ == "__main__": (required on macOS/Windows spawn start method).
  • Submitted functions & args must be picklable (top-level functions/classes, no lambdas or open sockets).

4. Measure Before Optimizing

  • timeit: Micro-benchmarks (disables GC by default, compares small expressions).
  • cProfile + pstats: Deterministic CPU call-count & cumulative-time profiler.
  • tracemalloc: Tracks exact file/line Python memory allocations & leaks (snapshot.compare_to).
  • py-spy (prod): Low-overhead sampling profiler that attaches to live PIDs without code edits.
