Redis, Background Queues & Distributed Resilience Cheat Sheet

Battle-tested fault-tolerance patterns for AI backends calling flaky external LLM & embedding APIs.

1. Redis Caching & Distributed Locks

  • Add random TTL jitter to cached keys to prevent synchronized cache stampedes.
  • Acquire locks with SET key token NX PX 5000 and unlock only via atomic Lua comparing get(key) == token.
  • Idempotency keys: store (payload_hash, response); replay on match, return 409 on hash mismatch.

2. Worker Queues & Token Bucket

  • Offload slow ingestion/embeddings to background workers; return 202 Accepted immediately.
  • Route poison-pill jobs exceeding max_attempts to a Dead-Letter Queue (DLQ).
  • Token Bucket: refill min(cap, tokens + elapsed * rate) to allow bounded bursts without exceeding sustained quotas.

3. Resilient httpx & Full Jitter

  • Always configure explicit httpx.Timeout(connect=..., read=..., write=..., pool=...) and reuse AsyncClient.
  • Retry only transient failures (timeouts, 429, 5xx)—never retry 400/401.
  • Full Jitter: delay = random.random() * min(cap, base * 2**attempt).

4. Circuit Breaker State Machine

  • CLOSED → trips to OPEN after N consecutive failures.
  • OPEN → fails fast until recovery_timeout elapses, then moves to HALF_OPEN.
  • HALF_OPEN → probe succeeds (→ CLOSED) or fails (→ OPEN).
