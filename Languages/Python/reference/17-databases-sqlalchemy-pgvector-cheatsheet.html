Databases, SQLAlchemy 2.0 Async & pgvector Cheat Sheet

Essential patterns for async ORM models, N+1 prevention, race-safe transactions, Alembic migrations, and hybrid RAG retrieval.

1. SQLAlchemy 2.0 Async & Pooling

  • One create_async_engine(..., pool_pre_ping=True) per app; one AsyncSession(expire_on_commit=False) per request.
  • Typed models: id: Mapped[str] = mapped_column(String(64), primary_key=True).
  • Keep SQL inside Repositories; commit once at Unit-of-Work / endpoint boundary.
  • Always bind parameters (? / ORM expressions)—never f-string user data into SQL.

2. N+1 Prevention & Alembic

  • Lazy loading crashes under AsyncIO (MissingGreenlet)—eager load via selectinload(...) or joinedload(...).
  • Aggregate counts with LEFT JOIN ... COUNT(child.id) GROUP BY parent.id (never COUNT(*) on outer joins).
  • Expand-and-Contract: add new column → backfill → deploy code → drop old column later.

3. Transactions & Race-Safe Locking

  • Avoid read-then-write in Python for quotas; use atomic UPDATE ... SET credits = credits - :amt WHERE id = :id AND credits >= :amt and check rowcount == 1.
  • Multi-step critical sections: SELECT ... FOR UPDATE.
  • Concurrent worker queues in Postgres: SELECT ... FOR UPDATE SKIP LOCKED LIMIT 1.

4. pgvector & Hybrid RRF Search

  • <=> is cosine distance; similarity = 1.0 - (embedding <=> query_vec).
  • Index large chunk tables with HNSW (vector_cosine_ops) and always filter by tenant_id.
  • Combine vector + keyword rankings with RRF: score += 1.0 / (60 + rank).
