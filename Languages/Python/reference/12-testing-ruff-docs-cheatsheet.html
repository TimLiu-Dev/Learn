Testing, Linting (ruff), Coverage & Docs Cheat Sheet

Fast reference for pytest, unittest, doctest, dependency fakes vs mock, hypothesis, ruff, tox, and Sphinx/MkDocs.

1. pytest & unittest Essentials

  • Follow Arrange → Act → Assert; test both happy path and edge/error cases.
  • @pytest.fixture injects reusable setup; yield inside a fixture runs teardown.
  • @pytest.mark.parametrize("inp,exp", [...]) runs one test over many cases cleanly.
  • Error checks: with pytest.raises(ValueError): (or self.assertRaises in unittest).

2. Test Doubles & hypothesis

  • Prefer Fakes (lightweight in-memory classes) over brittle internal mocks.
  • unittest.mock.patch rule: Patch where the name is looked up, not where it's defined.
  • Property-based testing (hypothesis): Write invariants (@given(...)); Hypothesis generates adversarial edge cases and shrinks failures.

3. ruff, Coverage & tox

  • ruff check --fix . (lint + imports + bugbear) and ruff format . (formatting).
  • pytest --cov=src --cov-branch --cov-report=term-missing checks line + branch coverage.
  • High coverage shows lines ran—it does not guarantee strong assertions.
  • tox runs tests across multiple Python versions (3.12–3.14) in clean envs.

4. Docs & doctest

  • Use Google-style docstrings (Args:, Returns:, Raises:) for MkDocs (mkdocstrings) and Sphinx (autodoc).
  • Put >>> examples in docstrings and verify with pytest --doctest-modules or doctest.testmod().
