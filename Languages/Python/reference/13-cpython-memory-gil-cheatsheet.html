CPython Memory, GC, Weakrefs & Free-Threaded Python Cheat Sheet

Fast reference for sys.getrefcount, reference cycles, generational gc, weakref, the GIL, PEP 684 subinterpreters, and PEP 703 (python3.13t–3.14t).

1. Reference Counting

  • Every PyObject tracks ob_refcnt; hits 0 → immediate deallocation + __del__.
  • sys.getrefcount(x) reads +1 higher because passing x adds a temporary call-frame ref.
  • Immortal objects (PEP 683: None, True, False, small ints) have huge sentinel refcounts and are never freed.

2. Cycles, Generational gc & weakref

  • Cycles (a.peer = b; b.peer = a) keep ob_refcnt >= 1 → reclaimed by generational gc (Gen 0/1/2).
  • gc tracks only containers (lists, dicts, instances), never primitives (int/str).
  • weakref.ref(obj) & WeakValueDictionary point without incrementing ob_refcnt.
  • Break parent/child cycles by keeping downward refs strong and upward back-pointers weak.

3. Why the GIL Exists

  • Protects non-atomic ob_refcnt & CPython internal dicts with one mutex per interpreter.
  • Released during blocking I/O syscalls and NumPy/PyTorch C loops.
  • Serializes pure-Python CPU-bound threads on standard CPython builds.

4. 2026–2027: Subinterpreters & PEP 703

  • Subinterpreters (PEP 684 / concurrent.interpreters): Multiple isolated heaps + per-interpreter GIL in 1 process.
  • Free-Threaded (PEP 703 / python3.13t–3.14t): No GIL; uses biased refcounting, mimalloc, and per-object locks.
  • Inspect GIL state at runtime: sys._is_gil_enabled().
  • User shared state still needs threading.Lock even on 3.14t!
