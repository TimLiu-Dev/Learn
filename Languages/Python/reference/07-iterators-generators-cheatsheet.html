Iterators, Generators & Streaming Pipelines Cheat Sheet

Fast reference for the Iterator Protocol, yield / yield from, generator expressions, and Python 3.12 itertools.

1. Iterator Protocol

  • Iterable: implements __iter__() returning a fresh iterator (reusable: list, tuple, dict).
  • Iterator: implements __iter__() returning self + __next__() raising StopIteration when done.
  • Single-pass trap: an exhausted iterator yields [] on a second loop without error.
  • Safe default pull: next(it, None) avoids StopIteration.

2. Generators & yield from

  • Any function with yield returns a lazy generator object (~200 bytes RAM).
  • Locals and execution line freeze at yield and resume on the next next().
  • yield from sub_iter delegates item-by-item without an inner loop.
  • return val inside a generator ends iteration immediately (does not yield val).

3. Comprehensions vs. GenExprs

  • List [...], Set {...}, Dict {k: v ...} are eager (allocate in RAM).
  • Generator expression (x for x in xs) is lazy (O(1) extra memory).
  • Short-circuit cleanly: any(x > 0 for x in xs), next((x for x in xs if ok(x)), None).
  • Avoid wrapping genexprs in [...] inside sum(), any(), all().

4. itertools Streaming Kit

  • islice(it, stop): lazy slice (since gen[:5] raises TypeError).
  • chain.from_iterable(groups): flatten nested iterables without copying.
  • batched(it, n) (Python 3.12+): yields tuple chunks of size n (last chunk may be shorter).
  • groupby(it, key=...): groups consecutive matching keys only — sort first if unsorted!
