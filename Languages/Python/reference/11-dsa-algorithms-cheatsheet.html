Data Structures, Algorithms & Memoization Cheat Sheet

Fast lookup for CPython container Big-O, deque, heapq, bisect, graph traversals, sliding windows, Timsort, and @lru_cache safety.

1. Container Big-O & Stacks / Queues

  • Stack (LIFO): list.append(x) + list.pop() → O(1).
  • Queue (FIFO): deque.append(x) + deque.popleft() → O(1). Never use list.pop(0) (O(n))!
  • Membership: x in set/dict is O(1) avg; x in list/deque is O(n).
  • Linked List: Node(val, next); O(1) pointer splice, O(n) index scan.

2. Heaps (heapq) & Binary Search (bisect)

  • heapq.heapify(xs) runs in O(n); heappush/heappop run in O(log n).
  • Max-heap trick: Push (-score, tie_id, item) so smallest tuple = highest score.
  • Top-K: Maintain size-k min-heap or heapq.nsmallest / nlargest.
  • bisect_left(arr, x): leftmost insertion index in O(log n) on sorted arr.
  • BST: Search is O(log n) balanced, O(n) if skewed.

3. Graphs & Sliding Windows

  • BFS: deque + visited.add(nxt) on enqueue → shortest unweighted path in O(V + E).
  • DFS: Recursion or list stack + visited set.
  • Kahn's Topo Sort: Track in_degree, enqueue 0s; if len(order) < len(nodes), a cycle exists.
  • Sliding Window: Add incoming arr[i], subtract outgoing arr[i - k] → O(n).

4. Timsort & @lru_cache

  • sorted() / .sort() use Timsort: stable, O(n log n) worst, O(n) nearly-sorted.
  • @functools.lru_cache(maxsize=128) / @cache memoizes hashable-arg calls.
  • Inspect cache stats via fn.cache_info() and clear via fn.cache_clear().
  • Trap: Never put @lru_cache directly on an instance method—it caches self forever and leaks memory! Use a @staticmethod or standalone helper.
