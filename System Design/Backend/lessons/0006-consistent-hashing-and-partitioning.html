Planetary Partitioning Big Tech Scale Dynamo & Cassandra Rings

Consistent Hashing & Dynamic Partition Rebalancing

Partitioning petabytes of data across thousands of commodity storage nodes requires distributing keys uniformly while preventing massive data migrations when nodes fail or scale horizontally.

1. The Catastrophic Flaw of Modulo Hashing: hash(key) % N

In naive partitioning, a key is assigned to node index hash(key) % N. When traffic surges and you add a single node ($N \to N+1$), almost every existing key maps to a completely different node:

  • In a 10-node cache cluster, scaling to 11 nodes invalidates over 90% of all cached keys ($1 - \frac{1}{N+1}$).
  • This causes a catastrophic Cache Stampede: millions of concurrent requests miss the cache simultaneously, hitting underlying databases and taking down the entire system.

All other nodes and keys remain completely unaffected.

2. Virtual Nodes (Vnodes) & Non-Uniform Distribution

A pure hash ring with few physical nodes leads to severe hotspots due to random clustering of hash positions.

The Virtual Node Solution (Amazon Dynamo / Apache Cassandra)

Instead of mapping each physical server to a single point on the ring, each physical node is assigned 100 to 256 virtual nodes (vnodes) (e.g. NodeA#1, NodeA#2, ...).

  • Uniform Key Spread: Interleaving hundreds of virtual nodes around the ring smooths variance, guaranteeing even distribution within ±3%.
  • Heterogeneous Hardware Support: A server with 64 CPU cores and 512GB RAM can be assigned 300 vnodes, while a smaller node receives 100 vnodes.
  • Rapid Rebalancing on Failure: When a physical node crashes, its load is automatically absorbed evenly across all remaining surviving nodes rather than crushing a single immediate neighbor.
