Distributed Object Storage, Erasure Coding & CDN Byte-Range Caching

Storing petabytes of unstructured media—video files, photos, backups, and machine learning models—demands immutable storage paradigms, presigned bypass uploads, erasure coding math, and edge byte-range caching.

1. Object Storage Architecture & Presigned Uploads

In prompts like "Design YouTube Video Ingestion", "Design Google Drive / Dropbox", or "Design Netflix Streaming", rookie candidates route massive video uploads through their microservice API servers.

⚠️ The Application Proxy Bottleneck

Routing a 2 GB video through an API server saturates server memory buffers, ties up connection sockets for minutes, and wastes expensive application CPU.

Senior Architecture: Presigned Direct-to-Storage Uploads:

  1. Client requests an upload ticket from API Gateway (metadata only: file size, content-type).
  2. API Gateway verifies auth and generates a cryptographic Presigned S3/GCS URL containing an expiring HMAC signature.
  3. Client uploads the binary payload directly to Object Storage (S3/GCS) via HTTP PUT.
  4. Object Storage emits an event (S3 Event Notification / Kafka) triggering asynchronous video transcoding or virus scanning workers.

2. Storage Efficiency: 3x Replication vs. Erasure Coding

At Big Tech petabyte scale, hardware storage efficiency dictates multi-million dollar infrastructure budgets:

Storage Strategy Durability Model Storage Overhead Trade-off & Best Use Case
3-Way Replication Stores 3 identical complete copies of the file across 3 separate availability zones/racks. 300% (3.0x):
1 PB data requires 3 PB raw storage.		 Low CPU overhead: Instant read access; ideal for hot active transactional data where latency is critical.
Erasure Coding
(Reed-Solomon $k + m$)		 Splits file into $k$ data shards and calculates $m$ parity shards. Any $k$ shards out of $(k+m)$ can reconstruct the original file. $\frac{k + m}{k} \times 100\%$:
For $10 + 4$: $\frac{14}{10} = 1.4\times$ (140%). 1 PB data needs only 1.4 PB raw storage!		 Extreme cost savings: Saves 50%+ in raw disk hardware while tolerating up to $m$ simultaneous node/rack failures. Higher CPU reconstruction cost for reads. Ideal for warm/cold object storage (S3 Standard / Glacier / f4).

CDN Byte-Range Caching for Video Streaming

Video players do not download complete 4K movies in a single HTTP request. They issue HTTP Byte-Range Requests: 

GET /video_4k.mp4 HTTP/1.1
Host: cdn.streamingservice.com
Range: bytes=0-1048575  -- Request first 1 MB chunk (approx. 2 seconds of playback)

HTTP/1.1 206 Partial Content
Content-Range: bytes 0-1048575/104857600
Content-Length: 1048576

CDN edge nodes cache individual 1 MB or 2 MB byte-ranges independently, allowing global users to seek to arbitrary timestamps instantly without forcing the origin object storage to stream the entire file.
