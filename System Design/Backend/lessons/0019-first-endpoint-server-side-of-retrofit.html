Your First Endpoint: The Server Side of Retrofit

You've written @GET("notes/{id}") in Retrofit plenty of times. In this lesson you write the other half: the server that receives that call. The one new skill is this: on the backend, you pick the status code. Your Android app only reacts to it.

1. The mirror image

Spring Boot's web layer looks a lot like Retrofit with the arrows reversed. Retrofit describes a call to make. A Spring @RestController handles a call that arrives (spring.io Kotlin tutorial).

2. Four status codes cover 90% of a first API

Your app's when (response.code()) branches only work if the server sends the right codes. These are the four meanings defined in RFC 9110 §15:

CodeSend it when…Spring (Kotlin)
200 OKA GET found the resource (§15.3.1)ResponseEntity.ok(note)
201 CreatedA POST created something. Include a Location header pointing to it (§15.3.2)ResponseEntity.created(uri).body(note)
400 Bad RequestThe client sent invalid input (§15.5.1)ResponseEntity.badRequest().build()
404 Not FoundNo resource exists at that URL (§15.5.5)ResponseEntity.notFound().build()

Here's the whole controller. It stores notes in memory on purpose, so the only new things in front of you are HTTP and Spring. You'll swap in Postgres in a later lesson.

// NoteController.kt
data class Note(val id: Long, val title: String)
data class CreateNote(val title: String)

@RestController
@RequestMapping("/notes")
class NoteController {
    private val notes = ConcurrentHashMap<Long, Note>()
    private val nextId = AtomicLong(1)

    @GetMapping("/{id}")
    fun get(@PathVariable id: Long): ResponseEntity<Note> =
        notes[id]?.let { ResponseEntity.ok(it) } ?: ResponseEntity.notFound().build()

    @PostMapping
    fun create(@RequestBody body: CreateNote): ResponseEntity<Note> {
        if (body.title.isBlank()) return ResponseEntity.badRequest().build()   // validate BEFORE side effects
        val note = Note(nextId.getAndIncrement(), body.title.trim())
        notes[note.id] = note
        return ResponseEntity.created(URI.create("/notes/${note.id}")).body(note)
    }
}
☕ Java on the side: the same controller in Java 
// NoteController.java
public record Note(long id, String title) {}
public record CreateNote(String title) {}

@RestController
@RequestMapping("/notes")
public class NoteController {
    private final Map<Long, Note> notes = new ConcurrentHashMap<>();
    private final AtomicLong nextId = new AtomicLong(1);

    @GetMapping("/{id}")
    public ResponseEntity<Note> get(@PathVariable long id) {
        Note note = notes.get(id);
        return note != null ? ResponseEntity.ok(note) : ResponseEntity.notFound().build();
    }

    @PostMapping
    public ResponseEntity<Note> create(@RequestBody CreateNote body) {
        if (body.title() == null || body.title().isBlank()) return ResponseEntity.badRequest().build();
        Note note = new Note(nextId.getAndIncrement(), body.title().trim());
        notes.put(note.id(), note);
        return ResponseEntity.created(URI.create("/notes/" + note.id())).body(note);
    }
}
Free 400s from Spring

If someone calls GET /notes/abc, Spring can't convert "abc" to a Long, so it answers 400 before your method ever runs. Your simulator below has to do the same.

5. Do it for real (on your machine)

  1. Open start.spring.io and choose Project: Gradle - Kotlin, Language: Kotlin, Spring Boot: the latest stable release (no SNAPSHOT/RC), Java: 21, Dependencies: Spring Web. Click Generate and open the project in IntelliJ IDEA.
  2. Paste the controller into src/main/kotlin/…/NoteController.kt and let the IDE add the imports.
  3. Run ./gradlew bootRun, then in another terminal: 
    curl -i -X POST localhost:8080/notes -H 'Content-Type: application/json' -d '{"title":"Buy milk"}'   # 201 + Location: /notes/1
curl -i localhost:8080/notes/1      # 200
curl -i localhost:8080/notes/999    # 404
curl -i localhost:8080/notes/abc    # 400
curl -i -X POST localhost:8080/notes -H 'Content-Type: application/json' -d '{"title":"   "}'   # 400
  4. Android bonus: point a Retrofit client in the emulator at http://10.0.2.2:8080/. That address is how the emulator reaches your computer's localhost (Android docs). Android blocks plain HTTP by default from API 28, so allow cleartext traffic for 10.0.2.2 in a debug-only network security config (docs).
  5. Java on the side: generate a second project with Language: Java, paste the Java version, and run the same curls. You should get identical output.
✓ Win condition

All five curls return the commented status codes. Then you have a working backend endpoint, and it's step one of your Phase 0 portfolio service.
