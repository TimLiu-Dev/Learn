API Contract Architecture: Keyset/Cursor Pagination & Webhook Integrity

In production systems, poorly designed API contracts are database killers. Using offset pagination against a multi-million row table exhausts database buffers, while unverified webhooks invite catastrophic replay vulnerabilities.

1. The Offset Pagination Trap vs. Keyset (Cursor) Navigation

The most common rookie mistake in senior interviews is proposing LIMIT 20 OFFSET 100000 for listing feeds, transactions, or notifications.

⚠️ The Physics of LIMIT / OFFSET

Relational databases cannot jump directly to row 100,000. To execute OFFSET 100000 LIMIT 20, the storage engine must read 100,020 rows from disk/cache, sort them in memory, discard the first 100,000 rows, and return the remaining 20.

  • Performance: Time complexity is $O(N)$ with respect to offset depth. As pages deepen, query latency spikes from 2ms to 8,000ms, locking CPU cores.
  • Data Inconsistency: If a new row is inserted while the user navigates between page 1 and page 2, existing rows shift down by 1 index, causing the user to see duplicate items or skip records entirely.
Dimension Offset-Based Pagination Keyset / Cursor-Based Pagination
SQL Query Shape SELECT * FROM txns ORDER BY id DESC LIMIT 20 OFFSET 50000; SELECT * FROM txns WHERE (created_at, id) < (:last_time, :last_id) ORDER BY created_at DESC, id DESC LIMIT 21;
Database Index Operation Full B+ Tree leaf scan up to $N + \text{limit}$ rows. Discards $N$. B+ Tree index seek straight to cursor key in $O(\log N)$ time.
Time Complexity $O(N)$ — degrades proportionally to offset depth. $O(1)$ constant time with respect to total table size.
Insertion / Deletion Stability Unstable: Concurrent inserts cause duplicate or skipped records. Stable: Deterministic tie-breaking prevents skips or duplicates.
Arbitrary Page Jumping Supported (e.g. "Jump to page 47"). Not supported: Sequential "Load More" / infinite scroll only.

2. Protocol Contracts: REST vs. gRPC & Webhook Security

REST vs. gRPC Architectural Trade-offs

Senior engineers distinguish between external client-facing APIs and internal microservice-to-microservice mesh communication:

  • External Facing (REST / JSON over HTTPS): Ubiquitous, human-readable, easily cached by CDN edges and corporate reverse proxies. Ideal for public developer APIs.
  • Internal Microservice Mesh (gRPC over HTTP/2): Protocol Buffers binary serialization provides 3x to 10x smaller network payloads and 5x to 20x faster deserialization compared to JSON. HTTP/2 multiplexing allows hundreds of concurrent RPC requests over a single persistent TCP connection.
