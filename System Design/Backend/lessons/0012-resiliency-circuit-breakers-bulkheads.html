Resilience Engineering: Circuit Breakers & Adaptive Throttling

In microservice architectures, unhandled downstream latency cascades upstream, exhausting thread pools and causing total system outages. Resilience patterns isolate failures and fail fast to preserve core system availability.

1. Anatomy of a Cascading Outage

Consider three microservices: OrderService → PaymentService → ExternalBankGateway.

  1. ExternalBankGateway degrades: latency spikes from 50ms to 15 seconds.
  2. PaymentService threads block waiting for HTTP responses. Within seconds, PaymentService's 200 HTTP worker threads are completely exhausted.
  3. PaymentService stops accepting health check pings. Kubernetes restarts it, creating a container crash loop.
  4. OrderService threads now block waiting for PaymentService. OrderService exhausts its own thread pool and crashes.
  5. Cascading Failure Complete: A slow third-party API has taken down the entire company's infrastructure.

2. Bulkheads and Exponential Backoff with Jitter

Resilience Pattern How It Operates Production Impact
Circuit Breaker Trips to OPEN when failures spike, failing fast (<1ms) with fallbacks without sending network requests. Shields downstream services while they recover; frees upstream threads immediately.
Bulkhead Isolation Partitions worker thread pools by downstream dependency (e.g. 50 threads for Payments, 20 for Recommendations). A total failure in Recommendations cannot consume Payment threads or block revenue-critical paths.
Exponential Backoff + Full Jitter Calculates sleep time as $\text{sleep} = \text{random}(0, \min(M, B \cdot 2^i))$. Decorrelates retry spikes across time, preventing synchronized thundering herd waves on recovering servers.
