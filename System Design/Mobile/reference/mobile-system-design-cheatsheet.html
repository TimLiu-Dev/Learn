Mobile System Design Interview Cheatsheet (2027)

High-density operational reference for 45-60 minute Senior & Staff Mobile interviews.

The 5-Stage Time Allocation Formula (45 Min Interview)

Stage 1: Scope & Clarifying Requirements 00:00 – 05:00 (5 mins)

Clarify Functional Requirements (core user flows), Non-Functional Requirements (offline capability, latency budget, battery limits, targeted Android OS versions / iOS versions), and Network Conditions (poor 3G, intermittent tunnels).

Goal: Never assume. Agree on 2-3 core features and 2 key non-functional constraints.
Stage 2: High-Level Architecture & Clean Boundaries 05:00 – 15:00 (10 mins)

Draw box diagrams showing: UI Layer (Compose/SwiftUI) ↔ ViewModel (UDF State) ↔ Domain Layer (UseCases) ↔ Repository (SSOT) ↔ Local DB (Room/SQLite) & Network (OkHttp/gRPC).

Goal: Establish clear unidirectional data flow and Single Source of Truth before deep diving.
Stage 3: Subsystem Deep Dives (Data, Sync & Storage) 15:00 – 30:00 (15 mins)

Dive deep into the hardest architectural problem of the question: Cache invalidation policy, offline write queue with exponential backoff, pagination cursors, or conflict resolution (CRDTs).

Goal: Write out concrete data models, schemas, and contract interfaces.
Stage 4: Edge Cases, Battery, Radio & Lifecycle Failures 30:00 – 40:00 (10 mins)

Address: Android Process Death (SavedStateHandle vs DB restore), Doze Mode / App Standby Buckets, memory leaks in coroutine scopes, and Cellular RRC tail power consumption.

Goal: Proactively point out OS failure modes before the interviewer asks.
Stage 5: Wrap-Up, Observability & 2027 Edge Scaling 40:00 – 45:00 (5 mins)

Highlight telemetry metrics (TTI - Time to Interactive, frame drop rate, crash-free sessions), Baseline Profiles for instant cold startup, and edge AI integration.

Goal: Leave the interviewer convinced you operate at Staff / Principal scope.

2027 Mobile Hardware Rules of Thumb for Design Estimation

Resource Metric Safe Production Budget Dangerous Threshold Architectural Mitigation
Heap Memory (RAM) < 150 MB active heap > 250 MB (OOM risk on low-end devices) LRU bitmap downsampling, avoid storing byte arrays in memory, streaming parser.
Disk SQLite Storage < 100 MB cached data > 500 MB (Triggers Android OS Storage Manager warning) LRU cache trim on startup, TTL eviction policy on stale records, vacuum.
App Cold Startup (TTI) < 500 ms > 1500 ms (Direct negative app store rating impact) ART Baseline Profiles, lazy dependency injection, off-main-thread initialization.
Network Payloads < 30 KB per page payload > 200 KB per response Protobuf over gRPC, Brotli/Zstandard compression, fields filtering / GraphQL.
Cellular Radio Active Batched bursts < 5s duration Scattered requests every 10-15s (Keeps radio in high-power DCH state) Batch telemetry and non-urgent sync calls; coalesce sockets over HTTP/3.
Hardware Video Codecs Pool of 2–3 active/preload players > 6 concurrent player instances (Exhausts MediaCodec hardware silicon) Player instance pooling; release and detach surfaces when scrolled offscreen.
Push Notifications Tickle pointer < 100 bytes > 4 KB payload (Exceeds FCM / APNs payload capacity limit) Sync-on-Tickle: Push sequence ID to wake app, pull ordered delta over API.
Auth Token Refresh Exactly 1 concurrent refresh via Mutex Multiple parallel 401 refresh requests (Invalidates Refresh Token Rotation) OkHttp Authenticator with Coroutine Mutex to queue and replay failed calls.
Continuous GPS Tracking Activity-gated adaptive polling Continuous 1Hz GNSS polling (Drains 20%+ battery per hour) Sleep GPS while STILL using ActivityTransition; Kalman filter in urban canyons.
Feature Flag Evaluation Local evaluation < 10 μs Synchronous remote network query (Blocks cold startup splash screen) Evaluate locally against cached disk manifest; sticky bucketing via hash % 100.
Search Typeahead Queries debounce(300ms) + flatMapLatest Firing queries on raw keystroke (Floods backend and causes race condition) Drop intermediate keystrokes with debounce; cancel in-flight queries with flatMapLatest.
Large Media Uploads 5MB slices via S3 Multipart / TUS Monolithic > 50MB single POST upload (Fails on cellular handover/drops) Upload chunked byte slices; record ETags in SQLite Room DB for instant resumption.
Background Audio Playback MediaSessionService foreground Hosting player inside Activity / ViewModel (Halts audio when screen locked) Run MediaSessionService with FOREGROUND_SERVICE_MEDIA_PLAYBACK and ducking.
