The culmination of the 2027 Mobile System Design curriculum. Architect, implement, and showcase PulseRelay: an Edge-AI Augmented Offline-First Real-Time Synchronization Engine engineered to land Senior and Staff Android roles.

1. Executive Architecture Summary

PulseRelay 2027 is a production-calibrated open-source mobile client engine designed to solve the hardest problems in distributed mobile systems:

Subsystem 1: CRDT Distributed Engine

LWW-Element-Set and Fractional Indexing text buffer with Room SQLite WAL persistence. Supports multi-master offline editing on intermittent network connections with zero data loss.

Subsystem 2: Radio-Aware Transport

Multiplexed gRPC/Protobuf over HTTP/3 (QUIC) featuring 0-RTT handshakes, seamless Wi-Fi/5G connection migration, and cellular radio (RRC) tail power minimization.

Subsystem 3: On-Device Edge AI

Gemini Nano execution via LiteRT on hardware NPU cores with INT4 quantization and memory-mapped (mmap) weights, running smart completions with sub-25ms latency.

Subsystem 4: Zero-Drop Telemetry

POSIX mmap binary ring buffer with Snappy compression and W3C distributed trace propagation, guaranteeing zero dropped breadcrumbs even during native kernel crashes.

2. Core Kotlin 2.x Architecture: PulseRelayEngine

package com.pulserelay.core.sync

import kotlinx.coroutines.flow.*
import kotlinx.coroutines.sync.Mutex
import kotlinx.coroutines.sync.withLock

class PulseRelayEngine(
    private val localDao: DocumentCrdtDao,
    private val transport: Http3QuicTransport,
    private val edgeAi: GeminiNanoAssistant,
    private val telemetry: MmapTelemetryBuffer
) {
    private val engineMutex = Mutex()
    private val _documentState = MutableStateFlow<DocSnapshot>(DocSnapshot.Empty)
    val documentState: StateFlow<DocSnapshot> = _documentState.asStateFlow()

    suspend fun applyLocalKeystroke(char: Char, leftPos: Double, rightPos: Double, authorId: String) {
        val newPos = (leftPos + rightPos) / 2.0
        val timestamp = System.currentTimeMillis()
        val operation = CrdtInsertOp(position = newPos, character = char, authorId = authorId, lamportTs = timestamp)

        engineMutex.withLock {
            // 1. Optimistic memory update (instant UI render < 5ms)
            _documentState.update { it.insert(operation) }
            
            // 2. Persist to Room SQLite WAL
            localDao.insertOperation(operation.toEntity())
            
            // 3. Log breadcrumb to mmap buffer
            telemetry.logEvent("KEYSTROKE_APPLIED", "pos=$newPos")
            
            // 4. Batch & queue for radio-aware HTTP/3 QUIC sync
            transport.enqueueCrdtOp(operation)
        }
    }

    suspend fun mergeRemoteBatch(remoteOps: List<CrdtInsertOp>) = engineMutex.withLock {
        // Deterministic CRDT convergence
        localDao.insertBatch(remoteOps.map { it.toEntity() })
        val mergedList = localDao.getAllActiveOperations()
        _documentState.value = DocSnapshot.fromSortedOps(mergedList)
    }
}

3. Interactive Practice: End-to-End Multi-Client Partition Simulation

Task: Simulate two mobile clients (Client A and Client B) who go offline, make concurrent edits using fractional indexes, and then merge. Implement simulateSync(clientAOps, clientBOps). It must merge both operation arrays into a single unified document string sorted by position, with ties broken deterministically by authorId.

PulseRelay Multi-Client Sync Engine Sandbox
Hint 1: Combine arrays using [...opsA, ...opsB].
Hint 2: Sort by a.pos - b.pos, and if equal use a.authorId.localeCompare(b.authorId).
Canonical Solution: 
function simulateSync(opsA, opsB) {
  const allOps = [...opsA, ...opsB];
  allOps.sort((a, b) => {
    if (a.pos !== b.pos) return a.pos - b.pos;
    return a.authorId.localeCompare(b.authorId);
  });
  return allOps.map(op => op.char).join('');
}
