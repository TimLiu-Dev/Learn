Lesson 0006: Background Task Scheduling: WorkManager vs Doze Mode & Standby Buckets

Navigate modern Android OS background restrictions. Understand Doze mode maintenance windows, App Standby Buckets, WorkManager persistent constraints, and expedited jobs.

1. Doze Mode & App Standby Buckets

In Android 15/16/17, you cannot arbitrarily run background threads once the user leaves your app. The OS enforces two primary power-saving mechanics:

Doze Mode System Sleep

When the device is unplugged and stationary with the screen off, Android disables network access and ignores wake locks. It wakes up periodically only during brief maintenance windows to let queued WorkManager tasks execute.

Standby Buckets Usage Tiering

Apps are dynamically classified by usage: ACTIVE, WORKING_SET, FREQUENT, RARE, and RESTRICTED. Apps in the RARE bucket are limited to running background jobs only once every 24 hours!

2. WorkManager Guaranteed Execution Pattern

WorkManager is built on top of JobScheduler and backed by an internal SQLite database. Work scheduled with WorkManager is guaranteed to execute even if the app process is terminated or the phone reboots: 

val syncConstraints = Constraints.Builder()
    .setRequiredNetworkType(NetworkType.UNMETERED) // Only Wi-Fi
    .setRequiresBatteryNotLow(true)
    .setRequiresCharging(true) // Run when user charges overnight
    .build()

val syncWorkRequest = PeriodicWorkRequestBuilder<FeedSyncWorker>(
    repeatInterval = 1, repeatIntervalTimeUnit = TimeUnit.HOURS
)
    .setConstraints(syncConstraints)
    .setBackoffCriteria(BackoffPolicy.EXPONENTIAL, 15, TimeUnit.SECONDS)
    .build()

WorkManager.getInstance(context).enqueueUniquePeriodicWork(
    "NightlyFeedSync",
    ExistingPeriodicWorkPolicy.KEEP,
    syncWorkRequest
)

3. Interactive Practice: Build a Constraint Evaluator

Task: Implement canRunJob(deviceState, constraints). deviceState contains: { isCharging: boolean, isWifi: boolean, batteryPct: number }. constraints contains: { requiresCharging: boolean, requiresWifi: boolean, minBatteryPct: number }. Return true only if all specified constraints are met.

Job Constraint Evaluator Sandbox
Hint 1: Check each constraint individually. If a constraint is true, verify the corresponding device state.
Hint 2: Ensure batteryPct >= minBatteryPct.
Canonical Solution: 
function canRunJob(deviceState, constraints) {
  if (constraints.requiresCharging && !deviceState.isCharging) return false;
  if (constraints.requiresWifi && !deviceState.isWifi) return false;
  if (deviceState.batteryPct < constraints.minBatteryPct) return false;
  return true;
}
