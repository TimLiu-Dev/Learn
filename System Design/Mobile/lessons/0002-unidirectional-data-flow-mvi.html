Lesson 0002: Unidirectional Data Flow (MVI/UDF) & State Machines at Scale

Architect bug-free UI state in Jetpack Compose. Learn the distinction between StateFlow (persistent state) and Channels (single-shot side effects), avoid unnecessary recomposition loops, and build an immutable reducer state machine.

1. The UDF / MVI Closed-Loop Architecture

In modern 2027 Android system design, MVVM with multiple scattered LiveData or mutable variables is an anti-pattern. Large codebases at scale enforce Unidirectional Data Flow (UDF):

1. UI Intent / Action

User interactions (taps, pulls, text input) are emitted as immutable sealed class events from Compose Composables to the ViewModel.

2. Pure Reducer / State Machine

The ViewModel processes intents against the current state and domain repositories to compute the next atomic, immutable state.

3. Single UI State Render

The UI observes a single StateFlow<UiState>. Because state is immutable and compared by value, Compose recomposes only modified subtrees.

2. StateFlow vs. Channel: The Anti-Pattern of Re-Triggered Snackbars

A classic trap in mobile system design interviews is modeling one-off side effects (such as showing a Snackbar or navigating to checkout) as properties inside UiState.

The Re-emission Bug (Why StateFlow fails for one-off events)

StateFlow is a state holder with replay cache of 1. If you store errorMessage: String? inside UiState, when the user rotates the device or returns to the screen, the newly subscribed UI observer immediately replays the cached state, re-triggering the Snackbar or duplicate navigation!

Staff Solution: Use a Kotlin coroutine Channel<UiEffect> (buffered) exposed as a cold receiveAsFlow() for single-consumption events.

3. Production Kotlin 2.x MVI State Machine

package com.systemdesign.feed.presentation

import androidx.lifecycle.ViewModel
import androidx.lifecycle.viewModelScope
import kotlinx.coroutines.channels.Channel
import kotlinx.coroutines.flow.*
import kotlinx.coroutines.launch

// 1. Immutable State
data class FeedUiState(
    val isLoading: Boolean = false,
    val items: List<FeedItem> = emptyList(),
    val isOfflineMode: Boolean = false
)

// 2. User Actions (Intents)
sealed interface FeedIntent {
    data object Refresh : FeedIntent
    data class ToggleLike(val itemId: String) : FeedIntent
}

// 3. One-off Side Effects
sealed interface FeedEffect {
    data class ShowToast(val message: String) : FeedEffect
    data class NavigateToDetail(val itemId: String) : FeedEffect
}

// 4. Production ViewModel
class FeedViewModel(private val repository: FeedRepository) : ViewModel() {
    private val _uiState = MutableStateFlow(FeedUiState(isLoading = true))
    val uiState: StateFlow<FeedUiState> = _uiState.asStateFlow()

    private val _effectChannel = Channel<FeedEffect>(Channel.BUFFERED)
    val effect: Flow<FeedEffect> = _effectChannel.receiveAsFlow()

    fun handleIntent(intent: FeedIntent) {
        when (intent) {
            is FeedIntent.Refresh -> refreshFeed()
            is FeedIntent.ToggleLike -> toggleLike(intent.itemId)
        }
    }

    private fun toggleLike(itemId: String) {
        viewModelScope.launch {
            // Optimistic UI state update
            _uiState.update { current ->
                current.copy(items = current.items.map { 
                    if (it.id == itemId) it.copy(isLiked = !it.isLiked) else it 
                })
            }
            try {
                repository.toggleLike(itemId)
            } catch (e: Exception) {
                // Rollback and emit one-off error
                _uiState.update { current ->
                    current.copy(items = current.items.map { 
                        if (it.id == itemId) it.copy(isLiked = !it.isLiked) else it 
                    })
                }
                _effectChannel.send(FeedEffect.ShowToast("Network failed. Like rolled back."))
            }
        }
    }
}

4. Interactive Practice: Implement an Immutable MVI State Reducer

Task: Implement the pure reducer function reduce(state, action). Given the current immutable state and an incoming action, return the new state without mutating the original state object.

Pure State Reducer Sandbox
Hint 1: Always use the spread operator { ...state, ... } to return a new reference so consumers detect state transitions.
Hint 2: Ensure that triggering FETCH_START clears any pre-existing error message to null.
Canonical Solution: 
function reduce(state, action) {
  switch (action.type) {
    case 'FETCH_START':
      return { ...state, loading: true, error: null };
    case 'FETCH_SUCCESS':
      return { ...state, loading: false, count: action.payload, error: null };
    case 'FETCH_ERROR':
      return { ...state, loading: false, error: action.error };
    case 'INCREMENT':
      return { ...state, count: state.count + 1 };
    default:
      return state;
  }
}

5. Calibration Quizzes

Question 1: In high-scale Compose apps, why is exposing single-time UI events (like checkout navigation) via a buffered Channel preferred over SharedFlow with replay=0?
A SharedFlow causes native memory heap fragmentation when observed across multiple screens.
B SharedFlow does not support coroutine unit test dispatchers during integration testing.
C SharedFlow drops events if fired while the UI lifecycle is temporarily stopped in background.
D SharedFlow triggers full screen recomposition passes whenever any new collector connects.
Breakdown:
  • Option C (Correct): If an event is posted to a SharedFlow(replay=0) while the Activity is stopped (e.g. screen off or user momentarily opened another app), the event is dropped. A buffered Channel holds the event until the collector resumes.
Question 2: Why must UI state objects in Jetpack Compose be modeled as immutable data classes with immutable collections (e.g. PersistentList)?
A Android OS low-memory killers cannot serialize mutable Java collections into Bundles.
B Compose compiler stability algorithms rely on reference changes to safely skip recomposition.
C Kotlin Coroutines throw fatal runtime exceptions when mutating objects across dispatchers.
D Immutable objects bypass garbage collection pauses by allocating memory on the call stack.
Breakdown:
  • Option B (Correct): Compose determines whether a composable can be skipped (smart recomposition) based on stability. If you mutate a list in-place, the object identity doesn't change, causing Compose to either miss updates or unnecessarily recompose the entire hierarchy.
