Lesson 0004: Network Layer Resilience: Exponential Backoff, Jitter & Idempotency

Build resilient mobile networking. Implement custom OkHttp interceptors, atomic JWT token refreshes with coroutine mutex locks, idempotency keys, and full-jitter exponential backoff to eliminate the thundering herd problem.

1. The Thundering Herd Problem & Full Jitter

When a backend service goes down and recovers, millions of mobile devices retrying with naive constant intervals (e.g. retry every 2 seconds) will synchronize and hit the backend simultaneously, immediately crashing it again.

Staff mobile architects apply Exponential Backoff with Full Jitter (formalized by AWS architecture research):

Full Jitter Mathematical Formula

sleep = random_between(0, min(max_backoff, base_backoff * 2^attempt))

Introducing uniform random jitter across the full backoff interval disperses retry waves into a flat, steady stream of requests, giving server clusters breathing room to recover.

2. Atomic Token Refresh with Mutex Locks

If a user opens an app and 5 requests fire concurrently while the auth token is expired, all 5 requests will return HTTP 401 Unauthorized. Without synchronization, the app triggers 5 separate token refresh calls, invalidating each other's refresh tokens! 

// Kotlin 2.x - Token Refresh Interceptor with Coroutine Mutex
class AuthInterceptor(
    private val tokenStorage: TokenStorage,
    private val authService: AuthRemoteService
) : Interceptor {
    private val refreshMutex = Mutex()

    override fun intercept(chain: Interceptor.Chain): Response {
        var request = chain.request()
        val currentToken = tokenStorage.getAccessToken()
        
        request = request.newBuilder()
            .header("Authorization", "Bearer $currentToken")
            .build()

        val response = chain.proceed(request)

        if (response.code == 401) {
            response.close() // Avoid connection leak
            
            val newToken = runBlocking {
                refreshMutex.withLock {
                    // Check if another thread already refreshed while waiting for lock
                    val latestToken = tokenStorage.getAccessToken()
                    if (latestToken != currentToken) {
                        latestToken
                    } else {
                        val refreshed = authService.refreshToken(tokenStorage.getRefreshToken())
                        tokenStorage.saveTokens(refreshed.accessToken, refreshed.refreshToken)
                        refreshed.accessToken
                    }
                }
            }

            // Retry original request with fresh token
            val newRequest = request.newBuilder()
                .header("Authorization", "Bearer $newToken")
                .build()
            return chain.proceed(newRequest)
        }
        return response
    }
}

3. Interactive Practice: Calculate Exponential Backoff with Jitter

Task: Implement calculateBackoff(attempt, baseDelay, maxDelay, mockRandom). It calculates $t = \min(\text{maxDelay}, \text{baseDelay} \cdot 2^{\text{attempt}})$, and multiplies by mockRandom (a float between 0.0 and 1.0) to compute full jitter. Return Math.floor(result).

Jitter Backoff Sandbox
Hint 1: Use Math.pow(2, attempt) to compute $2^{\text{attempt}}$.
Hint 2: Always cap by maxDelay via Math.min(maxDelay, baseDelay * Math.pow(2, attempt)) before multiplying by mockRandom.
Canonical Solution: 
function calculateBackoff(attempt, baseDelay, maxDelay, mockRandom = Math.random()) {
  const expDelay = Math.min(maxDelay, baseDelay * Math.pow(2, attempt));
  return Math.floor(expDelay * mockRandom);
}
