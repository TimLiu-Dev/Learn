Lesson 0015: Monorepo Modularization, Dynamic Feature Delivery & Plugin Architecture

Scale Android codebases to hundreds of engineers. Enforce strict API vs. Implementation boundaries to maximize Gradle build cache hits, eliminate circular dependencies, and stream on-demand dynamic feature modules.

1. API vs. Implementation Module Splitting

In monolithic Android codebases, modifying a single class in a feature module often triggers a 20-minute recompile of all dependent modules. Staff architects eliminate this using API/Impl separation: 

              [ :feature:feed:impl ]
                       │ (Depends on API)
                       ▼
             [ :feature:feed:api ] ◄── (Public interfaces & route contracts)
                       ▲
                       │ (Compile-time dependency only!)
             [ :feature:profile:impl ]
ABI Stability & Cache Hit Guarantees

The :feature:feed:api module contains only pure Kotlin interfaces, navigation route keys, and DTOs. It changes infrequently. When an engineer edits internal Composable layouts or ViewModels inside :feature:feed:impl, the public ABI (Application Binary Interface) remains unchanged. Gradle rebuilds only the impl module, skipping re-compilation of the rest of the application!

2. On-Demand Play Feature Delivery

Heavy features used by only 5% of users (such as KYC Passport Verification or AR Camera) should not bloat the initial download: 

val splitInstallManager = SplitInstallManagerFactory.create(context)
val request = SplitInstallRequest.newBuilder()
    .addModule("feature_id_verification")
    .build()

splitInstallManager.registerListener { state ->
    when (state.status()) {
        SplitInstallSessionStatus.DOWNLOADING -> updateProgressBar(state.bytesDownloaded(), state.totalBytesToDownload())
        SplitInstallSessionStatus.INSTALLED -> launchDynamicFeatureActivity()
    }
}
splitInstallManager.startInstall(request)

3. Interactive Practice: Detect Circular Module Dependencies

Task: Implement hasCircularDependency(moduleGraph). moduleGraph is an object mapping module names to an array of dependent modules (e.g. { ":feed": [":network"], ":network": [] }). Return true if there is any cycle (e.g. A → B → C → A), and false if it is a valid Directed Acyclic Graph (DAG).

Dependency Cycle Detector Sandbox
Hint 1: Use Depth-First Search (DFS) with a recursion stack (recStack) to identify back-edges.
Hint 2: Remember to remove the current node from recStack when backtracking!
Canonical Solution: 
function hasCircularDependency(graph) {
  const visited = new Set();
  const recStack = new Set();

  function isCyclic(node) {
    if (recStack.has(node)) return true;
    if (visited.has(node)) return false;

    visited.add(node);
    recStack.add(node);

    const neighbors = graph[node] || [];
    for (const neighbor of neighbors) {
      if (isCyclic(neighbor)) return true;
    }

    recStack.delete(node);
    return false;
  }

  for (const node in graph) {
    if (isCyclic(node)) return true;
  }
  return false;
}
