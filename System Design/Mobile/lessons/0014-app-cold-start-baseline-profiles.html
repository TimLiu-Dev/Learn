Lesson 0014: App Cold Start Optimization: Baseline Profiles, Dex Optimization & Lazy DI

Achieve sub-400ms cold startup at scale. Dissect Android Runtime (ART) Ahead-Of-Time compilation, eliminate startup page faults with Dex layout optimization, and orchestrate lazy dependency injection DAGs.

1. Anatomy of a Mobile Cold Launch

During an Android cold launch, every millisecond counts before the first pixel draws: 

[App Icon Tap] ──► [OS Forks Zygote] ──► [Load classes.dex] ──► [Application.onCreate()]
                                                                            │
   [First Render: TTID] ◄─── [Activity.onCreate()] ◄─── [Init Heavy DI Graph]

TTID (Time to Initial Display): Time until the window draws its initial frame (skeleton/placeholder). Target: < 400ms.
TTFD (Time to Full Display): Time until interactive content is hydrated and visible. Target: < 800ms.

2. The Baseline Profiles Revolution

Historically, Android interpreted Dalvik bytecode on launch until the JIT compiler warmed up after days of use.

Baseline Profiles & Dex Layout Optimization

Baseline Profiles specify the exact critical classes and methods invoked during cold launch and first frame rendering. During app installation via Google Play, ART runs Ahead-Of-Time (AOT) compilation on these exact methods, translating them directly into native ARM machine code!

Dex Layout Optimization: Groups all startup classes contiguously into classes.dex. This prevents random flash disk seek page faults, reducing flash I/O latency on initial process startup by up to 40%.

3. Interactive Practice: Build an App Startup DAG Orchestrator

Task: Implement executeStartupPlan(tasks). Each task has { id, deps: [depId, ...], run: () => void }. Execute tasks so that every task runs only after all of its dependencies have completed. Return the list of executed task IDs in order of completion.

Startup DAG Orchestrator Sandbox
Hint 1: Use topological traversal or recursive dependency resolution.
Hint 2: Before calling t.run(), recursively call runTask on all of t.deps.
Canonical Solution: 
function executeStartupPlan(tasks) {
  const executed = [];
  const completed = new Set();
  const taskMap = new Map(tasks.map(t => [t.id, t]));

  function runTask(t) {
    if (completed.has(t.id)) return;
    for (const depId of t.deps) {
      if (!completed.has(depId)) {
        runTask(taskMap.get(depId));
      }
    }
    t.run();
    completed.add(t.id);
    executed.push(t.id);
  }

  for (const t of tasks) runTask(t);
  return executed;
}
