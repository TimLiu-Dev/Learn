Lesson 0010: Enterprise Structured Logging (log/slog), Dynamic Levels, & PII Redaction

Third-party logging libraries (Logrus, Zap, Zerolog) fragmented the Go ecosystem for years. In Go 1.21, the Go team standardized structured, high-performance logging via log/slog. In this lesson, we build production-grade logging infrastructure: dynamic level switching via HTTP without restarting pods (slog.LevelVar), custom handler middleware, and automatic Personally Identifiable Information (PII) redaction.

⚙️ Senior Production Practice: slog.LogAttrs for Zero-Allocation Hot Paths

Calling variadic helpers like slog.Info("msg", "key", val)—or even passing typed slog.Int64("id", id) to slog.Info(...)—still boxes arguments into a []any variadic slice on hot paths. True zero-allocation logging uses slog.LogAttrs with strongly typed attributes:
• slog.LogAttrs(ctx, slog.LevelInfo, "request", slog.Int64("user_id", id), slog.Duration("latency", d))
Because LogAttrs accepts ...slog.Attr (concrete structs rather than ...any), typed values stay unboxed on the stack!

1. Dynamic Runtime Log Level Switching with slog.LevelVar

In production Kubernetes clusters, running at DEBUG level generates terabytes of noisy logs and overwhelms ingest pipelines. But when an outage occurs, you need debug logs immediately without redeploying containers:

dynamic_logging.go Live Runtime Adjustment via HTTP 
package main

import (
    "log/slog"
    "net/http"
    "os"
)

var programLevel = new(slog.LevelVar) // Defaults to INFO

func initLogger() {
    h := slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{
        Level: programLevel,
    })
    slog.SetDefault(slog.New(h))
}

// HTTP Admin endpoint to flip level live:
// curl -X POST "http://localhost:8081/admin/log-level?level=DEBUG"
func handleSetLogLevel(w http.ResponseWriter, r *http.Request) {
    if r.Method != http.MethodPost {
        http.Error(w, "method not allowed", http.StatusMethodNotAllowed)
        return
    }
    switch r.URL.Query().Get("level") {
    case "DEBUG":
        programLevel.Set(slog.LevelDebug)
    case "INFO":
        programLevel.Set(slog.LevelInfo)
    case "WARN":
        programLevel.Set(slog.LevelWarn)
    default:
        http.Error(w, "invalid level: expected DEBUG, INFO, or WARN", http.StatusBadRequest)
        return
    }
    _, _ = w.Write([]byte("Log level updated: " + programLevel.Level().String()))
}

2. Redacting Sensitive Fields with HandlerOptions.ReplaceAttr

Accidentally logging authorization headers, API keys, or tokens violates GDPR, PCI-DSS, and SOC2 compliance. Note that ReplaceAttr receives nested slog.Group names via groups []string, and should also walk any slog.KindGroup attribute values defensively:

redaction_handler.go Scrubbing Top-Level & Grouped Keys 
func RedactAttr(groups []string, a slog.Attr) slog.Attr {
    if a.Value.Kind() == slog.KindGroup {
        sub := a.Value.Group()
        cleaned := make([]slog.Attr, len(sub))
        for i, inner := range sub {
            cleaned[i] = RedactAttr(append(groups, a.Key), inner)
        }
        a.Value = slog.GroupValue(cleaned...)
        return a
    }
    switch strings.ToLower(a.Key) {
    case "authorization", "password", "secret_token", "api_key", "token":
        return slog.String(a.Key, "[REDACTED]")
    }
    return a
}

4. Architectural Knowledge Check (Senior Level)

Question 1 of 2 • Dynamic Log Levels
Why is slog.LevelVar preferred over static log levels in cloud microservices?
A It eliminates all log record allocations during background garbage collector sweeps
B It encrypts sensitive production audit payloads via hardware AES CPU instructions
C It changes verbosity atomically at runtime without restarting Kubernetes pods
D It compresses JSON log lines inline to reduce production storage overhead
A (INCORRECT): LevelVar controls severity threshold gating concurrently, whereas zero-alloc attr passing relies on slog.LogAttrs.
B (INCORRECT): Transport encryption is handled by TLS/log agents rather than slog.LevelVar.
C (CORRECT): slog.LevelVar stores levels atomically, letting operators flip verbosity from INFO to DEBUG during live incidents without redeploying containers.
D (INCORRECT): Log shippers compress telemetry payloads rather than logger level wrappers.
Question 2 of 2 • Production PII Security
How should sensitive customer PII like authorization tokens be protected in production slog output?
A Configure a handler ReplaceAttr hook scrubbing sensitive keys before serialization
B Delegate redaction exclusively to downstream log collectors reading container stdout
C Cast secret strings into raw pointer addresses prior to JSON encoding
D Disable all structured application telemetry across every production Kubernetes cluster
A (CORRECT): Defense-in-depth scrubs secrets at process emission via HandlerOptions.ReplaceAttr (or custom slog.Handler / LogValuer) before bytes reach stdout.
B (INCORRECT): Downstream filters still expose raw tokens in pod stdout buffers and local node logs.
C (INCORRECT): Logging pointer addresses provides unusable debug trails and invites unsafe conversions.
D (INCORRECT): Dropping telemetry blinds incident responders during live outages.
