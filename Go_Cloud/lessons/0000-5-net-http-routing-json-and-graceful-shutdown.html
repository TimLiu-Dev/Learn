0000-5. Modern net/http Routing, JSON & Graceful Shutdown

On Android you call APIs with Retrofit or Ktor Client. Building the backend side in Go 1.22–1.27 rarely requires heavyweight web frameworks: standard net/http now supports method+path patterns, path wildcards, structured timeouts, and zero-downtime shutdowns natively.

📱 Android / Kotlin Bridge: Server-Side Safety vs Client Requests

A mobile client talks to one known server; a cloud HTTP server faces hostile traffic, slow-loris connections, and rolling Kubernetes restarts. Never deploy http.ListenAndServe(":8080", mux) verbatim—always configure explicit http.Server timeouts (ReadHeaderTimeout, WriteTimeout, IdleTimeout) and drain in-flight requests via signal.NotifyContext + srv.Shutdown(ctx).

1. Method Routing & omitzero in Modern Go

Registering mux.HandleFunc("GET /orders/{id}", ...) and mux.HandleFunc("POST /orders", ...) delegates method dispatch and automatic 405 Method Not Allowed responses (including the Allow header) directly to Go's standard library. Inside the handler, read wildcards with r.PathValue("id").

For JSON serialization, Go 1.24 added the omitzero struct tag (for example json:"total_cents,omitzero"), which cleanly omits any field whose value equals its type zero value or whose IsZero() bool method returns true—fixing subtle bugs where omitempty ignored zero structs such as time.Time.

server_timeouts.go (Production HTTP Server Template) 
srv := &http.Server{
    Addr:              ":8080",
    Handler:           mux,
    ReadHeaderTimeout: 5 * time.Second,  // Defends against Slowloris header stalls
    WriteTimeout:      15 * time.Second,
    IdleTimeout:       60 * time.Second,
}
// Shutdown sequence in cmd/server/main.go:
// <-ctx.Done(); srv.Shutdown(shutdownCtx)

✅ Reference Solution (matches labs/m00_05_net_http) 
func NewOrderMux() *http.ServeMux {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /orders/{id}", func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "application/json")
		_ = json.NewEncoder(w).Encode(OrderResponse{
			ID:    r.PathValue("id"),
			Total: 4200,
		})
	})
	mux.HandleFunc("POST /orders", func(w http.ResponseWriter, r *http.Request) {
		var req OrderResponse
		if err := json.NewDecoder(http.MaxBytesReader(w, r.Body, 1<<20)).Decode(&req); err != nil || req.ID == "" {
			http.Error(w, "invalid order payload", http.StatusBadRequest)
			return
		}
		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusCreated)
		_ = json.NewEncoder(w).Encode(req)
	})
	return mux
}

3. Knowledge Verification Quizzes

Quiz 1 of 2 • Method-Scoped Routing
You register only "GET /orders/{id}" and "POST /orders" on a Go 1.22+ http.ServeMux. What happens on DELETE /orders/ord-77?
A It returns 404 Not Found without headers because no wildcard DELETE handler exists.
B It returns 405 Method Not Allowed and populates the Allow response header automatically.
C It invokes the GET handler while leaving r.PathValue("id") completely empty.
D It panics at router initialization because every resource path requires defining all HTTP verbs.
Option A (Incorrect): Because the path /orders/{id} matches another registered pattern, ServeMux returns 405 instead of 404.
Option B (Correct): Go 1.22+ ServeMux distinguishes path mismatch (404) from method mismatch (405 + Allow header) natively.
Option C (Incorrect): Method-prefixed routes only dispatch when the incoming HTTP verb matches.
Option D (Incorrect): You only register the HTTP methods your endpoint supports; panics occur only on conflicting ambiguous patterns.
Quiz 2 of 2 • Production Server Resilience
Why should Kubernetes Go services construct a custom *http.Server instead of calling package-level http.ListenAndServe(":8080", mux)?
A Custom servers set Slowloris header/write/idle timeouts and enable Shutdown(ctx) draining on SIGTERM.
B Package-level ListenAndServe handles only one connection sequentially unless configured with workers.
C Package-level ListenAndServe buffers response JSON bodies indefinitely unless flushed manually via hooks.
D Custom servers unlock HTTP/2 support, which Go disables inside package-level helper signatures completely.
Option A (Correct): Default ListenAndServe leaves timeouts infinite (vulnerable to slow-client fd exhaustion) and lacks a handle for Shutdown.
Option B (Incorrect): Go's net/http spawns a goroutine per accepted connection even via ListenAndServe.
Option C (Incorrect): Response flushing applies to streaming endpoints regardless of whether Server is instantiated directly.
Option D (Incorrect): TLS HTTP/2 is enabled automatically; missing timeouts and graceful drain hooks are the actual risk.
