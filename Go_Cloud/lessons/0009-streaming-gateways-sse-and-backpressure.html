Lesson 0009: LLM & Event Gateways: Server-Sent Events (SSE) & Backpressure

In 2027 cloud architectures, Go microservices frequently serve as high-concurrency API gateways for AI inference, real-time market feeds, and distributed event streams. Serving streaming tokens via Server-Sent Events (SSE) requires Go 1.20+ http.NewResponseController flushing, client disconnect propagation, and TCP backpressure deadlines.

⚙️ Senior Architecture Principle: http.NewResponseController

By default, Go's net/http buffers outbound writes before flushing to the socket, destroying token-by-token latency. Legacy Go code asserted w.(http.Flusher)—which silently breaks when logging or metrics middleware wraps http.ResponseWriter without forwarding Flush(). Modern Go (1.20+) provides rc := http.NewResponseController(w) to unwrap middleware cleanly and manage per-chunk write deadlines.

1. Anatomy of the Server-Sent Events Protocol

SSE is a lightweight unidirectional event protocol over HTTP/1.1, HTTP/2, or HTTP/3 (note: omit hop-by-hop Connection: keep-alive on HTTP/2+, where RFC 9113 forbids connection-specific headers): 

HTTP/2 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
X-Accel-Buffering: no

data: {"token": "The", "index": 0}

data: {"token": " Go", "index": 1}

data: [DONE]

2. Immediate Upstream Cancellation & Write Error Exit

If a client disconnects or stalls past its write deadline, r.Context().Done() closes or fmt.Fprintf returns an error. Always inspect write/flush errors so slow consumers cannot pin server goroutines indefinitely:

sse_gateway_loop.go ResponseController Select Loop 
rc := http.NewResponseController(w)
for {
    select {
    case <-r.Context().Done():
        return // Client aborted: halt upstream work immediately
    case token, ok := <-tokenStream:
        if !ok {
            _, _ = fmt.Fprintf(w, "data: [DONE]\n\n")
            _ = rc.Flush()
            return
        }
        _ = rc.SetWriteDeadline(time.Now().Add(5 * time.Second))
        if _, err := fmt.Fprintf(w, "data: %s\n\n", token); err != nil {
            return
        }
        if err := rc.Flush(); err != nil {
            return
        }
    }
}

3. Hands-On Practice: Building an SSE Token Stream Handler

Implement an HTTP handler that streams tokens as Server-Sent Events:

  • Task 1: Set headers (Content-Type: text/event-stream, Cache-Control: no-cache), construct rc := http.NewResponseController(w), and flush initial headers.
  • Task 2: Stream tokens as data: <token>\n\n (flushing every chunk and aborting on write errors or r.Context().Done()), and emit data: [DONE]\n\n when tokenStream closes.

Canonical Reference Solution

package sse

import (
    "fmt"
    "net/http"
)

func StreamHandler(w http.ResponseWriter, r *http.Request, tokenStream <-chan string) {
    w.Header().Set("Content-Type", "text/event-stream")
    w.Header().Set("Cache-Control", "no-cache")
    w.WriteHeader(http.StatusOK)

    rc := http.NewResponseController(w)
    if err := rc.Flush(); err != nil {
        return
    }

    ctx := r.Context()
    for {
        select {
        case <-ctx.Done():
            return
        case token, ok := <-tokenStream:
            if !ok {
                _, _ = fmt.Fprintf(w, "data: [DONE]\n\n")
                _ = rc.Flush()
                return
            }
            if _, err := fmt.Fprintf(w, "data: %s\n\n", token); err != nil {
                return
            }
            if err := rc.Flush(); err != nil {
                return
            }
        }
    }
}

4. Architectural Knowledge Check (Senior Level)

Question 1 of 2 • Flushing & ResponseController
Why should a Go streaming SSE handler prefer http.NewResponseController(w).Flush() over manual casting?
A The OS kernel drops un-flushed TCP packets silently after ten idle seconds
B It unwraps middleware decorators and flushes chunk buffers immediately per token
C The garbage collector evicts idle response sockets during concurrent mark phases
D It switches runtime compilation statically so streaming payloads skip kernel writes
A (INCORRECT): TCP manages transmission buffers independently and never discards written streams silently due to a 10s rule.
B (CORRECT): Go HTTP buffers responses unless flushed per event, and http.NewResponseController unwraps middleware wrappers cleanly to locate underlying flush support.
C (INCORRECT): Active network connections remain live runtime descriptors never discarded by GC cycles.
D (INCORRECT): Compiler passes never remove kernel socket writes from streaming handlers.
Question 2 of 2 • Client Disconnect Handling
How should an SSE gateway handle client disconnection during an active token stream?
A Continue streaming remaining tokens internally until inference completes cleanly
B Raise a runtime panic to reset server socket pools automatically
C Buffer unsent tokens indefinitely in package slices for future retries
D Watch r.Context().Done() and abort upstream work and writes immediately
A (INCORRECT): Continuing to stream or run LLM inference for an absent caller wastes GPU and CPU capacity.
B (INCORRECT): Panicking inside request handlers causes dropped alerts and unstable worker loops rather than clean shutdowns.
C (INCORRECT): Caching abandoned tokens in global memory causes unbounded OOM heap growth.
D (CORRECT): When clients close connections, Go closes r.Context().Done(); selecting on it alongside write error checks frees backend compute promptly.
