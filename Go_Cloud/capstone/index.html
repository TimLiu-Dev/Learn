4. Staff/Senior Interview Defense Guide

Be prepared to defend these core distributed systems design decisions when interviewers grill you:

❓ Question 1: Why did you choose the Transactional Outbox pattern instead of Two-Phase Commit (2PC) or Sagas?
Defense: Two-Phase Commit introduces blocking distributed locks across services and databases. If any coordinator or participant encounters network partition or GC pauses, locks remain held, causing connection pool exhaustion and cascading system failure. Sagas are appropriate for long-running workflows across multiple microservice domains, but within the financial ledger core, we required immediate local ACID consistency. The Transactional Outbox pattern allows us to write domain state and outbox events within a single local PostgreSQL transaction, then asynchronously stream to Kafka with at-least-once delivery and consumer idempotency keys.
❓ Question 2: How does GOMEMLIMIT prevent Kubernetes OOMKills compared to older versions of Go?
Defense: Historically, Go paced garbage collection based entirely on GOGC (percentage of heap growth). During sudden traffic bursts, memory could double before the GC kicked in, causing the Linux kernel to fire the OOMKiller (SIGKILL / Exit 137). By setting GOMEMLIMIT=460MiB (90% of our 512MiB container limit), the Go runtime initiates aggressive, proactive GC cycles as memory nears the ceiling, eliminating container termination while retaining maximum throughput.
❓ Question 3: Why use integer cents/minor units instead of float64 for monetary balances?
Defense: IEEE 754 floating-point numbers cannot accurately represent base-10 fractions (e.g. 0.1 + 0.2 = 0.30000000000000004). In financial ledgers, cumulative rounding errors result in irreconcilable balance discrepancies and regulatory compliance violations. Storing monetary values as 64-bit signed integers representing minor currency units (cents, satoshis, micro-units) guarantees exact arithmetic, eliminates precision drift, and fits natively into 8-byte CPU registers for atomic operations.
