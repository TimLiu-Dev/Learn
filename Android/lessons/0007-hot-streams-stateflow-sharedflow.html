Hot Streams & State Management: StateFlow vs SharedFlow

Model production UI state with StateFlow and one-off navigation/toast events with SharedFlow.

Recommended Primary Source
Kotlin Docs: StateFlow and SharedFlow
Official Documentation →

Unlike cold flows, Hot Streams emit data regardless of whether any collectors are listening. In Modern Android Architecture, hot streams drive ViewModel state and one-off event delivery.

🌱 Junior Android Dev Mental Model: StateFlow vs SharedFlow
  • StateFlow (State): Holds a single current value (replay = 1), conflates duplicate values (won't re-emit if new == old), and always requires an initial value. Use for: Screen UI State.
  • SharedFlow (Events): Can have replay = 0, emits every single item without conflation. Use for: One-off events like Snackbar messages or Navigation actions.

The Golden Standard: WhileSubscribed(5_000)

When converting a cold repository stream to a StateFlow in a ViewModel using stateIn(), always use SharingStarted.WhileSubscribed(5_000). This stops upstream network/database collection 5 seconds after the app enters the background (saving battery), while surviving brief screen rotations!

2027 Production Standard (Runnable Example)

Click ▶ Run Example to execute this snippet and inspect the simulated runtime output and state transformations:

KOTLIN 2.X HotStreams.kt 
import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

data class CounterUiState(val count: Int = 0)

fun main() = runBlocking {
    val state = MutableStateFlow(CounterUiState(count = 0))
    println("[LOG] Initial StateFlow Value: ${state.value}")

    // Collectors observe state changes
    val job = launch {
        state.collect { current ->
            println("[STATE] Observed State Update -> count = ${current.count}")
        }
    }

    delay(50L)
    state.value = CounterUiState(count = 1)
    delay(50L)
    state.value = CounterUiState(count = 2)
    
    // Conflation test: identical value should NOT re-trigger
    println("[LOG] Updating with identical value count = 2...")
    state.value = CounterUiState(count = 2)

    delay(50L)
    job.cancel()
    println("[SUCCESS] StateFlow managed reactive UI state and prevented duplicate emissions!")
}

🎯 Reference Production Solution 
import kotlinx.coroutines.CoroutineScope
import kotlinx.coroutines.flow.*

fun createHotUiStateFlow(
    source: Flow<List<String>>,
    scope: CoroutineScope
): StateFlow<List<String>> =
    source.stateIn(
        scope = scope,
        started = SharingStarted.WhileSubscribed(5_000),
        initialValue = emptyList()
    )

Why this works: WhileSubscribed(5_000) guarantees that upstream sensors, WebSockets, or database observers pause when the app is backgrounded, while preventing premature restarts during a 200ms screen orientation flip.
