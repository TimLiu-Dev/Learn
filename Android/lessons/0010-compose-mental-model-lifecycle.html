The Compose Mental Model & Lifecycle

Understand declarative UI composition, the 3 phases of Compose (Composition, Layout, Draw), and smart recomposition.

Recommended Primary Source

Official Documentation →

Jetpack Compose is a declarative UI framework. Instead of imperatively finding views and mutating them (e.g. findViewById, textView.setText()), you declare what the UI should look like for a given state.

🌱 Junior Android Dev Mental Model: The 3 Phases of Compose
  1. Composition: Compose determines WHAT to show (executes composable functions and builds the UI tree).
  2. Layout: Compose determines WHERE to place it (measures children and decides (x, y) coordinates).
  3. Draw: Compose renders pixels onto the screen canvas.

Phase skipping optimization: Changing a color only triggers the Draw phase, skipping Composition and Layout entirely!

Interactive Code Practice

Write a pure, stateless @Composable GreetingCard(name: String, onCardClick: () -> Unit). Annotate it with @Composable, pass the parameters, and invoke onCardClick inside your click handler.

🎯 Reference Production Solution 
import androidx.compose.runtime.Composable
import androidx.compose.material3.*

@Composable
fun GreetingCard(
    name: String,
    onCardClick: () -> Unit
) {
    Card(onClick = onCardClick) {
        Text(text = "Hello, $name!")
    }
}

Why this works: Stateless composables are purely driven by inputs and callback lambdas, making them trivial to test, preview in IDE, and reuse across multiple screens.
