The Compose Mental Model & Lifecycle

Understand declarative UI composition, the 3 phases of Compose (Composition, Layout, Draw), and smart recomposition.

Recommended Primary Source

Official Documentation →

Jetpack Compose is not an annotation processor; it is a Kotlin K2 Compiler Plugin paired with a low-allocation runtime engine. When the compiler encounters a @Composable function, it rewrites its signature at the IR level to inject a synthetic $composer: Composer parameter and a $changed: Int bitmask. As your composable executes, it emits group markers ($composer.startRestartGroup(key) / endRestartGroup()) into the Compose Slot Table.

Under the hood, the Slot Table is a flat, contiguous Gap Buffer stored in two primitive/reference arrays in RAM (one <code>IntArray</code> for group metadata—keys, node counts, parent offsets, and slot anchors—and one <code>Array<Any?></code> for remembered values, parameters, and <code>LayoutNode</code> references). Why a gap buffer instead of a linked tree of objects? Because traversing a linear array has massive CPU L1/L2 cache locality and zero object-allocation overhead during recomposition! When structural changes occur (e.g., an <code>if</code> branch toggles), Compose moves the "gap" to the current cursor index in O(1) amortized time and inserts or removes group slots.

While the <code>Composer</code> records changes into a deferred change-list (<code>ChangeList</code>), the <code>Applier<N></code> executes after composition completes to materialize those structural changes onto the actual tree—on Android UI, <code>UiApplier</code> attaches, moves, or removes <code>LayoutNode</code> instances in the layout tree (whereas in Compose HTML or Glance, a different <code>Applier</code> targets DOM nodes or <code>RemoteViews</code>).

🌱 Junior Android Dev Mental Model: The 3 Frame Phases & Phase Skipping

Every Compose frame runs three sequential phases:
1. Composition: Executes @Composable functions, updates the Slot Table, and builds the LayoutNode tree (What to show).
2. Layout: Measures and places each LayoutNode in 2D coordinates (Where to place it).
3. Drawing: Renders draw commands onto a hardware-accelerated RenderNode / Canvas (How it looks).
Key Optimization: If you read a rapidly changing state (like scroll offset or animation progress) inside a lambda modifier—Modifier.offset { IntOffset(0, scrollPx) } or Modifier.graphicsLayer { alpha = animAlpha }—Compose completely skips the Composition phase and invalidates only Layout or Draw!

🔥 Senior Interview Trap: Positional Memoization & Dynamic Loop Corruption in the Gap Buffer

Because the Slot Table identifies each composable call by its call-site source hash + execution index (positional memoization), prepending an item to the front of a <code>for (item in list)</code> loop shifts the execution index of every subsequent item. The Slot Table's gap buffer either has to shift or mismatches remembered state across items! Wrapping dynamic iterations in <code>key(item.id) { ... }</code> emits a movable group marker (<code>startMovableGroup</code>), allowing the Slot Table to relocate existing slots and their <code>remember</code>ed state in place without recreating nodes.

❌ Junior Anti-Pattern: State Read in Composition & Side Effects

@Composable
fun AnimatedHeader(scrollProvider: () -> Int, analytics: Analytics) {
    // BUG 1: Runs on EVERY recomposition (and potentially on background threads)!
    analytics.logScreenView("Header")

    // BUG 2: Reading scroll state directly in Composition forces full
    // Slot Table recomposition + Layout + Draw on every scrolled pixel!
    val offsetDp = (scrollProvider() / 2).dp
    Box(modifier = Modifier.offset(y = offsetDp))
}

✅ 2027 Senior Standard: Lambda Modifier Phase Deferral & Movable Keys

@Composable
fun AnimatedHeader(
    items: List<HeaderChip>,
    scrollProvider: () -> Int
) {
    // Deferred read inside Layout phase: ZERO Composition / Slot Table work!
    Box(modifier = Modifier.offset { IntOffset(x = 0, y = scrollProvider() / 2) }) {
        Row {
            for (chip in items) {
                // Emits startMovableGroup so Slot Table preserves node identity
                key(chip.id) { ChipView(chip) }
            }
        }
    }
}

enum class ComposePhase { COMPOSITION, LAYOUT, DRAW }

data class SlotGroup(val key: Any, val rememberedState: String)

class SimulatedGapBufferSlotTable {
    private val groups = mutableListOf<SlotGroup>()

    fun recordMovableGroup(key: Any, stateInitializer: () -> String): String {
        val existingIdx = groups.indexOfFirst { it.key == key }
        return if (existingIdx >= 0) {
            val retained = groups[existingIdx]
            println("[SLOT TABLE] Reused movable group key='$key' -> retained state='${retained.rememberedState}'")
            retained.rememberedState
        } else {
            val created = SlotGroup(key, stateInitializer())
            groups.add(created)
            println("[SLOT TABLE] Inserted new group at gap for key='$key' -> state='${created.rememberedState}'")
            created.rememberedState
        }
    }
}

fun determineInvalidatedPhases(readsInComposition: Boolean, readsInLayoutLambda: Boolean, readsInGraphicsLayer: Boolean): List<ComposePhase> =
    when {
        readsInComposition -> listOf(ComposePhase.COMPOSITION, ComposePhase.LAYOUT, ComposePhase.DRAW)
        readsInLayoutLambda -> listOf(ComposePhase.LAYOUT, ComposePhase.DRAW)
        readsInGraphicsLayer -> listOf(ComposePhase.DRAW)
        else -> emptyList()
    }

fun main() {
    val slotTable = SimulatedGapBufferSlotTable()
    slotTable.recordMovableGroup("item_101") { "Expanded=true" }
    slotTable.recordMovableGroup("item_102") { "Expanded=false" }
    // Reorder: item_101 still retains its remembered slot state via key!
    slotTable.recordMovableGroup("item_101") { "Expanded=false" }

    println("[PHASES] Modifier.offset(y = state.dp) executes: ${determineInvalidatedPhases(true, false, false)}")
    println("[PHASES] Modifier.offset { IntOffset(0, state) } executes: ${determineInvalidatedPhases(false, true, false)}")
    println("[PHASES] Modifier.graphicsLayer { alpha = state } executes: ${determineInvalidatedPhases(false, false, true)}")
}

🎯 Reference Production Solution 
import androidx.compose.foundation.layout.*
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import androidx.compose.ui.graphics.graphicsLayer
import androidx.compose.ui.unit.IntOffset

data class BannerItem(val id: String, val title: String)

@Composable
fun BannerRow(item: BannerItem) {}

@Composable
fun ParallaxBanner(
    items: List<BannerItem>,
    scrollOffsetProvider: () -> Int,
    alphaProvider: () -> Float
) {
    Column(
        modifier = Modifier
            .offset { IntOffset(0, scrollOffsetProvider()) }
            .graphicsLayer { alpha = alphaProvider() }
    ) {
        for (item in items) {
            key(item.id) {
                BannerRow(item)
            }
        }
    }
}

Why this works: Passing lambda providers (() -> Int and () -> Float) and reading them inside Modifier.offset { } and Modifier.graphicsLayer { } defers state reads to the Layout and Draw phases respectively—skipping Composition and Slot Table traversal entirely—while key(item.id) emits a movable group in the Slot Table.

Quiz 1: Code Analysis & Bug Hunt

Examine the two Modifier chains below. When 'animatedAlpha' updates 120 times per second during a fade-in, how do Snippet A and Snippet B differ in Compose's runtime execution?

// Snippet A:
Box(modifier = Modifier.alpha(animatedAlpha.value))

// Snippet B:
Box(modifier = Modifier.graphicsLayer { alpha = animatedAlpha.value })
Both snippets execute identical Composition, Layout, and Draw phases because Modifier.alpha is an inline graphicsLayer alias.
Snippet B triggers Composition and Layout, whereas Snippet A executes on RenderThread without touching Compose phases.
Snippet B never updates the rendered screen because Snapshot state mutations are ignored inside graphicsLayer lambdas.
Snippet A reads animatedAlpha.value during Composition, triggering all three phases, whereas Snippet B only runs Draw.

Quiz 2: Production Architectural Reasoning

Why does Jetpack Compose store its composition state in a flat Slot Table backed by a Gap Buffer (IntArray + Array<Any?>) rather than a traditional heap-allocated tree of View objects?

Contiguous gap buffers maximize CPU cache locality, avoid per-frame allocations, and enable O(1) cursor edits.
Android Binder IPC requires composable hierarchies inside one primitive IntArray so system_server can render views.
The Compose Applier executes directly on RenderThread hardware shaders, which only read flat primitive IntArrays.
Gap buffers allow @Composable functions to mutate Slot Table groups concurrently across background threads lock-free.
