Modern Type-Safe Networking: Retrofit 3 / Ktor 3 & Kotlinx Serialization

In 2027 Android development, reflection-heavy JSON parsers like Gson—which bypassed Kotlin constructor default values and silently injected <code>null</code> into non-null Kotlin <code>val</code> properties using <code>Unsafe.allocateInstance()</code>, causing delayed <code>NullPointerException</code>s far from the network layer—are strictly legacy. Modern Android stacks standardize on Kotlinx Serialization (<code>kotlinx.serialization.json.Json</code>) paired with either Retrofit 3 (via the official <code>converter-kotlinx-serialization</code> artifact) or Ktor Client 3 (for Kotlin Multiplatform & coroutine-native engines).

When configuring your production <code>Json</code> instance in Hilt, three settings are non-negotiable for forward/backward API compatibility:

  • ignoreUnknownKeys = true: Prevents the app from crashing with <code>SerializationException</code> whenever the backend team adds a new field to a JSON payload!
  • coerceInputValues = true: Safely falls back to a property's Kotlin default value if the server unexpectedly sends <code>null</code> for a non-nullable property with a default, or sends an unknown enum string (giving your app forward compatibility when new server enum variants roll out).
  • explicitNulls = false: Allows omitting missing nullable fields during deserialization without requiring explicit <code>= null</code> defaults on every nullable DTO field.
🌱 Junior Android Dev Mental Model: Never Leak Network DTOs to the UI!

Network DTOs (@Serializable data class AssetTickerDto) reflect how the backend formats JSON—complete with nullable fields, snake_case <code>@SerialName("price_24h_change")</code>, and stringified timestamps. Always map DTOs at the Repository boundary (<code>dto.toDomain()</code>) into clean, non-null Domain Models before exposing them to UseCases or ViewModels!

Senior Interview Trap: Catching <code>CancellationException</code> in Network Wrappers

When wrapping a <code>suspend</code> Retrofit/Ktor call inside <code>runCatching { api.getQuote() }</code> or <code>try { ... } catch (e: Exception)</code>, catching <code>CancellationException</code> swallows structured concurrency cancellation! If <code>viewModelScope</code> cancels the coroutine while the network request is in flight, swallowing <code>CancellationException</code> causes the coroutine to keep executing following steps as a zombie. Always rethrow: if (e is CancellationException) throw e!

✅ 2027 Senior Production Standard: Resilient Json Config + Safe NetworkResult

val productionJson = Json {
    ignoreUnknownKeys = true
    coerceInputValues = true
    explicitNulls = false
}

@Serializable
data class TickerDto(
    @SerialName("symbol") val symbol: String,
    @SerialName("last_price") val lastPrice: Double = 0.0
)

suspend inline fun <T, R> safeApiCall(
    crossinline call: suspend () -> T,
    crossinline transform: (T) -> R
): NetworkResult<R> = try {
    NetworkResult.Success(transform(call()))
} catch (e: CancellationException) {
    throw e // Always rethrow CancellationException!
} catch (e: IOException) {
    NetworkResult.NetworkError(e.message ?: "Offline")
} catch (e: Exception) {
    NetworkResult.ServerError(e.message ?: "Unknown Error")
}

data class RawJsonPayload(val fields: Map<String, Any?>)

data class MarketQuoteDto(
    val symbol: String,
    val priceUsd: Double = 0.0,
    val status: String = "UNKNOWN"
)

data class MarketQuote(val ticker: String, val formattedPrice: String, val isTradable: Boolean)

fun deserializeResilient(
    raw: RawJsonPayload,
    ignoreUnknownKeys: Boolean,
    coerceInputValues: Boolean
): MarketQuoteDto {
    val knownKeys = setOf("symbol", "price_usd", "status")
    val unknown = raw.fields.keys - knownKeys
    if (!ignoreUnknownKeys && unknown.isNotEmpty()) {
        error("SerializationException: Encountered unknown JSON keys: $unknown")
    }
    val symbol = raw.fields["symbol"] as? String ?: error("Missing required field 'symbol'")
    val rawPrice = raw.fields["price_usd"] as? Double
    val price = if (rawPrice == null && coerceInputValues) 0.0 else (rawPrice ?: error("Null price_usd"))
    val rawStatus = raw.fields["status"] as? String
    val validStatuses = setOf("OPEN", "HALTED", "UNKNOWN")
    val status = if ((rawStatus == null || rawStatus !in validStatuses) && coerceInputValues) "UNKNOWN" else (rawStatus ?: "UNKNOWN")
    return MarketQuoteDto(symbol, price, status)
}

fun MarketQuoteDto.toDomain(): MarketQuote = MarketQuote(
    ticker = symbol.uppercase(),
    formattedPrice = "$${"%,.2f".format(priceUsd)}",
    isTradable = status == "OPEN"
)

fun main() {
    val serverPayload = RawJsonPayload(
        mapOf(
            "symbol" to "btc-usd",
            "price_usd" to 94250.50,
            "status" to "POST_MARKET_AUCTION_V2", // New backend enum unknown to older client!
            "experimental_ai_score" to 0.98        // New backend field added after app release!
        )
    )
    val dto = deserializeResilient(serverPayload, ignoreUnknownKeys = true, coerceInputValues = true)
    val domain = dto.toDomain()
    println("[DESERIALIZE] Parsed DTO safely despite unknown keys & new enum -> $dto")
    println("[DOMAIN-MAP] Mapped to clean Domain Model -> $domain")
}

import kotlin.coroutines.cancellation.CancellationException
import kotlinx.serialization.json.Json

val networkJson = Json {
    ignoreUnknownKeys = true
    coerceInputValues = true
}

suspend fun <T> executeSafeCall(block: suspend () -> T): Result<T> {
    return try {
        Result.success(block())
    } catch (e: CancellationException) {
        throw e
    } catch (e: Exception) {
        Result.failure(e)
    }
}

Why this works: Enabling ignoreUnknownKeys and coerceInputValues protects production apps from crashing when backend schemas evolve, while explicitly rethrowing CancellationException preserves Kotlin Coroutines structured concurrency cancellation propagation.

Quiz 1: Code Analysis & Bug Hunt

Why did this production app utilizing Gson crash with a <code>NullPointerException</code> inside <code>OrderSummaryScreen</code> even though <code>OrderDto.currency</code> was declared as a non-null <code>val currency: String = "USD"</code> in Kotlin?

// Parsed using legacy GsonConverterFactory:
data class OrderDto(
    val id: String,
    val currency: String = "USD" // Server JSON returned: {"id": "991", "currency": null}
)

// Later in UI:
Text(text = orderDto.currency.uppercase()) // Crashes with NullPointerException!
Kotlin stdlib uppercase extensions always return null references whenever invoked on three-letter ISO currency strings.
Kotlin 2.x data classes ignore default constructor parameter values whenever compiled for the Android Runtime.
Retrofit converter factories coerce all deserialized String properties to null unless annotated with @JvmField explicitly.
Gson reflection bypasses Kotlin constructors, null-checks, and defaults, whereas Kotlinx Serialization respects them at compile-time.

Quiz 2: Production Architectural Reasoning

What happens in a Kotlin Coroutine if you use <code>runCatching { api.fetchFeed() }</code> inside a <code>suspend</code> function and convert its result to a UI error state without checking for <code>CancellationException</code>?

runCatching catches Throwable including CancellationException, swallowing cancellation signals, breaking structured concurrency, and reporting false errors.
The Kotlin standard library implementation of runCatching automatically detects and rethrows CancellationException to parent scopes.
Wrapping a suspend call inside runCatching automatically shifts coroutine continuation execution onto the Dispatchers.Main thread.
CancellationException inherits from VirtualMachineError and completely bypasses standard Throwable catch blocks inside compiled coroutine state-machines.
