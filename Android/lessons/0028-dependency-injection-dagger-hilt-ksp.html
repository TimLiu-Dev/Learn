Dependency Injection with Dagger Hilt & KSP

Set up lightning-fast dependency injection using Dagger Hilt with Kotlin Symbol Processing (KSP).

Recommended Primary Source
Google Android: Dependency injection with Hilt
Official Documentation →

Dependency Injection (DI) makes applications modular, testable, and maintainable by providing dependencies from the outside rather than having classes construct them internally. In Modern Android, Dagger Hilt backed by KSP (Kotlin Symbol Processing) is the standard.

🌱 Junior Android Dev Mental Model: @Binds vs. @Provides
  • @Binds (Preferred): An abstract function that tells Hilt: "Whenever someone asks for Interface X, give them concrete implementation Y". Zero boilerplate, zero generated factory classes!
  • @Provides: Used when you must write code to create the instance (e.g., third-party libraries like Retrofit or Room databases).

🎯 Reference Production Solution 
import dagger.Binds
import dagger.Module
import dagger.hilt.InstallIn
import dagger.hilt.components.SingletonComponent

interface MarketRepo
class DefaultMarketRepo : MarketRepo

@Module
@InstallIn(SingletonComponent::class)
abstract class RepositoryModule {
    @Binds
    abstract fun bindRepo(impl: DefaultMarketRepo): MarketRepo
}

Why this works: @Binds is more efficient than @Provides because it delegates directly to the implementation's @Inject constructor without generating intermediate factory methods.
