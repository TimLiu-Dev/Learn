Schema-First Mobile APIs: GraphQL (Apollo Kotlin 4) & gRPC / Protobuf

Eliminate REST over-fetching with Apollo Kotlin 4 normalized caching and stream low-latency binary RPCs with gRPC-Kotlin and Wire.

Recommended Primary Source
Apollo GraphQL Docs: Apollo Kotlin 4 & Normalized Caching
Official Documentation →

At scale-up and Big Tech engineering orgs (Airbnb, Block, Netflix, Reddit, Uber), mobile teams frequently move beyond hand-written JSON REST DTOs toward Schema-First Contracts: GraphQL via Apollo Kotlin 4 (KMP-ready) for complex UI-driven object graphs, and gRPC-Kotlin / Square Wire (Protocol Buffers) for ultra-compact, low-latency microservice and real-time streaming pipelines. In Apollo Kotlin 4, the Gradle plugin compiles your schema.graphqls + screen-specific .graphql query/fragment files at build time into 100% null-safe, reflection-free Kotlin models—fetching only the exact fields a Composable needs in a single round trip and eliminating REST N+1 waterfall requests.

Apollo's superpower on Android is its Normalized Cache (MemoryCacheFactory chained to SqlNormalizedCacheFactory): instead of caching raw HTTP responses by URL, Apollo flattens nested graph objects by a unique entity ID (e.g., Asset:BTC via TypePolicyCacheKeyGenerator). When a mutation updates Asset:BTC's watchlist flag on the Detail screen, every active apolloClient.query(...).watch() Flow on the Home and Portfolio screens automatically re-emits the updated state! Conversely, when bandwidth, CPU battery cost, and bidirectional streaming dominate (live order books, ride-share telemetry), Protobuf + gRPC over HTTP/2 encodes strongly typed numbers and enums as compact binary varints (3x–7x smaller than verbose UTF-8 JSON keys) and exposes server/client/bidirectional streams directly as Kotlin Flow<ResponseProto>!

🌱 Junior Android Dev Mental Model: When to Pick REST vs. GraphQL vs. gRPC

REST + kotlinx.serialization: Simple CRUD resources, public third-party APIs, standard HTTP CDN caching.
GraphQL (Apollo Kotlin 4): Rich, deeply nested product screens (feeds, profiles, e-commerce) where mobile needs exact field selection and automatic cross-screen entity cache normalization.
gRPC / Protobuf (grpc-kotlin / Square Wire): High-frequency binary telemetry, strict forward/backward numbered field evolution, and multiplexed HTTP/2 bidirectional coroutine streams.

⚠️ Senior Interview Trap: Missing GraphQL Cache Keys & Unbounded gRPC Calls Without Deadlines

Trap 1 (GraphQL): Enabling Apollo's Normalized Cache without configuring stable entity IDs (@typePolicy(keyFields = "id") or requesting id in your selection set)! Without a deterministic cache key, Apollo stores objects under their query path—meaning mutations on a detail screen fail to update list screens, and duplicate records bloat SQLite.
Trap 2 (gRPC & Protobuf): Reusing a deleted field tag number in a .proto schema without marking reserved 4; (corrupting older app versions on the wire!), or invoking a gRPC stub on mobile without a per-call deadline (stub.withDeadlineAfter(5, TimeUnit.SECONDS))—which can leave coroutines suspended indefinitely over half-open cellular sockets!

❌ Junior Anti-Pattern: Missing Entity ID in GraphQL & Reused Proto Tag

# 1. GraphQL query omits 'id' -> Normalized cache cannot deduplicate Asset!
query MarketRow {
  assets { symbol priceMicros isWatchlisted }
}

// 2. Protobuf schema reuses field number 3 for a different type -> Wire corruption!
message QuoteProto {
  string symbol = 1;
  // deleted: string old_note = 3;
  int64 timestamp_ms = 3; // CATASTROPHIC wire break for older clients!
}

✅ 2027 Senior Standard: Normalized Fragment + Reserved Protobuf Evolution

# 1. Colocated UI fragment always selects 'id' for Apollo Normalized Cache
fragment AssetCardFields on Asset {
  id
  symbol
  priceMicros
  isWatchlisted
}

// 2. Safe Protobuf schema evolution + bounded gRPC deadline in Kotlin
message QuoteProto {
  reserved 3;
  reserved "old_note";
  string symbol = 1;
  int64 price_micros = 2;
  int64 timestamp_ms = 4;
}
// Kotlin call: quoteStub.withDeadlineAfter(5, SECONDS).streamQuotes(req)

data class NormalizedRecord(val cacheKey: String, val fields: Map<String, Any>)

class SimulatedApolloNormalizedCache {
    private val store = mutableMapOf<String, NormalizedRecord>()

    fun writeEntity(typeName: String, id: String, fields: Map<String, Any>): String {
        val key = "$typeName:$id"
        val merged = (store[key]?.fields.orEmpty()) + fields
        store[key] = NormalizedRecord(key, merged)
        return key
    }

    fun readField(typeName: String, id: String, field: String): Any? =
        store["$typeName:$id"]?.fields?.get(field)
}

fun main() {
    val cache = SimulatedApolloNormalizedCache()
    cache.writeEntity("Asset", "BTC", mapOf("symbol" to "BTC", "priceMicros" to 94_200_000_000L, "isStarred" to false))
    // Detail screen mutation updates ONLY isStarred on Asset:BTC
    val updatedKey = cache.writeEntity("Asset", "BTC", mapOf("isStarred" to true))
    println("[APOLLO-CACHE] Normalized write '$updatedKey' -> HomeFeed & Watchlist Flows auto-updated! (isStarred=${cache.readField("Asset", "BTC", "isStarred")})")

    val jsonBytes = "{\"symbol\":\"BTC\",\"priceMicros\":94200000000,\"timestampMs\":1741000000000}".encodeToByteArray().size
    val protoSimBytes = 19 // 5-byte string tag + two varint64 tags
    val savedPct = ((jsonBytes - protoSimBytes) * 100) / jsonBytes
    println("[PROTO-WIRE] JSON payload=$jsonBytes bytes vs Protobuf varint frame=$protoSimBytes bytes (Saved $savedPct% cellular bandwidth)")
    println("[GRPC-CALL]  Deadline=5000ms configured -> Stream active")
}

First verify deadlineMs in 100L..30_000L; if outside that range, return Result.failure(IllegalArgumentException("INVALID_DEADLINE")). fun buildNormalizedCacheKey(
    typeName: String,
    fields: Map<String, String>,
    deadlineMs: Long
): Result<String> {
    if (deadlineMs !in 100L..30_000L) {
        return Result.failure(IllegalArgumentException("INVALID_DEADLINE"))
    }
    val id = fields["id"]?.takeIf { it.isNotBlank() }
        ?: return Result.failure(IllegalArgumentException("MISSING_ENTITY_ID"))
    return Result.success("$typeName:$id")
}

Why this works: Bounding RPC deadlines prevents zombie hung coroutines on flaky cellular transitions, while enforcing deterministic TypeName:id keys lets Apollo's Normalized Cache propagate mutations automatically across every observing screen.

Quiz 1: Code Analysis & Bug Hunt

A backend teammate deletes field 4 (string legacy_tag = 4;) from a shared Protobuf message and adds bool is_verified = 4; reusing tag number 4. What happens to existing Android users who have not updated their app yet?

// Shared market.proto
message AssetSummary {
  string id = 1;
  // Removed: string legacy_tag = 4;
  bool is_verified = 4; // Reused field number 4!
}
Protobuf sends JSON field names over the wire, so older Android clients ignore renamed boolean properties.
Protobuf binary framing keys fields by tag number, causing wire-type decoding failures; always mark deleted reserved.
Google Play Services automatically patches compiled Kotlin Protobuf classes over the air without requiring store updates.
Square Wire and grpc-kotlin automatically renumber all Protobuf tags alphabetically during every single Gradle KSP compilation.
