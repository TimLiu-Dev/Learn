Unidirectional Data Flow (UDF), MVI & Atomic State Reducers

At the heart of every scalable 2027 Android architecture lies Unidirectional Data Flow (UDF): State flows down from the ViewModel to the Composable UI as a single immutable stream (StateFlow<UiState>), and Events/Intents flow up from the UI to the ViewModel (onEvent(UiIntent)). Model-View-Intent (MVI) formalizes this loop with three strict contracts: an immutable UiState representing everything on screen, a sealed UiIntent representing user actions, and a stream of one-off UiEffect side effects (navigation, snackbars, haptic feedback) delivered via a buffered Channel<UiEffect>(Channel.BUFFERED) exposed as .receiveAsFlow().

Why a single StateFlow<UiState> instead of five separate StateFlow properties (isLoading, error, items, searchQuery, isRefreshing)? When five flows update asynchronously across coroutines, the UI can briefly observe impossible intermediate states (e.g., isLoading = true AND error != null AND items.isNotEmpty() simultaneously), causing visual flicker. By consolidating screen state or updating a MutableStateFlow<UiState> exclusively via atomic _uiState.update { current -> ... } CAS (Compare-And-Set) reducers, every state transition is deterministic, thread-safe, and trivially unit-testable.

🌱 Junior Android Dev Mental Model: State vs One-Off Effects

Ask yourself: "If the user rotates the screen 5 seconds later, should this happen again?" If YES (showing a dialog, displaying an inline validation error, rendering a list), it belongs in UiState. If NO (triggering haptic vibration, navigating to another screen, or firing a transient Toast/Snackbar that doesn't require state acknowledgment), send it through a Channel(Channel.BUFFERED) or represent it in UiState with a unique eventId and an explicit onEffectConsumed(id) reducer!

Senior Interview Trap: SharedFlow(replay = 0) Dropping Navigation Events

Many blog posts recommend MutableSharedFlow<UiEffect>(replay = 0) for one-off navigation or snackbar effects. In a senior interview, point out the critical bug: if a background coroutine emits an effect into a SharedFlow(replay = 0) while the Activity is briefly STOPPED (e.g., during a permission prompt, multi-window resize, or screen lock), repeatOnLifecycle(STARTED) has no active collector and the event is permanently dropped and lost! Using Channel(Channel.BUFFERED).receiveAsFlow() guarantees the event stays buffered until the UI lifecycle returns to STARTED and collects it to exactly one observer.

❌ Junior Anti-Pattern: Non-Atomic .value = Race Condition & SharedFlow Drop

class BadOrderViewModel : ViewModel() {
    val state = MutableStateFlow(OrderUiState())
    // BUG 1: SharedFlow(replay=0) drops events emitted while UI is STOPPED!
    val effects = MutableSharedFlow<OrderEffect>(replay = 0)

    fun onQuantityChanged(qty: Int) {
        // BUG 2: Non-atomic read-modify-write! Concurrent coroutines overwrite each other!
        state.value = state.value.copy(quantity = qty)
    }
}

✅ 2027 Senior Production Standard: CAS .update {} Reducer + Buffered Channel

data class OrderUiState(val symbol: String = "BTC", val quantity: Int = 1, val isSubmitting: Boolean = false)
sealed interface OrderIntent {
    data class ChangeQuantity(val qty: Int) : OrderIntent
    data object SubmitOrder : OrderIntent
}
sealed interface OrderEffect {
    data class NavigateToReceipt(val orderId: String) : OrderEffect
}

class OrderViewModel : ViewModel() {
    private val _uiState = MutableStateFlow(OrderUiState())
    val uiState: StateFlow<OrderUiState> = _uiState.asStateFlow()

    private val _effects = Channel<OrderEffect>(Channel.BUFFERED)
    val effects: Flow<OrderEffect> = _effects.receiveAsFlow()

    fun onIntent(intent: OrderIntent) {
        when (intent) {
            is OrderIntent.ChangeQuantity -> {
                // Atomic CAS loop: safe under concurrent coroutine updates!
                _uiState.update { it.copy(quantity = intent.qty.coerceAtLeast(1)) }
            }
            OrderIntent.SubmitOrder -> submit()
        }
    }
}

data class TradeUiState(
    val symbol: String = "BTC",
    val quantity: Int = 1,
    val unitPrice: Double = 94200.0,
    val isSubmitting: Boolean = false
) {
    val totalNotional: Double get() = quantity * unitPrice
}

sealed interface TradeIntent {
    data class SetQuantity(val qty: Int) : TradeIntent
    data object Submit : TradeIntent
    data class OrderConfirmed(val orderId: String) : TradeIntent
}

fun reduce(current: TradeUiState, intent: TradeIntent): Pair<TradeUiState, String?> = when (intent) {
    is TradeIntent.SetQuantity -> current.copy(quantity = intent.qty.coerceIn(1, 100)) to null
    TradeIntent.Submit -> current.copy(isSubmitting = true) to null
    is TradeIntent.OrderConfirmed -> current.copy(isSubmitting = false) to "EFFECT:NavigateToReceipt(${intent.orderId})"
}

fun main() {
    var state = TradeUiState()
    val intents = listOf(
        TradeIntent.SetQuantity(3),
        TradeIntent.Submit,
        TradeIntent.OrderConfirmed("ORD-2027-9941")
    )
    for (intent in intents) {
        val (nextState, effect) = reduce(state, intent)
        state = nextState
        println("[MVI-REDUCE] Intent=${intent::class.simpleName} -> State(qty=${state.quantity}, total=$${state.totalNotional.toInt()}, submitting=${state.isSubmitting})")
        if (effect != null) println("  -> [CHANNEL-EFFECT] Dispatched one-off effect: $effect")
    }
}

import kotlinx.coroutines.channels.Channel
import kotlinx.coroutines.flow.Flow
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.asStateFlow
import kotlinx.coroutines.flow.receiveAsFlow
import kotlinx.coroutines.flow.update

data class FilterUiState(val query: String = "", val onlyFavorites: Boolean = false)
sealed interface FilterEffect { data object ScrollToTop : FilterEffect }

class FilterStore {
    private val _uiState = MutableStateFlow(FilterUiState())
    val uiState: StateFlow<FilterUiState> = _uiState.asStateFlow()

    private val _effects = Channel<FilterEffect>(Channel.BUFFERED)
    val effects: Flow<FilterEffect> = _effects.receiveAsFlow()

    fun onQueryChanged(newQuery: String) {
        _uiState.update { current ->
            current.copy(query = newQuery)
        }
    }
}

Why this works: _uiState.asStateFlow() prevents external callers from casting back to MutableStateFlow, Channel(Channel.BUFFERED).receiveAsFlow() ensures one-off effects are never dropped when the UI is briefly stopped, and _uiState.update { ... } executes a lock-free compare-and-set loop to prevent lost updates.

Quiz 1: Code Analysis & Bug Hunt

Examine this ViewModel that runs two concurrent coroutines on Dispatchers.Default. Why does either balance or positions intermittently disappear after refreshPortfolio() completes?

fun refreshPortfolio() {
    viewModelScope.launch(Dispatchers.Default) {
        val bal = api.fetchBalance()
        _uiState.value = _uiState.value.copy(balance = bal, isLoadingBalance = false)
    }
    viewModelScope.launch(Dispatchers.Default) {
        val pos = api.fetchPositions()
        _uiState.value = _uiState.value.copy(positions = pos, isLoadingPositions = false)
    }
}
MutableStateFlow cannot be safely mutated from Dispatchers.Default and throws IllegalStateException unless updated on Dispatchers.Main.immediate directly.
Direct value assignment performs non-atomic read-modify-write snapshots; calling _uiState.update applies changes atomically via compare-and-set loops.
Compiler-generated data class copy methods mutate existing structural properties directly instead of allocating immutable instances.
StateFlow conflation automatically drops all concurrent emissions whenever multiple state properties change within one millisecond.

Quiz 2: Production Architectural Reasoning

Why is Channel<UiEffect>(Channel.BUFFERED).receiveAsFlow() preferred over MutableSharedFlow<UiEffect>(replay = 0) for one-off navigation triggers in MVI?

MutableSharedFlow is officially deprecated inside kotlinx.coroutines whenever delivering asynchronous user interface navigation events on Android.
Buffered coroutine channels automatically serialize pending navigation payloads into persistent SQLite storage across process death.
Zero-replay SharedFlow permanently drops effects emitted during rotation, whereas buffered Channel retains events until STARTED.
Channel receiveAsFlow dispatches emissions directly on the RenderThread hardware queue for faster Compose navigation transitions.
