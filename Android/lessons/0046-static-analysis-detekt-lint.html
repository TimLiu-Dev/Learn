Static Code Analysis & Code Health: Detekt & Lint

Enforce strict Kotlin code health, detect architectural leaks, and enforce Compose rules with Detekt and Android Lint.

Recommended Primary Source
Detekt: Static code analysis for Kotlin
Official Documentation →

Senior engineers never waste human code review bandwidth arguing over indentation, wildcard imports, or whether a junior developer accidentally used GlobalScope.launch or hardcoded an unthemed Color(0xFF000000) inside a feature screen. In 2027, automated static analysis acts as an uncompromising, zero-ego gatekeeper on every Pull Request.

Under the Hood: The 3-Pillar Static Analysis Stack

  • Ktlint / Spotless: Enforces deterministic formatting and official Kotlin coding conventions at the token/AST level, with an auto-fix task (./gradlew spotlessApply).
  • Detekt (with Type Resolution & Compose Rules): Parses Kotlin source files into the Kotlin Compiler PSI / FIR syntax tree to compute cyclomatic complexity, cognitive complexity, coroutine anti-patterns (GlobalCoroutineUsage, SuspendFunWithFlowReturnType), and Compose rules (via io.nlopez.compose.rules:detekt—catching missing Modifier parameters, unstable collections, or state reads without remember).
  • Android Lint (UAST + XML + Bytecode): Google's multi-language analyzer built on JetBrains' Universal Abstract Syntax Tree (UAST). Unlike Detekt, Android Lint inspects Kotlin, Java, AndroidManifest.xml, vector drawables, and SDK API levels (NewApi) simultaneously, and ships custom rules directly inside library AARs via lintPublish!
🌱 Junior Android Dev Mental Model: PSI/UAST AST Visitors

Static analysis doesn't just run regex on text files—it walks the compiler's Abstract Syntax Tree (AST)! When you write a custom Android Lint Detector for your :core:designsystem module, you can detect whenever a developer calls androidx.compose.material3.Button instead of your company's AetherButton and offer a one-click Android Studio QuickFix!

✅ 2027 Senior Production Standard: Custom Lint Detector + Clean API

class DesignSystemComponentDetector : Detector(), SourceCodeScanner {
    override fun getApplicableMethodNames() = listOf("Button", "TextField")

    override fun visitMethodCall(context: JavaContext, node: UCallExpression, method: PsiMethod) {
        if (context.evaluator.isMemberInPackage(method, "androidx.compose.material3")) {
            context.report(
                issue = ISSUE_RAW_MATERIAL_COMPONENT,
                scope = node,
                location = context.getLocation(node),
                message = "Use AetherButton / AetherTextField from :core:designsystem instead."
            )
        }
    }
}

⚠️ Senior Interview Trap: Detekt Without Type Resolution & Baseline Files

Running standard ./gradlew detekt runs without classpath type resolution, meaning Detekt only sees raw syntax tokens and cannot resolve whether an imported type is a StateFlow or a custom class—silently skipping over 35% of its advanced coroutine and potential-bug rules! Always run detektMain (which binds the module's compile classpath for full FIR/PSI type resolution). When introducing Detekt or Lint to a legacy codebase with 1,000 existing warnings, generate a detekt-baseline.xml / lint-baseline.xml so legacy tech debt is frozen while 100% of new code in PRs is strictly enforced with maxIssues: 0.

data class AstCallNode(
    val file: String,
    val line: Int,
    val calleePackage: String,
    val methodName: String,
    val hasModifierParam: Boolean = true
)

data class LintIncident(val ruleId: String, val severity: String, val location: String, val message: String)

class AetherStaticAnalyzer {
    private val bannedMaterialApis = mapOf(
        "Button" to "AetherButton",
        "TextField" to "AetherTextField",
        "TopAppBar" to "AetherTopBar"
    )

    fun scanAst(nodes: List<AstCallNode>): List<LintIncident> {
        val incidents = mutableListOf<LintIncident>()
        for (node in nodes) {
            if (node.calleePackage == "androidx.compose.material3" && node.methodName in bannedMaterialApis) {
                val replacement = bannedMaterialApis.getValue(node.methodName)
                incidents += LintIncident(
                    ruleId = "AetherDesignSystemDetector",
                    severity = "ERROR",
                    location = "${node.file}:${node.line}",
                    message = "Disallowed Material3 ${node.methodName}; use $replacement from :core:designsystem."
                )
            }
            if (node.calleePackage == "kotlinx.coroutines" && node.methodName == "GlobalScope.launch") {
                incidents += LintIncident(
                    ruleId = "GlobalCoroutineUsage",
                    severity = "ERROR",
                    location = "${node.file}:${node.line}",
                    message = "Avoid GlobalScope.launch; inject an application or lifecycle CoroutineScope."
                )
            }
        }
        return incidents
    }
}

fun main() {
    val astNodes = listOf(
        AstCallNode("MarketScreen.kt", 42, "androidx.compose.material3", "Button"),
        AstCallNode("MarketScreen.kt", 58, "com.aether.core.designsystem", "AetherButton"),
        AstCallNode("PriceSyncManager.kt", 19, "kotlinx.coroutines", "GlobalScope.launch")
    )
    val report = AetherStaticAnalyzer().scanAst(astNodes)
    println("[STATIC-ANALYSIS] Scanned ${astNodes.size} AST call expressions. Found ${report.size} errors:")
    report.forEach { inc ->
        println("  [${inc.severity}] ${inc.ruleId} at ${inc.location} -> ${inc.message}")
    }
}

data class ParamAst(val name: String, val type: String)
data class ComposableFunctionAst(
    val name: String,
    val returnsUnit: Boolean,
    val parameters: List<ParamAst>
)

class ComposeArchRuleChecker {
    fun inspectFunction(fn: ComposableFunctionAst): List<String> {
        val issues = mutableListOf<String>()
        if (fn.returnsUnit && fn.parameters.none { it.type == "Modifier" }) {
            issues += "MissingModifierParameter"
        }
        if (fn.parameters.any { it.type.startsWith("MutableState") || it.type.startsWith("ArrayList") }) {
            issues += "UnstableParameterType"
        }
        return issues
    }
}

Why this works: Public UI-emitting Composables must accept a default Modifier parameter for layout reuse and avoid MutableState or mutable collection parameters that break Compose skippability.

Quiz 1: Code Analysis & Bug Hunt

Why does Detekt flag suspend fun observePortfolio(): Flow<Portfolio> with the SuspendFunWithFlowReturnType rule?

interface PortfolioRepository {
    // Flagged by Detekt: SuspendFunWithFlowReturnType
    suspend fun observePortfolio(): Flow<Portfolio>
}
Returning cold Flow instances from suspend functions permanently leaks coroutine references inside the Continuation state machine.
Room database annotation processors crash during compilation whenever @Dao interfaces combine suspend methods with Flow queries.
Kotlin 2.x compilers strictly forbid combining the suspend modifier with generic return types inside interface declarations.
Cold Flows are already lazy and asynchronous; adding suspend is redundant and blocks property-level stateIn initialization.
