In Lesson 0051, we implement the two foundational modules that every feature in Aether depends upon: <code>:core:model</code> (pure Kotlin domain models optimized for Jetpack Compose stability) and <code>:core:designsystem</code> (Material 3 financial design tokens, semantic gain/loss colors, typography, and reusable components).

1. <code>:core:model</code>: Pure JVM Domain Contracts & Compose Stability

Because <code>:core:model</code> applies our <code>aether.jvm.library</code> convention plugin (pure <code>org.jetbrains.kotlin.jvm</code>), it compiles in under 400ms. However, <code>:feature:*</code> modules pass <code>:core:model</code> classes directly into <code>@Composable</code> functions! To guarantee 100% <strong>skippable Composables</strong> without polluting <code>:core:model</code> with the heavy Compose UI runtime, we either enable the <strong>Compose Stability Configuration File</strong> (<code>stability_config.conf</code> matching <code>com.aether.core.model.*</code>) in our <code>aether.android.library.compose</code> convention plugin or depend on the tiny annotations-only artifact <code>androidx.compose.runtime:runtime-annotation</code> and use <code>kotlinx.collections.immutable.ImmutableList</code> for collection properties.

2. <code>:core:designsystem</code>: Semantic Financial Tokens via <code>CompositionLocal</code>

Standard Material 3 <code>ColorScheme</code> provides <code>primary</code>, <code>secondary</code>, <code>surface</code>, and <code>error</code>, but a financial telemetry app like Aether requires semantic <strong>Bullish Gain (Emerald <code>#10B981</code>)</strong>, <strong>Bearish Loss (Crimson <code>#EF4444</code>)</strong>, and <strong>Neutral/Stale Quote</strong> tokens that adapt between Dark OLED Mode and Light Mode. We extend Material 3 cleanly using an <code>@Immutable data class AetherFinanceColors</code> provided via <code>staticCompositionLocalOf</code> inside <code>AetherTheme</code> and exposed via <code>AetherTheme.financeColors.bullish</code>!

🌱 Junior Android Dev Mental Model: <code>staticCompositionLocalOf</code> vs. <code>compositionLocalOf</code>

Use <code>staticCompositionLocalOf</code> when the provided value (like <code>AetherFinanceColors</code> or <code>AetherTypography</code>) rarely changes—Compose skips tracking individual reads in the slot table, making every <code>AetherTheme.financeColors</code> lookup zero-overhead! If the theme does toggle, the entire <code>CompositionLocalProvider</code> subtree recomposes, which is expected when switching Dark/Light mode.

⚠️ Senior Interview Trap: Tabular Figures (<code>fontFeatureSettings = "tnum"</code>) for Live Tickers

When a live WebSocket price ticker updates 10 times per second (e.g., <code>$94,111.11</code> → <code>$94,888.88</code>), proportional fonts cause the entire price label and adjacent UI elements to jitter horizontally because the glyph <code>'1'</code> is narrower than <code>'8'</code>! In <code>:core:designsystem</code>'s <code>AetherTypography</code>, all numeric ticker styles set <strong><code>fontFeatureSettings = "tnum"</code> (Tabular Numbers)</strong> so every digit occupies an identical monospaced advance width.

data class AssetQuote(
    val symbol: String,
    val name: String,
    val priceUsd: Double,
    val changePercent24h: Double,
    val sparklinePoints: List<Double>
)

data class AetherFinanceColors(
    val bullishHex: String,
    val bearishHex: String,
    val neutralHex: String
)

object AetherThemeTokens {
    val DarkFinanceColors = AetherFinanceColors(
        bullishHex = "#34D399", // High-contrast OLED Emerald
        bearishHex = "#F87171", // High-contrast OLED Coral Red
        neutralHex = "#9CA3AF"
    )
    const val TICKER_FONT_FEATURE = "tnum" // Tabular monospaced numerals

    fun resolveDeltaToken(quote: AssetQuote, colors: AetherFinanceColors = DarkFinanceColors): Pair<String, String> {
        val sign = if (quote.changePercent24h > 0) "+" else ""
        val color = when {
            quote.changePercent24h > 0.0 -> colors.bullishHex
            quote.changePercent24h < 0.0 -> colors.bearishHex
            else -> colors.neutralHex
        }
        return "$sign${"%.2f".format(quote.changePercent24h)}%" to color
    }
}

fun main() {
    val quotes = listOf(
        AssetQuote("BTC", "Bitcoin", 94250.50, +4.38, listOf(90100.0, 92400.0, 94250.5)),
        AssetQuote("ETH", "Ethereum", 3120.75, -1.65, listOf(3190.0, 3150.0, 3120.75)),
        AssetQuote("USDC", "USD Coin", 1.00, 0.00, listOf(1.0, 1.0, 1.0))
    )

    println("[DESIGN-SYSTEM] Active Theme: DarkFinanceColors (fontFeatureSettings='${AetherThemeTokens.TICKER_FONT_FEATURE}')")
    for (q in quotes) {
        val (formattedDelta, semanticHex) = AetherThemeTokens.resolveDeltaToken(q)
        println("  ${q.symbol.padEnd(5)} | $${"%10.2f".format(q.priceUsd)} | delta=${formattedDelta.padStart(7)} | token=$semanticHex")
    }
}

data class PortfolioHolding(
    val symbol: String,
    val quantity: Double,
    val averageBuyPriceUsd: Double,
    val currentPriceUsd: Double
) {
    val marketValueUsd: Double
        get() = quantity * currentPriceUsd

    val unrealizedPnlUsd: Double
        get() = (currentPriceUsd - averageBuyPriceUsd) * quantity
}

fun selectPnlColorHex(
    pnlUsd: Double,
    bullishHex: String,
    bearishHex: String
): String {
    return if (pnlUsd >= 0.0) bullishHex else bearishHex
}

Why this works: Pure computed domain properties on PortfolioHolding keep business math testable in :core:model without JVM-external dependencies, while selectPnlColorHex maps domain state cleanly to semantic design tokens.

Quiz 1: Code Analysis & Bug Hunt

Examine this <code>:core:model</code> class consumed by <code>:feature:market</code> Composables. Without a Compose Stability Configuration file or <code>ImmutableList</code>, why does the Compose compiler mark <code>AssetQuote</code> as <strong>UNSTABLE</strong>?

// Inside :core:model (Pure JVM module)
data class AssetQuote(
    val symbol: String,
    val priceUsd: Double,
    val sparklinePoints: List<Double> // Standard kotlin.collections.List
)
Kotlin Double is a 64-bit floating-point primitive that the Compose compiler treats as unstable regarding Double.NaN.
The List interface can wrap mutable ArrayLists, so without ImmutableList or stability configs, Compose infers instability.
External Kotlin data classes declaring more than two constructor properties are never inferred stable across modules.
Domain classes ending with the Quote identifier suffix are automatically excluded from compile-time stability inference passes.

Quiz 2: Production Architectural Reasoning

Why should <code>:core:designsystem</code> expose semantic component wrappers like <code>AetherTopAppBar</code>, <code>AetherCard</code>, and <code>AetherAsyncImage</code> rather than having every <code>:feature:*</code> module import Material 3 and Coil directly?

Jetpack Compose throws a runtime IllegalStateException whenever two separate Gradle feature modules import androidx.compose.material3 directly.
Wrapping Material 3 components inside custom composable functions automatically disables R8 obfuscation across feature modules.
Centralizing UI wrappers in :core:designsystem enforces visual consistency, isolates library migrations, and enables mockable Previews.
Material 3 components cannot resolve CompositionLocal styling tokens unless wrapped inside an isolated Gradle subproject.
