Jetpack Navigation Compose 2.8+ Type-Safe Routes

Eliminate string route parsing bugs with Kotlin Serializable route objects and type-safe argument extraction.

Recommended Primary Source
Google Android: Type safety in Navigation Compose
Official Documentation →

In legacy Navigation Compose, destinations were defined using string URLs (e.g. "profile/{userId}?ref={ref}"). This caused frequent runtime crashes from typoed route strings, URL encoding errors, and fragile argument parsing. Navigation Compose 2.8+ completely replaced string routes with Kotlin @Serializable objects and data classes.

🌱 Junior Android Dev Mental Model: Strongly-Typed Routes

Every destination is a typed contract:

  • Screens with no arguments are @Serializable data object HomeRoute
  • Screens with arguments are @Serializable data class DetailRoute(val id: String)
You navigate by passing the object instance: navController.navigate(DetailRoute(id = "42")). The compiler guarantees arguments cannot be forgotten!

import kotlinx.serialization.Serializable

@Serializable
data class MarketDetailRoute(
    val symbol: String,
    val initialPrice: Double
)

Why this works: @Serializable routes turn navigation arguments into compile-time contracts, allowing the compiler to verify destination arguments across modules.
