Compose Side-Effects: LaunchedEffect & Lifecycle

Master LaunchedEffect, rememberCoroutineScope, DisposableEffect, and rememberUpdatedState.

Recommended Primary Source
Google Android: Side-effects in Compose
Official Documentation →

A side-effect is any change to the state of the app that happens outside the scope of a composable function (e.g. showing a Snackbar, subscribing to a sensor, starting a timer). Because composables can execute repeatedly or abort mid-execution, running non-composable code directly inside a composable is dangerous.

🌱 Junior Android Dev Mental Model: Which Effect When?
  • LaunchedEffect(key): Runs a suspend coroutine when entering composition or when key changes. Automatically cancelled when exiting!
  • rememberCoroutineScope(): Obtains a scope to launch a coroutine in response to a user interaction (like a button tap).
  • DisposableEffect(key): For non-coroutine cleanup (like registering a broadcast receiver or listener). Must call onDispose { ... }.
  • rememberUpdatedState(): Captures the latest value of a lambda in a long-running effect without restarting the effect.

🎯 Reference Production Solution 
import androidx.compose.runtime.*

@Composable
fun AutoFetch(userId: String, onFetch: suspend (String) -> Unit) {
    LaunchedEffect(userId) {
        onFetch(userId)
    }
}

Why this works: Keying LaunchedEffect to userId ensures that the coroutine is cancelled and relaunched whenever the userId parameter changes, avoiding stale data fetches.

Quiz 1: Code Analysis & Bug Hunt

What is the key difference between LaunchedEffect and rememberCoroutineScope?

LaunchedEffect launches coroutines bound to composition lifecycle; rememberCoroutineScope is for user callbacks like button clicks
rememberCoroutineScope can only run on physical Android devices, not emulators
LaunchedEffect never cancels its coroutines even if the composable leaves the screen
rememberCoroutineScope causes the Android operating system to reboot into recovery mode
