Rich Media Engineering: Jetpack Media3 (ExoPlayer) & CameraX Pipelines

Architect TikTok-grade video feeds with ExoPlayer instance pooling, CacheDataSource pre-warming, MediaSessionService, and CameraX UseCases.

Recommended Primary Source
Android Developers: Jetpack Media3 & CameraX Architecture
Official Documentation →

Rich media—short-form vertical video feeds (TikTok/Reels), Picture-in-Picture (PiP) livestreams, background audio, and real-time camera capture—is where naive Android architectures crash hardest. Android devices have a strict hardware limit on concurrent MediaCodec hardware decoder instances (often 4 to 8 simultaneous 1080p/4K decoders across the entire SoC). If a developer creates a new ExoPlayer.Builder(context).build() inside every VerticalPager or LazyColumn item, scrolling past 6 videos exhausts hardware codecs and crashes with MediaCodecRenderer$DecoderInitializationException! In Jetpack Media3 (androidx.media3), a Senior Android Engineer maintains a Single Active ExoPlayer (or a strictly bounded 2-instance Ping-Pong Pool) scoped to the screen controller/ViewModel, dynamically attaching its output Surface (PlayerSurface in androidx.media3:media3-ui-compose) only to the currently settled page (pagerState.settledPage).

To achieve instant 0ms time-to-first-frame on swipe, you wire ExoPlayer with a CacheDataSource.Factory backed by a singleton SimpleCache (LeastRecentlyUsedCacheEvictor(200 * 1024 * 1024)) and run a background CacheWriter (or DefaultPreloadManager in Media3) that pre-fetches the first 512 KB–1 MB of segment bytes for settledPage + 1 while the user watches settledPage. For background audio/video playback, Media3 unifies legacy MediaBrowserServiceCompat into MediaSessionService, automatically syncing lock-screen media controls, Bluetooth headset buttons, and notification transport controls with your Player. On the capture side, Jetpack CameraX (ProcessCameraProvider) eliminates painful Camera2 state machines by binding lifecycle-aware UseCases (Preview, ImageCapture, VideoCapture, and ImageAnalysis) directly to your LifecycleOwner—typically limited to 3 simultaneous hardware surface streams.

🌱 Junior Android Dev Mental Model: SurfaceView vs. TextureView in Media3 Compose

In androidx.media3:media3-ui-compose, PlayerSurface defaults to SURFACE_TYPE_SURFACE_VIEW. Why? Because SurfaceView punches a hardware overlay hole directly to SurfaceFlinger, bypassing GPU texture copies on RenderThread, consuming 20–30% less battery, and supporting hardware DRM (Widevine L1) and HDR10! Only use SURFACE_TYPE_TEXTURE_VIEW when you must apply complex alpha/rotation clipping transformations that older devices cannot hardware-composite.

Senior Interview Trap & Production Edge Case

Trap: Inside CameraX ImageAnalysis.Analyzer { imageProxy -> ... }, forgetting to call imageProxy.close() on every code path (including early returns and exceptions!). When using STRATEGY_KEEP_ONLY_LATEST, CameraX holds a fixed buffer queue of ImageProxy frames; if you fail to close even one ImageProxy, the camera pipeline stalls silently and stops delivering frames forever!
Edge Case: Creating two SimpleCache instances pointing to the same File(cacheDir, "media3_cache") directory throws IllegalStateException: Another SimpleCache instance uses the folder. Always inject SimpleCache as an @Singleton in your DI graph and call player.release() deterministically when the host screen exits.

❌ Junior Anti-Pattern: ExoPlayer Per Item & Unclosed ImageProxy

// 1. Allocates a new hardware MediaCodec decoder per item -> Crashes after 6 swipes!
VerticalPager(state = pagerState) { page ->
    val player = remember { ExoPlayer.Builder(context).build() } // CODEC EXHAUSTION!
    PlayerSurface(player = player)
}

// 2. CameraX ImageAnalysis: Early return leaks ImageProxy & freezes camera!
analyzer.setAnalyzer(executor) { imageProxy ->
    if (!isScannerActive) return@setAnalyzer // BUG: imageProxy.close() never called!
    processBarcode(imageProxy)
    imageProxy.close()
}

✅ 2027 Senior Standard: Shared Player + Preload + use {} AutoClose

// 1. Single shared ExoPlayer switches media item cleanly on settledPage!
LaunchedEffect(pagerState.settledPage) {
    val activeItem = videoFeed[pagerState.settledPage]
    sharedPlayer.setMediaItem(MediaItem.fromUri(activeItem.url))
    sharedPlayer.prepare()
    sharedPlayer.playWhenReady = true
    preloadManager.PreloadNext(videoFeed.getOrNull(pagerState.settledPage + 1))
}

// 2. CameraX: Wrap ImageProxy in Kotlin .use {} so close() is guaranteed!
analyzer.setAnalyzer(executor) { imageProxy ->
    imageProxy.use { proxy ->
        if (isScannerActive) processBarcode(proxy)
    }
}

data class VideoClip(val id: String, val url: String)

class Media3FeedPoolController(private val maxHardwareDecoders: Int = 2) {
    var activeCodecCount: Int = 1 // 1 primary shared ExoPlayer
        private set
    private val prewarmedCacheIds = linkedSetOf<String>()

    fun onPageSettled(feed: List<VideoClip>, settledIndex: Int): String {
        val current = feed[settledIndex]
        val next = feed.getOrNull(settledIndex + 1)
        val cacheHit = current.id in prewarmedCacheIds
        if (next != null) {
            prewarmedCacheIds.add(next.id) // Pre-warm 512KB into SimpleCache
        }
        return "PLAYING(${current.id}, zeroWaitCacheHit=$cacheHit, codecs=$activeCodecCount/$maxHardwareDecoders, preloadingNext=${next?.id ?: "NONE"})"
    }
}

fun analyzeCameraFrameSafely(isAnalyzerEnabled: Boolean, frameId: Int): String {
    var closed = false
    val closeAction = { closed = true }
    try {
        if (!isAnalyzerEnabled) {
            return "SKIPPED(frame=$frameId, imageProxyClosed=" + run { closeAction(); closed } + ")"
        }
        return "PROCESSED_QR(frame=$frameId, imageProxyClosed=" + run { closeAction(); closed } + ")"
    } finally {
        if (!closed) closeAction()
    }
}

fun main() {
    val feed = listOf(VideoClip("vid_101", "https://cdn/1.mp4"), VideoClip("vid_102", "https://cdn/2.mp4"), VideoClip("vid_103", "https://cdn/3.mp4"))
    val controller = Media3FeedPoolController()

    println("[FEED-PAGE-0] ${controller.onPageSettled(feed, 0)}")
    println("[FEED-PAGE-1] ${controller.onPageSettled(feed, 1)}")
    println("[FEED-PAGE-2] ${controller.onPageSettled(feed, 2)}")
    println("[CAMERAX-1]   ${analyzeCameraFrameSafely(isAnalyzerEnabled = false, frameId = 1)}")
    println("[CAMERAX-2]   ${analyzeCameraFrameSafely(isAnalyzerEnabled = true, frameId = 2)}")
}

fun computePreloadWindow(
    feedIds: List<String>,
    settledPage: Int,
    preloadAheadCount: Int = 2
): List<String> {
    if (settledPage < 0 || preloadAheadCount <= 0) return emptyList()
    return feedIds.drop(settledPage + 1).take(preloadAheadCount)
}

fun processImageProxySafely(
    shouldProcess: Boolean,
    processFn: () -> String,
    closeFn: () -> Unit
): String {
    return try {
        if (!shouldProcess) "SKIPPED" else processFn()
    } finally {
        closeFn()
    }
}

Why this works: Bounding media pre-warming to the next N items after settledPage prevents bandwidth waste while delivering instant video playback, and wrapping ImageProxy processing in try / finally (or .use {}) guarantees close() is called on every frame.

Quiz 1: Code Analysis & Bug Hunt

A developer builds a QR code scanner screen using CameraX ImageAnalysis with STRATEGY_KEEP_ONLY_LATEST. When the user opens the screen, analyze() runs once for the first frame while isPaused == true, and then NEVER gets called again for any subsequent camera frames! Why?

val imageAnalysis = ImageAnalysis.Builder()
    .setBackpressureStrategy(ImageAnalysis.STRATEGY_KEEP_ONLY_LATEST)
    .build()

imageAnalysis.setAnalyzer(cameraExecutor) { imageProxy ->
    if (isPaused) {
        return@setAnalyzer // <-- Why does the camera pipeline freeze forever after this?
    }
    qrDecoder.decode(imageProxy)
    imageProxy.close()
}
CameraX STRATEGY_KEEP_ONLY_LATEST is specifically designed to capture only one single image frame per application installation.
CameraX ImageAnalysis pipelines require explicitly invoking ProcessCameraProvider.unbindAll on the main thread after every analyzed frame.
Executing a labeled return@setAnalyzer statement permanently terminates the underlying Android Linux kernel camera HAL driver.
STRATEGY_KEEP_ONLY_LATEST blocks new frames until ImageProxy closes; returning early without calling imageProxy.close starves the queue.
