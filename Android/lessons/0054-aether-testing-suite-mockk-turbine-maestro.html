1. Coroutine & <code>StateFlow</code> ViewModel Testing (<code>runTest</code> + <code>Turbine</code> + Fakes)

Why do senior Android teams prefer <strong>Fake repositories (<code>FakePortfolioRepository</code>)</strong> over heavy mocking (<code>MockK</code>) for <code>StateFlow</code>-driven ViewModels, reserving <code>MockK</code> (<code>coEvery</code>, <code>coVerify</code>) for boundary verification? Because a stateful <code>FakePortfolioRepository</code> backed by a <code>MutableSharedFlow</code> lets you deterministically emit cached snapshots, network errors, and real-time WebSocket updates! Combined with CashApp's <code>Turbine</code> (<code>viewModel.uiState.test { ... }</code>) and a custom <code>MainDispatcherRule(UnconfinedTestDispatcher())</code>, you assert every state transition (<code>Loading</code> → <code>Success</code> → <code>Error</code>) in under 5ms on the JVM.

🌱 Junior Android Dev Mental Model: Why <code>WhileSubscribed(5_000)</code> Needs <code>Turbine</code> or <code>backgroundScope</code>

Remember how <code>stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), Loading)</code> only starts collecting the upstream Room/Repository <code>Flow</code> when at least <strong>one subscriber is actively collecting <code>uiState</code></strong>? If your unit test simply reads <code>assertEquals(Success, viewModel.uiState.value)</code> without an active collector, <code>uiState.value</code> stays stuck at <code>Loading</code> forever! Wrapping your test in Turbine's <code>viewModel.uiState.test { awaitItem() }</code> registers a subscriber and wakes up the <code>WhileSubscribed</code> upstream pipeline immediately.

2. Headless Compose UI Tests (Robolectric) & Maestro E2E Flows

Using Robolectric + <code>createComposeRule()</code>, we run <code>@Composable</code> semantic assertions (<code>onNodeWithTag("candle_scrubber").performTouchInput { swipeRight() }</code>) directly on the local JVM without booting an emulator! Finally, at the top of the testing pyramid, we execute declarative Maestro YAML flows (<code>.maestro/portfolio_vault_flow.yaml</code>) against our release-minified APK to verify the complete cold-start → market scrub → biometric vault unlock journey.

@Test
fun uiState_emitsLoadingThenSuccess_whenRepositoryEmitsHoldings() = runTest {
    val fakeRepo = FakePortfolioRepository()
    val viewModel = PortfolioViewModel(fakeRepo)

    viewModel.uiState.test {
        assertEquals(PortfolioUiState.Loading, awaitItem())
        fakeRepo.emitHoldings(listOf(sampleBtcHolding))
        val state = awaitItem() as PortfolioUiState.Success
        assertEquals("BTC", state.holdings.first().symbol)
        cancelAndIgnoreRemainingEvents()
    }
}

sealed interface PortfolioUiState {
    data object Loading : PortfolioUiState
    data class Success(val symbols: List<String>, val totalUsd: Double) : PortfolioUiState
    data class Error(val reason: String) : PortfolioUiState
}

class FakePortfolioRepository {
    private val emissions = ArrayDeque<PortfolioUiState>()

    fun enqueueHoldings(symbols: List<String>, totalUsd: Double) {
        emissions.addLast(PortfolioUiState.Success(symbols, totalUsd))
    }

    fun nextEmission(): PortfolioUiState =
        if (emissions.isEmpty()) PortfolioUiState.Loading else emissions.removeFirst()
}

class TurbineTestCollector<T>(initialValue: T) {
    private val queue = ArrayDeque<T>().apply { addLast(initialValue) }

    fun push(item: T) = queue.addLast(item)
    fun awaitItem(): T = queue.removeFirst()
    fun ensureAllEventsConsumed(): Boolean = queue.isEmpty()
}

fun main() {
    val fakeRepo = FakePortfolioRepository()
    val turbine = TurbineTestCollector<PortfolioUiState>(PortfolioUiState.Loading)

    println("[TURBINE] Step 1 awaitItem() -> ${turbine.awaitItem()}")
    fakeRepo.enqueueHoldings(listOf("BTC", "ETH", "SOL"), totalUsd = 128_450.00)
    turbine.push(fakeRepo.nextEmission())

    println("[TURBINE] Step 2 awaitItem() -> ${turbine.awaitItem()}")
    println("[TURBINE] All events consumed = ${turbine.ensureAllEventsConsumed()}")
    println("[ROBOLECTRIC-COMPOSE] onNodeWithTag('candlestick_chart_canvas').assertIsDisplayed() -> PASSED (18ms)")
    println("[MAESTRO-E2E] .maestro/aether_smoke_flow.yaml (launchApp -> tapOn 'BTC' -> swipe chart -> Vault) -> PASSED")
}

import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.asStateFlow

class FakeMarketRepository {
    private val quotesFlow = MutableStateFlow<List<String>>(emptyList())

    fun observeQuotes(): StateFlow<List<String>> = quotesFlow.asStateFlow()

    fun emitTestQuotes(quotes: List<String>) {
        quotesFlow.value = quotes
    }
}

Why this works: Test fakes backed by MutableStateFlow allow unit tests to push deterministic state transitions synchronously into ViewModels under runTest without brittle reflection mocks.

Quiz 1: Code Analysis & Bug Hunt

Examine this coroutine unit test for a ViewModel that starts an infinite periodic ticker inside <code>viewModelScope</code>. When <code>runTest</code> finishes the test body, it fails with <code>UncompletedCoroutinesError: After waiting for 10s, the test body did not complete</code> or leaks an active job. Why, and how does <code>backgroundScope</code> in <code>kotlinx-coroutines-test</code> solve it?

@Test
fun ticker_updatesEverySecond() = runTest {
    val vm = MarketViewModel(
        // If injected with standard testScope, the infinite while(true) loop inside
        // MarketViewModel never terminates when the test assertions finish!
        externalScope = this
    )
    advanceTimeBy(3_000)
    assertEquals(3, vm.tickCount.value)
}
Calling advanceTimeBy(3_000) blocks and pauses the physical host CPU thread for three full real-world clock seconds.
The runTest coroutine builder only supports one-shot suspend functions and cannot observe hot StateFlow state properties.
All JUnit assertEquals assertions inside coroutine unit tests must be wrapped inside a withContext(Dispatchers.IO) execution block.
runTest awaits all TestScope children; passing backgroundScope runs infinite hot flows and cancels them when finished.

Quiz 2: Production Architectural Reasoning

Why have modern Android engineering teams adopted <strong>Robolectric + <code>ComposeTestRule</code></strong> for screen-level UI tests alongside <strong>Maestro</strong> for E2E smoke tests, replacing large suites of slow emulator-bound Espresso tests?

Robolectric runs Compose semantics and Roborazzi screenshot tests on the JVM, while Maestro verifies E2E flows.
Google officially deprecated ComposeTestRule for connected Android emulator instrumentation test suites starting in Jetpack Compose 1.7.
Maestro compiles declarative YAML test scripts directly into native ARM64 kernel drivers inside the release APK.
Running local Robolectric unit tests on the JVM automatically generates production Google Play App Signing keys.
