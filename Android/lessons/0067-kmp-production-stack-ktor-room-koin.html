KMP Production Stack: Ktor, Room KMP, DataStore & Koin

Assemble an offline-first multiplatform data layer using Ktor engines, Jetpack Room KMP with BundledSQLiteDriver, DataStore, and Koin DI.

Recommended Primary Source
Android Developers: Kotlin Multiplatform Support for Jetpack Libraries
Official Documentation →

Building a production offline-first data layer in Kotlin Multiplatform is dramatically simpler in 2027 because Google officially ships multiplatform versions of core Jetpack libraries: Room KMP (<code>androidx.room:room-runtime</code> 2.7+), DataStore KMP, Paging 3 KMP, and Lifecycle / ViewModel KMP (<code>androidx.lifecycle:lifecycle-viewmodel</code>). Because Retrofit and Dagger/Hilt rely on JVM bytecode generation and <code>java.lang.reflect.Proxy</code>, a KMP <code>:shared</code> data layer pairs Jetpack's multiplatform persistence libraries with Ktor Client for networking and Koin (or <code>kotlin-inject</code>) for multiplatform dependency injection.

Under the hood, Ktor Client separates its cross-platform request/serialization pipeline (<code>ContentNegotiation</code>, <code>kotlinx.serialization</code>, <code>HttpTimeout</code>, auth interceptors in <code>commonMain</code>) from its underlying platform socket engine: <code>OkHttp</code> on <code>androidMain</code> and <code>Darwin</code> (<code>NSURLSession</code>) on <code>iosMain</code>. Similarly, Room KMP compiles your <code>@Database</code>, <code>@Entity</code>, and <code>@Dao</code> interfaces (returning reactive <code>Flow<List<T>></code>) across both platforms via KSP (<code>kspAndroid</code>, <code>kspIosArm64</code>, <code>kspIosSimulatorArm64</code>). To avoid inconsistencies between Android's OEM-bundled SQLite and Apple's iOS SQLite build, Room KMP uses <code>BundledSQLiteDriver()</code> (<code>androidx.sqlite:sqlite-bundled</code>)—compiling the exact same up-to-date C SQLite source code into both platforms! On Android and iOS, the only platform-specific code required for Room and DataStore is resolving the sandboxed file system directory (<code>context.getDatabasePath(...)</code> on Android vs <code>NSFileManager.defaultManager.URLForDirectory(NSDocumentDirectory, ...)</code> on iOS).

🌱 Junior Android Dev Mental Model: Why Room KMP Needs @ConstructedBy on Non-JVM Targets

On Android JVM, <code>Room.databaseBuilder()</code> finds the KSP-generated <code>AppDatabase_Impl</code> class at runtime using <code>Class.forName()</code> reflection. Because Kotlin/Native on iOS does not support arbitrary JVM class-name reflection, you annotate your <code>@Database</code> class in <code>commonMain</code> with <code>@ConstructedBy(AppDatabaseConstructor::class)</code> alongside an <code>expect object AppDatabaseConstructor : RoomDatabaseConstructor<AppDatabase></code>—which KSP fills in automatically at compile time!

Senior Interview Trap & Production Edge Case

Trap: Calling <code>Room.inMemoryDatabaseBuilder()</code> or <code>Room.databaseBuilder()</code> in KMP without calling <code>.setDriver(BundledSQLiteDriver())</code> and <code>.setQueryCoroutineContext(Dispatchers.IO)</code>. In Room KMP, omitting the SQLite driver throws <code>IllegalArgumentException: Cannot create a RoomDatabase without a SQLiteDriver</code> at runtime!
Edge Case: Creating two separate instances of <code>DataStore<Preferences></code> pointing to the same <code>.preferences_pb</code> file path (for instance, because a developer didn't register DataStore as a <code>single {}</code> singleton in Koin) throws <code>IllegalStateException: There are multiple DataStores active for the same file</code>.

// commonMain: Crashes at runtime on both Android & iOS!

    // Missing .setDriver(BundledSQLiteDriver())!

✅ 2027 Senior Standard: BundledSQLiteDriver + Singleton Koin Graph

// commonMain: Consistent SQLite version across Android & iOS + IO dispatcher
fun configureRoomDatabase(builder: RoomDatabase.Builder<AppDatabase>): AppDatabase {
    return builder
        .setDriver(BundledSQLiteDriver())
        .setQueryCoroutineContext(Dispatchers.IO)
        .fallbackToDestructiveMigrationOnDowngrade(dropAllTables = true)
        .build()
}

data class AssetEntity(val symbol: String, val priceUsd: Double, val updatedAtEpochMs: Long)

class SimulatedBundledSqliteDao {
    private val table = linkedMapOf<String, AssetEntity>()
    fun upsertAll(items: List<AssetEntity>) { items.forEach { table[it.symbol] = it } }
    fun queryAllSorted(): List<AssetEntity> = table.values.sortedBy { it.symbol }
}

class KmpOfflineFirstAssetRepository(
    private val engineName: String,
    private val dao: SimulatedBundledSqliteDao
) {
    fun syncAndReadSsot(networkPayload: List<AssetEntity>, networkSucceeded: Boolean): List<AssetEntity> {
        println("[KTOR-$engineName] Fetching /v2/assets (success=$networkSucceeded)...")
        if (networkSucceeded) {
            dao.upsertAll(networkPayload)
            println("[ROOM-KMP] Upserted ${networkPayload.size} rows via BundledSQLiteDriver on Dispatchers.IO")
        } else {
            println("[ROOM-KMP] Network unavailable -> Serving cached Single Source of Truth from SQLite")
        }
        return dao.queryAllSorted()
    }
}

fun main() {
    val sharedDao = SimulatedBundledSqliteDao()
    val androidRepo = KmpOfflineFirstAssetRepository("OkHttp", sharedDao)
    val iosRepo = KmpOfflineFirstAssetRepository("Darwin-NSURLSession", sharedDao)

    val initialBatch = listOf(AssetEntity("SOL", 195.0, 1740001000L), AssetEntity("BTC", 94200.0, 1740001000L))

    println("iOS Offline  -> ${iosRepo.syncAndReadSsot(emptyList(), networkSucceeded = false)}")

fun validateKmpDataStack(
    hasBundledSqliteDriver: Boolean,
    queryDispatcher: String,
    dataStoreInstancesForPath: Int,
    ktorPlatformEngine: String
): Result<String> {
    if (!hasBundledSqliteDriver || queryDispatcher != "Dispatchers.IO") {
        return Result.failure(IllegalStateException("Room KMP requires BundledSQLiteDriver and Dispatchers.IO"))
    }
    if (dataStoreInstancesForPath != 1) {
        return Result.failure(IllegalStateException("DataStore must have exactly 1 singleton instance per file path"))
    }
    if (ktorPlatformEngine !in setOf("OkHttp", "Darwin")) {
        return Result.failure(IllegalStateException("Unsupported Ktor engine: $ktorPlatformEngine"))
    }
    return Result.success("KMP_DATA_STACK_READY:$ktorPlatformEngine")
}

Why this works: Room KMP requires an explicit SQLiteDriver (<code>BundledSQLiteDriver</code>) and <code>Dispatchers.IO</code>, DataStore enforces a single active instance per file path, and Ktor delegates sockets to <code>OkHttp</code> on Android and <code>Darwin</code> on iOS.

// commonMain/kotlin/com/aether/db/AppDatabase.kt
@Database(entities = [HoldingEntity::class], version = 1)

// Missing @ConstructedBy and RoomDatabaseConstructor!
Multiplatform Room KSP processors disallow abstract classes and require @Database annotations inside enumerations during compilation.
On non-JVM targets, Room lacks Class.forName reflection and requires @ConstructedBy with an expect RoomDatabaseConstructor object.
Apple iOS hardware architectures lack persistent flash storage, so relational SQLite tables cannot exist locally.
Database version 1 is forbidden because Multiplatform Room requires initial migration schema versions above 100.
