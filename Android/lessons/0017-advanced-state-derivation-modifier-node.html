Advanced State Derivation & Modifier.Node API

Prune redundant recompositions with derivedStateOf and master high-performance Modifier.Node implementations.

Recommended Primary Source
Google Android: derivedStateOf & High-performance Modifier.Node
Official Documentation →

Senior Compose performance engineering centers on two high-leverage mechanisms: pruning unnecessary recompositions with derivedStateOf and eliminating modifier allocation overhead with the Modifier.Node API.

1. derivedStateOf vs. remember(key): The Frequency Rule

Junior developers often confuse remember(key) { compute(key) } with remember { derivedStateOf { compute(state.value) } }. Here is the exact mechanical difference in the Snapshot system:

  • remember(key) { ... }: Use when the input changes at the same frequency as the output (e.g., sorting or filtering a list whenever items or sortOrder changes). The Composable is *already* recomposing because key changed; remember(key) simply caches the expensive transformation across *unrelated* recompositions.
  • remember { derivedStateOf { ... } }: Use ONLY when inputs change MUCH more frequently than the derived output (e.g., scrollState.value changes 120 times/sec on every pixel, or a password TextField changes on every keystroke, while the output isButtonEnabled = text.length >= 8 only flips between false and true). derivedStateOf creates a dedicated DerivedSnapshotState node in the Snapshot dependency graph: when scrollState.value changes from 100 to 101, derivedStateOf re-evaluates its lambda silently, sees that 101 > 50 is still true, and does NOT invalidate the enclosing Composable's RecomposeScope!
🌱 Junior Android Dev Mental Model: Why Modifier.composed { } Was Replaced by Modifier.Node

In Compose 1.0–1.4, stateful custom modifiers were written using Modifier.composed { ... }. However, Modifier.composed is NOT skippable: it had to execute a subcomposition and allocate new remember slots on every recomposition of the caller, causing massive memory churn in LazyColumn! Starting in Compose 1.5+ and mandatory in 2027, all custom modifiers use the three-part Modifier.Node architecture, which allocates the node once when attached to the LayoutNode and mutates it in-place on updates!

2. The 3-Part Modifier.Node Architecture

  1. Modifier.Node Subclass: Holds mutable state across recompositions, implements coroutineScope for animations, and mixes in zero-cost capability interfaces (DrawModifierNode, LayoutModifierNode, PointerInputModifierNode, SemanticsModifierNode).
  2. ModifierNodeElement<N : Modifier.Node>: A lightweight, immutable data class created on each recomposition with create(): N (called once on initial attach) and update(node: N) (called when the element's equals() changes, updating the existing Modifier.Node in place without reallocating!).
  3. Modifier Extension Function: Clean factory API (fun Modifier.circleBadge(color: Color) = this then CircleBadgeElement(color)).

❌ Junior Anti-Pattern: Legacy Modifier.composed & Redundant derivedStateOf

// BUG 1: Input (firstName, lastName) changes at exact same rate as output!
// Wrapping in derivedStateOf adds unnecessary Snapshot node overhead!
val fullName by remember(firstName, lastName) {
    derivedStateOf { "$firstName $lastName" }
}

// BUG 2: Legacy Modifier.composed materializes a non-skippable subcomposition
// on every recomposition of every item in LazyColumn!
fun Modifier.legacyTintBorder(color: Color) = composed {
    val animColor by animateColorAsState(color)
    this.border(2.dp, animColor)
}

✅ 2027 Senior Standard: High-Frequency derivedStateOf + Modifier.Node

// 1. Plain remember(k1, k2) for 1:1 input-to-output frequency:
val fullName = remember(firstName, lastName) { "$firstName $lastName" }

// 2. Zero-allocation Modifier.Node + ModifierNodeElement:
private class CircleTintNode(var color: Color) : Modifier.Node(), DrawModifierNode {
    override fun ContentDrawScope.draw() {
        drawContent()
        drawCircle(color = color, radius = size.minDimension / 4f)
    }
}

private data class CircleTintElement(val color: Color) : ModifierNodeElement<CircleTintNode>() {
    override fun create() = CircleTintNode(color)
    override fun update(node: CircleTintNode) { node.color = color }
}

fun Modifier.circleTintOverlay(color: Color): Modifier = this then CircleTintElement(color)

// Simulates how Compose's NodeChain diffs ModifierNodeElement and updates Modifier.Node in-place
abstract class SimulatedModifierNode {
    var isAttached: Boolean = false
    open fun onAttach() {}
}

interface SimulatedModifierNodeElement<N : SimulatedModifierNode> {
    fun create(): N
    fun update(node: N)
}

class BadgeOverlayNode(var badgeColorHex: String, var badgeRadiusPx: Float) : SimulatedModifierNode() {
    override fun onAttach() {
        println("[NODE] BadgeOverlayNode attached to LayoutNode once (hashCode=${this.hashCode()})")
    }
    fun drawFrame() {
        println("[DRAW] Rendering badge(color=$badgeColorHex, radius=$badgeRadiusPx) on same node instance")
    }
}

data class BadgeOverlayElement(
    val colorHex: String,
    val radiusPx: Float
) : SimulatedModifierNodeElement<BadgeOverlayNode> {
    override fun create(): BadgeOverlayNode = BadgeOverlayNode(colorHex, radiusPx)
    override fun update(node: BadgeOverlayNode) {
        node.badgeColorHex = colorHex
        node.badgeRadiusPx = radiusPx
        println("[ELEMENT DIFF] Updated existing BadgeOverlayNode in-place -> color=$colorHex, radius=$radiusPx")
    }
}

fun main() {
    val firstElement = BadgeOverlayElement("#10B981", 12f)
    val retainedNode = firstElement.create().apply { isAttached = true; onAttach() }
    retainedNode.drawFrame()

    // Parent recomposes with new color: Element is diffed via data class equals(), node updated in-place!
    val secondElement = BadgeOverlayElement("#EF4444", 16f)
    if (firstElement != secondElement) {
        secondElement.update(retainedNode)
    }
    retainedNode.drawFrame()
}

import androidx.compose.ui.Modifier
import androidx.compose.ui.graphics.Color
import androidx.compose.ui.graphics.drawscope.ContentDrawScope
import androidx.compose.ui.node.DrawModifierNode
import androidx.compose.ui.node.ModifierNodeElement

class DimOverlayNode(var dimAlpha: Float) : Modifier.Node(), DrawModifierNode {
    override fun ContentDrawScope.draw() {
        drawContent()
        drawRect(Color.Black.copy(alpha = dimAlpha))
    }
}

data class DimOverlayElement(
    val dimAlpha: Float
) : ModifierNodeElement<DimOverlayNode>() {
    override fun create(): DimOverlayNode = DimOverlayNode(dimAlpha)

    override fun update(node: DimOverlayNode) {
        node.dimAlpha = dimAlpha
    }
}

fun Modifier.dimOverlay(dimAlpha: Float): Modifier =
    this then DimOverlayElement(dimAlpha)

Why this works: DimOverlayNode is allocated once when attached to the LayoutNode, while DimOverlayElement uses data class structural equality to invoke update(node) in place whenever dimAlpha changes—achieving zero node reallocation and full skippability.

Quiz 1: Code Analysis & Bug Hunt

A developer writes the following Composable that takes 'query: String' as a function parameter and attempts to use derivedStateOf. Why does 'isValidQuery' fail to update when 'query' changes?

@Composable
fun SearchSubmitButton(query: String, onSubmit: () -> Unit) {
    // 'query' is a regular String parameter, NOT a State<String>!
    val isValidQuery by remember {
        derivedStateOf { query.trim().length >= 3 }
    }
    Button(enabled = isValidQuery, onClick = onSubmit) {
        Text("Search")
    }
}
derivedStateOf only supports numeric Int or Float state calculations and ignores primitive Boolean return values.
String.trim() is a suspending coroutine operation that cannot execute safely inside a derivedStateOf state lambda.
Material Button enabled prop ignores derived Snapshot Boolean states unless first wrapped inside Parcelable storage.
Because plain String query is not Snapshot state and remember omits keys, derivedStateOf never invalidates.

Quiz 2: Production Architectural Reasoning

Why must a custom ModifierNodeElement subclass always be implemented as a 'data class' (or manually override equals() and hashCode() for all constructor properties)?

Compose diffs ModifierNodeElement instances via equals() during recomposition, calling update() to mutate retained Modifier.Node instances.
ModifierNodeElement instances serialize inside local SQLite storage using runtime reflection on generated Parcelable componentN() methods.
Kotlin 2.x multiplatform compiler verification forbids inheriting from abstract ModifierNodeElement types without data class declarations.
Android 15+ allocates data class ModifierNodeElement instances directly inside hardware-accelerated RenderThread Vulkan texture heap memory.
