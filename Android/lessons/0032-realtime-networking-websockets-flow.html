Real-Time Networking: WebSockets & SSE with Flow

Bridge bidirectional WebSockets and Server-Sent Events into reactive Kotlin Flows with callbackFlow.

Recommended Primary Source
Kotlin Coroutines: callbackFlow and channelFlow
Official Documentation →

For financial feeds (like the live market prices in our Aether capstone app), polling HTTP endpoints every second wastes bandwidth and battery. Modern apps maintain persistent WebSockets or Server-Sent Events (SSE), streaming real-time quotes directly into a reactive Kotlin Flow.

🌱 Junior Android Dev Mental Model: callbackFlow & awaitClose

To convert callback-based listener APIs (like WebSocket listeners) into a Flow, use callbackFlow { ... }. CRITICAL: You MUST call awaitClose { ... } at the end of the block! awaitClose keeps the channel open until the subscriber cancels, and provides a cleanup hook to close the WebSocket socket connection.

🎯 Reference Production Solution 
import kotlinx.coroutines.channels.awaitClose
import kotlinx.coroutines.flow.Flow
import kotlinx.coroutines.flow.callbackFlow

interface MockSocket {
    fun setListener(onMessage: (String) -> Unit)
    fun close()
}

fun observeWebSocket(socket: MockSocket): Flow<String> = callbackFlow {
    socket.setListener { message ->
        trySend(message)
    }
    awaitClose {
        socket.close()
    }
}

Why this works: callbackFlow bridges asynchronous push-based callbacks into cold reactive streams, while awaitClose guarantees that underlying network connections are closed when the subscriber stops collecting.
