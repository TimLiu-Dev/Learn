Complex Animations & Micro-Interactions

Build fluid 120fps animations using animateContentSize, AnimatedVisibility, updateTransition, and gesture physics.

Recommended Primary Source
Google Android: Animations in Jetpack Compose
Official Documentation →

In 2027 Android engineering (Material 3 Expressive), time-based linear/tween animations (tween(300)) feel robotic and stutter whenever a user interrupts a gesture mid-flight. Modern Compose animations default to Spring Physics (spring(dampingRatio, stiffness)). Because a spring simulation tracks both position AND real-time velocity on every frame, retargeting a spring mid-animation (e.g., when a user flings a sheet up and immediately catches and drags it down) preserves momentum with C<sup>1</sup> velocity continuity and zero visual jump!

Choosing the right Compose animation API depends on your state topology:

  • Single-Value Fire-and-Forget (animateFloatAsState, animateColorAsState, animateDpAsState): Best for independent property transitions driven by a boolean or enum state. Read the returned State<T>.value inside a Layout or Draw lambda (Modifier.graphicsLayer { scaleX = scale }) to skip Composition!
  • Coordinated Multi-Property State Machine (updateTransition): Synchronizes multiple animated properties (animateFloat, animateColor, animateDp) across a shared Transition<S> state machine.
  • Imperative / Gesture-Driven Coroutine Control (Animatable): A single-value holder with suspend fun animateTo(target, initialVelocity) and suspend fun snapTo(target). Essential for custom pointerInput drag-to-dismiss gestures combined with VelocityTracker!
🌱 Junior Android Dev Mental Model: Why Springs Beat Duration Tweens

When a user taps a toggle button twice rapidly during a 300ms tween(300) animation, the animation abruptly reverses velocity at the turnaround point and still takes a full 300ms to travel only 20% of the distance back. A spring(dampingRatio = Spring.DampingRatioLowBouncy, stiffness = Spring.StiffnessMediumLow) naturally decelerates existing velocity before accelerating toward the new target!

🔥 Senior Deep Dive: LookaheadScope, Modifier.animateBounds(), & Shared Element Transitions

How does Compose smoothly animate a card expanding from a 2-column grid into a full-screen detail header, or animate layout changes when siblings reflow (Modifier.animateBounds(lookaheadScope) and SharedTransitionLayout / Modifier.sharedBounds()) without running expensive animations in the Composition phase?

Under the hood, LookaheadScope adds a Lookahead Pass right before the regular Measurement/Placement pass whenever the layout tree changes:

  1. Pass 1 (Lookahead Pass — Discrete Target Calculation): Compose measures and places the layout tree *once* as if the state change had already finished instantaneously, recording every node's destination size (lookaheadSize) and destination coordinates (lookaheadPosition).
  2. Pass 2 (Approach / Intermediate Pass — Per-Frame Interpolation): On each animation frame, ApproachLayoutModifierNode (used inside Modifier.animateBounds(lookaheadScope) and sharedElement) interpolates size and offset from the current frame toward the pre-calculated Lookahead target using spring physics—without re-running Lookahead unless the target layout itself changes!

✅ 2027 Senior Standard: LookaheadScope + animateBounds + Draw-Phase Spring

@Composable
fun ExpressiveMorphGrid(isDetailView: Boolean) {
    val alpha by animateFloatAsState(
        targetValue = if (isDetailView) 1f else 0.75f,
        animationSpec = spring(
            dampingRatio = Spring.DampingRatioNoBouncy,
            stiffness = Spring.StiffnessMediumLow
        )
    )

    LookaheadScope {
        Row {
            Box(
                modifier = Modifier
                    // Interpolates size & position smoothly toward Lookahead target!
                    .animateBounds(lookaheadScope = this@LookaheadScope)
                    .size(if (isDetailView) 280.dp else 120.dp)
                    // Reads spring state strictly in Draw phase (0 recompositions!)
                    .graphicsLayer { this.alpha = alpha }
            )
        }
    }
}

data class IntBounds(val x: Int, val y: Int, val width: Int, val height: Int)

class SpringLookaheadApproachSimulator(
    private val stiffnessFactor: Float = 0.35f,
    private val dampingFactor: Float = 0.75f
) {
    private var velocityW = 0f
    private var currentW = 0f

    fun runLookaheadAndApproach(startBounds: IntBounds, targetStateExpanded: Boolean): List<IntBounds> {
        // 1. Lookahead Pass computes final discrete target geometry once
        val lookaheadTarget = if (targetStateExpanded) {
            IntBounds(x = 0, y = 0, width = 320, height = 240)
        } else {
            IntBounds(x = 16, y = 16, width = 120, height = 120)
        }
        println("[LOOKAHEAD PASS] Computed destination geometry once: $lookaheadTarget")

        // 2. Approach Pass interpolates frame-by-frame with spring velocity continuity
        currentW = startBounds.width.toFloat()
        val frames = mutableListOf<IntBounds>()
        repeat(4) { frameIdx ->
            val displacement = lookaheadTarget.width - currentW
            velocityW = (velocityW + displacement * stiffnessFactor) * dampingFactor
            currentW += velocityW
            val frameBounds = lookaheadTarget.copy(width = currentW.toInt())
            frames.add(frameBounds)
            println("[APPROACH FRAME #${frameIdx + 1}] width=${frameBounds.width}px (velocity=${"%.1f".format(velocityW)}px/frame)")
        }
        return frames
    }
}

fun main() {
    val simulator = SpringLookaheadApproachSimulator()
    val collapsed = IntBounds(x = 16, y = 16, width = 120, height = 120)
    simulator.runLookaheadAndApproach(startBounds = collapsed, targetStateExpanded = true)
}

import androidx.compose.animation.animateBounds
import androidx.compose.animation.core.*
import androidx.compose.foundation.layout.Box
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import androidx.compose.ui.graphics.graphicsLayer
import androidx.compose.ui.layout.LookaheadScope

@Composable
fun MorphingMediaCard(isExpanded: Boolean) {
    val scale by animateFloatAsState(
        targetValue = if (isExpanded) 1.0f else 0.92f,
        animationSpec = spring(
            dampingRatio = Spring.DampingRatioLowBouncy,
            stiffness = Spring.StiffnessMediumLow
        )
    )

    LookaheadScope {
        Box(
            modifier = Modifier
                .animateBounds(this@LookaheadScope)
                .graphicsLayer {
                    scaleX = scale
                    scaleY = scale
                }
        )
    }
}

Why this works: spring() maintains velocity continuity if isExpanded flips mid-animation, LookaheadScope + Modifier.animateBounds pre-calculates destination geometry once and smoothly interpolates layout bounds during the Approach pass, and reading scale inside graphicsLayer { } restricts scale updates strictly to the Draw phase.

val scope = rememberCoroutineScope()

Box(

Animatable state cannot be mutated from rememberCoroutineScope blocks and requires launching all gesture animations inside GlobalScope.
Modifier.offset lambdas cannot read Animatable.value while an active pointerInput drag gesture is mutating layout snapshot state.
detectHorizontalDragGestures runs on Dispatchers.IO threads where Animatable updates fail with a MutatorMutex main thread confinement error.
Invoking animateTo during every touch event repeatedly interrupts in-flight animations and lags behind direct snapTo positioning.
