Advanced State Derivation & Modifier.Node API

Prune redundant recompositions with derivedStateOf and master high-performance Modifier.Node implementations.

Recommended Primary Source
Google Android: derivedStateOf & High-performance Modifier.Node
Official Documentation →

When UI state changes on every single pixel (like scrolling a list from 0 to 1200px), recalculating or recomposing on every pixel drop frames. derivedStateOf converts rapidly changing state into a boolean or threshold state that only invalidates when the calculated output changes.

🌱 Junior Android Dev Mental Model: derivedStateOf

If you write val showButton = scrollIndex > 0 directly in your composable, the function recomposes on EVERY single scroll offset change! Wrapping it in val showButton by remember { derivedStateOf { scrollIndex > 0 } } means Compose only recomposes ONCE when crossing the threshold (from false to true).

fun main() {
    println("[SCROLL] User scrolling list: offset changing every frame...")
    var offset = 0
    
    // Simulating derivedStateOf calculation
    fun isFabVisible(off: Int) = off > 100

    for (step in listOf(20, 45, 80, 110, 140, 180, 90)) {
        offset = step
        val visible = isFabVisible(offset)
        println("[OFFSET] scrollOffset = $offset -> derivedStateOf threshold: isFabVisible = $visible")
    }
    println("[SUCCESS] derivedStateOf triggered recomposition ONLY when boolean threshold changed!")
}

🎯 Reference Production Solution 
import androidx.compose.runtime.*

@Composable
fun ScrollToTopButton(firstVisibleIndex: () -> Int) {
    val showButton by remember {
        derivedStateOf { firstVisibleIndex() > 0 }
    }
}

Why this works: derivedStateOf dampens state change frequency, ensuring that fast-moving inputs (scroll position, sensor readings) only trigger recomposition when the downstream derived result actually flips.
