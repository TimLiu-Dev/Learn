Automated CI/CD Pipelines with GitHub Actions

Build blazing-fast CI/CD pipelines that run unit tests, linting, Gradle caching, and release APK/AAB generation.

Recommended Primary Source
GitHub Actions: Building and testing Android apps
Official Documentation →

Code that only compiles and passes tests on a developer's laptop is a liability. A production-grade 2027 Continuous Integration and Continuous Delivery (CI/CD) pipeline built on GitHub Actions validates every Pull Request in parallel and automates cryptographically signed Play Store releases without a single human ever holding production keystore files on their local machine.

Under the Hood: Gradle Build Cache, Configuration Cache & KVM Acceleration

Without optimization, a clean Gradle build in an ephemeral CI container downloads gigabytes of Gradle wrappers and Maven dependencies from scratch, taking 20+ minutes. Senior Android CI pipelines reduce PR verification under 4 minutes using four core mechanisms:

  1. gradle/actions/setup-gradle@v4: Automatically caches <code>~/.gradle/caches</code>, wrapper distributions, and the Gradle Build Cache across CI runs, writing cache entries only on the protected <code>main</code> branch and restoring read-only caches on PR branches to prevent cache poisoning.
  2. Gradle Configuration Cache & Parallel Execution: Passing --configuration-cache --parallel --stacktrace serializes the task graph so subsequent tasks skip configuration overhead.
  3. Change-Aware / Affected Module Execution: Running unit tests and Lint only on changed modules (or using remote build cache hits for untouched modules).
  4. Linux KVM Hardware Acceleration: Running instrumentation or Macrobenchmark suites on GitHub-hosted Linux runners by granting <code>/dev/kvm</code> permissions so the x86_64 Android Emulator runs at near-native speed without nested virtualization bottlenecks.
🌱 Junior Android Dev Mental Model: Ephemeral Secret Injection

Never commit <code>.jks</code> keystores, <code>service-account.json</code>, or API keys to Git! Store binary keystores as Base64-encoded strings inside GitHub Actions Encrypted Secrets (<code>SIGNING_KEYSTORE_BASE64</code>), decode them into an ephemeral runner directory (<code>$RUNNER_TEMP/release.jks</code>) during the release job, and let the container self-destruct when the job completes.

❌ Junior Anti-Pattern: Uncached Sequential CI & Plaintext Keystore

# Slow 25-min build, no Gradle cache, runs on every branch without concurrency cancel
jobs:
  build:
    runs-on: macos-latest # 10x more expensive runner minutes than ubuntu-latest!
    steps:
      - uses: actions/checkout@v4
      - run: ./gradlew clean build # 'clean' destroys incremental caches!

✅ 2027 Senior Production Standard: Cached, Concurrent GitHub Actions

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  verify-pr:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          distribution: 'temurin'
          java-version: '21'
      - uses: gradle/actions/setup-gradle@v4
        with:
          cache-read-only: ${{ github.ref != 'refs/heads/main' }}
      - name: Run Static Analysis & JVM Tests
        run: ./gradlew detektMain lintDebug testDebugUnitTest --parallel --configuration-cache

⚠️ Senior Interview Trap: Running <code>./gradlew clean</code> in CI & Stale PR Runs

Why is running <code>./gradlew clean</code> at the start of a CI job an anti-pattern when using Gradle Build Cache? Because <code>clean</code> wipes out any local build outputs and forces unnecessary work; furthermore, omitting a top-level <code>concurrency</code> block means that if a developer pushes 5 rapid commits to a PR branch, 5 full Android builds run simultaneously, exhausting your organization's GitHub Actions runner pool! Always configure <code>cancel-in-progress: true</code> for PR workflows.

data class CiStepResult(val stage: String, val durationSec: Int, val cacheHitRatePercent: Int, val passed: Boolean)

class GitHubActionsPipelineSimulator(
    private val isMainBranch: Boolean,
    private val secretKeystoreBase64Present: Boolean
) {
    fun runPullRequestPipeline(): List<CiStepResult> = listOf(
        CiStepResult("Checkout & Temurin JDK 21", durationSec = 6, cacheHitRatePercent = 100, passed = true),
        CiStepResult("Gradle Cache Restore (readOnly=${!isMainBranch})", durationSec = 9, cacheHitRatePercent = 94, passed = true),
        CiStepResult("Static Analysis (detektMain + lintDebug)", durationSec = 42, cacheHitRatePercent = 88, passed = true),
        CiStepResult("JVM Unit Tests (MockK + Turbine + Robolectric)", durationSec = 55, cacheHitRatePercent = 91, passed = true)
    )

    fun decodeEphemeralSigningConfig(): String {
        check(secretKeystoreBase64Present) { "Missing GitHub Secret: SIGNING_KEYSTORE_BASE64" }
        return "/tmp/runner_temp/aether-upload-key.jks (decoded in-memory, permissions 0600)"
    }
}

fun main() {
    val prPipeline = GitHubActionsPipelineSimulator(isMainBranch = false, secretKeystoreBase64Present = true)
    val steps = prPipeline.runPullRequestPipeline()
    val totalSec = steps.sumOf { it.durationSec }

    println("[CI] Running PR Verification Workflow (cancel-in-progress=true):")
    steps.forEach { s ->
        println("  ✅ ${s.stage} [${s.durationSec}s | Cache Hit: ${s.cacheHitRatePercent}%]")
    }
    println("[CI] Total PR Pipeline Time: ${totalSec}s (Passed=${steps.all { it.passed }})")
    println("[CD] Release Signing Keystore: ${prPipeline.decodeEphemeralSigningConfig()}")
}

data class SigningSpec(
    val keystoreBase64: String,
    val keystorePassword: String,
    val keyAlias: String
)

class ReleasePipelineValidator {
    fun validateReleaseEnv(env: Map<String, String>): Result<SigningSpec> {
        val keystoreBase64 = env["KEYSTORE_BASE64"]
        val keystorePassword = env["KEYSTORE_PASSWORD"]
        val keyAlias = env["KEY_ALIAS"]

        if (keystoreBase64.isNullOrBlank() || keystorePassword.isNullOrBlank() || keyAlias.isNullOrBlank()) {
            return Result.failure(IllegalStateException("Missing signing secrets"))
        }

        return Result.success(
            SigningSpec(
                keystoreBase64 = keystoreBase64,
                keystorePassword = keystorePassword,
                keyAlias = keyAlias
            )
        )
    }
}

Why this works: Failing fast at the start of a CD workflow when required GitHub Actions secrets are missing or blank prevents wasting 10 minutes compiling a release AAB only to fail at the final signing step.

Quiz 1: Code Analysis & Bug Hunt

Examine this GitHub Actions Gradle setup step. Why is <code>cache-read-only: ${{ github.ref != 'refs/heads/main' }}</code> configured on the <code>setup-gradle</code> action?

- name: Setup Gradle with Cache Guard
  uses: gradle/actions/setup-gradle@v4
  with:
    cache-read-only: ${{ github.ref != 'refs/heads/main' }}
GitHub Actions throws fatal permission errors whenever setup-gradle runs on feature branches without read-only mode.
Feature branches restore warm Gradle caches generated on main without polluting or evicting shared storage.
Setting cache-read-only to true disables Kotlin incremental compilation across all subprojects during pull request builds.
It prevents the R8 compiler from overwriting version numbers inside libs.versions.toml during automated release builds.

Quiz 2: Production Architectural Reasoning

When running Android instrumented tests on a GitHub Actions <code>ubuntu-latest</code> Linux runner, why is configuring <code>/dev/kvm</code> permissions essential before launching the Android Emulator?

The /dev/kvm character device provides the background Kotlin Virtual Machine daemon required during multi-module K2 compilation.
Without /dev/kvm permissions, the Gradle wrapper cannot download external dependencies from Google Maven repositories over HTTPS.
KVM enables hardware-assisted x86_64 CPU virtualization; without /dev/kvm access, the Android emulator fails to boot quickly.
Robolectric instrumented tests require /dev/kvm permissions because Robolectric boots an isolated Linux kernel inside local JVMs.
