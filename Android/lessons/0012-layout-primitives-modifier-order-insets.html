Layout Primitives, Modifier Order & WindowInsets (Edge-to-Edge)

Master Column, Row, Box, Scaffold, modifier chaining order, and Android 15/16+ mandatory edge-to-edge window insets.

Recommended Primary Source
Google Android: Display content edge-to-edge in your app
Official Documentation →

Jetpack Compose's layout engine enforces a fundamental performance invariant: Single-Pass Measurement. Unlike legacy Android XML RelativeLayout or nested LinearLayout weights—which measured children twice at every level of the tree, causing O(2<sup>N</sup>) exponential measurement explosions—Compose forbids a Measurable from calling measure(constraints) more than once per layout pass (throwing IllegalStateException: measure() may not be called multiple times on the same Measurable).

How does Modifier chaining work during this single pass? Every layout modifier wraps the subsequent modifiers in a chain of LayoutModifierNodes. Constraints flow down (left-to-right / outer-to-inner), and determined sizes flow back up (right-to-left / inner-to-outer). Therefore, Modifier.padding(16.dp).background(Blue).size(100.dp) creates an outer 16dp transparent margin around a 100dp blue box (total 132dp), whereas Modifier.size(100.dp).background(Blue).padding(16.dp) creates a 100dp blue box whose inner content is inset by 16dp (78dp content area)!

🌱 Junior Android Dev Mental Model: Mandatory Edge-to-Edge & WindowInsets

Starting in Android 15 (API 35) and enforced through Android 16/17, apps render edge-to-edge by default behind the system status bar, navigation bar, and camera cutouts. Never hardcode padding(top = 24.dp)! Use Material 3 Scaffold(contentWindowInsets = ...) and pass the innerPadding parameter into your root scrollable container (LazyColumn(contentPadding = innerPadding)), or use Modifier.windowInsetsPadding(WindowInsets.safeDrawing) and Modifier.imePadding() for keyboard animations.

🔥 Senior Deep Dive: Custom Layout vs. SubcomposeLayout vs. IntrinsicSize

What if a parent layout genuinely needs to know a child's preferred size before measuring its siblings (for example, making two side-by-side buttons in a Row match the height of the taller text, or drawing a vertical HorizontalDivider inside a Row)? Senior engineers choose among three tools with radically different performance profiles:

  1. IntrinsicSize.Min / IntrinsicSize.Max (Fastest — Pre-Measurement Query): Calling Row(Modifier.height(IntrinsicSize.Min)) asks each child's IntrinsicMeasurable for minIntrinsicHeight(width)—a lightweight arithmetic calculation that runs before actual measure() without violating the single-pass rule!
  2. Custom Layout(content) { measurables, constraints -> ... } (Standard Single-Pass): All children are composed upfront during the Composition phase, and your MeasurePolicy measures and places them in one pass during the Layout phase. You can measure Child A first, inspect placeableA.height, and use that value to construct the Constraints for Child B!
  3. SubcomposeLayout (Heavy — Use Sparingly!): Defers the Composition phase of certain children until the Layout phase of the parent (so the child's @Composable function receives parent Constraints, as in BoxWithConstraints or LazyColumn). ⚠️ Performance Pitfall: Because SubcomposeLayout runs sub-composition *inside* the Layout pass, any constraint change (like an animation or window resize) forces full Slot Table composition during layout! Never use BoxWithConstraints or SubcomposeLayout when a custom Layout or Modifier.layout can size children using Constraints directly.

❌ Junior Anti-Pattern: BoxWithConstraints Abuse & Dropped Scaffold Insets

@Composable
fun ProfileScreen() {
    Scaffold { _ -> // BUG 1: Ignoring innerPadding draws UI under status/nav bars!
        // BUG 2: BoxWithConstraints uses SubcomposeLayout just to split width in half,
        // running full subcomposition inside the Layout pass!
        BoxWithConstraints {
            val halfWidth = maxWidth / 2
            Card(Modifier.width(halfWidth)) { ... }
        }
    }
}

✅ 2027 Senior Standard: Single-Pass Layout + IntrinsicSize + Inset Consumption

@Composable
fun ProfileScreen() {
    Scaffold(contentWindowInsets = WindowInsets.safeDrawing) { innerPadding ->
        Column(
            modifier = Modifier
                .fillMaxSize()
                .padding(innerPadding)
                .consumeWindowInsets(innerPadding)
        ) {
            // IntrinsicSize.Min aligns divider height to tallest sibling in 1 pass!
            Row(modifier = Modifier.height(IntrinsicSize.Min)) {
                Text("Left Column", Modifier.weight(1f))
                VerticalDivider(Modifier.fillMaxHeight())
                Text("Right\nTwo Lines", Modifier.weight(1f))
            }
        }
    }
}

data class Constraints2D(val minW: Int, val maxW: Int, val minH: Int, val maxH: Int)
data class MeasuredBox(val width: Int, val height: Int, val drawOperations: List<String>)

sealed interface LayoutModifierStep {
    fun modifyConstraints(incoming: Constraints2D): Constraints2D = incoming
    fun modifySize(child: MeasuredBox): MeasuredBox = child
}

class SizeModifier(private val sizeDp: Int) : LayoutModifierStep {
    override fun modifyConstraints(incoming: Constraints2D) = Constraints2D(
        minW = sizeDp.coerceIn(incoming.minW, incoming.maxW),
        maxW = sizeDp.coerceIn(incoming.minW, incoming.maxW),
        minH = sizeDp.coerceIn(incoming.minH, incoming.maxH),
        maxH = sizeDp.coerceIn(incoming.minH, incoming.maxH)
    )
}

class PaddingModifier(private val padDp: Int) : LayoutModifierStep {
    override fun modifyConstraints(incoming: Constraints2D) = Constraints2D(
        minW = (incoming.minW - padDp * 2).coerceAtLeast(0),
        maxW = (incoming.maxW - padDp * 2).coerceAtLeast(0),
        minH = (incoming.minH - padDp * 2).coerceAtLeast(0),
        maxH = (incoming.maxH - padDp * 2).coerceAtLeast(0)
    )
    override fun modifySize(child: MeasuredBox) = child.copy(
        width = child.width + padDp * 2,
        height = child.height + padDp * 2
    )
}

class BackgroundModifier(private val colorName: String) : LayoutModifierStep {
    override fun modifySize(child: MeasuredBox) = child.copy(
        drawOperations = listOf("DrawRect($colorName, ${child.width}x${child.height})") + child.drawOperations
    )
}

fun evaluateChain(chain: List<LayoutModifierStep>, rootConstraints: Constraints2D): MeasuredBox {
    val constraintsAtLeaf = chain.fold(rootConstraints) { c, step -> step.modifyConstraints(c) }
    val leafBox = MeasuredBox(constraintsAtLeaf.minW, constraintsAtLeaf.minH, listOf("LeafContent(${constraintsAtLeaf.minW}x${constraintsAtLeaf.minH})"))
    return chain.foldRight(leafBox) { step, box -> step.modifySize(box) }
}

fun main() {
    val root = Constraints2D(0, 400, 0, 800)
    // Case A: padding(16) -> background(Blue) -> size(100)
    val chainA = listOf(PaddingModifier(16), BackgroundModifier("Blue"), SizeModifier(100))
    println("[CHAIN A: padding(16).background(Blue).size(100)] -> ${evaluateChain(chainA, root)}")

    // Case B: size(100) -> background(Blue) -> padding(16)
    val chainB = listOf(SizeModifier(100), BackgroundModifier("Blue"), PaddingModifier(16))
    println("[CHAIN B: size(100).background(Blue).padding(16)] -> ${evaluateChain(chainB, root)}")
}

import androidx.compose.foundation.layout.*
import androidx.compose.material3.*
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier

@Composable
fun EdgeToEdgeCompareBanner(leftText: String, rightText: String) {
    Scaffold(
        contentWindowInsets = WindowInsets.safeDrawing
    ) { innerPadding ->
        Row(
            modifier = Modifier
                .padding(innerPadding)
                .consumeWindowInsets(innerPadding)
                .height(IntrinsicSize.Min)
        ) {
            Text(text = leftText, modifier = Modifier.weight(1f))
            VerticalDivider(modifier = Modifier.fillMaxHeight())
            Text(text = rightText, modifier = Modifier.weight(1f))
        }
    }
}

Why this works: Applying padding(innerPadding) and consumeWindowInsets(innerPadding) prevents downstream composables from double-applying system bar insets, while height(IntrinsicSize.Min) queries the children's minimum intrinsic height prior to measurement so fillMaxHeight() on VerticalDivider bounds to the taller Text.

Quiz 2: Production Architectural Reasoning

Why should senior Compose engineers avoid using 'BoxWithConstraints' (or 'SubcomposeLayout') inside every item of a scrolling feed when a custom 'Layout' or 'Modifier.layout' can achieve the same sizing?

SubcomposeLayout defers child Composition until Layout measurement, blocking background prefetching and adding Slot Table overhead.
BoxWithConstraints remeasures every child hierarchy eight times per frame using exponential O(2^N) intrinsic measurement passes.
SubcomposeLayout disables RenderThread hardware acceleration and forces CPU software Canvas rasterization across Android 15+ devices.
BoxWithConstraints resets its child CompositionLocal scope, preventing children from reading WindowInsets or LocalDensity values properly.
