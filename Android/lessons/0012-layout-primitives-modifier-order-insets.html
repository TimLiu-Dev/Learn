Layout Primitives, Modifier Order & WindowInsets (Edge-to-Edge)

Master Column, Row, Box, Scaffold, modifier chaining order, and Android 15/16+ mandatory edge-to-edge window insets.

Recommended Primary Source
Google Android: Display content edge-to-edge in your app
Official Documentation →

In modern Android (mandatory in Android 15+), applications must draw Edge-to-Edge: your UI renders underneath the transparent system status bar and gesture navigation bar.

🌱 Junior Android Dev Mental Model: Safe Insets vs. Hardcoded Padding

Never hardcode padding(top = 24.dp)! Devices have different camera punch-holes, dynamic islands, and system bars. Use Compose's WindowInsets.safeDrawing or Modifier.safeDrawingPadding() to protect interactive buttons while letting background imagery fill the entire screen.

Modifier Chaining: Order Matters!

Modifiers chain from the outside in. A padding() placed before clickable() expands the touch target or creates outer margins; a padding() placed after clickable() only indents child content inside the clickable bounds.

Interactive Code Practice

Write a composable EdgeToEdgeScaffold(onAction: () -> Unit) that uses Scaffold(contentWindowInsets = WindowInsets.safeDrawing) and applies innerPadding to a Column with Modifier.padding(innerPadding).

🎯 Reference Production Solution 
import androidx.compose.foundation.layout.*
import androidx.compose.material3.*
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier

@Composable
fun EdgeToEdgeScaffold(onAction: () -> Unit) {
    Scaffold(
        contentWindowInsets = WindowInsets.safeDrawing
    ) { innerPadding ->
        Column(
            modifier = Modifier.padding(innerPadding)
        ) {
            Button(onClick = onAction) {
                Text("Proceed")
            }
        }
    }
}

Why this works: Using Scaffold's contentWindowInsets automatically manages system bars and notch cutouts, preventing content from colliding with OS status icons.
