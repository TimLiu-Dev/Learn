Offline-First Repository Pattern (Single Source of Truth)

Architect resilient offline-first data engines where the local database is the Single Source of Truth (SSOT).

Recommended Primary Source
Google Android: Guide to App Architecture - Data Layer & Offline-First
Official Documentation →

In modern high-performance apps, network access is a background synchronization mechanism, not a precondition for rendering UI. If a user opens your app on a subway tunnel or airplane, cached data must render instantly!

🌱 Junior Android Dev Mental Model: Single Source of Truth (SSOT)

The Golden Rule: The UI never observes the network directly. The UI observes the local Room database (which emits cached data instantly in 5ms). In the background, the Repository triggers a network sync. When fresh data arrives, it is saved into Room, which automatically pushes the update to the UI via Flow!

import kotlinx.coroutines.flow.Flow

interface MockDao {
    fun observeAssets(): Flow<List<String>>
    suspend fun upsert(items: List<String>)
}

interface MockApi {
    suspend fun fetch(): List<String>
}

class OfflineAssetRepository(
    private val dao: MockDao,
    private val api: MockApi
) {
    val assetStream: Flow<List<String>> = dao.observeAssets()

    suspend fun refresh() {
        val remote = api.fetch()
        dao.upsert(remote)
    }
}

Why this works: Making the local database the Single Source of Truth ensures the application functions flawlessly offline and renders cached data without waiting for network latency.
