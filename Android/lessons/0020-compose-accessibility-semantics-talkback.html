Compose Accessibility, Semantics & TalkBack

Build inclusive apps using Semantics tree, contentDescription, custom actions, and mergeDescendants.

Recommended Primary Source
Google Android: Accessibility in Jetpack Compose
Official Documentation →

Accessibility is not an afterthought: top-tier companies test accessibility in interviews and production code reviews. Alongside the visual UI tree, Compose maintains a parallel Semantics Tree that communicates UI state to Android's TalkBack screen reader and automated testing harnesses.

🌱 Junior Android Dev Mental Model: Accessibility Checklist
  • Content Description: Never pass contentDescription = null on interactive icons! Screen readers will announce them as "unlabeled button".
  • Touch Targets: Interactive elements must have a minimum touch target size of 48.dp x 48.dp (even if the icon is only 24dp).
  • mergeDescendants: Use Modifier.semantics(mergeDescendants = true) { } on a list item row so TalkBack reads the title, price, and date together as a single coherent sentence.

Write an accessible composable SecureVaultButton(onUnlock: () -> Unit) that renders an IconButton(onClick = onUnlock) containing an Icon with contentDescription = 'Unlock Biometric Vault'.

🎯 Reference Production Solution 
import androidx.compose.material3.*
import androidx.compose.material.icons.Icons
import androidx.compose.material.icons.filled.Lock
import androidx.compose.runtime.Composable

@Composable
fun SecureVaultButton(onUnlock: () -> Unit) {
    IconButton(onClick = onUnlock) {
        Icon(
            imageVector = Icons.Default.Lock,
            contentDescription = "Unlock Biometric Vault"
        )
    }
}

Why this works: Providing explicit contentDescription metadata on interactive buttons allows TalkBack screen readers to describe actions accurately to visually impaired users.
