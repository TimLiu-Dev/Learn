Unified Auth & Trust: Credential Manager & Play Integrity

Implement Passkeys with Credential Manager, retire deprecated EncryptedSharedPreferences, and enforce server-verified Play Integrity.

Recommended Primary Source
Android Developers: Credential Manager & Play Integrity API
Official Documentation →

Modern Android authentication and anti-abuse architecture replaces legacy passwords and fragmented sign-in SDKs with two cryptographic pillars: Jetpack Credential Manager (Passkeys / WebAuthn) and the Play Integrity API. With Credential Manager, a single credentialManager.getCredential(activityContext, request) call presents a unified system bottom sheet aggregating Passkeys (GetPublicKeyCredentialOption), saved passwords (GetPasswordOption), and Sign in with Google (GetGoogleIdOption). Under the hood, a Passkey is an asymmetric FIDO2 / WebAuthn keypair: the private key is sealed inside the user's hardware keystore / credential provider (synced end-to-end encrypted across devices via Google Password Manager), while your backend stores only the public key. During login, your server sends a random single-use challenge; the device signs the challenge with the private key after biometric verification, eliminating phishing and credential stuffing entirely.

However, authenticating who the user is does not prove that the request came from an unmodified binary on a genuine Android device rather than a rooted emulator or a reverse-engineered Python script replaying API calls. The Play Integrity API solves this via hardware-backed attestation. Using StandardIntegrityManager, you warm up an integrity token provider during app startup (prepareIntegrityToken). When executing a sensitive action (login, wire transfer, checkout), you compute a SHA-256 requestHash of the canonical request payload (action + amount + server nonce), request a signed integrity token bound to that hash, and send both to your backend. Your backend decrypts and verifies the token with Google's servers to inspect deviceRecognitionVerdict (MEETS_STRONG_INTEGRITY, MEETS_DEVICE_INTEGRITY), appRecognitionVerdict (PLAY_RECOGNIZED), and confirms that the embedded requestHash matches the actual HTTP body.

🌱 Junior Android Dev Mental Model: Why Client-Side Integrity Checks & Missing requestHash Fail

Never evaluate integrity verdicts inside your Kotlin code, and never pass a static string like "login" as your Play Integrity requestHash! If you don't bind the hash of the exact request payload (including a server nonce or timestamp), an attacker can capture one valid integrity token from a real phone and replay it inside a tampered script to authorize fraudulent transfers.

Senior Interview Trap & Production Edge Case

Trap: Passing applicationContext instead of the foreground Activity context to credentialManager.getCredential(context, request), or forgetting to host /.well-known/assetlinks.json with your Play App Signing SHA-256 certificate fingerprint on your Relying Party domain. Without valid Digital Asset Links, Credential Manager throws GetPublicKeyCredentialDomException (SecurityError).
Edge Case: When a user selects "Cancel" on the Passkey biometric bottom sheet or has no saved credentials on a brand-new phone, Credential Manager throws GetCredentialCancellationException or NoCredentialException. These are expected user flows—not crashes! Handle them explicitly without logging false-positive fatal errors to Crashlytics.

val requestHashHex = sha256Hex(canonicalPayload)

    StandardIntegrityTokenRequest.builder()
        .setRequestHash(requestHashHex)
        .build()
).await()

KOTLIN 2.X PasskeyAndIntegrityVerifier.kt 
import java.security.MessageDigest

data class SignedPasskeyAssertion(val credentialId: String, val clientDataChallenge: String, val signatureHex: String)
data class IntegrityEnvelope(val tokenId: String, val embeddedRequestHash: String, val deviceVerdict: String, val appVerdict: String)

object BackendTrustVerifier {
    fun sha256Hex(input: String): String =
        MessageDigest.getInstance("SHA-256")
            .digest(input.toByteArray())
            .joinToString("") { "%02x".format(it) }

    fun verifyAuthenticatedAction(
        expectedChallenge: String,
        canonicalPayload: String,
        passkey: SignedPasskeyAssertion,
        integrity: IntegrityEnvelope
    ): Result<String> {
        if (passkey.clientDataChallenge != expectedChallenge) {
            return Result.failure(SecurityException("WebAuthn challenge mismatch (replay attempt)"))
        }
        val expectedHash = sha256Hex(canonicalPayload)
        if (integrity.embeddedRequestHash != expectedHash) {
            return Result.failure(SecurityException("Play Integrity requestHash mismatch (payload tampered in transit!)"))
        }
        if (integrity.appVerdict != "PLAY_RECOGNIZED" || !integrity.deviceVerdict.contains("MEETS_DEVICE_INTEGRITY")) {
            return Result.failure(SecurityException("Untrusted environment: ${integrity.appVerdict} / ${integrity.deviceVerdict}"))
        }
        return Result.success("SESSION_ISSUED(cred=${passkey.credentialId}, hash=${expectedHash.take(12)}...)")
    }
}

fun main() {
    val challenge = "srv_nonce_88412"
    val payload = "wire_transfer|acct_99|5000.00|$challenge"
    val validHash = BackendTrustVerifier.sha256Hex(payload)

    val assertion = SignedPasskeyAssertion("passkey_hw_01", challenge, "3045022100ab...")
    val honestEnvelope = IntegrityEnvelope("tok_1", validHash, "MEETS_DEVICE_INTEGRITY,MEETS_STRONG_INTEGRITY", "PLAY_RECOGNIZED")
    println("[BACKEND-VERIFY] Honest request  -> ${BackendTrustVerifier.verifyAuthenticatedAction(challenge, payload, assertion, honestEnvelope)}")

    val tamperedPayload = "wire_transfer|attacker_acct|99999.00|$challenge"
    println("[BACKEND-VERIFY] Tampered replay -> ${BackendTrustVerifier.verifyAuthenticatedAction(challenge, tamperedPayload, assertion, honestEnvelope)}")
}

fun verifyBackendIntegrityVerdict(
    actualPayload: String,
    tokenRequestHash: String,
    appVerdict: String,
    deviceVerdict: String,
    hashFn: (String) -> String
): Result<String> {
    val expectedHash = hashFn(actualPayload)
    if (tokenRequestHash != expectedHash) {
        return Result.failure(SecurityException("HASH_MISMATCH"))
    }
    if (appVerdict != "PLAY_RECOGNIZED" || !deviceVerdict.contains("MEETS_DEVICE_INTEGRITY")) {
        return Result.failure(SecurityException("UNTRUSTED_DEVICE"))
    }
    return Result.success("VERIFIED:$expectedHash")
}

Why this works: Binding the cryptographic digest of the exact action payload to the Play Integrity token and verifying PLAY_RECOGNIZED + MEETS_DEVICE_INTEGRITY on the server stops both tampered APKs and man-in-the-middle token replay attacks.

A mobile engineer integrates the Play Integrity Standard API for a high-value payout endpoint as shown below. How can an attacker on a genuine phone exploit this implementation to drain funds?

suspend fun submitPayout(recipientAccount: String, amountUsd: Double) {

            .setRequestHash(sha256("payout_action")) // <-- Look closely at what is hashed!
            .build()

    api.executePayout(
        recipient = recipientAccount,
        amount = amountUsd,
        integrityToken = integrityToken.token()
    )
}
StandardIntegrityTokenRequest only transmits tokens over unencrypted HTTP connections and fails whenever HTTPS TLS is active.
Hashing a static constant instead of binding recipient, amount, and server nonce enables replay attacks.
Passing a floating-point Double for amountUsd causes Play Integrity to throw a NumberFormatException at runtime.
Calling await() executes token generation on the GPU RenderThread and corrupts the resulting SHA-256 digest.
