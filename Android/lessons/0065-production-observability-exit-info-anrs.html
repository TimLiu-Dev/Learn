Production Observability: ApplicationExitInfo, ANRs & Staged Rollouts

Diagnose silent OOM/LMK kills and ANRs via ApplicationExitInfo, and ship safely using staged rollouts and remote kill switches.

Recommended Primary Source
Android Developers: Android Vitals & ApplicationExitInfo
Official Documentation →

Crashlytics only catches uncaught JVM/native exceptions—it stays silent when Android's Low Memory Killer (LMK) terminates your app or when an ANR kills the process before telemetry flushes. Seniors query ActivityManager.getHistoricalProcessExitReasons() (ApplicationExitInfo) on next cold start to surface exact exit reasons, RSS memory snapshots, and ANR thread dumps, then pair telemetry with Play staged rollouts (1% → 5% → 20% → 100%) and remote kill switches.

🌱 Senior Forensics: What ApplicationExitInfo Reveals

On the launch after an incident, ApplicationExitInfo gives you reason (REASON_ANR, REASON_LOW_MEMORY, REASON_CRASH_NATIVE, REASON_EXCESSIVE_RESOURCE_USAGE), importance (whether the app was foreground or cached!), pss/rss memory footprints, and traceInputStream for ANR/tombstone stacks. Cross-reference with Lesson 0049 and Lesson 0058.

❌ Junior Pitfall: Flying Blind at 100% Rollout

Pushing releases straight to 100% and assuming "0% Crashlytics crashes" means users aren't experiencing ANRs or silent OOM kills.

✅ 2027 Senior Standard: Exit Forensics + Guarded Rollouts

Log ApplicationExitInfo on startup (filtering foreground LMK/ANR exits), gate risky features behind Remote Config, and ramp rollouts incrementally.

2027 Production Standard (Runnable Example)

Click ▶ Run Example to classify historical process exit records and distinguish real foreground regressions from normal OS background trimming:

KOTLIN 2.X ExitReasonAnalyzer.kt 
data class ExitSnapshot(val reason: String, val wasForeground: Boolean, val rssMb: Int)

fun isActionableIncident(exit: ExitSnapshot): Boolean =
    exit.wasForeground && (exit.reason == "REASON_LOW_MEMORY" || exit.reason == "REASON_ANR")

fun main() {
    val exits = listOf(
        ExitSnapshot("REASON_USER_REQUESTED", wasForeground = false, rssMb = 140),
        ExitSnapshot("REASON_LOW_MEMORY", wasForeground = true, rssMb = 912),
        ExitSnapshot("REASON_ANR", wasForeground = true, rssMb = 284)
    )
    exits.forEach { e ->
        if (isActionableIncident(e)) {
            println("[EXIT-AUDIT] Reason=${e.reason} | Foreground=true | RSS=${e.rssMb}MB -> ALERT!")
        } else {
            println("[EXIT-AUDIT] Reason=${e.reason} | Foreground=false -> Benign baseline noise")
        }
    }
    println("[ROLLOUT] Holding Play staged rollout at 5% while investigating foreground ANR spike.")
}

fun latestActionableExit(
    activityManager: ActivityManager,
    pkg: String
): ApplicationExitInfo? =
    activityManager.getHistoricalProcessExitReasons(pkg, 0, 5)
        .firstOrNull {
            it.reason == ApplicationExitInfo.REASON_ANR ||
                it.reason == ApplicationExitInfo.REASON_LOW_MEMORY
        }

Why this works: Querying historical exit reasons on a background dispatcher during app startup uncovers silent OS kills that standard uncaught-exception handlers never see.
