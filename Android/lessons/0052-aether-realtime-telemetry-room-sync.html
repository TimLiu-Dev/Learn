In Lesson 0052, we build the beating heart of Aether's data layer across <code>:core:network</code>, <code>:core:database</code>, and <code>:core:data</code>: a real-time Ktor WebSocket telemetry stream with full-jitter exponential backoff, a Room SQLite database (<code>AssetEntity</code>, <code>PortfolioDao</code>) acting as the Single Source of Truth, and an <code>OfflineFirstPortfolioRepository</code> paired with a <code>WorkManager</code> delta-sync worker.

1. <code>:core:network</code>: Resilient Ktor WebSocket Stream with Conflation & Backoff

Financial markets broadcast dozens of tick frames per second over <code>wss://telemetry.aether.io/v1/stream</code>. If we write every individual 10ms WebSocket frame directly to SQLite on disk, we will thrash the flash storage controller and trigger Room <code>InvalidationTracker</code> storms! Instead, <code>KtorRealtimeMarketDataSource</code> parses incoming <code>Frame.Text</code> JSON ticks via <code>kotlinx.serialization</code>, buffers them inside a <code>callbackFlow</code> / <code>flow</code> using windowed batching or <code>sample(250.milliseconds)</code>, and automatically reconnects using exponential backoff + random jitter on socket drops.

2. <code>:core:database</code> & <code>:core:data</code>: Atomic Room <code>@Upsert</code> SSOT

<code>AssetDao</code> exposes <code>observePortfolioHoldings(): Flow<List<PopulatedHoldingEntity>></code> using <code>@Transaction</code> and <code>@Upsert</code> to batch-write incoming WebSocket price ticks into SQLite inside a single WAL transaction, while <code>AetherSyncWorker</code> (<code>@HiltWorker</code>) reconciles full historical candlesticks in the background when <code>NetworkType.CONNECTED</code> is satisfied.

🌱 Junior Android Dev Mental Model: Why Batch WebSocket Writes to Room?

Every individual Room <code>@Upsert</code> commits a SQLite WAL transaction and notifies <code>InvalidationTracker</code> to re-run active <code>SELECT</code> queries. Grouping high-frequency WebSocket ticks into 250ms micro-batches (<code>chunked</code> / <code>sample</code>) cuts disk I/O and UI recompositions by 95% while still updating prices 4 times per second—faster than human visual perception!

✅ 2027 Senior Production Standard: Micro-Batched Ktor WebSocket + Room SSOT

// :core:data/OfflineFirstPortfolioRepository.kt
class OfflineFirstPortfolioRepository @Inject constructor(
    private val dao: AssetDao,
    private val wsDataSource: KtorRealtimeMarketDataSource
) : PortfolioRepository {

    override val holdings: Flow<List<PortfolioHolding>> =
        dao.observeHoldings().map { list -> list.map(HoldingEntity::asExternalModel) }

    override suspend fun streamLiveTelemetry() =
        wsDataSource.observeTickBatches(windowMs = 250L)
            .retryWhen { cause, attempt ->
                cause is IOException && run {
                    delay( computeJitterBackoffMs(attempt) )
                    true
                }
            }
            .collect { batch ->
                dao.upsertAssetPrices(batch.map(NetworkTickDto::asEntity))
            }
}

⚠️ Senior Interview Trap: Cold vs. Hot Sharing of WebSocket Connections (<code>WhileSubscribed(5_000)</code>)

If two Composables or ViewModels collect a cold WebSocket <code>Flow</code> independently, Ktor opens <strong>two duplicate TCP/TLS WebSocket connections</strong>! Always share the upstream telemetry pipeline in the repository or ViewModel using <code>shareIn(scope, SharingStarted.WhileSubscribed(stopTimeoutMillis = 5_000), replay = 1)</code> so rotating the screen keeps the WebSocket open during the 5-second configuration change window, and backgrounding the app cleanly closes the socket after 5 seconds to save battery.

data class NetworkTickDto(val symbol: String, val priceUsd: Double, val timestampMs: Long)
data class AssetPriceEntity(val symbol: String, val priceUsd: Double, val updatedAtMs: Long)

class AetherRoomDaoSim {
    private val rows = linkedMapOf(
        "BTC" to AssetPriceEntity("BTC", 93000.0, 1000L),
        "ETH" to AssetPriceEntity("ETH", 3100.0, 1000L)
    )
    var transactionCount: Int = 0
        private set

    fun upsertBatchTransaction(entities: List<AssetPriceEntity>) {
        transactionCount++
        for (e in entities) {
            rows[e.symbol] = e
        }
    }

    fun snapshot(): List<AssetPriceEntity> = rows.values.toList()
}

class AetherTelemetryCoordinator(private val dao: AetherRoomDaoSim) {
    fun computeBackoffWithJitterMs(attempt: Int, baseMs: Long = 500L, maxMs: Long = 16_000L): Long {
        val exp = (baseMs * (1L shl attempt.coerceAtMost(5))).coerceAtMost(maxMs)
        val deterministicJitter = (attempt * 137L) % (exp / 2)
        return (exp / 2) + deterministicJitter
    }

    fun ingestMicroBatch(rawTicks: List<NetworkTickDto>) {
        // Deduplicate by symbol within the 250ms window keeping only the newest tick per symbol!
        val latestPerSymbol = rawTicks
            .groupBy { it.symbol }
            .mapValues { (_, ticks) -> ticks.maxBy { it.timestampMs } }
            .values
            .map { AssetPriceEntity(it.symbol, it.priceUsd, it.timestampMs) }
        dao.upsertBatchTransaction(latestPerSymbol)
    }
}

fun main() {
    val dao = AetherRoomDaoSim()
    val coordinator = AetherTelemetryCoordinator(dao)

    val burst250ms = listOf(
        NetworkTickDto("BTC", 93150.0, 1050L),
        NetworkTickDto("BTC", 93420.0, 1120L),
        NetworkTickDto("ETH", 3115.0, 1180L),
        NetworkTickDto("BTC", 93890.0, 1240L)
    )
    coordinator.ingestMicroBatch(burst250ms)
    println("[WEBSOCKET-BATCH] Coalesced ${burst250ms.size} ticks into ${dao.transactionCount} SQLite WAL transaction!")
    println("[SSOT-SNAPSHOT]   ${dao.snapshot()}")
    println("[BACKOFF-JITTER]  Reconnection schedule: ${(0..3).map { "attempt#$it=${coordinator.computeBackoffWithJitterMs(it)}ms" }}")
}

data class PriceTick(
    val symbol: String,
    val priceUsd: Double,
    val timestampMs: Long
)

class TelemetryBatchCoalescer {
    fun coalesceLatestBySymbol(ticks: List<PriceTick>): List<PriceTick> {
        return ticks
            .groupBy { it.symbol }
            .map { (_, symbolTicks) ->
                symbolTicks.maxBy { it.timestampMs }
            }
    }
}

Why this works: When 20 ticks for BTC arrive within a 250ms micro-batch window, intermediate ticks are already obsolete; coalescing by symbol with maxBy { it.timestampMs } minimizes SQLite row updates per batch.

Quiz 1: Code Analysis & Bug Hunt

Examine this Room DAO method in <code>:core:database</code>. When <code>observePortfolioWithTransactions()</code> runs, Room logs a build warning: <code>The query returns some columns [id, symbol] which are not used... and executes a relation query without @Transaction</code>. What runtime bug can happen without <code>@Transaction</code>?

@Dao
interface PortfolioDao {
    // Missing @Transaction on a @Relation query!
    @Query("SELECT * FROM holdings")
    fun observeHoldingsWithHistory(): Flow<List<HoldingWithTrades>>
}
Without the @Transaction annotation, Room always executes relational SELECT queries synchronously on the main UI thread.
Room automatically truncates and deletes all child rows from the trades table when @Transaction is omitted.
The bundled Android SQLite engine rejects wildcard SELECT queries unless the DAO method includes @Transaction metadata.
Room runs two separate SELECT queries for @Relation, so concurrent writes between them emit torn snapshots.

Quiz 2: Production Architectural Reasoning

When 10,000 WebSocket reconnection attempts occur concurrently across 10,000 mobile clients after a brief server deploy, why must your Ktor retry logic include <strong>random jitter</strong> on top of exponential backoff (<code>2^attempt</code>)?

Deterministic backoff synchronizes client retries into thundering herds; random jitter spreads reconnection traffic across time.
Android's Dispatchers.IO thread pool throws an IllegalStateException whenever multiple coroutines call delay with identical durations.
The TLS 1.3 handshake specification requires mobile client connection timestamps to include randomized millisecond offsets.
Adding randomized coroutine delay jitter prevents Room from exclusively locking the local SQLite write-ahead log.
