Jetpack DataStore: Proto DataStore vs Preferences

Replace deprecated SharedPreferences with transactional, non-blocking Preferences DataStore and Proto DataStore.

Recommended Primary Source
Google Android: Working with Jetpack DataStore
Official Documentation →

For over a decade, Android developers used SharedPreferences for key-value storage. In 2026/2027, SharedPreferences is considered legacy and dangerous! SharedPreferences parses XML synchronously on the main thread, causing Application Not Responding (ANR) frame freezes.

🌱 Junior Android Dev Mental Model: Preferences vs Proto DataStore
  • Preferences DataStore: Key-value storage (like SharedPreferences), but 100% asynchronous, transactional, and runs on Kotlin Flow and Coroutines.
  • Proto DataStore (Recommended for Complex Settings): Stores structured typed schema objects backed by Protocol Buffers with compile-time type safety.

🎯 Reference Production Solution 
import androidx.datastore.preferences.core.booleanPreferencesKey

val BIOMETRICS_ENABLED = booleanPreferencesKey("biometrics_enabled")

Why this works: Preferences keys are strongly typed tokens that prevent type-cast errors when reading or writing values in DataStore.
