Kotlin 2.x Context Parameters & Type-Safe DSLs

Eliminate dependency plumbing using Kotlin 2.x context parameters and build expressive UI DSLs with @DslMarker.

Recommended Primary Source
Kotlin Evolution: Context Parameters Specification
Official Documentation →

In complex Android apps, functions frequently require contextual dependencies (e.g., CoroutineScope, ThemeContext, AnalyticsTracker). Passing these as repetitive method arguments pollutes function signatures. Kotlin 2.x introduces Context Parameters (the refined successor to experimental context receivers).

🌱 Junior Android Dev Mental Model: Implicit Environmental Capabilities

Think of a context parameter as an implicit ambient capability. If a function declares context(scope: CoroutineScope), it can only be invoked from within a place where a CoroutineScope is active, preventing accidental calls from outside structured concurrency!

Type-Safe DSLs with @DslMarker

When creating nested builders (like Gradle scripts or Compose layouts), inner lambdas can accidentally access outer receivers, causing subtle configuration bugs. Annotating builder DSLs with @DslMarker instructs the compiler to prohibit implicit calls to outer receivers.

KOTLIN 2.X ContextParametersDsl.kt 
@DslMarker
annotation class LayoutDsl

@LayoutDsl
class ColumnBuilder {
    private val children = mutableListOf<String>()
    
    fun text(content: String) {
        children.add("Text('$content')")
    }
    
    fun render(): String = "Column [ ${children.joinToString(", ")} ]"
}

fun column(block: ColumnBuilder.() -> Unit): String =
    ColumnBuilder().apply(block).render()

fun main() {
    val layout = column {
        text("Welcome to Android 2027")
        text("Powered by Kotlin 2.x K2")
    }
    println("[STATE] Rendered UI Layout Hierarchy:")
    println(layout)
    println("[SUCCESS] Type-safe DSL built cleanly without boilerplate!")
}

@DslMarker
annotation class EventDsl

@EventDsl
class AnalyticsEventBuilder {
    var name: String = ""
    val params = mutableMapOf<String, String>()

    fun param(key: String, value: String) {
        params[key] = value
    }
}

fun trackEvent(block: AnalyticsEventBuilder.() -> Unit): String {
    val builder = AnalyticsEventBuilder().apply(block)
    return "Event: ${builder.name}, Params: ${builder.params}"
}

Why this works: @DslMarker restricts receiver scope resolution inside nested lambdas, preventing developers from mistakenly configuring an outer builder from within an inner component.
