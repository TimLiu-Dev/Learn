🌱 Junior Android Dev Mental Model: Strict Module Contracts
  • :core:model (Pure Kotlin JVM): Immutable domain entities (AssetQuote, Candlestick, PortfolioHolding, VaultSecret) with @Immutable stability markers. Zero Android or third-party annotations.
  • :core:network & :core:database: Internal implementation details (internal class KtorTickerDataSource, internal interface AssetDao) exposed via Hilt bindings to :core:data only.
  • :core:data: Public repository interfaces (MarketRepository, PortfolioRepository, VaultRepository) and offline-first SSOT orchestrators.
  • :feature:market, :feature:portfolio, :feature:vault: Standalone UDF vertical slices (UiState, ViewModel, Compose screens, type-safe @Serializable navigation routes) that never depend on sibling :feature:* modules.

❌ Junior Anti-Pattern: Leaky Monolithic Models

// Putting Room @Entity and Retrofit @SerializedName on the same class
// couples Compose UI directly to SQLite schema and JSON wire changes!
@Entity(tableName = "assets")
data class Asset(
    @PrimaryKey @SerializedName("id") val id: String,
    @ColumnInfo(name = "price") val price: Double
)

✅ 2027 Senior Production Standard: 3-Tier Model Mapping

// 1. :core:network (NetworkAssetDto.kt) -> Wire resilience
@Serializable data class NetworkAssetDto(val id: String, val priceUsd: Double)

// 2. :core:database (AssetEntity.kt) -> SQLite indexing & sync tombstones
@Entity(tableName = "assets") data class AssetEntity(@PrimaryKey val id: String, val priceUsd: Double)

// 3. :core:model (AssetQuote.kt) -> Pure Compose-stable Domain Model
data class AssetQuote(val id: String, val priceUsd: Double)

⚠️ Senior Interview Trap: Enabling TYPESAFE_PROJECT_ACCESSORS

Notice enableFeaturePreview("TYPESAFE_PROJECT_ACCESSORS") in settings.gradle.kts. Instead of fragile string references like implementation(project(":core:designsystem")) that only fail at sync time if misspelled, Gradle generates compile-time type-safe accessors: implementation(projects.core.designsystem)!

🧭 2027 Aether Upgrade: Navigation 3 Adaptive Scenes & UsdMicros

In :app, Aether uses greenfield Jetpack Navigation 3 (rememberNavBackStack + NavDisplay + ListDetailSceneStrategy) so phones render single-pane transitions while foldables and Android 17 tablets (≥ 600dp) automatically display the Market Watchlist and Candlestick Detail panes side-by-side. Across :core:model, monetary amounts use @JvmInline value class UsdMicros(val micros: Long) to prevent floating-point rounding drift.

class AetherSettingsBuilder {
    fun generateSettingsFile(modules: List<String>): String {
        val includes = modules.joinToString("\n") { "include(\"$it\")" }
        return """
            pluginManagement {
                includeBuild("build-logic")
            }
            rootProject.name = "Aether"
            enableFeaturePreview("TYPESAFE_PROJECT_ACCESSORS")
            $includes
        """.trimIndent()
    }
}

Why this works: Combining includeBuild("build-logic") with TYPESAFE_PROJECT_ACCESSORS gives every module in the Aether graph compile-time verified project dependencies and centralized convention plugins.

Quiz 1: Code Analysis & Bug Hunt

Examine this :core:database DAO declaration in the Aether architecture. Why is marking AssetDao and AetherDatabase as internal failsafe without breaking Hilt injection into :core:data?

// Inside :core:database
@Dao
internal interface AssetDao {
    @Query("SELECT * FROM assets")
    fun observeAssets(): Flow<List<AssetEntity>>
}

@Module
@InstallIn(SingletonComponent::class)
internal object DatabaseModule {
    @Provides
    fun provideAssetDao(db: AetherDatabase): AssetDao = db.assetDao()
}
Kotlin's internal visibility modifier exposes declarations to every sibling Gradle subproject sharing the same :core: prefix.
Hilt's annotation processor automatically rewrites internal DAO interfaces into public types inside the :core:data source set.
The Room KSP compiler refuses to generate SQLite implementation classes for public @Dao annotated Kotlin interfaces.
Wait: marking AssetDao internal blocks :core:data from injecting it; only AetherDatabase should be internal, not AssetDao.

Quiz 2: Production Architectural Reasoning

In the Aether architecture, how does :feature:market navigate to :feature:vault when the user taps 'Lock in Hardware Vault' without :feature:market depending on :feature:vault?

MarketRoute in :feature:market exposes an onNavigateToVault callback that :app's AetherNavHost wires to navigate to VaultRoute(assetId).
The :feature:market module calls Class.forName("VaultActivity") through reflection to launch an explicit Android Activity Intent directly.
The :feature:market module persists the requested destination screen inside SQLite while :feature:vault polls database tables.
The shared :core:model module imports androidx.navigation.NavController and executes screen transitions directly inside domain data classes.
