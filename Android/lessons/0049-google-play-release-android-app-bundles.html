Google Play Release & Android App Bundles (AAB)

Prepare production Android App Bundles (.aab), configure Play App Signing, and monitor Android Vitals.

Recommended Primary Source
Google Android: About Android App Bundles
Official Documentation →

Since 2021—and with strict enforcement of 16KB native page alignment and API 35/36 targetSdk mandates in 2026/2027—Google Play requires all production apps to be published as Android App Bundles (<code>.aab</code>) rather than monolithic universal <code>.apk</code> files. Mastering Play App Signing, split APK delivery, native crash symbolication, and staged rollouts is essential for senior release engineering.

Under the Hood: Android App Bundles (<code>.aab</code>) & Dynamic Split APKs

A traditional universal APK bundles every CPU architecture (<code>arm64-v8a</code>, <code>armeabi-v7a</code>, <code>x86_64</code>), every screen density (<code>mdpi</code> through <code>xxxhdpi</code>), and every localized string table into a single bloated download. An <strong>Android App Bundle (<code>.aab</code>)</strong> is a signed publishing archive (containing protocol buffer resource tables <code>resources.pb</code> instead of binary <code>resources.arsc</code>) that cannot be installed directly on a device. Instead, Google Play's <code>bundletool</code> uses your <code>.aab</code> to generate and sign optimized <strong>Split APKs</strong> tailored to the exact requesting device:

  • Base APK (<code>base-master.apk</code>): Core code and shared non-config resources.
  • ABI Configuration Split (<code>base-arm64_v8a.apk</code>): Only the native <code>.so</code> libraries for the user's exact CPU architecture (saving 15–40MB!).
  • Density Configuration Split (<code>base-xxhdpi.apk</code>): Only drawables matching the device's display density.
  • Language Split (<code>base-en.apk</code>, <code>base-ja.apk</code>): Only the user's active system locales.
🌱 Junior Android Dev Mental Model: Upload Key vs. App Signing Key

With Play App Signing, there are two cryptographic keys: (1) the App Signing Key (held inside Google's cloud HSM hardware, used to sign the final Split APKs delivered to users' phones), and (2) your Upload Key (used by your GitHub Actions CI pipeline to sign the <code>.aab</code> uploaded to Play Console). If your Upload Key is ever compromised or lost, an admin can revoke and reset the Upload Key in Play Console without ever losing ability to update your existing app!

❌ Junior Anti-Pattern: 100% Rollout Without Symbols or Versioning

// Static versionCode fails Play upload on the second release!
// Missing native debug symbols leaves C++/RenderThread crashes unreadable!
android {
    defaultConfig {
        versionCode = 1
        versionName = "1.0"
    }
}

✅ 2027 Senior Production Standard: CI VersionCode + Full Debug Symbols

android {
    defaultConfig {
        // Monotonically increasing CI run number or semantic integer (MAJ*10000 + MIN*100 + PATCH)
        versionCode = System.getenv("CI_RUN_NUMBER")?.toIntOrNull() ?: 10000
        versionName = "1.4.2"
        ndk {
            // Bundles unstripped .so symbols into AAB for Play Vitals symbolication!
            debugSymbolLevel = "FULL"
        }
    }
}

⚠️ Senior Interview Trap: Android 15/16 16KB Page Size Alignment & Staged Rollouts

Starting with Android 15+ and Google Play's 2026+ policy enforcement, flagship ARM64 devices configure the Linux kernel with <strong>16KB memory pages</strong> instead of legacy 4KB pages for 5–10% higher system throughput. Any app packaging native <code>.so</code> libraries (such as SQLCipher, Ktor/Cronet engines, or image decoders) must compile with <strong>AGP 8.5.1+ / NDK r27+</strong> so ELF segments are aligned on 16KB (<code>0x4000</code>) boundaries—otherwise the app immediately crashes on launch on 16KB devices with <code>dlopen failed: empty/missing DT_HASH/ELF alignment</code>! Always deploy production releases using a <strong>Staged Rollout</strong> (1% → 5% → 20% → 100%) while monitoring <strong>Android Vitals</strong> crash-free user rate (> 99.5%) and ANR rate (< 0.47%).

data class DeviceProfile(val model: String, val abi: String, val density: String, val locale: String, val pageSizeKb: Int)
data class AabModuleSlice(val name: String, val category: String, val targetKey: String, val sizeKb: Int)

class PlayBundleToolSimulator(private val aabSlices: List<AabModuleSlice>, private val elf16KbAligned: Boolean) {
    fun buildDeviceApks(device: DeviceProfile): String {
        if (device.pageSizeKb == 16 && !elf16KbAligned) {
            return "❌ [INSTALL-FAIL] ${device.model} uses 16KB memory pages, but native .so ELF segments are 4KB-aligned!"
        }
        val selected = aabSlices.filter { slice ->
            slice.category == "base" ||
                (slice.category == "abi" && slice.targetKey == device.abi) ||
                (slice.category == "density" && slice.targetKey == device.density) ||
                (slice.category == "lang" && slice.targetKey == device.locale)
        }
        val totalUniversalKb = aabSlices.sumOf { it.sizeKb }
        val splitKb = selected.sumOf { it.sizeKb }
        val savedPercent = ((totalUniversalKb - splitKb) * 100) / totalUniversalKb
        return "✅ [SPLIT-APK] ${device.model}: Delivered ${selected.map { it.name }} = ${splitKb}KB " +
            "(Saved $savedPercent% vs ${totalUniversalKb}KB Universal APK)"
    }
}

fun main() {
    val aabContents = listOf(
        AabModuleSlice("base-master.apk", "base", "all", 4200),
        AabModuleSlice("base-arm64_v8a.apk", "abi", "arm64-v8a", 6800),
        AabModuleSlice("base-x86_64.apk", "abi", "x86_64", 7400),
        AabModuleSlice("base-armeabi_v7a.apk", "abi", "armeabi-v7a", 5900),
        AabModuleSlice("base-xxxhdpi.apk", "density", "xxxhdpi", 3100),
        AabModuleSlice("base-xhdpi.apk", "density", "xhdpi", 1900),
        AabModuleSlice("base-en.apk", "lang", "en", 450),
        AabModuleSlice("base-ja.apk", "lang", "ja", 520)
    )

    val pixel10Pro = DeviceProfile("Pixel 10 Pro", abi = "arm64-v8a", density = "xxxhdpi", locale = "en", pageSizeKb = 16)
    val simAligned = PlayBundleToolSimulator(aabContents, elf16KbAligned = true)
    val simLegacy = PlayBundleToolSimulator(aabContents, elf16KbAligned = false)

    println(simLegacy.buildDeviceApks(pixel10Pro))
    println(simAligned.buildDeviceApks(pixel10Pro))
}

enum class RolloutDecision {
    PROMOTE_NEXT_STAGE,
    HALT_AND_ROLLBACK
}

class PlayVitalsRolloutGate {
    companion object {
        const val PLAY_BAD_CRASH_THRESHOLD_PERCENT = 1.09
        const val PLAY_BAD_ANR_THRESHOLD_PERCENT = 0.47
    }

    fun evaluateStagedRollout(
        crashRatePercent: Double,
        anrRatePercent: Double
    ): RolloutDecision {
        return if (
            crashRatePercent >= PLAY_BAD_CRASH_THRESHOLD_PERCENT ||
            anrRatePercent >= PLAY_BAD_ANR_THRESHOLD_PERCENT
        ) {
            RolloutDecision.HALT_AND_ROLLBACK
        } else {
            RolloutDecision.PROMOTE_NEXT_STAGE
        }
    }
}

Why this works: Google Play Console enforces strict Android Vitals bad-behavior thresholds (1.09% user-perceived crash rate and 0.47% user-perceived ANR rate); exceeding them penalizes Play Store discovery and search ranking.
