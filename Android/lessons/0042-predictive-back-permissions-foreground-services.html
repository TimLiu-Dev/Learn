Predictive Back, Modern Permissions & Foreground Service Types

Replace broken legacy back overrides, drop broad storage permissions with Photo Picker, and declare compliant typed Foreground Services.

Recommended Primary Source
Android Developers: Add Support for the Predictive Back Gesture
Official Documentation →

Targeting Android 15, 16, and 17 (API 35–37) requires adapting to three strict OS system boundary changes: Predictive Back Gestures, Zero-Permission System Photo Picker, and Typed Foreground Services with Runtime Quotas. Historically, Android did not know whether an app would consume the back button until after the user lifted their finger and Activity.onBackPressed() returned. To render smooth cross-activity and back-to-home preview animations as the user swipes inward from the screen edge, Android replaced imperative back interception with an ahead-of-time registration model via OnBackPressedDispatcher and Compose's BackHandler / PredictiveBackHandler.

In Compose, PredictiveBackHandler(enabled: Boolean) delivers a cold Flow<BackEventCompat> emitting real-time touch coordinates and normalized progress (0.0f..1.0f) as the user drags their finger. If the user completes the swipe, the flow finishes normally and you commit the navigation/dismissal; if the user flings their finger back toward the screen edge to cancel the gesture, the flow throws CancellationException so you can snap your UI back to 0f! Simultaneously, Google Play policy strictly rejects apps that request broad READ_MEDIA_IMAGES / READ_MEDIA_VIDEO permissions for one-off uploads (requiring ActivityResultContracts.PickVisualMedia instead), and Android 15/16+ mandates explicit android:foregroundServiceType declarations (with a strict 6-hour per 24-hour runtime limit on dataSync and mediaProcessing Foreground Services before throwing ForegroundServiceStartNotAllowedException).

🌱 Junior Android Dev Mental Model: Why BackHandler(enabled = true) Breaks Predictive Back

If you write BackHandler(enabled = true) { if (hasUnsavedText) showDialog() else navController.popBackStack() }, you tell the Android OS that your custom handler always intercepts the back gesture—which disables the system back-to-home animation even when the form is clean! Always bind enabled = hasUnsavedText reactively so your handler is disabled whenever the OS should own the transition.

Senior Interview Trap & Production Edge Case

Trap: Forgetting to catch CancellationException inside PredictiveBackHandler { progressFlow -> ... }. If you modify a drawer offset or dialog scale while collecting progressFlow and do not reset that state inside catch (e: CancellationException), cancelling a half-swiped back gesture leaves your UI permanently stuck at 50% scale!
Edge Case: Starting a Foreground Service from the background (or failing to call ServiceCompat.startForeground(service, id, notification, FOREGROUND_SERVICE_TYPE_LOCATION) within 5–10 seconds with the matching runtime permission granted) crashes immediately with ForegroundServiceDidNotStartInTimeException or SecurityException.

❌ Junior Anti-Pattern: Always-Enabled BackHandler & Missing Cancel

// 1. Always enabled = true breaks OS back-to-home preview!
// 2. No try/catch(CancellationException) leaves scale stuck if user cancels swipe!
var cardScale by remember { mutableFloatStateOf(1f) }
PredictiveBackHandler(enabled = true) { progress ->
    progress.collect { event ->
        cardScale = 1f - (event.progress * 0.15f)
    }
    onDismissSheet()
}

✅ 2027 Senior Standard: Reactive Enabled & Cancellation Reset

var cardScale by remember { mutableFloatStateOf(1f) }
PredictiveBackHandler(enabled = uiState.hasUnsavedEdits) { progress ->
    try {
        progress.collect { backEvent ->
            cardScale = 1f - (backEvent.progress * 0.15f)
        }
        cardScale = 1f
        onShowUnsavedChangesDialog()
    } catch (e: CancellationException) {
        cardScale = 1f // User aborted gesture -> restore UI cleanly!
        throw e
    }
}

import kotlin.coroutines.cancellation.CancellationException

data class BackSwipeSample(val progress: Float, val swipeEdge: Int = 0)

class PredictiveSheetController(val hasUnsavedChanges: Boolean) {
    var scale: Float = 1.0f
        private set
    var confirmDialogVisible: Boolean = false
        private set

    fun handleSwipeStream(events: List<BackSwipeSample>, cancelledByUser: Boolean): String {
        if (!hasUnsavedChanges) {
            return "OS_HANDLED_BACK_TO_HOME_ANIMATION (Interceptor disabled ahead-of-time)"
        }
        return try {
            for (event in events) {
                scale = 1.0f - (event.progress.coerceIn(0f, 1f) * 0.2f)
            }
            if (cancelledByUser) throw CancellationException("User flung back to screen edge")
            scale = 1.0f
            confirmDialogVisible = true
            "COMMITTED_CUSTOM_BACK (confirmDialogVisible=$confirmDialogVisible, scale=$scale)"
        } catch (e: CancellationException) {
            scale = 1.0f
            "GESTURE_CANCELLED_CLEANLY (restored scale=$scale, dialog=$confirmDialogVisible)"
        }
    }
}

fun main() {
    val cleanScreen = PredictiveSheetController(hasUnsavedChanges = false)
    println("[CLEAN-FORM] ${cleanScreen.handleSwipeStream(listOf(BackSwipeSample(0.5f)), false)}")

    val dirtyCancel = PredictiveSheetController(hasUnsavedChanges = true)
    println("[ABORT-SWIPE] ${dirtyCancel.handleSwipeStream(listOf(BackSwipeSample(0.3f), BackSwipeSample(0.6f)), cancelledByUser = true)}")

    val dirtyCommit = PredictiveSheetController(hasUnsavedChanges = true)
    println("[COMMIT-SWIPE] ${dirtyCommit.handleSwipeStream(listOf(BackSwipeSample(0.4f), BackSwipeSample(0.9f)), cancelledByUser = false)}")
}

fun computePredictiveScale(progress: Float, cancelled: Boolean): Float {
    if (cancelled) return 1.0f
    return 1.0f - (progress.coerceIn(0f, 1f) * 0.15f)
}

fun validateFgsStart(
    serviceType: String,
    runtimeHoursLast24h: Double,
    isAppInForeground: Boolean
): Result<String> {
    if (!isAppInForeground) {
        return Result.failure(IllegalStateException("ForegroundServiceStartNotAllowedException: App in background"))
    }
    if (serviceType in setOf("dataSync", "mediaProcessing") && runtimeHoursLast24h >= 6.0) {
        return Result.failure(IllegalStateException("6-hour FGS quota exceeded for $serviceType"))
    }
    return Result.success("FGS_ALLOWED:$serviceType")
}

Why this works: Resetting UI scale on gesture cancellation keeps Predictive Back fluid, while respecting Android 15/16's foreground start requirement and 6-hour dataSync/mediaProcessing timeout prevents production ForegroundService crashes.

@Composable
fun MarketSearchScreen(query: String, onClearQuery: () -> Unit, onNavigateUp: () -> Unit) {
    BackHandler(enabled = true) {
        if (query.isNotEmpty()) {
            onClearQuery()
        } else {
            onNavigateUp()
        }
    }
}
PredictiveBackHandler only registers callbacks inside legacy XML Fragments and is completely ignored within Composable screens.
Invoking onClearQuery() inside the back handler callback throws a fatal ConcurrentModificationException on the UI thread.
Android 16 requires invoking System.exit(0) manually inside the gesture collector to trigger system back-to-home animations.
Hardcoding enabled to true intercepts every gesture and blocks system back-to-home previews; bind query.isNotEmpty() instead.
