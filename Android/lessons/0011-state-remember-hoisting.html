State in Compose: remember, rememberSaveable & Hoisting

Master mutableStateOf, state survival across recomposition and configuration changes, and state hoisting.

Recommended Primary Source
Google Android: State and Jetpack Compose
Official Documentation →

Compose UI does not automatically update when regular variables change. To trigger recomposition, you must wrap values in a MutableState (via mutableStateOf) and retain them across recompositions using remember.

🌱 Junior Android Dev Mental Model: remember vs. rememberSaveable
  • remember { mutableStateOf(0) }: Survives recomposition only. If the user rotates the device, the count resets to 0!
  • rememberSaveable { mutableStateOf(0) }: Survives both recomposition AND configuration changes/process death via Android's SavedStateRegistry.

🎯 Reference Production Solution 
import androidx.compose.runtime.*
import androidx.compose.runtime.saveable.rememberSaveable

@Composable
fun CounterContainer() {
    var count by rememberSaveable { mutableStateOf(0) }
    CounterDisplay(count = count, onIncrement = { count++ })
}

@Composable
fun CounterDisplay(count: Int, onIncrement: () -> Unit) {
    // Stateless display component
}

Why this works: State hoisting moves state to the caller, making CounterDisplay a pure function that is easy to preview and unit test without maintaining internal mutable state.
