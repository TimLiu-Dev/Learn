Design System & Theming with Material 3 Expressive

Implement Material You dynamic color, dark/light modes, custom design tokens, and CompositionLocal.

Recommended Primary Source
Google Android: Material 3 in Jetpack Compose
Official Documentation →

In 2027 Android applications, visual identity is built on Material 3 Expressive paired with a custom semantic Design Token System. On Android 12+ (API 31+), M3 supports Dynamic Color (dynamicDarkColorScheme(context) / dynamicLightColorScheme(context)), which uses the CAM16 and HCT (Hue-Chroma-Tone) perceptually uniform color space (MaterialKolor / Monet engine) to extract a seed color from the user's wallpaper and generate accessible tonal palettes with guaranteed contrast ratios across primary, onPrimary, PrimaryContainer, and surfaceContainerHigh roles.

How does MaterialTheme.colorScheme.primary reach a deeply nested Button 15 levels down the UI tree without passing colorScheme as a function parameter through every intermediate Composable? Through CompositionLocal—Compose's lexical, tree-scoped implicit dependency mechanism stored directly in the Slot Table!

🌱 Junior Android Dev Mental Model: Semantic Roles Over Hardcoded Hex Colors

Never write Color(0xFF1E88E5) or 16.dp directly inside feature screens! Hardcoded colors break dark mode, high-contrast accessibility modes, and wallpaper dynamic theming. Always reference semantic tokens (MaterialTheme.colorScheme.surfaceContainerLow, AppTheme.spacing.medium) so switching themes updates the entire app automatically.

🔥 Senior Interview Trap: compositionLocalOf vs. staticCompositionLocalOf!

One of the most frequent Senior Compose interview questions is: "What is the exact runtime difference between compositionLocalOf and staticCompositionLocalOf, and what happens if you pick the wrong one?"

  • compositionLocalOf { ... } (Dynamic / Fine-Grained Tracking): Compose tracks every individual @Composable scope that reads .current in the Slot Table. When the provided value in CompositionLocalProvider(LocalToken provides newValue) changes, ONLY the specific Composables that called LocalToken.current are recomposed! However, maintaining those fine-grained subscription edges in the Slot Table carries a small bookkeeping cost. Use this for values that CAN change dynamically at runtime (e.g., dynamic theme colors, user locale overrides, or elevation levels).
  • staticCompositionLocalOf { ... } (Static / Zero Read-Tracking Overhead): Compose performs zero read tracking when .current is accessed! That makes reads ultra-cheap. The Catch: If the provided value *ever* changes, Compose has no record of which children read it, so it invalidates and recomposes the ENTIRE CompositionLocalProvider content subtree from scratch! Use staticCompositionLocalOf ONLY for dependencies that rarely or never change (e.g., LocalContext, LocalHapticFeedback, LocalSpacing layout constants, or LocalAnalytics).

❌ Junior Anti-Pattern: staticCompositionLocalOf for Rapidly Changing Values

// BUG: Using staticCompositionLocalOf for a rapidly changing
// scroll-driven elevation or live theme accent color!
val LocalLiveAccentColor = staticCompositionLocalOf { Color.Blue }

@Composable
fun AppRoot(liveColor: Color) {
    // Every time liveColor changes, 100% of the entire app tree
    // inside CompositionLocalProvider is torn down and recomposed!
    CompositionLocalProvider(LocalLiveAccentColor provides liveColor) {
        MainAppNavigationTree()
    }
}

✅ 2027 Senior Standard: Split Static Structural Tokens vs. Dynamic Color Tokens

@Immutable
data class AppSpacing(val small: Dp = 8.dp, val medium: Dp = 16.dp, val large: Dp = 24.dp)

// Spacing constants never change at runtime -> staticCompositionLocalOf (0 tracking cost)
val LocalAppSpacing = staticCompositionLocalOf { AppSpacing() }

// Brand palette switches with dark mode / user tier -> compositionLocalOf (targeted recomposition)
val LocalBrandColors = compositionLocalOf { DefaultBrandColors }

object AppTheme {
    val spacing: AppSpacing @Composable @ReadOnlyComposable get() = LocalAppSpacing.current
    val brandColors: BrandColors @Composable @ReadOnlyComposable get() = LocalBrandColors.current
}

enum class LocalTrackingPolicy { DYNAMIC_TRACKED, STATIC_UNTRACKED }

class SimulatedCompositionLocal<T>(
    val name: String,
    val policy: LocalTrackingPolicy,
    initialValue: T
) {
    var currentValue: T = initialValue
        private set
    private val subscribedNodes = mutableSetOf<String>()

    fun readInNode(nodeName: String): T {
        if (policy == LocalTrackingPolicy.DYNAMIC_TRACKED) {
            subscribedNodes.add(nodeName)
        }
        return currentValue
    }

    fun provideNewValue(newValue: T, allSubtreeNodes: List<String>): List<String> {
        if (currentValue == newValue) return emptyList()
        currentValue = newValue
        return when (policy) {
            LocalTrackingPolicy.DYNAMIC_TRACKED -> subscribedNodes.toList()
            LocalTrackingPolicy.STATIC_UNTRACKED -> allSubtreeNodes // Recomposes ENTIRE subtree!
        }
    }
}

fun main() {
    val subtree = listOf("RootScaffold", "TopBar", "FeedList", "FeedItem_1", "FeedItem_2", "AccentBadge")
    val dynamicColorLocal = SimulatedCompositionLocal("LocalAccentColor", LocalTrackingPolicy.DYNAMIC_TRACKED, "Blue")
    val staticSpacingLocal = SimulatedCompositionLocal("LocalSpacing", LocalTrackingPolicy.STATIC_UNTRACKED, 16)

    // Only AccentBadge reads LocalAccentColor.current
    dynamicColorLocal.readInNode("AccentBadge")
    staticSpacingLocal.readInNode("AccentBadge")

    val recomposedOnColorChange = dynamicColorLocal.provideNewValue("Emerald", subtree)
    println("[compositionLocalOf update] Recomposed nodes (${recomposedOnColorChange.size}/${subtree.size}): $recomposedOnColorChange")

    val recomposedOnStaticChange = staticSpacingLocal.provideNewValue(20, subtree)
    println("[staticCompositionLocalOf update] Recomposed nodes (${recomposedOnStaticChange.size}/${subtree.size}): $recomposedOnStaticChange")
}

import androidx.compose.runtime.*

@Immutable
data class ElevationTokens(val card: Int = 2, val modal: Int = 8)

val LocalElevationTokens = staticCompositionLocalOf {
    ElevationTokens()
}

@Composable
fun AppDesignTheme(
    tokens: ElevationTokens = ElevationTokens(),
    content: @Composable () -> Unit
) {
    CompositionLocalProvider(
        LocalElevationTokens provides tokens
    ) {
        content()
    }
}

Why this works: Marking ElevationTokens with @Immutable guarantees stability to the Compose compiler, staticCompositionLocalOf avoids read-tracking overhead in the Slot Table for unchanging design metrics, and CompositionLocalProvider scopes the tokens cleanly to the subtree.

Quiz 1: Code Analysis & Bug Hunt

A team stores the current audio playback timestamp (updating every 50ms) inside a staticCompositionLocalOf and provides it at the root of the screen so a tiny mini-player bar at the bottom can read it. What happens during playback?

val LocalPlaybackMillis = staticCompositionLocalOf { 0L }

@Composable
fun MusicAppScreen(currentMillis: Long) {
    CompositionLocalProvider(LocalPlaybackMillis provides currentMillis) {
        AlbumArtHeader()
        PlaylistTrackLazyColumn()
        MiniPlayerProgressBar() // Only composable that reads LocalPlaybackMillis.current!
    }
}
Only MiniPlayerProgressBar recomposes every 50ms because staticCompositionLocalOf registers fine-grained Snapshot state observers on reader nodes.
MiniPlayerProgressBar never updates during playback because staticCompositionLocalOf permanently ignores all value changes after initial composition.
Composition crashes immediately with IllegalStateException whenever a primitive Long timestamp is provided through root CompositionLocalProvider.
Every 50ms, the entire CompositionLocalProvider subtree recomposes because staticCompositionLocalOf never tracks individual child .current reads.

Quiz 2: Production Architectural Reasoning

Why should custom theme accessor properties on an object (e.g., object AppTheme { val spacing: AppSpacing @Composable @ReadOnlyComposable get() = LocalAppSpacing.current }) be annotated with '@ReadOnlyComposable'?

@ReadOnlyComposable prevents generating synthetic startRestartGroup calls, eliminating Slot Table group overhead for read-only theme getters.
@ReadOnlyComposable enforces deep compile-time immutability, preventing callers from mutating var properties on returned theme objects.
@ReadOnlyComposable removes the synthetic Composer parameters, allowing theme properties direct access inside non-composable ViewModel methods.
@ReadOnlyComposable automatically serializes and caches resolved theme tokens inside encrypted SharedPreferences storage across process restarts.
