Advanced Hilt: Qualifiers, Scopes & Test Injections

Differentiate duplicate dependencies with @Qualifier, control lifecycles with Scopes, and swap test fakes with @TestInstallIn.

Recommended Primary Source
Google Android: Testing with Hilt & Qualifiers
Official Documentation →

When you have multiple bindings of the same type (e.g. CoroutineDispatcher for IO vs Default, or Staging vs Production HTTP base URLs), Hilt throws a duplicate binding error. You resolve this using custom @Qualifier annotations.

🌱 Junior Android Dev Mental Model: Test Injection with @TestInstallIn

In integration tests, you don't want to make real network calls! @TestInstallIn(components = [SingletonComponent::class], replaces = [ProductionNetworkModule::class]) instructs Hilt to swap the real network module with a test fake automatically across your test suite!

🎯 Reference Production Solution 
import javax.inject.Qualifier

@Qualifier
@Retention(AnnotationRetention.BINARY)
annotation class IoDispatcher

Why this works: @Qualifier annotations disambiguate between multiple implementations of the same type without relying on fragile string names.
