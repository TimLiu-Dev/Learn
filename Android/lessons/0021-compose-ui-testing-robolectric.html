Compose UI Testing with Robolectric & ComposeTestRule

Write blazing-fast headless UI unit tests under 500ms using createComposeRule and Robolectric.

Recommended Primary Source
Google Android: Testing your Jetpack Compose layout

In legacy Android, UI tests required launching a slow Android emulator (taking minutes). In Modern Android, you write Robolectric headless Compose tests that execute directly on your local workstation's JVM in under 500 milliseconds!

🌱 Junior Android Dev Mental Model: Finders, Actions, Assertions

Compose UI tests follow the standard AAA pattern using the Semantics Tree:

  1. Finder: composeTestRule.onNodeWithText("Sign In") or onNodeWithTag("login_btn")
  2. Action: .performClick(), .performTextInput("alice")
  3. Assertion: .assertIsDisplayed(), .assertTextEquals("Welcome, Alice")
Because testing queries the Semantics Tree, writing accessible apps automatically makes your app easy to test!

fun testButtonClick(rule: MockTestRule) {
    rule.onNodeWithText("Increment").performClick()
    rule.onNodeWithText("Count: 1").assertIsDisplayed()
}

Why this works: ComposeTestRule queries the accessibility semantics tree to interact with components exactly as a user or screen reader would, making tests robust against refactoring.
