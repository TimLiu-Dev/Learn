Compose Multiplatform (CMP) & On-Device AI (Gemini Nano)

Evaluate shared Compose UI via Compose Multiplatform and integrate privacy-first on-device GenAI with graceful capability fallbacks.

With your Compose expertise (Lessons 0010–0021), Compose Multiplatform (CMP) lets you share declarative UI screens across Android, iOS, and Desktop using the same Skia renderer, Material 3 components, and multiplatform resources. Meanwhile, on Android devices equipped with AICore / Gemini Nano (or ML Kit GenAI APIs), apps can summarize notes, classify intents, or draft replies locally with zero cloud token cost—provided you always verify hardware availability and define a fallback.

🌱 Senior Tradeoff: Shared UI vs. Platform-Native Feel & AI Fallbacks

CMP Decision: Share UI with CMP when brand consistency and feature velocity across Android/iOS beat deep Apple-specific UIKit fidelity (still wrap native maps, camera, or Passkey sheets with platform hooks).
Gemini Nano Rule: Never assume AICore is downloaded or supported on every budget device! Check checkFeatureStatus() first and degrade gracefully to cloud inference or deterministic UI.

❌ Junior Pitfall: Hard-Requiring On-Device Models

Calling Gemini Nano unconditionally (crashing on unsupported devices) or bundling multi-gigabyte weights directly inside your Play AAB.

✅ 2027 Senior Standard: Capability Probe + Strategy

Probe AICore feature availability via an interface in commonMain, stream tokens via Flow<String>, and fall back cleanly when unavailable.

2027 Production Standard (Runnable Example)

KOTLIN 2.X OnDeviceAiRouter.kt 
enum class AiCapability { AVAILABLE, DOWNLOADABLE, UNAVAILABLE }

fun selectSummarizer(status: AiCapability): String = when (status) {
    AiCapability.AVAILABLE -> "GeminiNanoLocalSummarizer"
    AiCapability.DOWNLOADABLE -> "TriggerModelDownloadThenLocal"
    AiCapability.UNAVAILABLE -> "CloudFallbackSummarizer"
}

fun main() {
    println("[AI-ROUTER] Probing AICore Gemini Nano availability...")
    println("[AI-ROUTER] Status = AVAILABLE (Pixel/Flagship AICore ready)")
    println("[GEMINI-NANO] Streaming local summary (0 bytes sent to cloud, 42ms latency)...")
    println("[SUMMARY] Portfolio up +4.2% today; BTC weight exceeds target cap.")
    println("[AI-ROUTER] Probing budget device -> Status = UNAVAILABLE -> Routing cleanly to ${selectSummarizer(AiCapability.UNAVAILABLE)}!")
}

🎯 Reference Production Solution 
suspend fun summarizeSafely(
    probe: suspend () -> Boolean,
    localAi: suspend (String) -> String,
    cloudFallback: suspend (String) -> String,
    text: String
): String = if (probe()) localAi(text) else cloudFallback(text)

Why this works: Hardware capabilities vary widely across the Android ecosystem; probing at runtime keeps your app resilient on every device tier.
