Asynchronous Flow: Cold Streams & Transformation

Build reactive pipelines with backpressure management, debounce, and in-flight request cancellation.

Kotlin Coroutines: Asynchronous Flow Guide

While suspend functions return a single value asynchronously, Kotlin Flow emits multiple sequentially calculated values over time. A standard Flow is Cold: the producer code inside flow { ... } does not even begin executing until a terminal operator (like collect) is invoked.

🌱 Junior Android Dev Mental Model: Instant Search without Race Conditions

When a user rapidly types "Android", you don't want 7 simultaneous network requests firing and returning out-of-order! By combining debounce(300L), distinctUntilChanged(), and flatMapLatest, previous in-flight network searches are cancelled instantly when new input arrives.

KOTLIN 2.X ColdFlowPipeline.kt 
import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

fun sampleSearchStream(): Flow<String> = flow {
    emit("A")
    delay(50L)
    emit("And")
    delay(50L)
    emit("Android")
    delay(350L) // User pauses typing!
    emit("Android 2027")
}

fun main() = runBlocking {
    println("[LOG] Starting search flow debounce pipeline...")
    
    sampleSearchStream()
        .debounce(200L) // Only emit if 200ms pass without another emission
        .map { it.uppercase() }
        .collect { query ->
            println("[STATE] Executing API query for: '$query'")
        }

    println("[SUCCESS] Search stream debounced intermediate keystrokes cleanly!")
}

🎯 Reference Production Solution 
import kotlinx.coroutines.flow.*

fun processQueryFlow(input: Flow<String>): Flow<String> =
    input
        .map { it.trim() }
        .filter { it.isNotBlank() }
        .distinctUntilChanged()
        .map { it.lowercase() }

Why this works: Cold flow pipelines are lazy and compose cleanly; distinctUntilChanged prevents duplicate downstream requests, reducing network usage and battery consumption.
