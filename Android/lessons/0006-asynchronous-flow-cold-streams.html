Asynchronous Flow: Cold Streams & Transformation

Build reactive pipelines with backpressure management, debounce, and in-flight request cancellation.

Recommended Primary Source
Kotlin Coroutines: Asynchronous Flow Guide
Official Documentation →

A standard Kotlin Flow<T> is a cold asynchronous stream backed by suspending functions. "Cold" means the builder block inside flow { ... } is completely inert until a terminal operator (such as collect, first, or toList) is invoked—and every new collector triggers an independent execution of the upstream producer from scratch. Under the hood, a cold Flow is remarkably lightweight: just two interfaces (Flow<T> with suspend fun collect(collector: FlowCollector<T>) and FlowCollector<T> with suspend fun emit(value: T)).

Because both collect and emit are suspend functions, backpressure is handled automatically without reactive boilerplate. If a downstream collector takes 100ms to process an emitted item while the upstream producer generates items every 10ms, the producer's call to emit(item) simply suspends until the collector finishes processing!

🌱 Junior Android Dev Mental Model: Context Preservation & flowOn

A Flow enforces Context Preservation: you are forbidden from calling emit() from a different CoroutineContext than the collector (so wrapping withContext(Dispatchers.IO) { emit(data) } inside flow { ... } crashes with IllegalStateException: Flow invariant is violated!). To move upstream work to a background thread, always apply .flowOn(Dispatchers.IO)—which affects only operators above it in the chain.

High-Performance Flow Operators & FuseableFlow

  • flatMapLatest / mapLatest / collectLatest: Essential for search bars and user filter switches. When a new upstream item arrives, the active downstream coroutine for the previous item is immediately cancelled at its next suspension point.
  • buffer() vs conflate(): By default, producer and collector run sequentially in the same coroutine (ping-pong execution). Adding .buffer() splits the upstream into a separate coroutine communicating over a Channel, running producer and consumer concurrently. .conflate() is shorthand for buffer(Channel.CONFLATED)—dropping intermediate values when the collector is busy so it always receives the latest emitted item.
  • callbackFlow: Bridges legacy callback/listener Android APIs (e.g., LocationManager, ConnectivityManager.NetworkCallback, Firebase listeners) into a cold Flow. It requires awaitClose { unregisterCallback() } at the end of the block to prevent memory leaks when the collector cancels.

⚠️ Senior Interview Trap: Operator Fusion & Exception Transparency

Two critical internal rules of Kotlin Flow frequently trip up candidates:

  1. Exception Transparency Violation: Never wrap emit(value) inside a try { ... } catch (e: Exception) block inside flow { ... }! If the downstream collector throws an exception (or cancels), your upstream try/catch intercepts the downstream's failure and emits a fallback value into an already-failed collector, violating exception transparency. Always use the declarative .catch { e -> emit(fallback) } operator instead.
  2. Channel Operator Fusion (ChannelFlow): Chaining .flowOn(Dispatchers.IO).buffer(64).conflate() does NOT create three separate channels and coroutines. Internally, operators implement FusibleFlow and fuse adjacent channel configurations into a single channel and coroutine at runtime.

❌ Junior Anti-Pattern: Violating Flow Invariants & Leaking Listeners

fun observeSearch(queryFlow: Flow<String>): Flow<List<Item>> = flow {
    // BUG 1: Calling emit() inside withContext violates Context Preservation!
    withContext(Dispatchers.IO) {
        queryFlow.collect { q ->
            try {
                // BUG 2: Catching around emit() violates Exception Transparency!
                emit(api.search(q))
            } catch (e: Exception) {
                emit(emptyList())
            }
        }
    }
}

✅ 2027 Senior Standard: flatMapLatest + catch + flowOn

fun observeSearch(queryFlow: Flow<String>): Flow<List<Item>> =
    queryFlow
        .debounce(250L)
        .map { it.trim() }
        .distinctUntilChanged()
        .flatMapLatest { query ->
            if (query.length < 2) flowOf(emptyList())
            else flow { emit(api.search(query)) }
                .catch { emit(emptyList()) } // Catches upstream errors only
                .flowOn(Dispatchers.IO)      // Shifts upstream I/O safely
        }

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

suspend fun queryRemoteCatalog(query: String): List<String> {
    delay(60L) // Simulates network latency; cancellable by flatMapLatest!
    if (query == "crash") throw RuntimeException("502 Bad Gateway")
    return listOf("$query: Compose 2027", "$query: Kotlin K2")
}

fun buildSearchPipeline(keystrokes: Flow<String>): Flow<List<String>> =
    keystrokes
        .map { it.trim().lowercase() }
        .filter { it.length >= 2 }
        .distinctUntilChanged()
        .flatMapLatest { query ->
            flow {
                println("[UPSTREAM] Starting network request for '$query'...")
                val results = queryRemoteCatalog(query)
                emit(results)
            }.catch { e ->
                println("[RECOVERY] Upstream error for '$query' (${e.message}), emitting empty fallback")
                emit(emptyList())
            }.flowOn(Dispatchers.Default)
        }

fun main() = runBlocking {
    val simulatedTyping = flow {
        emit("k")
        delay(20L)
        emit("ko")
        delay(20L) // "ko" request (60ms) will be cancelled in-flight when "kot" arrives at 20ms!
        emit("kot")
        delay(100L)
        emit("crash")
        delay(100L)
    }

    buildSearchPipeline(simulatedTyping).collect { items ->
        println("[UI COLLECTOR] Rendered results: $items")
    }
}

import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

fun buildTelemetryStream(
    rawInput: Flow<String>,
    parser: suspend (String) -> Int
): Flow<Int> {
    return rawInput
        .map { it.trim() }
        .distinctUntilChanged()
        .mapLatest { cleaned ->
            parser(cleaned)
        }
        .catch {
            emit(-1)
        }
        .flowOn(Dispatchers.Default)
}

Why this works: distinctUntilChanged() avoids redundant parsing, mapLatest cancels in-flight parser() calls when newer input arrives, .catch preserves exception transparency by handling only upstream errors, and .flowOn(Dispatchers.Default) shifts all preceding operators off the main thread.
