System Surfaces: Jetpack Glance App Widgets & Android 16/17 Live Updates

Extend app engagement to the home screen and lock screen with GlanceAppWidget, RemoteViews composition trees, and Promoted Ongoing Notifications.

Recommended Primary Source
Android Developers: Jetpack Glance & Live Update Notifications
Official Documentation →

Senior Android Engineers don't confine product experiences to an open Activity—they project real-time state onto System Surfaces: the Launcher Home Screen via Jetpack Glance (androidx.glance:glance-appwidget) and the Lock Screen / Status Bar chip via Android 16/17 Live Updates (Promoted Ongoing Notifications). Although Jetpack Glance uses @Composable syntax, it is critical to understand what happens under the hood: because your Home Screen Widget runs inside the Launcher's OS process (not your app's process!), Glance cannot render an arbitrary Skia Canvas or run 60fps Animatable coroutines. Instead, Glance's custom Compose Applier translates your @Composable tree (GlanceModifier, Column, Row, Text, Image from androidx.glance.*) into a serialized RemoteViews parcel sent across Binder IPC to the Launcher!

In Glance, provideGlance(context, id) suspends to load initial data (e.g., from Room or DataStore) before calling provideContent { ... }. To make widgets responsive across compact 2x1 tiles and expanded 4x3 tablet panels without re-querying the network on every resize, configure SizeMode.Responsive(setOf(SMALL_BOX, MEDIUM_RECT, LARGE_SQUARE)) and inspect LocalSize.current. User taps inside a widget cannot execute a normal in-memory lambda (onClick = { viewModel.buy() }) because your app process may be dead when the user taps the widget on their home screen! Instead, Glance serializes clicks via actionRunCallback<RefreshTradeAction>() (ActionCallback) or actionStartActivity<MainActivity>(), waking your receiver to mutate GlanceAppWidgetState and call widget.update(context, glanceId). Complementing widgets, Android 16/17 Live Updates (NotificationCompat.ProgressStyle + setShortCriticalText + setRequestPromotedOngoing(true)) render ride-share, delivery, navigation, and live order trackers as persistent status-bar chips and lock-screen cards.

End-to-End Push Pipeline: FCM Data Payloads Driving Live Updates & Glance

How do widgets and Live Update chips stay fresh when the user is not actively inside the app? Via Firebase Cloud Messaging (FCM) Data-Only Payloads handled by FirebaseMessagingService.onMessageReceived(RemoteMessage). Unlike legacy Notification messages (which the OS system tray intercepts directly when your app is backgrounded, bypassing your code), Data messages always invoke onMessageReceived()—giving you a ~10-second execution window to write the updated state into Room/DataStore, post or update the Android 16/17 ProgressStyle Live Update notification on a dedicated high-importance NotificationChannel (with an idempotent deep-link PendingIntent), and trigger GlanceAppWidget.updateAll(context). If synchronization requires longer than 10 seconds, immediately hand off to an expedited WorkManager job.

🌱 Junior Android Dev Mental Model: Never Import androidx.compose.material3 Inside a Glance Widget!

The #1 compiler and runtime mistake with Jetpack Glance is importing androidx.compose.ui.Modifier or androidx.compose.material3.Text inside a GlanceAppWidget! Because Glance compiles to RemoteViews rather than standard Compose LayoutNodes, you must use androidx.glance.GlanceModifier, androidx.glance.text.Text, and androidx.glance.appwidget.components.Scaffold.

Senior Interview Trap & Production Edge Case

Trap: Calling MyGlanceWidget().updateAll(context) every 1 second from a background timer or passing high-resolution 4K Bitmaps inside a Glance Image(). Every widget update crosses the 1 MB Binder IPC transaction buffer into the Launcher process and wakes the CPU; frequent updates or oversized Bitmaps cause TransactionTooLargeException or Launcher lag. Downsample widget bitmaps (<= 512px) and throttle updates via DataStore triggers or WorkManager.
Edge Case: On Android 16/17, setting setRequestPromotedOngoing(true) on a notification does not guarantee it will appear as a promoted Live Update chip—the user or OS can revoke promotion (NotificationManager.canPostPromotedNotifications()), so your notification must still degrade gracefully into a standard ongoing notification.

override val sizeMode = SizeMode.Responsive(setOf(SMALL_TILE, WIDE_CARD))

override suspend fun provideGlance(context: Context, id: GlanceId) {
    val tickerFlow = repo.observeTopTickers() // Suspend / Flow before provideContent!

data class WidgetDpSize(val widthDp: Int, val heightDp: Int)

enum class GlanceLayoutTier { COMPACT_PILL, MEDIUM_CARD, EXPANDED_DASHBOARD }

data class LiveUpdateNotificationSpec(
    val orderId: String,
    val shortCriticalText: String,
    val progressPct: Int,
    val isOngoing: Boolean,
    val canPostPromoted: Boolean
)

object SystemSurfaceEngine {
    fun resolveGlanceTier(size: WidgetDpSize): GlanceLayoutTier = when {
        size.widthDp >= 250 && size.heightDp >= 180 -> GlanceLayoutTier.EXPANDED_DASHBOARD
        size.widthDp >= 180 -> GlanceLayoutTier.MEDIUM_CARD
        else -> GlanceLayoutTier.COMPACT_PILL
    }

    fun buildLiveUpdateStatus(spec: LiveUpdateNotificationSpec): String {
        val promoted = spec.isOngoing && spec.canPostPromoted && spec.shortCriticalText.length <= 7
        return if (promoted) {
            "PROMOTED_LIVE_CHIP(chip='${spec.shortCriticalText}', progress=${spec.progressPct}%, order=${spec.orderId})"
        } else {
            "STANDARD_ONGOING_NOTIFICATION(order=${spec.orderId}, progress=${spec.progressPct}%)"
        }
    }
}

fun main() {
    println("[GLANCE-2x1] ${SystemSurfaceEngine.resolveGlanceTier(WidgetDpSize(140, 90))}")
    println("[GLANCE-4x2] ${SystemSurfaceEngine.resolveGlanceTier(WidgetDpSize(260, 120))}")
    println("[GLANCE-4x3] ${SystemSurfaceEngine.resolveGlanceTier(WidgetDpSize(280, 220))}")

    val driverNear = LiveUpdateNotificationSpec("ord_99", "2 min", 85, isOngoing = true, canPostPromoted = true)
    val permissionOff = LiveUpdateNotificationSpec("ord_99", "2 min", 85, isOngoing = true, canPostPromoted = false)
    println("[ANDROID-16-LIVE] ${SystemSurfaceEngine.buildLiveUpdateStatus(driverNear)}")
    println("[ANDROID-16-FALLBACK] ${SystemSurfaceEngine.buildLiveUpdateStatus(permissionOff)}")
}

fun validateSystemSurfaceConfig(
    usesGlanceModifier: Boolean,
    bitmapBytes: Int,
    isOngoing: Boolean,
    shortChipText: String
): Result<String> {
    if (!usesGlanceModifier) {
        return Result.failure(IllegalArgumentException("INVALID_COMPOSE_UI_MODIFIER"))
    }
    if (bitmapBytes > 250_000) {
        return Result.failure(IllegalArgumentException("REMOTE_VIEWS_BITMAP_TOO_LARGE"))
    }
    val mode = if (isOngoing && shortChipText.isNotBlank() && shortChipText.length <= 7) {
        "LIVE_UPDATE_PROMOTED"
    } else {
        "STANDARD_NOTIFICATION"
    }
    return Result.success("GLANCE_OK:$mode")
}

Why this works: Enforcing GlanceModifier and bounded RemoteViews bitmap sizes prevents Glance Applier crashes and TransactionTooLargeException, while checking ongoing status and compact chip text length (<= 7 chars) aligns with Android 16/17 Live Update promotion rules.

Quiz 2: Production Architectural Reasoning

Why are custom Canvas drawing (Modifier.drawBehind), arbitrary shaders, and 60fps physics animations (animateFloatAsState) unavailable inside a Jetpack Glance GlanceAppWidget?

Kotlin 2.x compilers permanently removed the 2D Canvas drawing APIs from Jetpack Compose UI artifacts.
Home Screen Launcher applications execute on restricted efficiency CPU cores lacking hardware floating-point math instructions.
Glance lacks a live Skia render loop, translating @Composable trees into RemoteViews primitives over Binder.
Developers can unlock 120fps Canvas shaders inside Glance widgets by declaring android:largeHeap in AndroidManifest.xml files.
