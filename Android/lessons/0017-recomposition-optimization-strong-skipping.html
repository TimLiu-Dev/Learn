Recomposition Optimization & Strong Skipping Mode

Master the Compose compiler metrics, @Immutable, @Stable, and Kotlin 2.x default Strong Skipping Mode.

Recommended Primary Source
Google Android: Compose Compiler Stability & Strong Skipping
Official Documentation →

Prior to Kotlin 2.0.20, if a composable accepted even a single unstable parameter (like standard Kotlin List<T>), Compose marked the function un-skippable, forcing it to recompose whenever its parent did. In Kotlin 2.0+ and 2026/2027 standards, Strong Skipping Mode is enabled by default.

🌱 Junior Android Dev Mental Model: Does Stability Still Matter?

YES! Strong Skipping does NOT make unstable types stable:

  • Stable parameters: Compared using structural equality (equals()). Skips if data contents are the same.
  • Unstable parameters: Compared using referential equality (===). Skips only if the object instance reference hasn't changed. If your ViewModel emits a new List reference every time, it will STILL recompose!
Use ImmutableList or annotate domain models with @Immutable for guaranteed structural skipping!

    println("[KOTLIN 2.X] Strong Skipping Mode (Active by Default):")
    println("[STABILITY] Checking parameter: UserList (standard Kotlin List<User> - Unstable)")
    println("[RULE] Strong Skipping applies instance equality (oldRef === newRef)")
    
    val ref1 = listOf("BTC", "ETH")
    val ref2 = ref1 // Same instance pointer
    val ref3 = listOf("BTC", "ETH") // New instance pointer with identical content

    println("[EVAL] ref1 === ref2: ${ref1 === ref2} -> SKIPPED RECOMPOSITION!")
    println("[EVAL] ref1 === ref3: ${ref1 === ref3} -> FORCED RECOMPOSITION (Unstable allocation trap)")
    println("[SOLUTION] Use kotlinx.collections.immutable.ImmutableList for structural equals() skipping!")
}

🎯 Reference Production Solution 
import androidx.compose.runtime.Immutable
import kotlinx.collections.immutable.ImmutableList

@Immutable
data class UserPortfolio(
    val userId: String,
    val holdings: ImmutableList<String>
)

Why this works: @Immutable guarantees to the Compose compiler that fields will never mutate after creation, allowing Compose to compare objects structurally and skip recompositions safely.
