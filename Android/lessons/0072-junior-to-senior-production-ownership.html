Junior-to-Senior Transition: Production Ownership & Code Reviews

Accelerate your career: write high-converting PRs, conduct staff-level code reviews, and handle production incidents.

Recommended Primary Source
Google Engineering Practices: Code Review Developer Guide
Official Documentation →

Transitioning from a junior or mid-level developer to a Senior Android Engineer is not achieved by memorizing extra Kotlin operators—it is defined by end-to-end production ownership, staff-grade code reviews, and calm incident leadership. A junior engineer considers a ticket "done" when it compiles and works on a Pixel emulator over Wi-Fi. A senior engineer considers a feature done only when it is guarded by a remote kill switch, verified against process death and flaky networks, accompanied by an atomic, reviewable Pull Request (<400 lines), and monitored through a staged Play Console rollout.

When reviewing Pull Requests, senior engineers apply the Architectural Pyramid of Code Review. Instead of nitpicking indentation or bracket placement (which belong in automated CI gates via ktlint and Detekt), seniors hunt for structural defects that automated linters miss: lifecycle leaks (capturing an Activity or View inside a long-lived callback), concurrency hazards (calling non-atomic _state.value = ... instead of _state.update { ... } across coroutines), Unidirectional Data Flow violations, and database migration safety. Furthermore, comments are prefixed with explicit intent labels—[BLOCKING] for correctness/security bugs, [SUGGESTION] for non-mandatory improvements, and [NIT] for minor polish—so authors never have to guess what blocks merge approval.

🌱 Junior Android Dev Mental Model: Stacked PRs Beat 2,000-Line Monster PRs

Submitting a single 2,000-line PR combining Room entities, Ktor DTOs, ViewModels, and Compose screens slows team velocity to a crawl. Break large features into Stacked / Atomic PRs: PR #1 (Domain & Data layer + unit tests, ~250 LOC), PR #2 (ViewModel state machine + Turbine tests, ~200 LOC), and PR #3 (Compose UI behind a default-off Feature Flag + screenshot tests, ~250 LOC). Each PR gets reviewed in 15 minutes and can merge safely to main!

Senior Interview Trap & Production Edge Case

Trap: During a behavioral interview ("Tell me about a production outage you caused or resolved"), blaming QA or a junior teammate is an instant disqualifier. Senior engineers practice Blameless Postmortems (5 Whys): First mitigate user pain (halt staged rollout + flip remote kill switch), then trace the systemic root cause (e.g., "Why did a missing Room migration reach production? Because CI didn't run MigrationTestHelper against exported schemas"), and add an automated guardrail.
Edge Case: If a bad release is already on 100% of user devices and crashing on cold start before Firebase Remote Config can fetch new flags over the network, a remote kill switch won't fire unless your app caches last-known flags cleanly or detects consecutive startup crashes via a lightweight local crash-loop counter and resets corrupt local cache state.

❌ Junior Anti-Pattern: Race-Prone State & Unhelpful Review

// Code under review: Non-atomic read-modify-write & leaked scope!
fun onRefreshClicked() {
    GlobalScope.launch { // Leaks outside lifecycle!
        _uiState.value = _uiState.value.copy(isLoading = true) // Race condition!
        val data = repo.fetch()
        _uiState.value = _uiState.value.copy(isLoading = false, items = data)
    }
}
// Junior review comment: "LGTM! Maybe rename 'data' to 'itemList'?"

✅ 2027 Senior Standard: Atomic State Update & Structured Review

// [BLOCKING] Replace GlobalScope with viewModelScope to respect lifecycle cancellation.
// [BLOCKING] Use MutableStateFlow.update {} to prevent concurrent lost updates:
fun onRefreshClicked() {
    viewModelScope.launch {
        _uiState.update { it.copy(isLoading = true) }
        runCatching { repo.fetch() }
            .onSuccess { items -> _uiState.update { it.copy(isLoading = false, items = items) } }
            .onFailure { err -> _uiState.update { it.copy(isLoading = false, error = err.message) } }
    }
}

enum class ReviewSeverity { BLOCKING, SUGGESTION, NIT }

data class ReviewFinding(val severity: ReviewSeverity, val ruleId: String, val message: String)

object SeniorCodeReviewBot {
    fun analyzeDiff(linesChanged: Int, diffSnippet: String): List<ReviewFinding> = buildList {
        if (linesChanged > 400) {
            add(ReviewFinding(ReviewSeverity.SUGGESTION, "PR_SIZE", "PR touches $linesChanged lines (>400); split into stacked atomic PRs."))
        }
        if ("GlobalScope.launch" in diffSnippet) {
            add(ReviewFinding(ReviewSeverity.BLOCKING, "STRUCTURED_CONCURRENCY", "Never use GlobalScope; inject a managed CoroutineScope or use viewModelScope."))
        }
        if (Regex("_\w+\.value\s*=\s*_\w+\.value\.copy").containsMatchIn(diffSnippet)) {
            add(ReviewFinding(ReviewSeverity.BLOCKING, "NON_ATOMIC_STATEFLOW", "Use _state.update { it.copy(...) } for thread-safe CAS state transitions."))
        }
        if ("fallbackToDestructiveMigration()" in diffSnippet) {
            add(ReviewFinding(ReviewSeverity.BLOCKING, "DATA_LOSS_MIGRATION", "Destructive Room migration wipes user offline data in production!"))
        }
    }
}

fun main() {
    val riskyPrDiff = """
        fun sync() {
            GlobalScope.launch {
                _state.value = _state.value.copy(loading = true)
            }
        }
    """.trimIndent()

    val findings = SeniorCodeReviewBot.analyzeDiff(linesChanged = 620, diffSnippet = riskyPrDiff)
    println("[PR-REVIEW] Analyzed diff -> Found ${findings.size} architectural findings:")
    findings.forEach { f ->
        println("  [${f.severity}] (${f.ruleId}): ${f.message}")
    }
    val canMerge = findings.none { it.severity == ReviewSeverity.BLOCKING }
    println("[MERGE-GATE] Approved to merge = $canMerge")
}

fun evaluateReleaseIncident(
    crashFreeRatePct: Double,
    anrRatePct: Double,
    rolloutStagePct: Int
): String {
    if (crashFreeRatePct < 98.91 || anrRatePct >= 0.47) {
        return "HALT_AND_KILLSWITCH:${rolloutStagePct}%"
    }
    if (crashFreeRatePct < 99.5) {
        return "HOLD_ROLLOUT:${rolloutStagePct}%"
    }
    return "PROMOTE_NEXT_STAGE"
}

Why this works: Google Play penalizes store search ranking when user-perceived crash rate exceeds 1.09% (crash-free < 98.91%) or ANR rate reaches 0.47%; automated rollout gates catch regressions at 1%-5% before they impact your entire user base.

Quiz 1: Code Analysis & Bug Hunt

You are reviewing a teammate's Pull Request and spot this ViewModel code. What is the most critical '[BLOCKING]' concurrency defect here?

class CheckoutViewModel(private val repo: OrderRepository) : ViewModel() {
    private val _state = MutableStateFlow(CheckoutUiState())
    val state: StateFlow<CheckoutUiState> = _state.asStateFlow()

    fun applyPromoAndRecalculate(code: String) {
        viewModelScope.launch(Dispatchers.Default) {
            val discount = repo.validatePromo(code)
            _state.value = _state.value.copy(discount = discount)
        }
        viewModelScope.launch(Dispatchers.Default) {
            val tax = repo.calculateTax()
            _state.value = _state.value.copy(tax = tax)
        }
    }
}
MutableStateFlow throws an IllegalStateException at runtime whenever its value property is mutated from background Dispatchers.Default.
Calling asStateFlow() freezes the backing MutableStateFlow instance permanently so subsequent coroutines cannot emit updated values.
The built-in viewModelScope supervisor job automatically cancels itself immediately after the first child coroutine completes.
Concurrent non-atomic _state.value assignments race on Dispatchers.Default and lose updates; use atomic _state.update blocks instead.
