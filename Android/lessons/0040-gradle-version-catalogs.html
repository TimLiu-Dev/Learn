Gradle Version Catalogs (libs.versions.toml)

Centralize and standardize dependencies across 30+ modules with Gradle Version Catalogs and bundles.

Recommended Primary Source
Google Android: Migrate your build to version catalogs
Official Documentation →

In multi-module projects, hardcoding version strings in 25 different build.gradle.kts files leads to version divergence. Gradle Version Catalogs (stored in gradle/libs.versions.toml) centralize all dependency definitions into a single source of truth.

🌱 Junior Android Dev Mental Model: Anatomy of libs.versions.toml
[versions]
kotlin = "2.1.0"
composeBom = "2026.02.00"

[libraries]
compose-bom = { group = "androidx.compose", name = "compose-bom", version.ref = "composeBom" }

[bundles]
compose = ["compose-ui", "compose-material3"]

🎯 Reference Production Solution 
fun getTomlLibraryEntry(): String =
    "retrofit = { group = \"com.squareup.retrofit2\", name = \"retrofit\", version.ref = \"retrofit\" }"

Why this works: Version catalogs generate type-safe Kotlin accessors in Gradle build scripts (e.g. libs.retrofit), offering IDE code completion and compile-time verification of dependencies.
