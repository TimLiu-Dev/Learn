Kotlin Coroutines Fundamentals & Structured Concurrency

Harness structured concurrency, CPS state machines, coroutine cancellation, and error isolation.

Kotlin Coroutines are lightweight threads: millions of coroutines can run concurrently on a handful of OS threads without OutOfMemory errors. Under the hood, the Kotlin compiler transforms every suspend fun into a Continuation Passing Style (CPS) state machine.

🌱 Junior Android Dev Mental Model: Structured Concurrency

In legacy Android, launching background threads resulted in leaks: when the user rotated the screen or exited, background threads kept running. Structured Concurrency guarantees that child coroutines are bound to their parent scope. If the parent scope is cancelled, all children are cancelled immediately!

coroutineScope vs supervisorScope: The Senior Interview Question

  • coroutineScope: All-or-nothing. If one child throws an exception, all other siblings and the parent are immediately cancelled.
  • supervisorScope: Failure isolation. If one child fails, its siblings continue executing unaffected. Essential for independent background operations!

KOTLIN 2.X StructuredConcurrency.kt 
import kotlinx.coroutines.*

suspend fun fetchUserData(): String {
    delay(100L) // Simulating non-blocking network I/O
    return "User: Alex"
}

suspend fun fetchUserBalance(): Double {
    delay(80L)
    return 1520.50
}

fun main() = runBlocking {
    println("[LOG] Starting parallel async execution...")
    val startTime = System.currentTimeMillis()

    // Structured concurrency using coroutineScope
    coroutineScope {
        val userDeferred = async { fetchUserData() }
        val balanceDeferred = async { fetchUserBalance() }

        val user = userDeferred.await()
        val balance = balanceDeferred.await()
        val duration = System.currentTimeMillis() - startTime

        println("[STATE] Fetched: $user, Balance: $$balance in ${duration}ms")
    }

    println("[SUCCESS] Both requests executed in parallel under structured concurrency!")
}

🎯 Reference Production Solution 
import kotlinx.coroutines.*

suspend fun safeParallelFetch(
    fetchA: suspend () -> String,
    fetchB: suspend () -> String
): Pair<String, String> = coroutineScope {
    val deferredA = async { fetchA() }
    val deferredB = async { fetchB() }
    Pair(deferredA.await(), deferredB.await())
}

Why this works: coroutineScope ensures that if either fetchA or fetchB throws an unhandled exception, the sibling is cancelled cleanly and the exception propagates without leaking background resources.
