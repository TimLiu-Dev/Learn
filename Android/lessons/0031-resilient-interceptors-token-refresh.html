Resilient Interceptors & OAuth2 Token Auto-Refresh

Handle 401 Unauthorized responses with Mutex synchronization to eliminate concurrent token refresh race conditions.

Recommended Primary Source

Official Documentation →

When an OAuth2 access token expires, the server returns HTTP 401 Unauthorized. If 5 network requests fail with 401 at the same millisecond, an uncoordinated app will fire 5 simultaneous refresh requests, invalidating refresh tokens and logging the user out! Solving this requires an asynchronous Mutex lock.

🌱 Junior Android Dev Mental Model: Mutex Double-Check Pattern

When a request gets a 401:

  1. Acquire mutex.withLock { ... }.
  2. Check if the active token was already refreshed by a previous coroutine while waiting for the lock. If so, simply retry with the new token!
  3. If not yet refreshed, call the refresh API once, save the new token, and release the lock.

🎯 Reference Production Solution 
import kotlinx.coroutines.sync.Mutex
import kotlinx.coroutines.sync.withLock

class TokenManager {
    private val mutex = Mutex()
    private var token: String = ""

    suspend fun updateToken(newToken: String) = mutex.withLock {
        token = newToken
    }
}

Why this works: Mutex.withLock is non-blocking to the underlying thread, providing cooperative mutual exclusion across concurrent coroutines.
