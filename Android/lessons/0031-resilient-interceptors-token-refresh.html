Resilient Networking: OkHttp <code>Interceptor</code> vs <code>Authenticator</code> & Single-Flight Token Refresh

In production fintech and enterprise apps, short-lived OAuth2 / JWT access tokens (e.g., 15-minute TTL) expire while the user is actively using the app. Handling authentication cleanly requires understanding the architectural separation between two OkHttp components:

  • Application Interceptor (<code>addInterceptor</code>): Runs proactively on every outgoing request before it hits the network cache or wire. Its job is to attach the current <code>Authorization: Bearer <accessToken></code> header, correlation <code>X-Request-ID</code>, and telemetry headers.
  • Authenticator (<code>authenticator(...)</code>): Runs reactively only when the server responds with <code>HTTP 401 Unauthorized</code>. Its job is to exchange the long-lived <code>refreshToken</code> for a new <code>accessToken</code> and return a retried <code>Request</code> with the updated <code>Authorization</code> header (or return <code>null</code> to stop retrying and force logout).

However, a naive <code>Authenticator</code> creates a catastrophic production outage known as a Token Refresh Stampede (Thundering Herd): when a screen launches 4 parallel API calls (<code>getBalance</code>, <code>getPositions</code>, <code>getWatchlist</code>, <code>getAlerts</code>) with an expired token, all 4 fail with <code>HTTP 401</code> simultaneously on different OkHttp dispatcher threads. Without synchronization, all 4 threads call <code>/oauth/refresh</code> concurrently—invalidating the single-use refresh token on the server and logging the user out! The 2027 Senior Android standard is a double-checked lock (<code>Mutex</code> or <code>synchronized</code>) inside the <code>Authenticator</code>: the first thread acquires the lock and refreshes the token; when the remaining 3 threads enter the lock, they compare the request's failed bearer token against the newly stored token—seeing it has already changed, they immediately retry with the new token without hitting <code>/oauth/refresh</code> a second time!

🌱 Junior Android Dev Mental Model: Bound Retry Loops with <code>responseCount</code>!

What if the server has a bug and returns 401 Unauthorized even with a brand-new token? An unguarded Authenticator will loop until OkHttp throws a protocol exception after 20 attempts! Always check response.priorResponse depth (e.g., if responseCount(response) >= 2, return null immediately to abort).

Senior Interview Trap: Exponential Backoff with Full Jitter

When retrying transient <code>HTTP 503</code> / <code>429</code> or network timeouts, fixed-interval retries (<code>delay(2000)</code>) synchronize thousands of reconnecting mobile clients into destructive traffic spikes on your backend. Always apply Exponential Backoff with Jitter: val sleepMs = min(maxDelay, baseDelay * (1L shl attempt)) + Random.nextLong(0, 500), and never retry non-idempotent POST requests unless an <code>Idempotency-Key: <UUID></code> header is attached!

❌ Junior Anti-Pattern: Unsynchronized 401 Refresh Storm & Infinite Retry Risk

class BadTokenAuthenticator(
    private val tokenStore: TokenStore,
    private val authApi: AuthApi
) : Authenticator {
    override fun authenticate(route: Route?, response: Response): Request? {
        // BUG 1: 4 concurrent 401s will all hit refreshTokenSync() simultaneously!
        // BUG 2: No retry depth check — loops 20x if server keeps returning 401!
        val newToken = authApi.refreshTokenSync(tokenStore.getRefreshToken())
        tokenStore.saveAccessToken(newToken)
        return response.request.newBuilder()
            .header("Authorization", "Bearer $newToken")
            .build()
    }
}

✅ 2027 Senior Production Standard: Double-Checked Synchronized Single-Flight Authenticator

class SingleFlightAuthenticator @Inject constructor(
    private val tokenStore: TokenStore,
    private val authApi: AuthApi
) : Authenticator {
    private val lock = Any()

    override fun authenticate(route: Route?, response: Response): Request? {
        if (responseCount(response) >= 2) return null // Prevent infinite 401 loop!
        val failedHeader = response.request.header("Authorization")

        synchronized(lock) {
            val currentToken = tokenStore.getAccessToken()
            // Double-check: Did another thread ALREADY refresh the token while we waited?
            val tokenToUse = if (currentToken != null && "Bearer $currentToken" != failedHeader) {
                currentToken // Reuse fresh token without a duplicate network refresh call!
            } else {
                val refreshed = authApi.refreshTokenSync(tokenStore.getRefreshToken()) ?: return null
                tokenStore.saveAccessToken(refreshed)
                refreshed
            }
            return response.request.newBuilder()
                .header("Authorization", "Bearer $tokenToUse")
                .build()
        }
    }
}

class SingleFlightTokenCoordinator(initialToken: String) {
    var currentAccessToken: String = initialToken
        private set
    var networkRefreshCalls: Int = 0
        private set

    fun handle401(endpoint: String, requestTokenUsed: String, priorAttempts: Int): String? {
        if (priorAttempts >= 2) return null
        if (currentAccessToken != requestTokenUsed) {
            println("[401-HANDLER $endpoint] Token already updated ($requestTokenUsed -> $currentAccessToken). Reusing without network call!")
            return currentAccessToken
        }
        networkRefreshCalls++
        currentAccessToken = "JWT_V${networkRefreshCalls + 1}_FRESH"
        println("[401-HANDLER $endpoint] Executed single-flight /oauth/refresh (#$networkRefreshCalls) -> Issued $currentAccessToken")
        return currentAccessToken
    }
}

fun main() {
    val coordinator = SingleFlightTokenCoordinator(initialToken = "JWT_V1_EXPIRED")
    val concurrent401Endpoints = listOf("/v1/balance", "/v1/positions", "/v1/watchlist", "/v1/orders")

    for (endpoint in concurrent401Endpoints) {
        val retryToken = coordinator.handle401(endpoint, requestTokenUsed = "JWT_V1_EXPIRED", priorAttempts = 1)
        println("  -> Retrying $endpoint with Authorization: Bearer $retryToken")
    }
    println("[SUMMARY] 4 concurrent 401 responses handled with only ${coordinator.networkRefreshCalls} /oauth/refresh network call!")
}

import kotlinx.coroutines.sync.Mutex
import kotlinx.coroutines.sync.withLock

class SingleFlightTokenRefresher(
    initialToken: String,
    private val fetchNewToken: suspend () -> String
) {
    private val mutex = Mutex()
    var currentToken: String = initialToken
        private set

    suspend fun refreshTokenIfNeeded(failedToken: String): String = mutex.withLock {
        if (currentToken != failedToken) {
            return@withLock currentToken
        }
        val newToken = fetchNewToken()
        currentToken = newToken
        newToken
    }
}

Why this works: mutex.withLock serializes concurrent 401 handlers without blocking OS threads, and comparing currentToken != failedToken inside the critical section ensures only the first coroutine triggers a network refresh while queued coroutines immediately reuse the freshly fetched token.
