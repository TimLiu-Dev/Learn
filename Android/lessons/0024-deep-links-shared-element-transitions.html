Verified App Links (<code>assetlinks.json</code>) & Compose Shared Element Transitions

Two capabilities separate a prototype UI from a flagship 2027 Android experience: cryptographically verified Android App Links that jump directly into deep destinations without a browser disambiguation dialog, and 60/120fps Shared Element Transitions (<code>SharedTransitionLayout</code>) that morph hero elements (such as a token icon, ticker title, and price badge) seamlessly between list and detail screens.

Under the hood, Android App Links require two halves: an <intent-filter android:autoVerify="true"> in <code>AndroidManifest.xml</code> declaring <code>https</code> host/path patterns, and a publicly hosted <code>https://yourdomain.com/.well-known/assetlinks.json</code> file containing the SHA-256 signing certificate fingerprint of your Play App Signing key. At install time, the Android OS fetches <code>assetlinks.json</code> and grants your package instant domain verification. Meanwhile, inside Compose, SharedTransitionLayout introduces a dedicated lookahead measurement pass that calculates the start bounds in the exiting screen (<code>AnimatedVisibilityScope</code>) and target bounds in the entering screen, interpolating position and size in an overlay layer via Modifier.sharedElement() or Modifier.sharedBounds().

🌱 Junior Android Dev Mental Model: sharedElement vs sharedBounds

Use Modifier.sharedElement when the hero element is the exact same visual asset changing size/position (like an avatar image or company logo). Use Modifier.sharedBounds when two visually distinct containers (like a compact list card morphing into a full-screen detail header, or text whose font size/weight changes) share a bounding box transition.

Senior Interview Trap: Deep Link Parameter Injection & Synthetic Back Stacks

Never trust deep link URI parameters directly as SQL queries or unvalidated file paths! Always validate and sanitize incoming deep link arguments in your <code>ViewModel</code> before hitting repositories. Additionally, notice the difference between launching an app via a launcher icon versus an external notification/web deep link: when launched cold from an external intent, Navigation builds a synthetic back stack up to the parent graph's <code>startDestination</code> so pressing Back returns the user to your home screen rather than exiting immediately.

❌ Junior Anti-Pattern: Unverified Custom Scheme & Mismatched Shared Keys

// BUG 1: "aether://trade/btc" can be hijacked by ANY malicious app on the device!
navDeepLink { uriPattern = "aether://trade/{symbol}" }

// BUG 2: Static key "hero_image" collides when multiple list items exist in LazyColumn!
Image(
    painter = painter,
    modifier = Modifier.sharedElement(
        rememberSharedContentState(key = "hero_image"),
        animatedVisibilityScope = scope
    )
)

data class Bounds(val x: Float, val y: Float, val width: Float, val height: Float) {
    fun lerpTo(target: Bounds, fraction: Float): Bounds = Bounds(
        x = x + (target.x - x) * fraction,
        y = y + (target.y - y) * fraction,
        width = width + (target.width - width) * fraction,
        height = height + (target.height - height) * fraction
    )
}

fun verifyAndParseAppLink(uri: String, verifiedDomain: String): Map<String, String>? {
    if (!uri.startsWith("https://$verifiedDomain/market/")) return null
    val symbol = uri.removePrefix("https://$verifiedDomain/market/").substringBefore("?").uppercase()
    if (!symbol.matches(Regex("^[A-Z0-9]{2,10}$"))) return null
    return mapOf("symbol" to symbol)
}

fun main() {
    val incomingUri = "https://aether.finance/market/btc"
    val parsed = verifyAndParseAppLink(incomingUri, verifiedDomain = "aether.finance")
    println("[APP-LINK] Verified HTTPS URI '$incomingUri' -> args=$parsed")

    val listCardBounds = Bounds(x = 16f, y = 240f, width = 360f, height = 72f)
    val detailHeaderBounds = Bounds(x = 0f, y = 0f, width = 392f, height = 280f)
    for (progress in listOf(0.0f, 0.5f, 1.0f)) {
        val frame = listCardBounds.lerpTo(detailHeaderBounds, progress)
        println("[SHARED-BOUNDS key='card_BTC' t=${(progress * 100).toInt()}%] x=${frame.x.toInt()}, y=${frame.y.toInt()}, size=${frame.width.toInt()}x${frame.height.toInt()}")
    }
}

import androidx.compose.animation.AnimatedVisibilityScope
import androidx.compose.animation.ExperimentalSharedTransitionApi
import androidx.compose.animation.SharedTransitionScope
import androidx.compose.foundation.layout.Box
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier

@OptIn(ExperimentalSharedTransitionApi::class)
@Composable
fun SharedTransitionScope.AssetHeroBadge(
    symbol: String,
    animatedVisibilityScope: AnimatedVisibilityScope,
    modifier: Modifier = Modifier
) {
    Box(
        modifier = modifier.sharedElement(
            sharedContentState = rememberSharedContentState(key = "asset-logo-$symbol"),
            animatedVisibilityScope = animatedVisibilityScope
        )
    )
}

Why this works: rememberSharedContentState(key = "asset-logo-$symbol") creates a unique per-item identity across the exiting and entering AnimatedVisibilityScopes, allowing SharedTransitionScope's lookahead pass to interpolate the element's bounds smoothly in an overlay layer.

Quiz 1: Code Analysis & Bug Hunt

You configured <code><intent-filter android:autoVerify="true"></code> for <code>https://aether.finance/market</code> and deployed <code>.well-known/assetlinks.json</code>. It works in debug builds when tested locally via <code>adb</code>, but production Play Store users see the Chrome browser instead of your app opening directly. Why?

[{
  "relation": ["delegate_permission/common.handle_all_urls"],
  "target": {
    "namespace": "android_app",
    "package_name": "finance.aether.app",
    "sha256_cert_fingerprints": ["14:6D:E9:83:... (Developer Laptop Upload Key)"]
  }
}]
The android:autoVerify attribute only validates custom URI schemes like aether:// and ignores standard https:// web domains.
The assetlinks.json configuration file must be bundled inside the application res/raw directory instead of hosted remotely.
Production Play Store installations require users to manually approve verified domain links inside Android System Settings.
Play App Signing re-signs production builds with a certificate whose SHA-256 fingerprint is missing from assetlinks.json.

Quiz 2: Production Architectural Reasoning

When implementing a shared transition where a compact list row's background surface and title text expand into a full-width detail screen header with larger typography, why should you choose <code>Modifier.sharedBounds()</code> over <code>Modifier.sharedElement()</code>?

sharedBounds() cross-fades and re-measures distinct layouts while animating outer bounds, whereas sharedElement() scales one identical snapshot.
sharedElement() throws an exception inside scrollable LazyColumn item compositions, whereas sharedBounds() supports virtualized lazy list layouts.
sharedBounds() calculates all frame interpolation directly on a background RenderThread without requiring an enclosing SharedTransitionLayout scope.
Modifier.sharedElement() is officially deprecated in Jetpack Compose 1.8 and replaced by Modifier.sharedBounds() across all animation APIs.
