Unidirectional Data Flow (UDF) & MVI State Architecture

Architect rock-solid screens with Model-View-Intent (MVI), single immutable UiState, and sealed user intents.

Recommended Primary Source
Google Android: Guide to app architecture - UI Layer
Official Documentation →

Unidirectional Data Flow (UDF) is the core architectural principle of Modern Android Development. Data flows down (from ViewModel to UI as immutable State); events flow up (from UI to ViewModel as user Actions/Intents).

🌱 Junior Android Dev Mental Model: The MVI Loop
  1. State: Exactly one immutable data class or sealed interface representing the entire screen (e.g. MarketUiState).
  2. Intent / Action: Sealed interface representing user actions (e.g. MarketIntent.Refresh, MarketIntent.SelectCoin(id)).
  3. Reducer / ViewModel: The ViewModel receives the Intent, processes business logic, and emits a new UiState. The UI never mutates state directly!

2027 Production Standard (Runnable Example)

Click ▶ Run Example to execute this snippet and inspect the simulated runtime output and state transformations:

KOTLIN 2.X UdfArchitecture.kt 
sealed interface CartIntent {
    data class AddItem(val name: String) : CartIntent
    data object ClearCart : CartIntent
}

data class CartUiState(val items: List<String> = emptyList())

fun reduce(state: CartUiState, intent: CartIntent): CartUiState = when (intent) {
    is CartIntent.AddItem -> state.copy(items = state.items + intent.name)
    CartIntent.ClearCart -> state.copy(items = emptyList())
}

fun main() {
    println("[UDF] Initial State: items = []")
    var state = CartUiState()

    println("[ACTION] User taps 'Add Coffee' -> CartIntent.AddItem('Coffee')")
    state = reduce(state, CartIntent.AddItem("Coffee"))
    println("[STATE] Emitted new immutable UiState: ${state.items}")

    println("[ACTION] User taps 'Add Croissant' -> CartIntent.AddItem('Croissant')")
    state = reduce(state, CartIntent.AddItem("Croissant"))
    println("[STATE] Emitted new immutable UiState: ${state.items}")

    println("[SUCCESS] State flowed down; events flowed up. 100% predictable UDF loop!")
}

sealed interface SearchIntent {
    data class QueryChanged(val query: String) : SearchIntent
    data object ClearQuery : SearchIntent
}

Why this works: Representing user actions as sealed types provides an exhaustive contract of all operations the screen can perform, simplifying testing and analytics logging.
