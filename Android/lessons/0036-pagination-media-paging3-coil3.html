Infinite Feeds & Media: Paging 3 (RemoteMediator) & Coil 3 (AsyncImage)

Rendering a 50,000-item transaction history or social market feed with high-resolution avatars requires coordinating pagination, offline caching, and bitmap memory management. In 2027 Android architectures, this is powered by Jetpack Paging 3 and Coil 3 (io.coil-kt.coil3).

Paging 3 offers two architectural tiers:

  1. Network-Only (PagingSource<Key, Value>): Fetches pages directly from a REST API into memory as the user scrolls near the prefetch distance. Simple, but loses data when offline.
  2. Offline-First Single Source of Truth (RemoteMediator<Key, Value> + Room PagingSource): The 2027 enterprise standard! As the user scrolls, RemoteMediator.load(loadType, state) fetches the next page from the network and writes it inside a Room @Transaction (alongside a RemoteKeys table tracking nextKey/prevKey). Meanwhile, the UI observes Room's auto-invalidating Dao.pagingSource() directly!

In the ViewModel, you must append .cachedIn(viewModelScope) to Pager(...).flow. In the Composable UI, you collect it via val items = viewModel.pagedFlow.collectAsLazyPagingItems() and pass a stable key = items.itemKey { it.id } to LazyColumn. For images inside those rows, Coil 3's AsyncImage uses Kotlin Coroutines, Okio, and a two-tier cache (in-memory MemoryCache + on-disk DiskCache) while automatically downsampling bitmaps to match the exact measured pixel size of the Composable node!

🌱 Junior Android Dev Mental Model: Why Decoding a Full 4K Image in a 48dp Avatar Crashes the App

A 4000×3000 RGBA_8888 bitmap consumes 48 MB of RAM (4000 * 3000 * 4 bytes) regardless of how compressed the JPEG file was! Never decode bitmaps manually with BitmapFactory.decodeStream(). Coil 3 inspects your Modifier.size(48.dp) constraints before decoding and downsamples the image into a tiny ~36 KB bitmap!

Senior Interview Trap: Forgetting .cachedIn(viewModelScope) or Recreating Pager Inside a Composable

What happens if you omit .cachedIn(viewModelScope) on Pager.flow? First, rotating the screen restarts pagination from Page 0, losing the user's scroll position. Second, if two collectors observe the same uncached Flow<PagingData<T>> (or after config change), Paging 3 throws IllegalStateException: Attempt to collect twice from pageEventFlow! Always cache Flow<PagingData<T>> with .cachedIn(viewModelScope) as a property in the ViewModel.

❌ Junior Anti-Pattern: Pager Inside Composable, Missing cachedIn & No Item Keys

@Composable
fun BadTradeHistoryList(repo: TradeRepo) {
    // BUG 1: Recreates Pager on every recomposition & lacks cachedIn(viewModelScope)!
    val items = repo.getTradePagerFlow().collectAsLazyPagingItems()

    LazyColumn {
        // BUG 2: Missing itemKey causes scroll jumps when items insert/update!
        items(count = items.itemCount) { index ->
            items[index]?.let { TradeRow(it) }
        }
    }
}

✅ 2027 Senior Production Standard: cachedIn(viewModelScope) + itemKey + Coil 3

class TradeHistoryViewModel @Inject constructor(
    pager: Pager<Int, TradeEntity>
) : ViewModel() {
    val pagedTrades: Flow<PagingData<TradeUiModel>> = pager.flow
        .map { pagingData -> pagingData.map { it.toUiModel() } }
        .cachedIn(viewModelScope) // Survives rotation & prevents double-collect crash!
}

@Composable
fun TradeHistoryList(items: LazyPagingItems<TradeUiModel>) {
    LazyColumn {
        items(
            count = items.itemCount,
            key = items.itemKey { it.id },
            contentType = items.itemContentType { "trade_row" }
        ) { index ->
            items[index]?.let { trade ->
                Row {
                    AsyncImage(
                        model = trade.iconUrl,
                        contentDescription = null,
                        modifier = Modifier.size(40.dp)
                    )
                    Text(trade.title)
                }
            }
        }
    }
}

enum class LoadType { REFRESH, PREPEND, APPEND }

data class TradeItem(val id: String, val symbol: String, val amountUsd: Double)

class SimulatedRemoteMediator(private val pageSize: Int = 2) {
    val sqliteTable = mutableListOf<TradeItem>()
    var nextRemotePage: Int? = 1

    fun load(loadType: LoadType): String {
        if (loadType == LoadType.PREPEND) return "MediatorResult.Success(endOfPaginationReached = true)"
        val pageToFetch = if (loadType == LoadType.REFRESH) 1 else (nextRemotePage ?: return "MediatorResult.Success(endOfPaginationReached = true)")
        val fetched = (1..pageSize).map { idx ->
            val globalId = (pageToFetch - 1) * pageSize + idx
            TradeItem(id = "TX-$globalId", symbol = "BTC", amountUsd = globalId * 500.0)
        }
        if (loadType == LoadType.REFRESH) sqliteTable.clear()
        sqliteTable.addAll(fetched)
        nextRemotePage = if (pageToFetch < 2) pageToFetch + 1 else null
        val endReached = nextRemotePage == null
        return "MediatorResult.Success(endOfPaginationReached = $endReached) | SQLite rows=${sqliteTable.map { it.id }}"
    }
}

fun main() {
    val mediator = SimulatedRemoteMediator(pageSize = 2)
    println("1. Initial Launch (LoadType.REFRESH):")
    println("   -> ${mediator.load(LoadType.REFRESH)}")
    println("2. User scrolls near bottom prefetch threshold (LoadType.APPEND):")
    println("   -> ${mediator.load(LoadType.APPEND)}")
    println("3. User scrolls further (LoadType.APPEND at end of feed):")
    println("   -> ${mediator.load(LoadType.APPEND)}")
}

import androidx.lifecycle.ViewModel
import androidx.lifecycle.viewModelScope
import androidx.paging.PagingData
import androidx.paging.cachedIn
import androidx.paging.map
import kotlinx.coroutines.flow.Flow
import kotlinx.coroutines.flow.map

data class AssetDto(val symbol: String)

class AssetFeedViewModel(
    rawPagingFlow: Flow<PagingData<AssetDto>>
) : ViewModel() {
    val pagedSymbols: Flow<PagingData<String>> = rawPagingFlow
        .map { pagingData ->
            pagingData.map { dto -> dto.symbol.uppercase() }
        }
        .cachedIn(viewModelScope)
}

Why this works: Transforming PagingData before calling .cachedIn(viewModelScope) ensures the mapped UI models are cached in memory across configuration changes and prevents IllegalStateException from multiple collections.

Quiz 1: Code Analysis & Bug Hunt

Examine this ViewModel pipeline using Paging 3. Why does the mapping transformation (toExpensiveUiModel()) re-run from scratch on every screen rotation even though .cachedIn(viewModelScope) was called?

class FeedViewModel(pager: Pager<Int, FeedEntity>) : ViewModel() {
    val feedPagingFlow: Flow<PagingData<FeedUiModel>> = pager.flow
        .cachedIn(viewModelScope)
        .map { pagingData ->
            pagingData.map { entity -> entity.toExpensiveUiModel() }
        }
}
The pagingData.map transformation runs synchronously on the main thread and cannot execute inside viewModelScope coroutines.
Placing map downstream of cachedIn re-executes the transformation for every new collector on configuration changes.
The Pager container and its underlying PagingConfig parameters must be reconstructed on every configuration change.
The cachedIn operator only retains the initial ten prefetched items emitted from your repository PagingSource.

Quiz 2: Production Architectural Reasoning

In a Paging 3 + Room offline-first architecture using RemoteMediator, does the Composable UI render items returned directly from RemoteMediator.load(), or how do newly fetched network items reach the screen?

RemoteMediator.load returns a LoadResult.Page instance containing network items and pagination keys directly to Compose LazyPagingItems.
The LazyColumn composable actively polls RemoteMediator every five hundred milliseconds while users scroll through pages.
RemoteMediator writes network pages into Room, and InvalidationTracker invalidates the DAO PagingSource to emit rows.
RemoteMediator serializes fetched network pages inside SavedStateHandle bundles rather than persisting rows into local SQLite.
