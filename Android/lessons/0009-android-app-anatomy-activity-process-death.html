Android App Anatomy, ComponentActivity & Process Death

Master the Android application lifecycle, ComponentActivity, SavedStateHandle, and surviving system process death.

Recommended Primary Source
Google Android: Understanding the Activity Lifecycle & Process Death
Official Documentation →

Before writing Jetpack Compose UI, every Android engineer must understand the runtime container hosting it: ComponentActivity and the Android OS Process Model. Unlike desktop or web apps, the Android OS can terminate your app's process at any time when it is in the background to reclaim RAM for other apps.

🌱 Junior Android Dev Mental Model: Configuration Change vs. Process Death

Configuration Change (e.g. Screen Rotation): The Activity instance is destroyed and recreated, but the underlying Linux OS process remains alive in RAM. ViewModels survive in memory.
System-Initiated Process Death: When the user leaves your app and opens a heavy game, Android kills your entire process. ViewModels are erased! Only state saved in SavedStateHandle or rememberSaveable survives.

class MockSavedStateHandle {
    private val bundle = mutableMapOf<String, Any>()
    fun set(key: String, value: Any) { bundle[key] = value }
    fun get(key: String): Any? = bundle[key]
}

fun main() {
    println("[LOG] App running in foreground. User edits form draft...")
    val savedState = MockSavedStateHandle()
    savedState.set("form_draft", "Order for 3 Aether Shares")
    println("[STATE] State saved to SavedStateHandle: ${savedState.get("form_draft")}")

    println("[OS] User switches apps. Android system triggers low-memory Process Death!")
    println("[OS] Activity destroyed. Process PID 4812 terminated.")

    println("[OS] User returns to app! New Process PID 9204 spawned.")
    val restoredDraft = savedState.get("form_draft")
    println("[SUCCESS] Successfully restored state from SavedStateHandle: '$restoredDraft'")
}

🎯 Reference Production Solution 
class ResilientDraftManager(private val stateHandle: Map<String, Any>) {
    fun restoreDraft(key: String): String =
        stateHandle[key] as? String ?: "DEFAULT_EMPTY"
}

Why this works: SavedStateHandle uses Android's underlying SavedStateRegistry to persist lightweight key-value bundles across process death without requiring disk persistence.
