Recomposition Optimization & Strong Skipping Mode

Master the Compose compiler metrics, @Immutable, @Stable, and Kotlin 2.x default Strong Skipping Mode.

Recommended Primary Source
Google Android: Compose Compiler Stability & Strong Skipping
Official Documentation →

To avoid re-executing every @Composable function in the UI tree on every frame, the Compose K2 Compiler Plugin analyzes every function and class to generate Restartable and Skippable bytecode. Before Kotlin 2.0.20, a Composable was only marked skippable if 100% of its parameters were proven Stable at compile time. Passing a standard kotlin.collections.List<T>, Map<K, V>, Set<T>, or a class from a non-Compose domain module caused the compiler to mark the parameter UNSTABLE and disable skipping for the entire Composable!

In Kotlin 2.0.20+ and 2027 production Android, Strong Skipping Mode is enabled by default in the Compose compiler. Under Strong Skipping Mode, two fundamental rules change:

  1. All Restartable Composables Are Skippable (Instance vs. Structural Equality): Even if a Composable accepts an unstable parameter (like List<User> or LocalDate), it remains skippable! At runtime, the generated $changed comparison checks unstable parameters via referential instance equality (===) and stable parameters via structural equality (Object.equals()).
  2. Automatic remember Wrapping for Lambdas: All lambdas inside a Composable—even those capturing unstable variables like a ViewModel or List—are automatically wrapped in a remember(captures...) { { ... } } slot by the compiler so lambda allocations don't trigger downstream recompositions!
🌱 Junior Android Dev Mental Model: @Immutable vs. @Stable

• @Immutable: A strict contract promising that no publicly accessible property will ever change after the object is constructed (all fields are val and hold immutable types).
• @Stable: A softer contract: the object may be mutable, provided that whenever any public property changes, the Compose Snapshot system is notified (e.g., an interface or state holder backed by mutableStateOf), and equals() is always consistent for two instances.

🔥 Senior Interview Trap: Why @Immutable / @Stable and ImmutableList Still Matter Under Strong Skipping!

A favourite 2026/2027 Senior Android interview question is: "Since Strong Skipping Mode is enabled by default in Kotlin 2.x, can we delete @Immutable, @Stable, and kotlinx.collections.immutable.ImmutableList from our codebase?" NO! Look at what happens when you pass an unstable List<Item>:

  • Because List<Item> is unstable, Strong Skipping compares it using referential equality (oldList === newList).
  • Whenever your Repository or ViewModel maps a Flow (e.g., items.map { ... } or state.copy(items = items.filter { ... })), a new ArrayList instance is allocated on the heap even if its contents are 100% identical!
  • Because oldList !== newList (=== is false), Strong Skipping CANNOT skip the Composable and recomposes it needlessly!
  • By contrast, if you use ImmutableList<Item> (from kotlinx.collections.immutable) or annotate your wrapper with @Immutable, the compiler marks the parameter Stable, switching the runtime check from === to structural .equals(), skipping recomposition whenever the list contents are equal! Furthermore, for types from external modules (like java.time.Instant or domain models), you can register them in a stability_config.txt file (stabilityConfigurationFile in composeCompiler { }) without adding Compose dependencies to pure Kotlin modules!

❌ Junior Anti-Pattern: Relying on === for Re-Allocated Unstable Lists

// Unstable parameter: List<String> is an interface (could be MutableList).
// Strong Skipping uses 'oldTags === newTags' (referential equality)!
@Composable
fun TagCloud(tags: List<String>) { ... }

// In ViewModel: every state emission allocates a new List reference via .map{},
// so 'oldTags === newTags' is ALWAYS false and TagCloud ALWAYS recomposes!
val uiState = repoFlow.map { raw ->
    UiState(tags = raw.tags.map { it.lowercase() })
}

✅ 2027 Senior Standard: @Immutable / ImmutableList + @NonRestartableComposable

import kotlinx.collections.immutable.ImmutableList

// Stable parameter: Strong Skipping uses structural 'oldTags == newTags' (.equals())!
@Immutable
data class TagCloudState(val tags: ImmutableList<String>)

// Thin wrapper that only forwards parameters: @NonRestartableComposable
// eliminates redundant restart group overhead in the Slot Table!
@Composable
@NonRestartableComposable
fun TagCloudHeader(state: TagCloudState) {
    TagCloudContent(tags = state.tags)
}

KOTLIN 2.X StrongSkippingEqualityVerifier.kt 
enum class ParameterStability { STABLE, UNSTABLE }

class StrongSkippingVerifier {
    fun shouldSkipRecomposition(
        stability: ParameterStability,
        previousArg: Any?,
        newArg: Any?
    ): Boolean = when (stability) {
        // Strong Skipping compares UNSTABLE parameters via referential identity (===)
        ParameterStability.UNSTABLE -> previousArg === newArg
        // Strong Skipping compares STABLE parameters via structural equality (== / .equals())
        ParameterStability.STABLE -> previousArg == newArg
    }
}

fun main() {
    val verifier = StrongSkippingVerifier()

    // Two distinct ArrayList instances on the heap with identical elements
    val listInstanceA: List<String> = listOf("Compose", "Kotlin2").toList()
    val listInstanceB: List<String> = ArrayList(listOf("Compose", "Kotlin2"))

    val skippedAsUnstableList = verifier.shouldSkipRecomposition(
        stability = ParameterStability.UNSTABLE,
        previousArg = listInstanceA,
        newArg = listInstanceB
    )
    val skippedAsStableImmutable = verifier.shouldSkipRecomposition(
        stability = ParameterStability.STABLE,
        previousArg = listInstanceA,
        newArg = listInstanceB
    )

    println("[IDENTITY CHECK] listInstanceA === listInstanceB: ${listInstanceA === listInstanceB}")
    println("[STRUCTURAL CHECK] listInstanceA == listInstanceB: ${listInstanceA == listInstanceB}")
    println("[STRONG SKIPPING: Unstable List<T> (uses ===)] -> Skipped? $skippedAsUnstableList (Recomposes!)")
    println("[STRONG SKIPPING: @Immutable / ImmutableList<T> (uses ==)] -> Skipped? $skippedAsStableImmutable (Skipped!)")
}

import androidx.compose.runtime.Immutable
import androidx.compose.runtime.Stable

@Immutable
data class FeedSectionUiModel(
    val sectionId: String,
    val tags: List<String>
)

@Stable
interface ExpandableState {
    val isExpanded: Boolean
    fun toggle()
}

fun canStrongSkipParameter(
    isMarkedStable: Boolean,
    oldVal: Any?,
    newVal: Any?
): Boolean {
    return if (isMarkedStable) {
        oldVal == newVal
    } else {
        oldVal === newVal
    }
}

Why this works: Under Strong Skipping Mode, @Immutable and @Stable instruct the Compose compiler to generate structural equality (oldVal == newVal) checks in the $changed bitmask logic rather than falling back to referential identity (oldVal === newVal).
