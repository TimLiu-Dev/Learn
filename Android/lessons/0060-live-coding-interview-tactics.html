Technical live coding screens test more than syntax: interviewers evaluate your thought process, communication, edge case handling, and ability to accept hints.

🌱 Junior Android Dev Mental Model: Live Coding Protocol
  1. Clarify before typing: State assumptions aloud (threading, nullability, empty state, rotation).
  2. Think out loud: Explain why you choose an API (e.g. why flatMapLatest over flatMapMerge).
  3. Write clean idiomatic Kotlin 2.x: Use val by default, sealed interface for states, and handle errors.
  4. Test your own code proactively: Trace through edge cases (null inputs, empty lists, orientation changes) before saying you're finished!

Write a live-coding solution for an operator pipeline fun transformStream(source: Flow<Int>): Flow<Int> that multiplies each number by 2 and drops consecutive identical values with distinctUntilChanged().

🎯 Reference Production Solution 
import kotlinx.coroutines.flow.*

fun transformStream(source: Flow<Int>): Flow<Int> =
    source
        .map { it * 2 }
        .distinctUntilChanged()

Why this works: Concise, declarative Kotlin Flow pipelines prove your mastery of reactive asynchronous streams under live coding conditions.
