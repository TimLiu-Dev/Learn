Jetpack Navigation 3 & Adaptive Multi-Pane Layouts: The 2027 Greenfield Standard

While Navigation 2.8+ (Lesson 0022) modernized route type-safety for existing NavController apps, it inherited a fundamental architectural flaw from the legacy View era: an opaque, internal black-box back stack coupled to a single-pane container (`NavHost`). When building for foldables, tablets, Desktop/ChromeOS, and XR in 2027, a single screen often displays a List pane and a Detail pane side-by-side simultaneously, which violated Navigation 2's assumptions.

Jetpack Navigation 3 (androidx.navigation3) solves this as the 2027 greenfield standard by inverting control: you own the back stack directly as a reactive Compose SnapshotStateList<NavKey> created via rememberNavBackStack(HomeKey). Navigating forward is literally backStack.add(AssetDetailKey("BTC")), and navigating back is backStack.removeLastOrNull()! You pass your list to NavDisplay, which observes your state list, scopes `ViewModelStoreOwner` lifetimes to individual entries via `rememberViewModelStoreNavEntryDecorator()`, and uses SceneStrategy (or Material 3 Adaptive's SupportingPaneScaffold / ListDetailPaneScaffold) to render one or multiple back-stack entries side-by-side based on `WindowSizeClass`.

🌱 Junior Android Dev Mental Model: Nav 2.8 vs Nav 3 in One Sentence

In Navigation 2.8 (brownfield), you send imperative commands (navController.navigate(...)) to a black box and hope its internal state matches your UI. In Navigation 3 (greenfield), your back stack is just a MutableList of @Serializable keys—adding or removing keys from that list automatically drives single-pane transitions on phones and split-pane scenes on foldables!

Senior Interview Trap: Scoping ViewModels to NavEntries in Navigation 3

Because `NavDisplay` is a lightweight display composable, ViewModels created inside an `entry<K>` block will share the parent Activity/Fragment's `ViewModelStore` unless you supply entry decorators! In production Navigation 3, always pass entryDecorators = listOf(rememberSceneSetupNavEntryDecorator(), rememberSavedStateNavEntryDecorator(), rememberViewModelStoreNavEntryDecorator()) to `NavDisplay` so each back-stack entry gets its own isolated `SavedStateRegistry` and `ViewModelStore` that clears automatically when popped from `backStack`.

✅ 2027 Greenfield Standard: Navigation 3 rememberNavBackStack + NavDisplay

@Serializable data object MarketListKey : NavKey
@Serializable data class MarketDetailKey(val ticker: String) : NavKey

@Composable
fun AetherAdaptiveRoot() {
    // 1. User-owned, process-death-resilient SnapshotStateList back stack!
    val backStack = rememberNavBackStack(MarketListKey)

    // 2. NavDisplay renders 1 or 2 panes automatically via SceneStrategy
    NavDisplay(
        backStack = backStack,
        onBack = { backStack.removeLastOrNull() },
        sceneStrategy = ListDetailSceneStrategy(),
        entryDecorators = listOf(
            rememberSceneSetupNavEntryDecorator(),
            rememberSavedStateNavEntryDecorator(),
            rememberViewModelStoreNavEntryDecorator()
        ),
        entryProvider = entryProvider {
            entry<MarketListKey>(metadata = ListDetailSceneStrategy.listPane()) {
                MarketListScreen(onSelect = { id -> backStack.add(MarketDetailKey(id)) })
            }
            entry<MarketDetailKey>(metadata = ListDetailSceneStrategy.detailPane()) { key ->
                MarketDetailScreen(ticker = key.ticker, onBack = { backStack.removeLastOrNull() })
            }
        }
    )
}

sealed interface NavKey
data object MarketListKey : NavKey
data class MarketDetailKey(val symbol: String) : NavKey

enum class WindowWidthSizeClass { COMPACT, EXPANDED }

class Nav3DisplaySimulator(private val backStack: MutableList<NavKey>) {
    fun renderScene(sizeClass: WindowWidthSizeClass): String {
        return when (sizeClass) {
            WindowWidthSizeClass.COMPACT -> {
                val top = backStack.last()
                "[SINGLE-PANE SCENE] Rendering active top entry: $top (stack=${backStack.size})"
            }
            WindowWidthSizeClass.EXPANDED -> {
                val listEntry = backStack.firstOrNull { it is MarketListKey }
                val detailEntry = backStack.lastOrNull { it is MarketDetailKey }
                "[SPLIT-PANE SCENE] LeftPane=$listEntry | RightPane=${detailEntry ?: "PlaceholderPane"}"
            }
        }
    }
}

fun main() {
    val backStack = mutableListOf<NavKey>(MarketListKey)
    val navDisplay = Nav3DisplaySimulator(backStack)

    println("1. Phone (Compact) at launch -> ${navDisplay.renderScene(WindowWidthSizeClass.COMPACT)}")
    backStack.add(MarketDetailKey("SOL"))
    println("2. Phone after backStack.add(MarketDetailKey("SOL")) -> ${navDisplay.renderScene(WindowWidthSizeClass.COMPACT)}")
    println("3. User unfolds device to Expanded -> ${navDisplay.renderScene(WindowWidthSizeClass.EXPANDED)}")
    backStack.removeLastOrNull()
    println("4. After backStack.removeLastOrNull() on Expanded -> ${navDisplay.renderScene(WindowWidthSizeClass.EXPANDED)}")
}

import androidx.compose.runtime.Composable
import kotlinx.serialization.Serializable

@Serializable data object PortfolioListKey : NavKey
@Serializable data class AssetPaneKey(val symbol: String) : NavKey

@Composable
fun AdaptivePortfolioApp() {
    val backStack = rememberNavBackStack(PortfolioListKey)

    NavDisplay(
        backStack = backStack,
        onBack = { backStack.removeLastOrNull() },
        entryProvider = entryProvider {
            entry<PortfolioListKey> {
                PortfolioListContent(
                    onOpenAsset = { symbol -> backStack.add(AssetPaneKey(symbol)) }
                )
            }
            entry<AssetPaneKey> { key ->
                AssetDetailContent(symbol = key.symbol)
            }
        }
    )
}

Why this works: rememberNavBackStack creates a SnapshotStateList<NavKey> that survives configuration changes and process death, while NavDisplay observes list mutations (add / removeLastOrNull) directly to drive single-pane or adaptive multi-pane transitions.

Quiz 1: Code Analysis & Bug Hunt

Examine this Navigation 3 setup. Why does `DetailViewModel`'s `onCleared()` never fire when the user navigates back from `MarketDetailKey` to `MarketListKey`, causing a memory leak of old detail ViewModels?

@Composable
fun BrokenNav3Host() {
    val backStack = rememberNavBackStack(MarketListKey)
    NavDisplay(
        backStack = backStack,
        onBack = { backStack.removeLastOrNull() },
        // Notice: entryDecorators omitted!
        entryProvider = entryProvider {
            entry<MarketDetailKey> { key ->
                val vm: DetailViewModel = viewModel(key = key.symbol)
                DetailScreen(vm)
            }
        }
    )
}
backStack.removeLastOrNull() does not trigger Compose snapshot invalidation unless wrapped in a coroutine.
Without `rememberViewModelStoreNavEntryDecorator()` in `entryDecorators`, `viewModel()` resolves against the parent Activity's `ViewModelStoreOwner`, which stays alive until the entire Activity finishes.
Navigation 3 does not support ViewModels and requires all state to live inside composable remember blocks.
entryProvider caches composable lambdas permanently in static memory.

Quiz 2: Production Architectural Reasoning

What happens in a Navigation 3 app using `ListDetailSceneStrategy` (or `SupportingPaneScaffold`) when a user on a foldable phone opens `MarketListKey`, taps an item (`backStack.add(MarketDetailKey("BTC"))`), and then physically unfolds the device into an expanded tablet posture?

The app must clear the back stack and restart from the home destination whenever WindowSizeClass changes.
NavDisplay throws an IllegalStateException if two entries from the same back stack are visible simultaneously.
Because the single `backStack` holds `[MarketListKey, MarketDetailKey("BTC")]`, `NavDisplay` seamlessly recomposes the Scene to display both `MarketListKey` in the left pane and `MarketDetailKey("BTC")` in the right pane without losing scroll position or state.
Android restarts the process whenever a foldable screen unfolds.
