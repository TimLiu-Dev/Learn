Extension Functions, Generics & Reified Type Parameters

Build ergonomic Android utility APIs and overcome JVM type erasure with inline reified generics.

Recommended Primary Source
Kotlin Docs: Inline Functions & Reified Type Parameters
Official Documentation →

On the JVM, generic types are subject to Type Erasure. At runtime, List<String> and List<Int> become raw List, preventing checks like if (item is T). Kotlin solves this cleanly using inline functions with reified type parameters (inline fun <reified T>), inlining bytecode directly at the call site where the concrete class type is known.

🌱 Junior Android Dev Mental Model: Clean Syntax without Reflection

Instead of passing ugly class tokens like Intent(context, DetailActivity::class.java) or manually casting JSON models, reified parameters let you write clean APIs like context.startActivity<DetailActivity>() or bundle.getParcelable<User>().

2027 Production Standard (Runnable Example)

Click ▶ Run Example to execute this snippet and inspect the simulated runtime output and state transformations:

KOTLIN 2.X ReifiedGenerics.kt 
inline fun <reified T> filterType(list: List<Any>): List<T> =
    list.filterIsInstance<T>()

fun main() {
    val mixedList: List<Any> = listOf("Kotlin", 42, "Compose", 2027, true)
    
    val strings: List<String> = filterType<String>(mixedList)
    val numbers: List<Int> = filterType<Int>(mixedList)

    println("[LOG] Filtered Strings: $strings")
    println("[LOG] Filtered Integers: $numbers")
    println("[SUCCESS] Reified type parameter checked concrete types without type erasure!")
}

🎯 Reference Production Solution 
inline fun <reified T> Map<String, Any>.getAs(key: String): T? =
    this[key] as? T

fun testExtractor(map: Map<String, Any>): String? =
    map.getAs<String>("user_name")

Why this works: Marking the function as inline copies the bytecode into the call site, enabling the compiler to replace the generic placeholder T with the actual type String, preserving type checks after compilation.
