Extension Functions, Generics & Reified Type Parameters

Build ergonomic Android utility APIs and overcome JVM type erasure with inline reified generics.

Recommended Primary Source
Kotlin Docs: Inline Functions & Reified Type Parameters
Official Documentation →

On the Android Runtime (ART) and JVM, generics are implemented via Type Erasure: at compile time, the K2 compiler enforces type constraints on List<UserProfile> and Flow<NetworkResponse<Order>>, but the emitted bytecode erases the type arguments to raw List and Flow. Consequently, attempting to write if (value is T) or T::class.java inside a regular generic function fails to compile because the runtime token for T no longer exists.

Kotlin solves this without reflection overhead by combining inline functions with reified type parameters (inline fun <reified T>). When a function is marked inline, the compiler splices the function's bytecode body directly into every call site and substitutes T with the concrete class token known statically at that call site. This powers modern Android APIs like Intent.getParcelableExtra<T>(), SavedStateHandle.toRoute<T>(), Hilt's hiltViewModel<T>(), and kotlinx.serialization's Json.decodeFromString<T>().

🌱 Junior Android Dev Mental Model: Variance (in vs out) — PECS

When designing generic repositories or UI mappers, remember Producer out, Consumer in:
• out T (Covariance): The class only produces/returns T (e.g., Flow<out T>, List<out T>). Therefore, a Producer<Dog> is safely a subtype of Producer<Animal>.
• in T (Contravariance): The class only consumes/accepts T (e.g., Comparable<in T>, EventSink<in T>). A Consumer<Animal> can safely handle a Dog, so it is a subtype of Consumer<Dog>.

Under the Hood: Extension Functions & Static Dispatch

An extension function like fun Context.openSettings() does not modify the Context class bytecode or attach a method to its virtual method table (vtable). Instead, it compiles to a public static final void openSettings(Context thisopenSettings) method in a synthetic file class. Because extensions are resolved statically at compile time based on the declared variable type—not dynamically via polymorphic vtable lookup—defining an extension with the same signature for both a superclass and subclass is a dangerous anti-pattern.

⚠️ Senior Interview Trap: noinline, crossinline, and Bytecode Bloat

  • When does inline hurt performance? Inlining a 100-line function that takes no lambdas and no reified types bloats your APK's DEX size and overflows CPU instruction caches. Only use inline when accepting higher-order lambdas (to avoid allocating FunctionN closure objects and enable non-local return) or when using reified T.
  • Why use crossinline? By default, a lambda passed to an inline fun can execute a non-local return (returning from the enclosing caller function). If your inline function passes that lambda into another execution context—such as a coroutine launch { ... } or a Runnable { ... }—a non-local return is impossible after the outer function has already returned. Marking the parameter crossinline keeps the lambda inlined while forbidding non-local returns.

    cache: Map<String, Any>,
    key: String,
    clazz: Class<T>

    val raw = cache[key] ?: return null
    @Suppress("UNCHECKED_CAST")

✅ 2027 Senior Standard: Inline Reified Extension API

// Zero reflection, compile-time type inference at call site:
// val profile: UserProfile? = cache.getTyped("current_user")
inline fun <reified T : Any> Map<String, Any?>.getTyped(
    key: String
): T? = this[key] as? T

inline fun <reified T : Any> Iterable<*>.firstInstanceOf(
    crossinline predicate: (T) -> Boolean = { true }
): T? = filterIsInstance<T>().firstOrNull { predicate(it) }

sealed interface TelemetryPayload {
    val timestampMs: Long
}

data class ScreenViewPayload(val route: String, override val timestampMs: Long) : TelemetryPayload
data class CrashReportPayload(val stackHash: String, val fatal: Boolean, override val timestampMs: Long) : TelemetryPayload
data class NetworkTimingPayload(val endpoint: String, val latencyMs: Int, override val timestampMs: Long) : TelemetryPayload

// Contravariant consumer interface: EventHandler<TelemetryPayload> can handle CrashReportPayload
fun interface EventConsumer<in T> {
    fun accept(event: T)
}

// Reified inline extension: filters heterogeneous stream to exact subtype T at zero reflection cost
inline fun <reified T : TelemetryPayload> List<TelemetryPayload>.dispatchMatching(
    crossinline filterBlock: (T) -> Boolean = { true },
    consumer: EventConsumer<T>
) {
    for (item in this) {
        if (item is T && filterBlock(item)) {
            consumer.accept(item)
        }
    }
}

fun main() {
    val buffer: List<TelemetryPayload> = listOf(
        ScreenViewPayload(route = "/home", timestampMs = 100L),
        NetworkTimingPayload(endpoint = "/v2/feed", latencyMs = 42, timestampMs = 110L),
        CrashReportPayload(stackHash = "0x99f2a", fatal = true, timestampMs = 125L),
        CrashReportPayload(stackHash = "0x11b0c", fatal = false, timestampMs = 140L)
    )

    println("[DISPATCH] Scanning telemetry buffer for fatal CrashReportPayloads...")
    buffer.dispatchMatching<CrashReportPayload>(
        filterBlock = { it.fatal },
        consumer = { crash ->
            println("[ALERT] Fatal crash detected: hash=${crash.stackHash} at t=${crash.timestampMs}ms")
        }
    )
}

inline fun <reified T : Any> Map<String, Any?>.requireTyped(
    key: String
): Result<T> {
    val raw = this[key]
    return if (raw is T) {
        Result.success(raw)
    } else {
        Result.failure(
            IllegalArgumentException("Expected ${T::class.simpleName} for key '$key'")
        )
    }
}

Why this works: Marking the extension function 'inline' with '<reified T : Any>' preserves the concrete type T at the call site, enabling both the runtime 'raw is T' smart cast and 'T::class.simpleName' diagnostic inspection.
