High-Performance Lists: LazyColumn & Item Animations

Render 10,000+ items smoothly with LazyColumn, stable keys, contentType optimization, and animateItem.

Recommended Primary Source
Google Android: Lazy lists and grids in Compose
Official Documentation →

While a standard Column(Modifier.verticalScroll(...)) composes and lays out 100% of its children upfront—immediately exhausting RAM and dropping dozens of frames on a 5,000-item feed—LazyColumn, LazyVerticalGrid, and LazyVerticalStaggeredGrid are built on top of LazyLayout (backed by SubcomposeLayout + LazyLayoutPrefetchScheduler). Only the items intersecting the visible viewport (plus a small prefetch window ahead of the scroll vector) are composed and measured.

To hit a rock-solid 120fps (8.33ms frame budget) on flagship Android devices, senior engineers optimize four critical pillars of <code>LazyLayout</code>:

  1. Stable <code>key</code>s (<code>items(feed, key = { it.id })</code>): By default, <code>LazyColumn</code> keys items by their integer index (<code>0, 1, 2...</code>). If a new item is inserted at index 0 without an explicit <code>key</code>, every visible item's index shifts by +1—forcing Compose to recompose every visible row and corrupting any internal <code>remember</code> state! Providing a unique, Parcelable <code>key</code> binds slot identity to the domain entity and enables <strong><code>Modifier.animateItem()</code></strong> (which unified placement, fade-in appearance, and fade-out disappearance animations in Compose 1.7+).
  2. <code>contentType</code> Slot Recycling (<code>contentType = { it.cardType }</code>): Just like legacy <code>RecyclerView.getItemViewType()</code>, specifying <code>contentType</code> tells <code>LazyLayoutItemContentFactory</code> and <code>SubcomposeLayoutState</code> which items share identical composition structure so deactivated slot compositions can be pooled and reused ONLY among matching item types instead of tearing down and rebuilding different trees!
  3. <code>LazyLayoutCacheWindow</code> & Prefetching: When a user flings a list, Compose's <code>LazyLayoutPrefetchScheduler</code> checks the remaining nanoseconds before the next Choreographer VSync deadline and pre-composes + pre-measures upcoming items during idle frame time.
  4. Guarding <code>LazyListState</code> Reads: Never read <code>lazyListState.firstVisibleItemScrollOffset</code> directly inside your Composable scope! It changes on every scrolled pixel, triggering full-screen recomposition 120 times per second. Always wrap threshold checks inside <code>remember { derivedStateOf { lazyListState.firstVisibleItemIndex > 0 } }</code> or observe via <code>snapshotFlow { lazyListState.firstVisibleItemIndex }</code> inside a <code>LaunchedEffect</code>.
🌱 Junior Android Dev Mental Model: Never Nest Same-Axis Scrollables!

Placing a vertically scrolling LazyColumn (or Modifier.verticalScroll()) inside another vertically scrolling container without bounded height constraints throws a fatal runtime crash: IllegalStateException: Vertically scrollable component was measured with an infinity maximum height constraint! Instead, flatten multiple sections into a single LazyColumn DSL using multiple item { Header() }, stickyHeader { ... }, and items(sectionA) { ... } blocks.

❌ Junior Anti-Pattern: Positional Keys, Missing contentType & Scroll Jank

@Composable
fun FeedList(items: List<FeedItem>, listState: LazyListState) {
    // BUG 1: Direct state read recomposes the entire screen on every pixel!
    val showFab = listState.firstVisibleItemIndex > 2

    LazyColumn(state = listState) {
        // BUG 2: No key and no contentType! Inserting at index 0
        // recomposes every row and breaks slot recycling across item types!
        items(items) { item ->
            FeedRow(item)
        }
    }
}

✅ 2027 Senior Standard: Stable Keys + contentType + animateItem() + derivedStateOf

@Composable
fun FeedList(items: List<FeedItem>, listState: LazyListState) {
    // Only invalidates when boolean threshold flips (true <-> false)!
    val showFab by remember {
        derivedStateOf { listState.firstVisibleItemIndex > 2 }
    }

    LazyColumn(state = listState) {
        items(
            items = items,
            key = { it.id },
            contentType = { it.kind } // Enables exact composition slot reuse!
        ) { item ->
            FeedRow(
                item = item,
                modifier = Modifier.animateItem() // Smooth fade + placement spring
            )
        }
    }
}

enum class FeedContentType { TEXT_POST, VIDEO_CARD, SPONSORED_BANNER }
data class FeedEntry(val id: String, val type: FeedContentType, val title: String)

class SimulatedSubcomposeReusePool {
    private val reusableSlotsByType = mutableMapOf<FeedContentType, MutableList<String>>()
    var totalAllocations = 0
        private set
    var totalPoolHits = 0
        private set

    fun deactivateOffscreenItem(entry: FeedEntry) {
        reusableSlotsByType.getOrPut(entry.type) { mutableListOf() }.add(entry.id)
        println("[POOL] Deactivated '${entry.id}' into bucket [${entry.type}]")
    }

    fun composeEnteringItem(entry: FeedEntry) {
        val bucket = reusableSlotsByType[entry.type]
        if (!bucket.isNullOrEmpty()) {
            val recycledFrom = bucket.removeAt(0)
            totalPoolHits++
            println("[PREFETCH HIT] Reused [${entry.type}] slot from '$recycledFrom' for '${entry.id}' (0 new node allocations)")
        } else {
            totalAllocations++
            println("[ALLOCATE] Created fresh [${entry.type}] composition slot for '${entry.id}'")
        }
    }
}

fun main() {
    val pool = SimulatedSubcomposeReusePool()
    val p1 = FeedEntry("post_1", FeedContentType.TEXT_POST, "Kotlin 2.2 Released")
    val v1 = FeedEntry("vid_1", FeedContentType.VIDEO_CARD, "Compose 120fps Deep Dive")
    val p2 = FeedEntry("post_2", FeedContentType.TEXT_POST, "Slot Table Internals")

    pool.composeEnteringItem(p1)
    pool.composeEnteringItem(v1)
    // User scrolls down: post_1 leaves viewport, post_2 enters viewport
    pool.deactivateOffscreenItem(p1)
    pool.composeEnteringItem(p2)
    println("[METRICS] Allocations=${pool.totalAllocations}, PoolReuseHits=${pool.totalPoolHits}")
}

import androidx.compose.foundation.lazy.*
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier

data class TxItem(val id: String, val category: String, val amountCents: Long)

@Composable
fun TransactionRow(tx: TxItem, modifier: Modifier = Modifier) {}

@Composable
fun TransactionFeed(transactions: List<TxItem>, listState: LazyListState) {
    val isScrolled by remember {
        derivedStateOf { listState.firstVisibleItemIndex > 0 }
    }

    LazyColumn(state = listState) {
        items(
            items = transactions,
            key = { it.id },
            contentType = { it.category }
        ) { tx ->
            TransactionRow(
                tx = tx,
                modifier = Modifier.animateItem()
            )
        }
    }
}

Why this works: derivedStateOf prevents scroll-frame recomposition storms, key = { it.id } preserves item identity across insertions/deletions, contentType = { it.category } partitions composition slot pooling by item structure, and Modifier.animateItem() animates item appearance, disappearance, and reordering.

Quiz 2: Production Architectural Reasoning

In a LazyColumn displaying a heterogeneous feed of TextPosts, ImageGalleries, and VideoPlayers, why is providing 'contentType = { it.type }' critical for 120fps scrolling performance?

contentType becomes strictly required by the Compose compiler plugin whenever itemKey is supplied to LazyListScope.items().
contentType instructs Compose to synthesize @Stable metadata annotations onto unstable feed model classes during runtime.
contentType lets SubcomposeLayout reuse matching composition slots instead of tearing down mismatched item trees mid-scroll.
contentType pre-rasterizes identical feed composables onto a single shared HardwareBuffer texture inside dedicated GPU memory.
