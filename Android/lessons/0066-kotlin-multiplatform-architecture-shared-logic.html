Kotlin Multiplatform (KMP): Architecture, expect/actual & Shared Logic

Share domain models, validation, and repositories across Android and iOS natively without leaking platform dependencies into commonMain.

Recommended Primary Source
Kotlin Official Docs: Kotlin Multiplatform Overview
Official Documentation →

Unlike wrapper frameworks, Kotlin Multiplatform (KMP) compiles Kotlin to JVM bytecode on Android and native LLVM binaries (XCFramework) on iOS. Your :shared module separates platform-agnostic code (commonMain) from platform bridges (androidMain, iosMain), letting teams share networking, caching, and business rules while keeping Jetpack Compose on Android and SwiftUI (or Compose Multiplatform) at the UI layer.

🌱 Senior Judgment: Interface Injection Beats Overusing expect/actual

Juniors sprinkle expect class everywhere in commonMain, which turns unit testing into a platform-linker headache. Seniors reserve expect/actual for tiny leaf primitives (like PlatformLogger or engine factories) and define regular Kotlin interfaces in commonMain implemented in androidMain/iosMain—making commonTest 100% fakeable! Also check Lesson 0039 and Reference Sheet 04.

❌ Junior Pitfall: Leaking JVM Types into commonMain

Importing java.util.UUID, java.time.Instant, or android.content.Context inside commonMain breaks iOS compilation immediately.

✅ 2027 Senior Standard: Pure Kotlin + Multiplatform Libs

Use kotlin.time / kotlinx-datetime, kotlinx.coroutines, and interface abstractions in commonMain, bridged to Swift via SKIE or clean wrappers.

2027 Production Standard (Runnable Example)

Click ▶ Run Example to simulate a pure commonMain portfolio calculator shared identically between Android (Compose) and iOS (SwiftUI):

KOTLIN 2.X (commonMain) SharedAllocationUseCase.kt 
interface DeviceClock {
    fun epochMillis(): Long
}

class CalculateAllocationUseCase(private val clock: DeviceClock) {
    fun weightPercent(assetUsd: Double, totalUsd: Double): Double =
        if (totalUsd <= 0.0) 0.0 else (assetUsd / totalUsd) * 100.0
}

fun main() {
    val useCase = CalculateAllocationUseCase(object : DeviceClock { override fun epochMillis() = 1_794_555_000L })
    val pct = useCase.weightPercent(6250.0, 10000.0)
    println("[commonMain] Calculating net allocation with zero JVM/Android imports...")
    println("[ANDROID-UI] Rendering Compose PortfolioRow(symbol=BTC, weight=$pct%)")
    println("[IOS-SWIFTUI] Rendering SwiftUI PortfolioRow(symbol=BTC, weight=$pct%)")
    println("[commonTest] Passed on JVM + iOS Simulator targets identically!")
}

Quiz 1: Code Analysis & Bug Hunt

Why does importing java.util.UUID inside commonMain fail a Kotlin Multiplatform build?

iOS and Native targets compile with Kotlin/Native and have no JVM standard library
Kotlin 2.x forbids generating random identifiers inside shared domain layer modules
Gradle Version Catalogs automatically block all java.* packages in Android apps
SwiftUI forbids receiving string identifiers generated by compiled XCFramework binaries
