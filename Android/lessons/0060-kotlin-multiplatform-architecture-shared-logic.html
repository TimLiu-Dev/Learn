Kotlin Multiplatform (KMP): Architecture, expect/actual & Shared Logic

Share domain models, validation, and repositories across Android and iOS natively without leaking platform dependencies into commonMain.

Recommended Primary Source
Kotlin Official Docs: Kotlin Multiplatform Overview
Official Documentation →

In 2027, Kotlin Multiplatform (KMP) is officially endorsed by Google and JetBrains as the industry standard for sharing business logic, networking, caching, and domain rules across Android, iOS, Desktop, and Server. Unlike cross-platform webviews or single-threaded JS bridges, KMP compiles commonMain Kotlin source code directly to JVM bytecode for Android and ahead-of-time native ARM64 machine code (.xcframework) via LLVM for iOS. Since Kotlin 2.x, Kotlin/Native's modern concurrent garbage collector and thread-safe memory manager allow coroutines and immutable/mutable state to cross threads seamlessly on iOS just like on the JVM.

Structuring a senior-grade KMP module requires discipline at two boundaries: Dependency Direction (commonMain vs androidMain / iosMain) and Swift Interoperability. First, commonMain must remain 100% free of java.* and android.* imports—use kotlinx.coroutines, kotlinx.serialization, kotlinx-datetime (or kotlin.time.Duration), and kotlin.uuid.Uuid. Second, resist overusing expect class / actual class for complex services! Reserve expect/actual for lightweight platform factories or leaf utilities, and prefer standard Kotlin interfaces in commonMain injected via constructor DI so commonTest can swap in pure Kotlin Fakes without needing platform linker tricks. Finally, when exposing Kotlin APIs to Swift (iosMain), basic Objective-C header interop erases Kotlin Flow<T> generics and turns sealed interface hierarchies into awkward class references—so production teams enable Touchlab SKIE (Swift Kotlin Interface Enhancer), which automatically bridges Kotlin StateFlow/Flow into native Swift AsyncSequence (for await state in viewModel.uiState) and Kotlin sealed types into exhaustive Swift enums!

🌱 Junior Android Dev Mental Model: Why Default Parameters Disappear in Swift

Kotlin functions with default arguments—like fun fetchFeed(limit: Int = 20, forceRefresh: Boolean = false)—do not generate default parameter overloads in Objective-C/Swift headers out of the box, forcing iOS developers to pass every parameter manually unless you use SKIE (which generates Swift default argument wrappers automatically) or explicit overloads!

Senior Interview Trap & Production Edge Case

Trap: Catching exceptions across the Kotlin-to-Swift boundary without declaring @Throws(MyDomainException::class) (or returning a typed Result / Either / sealed interface state). In Kotlin/Native, if an uncaught Kotlin exception crosses into Swift from a function that is not annotated with @Throws, the Kotlin runtime terminates the iOS app immediately with a fatal abort()! Senior KMP architects never use raw exceptions for expected network/validation failures across language boundaries—they return typed sealed interface results.
Edge Case: Exposing 20 internal :core:* Gradle modules individually to Xcode creates duplicate runtime symbols and gigantic .xcframework binaries. Always create a single Umbrella :shared Module on iOS that exports (export(project(":core:domain"))) only the public surface area needed by SwiftUI.

❌ Junior Anti-Pattern: JVM Leaks & Unchecked Throwing to Swift

// commonMain: Fails to compile on iOS (java.util.UUID) & crashes Swift on throw!
import java.util.UUID // ERROR: Unresolved reference 'java' in commonMain!

class SharedAuthService {
    suspend fun login(email: String): String {
        if (!email.contains("@")) throw IllegalArgumentException("Bad email") // Fatal abort in Swift!
        return UUID.randomUUID().toString()
    }
}

// Pure commonMain code: compiles identically to Android DEX and iOS ARM64 XCFramework
fun interface MultiplatformClock {
    fun nowMs(): Long
}

sealed interface TradeValidationResult {
    data class ValidOrder(val orderId: String, val notionalUsd: Double, val timestampMs: Long) : TradeValidationResult
    data class Rejected(val code: String, val reason: String) : TradeValidationResult
}

class SharedOrderUseCase(private val clock: MultiplatformClock) {
    fun validateAndPrepareOrder(
        symbol: String,
        quantity: Double,
        priceUsd: Double,
        maxRiskUsd: Double = 50_000.0
    ): TradeValidationResult {
        val cleanSymbol = symbol.trim().uppercase()
        if (cleanSymbol.isEmpty() || quantity <= 0.0 || priceUsd <= 0.0) {
            return TradeValidationResult.Rejected("INVALID_INPUT", "Symbol, quantity, and price must be positive")
        }
        val notional = quantity * priceUsd
        if (notional > maxRiskUsd) {
            return TradeValidationResult.Rejected("RISK_CAP_EXCEEDED", "Notional $$notional exceeds limit $$maxRiskUsd")
        }
        val ts = clock.nowMs()
        return TradeValidationResult.ValidOrder("ord_${cleanSymbol}_$ts", notional, ts)
    }
}

fun main() {
    val fakeClock = MultiplatformClock { 1740990000000L }
    val useCase = SharedOrderUseCase(fakeClock)

    println("[commonMain -> Android/iOS] Valid order : ${useCase.validateAndPrepareOrder("btc", 0.4, 92_000.0)}")
    println("[commonMain -> Android/iOS] Over limit  : ${useCase.validateAndPrepareOrder("btc", 1.2, 92_000.0)}")
    println("[commonMain -> Android/iOS] Bad quantity: ${useCase.validateAndPrepareOrder("eth", -2.0, 3_100.0)}")
}

sealed interface AllocationCheck {
    data class Balanced(val totalPct: Int) : AllocationCheck
    data class Invalid(val reason: String) : AllocationCheck
}

fun validateAllocations(weightsPct: Map<String, Int>): AllocationCheck {
    if (weightsPct.isEmpty()) {
        return AllocationCheck.Invalid("EMPTY")
    }
    if (weightsPct.values.any { it < 0 }) {
        return AllocationCheck.Invalid("NEGATIVE_WEIGHT")
    }
    val sum = weightsPct.values.sum()
    if (sum != 100) {
        return AllocationCheck.Invalid("SUM_NOT_100")
    }
    return AllocationCheck.Balanced(sum)
}

Why this works: Using a pure Kotlin sealed interface in commonMain prevents uncaught cross-language exceptions on iOS and compiles via SKIE into an exhaustive Swift enum with zero JVM dependencies.

When the device is offline, Ktor throws an IOException inside Kotlin, and the iOS app crashes immediately with a fatal native abort instead of entering Swift's catch block! Why?

// Inside KMP commonMain (No @Throws annotation, returns raw UserProfile)
class SharedUserRepository(private val api: KmpApiClient) {
    suspend fun fetchProfile(id: String): UserProfile {
        return api.get("/users/$id") // Throws IOException when offline!
    }
}
Swift structured concurrency async/await cannot invoke compiled Kotlin suspend functions on modern 64-bit iPhone architectures.
Kotlin Multiplatform strips all try/catch blocks inside Xcode builds whenever iOS devices enter Airplane Mode.
Kotlin string interpolation syntax is exclusively supported on Android JVM targets and crashes LLVM backends.
Kotlin/Native only bridges CancellationException to NSError unless annotated with @Throws or returning a typed Result.
