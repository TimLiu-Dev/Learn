One fact worth knowing about each

  • Orbit: side effects are cached with no observer and go to one collector by default. Its test DSL uses expectState { } and expectSideEffect(). API renamed to OrbitContainerHost / orbitContainer.
  • Mavericks: setState is queued on a background thread, not immediate. Async<T> = Uninitialized / Loading / Success / Fail. @PersistState handles process death.
  • MVIKotlin: Intent → Executor → Msg → Reducer, plus Labels and a Bootstrapper. Kotlin Multiplatform, with time-travel debugging.

When MVI is overkill

Use it when there are many interacting transitions, you want every transition tested, or a team needs one consistent shape. Skip it when a screen has one or two independent values, or when the Intent, Result and State types would outnumber the logic. Google's single-UiState MVVM already gives you most of the benefit.
