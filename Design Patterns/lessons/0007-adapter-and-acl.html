Adapter & Anti-Corruption Layer (ACL)

Third-party payment SDKs ship weird naming, callback-based APIs, float-dollar amounts, and breaking v2→v3 migrations. An Adapter translates incompatible interfaces; an Anti-Corruption Layer ensures vendor DTO quirks never leak into :core:domain.

StructuralVendor IsolationDTO MappersRetrofit / Ktor

1. Object Adapter: Bridging Incompatible Contracts

Per Refactoring.Guru, an Adapter wraps an existing class with a different interface so callers only see your clean Domain interface.

Kotlin — Wrapping Legacy Stripe Callback SDK
// Domain contract (pure Kotlin)
interface PaymentGateway { fun charge(cents: Long): Receipt }

// Legacy vendor SDK uses Dollars as Double + weird status integers!
class LegacyStripeAdapter(private val sdk: LegacyStripeSdk) : PaymentGateway {
    override fun charge(cents: Long): Receipt {
        val raw = sdk.doChargeDollars(cents / 100.0) // Translation boundary!
        return Receipt(id = raw.refCode, approved = raw.statusCode == 200)
    }
}

2. Anti-Corruption Layer (ACL) in 2027 Android

Never annotate your Domain models with @SerializedName or @Entity! Keep Retrofit JSON DTOs and Room Entities strictly in :core:network and :core:database, translating at the boundary via mapper functions.

5. 2027 Senior Android Interview Corner

Q1: "Why not just put `@JsonClass` and `@Entity` on one shared `Transaction` class to avoid writing mappers?"
Senior Answer: Sharing one model couples UI, business rules, SQLite schema migrations, and backend JSON renames together. If the backend renames `tx_amt` to `amountCents`, or Room needs a foreign-key column, you break Domain and Compose previews. Mappers are 10 lines of trivial, testable code that buy complete isolation.
