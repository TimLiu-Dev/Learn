Flyweight, Interpreter & Null Object (Java & Kotlin Side-by-Side)

Welcome to Part 3—where every lesson compares Java 21+ Spring Boot and Kotlin Spring Boot side by side! First, we close out the final two classic Gang of Four patterns—Flyweight and Interpreter (plus Null Object)—bringing your mastery to 23 / 23 GoF Patterns.

FlyweightInterpreterNull ObjectJava + Kotlin Spring

1. Flyweight: Sharing Immutable Intrinsic State Across 100k Rows

When exporting 100,000 ledger rows in Spring Boot, allocating 100,000 duplicate `CurrencyMeta("USD", "$", 2)` objects wastes heap. Flyweight caches and shares the immutable intrinsic metadata (`CurrencyFlyweightFactory.of("USD")`) while keeping extrinsic per-row data (`amountCents`, `txId`) separate! (Unlike Object Pool, Flyweights are immutable and shared concurrently without check-out/release!)

2. Interpreter & Null Object

  • Interpreter: Represents a mini-language (e.g. dynamic risk rules `"amount > 50000 AND country == 'NG'"`) as an AST of expression objects evaluated against a transaction context.
  • Null Object: Instead of `if (auditSink != null) auditSink.record(...)` everywhere, inject a no-op `NoOpAuditSink` implementing the same interface!

5. 2027 Senior Interview Corner

Q1: "When is Interpreter useful in Spring Boot vs. when should you use an existing rules engine / CEL?"
Senior Answer: Small, fixed internal grammars (like query filters or 4-operator compliance rules) are clean to model with Interpreter + Composite. For arbitrary user-authored scripts or complex expressions, embed a battle-tested evaluator (SpEL sandboxed, CEL-Java) to avoid parser bugs and security vulnerabilities!
