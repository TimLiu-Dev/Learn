Lesson 0018 • Phase 3: Behavioral Patterns

Mediator, Iterator & Visitor (Modern Kotlin Edition)

Rounding out the classic Gang of Four Behavioral catalog with three focused patterns: Mediator stops peer widgets/panes from forming N² spaghetti links (like tablet adaptive two-pane navigation); Iterator powers lazy paginated cursors (`Paging 3`); and Visitor (simplified in Kotlin via `sealed` exhaustive `when`) separates export formats (CSV/JSON/PDF) from Ledger domain classes!

BehavioralTwo-Pane CoordinatorPaginated CursorMulti-Format Export

1. Mediator: N-to-1 Hub Instead of N² Mesh

When RecipientPicker, AmountInput, FeeBadge, and SubmitButton each hold direct references to one another, changing one widget breaks three. A Mediator (like a parent Compose state holder or Navigation Coordinator) centralizes coordination so children emit intents to the hub without knowing peer widgets.

2. Iterator (Lazy Paging) & Visitor (Sealed Ledger Exporters)

Instead of loading 50,000 ledger rows into memory, an Iterator / Cursor fetches pages lazily on demand. And instead of stuffing toCsv(), toPdf(), and toTaxJson() onto domain LedgerEntry classes, a Visitor separates export formatting from domain data.

5. 2027 Senior Android Interview Corner

Q1: "Why do Kotlin developers rarely write classic Java `accept(Visitor)` double-dispatch methods?"
Senior Answer: Classic double-dispatch existed because Java lacked sealed exhaustiveness and smart casts. In Kotlin, a `sealed interface LedgerEntry` + an exhaustive `when (entry)` inside `CsvStatementVisitor` achieves the exact same Visitor separation with zero `accept()` boilerplate on domain models!
