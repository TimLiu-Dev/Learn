Modern Java (21–25) & Spring IoC/DI Strategy Injection

Junior Java Spring developers write Lombok-heavy mutable POJOs, field-inject dependencies with @Autowired, and switch on rail strings inside bloated @Service classes. 2027 Senior Backend Engineers model domains with Java Records + Sealed Interfaces + Pattern Matching and wire polymorphic Strategies cleanly via Spring's Map<String, RailBean> constructor injection!

Java 21+Spring IoC / DIRecords & SealedMap Bean Injection

1. Data-Oriented Java: Records, Sealed Interfaces & Exhaustive Switch

Per Oracle Java Pattern Matching Docs and Sealed Classes, Java now enforces compile-time exhaustiveness on domain results without `default:` fallbacks.

Java 21+ — Sealed SettlementResult with Record Deconstruction
public sealed interface SettlementResult permits Settled, Rejected {
    record Settled(String txId, long cents) implements SettlementResult {}
    record Rejected(String code) implements SettlementResult {}
}

static int httpStatusFor(SettlementResult res) {
    return switch (res) {
        case Settled(var id, var cents) -> 200;
        case Rejected(var code) -> 422;
    }; // Exhaustive! Zero default branch needed.
}

5. 2027 Senior Backend Interview Corner

Q1: "Why is field `@Autowired` banned in Senior Spring Boot codebases?"
Senior Answer: 1) Fields cannot be `final`, breaking immutability and safe publication. 2) Unit tests cannot instantiate the class with plain `new MyService(fakeRepo)` without Spring reflection. 3) Constructor injection surfaces 10-dependency God-classes immediately in PR reviews.
