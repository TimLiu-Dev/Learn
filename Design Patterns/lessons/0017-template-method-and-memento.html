Lesson 0017 • Phase 3: Behavioral Patterns

Template Method vs. Higher-Order Functions & Memento

Two pragmatic tools: Template Method standardizes an algorithm's invariant skeleton (Acquire Lock → Fetch → Persist → Release Lock)—which in 2027 Kotlin is usually cleaner via higher-order functions than inheritance; and Memento snapshots/restores multi-step wizard drafts across Android OS process death without exposing private internals.

BehavioralHigher-Order HooksMemento SnapshotSavedStateHandle

1. Template Method: From Inheritance to Kotlin Hooks

Classic GoF Template Method used an `abstract class` with `abstract fun step2()`. Because inheritance couples subclasses tightly (Lesson 0001!), 2027 Kotlin replaces most Template classes with a higher-order function accepting hook lambdas (`runSyncTransaction(fetch = ..., save = ...)`).

2. Memento: Undo & Android Process-Death Restoration

Per Refactoring.Guru, Memento captures an object's internal state in an opaque snapshot (`TransferDraftMemento`) managed by a Caretaker (`SavedStateHandle` or Draft History) so the user doesn't lose a 4-step international wire form when Android kills the backgrounded app!

5. 2027 Senior Android Interview Corner

Q1: "How do you test Android Process Death for a Memento-backed Transfer Wizard?"
Senior Answer: Trigger "Don't keep activities" or background the app and run `adb shell am kill <pkg>`, then resume from Recents. Your ViewModel should restore the draft from `SavedStateHandle` (Memento caretaker) cleanly without losing user-entered recipient/amount fields.
