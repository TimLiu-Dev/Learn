Lesson 0011 • Phase 2: Structural Patterns

Composite & Bridge: Recursive Trees & KMP Platform Splits

Two architectural powerhouses: Composite lets you build arbitrarily nested spending-policy trees (AND(MaxAmount, OR(VerifiedKyc, LowRisk))) treated uniformly as one PolicyRule; Bridge decouples high-level abstractions (SecureWallet) from platform drivers (Android Keystore, iOS Keychain, JVM Test Store).

StructuralComposite TreesKMP BridgeCompose UI

1. Composite: Treating Leaves and Branches Uniformly

Jetpack Compose's entire layout node tree (LayoutNode) is a Composite. In PayVault domain rules, both a single leaf check (MaxAmountRule) and a combined branch (AndRule(rules)) implement the exact same SpendingRule interface.

2. Bridge: Avoiding an M × N Class Matrix in KMP

Suppose you have 2 wallet modes (PersonalWallet, BusinessWallet) × 3 storage platforms (AndroidKeystore, IosKeychain, InMemoryTest). Inheritance creates 6 classes. Bridge separates the Abstraction hierarchy from the Implementation (Driver) hierarchy via composition!

5. 2027 Senior Android Interview Corner

Q1: "Bridge vs. Adapter: both hold a reference to another object. How do you tell them apart?"
Senior Answer: Adapter is retroactive: you use it after code is written to make an existing messy 3rd-party class fit your interface. Bridge is up-front architecture: you design two independent dimensions (e.g., Wallet Type × Platform Storage Driver) so both can evolve independently.
