Observer, Reactive Streams & Kotlin Flow

When a transfer settles in the background, the Wallet Balance header, Recent Activity list, and Badge counter all need to update immediately—without the Ledger knowing any UI screens exist. Observer decouples event producers from subscribers; in 2027 Android, Kotlin Flow (`StateFlow` & `SharedFlow`) replaces error-prone manual listener lists.

1. Classic Observer & The Memory Leak Trap

In naive Android Observer code, an Activity registers a listener on a long-lived `WalletManager` and forgets `unsubscribe()` in `onDestroy()`—leaking the entire screen! Structured concurrency + collectAsStateWithLifecycle() cancels collection automatically when the UI stops.

2. Cold Flow vs. Hot StateFlow vs. SharedFlow

Per the Official Kotlin Flow Guide:

  • Cold flow { }: Runs fresh per collector (great for Room DB queries & one-shot streams).
  • StateFlow: Always holds latest state (`replay = 1`), conflates identical values (ideal for Compose UI state).
  • SharedFlow: Event bus broadcast (`replay = 0` default) for one-time events (though see Lesson 0020 on why State often beats SharedFlow for UI navigation/snackbars!).

5. 2027 Senior Android Interview Corner

Q1: "Why use `collectAsStateWithLifecycle()` instead of `collectAsState()` in Jetpack Compose?"
Senior Answer: `collectAsState()` keeps collecting upstream Flows (database observers, WebSocket FX tickers, GPS) even when the app is backgrounded (`STOPPED`). `collectAsStateWithLifecycle()` cancels collection below `Lifecycle.State.STARTED`, saving battery and avoiding background resource waste.
