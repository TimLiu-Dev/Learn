UDF, MVVM vs. MVI & Jetpack Compose Performance

In 2027 Compose, UI is a pure function of state: State flows down, Events flow up (Unidirectional Data Flow). Learn how MVI reducers unify complex flows, why Google warns against `Channel` / `SharedFlow` for one-off UI events, and how `@Immutable` keeps Compose at 120fps.

2027 ArchitectureJetpack ComposeUDF / MVIcollectAsStateWithLifecycle

1. MVVM vs. MVI in Practice

Both use UDF. MVVM exposes one `StateFlow<UiState>` + named ViewModel methods (`onPayClicked()`). MVI channels every action through a single `onIntent(TransferIntent)` + pure `reduce(state, intent)`. Choose MVI when a screen has intricate multi-step transitions (like PayVault's 3DS transfer sheet), and lean MVVM for simple display screens.

2. Why State Beats Channel for One-Off UI Events

Using a `Channel` or `SharedFlow(replay = 0)` for "Show Receipt Dialog" or "Navigate to 3DS" can drop events if emitted right as the screen rotates (`STOPPED` → `STARTED`)! Official Android guidance recommends modeling one-off events as properties inside `UiState` (e.g., `pendingSnackbar: String?`) cleared via `onSnackbarShown()`.

3. Compose Stability & Avoiding Recomposition Storms

Passing a raw `java.util.List` or mutable `var` object into a `@Composable` can prevent skipping (unless Strong Skipping or `ImmutableList` / `@Immutable` is used). Always expose immutable `UiState` snapshots to Compose!
