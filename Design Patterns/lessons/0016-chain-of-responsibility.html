Lesson 0016 • Phase 3: Behavioral Patterns

Chain of Responsibility: Pre-Flight Compliance Pipelines

Before a PayVault transfer leaves the phone, it must pass KYC Verified → Sufficient Balance → Daily Limit → Fraud Risk. Putting all 4 inside one nested if/else pyramid creates unreadable spaghetti. Chain of Responsibility turns each check into an independent, reorderable handler that either rejects immediately or passes control forward.

BehavioralValidation PipelineShort-CircuitDeep Link Routing

1. Classic Linked Chain vs. Pipeline List

Per Refactoring.Guru, Chain of Responsibility passes a request along a sequence of handlers. In modern Kotlin, an ordered List<TransferCheck> (or linked Handler.handle(req, next)) keeps every rule small, testable, and Open/Closed.

2. Real Android Examples You Already Use

  • Android Touch Dispatch: `Activity → ViewGroup → Child View` (`onTouchEvent` returns `true` to consume or `false` to pass on).
  • Deep Link / Notification Routers: Ordered `DeepLinkHandler`s where the first matching handler opens the screen.

5. 2027 Senior Android Interview Corner

Q1: "When is `Chain of Responsibility` better than a `Composite` rule tree?"
Senior Answer: Use **Chain of Responsibility** when order matters, handlers short-circuit with specific rejection reasons (e.g., fail KYC before wasting an HTTP fraud-score call), or handlers modify/enrich a request as it flows downstream. Use **Composite** for unordered boolean expression trees (`AND`/`OR`).
