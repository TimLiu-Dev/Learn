  1. Enable `spring.threads.virtual.enabled=true` and size HikariCP explicitly (`maximumPoolSize`).
  2. Verify `ApplicationModules.of(PayVaultServerApp.class).verify()` in unit CI.
  3. Isolate `DoubleEntryLedger` + `@Version` locking inside short `@Transactional` beans (no HTTP inside!).

Backend ADR Defense: "How do the Android Client (Part 1) and Spring Boot Server (Part 2) lock arms to guarantee zero double charges?"
Senior Answer: The Android client generates one UUID `Idempotency-Key` when creating its local Room Outbox `TransferCommand` and keeps retrying that exact key over WorkManager + Jitter. The Spring Boot server atomically claims `(userId, idempotencyKey, payloadHash)` via a PostgreSQL UNIQUE constraint: mismatched payloads return `422`, concurrent duplicates get `409`, and retries after dropped HTTP ACKs replay the original `200` receipt without re-debiting the Double-Entry Ledger!
