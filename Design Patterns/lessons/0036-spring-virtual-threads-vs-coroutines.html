Lesson 0036 • Part 3: Java Virtual Threads vs. Kotlin Coroutines

Spring Boot Concurrency: Virtual Threads vs. Kotlin Coroutines

In 2027, both Java and Kotlin achieve massive non-blocking I/O concurrency in Spring Boot—via different paradigms: Java uses blocking-style code on Virtual Threads (`StructuredTaskScope`); Kotlin uses `suspend` Controllers + `Flow` + `coroutineScope` (and `MDCContext` across dispatcher hops!).

Virtual Threads vs. Coroutinessuspend ControllerStructuredTaskScopeMDCContext

1. Structured Fan-Out: `StructuredTaskScope` vs. `coroutineScope { async }`

When PayVault's Risk Aggregator must call `kycClient.check()` AND `fraudClient.score()` in parallel and cancel the sibling immediately if one fails: Java uses `StructuredTaskScope.ShutdownOnFailure`, while Kotlin uses `coroutineScope { val a = async { ... }; val b = async { ... } }`!

2. Why `ThreadLocal` MDC Works on Virtual Threads—But Fails Across Coroutine Hops

A Virtual Thread keeps its own `ThreadLocal` across blocking JDBC/HTTP calls seamlessly. A Kotlin Coroutine can resume on a different worker thread after suspension—losing `MDC.get("traceId")` unless you install `MDCContext()` (`kotlinx-coroutines-slf4j`)!
