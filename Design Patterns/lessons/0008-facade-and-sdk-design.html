Lesson 0008 • Phase 2: Structural Patterns

Facade & Public SDK API Design

If every screen has to call CryptoSigner.sign(), then RiskScorer.check(), then LedgerApi.post(), then Analytics.track() in the exact right order, bugs are guaranteed. A Facade provides one clean, high-level entry point over complex collaborating subsystems.

StructuralSDK DesignInformation HidingUseCase Facade

1. Facade vs. Adapter

An Adapter makes one existing interface match another expected interface (1-to-1 translation). A Facade defines a brand-new, simplified interface over multiple subsystems (PayVaultClient.sendMoney() orchestrating Keystore, Risk, Network, and Telemetry).

2. Keeping Internal Subsystems `internal`

Kotlin — PayVaultClient SDK Facade
class PayVaultClient internal constructor(
    private val signer: PayloadSigner,
    private val riskEngine: RiskEngine,
    private val gateway: PaymentGateway,
    private val telemetry: Telemetry
) {
    fun pay(recipient: String, cents: Long): Receipt {
        if (!riskEngine.allow(cents)) return Receipt("", false)
        val sig = signer.sign("$recipient:$cents")
        val receipt = gateway.submit(recipient, cents, sig)
        telemetry.track("pay_done")
        return receipt
    }
}

5. 2027 Senior Android Interview Corner

Q1: "What keeps a Facade from becoming a 2,000-line God Class?"
Senior Answer: A Facade delegates actual work to focused subsystems (`signer`, `riskEngine`, `gateway`) rather than implementing cryptography, HTTP retries, and SQL inside itself. It coordinates the workflow—it doesn't own the details.
