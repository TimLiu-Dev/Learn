Kotlin Idioms as Built-in Design Patterns

Many classic 1994 Java patterns exist only because Java lacked language support for sealed algebraic types, delegation, value wrappers, and first-class functions. Mastering Kotlin 2.x idioms removes 50% of pattern boilerplate while making PayVault money bugs uncompileable.

The Junior → Senior Shift: Primitive Obsession & Ambiguous Results

A junior writes fun transfer(amount: Long, currency: String): Boolean. Soon a caller accidentally passes cents as dollars, swaps fromId and toId, or forgets to handle a Pending3DS status because a Boolean only expresses true/false.

A 2027 Senior uses Value Classes (zero runtime allocation overhead on JVM), Sealed Interfaces (Kotlin Sealed Docs), and Interface Delegation (Kotlin Delegation Docs) so illegal states fail at compile time.

1. Sealed Hierarchies: Compile-Time Exhaustiveness

Kotlin — PayVault TransferResult ADT
sealed interface TransferResult {
    data class Settled(val txId: String) : TransferResult
    data class Requires3DS(val challengeUrl: String) : TransferResult
    data class Rejected(val reason: String) : TransferResult
}

fun describe(res: TransferResult): String = when (res) {
    is TransferResult.Settled -> "Done: ${res.txId}"
    is TransferResult.Requires3DS -> "Verify: ${res.challengeUrl}"
    is TransferResult.Rejected -> "Declined: ${res.reason}"
} // No 'else' branch! Adding a 4th subtype forces compiler check everywhere.

2. Inline Value Classes & by Delegation

Kotlin — Type-Safe Money & Zero-Boilerplate Forwarding
@JvmInline value class MoneyCents(val value: Long) {
    init { require(value >= 0) { "Negative money not allowed" } }
    operator fun plus(other: MoneyCents) = MoneyCents(value + other.value)
}

interface LedgerReader { fun count(): Int }
class AuditedLedgerReader(
    private val inner: LedgerReader
) : LedgerReader by inner { // Forwards count() automatically!
    fun auditLabel() = "Entries=${inner.count()}"
}

5. 2027 Senior Android Interview Corner

Q1: "When should I avoid `else` in a `when (sealedResult)` block?"
Senior Answer: Always avoid `else` when branching over a sealed hierarchy. Using `else` silently swallows newly added sealed variants at compile time, turning a missing UI or payment handler into a subtle production bug.
Q2: "What is the runtime cost of `@JvmInline value class MoneyCents(val value: Long)`?"
Senior Answer: Normally zero heap allocation—the compiler unboxes it to primitive `long` in bytecode. Boxing only happens when used as a nullable (`MoneyCents?`), generic (`List<MoneyCents>`), or via an interface reference.
