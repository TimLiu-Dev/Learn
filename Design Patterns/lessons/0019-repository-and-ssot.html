Lesson 0019 • Phase 4: 2027 Senior Android Architecture

Repository, DataSources & Single Source of Truth (SSOT)

Junior apps read balance from Room on Screen A, from an in-memory cache on Screen B, and directly from Retrofit on Screen C—then show three conflicting balances! Per the Android Guide to App Architecture, UI must observe one Single Source of Truth (Room) while network syncs write into Room, never straight to UI.

2027 ArchitectureSSOT (Room + Flow)Repository PatternOffline Reads

1. UI ← Repository ← Room DB ← Network

When Room is the SSOT: 1) Opening PayVault on an airplane renders cached balance instantaneously; 2) A background refresh writes fresh API data into Room; 3) Room's reactive `Flow` automatically updates every observing screen without manual refresh callbacks.

2. Stale-While-Revalidate & TTL Caching

Kotlin — SSOT Repository with Graceful Network Fallback
class OfflineFirstWalletRepo(
    private val dao: WalletDao,
    private val api: WalletRemoteDataSource
) : WalletRepository {
    override fun observeWallet() = dao.observeWallet() // Only reads from local SSOT!

    override suspend fun sync(): Boolean = runCatching {
        val remote = api.fetchWallet()
        dao.upsert(remote.toEntity()) // Updates SSOT; Flow notifies UI automatically
    }.isSuccess
}

5. 2027 Senior Android Interview Corner

Q1: "When is it safe to skip Room SSOT and return network responses directly in a Repository?"
Senior Answer: Ephemeral search autocomplete or one-time real-time FX quotes that lose validity within seconds don't belong in persistent SQLite. Everything core to user state (balances, ledger, profile) belongs in Room SSOT.
