Lesson 0038 • Part 3: Testing Java & Kotlin Spring Boot

Senior Backend Testing: Fakes, MockK vs. Mockito & Testcontainers

Junior Spring suites boot `@SpringBootTest` + H2 in-memory DB on every single unit test—taking 15 minutes in CI and missing real PostgreSQL `UNIQUE` / `FOR UPDATE` bugs! Senior engineers run pure-JVM domain tests with Fakes, fast Spring slices (`@WebMvcTest`, `@ApplicationModuleTest`), and real PostgreSQL/Kafka via Testcontainers.

Testing StrategyMockito vs. MockKTestcontainersFake Ports

1. Why H2 Lies in Fintech Tests (And Fakes Beat Heavy Mocks)

  • H2 Trap: H2 behaves differently from PostgreSQL on `INSERT ... ON CONFLICT DO NOTHING`, JSONB, and `SELECT ... FOR UPDATE` locks! Always test persistence with real PostgreSQL via Testcontainers.
  • Domain Fakes > Over-Mocking: For Hexagonal Outbound Ports (`WalletPort`), a 15-line `InMemoryWalletPort` Fake tests real transfer invariants without brittle `verify(mock, times(1))` coupling!
  • Mockito vs. MockK: In Java use Mockito (`when(...).thenReturn(...)`); in Kotlin use MockK (`coEvery { ... } returns ...`) because MockK handles `final` classes, `suspend` functions, and Kotlin non-null types natively.

2. Choosing the Right Test Slice

Plain JUnit 5: Domain & UseCases (<5ms). `@WebMvcTest`: HTTP routing, JSON validation, `422`/`429` status codes. `@DataJpaTest` + Testcontainers: Real PostgreSQL `@Version` & `UNIQUE` idempotency constraints. `@ApplicationModuleTest`: Spring Modulith slice verification.
