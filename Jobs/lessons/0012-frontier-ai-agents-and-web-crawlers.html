Frontier AI Agents & Web Crawlers for Job Discovery

Prototype your job-discovery crawler first using frontier models (Claude, Gemini, OpenAI Codex) paired with direct ATS JSON APIs, Crawl4AI, Stagehand, and browser-use.

Primary Source & Citations

Grounded in Crawl4AI, Stagehand, browser-use, and public ATS API specs (Greenhouse, Lever, Ashby).

1. Tier 1: Direct Public ATS JSON APIs (Zero Browser Needed)

Before spinning up headless browsers, always pull structured JSON directly from unauthenticated ATS job board endpoints: 

# Greenhouse (include ?content=true for full HTML JD)
GET https://boards-api.greenhouse.io/v1/boards/{company_token}/jobs?content=true

# Lever (requires ?mode=json)
GET https://api.lever.co/v0/postings/{company}?mode=json

# Ashby (optional ?includeCompensation=true for salary bands)
GET https://api.ashbyhq.com/posting-api/job-board/{board_name}?includeCompensation=true

2. Tier 2: AI Web Crawlers & Inbox Status Ingestion

  • Crawl4AI: Converts heavy JS-rendered company career pages into clean LLM-ready Markdown for bulk filtering.
  • Stagehand (Playwright + Zod/Pydantic): Uses self-healing AI selectors (act, extract, observe) to parse structured JobDetails schemas even when companies redesign DOM layouts.
  • browser-use: Autonomous observe → think → act Chromium loop for multi-step navigation and form workflows.
  • Polite Rate-Limiting & Email Sync: Cache ETag/hash digests and use jittered exponential backoff across Greenhouse/Ashby/Workday endpoints so your IP stays unblocked, and parse ATS confirmation, OA-invite, and rejection emails via IMAP/Gmail API to keep your CRM stages accurate automatically.
  • Why prototype on Frontier Agents & APIs first? Use Claude Code (Anthropic), Google Gemini, OpenAI Codex, or Meta Muse (Muse Code / Muse Secure VM) to validate extraction schemas and browser flows on 50 real JDs before shifting bulk execution to your local 128GB models in Lesson 0013.
