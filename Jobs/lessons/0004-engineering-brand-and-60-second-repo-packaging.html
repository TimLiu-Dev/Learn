Lesson 0004 Packaging · Conversion ~15 min

Engineering Brand & 60-Second Repo Packaging

A hiring manager spends ~60 seconds on a GitHub link and rarely clones Gradle projects during initial screening. Package your repos and portfolio hub so the architecture sells itself without a local build.

Primary Source & Citations

Grounded in r/androiddev hiring reviews and Pragmatic Engineer portfolio principles.

1. Above-the-Fold README Spec

Two Audiences: Non-technical recruiters scan the GIF + tech badges; Senior SWEs scan your architecture diagram, tradeoffs, and CI status. Every pinned Android and Spring Boot repository must answer four questions within the first screen of README.md:

  1. What it does + Visual Proof: A 1-sentence summary plus an embedded emulator GIF (Android) or Mermaid architecture diagram (Spring Boot).
  2. Stack & Why: Brief rationale for key choices (e.g., "Room + StateFlow for offline-first sync; Hilt for scoped DI; Testcontainers for Postgres parity").
  3. Tricky Problem Solved: One short paragraph describing a real bug or tradeoff (e.g., process death via SavedStateHandle, or avoiding JPA N+1 queries).
  4. One-Command Run: docker compose up or ./gradlew assembleDebug + a signed demo APK release or OpenAPI spec link.

2. Minimalist Portfolio Hub

# Clean static portfolio page (GitHub Pages) — zero bloat:

- 3 Project Cards: GIF/Diagram + 2 XYZ bullets + GitHub/APK/Swagger links
