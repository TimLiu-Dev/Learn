Track 03: Modern Embedded C++ • Lesson 0014

Heapless Modern C++:
RAII Hardware Guards & std::span

Many embedded engineers avoid C++ under the misconception that it requires a heavy runtime and dynamic heap. In this lesson, we study the strict rules of embedded C++ (no RTTI, no exceptions), leverage RAII for deterministic hardware cleanup, and replace raw C pointer-length pairs with `std::span`.

Mental Model Shift: try/finally Blocks vs C++ RAII Destructors

In Kotlin/Java, guaranteeing resource cleanup requires try { ... } finally { lock.unlock() } or use { ... }.

In C++, RAII (Resource Acquisition Is Initialization) is baked into the language. When a stack object goes out of scope (through a return, loop break, or condition branch), its destructor runs deterministically in the exact reverse order of creation. No exceptions, no garbage collector, zero overhead.

1. The Golden Rules of Embedded C++

When compiling modern C++ for bare-metal ARM microcontrollers, pass these compiler flags:

  • -fno-exceptions: Disables C++ exception handling. Eliminates massive unwind tables that bloat Flash memory.
  • -fno-rtti: Disables Run-Time Type Information (`typeid`, `dynamic_cast`). Strips hidden type metadata overhead.
  • -fno-threadsafe-statics: Prevents the compiler from generating hidden mutex locks around local static variables.

2. RAII Hardware Peripheral Lock Guard

Guarantee that an on-chip SPI bus clock is enabled and the chip-select pin is pulled low during transmission, and automatically restored upon exit:

SpiTransaction.hpp (RAII Hardware Pattern) 
class SpiTransaction {
public:
    explicit SpiTransaction(SPI_TypeDef* spi) noexcept : m_spi(spi) {
        gpio_pin_set_low(CS_PIN);    // Assert Chip Select (Active Low)
        enable_spi_clock(m_spi);
    }

    ~SpiTransaction() noexcept {
        disable_spi_clock(m_spi);
        gpio_pin_set_high(CS_PIN);   // Deassert Chip Select (Release Bus)
    }

    // Non-copyable to prevent multiple releases
    SpiTransaction(const SpiTransaction&) = delete;
    SpiTransaction& operator=(const SpiTransaction&) = delete;

private:
    SPI_TypeDef* m_spi;
};

// Usage:
void read_accelerometer_data() {
    SpiTransaction lock(SPI1); // CS pin pulled low here
    spi_transmit(0x8F);
    uint8_t id = spi_receive();
    // Destructor runs automatically here when exiting scope: CS pin goes high!
}

3. Modern Memory Views: `std::span`

In C, passing an array requires two arguments: uint8_t* buffer, size_t length. This is error-prone and leads to buffer overflows. In C++20, std::span packages a pointer and length into a lightweight zero-overhead struct with bounds checking!

3. Check Your Understanding

Question 1 • Embedded C++ Compiler Flags
Why must embedded C++ firmware be compiled using the -fno-exceptions flag?
Eliminates massive stack unwinding tables from flash
Enables automatic memory allocation inside dynamic heap
Doubles the maximum clock frequency of execution
Forces nested vectored interrupt controllers into sleep
✓ Correct! (Option A: Eliminates massive unwinding tables)
C++ exception handling requires substantial metadata tables (often 20 KB to 50 KB of Flash) for stack unwinding, which consumes limited ROM on microcontrollers.
Analysis of Distractors:
• Option B, C, D: Unrelated to heap, CPU clocks, or NVIC sleep modes.
Question 2 • RAII Destructor Execution
When is the destructor of a local C++ RAII stack object guaranteed to execute?
When garbage collector runs during periodic idle
When enclosing scope block exits during execution
When microcontroller experiences physical power on reset
When operating system scheduler triggers task preemption
✓ Correct! (Option B: When enclosing scope block exits)
In C++, stack object destructors are guaranteed to execute deterministically the exact moment the enclosing curly-brace scope block { ... } exits.
Analysis of Distractors:
• Option A: C++ has no garbage collector.
• Option C & D: Destructors are tied to lexical scope, not resets or preemption.
