Structs, Padding, Alignment, Unions & Function Pointers

Systems C replaces Kotlin data classes and lambdas with memory-mapped structs and function pointer tables. Master struct padding/offsetof, why packed pointers trap, wire-protocol parsing via memcpy, union overlays, and callback dispatchers used by vector tables and Linux drivers.

Mental Model Shift: Kotlin data class vs Physical Byte Layout

In Kotlin, field declaration order inside a data class is invisible to you; the JVM lays out objects freely in memory.

In C, struct fields sit in exact declaration order—with invisible compiler padding bytes inserted so 4-byte integers align to 4-byte addresses. Ordering fields poorly wastes 30–50% of microcontroller SRAM! Meanwhile, C callbacks pass function code addresses (void (*cb)(void)) instead of heap-allocated lambda objects.

1. Struct Padding, Alignment & packed vs memcpy

struct_alignment.c 
#include <stdint.h>
#include <stddef.h>
#include <string.h>

// POOR LAYOUT: 1 byte + [3 pad] + 4 bytes + 1 byte + [3 pad] = 12 BYTES!
typedef struct {
    uint8_t  flags;
    uint32_t timestamp_ms;
    uint8_t  sensor_id;
} WastefulSensor;

// PACKED IN HARDWARE/ORDER: largest-to-smallest = 4 + 1 + 1 + [2 pad] = 8 BYTES!
typedef struct {
    uint32_t timestamp_ms; // offsetof == 0
    uint8_t  flags;        // offsetof == 4
    uint8_t  sensor_id;    // offsetof == 5
} CompactSensor;

// SAFE WIRE DESERIALIZATION: Never cast raw unaligned network/SPI bytes directly!
uint32_t read_u32_unaligned(const uint8_t *rx_buf) {
    uint32_t val;
    memcpy(&val, rx_buf, sizeof(val)); // Compiler optimizes to fast safe loads!
    return val;
}

2. Unions, Enums & Why C Bitfields Are Non-Portable

A union overlays multiple fields onto the exact same memory address (useful for protocol variant headers or saving RAM in RTOS message queues). Avoid C struct bitfields (uint32_t enable : 1;) for hardware registers or CAN/SPI packets—bit packing direction flips between compilers and big/little endian CPUs! Use explicit shifts and masks instead.

3. Function Pointers & Hardware Dispatch Tables

Every interrupt vector table (Lesson 0006) and every Linux driver struct file_operations (Lesson 0019) is built from function pointers:

callbacks_and_vtables.c 
// Reads cleanly with typedef: irq_fn_t is a pointer to void f(uint32_t)
typedef void (*irq_fn_t)(uint32_t source_id);

void uart_irq(uint32_t src) { /* clear RX FIFO */ (void)src; }
void timer_irq(uint32_t src) { /* tick scheduler */ (void)src; }

static irq_fn_t vector_table[2] = { uart_irq, timer_irq };

void dispatch_irq(uint32_t irq_num) {
    if (irq_num < 2U && vector_table[irq_num] != NULL) {
        vector_table[irq_num](irq_num); // Zero-heap dynamic dispatch!
    }
}

Knowledge Check

Question 1 • Mastery Verification
Why should portable firmware parse unaligned SPI/CAN bytes using memcpy rather than casting a wire buffer directly to a packed struct pointer?
Packed struct members disappear completely during GCC preprocessing stage
Unaligned packed pointer dereferences can trap or trigger UB
Function pointers cannot target struct layouts without heap allocation
Union overlays double physical SRAM usage inside linker sections
✓ Correct! (Option B: Alignment faults & strict-aliasing UB)
Taking the address of a multi-byte field inside a packed struct or casting raw uint8_t* packet pointers can cause strict-aliasing UB or ARM hardware UsageFault traps, whereas memcpy into an aligned variable is 100% standard-compliant and compiles cleanly to native instructions.
Analysis of Distractors:
• Option A: Preprocessing ignores C structs.
• Option C: Function pointers target code addresses in .text, unrelated to heap allocation.
• Option D: Unions share memory (size equals largest member), reducing rather than doubling SRAM.
Question 2 • Mastery Verification
What is the declaration typedef void (*isr_fn_t)(uint32_t); defining in C?
Constant macro returning pointer to an unsigned integer array
Packed union storing hardware interrupt priorities and stack addresses
Type alias for function pointers taking integer returning void
Volatile register pointer mapped directly onto NVIC interrupt vectors
✓ Correct! (Option C: Function pointer typedef)
Wrapping (*isr_fn_t) in parentheses binds * to the identifier name, creating a clean alias for any function taking a uint32_t parameter and returning void.
Analysis of Distractors:
• Option A: typedef is a C compiler type alias, not a preprocessor macro.
• Option B: No union keyword appears in the declaration.
• Option D: The declaration contains neither volatile nor a fixed NVIC address.
