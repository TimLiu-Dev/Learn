Track 03: Modern Embedded C++ • Lesson 0016

Embedded Design Patterns:
CRTP Static Polymorphism & State Machines

In desktop software, object-oriented polymorphism uses virtual methods (vtable). In embedded systems, virtual function calls incur RAM overhead and prevent compiler inlining. In this lesson, we master static polymorphism via the Curiously Recurring Template Pattern (CRTP) and model automotive power state machines.

Mental Model Shift: Kotlin Interfaces vs C++ CRTP

In Kotlin, implementing an interface Sensor and calling sensor.read() uses dynamic dispatch via the JVM vtable/itable.

On microcontrollers, dynamic dispatch requires a hidden pointer in every instance (wasting SRAM) and defeats compiler optimization. With CRTP (Curiously Recurring Template Pattern), polymorphism is resolved at compile time. The compiler inlines driver calls directly into physical machine instructions.

1. The Cost of Virtual Methods in Embedded Systems

When you add virtual to a C++ class:

  • Every single object instance gains a hidden pointer (vptr—4 bytes on 32-bit MCUs, 8 bytes on 64-bit ARM64) pointing to a vtable in Flash/rodata, increasing RAM footprint.
  • Every method call requires two pointer dereferences instead of a direct function jump.
  • Compiler Inlining is Blocked: The optimizer cannot eliminate unused registers or collapse calculations across virtual call boundaries.

2. Static Polymorphism via CRTP

The derived class inherits from a base template parameterized with the derived class itself:

CRTP Driver Pattern in C++ 
template <typename Derived>
class UartDriverBase {
public:
    void send_byte(uint8_t byte) noexcept {
        // Static dispatch: Inlined at compile time!
        static_cast<Derived*>(this)->send_byte_impl(byte);
    }
};

class Stm32UartDriver : public UartDriverBase<Stm32UartDriver> {
public:
    void send_byte_impl(uint8_t byte) noexcept {
        // Direct MMIO write
        UART1->DR = byte;
    }
};

// Usage: Zero vtables, zero overhead, 100% inlined!
Stm32UartDriver uart;
uart.send_byte(0x42);

✅ Reference Production Solution:
int transition_power_state(int current_state, int event) {
    if (event == EVENT_IGNITION_ON) return STATE_ACTIVE;
    if (event == EVENT_IGNITION_OFF) return STATE_STANDBY;
    return current_state;
}

3. Check Your Understanding

Question 1 • CRTP vs Virtual Methods
What technical advantage does CRTP static polymorphism provide over virtual methods?
Eliminates virtual table pointers and enables compiler inlining
Allocates variables exclusively inside dynamic system heap memory
Disables nested vectored interrupt controller priority preemption groups
Enables automatic garbage collection for all runtime variables
✓ Correct! (Option A: Eliminates vtables and enables inlining)
CRTP resolves function calls at compile time using static casts. No hidden vptr is allocated in RAM, and the compiler can inline driver operations directly into machine instructions.
Analysis of Distractors:
• Option B, C, D: Unrelated to heap, NVIC, or garbage collection.
Question 2 • Hierarchical State Machines
Why are deterministic state machines favored for automotive embedded systems?
State machines automatically double microcontroller processor clock frequency
Guaranteed predictable transitions eliminate invalid illegal hardware states
Eliminates requirement for physical pullup bus termination resistors
Compresses executable machine code instructions inside flash storage
✓ Correct! (Option B: Predictable behavior and prevents illegal states)
State machines formally define all valid states and transitions, ensuring the system cannot end up in an undefined or unsafe hardware state during power faults.
Analysis of Distractors:
• Option A, C, D: State machines do not change clocks, replace pullups, or compress code.
