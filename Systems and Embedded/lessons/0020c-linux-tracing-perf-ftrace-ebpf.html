Track 04: Non-AOSP Linux Systems • Lesson 0020c

Production Linux Debugging & Profiling:
perf, ftrace, eBPF & Core Dumps

When a customer's gateway drops CAN frames every 4 hours or exhibits a 40ms scheduling spike under thermal load, printf changes the timing and hides the bug. Senior Linux engineers diagnose live systems non-invasively with perf, ftrace, and bpftrace.

Mental Model Shift: Android Studio Profiler vs Linux Kernel Observability

In Android apps, you attach Android Studio's CPU/Memory Profiler or capture a Perfetto UI trace over ADB. (Under the hood, Perfetto reads Linux ftrace!)

On headless Embedded Linux boards with 256 MB RAM and no Android Studio, you SSH into the target and inspect PMU hardware counters (perf), scheduler/IRQ wakeup latency (ftrace), safe live syscall histograms (bpftrace), and offline core dumps in gdb-multiarch.

Knowledge Check

Question 1 • Mastery Verification
Why can eBPF programs safely run inside a live production Linux kernel without risking kernel panics?
Kernel disables all hardware interrupts globally whenever user space installs tracing hooks
In-kernel verifier proves bounded loops and safe pointer bounds before JIT loading
Programs execute inside an external Java virtual machine outside Linux kernel space
Kernel automatically restarts the board silently whenever tracing scripts dereference invalid pointers
✓ Correct! (Option B: Static in-kernel eBPF verifier)
Before any eBPF bytecode loads, the kernel verifier symbolically checks termination (bounded loops), valid register/stack bounds, and no arbitrary memory writes.
Analysis of Distractors:
• Option A, C, D: eBPF runs natively in-kernel after static verification, with zero JVM and without disabling IRQs globally.
Question 2 • Mastery Verification
You observe a 25ms pause between a SPI hardware interrupt firing and your user-space RT thread waking up. Which tool pinpoints whether an unrelated kernel driver or scheduler delay caused it?
Capturing kernel irq_handler and sched_switch events using ftrace and trace-cmd
Running readelf symbol inspection commands on static binary archive objects
Adding printf timestamps inside every user space helper loop sequentially
Rebuilding the Yocto root filesystem with higher GCC optimization flags
✓ Correct! (Option A: ftrace IRQ + scheduler tracepoints)
ftrace records nanosecond-accurate irq_handler_entry, sched_wakeup, and sched_switch timelines directly from kernel ring buffers.
Analysis of Distractors:
• Option B: readelf is static ELF inspection.
• Option C: printf perturbs timing and misses kernel scheduler states.
• Option D: Compiler flags don't diagnose kernel IRQ preemption delays.
