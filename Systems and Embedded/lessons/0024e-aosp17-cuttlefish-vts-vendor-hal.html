AOSP 17 Vendor HAL Stack:
Cuttlefish KVM, Side-by-Side C++/Rust AIDL & VTS

Build and boot AOSP 17 on Linux KVM Cuttlefish on your ROG Flow Z13 (~400 GB+ ext4). Bridge your Raspberry Pi 4 Phase 5A telemetry socket into a @VintfStability vendor.dev.hardware.fitnesstelemetry AIDL HAL—implemented side-by-side in C++ and Rust—verified with VTS and surfaced to a Kotlin Compose dashboard.

Mental Model Shift: Vendor Namespace vs android.hardware.*

Never put custom HALs inside Google's reserved android.hardware.* namespace! Always define vendor extensions under vendor.<org>.hardware.* (e.g., vendor.dev.hardware.fitnesstelemetry) marked with @VintfStability, and declare them in a vendor VINTF manifest fragment + device compatibility matrix.

On Cuttlefish, your HAL daemon runs inside its own SELinux hal_fitnesstelemetry_default domain, reads live BLE/CAN/INA226 frames from the Pi 4 appliance socket, and exposes Binder callbacks to your framework/Compose client.

Knowledge Check

Question 1 • Vendor Namespace & VINTF
Why should your custom AOSP 17 telemetry HAL live under vendor.dev.hardware.* with @VintfStability instead of android.hardware.*?
Rust AIDL compilers reject packages beginning with android prefix
Google reserves android namespace and Treble checks vendor compatibility
Vendor packages skip SELinux checks and run as root
Cuttlefish virtual machines disable binder transactions for standard namespaces
✓ Correct! (Option B: Treble namespace separation & VINTF contracts)
android.hardware.* is owned by AOSP upstream; vendor extensions use vendor.<org>.hardware.* and declare @VintfStability so the framework-to-vendor interface passes VINTF checks cleanly.
Analysis of Distractors:
• Options A, C, D: Rust AIDL compiles both namespaces, vendor HALs face strict SELinux isolation, and Cuttlefish runs full Binder IPC.
Question 2 • Comparing IPC Mechanisms
Compared to raw AF_UNIX sockets used on fitness consoles, what extra platform capability does an AOSP AIDL HAL over /dev/binder give you?
Zero kernel involvement with direct CPU register sharing
Automatic Wi-Fi encryption across external internet cloud routers
Typed Parcel contracts, VINTF versioning, and caller identity
Hard real-time microsecond guarantees inside Java ART runtimes
✓ Correct! (Option C: Typed ABI, VINTF versioning & kernel-verified UID/PID)
Binder provides generated C++/Rust/Java proxies, kernel-authenticated caller UID/PID, DeathRecipients, and Treble VINTF version guarantees—things you had to hand-roll on raw Unix sockets.
Analysis of Distractors:
• Options A, B, D: Binder runs through the kernel /dev/binder driver, stays local to the device, and ART is not hard real-time.
