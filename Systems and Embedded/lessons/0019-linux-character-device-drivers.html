Linux Character Device Drivers:
The User/Kernel Space Boundary

Linux models everything as a file. When an Android service reads /dev/telem_bridge, that standard POSIX read() system call is answered by a kernel driver. In this lesson, we write a Linux Character Device Driver from scratch, implementing file_operations and crossing the user-kernel memory boundary safely.

Mental Model Shift: User Space Apps vs Kernel Ring 0

In Android application development, if your app crashes, ART throws an unhandled exception and the OS kills only your process.

In the Linux Kernel, you run in Ring 0 (highest privilege). There is no safety net. If you dereference a NULL pointer or access invalid memory, the entire operating system experiences a Kernel Panic and the car or phone reboots immediately.

1. The file_operations Structure

When user space calls open(), read(), or ioctl() on a device node (like /dev/my_sensor), the kernel dispatches to function pointers in a struct file_operations:

my_char_driver.c (Linux Kernel Module Skeleton) 
#include <linux/module.h>
#include <linux/fs.h>
#include <linux/uaccess.h>

static int dev_open(struct inode* inodep, struct file* filep) {
    pr_info("Device opened successfully\n");
    return 0;
}

static ssize_t dev_read(struct file* filep, char __user* buffer, size_t len, loff_t* offset) {
    char data[] = "TELEMETRY_OK\n";
    size_t data_len = sizeof(data);

    // CRITICAL: NEVER dereference user-space pointer 'buffer' directly!
    // Must use copy_to_user to handle page faults safely!
    if (copy_to_user(buffer, data, data_len)) {
        return -EFAULT; // Bad address
    }
    return data_len;
}

static struct file_operations fops = {
    .owner = THIS_MODULE,
    .open = dev_open,
    .read = dev_read,
};

2. The Sacred Boundary: copy_to_user() & copy_from_user()

Why can't the kernel just execute buffer[0] = 'A';?

  • The user pointer buffer belongs to the user-space process's virtual memory map.
  • The page may be swapped out to disk or unmapped. A direct read/write in kernel space would cause an unhandled kernel page fault.
  • Security: Malicious user apps could pass a kernel-space memory address to trick the kernel into overwriting its own page tables (privilege escalation)!

3. Check Your Understanding

Question 1 • Kernel Memory Boundary Safety
Why must Linux device drivers use copy_to_user() instead of standard memcpy()?
Safely handles user space page faults and permissions
Compresses transfer payload using kernel lz4 compression algorithms
Disables nested vectored interrupt controllers during data copy
Doubles the maximum physical clock frequency of bus
✓ Correct! (Option A: Safely handles page faults and permissions)
copy_to_user() validates that the pointer resides in user-accessible virtual memory and catches page faults safely without crashing the kernel.
Analysis of Distractors:
• Option B, C, D: It does not compress, disable interrupts, or alter clock frequencies.
Question 2 • Character Device Node Identification
In a Linux character device driver, what role does the Major Number perform?
Identifies specific physical channel of multiple connected devices
Identifies device driver module registered with linux kernel
Specifies baud rate speed of universal asynchronous serial
Defines total byte capacity of internal flash storage
✓ Correct! (Option B: Identifies device driver registered with kernel)
The Major Number tells the kernel which driver handles requests for this device node. The Minor Number is used by the driver to distinguish between individual ports or channels.
Analysis of Distractors:
• Option A: Handled by the Minor Number.
• Option C & D: Irrelevant to baud rates or flash capacity.
