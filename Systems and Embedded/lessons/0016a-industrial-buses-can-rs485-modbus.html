1. Native bxCAN + SN65HVD230 (1 Mbps)

  • Bit Timing & Sampling Point: On a 36 MHz APB1 clock, configure CAN_BTR prescaler + TS1/TS2 to land the sample point near 80–87.5% of the bit time at 1 Mbps or 500 kbps.
  • Hardware Acceptance Filters: Never waste CPU cycles dropping unwanted frames in an ISR. Configure CAN_FMR filter banks in mask/ID mode so only relevant IDs enter RX FIFO0.
  • USB + CAN Pin Conflict on STM32F103: Remember that on STM32F103, PA11/PA12 are shared between USB and default CAN—remap CAN to PB8/PB9 (AFIO_MAPR_CAN_REMAP_REMAP2) if USB is active.

2. Half-Duplex RS485 (SP3485) & Modbus RTU

The Classic RS485 DE/RE Turnaround Bug 
// WRONG: Checking TXE (Transmit Data Register Empty) before dropping DE!
// The last byte is still shifting out of the UART shift register!
// Dropping DE early clips the stop bit and corrupts the Modbus CRC.
//
// RIGHT: Assert DE/RE = HIGH -> send frame -> wait for USART_SR_TC (Transmission Complete)
//        -> only THEN drop DE/RE = LOW to listen for the slave's reply.

Modbus RTU Framing: No start/end delimiters exist—frames are separated by 3.5 character times of bus silence (e.g., ~1.75 ms at 19200 baud, or fixed 1.75 ms minimum above 19200 baud) and verified with little-endian CRC-16/MODBUS (polynomial 0xA001, init 0xFFFF).

Interactive Practice: Modbus RTU CRC-16 Calculator

Implement modbus_crc16(std::span<const uint8_t> frame) in C++20: start with uint16_t crc = 0xFFFF;, XOR each byte into crc, then loop 8 bits—if crc & 1U shift right by 1 and XOR with 0xA001U, else just shift right by 1.

modbus_crc.cpp
💡 Progressive Guidance Hints:
Hint 1: Use a range-based for loop: for (uint8_t b : frame).
Hint 2: Modbus puts the low byte of crc first on the wire (crc & 0xFF, then crc >> 8).
✅ Reference Production Solution:
uint16_t modbus_crc16(std::span<const uint8_t> frame) {
    uint16_t crc = 0xFFFFU;
    for (uint8_t b : frame) {
        crc ^= b;
        for (int i = 0; i < 8; ++i) {
            if (crc & 1U) crc = static_cast<uint16_t>((crc >> 1) ^ 0xA001U);
            else          crc >>= 1;
        }
    }
    return crc;
}

Knowledge Check

Question 1 • Half-Duplex RS485 Driver Control
Your Blue Pill RS485 master drops the SP3485 DE pin immediately after the UART TXE flag sets, and the slave rejects every Modbus packet. Why?
TXE means the slave finished computing its CRC
TXE fires while the last byte still shifts
RS485 requires holding DE high during idle periods
Modbus requires full-duplex signaling across four twisted wires
✓ Correct! (Option B: Wait for TC, not TXE)
TXE only means the transmit holding register moved into the shift register; the final byte is still clocking out on TX! Wait for TC (Transmission Complete) before switching DE back to receive mode.
Analysis of Distractors:
• Options A, C, D: TXE is local hardware status, keeping DE high on idle blocks all slave replies, and RS485 Modbus RTU runs half-duplex on two wires.
Question 2 • Dual-Node Debugging & Clones
You wire your CMSIS-DAP to a low-cost STM32F103 Blue Pill and OpenOCD aborts with an unexpected IDCODE mismatch error. What is the clean first fix?
Increase SWD clock speed above fifty megahertz first
Remove both CAN termination resistors from the breadboard
Pass set CPUTAPID zero to accept clone silicon
Enable exceptions and RTTI inside CMake compiler flags
✓ Correct! (Option C: Override CPUTAPID for clone IDCODEs)
Clone F103 dies (CKS32/CS32/GD32) often report a non-ST TAP IDCODE (e.g. 0x2ba01477 instead of 0x1ba01477). Adding -c "set CPUTAPID 0" before sourcing target/stm32f1x.cfg allows OpenOCD to attach cleanly.
Analysis of Distractors:
• Options A, B, D: High SWD clocks worsen signal integrity, CAN resistors aren't on SWD, and C++ compiler flags don't alter JTAG/SWD silicon IDs.
