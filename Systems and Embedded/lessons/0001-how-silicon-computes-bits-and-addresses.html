Track 00: Silicon & C Foundations • Lesson 0001

How Silicon Computes:
Bits, Bytes, Hex & Physical Memory Addresses

In Android application development, memory is an abstract sea managed by the ART garbage collector. In systems engineering, memory is physical electrical potential stored across billions of microscopic capacitors. Here is how silicon truly represents data at the hardware level.

The Android Developer Mental Model Shift

In Kotlin, when you write val packetId: Int = 0x4A, you are asking the Android Runtime (ART) to manage an integer value. The runtime tracks object references, performs garbage collection, and shields you from physical memory addresses.

In bare-metal C, there is no runtime. An integer is simply 4 contiguous bytes in a physical SRAM chip. The memory address (such as 0x20000004) is not a symbolic reference—it is literally a binary integer transmitted across 32 copper traces on the printed circuit board.

1. The Physical Bit and The Byte

A bit is physically represented by a voltage level on a microscopic wire: 3.3V or 1.8V represents logical 1; 0V (ground) represents logical 0.

CPUs cannot address individual bits directly on the bus. The smallest unit of physical memory that modern microcontrollers (ARM Cortex-M, RISC-V, ARM64) can independently fetch from RAM is a byte (8 contiguous bits).

Why Hexadecimal? (The 4-Bit Nibble Rule)

Binary strings like 1011101001111111 are unreadable for humans. We group bits into chunks of 4 (called a nibble). Because $2^4 = 16$, exactly one hexadecimal character (0–F) encodes exactly 4 bits. Thus, 1 byte is always exactly 2 hex digits:

Binary: 1010 1111
Hex: 0xAF
Unsigned Dec: 175
Signed (Two's Comp): -81

2. How Silicon Encodes Negative Numbers: Two's Complement

Hardware ALUs (Arithmetic Logic Units) do not have a separate "subtraction" circuit. Instead, subtraction is performed as addition using Two's Complement encoding:

A - B = A + (~B + 1)

In an 8-bit signed integer (int8_t), the most significant bit (MSB, bit 7) has a negative weight of -128 ($ -2^7 $). The remaining bits have normal positive weights:

Bit Weight Decomposition of 0xFB (-5 in Two's Complement) 
Bit Index:     Bit 7   Bit 6   Bit 5   Bit 4   Bit 3   Bit 2   Bit 1   Bit 0
Bit Value:       1       1       1       1       1       0       1       1
Weight:        -128    +64     +32     +16     +8      +4      +2      +1
Calculation:   -128 + 64 + 32 + 16 + 8 + 0 + 2 + 1 = -5

To negate any integer in C: invert all bits (NOT ~) and add 1. This elegant mathematical property allows the exact same CPU silicon adder circuit to add signed and unsigned numbers with zero performance penalty.

3. Byte Ordering: Little-Endian vs Big-Endian

When an integer spans multiple bytes (e.g. a 32-bit uint32_t consists of 4 bytes), the CPU must decide in what order to store those 4 bytes across consecutive memory addresses.

  • Little-Endian (ARM, x86, RISC-V): The least significant byte is placed at the lowest numerical memory address.
  • Big-Endian (Network protocols, CAN-bus standard, legacy mainframes): The most significant byte is placed at the lowest numerical memory address.
Physical SRAM Memory Layout of 32-bit Value: 0xAABBCCDD 
Address:        0x20000000   0x20000001   0x20000002   0x20000003
Little-Endian:     0xDD         0xCC         0xBB         0xAA   (ARM default)
Big-Endian:        0xAA         0xBB         0xCC         0xDD   (Network order)
💡 The Automotive & Android Connection:
When your Android Automotive (AAOS) vehicle gateway reads a CAN-FD frame from the vehicle chassis, the frame payload is formatted in Big-Endian. But your ARM64 Android SoC executes in Little-Endian. If you do not perform a byte swap, your sensor readings will be completely corrupted!

✅ Reference Production Solution:
uint32_t swap_uint32(uint32_t val) {
    return ((val & 0x000000FF) << 24) |
           ((val & 0x0000FF00) <<  8) |
           ((val & 0x00FF0000) >>  8) |
           ((val & 0xFF000000) >> 24);
}

5. Check Your Understanding

These questions reinforce your retrieval strength. Each option has identical formatting to test true recall.

Question 1 • Two's Complement Binary Representation
What is the decimal equivalent of the 8-bit signed hexadecimal value 0xF7?
Represents positive two hundred forty seven
Represents negative one hundred twenty eight
Represents negative nine in signed representation
Represents positive nine in unsigned format
✓ Correct! (Option C: Negative nine)
Hex 0xF7 in binary is 1111 0111. Since the MSB is 1, it is negative. To find the magnitude using Two's Complement: invert all bits (0000 1000 = 8) and add 1 (8 + 1 = 9). Therefore, 0xF7 == -9!
Analysis of Distractors:
• Option A (+247) is what you get if interpreted as an unsigned integer (uint8_t), not signed.
• Option B (-128) is the value of 0x80 (only the MSB set).
• Option D (+9) would be binary 0000 1001 (0x09).
Question 2 • Hexadecimal to Nibble Mapping
Which binary sequence corresponds to the single hexadecimal nibble character 0xC?
Binary value one zero one zero
Binary value zero zero one one
Binary value one one zero zero
Binary value zero one one zero
✓ Correct! (Option C: 1100)
In hexadecimal, A=10, B=11, C=12. Twelve in 4-bit binary is $8 + 4 + 0 + 0 = 1100_2$.
Analysis of Distractors:
• Option A (1010) is $8 + 2 = 10$, which is 0xA.
• Option B (0011) is $2 + 1 = 3$, which is 0x3.
• Option D (0110) is $4 + 2 = 6$, which is 0x6.
Question 3 • Memory Endianness
In an ARM Cortex-M Little-Endian system, how is multi-byte data ordered across memory addresses?
Lowest byte at the lowest address
Highest byte at the lowest address
Middle byte at the lowest address
Random byte at the lowest address
✓ Correct! (Option A: Lowest byte at lowest address)
"Little-Endian" literally means the "little end" (the least significant byte) is stored first at the lowest numerical memory address.
Analysis of Distractors:
• Option B (Highest byte at lowest address) defines Big-Endian (network byte order).
• Option C and D are non-existent orderings in standard computer architectures.
