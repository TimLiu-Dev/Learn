Automated Embedded Testing:
HAL Mocking, Host Sanitizers & QEMU / HIL Pipelines

Junior firmware devs test by flashing a board on their desk and watching an LED blink. Senior engineers build a three-tier test pyramid: pure host unit tests with fake hardware buses, QEMU virtual-board boot smoke tests in every PR, and nightly Hardware-in-the-Loop (HIL) racks.

Mental Model Shift: Android Robolectric/Espresso vs Firmware Test Pyramid

In Android apps, you run fast JUnit tests on the JVM, Robolectric for framework fakes, and Espresso on emulators.

In Embedded Systems, separating hardware register access behind a tiny HAL trait (Rust), C++ concept/CRTP, or C vtable lets 90% of your protocol, CRC, state-machine, and buffer logic run on x86_64/ARM64 hosts in milliseconds under ASan/UBSan—while QEMU + HIL verify real interrupts and DMA!

typedef struct {
    int (*spi_xfer)(const uint8_t *tx, uint8_t *rx, size_t len);
} BusOps;

int read_temp_celsius(const BusOps *bus, int32_t *out_c) {
    uint8_t tx[2] = { 0x80, 0x00 }, rx[2] = {0};
    if (bus->spi_xfer(tx, rx, 2) != 0) return -1;
    *out_c = (int32_t)(int8_t)rx[1];
    return 0;
}

struct FakeBus;
impl SpiBus for FakeBus {
    fn read_two_bytes(&mut self) -> Result<[u8; 2], ()> {
        Ok([0xAA, 42])
    }
}

    let mut bus = FakeBus;
    assert_eq!(read_sensor_temp(&mut bus), Ok(42));
}

Question 1 • Mastery Verification
Why can't QEMU virtual emulation completely replace a physical Hardware-in-the-Loop (HIL) test rack?
QEMU omits real silicon errata, electrical timing skew, and analog peripheral noise
QEMU cannot execute ARM Cortex-M instructions inside Linux Docker continuous integration containers
QEMU forbids compiling firmware binaries using standard GNU linker memory allocation scripts
QEMU automatically deletes vector tables whenever interrupts fire inside automated unit tests
✓ Correct! (Option A: Physical silicon timing & electrical reality)
QEMU models instruction sets and basic peripherals, making it unbeatable for fast PR boot/RTOS checks—but real SPI signal integrity, DMA bus contention, and silicon errata only surface on physical HIL boards.
Analysis of Distractors:
• Option B, C, D: QEMU executes ARM ELF firmware with real linker scripts and vector tables inside Docker CI smoothly.
Question 2 • Mastery Verification
What architectural practice lets 90% of embedded C/C++/Rust protocol code run on fast host CI under ASan/UBSan?
Hardcoding absolute physical peripheral register addresses directly inside every business module
Isolating hardware bus I/O behind thin swappable HAL traits or vtables
Compiling entire Zephyr RTOS kernels inside Android Jetpack Compose preview tools
Replacing all C structs and fixed buffers with dynamic Python scripts
✓ Correct! (Option B: Thin HAL abstraction boundary)
Keeping MMIO register writes in a thin hardware layer lets the same state-machine and protocol code link against a fake bus in host tests and real silicon in firmware builds.
Analysis of Distractors:
• Option A, C, D: Hardcoded MMIO addresses segfault on host OSes.
