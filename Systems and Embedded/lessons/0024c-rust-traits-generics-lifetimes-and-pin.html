Traits Without Inheritance:
Generics, dyn Trait, Lifetimes ('a) & Pin

Rust has zero class inheritance. Every hardware abstraction—from embedded-hal (Lesson 0025) and Embassy's Output<'static> (Lesson 0026) to Linux InPlaceModule (Lesson 0027) and AOSP dyn IVehicleCallback (Lesson 0035)—is built from Traits, Lifetimes, Closures, and Pinning.

Mental Model Shift: Kotlin interface & Lambdas vs Rust Traits & Monomorphization

In Kotlin, calling a generic interface dispatches via JVM vtables and type erasure.

In Rust, bounded generics (fn send<B: BusTx>(bus: &mut B)) compile into specialized machine code per concrete chip driver (monomorphization, like C++ templates/CRTP with zero vtable cost!). Only when you intentionally hold heterogeneous listeners at runtime (like Binder callbacks in Lesson 0035) do you opt into dynamic dispatch with dyn Trait.

1. Traits, Associated Types & Static vs Dynamic Dispatch

traits_and_lifetimes.rs (Generic Static Dispatch + Explicit Lifetime Slice) 
pub trait SensorRead {
    type Error; // Associated type: concrete chip fixes its own error type
    fn read_sample(&mut self) -> Result<u16, Self::Error>;
}

// 1. Static dispatch (zero vtable, inlined cleanly on MCU)
pub fn poll_twice<S: SensorRead>(dev: &mut S) -> Result<u32, S::Error> {
    let a = dev.read_sample()? as u32;
    let b = dev.read_sample()? as u32;
    Ok((a + b) / 2)
}

// 2. Explicit lifetime 'a proves returned subslice cannot outlive input 'buf'
pub fn header_slice<'a>(buf: &'a [u8]) -> Option<&'a [u8]> {
    buf.get(..4)
}

2. Lifetimes ('a, 'static), Closures & Why Pin Exists

  • 'static Lifetime: Data valid for the entire program lifetime (ROM string literals like &'static str, or hardware drivers moved into background tasks such as Embassy's Output<'static> in Lesson 0026). It does not restrict you from returning owned values—it means a type contains no short-lived borrowed pointers!
  • Closures (Fn, FnMut, FnOnce) & Zero-Cost Iterators: Rust closures capture environment variables as anonymous stack structs. move || { ... } moves owned handles into spawned threads or async tasks.
  • Why Pin<&mut T> Matters in Embedded & Linux Kernel: By default, any Rust value can move in memory via bitwise memcpy. However, an async fn state machine across an .await (Lesson 0026) and a Linux kernel struct mutex wait-list (Lesson 0027) hold self-referential internal pointers. Wrapping them in Pin<P> statically forbids moving the memory address once pinned!

Question 1 • Mastery Verification
How does bounded static dispatch (fn write<P: OutputPin>(pin: &mut P)) differ from a trait object (&mut dyn OutputPin)?
Trait objects disable borrow checker verification across all asynchronous firmware loops
Bounded generics monomorphize per type enabling inlining without runtime vtable lookups
Generic functions require heap allocation on microcontrollers using Box fat pointers
Dynamic dispatch forces every compile unit into slow debug optimization passes
✓ Correct! (Option B: Monomorphization + inlining vs vtable indirection)
Bounded generics emit specialized machine code for each concrete peripheral driver, allowing the optimizer to inline register writes down to single assembly instructions. dyn Trait uses a fat pointer and runtime vtable dispatch.
Analysis of Distractors:
• Option A: Borrow checking applies identically to both.
• Option C: Bounded generics require zero heap allocation.
• Option D: dyn Trait simply emits indirect calls via vtables, not debug-only optimization.
Question 2 • Mastery Verification
Why do Embassy Futures and Rust for Linux kernel synchronization primitives use Pin<&mut T>?
Pinning compresses async state machines into smaller read only flash sections
Pinning notifies garbage collectors never to relocate variables between background cores
Pinning forbids moving memory once self referential internal pointers exist safely
Pinning grants driver tasks automatic Ring zero hardware interrupt elevation flags
✓ Correct! (Option C: Guarantees stable address for self-referential state)
Relocating an async state machine holding a reference to a local buffer inside itself—or moving a Linux C mutex wait-list—would leave internal pointers pointing at stale stack addresses. Pin prevents movement after pinning unless the type implements Unpin.
Analysis of Distractors:
• Option A, B, D: Pinning is purely a Rust type-system contract guaranteeing address immobility, with zero Flash compression, GC, or privilege elevation.
