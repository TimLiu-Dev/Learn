Track 04: Embedded Linux & Kernel • Lesson 0018

Linux Device Trees (DTS & DTB):
Hardware Abstraction & Kernel Bus Topography

In x86 PCs, PCI buses allow the operating system to automatically probe connected devices. On ARM Embedded Linux systems, on-chip buses cannot probe themselves. In this lesson, we study Device Trees (DTS/DTB), writing nodes that inform the Linux kernel of memory addresses, interrupt lines, and driver bindings.

Mental Model Shift: AndroidManifest.xml vs Linux Device Tree

In Android app development, AndroidManifest.xml declares your application components (Activities, Services, Permissions) to the Android OS.

In Embedded Linux, the Device Tree (`.dts`) is the hardware manifest. It informs the Linux kernel which peripherals exist, what base physical addresses they occupy, which clocks feed them, and which kernel driver module should be bound to each device.

1. Device Tree Syntax & Properties

A Device Tree is a tree of nodes representing buses and peripherals:

bme280_sensor.dts (Device Tree SPI Sensor Node) 
&spi0 {
    status = "okay";
    pinctrl-names = "default";
    pinctrl-0 = <&spi0_pins>;

    sensor@0 {
        compatible = "bosch,bme280";     // Matches Linux driver `of_device_id`!
        reg = <0>;                       // Chip Select 0
        spi-max-frequency = <10000000>;  // 10 MHz SPI clock
        interrupt-parent = <&gpio1>;     // Interrupt controller node
        interrupts = <14 IRQ_TYPE_EDGE_RISING>; // GPIO pin 14 rising edge
    };
};

2. Compilation & Boot Process

  • DTS (Source): Human-readable text written by BSP engineers.
  • DTC (Compiler): The Device Tree Compiler (dtc -I dts -O dtb -o board.dtb board.dts).
  • DTB (Blob): Compact binary representation parsed by U-Boot and loaded into RAM for the Linux kernel.
  • DTO (Overlays): Dynamic fragments applied at runtime to describe hot-swappable daughterboards.

3. Check Your Understanding

Question 1 • Device Tree Matching
Which Device Tree property is used by Linux to bind a peripheral to its kernel driver?
The compatible string property declared inside node
The clock frequency property configured inside node
The status okay property configured inside node
The reg base address property inside node
✓ Correct! (Option A: The compatible string property)
The kernel uses the compatible property (e.g. "vendor,device") to scan registered device drivers and call the matching driver's probe() function.
Analysis of Distractors:
• Option B, C, D: clock-frequency, status, and reg describe settings, not driver bindings.
Question 2 • Device Tree Compiler Tool
Which command compiles a human-readable .dts file into a binary .dtb blob?
The gcc preprocessor tool utility command
The dtc device tree compiler command
The ld GNU static linker command
The readelf binary inspection utility command
✓ Correct! (Option B: The dtc command)
dtc (Device Tree Compiler) compiles .dts files into .dtb (Flattened Device Tree Blobs) read by the bootloader and kernel.
Analysis of Distractors:
• Option A, C, D: gcc, ld, and readelf are C compiler and ELF utilities.
