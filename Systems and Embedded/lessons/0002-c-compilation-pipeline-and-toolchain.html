Track 00: Silicon & C Foundations • Lesson 0002

The C Compilation Pipeline:
From Source Code to Machine Silicon

In Android, Gradle abstracts the build behind a single green play button. In systems engineering, understanding the four discrete compilation stages—Preprocessor, Compiler, Assembler, and Linker—is mandatory to diagnose link errors, symbol collisions, and binary bloat.

Mental Model Shift: Gradle/DEX vs GNU Toolchain

In Android app development, javac and d8 translate Java/Kotlin into Dalvik Executable (.dex) bytecode, packaged inside an APK/AAB to be interpreted or JIT/AOT compiled by the Android Runtime (ART) virtual machine.

In systems engineering, there is no virtual machine. The GNU toolchain (arm-none-eabi-gcc or clang) translates C text directly into physical ARM or RISC-V machine instructions that the CPU hardware decoder executes directly from silicon flash memory.

1. The Four Discrete Compilation Stages

Every C build command like gcc main.c -o app is a convenience wrapper orchestrating four separate tools:

The Four Stages of C Translation 
Source (.c) 
    │
    ▼ [1. Preprocessor (cpp)]  ──> Handles #include, #define, #ifdef
Preprocessed (.i)
    │
    ▼ [2. Compiler (cc1)]      ──> Translates C to Assembly language
Assembly (.s)
    │
    ▼ [3. Assembler (as)]      ──> Emits machine code Object files
Object (.o)
    │
    ▼ [4. Linker (ld)]         ──> Resolves symbols & applies Linker Script
Final Binary (.elf / .bin)

Stage 1: The Preprocessor (gcc -E)

A pure text manipulator. It strips comments, copies the contents of header files (#include) directly into the source file, and substitutes text macros (#define). Inspecting preprocessor output is the #1 way to debug macro expansion bugs.

Stage 2: The Compiler (gcc -S)

Translates C syntax into human-readable assembly mnemonics (like MOV, LDR, ADD, BL). This stage performs optimizations (-O0, -O2, -Os for size).

Stage 3: The Assembler (gcc -c)

Converts assembly text into binary machine code instructions. It produces an Object file (.o) in ELF (Executable and Linkable Format). Each object file has unlinked symbols: functions it calls that are defined in other files remain blank address placeholders.

Stage 4: The Linker (ld / gcc)

The stitcher. The linker takes multiple .o files and static libraries (.a), resolves external symbols (e.g. connecting main() to uart_init()), and assigns exact physical memory addresses to sections according to a Linker Script (.ld).

💡 Progressive Guidance Hints:
Hint 1: Preprocessing only uses flag -E.
Hint 2: Assembly output generation uses capital -S.
Hint 3: Object file generation (compiling without linking) uses lowercase -c.
✅ Reference Production Solution:
const char* get_compiler_flag(int stage) {
    switch (stage) {
        case 1: return "-E";  // Preprocess only
        case 2: return "-S";  // Compile to assembly
        case 3: return "-c";  // Assemble to .o object
        case 4: return "-Os"; // Optimize for code size
        default: return "";
    }
}

2. Check Your Understanding

Test your mental model of compilation stages. Each answer choice has identical word length.

Question 1 • Preprocessor Output
What is the primary responsibility executed during the C preprocessor stage?
Generates machine code instructions for execution
Allocates variables to physical memory addresses
Performs text substitution and macro expansions
Resolves external library functions during linking
✓ Correct! (Option C: Performs text substitution)
The preprocessor does not generate binary code or assign memory addresses; it is purely a textual pass that expands macros, handles #include files, and evaluates conditional compilation blocks (#ifdef).
Analysis of Distractors:
• Option A: Performed by the Assembler.
• Option B & D: Performed by the Linker.
Question 2 • Linker Responsibilities
Which error occurs exclusively during the final linker stage of compilation?
Missing semicolon at end of line
Undefined reference to external function symbol
Invalid syntax in macro definition statement
Type mismatch during variable assignment operation
✓ Correct! (Option B: Undefined reference to symbol)
"Undefined reference" occurs when the compiler happily compiles a function call declared in a header, but during the linking phase, no object file or library actually supplies the body of that symbol.
Analysis of Distractors:
• Option A & D: Compiler parser/type check errors.
• Option C: Preprocessor syntax error.
