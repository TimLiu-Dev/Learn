Track 01: Bare-Metal C & Hardware • Lesson 0005

The Silicon-to-Software Bridge:
Memory Maps, MMIO & Register Bitmasking

In this lesson, we transition to real hardware registers. Learn how physical CPU address lines connect to on-chip peripherals, why omitting `volatile` crashes production release builds, and how to control silicon pins using bitwise manipulation and struct pointer mappings.

Mental Model Shift: Object References vs Physical MMIO Registers

In Android app development, calling cameraManager.openCamera() dispatches an IPC transaction through Binder down to a native daemon.

In bare-metal embedded programming, writing *UART_CR1 |= (1U << 13); emits a 32-bit store instruction across the APB peripheral bus. It physically powers on the clock gates and transmitter transistors inside the silicon UART core.

1. Memory-Mapped I/O (MMIO) and the Flat Address Space

ARM Cortex-M and RISC-V processors map hardware peripherals directly into the CPU's 4 GB memory map:

  • 0x08000000 - 0x080FFFFF: Flash ROM (Firmware code, Vector Table).
  • 0x20000000 - 0x2001FFFF: Internal SRAM (Stack, Heap, .data, .bss).
  • 0x40000000 - 0x5FFFFFFF: Peripherals MMIO (GPIO, Timers, UART, SPI, I2C, CAN).
  • 0xE0000000 - 0xE00FFFFF: System Control Space (NVIC Interrupt Controller, SysTick).

2. Pointer Physics and the `volatile` Hazard

If an MMIO pointer is not qualified with volatile, an optimizing compiler (-O2) assumes memory is static and caches the value in a general CPU register (e.g. r0). The CPU then spins in an infinite loop without ever reading the physical bus again!

Correct Volatile Register Pointer Declaration 
// Correct: Instructs compiler that memory changes outside software control
volatile uint32_t* uart_sr = (volatile uint32_t*)0x40004400;

// Emits an LDR bus read instruction on EVERY iteration
while ((*uart_sr & (1U << 7)) == 0) {
    // Waits safely for hardware TXE bit to flip
}

3. Industry Struct-Based Peripheral Mapping

Instead of defining raw hex macros for every single register offset, production code (such as ARM CMSIS and Zephyr) defines contiguous register blocks as C structures:

uart_regs.h (CMSIS-style peripheral struct) 
typedef struct {
    volatile uint32_t SR;   // Offset 0x00: Status Register
    volatile uint32_t DR;   // Offset 0x04: Data Register
    volatile uint32_t BRR;  // Offset 0x08: Baud Rate Register
    volatile uint32_t CR1;  // Offset 0x0C: Control Register 1
} UART_TypeDef;

#define UART1 ((UART_TypeDef*)0x40011000UL)

void uart_enable(UART_TypeDef* uart) {
    uart->CR1 |= ((1U << UART_CR1_UE_BIT) | (1U << UART_CR1_TE_BIT));
    uart->CR1 &= ~(1U << UART_CR1_PCE_BIT);
}

4. Check Your Understanding

Question 1 • Volatile Pointer Semantics
What physical action does the CPU take when reading a volatile pointer variable?
Reuses previous cached value stored inside register
Performs actual read transaction across peripheral bus
Suspends execution until hardware interrupt service triggers
Flushes all instructions from processor pipeline stages
✓ Correct! (Option B: Performs actual read transaction)
The volatile qualifier forces the compiler to emit an explicit LDR bus read every single time the variable is accessed, preventing the optimizer from reusing a cached value from a CPU register.
Analysis of Distractors:
• Option A: That is what happens WITHOUT volatile.
• Option C & D: Volatile does not trigger ISRs or flush pipelines.
Question 2 • Pointer Arithmetic Scaling
What physical memory address is produced by evaluating ptr + 2 where uint32_t* ptr = (uint32_t*)0x40001000;?
Memory address value zero x four zero zero zero one zero zero two
Memory address value zero x four zero zero zero one zero zero four
Memory address value zero x four zero zero zero one zero zero eight
Memory address value zero x four zero zero zero one zero one zero
✓ Correct! (Option C: 0x40001008)
Pointer arithmetic scales by sizeof(*ptr). Since sizeof(uint32_t) == 4 bytes, ptr + 2 evaluates to 0x40001000 + (2 * 4) = 0x40001008!
Analysis of Distractors:
• Option A (+2): Incorrectly treats ptr as a 1-byte uint8_t*.
• Option B (+4): Represents ptr + 1.
