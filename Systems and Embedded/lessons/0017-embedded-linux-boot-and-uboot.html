Embedded Linux Boot Architecture:
From Silicon ROM to U-Boot & Init

We now transition from microcontrollers to microprocessors with Memory Management Units (MMUs) capable of running Linux and Android. In this lesson, we trace the complete Linux boot sequence: On-chip Boot ROM, U-Boot Secondary Program Loader (SPL), kernel image decompression, and mounting rootfs.

Mental Model Shift: MCU Boot vs Application Processor Boot

On a microcontroller (ARM Cortex-M), external DDR RAM does not exist; the CPU executes code directly from on-chip Flash memory within microseconds of power-on.

On an application processor (ARM Cortex-A running Linux or Android), external DDR RAM is uninitialized and non-functional at boot! The CPU runs mask ROM code from on-chip silicon, initializes the DDR RAM controller, loads the U-Boot bootloader into RAM, and boots the Linux kernel.

1. The Four Boot Stages of Embedded Linux

The Complete Embedded Linux Boot Chain 
[Stage 1: Boot ROM]   ──> Hardwired into silicon. Initializes internal SRAM & reads boot pins.
          │
          ▼
[Stage 2: SPL]        ──> Secondary Program Loader. Initializes external DDR RAM controller.
          │
          ▼
[Stage 3: U-Boot]     ──> Das U-Boot. Loads Linux kernel (Image) & Device Tree (dtb) into DDR RAM.
          │
          ▼
[Stage 4: Kernel]     ──> Linux Kernel initializes MMU, drivers, mounts rootfs, spawns PID 1 (init).

2. Controlling the Bootloader: U-Boot Environment

U-Boot is an interactive command-line environment configured using environment variables:

  • bootcmd: The automatic script command executed when the boot countdown timer expires.
  • bootargs: The command line passed to the Linux kernel (e.g. console=ttyS0,115200 root=/dev/mmcblk0p2 rw rootwait).
  • bootm / booti: Jumps to the kernel entry point in RAM, passing the Device Tree blob address in register r2 / x0.

3. Check Your Understanding

Question 1 • Secondary Program Loader Role
Why is a Secondary Program Loader (SPL) required before running full U-Boot?
Initializes external dynamic random access memory controllers
Enables automatic garbage collection for runtime memory
Decodes encrypted android application packages from storage
Configures nested vectored interrupt controllers for sleep
✓ Correct! (Option A: Initializes external DRAM controllers)
At initial boot, external DDR RAM is not powered or initialized. The SPL fits into tiny internal SRAM (e.g. 64 KB), configures memory timings, and enables external DDR RAM so full U-Boot and Linux can load!
Analysis of Distractors:
• Option B, C, D: Unrelated to GC, APKs, or NVIC sleep modes.
Question 2 • Kernel Boot Arguments
What is the primary function of the bootargs environment variable in U-Boot?
Allocates variables exclusively inside the dynamic system heap
Passes boot command line arguments into the kernel
Disables all processor hardware floating point register banks
Compiles assembly language files into binary machine code
✓ Correct! (Option B: Passes command line parameters into kernel)
bootargs specifies the console serial port, root filesystem location, and initialization parameters passed to the Linux kernel during handoff.
Analysis of Distractors:
• Option A, C, D: Unrelated to heap, FPU, or compilers.
