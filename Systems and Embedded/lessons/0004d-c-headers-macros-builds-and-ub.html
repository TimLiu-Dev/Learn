Track 00: Silicon & C Foundations • Lesson 0004d

Multi-File C Projects, Storage Classes, Safe Macros, Makefile & UB Sanitizers

Scaling past single-file snippets requires understanding .h vs .c linkage (static vs extern), header guards, macro hygiene (do { ... } while(0)), C11/C23 compile-time assertions (_Static_assert), kernel-style negative error returns, Make/CMake, and AddressSanitizer/UBSan.

Mental Model Shift: Kotlin Packages & Gradle vs C Translation Units & Linkage

In Android, Kotlin files inside a Gradle module see each other cleanly through packages and private/internal visibility.

In C, every .c file compiles blind in isolation (one translation unit). Header files (.h) share declarations (extern int count;), while a single .c file owns the definition (int count = 0;). Put static on internal helper functions and file-local globals so symbols never collide at link time!

1. Declarations vs Definitions, static, extern & Header Guards

can_driver.h & can_driver.c 
/* --- can_driver.h --- */
#ifndef CAN_DRIVER_H      // Include guard prevents double-declaration errors
#define CAN_DRIVER_H
#include <stdint.h>

extern volatile uint32_t g_rx_errors; // DECLARATION only (no storage allocated here)
int can_send_frame(uint32_t id, const uint8_t *data, uint8_t len); // Returns 0 or -EINVAL
#endif

/* --- can_driver.c --- */
#include "can_driver.h"
#include <errno.h>

volatile uint32_t g_rx_errors = 0U;   // DEFINITION in ONE .c file only!
static uint8_t s_tx_seq = 0U;         // File-private internal linkage (.bss) + persistent lifetime

static int validate_dlc(uint8_t len) { // File-private helper (hidden from linker)
    return (len <= 8U) ? 0 : -EINVAL;  // Negative errno convention (used in Linux/RTOS)
}

2. Macro Hygiene, do { ... } while(0) & C11/C23 Compile-Time Checks

macro_safety.c 
// 1. Always parenthesize BOTH arguments AND the whole macro expression:
#define BIT_MASK(n)   (1U << (n))
#define MIN_U32(a, b) (((a) < (b)) ? (a) : (b))

// 2. Wrap multi-statement macros in do { ... } while (0) so semicolons work in if/else!
#define SET_AND_LOG(reg, mask) do { \
    (reg) |= (mask);                \
    g_rx_errors++;                  \
} while (0)

// 3. C11/C23 Compile-Time Struct Verification (zero runtime cost!)
_Static_assert(sizeof(uint32_t) == 4, "Platform requires 32-bit uint32_t");
// C23 adds: static_assert without underscore, constexpr variables, and <stdckdint.h> checked math

3. Strict Tooling, Makefile & Sanitizers (What We Trimmed & Why)

Before flashing an MCU, compile host-side unit tests with strict warnings and sanitizers to catch memory bugs instantly:

Makefile (Host Safety Test + Cross-Build Flags) 
CC     = clang
CFLAGS = -std=c17 -Wall -Wextra -Werror -Wconversion -g -fsanitize=address,undefined

test: main.o can_driver.o
	$(CC) $(CFLAGS) -o host_test $^

%.o: %.c can_driver.h
	$(CC) $(CFLAGS) -c $< -o $@

Intentionally trimmed from desktop C roadmaps: Buffered stdio FILE* text parsing (fopen/fscanf), setjmp/longjmp (banned in MISRA/AUTOSAR/Linux), authoring <stdarg.h> variadic functions, and vcpkg/Conan (AOSP/Linux/Zephyr use Soong, Kbuild, and West/CMake).

Interactive C Workbench: Safe Macro Wrapper & Compile-Time Wire Check

Fix two classic C hazards below: wrap the multi-statement CLEAR_FAULT macro in do { ... } while (0), and add a _Static_assert verifying sizeof(CanHeader) == 8.

Knowledge Check

Question 1 • Mastery Verification
What happens when two .c files both include a header containing int sensor_count = 0; (without extern)?
Linker fails reporting multiple definitions of the same symbol
Preprocessor merges duplicate symbols automatically during header expansion stage
Compiler converts global variables implicitly into thread local storage
Static initialization skips zero values leaving SRAM contents untouched
✓ Correct! (Option A: Multiple definition linker error)
Because #include textually pastes the header into both .c translation units, both .o files export a strong sensor_count symbol and ld aborts with a multiple-definition error.
Analysis of Distractors:
• Option B: Preprocessor runs per file and never sees duplicate symbols across .c files.
• Option C: Globals never become thread-local unless marked _Thread_local.
• Option D: Startup code always zeroes .bss regardless of headers.
Question 2 • Mastery Verification
Why must multi-statement C function-like macros be wrapped inside do { ... } while (0)?
Hardware watchdogs require infinite loops around register write macros
Wrapper forms one safe statement swallowing trailing semicolons cleanly
Optimizer unrolls loops automatically eliminating macro expansion overhead completely
Preprocessor evaluates macro bodies repeatedly at compile time checks
✓ Correct! (Option B: Swallows semicolon as a single statement)
Without do { ... } while (0), calling if (ok) MY_MACRO(); else ...; either breaks the if/else chain with an extra semicolon after {...}; or runs the second statement unconditionally!
Analysis of Distractors:
• Option A: while (0) executes once and exits immediately.
• Option C: Loop unrolling is unrelated to macro syntax safety.
• Option D: Macros substitute raw tokens before compilation.
