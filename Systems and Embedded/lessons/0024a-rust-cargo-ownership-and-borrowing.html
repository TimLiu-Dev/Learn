Track 05: Systems Rust • Lesson 0024a

Rust Systems Foundations:
Cargo, Ownership, Move Semantics & Borrowing

C++ gives you deterministic memory without a garbage collector if you stay disciplined. Rust goes one step further: the compiler proves exclusive ownership and non-aliasing borrows at compile time. Master Cargo, core vs std, move vs Copy, and slice borrowing before writing no_std firmware and Binder HALs.

Mental Model Shift: Kotlin Shared Refs / C++ Pointers vs Rust Move & Exclusive Borrow

In Kotlin, passing a buffer shares a reference until GC collects it. In C++, forgetting std::move silently clones buffers or leaves raw pointers dangling after free.

In Rust, assignment and function calls move ownership by default (unless the type is bitwise Copy like u32). After moving pkt into a consumer, the compiler forbids touching the old binding. To inspect without consuming, borrow with &T (many readers) or &mut T (one exclusive writer).

1. Cargo Workspaces, Feature Flags & core vs alloc vs std

  • core (always available in #![no_std]): Primitives (u8–u64, usize), slices, Option, Result, iterators, atomics—zero OS, zero heap.
  • alloc (optional heap): Adds owned containers (Vec, String, Box, Arc) when an allocator exists (used in Linux kernel fallible collections in Lesson 0027).
  • std (Linux / Android user space): Full OS abstraction (threads, File, sockets, Mutex—used in AOSP AIDL services in Lesson 0028).
  • Cargo.toml & cargo clippy: Use default-features = false on crates when building for microcontrollers so dependencies don't accidentally pull in std.

2. Ownership, Borrowing & Slices (&[u8], &str)

ownership_slices.rs (Zero-Copy Borrowing Without GC or Pointer Decay) 
pub fn checksum_xor(bytes: &[u8]) -> u8 {
    let mut acc: u8 = 0;
    for &b in bytes {
        acc ^= b;
    }
    acc
} // Immutable borrow ends cleanly; caller still owns bytes!

pub fn rust_rules_demo() {
    let rx: [u8; 4] = [0xAA, 0x55, 0x10, 0x01]; // Fixed stack array (Copy of u8)
    let csum = checksum_xor(&rx[..3]);          // Fat pointer slice (&[u8]) = (ptr, len)

    let mut payload = [0u8; 8];
    let w = &mut payload[..4];                  // Exclusive mutable borrow
    w[0] = csum;
    // let r = &payload;                        // COMPILE ERROR while 'w' is still active!
    let _ = w;
    let r = &payload;                           // Non-Lexical Lifetimes allow read once 'w' finishes!
    let _ = r[0];
}

pub fn parse_can_header(frame: &[u8]) -> Option<(u16, u8)> {
    if frame.len() < 3 {
        return None;
    }
    let id = u16::from_le_bytes([frame[0], frame[1]]);
    Some((id, frame[2]))
}

Question 1 • Mastery Verification
What happens after passing a non-Copy value (like a heap-owned telemetry buffer) by value into a Rust function?
Runtime reference counting increments atomically inside hidden heap metadata blocks
Ownership moves permanently and compiler rejects later caller reads cleanly
Compiler silently deep copies heap allocations across stack argument registers
Garbage collector scans both stack frames before reclaiming memory asynchronously
✓ Correct! (Option B: Move semantics enforce single ownership)
Non-Copy types transfer ownership on move. Because the caller binding is invalidated at compile time, the buffer can never be double-freed or accessed after the callee drops it.
Analysis of Distractors:
• Option A: Atomic reference counting only occurs when explicitly wrapped in Arc<T>.
• Option C: Heap deep copies require an explicit .clone() call in Rust.
• Option D: Rust has no garbage collector.
Question 2 • Mastery Verification
Why does adding a no_std dependency in Cargo.toml typically require setting default-features = false?
Cargo disables hardware interrupt vector tables unless defaults are stripped
Toolchain refuses compiling Rust binaries unless all crates disable generics
Many crates enable the OS dependent std feature by default
Disabling default features forces LLVM into single thread assembly mode
✓ Correct! (Option C: Prevents pulling in OS-dependent std)
Ecosystem crates commonly enable a default "std" feature assuming desktop/server OSes. Setting default-features = false keeps the crate strictly inside core so microcontroller targets link cleanly.
Analysis of Distractors:
• Option A, B, D: Feature flags control conditional Cargo features/dependencies, not hardware interrupts, generics, or LLVM threads.
