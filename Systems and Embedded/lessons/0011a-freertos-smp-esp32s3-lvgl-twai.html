FreeRTOS SMP on ESP32-S3:
Core Pinning, PSRAM LVGL, TWAI & INA226 Profiling

Build Node B of Milestone 4 on your ESP32-S3 DevKitC-1 N16R8: pin BLE/TWAI networking to Core 0 and LVGL rendering (1.3" ST7789 TFT) to Core 1, allocate framebuffers cleanly in Octal PSRAM, and measure active current with the INA226.

Hardware Traps: GPIO35–37 PSRAM, No-CS ST7789 & Dual-Core Spinlocks

On the N16R8 variant, GPIO35, GPIO36, GPIO37 are wired internally to Octal PSRAM—never attach external wires to them! Also, your 1.3" ST7789 module has no CS pin and typically uses SPI Mode 3, so dedicate its own SPI host away from any other SPI device.

On dual-core SMP FreeRTOS, disabling interrupts on Core 0 does not stop Core 1—critical sections require ESP-IDF portMUX_TYPE spinlocks (taskENTER_CRITICAL(&mux))!

1. Dual-Core Task Pinning & PSRAM LVGL Buffers

  • Core Partitioning: Pin radio/CAN/UART tasks (BLE Central + TWAI RX) to Core 0 alongside Wi-Fi/BT protocol stacks, and pin the LVGL + esp_lcd flush task to Core 1 via xTaskCreatePinnedToCore().
  • Partial DMA vs Full PSRAM Framebuffer: A full 240 × 240 RGB565 frame is 115.2 KB. Keep two small partial draw buffers (e.g. 20–40 lines) in internal DMA-capable SRAM (`MALLOC_CAP_DMA`) for fast SPI DMA, while storing off-screen widgets/caches in 8 MB Octal PSRAM (`MALLOC_CAP_SPIRAM`).
  • Verify Core Load: Enable CONFIG_FREERTOS_GENERATE_RUN_TIME_STATS and dump vTaskGetRunTimeStats() to prove Core 0 / Core 1 split and catch starvation.

Knowledge Check

Question 1 • Dual-Core SMP Concurrency
Why is disabling CPU interrupts alone insufficient to protect a shared struct between a Core 0 CAN task and a Core 1 LVGL task on the ESP32-S3?
ESP32-S3 lacks hardware interrupts for all peripheral SPI buses
Masking interrupts on one core never halts the other
FreeRTOS SMP disables every mutex across both CPU cores
Octal PSRAM blocks reads whenever interrupts are enabled locally
✓ Correct! (Option B: Interrupt masking is per-core)
Core 1 keeps running concurrently while Core 0's interrupts are masked! ESP-IDF's taskENTER_CRITICAL(&mux) uses an atomic portMUX_TYPE spinlock so both cores synchronize safely.
Analysis of Distractors:
• Options A, C, D: ESP32-S3 has full peripheral interrupts, FreeRTOS SMP supports cross-core mutexes/queues, and Octal PSRAM works with interrupts enabled.
Question 2 • Power Measurement Limits
Why can your INA226 module measure active BLE/TFT current accurately on the nRF54L15-DK, yet struggle to resolve microamp deep-sleep current?
I2C buses automatically power down whenever deep sleep begins
Nordic boards lock the I2C pins inside TrustZone memory
Standard shunt resolution sits near twenty-five microamps per bit
INA226 requires five-volt logic levels exceeding Nordic I/O limits
✓ Correct! (Option C: ~25μA/LSB floor with a 0.1Ω shunt)
With its 2.5μV shunt ADC LSB across a 0.1Ω resistor, one LSB is 25μA—too coarse for 1–5μA deep sleep! Use your Delixi DMM in microamp range or a PPK2 on the DK's current header for sleep measurements.
Analysis of Distractors:
• Options A, B, D: You power/read the INA226 from an external controller or host, TrustZone doesn't block passive shunt sensing, and INA226 runs natively at 3.3V.
