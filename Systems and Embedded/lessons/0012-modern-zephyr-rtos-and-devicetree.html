Track 02: Real-Time Operating Systems • Lesson 0012

Modern Zephyr RTOS:
Devicetrees, Kconfig & Cross-Architecture Abstraction

While FreeRTOS is a simple microkernel, Zephyr is a complete open-source embedded operating system built by the Linux Foundation. In this lesson, we study Zephyr's architecture, learn how Devicetrees decouple hardware pins from application code, and configure features with Kconfig.

Mental Model Shift: Gradle Build Flavors vs Kconfig/Devicetree

In Android, configuring different build targets (e.g. Free vs Paid, Phone vs Automotive) uses Gradle buildTypes and productFlavors.

In Zephyr and Embedded Linux, configuration is split cleanly: Kconfig controls software features (e.g. CONFIG_GPIO=y), while Devicetree (.dts) controls hardware topography (e.g. what physical pin connects to the LED). You can port your entire app to a brand new ARM or RISC-V chip simply by supplying a new devicetree!

1. The Devicetree Architecture (.dts)

Instead of hardcoding register addresses like 0x40011000 in C source code, hardware is declared in a hierarchical Devicetree:

app.overlay (Zephyr Devicetree Node) 
/ {
    leds {
        compatible = "gpio-leds";
        status_led: led_0 {
            gpios = <&gpioa 5 GPIO_ACTIVE_HIGH>;
            label = "System Heartbeat LED";
        };
    };
};

2. Accessing Hardware via Device API in C

At compile time, Zephyr parses the Devicetree and generates static macros. In C, you retrieve the hardware device pointer cleanly:

main.c (Zephyr Hardware Abstraction) 
#include <zephyr/kernel.h>
#include <zephyr/drivers/gpio.h>

static const struct gpio_dt_spec led = GPIO_DT_SPEC_GET(DT_NODELABEL(status_led), gpios);

int main(void) {
    gpio_is_ready_dt(&led);
    gpio_pin_configure_dt(&led, GPIO_OUTPUT_ACTIVE);

    while (1) {
        gpio_pin_toggle_dt(&led);
        k_msleep(500); // Zephyr cooperative sleep
    }
}

3. Check Your Understanding

Question 1 • Devicetree Benefits
What is the primary architectural purpose of Devicetrees in Zephyr RTOS?
Decouples physical hardware descriptions from application code
Automatically compresses executable machine code inside flash
Replaces nested vectored interrupt controllers with software
Enables garbage collection for all runtime variables
✓ Correct! (Option A: Decouples hardware from application)
Devicetree allows you to describe pin assignments, bus speeds, and peripheral addresses separately from C source code, making the code 100% portable across different boards.
Analysis of Distractors:
• Option B, C, D: Devicetree does not compress code, replace interrupt hardware, or add garbage collection.
Question 2 • Kconfig vs Devicetree
What is the distinct role fulfilled by Kconfig in Zephyr builds?
Defines physical memory addresses of hardware registers
Configures software subsystem features and kernel options
Maps interrupt service routines inside vector tables
Generates linker scripts for arm processor compilation
✓ Correct! (Option B: Configures software subsystem features)
Kconfig enables and disables software modules (e.g. CONFIG_BT=y for Bluetooth, CONFIG_LOG=y for logging), while Devicetree defines physical hardware pins and addresses.
Analysis of Distractors:
• Option A: Handled by Devicetree.
• Option C & D: Handled by the vector table and linker scripts.
