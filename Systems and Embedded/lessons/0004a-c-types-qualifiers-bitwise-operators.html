C for Android Developers:
Fixed-Width Types, Qualifiers & Bitwise Precedence

Kotlin hides word sizes, overflows, and memory rules behind JVM abstractions. Before touching bare-metal peripheral registers in Track 01, master exact-width integers (<stdint.h>), type qualifiers (const, volatile, restrict), signed undefined behavior traps, and C operator precedence.

Mental Model Shift: Kotlin Int vs C Architecture-Dependent Widths

In Kotlin/Java, an Int is always signed 32-bit, a Long is always signed 64-bit, and signed overflow wraps silently.

In C, plain long is 32 bits on 32-bit ARM Cortex-M (ILP32) and Windows, but 64 bits on 64-bit Linux/ARM64 (LP64). Furthermore, signed integer overflow is Undefined Behavior (UB)—allowing GCC/Clang optimizers to delete sanity checks! Systems engineers always use <stdint.h> types.

1. Exact-Width Systems Types (<stdint.h> & <stdbool.h>)

Hardware datasheets specify exact bit layouts (e.g., 16-bit ADC reading or 32-bit register). Never use bare short, int, or long for hardware or wire protocols:

types_and_promotions.c 
#include <stdint.h>   // uint8_t, int16_t, uint32_t, uintptr_t
#include <stddef.h>   // size_t (unsigned buffer length / sizeof result)
#include <stdbool.h>  // bool, true, false (native keywords in C23)

// Portable across STM32 (32-bit MCU) AND Qualcomm Snapdragon (64-bit SoC)
uint32_t reg_val = 0x40004400U;
int16_t  battery_temp_c = -40;
size_t   payload_bytes = 64U;
uintptr_t mmio_addr = (uintptr_t)0x40011000UL;

// TRAP 1: Unsigned integer wrap is well-defined mod 2^N; Signed overflow is UB!
uint32_t ticks = 0xFFFFFFFFU;
ticks += 1U; // Defined: wraps cleanly to 0x00000000

// TRAP 2: Unsigned left-shift vs signed bit inversion
uint32_t mask_safe = ~(1U << 31); // Always use 1U (unsigned) when shifting bit 31!
// int bad_mask = 1 << 31;       // Undefined Behavior in C for signed 32-bit int!

2. Type Qualifiers: const, volatile & restrict

  • const: Promises code will not mutate data through this identifier. In embedded firmware, globals marked const are placed in read-only Flash (.rodata), saving precious SRAM.
  • volatile: Commands the compiler never to cache or omit memory loads/stores. Required for memory-mapped hardware registers (MMIO) and variables shared with ISRs (unless using atomics). Note: volatile guarantees visibility per instruction, not thread atomicity!
  • restrict (C99): Tells the optimizer two pointer arguments never point to overlapping memory (e.g., DMA memcpy(void *restrict dst, const void *restrict src, size_t n)), allowing tighter vector/loop code generation.

3. Operator Precedence & Control-Flow Traps vs Kotlin

In Kotlin, bitwise operations use named infix calls (and, shl). In C, bitwise operators (&, |, ^) have LOWER precedence than equality (==, !=)! This is one of the most common firmware bugs on Earth:

precedence_trap.c 
#define STATUS_BUSY (1U << 3) // 0x08

// BUG: Parses as if (reg & (STATUS_BUSY == 0)) -> (reg & 0) -> ALWAYS FALSE!
if (reg & STATUS_BUSY == 0) {
    // Dead code! Even when BUSY bit is clear, condition fails!
}

// CORRECT: Always wrap bitwise masks in parentheses
if ((reg & STATUS_BUSY) == 0U) {
    start_spi_transfer();
}

// TRAP 3: Switch fallthrough (unlike Kotlin 'when', C falls through silently!)
switch (irq_source) {
    case 1:
        clear_rx_flag();
        break; // Omit 'break' and execution falls into case 2!
    case 2:
        clear_tx_flag();
        break;
    default:
        break;
}

Reference Solution: 
bool is_peripheral_ready(uint32_t status_reg) {
    return ((status_reg & READY_BIT) != 0U) &&
           ((status_reg & FAULT_BIT) == 0U);

Knowledge Check

Question 1 • Mastery Verification
Why should embedded firmware prefer uint32_t over plain int or long?
Exact bit widths remain guaranteed identical across CPU architectures
Plain integer variables cannot pass across C function parameters
Exact width integers automatically trigger hardware cache flush lines
Compilers forbid standard arithmetic operators on fixed width types
✓ Correct! (Option A: Guaranteed fixed bit widths)
Standard C only defines minimum ranges for int and long (so long flips between 32 and 64 bits across Cortex-M and ARM64 Linux). <stdint.h> types guarantee exact layout for MMIO registers and binary packets.
Analysis of Distractors:
• Option B: Plain integers pass normally as function arguments.
• Option C: Cache flushing requires explicit barrier/cache instructions, not type names.
• Option D: All normal C arithmetic and bitwise operators work on uint32_t.
Question 2 • Mastery Verification
What bug occurs when writing if (reg & BUSY_BIT == 0) without parentheses in C?
Compiler rejects mixed bitwise logical lines as syntax errors
Equality evaluates before bitwise AND silently corrupting mask logic
Hardware arithmetic unit traps immediately on unaligned memory accesses
Preprocessor expands the bitmask constant into floating point notation
✓ Correct! (Option B: == binds tighter than &)
Because == has higher precedence than & in C, reg & BUSY_BIT == 0 compiles as reg & (BUSY_BIT == 0) → reg & 0 → always 0!
Analysis of Distractors:
• Option A: C compiles it without failing (only issuing an optional warning if -Wparentheses is enabled).
• Option C: Integer ALU operations do not cause alignment faults.
• Option D: Preprocessor text substitution never turns integer masks into floats.
