Algebraic Types & Safety Without Null:
Enums, Pattern Matching, Option, Result & ?

Rust has no null pointers and no runtime exceptions. Instead, it turns Kotlin sealed class patterns into stack-allocated tagged unions (enum) and enforces failure handling at compile time using Option<T>, Result<T, E>, and the ? propagation operator.

Mental Model Shift: Kotlin sealed class + try/catch vs Rust Zero-Heap Tagged Unions

In Kotlin, a sealed class Packet allocates subclasses on the heap, and unhandled failures throw stack-unwinding exceptions.

In Rust, an enum stores the discriminant tag and the largest variant inline on the stack (or inside static memory) with zero heap allocations. Errors return Result<T, E>—marked #[must_use] by the language—so ignoring a hardware failure emits a compiler warning!

1. Data-Carrying enums & Exhaustive match

telemetry_errors.rs (Stack-Allocated Algebraic Types + From Conversion) 
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum CanFrame {
    Standard { id: u16, len: u8 },
    RemoteReq(u16),
    BusFault,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ParseErr {
    TooShort,
    OutOfRange(u8),
}

pub fn describe_id(frame: CanFrame) -> Option<u16> {
    match frame {
        CanFrame::Standard { id, len } if len <= 8 => Some(id),
        CanFrame::Standard { .. } => None,
        CanFrame::RemoteReq(id) => Some(id),
        CanFrame::BusFault => None,
    } // Compiler rejects match if ANY variant is missing!
}

2. Propagating Errors With ? vs Avoiding .unwrap()

  • The ? operator: Inside a function returning Result<T, E> (or Option<T>), expr? unwraps Ok(v) or returns Err(From::from(e)) immediately—replacing verbose C if (ret < 0) return ret; boilerplate across Linux drivers (Lesson 0027) and Binder HALs (Lesson 0028).
  • Firmware & HAL Discipline: Calling .unwrap() or .expect() triggers a panic (halting an MCU or crashing an AOSP HAL daemon). Reserve .unwrap() strictly for unit tests or provably impossible states; return Result or use unwrap_or / if let in production paths.

pub fn decode_voltage_mv(pkt: &[u8]) -> Result<u16, DecodeErr> {
    let mv = read_u16(pkt)?;
    if mv > 5000 {
        return Err(DecodeErr::OverVoltage);
    }
    Ok(mv)
}

What advantage do Rust data-carrying enums + match provide over C unions or Kotlin subclasses in firmware?
Variants allocate dynamically inside garbage collected heap arenas automatically
Compiler tracks variant tags inline and enforces exhaustive pattern handling
Match blocks allow silently reading uninitialized union fields anytime without checks
Enums bypass virtual table generation while forcing global mutex synchronization
✓ Correct! (Option B: Safe stack-stored tagged union + exhaustiveness)
Unlike raw C unions (where reading the wrong member is Undefined Behavior) or Kotlin sealed class objects (heap allocated), Rust stores the discriminant inline on the stack and refuses to compile if any enum case is unhandled.
Analysis of Distractors:
• Option A: Rust enums live inline on stack/static RAM unless boxed.
• Option C: Safe Rust makes reading inactive variant data impossible.
• Option D: Enums involve no global mutex synchronization.
Question 2 • Mastery Verification
Why should production bare-metal firmware and AOSP Binder HAL methods propagate Result with ? instead of calling .unwrap()?
Question mark converts hardware errors into ignored silent compiler attributes
Calling unwrap allocates dynamic exception unwinding frames inside read only flash
Calling unwrap panics on failure crashing daemons or halting microcontrollers
Question mark bypasses trait boundaries enabling mutable shared globals cleanly
✓ Correct! (Option C: Prevents panics by returning errors)
An uncaught .unwrap() on an error triggers panic!, crashing a vendor HAL service or trapping an MCU in its panic handler. Using ? cleanly bubbles the error up to callers or back to Binder/Linux errno.
Analysis of Distractors:
• Option A: ? returns Err(e) immediately to the caller.
• Option B: Embedded Rust builds typically configure panic = "abort" rather than unwind tables.
• Option D: ? strictly enforces return types and never bypasses borrow/trait rules.
