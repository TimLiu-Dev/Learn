Mental Model Shift: ARM Cortex-M NVIC vs RISC-V CSRs & Interrupt Matrix

On ARM Cortex-M, hardware automatically pushes 8 registers to the stack and jumps into the Vector Table (VTOR).

On 32-bit RISC-V (RV32IMC), traps jump to mtvec, latch the fault/IRQ code in mcause, and save the return PC in mepc—and software saves caller-saved registers! On the ESP32-C3, an interrupt matrix routes 60+ peripheral sources into 31 CPU interrupt lines.

1. RISC-V Trap CSRs (mtvec, mcause, mepc)

  • mtvec (Machine Trap-Vector Base-Address): Mode bits [1:0] select Direct (0: all traps jump to one handler) vs Vectored (1: async interrupts jump to base + 4 * cause).
  • mcause: Top bit (bit 31 on RV32) = 1 for asynchronous Interrupt, 0 for synchronous Exception (illegal instruction, misaligned access, ecall). Lower bits hold the numeric cause ID.
  • mepc: Holds the PC of the offending instruction (exceptions) or next instruction (interrupts), restored by mret.

Interactive Practice: RV32 mcause Trap Decoder

Implement decode_mcause(mcause: u32) -> TrapKind in Rust: bit 31 (0x8000_0000) distinguishes Interrupt from Exception, and bits [30:0] hold the cause code.

riscv_trap.rs
💡 Progressive Guidance Hints:
Hint 1: Mask out the MSB with let code = mcause & 0x7FFF_FFFF;.
Hint 2: Check bit 31 with if (mcause & 0x8000_0000) != 0.
✅ Reference Production Solution:
pub fn decode_mcause(mcause: u32) -> TrapKind {
    let code = mcause & 0x7FFF_FFFF;
    if (mcause & 0x8000_0000) != 0 {
        TrapKind::Interrupt(code)
    } else {
        TrapKind::Exception(code)
    }
}

Question 1 • Zero-Cost Firmware Logging
Why does defmt combined with probe-rs eliminate the Flash and CPU penalties of traditional MCU printf logging?
MCU allocates heap strings and transmits compressed JSON frames
MCU transmits tiny string IDs decoded on the host
MCU disables interrupts globally until the host sends acknowledgements
Host compiles Rust format strings directly into ROM bootloaders
✓ Correct! (Option B: Deferred formatting on the host PC)
The MCU only writes an interned string ID and raw binary arguments into an RTT ring buffer; probe-rs reads the ELF symbol table on your Mac to render human-readable logs.
Analysis of Distractors:
• Options A, C, D: defmt uses zero heap, doesn't block waiting on host ACKs like semi-hosting, and stores format metadata in non-loaded ELF sections.
Question 2 • Cross-Architecture Driver Portability
How can the exact same Rust BME280 driver crate run unmodified on both your ARM STM32F411 and RISC-V ESP32-C3?
Both chips share identical peripheral memory register addresses
Cargo translates ARM instructions into RISC-V at runtime
Driver depends on generic embedded-hal bus traits only
ESP32-C3 executes Thumb-2 binaries inside a hardware emulator
✓ Correct! (Option C: Generic embedded-hal trait bounds)
Writing drivers against embedded_hal::i2c::I2c or embedded_hal_async::spi::SpiDevice decouples sensor logic from MCU silicon; each HAL crate (embassy-stm32, esp-hal) implements those traits.
Analysis of Distractors:
• Options A, B, D: STM32 and ESP32 have completely different MMIO layouts and ISAs, and Rust compiles native machine code per target triple.
