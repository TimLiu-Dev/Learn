Track 07: Android Automotive OS (AAOS) • Lesson 0030

Android Automotive OS Architecture:
CarService, IVehicle AIDL HAL & CarPropertyManager

Android Automotive OS (AAOS) is a full-fledged, in-vehicle operating system powering infotainment and digital cockpits in modern vehicles. In this lesson, you will trace vehicle telemetry from the physical hardware bus, through the Vehicle Hardware Abstraction Layer (VHAL), into Android's CarService, and finally to Jetpack Compose automotive apps via CarPropertyManager.

Mental Model Shift: Android Phone SDK vs Android Automotive OS (AAOS)

In standard Android phones, your app interacts with LocationManager, CameraManager, and BatteryManager. You know nothing about battery chemistry or internal power circuits; the OS abstracts everything into simple percentages.

In AAOS, the car itself is the computer. Your application interfaces with CarPropertyManager, which exposes hundreds of zoned vehicle properties (such as PERF_VEHICLE_SPEED, HVAC_TEMPERATURE_SET, GEAR_SELECTION, and TIRE_PRESSURE). Underneath, a privileged native daemon implementing IVehicle.aidl communicates with vehicle microcontrollers over CAN or SPI!

2. Inside `IVehicle.aidl`: Modern Automotive HAL

Starting in Android 13 and standard across Android 14/15/16, the Vehicle HAL uses stable AIDL located at android.hardware.automotive.vehicle. The interface is optimized for high-throughput batching:

android.hardware.automotive.vehicle.IVehicle.aidlAIDL Interface
package android.hardware.automotive.vehicle;

@VintfStability
interface IVehicle {
    // Read one or more property values
    void getValues(IVehicleCallback callback, in GetValueRequests requests);

    // Write a property value (e.g. Set HVAC Cabin Temperature)
    void setValues(IVehicleCallback callback, in SetValueRequests requests);

    // Subscribe to continuous or on-change property updates
    void subscribe(IVehicleCallback callback, in SubscribeOptions[] options);

    // Unsubscribe from updates
    void unsubscribe(IVehicleCallback callback, in int[] propIds);
}

Anatomy of a Vehicle Property ID

In AAOS, property IDs are 32-bit integers packed with metadata:

  • Bits 31–28: Type (0x1: Int32, 0x2: Int64, 0x4: Float, 0x5: String).
  • Bits 27–20: Group (0x1: System standard, 0x2: OEM Vendor extension).
  • Bits 19–16: Change Mode (0x1: Static, 0x2: OnChange, 0x3: Continuous).
  • Bits 15–0: Unique Property Index (e.g., 0x0207 for Vehicle Speed).

For example, PERF_VEHICLE_SPEED is 0x11600207 (Float, System, Continuous, ID 0x0207).

3. The Android App Layer: `CarPropertyManager`

For an automotive developer, reading vehicle telemetry in Kotlin is clean and reactive:

DashboardViewModel.ktKotlin (AAOS App)
val car = Car.createCar(context)
val carPropertyManager = car.getCarManager(Car.PROPERTY_SERVICE) as CarPropertyManager

val speedCallback = object : CarPropertyManager.CarPropertyEventCallback {
    override fun onChangeEvent(value: CarPropertyValue<*>) {
        if (value.propertyId == VehiclePropertyIds.PERF_VEHICLE_SPEED) {
            val speedMps = value.value as Float
            val speedKmh = speedMps * 3.6f
            _vehicleSpeed.value = speedKmh
        }
    }

    override fun onErrorEvent(propId: Int, zone: Int) {
        Log.e("AAOS", "Error reading prop: $propId in zone $zone")
    }
}

// Subscribe at 10 Hz (10 samples per second)
carPropertyManager.registerCallback(
    speedCallback,
    VehiclePropertyIds.PERF_VEHICLE_SPEED,
    CarPropertyManager.SENSOR_RATE_NORMAL
)

Reference Solution: 
float dispatch_vhal_speed_event(const VhalEventPacket *packet) {
    if (packet->prop_id != PROP_PERF_VEHICLE_SPEED) return -1.0f;
    return packet->value_float * 3.6f;
}
