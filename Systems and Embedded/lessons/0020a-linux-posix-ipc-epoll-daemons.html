Track 04: Non-AOSP Linux Systems • Lesson 0020a

Non-AOSP Linux User-Space:
epoll Event Loops, POSIX IPC & systemd

Most embedded Linux products—robotics controllers, medical analyzers, charging stations, and industrial gateways—run pure Linux without Android. Learn how senior Linux engineers multiplex kernel device nodes, sockets, and timers on a single deterministic event loop and supervise them with systemd and cgroups.

Mental Model Shift: Android Looper & Binder vs Linux epoll & POSIX IPC

In Android apps, you rely on Looper, Handler, and Binder without ever seeing the Linux syscalls underneath. (In fact, Android's native Looper is literally built on Linux epoll + eventfd!)

On non-AOSP Embedded Linux, there is no Binder, no Zygote, and no ActivityManager. You combine file descriptors directly: open("/dev/cockpit_bridge"), AF_UNIX sockets, timerfd, and shm_open() shared memory inside one non-blocking epoll_wait() loop supervised by systemd.

1. The Universal Linux Abstraction: Everything Is a File Descriptor

Instead of spawning one blocking thread per sensor or network socket, a Linux systems daemon sets descriptors to O_NONBLOCK and sleeps inside epoll_wait() until the kernel wakes it with only the ready descriptors:

epoll_gateway.c (Single-Thread O(1) Multiplexer) 
#include <sys/epoll.h>
#include <unistd.h>
#include <fcntl.h>

int run_event_loop(int spi_dev_fd, int timer_fd) {
    int ep = epoll_create1(EPOLL_CLOEXEC);
    if (ep < 0) return -1;

    struct epoll_event ev = { .events = EPOLLIN, .data.fd = spi_dev_fd };
    epoll_ctl(ep, EPOLL_CTL_ADD, spi_dev_fd, &ev);

    ev.data.fd = timer_fd;
    epoll_ctl(ep, EPOLL_CTL_ADD, timer_fd, &ev);

    struct epoll_event ready[8];
    for (;;) {
        int n = epoll_wait(ep, ready, 8, -1); // Sleeps with 0% CPU until IRQ/timer
        for (int i = 0; i < n; ++i) {
            if (ready[i].data.fd == spi_dev_fd) { /* read & forward telemetry */ }
            if (ready[i].data.fd == timer_fd)   { /* kick hardware watchdog */ }
        }
    }
}

2. POSIX IPC & systemd Service Supervision

  • Unix Domain Sockets (AF_UNIX): Fast, local, kernel-buffered IPC between daemons on the same board—can even pass open file descriptors via SCM_RIGHTS.
  • POSIX Shared Memory (shm_open + mmap): Zero-copy RAM ring buffers for high-bandwidth camera, LiDAR, or audio streams, paired with eventfd wakeups.
  • systemd + cgroups v2: Replaces Android's init.rc on standard Embedded Linux. Enforces MemoryMax=, CPUQuota=, automatic crash restart, and WatchdogSec= heartbeat supervision.

int register_fd_for_read(int target_fd) {
    int ep = epoll_create1(EPOLL_CLOEXEC);
    if (ep < 0) return -1;

    struct epoll_event ev = {0};
    ev.events = EPOLLIN;
    ev.data.fd = target_fd;

    if (epoll_ctl(ep, EPOLL_CTL_ADD, target_fd, &ev) < 0) {
        return -1;
    }
    return ep;
}

Knowledge Check

Question 1 • Mastery Verification
Why do production Linux gateway daemons prefer epoll_wait() over spawning one blocking thread per device node?
Single event loop scales cleanly with minimal stack overhead and deterministic ordering
Linux kernel forbids user space programs from creating multiple concurrent POSIX threads
Calling epoll bypasses virtual memory protection to access physical DMA buffers directly
Blocking threads automatically allocate Java garbage collection heaps on every single syscall
✓ Correct! (Option A: Deterministic O(1) readiness multiplexing)
One epoll thread avoids megabytes of per-thread stack memory, minimizes context switches and mutex contention, and handles character devices, sockets, and timerfd uniformly.
Analysis of Distractors:
• Option B: Linux supports pthreads freely.
• Option C: epoll only monitors readiness; it does not bypass MMU isolation.
• Option D: Native C/Rust Linux daemons have no JVM or GC.
Question 2 • Mastery Verification
Which POSIX mechanism transfers gigabytes per second of camera or LiDAR frames between two Linux daemons without copying payloads?
Writing JSON encoded pixel arrays repeatedly across standard shell Linux environment variables
Mapping shared memory regions via shm_open and mmap with kernel eventfd signals
Serializing binary frames into ASCII hex strings over loopback HTTP REST endpoints
Spawning child processes on every incoming frame using synchronous fork system calls
✓ Correct! (Option B: shm_open + mmap + eventfd)
shm_open() + mmap() maps the exact same physical RAM pages into both processes' address spaces, while an 8-byte eventfd write notifies the consumer inside epoll.
Analysis of Distractors:
• Option A, C, D: Copying, JSON/HTTP parsing, or forking per frame destroys real-time throughput.
