Track 06: Systems Rust & AOSP • Lesson 0025

Bare-Metal Rust (`no_std`):
Ownership, Volatile Registers & embedded-hal

Welcome to Modern Systems Rust. Over 70% of high-severity vulnerabilities in C/C++ codebases stem from memory safety bugs (buffer overflows, use-after-free, data races). In this lesson, we strip the Rust standard library (`no_std`) and write bare-metal firmware with zero runtime overhead and compile-time memory safety.

Mental Model Shift: Kotlin Val/Var vs Rust Move & Borrowing

In Kotlin, passing an object passes a reference; multiple coroutines can hold that reference simultaneously, leading to race conditions unless manually guarded by mutexes.

In Rust, Ownership and Borrowing are strictly verified by the compiler. A variable has exactly one owner. You may have either one mutable reference (&mut T) OR many immutable references (&T), but never both. Data races and dangling pointers are physically impossible to compile!

1. Stripping the Runtime: `#![no_std]`

On microcontrollers without an operating system, Rust firmware disables the standard library:

main.rs (Bare-Metal Rust Firmware Skeleton) 
#![no_std]
#![no_main]

use core::panic::PanicInfo;
use cortex_m_rt::entry;

// Custom panic handler required when standard library is disabled
#[panic_handler]
fn panic(_info: &PanicInfo) -> ! {
    loop {
        // Halt microcontroller on panic
    }
}

#[entry]
fn main() -> ! {
    let uart_cr1 = 0x4001_100C as *mut u32;

    unsafe {
        // Core pointer volatile write: emits physical STR bus instruction
        core::ptr::write_volatile(uart_cr1, (1 << 13) | (1 << 3));
    }

    loop {}
}

2. Type-Safe Hardware Abstraction: `embedded-hal`

In C, hardware drivers are tightly coupled to vendor headers. In the Rust ecosystem, `embedded-hal` provides universal traits for GPIO pins, SPI, I2C, and UART. A driver written for a temperature sensor works interchangeably across STM32, ESP32, and Raspberry Pi RP2040!

3. Check Your Understanding

Question 1 • Rust no_std Attribute
What is the primary effect of applying the #![no_std] attribute in Rust?
Disables standard library linking relying on core
Doubles the maximum physical clock frequency bus
Enables automatic garbage collection for runtime variables
Compresses dalvik executable bytecode inside package files
✓ Correct! (Option A: Disables standard library relying on core)
#![no_std] strips the standard library (which assumes an OS with filesystems, threads, and dynamic heap) and links only core, which has zero runtime requirements.
Analysis of Distractors:
• Option B, C, D: Unrelated to clock frequencies, garbage collection, or Android bytecode.
Question 2 • Compile-Time Data Race Prevention
How does the Rust borrow checker prevent data races at compile time?
Allocates variables exclusively inside dynamic system heap
Prohibits simultaneous multiple aliased mutable variable references
Disables nested vectored interrupt controller priority preemption
Eliminates requirement for physical pullup bus resistors
✓ Correct! (Option B: Prohibits simultaneous mutable references)
Rust enforces the rule: You can have any number of immutable references (&T), OR exactly one mutable reference (&mut T), but never both simultaneously. Data races cannot compile!
Analysis of Distractors:
• Option A, C, D: Unrelated to heap, NVIC, or pullup resistors.
