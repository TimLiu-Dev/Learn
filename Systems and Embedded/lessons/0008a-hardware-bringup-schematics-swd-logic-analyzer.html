Track 01: Bare-Metal C & Hardware • Lesson 0008a

Hardware Bring-Up:
Datasheets, SWD/JTAG, Clock Trees & Logic Analyzers

AI can generate C driver code, but it cannot tell you why your brand-new PCB refuses to ACK on I2C or why your board resets every 400ms. Real hardware bring-up—reading schematics, decoding clock/reset registers, attaching SWD probes, and probing wires with a logic analyzer—is your strongest engineering moat.

Mental Model Shift: Android Logcat vs Electrical & Silicon Truth

In Android app development, the device already boots, clocks run, and Logcat prints readable stack traces over USB ADB.

On fresh bare-metal silicon, nothing works until you verify power rails with a multimeter, flash via SWD/JTAG (OpenOCD), enable peripheral clock gates, check reset-cause flags (RCC->CSR), and inspect physical SPI/I2C waveforms on a logic analyzer.

1. The 5-Step Board Bring-Up Checklist

  1. Power, Rail & Brownout Check: Verify 3.3 V / 1.8 V rails with your Delixi DT9205APRO before plugging in any sensor (set nRF54L15-DK I/O to 3.3 V in Nordic's Board Configurator and set CP2102 to 3.3 V); inspect RCC->CSR on boot to catch BOR/IWDG resets.
  2. SWD/JTAG Probe Connection: Two wires (SWDIO + SWCLK + GND) let CMSIS-DAP or ST-LINK V2 halt the CPU core via OpenOCD or probe-rs. On low-cost STM32F103 clones, pass set CPUTAPID 0 if OpenOCD rejects the IDCODE.
  3. HardFault Frame Decoding (PC, LR, CFSR): On an illegal bus/alignment/usage fault, Cortex-M stacks R0–R3, R12, LR, PC, xPSR and latches the root cause in SCB->CFSR (0xE000ED28). Inspect PC with addr2line (practice in ./labs/08_hardfault_decoder/).
  4. Silicon Identity & Pull-Ups: Check BME280 register 0xD0 == 0x60 (not 0x58 BMP280), LSM6DSV16X WHO_AM_I (0x0F == 0x70), and 2.2 kΩ–4.7 kΩ I2C pull-ups. Watch for 74LVC125 buffers on cheap MicroSD breakouts holding MISO active.
  5. Logic Analyzer & Scope Verification: Capture CS, SCLK, MOSI, MISO in PulseView (≤ 4 MHz SPI clock for your 24 MHz analyzer), and use your DSO2512G (10x probes, CH1 - CH2 math) to inspect SPI rise times and differential CAN/RS485 waveforms.
reset_cause.c (Diagnosing Field Resets on First Boot) 
#define RCC_CSR_IWDGRSTF  (1U << 29) // Independent Watchdog Reset Flag
#define RCC_CSR_BORRSTF   (1U << 25) // Brownout Reset Flag
#define RCC_CSR_RMVF      (1U << 24) // Remove Reset Flags

const char* inspect_and_clear_reset_cause(volatile uint32_t *rcc_csr) {
    uint32_t csr = *rcc_csr;
    *rcc_csr |= RCC_CSR_RMVF; // Clear latched flags for next boot
    if (csr & RCC_CSR_IWDGRSTF) return "WATCHDOG_TIMEOUT";
    if (csr & RCC_CSR_BORRSTF)  return "BROWNOUT_POWER_DIP";
    return "NORMAL_RESET";
}

✅ Reference Production Solution:
int decode_reset_cause(volatile uint32_t *rcc_csr) {
    uint32_t csr = *rcc_csr;
    *rcc_csr |= RCC_CSR_RMVF;
    if (csr & RCC_CSR_IWDGRSTF) return 1;
    if (csr & RCC_CSR_BORRSTF)  return 2;
    return 0;
}

Knowledge Check

Question 1 • Open-Drain Bus Bring-Up
You probe an I2C bus on a new PCB and both SDA and SCL sit flat at 0 V even before software starts. What is the most likely hardware cause?
Missing external pull-up resistors on open-drain I2C bus lines
Missing linker script sections inside microcontroller flash memory tables
Incorrect compiler optimization flags passed to the GNU toolchain
Excessive heap fragmentation inside RTOS dynamic memory allocator pools
✓ Correct! (Option A: Missing external I2C pull-up resistors)
I2C drivers only pull lines LOW via open-drain MOSFETs. External pull-up resistors to VCC are mandatory to pull idle lines HIGH.
Analysis of Distractors:
• Options B, C, D: Linker scripts, compiler flags, and RTOS heap allocators cannot cause unpowered/unpulled electrical lines before firmware runs.
Question 2 • Hardware Debug Interfaces
Why must firmware snapshot and clear hardware reset-cause flags immediately on boot?
Reset flags automatically encrypt external SPI flash chip contents
Reset flags stay latched across reboots hiding newer faults
Clearing reset bits doubles the CPU core clock frequency
Watchdog timers cannot start until Linker BSS zeros SRAM
✓ Correct! (Option B: Flags remain latched until cleared)
Hardware reset flags accumulate across warm resets. If you don't clear them with RMVF after reading, a future normal reset will still falsely report a stale watchdog or brownout event.
Analysis of Distractors:
• Options A, C, D: Reset flags neither encrypt flash nor alter PLL clocks.
