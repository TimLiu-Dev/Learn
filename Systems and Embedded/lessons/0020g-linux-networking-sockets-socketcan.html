Linux Networking & Bus Stacks:
Non-Blocking Sockets, SocketCAN & Packet Triage

Whether your Linux board connects to industrial PLCs over Ethernet, sensors over CAN-FD, or cloud brokers over TLS, Linux treats network sockets and CAN buses uniformly as file descriptors. Master BSD sockets, EAGAIN non-blocking I/O, SocketCAN, and live network triage with ip, ss, and tcpdump.

Mental Model Shift: OkHttp / Retrofit vs Raw Linux Sockets & SocketCAN

In Android apps, OkHttp hides DNS, TCP handshakes, partial socket reads, and reconnect loops behind clean Kotlin suspending calls.

In Linux systems C/Rust, TCP is a raw byte stream (a single recv() can return half a frame!), non-blocking sockets return -1 with errno == EAGAIN when buffers drain, and even vehicle/robotics CAN buses plug into the exact same socket(PF_CAN, SOCK_RAW, CAN_RAW) API!

1. Non-Blocking Sockets & Production Options

  • SO_REUSEADDR: Mandatory on server sockets so a crashed daemon restarted by systemd can re-bind its port immediately instead of failing with EADDRINUSE while old sockets sit in TIME_WAIT.
  • TCP Framing & Partial I/O: Never assume one send() equals one recv(). Loop until your exact header/length prefix arrives or EAGAIN tells epoll to wait for the next EPOLLIN wakeup.
  • Field Triage Tools: ip link show (check carrier/MTU/drops), ss -tulnp (listening sockets + PIDs), tcpdump -i eth0 -w cap.pcap (packet capture), and candump vcan0 (live CAN bus frames).

2. Linux SocketCAN: Networking Meets Hardware Buses

socketcan_rx.c (Opening a Linux CAN Interface as a Socket) 
int open_can_socket(const char *ifname) {
    int s = socket(PF_CAN, SOCK_RAW | SOCK_NONBLOCK, CAN_RAW);
    if (s < 0) return -1;

    struct ifreq ifr = {0};
    snprintf(ifr.ifr_name, sizeof(ifr.ifr_name), "%s", ifname);
    if (ioctl(s, SIOCGIFINDEX, &ifr) < 0) { close(s); return -1; }

    struct sockaddr_can addr = { .can_family = AF_CAN, .can_ifindex = ifr.ifr_ifindex };
    if (bind(s, (struct sockaddr *)&addr, sizeof(addr)) < 0) { close(s); return -1; }
    return s; // Ready to add straight into epoll_ctl()!
}

✅ Reference Production Solution:
int classify_recv_result(ssize_t n, int err) {
    if (n == 0) return -2;
    if (n < 0) {
        if (err == EAGAIN || err == EWOULDBLOCK) return 0;
        return -1;
    }
    return (int)n;
}

Question 1 • Socket Restart Resilience
A TCP telemetry daemon crashes and systemd restarts it in 200ms, but bind() fails with EADDRINUSE. Which option fixes this?
Setting TCP_NODELAY flag before calling accept on passive descriptors
Setting SO_REUSEADDR socket option prior to calling bind directly
Switching transport protocol from TCP sockets to raw CAN frames
Increasing kernel virtual memory page sizes inside device tree blobs
✓ Correct! (Option B: SO_REUSEADDR before bind)
SO_REUSEADDR allows a restarted server to immediately re-bind a port whose previous connections are lingering in TIME_WAIT.
Analysis of Distractors:
• Option A: TCP_NODELAY disables Nagle buffering, unrelated to TIME_WAIT port reuse.
• Options C & D: Unrelated to TCP port rebinding.
Question 2 • SocketCAN Architecture
What is the primary operational benefit of using Linux SocketCAN instead of proprietary vendor USB/UART CAN libraries?
Standard epoll loops and tcpdump tools work natively on CAN
Hardware automatically raises CAN bus bitrate above ten gigabits daily
Applications bypass Linux kernel device drivers completely during frame transmission
Physical termination resistors become completely unnecessary on twisted pair wires
✓ Correct! (Option A: Unified Linux socket/epoll/vcan ecosystem)
Because SocketCAN exposes CAN interfaces as standard network devices and sockets, you can multiplex them inside epoll, test offline with virtual vcan0, and capture traffic with candump/tcpdump.
Analysis of Distractors:
• Options B, C, D: CAN-FD remains megabit-range, SocketCAN runs inside the Linux kernel netstack, and 120 Ω bus termination is still physically required.
