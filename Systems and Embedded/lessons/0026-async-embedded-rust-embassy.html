Async Embedded Rust with Embassy:
Cooperative Tasks, Zero-Heap & Hardware Wakers

In traditional embedded systems, handling concurrent operations requires either a preemptive RTOS (which costs 1–4 KB of RAM per task stack) or complex, error-prone manual state machines. Embassy transforms microcontroller programming by bringing Rust's async/await directly to bare metal—allocating task states statically at compile time with zero dynamic heap allocation.

Mental Model Shift: Kotlin Coroutines vs Embassy Embedded Async

In Android Kotlin, when you write suspend fun fetchData() and launch it via CoroutineScope.launch(Dispatchers.IO), the runtime allocates a Continuation object on the Java heap, dispatches execution to an OS thread pool, and handles thread synchronization via the JVM.

In Embassy, there is no heap, no thread pool, and no OS. The Rust compiler analyzes your async fn and compiles it into an exact enum state machine. The Embassy executor stores all task state machines in static .bss memory. Hardware interrupts (NVIC) act directly as Waker triggers that put the CPU into low-power sleep (WFE/WFI) until the peripheral finishes!

1. The Problem with RTOS Stacks on Constrained Microcontrollers

Consider a telematics gateway microcontroller (like an STM32 with 64 KB RAM) running 8 concurrent tasks: CAN bus receiver, GPS UART parser, LTE modem handler, IMU accelerometer sampler, flash logger, power supervisor, BLE beacon, and status LED blinker.

  • FreeRTOS / Preemptive Thread Model: Every task needs its own dedicated stack space to hold local variables and interrupt frames during preemptive context switches. At 2 KB per task stack, 8 tasks consume 16 KB (25% of all microcontroller RAM), and a single unexpected recursion or deep call tree triggers stack overflow crashes.
  • Embassy Async Model: All tasks share a single system call stack! When a task yields at an .await point, its live state is saved inside its static generator struct. Only active computation uses the stack. You can run dozens of concurrent async tasks on a chip with just 16 KB of RAM.

2. Anatomy of an Embassy Application

An Embassy project requires no C runtime or dynamic allocator. Let's inspect an Embassy application that concurrently samples an ADC temperature sensor and blinks a status LED:

src/main.rsRust (no_std + Embassy)
#![no_std]
#![no_main]

use embassy_executor::Spawner;
use embassy_time::{Duration, Timer};
use embassy_stm32::gpio::{Level, Output, Speed};
use panic_halt as _;

// Statically allocated async task
#[embassy_executor::task]
async fn blink_task(mut led: Output<'static>) {
    loop {
        led.set_high();
        Timer::after(Duration::from_millis(500)).await;
        led.set_low();
        Timer::after(Duration::from_millis(500)).await;
    }
}

// Main entry point - Initializes hardware and spawns tasks
#[embassy_executor::main]
async fn main(spawner: Spawner) {
    let p = embassy_stm32::init(Default::default());

    let led = Output::new(p.PA5, Level::Low, Speed::Low);
    spawner.spawn(blink_task(led)).unwrap();

    loop {
        // Main task can perform telemetry or sleep
        Timer::after(Duration::from_secs(5)).await;
    }
}

How Hardware Wakers Work Without Spinning

When Timer::after(...).await or uart.read(&mut buf).await is executed:

  1. The task checks if data is ready. If not, it registers its Waker in a hardware interrupt callback or timer queue.
  2. The task returns Poll::Pending to the Embassy executor.
  3. The Embassy executor sees no other tasks are ready, and executes the ARM assembly instruction wfe (Wait For Event). The CPU clock stops, dropping power consumption from 30 mA to 15 µA.
  4. When the hardware DMA or timer hardware completes, the NVIC triggers the interrupt. The ISR wakes the specific task's waker, the executor wakes up, polls the task, which returns Poll::Ready(data) and continues execution.

3. Async DMA: Non-Blocking High-Throughput Bus Operations

In C bare metal, receiving 1024 bytes over SPI or UART requires either blocking the CPU in a tight loop or managing complex ring buffers with volatile interrupt flags. In Embassy, peripherals implement async DMA out of the box:

Async DMA SPI TransferRust
// Async SPI transfer with zero CPU overhead during the 1024-byte transfer:
let mut tx_buf = [0x55u8; 1024];
let mut rx_buf = [0x00u8; 1024];

// Uses STM32 DMA controller. CPU sleeps until transfer finishes!
spi.transfer(&mut rx_buf, &tx_buf).await.unwrap();
