Android Platform & Unix IPC Refresher:
AF_UNIX Sockets, System Services & AOSP IME

Your commercial fitness-console Android work exposed you to Unix domain sockets, system services, and AOSP Input Method (IME) integration. This refresher solidifies the systems mechanics underneath them so Phases 5A and 5B connect effortlessly.

Mental Model Bridge: What You Used on Fitness Consoles vs What's Underneath

In Android app code, LocalSocket wraps Linux AF_UNIX, getSystemService() wraps Binder proxies registered in servicemanager, and an AOSP IME (InputMethodService) receives key/telemetry events across process boundaries.

Understanding socket framing, daemon-to-framework boundaries, and SELinux labels turns those familiar console touchpoints into your unfair advantage in Phases 5A and 5B.

1. Unix Domain Sockets (AF_UNIX) & Message Framing

On embedded Android/Linux consoles, native C/C++ hardware daemons frequently push sensor/console telemetry to Kotlin services over AF_UNIX (bypassing TCP/IP headers and checksum overhead):

  • SOCK_STREAM vs SOCK_SEQPACKET: SOCK_STREAM is a raw byte stream—a single read() can return half a struct or two merged structs! Always prepend a fixed length header (or use SOCK_SEQPACKET to preserve message boundaries).
  • Filesystem vs Abstract Namespace: Filesystem sockets (/dev/socket/fitness_telem) live in VFS and get clean init.rc ownership + SELinux file-context labels; abstract sockets (\0name) skip filesystem paths and are discouraged by modern Android SELinux policy.

Hands-On Practice Lab

Interactive Practice: Length-Prefixed AF_UNIX Stream Parser

Because SOCK_STREAM can deliver partial packets, implement parse_unix_frame(): read a 2-byte big-endian payload length from rx[0..1], reject lengths 0 or > max_payload (return -1), return 0 if rx_len < 2 + payload_len (need more bytes), or return the total consumed bytes (int)(2U + payload_len).

unix_frame_check.c
💡 Progressive Guidance Hints:
Hint 1: Big-endian decode: size_t payload_len = ((size_t)rx[0] << 8) | (size_t)rx[1];
Hint 2: Reject bad headers with -1 before checking whether all 2U + payload_len bytes have arrived yet.
✅ Reference Production Solution:
int parse_unix_frame(const uint8_t *rx, size_t rx_len, size_t max_payload) {
    if (rx == NULL || rx_len < 2U) return 0;
    size_t payload_len = ((size_t)rx[0] << 8) | (size_t)rx[1];
    if (payload_len == 0U || payload_len > max_payload) return -1;
    if (rx_len < 2U + payload_len) return 0;
    return (int)(2U + payload_len);
}

Knowledge Check

Question 1 • Unix Domain Socket Semantics
Why does a native C daemon sending 32-byte telemetry packets over AF_UNIX SOCK_STREAM still require explicit message length framing?
Stream sockets automatically encrypt every outgoing telemetry byte
Stream sockets do not preserve individual write boundaries
Stream sockets drop messages larger than sixteen bytes
Stream sockets require TCP routers for local delivery
✓ Correct! (Option B: Byte streams coalesce or split writes)
Two 32-byte write() calls can arrive as one 64-byte read() or a 20-byte + 44-byte split. Always add a length header or switch to SOCK_SEQPACKET.
Analysis of Distractors:
• Options A, C, D: AF_UNIX does not encrypt payloads, imposes no 16-byte cap, and stays strictly inside the local kernel without TCP routing.
Question 2 • Android Platform Layering
Why do production AOSP builds favor filesystem sockets in /dev/socket/ or Binder AIDL HALs over ad-hoc abstract Unix sockets?
Abstract sockets consume four megabytes of kernel RAM
Filesystem sockets bypass all Linux user permission checks
Abstract sockets only run inside Dalvik debug builds
Filesystem sockets and AIDL support clean SELinux isolation
✓ Correct! (Option D: Clean SELinux labeling and Treble isolation)
init.rc creates /dev/socket/* with exact UID/GID and SELinux file_contexts labels, and Vendor AIDL enforces VINTF versioning between framework and vendor partitions.
Analysis of Distractors:
• Options A, B, C: Abstract sockets don't consume 4 MB, filesystem sockets enforce DAC + SELinux checks (not bypass them), and abstract sockets are standard Linux, not Dalvik-only.
