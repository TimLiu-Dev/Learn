Production embedded daemons never run as unchecked root, never leak zombie child processes, and never corrupt state when systemd sends SIGTERM. Learn signalfd inside epoll, least-privilege Linux capabilities, and deterministic udev device symlinks.

Mental Model Shift: Android App Permissions vs Linux Least-Privilege Daemons

In Android, every app runs in an isolated Linux UID sandbox with permissions granted via framework binders and SELinux.

In Non-AOSP Embedded Linux, junior engineers make everything run as root. Senior engineers run daemons under unprivileged service users, grant only surgical Linux Capabilities (e.g., CAP_NET_RAW), bind stable /dev/ symlinks with udev, and consume SIGTERM safely via signalfd.

1. Async-Signal-Safety & signalfd

Calling printf(), malloc(), or pthread_mutex_lock() inside a traditional signal()/sigaction() handler causes deadlocks if the signal interrupted code already holding that lock! Instead, block SIGINT/SIGTERM with sigprocmask() and convert signals into readable events with signalfd() inside your main epoll loop.

2. Linux Capabilities & udev Rules

Interactive Practice: Safe signalfd Shutdown Setup

Configure a sigset_t containing SIGINT and SIGTERM, block asynchronous delivery with sigprocmask(SIG_BLOCK, &mask, NULL), and create a non-blocking signalfd(-1, &mask, SFD_NONBLOCK | SFD_CLOEXEC) ready for epoll.

signalfd_setup.c
💡 Progressive Guidance Hints:
Hint 1: Call sigaddset(&mask, SIGINT); sigaddset(&mask, SIGTERM);.
Hint 2: Block via if (sigprocmask(SIG_BLOCK, &mask, NULL) < 0) return -1; then return signalfd(-1, &mask, SFD_NONBLOCK | SFD_CLOEXEC);.
✅ Reference Production Solution:
int create_shutdown_signalfd(void) {
    sigset_t mask;
    sigemptyset(&mask);
    sigaddset(&mask, SIGINT);
    sigaddset(&mask, SIGTERM);
    if (sigprocmask(SIG_BLOCK, &mask, NULL) < 0) return -1;
    return signalfd(-1, &mask, SFD_NONBLOCK | SFD_CLOEXEC);
}

Knowledge Check

Question 1 • Async-Signal-Safety
Why is calling malloc() or printf() inside a traditional POSIX signal handler dangerous?
Interrupting code holding allocator locks triggers permanent self deadlock
POSIX forbids any Linux process from allocating heap dynamically
Standard output file descriptors always destroy DMA hardware buffers
Compiler linkers strip standard C headers inside interrupt tables
✓ Correct! (Option A: Reentrant lock deadlock)
If a signal fires while the interrupted thread already holds the heap allocator or stdio lock, calling malloc()/printf() inside the handler deadlocks forever. signalfd() eliminates this completely.
Analysis of Distractors:
• Options B, C, D: The hazard is strictly non-reentrancy and lock contention on the interrupted thread.
Question 2 • Least-Privilege Devices
Why pair a udev rule with systemd CapabilityBoundingSet= instead of running an embedded daemon as root?
Capabilities bypass physical SPI clock dividers inside microcontroller silicon
Grants deterministic device access while sharply limiting exploit impact
Root user accounts cannot open Linux character device nodes
Udev scripts automatically compile Yocto recipes during board boot
✓ Correct! (Option B: Least-privilege hardware access)
udev assigns predictable symlinks and non-root group permissions (0660), while CapabilityBoundingSet= grants only the exact kernel privileges required (e.g., CAP_NET_RAW).
Analysis of Distractors:
• Options A, C, D: Unrelated to silicon clocks, root permissions, or Yocto compilation.
