Track 07: Android Automotive OS (AAOS) • Lesson 0032

Dual-OS Hypervisors in Automotive Cockpits:
QNX, Xen, ARM EL2 & VirtIO Shared Peripherals

In modern vehicles, automakers consolidate multiple screens into a single high-performance System-on-Chip (Cockpit Domain Controller). A safety-certified Type-1 Hypervisor runs QNX Neutrino (ASIL-B digital instrument cluster) and Android Automotive OS (rich infotainment) simultaneously on the same silicon. In this lesson, you will master ARM hardware virtualization, VirtIO device sharing, and zero-copy cross-domain graphics.

Mental Model Shift: One OS Per Machine vs Multi-Tenant Cockpit Virtualization

In smartphones and traditional PCs, one operating system owns all physical DRAM, display controllers, and CPU cores. If the operating system kernel panics, the entire physical hardware goes black.

In an Automotive Cockpit Hypervisor, a lightweight Type-1 hypervisor boots directly on silicon at ARM Exception Level 2 (EL2). It partitions RAM into isolated hardware memory pools. Even if Android Automotive crashes or executes a full reboot in Guest VM 2, the QNX Instrument Cluster in Guest VM 1 continues rendering speedometer gauges at 60 FPS without dropping a single frame!

2. ARMv8-A Exception Levels & Stage-2 Translation

ARM processors provide four hardware privilege levels (Exception Levels):

  • EL0 (User Space): Unprivileged applications (Android APKs, QNX user daemons).
  • EL1 (Kernel Space): Guest operating system kernels (Linux kernel, QNX microkernel).
  • EL2 (Hypervisor Mode): Type-1 hypervisor. Intercepts privileged CPU traps, manages virtual interrupts, and configures Stage-2 MMU tables.
  • EL3 (Secure Monitor): ARM TrustZone firmware (ATF) for cryptographic key storage.

Two-Stage Address Translation

When Android accesses memory at address 0x8000_0000:

  1. Stage-1 MMU (Controlled by Android Kernel): Virtual Address (VA) → Intermediate Physical Address (IPA).
  2. Stage-2 MMU (Controlled strictly by Hypervisor): Intermediate Physical Address (IPA) → Real Physical Silicon Address (PA).

Even if an Android kernel root exploit gains full control of Stage-1 tables, the hypervisor's Stage-2 translation hardware prevents Android from touching QNX memory!

3. VirtIO Shared Devices & Ring Buffers

How does Android output audio, receive touch inputs, or render 3D maps without direct ownership of the physical sound card or display controller? Through VirtIO (Virtual I/O) standardized virtual buses.

VirtIO splits devices into a Front-end driver (inside guest Linux/Android) and a Back-end device emulator (inside the host/hypervisor):
