The ARM Boot Pipeline:
Reset Handlers, Vector Tables & Linker Scripts

When power is applied to an ARM microcontroller, there is no operating system to load your code. In this lesson, we trace the exact electrical and software boot pipeline from physical power-on-reset to main(), demystifying vector tables and GNU linker scripts.

Mental Model Shift: Application.onCreate() vs Reset_Handler

In Android, app execution begins when the OS spawns an app process from Zygote and calls Application.onCreate() or Activity.onCreate().

On bare silicon, the CPU hardware reads address 0x00000000 to find where the top of the stack is, then reads address 0x00000004 to find the memory address of Reset_Handler(). Your startup code must physically copy global variables into RAM before main() can run!

1. The Hardware Reset Sequence

When the physical reset line deasserts on an ARM Cortex-M processor:

  1. The CPU fetches the 32-bit word at 0x08000000 (aliased to 0x00000000) and loads it into the Main Stack Pointer (MSP).
  2. The CPU fetches the 32-bit word at 0x08000004 and loads it into the Program Counter (PC). This word is the memory address of Reset_Handler().
  3. Execution begins immediately inside Reset_Handler().
The ARM Cortex-M Vector Table (First 16 Entries) 
__attribute__((section(".isr_vector")))
const void* g_pfnVectors[] = {
    (void*)&_estack,         // 0x00: Initial Main Stack Pointer
    Reset_Handler,           // 0x04: Reset Handler
    NMI_Handler,             // 0x08: Non-Maskable Interrupt
    HardFault_Handler,       // 0x0C: Hard Fault Trap
    MemManage_Handler,       // 0x10: Memory Management Fault
    BusFault_Handler,        // 0x14: Bus Fault Trap
    UsageFault_Handler,      // 0x18: Usage Fault (e.g. unaligned access)
    0, 0, 0, 0,              // 0x1C-0x28: Reserved
    SVC_Handler,             // 0x2C: Supervisor Call (used by RTOS)
    DebugMon_Handler,        // 0x30: Debug Monitor
    0,                       // 0x34: Reserved
    PendSV_Handler,          // 0x38: PendSV (used by RTOS context switcher)
    SysTick_Handler          // 0x3C: System Tick Timer
};

2. What Reset_Handler() Must Do Before main()

At power-on, SRAM contains random electric noise. Global variables like int status = 1; or char buffer[256]; do not exist in RAM yet! The startup code must prepare memory:

startup.c (Minimal C Runtime Initialization) 
extern uint32_t _sidata, _sdata, _edata, _sbss, _ebss;

void Reset_Handler(void) {
    // 1. Copy initialized globals (.data) from Flash to SRAM
    uint32_t* src = &_sidata;
    uint32_t* dst = &_sdata;
    while (dst < &_edata) {
        *dst++ = *src++;
    }

    // 2. Zero-out uninitialized globals (.bss) in SRAM
    dst = &_sbss;
    while (dst < &_ebss) {
        *dst++ = 0;
    }

    // 3. Call system initialization and main
    SystemInit();
    main();

    // Catch runaway return
    while (1);
}

3. The GNU Linker Script (linker.ld)

The symbols _sdata, _edata, and _sidata are defined by the Linker Script:

linker.ld (GNU Linker Script Core Layout) 
MEMORY {
    FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 512K
    RAM   (rwx) : ORIGIN = 0x20000000, LENGTH = 128K
}

SECTIONS {
    .text : {
        KEEP(*(.isr_vector))  /* Vector table at very beginning of Flash */
        *(.text*)
        *(.rodata*)
    } > FLASH

    _sidata = LOADADDR(.data); /* Physical address of .data stored in Flash */

    .data : {
        _sdata = .;           /* Start of .data in RAM */
        *(.data*)
        _edata = .;           /* End of .data in RAM */
    } > RAM AT > FLASH

    .bss : {
        _sbss = .;
        *(.bss*)
        _ebss = .;
    } > RAM
}

4. Check Your Understanding

Question 1 • Initial Reset Address
What physical value is located at address 0x00000000 in an ARM Cortex-M processor?
The initial main stack pointer address
The initial reset handler code entry
The first hardware interrupt vector callback
The base address of peripheral registers
✓ Correct! (Option A: The initial main stack pointer)
At address 0x00000000, the ARM hardware loads the initial stack pointer value (MSP) into r13. The address of Reset_Handler is located at the subsequent word: 0x00000004.
Analysis of Distractors:
• Option B: Reset handler entry is at 0x00000004.
• Option C: First interrupt vector begins at 0x00000040.
• Option D: Peripherals reside at 0x40000000.
Question 2 • Linker Script Directives
Why does the linker script place the .data section at > RAM AT > FLASH?
RAM memory retains data through resets
Flash memory allows rapid runtime writes
Initialized values persist inside flash storage
Stack pointer requires non volatile memory
✓ Correct! (Option C: Initialized values persist inside flash)
Initial global values must persist in non-volatile Flash while the device is powered off (Load Memory Address - LMA). But at runtime, variables must be read/write mutable in SRAM (Virtual Memory Address - VMA).
Analysis of Distractors:
• Option A: RAM is volatile and loses contents on reset.
• Option B: Flash writes are slow and require block erasing.
• Option D: The stack lives in RAM, not Flash.
