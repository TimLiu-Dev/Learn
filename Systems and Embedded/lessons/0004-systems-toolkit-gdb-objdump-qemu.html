The Systems Debugging Toolkit:
GDB, Binutils & Free QEMU Emulation

Senior systems engineers do not debug with print statements. When firmware freezes, hard-faults, or deadlocks without an operating system, the GNU Debugger (GDB), `objdump`, and QEMU virtual hardware emulation give you X-ray vision into the CPU's internal registers and physical memory.

Mental Model Shift: Android Studio Profiler vs Low-Level GDB

In Android Studio, Logcat streams log tags, and the visual debugger attaches via JDWP (Java Debug Wire Protocol).

In bare-metal systems, GDB communicates with physical hardware via a JTAG/SWD debug probe (or QEMU virtual machine) over a TCP socket. You inspect raw 32-bit registers (r0–r15), program counters (PC), link registers (LR), and memory dumps formatted in raw hex.

1. The Binutils Binary Inspection Arsenal

Before running code, inspect the compiled ELF binary using the GNU Binutils:

  • arm-none-eabi-size app.elf: Reports exact byte consumption in Flash (text + data) and SRAM (data + bss).
  • arm-none-eabi-objdump -d app.elf: Disassembles raw binary machine code into readable ARM assembly instructions.
  • arm-none-eabi-readelf -S app.elf: Displays section headers, memory addresses, and file offsets.
  • arm-none-eabi-nm app.elf: Prints the global symbol table (functions, variables, and their exact addresses).

2. Core GDB Commands for Systems Engineers

Essential GDB Commands Reference 
target remote :1234       # Connect to QEMU or OpenOCD JTAG probe
b Reset_Handler           # Set hardware breakpoint at function symbol
stepi                     # Step exactly ONE machine assembly instruction
info registers            # Dump contents of r0-r15, MSP, PSP, and xPSR
x/16xw 0x20000000         # Examine 16 32-bit words in hex starting at address
print/x *0x40011000       # Inspect memory-mapped UART register in hex

3. Zero-Cost Emulation: Running ARM in QEMU

You do not need to buy hardware to practice bare-metal programming! QEMU can emulate an ARM Cortex-M3 microcontroller on your computer:

QEMU Terminal Launch Command 
# Launch QEMU emulating an ARM Cortex-M board, freezing at reset (-S) and opening GDB port 1234 (-s)
qemu-system-arm -M lm3s6965evb -nographic -kernel firmware.elf -s -S

4. Check Your Understanding

Question 1 • Assembly Instruction Stepping
Which GDB command advances execution by exactly one machine instruction?
Execute stepi command inside debugger
Execute continue command inside debugger
Execute backtrace command inside debugger
Execute finish command inside debugger
✓ Correct! (Option A: Execute stepi command)
stepi (step instruction) executes exactly one CPU machine instruction, stepping across assembly boundaries rather than C source lines.
Analysis of Distractors:
• Option B: continue runs freely until the next breakpoint.
• Option C: backtrace prints the call stack.
• Option D: finish runs until the current function returns.
Question 2 • Symbol Inspection Tools
Which binutils tool disassembles executable machine instructions into human-readable assembly?
The arm none eabi size utility
The arm none eabi objdump utility
The arm none eabi strip utility
The arm none eabi ar utility
✓ Correct! (Option B: The objdump utility)
objdump -d disassembles binary machine code into readable assembly instructions, allowing you to verify what the compiler generated.
Analysis of Distractors:
• Option A: size reports memory footprints.
• Option C: strip removes debug symbols.
• Option D: ar creates static archive libraries (.a).
