Track 04: Non-AOSP Linux Systems • Lesson 0020b

Custom Embedded Linux Distributions:
Yocto Project, BitBake Recipes & Buildroot

Commercial embedded products do not ship Ubuntu or Debian on flash. Senior Embedded Linux engineers assemble reproducible, minimal, license-audited operating systems from source using The Yocto Project (BitBake + OpenEmbedded) or Buildroot.

Mental Model Shift: Android Gradle / Soong vs BitBake Layers & Recipes

In Android app builds, Gradle downloads precompiled AARs into an existing OS. Even in AOSP, Google provides the base OS tree and Soong compiles modules inside it.

In Yocto / BitBake, you build the entire cross-compiler, C library (glibc/musl), Linux kernel, Device Tree, systemd, and your C++/Rust daemons from scratch as layered recipes—producing a tiny 32 MB read-only rootfs image plus an SBOM (Software Bill of Materials) for compliance.

1. Yocto Layer Architecture & BitBake Recipes

  • BSP Layer (meta-raspberrypi, meta-freescale): Hardware kernel config, U-Boot patches, and Device Trees.
  • Distro / Middleware Layer (meta-openembedded, meta-rust): Libraries, systemd, MQTT brokers, RAUC OTA agents.
  • Product Layer (meta-mygateway): Your custom recipes (.bb) and extensions (.bbappend) cleanly separated from upstream vendor code.
meta-mygateway/recipes-app/telem-daemon/telem-daemon_1.0.bb 
SUMMARY = "Non-AOSP Telemetry Gateway Daemon"
LICENSE = "MIT"
LIC_FILES_CHKSUM = "file://LICENSE;md5=d41d8cd98f00b204e9800998ecf8427e"

SRC_URI = "git://github.com/acme/telem-daemon.git;protocol=https;branch=main \
           file://telem-daemon.service"
SRCREV = "a1b2c3d4e5f6..."

S = "${WORKDIR}/git"

inherit cmake systemd

SYSTEMD_SERVICE:${PN} = "telem-daemon.service"

do_install:append() {
    install -d ${D}${systemd_system_unitdir}
    install -m 0644 ${WORKDIR}/telem-daemon.service ${D}${systemd_system_unitdir}/
}

Knowledge Check

Question 1 • Mastery Verification
Why should you customize a silicon vendor's Linux kernel configuration using a .bbappend file in your own layer instead of editing the vendor layer directly?
BitBake refuses parsing kernel recipes unless vendor directories remain completely read only
Product customizations stay cleanly isolated allowing effortless upstream vendor BSP security upgrades
Appended files automatically compress the resulting flash rootfs image by fifty percent
Modifying vendor recipes directly disables hardware floating point instructions during cross compilation
✓ Correct! (Option B: Clean layer separation for upgrades)
Isolating board/product diffs in your own meta-product layer via .bbappend lets you pull new upstream BSP security releases without merge conflicts.
Analysis of Distractors:
• Option A, C, D: Layer separation is an engineering maintainability pattern, not a compiler or compression restriction.
Question 2 • Mastery Verification
What makes Yocto's sstate-cache critical for Embedded Linux CI/CD pipelines?
It stores user runtime telemetry databases directly inside volatile bootloader SRAM memory
It converts C kernel device drivers automatically into memory safe Rust crates
It caches task outputs by input checksum avoiding multi hour full rebuilds
It bypasses cryptographic license verification checks when building final production release images
✓ Correct! (Option C: Content-addressed build artifact reuse)
BitBake hashes recipe inputs, compiler flags, and patches. Shared sstate-cache servers let CI builds reuse unchanged packages in minutes instead of 4+ hours.
Analysis of Distractors:
• Option A, B, D: sstate-cache is strictly a build-time artifact cache.
