Track 05: AOSP Internals & AIDL HALs • Lesson 0021

AOSP Architecture & Boot Sequence:
From Kernel PID 1 to Zygote & System Server

Welcome to your Android superpower. Generic embedded engineers rarely understand Android framework plumbing, while app developers treat the OS below the SDK as a black box. In this lesson, we trace how Android boots from the Linux kernel, parses `init.rc` scripts, spawns native daemons, and launches the Java framework via Zygote.

Mental Model Shift: Android App Lifecycle vs Android OS Lifecycle

In Android app development, you interact with high-level services like Context.getSystemService(Context.SENSOR_SERVICE).

In AOSP systems engineering, you build the infrastructure that hosts those services. You write the native init.rc script that launches the sensor daemon at boot, allocates its Linux user/group IDs, and binds it to the kernel device node created in Track 04!

2. Authoring Native Services in `init.rc`

Android's init process parses .rc configuration files to start system daemons:

telem_daemon.rc (AOSP Init Service Definition) 
service vendor.telem_daemon /vendor/bin/hw/telem_daemon
    class hal
    user system
    group system
    capabilities NET_ADMIN
    shutdown critical

3. Check Your Understanding

Question 1 • Android Init Responsibilities
What is the primary role performed by /system/bin/init in Android?
Acts as root process pid one launching daemons
Renders jetpack compose application user interfaces on screen
Compresses dalvik executable bytecode inside package files
Initializes external dynamic random access memory controllers
✓ Correct! (Option A: Root process PID 1 launching daemons)
init is the first user-space program executed by the Linux kernel. It mounts partitions, sets up SELinux, and parses init.rc scripts to spawn native daemons and Zygote.
Analysis of Distractors:
• Option B: Done by UI applications.
• Option C: Done by d8/dex2oat.
• Option D: Handled by U-Boot SPL in Track 04.
Question 2 • Zygote Process Architecture
Why does Android spawn new Java/Kotlin applications by forking Zygote?
Disables processor hardware floating point register banks
Shares preloaded framework classes and accelerates process startup
Bypasses mandatory access control selinux security policy
Eliminates requirement for physical pullup bus resistors
✓ Correct! (Option B: Shares preloaded classes and accelerates startup)
Starting a JVM from scratch is slow. Zygote preloads all core Android framework classes into RAM once at boot. When an app launches, Zygote simply calls Linux fork(), providing instant startup with Copy-on-Write memory sharing!
Analysis of Distractors:
• Option A, C, D: Unrelated to FPU, SELinux bypass, or pullup resistors.
