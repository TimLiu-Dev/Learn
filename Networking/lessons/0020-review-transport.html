1 · Explain it from memory

Write your answers in full sentences before revealing the key points:

Compare TCP and UDP across four dimensions: connection state, packet overhead, ordering/reliability, and message framing boundaries.

  • Connection state: TCP requires stateful 3-way handshake and 4-way teardown; UDP is completely connectionless (0-RTT).
  • Header overhead: TCP header is 20–60 bytes; UDP header is fixed at 8 bytes.
  • Reliability & Ordering: TCP guarantees in-order, lossless byte delivery via sequence numbers, ACKs, and retransmissions. UDP is best-effort (packets can be dropped, delayed, or duplicated).
  • Framing: TCP is an unbroken byte stream (requires application framing); UDP is message-oriented (preserves datagram boundaries).

What is the difference between Flow Control and Congestion Control? What variable controls each, and what is the formula for maximum in-flight data?

  • Flow Control: Protects the receiver's application memory buffer from being overwhelmed by a fast sender. Controlled by rwnd (advertised in TCP header).
  • Congestion Control: Protects intermediate network routers from queue overflow. Controlled by cwnd (calculated by sender).
  • In-Flight Formula: Max Bytes in Flight = min(rwnd, cwnd).

Code Example: Transport Failure Triage Engine in Java & Kotlin

public class TransportTriage {
    public static String diagnose(boolean isConnecting, boolean rstReceived, boolean timeoutExpired, int timeWaitCount) {
        if (timeWaitCount > 28000) return "PORT_EXHAUSTION";
        if (isConnecting && rstReceived) return "CONNECTION_REFUSED";
        if (isConnecting && timeoutExpired) return "CONNECTION_TIMEOUT";
        if (!isConnecting && rstReceived) return "CONNECTION_RESET";
        return "HEALTHY";
    }

    public static void main(String[] args) {
        System.out.println("SYN + RST: " + diagnose(true, true, false, 10));
        System.out.println("SYN + timeout: " + diagnose(true, false, true, 10));
    }
}
object TransportTriage {
    fun diagnose(isConnecting: Boolean, rstReceived: Boolean, timeoutExpired: Boolean, timeWaitCount: Int): String = when {
        timeWaitCount > 28000 -> "PORT_EXHAUSTION"
        isConnecting && rstReceived -> "CONNECTION_REFUSED"
        isConnecting && timeoutExpired -> "CONNECTION_TIMEOUT"
        !isConnecting && rstReceived -> "CONNECTION_RESET"
        else -> "HEALTHY"
    }
}

fun main() {
    println("SYN + RST: ${TransportTriage.diagnose(true, true, false, 10)}")
    println("SYN + timeout: ${TransportTriage.diagnose(true, false, true, 10)}")
}

3 · The Senior Interview Gauntlet

  

    
System Design Question: "You are designing a multiplayer online game. Character coordinates must update 30 times a second; player inventory trade transactions occur occasionally. Which transport protocol do you use for each, and why?"

    

      
The Architect's Answer:

      
    
        
  • Character Coordinates → UDP: Position updates are ephemeral and real-time. If coordinate update #42 is lost, coordinate update #43 arrives 33 ms later with newer data. TCP retransmissions would cause Head-of-Line blocking and rubber-banding. UDP delivers the lowest possible latency.
    • 
        
  • Inventory & In-game Purchases → TCP: Trade transactions cannot lose a single byte, cannot arrive out of order, and cannot be duplicated. TCP guarantees ordered, reliable byte streams with built-in acknowledgment and retransmission.
