Where does this packet go next?

Routing tables, longest-prefix match, and traceroute

Warm-up · from earlier sessions

What does a router do to a packet's TTL field, and what happens when it reaches zero?

Every router decrements TTL by one. A router that brings it to zero discards the packet and sends an ICMP Time Exceeded message back to the source. This stops packets looping forever. (Session 5.) Today you'll exploit it.

Is 10.1.2.200 inside 10.1.2.128/25? How many addresses does a /25 contain, and what range does this one cover?

A /25 leaves 32 − 25 = 7 host bits: 2⁷ = 128 addresses. This one runs from 10.1.2.128 to 10.1.2.255, so yes, .200 is inside. Equivalently: 10.1.2.200 AND 255.255.255.128 = 10.1.2.128, the network address. (Session 6.)

Why this matters

Every packet your code sends passes through a lookup that decides where it goes next. When that lookup goes wrong, your code sees timeouts, not error messages.

"It works off the VPN but not on it", "the container can't reach the database", "only one subnet is unreachable": these are often routing-table problems, and reading the table is the fastest way to see them. Interviewers ask how a packet crosses the internet and how a router picks among overlapping routes. And when a connection is slow or dead, traceroute is how you find out where along the path things go wrong.

Forwarding and routing

Two jobs share one word in casual speech, but engineers keep them apart:Kurose & Ross §4.1.1; Systems Approach §3.4, which also separates the forwarding table from the routing table it is built from. On a host, you'll hear both names for the one table.

  • Forwarding is local and per packet: a packet arrives, the device looks up its destination address in a table and sends it out the right interface. It happens for every packet, on every router and on your Mac.
  • Routing is the network-wide process that builds those tables. Routers exchange information with routing protocols: inside one organisation, typically OSPF; between the networks that make up the internet, BGP.OSPF: Systems Approach §3.4.3; BGP: §4.1.2. Kurose & Ross ch. 5. We only name them in this course. Your Mac doesn't run either; DHCP gave it the one route it really needs (session 8).

The routing table

A routing table is a list of rules: destination prefix → next hop, out of this interface."Conceptually just a list of (NetworkNum, NextHop) pairs": Systems Approach §3.3.4. The next hop is either

  • directly connected: the destination is on this link, so deliver the packet to it directly (ARP for the destination itself, session 7); or
  • a gateway: a router's address on this link. Hand the packet to it (ARP for the router). The packet's destination IP doesn't change; only the frame's destination MAC does (session 4).

The default route, 0.0.0.0/0 (macOS prints default), has zero prefix bits, so it matches every address. It means "anything I don't know a better route for goes to the gateway".RFC 4632 §5.1: "the degenerate route to prefix 0.0.0.0/0 is used as a default route and MUST be accepted by all implementations."

Longest-prefix match

Prefixes can overlap, so one destination may match several rules. The rule: longest-prefix match. The matching entry with the most prefix bits, the most specific one, wins."Forwarding in the Internet is done on a longest-match basis": RFC 4632 §5.1. Worked example: Systems Approach §3.3.5, "IP Forwarding Revisited"; Kurose & Ross §4.2.1. Take this table:

DestinationNext hop
0.0.0.0/0192.0.2.1
198.51.100.0/24192.0.2.2
198.51.100.128/25192.0.2.3
203.0.113.0/24directly connected

A packet to 198.51.100.20 matches /0 and /24 but not the /25 (which covers .128 to .255). The /24 is longer, so it goes to 192.0.2.2. A packet to 8.8.8.8 matches only the default.

Why this rule? It lets one short entry cover a huge block while a longer entry carves out an exception. Your VPN uses exactly this: it adds routes for the company's prefixes, which beat your default route for those addresses only.

Hop by hop

Each router repeats the same lookup on its own table and hands the packet one step onward. No device knows the whole path, and the path back can differ from the path out. Each hop costs a TTL decrement, which gives us a way to see the path.

Traceroute: making each router identify itself

traceroute sends probes with TTL 1, then 2, then 3, and so on. The probe with TTL n dies at the nth router, which sends back ICMP Time Exceeded (type 11) from its own address. That reveals hop n.Algorithm and defaults: man traceroute on macOS. ICMP types 11 (Time Exceeded) and 3 code 3 (Port Unreachable): RFC 792. Kurose & Ross §1.4.3 and §5.6.

How does it know it has arrived? On macOS, probes are UDP datagrams to an unlikely port (33434 and up). The destination has nothing listening there, so it answers ICMP Port Unreachable instead, and traceroute stops. Useful defaults and options:

  • 3 probes per TTL, each waiting up to 5 seconds; up to 64 hops.
  • -n: print addresses only, skipping a slow reverse-DNS lookup for every hop.
  • -I: send ICMP Echo (ping) probes instead of UDP. Some networks treat the two differently.

What * * * means. Each * is one probe that got no reply within the wait time. That's not the same as packet loss. Many routers are configured not to send Time Exceeded, or rate-limit ICMP, while forwarding traffic perfectly well. If later hops answer, the silent hop is passing your probes on. Stars at the very end usually mean a firewall near the destination drops the probes or their replies; try -I.man traceroute: a * is printed when there is no response within the timeout, and its examples show silent gateways that "don't send ICMP 'time exceeded' messages". Routers are also allowed to rate-limit Time Exceeded: RFC 1812 §4.3.2.8.

Try it: read the table, then trace the path

netstat -rn -f inet prints the IPv4 table (-r routes, -n numeric). The format looks like this (values replaced with xx, columns squeezed):

Destination   Gateway            Flags    Netif Expire
default       xx.xx.xx.xx        UGScg      en0
127           127.0.0.1          UCS        lo0
xx.xx.xx      link#xx            UCS        en0      !
xx.xx.xx.xx   xx:xx:xx:xx:xx:xx  UHLWIir    en0   xxxx
…

How to read it: macOS drops trailing zero octets from network destinations, so 127 means 127.0.0.0/8 and 10.1.2 would mean 10.1.2.0/24; it adds /n where that shorthand doesn't work. A gateway of link#N means directly connected. A gateway that is a MAC address is a single-host entry learned by ARP. In Flags, U = up, G = via a gateway, H = a single host, not a network.The full flag list is in man netstat under "flags field". route -n get prints the matched entry's full mask if you're unsure what a shorthand means. route -n get <address> runs the lookup for you and prints the winning entry: destination, mask, gateway (if any), interface, flags.
