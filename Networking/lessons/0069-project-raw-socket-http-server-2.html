From Toy Parser to High-Throughput Server

In Session 68, we parsed raw TCP byte streams into HTTP request lines and generated compliant RFC 9112 responses. However, our server suffered from a catastrophic structural limitation: sequential execution. If a browser opened a socket and waited 30 seconds before sending bytes, or downloaded a massive file across a slow mobile link, every other client in the world was blocked in the OS accept queue.

In this second capstone session, we scale our engine to handle massive concurrency using modern runtime capabilities: Java 21+ Virtual Threads (Project Loom) or lightweight coroutines. We then implement the three remaining pillars of production HTTP servers: persistent TCP connections (Connection: keep-alive), path-traversal-safe static file delivery with MIME resolution, and dynamic streaming via Transfer-Encoding: chunked.

The Concurrency Evolution: Threads vs Virtual Threads

Network servers have evolved through three distinct concurrency architectures over the past three decades:

  • Thread-per-Connection (Classic POSIX): Each accepted socket is handed to a kernel OS thread (pthread). Because each platform thread reserves a 1 MB virtual memory stack and requires kernel context switches, memory exhausts around 2,000 to 5,000 connections (the classic C10K problem).
  • Non-blocking Event Loops (Reactor / epoll): Frameworks like Netty or Node.js use a small pool of threads running an OS event loop (epoll, kqueue). This handles 100,000+ connections with low memory, but fractures business logic into asynchronous callbacks, futures, or reactive pipelines ("callback hell").
  • Virtual Threads (Java 21+ / Coroutines): Millions of user-mode lightweight threads managed by the JVM rather than the OS kernel. When a virtual thread executes a blocking socket read or write (InputStream.read()), the JVM unmounts the virtual thread from its underlying OS carrier thread, parking its tiny call stack (often under 1 KB) in heap memory. When the socket triggers an epoll readiness event, the runtime reschedules the virtual thread onto an available carrier thread. You write simple, synchronous, blocking code that scales to hundreds of thousands of concurrent connections.

Persistent Connections (HTTP/1.1 Keep-Alive)

In HTTP/1.0, every single request required a fresh TCP handshake (SYN, SYN-ACK, ACK) and teardown (FIN-ACK dance). In HTTP/1.1 (RFC 9112 Section 9.3), connections are persistent by default. The server must keep the TCP socket open to serve multiple sequential requests from the same client until either:

  1. The client sends Connection: close in its request headers.
  2. The server decides to close the connection and sends Connection: close.
  3. A read timeout expires (e.g. socket.setSoTimeout(5000)) due to client inactivity.

To support persistent connections, the connection handler must wrap request parsing inside a while loop. Crucially, the server must strictly calculate and consume exact request and response boundaries (via Content-Length or Chunked encoding); otherwise, trailing bytes leak into the next request line, corrupting the connection.

Static File Delivery & Security Guards

A production web server serves static files (HTML, CSS, JavaScript, WebP images). This introduces two critical engineering requirements:

1. Directory Traversal Vulnerability (Path Traversal)

If a client requests GET /../../etc/passwd HTTP/1.1, a naive implementation concatenates the root directory with the URI: public_html/../../etc/passwd. The operating system resolves this path to /etc/passwd, leaking sensitive host files!

To prevent path traversal, the server must resolve the path against the document root and verify that the canonical normalized path still starts with the authorized root directory prefix:

Path docRoot = Path.of("./public").toRealPath();
Path target = docRoot.resolve(uriPath.substring(1)).normalize();
if (!target.startsWith(docRoot)) {
    // 403 Forbidden or 404 Not Found
    sendError(403, "Access Denied");
}

2. MIME Type Content Resolution

The client browser relies on the Content-Type response header to determine whether to execute a file as JavaScript, render it as HTML, or style it as CSS. The server must map file extensions to authoritative IANA media types (e.g. .html → text/html; charset=utf-8, .css → text/css, .png → image/png).

Chunked Transfer Encoding (Dynamic Streaming)

What if the response size is unknown upfront (e.g. dynamic live database streaming, real-time log tailing, or compressed data generation)? In HTTP/1.1, the server cannot emit a Content-Length header. Instead, it emits:

HTTP/1.1 200 OK\r\n
Content-Type: text/plain\r\n
Transfer-Encoding: chunked\r\n
\r\n

The body is then streamed as a sequence of chunks. Each chunk begins with its byte size formatted in hexadecimal followed by \r\n, followed by the chunk payload, followed by another \r\n. The stream terminates with a zero-length chunk (0\r\n\r\n):

7\r\n
Mozilla\r\n
9\r\n
Developer\r\n
7\r\n
Network\r\n
0\r\n
\r\n

Complete Production Server Implementation

Below is the complete, self-contained single-file Java 21+ server (HttpServerV2.java). It features Virtual Thread per-connection scheduling, persistent Keep-Alive request loops, directory traversal guards, static file streaming, and a dynamic chunked streaming endpoint (/stream):

// HttpServerV2.java (Requires Java 21+)
// Run: java HttpServerV2.java
import java.io.*;
import java.net.*;
import java.nio.charset.StandardCharsets;
import java.nio.file.*;
import java.util.*;
import java.util.concurrent.Executors;

public class HttpServerV2 {
    private static final int PORT = 8080;
    private static final Path PUBLIC_DIR = Path.of("./public");

    public static void main(String[] args) throws IOException {
        Files.createDirectories(PUBLIC_DIR);
        Files.writeString(PUBLIC_DIR.resolve("index.html"), 
            "<html><body><h1>Raw Socket Server Live!</h1><p>Delivered via Java Virtual Threads.</p></body></html>");

        // Java 21+ Virtual Thread Executor: Spawns lightweight thread per connection
        try (var executor = Executors.newVirtualThreadPerTaskExecutor();
             var serverSocket = new ServerSocket(PORT)) {
            
            serverSocket.setReuseAddress(true);
            System.out.printf("🚀 HTTP/1.1 Server running on http://127.0.0.1:%d%n", PORT);

            while (!serverSocket.isClosed()) {
                Socket clientSocket = serverSocket.accept();
                // Hand each socket to an independent virtual thread
                executor.submit(() -> handleClient(clientSocket));
            }
        }
    }

    private static void handleClient(Socket socket) {
        try (socket) {
            // Socket inactivity timeout of 5 seconds for Keep-Alive connections
            socket.setSoTimeout(5000);
            InputStream in = socket.getInputStream();
            OutputStream out = socket.getOutputStream();

            boolean keepAlive = true;

            // Persistent Connection Loop
            while (keepAlive) {
                String requestLine = readLine(in);
                if (requestLine == null || requestLine.isBlank()) {
                    break; // Connection dropped by client or timeout
                }

                String[] parts = requestLine.split(" ");
                if (parts.length < 3) break;
                String method = parts[0];
                String uri = parts[1];
                String version = parts[2];

                // Parse headers
                Map<String, String> headers = new HashMap<>();
                String headerLine;
                while ((headerLine = readLine(in)) != null && !headerLine.isEmpty()) {
                    int colon = headerLine.indexOf(':');
                    if (colon > 0) {
                        headers.put(headerLine.substring(0, colon).trim().toLowerCase(),
                                    headerLine.substring(colon + 1).trim());
                    }
                }

                // Check Keep-Alive header preferences
                String connHeader = headers.getOrDefault("connection",
                        "HTTP/1.0".equalsIgnoreCase(version) ? "close" : "keep-alive");
                if ("close".equalsIgnoreCase(connHeader)) {
                    keepAlive = false;
                }

                // Drain any declared request body so trailing bytes never desync Keep-Alive!
                if (!drainRequestBody(in, headers)) {
                    keepAlive = false;
                }

                // Route request
                if (uri.equals("/stream")) {
                    sendChunkedResponse(out, keepAlive);
                } else if ("GET".equalsIgnoreCase(method)) {
                    serveStaticFile(uri, out, keepAlive);
                } else {
                    sendError(out, 405, "Method Not Allowed", "Only GET supported", keepAlive);
                }
                out.flush();
            }
        } catch (SocketTimeoutException e) {
            // Client idle timeout reached; cleanly terminate socket
        } catch (IOException e) {
            // Socket disconnected
        }
    }

    private static boolean drainRequestBody(InputStream in, Map<String, String> headers) throws IOException {
        if (headers.containsKey("transfer-encoding")) {
            return false; // Close connection rather than risking unparsed chunked body desync
        }
        String cl = headers.get("content-length");
        if (cl == null) return true;
        long remaining;
        try {
            remaining = Long.parseLong(cl.trim());
        } catch (NumberFormatException e) {
            return false;
        }
        if (remaining < 0 || remaining > 1_048_576) return false; // Cap drained body at 1 MiB
        byte[] discard = new byte[4096];
        while (remaining > 0) {
            int n = in.read(discard, 0, (int) Math.min(discard.length, remaining));
            if (n == -1) return false;
            remaining -= n;
        }
        return true;
    }

    private static void serveStaticFile(String uri, OutputStream out, boolean keepAlive) throws IOException {
        String cleanUri = uri.equals("/") ? "/index.html" : uri;
        Path requestedPath = PUBLIC_DIR.resolve(cleanUri.substring(1)).normalize();

        // Path Traversal Security Check
        if (!requestedPath.toAbsolutePath().startsWith(PUBLIC_DIR.toAbsolutePath())) {
            sendError(out, 403, "Forbidden", "Access Denied", keepAlive);
            return;
        }

        if (!Files.exists(requestedPath) || Files.isDirectory(requestedPath)) {
            sendError(out, 404, "Not Found", "File Not Found", keepAlive);
            return;
        }

        byte[] content = Files.readAllBytes(requestedPath);
        String contentType = getMimeType(requestedPath);

        StringBuilder res = new StringBuilder();
        res.append("HTTP/1.1 200 OK\r\n");
        res.append("Content-Type: ").append(contentType).append("\r\n");
        res.append("Content-Length: ").append(content.length).append("\r\n");
        res.append("Connection: ").append(keepAlive ? "keep-alive" : "close").append("\r\n");
        res.append("\r\n");

        out.write(res.toString().getBytes(StandardCharsets.US_ASCII));
        out.write(content);
    }

    private static void sendChunkedResponse(OutputStream out, boolean keepAlive) throws IOException {
        StringBuilder headers = new StringBuilder();
        headers.append("HTTP/1.1 200 OK\r\n");
        headers.append("Content-Type: text/plain\r\n");
        headers.append("Transfer-Encoding: chunked\r\n");
        headers.append("Connection: ").append(keepAlive ? "keep-alive" : "close").append("\r\n");
        headers.append("\r\n");
        out.write(headers.toString().getBytes(StandardCharsets.US_ASCII));

        // Stream 3 distinct chunks with simulated work
        for (int i = 1; i <= 3; i++) {
            byte[] chunkData = ("Live event chunk #" + i + "\n").getBytes(StandardCharsets.UTF_8);
            // Write chunk length in hex followed by \r\n
            String hexLength = Integer.toHexString(chunkData.length) + "\r\n";
            out.write(hexLength.getBytes(StandardCharsets.US_ASCII));
            out.write(chunkData);
            out.write("\r\n".getBytes(StandardCharsets.US_ASCII));
            out.flush();
            try { Thread.sleep(200); } catch (InterruptedException ignored) {}
        }

        // Terminal 0-byte chunk
        out.write("0\r\n\r\n".getBytes(StandardCharsets.US_ASCII));
    }

    private static void sendError(OutputStream out, int code, String phrase, String msg, boolean keepAlive) throws IOException {
        byte[] body = ("<h1>" + code + " " + phrase + "</h1><p>" + msg + "</p>").getBytes(StandardCharsets.UTF_8);
        String res = "HTTP/1.1 " + code + " " + phrase + "\r\n" +
                     "Content-Type: text/html\r\n" +
                     "Content-Length: " + body.length + "\r\n" +
                     "Connection: " + (keepAlive ? "keep-alive" : "close") + "\r\n" +
                     "\r\n";
        out.write(res.getBytes(StandardCharsets.US_ASCII));
        out.write(body);
    }

    private static String getMimeType(Path path) {
        String name = path.getFileName().toString().toLowerCase();
        if (name.endsWith(".html") || name.endsWith(".htm")) return "text/html; charset=utf-8";
        if (name.endsWith(".css")) return "text/css";
        if (name.endsWith(".js")) return "application/javascript";
        if (name.endsWith(".png")) return "image/png";
        if (name.endsWith(".jpg") || name.endsWith(".jpeg")) return "image/jpeg";
        return "application/octet-stream";
    }

    private static String readLine(InputStream in) throws IOException {
        ByteArrayOutputStream buf = new ByteArrayOutputStream();
        int c;
        while ((c = in.read()) != -1) {
            if (c == '\r') {
                int next = in.read();
                if (next == '\n') break;
                if (next != -1) buf.write(next);
            } else if (c == '\n') {
                break;
            } else {
                buf.write(c);
            }
        }
        if (c == -1 && buf.size() == 0) return null;
        return buf.toString(StandardCharsets.US_ASCII);
    }
}
Production Security Trap: Keep-Alive Framing Desync & HTTP Request Smuggling

Notice drainRequestBody() inside the Keep-Alive loop! If a client sends POST /upload HTTP/1.1 with Content-Length: 60 and your server returns 405 Method Not Allowed without draining those 60 body bytes (or closing the socket), the next iteration of while (keepAlive) reads the leftover POST body as a brand-new HTTP request line! When a reverse proxy and backend server disagree on where a body ends (Content-Length vs Transfer-Encoding), attackers exploit this exact desync to smuggle unauthorized requests across shared backend sockets (HTTP Request Smuggling).

Hands-On: Benchmarking & Testing with curl

  1. Test persistent connection reuse over a single TCP socket using curl -v: 
    $ curl -v http://127.0.0.1:8080/ http://127.0.0.1:8080/index.html
    Notice the terminal output: "Re-using existing connection! (#0) with host 127.0.0.1". A single TCP handshake served both requests!
  2. Inspect the dynamic chunked response stream: 
    $ curl -i http://127.0.0.1:8080/stream
    Observe the Transfer-Encoding: chunked header and the arrival of each payload block before the connection finishes.
  3. Test directory traversal security defense: 
    $ curl -i --path-as-is http://127.0.0.1:8080/../../etc/passwd
    Verify that your server returns HTTP/1.1 403 Forbidden instead of serving the host system file.
