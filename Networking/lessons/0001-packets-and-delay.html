Packets, and why the network is never instant

Packet switching and the four kinds of delay

~25 minutesTools: ping★ interview
Your win today

You'll be able to estimate the fastest physically possible round trip to any city, then use ping to catch a server that cannot be where you assumed it is.

Why this comes first

When a networked app feels slow, the first question an experienced engineer asks is: is this a latency problem or a bandwidth problem?

The two have different causes and opposite fixes. A bigger internet plan does nothing for an API that makes forty sequential calls to a server across an ocean. Batching those calls does nothing for a 4 GB download. Every later topic, from TCP's handshake and HTTP/2's multiplexing to CDNs and connection pooling, exists partly to fight one of these two. So we start with the physics.

Data travels in packets

Your computer never sends "a file" or "a request" as one unbroken stream. It chops data into packets: chunks of bytes, each with a header in front (addresses and bookkeeping, like an envelope) and a payload (a slice of your data).Peterson & Davie call each block "a packet or a message" and use the terms interchangeably at first. Systems Approach §1.2. On a typical Ethernet or Wi-Fi network, one packet carries at most about 1,500 bytes.

Why chop data up? Because links are shared. The old telephone network used circuit switching: a call reserved a fixed slice of capacity end to end for its whole duration, even during silence. Computer traffic is bursty. A web page loads in a flash, then nothing happens for a minute. Reserving capacity for that would waste most of it. Packet switching lets everyone share every link on demand, packet by packet.Circuit vs packet switching: Kurose & Ross §1.3; Systems Approach §1.2.

The price: nobody is guaranteed capacity. If packets arrive at a router faster than its outgoing link can send them, they wait in a queue. If the queue fills up, new packets are simply dropped. That's packet loss, and the network itself does nothing to fix it. Recovering lost data is TCP's job (session 16).

Routers are store-and-forward devices: a router receives a whole packet before it starts sending it on.

The four delays

At every hop, a packet pays four kinds of delay.The four-component breakdown is from Grigorik, High Performance Browser Networking, ch. 1; Kurose & Ross §1.4 uses the same four. Learn these by name. Every performance discussion later in the course reduces to them.

DelayWhat it isDepends on
ProcessingRouter reads the header, checks for errors, decides where the packet goesRouter hardware; usually microseconds
QueuingWaiting behind other packets for the outgoing linkHow busy the link is right now. Varies wildly.
TransmissionPushing every bit of the packet onto the wirePacket size L ÷ link bandwidth R
PropagationThe signal physically travelling down the wireDistance d ÷ signal speed s

Students mix up transmission and propagation more than anything else in this lesson. Transmission is how long it takes to get the packet onto the link. It doesn't care how long the link is. Propagation is how long one bit takes to travel along the link. It doesn't care how big the packet is or how fast the link is.

Light in optical fibre travels at about 2 × 10⁸ m/s, two-thirds of its speed in a vacuum.3.0×10⁸ m/s in vacuum, 2.3×10⁸ in copper, 2.0×10⁸ in fibre: Systems Approach §1.5.1. That's about 200 km per millisecond, a number worth memorising. No engineering can beat it. Better hardware cuts the other three delays but not this one.

Play with the calculator before moving on. Try a 1,500-byte packet on a 100 Mbps link over 1 km, then over 10,000 km. Which delay dominates in each case? Then try a 10 MB file.

Latency, bandwidth, throughput

Picture a pipe:

  • Latency is the pipe's length: how long one bit takes to get from one end to the other. Usually quoted in milliseconds, and usually one-way.
  • Round-trip time (RTT) is there and back. Most real interactions (a request, then a response) cost at least one RTT. ping measures RTT.
  • Bandwidth is the pipe's width: the maximum bits per second a link can carry.
  • Throughput is the rate you actually get end to end. It can never beat the slowest link on the path, the bottleneck, and it is usually lower.Peterson & Davie note that "bandwidth" and "throughput" are often used interchangeably. In this course, bandwidth is the capacity and throughput is what you achieve.

One trap: network speeds are in bits per second (Mbps), file sizes in bytes (MB). Divide by 8. A "100 Mbps" plan downloads at most about 12.5 MB/s.

And the physics sets a hard floor on RTT: minimum RTT ≈ 2 × distance ÷ 200 km/ms. New York to Sydney is about 16,000 km, so no packet can make the round trip in under about 160 ms.HPBN, Table 1-1. Real cables don't follow the great-circle path, so real RTTs are higher still. You'll use this floor as a lie detector.

Try it: ping as a lie detector

ping sends a small packet to a host and times how long the reply takes. Open Terminal. Each reply line shows time=… ms, and the last line summarises min/avg/max/stddev. For "how far away is it?", the min is the number to use: it's the run with the least queuing.

PING 1.1.1.1 (1.1.1.1): 56 data bytes
64 bytes from 1.1.1.1: icmp_seq=0 ttl=… time=xx.x ms
…
round-trip min/avg/max/stddev = xx.x/xx.x/xx.x/x.x ms
  1. Ping your own machine, which never touches the network: ping -c 5 127.0.0.1
  2. Find your router (the default gateway): route -n get default | grep gateway. Then ping that address with -c 5.
  3. Ping a big public service: ping -c 5 1.1.1.1
  4. Ping two universities on the other side of the world from each other: ping -c 5 www.unimelb.edu.au (Melbourne) and ping -c 5 www.ox.ac.uk (Oxford).
  5. Use a great-circle distance calculator to find the distance from your city to Melbourne and to Oxford. Compute the minimum possible RTT for each with the formula above.
  6. Write all five min-RTTs next to the physical floors in a little table, in your notes or in chat.

Then answer these. Bring your answers to chat rather than looking them up:

  • Is any measurement faster than physics allows for where you assumed that server is? If so, what must be true about the machine that actually answered you?
  • Your router is a few metres away, yet its RTT isn't zero, and it's far more than loopback. Which of the four delays explain that, given that propagation over a few metres is nanoseconds?
  • Run ping -c 30 to your router while something big downloads or streams. What happens to max and stddev, and which delay is responsible?

Check yourself

Answer from memory first. Scroll up only after you've committed to an answer.

A 1,500-byte packet is sent onto a 12 Mbps link. What is its transmission delay?

  1. 8 ms
  2. 0.125 ms
  3. 1 ms
  4. 125 ms
1,500 bytes × 8 = 12,000 bits. 12,000 bits ÷ 12,000,000 bits/s = 0.001 s = 1 ms. If you got 0.125 ms, you forgot to convert bytes to bits.

Which delay does doubling a link's bandwidth directly cut in half?

  1. Transmission
  2. Propagation
  3. Processing
  4. Queuing
Transmission = L ÷ R, so doubling R halves it. Propagation depends on distance and the medium, not the link's bit rate. Queuing may shrink too, but not in any fixed proportion.

Your service in Frankfurt calls a database in Virginia, about 6,500 km away. What's the lowest RTT physics allows over fibre?

  1. 6.5 ms
  2. 22 ms
  3. 33 ms
  4. 65 ms
One way: 6,500 km ÷ 200 km/ms ≈ 32.5 ms. Round trip doubles it: ≈ 65 ms. Make 20 sequential queries per request and you've spent over a second on physics alone.

Compared with circuit switching, what does packet switching give up?

  1. efficient use of idle capacity
  2. guaranteed capacity for each conversation
  3. the ability to share links
  4. any need for packet headers
Packets share links on demand, which is efficient for bursty traffic. Nobody has reserved capacity, though, so packets can queue or be dropped.

Your ISP plan is 200 Mbps. What's the fastest download rate a file manager could ever show?

  1. 200 MB/s
  2. 1,600 MB/s
  3. 25 MB/s
  4. 50 MB/s
200 megabits ÷ 8 = 25 megabytes per second, and real throughput will be lower than that ceiling.

ping prints time=40 ms. What is that number?

  1. one-way latency to the host
  2. bandwidth between you and host
  3. transmission delay of one packet
  4. round-trip time to the host
ping times a request and its reply: there and back. One-way latency is roughly half, assuming the path is symmetric (it often isn't exactly).
