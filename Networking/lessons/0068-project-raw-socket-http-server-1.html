What exact byte sequence delimits headers in an HTTP/1.1 request message?

Each individual header line ends with \r\n (Carriage Return + Line Feed, ASCII bytes 0x0D 0x0A). The end of the entire header block is signaled by a blank line containing an extra \r\n (resulting in \r\n\r\n).

Demystifying the web server

Frameworks like Spring Boot, Express, Ktor, and Django make web development feel like magic: you annotate a method with @GetMapping("/users") and JSON responses appear.RFC 9112: HTTP/1.1 (Section 2: Message Format).

Underneath the abstractions, however, there is no magic: a web server is just a plain TCP socket listening on port 8080, reading raw ASCII bytes out of an operating system buffer, and writing back bytes conforming to RFC 9112. Today you build that engine from raw silicon up.

Single-File Implementation (Java 26)

Here is a complete, standalone HTTP/1.1 server. Save this code to HttpServer.java and run it directly with java HttpServer.java:

import java.io.*;
import java.net.*;
import java.nio.charset.StandardCharsets;
import java.util.*;

public class HttpServer {
    private static final int PORT = 8080;

    public static void main(String[] args) throws IOException {
        try (ServerSocket serverSocket = new ServerSocket(PORT)) {
            System.out.println("HTTP Server listening on http://localhost:" + PORT);

            while (true) {
                // 1. Accept incoming client TCP connection
                Socket clientSocket = serverSocket.accept();
                handleClient(clientSocket);
            }
        }
    }

    private static void handleClient(Socket socket) {
        try (socket;
             InputStream in = socket.getInputStream();
             OutputStream out = socket.getOutputStream()) {

            BufferedReader reader = new BufferedReader(new InputStreamReader(in, StandardCharsets.UTF_8));

            // 2. Parse the Request Line (e.g. "GET /hello HTTP/1.1")
            String requestLine = reader.readLine();
            if (requestLine == null || requestLine.isBlank()) return;

            String[] parts = requestLine.split(" ");
            if (parts.length < 3) return;
            String method = parts[0];
            String path = parts[1];

            // 3. Parse HTTP Headers until the blank line (\r\n)
            Map<String, String> headers = new HashMap<>();
            String headerLine;
            while ((headerLine = reader.readLine()) != null && !headerLine.isEmpty()) {
                int colonIndex = headerLine.indexOf(":");
                if (colonIndex != -1) {
                    headers.put(headerLine.substring(0, colonIndex).trim().toLowerCase(),
                                headerLine.substring(colonIndex + 1).trim());
                }
            }

            // 4. Route and dispatch response
            if (method.equals("GET") && path.equals("/")) {
                sendResponse(out, 200, "OK", "text/plain", "Welcome to Raw Sockets HTTP/1.1!\n");
            } else if (method.equals("GET") && path.equals("/json")) {
                sendResponse(out, 200, "OK", "application/json", "{\"status\":\"healthy\",\"engine\":\"raw-java\"}\n");
            } else {
                sendResponse(out, 404, "Not Found", "text/plain", "404 Not Found: " + path + "\n");
            }

        } catch (IOException e) {
            System.err.println("Client handler exception: " + e.getMessage());
        }
    }

    private static void sendResponse(OutputStream out, int code, String text, String contentType, String body) throws IOException {
        byte[] bodyBytes = body.getBytes(StandardCharsets.UTF_8);
        String responseHeaders = "HTTP/1.1 " + code + " " + text + "\r\n" +
                "Content-Type: " + contentType + "; charset=utf-8\r\n" +
                "Content-Length: " + bodyBytes.length + "\r\n" +
                "Connection: close\r\n" +
                "\r\n";

        out.write(responseHeaders.getBytes(StandardCharsets.UTF_8));
        out.write(bodyBytes);
        out.flush();
    }
}

The Critical Invariants of HTTP/1.1

  • Exact Content-Length: The Content-Length header MUST match the exact byte length of the UTF-8 payload (body.getBytes().length), not the character length of the string! If an emoji or multi-byte Unicode character is included, string length is smaller than byte length, causing the browser to hang waiting for missing bytes.
  • Case-Insensitive Headers: RFC 9110 specifies that header field names are case-insensitive. Your parser must normalize keys (e.g. converting Content-Type to content-type) so lookups never fail.

Free Recall Practice

From memory: describe the four parts of an HTTP/1.1 request message. Why is measuring Content-Length in string length dangerous?

Key points to compare against:

  • Four parts of an HTTP request: (1) Request Line (Method, URI path, HTTP version delimited by spaces and ended with `\r\n`), (2) Header block (key-value pairs ended by `\r\n`), (3) Empty line delimiter (an extra `\r\n` signaling end of headers), and (4) Optional Request Body.
  • The Content-Length danger: String length counts UTF-16 character units, whereas the HTTP protocol requires the exact number of octets (bytes) on the wire. In UTF-8, characters like emojis, accents, or symbols require 2 to 4 bytes. Specifying string length instead of byte array length truncates the payload, causing client timeouts or corrupted frames.

// Raw Socket HTTP/1.1 Request Parser in Java
import java.util.*;

public class RawHttpParser {
    public record Request(String method, String path, String version, Map<String, String> headers) {}

    public static Request parse(String raw) {
        var lines = raw.split("\r?\n");
        if (lines.length == 0) return null;
        var req = lines[0].split("\\s+");
        if (req.length < 3) return null;
        var headers = new HashMap<String, String>();
        for (int i = 1; i < lines.length; i++) {
            if (lines[i].isBlank()) break;
            int idx = lines[i].indexOf(':');
            if (idx > 0) headers.put(lines[i].substring(0, idx).trim().toLowerCase(), lines[i].substring(idx + 1).trim());
        }
        return new Request(req[0], req[1], req[2], headers);
    }
}
Kotlin 
// Raw Socket HTTP/1.1 Request Parser in Kotlin
data class HttpRequest(val method: String, val path: String, val version: String, val headers: Map<String, String>)

fun parseHttp(raw: String): HttpRequest? {
    val lines = raw.lines()
    val req = lines.firstOrNull()?.split("\\s+".toRegex()) ?: return null
    if (req.size < 3) return null
    val headers = mutableMapOf<String, String>()
    for (line in lines.drop(1)) {
        if (line.isBlank()) break
        val idx = line.indexOf(':')
        if (idx > 0) headers[line.substring(0, idx).trim().lowercase()] = line.substring(idx + 1).trim()
    }
    return HttpRequest(req[0], req[1], req[2], headers)
}
