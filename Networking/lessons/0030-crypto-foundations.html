The three pillars of network security

When bytes leave your network card, they travel across untrusted wires, public Wi-Fi routers, and commercial transit ISPs where anyone with packet capture software can listen or tamper with packets.

To secure communication, network cryptography guarantees three distinct properties:

  1. Confidentiality: Only the intended recipient can read the data (achieved via encryption).
  2. Integrity: If an attacker modifies or corrupts a single bit of the packet in transit, the receiver immediately detects it and rejects the packet (achieved via cryptographic hashes and MACs).
  3. Authentication: Confirming that the server you are talking to is genuine, rather than an imposter intercepting your traffic (achieved via digital signatures and PKI certificates).

Symmetric vs. asymmetric cryptography

The internet relies on a combination of two fundamentally different cryptographic systems:

Diffie-Hellman & Perfect Forward Secrecy (PFS)

In 1976, Whitfield Diffie and Martin Hellman solved the key distribution problem. The Diffie-Hellman Key Exchange (DH) allows two parties who have never met to exchange public values over an insecure network and compute the exact same secret symmetric key—without an eavesdropper being able to calculate it!RFC 7748: Elliptic Curve Cryptography (Curve25519).

In modern TLS 1.3, this is implemented as ECDHE (Elliptic Curve Diffie-Hellman Ephemeral):

  • The "E" stands for Ephemeral: a brand-new, disposable keypair is generated for every single connection and destroyed immediately after!
  • This provides Perfect Forward Secrecy (PFS): Even if a government or hacker records all encrypted internet traffic today and breaks into the server data center five years from now to steal its private keys, they cannot decrypt past recorded sessions because the ephemeral keys were erased from RAM years ago!

Hybrid cryptography: The universal architecture

Modern secure protocols (TLS/HTTPS, SSH, WireGuard, Signal) all use Hybrid Cryptography:

  1. Use Asymmetric Cryptography (ECDHE) for the initial handshake to negotiate a temporary shared symmetric key.
  2. Immediately switch to Symmetric Cryptography (AES-256-GCM or ChaCha20-Poly1305) to encrypt all subsequent bulk stream data at wire speed!

Try it: generating keys with OpenSSL

  1. Generate a state-of-the-art modern Ed25519 elliptic-curve private key: 
    $ openssl genpkey -algorithm ED25519 -out private.pem
  2. Extract the corresponding public key from that private key: 
    $ openssl pkey -in private.pem -pubout -out public.pem
  3. Inspect both keys in your terminal using cat public.pem and cat private.pem!

Free Recall Practice

From memory: explain why modern secure protocols use hybrid cryptography instead of asymmetric encryption alone. What is Perfect Forward Secrecy (PFS)?

Key points to compare against:

  • Hybrid Cryptography: Asymmetric encryption is computationally expensive (1,000x slower than symmetric). Hybrid cryptography uses asymmetric Diffie-Hellman key exchange only during the initial handshake to safely establish a shared secret, then switches to ultra-fast symmetric ciphers (AES-GCM) for bulk transmission.
  • Perfect Forward Secrecy (PFS): Generates ephemeral, single-use keys for every session. Compromising the server's long-term private key in the future does not compromise past recorded encrypted sessions.
