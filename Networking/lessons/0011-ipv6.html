IPv6: enough addresses that nobody has to share

Address format, address types, SLAAC and Neighbor Discovery

~30 minutesTools: ifconfig, ndp, ping6, curl, Wireshark, Java
Your win today

You'll read and compress IPv6 addresses, classify every address on your Mac (by hand and with your first Java program), and explain how IPv6 does without NAT and ARP.

Warm-up · from earlier sessions

Your Mac wants to send a packet to an address on its own subnet, but it only knows the IP address. What does it do? What changes if the destination is on another subnet?

It sends an ARP request as a link-layer broadcast (ff:ff:ff:ff:ff:ff): "who has this IP?" The owner answers with a unicast reply containing its MAC address, and your Mac caches the answer for a while. For an off-subnet destination it ARPs for the default gateway's MAC instead, because the frame only goes as far as the router. (Session 7.)

Which four settings does a host need before it can talk to the internet, and which four DHCP messages deliver them?

IP address, subnet mask, default gateway, DNS server. Discover → Offer → Request → Ack, over UDP ports 67/68. The address is a lease that must be renewed. (Session 8.) Today you'll see IPv6 get an address with no DHCP server at all.

Why this matters

Last session, NAT stretched IPv4's 4.3 billion addresses across billions more devices, and broke inbound connections and peer-to-peer along the way. IPv6 fixes the shortage itself instead of working around it.

You'll meet IPv6 as a programmer whether or not your network uses it. On macOS, localhost means both 127.0.0.1 and ::1 (look in /etc/hosts). A server listening only on 127.0.0.1 can therefore refuse a client that happened to try ::1, a classic "works for me" bug. IPv6 addresses also turn up in logs, allowlists and URLs, where they need square brackets: http://[::1]:8080/.Brackets around the address, port outside: RFC 5952 §6, following RFC 3986 §3.2.2. And understanding why your laptop may already have three or four IPv6 addresses is the quickest way to stop being puzzled by them.

Reading an IPv6 address

An IPv6 address is 128 bits, four times IPv4's 32. That's 2¹²⁸ ≈ 3.4 × 10³⁸ addresses. It's written as eight groups of 16 bits, each in hexadecimal and separated by colons:Systems Approach §4.2.2; RFC 4291 §2.2. 2001:db8::/32 is reserved for documentation (RFC 3849), so examples here aren't real hosts.

Nobody writes 32 hex digits if they can avoid it, so there are shortening rules. RFC 5952 fixes one canonical form, so the same address always prints the same way and you can search logs for it:RFC 5952 §4.1–4.3.

  1. Drop leading zeros in each group: 0db8 → db8, 0000 → 0.
  2. Replace the longest run of all-zero groups with ::. Do this only once per address, otherwise you couldn't tell how many zeros each :: hides.
  3. If two runs tie, compress the first. Never use :: for a single zero group.
  4. Write hex digits in lowercase.

So 0000:0000:0000:0000:0000:0000:0000:0001 becomes ::1, which is IPv6's loopback address.

Kinds of address

The first few bits tell you what kind of address you're looking at. A single interface normally has several IPv6 addresses at once.Prefixes: RFC 4291 §2.4; ULA RFC 4193 §3.1; global unicast in the IANA IPv6 address space registry.

PrefixTypeWhat it's for
::1/128loopbackthis host, like 127.0.0.1
fe80::/10link-localthis link only, never routed. Every IPv6 interface has one.
fc00::/7unique local (ULA)private to a site, like RFC 1918. In practice they start fd.
2000::/3global unicastroutable on the public internet. Starts with 2 or 3.
ff00::/8multicasta group. ff02::1 means "all nodes on this link".

IPv6 has no broadcast. Anything IPv4 did with broadcast, IPv6 does with multicast.RFC 4291 §2: "There are no broadcast addresses in IPv6." Every interface must have a link-local address: §2.1. Because every link uses the same fe80::/64 prefix, a link-local address only makes sense together with an interface. That's why you'll see a zone index such as fe80::1%en0.The <address>%<zone_id> format: RFC 4007 §11.

Getting an address without a server

IPv6 hosts usually configure themselves with SLAAC (stateless address autoconfiguration):RFC 4862 §4–5: "no manual configuration of hosts, minimal (if any) configuration of routers, and no additional servers." DHCPv6 (RFC 8415) also exists, and some networks use it.

  1. The host makes itself a link-local address (fe80:: + an interface ID) and checks that no neighbour already uses it (duplicate address detection).
  2. It asks the link for routers. Routers answer with a Router Advertisement listing one or more /64 prefixes.
  3. For each prefix, the host appends its own 64-bit interface ID. Nothing is leased, and no server keeps track.

Where does the interface ID come from? Originally from the MAC address, a format called modified EUI-64: put ff:fe in the middle of the 48-bit MAC and flip its U/L bit (session 4). That made your device trackable across every network it joined, so modern systems use random-looking stable IDs instead.Modified EUI-64: RFC 4291 Appendix A. RFC 8064 §3: nodes "SHOULD NOT" embed a stable link-layer address in the interface ID. They also add temporary addresses that rotate, by default about once a day, and use those for outgoing connections.RFC 8981 §3.8: default preferred lifetime 1 day, valid lifetime 2 days. In ifconfig, SLAAC addresses carry the flag autoconf, and temporary ones carry temporary.

Neighbor Discovery replaces ARP

IPv6 has no ARP. Its job moves into NDP (Neighbor Discovery Protocol), a set of ICMPv6 messages:RFC 4861 §3–4: NDP combines IPv4's ARP, ICMP Router Discovery and ICMP Redirect.

ICMPv6 typeMessageIPv4 equivalent
135 / 136Neighbor Solicitation / AdvertisementARP request / reply
133 / 134Router Solicitation / AdvertisementICMP Router Discovery (in practice, DHCP's gateway option)
137RedirectICMP Redirect

A Neighbor Solicitation isn't broadcast. It goes to a multicast group built from the last 24 bits of the target address, the solicited-node address ff02::1:ffxx:xxxx, so only hosts whose addresses end in those 24 bits listen for it: usually just the owner.Solicited-node multicast: RFC 4291 §2.7.1. On macOS, ndp -an is IPv6's arp -a.

A simpler header, and no NAT

The IPv6 header has a fixed 40 bytes. TTL is renamed hop limit and works the same way. Routers never fragment: a packet that's too big for the next link is dropped, and the router sends back an ICMPv6 "Packet Too Big" so the sender can use smaller packets. Every link must carry at least 1,280 bytes.RFC 8200 §3 (hop limit), §4.5 ("fragmentation in IPv6 is performed only by source nodes"), §5 (1,280-byte minimum MTU); Packet Too Big: RFC 4443 §3.2.

With 2⁶⁴ addresses on every LAN, each device gets its own global address and replies come straight back, with no translation table. Home routers still drop unsolicited inbound traffic, but by deliberate stateful filtering rather than as a side effect of NAT.RFC 4864 §4 shows how to get NAT's perceived benefits in IPv6 without NAT.

Most of the internet is still dual stack: hosts run IPv4 and IPv6 side by side, and a name can have both IPv4 and IPv6 addresses in DNS (session 21). Clients use Happy Eyeballs: try IPv6 first, and if it hasn't connected within about 250 ms, start IPv4 in parallel and keep whichever connects first. A broken IPv6 path then costs a quarter of a second instead of a long timeout.RFC 8305 §5: recommended Connection Attempt Delay 250 ms.

Your first networking code

Java's java.net.NetworkInterface lists the same interfaces ifconfig shows. For each address, getInterfaceAddresses() also gives the prefix length.NetworkInterface and Inet6Address (JDK 26 API docs). Save this as ListAddresses.java and run java ListAddresses.java. Single-file programs run without a separate compile step.

import java.net.*;

// Lists every network interface's addresses and says what kind each one is.
// Run with:  java ListAddresses.java
public class ListAddresses {

    public static void main(String[] args) throws SocketException {
        for (NetworkInterface nif : NetworkInterface.networkInterfaces().toList()) {
            if (nif.getInterfaceAddresses().isEmpty()) continue;
            System.out.println(nif.getName() + (nif.isUp() ? " (up)" : " (down)"));
            for (InterfaceAddress ia : nif.getInterfaceAddresses()) {
                InetAddress addr = ia.getAddress();
                String cidr = addr.getHostAddress() + "/" + ia.getNetworkPrefixLength();
                System.out.printf("  %-46s %s%n", cidr, classify(addr));
            }
        }
    }

    static String classify(InetAddress addr) {
        byte[] b = addr.getAddress();               // 4 bytes for IPv4, 16 for IPv6
        int b0 = b[0] & 0xff, b1 = b[1] & 0xff;    // bytes are signed in Java
        if (addr.isLoopbackAddress()) return "loopback";
        if (addr.isMulticastAddress()) return "multicast";
        if (addr instanceof Inet4Address) {
            if (addr.isLinkLocalAddress()) return "IPv4 link-local (169.254/16)";
            if (addr.isSiteLocalAddress()) return "IPv4 private (RFC 1918)";
            if (b0 == 100 && (b1 & 0xc0) == 64) return "IPv4 shared, CGNAT (100.64/10)";
            return "IPv4 other (usually public)";
        }
        if (addr.isLinkLocalAddress()) return "IPv6 link-local (fe80::/10)";
        if ((b0 & 0xfe) == 0xfc) return "IPv6 unique local, ULA (fc00::/7)";
        if ((b0 & 0xe0) == 0x20) return "IPv6 global unicast (2000::/3)";
        return "IPv6 other";
    }
}

Two details are worth knowing. The prefix checks are bit masks: fc00::/7 means "the first 7 bits match", so you mask the first byte with 0xfe (seven 1-bits) and compare. And Java's isSiteLocalAddress() recognises RFC 1918 for IPv4 but, for IPv6, only the long-deprecated fec0::/10, not ULAs. That's why the ULA check is written by hand.

The same program in Kotlin

In IntelliJ, put this in a .kt file in any Kotlin project and click the run arrow next to fun main.

import java.net.Inet4Address
import java.net.InetAddress
import java.net.NetworkInterface

// Lists every network interface's addresses and says what kind each one is.
fun main() {
    for (nif in NetworkInterface.networkInterfaces().toList()) {
        if (nif.interfaceAddresses.isEmpty()) continue
        println(nif.name + if (nif.isUp) " (up)" else " (down)")
        for (ia in nif.interfaceAddresses) {
            val cidr = "${ia.address.hostAddress}/${ia.networkPrefixLength}"
            println("  %-46s %s".format(cidr, classify(ia.address)))
        }
    }
}

fun classify(addr: InetAddress): String {
    val b = addr.address                          // 4 bytes for IPv4, 16 for IPv6
    val b0 = b[0].toInt() and 0xff                // bytes are signed on the JVM
    val b1 = b[1].toInt() and 0xff
    return when {
        addr.isLoopbackAddress -> "loopback"
        addr.isMulticastAddress -> "multicast"
        addr is Inet4Address -> when {
            addr.isLinkLocalAddress -> "IPv4 link-local (169.254/16)"
            addr.isSiteLocalAddress -> "IPv4 private (RFC 1918)"
            b0 == 100 && (b1 and 0xc0) == 64 -> "IPv4 shared, CGNAT (100.64/10)"
            else -> "IPv4 other (usually public)"
        }
        addr.isLinkLocalAddress -> "IPv6 link-local (fe80::/10)"
        (b0 and 0xfe) == 0xfc -> "IPv6 unique local, ULA (fc00::/7)"
        (b0 and 0xe0) == 0x20 -> "IPv6 global unicast (2000::/3)"
        else -> "IPv6 other"
    }
}

Try it: your Mac's IPv6 life

Output formats look like this (your values will differ, and you may have more or fewer lines):

$ ifconfig en0 inet6
en0: flags=…<UP,BROADCAST,SMART,RUNNING,SIMPLEX,MULTICAST> mtu 1500
	inet6 fe80::xxxx:xxxx:xxxx:xxxx%en0 prefixlen 64 … scopeid 0x…
	inet6 xxxx:xxxx:xxxx:…  prefixlen 64 autoconf …
$ ndp -an
Neighbor                        Linklayer Address  Netif Expire    St Flgs Prbs
fe80::xxxx:xxxx:xxxx:xxxx%en0   xx:xx:xx:xx:xx:xx    en0 xxs       R  R

In ndp -an, St is the entry's state (R reachable, S stale…) and an R under Flgs marks a router (see man ndp).

  1. List your Wi-Fi interface's IPv6 addresses: ifconfig en0 inet6. Classify each one with the table above, and note its flags.
  2. Show IPv6's neighbour cache: ndp -an. Compare it with arp -a -n from session 7.
  3. Start a Wireshark capture on Wi-Fi (en0) with the display filter icmpv6, and leave it running.
  4. Ping every IPv6 node on your link at once: ping6 -c 3 -I en0 ff02::1. (-I en0 picks the interface; a link-local multicast needs one.) Then stop the capture. To look for Router Advertisements specifically, try the filter icmpv6.type == 134.
  5. Try the internet over each protocol: curl -sS -m 5 https://ipv6.icanhazip.com, then curl -sS -m 5 https://ipv4.icanhazip.com. Each of these hosts has addresses of only one family. Also ask DNS directly: dig +short AAAA ipv6.icanhazip.com.
  6. Run java ListAddresses.java (the Kotlin version too, if you like) and compare its output with step 1.

Check yourself

Answer from memory first. Scroll up only after you've committed to an answer.

What is the RFC 5952 canonical form of 2001:0db8:0000:0000:0000:ff00:0042:8329?

  1. 2001:db8:0:0:0:ff00:42:8329
  2. 2001:db8::ff00:0042:8329
  3. 2001:db8:ff00:42:8329
  4. 2001:db8::ff00:42:8329
Drop leading zeros in every group (0db8 → db8, 0042 → 42), then replace the run of three zero groups with ::. Leaving zeros in place isn't canonical, and dropping the zero groups without :: changes the address.

With SLAAC, where does a host's global IPv6 address come from?

  1. A DHCP server leases the whole address
  2. The router's advertised prefix plus host-chosen ID
  3. The ISP assigns it during PPP login
  4. Derived from its IPv4 address by mapping
A Router Advertisement supplies the /64 prefix and the host fills in the 64-bit interface ID itself. No server is involved and nothing is leased (RFC 4862).

IPv6 has no ARP. How does a host learn a neighbour's MAC address?

  1. Neighbor Solicitation sent to multicast
  2. ARP request sent to broadcast
  3. DHCPv6 server lookup by address
  4. Router Advertisement listing all hosts
NDP's Neighbor Solicitation (ICMPv6 type 135) goes to the target's solicited-node multicast group, and the owner replies with a Neighbor Advertisement (136). IPv6 has no broadcast at all.

Which statement about fe80:: addresses is true?

  1. Routers forward them to other networks
  2. They exist only after DHCPv6 succeeds
  3. Every IPv6 interface must have one
  4. They require a global prefix first
Link-local addresses are self-made from fe80::/64 plus an interface ID, before any router or server is involved. They're never forwarded off the link, which is why they need a zone index like %en0.

An IPv6 router receives a packet too big for its next link. What does it do?

  1. Fragments it the way IPv4 routers can
  2. Drops it and sends Packet Too Big
  3. Sends it as several smaller link frames
  4. Lowers its hop limit and tries again
In IPv6 only the source fragments (RFC 8200 §4.5). The router drops the packet and returns ICMPv6 Packet Too Big (RFC 4443 §3.2), so the sender can lower its packet size.

A dual-stack client finds both IPv6 and IPv4 addresses for a server. What does Happy Eyeballs do?

  1. Tries IPv6 first, races IPv4 shortly after
  2. Uses IPv4 only, since it is safer
  3. Waits for IPv6 to time out first
  4. Picks whichever record arrived from DNS first
It prefers IPv6, but if that hasn't connected within about 250 ms it starts IPv4 in parallel and keeps whichever wins (RFC 8305). Broken IPv6 then costs milliseconds, not a full timeout.
