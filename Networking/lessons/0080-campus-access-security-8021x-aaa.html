Warm-up · from earlier sessions

Two minutes, from memory, before you read on:

Even with great BGP/RPKI and perimeter firewalls, an attacker walks into an office conference room, plugs a laptop into an open RJ-45 wall jack, and broadcasts fake DHCP replies + spoofed ARP packets claiming to be the default gateway. What three switch-level controls stop that cold?

1) IEEE 802.1X Port-Based NAC blocks all non-EAPOL traffic until a valid user/device certificate authenticates against RADIUS; 2) DHCP Snooping drops DHCP Server OFFER/ACK messages on untrusted access ports while recording valid IP-to-MAC leases; and 3) Dynamic ARP Inspection (DAI) drops any ARP packet violating the DHCP Snooping binding table.

1 · IEEE 802.1X Port Access Control & AAA (RADIUS vs TACACS+)

Before an endpoint receives an IP address on a secured enterprise switch port, it must pass 802.1X:

  • Three Roles: Supplicant (laptop/phone/Android EAP client) ↔ Authenticator (switch/AP blocking all traffic except EAPOL frames) ↔ Authentication Server (RADIUS server like ISE/ClearPass/FreeRADIUS validating credentials or EAP-TLS client certs and pushing back a dynamic VLAN ID).
  • RADIUS vs TACACS+: Know this interview classic cold:
    • RADIUS (UDP 1812/1813): Encrypts only the password attribute (legacy RFC 2865; RadSec wraps in TLS/TCP 2083). Combines Authentication + Authorization into one Access-Accept packet. Best for network user access (802.1X, Wi-Fi, VPN).
    • TACACS+ (TCP 49): Encrypts the entire packet body (excluding header) and separates Authentication, Authorization, and Accounting—allowing per-CLI-command authorization (e.g., operator can run show bgp but not conf t). Best for device admin login.

2 · The L2 Security Trio: DHCP Snooping + DAI + IP Source Guard

Why do these three features always deploy together in campus access closets?

  1. DHCP Snooping: Marks uplinks as trusted and user wall jacks as untrusted. Any rogue DHCP Offer/Ack arriving on an untrusted port is dropped, and valid leases populate the hardware DHCP Binding Table (MAC, IP, VLAN, Port, Lease).
  2. Dynamic ARP Inspection (DAI): Intercepts every ARP packet on untrusted ports and checks (sender MAC, sender IP) against the DHCP Snooping binding table. Spoofed gateway ARPs are immediately dropped! (Static-IP printers/servers require explicit static ARP ACL entries.)
  3. IP Source Guard: Installs per-port hardware filters dropping IP data packets whose source IP violates the DHCP binding table.

3 · Infrastructure Essentials: NTP, Stratum & Zero-Trust (ZTNA/SASE)

  • NTP (UDP 123) & NTS: Broken switch clocks silently break TLS certificate validation, Kerberos tickets, RPKI ROAs, and incident log correlation across switches! Use authenticated NTP (or Network Time Security, NTS) tied to trusted Stratum 1/2 sources.
  • ZTNA / SASE Shift: Classic corporate VPNs put remote employees straight onto an internal L3 subnet (wide lateral blast radius). Zero Trust Network Access (ZTNA) authenticates device posture + identity per-application through identity-aware proxies, never exposing raw internal RFC 1918 subnets to endpoints.

TACACS+ for device administration; RADIUS (or RadSec) for 802.1X/Wi-Fi/VPN user access.

    

    

      
You enable Dynamic ARP Inspection (DAI) on VLAN 10 without configuring static ARP ACLs, and suddenly your static-IP building badge printer stops communicating. Why?

      
    
        
  1. DAI automatically increases Ethernet MTU to 9000 bytes, fragmenting printer ARP frames.
    2. 
        
  2. DAI blocks any device lacking a signed TLS 1.3 client certificate inside its ARP header.
    3. 
        
  3. Because the static printer never went through DHCP, it has no entry in the DHCP Snooping table.
    4. 
        
  4. Printer NICs send IPv6 Neighbor Discovery frames using UDP port 67.
    5. 
      

      
Static-IP devices on DAI-protected VLANs need explicit ARP ACL exceptions (or DHCP reservations).

    

    

      
How does ZTNA differ fundamentally from traditional corporate IPsec/SSL VPNs?

      
    
        
  1. ZTNA proxies per-app access based on identity/posture instead of granting subnet-level L3 routing.
    2. 
        
  2. ZTNA runs all enterprise apps over unencrypted HTTP port 80 inside multicast VLANs.
    3. 
        
  3. ZTNA replaces BGP across internet backbone routers with local client DNS host files.
    4. 
        
  4. ZTNA mandates disabling all firewalls and opening 0.0.0.0/0 inbound on every database host.
    5. 
      

      
Legacy VPNs trust the network segment after login; ZTNA verifies identity, device health, and app policy per session.
