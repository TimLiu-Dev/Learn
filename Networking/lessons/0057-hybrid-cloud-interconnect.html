How does AS-PATH prepending influence an external network's inbound routing decision?

Repeating your own ASN multiple times in an advertisement artificially inflates the path length. Because BGP prefers shorter AS-PATHs, remote networks divert traffic away from the prepended link toward your primary link.

AWS Direct Connect Architecture: VIFs

To provision AWS Direct Connect, your on-premise router connects via optical fiber to an AWS Direct Connect router inside a co-location facility (such as Equinix or Digital Realty). You partition this physical fiber using 802.1Q VLANs into Virtual Interfaces (VIFs):

  • Private VIF: Connects directly to a specific VPC or an AWS Direct Connect Gateway to access private subnets across multiple VPCs in any global region.
  • Transit VIF: Attaches directly to an AWS Transit Gateway (TGW), allowing on-premise networks to route to thousands of VPCs through a single hub.
  • Public VIF: Connects directly to AWS public endpoints (S3, public APIs) over the dedicated line, bypassing public Internet ISPs entirely.

Dynamic Failover via BGP Routing

To eliminate manual intervention during fiber cuts or maintenance, the on-premise router establishes two separate eBGP peering sessions: one over Direct Connect and one over the IPsec VPN:

1. Controlling Outbound Traffic (On-Premise → AWS)

Your on-premise router receives AWS VPC prefixes over both links. By applying an inbound BGP route-map, you assign a higher Local Preference to Direct Connect:

  • Direct Connect routes: set local-preference 200
  • IPsec VPN routes: set local-preference 100

Because BGP evaluates Local Preference before AS-PATH, all outbound corporate traffic exits via Direct Connect.

2. Controlling Inbound Traffic (AWS → On-Premise)

AWS decides how to route return packets back to your on-premise subnets. You cannot set Local Preference inside AWS, but AWS adheres to standard BGP path selection:

  • Over Direct Connect: Advertise your on-premise prefixes (10.50.0.0/16) normally: AS-PATH: 65001.
  • Over IPsec VPN: Apply an outbound route-map with AS-PATH Prepending: AS-PATH: 65001 65001 65001.

When AWS evaluates routes, the Direct Connect advertisement wins because its AS-PATH is shorter (1 hop vs 3 hops). If Direct Connect fails, BGP withdraws the short path, and AWS seamlessly flips all traffic to the IPsec VPN in seconds!

Hands-on: Inspecting hybrid BGP neighbor status

  1. View active Direct Connect connections and optical port status: 
    $ aws directconnect describe-connections --query "connections[*].[connectionId,connectionName,connectionState,bandwidth]" --output table
    Verify that connectionState is available with 10Gbps bandwidth.
  2. Inspect the BGP neighbor state on your edge border router: 
    router# show ip bgp summary
    Look for: Neighbor: 169.254.100.1 (the AWS BGP peer), AS: 64512, and State/PfxRcd: 45 (prefixes received).
  3. Verify that the primary Direct Connect path is selected in the local routing table: 
    router# show ip route 10.100.0.0 255.255.0.0
    Notice the route metric points to the Direct Connect subinterface instead of the VPN tunnel interface!

From memory: explain how an enterprise configures BGP attributes to achieve automatic active/passive failover between Direct Connect and a backup IPsec VPN.

Key points to compare against:

  • Outbound failover (On-Prem to AWS): The on-premise router sets a higher BGP Local Preference (e.g. 200) on routes received over Direct Connect than on routes received over the backup VPN (100). Outbound traffic always chooses the higher Local Preference.
  • Inbound failover (AWS to On-Prem): When advertising on-premise subnets to AWS, the router prepends its own ASN multiple times (AS-PATH prepending) across the backup VPN advertisement. AWS evaluates rule #4 (shortest AS-PATH) and sends all inbound traffic over Direct Connect until that session fails.

Code Implementation: Java & Kotlin

Java 25 
// Hybrid Cloud BGP Path Selection in Java
public class HybridPathEngine {
    public record Path(String name, int asPathLen, boolean up) {}

    public static String pickBestPath(Path dx, Path vpn) {
        if (!dx.up() && !vpn.up()) return "UNREACHABLE";
        if (!dx.up()) return vpn.name();
        if (!vpn.up()) return dx.name();
        return dx.asPathLen() <= vpn.asPathLen() ? dx.name() : vpn.name();
    }
}
Kotlin 
// Hybrid Cloud BGP Path Selection in Kotlin
data class Path(val name: String, val asPathLen: Int, val up: Boolean)

fun pickBestPath(dx: Path, vpn: Path): String = when {
    !dx.up && !vpn.up -> "UNREACHABLE"
    !dx.up -> vpn.name
    !vpn.up -> dx.name
    dx.asPathLen <= vpn.asPathLen -> dx.name
    else -> vpn.name
}
