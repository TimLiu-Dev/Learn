What is the standard Ethernet Maximum Transmission Unit (MTU), and what happens if a packet exceeds it with the Don't Fragment (DF) bit set?

Standard Ethernet MTU is 1,500 bytes. If a packet exceeds the MTU with the DF bit set to 1, the router drops the packet and transmits an ICMP "Destination Unreachable, Fragmentation Needed" (Type 3, Code 4) message.

Connecting remote branch offices securely

In the 1990s, connecting a branch office in Chicago to corporate headquarters in New York required leasing a dedicated physical T1/T3 circuit from telecom carriers at exorbitant monthly costs.RFC 4301: Security Architecture for the Internet Protocol (IPsec). S. Kent, K. Seo (2005).

A Virtual Private Network (VPN) eliminates expensive private leased lines by building an encrypted virtual overlay tunnel across commodity broadband Internet. At Layer 3, the undisputed enterprise standard is IPsec (IP Security).

The IPsec Architecture: AH vs ESP

IPsec operates directly at the Network Layer (Layer 3), protecting all upper-layer protocols (TCP, UDP, ICMP) without modifying client applications. It defines two primary protocols:

  • AH (Authentication Header, IP Protocol 51): Provides packet integrity and origin authentication, but zero confidentiality (no encryption!). Because AH hashes the outer IP header (including IP addresses), passing AH through a standard NAT gateway modifies the header and invalidates the checksum. AH is virtually obsolete.
  • ESP (Encapsulating Security Payload, IP Protocol 50): The workhorse of IPsec. Provides robust encryption (AES-256-GCM or ChaCha20), data integrity, and anti-replay protection.

Transport Mode vs Tunnel Mode

ESP operates in two distinct encapsulation modes:

1. Transport Mode (Host-to-Host)

Encrypts only the transport payload. The original IP header remains visible on the wire. Used when two specific servers communicate directly across a secure transit network.

2. Tunnel Mode (Site-to-Site Gateways)

The standard for enterprise branch office connectivity. The VPN gateway takes the entire original IP packet (including internal source and destination IPs like 10.1.0.5 -> 10.2.0.8), encrypts it, and slaps a brand-new Outer IP Header in front addressed between the two public gateway IPs (203.0.113.1 -> 198.51.100.2). Attackers and eavesdroppers on the Internet cannot even see which internal machines are communicating!

Key Negotiation: IKEv2 Phase 1 & Phase 2

Before two gateways can encrypt data, they must agree on encryption keys using IKE (Internet Key Exchange, RFC 7296) over UDP port 500:

  • IKE Phase 1 (IKE SA): The gateways authenticate each other (via Pre-Shared Key [PSK] or digital X.509 certificates) and establish an encrypted, bi-directional control tunnel using Diffie-Hellman key exchange.
  • IKE Phase 2 (Child / IPsec SA): Inside the secure Phase 1 tunnel, gateways negotiate encryption ciphers (e.g. AES-GCM) and generate unidirectional keys for actual user data traffic.

The NAT-Traversal (NAT-T) Dilemma

Standard IPsec ESP is Layer 3 (IP protocol 50); it has no TCP or UDP port numbers! If a branch office sits behind a common residential broadband router running Port Address Translation (PAT), the NAT router has no port numbers to track and cannot translate the return ESP packets.

To fix this, gateways use NAT-Traversal (NAT-T / RFC 3948): during IKE Phase 1, gateways detect the presence of NAT devices along the path. If detected, the gateways wrap all subsequent ESP packets inside standard UDP port 4500 datagrams, allowing NAT gateways to translate them flawlessly!

Tunnel Overhead & MTU Black Holes

Tunnel mode headers (Outer IP 20B + ESP Header 8B + IV 8B + Pad + ESP Trailer 16B + ICV 16B) add approximately 56 to 70 bytes of overhead per packet.

If an internal server sends a standard 1,500-byte packet into an IPsec tunnel, the resulting encapsulated packet becomes 1500 + 60 = 1560 bytes! Because the physical internet path drops packets larger than 1,500 bytes with the DF bit set, the packet vanishes into an MTU Black Hole. Network engineers must configure TCP MSS Clamping (e.g. ip tcp adjust-mss 1360) on VPN gateways to force client TCP connections to stay below 1,360 bytes.

WireGuard: The Modern Lightweight Alternative

While IPsec contains hundreds of thousands of lines of code and complex IKEv2 negotiation state machines, WireGuard (RFC 8439) was designed from scratch in ~4,000 lines of kernel C:Jason A. Donenfeld, "WireGuard: Next Generation Kernel Network Tunnel" (NDSS 2017).

  • Opinionated modern cryptography: Curve25519 for ECDH, ChaCha20-Poly1305 for authenticated encryption, BLAKE2s for hashing.
  • Fixed UDP transport: always encapsulated in UDP; completely immune to NAT-T issues.
  • Silent operation: if an unauthenticated packet arrives, WireGuard drops it with zero response, making WireGuard endpoints invisible to port scans.
  • Cryptographic roaming: automatically updates peer endpoint IP when a client switches from Wi-Fi to cellular data without dropping the tunnel.

Hands-on: Inspecting active IPsec SAs and WireGuard

  1. View active IPsec Security Associations on an enterprise gateway: 
    router# show crypto ipsec sa
    Look for: #pkts encaps: 14209, #pkts encrypt: 14209, #pkts digest: 14209 and verify inbound esp sas and outbound esp sas (IPsec SAs are strictly unidirectional!).
  2. Check IKEv2 Phase 1 tunnel status: 
    router# show crypto ikev2 sa
    Confirm the state is READY with negotiated cipher AES-GCM-256.
  3. Inspect an active WireGuard interface on macOS/Linux: 
    $ sudo wg show
    Notice the simplicity: interface: wg0, public key: [...], endpoint: 198.51.100.1:51820, and latest handshake: 42 seconds ago.

Free Recall Practice

From memory: explain why IPsec Tunnel Mode is used for site-to-site VPNs instead of Transport Mode. Why does NAT-T use UDP port 4500?

Key points to compare against:

  • Why Tunnel Mode: Site-to-site VPNs connect private subnets across the public Internet. Tunnel Mode encrypts the entire original packet—including internal private source and destination IPs—and attaches a new public outer IP header so traffic can route across the public Internet without exposing private topology.
  • Why NAT-T uses UDP 4500: Native ESP is IP protocol 50 and lacks Layer 4 port numbers. Residential and enterprise NAT routers running PAT require TCP/UDP port numbers to multiplex multiple hosts onto a single public IP. Wrapping ESP in UDP port 4500 provides port headers that NAT routers can translate.
