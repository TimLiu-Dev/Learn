Warm-up · from earlier sessions

Two minutes, from memory, before you read on:

Why is standard 802.1Q VLAN trunking limited to 4,094 usable networks?

The VLAN Identifier (VID) field in the IEEE 802.1Q tag header is strictly 12 bits wide (212 = 4,096 total values, with 0 and 4095 reserved).

Why traditional Layer 2 died in the data center

In a 2005 enterprise data center, servers lived in a flat Layer 2 broadcast network. Redundant switch links were disabled by Spanning Tree, wasting 50% of purchased fiber bandwidth.RFC 7348: Virtual eXtensible Local Area Network (VXLAN). M. Mahalingam et al. (2014).

When Amazon Web Services, Google Cloud, and modern private clouds emerged, this architecture collapsed under three fatal limits:

  1. The 4,096 VLAN Limit: A cloud provider hosting 50,000 corporate customers—each needing multiple isolated subnets—ran out of 802.1Q VLAN IDs in week one.
  2. CAM Table Explosion: Every top-of-rack switch had to learn the MAC addresses of every single virtual machine (VM) in the entire building, blowing past switch ASIC hardware limits.
  3. STP Loop Blocking: Modern data center traffic is overwhelmingly East-West (server-to-server). Having half of all switch links blocked by Spanning Tree created intolerable congestion.

The Modern Solution: Underlay vs Overlay

To eliminate Spanning Tree and scale to millions of isolated networks, data center architects decoupled the network into two distinct layers:

  • The Underlay Network: A pure, non-blocking Layer 3 routed IP network arranged in a Leaf-Spine (Clos) topology. Every Leaf switch connects to every Spine switch. Routers speak BGP or OSPF with Equal-Cost Multi-Path (ECMP). Zero links are blocked! 100% of all fiber bandwidth is active simultaneously.
  • The Overlay Network: Virtual Layer 2 Ethernet networks encapsulated inside standard Layer 3 IP/UDP packets. To the virtual machine, it looks like a flat local LAN; to the physical switches, it is just normal routed UDP traffic!

How VXLAN Works

The dominant data center encapsulation standard is VXLAN (Virtual eXtensible Local Area Network):

  • 24-Bit VNI (VXLAN Network Identifier): Instead of a 12-bit VLAN tag, VXLAN uses a 24-bit identifier (224 = 16,777,216 unique virtual networks). Multi-tenant clouds can allocate separate VNIs for thousands of independent customers without collisions.
  • VTEPs (VXLAN Tunnel Endpoints): Devices that originate and terminate VXLAN encapsulation. VTEPs can reside in physical top-of-rack switches (hardware VTEPs) or directly inside the Linux hypervisor kernel (Open vSwitch / Cilium).

Why Outer UDP is an ECMP Masterstroke

Notice the Outer UDP header: the destination port is always 4789 (IANA assigned for VXLAN). But the Outer UDP Source Port is dynamically generated by the VTEP as a hash of the inner packet's headers (source IP, dest IP, TCP ports)!

Why does this matter? Physical spine routers do not look inside VXLAN payloads. When they see hundreds of VXLAN packets, each has a different UDP source port. Standard router ECMP hashing algorithms automatically distribute these flows evenly across dozens of parallel Spine links without packet polarization!

The Jumbo Frames Requirement

Because VXLAN adds 50 bytes of overhead, encapsulating a standard 1,500-byte VM frame produces a 1,550-byte packet. To prevent fragmentation, all physical links in modern data center underlays are configured for Jumbo Frames (MTU 9,000 or 9,216 bytes).

Hands-on: Decoding a VXLAN frame in Wireshark

  1. Capture and decode a VXLAN packet using Wireshark or tshark: 
    $ tshark -i eth0 -Y "vxlan" -T fields -e ip.src -e ip.dst -e vxlan.vni -e eth.src
    Observe the outer underlay IP addresses (10.0.0.1 -> 10.0.0.3) wrapping the virtual network identifier (e.g. VNI: 10500).
  2. Inspect the interface MTU settings on a cloud data center switch: 
    switch# show interfaces Ethernet1/1 | include MTU
    Verify that the physical interface MTU is set to 9216 bytes (Jumbo MTU) to accommodate the 50-byte overlay overhead without fragmentation.
  3. Inspect the VTEP peer status on an Arista/Cisco data center switch: 
    switch# show vxlan address-table
    Notice how virtual MAC addresses are mapped directly to remote VTEP IP addresses.

Free Recall Practice

From memory: why does VXLAN use a 24-bit VNI instead of a 12-bit VLAN ID? Why does VXLAN randomize the outer UDP source port?

Key points to compare against:

  • 24-bit VNI capacity: 12-bit VLANs restrict networks to 4,094 broadcast domains. A 24-bit VNI provides over 16 million (224) isolated virtual networks, allowing massive multi-tenant clouds to support thousands of customers.
  • Outer UDP source port hashing: The VTEP sets the outer UDP source port to a hash of the inner flow's 5-tuple. Underlay spine switches use this port entropy in their Equal-Cost Multi-Path (ECMP) hash functions to spread traffic evenly across all available spine links without inspecting the inner payload.
