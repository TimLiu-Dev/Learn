Warm-up · from earlier sessions

Two minutes, from memory, before you read on. Grounding in Part 1 makes transport layer concepts intuitive:

What kind of address does each layer use: link layer, network layer, and transport layer? What does each address identify?

Link layer: MAC address (identifies a physical network interface on the local wire).
Network layer: IP address (identifies a specific host interface across interconnected networks).
Transport layer: Port number (identifies a specific running process or socket on that host).

The multiplexing problem

Your computer has a single Wi-Fi card with one IP address. Yet right now, you might have Spotify streaming, Slack polling, three browser tabs fetching pages, and an IDE downloading dependencies.

When an incoming Ethernet frame arrives carrying an IP packet, the OS network stack strips the IP header. The payload is raw application data. Which program receives those bytes?

The network layer has no concept of programs, processes, or tabs—it only knows host IP addresses. Solving this is the primary job of the transport layer: multiplexing data from many local programs into outbound packets, and demultiplexing incoming packets to the exact process that owns them.

The 5-tuple: The universal identity of a connection

To keep every conversation distinct, the transport layer identifies every connection by five values, known across the industry as the 5-tuple:

FieldLayerExampleWho sets it
Source IPNetwork (L3)192.168.1.50Client OS (your local machine)
Destination IPNetwork (L3)93.184.216.34DNS lookup of the server
Transport ProtocolTransport (L4)TCP (6) or UDP (17)Application program
Source PortTransport (L4)54321 (Ephemeral)Client OS kernel (random)
Destination PortTransport (L4)443 (HTTPS)Target service convention

As long as at least one of these five values differs, two connections are completely independent. This is why a web server can accept 50,000 users all connecting to port 443 at the same time: each client connects from a different Source IP or a different Source Port!

Port numbers & ranges

A port number is a 16-bit unsigned integer, ranging from 0 to 65,535. The Internet Assigned Numbers Authority (IANA) divides ports into three standardized bands:IANA Port Number Registry: Service Name and Transport Protocol Port Number Registry; RFC 6335 §6.

  • Well-Known Ports (0–1023): Reserved for standard system services. On Unix/macOS, binding to these ports requires superuser (root) privileges. Examples: 80 (HTTP), 443 (HTTPS), 22 (SSH), 53 (DNS).
  • Registered Ports (1024–49151): Assigned to specific software vendors and database services upon request. Examples: 3306 (MySQL), 5432 (PostgreSQL), 6379 (Redis), 8080 (Alternative HTTP).
  • Dynamic / Ephemeral Ports (49152–65535): Used by client operating systems for temporary outgoing connections. When your browser opens a link, the OS automatically picks an unused port from this range as your Source Port, and releases it when the connection closes.macOS and Linux default to ephemeral port ranges configured in kernel sysctl (macOS: net.inet.ip.portrange.first = 49152, last = 65535).

What is a socket?

In software engineering, a socket is the operating system's software abstraction for a network connection. Think of a socket like a telephone handset or a file descriptor: your code writes bytes into the socket, and the OS handles packet fragmentation, checksums, and delivery.

  • A Listening Socket (Server): Created by a server using bind() and listen(). It sits permanently bound to a well-known port (e.g., 0.0.0.0:8080), waiting for incoming connection requests.
  • A Connected Socket (Client or Active Stream): Created when a client calls connect() or when a server accepts an incoming request with accept(). It is bound to an active 5-tuple and actively streams bidirectional bytes.

The Classic Interview Trap & Production Bug

The Interview Question: "If a server has only one network card and one IP address, what is the maximum number of simultaneous TCP connections it can handle on port 443? Is it capped at 65,535?"

The Answer: No, it is NOT capped at 65,535. 65,535 is the limit of ports on a single IP, but connections are identified by the 5-tuple. The server's port is fixed at 443, but each client has a different IP address and a different ephemeral port! A single server can easily hold millions of concurrent connections, limited only by available OS memory (RAM) and file descriptors.

Production Incident (Ephemeral Port Exhaustion): If your backend microservice makes thousands of rapid HTTP requests to an upstream payment API without using connection pooling, the client OS runs out of free ephemeral ports (49152–65535). You will suddenly see: bind: address already in use or Cannot assign requested address. Connection pools prevent this by reusing active sockets!

Try it: inspect active sockets on your Mac

macOS comes with powerful tools to inspect the kernel's network socket table in real time.

  1. List all programs currently listening for incoming connections: 
    $ lsof -iTCP -sTCP:LISTEN -P -n
    -P suppresses port name conversion (prints 443 instead of https); -n suppresses slow IP reverse-DNS lookups.
  2. Look at the columns: COMMAND, PID, USER, NODE, and NAME. Notice entries showing *:port or 127.0.0.1:port.
  3. Inspect all active established connections to remote servers: 
    $ netstat -an -p tcp | grep ESTABLISHED
  4. Look at a specific line. You will see your local IP and high ephemeral port on the left, connected to a remote IP and well-known port (e.g. .443) on the right.

Free Recall Practice

From memory: name the five components of the 5-tuple. Why does the transport layer need all five to route packets to the correct application?

Key points to compare against:

  • The 5-tuple components: Source IP, Destination IP, Transport Protocol (TCP/UDP), Source Port, Destination Port.
  • Why all five are required: IP addresses only identify machines. Ports identify processes. Because multiple clients connect to the same server port (e.g. port 443), and a single client may open multiple parallel tabs, only the full 5-tuple uniquely separates each independent stream of data.
