Warm-up · from earlier sessions

Two minutes, from memory, before you read on:

What transport protocol and port number does DNS use for standard lookup queries, and why?

DNS uses UDP port 53. Because a query and its reply fit in a single packet, UDP avoids the latency penalty of a 1-RTT TCP handshake (0-RTT resolution).

Why DNS exists

Computers route packets exclusively using IP addresses (e.g. 93.184.216.34). Humans remember hierarchical names (e.g. example.com).

In the 1970s, the entire internet used a single text file called HOSTS.TXT maintained by SRI and downloaded via FTP. As the network exploded, centralized flat files became impossible. In 1983, Paul Mockapetris invented the Domain Name System (DNS) (RFC 1034 & 1035): a distributed, hierarchical, globally cached database that scales to billions of hosts without a single bottleneck.RFC 1034 & RFC 1035: Domain Names - Concepts and Facilities (P. Mockapetris, 1987).

The naming tree

Domain names are read from right to left, representing levels in a hierarchical tree:

  • The Root Zone (.): The top of the tree. There are 13 logical root server IP addresses (named a.root-servers.net through m.root-servers.net), operated by 12 independent institutions and distributed across 1,700+ physical servers worldwide using Anycast routing.Root server distribution: root-servers.org.
  • Top-Level Domains (TLDs): Generic (.com, .net, .org) and country-code (.uk, .de, .jp). Managed by registries (e.g. Verisign operates .com).
  • Authoritative Nameservers: The nameservers designated by the domain owner (e.g. AWS Route 53, Cloudflare) that hold the actual DNS record mappings.

Recursive vs. iterative resolution

When you type a URL, two kinds of DNS lookups take place:

  1. Recursive Query (Client → Recursive Resolver): Your Mac's OS sends a recursive query to a designated resolver (such as your home router, Cloudflare's 1.1.1.1, or Google's 8.8.8.8). A recursive query asks: "Get me the final answer; do not return until you have resolved it."
  2. Iterative Queries (Resolver → Hierarchy): The recursive resolver performs the legwork on your behalf by asking iterative questions down the tree:
    • Resolver → Root Server: "Where is example.com?" → Root replies: "I don't know, but here are the nameservers for .com."
    • Resolver → TLD Server: "Where is example.com?" → TLD replies: "I don't know, but here are the authoritative nameservers for example.com."
    • Resolver → Authoritative Server: "What is the IP of example.com?" → Authoritative server replies: "The IP is 93.184.216.34, TTL 3600."
    The resolver saves the answer in its memory cache and returns the IP to your Mac.

Try it: trace the root with dig +trace

The standard Unix tool dig (Domain Information Groper) can bypass your local cache and walk the iterative tree step-by-step from the root servers.

  1. Open Terminal and execute an end-to-end trace for a domain: 
    $ dig +trace example.com
  2. Notice the four distinct blocks of output:
    • Block 1 (Root): One of the 13 root servers (e.g. k.root-servers.net) returns the NS delegation for .com.
    • Block 2 (TLD): One of Verisign's .com servers (e.g. a.gtld-servers.net) returns the authoritative nameservers for example.com (a.iana-servers.net).
    • Block 3 (Authoritative): An IANA authoritative nameserver returns the final A record: 93.184.216.34!

Free Recall Practice

From memory: describe the step-by-step difference between a recursive DNS query and an iterative DNS query.

Key points to compare against:

  • Recursive query: Sent by the client (stub resolver) to the recursive resolver (e.g. 1.1.1.1). The client asks for the complete answer, delegating all traversal work to the resolver.
  • Iterative query: Executed by the recursive resolver against the DNS hierarchy. Each server queried returns the best referral it has (Root points to TLD → TLD points to Authoritative → Authoritative returns the final record), without forwarding the query on behalf of the asker.
