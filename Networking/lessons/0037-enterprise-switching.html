What is the bit length of an Ethernet MAC address, and how does a broadcast frame indicate its destination?

An Ethernet MAC address is 48 bits (6 octets). A broadcast frame has all 48 bits set to 1, represented in hexadecimal as ff:ff:ff:ff:ff:ff.

From shared hubs to micro-segmented switches

In the 1980s, Ethernet operated over shared coax or multiport repeaters ("hubs"). Every connected machine shared a single collision domain; when two devices transmitted simultaneously, electrical voltages collided and aborted.See Kurose & Ross §6.4.3: Link-Layer Switches.

Modern enterprise switches completely eliminate collision domains through micro-segmentation: every switch port is an isolated full-duplex circuit with dedicated transmit and receive wire pairs. To route frames between these ports in nanoseconds, switches rely on dedicated hardware called ASICs (Application-Specific Integrated Circuits) and CAM (Content Addressable Memory).

How the CAM Table Works

Unlike standard computer RAM, where you provide a memory address to retrieve data, Content Addressable Memory (CAM) is inverted: you supply a 48-bit MAC address, and in a single clock cycle, the CAM returns the exact physical port connected to that device.

The Three Iron Rules of Switch Forwarding

  1. 1. Learning (Ingress Inspection): When a frame enters an interface, the switch reads the Source MAC address. It checks its CAM table:
    • If the MAC is not present, it adds the mapping (Source MAC -> Port, VLAN) and starts an aging timer (default 300 seconds / 5 minutes).
    • If the MAC already exists, it refreshes the 300s timer. If the port changed, the switch immediately updates the mapping (a device moved).
  2. 2. Filtering: If the destination MAC is already known to reside on the exact same port where the frame arrived, the switch discards the frame without wasting bandwidth on other ports.
  3. 3. Forwarding vs Flooding: The switch inspects the Destination MAC address:
    • Known Unicast: If the destination MAC exists in the CAM table, the frame is forwarded strictly and exclusively out that single destination port.
    • Unknown Unicast Flooding: If the destination MAC is not in the CAM table, the switch does not drop it! It floods a copy of the frame out every active port in the VLAN except the ingress port. When the recipient replies, its source MAC is learned, and subsequent frames become known unicast.
    • Broadcast & Multicast: Sent out every port in the broadcast domain (except the ingress port).

CAM Table Flooding & Port Security

CAM tables have a finite capacity (typically 8,000 to 128,000 entries). An attacker connected to a switch port can run a tool like macof to spray hundreds of thousands of fake, randomized MAC addresses per second.See Cisco Security: Configuring Port Security on Catalyst Switches.

When the CAM table fills to capacity, the switch enters a fail-open state: unable to record new addresses, it is forced to treat every frame as an Unknown Unicast and flood it out all ports! The switch effectively degrades into a 1980s hub, allowing the attacker to sniff everyone's traffic.

To prevent this, network engineers configure Port Security:

  • Limits the number of valid MAC addresses learned on an access port (e.g. switchport port-security maximum 2).
  • Defines violation modes: protect (silently drop extra MACs), restrict (drop and generate SNMP trap), or shutdown (put port into err-disabled state).

Hands-on: Inspecting the CAM table

  1. View the switch MAC address table: 
    switch# show mac address-table
    Notice the columns: Vlan, Mac Address, Type (DYNAMIC/STATIC), and Ports.
  2. Filter the table for a specific host's MAC address: 
    switch# show mac address-table address 0050.56a1.23b4
    Verify which physical port connects to the target machine.
  3. Inspect port security violations on an access port: 
    switch# show port-security interface GigabitEthernet0/1
    Confirm whether Port Status is Secure-up or Secure-shutdown (err-disabled).
