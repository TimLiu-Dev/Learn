Warm-up · from earlier sessions

Two minutes, from memory, before you read on:

How does a stateful firewall handle the return packet of an outbound connection?

A stateful firewall tracks the connection in an in-memory state table (`conntrack`). When return traffic arrives, it matches the existing state entry and is automatically allowed through, regardless of inbound rule configuration.

Two layers of cloud firewall defense

When a packet approaches a virtual server inside a cloud VPC, it must pass through two completely independent security gates before its bytes touch the operating system kernel.AWS VPC Documentation: Security Groups and Network ACLs.

These two layers operate on opposing architectural principles: one is stateless and evaluates subnets; the other is stateful and attaches directly to virtual network interfaces. Confusing their mechanics is the single most common cause of cloud network outages.

Security Group Referencing: Zero IP Hardcoding

In traditional on-premise firewalls, if you deploy an autoscaling cluster of 20 web servers that need to query a backend database, you must write firewall rules listing all 20 IP addresses. In the cloud, instances auto-scale, terminate, and obtain new dynamic private IPs constantly.

To eliminate fragile IP management, Security Groups support Security Group Referencing:

# On the Database Security Group (sg-db):
Type: PostgreSQL (TCP 5432)
Source: sg-0a1b2c3d4e5f (sg-app-servers)

This rule states: "Allow incoming PostgreSQL connections from any virtual machine that has sg-app-servers attached to its network interface, regardless of its IP address!" As your web fleet scales from 2 to 200 instances, the database firewall adjusts automatically in real-time with zero human intervention.

The Infamous NACL Ephemeral Port Drop Trap

Consider this real-world production outage: An engineer modifies the subnet NACL to only allow inbound port 443 (HTTPS). Immediately, instances inside that subnet can no longer run apt-get update, cannot query external APIs, and cannot download Docker images!

Why did outbound traffic break?

  1. The private instance initiates an outbound connection to GitHub: 10.0.1.50:54120 -> 140.82.113.3:443.
  2. The outbound packet passes the NACL outbound table because port 443 is permitted outbound.
  3. GitHub responds with destination port 54120 (an ephemeral port selected by the Linux kernel from range 32768–60999 or 1024–65535).
  4. The Trap: Because the NACL is 100% stateless, it does not remember that the client initiated the connection! It inspects the inbound packet against its inbound rules. Finding only Rule 100 (Allow 443), it hits the default Rule * (Deny All) and silently drops the return packet!
Production Rule: Every custom Network ACL inbound table MUST include an explicit rule allowing return traffic across Ephemeral Ports (TCP 1024–65535) from 0.0.0.0/0!

Hands-on: Auditing Security Groups and NACLs

  1. Inspect the inbound rules of an EC2 instance's Security Group: 
    $ aws ec2 describe-security-groups --group-ids sg-0123456789abcdef0
    Look for: IpPermissions specifying FromPort: 443, ToPort: 443, IpProtocol: tcp and check whether UserIdGroupPairs references another Security Group ID!
  2. Inspect the numerical rule order of a subnet Network ACL: 
    $ aws ec2 describe-network-acls --network-acl-ids acl-0123456789abcdef0
    Verify that an inbound rule exists with PortRange: {From: 1024, To: 65535}, RuleAction: allow.
  3. Test security group statefulness using curl: 
    $ curl -Iv https://www.google.com
    Notice that even if your Security Group inbound rules are 100% empty, the TLS handshake completes successfully because outbound sessions are statefully tracked!

Free Recall Practice

From memory: why does a stateful Security Group not require ephemeral port openings, whereas a stateless Network ACL does? How does Security Group referencing work?

Key points to compare against:

  • Why SGs bypass ephemeral rules: A Security Group is stateful: it records the 5-tuple of outbound requests in connection tracking memory (`conntrack`). When return packets arrive on client ephemeral ports, the hypervisor recognizes the existing flow and automatically admits the packets. Stateless NACLs evaluate every packet in isolation; without an explicit rule allowing ephemeral ports inbound, return traffic is blocked by default.
  • Security Group referencing: Instead of hardcoding static IP CIDRs, an SG rule can specify another Security Group ID as its source. Any instance assigned that referenced SG is automatically granted access, allowing elastic autoscaling without dynamic IP reconfiguration.

Code Implementation: Java & Kotlin

Java 25 
// AWS SG vs NACL Evaluation in Java
import java.util.*;

public class CloudFirewall {
    public record NaclRule(int ruleNum, int port, boolean allow) {}

    public static boolean checkInbound(int port, boolean isReturn, List<NaclRule> nacls, Set<Integer> sgAllowedPorts) {
        // Stateless NACL: lowest number wins
        var naclDecision = nacls.stream()
            .sorted(Comparator.comparingInt(NaclRule::ruleNum))
            .filter(r -> r.port() == 0 || r.port() == port)
            .findFirst()
            .map(NaclRule::allow)
            .orElse(false);

        if (!naclDecision) return false;
        // Stateful SG: established return traffic automatically permitted
        return isReturn || sgAllowedPorts.contains(port);
    }
}
Kotlin 
// AWS SG vs NACL Evaluation in Kotlin
data class NaclRule(val ruleNum: Int, val port: Int, val allow: Boolean)

fun checkInbound(port: Int, isReturn: Boolean, nacls: List<NaclRule>, sgPorts: Set<Int>): Boolean {
    val naclOk = nacls.sortedBy { it.ruleNum }
        .firstOrNull { it.port == 0 || it.port == port }
        ?.allow ?: false

    return naclOk && (isReturn || port in sgPorts)
}
