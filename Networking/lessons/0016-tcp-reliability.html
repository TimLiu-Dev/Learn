Warm-up · from earlier sessions

Two minutes, from memory, before you read on:

What sequence number and acknowledgment number does the server return in step 2 of the 3-way handshake?

The server returns seq = server_isn (its own randomly chosen Initial Sequence Number) and ack = client_isn + 1 (confirming receipt of the client's SYN).

Sequence numbers count bytes, not packets

The most common misunderstanding of TCP is assuming sequence numbers count packets (packet 1, packet 2, packet 3). They do not. TCP sequence numbers count individual bytes in the stream.

If a sender transmits a segment with Sequence Number 10,001 containing 1,000 bytes of payload:

  • The segment carries bytes 10,001 through 11,000.
  • The next segment sent by this host will have Sequence Number 11,001.
  • When the receiver gets this segment intact, it returns an Acknowledgment Number of 11,001: "I have successfully received everything up to byte 11,000; I am expecting byte 11,001 next."

TCP acknowledgments are cumulative: an ACK for byte N confirms that every single byte before N has arrived safely.

Handling packet loss: The gap problem

Suppose a sender transmits three segments of 1,000 bytes each: Segment A (bytes 1–1,000), Segment B (bytes 1,001–2,000), and Segment C (bytes 2,001–3,000). A router drops Segment B in transit:

Because ACKs are strictly cumulative, when the receiver gets Segment C, it cannot acknowledge byte 3,001—doing so would falsely imply that Segment B was received! The receiver buffers Segment C in memory and immediately repeats: ACK = 1001. This is a duplicate ACK.

Selective Acknowledgment (SACK)

In standard TCP, the sender only knows that byte 1,001 is missing. It has no way of knowing whether the receiver received Segment C, D, or E. In the old days, the sender had to retransmit everything from byte 1,001 onwards (a wasteful strategy called Go-Back-N).RFC 2018: TCP Selective Acknowledgment Options. SACK is enabled by default on all modern OS kernels.

With SACK (Selective ACK), the receiver appends an optional block in the TCP header: "I still need byte 1,001, but I have already safely stored bytes 2,001 to 3,000." Now, the sender selectively retransmits only the single missing 1,000-byte hole, saving massive amounts of bandwidth!

How loss is detected: Timers vs. Fast Retransmit

A sender detects that a packet was lost through one of two mechanisms:

  1. Retransmission Timeout (RTO): The sender starts a countdown timer whenever it sends a segment. If no ACK arrives before the timer expires, it assumes loss, retransmits the segment, and doubles the timer (exponential backoff).
    The problem: RTO is typically between 200 ms and 1,000 ms. Waiting for a timer to expire causes a noticeable stall in user-facing throughput.
  2. Fast Retransmit (3 Duplicate ACKs): If the sender receives three duplicate ACKs in a row for the same byte (e.g., four ACKs for 1001 total), it doesn't wait for the RTO timer. The sender reasons: "Packets are clearly still flowing through the network to generate duplicate ACKs; only segment 1001 went missing." It immediately retransmits the missing segment within milliseconds!

Try it: spotting retransmissions in Wireshark

Wireshark features built-in expert analysis that flags TCP sequence anomalies automatically.

  1. Open Wireshark and inspect any capture with significant traffic (or capture while downloading a large file).
  2. Type this display filter into the filter bar: 
    $ tcp.analysis.retransmission || tcp.analysis.duplicate_ack
  3. Wireshark highlights duplicate ACKs in black and retransmissions in red.
  4. Expand Transmission Control Protocol → [SEQ/ACK analysis] in the details pane to view the calculated RTT and delay since the original transmission.

Free Recall Practice

From memory: explain how cumulative ACKs differ from Selective ACKs (SACK). How does Fast Retransmit detect packet loss before a timeout occurs?

Key points to compare against:

  • Cumulative vs SACK: A cumulative ACK only reports the contiguous prefix of received bytes (next expected byte). If a gap occurs, the receiver cannot acknowledge newer out-of-order bytes. SACK adds explicit blocks in the TCP header naming disjoint received ranges, allowing the sender to retransmit only the missing holes.
  • Fast Retransmit: When the receiver gets out-of-order segments past a hole, it repeatedly sends duplicate ACKs. Upon receiving 3 duplicate ACKs, the sender infers that the network is healthy and delivering later packets, but that one specific segment was dropped, triggering an immediate retransmit without waiting for the slow RTO timer.
