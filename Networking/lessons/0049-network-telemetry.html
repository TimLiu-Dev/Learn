What constitutes a network flow, and why is capturing full raw packets impractical on a 100 Gbps core link?

A flow is a sequence of packets sharing the same 5-tuple (src/dst IP, src/dst port, protocol). Capturing raw packet payloads at 100 Gbps produces ~12.5 Gigabytes of data per second (over 1 Petabyte per day), overwhelming storage disks and CPU analysis pipelines.

You cannot fix what you cannot measure

When a critical enterprise service slows down, network engineers are universally guilty until proven innocent.RFC 5424: The Syslog Protocol (R. Gerhards, 2009).

To defend the network and isolate real outages (fiber cuts, optical degradation, route flap, DDoS attacks), engineers rely on four distinct observability technologies spanning events, counters, flow metadata, and real-time streaming telemetry.

Pillar 1: Syslog Event Logging (RFC 5424)

Network devices emit asynchronous text log events when significant state changes occur (link down, configuration change, BGP neighbor dropped). Transmitted over UDP port 514 (or TLS port 6514).

Pillar 2: SNMP & MIB/OID Architecture

The Simple Network Management Protocol (SNMP) operates on a pull-based polling architecture. A central Network Management Station (NMS) queries agents running on switches over UDP port 161:

  • OIDs (Object Identifiers): Dot-delimited integer trees standardized by the IETF. For example, .1.3.6.1.2.1.2.2.1.10.1 represents iso.org.dod.internet.mgmt.mib-2.interfaces.ifTable.ifEntry.ifInOctets.1 (total bytes received on Interface 1).
  • MIBs (Management Information Bases): Text dictionary files that translate cryptic numeric OIDs into human-readable strings.

SNMP Security: Why SNMPv1/v2c is Dangerous

SNMPv1 and SNMPv2c protect queries using plaintext passwords called Community Strings (e.g. public for read-only, private for read-write). Anyone with Wireshark on the LAN can sniff the password and issue an SNMP SET command to reboot your core router!

SNMPv3 (RFC 3411) eliminates this using the User-based Security Model (USM) offering three modes:

  • noAuthNoPriv: No authentication, no encryption (obsolete).
  • authNoPriv: Cryptographic authentication (SHA-256), but unencrypted payload.
  • authPriv: Full cryptographic authentication (HMAC-SHA-256) AND AES-256 encryption. Mandatory for production enterprise networks.

Pillar 4: Modern Push Streaming Telemetry (gNMI)

In massive hyperscale data centers, SNMP polling hits a wall: polling 10,000 switch ports every 5 minutes requires excessive CPU interrupts and only gives coarse 5-minute averages. If a microburst causes buffer packet drops for 50 milliseconds, SNMP will completely miss it!

Modern data centers deploy Model-Driven Streaming Telemetry using gNMI (gRPC Network Management Interface) over HTTP/2 and Protocol Buffers:OpenConfig Consortium: gNMI Specification (gRPC Network Management Interface).

  • Push Model: The collector establishes a single persistent gRPC connection to the switch. The switch hardware ASIC directly streams interface counters continuously at sub-second intervals (e.g. every 100 ms).
  • YANG Data Modeling: Telemetry metrics are structured using vendor-neutral OpenConfig YANG schemas, eliminating vendor-specific proprietary MIB files.

Hands-on: Inspecting network telemetry

  1. View system log messages on a macOS terminal: 
    $ log show --predicate 'eventMessage contains "link"' --last 5m
    Look for interface state transitions, MTU updates, and DHCP renewals.
  2. Query an SNMP agent using snmpwalk (if installed) or inspect local interface statistics: 
    $ netstat -in -I en0
    Notice the core counters: Ipkts (input packets), Ierrs (input CRC errors), Opkts (output packets), and Oerrs.
  3. Examine active TCP socket statistics and buffer allocations: 
    $ netstat -s -p tcp | head -n 25
    Observe retransmitted data packets, connection requests accepted, and window updates.

Free Recall Practice

From memory: what is the fundamental difference between what SNMP interface counters show versus what NetFlow records show? Why is gNMI streaming telemetry replacing SNMP?

Key points to compare against:

  • SNMP vs NetFlow: SNMP interface counters show cumulative volume metrics (total octets in/out, error counts) per physical port, but reveal nothing about which endpoints or applications generated the traffic. NetFlow aggregates packets by 5-tuple into flow records, detailing exact source/destination IPs, ports, protocols, and per-flow byte totals.
  • Why gNMI replaces SNMP: SNMP relies on pull-based polling that consumes switch CPU and provides coarse (multi-minute) averages that miss microbursts. gNMI uses a persistent gRPC push connection directly from switch ASICs to stream structured OpenConfig metrics at sub-second granularity with minimal CPU overhead.
