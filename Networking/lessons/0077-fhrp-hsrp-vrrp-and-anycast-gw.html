FHRP (HSRP, VRRP, GLBP) &amp; Distributed Anycast Gateway

Eliminating the default-gateway single point of failure with virtual IPs and MACs, aligning STP Root with FHRP Active, and scaling to spine-leaf EVPN Anycast Gateways.

Your win today

Understand how HSRP and VRRP hand off a shared virtual gateway IP and MAC seamlessly during failover, why FHRP Active must match the STP Root Bridge, and why EVPN fabrics replace HSRP/VRRP with Distributed Anycast Gateways.

Warm-up · from earlier sessions

Two minutes, from memory, before you read on:

A host configured via DHCP with default gateway 10.10.1.1 caches that gateway's MAC address in its ARP table. If Switch-A dies, why doesn't merely giving Switch-B the same IP 10.10.1.1 with a different NIC MAC recover traffic immediately?

Endpoints cache ARP entries for minutes (Linux/Windows/Android won't re-ARP just because a router died). FHRP protocols share a Virtual MAC (vMAC) alongside the Virtual IP (VIP). When Switch-B takes over, it already owns the exact same vMAC and emits a Gratuitous ARP (GARP) so access switches instantly repoint their CAM tables to Switch-B's port without waiting for host ARP timeouts.

1 · Comparing HSRP, VRRP & GLBP

ProtocolStandard / ScopeVirtual MAC FormatDefault Timers / Preemption
HSRP v2Cisco proprietary (RFC 2281 informational)0000.0c9f.fXXX (group hex)Hello 3s / Hold 10s; Preemption OFF by default
VRRP v3IETF Open Standard (RFC 9568)0000.5e00.01XX (IPv4) / 0000.5e00.02XX (IPv6)1s default (centiseconds in v3); Preemption ON by default

Key rule: Highest priority wins Active/Master election (tie-broken by highest interface IP). Always tie HSRP/VRRP to Interface/Object Tracking (e.g., decrement priority by 30 if the WAN uplink fails) so a router whose internet uplink died doesn't stay Active Gateway and black-hole LAN traffic!

2 · Critical Alignment: FHRP Active == STP Root Bridge

In a classic collapsed-core VLAN with Switch-A and Switch-B connected by an L2 trunk and dual uplinks to an access switch:

  • If Switch-A is STP Root for VLAN 10, the access switch blocks its redundant uplink toward Switch-B.
  • If Switch-B is mistakenly left as HSRP/VRRP Active for VLAN 10, packets from hosts on the access switch walk up to Switch-A, cross the inter-switch trunk over to Switch-B just to reach the L3 gateway, then get routed right back across the trunk! Aligning STP Root and FHRP Active on the exact same switch per VLAN avoids suboptimal hairpins.

3 · Modern Data Centers: Distributed Anycast Gateway

HSRP/VRRP only supports 1 Active router per subnet (2-router pair). In a 64-leaf VXLAN/EVPN fabric, you cannot send east-west traffic from Leaf-1 to Leaf-2 via a centralized HSRP pair without creating massive trombone loops. Instead, every Leaf switch simultaneously configures the exact same gateway IP + vMAC on the SVI. Any VM migrating between racks keeps routing locally via its nearest leaf—zero FHRP election chatter needed.

VRRP Election & Uplink Track Priority Model

Java 25 
// Effective priority evaluation with uplink tracking
record VrrpRouter(String name, int basePriority, int decrement, boolean uplinkUp, String ip) {
    int effectivePriority() {
        return uplinkUp ? basePriority : Math.max(1, basePriority - decrement);
    }
}
Kotlin 
// Pick VRRP Master: highest effective priority, then lexicographically/numerically highest IP
fun electMaster(routers: List<VrrpRouter>): VrrpRouter? =
    routers.maxWithOrNull(compareBy<VrrpRouter> { it.effectivePriority() }.thenBy { ipToLong(it.ip) })

Check yourself

  

    

      
In a dual-switch campus distribution layer, Switch-A is STP Root Bridge for VLAN 20 while Switch-B is HSRP Active for VLAN 20. What happens to host traffic heading off-subnet?

      
    
        
  1. Access switches drop all frames because HSRP requires STP to disable loop protection.
    2. 
        
  2. Packets flow up to STP Root (Switch-A), then cross the inter-switch trunk over to Switch-B.
    3. 
        
  3. Switch-A automatically intercepts packets and tunnels them inside GRE over to Switch-B.
    4. 
        
  4. Hosts receive ICMP Redirect messages forcing them to disable their Ethernet NIC.
    5. 
      

      
Best practice: always align STP Primary Root and HSRP/VRRP Active on the exact same distribution switch per VLAN.

    

    

      
Router-1 is VRRP Master for LAN 10.0.1.0/24, but its sole upstream BGP WAN link goes down while its LAN NIC stays up. Without interface tracking configured, what happens?

      
    
        
  1. VRRP automatically pings 8.8.8.8 every second and abdicates Master when pings drop.
    2. 
        
  2. Hosts query the Backup router dynamically via multicast DNS to discover a working WAN.
    3. 
        
  3. Router-1 keeps sending VRRP hellos on the LAN and remains Master, black-holing outbound traffic.
    4. 
        
  4. Switches convert the packet's destination IP into an L2 broadcast so Backup routes it.
    5. 
      

      
Always pair HSRP/VRRP with uplink/BFD/SLA object tracking that decrements priority below the standby router.

    

    

      
Why do EVPN-VXLAN spine-leaf fabrics abandon HSRP/VRRP in favor of Distributed Anycast Gateways?

      
    
        
  1. Every leaf acts locally as the default gateway with the same VIP/vMAC, eliminating hairpins.
    2. 
        
  2. VXLAN blocks all Ethernet broadcast and multicast frames so VRRP hellos cannot traverse leaf ports.
    3. 
        
  3. Anycast gateways replace IPv4 subnets completely with MAC-only Ethernet forwarding.
    4. 
        
  4. EVPN limits a fabric to two switches total, which violates VRRP RFC minimum cluster size.
    5. 
      

      
Distributed Anycast Gateway removes the 2-router Active/Standby constraint across large spine-leaf fabrics.
