Why does pulling terabytes of data from Amazon S3 through a Managed NAT Gateway cause financial bill shock?

AWS charges approximately $0.045 per Gigabyte of data processed through a Managed NAT Gateway. Pulling 10 Terabytes of S3 backups through a NAT Gateway adds ~$450 in redundant data processing fees!

The Cloud Public API Paradox

Amazon Web Services provides hundreds of managed services: Amazon S3 object storage, DynamoDB, SQS queues, and Secrets Manager. But all these services were originally designed to be accessed via public DNS hostnames over public IPv4 addresses.AWS VPC Documentation: What is AWS PrivateLink?

This created an absurd paradox: if an isolated database instance in a private subnet needed to write an encrypted backup to Amazon S3, that traffic had to leave the VPC, cross an expensive NAT Gateway, and traverse the public Internet! This raised compliance red flags and generated massive NAT bills. VPC Endpoints and AWS PrivateLink solve this completely.

How Interface Endpoints Work (AWS PrivateLink)

An Interface Endpoint provisions an Elastic Network Interface (ENI) with a private IP address directly inside your subnet (e.g. 10.0.1.75):

  • Private DNS Integration: When you enable Private DNS, Route 53 intercepts queries for public service domains (like sqs.us-east-1.amazonaws.com) and returns the private IP of your endpoint ENI (10.0.1.75)! Your application code does not need to change a single configuration string.
  • SaaS Consumption: Major cloud software providers (Datadog, Snowflake, MongoDB Atlas) publish their services as Endpoint Services. You can consume their data platforms directly into your private VPC without allowing Internet egress.

The Overlapping CIDR Miracle

In Session 52, we learned that VPC Peering and Transit Gateways completely fail if two networks have overlapping IP addresses (e.g. both VPCs use 10.0.0.0/16).See AWS Architecture: Connecting Overlapping Networks Using AWS PrivateLink.

PrivateLink is immune to overlapping CIDRs! Because PrivateLink operates as a unidirectional TCP proxy at Layer 4, the consumer VPC only sees a single private IP address (the ENI) inside its own subnet. The underlying IP scheme of the service provider VPC is completely hidden, allowing seamless B2B SaaS connectivity regardless of IP address collisions.

VPC Endpoint Policies: Preventing Data Exfiltration

A rogue employee or malicious script on an EC2 instance might attempt to exfiltrate proprietary customer data by uploading it to a personal, attacker-controlled Amazon S3 bucket. Standard firewall rules cannot prevent this because the destination is a legitimate S3 IP address on port 443!

VPC Endpoint Policies solve this by attaching an IAM policy directly to the endpoint gate:

{
  "Statement": [{
    "Effect": "Allow",
    "Principal": "*",
    "Action": "s3:*",
    "Resource": [
      "arn:aws:s3:::my-company-corporate-data/*",
      "arn:aws:s3:::my-company-corporate-data"
    ]
  }]
}

Even if an attacker gains root access to an EC2 instance, any attempt to upload data to a personal S3 bucket (e.g. arn:aws:s3:::hacker-bucket) is intercepted and rejected at the VPC boundary!

Hands-on: Querying private endpoint DNS

  1. Query the DNS resolution of Amazon S3 inside a private VPC with Private DNS enabled: 
    $ dig +short s3.us-east-1.amazonaws.com
    Observe that instead of public 52.216.x.x addresses, it resolves to private IPs (e.g. 10.0.1.75)!
  2. List active VPC endpoints using the AWS CLI: 
    $ aws ec2 describe-vpc-endpoints --query "VpcEndpoints[*].[VpcEndpointId,ServiceName,VpcEndpointType,State]" --output table
    Look for: VpcEndpointType: Interface vs Gateway.
  3. Verify that traffic to an interface endpoint bypasses the NAT Gateway: 
    $ curl -Iv https://sqs.us-east-1.amazonaws.com
    Verify that the remote IP connection address is internal private RFC 1918 space!

Free Recall Practice

From memory: explain the difference between Gateway Endpoints and Interface Endpoints (PrivateLink). How does PrivateLink solve the overlapping CIDR problem?

Key points to compare against:

  • Gateway vs Interface Endpoints: Gateway Endpoints are free route-table entries supporting only S3 and DynamoDB; they cannot be accessed from on-premise networks. Interface Endpoints (PrivateLink) deploy actual private IP Elastic Network Interfaces (ENIs) inside your subnet, support 100+ AWS and third-party SaaS services, and are accessible from on-premise via Direct Connect.
  • Solving overlapping CIDRs: PrivateLink does not route network-to-network like VPC Peering. It functions as a point-to-point Layer 4 proxy: the consumer only initiates a connection to the local private IP of the interface endpoint ENI, completely decoupling consumer and provider IP address schemes.

Code Implementation: Java & Kotlin

Java 25 
// AWS PrivateLink Split-Horizon DNS Resolver in Java
public class PrivateLinkResolver {
    public static String resolve(String query, String serviceFqdn, boolean privDns, String eniIp, String pubIp) {
        if (!query.equalsIgnoreCase(serviceFqdn)) return "NXDOMAIN";
        return privDns ? eniIp : pubIp;
    }

    public static void main(String[] args) {
        String s3 = "s3.us-east-1.amazonaws.com";
        System.out.println("Priv: " + resolve(s3, s3, true, "10.0.1.5", "52.216.1.1")); // 10.0.1.5
    }
}

    } else "NXDOMAIN"

}
