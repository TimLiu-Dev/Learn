How does HTTP/2 multiplex multiple requests across a single TCP socket?

HTTP/2 uses a binary framing layer where every frame carries a 31-bit Stream ID. Frames from different requests are interleaved on the wire and reassembled at the receiver, preventing slow requests from blocking subsequent ones.

The hidden tax of JSON REST APIs

For external browser-to-backend communication, JSON over HTTP/1.1 is universal because it is human-readable. But inside modern data centers, where thousands of microservices make millions of inter-service calls per second, JSON becomes an enormous CPU and bandwidth bottleneck.gRPC Documentation: What is gRPC?. Originally developed by Google as Stubby.

The three fatal performance penalties of JSON REST:

  1. String Parsing Overhead: JSON is text. Parsing strings, converting ASCII numbers to 64-bit floating-point integers, and unescaping quotes burns substantial CPU cycles on every single call.
  2. Repeated Field Name Bloat: If you return a list of 10,000 user objects, the field name "user_identification_number" is repeated 10,000 times as raw ASCII characters on the wire!
  3. Lack of Strict Schema Contracts: JSON has no built-in schema enforcement. If a backend team renames a field, downstream microservices crash silently at runtime.

Protocol Buffers: Binary serialization

Protocol Buffers (Protobuf) is Google's open-source binary serialization format.Protocol Buffers v3 Language Guide. You define your data structure in a strict .proto contract:

syntax = "proto3";

message UserProfile {
    int32 id = 1;
    string username = 2;
    string email = 3;
    bool is_active = 4;
}

Notice the numbers (= 1, = 2). These are not values—they are field tags. On the wire, Protobuf never sends the field names! It transmits only the 1-byte tag number and the raw binary bytes. A 500-byte JSON payload frequently compresses to 40 bytes in Protobuf, and parses up to 10x faster in native CPU memory.

What is gRPC?

gRPC is an open-source Remote Procedure Call framework built directly on top of HTTP/2 and Protocol Buffers. It allows a client in Kotlin to invoke a function on a server in Go as if it were a local function call:

The 4 gRPC streaming models

  1. Unary RPC: Classic request → response (like standard HTTP). Client sends 1 request, server returns 1 response.
  2. Server Streaming RPC: Client sends 1 request (e.g. SubscribeStockTicker); server returns a continuous stream of response messages over the HTTP/2 stream.
  3. Client Streaming RPC: Client streams a continuous series of messages (e.g. IoT sensor logs); server reads them and returns a single summary response.
  4. Bidirectional Streaming RPC: Both client and server stream messages independently and concurrently across the same HTTP/2 stream (used in collaborative editing and real-time voice translation).

Free Recall Practice

From memory: why is gRPC significantly faster than JSON REST APIs? Name the four gRPC streaming models.

Key points to compare against:

  • Why gRPC is faster: (1) Protobuf serializes data into compact binary using numeric field tags rather than verbose JSON strings; (2) Binary parsing requires far less CPU than string parsing; (3) gRPC runs on HTTP/2, leveraging native stream multiplexing and HPACK compression over a single persistent connection.
  • Four Streaming Models: Unary (1 to 1), Server Streaming (1 to many), Client Streaming (many to 1), and Bidirectional Streaming (many to many).
