Two minutes, from memory, before you read on:

How can one Linux container host run 20 containers that each bind 0.0.0.0:8080 and hold completely separate routing tables without stepping on each other?

Each container runs inside its own Linux Network Namespace (netns). A network namespace isolates loopback, network interfaces (eth0), IP addresses, routing tables, Netfilter/nftables firewall rules, and port-binding tables—while sharing the underlying Linux kernel.

1 · Why iproute2 Replaced net-tools

ifconfig, route, and netstat use legacy Linux ioctl calls that break on modern features (multiple IPs per NIC via primary/secondary prefixes, policy routing tables, VXLAN, VRFs, eBPF hooks). Modern Linux networking runs over Netlink sockets via iproute2:

2 · Building Topology Primitives: netns, veth, Bridges & VRFs

Before touching a physical switch or cloud VPC, realize that every container network and virtual lab is built from three Linux kernel objects:

  1. Network Namespace (ip netns add ns1): An independent virtual network stack (interfaces, routes, sockets, sysctls).
  2. Virtual Ethernet Pair (veth): A virtual patch cable with two ends. Any frame injected into veth-a immediately pops out of veth-b. Place veth-a inside ns1 and attach veth-b to the host bridge!
  3. Linux Bridge & VRF: A bridge acts as an L2 switch (forwarding by MAC table), whereas a VRF (Virtual Routing and Forwarding) device groups L3 interfaces into isolated routing tables inside the same namespace—vital for multi-tenant edge routers and management vs data-plane separation.

3 · Netfilter Packet Flow & nftables

nftables compiles rules into an in-kernel bytecode VM (replacing separate iptables, ip6tables, arptables, and ebtables). Traffic crosses hooks based on packet direction:

  • Traffic destined TO the local host: ingress → prerouting → Routing Decision → input → Local Socket.
  • Traffic ROUTED THROUGH the host: ingress → prerouting → Routing Decision → forward → postrouting.
  • Traffic FROM the local host: Local Socket → Routing Decision → output → postrouting.

Critical NetEng sysctls: A Linux host drops forwarded transit packets until sysctl -w net.ipv4.ip_forward=1 (and net.ipv6.conf.all.forwarding=1) is enabled!

Hands-On Lab (macOS via Docker Alpine Linux Container)

  1. Launch an ephemeral privileged Linux shell with iproute2 inside Docker/OrbStack: docker run --rm -it --privileged alpine sh -c 'apk add -q iproute2 tcpdump nftables && sh'.
  2. Create two namespaces connected by a veth pair inside that container:
    ip netns add h1 && ip netns add h2
    ip link add veth1 type veth peer name veth2
    ip link set veth1 netns h1 && ip link set veth2 netns h2
  3. Assign 10.99.0.1/24 to h1 and 10.99.0.2/24 to h2, bring up links + loopback, and ping across your virtual cable:
    ip -n h1 addr add 10.99.0.1/24 dev veth1 && ip -n h1 link set veth1 up
    ip -n h2 addr add 10.99.0.2/24 dev veth2 && ip -n h2 link set veth2 up
    ip netns exec h1 ping -c 2 10.99.0.2.
  4. Run ip -n h1 route get 10.99.0.2 and ip netns exec h1 ss -tulpan to watch kernel route lookup and socket state.
