What is the difference between 1-to-1 Static NAT and Port Address Translation (PAT)?

1-to-1 Static NAT maps one private IP to one dedicated public IP, allowing both inbound and outbound traffic. PAT (Port Address Translation) maps multiple private IPs to a single public IP by tracking unique Layer 4 port numbers, permitting outbound traffic while blocking unsolicited inbound connections.

How packets leave a cloud VPC

A virtual machine sitting inside a private cloud subnet has no direct physical link to the outside world. It cannot emit photons onto public fiber cables.AWS VPC Documentation: Internet Gateways and NAT Gateways.

To reach the public Internet, a packet must traverse cloud SDN route tables and specialized gateway endpoints. Understanding the difference between an Internet Gateway (IGW) and a Managed NAT Gateway is the hallmark of professional cloud network engineering.

The Internet Gateway (IGW): Zero-Cost Horizontal Scale

An Internet Gateway (IGW) is not a physical server or bottleneck appliance; it is a globally distributed, software-defined software construct built directly into the cloud hypervisor fabric:

  • Provides 1-to-1 Static NAT: When an EC2 instance with a Public IP transmits a packet, the IGW translates the internal private IP (10.0.1.50) to its allocated public Elastic IP (54.210.10.4), decrements TTL, and routes it directly onto the AWS edge network.
  • It has infinite bandwidth: It scales automatically with your instance network interfaces, never requires maintenance, has no throughput bottleneck, and carries zero hourly gateway fees!
  • The Catch: Traffic flows bi-directionally. If an instance has a public IP and sits in a subnet pointing to an IGW, anyone on the public Internet can attempt to connect to it (relying solely on firewall rules for defense).

Managed NAT Gateways: Outbound Only

Production backend instances (databases, internal APIs, Kubernetes worker nodes) must never have public IP addresses. But they frequently require outbound Internet access to download Linux security patches, fetch third-party API webhooks, or pull container images.

To provide one-way egress, cloud providers supply Managed NAT Gateways:

  • Runs high-speed Port Address Translation (PAT): Multiplexes thousands of internal private IP sockets onto a single public Elastic IP (EIP).
  • Blocks all inbound connections: External attackers on the Internet cannot initiate a TCP SYN into private instances through a NAT Gateway.
  • The Placement Iron Rule: A NAT Gateway MUST be deployed inside a Public Subnet (a subnet whose route table points 0.0.0.0/0 to an IGW)! If you deploy a NAT Gateway in a private subnet, it has no route to the Internet and silently fails.

Cloud Route Tables: Directing the Egress

Every subnet in a VPC is explicitly associated with a Route Table. Route evaluation follows Longest Prefix Match (LPM):

The NAT Gateway Bill Shock & Multi-AZ Design

In cloud networking, NAT Gateways are notorious for two severe architectural traps:

  1. The Financial Bill Shock: AWS charges ~$0.045 per hour per NAT Gateway (~$32/month) PLUS $0.045 per Gigabyte of data processed! If your private Kubernetes cluster pulls hundreds of gigabytes of machine learning models or backups through a NAT Gateway, your monthly bill spikes by thousands of dollars! (Solved in Session 56 using VPC Endpoints).
  2. Availability Zone Resilience: A NAT Gateway is a zonal resource; it lives in a single physical AZ. If us-east-1a suffers a power outage, its NAT Gateway dies. If your private subnets in us-east-1b point their default route to the NAT Gateway in us-east-1a, all availability zones lose Internet connectivity simultaneously! Production architecture mandates deploying one independent NAT Gateway in each AZ.

Hands-on: Inspecting cloud route tables

  1. View the active routing rules for a cloud subnet using the AWS CLI: 
    $ aws ec2 describe-route-tables --route-table-ids rtb-0123456789abcdef0
    Look for: DestinationCidrBlock: 0.0.0.0/0 mapped to GatewayId: igw-xxx or NatGatewayId: nat-xxx.
  2. Trace the public egress IP of an instance behind a NAT Gateway: 
    $ curl https://checkip.amazonaws.com
    Verify that the returned IP matches the Elastic IP assigned to your NAT Gateway—not the private IP of your virtual machine!
  3. Inspect the NAT Gateway allocation and active state: 
    $ aws ec2 describe-nat-gateways --filter "Name=state,Values=available"
    Confirm the public AllocationId and the associated SubnetId.

Free Recall Practice

From memory: why must a NAT Gateway be deployed in a public subnet, and why should production multi-AZ architectures deploy one NAT Gateway per zone?

Key points to compare against:

  • Why public subnet placement: A NAT Gateway translates private IPs to an Elastic IP, but it cannot reach the Internet on its own; it requires a route table with 0.0.0.0/0 pointing to an Internet Gateway (IGW). Only public subnets possess this route. Placing a NAT Gateway in a private subnet leaves it stranded without internet egress.
  • Why one NAT Gateway per AZ: A NAT Gateway is physically bound to a single Availability Zone. If an AZ fails, its NAT Gateway fails with it. Having all private subnets across multiple AZs rely on a single NAT Gateway creates a catastrophic single point of failure (SPOF) that negates multi-AZ redundancy.

// Cloud Route Table Longest Prefix Match in Java
import java.util.*;

public class VpcRouteResolver {
    public record Route(String cidr, String target) {}

    public static String resolve(String destIp, List<Route> table) {
        long d = ipToLong(destIp);
        Route best = null;
        int maxLen = -1;
        for (var r : table) {
            var parts = r.cidr().split("/");
            long net = ipToLong(parts[0]);
            int len = Integer.parseInt(parts[1]);
            long mask = len == 0 ? 0L : (0xFFFFFFFFL << (32 - len)) & 0xFFFFFFFFL;
            if ((d & mask) == (net & mask) && len > maxLen) {
                maxLen = len;
                best = r;
            }
        }
        return best != null ? best.target() : "DROP";
    }

    private static long ipToLong(String ip) {
        long res = 0;
        for (var p : ip.split("\\.")) res = (res << 8) | Long.parseLong(p);
        return res;
    }
}

// Cloud Route Table Longest Prefix Match in Kotlin
data class Route(val cidr: String, val target: String)

fun resolveRoute(destIp: String, table: List<Route>): String {
    val d = ipToLong(destIp)
    return table.map { r ->
        val (ipStr, lenStr) = r.cidr.split("/")
        val len = lenStr.toInt()
        val mask = if (len == 0) 0L else (0xFFFFFFFFL shl (32 - len)) and 0xFFFFFFFFL
        val net = ipToLong(ipStr)
        Triple(r, len, (d and mask) == (net and mask))
    }.filter { it.third }
     .maxByOrNull { it.second }
     ?.first?.target ?: "DROP"
}

private fun ipToLong(ip: String) = ip.split(".").fold(0L) { acc, s -> (acc shl 8) or s.toLong() }
