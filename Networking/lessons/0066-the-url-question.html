What are the five practical layers of the TCP/IP network model?

Layer 5: Application (HTTP, DNS, TLS), Layer 4: Transport (TCP, UDP), Layer 3: Network/Internet (IP, ICMP), Layer 2: Data Link (Ethernet, MAC, VLAN), and Layer 1: Physical (Copper, Fiber optics, Radio).

The Ultimate Systems Interview Question

"What happens when you type https://www.google.com into your browser and press Enter?"See the open-source community effort: what-happens-when.

A junior engineer answers: "DNS resolves the IP, TCP connects, and HTTP returns the HTML." A Principal Engineer understands that this single action triggers a symphonic collaboration across hardware electrical signals, optical dispersion, kernel system calls, cryptographic math, BGP peering economics, and cloud virtual overlays. Here is the definitive end-to-end trace.

Stage 1: Keystroke to URL Parsing

  1. Keyboard Interrupt: You press Enter. The keyboard controller generates a hardware interrupt (IRQ 1); the OS keyboard driver passes the scancode to the browser process.
  2. URL Parsing: The browser parses the string:
    • Protocol: https:// (Port 443 default).
    • Host: www.google.com.
    • Path: / (root document).
  3. HSTS Preload Check: The browser checks its internal hardcoded HSTS (HTTP Strict Transport Security) list. Because google.com is preloaded, the browser enforces HTTPS and will never send an unencrypted HTTP/1.1 request.

Stage 2: The DNS Resolution Walk

  1. Cache Check: The browser checks: (1) browser memory DNS cache, (2) OS resolver cache (systemd-resolved / macOS mDNSResponder), (3) /etc/hosts.
  2. Recursive Query: If missing, the OS sends a UDP packet on port 53 to the local DNS server learned via DHCP (e.g. 192.168.1.1 or 8.8.8.8).
  3. The Root Walk: If the resolver's cache is empty, it queries the 13 global Root clusters (.) → referred to .com TLD nameservers → referred to Google's authoritative nameservers (ns1.google.com).
  4. The authoritative nameserver returns the A record (IPv4: 142.250.190.46) and AAAA record (IPv6: 2607:f8b0:4009:816::2004) with a TTL.

Stage 3: ARP & The Gateway Hop

  1. The OS routing table evaluates destination 142.250.190.46 via Longest Prefix Match. It matches the default route (0.0.0.0/0) pointing to Gateway 192.168.1.1.
  2. ARP Lookup: The host checks its in-memory ARP cache for the router's MAC address. If missing, it emits an Ethernet broadcast (ff:ff:ff:ff:ff:ff): "Who has 192.168.1.1? Tell 192.168.1.50." The home router replies with its 48-bit MAC address.
  3. The switch updates its CAM table and forwards the frame out the router port.

Stage 4: The TCP 3-Way Handshake

  1. The client kernel chooses an ephemeral port (e.g. 52140) and generates a random Initial Sequence Number (ISN).
  2. SYN: Client sends [SYN, Seq=0, Win=65535, MSS=1460, SACK_PERM].
  3. The home router translates the client's private IP to its public WAN IP via PAT, updating its NAT state table.
  4. SYN-ACK: Google's server receives the SYN, verifies its syncookies, and replies with [SYN, ACK].
  5. ACK: Client sends [ACK]. The TCP socket enters the ESTABLISHED state. Total time: 1 RTT.

Stage 5: The TLS 1.3 Handshake

  1. ClientHello (1-RTT): Client sends supported cipher suites (e.g. TLS_AES_256_GCM_SHA384), the SNI (Server Name Indication) extension (www.google.com), and an ECDHE KeyShare (Curve25519 public key parameter).
  2. ServerHello: Server selects the cipher suite, generates its own KeyShare, and transmits its public key. Both sides calculate the shared symmetric secret independently using Diffie-Hellman!
  3. Encrypted Payload: The server sends its X.509 certificate chain, digital signature (CertificateVerify), and Finished block—all 100% encrypted!
  4. The browser verifies the certificate chain up to a trusted Root CA in its trust store.

Stage 6: Global Anycast & Cloud Ingress

  1. The IP packet traverses the public Internet using Anycast BGP. BGP shortest AS-PATH routes the packet to Google's topologically nearest Point of Presence (PoP) in the user's city.
  2. At the edge data center, the packet enters a hardware Layer 4 Network Load Balancer (Maglev) that hashes the 5-tuple to forward packets to an edge reverse proxy.
  3. Traffic flows across an internal Leaf-Spine underlay running an overlay tunnel (VXLAN / Geneve) into a Kubernetes worker node.
  4. The node's eBPF / CNI routes the packet into the container network namespace, where the application server processes the HTTP/2 or HTTP/3 request.

Stage 7: HTTP Response & The Critical Render Path

  1. The web server streams an HTTP response: status 200 OK, Content-Type: text/html.
  2. The browser receives chunks of HTML and begins the Critical Render Path:
    • Parses HTML tokens → builds the DOM (Document Object Model) tree.
    • Discovers external CSS → parses CSS rules → builds the CSSOM tree.
    • Combines DOM + CSSOM → generates the Render Tree.
    • Layout (Reflow): Computes exact pixel coordinates and geometry for every visible element.
    • Paint & Composite: GPU rasterizes pixels onto screen buffers. Google's search homepage appears!

Hands-on: Replicating the full URL trace with terminal tools

  1. Trace the recursive DNS resolution walk using dig +trace: 
    $ dig +trace www.google.com
    Observe the iterative referrals: . (Root) → .com (TLD) → google.com authoritative nameservers!
  2. Observe the TCP handshake and TLS 1.3 negotiation with verbose curl: 
    $ curl -Iv https://www.google.com
    Look for: * Connected to www.google.com (142.250.190.46) port 443, * SSL connection using TLSv1.3, and the ALPN negotiation: * ALPN: server accepted h2.
  3. Inspect the physical network hops using traceroute: 
    $ traceroute -n -m 12 www.google.com
    Identify your local default gateway (Hop 1), your regional ISP transit router, and the final Google Anycast edge router.

From memory: summarize the 7 critical stages of "What happens when you type a URL and hit Enter."

Key points to compare against:

  • 1. Parsing & HSTS: Browser parses URL, checks HSTS preload list to enforce HTTPS.
  • 2. DNS Resolution: Traverses browser cache, OS resolver, and recursive DNS to root/TLD/authoritative nameservers to resolve IP address.
  • 3. ARP & L2: Resolves local default router MAC address via ARP and forwards frame out switch port.
  • 4. TCP Handshake: Completes SYN, SYN-ACK, ACK 3-way handshake over ephemeral port with PAT at edge.
  • 5. TLS 1.3 Handshake: ClientHello with SNI and KeyShare; server authenticates via cert and derives shared ECDHE keys in 1 RTT.
  • 6. Ingress & Routing: Anycast BGP routes to nearest edge PoP; packet traverses cloud load balancers and container overlay (CNI/eBPF) to application pod.
  • 7. HTTP Response & Render: Server streams HTML; browser parses DOM/CSSOM, executes layout reflow, and GPU paints pixels.

// URL Request Lifecycle State Machine in Java
public class UrlStateMachine {
    public enum State { IDLE, DNS_RESOLVED, TCP_CONNECTED, TLS_ESTABLISHED, REQUEST_SENT, RESPONSE_RECEIVED, ERROR }
    public enum Event { RESOLVE_DNS, CONNECT_TCP, HANDSHAKE_TLS, SEND_REQUEST, RECEIVE_RESPONSE }

    public static State step(State current, Event event) {
        return switch (current) {
            case IDLE -> event == Event.RESOLVE_DNS ? State.DNS_RESOLVED : State.ERROR;
            case DNS_RESOLVED -> event == Event.CONNECT_TCP ? State.TCP_CONNECTED : State.ERROR;
            case TCP_CONNECTED -> event == Event.HANDSHAKE_TLS ? State.TLS_ESTABLISHED : State.ERROR;
            case TLS_ESTABLISHED -> event == Event.SEND_REQUEST ? State.REQUEST_SENT : State.ERROR;
            case REQUEST_SENT -> event == Event.RECEIVE_RESPONSE ? State.RESPONSE_RECEIVED : State.ERROR;
            default -> State.ERROR;
        };
    }
}
Kotlin 
// URL Request Lifecycle State Machine in Kotlin
enum class UrlState { IDLE, DNS_RESOLVED, TCP_CONNECTED, TLS_ESTABLISHED, REQUEST_SENT, RESPONSE_RECEIVED, ERROR }
enum class UrlEvent { RESOLVE_DNS, CONNECT_TCP, HANDSHAKE_TLS, SEND_REQUEST, RECEIVE_RESPONSE }

fun stepUrl(state: UrlState, event: UrlEvent): UrlState = when (state) {
    UrlState.IDLE -> if (event == UrlEvent.RESOLVE_DNS) UrlState.DNS_RESOLVED else UrlState.ERROR
    UrlState.DNS_RESOLVED -> if (event == UrlEvent.CONNECT_TCP) UrlState.TCP_CONNECTED else UrlState.ERROR
    UrlState.TCP_CONNECTED -> if (event == UrlEvent.HANDSHAKE_TLS) UrlState.TLS_ESTABLISHED else UrlState.ERROR
    UrlState.TLS_ESTABLISHED -> if (event == UrlEvent.SEND_REQUEST) UrlState.REQUEST_SENT else UrlState.ERROR
    UrlState.REQUEST_SENT -> if (event == UrlEvent.RECEIVE_RESPONSE) UrlState.RESPONSE_RECEIVED else UrlState.ERROR
    else -> UrlState.ERROR
}
