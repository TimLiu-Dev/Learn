Who are your neighbours? Subnet math in one AND

Prefixes, netmasks and CIDR notation

~30 minutesTools: ifconfig, subnet trainer★ interview
Your win today

Given any address like 172.20.77.9/21, you'll work out its network, broadcast address and host range, decide whether two hosts share a subnet, and then compute your own Mac's network from what ifconfig prints.

Warm-up · from earlier sessions

Which kind of address does each layer use: transport, network, link? And how far up the layer stack does a host, a router and a switch go?

Transport: port. Network: IP address. Link: MAC address. Hosts implement all five layers; routers go up to the network layer; switches only up to the link layer. (Session 2)

A packet crosses two routers on its way to a server. Which addresses in it change at every hop, and which stay the same end to end?

The link-layer frame is rebuilt on every link, so its source and destination MAC addresses change at each hop. The IP source and destination addresses stay the same the whole way. A MAC address only matters on one link. (Session 4)

Why this matters

Every time your Mac sends a packet, it first answers one question: is the destination on my own network, or do I hand it to the router?

That decision is subnet math, and the rules require every host to make it.RFC 1122 §3.3.1.1, "Local/Remote Decision": a host MUST compare the destination with its own address under its mask. Get the mask wrong and you see strange, half-working networks: the internet works but the printer two metres away doesn't, or the other way round. The same notation, 10.0.0.0/16, is how cloud networks, Docker networks and firewall allow-lists are written, so you'll read it for the rest of your career. And "how many hosts fit in a /26?" is a classic interview warm-up.

An address has two parts

Back in session 4, MAC addresses were flat: the number says nothing about where the device is. IP addresses are hierarchical. The first bits name a network; the remaining bits name one interface on it.Network part and host part: Systems Approach §3.3.3; Kurose & Ross §4.3, "IPv4 Addressing".

  • The prefix (network part) is the first n bits. Every host on the same network shares it.
  • The host part is the remaining 32 − n bits. It is different for every interface on that network.
  • A subnet is the block of addresses that share one prefix. Hosts in the same subnet reach each other directly over the link. Everything else goes through a router.

We write the split as address/n, where n is the prefix length. This is CIDR notation (Classless Inter-Domain Routing, say "cider")."Followed by the '/' (slash) character, followed by a decimal value between 0 and 32 that describes the number of significant bits": RFC 4632 §3.1. A subnet of length n holds 232−n addresses: a /24 holds 256, a /21 holds 2,048, a /30 holds 4.

The mask: same idea, three spellings

A subnet mask (netmask) writes the prefix length as a 32-bit number: n one-bits followed by 32 − n zero-bits. You'll meet it in three spellings. For /20:

Spelling/20 written that wayWhere you see it
Prefix length/20Cloud consoles, routing tables, docs
Dotted decimal255.255.240.0System settings, most tools
Hexadecimal0xfffff000macOS ifconfig

Only one octet is ever "partial". An octet whose first b bits are ones is worth 256 − 28−b: 128, 192, 224, 240, 248, 252, 254, 255 for b = 1…8. In hex, each digit is four bits, so count ones per digit: f = 4, e = 3, c = 2, 8 = 1, 0 = 0. For 0xfffff000 that's 5 × 4 = 20.

The method: AND with the mask

To find the network an address belongs to, keep the prefix bits and zero the host bits. That's a bitwise AND with the mask.The AND method, with a worked example: Systems Approach §3.3.5.

Everything else follows from that one picture:

QuantityRule172.20.77.9/21
Network addressall host bits 0172.20.72.0
Broadcast addressall host bits 1172.20.79.255
Usable hostsnetwork + 1 … broadcast − 1172.20.72.1 – 172.20.79.254
How many232−n − 2211 − 2 = 2,046

Why "− 2"? A host part of all zeros names the network itself, and all ones means "every host on this network" (the broadcast address). Neither may be assigned to a host."IP addresses are not permitted to have the value 0 or -1 for any of the <Host-number> … fields": RFC 1122 §3.2.1.3. Two edge cases: a /32 is exactly one host, and a /31 (2 addresses) may use both for a point-to-point link between two routers.RFC 3021, "Using 31-Bit Prefixes on IPv4 Point-to-Point Links".

The shortcut you'll use in your head: find the octet where the prefix ends. If b of its bits are network bits, subnets in that octet come in blocks of 28−b. For /21 that's the third octet with 5 network bits, so blocks of 8: 0, 8, … 72, 80 … Round 77 down to a multiple of 8 for the network (72); the block ends at 72 + 8 − 1 = 79 for the broadcast. Earlier octets are copied; later ones become 0 (network) or 255 (broadcast).

Same subnet? Direct, or via the gateway

Now the question from the top. Your Mac ANDs the destination with its own mask and compares the result with its own network address. Equal: the destination is on the link, so the Mac delivers the frame straight to it (session 7 shows how it finds the MAC address). Different: the Mac hands the packet to its default gateway, the router (session 9). For example, with 10.1.2.3/24, the address 10.1.2.200 is a neighbour, while 10.1.3.4 already needs the router.

Where "class C" comes from

Until 1993, the prefix length wasn't written down. It was implied by the first bits of the address: class A was /8, class B /16, class C /24. Nothing in between. A company with 300 hosts was too big for a C, so it got a B with room for 65,534, and B's ran out. CIDR made the prefix length explicit and any size, so blocks could match real needs and neighbouring blocks could be advertised as one route.The classful scheme and its waste: Systems Approach §3.3.5. CIDR: RFC 1519 (September 1993), now RFC 4632. You'll still hear "a class C" used as slang for a /24.

Practise until it's boring

Subnet math is a skill, not a fact: it gets fast only with repetition. Do problems until you get five in a row right on the first try. Use the drop-down to drill one kind. After each problem, read the binary working: the | marks where the prefix ends.

Try it: find your own network

Your Mac already knows its address and mask; it just prints the mask in hex. The line you want looks like this:

inet xx.xx.xx.xx netmask 0xhhhhhhhh broadcast xx.xx.xx.xx

Do the math on paper first. The trainer can't help you here, and that's the point.

  1. Print your IPv4 address and mask: ifconfig en0 | grep 'inet ' (the space after inet skips the IPv6 lines).
  2. Convert the hex netmask into a prefix length /n and into dotted decimal. Check the dotted version with ipconfig getoption en0 subnet_mask.
  3. By hand, compute your network address, broadcast address, first and last usable host, and the number of usable hosts.
  4. Compare your broadcast address with the one ifconfig printed. If they differ, find the mistake before moving on.
  5. Find your router again (session 1): route -n get default | grep gateway. Run the same-subnet test on it, then on 1.1.1.1.
  6. Write your results as a small table: address, /n, network, broadcast, host range, host count, and the two same-subnet verdicts.

Then answer these. Bring your answers to chat rather than looking them up:

  • How many devices could your network hold? Why might whoever set up your router have picked that size rather than a bigger or smaller one?
  • Was your default gateway inside your subnet? Must a gateway always be? What would go wrong if it weren't?
  • Suppose your mask were misconfigured one bit longer (/n+1). Which addresses would your Mac now treat as remote? Could you still reach the internet? Could you still reach every device at home?

Check yourself

Answer from memory first, on paper if you like. Scroll up only after you've committed to an answer.

How many usable host addresses does a /26 subnet have?

  1. 64
  2. 30
  3. 62
  4. 126
32 − 26 = 6 host bits, so 2⁶ = 64 addresses. Take away the network and broadcast addresses: 62 usable.

What is the network address of 10.4.150.77/20?

  1. 10.4.144.0
  2. 10.4.150.0
  3. 10.4.128.0
  4. 10.4.159.0
/20 ends in the third octet, which has 4 network bits, so blocks of 2⁴ = 16. Round 150 down to a multiple of 16: 144. The last octet becomes 0. (The broadcast would be 10.4.159.255.)

ifconfig shows netmask 0xfffffc00. What is the prefix length?

  1. /20
  2. /24
  3. /26
  4. /22
Five f digits are 5 × 4 = 20 ones; c = 1100 adds 2 more; the zeros add none. 22 ones: /22, or 255.255.252.0.

Which pair of hosts is in the same /25 subnet?

  1. 10.0.0.100 and 10.0.0.130
  2. 10.0.0.129 and 10.0.0.250
  3. 10.0.0.127 and 10.0.0.128
  4. 10.0.1.50 and 10.0.0.50
A /25 splits the last octet into two blocks of 128: 0–127 and 128–255. Only 129 and 250 fall in the same block. The last pair differs in the third octet, which is entirely network bits.

Your Mac is 10.1.2.3/24 and sends a packet to 10.1.3.4. What does it do?

  1. Sends it to its default gateway
  2. Delivers it directly over the link
  3. Broadcasts it to every local host
  4. Drops it as an invalid destination
10.1.3.4 AND 255.255.255.0 = 10.1.3.0, which isn't the Mac's network 10.1.2.0. Off-subnet destinations go to the default gateway. Close-looking numbers don't matter; only the prefix bits do.

A /24 has 256 addresses. Why can only 254 of them be given to hosts?

  1. The router always takes two addresses
  2. Spare addresses are kept for growth
  3. Network and broadcast addresses are reserved
  4. Neighbouring subnets share their edge addresses
A host part of all zeros names the network itself; all ones is the broadcast address. The router does need an address, but it takes one of the 254 like any other interface.
