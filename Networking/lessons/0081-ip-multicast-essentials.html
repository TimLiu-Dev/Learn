Warm-up · from earlier sessions

Two minutes, from memory, before you read on:

Suppose a stock exchange feed server streams 500 Mbps of UDP market ticks to 400 subscribers. Why would opening 400 separate unicast streams break latency budgets, while using L3 broadcast breaks subnets?

Unicast forces the sender NIC to copy and transmit 400 × 500 Mbps = 200 Gbps, burning sender CPU and link capacity; broadcast hits every non-subscriber host and never crosses L3 routers. IP Multicast sends the 500 Mbps packet once; routers and snooping switches replicate it selectively only down links leading to joined receivers.

1 · IPv4 Class D (224.0.0.0/4) & L2 Multicast MAC Mapping

  • 224.0.0.0/24 — Link-Local Control (TTL=1, never routed): 224.0.0.2 all routers, 224.0.0.5/6 OSPF, 224.0.0.18 VRRP, 224.0.0.22 IGMPv3, 224.0.0.251 mDNS.
  • 232.0.0.0/8 — Source-Specific Multicast (SSM), where receivers subscribe directly to (Source, Group) using IGMPv3 without a Rendezvous Point.
  • 239.0.0.0/8 — Administratively Scoped (Private Multicast), analogous to RFC 1918 for enterprise feeds & VXLAN underlays.
IPv4-to-MAC Multicast Mapping (RFC 1112): Ethernet allocates OUI 01:00:5e (with bit 24 = 0) for IPv4 multicast. A multicast IP has 28 variable host bits (after the leading 1110 Class D prefix), but only the lowest 23 bits fit into the Ethernet MAC! Because 5 middle bits are ignored, 25 = 32 different multicast IP addresses map to the exact same Layer-2 MAC address!

2 · IGMP (v2/v3) & Switch IGMP Snooping

By default, an unmanaged L2 switch sees an unknown multicast destination MAC and floods it out every port in the VLAN like a broadcast! IGMP Snooping fixes this: the switch peeks inside host IGMP Membership Report packets heading toward the router and programs hardware L2 multicast tables so group traffic only leaves ports that explicitly asked to join. (Always ensure an active IGMP Querier exists on isolated L2 VLANs, or switches will age out snooped entries after ~260 seconds!)

3 · PIM Sparse Mode (PIM-SM) & RPF Check

Between L3 routers, PIM Sparse Mode (PIM-SM) avoids flooding the entire WAN by building distribution trees explicitly on receiver demand:

  • (*, G) Shared Tree: Receivers send IGMP Joins → Last-Hop Router sends PIM Join up to a central Rendezvous Point (RP).
  • (S, G) Shortest-Path Tree (SPT): Once traffic starts flowing from source S, the last-hop router learns S's IP and switches directly to the shortest unicast path to S, bypassing any RP bottleneck!
  • Reverse Path Forwarding (RPF) Check: The number-one multicast routing defense against loops! A router only accepts a multicast packet from source S if it arrived on the exact interface the unicast routing table uses to reach S.

RFC 1112 IPv4-to-MAC Multicast Mapper & PIM RPF Check

Java 25 
// Mapping IPv4 multicast 224.0.0.0/4 -> 01:00:5e:XX:YY:ZZ (low 23 bits only!)
public static String toMulticastMac(int ipv4) {
    int low23 = ipv4 & 0x7FFFFF; // clear top 9 bits (including bit 23!)
    return String.format("01:00:5e:%02x:%02x:%02x",
        (low23 >> 16) & 0x7F, (low23 >> 8) & 0xFF, low23 & 0xFF);
}

  1. RFC 1112 mandates reserving 239.0.0.0/8 strictly for broadcast Ethernet frames.
    2. 
        
  2. PIM Rendezvous Points rewrite every second octet to 129 during GRE encapsulation.
    3. 
        
  3. Ethernet multicast mapping preserves only the low 23 bits, discarding 5 middle bits.
    4. 
        
  4. Switches ignore IPv4 destination octets and hash UDP port numbers directly into the MAC.
    5. 
      

      
Avoid overlapping low 23 bits (like x.1.1.5 and x.129.1.5) when isolating separate multicast feeds on shared switches.

  1. Drops the packet immediately because ingress interface eth1 fails the RPF check.
    2. 
        
  2. Forwards the packet out eth0 only after converting it into an ICMP Redirect.
    3. 
        
  3. Floods the packet out both eth1 and eth0 to repair asymmetric unicast routing.
    4. 
        
  4. Caches the packet in OSPF LSA Type 9 until the Rendezvous Point replies.
    5. 
      

      
RPF against the unicast RIB prevents catastrophic Layer-3 multicast forwarding loops.

    

    

      
Why does an isolated Layer-2 VLAN (no L3 multicast router attached) running IGMP Snooping suddenly drop multicast video feeds every 4–5 minutes?

      
    
        
  1. IGMP requires TCP three-way handshakes every 60 seconds across every access port.
    2. 
        
  2. Ethernet switches expire MAC addresses automatically if VLAN IDs exceed 100.
    3. 
        
  3. Class D multicast packets always carry a hard maximum IP lifetime of 255 seconds.
    4. 
        
  4. Switches age out snooped ports because no IGMP Querier sends periodic membership queries.
    5. 
      

      
Isolated L2 multicast VLANs must designate one switch as the IGMP Snooping Querier.
