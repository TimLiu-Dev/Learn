The address that only lasts one hop

MAC addresses, Ethernet frames and switches

~25 minutesTools: ifconfig, networksetup, Wireshark
Your win today

You'll read an Ethernet frame header field by field, tell from its bits whether your own Mac's address is a factory address or a made-up one, and explain why a MAC address only matters for one hop.

Warm-up · from earlier sessions

Two minutes, from memory, before you read on. Both prompts come from session 1 and session 2.

What are the two parts of every packet? Why does the internet use packet switching instead of circuit switching?

A header (addresses and bookkeeping, like an envelope) and a payload (a slice of your data). Circuit switching reserves capacity end to end for the whole conversation, even when idle. Computer traffic is bursty, so packet switching shares every link on demand instead. The cost: no guaranteed capacity, so packets can queue or be dropped.

What kind of address does each of the transport, network and link layers use? Up to which layer does a host, a router and a switch each work?

Transport: port. Network: IP address. Link: MAC address. Hosts implement all five layers. Routers work up to the network layer. Switches work up to the link layer.

Why two addresses?

Your Mac already has an IP address. So why does every frame it sends also carry a second, completely different address?

Because the two answer different questions. The IP address says where the packet is ultimately going. The MAC address says which device on this one link should pick it up next. Once you see that split, a lot of confusing things make sense. In session 2 you found a MAC address in your capture that belonged to neither your Mac nor the server. You'll understand why ARP exists (session 7), why a "wrong gateway" breaks everything, and why the coffee-shop Wi-Fi forgets you paid when your Mac changes its address. It's also the first header you'll see in every Wireshark capture you ever open.

MAC addresses

A MAC address is 48 bits long, written as six bytes in hex: xx:xx:xx:xx:xx:xx. That's 2⁴⁸, about 281 trillion possible addresses. It belongs to a network interface, not to a computer: your Mac has one for Wi-Fi, another for each Ethernet adapter, and so on."Technically, the address belongs to the adaptor, not the host." Systems Approach §2.6, "Addresses".

Factory addresses are made unique by splitting them in two. The first three bytes are an OUI (Organizationally Unique Identifier), a prefix the IEEE sells to each manufacturer. The manufacturer picks the last three bytes so that no two of its interfaces collide.OUI and NIC-specific halves: RFC 9724 §2.1. The IEEE also sells longer 28- and 36-bit prefixes: RFC 9542 §2.1. That's why Wireshark can often print a vendor name in front of a MAC address.

Two bits in the very first byte change what the address means:Both bits: RFC 9542 §2.1.1 (which calls them M and X) and RFC 9724 §2.1, Figure 1.

  • The I/G bit (individual/group), the lowest bit, worth 1. 0 means unicast: one specific interface. 1 means a group: multicast or broadcast.
  • The U/L bit (universal/local), the next bit up, worth 2. 0 means universally administered: a factory address under an OUI. 1 means locally administered: software chose it, so the OUI part means nothing.

To read them, take the first byte, look only at its second hex digit, and write that digit in binary. The rightmost bit is I/G; the one left of it is U/L. Example: an address starting f6:. The digit 6 is 0110. The rightmost bit is 0, so it's unicast. The next bit is 1, so it's locally administered. Another example: 00:00:5e:00:53:01, an address reserved for documentation. The digit 0 is 0000: unicast and universal.00-00-5E-00-53-00 to …-53-FF are reserved for documentation: RFC 9542 §2.1.4.

Why would software make up an address? Privacy. A factory MAC address never changes and anyone within radio range can read it, so it can track you from café to airport to office. Since macOS 15, your Mac can use a private Wi-Fi address instead: a different address for each network, set to Off, Fixed or Rotating per network.Apple: Use private Wi-Fi addresses on Apple devices. Randomised addresses use the U/L bit so no global coordination is needed: RFC 9724 §2.2. Randomised addresses are locally administered addresses. You'll check yours shortly.

One special group address: broadcast, ff:ff:ff:ff:ff:ff (all 48 bits set). Every interface on the local network accepts a frame sent to it.All-ones broadcast: RFC 894, "Broadcast Address"; Systems Approach §2.6. ARP and DHCP (sessions 7 and 8) rely on it.

The Ethernet frame

A link-layer frame wraps one network-layer packet for one trip across one link. The common format on Ethernet is Ethernet II.Field sizes: Systems Approach §2.6, "Frame Format"; IP over Ethernet: RFC 894. Its header is just 14 bytes:

FieldBytesWhat it's for
Preamble8Alternating bits that let the receiver sync to the signal. Added and removed by the hardware, so Wireshark never shows it.
Destination MAC6Who on this link should take the frame. It comes first.
Source MAC6Which interface sent it
EtherType2What's inside: 0x0800 IPv4, 0x86DD IPv6, 0x0806 ARP
Payload46–1500The packet. Short payloads are padded up to 46 bytes.
FCS4A CRC checksum. The receiver drops frames that fail it. Usually stripped before Wireshark sees it.

The EtherType is how the receiver knows which protocol to hand the payload to.EtherType values: IANA IEEE 802 Numbers registry. The 1,500-byte payload limit is Ethernet's MTU (maximum transmission unit): the biggest packet the link can carry in one frame. That's the "about 1,500 bytes" from session 1. Session 5 shows what happens to bigger packets.

And Wi-Fi? Real 802.11 frames have their own header with four address fields.Systems Approach §2.7.2, "Frame Format". Unless you capture in special monitor mode, though, the Wi-Fi driver translates each frame into a "fake" Ethernet II header before Wireshark sees it.Wireshark wiki: WLAN capture setup: "the 802.11 packet headers are 'translated' by the network driver to 'fake' Ethernet packet headers." On macOS you only get 802.11 headers in monitor mode. That answers the last question from session 2.

Switches learn where everyone is

A switch connects many devices on one network and forwards frames by destination MAC. Nobody configures it. It learns:Learning algorithm, table timeouts and flooding: Systems Approach §3.2.1, "Learning Bridges". A switch is a multi-port bridge.

  1. When a frame arrives, the switch records source MAC → the port it came in on. Entries expire after a while, in case a device moves.
  2. If the destination MAC is in its table, it sends the frame out of that one port only.
  3. If not, or if it's the broadcast address, it floods the frame out of every port except the one it came in on.

A switch doesn't change the frame and doesn't put its own MAC address in it. To the hosts it's invisible. Your home "router" is usually several devices in one box: a router, a small switch for its Ethernet ports, and a Wi-Fi access point.

Why a MAC address only lasts one hop

Here's the payoff. A router works up to the network layer. When a frame arrives, the router strips the frame off, reads the IP header to choose the next hop, and wraps the packet in a brand-new frame for the next link: new source MAC (its own outgoing interface), new destination MAC (the next router)."Each IP datagram is re-encapsulated for each physical network over which it travels." Systems Approach §3.3.2. Also Kurose & Ross §6.4.1. The IP addresses inside ride through unchanged.One exception you'll meet in session 10: a home router doing NAT rewrites the source IP address.

So when your Mac sends a packet to a server on the other side of the world, the destination MAC on the frame it sends is your router's. Your Mac never learns the server's MAC address, and doesn't need to. How does it learn the router's MAC in the first place? That's ARP, session 7.

Code Example: Inspecting MAC Addresses in Java & Kotlin

Every MAC address encodes critical hardware properties in its first byte: the least significant bit (I/G) indicates Individual vs Group (Multicast), and the second bit (U/L) indicates Universally vs Locally Administered (used by Docker containers and iOS/Android private Wi-Fi randomization):

public class MacInspector {
    public static boolean isBroadcast(String mac) {
        return "FF:FF:FF:FF:FF:FF".equalsIgnoreCase(mac.trim());
    }

    public static boolean isMulticast(String mac) {
        if (isBroadcast(mac)) return false;
        int firstByte = parseFirstByte(mac);
        return (firstByte & 0x01) == 1; // Bit 0: I/G (Individual/Group)
    }

    public static boolean isLocallyAdministered(String mac) {
        int firstByte = parseFirstByte(mac);
        return (firstByte & 0x02) == 2; // Bit 1: U/L (Universal/Local)
    }

    public static String extractOui(String mac) {
        String[] parts = mac.trim().split("[:-]");
        if (parts.length < 3) return "";
        return (parts[0] + ":" + parts[1] + ":" + parts[2]).toUpperCase();
    }

    private static int parseFirstByte(String mac) {
        String clean = mac.trim().replaceAll("[:-]", "");
        return Integer.parseInt(clean.substring(0, 2), 16);
    }

    public static void main(String[] args) {
        String dockerMac = "02:42:ac:11:00:02";
        System.out.println("Docker MAC local? " + isLocallyAdministered(dockerMac)); // true
        System.out.println("Multicast 01:00:5e:00:00:01? " + isMulticast("01:00:5e:00:00:01")); // true
        System.out.println("OUI for dc:a6:32:12:34:56: " + extractOui("dc:a6:32:12:34:56")); // DC:A6:32
    }
}
object MacInspector {
    fun isBroadcast(mac: String): Boolean =
        mac.trim().equals("FF:FF:FF:FF:FF:FF", ignoreCase = true)

    fun isMulticast(mac: String): Boolean {
        if (isBroadcast(mac)) return false
        return (parseFirstByte(mac) and 0x01) == 1
    }

    fun isLocallyAdministered(mac: String): Boolean =
        (parseFirstByte(mac) and 0x02) == 2

    fun extractOui(mac: String): String {
        val parts = mac.trim().split("[:-]".toRegex())
        return if (parts.size >= 3) "${parts[0]}:${parts[1]}:${parts[2]}".uppercase() else ""
    }

    private fun parseFirstByte(mac: String): Int {
        val clean = mac.trim().replace("[:-]".toRegex(), "")
        return clean.substring(0, 2).toInt(16)
    }
}

fun main() {
    println("Docker local? ${MacInspector.isLocallyAdministered("02:42:ac:11:00:02")}")
    println("Multicast? ${MacInspector.isMulticast("01:00:5e:00:00:01")}")
}

Why did Docker generate a MAC with 02 as the first byte?

      
    
        
  1. To match the official IEEE OUI registered to Docker Inc.
    2. 
        
  2. To assert the U/L bit, marking it as a Locally Administered MAC address
    3. 
        
  3. To enable hardware multicast routing on the Linux bridge
    4. 
        
  4. To signal that the container uses IPv4 rather than IPv6
    5. 
      

      
In IEEE 802, setting bit 1 of the first byte marks the MAC address as Locally Administered. Hypervisors (Docker, KVM, VMware) and mobile OS private Wi-Fi randomizers use local MACs to avoid conflicting with globally registered hardware vendor OUIs.
