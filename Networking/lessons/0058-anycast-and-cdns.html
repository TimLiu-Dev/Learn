Warm-up · from earlier sessions

Two minutes, from memory, before you read on:

What is the physical minimum speed-of-light round trip time (RTT) between London and Sydney?

London to Sydney is ~17,000 km. In optical fiber, light travels at ~200,000 km/s. The physical minimum theoretical RTT is ~170 ms (in practice ~250–300 ms across transit hops).

Beating the speed of light

No software optimization can make light travel faster than 200,000 km/s in glass fiber. If your server is in Virginia and your user is in Tokyo, a 3-way TCP handshake plus a TLS 1.3 key exchange takes at least 300 milliseconds of dead waiting time before a single byte of application data is received.See Ilya Grigorik, High Performance Browser Networking: Delivering data to the edge.

To eliminate this delay, you cannot move your user closer to Virginia; you must move Virginia closer to your user. Modern global infrastructure achieves this through Anycast BGP and Content Delivery Networks (CDNs).

Unicast vs Anycast Addressing

In standard Unicast routing, every IP address points to exactly one physical network interface on Earth. In Anycast routing, multiple physical servers distributed in hundreds of data centers across continents advertise the exact same IP address into global BGP:

How Anycast Works in BGP

  1. Cloudflare, Google, or AWS configures edge routers in 300+ cities to advertise the same prefix (e.g. 1.1.1.0/24) to their local upstream transit ISPs and IXP peers.
  2. When an end-user's ISP in London resolves 1.1.1.1, its local border router evaluates the global BGP table. The London edge advertisement is only 1 AS hop away, whereas Tokyo is 6 hops away across a transpacific cable. The router forwards packets to London.
  3. Simultaneously, a user in Tokyo sending to the exact same IP address routes directly to Tokyo.

The Superpower: DDoS Dilution

In a standard unicast network, a 1 Terabit/sec volumetric Distributed Denial of Service (DDoS) attack overwhelms the single data center hosting that IP, saturating its transit links and crashing its firewalls.

With Anycast BGP, a global DDoS attack is geographically chopped up and diluted across the entire planet! Infected botnet machines in Germany route into the Frankfurt edge; botnet machines in Brazil route into the São Paulo edge. No single data center absorbs more than a fraction of the attack, allowing edge scrubber hardware to filter the malicious packets at line rate.

The Anycast TCP Flapping Paradox

Anycast was originally thought to be suitable only for connectionless UDP traffic (like DNS: query in, reply out). Why? Because TCP is stateful.

If an ISP router experiences a minor BGP route shift mid-download, packets that were routing to London might suddenly be diverted to Paris. If Paris does not have the TCP connection state in its memory, Paris will drop the packet and transmit a TCP RST, tearing down the user's connection!

How Modern Anycast Runs Reliable TCP

  • BGP Path Stability: Tier-1 peering agreements maintain stable BGP routes; route shifts occur infrequently (typically hours apart).
  • Consistent Flow Hashing: Edge load balancers use consistent 5-tuple hashing (e.g. Maglev / Katran) so packets arriving within a data center hit the same proxy core.
  • Cross-PoP State Sharing: Modern edge networks can forward stateful TCP session tokens between adjacent regional data centers.

Content Delivery Networks (CDNs)

A Content Delivery Network (CDN) (Cloudflare, AWS CloudFront, Fastly, Akamai) combines Anycast routing with reverse proxy caching:

  • TLS Termination at the Edge: The user completes TCP handshakes and TLS 1.3 key exchanges with an edge server only 5 milliseconds away.
  • Static Asset Caching: Images, CSS, video segments, and JavaScript bundles are cached in edge RAM/NVMe. 90%+ of user requests are served directly from the edge PoP without ever touching your origin server.
  • Dynamic Origin Shielding: When a request must reach the backend origin, the CDN uses an already established, persistent, pre-warmed TCP/TLS connection across its private high-speed fiber backbone, bypassing public internet congestion.

Hands-on: Testing Anycast latency physics

  1. Ping Cloudflare's Anycast DNS resolver from your terminal: 
    $ ping -c 4 1.1.1.1
    Notice the RTT is typically under 15 ms! A speed-of-light calculation proves this packet could not possibly have crossed an ocean.
  2. Trace the network path to discover your nearest Anycast Point of Presence (PoP): 
    $ traceroute 1.1.1.1
    Look at the airport IATA codes in the final hops (e.g. ord for Chicago O'Hare, lhr for London Heathrow, nrt for Tokyo Narita).
  3. Inspect CDN caching headers on a public web asset using curl: 
    $ curl -I https://cdnjs.cloudflare.com/ajax/libs/react/18.2.0/umd/react.production.min.js
    Look for: cf-cache-status: HIT, age: 482012, and server: cloudflare!

Free Recall Practice

From memory: how does Anycast BGP route packets to the nearest server? Why was running TCP over Anycast historically considered difficult?

Key points to compare against:

  • How Anycast routes to the nearest: Multiple distributed data centers announce the exact same IP prefix into global BGP. When intermediate routers forward packets toward that IP, standard BGP path selection chooses the announcement with the shortest AS-PATH, naturally steering traffic to the topologically closest edge facility.
  • Why Anycast TCP was difficult: TCP is a stateful, connection-oriented protocol requiring continuous multi-packet handshakes and sequence tracking. If a BGP route shifts mid-session, subsequent TCP packets arrive at a different physical data center that lacks the existing session state, causing the new server to emit a TCP RST and terminate the connection.

// CDN Edge Cache-Control Evaluator in Java
public class CdnCacheEngine {
    public static String evaluate(String cc, long cachedAt, long now) {
        if (cc == null || cc.contains("no-store")) return "BYPASS";
        long ttl = -1;
        for (var token : cc.toLowerCase().split(",")) {
            var t = token.trim();
            if (t.startsWith("s-maxage=")) ttl = Long.parseLong(t.substring(9));
            else if (ttl == -1 && t.startsWith("max-age=")) ttl = Long.parseLong(t.substring(8));
        }
        return (ttl > 0 && (now - cachedAt) <= ttl) ? "HIT" : "STALE";
    }
}
Kotlin 
// CDN Edge Cache-Control Evaluator in Kotlin
fun evaluateCdn(cc: String?, cachedAt: Long, now: Long): String {
    if (cc == null || "no-store" in cc) return "BYPASS"
    val tokens = cc.lowercase().split(",").map { it.trim() }
    val sMax = tokens.firstOrNull { it.startsWith("s-maxage=") }?.substringAfter("=")?.toLongOrNull()
    val max = tokens.firstOrNull { it.startsWith("max-age=") }?.substringAfter("=")?.toLongOrNull()
    val ttl = sMax ?: max ?: return "STALE"
    return if (now - cachedAt <= ttl) "HIT" else "STALE"
}
