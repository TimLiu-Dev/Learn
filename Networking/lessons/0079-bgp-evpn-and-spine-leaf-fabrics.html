Warm-up · from earlier sessions

Two minutes, from memory, before you read on:

In Session 0047 we saw plain VXLAN tunnel Ethernet frames inside UDP over an L3 IP underlay. Without a control plane, a leaf switch seeing an unknown destination MAC has to flood the frame to every remote VTEP via multicast or head-end replication. How does EVPN (RFC 7432 / 8365) make MAC learning look like BGP routing instead of Ethernet flooding?

When a server plugs into Leaf-1 and sends its first packet/ARP, Leaf-1 learns the MAC/IP locally and immediately advertises an MP-BGP EVPN Type-2 route (binding MAC + IP -> VTEP-1 IP + VNI) to all spines/leaves! Now every leaf already knows exactly which VTEP hosts that MAC in its control plane—no data-plane flood-and-learn across the WAN needed.

1 · Why Data Centers Moved to Clos Spine-Leaf

Legacy 3-tier data centers (Access → Aggregation → Core) relied on Spanning Tree, blocking half the redundant uplinks and starving east-west microservice bandwidth. A 2-tier Clos Spine-Leaf topology connects every Leaf switch to every Spine switch (no leaf-to-leaf, no spine-to-spine) using pure L3 ECMP routing in the underlay:

  • Predictable east-west hops: Any server to any other server is always 1 leaf (same rack) or Leaf → Spine → Leaf (3 hops max).
  • Every link active: Zero STP blocked ports; adding another Spine immediately adds aggregate bisection bandwidth.
  • BGP as the Underlay (RFC 7938): Spines share an ASN (or each Spine/Leaf gets its own private ASN like 65101..) exchanging loopback reachability (/32 VTEP IPs) via fast eBGP/unnumbered BGP.

2 · Essential MP-BGP EVPN Route Types

Think of EVPN (address-family l2vpn evpn) as extending BGP to distribute MAC tables and subnet prefixes cleanly across your VXLAN VTEPs:

EVPN Route TypeWhat It AdvertisesReal-World Job
Type 2 (MAC/IP)MAC (+ optional IP), VNI, NextHop=VTEPReplaces flood-and-learn; populates L2 MAC table & ARP Suppression cache so leaves answer remote ARPs locally!
Type 3 (Inclusive Multicast / IMET)VNI, Originating VTEP IPBuilds the BUM (Broadcast/Unknown-unicast/Multicast) replication list per VNI automatically without PIM multicast underlay.
Type 5 (IP Prefix)IP Prefix / len (e.g. 10.20.0.0/24), L3 VNIAdvertises entire L3 subnets across EVPN tenants/WAN gateways cleanly, independent of individual host Type-2 routes.

3 · Symmetric vs Asymmetric IRB (Inter-VLAN over VXLAN)

What happens when VM-A in VNI 10010 on Leaf-1 talks to VM-B in VNI 10020 on Leaf-2?

  • Asymmetric IRB: Ingress Leaf-1 routes into VNI 10020 locally and encapsulates with VNI 10020; Leaf-2 merely bridges L2 to VM-B. Flaw: Every leaf must hold every VLAN/VNI even if it hosts zero VMs in VNI 10020!
  • Symmetric IRB (Industry Standard): Both leaves route via a shared tenant L3 VNI (Transit VRF VNI, e.g., VNI 50000). Leaf-1 routes VNI 10010 → VRF/L3-VNI 50000, sends VXLAN 50000 across the spine, and Leaf-2 routes L3-VNI 50000 → VNI 10020. Leaves only configure L2 VNIs for subnets actually attached to their local ports!
