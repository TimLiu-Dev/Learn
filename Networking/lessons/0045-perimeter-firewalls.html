Why routing is not security

A router's sole job is to deliver packets to their destination as fast as possible. It asks only: can I route this? It never asks: should this packet be allowed to exist?William R. Cheswick & Steven M. Bellovin, Firewalls and Internet Security: Repelling the Wily Hacker (Addison-Wesley).

To prevent malicious traffic from entering protected networks, organizations place firewalls at perimeter boundaries. Understanding firewall architecture requires examining the critical evolution from static packet filters to stateful connection engines.

Generation 1: Stateless Packet Filters (ACLs)

A Stateless Access Control List (ACL) evaluates each packet in complete isolation. It inspects only static Layer 3 and Layer 4 headers against a list of sequential rules:

access-list 101 permit tcp any host 203.0.113.10 eq 443
access-list 101 deny   ip  any any

The Fatal Flaw of Stateless ACLs

Stateless ACLs have no memory. When an internal employee visits an external website, their browser sends an outbound request: 192.168.1.50:52134 -> 93.184.216.34:443. The external web server replies with destination port 52134 (an ephemeral port).

Because the stateless ACL cannot remember that the internal client initiated the request, it sees the reply as an unknown inbound connection. To allow the web page to load, an engineer is forced to open all ephemeral ports (1024–65535) inbound to the entire world! Attackers easily bypass this filter by firing malicious traffic into any port above 1024.

Generation 2: Stateful Inspection Firewalls

In 1993, Check Point introduced Stateful Inspection (now standard in Linux netfilter/conntrack and BSD/macOS pf). A stateful firewall actively monitors protocol handshakes and maintains a dynamic State Table in memory.See Linux Kernel Documentation: Connection Tracking (conntrack).

How Connection Tracking Works

  1. When an internal host transmits a TCP SYN packet outbound, the firewall inspects the rulebase. If allowed, it creates a temporary state record indexing the 5-tuple, initial sequence numbers, and TCP flags.
  2. When the remote web server responds with a SYN-ACK, the firewall checks its state table first. Because a matching entry exists with correct sequence numbers, the packet is classified as ESTABLISHED and permitted immediately!
  3. Inbound traffic that does not match an existing state entry is treated as a new connection attempt and dropped by default.
  4. When a connection terminates (FIN/RST exchange or idle timeout), the entry is deleted from the table.

Demilitarized Zones (DMZs)

Public-facing servers (web servers, mail relays, public DNS) must accept connections from the untrusted Internet, making them primary targets for compromise. If a hacker breaches a web server that sits on your internal office LAN, the entire corporate network is compromised!

To contain breaches, network engineers build a tri-homed perimeter with a DMZ (Demilitarized Zone):

Traffic Flow DirectionPolicy EnforcementSecurity Rationale
Internet → DMZPermitted (Strictly ports 80/443)Allows public users to reach public web servers.
Internet → Internal LANBlocked (100% Deny)Protects internal workstations and domain controllers.
DMZ → Internal LANBLOCKED (Never Allowed!)If web server is hacked, attacker cannot pivot to internal corporate LAN!
Internal LAN → DMZPermitted (e.g. SSH / DB replication)Allows internal administrators to manage DMZ servers.

Hands-on: Inspecting active firewall state on macOS

  1. View active connection state entries tracked by the macOS Packet Filter (PF): 
    $ sudo pfctl -ss
    Look for: ALL tcp 192.168.1.5:54210 -> 140.82.113.3:443 ESTABLISHED:ESTABLISHED.
  2. Inspect overall packet filter status and dropped packet counters: 
    $ sudo pfctl -si
    Check the State Table: current entries and Counters: match / bad-offset / state-mismatch.
  3. Observe the TCP state timeout values configured in the kernel: 
    $ sudo pfctl -st
    Notice the difference between tcp.opening (30s), tcp.established (86400s / 24h), and tcp.closing (60s)!

Free Recall Practice

From memory: explain why stateless ACLs require dangerous ephemeral port openings, and how stateful inspection solves this. Why must DMZs never initiate connections to the LAN?

Key points to compare against:

  • Stateless ACL vulnerability: Because stateless ACLs have no memory of outbound sessions, inbound return packets arriving on client ephemeral ports (>1023) look like unsolicited new connections. Opening all ephemeral ports inbound allows attackers to probe and attack internal systems.
  • Stateful inspection solution: A stateful firewall records the 5-tuple of outbound requests in an in-memory state table. Return packets matching this table are recognized as part of an established flow and allowed in, keeping unused ephemeral ports closed to unsolicited external traffic.
  • DMZ isolation: If a public-facing web server in the DMZ is compromised, blocking DMZ-to-LAN initiated connections prevents the attacker from pivoting laterally into internal databases, Active Directory, or employee workstations.
