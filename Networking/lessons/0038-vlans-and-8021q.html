Warm-up · from earlier sessions

Two minutes, from memory, before you read on:

What defines a broadcast domain, and how far can an ARP request propagate on an unmanaged switch?

A broadcast domain is the logical area in a network where any device can transmit a broadcast frame directly to all other devices. On an unmanaged switch, every single port belongs to the exact same broadcast domain.

Why broadcast domains must be segmented

If an enterprise connects 2,000 laptops, printers, and servers to a flat Layer 2 network, broadcast traffic (ARP requests, DHCP queries, SSDP discovery) consumes 20% of network capacity, and a single rogue network card emitting broadcast babble halts the entire company.See Kurose & Ross §6.4.4: Virtual Local Area Networks (VLANs).

Furthermore, without segmentation, any guest in the lobby can sniff packets destined for payroll servers. Running separate physical switches for Finance, Engineering, and Guests wastes money and switch ports. Virtual LANs (VLANs) solve this by partitioning switch hardware into isolated logical broadcast domains.

Access Ports vs Trunk Ports

To support VLANs, switch interfaces are classified into two roles:

  • Access Port: Belongs to exactly one VLAN (e.g. VLAN 10). Connected to end devices (laptops, printers, IP phones). The switch strips all VLAN tags before sending frames to the end device; the laptop has no awareness of VLANs.
  • Trunk Port: Connects switches to other switches or routers. A single trunk carries traffic for dozens or hundreds of VLANs simultaneously across a single physical cable by inserting an identification tag into each frame.

The IEEE 802.1Q Frame Format

To distinguish which VLAN a frame belongs to across a trunk link, the IEEE defined the 802.1Q tag: a 4-byte (32-bit) header inserted directly between the Source MAC address and the original EtherType field.IEEE Std 802.1Q: Bridges and Bridged Networks.

Dissecting the 4 Tag Fields

  • TPID (Tag Protocol Identifier, 16 bits): Always set to 0x8100 to notify the receiving switch that an 802.1Q tag follows.
  • PCP (Priority Code Point, 3 bits): Specifies Layer 2 Quality of Service (Class of Service 0 to 7; e.g. voice traffic is marked PCP 5 for low-latency queuing).
  • DEI (Drop Eligible Indicator, 1 bit): Marks frames that can be dropped during switch buffer congestion.
  • VID (VLAN Identifier, 12 bits): Identifies the specific VLAN. With 12 bits, the theoretical maximum is 212 = 4,096 VLANs. Values 0 and 4095 are reserved; usable range is 1 to 4094.

The Native VLAN & VLAN Hopping

By default in 802.1Q, each trunk port has a designated Native VLAN (typically VLAN 1). Frames belonging to the Native VLAN are transmitted across the trunk completely untagged.

This creates a dangerous security vulnerability called Double-Tagging VLAN Hopping:

  1. An attacker on an access port configured with Native VLAN 1 crafts a frame containing two 802.1Q tags: Outer Tag = VLAN 1, Inner Tag = Target VLAN 20 (Payroll).
  2. The first switch receives the frame, strips the outer VLAN 1 tag (because it matches the Native VLAN), and sends the frame across the trunk untagged.
  3. The second switch reads the frame, encounters the inner tag (VLAN 20), and forwards the packet into the private Payroll VLAN!
Production Defense: Never leave Native VLAN set to VLAN 1. Assign the Native VLAN to an unused, dummy VLAN ID (e.g. VLAN 999) that contains no access ports, or force switches to tag Native VLAN traffic across trunks (vlan dot1q tag native).

Hands-on: Dissecting 802.1Q tags in Wireshark

  1. View VLAN and trunk status on an enterprise switch: 
    switch# show interfaces trunk
    Look for: Port: Gi0/1, Mode: on, Encapsulation: 802.1q, and Native vlan: 1.
  2. Verify VLAN member assignments across access ports: 
    switch# show vlan brief
    Confirm which ports belong to VLAN 10 (Engineering) vs VLAN 20 (HR).
  3. Capture packets traversing a trunk interface in Wireshark: 
    $ tshark -i eth0 -Y "vlan" -T fields -e eth.src -e vlan.id -e ip.dst
    Observe the decoded 802.1Q Virtual LAN, PRI: 0, DEI: 0, ID: 10 header inserted right after Ethernet source MAC!

Free Recall Practice

From memory: why does the 802.1Q tag have a 12-bit VID field, and how does double-tagging VLAN hopping exploit the Native VLAN?

Key points to compare against:

  • 12-bit VID limit: 12 bits yield 212 = 4,096 total values, restricting standard Ethernet networks to a maximum of 4,094 usable VLANs (leading to modern cloud overlays like VXLAN).
  • Double-tagging exploitation: An attacker sends a frame with two 802.1Q tags where the outer tag matches the Native VLAN. The first switch strips the outer tag because Native VLAN traffic travels untagged across trunks; the second switch interprets the inner tag and delivers the packet to the victim's VLAN.
