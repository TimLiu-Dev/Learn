Warm-up · from earlier sessions

Two minutes, from memory, before you read on:

What prevents an IP packet from looping forever between misconfigured routers, and does Ethernet have a comparable mechanism?

An IP packet contains a Time-To-Live (TTL) field decremented by each router; when TTL reaches 0, the packet is dropped with an ICMP Time Exceeded. Standard Ethernet frames have zero TTL; a looped frame circles forever until links saturate!

The Layer 2 Loop Catastrophe

Redundancy is essential in enterprise networking: if a core fiber cable gets severed, a backup link must take over instantly. But in a switched Ethernet network, physical redundancy creates physical loops.Radia Perlman, Interconnections: Bridges, Routers, Switches, and Internetworking Protocols (Addison-Wesley).

Because Ethernet frames lack a TTL counter, a single physical loop causes catastrophic failure within fractions of a second:

  • Broadcast Storm: When Host A sends an ARP broadcast (ff:ff:ff:ff:ff:ff), Switch 1 floods it out Port 2 to Switch 2. Switch 2 floods it out Port 3 back to Switch 1. Switch 1 floods it out Port 1 and Port 2 again. Within 100 milliseconds, millions of cloned broadcast frames saturate the switch backplane, dropping line throughput to 0% and crashing switch management CPUs!
  • MAC Table Flapping: Switch CAM tables are updated on every ingress frame. Because copies of the looping frame arrive alternating between Port 1 and Port 2, the switch CAM table thrashes thousands of times per second, corrupting unicast forwarding.

Radia Perlman's Breakthrough: Spanning Tree (802.1D)

In 1985, Dr. Radia Perlman invented the Spanning Tree Protocol (STP) to allow physical redundancy while maintaining a loop-free logical tree:Radia summarized her algorithm in an eight-line poem, Algorhyme: "I think that I shall never see / A graph more lovely than a tree / A tree whose crucial property / Is loop-free connectivity..."

How STP Works: The 3-Step Election

Switches constantly exchange specialized management frames called BPDUs (Bridge Protocol Data Units) every 2 seconds to execute a deterministic three-step algorithm:

Step 1: Elect One Root Bridge

Every switch has a Bridge ID (BID) = Priority (16 bits) + MAC Address (48 bits). By default, priority is 32768. The switch with the lowest Bridge ID wins and becomes the Root Bridge (the root of the tree).

Step 2: Elect Root Ports (RP)

Every non-root switch chooses exactly one Root Port: the physical port with the lowest cumulative Root Path Cost to reach the Root Bridge (10 Gbps = cost 2, 1 Gbps = cost 4, 100 Mbps = cost 19). Tie-breakers: lowest sender Bridge ID, then lowest sender Port ID.

Step 3: Elect Designated Ports (DP) & Block the Rest

On every individual cable/segment, the switch with the lowest path cost to the root places its port into the Designated Port (DP) role (forwarding). Any remaining port is placed into the Alternate / Blocked state. Blocked ports drop all user frames while silently listening for BPDUs; if an active link fails, the blocked port wakes up!

802.1D Slow Convergence vs RSTP (802.1w)

Original 802.1D transitions ports through strict safety timers to avoid temporary loops:

  • Blocking -> Listening (15s) -> Learning (15s) -> Forwarding. Total failover time = 30 to 50 seconds! For modern applications, a 50-second freeze drops all voice calls and database connections.

Rapid Spanning Tree Protocol (RSTP / 802.1w)

RSTP replaces slow timers with an active Proposal / Agreement handshake: switches negotiate directly with neighbors and unblock redundant links in under 1 second!

  • PortFast / Edge Ports: Applied to access ports connected directly to PCs or servers. Bypasses listening/learning to transition immediately to forwarding in 0 seconds.
  • BPDU Guard: A critical security defense on edge ports. If someone accidentally plugs an unmanaged switch or brings a rogue laptop running STP into an access port, BPDU Guard immediately disables the port (err-disabled) to prevent an external device from hijacking the Root Bridge!

Hands-on: Inspecting STP topology and Root Bridge

  1. View Spanning Tree topology details on a switch: 
    switch# show spanning-tree
    Look for: Root ID: Priority 4096, Address 0001.64a0.1234, and check if it says This bridge is the root!
  2. Inspect the role and state of each physical port: 
    switch# show spanning-tree interface GigabitEthernet0/1
    Verify whether the port role is Root (FWD), Desg (FWD), or Altn (BLK).
  3. Enable PortFast and BPDU Guard on all edge access ports: 
    switch(config)# spanning-tree portfast default
switch(config)# spanning-tree portfast bpduguard default
    Verify that rogue switches plugged into office cubicle wall jacks are safely blocked!

Free Recall Practice

From memory: explain why Layer 2 loops cause broadcast storms while IP packets do not. How does STP break the loop?

Key points to compare against:

  • Why L2 loops storm: IP packets possess a Time-To-Live (TTL) field decremented by routers, expiring safely if looped. Ethernet frames lack a TTL; broadcast frames replicate indefinitely across looping links until link bandwidth and switch CPUs saturate.
  • How STP breaks the loop: Switches elect a single Root Bridge via the lowest Bridge ID, determine the shortest root path cost for all other switches, and selectively place redundant interfaces into an Alternate/Blocked state, maintaining physical redundancy while ensuring a single loop-free logical forwarding tree.
