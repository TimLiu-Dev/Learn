Warm-up · from earlier sessions

Two minutes, from memory, before you read on:

Why does Voice over IP (VoIP) use UDP instead of TCP, and what is jitter?

VoIP uses UDP because lost audio packets cannot be retransmitted in real-time (retransmissions arrive too late to hear). Jitter is the variation in packet arrival delay; high jitter causes robotic audio breakup when jitter buffers deplete.

Why Best-Effort networking breaks real-time apps

By default, the Internet operates on a Best-Effort model. Every router forwards packets using FIFO (First-In, First-Out): an interactive Zoom audio packet sits in line behind a massive 50 MB database backup.RFC 2474: Definition of the Differentiated Services Field (DiffServ). K. Nichols et al. (1998).

When the router's egress interface buffer fills, it executes tail drop: it drops every arriving packet indiscriminately, dropping voice calls while leaving file downloads to slowly recover. Quality of Service (QoS) provides routers with the intelligence to identify, prioritize, and guarantee bandwidth for mission-critical traffic.

The DiffServ Architecture: Classification & Marking

The modern scalable standard is Differentiated Services (DiffServ). DiffServ separates QoS into two steps:

  • Edge Classification: Edge routers or phones classify traffic and stamp a code point into the packet header.
  • Core Per-Hop Behavior (PHB): High-speed backbone routers do not re-inspect deep packet payloads; they simply read the header marking and schedule packets into appropriate hardware queues.

The DSCP Field (IPv4 TOS / IPv6 Traffic Class)

In the IP header, 6 bits are allocated for the Differentiated Services Code Point (DSCP), providing 64 distinct traffic classes (the remaining 2 bits are used for Explicit Congestion Notification / ECN):

Queuing Algorithms: How Routers Prioritize

When an egress interface experiences congestion, arriving packets enter hardware queues scheduled by algorithms:

  • Priority Queuing (PQ): A strict priority queue is emptied completely before any lower queue receives a single cycle. Danger: high-priority traffic can completely starve regular data!
  • Class-Based Weighted Fair Queuing (CBWFQ): Guarantees a minimum percentage of interface bandwidth to each user-defined class (e.g. 30% for Business Apps, 20% for Web).
  • Low Latency Queuing (LLQ): The enterprise industry standard for converged voice/video networks. Combines a strict priority queue for VoIP (DSCP EF) with CBWFQ for other queues. To prevent voice from starving regular data, the voice queue is enforced with a strict rate limiter (policer).

Congestion Avoidance: WRED

When buffers fill, standard tail drop drops packets from dozens of TCP connections simultaneously. All those TCP senders detect loss at the exact same moment, cut their congestion windows in half simultaneously, and throttle their throughput at the same instant (TCP Global Synchronization).Sally Floyd & Van Jacobson, "Random Early Detection Gateways for Congestion Avoidance" (IEEE/ACM Transactions on Networking).

WRED (Weighted Random Early Detection) solves this: as the buffer queue begins to fill, the router probabilistically drops occasional random TCP packets. Senders throttle gradually and at staggered intervals, keeping buffer usage stable and maximizing link throughput.

Traffic Conditioning: Policing vs Shaping

When traffic exceeds an allocated contract bandwidth, routers enforce limits using one of two techniques:

  • Traffic Policing: Enforces a hard ceiling. Packets exceeding the Committed Information Rate (CIR) are dropped immediately or re-marked to a lower DSCP. Used by ISPs at ingress customer handoffs.
  • Traffic Shaping: Buffers burst traffic in memory and paces packet transmission out over time using the Token Bucket algorithm. Smooths out traffic to prevent egress carrier packet drops at the expense of slight queuing delay.

Hands-on: Inspecting DSCP markings in Wireshark

  1. Capture packets and filter for Expedited Forwarding (VoIP audio) DSCP markings: 
    $ tshark -i any -Y "ip.dsfield.dscp == 46" -T fields -e ip.src -e ip.dst -e ip.dsfield.dscp
    Verify that packets carry 0x2e (decimal 46, Expedited Forwarding).
  2. Send test traffic with explicit DSCP marking using ping: 
    $ ping -c 4 -Q 184 127.0.0.1
    (184 is 46 << 2 to align with the 6-bit DSCP offset in the TOS byte!).
  3. View QoS queue drops on an enterprise switch interface: 
    switch# show policy-map interface GigabitEthernet0/1
    Inspect Class-map: VOICE-EF (match dscp ef) and check 0 packets dropped vs Class-map: class-default (tail drops: 142).

Free Recall Practice

From memory: why is Low Latency Queuing (LLQ) preferred for VoIP networks? What is the difference between traffic policing and traffic shaping?

Key points to compare against:

  • Low Latency Queuing (LLQ): LLQ provides a strict priority queue for delay-sensitive VoIP (DSCP EF) so audio packets jump to the head of the transmission line, while enforcing an explicit bandwidth policer on the voice queue to prevent it from starving lower-priority business data queues.
  • Policing vs Shaping: A policer strictly enforces a rate limit by immediately dropping (or down-marking) packets that exceed the committed rate, causing TCP backoff. A shaper buffers burst packets in memory queues and paces them out smoothly over time, preventing loss at the cost of slight queuing latency.
