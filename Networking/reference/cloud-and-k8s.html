1. Cloud VPC Architecture & IP Reservation Math

AWS Subnet 5 Reserved IP Addresses

OffsetAssigned Role
.0Network address (base of CIDR block)
.1VPC Local Router (default gateway for subnet)
.2Amazon Provided DNS (Route 53 Resolver)
.3AWS internal future reservation
.255Network broadcast address

Usable Host Formula: $\text{Usable IPs} = 2^{(32 - \text{prefix})} - 5$. A /24 has $256 - 5 = 251$ usable hosts; a /28 has $16 - 5 = 11$ usable hosts.

Cloud Subnet Tiers

  • Public Subnet: Route table has 0.0.0.0/0 -> igw-xxxx. Hosts can hold public IPv4 IPs and communicate bidirectionally with Internet.
  • Private App Subnet: Route table has 0.0.0.0/0 -> nat-xxxx. Instances have only private RFC 1918 IPs; can initiate outbound traffic, external incoming blocked.
  • Isolated Database Subnet: No route table entry for 0.0.0.0/0. Zero external Internet egress or ingress.

4. The Kubernetes Network Model & CNI Architecture

Fundamental K8s Networking Principles

  • Every Pod gets its own real IP address.
  • Pods on any node can communicate with all Pods on all other nodes without NAT.
  • Agents on a node (kubelet, system daemons) can communicate with all Pods on that node.
  • Containers inside the same Pod share the same network namespace and communicate over localhost (127.0.0.1).

CNI Architecture: Overlay vs Underlay

CNI TypeExamplesData Path Mechanism
Overlay CNIFlannel, Calico (VXLAN/Geneve)Wraps Pod packets inside host UDP datagrams (adds 50B overhead; requires reducing Pod MTU to 1450). Pod IPs hidden from physical network.
Underlay / Native CNIAWS VPC CNI, Azure CNI, Cilium NativeAssigns real VPC secondary private IPs directly to Pod ENIs. Zero encapsulation overhead; directly routable across VPC and Direct Connect.

5. Kubernetes Services & eBPF Datapath

ComponentMechanismPerformance Characteristics
ClusterIP (kube-proxy iptables)ClusterIP is a virtual ghost IP. kube-proxy writes iptables chains using statistic mode random (probability $1/N$) to DNAT target to Pod IP.$O(N)$ sequential rule evaluation. Noticeable CPU overhead and latency spikes when cluster scales beyond 5,000 services.
ClusterIP (kube-proxy IPVS)Uses Linux kernel IP Virtual Server (IPVS) hash tables to rewrite destination IPs.$O(1)$ constant-time lookup. Scales smoothly to tens of thousands of services.
eBPF / Cilium DatapathAttaches eBPF bytecode programs directly to socket layer (sockops) and driver (XDP), bypassing netfilter iptables entirely.$O(1)$ BPF hash map lookups. Extreme throughput, native L7 observability, and line-rate DDoS filtering in the network driver.
Service Mesh (Envoy Sidecars)Sidecar proxy injected in every Pod. Intercepts traffic via iptables loopback redirect; enforces mTLS, SPIFFE identity, and canary routing.Adds "Sidecar Tax" (~1–3 ms latency and extra memory per Pod). Modern alternative: Ambient mesh / eBPF daemonset proxying.
