Rules

  • Sending: top down; each layer treats what it's handed as opaque payload and puts its header in front. The link layer also adds a trailer (FCS).
  • Receiving: bottom up; each layer reads and strips its own header: Ethernet → IP → TCP → message to the app.
  • Each layer serves the one above and uses only the one below. Payoff: swap Wi-Fi for Ethernet and nothing above changes. Cost: header overhead on every packet.
  • Fixed sizes taught so far: Ethernet header 14 B (+ 4 B FCS, payload 46–1500 B) · IPv4 header 20 B (IHL 5) · IPv6 header 40 B · ICMP header 8 B.

Packets and the four delays

Session 1 · HPBN ch. 1 · Systems Approach §1.5

Packet
Header (addresses, bookkeeping) + payload (a slice of your data). At most about 1,500 bytes on Ethernet/Wi-Fi.
Circuit switching
Reserves capacity end to end for a whole call, even in silence (old telephone network).
Packet switching
Links shared on demand, packet by packet; suits bursty traffic. Price: no guaranteed capacity, so packets queue, and a full queue drops them (loss). Recovery is TCP's job, not the network's.
Store-and-forward
A router receives the whole packet before sending it on.

Worked numbers

  • Minimum RTT ≈ 2 × distance ÷ 200 km/ms. New York–Sydney ≈ 16,000 km → ≥ 160 ms. Real cables aren't great circles, so real RTTs are higher.
  • 1,500 B on 100 Mbps: 12,000 bits ÷ 10⁸ bits/s = 0.12 ms transmission.
  • No engineering beats propagation; better hardware only cuts the other three.

Latency, bandwidth, throughput

Session 1 · HPBN ch. 1

Latency
The pipe's length: time for one bit to get from end to end. Usually one-way, in ms.
RTT
Round-trip time: there and back. Every request/response costs ≥ 1 RTT. ping reports RTT.
Bandwidth
The pipe's width: a link's capacity in bits/s.
Throughput
The rate actually achieved end to end. ≤ the slowest link on the path (the bottleneck), usually lower.

Bits vs bytes: link speeds are bits/s (Mbps), file sizes bytes (MB). Divide by 8: 100 Mbps ≈ 12.5 MB/s at most.

Which problem is it? Many small sequential round trips across an ocean → latency-bound (batch them; a faster plan won't help). One huge transfer → bandwidth-bound.

Reading ping: use min of min/avg/max/stddev for distance: it's the run with least queuing.
