3. Flow Control vs Congestion Control

Flow Control (Receiver Buffer Protection)

Governed by the Receiver Window (rwnd) advertised in TCP headers. Senders strictly respect W = min(cwnd, rwnd). When receiver buffer fills, rwnd = 0 triggers ZeroWindow Probes.

Congestion Control (Network Protection)

Governed by the Congestion Window (cwnd) tracked in sender memory.

  • Slow Start: Exponential growth ($cwnd \mathrel{+}= 1\text{ MSS}$ per ACK, doubling every RTT) until ssthresh.
  • Congestion Avoidance: Linear increase ($cwnd \mathrel{+}= 1\text{ MSS}$ per RTT).
  • Fast Retransmit / Fast Recovery: Triggered by 3 duplicate ACKs (4 total), avoiding full RTO timeout stalls.
  • Modern BBR: Replaces loss-based CUBIC with model-based pacing matching bottleneck bandwidth and min-RTT.

4. Essential Senior Engineer Socket Options

OptionLevelDefaultWhen to Enable in Production
TCP_NODELAYIPPROTO_TCPfalseAlways for microservices/APIs: Disables Nagle's algorithm, eliminating 40–200 ms latency spikes caused by Delayed ACKs on small request/response payloads.
SO_REUSEADDRSOL_SOCKETfalseAlways for server daemons: Allows fast server restarts by rebinding to local port even if previous sockets remain in TIME_WAIT.
SO_REUSEPORTSOL_SOCKETfalseHigh-concurrency servers (Netty, Nginx): Enables multi-threaded processes to bind the exact same port; kernel automatically distributes connections with hardware RSS load balancing.
SO_KEEPALIVESOL_SOCKETfalseDetects dead peers over idle connections. Warning: Default Linux probe interval is 2 hours (7200s); AWS NAT Gateway and NLB drop idle connections after 350s! Tune tcp_keepalive_time to 60s.
SO_RCVBUF / SO_SNDBUFSOL_SOCKETKernel auto-tuningSocket receive and send buffers. Best practice: Rely on Linux TCP autotuning (tcp_rmem, tcp_wmem) rather than manual hardcoding.
