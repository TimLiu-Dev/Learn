The Repository Map & PageRank: Graph Centrality for Codebase Navigation

When an AI coding agent is dropped into an unfamiliar 100,000-line codebase, how does it know which files matter without blowing its token budget? Dumping the entire repo into prompt context wastes millions of tokens and triggers "lost-in-the-middle" attention degradation. Merely providing a file directory tree lists paths without revealing symbols or connections. In this lesson, we study the Repository Map—pioneered by Aider—which builds a global symbol reference graph and calculates PageRank centrality under strict token budgets.

Primary Source & Architecture Reference

"Building a Better Repo Map with Tree-sitter and PageRank" — Paul Gauthier (Aider Architecture, 2023–2025).

Explore Aider Repo Map Architecture → • Core Insight: Codebases are directed graphs where definitions (classes, functions) are connected by references (calls, imports, inheritance). Running PageRank over this symbol graph highlights architectural crossroads. Greedy budget packing then fits the most critical interfaces into a strict token window (e.g. 1,024 tokens).

1. The Code Perception Dilemma

Consider an agent tasked with: "Resolve intermittent JWT token verification failures during distributed sync." How should the runtime frame the codebase context?

Codebase Perception Strategies Token Cost vs. Structural Precision
STRATEGY A

Full Text Dump

Dumps 100+ raw source files into context. Consumes 150,000+ tokens per turn. Prohibitive latency, catastrophic costs, and severe attention dilution.

STRATEGY B

Raw Directory Tree

Outputs find . or tree. Consumes few tokens (~300), but conveys zero insight into whether utils.py houses 500 lines of JWT crypto or string helpers.

STRATEGY C

PageRank Repo Map

Extracts definitions & references via Tree-sitter AST, scores symbol centrality with PageRank, and greedily packs signatures into a strict 1,024-token budget.

RESULT

Architectural Clarity

Agent instantly identifies central models, utility crossroads, and entrypoint routes, while leaving 98% of the context window free for multi-turn reasoning.

2. Building the Symbol Reference Graph

The repository map is powered by two fundamental AST concepts:

  • Definitions: Named identifiers established by the programmer (e.g., class UserSession:, def refresh_token():).
  • References: Identifiers invoked, instantiated, or imported elsewhere (e.g., session = UserSession(), refresh_token(tok)).

We model this as a directed graph G = (V, E), where each node v ∈ V is a symbol. If function A calls or imports symbol B, we add a directed reference edge A → B. We then compute PageRank: 

PR(u) = (1 - d) / N + d * SUM_{v in In(u)} [ PR(v) / OutDegree(v) ]

Symbols that are invoked by many other critical modules (such as core database connections, auth handlers, and dispatchers) naturally receive the highest PageRank scores.

3. Token-Budgeted Greedy Packing

After scoring all symbols, we cannot simply emit the entire graph. We define an explicit token budget (e.g., 1,024 tokens). We sort symbols descending by PageRank score and greedily include signatures until the budget is exhausted. Finally, we group selected signatures by file path to produce an intuitive skeleton overview.
