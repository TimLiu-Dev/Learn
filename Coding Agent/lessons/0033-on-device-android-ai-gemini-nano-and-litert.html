On-Device & Hybrid Mobile AI: Android AICore (Gemini Nano) & LiteRT

Most pure-web AI applicants only know how to call a remote HTTP endpoint. As an Android-rooted Senior AI Engineer in 2027, you design hybrid edge-to-cloud AI architectures: routing PII-sensitive, offline, or low-latency tasks onto on-device NPUs via Android AICore (Gemini Nano) and LiteRT, escalating complex reasoning selectively to frontier cloud models.

1. Android On-Device Runtime Choices: AICore vs. LiteRT

  • Android AICore + Gemini Nano (System Service): OS-managed shared foundation model on supported flagship hardware (zero app APK bloat, automatic NPU/TPU delegation, LoRA adapter support for narrow tasks like summarization/classification/local tool calls).
  • LiteRT / LiteRT-LM (Formerly TFLite, Bring-Your-Own-Model): Bundle quantized INT4/INT8 open-weights SLMs (e.g., Gemma) inside your app or feature module with explicit NPU/GPU/CPU delegate fallback when device OEM lacks AICore or custom domain weights are mandatory.

2. Hardware Constraints Senior Mobile AI Engineers Enforce

Running a 2–4B quantized model locally consumes heavy unified RAM and sustained SoC power. Production routers always check available memory headroom, thermal throttling state (THERMAL_SEVERE should defer or offload to cloud rather than draining battery), and network state before dispatching inference.
