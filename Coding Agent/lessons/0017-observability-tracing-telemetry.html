Observability & Telemetry: OpenTelemetry Spans, Token Attribution, & Loop Detection

Autonomous coding agents that execute multi-turn loops without distributed tracing are catastrophic black boxes. When an agent enters an infinite retry loop or silently burns \$50 in token thrashing, traditional flat stdout logging fails. Production agent harnesses implement OpenTelemetry (OTel) hierarchical spans, token cost attribution, and automated loop circuit breakers.

Primary Source & Architecture Reference

"OpenTelemetry Semantic Conventions for Generative AI Systems" — Cloud Native Computing Foundation (CNCF, 2024–2025) & "Arize Phoenix OpenInference Agent Tracing Specification".

CNCF OpenTelemetry GenAI Semantic Conventions → • Core Insight: Modeling agent workflows as hierarchical directed acyclic graphs of spans—linking parent agent sessions, intermediate model calls, and discrete tool executions with typed attributes—enables granular latency profiling, per-task cost attribution, and real-time loop detection.

1. The Observability Blindspot: Why Flat Logs Fail

Traditional logging prints unstructured lines to terminal stdout: [INFO] Calling tool read_file(auth.py). In production multi-agent systems, flat logs collapse under three critical challenges:

  • Runaway Infinite Tool Loops: If a model receives an ambiguous tool error (e.g., "Permission Denied") and repeats the exact same tool call 40 times, stdout fills with repetitive text while token costs compound silently until hard timeouts hit.
  • Untracked Cost Attribution: In a multi-agent swarm with an Orchestrator, Planner, and 3 Coders, flat logs cannot tell you which subagent or specific step consumed 85% of your token budget.
  • Asynchronous Distributed Latency: When tool executions invoke remote compiler containers, AST parsers, or git operations, debugging where wall-clock time was lost requires hierarchical span parent-child relationships.

2. OpenTelemetry Hierarchical Span Architecture

OpenTelemetry structures an agent run into a nested hierarchy of Spans. Each span captures start/end timestamps, input/output attributes, status codes, and events:

Distributed Trace Tree for Coding Agent Run Trace ID: trace_7f9b841a • Total Latency: 4.82s • Cost: $0.048
ROOT SPAN

agent.workflow

Captures top-level user objective, total duration, overall status, and cumulative tokens consumed.

CHILD SPAN 1

llm.generation

Attributes: gen_ai.system="anthropic", gen_ai.usage.input_tokens=1420, output_tokens=310.

CHILD SPAN 2

tool.execution

Attributes: tool.name="ast_grep", tool.arguments={"query": "def verify"}, exit_code=0.

CHILD SPAN 3

llm.generation

Second reasoning step observing tool output and synthesizing the final unified diff patch.

// OpenTelemetry Standard GenAI Attributes

  "agent.step.index": 3,
  "agent.persona": "CoderWorker-01"
}

4. Algorithmic Loop Detection & Safety Circuit Breakers

To prevent catastrophic infinite tool-call ping-pongs, the telemetry tracer acts as a safety circuit breaker.

The tracer maintains an action history of serialized signatures: (tool_name, hash(arguments)). When an agent repeats the identical action signature $N \ge 3$ consecutive times, the tracer trips a circuit breaker: 

// ❌ DETECTING INFINITE REPETITIVE ACTION LOOP:
Turn 12: read_file[path="src/config.py"] -> Observation: [content]
Turn 13: read_file[path="src/config.py"] -> Observation: [content]
Turn 14: read_file[path="src/config.py"] -> CIRCUIT BREAKER TRIPPED!

// Telemetry Engine intercepts control, aborts the runaway loop,
// and injects an intervention observation:
"Execution Warning: Identical tool call repeated 3 times. You are stuck in a loop. Re-evaluate your approach or state your roadblock."
