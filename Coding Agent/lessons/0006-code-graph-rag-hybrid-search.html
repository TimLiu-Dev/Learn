Code Graph RAG & Hybrid Search: Fusing AST Graphs with BM25 & Dense Vectors

Standard document RAG applications rely exclusively on dense vector embeddings (cosine distance across 1,536-dimensional vector spaces). In production software repositories, pure dense retrieval fails catastrophically: it conflates token_v1 with token_v2, cannot match exact variable names or UUIDs, and remains blind to AST call hierarchies. Modern coding agents deploy Code Graph RAG & Hybrid Search: fusing sparse lexical search (BM25), dense semantic vectors, and AST call-graph hops using Reciprocal Rank Fusion (RRF).

Primary Source & Architecture Reference

"Benchmarking Large Language Models for Code Retrieval: Dense vs Sparse vs Graph-Augmented Search" — Microsoft Research & Cursor Search Architecture (2024–2025).

Read the Code Retrieval Benchmark on arXiv → • Core Insight: Source code requires dual-precision perception. Sparse lexical search (BM25) guarantees exact token and identifier precision, dense embeddings capture high-level conceptual intent, and AST graph traversals fetch connected caller/callee context. Reciprocal Rank Fusion (RRF) combines these disparate distributions without brittle calibration.

1. The Dense Embedding Failure Mode in Code

Vector embedding models project text into continuous latent manifolds where semantic synonyms are pulled close together. In natural language prose, mapping "automobile" near "car" is ideal. In source code, mapping AUTH_V1_LEGACY near AUTH_V2_SECURE is disastrous:

Retrieval Modality Comparison Exact Identifier vs. Conceptual Semantics
SPARSE (BM25)

Exact Lexical Match

Excels at exact identifier lookups: AUTH_COOKIE_PREFIX_V2, specific error codes, or function names. Fails when natural language queries lack keyword overlap.

DENSE (VECTOR)

Semantic Similarity

Excels at conceptual queries: "Where do we validate incoming payload schemas?" matches verify_request_body() even with zero word overlap. Fails on exact symbol diffs.

GRAPH (AST)

Call-Graph Proximity

Traverses 1-hop and 2-hop caller-callee hierarchies. If the agent inspects login(), the graph immediately surfaces hash_password() and generate_session().

HYBRID FUSION

Reciprocal Rank Fusion

Merges ranking positions across all three retrieval channels into a calibrated, unified candidate list with zero score-normalization distortion.

2. Why Linear Normalization Fails & Why RRF Wins

Why can't we simply calculate CombinedScore = 0.5 * BM25 + 0.5 * CosineSimilarity?

Because their numerical distributions are fundamentally incompatible. BM25 produces unbounded positive log-odds scores (e.g. $4.2$ to $38.7$), cosine similarities range from $-1.0$ to $+1.0$, and graph hops are discrete integers ($1, 2, 3$). Attempting min-max normalization shifts wildly whenever a single outlier document appears.

Reciprocal Rank Fusion (RRF) sidesteps numerical scores entirely by operating purely on positional rank orders: 

RRF_Score(d) = SUM_{m in Systems} [ 1.0 / (k + Rank_m(d)) ]

where $k$ is a smoothing constant (standardized at $60$). A document ranked #1 across all 3 systems receives a score of $\frac{3}{61} \approx 0.0491$, dominating any document that appears high in only one list.
