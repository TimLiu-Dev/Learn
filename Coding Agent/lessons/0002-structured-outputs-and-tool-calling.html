Structured Tool Calling & JSON Schemas: Deterministic Function Invocations

In Lesson 0001, we parsed tool calls with simple regex brackets like Action: tool[arg]. In production codebases, this brittle string matching collapses when passing multi-line code diffs, file lists, or nested configurations. Here, we transition to typed JSON Schemas and native function calling.

Primary Source & Architecture Reference

"Anthropic Tool Use & OpenAI Function Calling Protocols" — Structured schema definitions and constrained decoding architectures (2023–2025).

Anthropic Tool Use Documentation → • Core Insight: Constrained token decoding enforces valid JSON syntax at the logit level, guaranteeing that arguments conform to the JSON schema without regex failures.

1. The Brittle String Trap vs. Constrained Schemas

Consider what happens when an agent wants to perform a surgical file edit replacing 15 lines of Python code containing brackets, quotes, and newlines: 

// ❌ REGEX FAILURE MODE (BRITTLE STRING SPLITTING):
Action: edit_file[path="auth.py", code="def verify(token): return token['sub']"]
// Parsing fails if the code itself contains brackets [ ] or escaped quotes!

Modern inference engines solve this using Context-Free Grammar (CFG) masking and JSON Schema validation. The model is constrained during token sampling so it physically cannot emit tokens that violate the JSON schema.

2. Anatomy of a Production Tool Envelope

A tool definition consists of a strict JSON schema describing parameters, types, descriptions, and required fields: 

TOOL_DEFINITIONS = [
    {
        "name": "edit_file_block",
        "description": "Surgically replaces an exact text block within a file with new content.",
        "parameters": {
            "type": "object",
            "properties": {
                "file_path": {
                    "type": "string",
                    "description": "Relative file path (e.g. 'src/auth/jwt.py')"
                },
                "target_block": {
                    "type": "string",
                    "description": "The exact original string block to locate and replace"
                },
                "replacement_block": {
                    "type": "string",
                    "description": "The new replacement string block"
                }
            },
            "required": ["file_path", "target_block", "replacement_block"]
        }
    }
]
