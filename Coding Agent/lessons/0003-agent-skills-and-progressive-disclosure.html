Module 1: Foundations Est. 18 Mins Architecture Standard

Agent Skills & Progressive Disclosure: Dynamic Capabilities without Context Bloat

As coding agents evolve from simple scripts into enterprise engineering partners, they accumulate dozens of specialized capabilities: Docker deployments, AST refactoring, database migrations, and cloud provisioning. Dumping every tool definition and multi-page prompt into the context window causes catastrophic token bloat, degrades model attention, and triggers tool hallucinations. In this lesson, we architect Dynamic Agent Skills and Progressive Disclosure.

Primary Source & Architecture Reference

"Antigravity Agent Skills & Claude Code Dynamic Tool Systems" — Modular Capability Architecture & Progressive Disclosure Protocols (2024–2026).

Explore Agent Skills Open Standard (agentskills.io) → • Core Insight: Decoupling skill discovery from full instruction disclosure preserves context. Presenting lightweight metadata (names, descriptions, triggers) reduces baseline prompt tokens by 95%, while full executable schemas and detailed guidance are injected on-demand only when activated.

1. The Monolithic Tool Trap vs. Progressive Disclosure

In early agent implementations, developers registered every possible tool directly into the initial system prompt. Consider an agent equipped with 40 domain tools across Git, Docker, Kubernetes, SQL, and AWS:

Context Architecture Comparison Token Budget & Attention Mechanics
NAIVE PATTERN

Monolithic Tool Injection

40 full JSON schemas & docs dumped into system prompt on turn 1. Consumes 35,000+ tokens before the user even types a word. High latency, high cost, and frequent tool selection hallucination.

TIER 1 DISCLOSURE

Metadata Index (Catalog)

System prompt receives only a compact catalog of skills: name, 1-line description, and trigger keywords. Consumes under 400 tokens across 40 capabilities.

TIER 2 DISCLOSURE

On-Demand Activation

When user prompt matches a skill (e.g. /docker or "build image"), runtime dynamically loads the full SKILL.md instructions and activates its dedicated tool schemas.

RESULT

Context Efficiency

90%+ token reduction on idle turns. Zero tool distraction. Precision jumps from 68% to 99% on complex multi-turn workflows.

2. Anatomy of the SKILL.md Specification

Production coding agents standardize capabilities as self-contained directories containing a SKILL.md document with structured YAML frontmatter and detailed behavioral markdown: 

---
name: docker-container-manager
description: Builds, inspects, and troubleshoots Dockerfiles and containerized dev environments.
triggers:
  - "docker"
  - "dockerfile"
  - "container"
  - "compose"
tools:
  - docker_build
  - docker_run
  - docker_inspect
---

# Docker Container Manager Skill

## Operational Directives
1. Never run `docker run` without memory and CPU limits in dev mode.
2. Inspect `.dockerignore` before initiating builds to avoid sending large git histories to daemon.
3. If build fails on missing dependency, analyze intermediate build layer logs before restarting.

## Common Remediation Commands
```bash
docker build --no-cache -t app:debug .
docker inspect --format='{{range .State.Health.Log}}{{.Output}}{{end}}' app-container
```

3. The Dynamic Indexer & On-Demand Loader

The agent runtime maintains a SkillRegistry. During bootstrap, it scans workspace and global directories (e.g. .gemini/skills/), parses frontmatter, and constructs a compact indexing prompt. When a query is analyzed or a slash-command is invoked, the full instructions are fetched into working memory.

4. Hands-On Interactive Code Practice

Your Challenge: Implement SkillRegistry. You must build:

  • register_skill(raw_content): Extracts YAML frontmatter attributes (name, description, triggers, tools) and body markdown into self.skills.
  • generate_compact_index(): Produces a compact, bulleted list of - {name}: {description} for system prompt injection.
  • match_skills(user_query): Identifies which skills match the user's intent based on skill names and triggers.
  • load_skill_instructions(skill_name): Returns the full instruction body for dynamic injection.
