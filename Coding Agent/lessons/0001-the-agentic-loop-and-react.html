The Agentic Loop & ReAct: From Next-Token Prediction to Autonomous Execution

Traditional LLMs generate tokens in a single forward pass without environmental verification. Autonomous coding agents, by contrast, operate inside a closed feedback loop: formulating verbal hypotheses, invoking concrete development tools, observing terminal output, and self-correcting.

Primary Source & Foundation Paper

"ReAct: Synergizing Reasoning and Acting in Language Models" — Shunyu Yao, Jeffrey Zhao, Dian Yu, Nan Du, Izhak Shafran, Karthik Narasimhan, Yuan Cao (Princeton University & Google Brain, ICLR 2023).

Read paper on arXiv → • Core Insight: Interleaving reasoning traces ("Thought") with domain-specific actions ("Action") reduces hallucination cascades and enables dynamic trajectory recovery.

1. Next-Token Predictor vs. Autonomous State Machine

Standard chatbot applications treat language models as stateless text transducers: Output = LLM(Input). If the model hallucinates a non-existent API or makes an off-by-one error, the user receives broken code.

An AI Coding Agent wraps the LLM inside a continuous state machine:

Architectural State Diagram Deterministic Transition Protocol
STEP 1

Thought (Reasoning)

Model articulates reasoning: "I need to inspect auth.py line 42 to check why the token expiry check raises ValueError."

STEP 2

Action (Tool Call)

Model issues a structured tool call: read_file_range[path="auth.py", start=40, end=50].

STEP 3

Halt & Environment Exec

Inference halts on stop sequence Observation:. The sandbox environment executes the tool safely.

STEP 4

Observation & Loop

Real tool output is injected into the context window: Observation: [code lines...]. The cycle repeats until resolution.

2. The Critical Mechanics: Stop Sequences & Hallucination Prevention

Why can't we let the LLM generate the full trajectory in one go? Because language models are trained to predict plausible text. If left unchecked, the model will hallucinate the tool output: 

// ❌ UNCONSTRAINED GENERATION (FAILURE MODE):
Thought: I should run pytest to see if my fix worked.
Action: run_pytest[test_auth.py]
Observation: 1 passed in 0.04s.   <-- HALLUCINATED! Tests never actually ran!
Final Answer: Bug is completely resolved.

To prevent this, production coding agent runtimes configure Stop Sequences (e.g., ["\nObservation:", "Observation:"]). As soon as the LLM emits Action: ...\nObservation:, the generation server cuts token emission immediately. The runtime dispatches the real command in a sandbox and injects genuine stdout.

3. Production-Grade Reference Implementation

Here is how the foundational ReAct loop is implemented cleanly in Python without bloated frameworks: 

import re

class ReActAgent:
    def __init__(self, llm_client, tools):
        self.llm = llm_client
        self.tools = tools
        self.history = []

    def run(self, user_goal: str, max_steps: int = 10) -> str:
        prompt = f"Goal: {user_goal}\nSolve using Thought, Action, and Observation.\n"
        self.history.append({"role": "user", "content": prompt})

        for step in range(max_steps):
            # Model generates up to stop sequence 'Observation:'
            response = self.llm.generate(
                messages=self.history,
                stop_sequences=["Observation:", "Observation:\n"]
            )
            self.history.append({"role": "assistant", "content": response})

            # Check for termination condition
            if "Final Answer:" in response:
                return response.split("Final Answer:")[-1].strip()

            # Parse Action: tool_name[arguments]
            match = re.search(r"Action:\s*([a-zA-Z0-9_]+)\[(.*?)\]", response)
            if not match:
                observation = "Error: Invalid action format. Use Action: tool_name[args]."
            else:
                tool_name, tool_arg = match.groups()
                tool_fn = self.tools.get(tool_name)
                if not tool_fn:
                    observation = f"Error: Unknown tool '{tool_name}'."
                else:
                    try:
                        observation = tool_fn(tool_arg)
                    except Exception as e:
                        observation = f"Execution Exception: {str(e)}"

            # Feed ground truth observation back to model
            obs_payload = f"Observation: {observation}\n"
            self.history.append({"role": "user", "content": obs_payload})

        return "Error: Maximum execution steps exceeded."
