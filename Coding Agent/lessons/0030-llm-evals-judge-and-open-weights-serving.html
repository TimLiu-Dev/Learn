1. Eliminating Position Bias in LLM-as-a-Judge Harnesses

As Zheng et al. demonstrated, raw LLM judges suffer from position bias (favoring whichever answer appears first), verbosity bias (rewarding longer answers), and self-enhancement bias. To run trustworthy CI evals without human raters on every PR:

  • Position Swap Verification: Evaluate (A, B) AND swapped (B, A). If the verdict flips solely due to slot order, declare an inconsistent "TIE" rather than letting ordering noise corrupt metrics.
  • Explicit Rubric & Reference Grounding: Pass explicit scoring criteria + ground truth facts so verbosity does not outscore concise accuracy.
Open-Weights Serving & GPU Memory Budgeting Weights (FP16 vs Q8 vs AWQ INT4) + KV Cache + PagedAttention 
Model Parameters (e.g. 32B Coding Model):
  FP16 (2.0 bytes/param) = ~64 GB weights  ──> Overflow on single 48GB GPU!
  INT8 (1.0 bytes/param) = ~32 GB weights  ──> Tight fit on 48GB GPU
  INT4 (0.5 bytes/param) = ~16 GB weights  ──> Fits comfortably on 24GB/48GB + KV Cache!

vLLM PagedAttention:
  Allocates KV cache in non-contiguous fixed-size blocks (like OS Virtual Memory Pages),
  eliminating fragmentation waste and supporting continuous concurrent batching.

2. Back-of-the-Envelope GPU VRAM & Quantization Math

Whether running Ollama / LM Studio locally or deploying vLLM on Kubernetes GPUs, Senior AI Engineers estimate total VRAM before provisioning: Total VRAM = Weights_GB + KV_Cache_GB + Activation_Overhead_GB. Dropping weights from FP16 (2 bytes/param) to 4-bit quantization (0.5 bytes/param, e.g., AWQ or GGUF Q4_K_M) cuts weight memory by ~4x while leaving room for long-context KV caches across concurrent requests.
