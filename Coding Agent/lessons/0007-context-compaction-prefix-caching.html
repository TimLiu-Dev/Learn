Module 2: Code Perception & Context Est. 20 Mins Cache Optimization

Context Compaction & Prefix Caching: Slashing Latency & Costs by 90%

In a 25-turn autonomous coding session, an agent might re-transmit 30,000+ tokens of system instructions, tool schemas, and repository maps on every single step. In naive runtimes, this generates quadratic cost escalation and 15-second response delays. Modern inference engines (Anthropic, OpenAI, vLLM RadixAttention) offer KV Cache / Prefix Caching, allowing models to reuse precomputed attention tensors for static prompt prefixes. In this lesson, we master Prefix Cache Optimization and Context Compaction to cut token bills and latency by up to 90%.

Primary Source & Architecture Reference

"Prompt Caching: Accelerating Multi-Turn Agent Workflows & Slashing Costs" — Anthropic Engineering & vLLM RadixAttention Architecture (2024–2025).

Explore Anthropic Prompt Caching → • Core Insight: Attention Key-Value tensors are cached in a radix tree indexed by exact token prefixes. Mutating even a single character at token position N instantly invalidates all cached states from N to the end of the prompt. Prompts must be strictly structured from most static to most volatile to preserve cache reuse across turns.

1. The Multi-Turn KV Cache Bottleneck

In transformer architectures, computing attention requires projecting previous tokens into Key and Value (K, V) matrices. In a stateless API call without prefix caching, every turn forces the inference engine to recompute attention across the entire prompt history:

Inference Economics Over 20 Agent Turns Stateless Re-computation vs. Prefix KV Caching
UNCACHED

Stateless Re-Encoding

Every turn re-processes 35,000 tokens of system prompts, schemas, and repo maps. Over 20 turns, the client is billed for 700,000+ input tokens. Time-to-First-Token (TTFT) hovers around 8–14 seconds.

TURN 1

Cache Creation

The 35,000-token static prefix is computed once and stored in the inference server's Radix KV cache tree at standard base pricing.

TURNS 2–20

Prefix Cache Hits

Turns 2 through 20 read the precomputed KV tensors directly from GPU memory at 10% of base cost. Only the incremental dynamic turn is computed fresh.

RESULT

90% Cost & Latency Reduction

Total bill drops from $3.50 to $0.42. TTFT drops from 12 seconds to under 800 milliseconds per turn.

2. The Golden Rule of Prefix Ordering & Cache Invalidation

The Key-Value cache is stored as a Radix Tree matching token sequences from left to right.

⚠️ The Invalidation Law: Mutating token N destroys all cached KV tensors from token N onwards!

Avoid common anti-patterns that accidentally wipe the cache on every turn:

  • Dynamic Timestamps in Headers: Placing Current Time: 14:02:41 UTC at line 2 of the system prompt changes the token prefix every second, invalidating 100% of the cache.
  • Unsorted Tool Lists: Serializing tool schemas in arbitrary dictionary order causes non-deterministic JSON strings between runs.
  • In-Place History Mutation: Editing past turns instead of appending cleanly breaks cache matching.

Canonical Prefix Structure: 

[1. Static System Directives]  ──► 100% Static (Never changes)
[2. Alphabetized Tool Schemas]  ──► 100% Static (Deterministically ordered)
[3. Static Repository Map]      ──► Static throughout session
[4. Append-Only Turn History]   ──► Monotonically grows at tail
[5. Volatile Dynamic Turn]      ──► Dynamic ephemeral scratchpad (Tail only!)

3. Dynamic Context Compaction & Micro-Summaries

As an agent trajectory approaches 80% of total context limit (e.g., 160,000 tokens), we cannot wipe history without destroying prior reasoning.

Instead, we apply Observation Micro-Summarization: old, sprawling command outputs (e.g. 800 lines of terminal test logs) are trimmed into a concise 4-line summary preserving only the failure lines and exit status.
