Module 9: 2027 Frontier Est. 25 Mins Reasoning & Search

Test-Time Compute & Trajectory Search: Beyond Greedy ReAct Loops

In Lesson 0001, we built a standard single-path ReAct agent. In 2027, production coding agents transcend single-path greedy decoding: they scale Test-Time Compute (TTC) using Tree-of-Thought, Monte Carlo Tree Search (MCTS), and execution-based Process Reward Models (PRMs) to search the trajectory space and backtrack before making unrecoverable edits.

Primary Source & Architecture Reference

"Scaling LLM Test-Time Compute Optimally can be More Effective than Scaling Parameters" — Charlie Snell, Jaehoon Lee, Kelvin Xu, Aviral Kumar (UC Berkeley & Google DeepMind, 2024).

Snell et al., arXiv:2408.03314 → • Core Insight: Trading inference-time search compute (exploring multiple action rollouts with verifiers) matches or exceeds the coding benchmark performance of models 14× larger operating on greedy decoding.

1. The Fatal Flaw of Greedy ReAct in Complex Codebases

Standard ReAct operates as a greedy Markov decision process: at step $t$, the agent selects the single argmax action $a_t$. If $a_2$ chooses a flawed architectural hypothesis (e.g., refactoring the database schema instead of adjusting the serialization query), subsequent steps $a_3, a_4, \dots$ inherit the poisoned context. The agent enters catastrophic hallucination loops trying to fix downstream symptoms of an upstream blunder.

                      └── Action 1c ──> Verifier: 0.50 (BACKTRACK BUFFER)

2. Outcome Reward Models (ORMs) vs. Process Reward Models (PRMs)

In autonomous coding, we have a unique superpower that creative writing agents lack: deterministic execution environments.

  • Outcome Reward Models (ORMs): Evaluate only the final terminal patch against the full test suite. If the patch fails, ORMs give a zero reward without telling the agent where in the 15-step trajectory the logic derailed.
  • Process Reward Models (PRMs) / Execution Verifiers: Score every intermediate action step $s_t$. For coding agents, we construct hybrid verifiers combining:
    1. Syntax AST validity (0.0 if syntax error generated).
    2. Type-check diagnostics (mypy/pyright error count delta).
    3. Localized test assertions (fast in-memory unit tests).
    4. Diff volatility / blast radius (penalizing massive, unrequested file deletions).
