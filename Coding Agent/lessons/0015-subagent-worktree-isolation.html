Subagent Worktree Workspace Isolation: Concurrent Safe Editing & Atomic Merges

When multiple subagents operate concurrently across a codebase, unisolated edits lead to race conditions, clobbered source files, and corrupted git indices. Production agent harnesses utilize Git worktrees to furnish each parallel worker with an isolated filesystem checkout sharing a single repository database.

Primary Source & Architecture Reference

"git-worktree(1) Manual & SWE-agent Architecture" — Git Core Engineering & John Yang, Carlos E. Jimenez et al. (Princeton University, 2024).

Official git-worktree Documentation → • Core Insight: Decoupling the active working directory from the repository database enables concurrent branch checkouts with $O(1)$ storage overhead, isolating worker experiments while maintaining atomic rollback and merge control.

1. The Multi-Agent Race Condition: Why Shared Directories Fail

Imagine an orchestrator launching two parallel subagents: Agent A implements a new JWT validator, while Agent B refactors database connection pooling. Both agents are granted direct filesystem write access to the same local repository directory. 

// ❌ UNISOLATED CONCURRENT EXECUTION COLLAPSE:
Time T1: Agent A modifies 'src/server.py' (adding auth middleware import).
Time T2: Agent B modifies 'src/server.py' (overwriting server config).
Time T3: Agent A runs 'pytest tests/test_auth.py' in the same folder.
         -> FAILS: Agent B's partial, broken server edit caused test crash!
Time T4: Agent A assumes its auth patch broke the build, reverting server.py.
         -> Agent B's work is now completely clobbered and lost!

Naive solutions like cloning the entire repository (git clone /repo /repo-copy) for each agent fail because large codebases (e.g., Linux, Chromium, or monorepos) incur prohibitive disk consumption, slow network I/O, and detached branch tracking.

2. Git Worktrees: Shared Object Store, Isolated Working Trees

Git internally separates its Object Database (commits, trees, blobs located in .git/objects) from the Working Tree (the checked-out files you edit). Git Worktrees leverage this decoupling to link multiple independent filesystem directories to a single shared repository:

Git Worktree Filesystem Topology Single Repository Object Database • Multiple Concurrently Checked-Out Heads
STORAGE

Shared .git Database

Contains all commits, refs, and packs in .git/objects/. Zero file duplication across subagents.

WORKTREE A

/worktrees/agent-alpha/

Checked out on branch agent/feat-auth. Subagent A can edit, run tests, and commit independently.

WORKTREE B

/worktrees/agent-beta/

Checked out on branch agent/feat-db. Subagent B edits concurrently without seeing Agent A's files.

MAIN

/workspaces/primary/

Main branch remains completely clean and stable while parallel workers test experimental hypotheses.

3. The Subagent Worktree Lifecycle

A production worktree orchestrator manages workers through four deterministic phases:

  1. Provisioning: The orchestrator creates a new worktree linked to a feature branch: 
    git worktree add -b agent/task-42 /tmp/worktrees/task-42 HEAD
  2. Isolated Execution: The subagent operates exclusively inside /tmp/worktrees/task-42. Tool calls (read_file, write_file, pytest) are sandboxed to this path.
  3. Verification & Atomic Merge: Once the subagent confirms all tests pass, the orchestrator inspects the branch diff. If clean, it performs an atomic merge or squash onto the target branch: 
    git merge --no-ff agent/task-42
  4. Safe Teardown: The worktree directory is removed, pruning metadata references: 
    git worktree remove --force /tmp/worktrees/task-42
git branch -D agent/task-42

4. Production-Grade Reference Implementation

Here is how a production agent harness implements an in-memory and shell-safe WorktreeManager: 

import os
import subprocess
from typing import Dict, Any, Optional

class WorktreeManager:
    def __init__(self, repo_root: str, worktrees_dir: str):
        self.repo_root = os.path.abspath(repo_root)
        self.worktrees_dir = os.path.abspath(worktrees_dir)
        os.makedirs(self.worktrees_dir, exist_ok=True)
        self.active_worktrees: Dict[str, str] = {}

    def allocate_worktree(self, agent_id: str, base_ref: str = "HEAD") -> str:
        """Allocates an isolated worktree directory for a subagent."""
        branch_name = f"subagent/{agent_id}"
        worktree_path = os.path.join(self.worktrees_dir, agent_id)

        # git worktree add -b <branch> <path> <base_ref>
        cmd = ["git", "worktree", "add", "-b", branch_name, worktree_path, base_ref]
        subprocess.run(cmd, cwd=self.repo_root, check=True, capture_output=True)

        self.active_worktrees[agent_id] = worktree_path
        return worktree_path

    def release_worktree(self, agent_id: str, delete_branch: bool = True) -> None:
        """Removes the worktree and cleans up references."""
        worktree_path = self.active_worktrees.pop(agent_id, None)
        if not worktree_path:
            return

        # git worktree remove --force <path>
        subprocess.run(["git", "worktree", "remove", "--force", worktree_path],
                       cwd=self.repo_root, check=True, capture_output=True)

        if delete_branch:
            branch_name = f"subagent/{agent_id}"
            subprocess.run(["git", "branch", "-D", branch_name],
                           cwd=self.repo_root, check=False, capture_output=True)
