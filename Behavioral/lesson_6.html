💻 Interactive Code Practice: Non-Blocking Startup Initializer

The technical fix: Refactor synchronous blocking SDK calls into a non-blocking background initialization.

Jetpack App Startup
The Problem: The existing AppInitializer blocks the main thread in Application.onCreate() to initialize heavy analytics and crash tracking.

Your Task: Refactor initHeavySdk() to dispatch initialization on Dispatchers.Default using an injected CoroutineScope, ensuring the main thread is immediately freed to render the first frame.
AppInitializer.kt Kotlin / Startup
💡 Hint: Pass appScope: CoroutineScope and launch the heavy SDK inside appScope.launch(Dispatchers.Default) { AnalyticsSdk.start(context) }.

🏆 Production Non-Blocking Startup Architecture:

class AppInitializer(
    private val appScope: CoroutineScope,
    private val ioDispatcher: CoroutineDispatcher = Dispatchers.IO
) {
    fun initialize(context: Context) {
        // Defer heavy SDK initialization off the Main Thread
        appScope.launch(ioDispatcher) {
            AnalyticsSdk.start(context)
        }
    }
}
