💻 Interactive Code Practice: Fix the Buggy Event Bus

The technical dispute: Replace the fragile SharedFlow navigation leak with a production-grade Channel or SingleLiveEvent pattern.

Kotlin Flow Architecture
The Bug: The current code uses MutableSharedFlow(replay = 1) for one-time Snackbar and navigation events. When the user rotates their screen, the new Activity reconnects and triggers the event a second time! If replay = 0, events emitted while the app is in the background get silently dropped.

Your Task: Refactor UiEventCoordinator to use a buffered Kotlin Channel exposed via receiveAsFlow(), ensuring each one-time event is consumed exactly once.
UiEventCoordinator.kt Kotlin / Coroutines
💡 Hint: Replace MutableSharedFlow with Channel<String>(Channel.BUFFERED) and expose it as a cold stream using channel.receiveAsFlow(). Channels guarantee single-receiver semantics, preventing repeat triggers on configuration change!

🏆 Production Senior Architecture:

class UiEventCoordinator {
    // Channels guarantee exactly-once delivery and buffer events when screen is paused
    private val _eventChannel = Channel<String>(Channel.BUFFERED)
    val events: Flow<String> = _eventChannel.receiveAsFlow()

    suspend fun sendEvent(message: String) {
        _eventChannel.send(message)
    }
}
