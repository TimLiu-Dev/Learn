📐 Why Traditional STAR Fails in Senior Technical Interviews

Most candidates use basic STAR (Situation, Task, Action, Result). For a junior role, that suffices. But for Mid-level (L4/E4) and Senior (L5/E5) software engineers, interviewers specifically listen for the 5th element: Technical Deep-Dive & Systemic Safeguards.

In 2027, top companies look for engineers who don't just put out fires, but who understand the underlying system failure, eliminate the root cause, and establish automated guardrails so that no engineer can introduce that class of bug ever again.

💻 Interactive Code Practice: Fix the Leaking Production Flow

The real bug behind the outage: A repository leaking coroutines and crashing under network reconnects.

Kotlin Coroutines / Flow Engine
Scenario: You are tasked with fixing TelemetryRepository. Currently, whenever observeTelemetry() is called, it launches an unconfined Coroutine inside GlobalScope that never stops, mutates an unsafe ArrayList across threads, and crashes when collectors disconnect.

Your Task: Refactor this class to use modern, leak-free Android architecture:
  • Eliminate GlobalScope and unmanaged background jobs.
  • Use thread-safe state management (such as MutableStateFlow or thread-safe state updates).
  • Ensure proper lifecycle awareness (or provide a safe stop() / close() cancellation mechanism).
TelemetryRepository.kt Kotlin / Android Jetpack
💡 Hint 1: Never use GlobalScope in Android. Repositories should either expose a cold Flow that stops when the collector disconnects, or use a CoroutineScope injected via constructor (e.g., bound to SupervisorJob) or StateFlow with SharingStarted.WhileSubscribed(5000).

💡 Hint 2: To make state updates thread-safe without locks, use MutableStateFlow<List<String>> and update it atomically via _state.update { current -> current + event } or expose a read-only asStateFlow().

🏆 Production Senior Architecture (Clean & Thread-Safe):

class TelemetryRepository(
    private val externalScope: CoroutineScope,
    private val defaultDispatcher: CoroutineDispatcher = Dispatchers.Default
) {
    // Thread-safe, reactive state holder
    private val _telemetryState = MutableStateFlow<List<String>>(emptyList())
    val telemetryState: StateFlow<List<String>> = _telemetryState.asStateFlow()

    private var collectionJob: Job? = null

    fun startStreaming(dataSource: StreamSource) {
        // Cancel existing job to prevent multiple redundant collectors
        collectionJob?.cancel()

        collectionJob = externalScope.launch(defaultDispatcher) {
            dataSource.events
                .buffer(Channel.CONFLATED) // Prevent backpressure buffer overflow
                .collect { event ->
                    _telemetryState.update { currentList ->
                        currentList + event
                    }
                }
        }
    }

    fun stopStreaming() {
        collectionJob?.cancel()
        collectionJob = null
    }
}

Why Big Tech Bars Love This: It uses dependency injection for CoroutineScope and Dispatcher (enabling seamless unit testing with TestScope and StandardTestDispatcher), prevents backpressure overflow via Channel.CONFLATED, and guarantees atomic updates with StateFlow.update.
